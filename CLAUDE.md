# CLAUDE.md

Pulse is a self-describing tabular data processing engine. Ships as Go library (`github.com/frankbardon/pulse`) and CLI (`cmd/pulse/`). Library primary; CLI thin adapter.

**Design principles**

- **Library-first.** `pulse.go` facade (`New`, `Open`, `Process`, `Compose`, `Import`, `Export`, `Convert`, `Inspect`, `Predict`, `Sample`, `Facet`, `Synth`, `Profile`, `ProcessStream`, `ProcessChain`, `CountRecords`, `ComposeParallel`, `Lookup`, `BuildIndex`, `VerifyIndex`, `ListIndexes`, `DropIndex`, `ListTemplates`, `GetTemplate`, `RenderTemplate`, `RenderTemplateRequest`, `ReloadTemplates`) is the public API. CLI never contains business logic.
- **Self-describing.** Every `.pulse` file carries its schema in the header. `descriptor/` provides `manifest`, `predict`, `inspect` — no-execute operations.
- **Skill-augmented.** `skills/` embeds an atomic-per-surface skill pack (`op-*` / `tool-*` / `type-*`) plus ~20 topical design skills via `//go:embed *.md`. LLM agents call `skills.List()` / `skills.Get(name)` for domain guidance; the filesystem walk + frontmatter parse is the source of truth.
- **Embedder-extensible.** `pulse.Options.Extensions` registers custom operators (AGG/ATTR/FILTER/GROUP/WIN/FEAT/TEST/SYNTH) + expr functions + lookup tables. First-class — predict, manifest, MCP, runtime treat identically to built-ins. See `docs/src/internals/extension-points.md`.
- **Nexus relationship.** Pulse standalone. Nexus discovers via `pulse manifest --json` + loads embedded skills. No reverse dependency.

For recipes (adding operators, I/O formats, MCP tools, error codes, field types; porting; debugging predict; regenerating goldens; wiring MCP client) read the mdBook Internals chapter under `docs/src/internals/` (adding-aggregator.md, adding-attribute.md, adding-filterer.md, adding-grouper.md, adding-window.md, adding-feature.md, adding-test.md, adding-synth-distribution.md, adding-mcp-tool.md, adding-io-format.md, adding-field-type.md, adding-error-code.md, adding-chain-predicate.md, adding-facet-capability.md, regenerating-goldens.md, debugging-predict.md, wiring-mcp-client.md, extension-points.md). Long-form reference docs live under `.claude/reference/` — see "Reference Docs" at the bottom.

## Architecture

```
pulse/
├── cmd/pulse/              # CLI binary — only binary
├── pulse.go                # Public facade
├── service/                # Orchestration: wires processing to encoding
├── processing/             # Aggregators, attributes, filterers, groupers
│   ├── window/             # WIN_* operators
│   └── feature/            # FEAT_* pre-filter feature engineers
├── encoding/               # .pulse binary codec (incl. archive + cohesion)
├── io/                     # Tabular ↔ .pulse adapters (csv|tsv|ndjson|jsonarray|jsonshared|arrow|parquet|excel|spss)
├── fs/                     # afero-based filesystem abstraction
├── errors/                 # Typed error codes (CodedError system)
├── types/                  # Request/response structs + streamability table
├── descriptor/             # manifest, predict, inspect, envelope (no-execute)
├── skills/                 # //go:embed markdown skill pack
├── examples/               # //go:embed runnable request examples
├── synth/                  # Synthetic data generator
├── mcp/                    # SDK-free MCP core (typed In/Out, reflected schemas, handlers, bind)
│   ├── gosdk/              # go-sdk adapter — the ONLY package importing the MCP SDK
│   └── toolmeta/           # Leaf tool name+description metadata (descriptor + core import it)
├── docs/                   # mdBook source (GitHub Pages)
└── internal/cli/           # CLI internals
```

`pulse.go` re-exports `types.Request` → `pulse.Request`, `types.Response` → `pulse.Response`, `types.ComposedRequest` → `pulse.ComposedRequest`, plus `synth.Spec`/`Result`/`Options`/`Profile`/`ProfileOptions`.

CLI commands map 1:1 to manifest commands: `process`, `compose`, `sample`, `facet`, `inspect`, `predict`, `manifest`, `schema`, `mcp`, plus `synth from-schema`, `synth from-profile`, `profile create`, `shard {create,add,remove,list,compact,verify,extract}`, `index {build,list,verify,drop}`, `api {process,compose,facet,process-chain,lookup}`. `pulse schema` prints the payload JSON Schema raw (built by `descriptor.BuildPayloadSchema`); not envelope-wrapped.

The MCP layer is split: `mcp/` is the SDK-free core (typed In/Out structs, reflected JSON schemas, typed handlers over `*pulse.Pulse`, `ToolDescriptor`, `Tools(cfg)`, strict-decode, bind classification — imports no MCP SDK, gated by `TestMCPCore_NoSDKImport`); `mcp/gosdk/` is the only package importing `github.com/modelcontextprotocol/go-sdk`, and its `Register(server, p, cfg)` mounts the core catalog onto a caller-supplied server; `mcp/toolmeta/` is the leaf name+description metadata imported by both `descriptor` and the core. The former internal MCP server tree has been removed — `pulse mcp` builds a bare go-sdk server and calls `gosdk.Register`. The registry registers one tool per facade method plus skills/examples/errors/import/label tools (the manifest is the source-of-truth count; do not hardcode it) and two resource schemes (`pulse://`, `pulse-skill://`). The reserved static resource `pulse://schema` serves the payload JSON Schema (`descriptor.BuildPayloadSchema`) — a resource, not a tool, so the tool surface is unchanged. MCP tool I/O is the structured typed shape: payload tools take the structured request at top level, outputs are typed-wrapped, coded errors surface as `{code, message, details}`.

Docs at <https://frankbardon.github.io/pulse/>. Skills under `skills/` are the LLM surface.

## Code Conventions

### Naming

- Pulse-native identifiers. No predecessor references (`TestNoOrbitPrefix`, `TestNoOrbitPrefixes`).
- Module path: `github.com/frankbardon/pulse`. `io/` sub-packages imported as `pio "..."`.
- Component types: SCREAMING_SNAKE — `AGG_COUNT`, `ATTR_ZSCORE`, `FILTER_INCLUDE`, `GROUP_CATEGORY`, `WIN_LAG`, `FEAT_LOG`, `TEST_T`.
- Error codes: DOMAIN_CATEGORY — `ENCODING_INVALID`, `PROCESSING_CONFIG`, `SERVICE_VALIDATION`, `DATA_FILE`, `CLI_INPUT`, `PULSE_IMPORT_ROW_ERROR`.

### Error handling

Six domains: `CLI`, `DATA`, `ENCODING`, `PROCESSING`, `PULSE`, `SERVICE`. Canonical list in `errors/codes.go` (`allCodes`). Every code needs `codeMetadata` entry (`errors/fixup_metadata.go`) with `Message` + ≥1 `Fixup` template OR `FixupNotApplicable: true`. Per-code prose surfaced via `pulse_errors_lookup` (MCP) / `pulse errors lookup CODE` (CLI). Manifest carries name-only list.

Field descriptions in `.pulse` capped at 1000 bytes (`PULSE_IMPORT_DESCRIPTION_TOO_LONG`). Low-quality descriptions emit `PULSE_FIELD_DESCRIPTION_LOW_QUALITY` warnings (errors under `--strict`).

### Byte-layout invariants

`.pulse` binary format:

1. **9-byte header:** 8-byte magic `PULSE\x00\x00\x00` + 1-byte format version `0x01`. `encoding.MagicBytes`, `encoding.FormatVersion`, `encoding.HeaderSize = 9`.
2. **Schema block:** field descriptors (name, type byte, **nullable flag byte**, byte offset, bit position, optional description). Nullable flag immediately after type byte; `1` = participates in null bitmap.
3. **Dictionary blocks:** inline after schema for `categorical_u8/u16/u32`.
4. **Record data:** fixed-width rows; size derived from schema.
5. **Per-record null bitmap (optional).** When schema has any nullable field (`Schema.HasBitmap()`), every record carries trailing bitmap of `ceil(field_count / 8)` bytes. Field index `i` → byte `i/8`, bit `i%8` (LSB-first); `1` = null. Absent when no nullable fields. Helpers: `encoding.ReadBitmap`, `encoding.WriteBitmap`, `encoding.BitmapIsNull`, `encoding.BitmapSetNull`, `Schema.BitmapByteSize()`.

18 field types (full table in `skills/cohort-schema-design.md`): `u4`, `u8`/`u16`/`u32`/`u64`, `f32`/`f64`, `date`, `datetime`, `packed_bool`, `categorical_u8`/`u16`/`u32`, `decimal128`, `set_u8`/`u16`/`u32`/`u64`. Bit-packed (`u4`, `packed_bool`) return `ByteSize() == 0` (share bytes with neighbours via `FieldType.IsBitPacked()`). `categorical_*` and `set_*` both carry an inline dictionary block (`FieldType.HasDictionary()`); for `set_*` the on-wire value is a fixed-width bitmask where bit `i` ↔ dictionary entry `i` (up to 8/16/32/64 entries) and an empty mask is a valid "no selection" — distinct from null. `date` is epoch DAYS as a 4-byte `uint32`; `datetime` (type byte `17`) is epoch SECONDS as an 8-byte `uint64` — the two are never interchangeable, and swapping them rescales every value by 86,400. `datetime` is naive UTC (an offset-bearing literal normalises to the same instant, the offset itself is discarded), second-resolution (sub-second input truncates toward the epoch), carries no dictionary, and is not bit-packed; text form round-trips through `encoding.ParseDateTime` / `FormatDateTime` / `CanonicalDateTimeLayout` (`encoding/datetime.go`). Nullability orthogonal to type. Unknown type byte → `ENCODING_INVALID`. Decimal128 and set_* nulls via bitmap only — no in-band sentinel.

**Shard archive variant.** `.pulse` path resolves to either single-file layout above or **shard archive** — uncompressed Zip64 (Method 0, store-only) whose first four bytes are zip magic `PK\x03\x04` instead of `PULSE` magic. Single-file byte format **unchanged**; magic-byte dispatch at `pulse.Open` selects shape. Shard archive carries reserved `_schema.pulse` entry (header-only canonical schema + SHRD trailer with `aggregate_record_count` + `shard_count`) plus N standalone shard payloads. Per-shard cohesion: structural strict (byte-equal at insert), descriptions tolerant. Categorical dictionaries grow under union-merge semantics; divergent incoming shards byte-rewritten with remapped indices. Width overflow → `PULSE_SHARD_DICT_WIDTH_OVERFLOW`. Stricter prefix-only validator (`PULSE_SHARD_DICT_DIVERGENCE`) retained for `pulse shard verify`. Anchor syntax `archive.pulse#shard.pulse` opens one shard as one-shard cohort. Caller-owned concurrency. Full detail in `skills/cohort-schema-design.md` (Sharded cohorts).

**Sidecar point-lookup index.** `Pulse.Lookup` / `pulse index build` / `pulse api lookup` are backed by a **separate file** next to the cohort — `cohort.pulse.<keyhash>.idx` — never the `.pulse` layout above. Format **v3** (own magic + version, distinct from `encoding.MagicBytes`/`FormatVersion`): 9-byte header (magic `PULSEIDX` + version `0x03`) → 32-byte SHA-256 source fingerprint → key-spec (ordered key columns + types) → `SourceSize` (u64) + `SourceModTime` (i64 Unix ns) → `u32 bucket_count` → fixed-width `bucket_count × u64` bucket-offset table → self-delimited bucket data (FNV-1a hash buckets → `[]uint64` row-id multimap). The fixed-width offset table makes one bucket directly addressable — a lookup hashes the key, seeks to its offset entry, seeks to that bucket's data, then seeks straight to each matched record via `RecordLocator`; never a full-cohort or full-index read (O(1) flat, measured ~5µs across 10k→1M rows vs. linear unindexed scan). Read-path staleness is a cheap O(1) size+mtime stat (mismatch → `PULSE_INDEX_STALE`); `pulse index verify` recomputes the authoritative full SHA-256 fingerprint instead. **Keyable-type policy** (`processing.IsIndexKeyableFieldType`): ALLOW `u4`/`u8`/`u16`/`u32`/`u64`, `f32`/`f64` (raw bit-pattern equality — `-0.0`/NaN caveat), `date`, `datetime` (epoch seconds; literal resolves through `encoding.ParseDateTime`, never `ParseFloat` — inherits `u64`'s >2^53 float-echo caveat, reachable only by a pre-1970 instant), `decimal128` (exact mantissa, no float round-trip), `categorical_*` (dictionary ID), `packed_bool`. REJECT `set_*` (a multi-select bitmask has no single unambiguous equality value — use `FILTER_SET` instead). Single-file cohorts only: shard archives → `PULSE_INDEX_UNSUPPORTED_SHARDED` (the `archive.pulse#shard.pulse` anchor is a tested single-shard workaround). Equality-only, full-key required, composite-key order significant end to end. Coded errors: `PULSE_INDEX_MISSING`, `PULSE_INDEX_STALE`, `PULSE_INDEX_UNSUPPORTED_SHARDED`, `PULSE_LOOKUP_NOT_FOUND`, `PULSE_LOOKUP_AMBIGUOUS`. Detail: `skills/cohort-schema-design.md` (Sidecar index) + `skills/tool-lookup.md`.

**SPSS metadata sidecar.** An SPSS import writes a SECOND sidecar next to the cohort — `cohort.pulse.spss.json` (`spss.SidecarSuffix`, the `imports.Sidecar` "suffix appended to the cohort filename" convention; deliberately distinct from `imports.SidecarSuffix` `.meta.json`, which a managed import writes for the same cohort). JSON, not a `.pulse` layout. It holds every dictionary element the `.pulse` byte format has no slot for: measure levels, print/write format codes, records `7/17` file attributes and `7/18` variable attributes (kept distinct), record `6` documents, weight variable, compression bias, `nominal_case_size`, original short names, declared byte widths + `7/14` very-long-string segmentation, MR/MC set definitions, `7/5` variable sets, the source charset **in the file's own declared spelling**, product name, missing-value specs in all three shapes (discrete ≤3 / range / range-plus-one-discrete, raw 8-byte slots retained verbatim), and — the load-bearing payload — the `code ↔ label ↔ Pulse dictionary ID` triple per categorical column, since the cohort dictionary holds SPSS **codes** and this is the only place the **labels** live. Document shape: `{format_version, kind, fingerprint, payload}`. **`payload` is flat and self-contained** (no paths, no offsets, no external references) so it can be lifted verbatim into a future `.pulse` schema metadata block — that block is **deferred, not rejected** (it needs a `FormatVersion` `0x01` → `0x02` bump affecting every Pulse user), and this shape is what keeps the door open. `fingerprint` is the only file-bound part and a lift drops it: 32-byte SHA-256 + `SourceSize` (u64) + `SourceModTime` (i64 Unix ns) over the **`.pulse` cohort** (not the source `.sav`), mirroring the sidecar index's O(1) size+mtime staleness check. Read-path policy, implemented at `spss.LoadSidecar(fs, cohortPath, spss.WriterOptions{})` (the write side's first act, reached from `pulse export spss`): **absent → warning** `PULSE_SPSS_SIDECAR_ABSENT` and the caller synthesises a default dictionary from the `.pulse` schema (a cohort that was never SPSS-derived correctly has none), **stale → error** `PULSE_SPSS_SIDECAR_STALE` (a stale dictionary over changed data produces a file that looks authoritative and is wrong — a refusal returns NO `SidecarResolution`, so there is no shape in which a caller reaches the stale document), **present-but-unreadable → error** `PULSE_SPSS_SIDECAR_INVALID` (foreign `kind`, unrecognised `format_version`, malformed digest, or a broken `multiple_response_sets[].fields` parallel array). The staleness check is the same cheap O(1) size+mtime comparison `PULSE_INDEX_STALE` uses, with the same residual gap (a size- and mtime-preserving in-place edit); `Document.VerifyDigest` is the authoritative full SHA-256 recompute for a verify-style pass. `spss.WriterOptions{IgnoreSidecar: true}` (`--ignore-sidecar`) suppresses the sidecar READ entirely — not merely the staleness verdict — so a healthy sidecar is ignored too and an unreadable one cannot block; it downgrades both refusals to a `PULSE_SPSS_SIDECAR_IGNORED` warning on the same synthesise-a-default path, and never applies a stale dictionary. That warning deliberately does not report which refusal it silenced — skipping the read means nothing on that path knows. `MRSet.Fields` is additive under `omitempty` and `SidecarFormatVersion` did not move for it, so an ABSENT `fields` key means “written before the slot existed” and is back-filled by `Document.Normalise` from `variables[].short_name` (case-insensitive, first declaration wins), never rejected; a PRESENT one of the wrong length IS rejected. Written via `afero.Fs` + `encoding/json` through the optional `io.SidecarEmitter` interface, which `ImportJob.Run` calls after the cohort write; a source not implementing it yields a byte-identical import and no sidecar. Detail: `skills/spss-cohorts.md` (the metadata sidecar + the derived-column registry) + `docs/src/cli/import-spss.md` + `docs/src/internals/adding-io-format.md`.

**SPSS derived columns.** An SPSS import can produce a cohort WIDER than the source dictionary — count columns from the returned schema, never from the SPSS variable count. Two synthesised kinds, both **additive**: a `<var>_missing` `categorical_*` sibling immediately after every numeric variable declaring user-missing values (the null bitmap is one bit and cannot record *why*, so the reason must be materialised as data), and one `set_*` bitmask per multiple-DICHOTOMY response set immediately after its LAST constituent (never instead of the constituents — a bit cannot separate "not selected" from "not asked"). The asymmetry with the CATEGORICAL arm is deliberate and must not be "fixed": a categorical column already stores the SPSS code as a dictionary entry, so the code is preserved losslessly and a sibling would double the width of an all-categorical survey; those entries are FLAGGED instead (`variables[].categories[].missing` on the sidecar + one per-FILE `PULSE_SPSS_CATEGORICAL_USER_MISSING` diagnostic). `--spss-missing=null` / `spss.WithMissingMode` suppresses the numeric siblings only; the `set_*` column has no opt-out. Every synthesised column is registered on the sidecar's `payload.derived` (closed `kind` vocabulary — `spss.DerivedKinds()` / `spss.DerivedFoldFor`; a cohort that derived nothing writes `"derived": []`, never a missing key), so the export folds them mechanically rather than by name-matching. Detail: `skills/spss-cohorts.md`.

**SPSS export.** `pulse export spss -i cohort.pulse -o out.sav` (and `pulse convert x.csv out.sav`) writes `.sav`; `descriptor.importCapability()` carries `Export: true` for `spss` and `exportCapability()` its `warn_and_skip` overlay entry — `TestManifestImportCapability_ExportFlagMatchesExportBlock` fails if only one moves. Four per-command flags, one per `spss.WriterOptions` field: `--ignore-sidecar`, `--uncompressed`, `--charset`, `--sanitize-names`. The `.sav` writer is a **`pio.CohortWriter`**, the one optional writer interface that replaces the row loop rather than decorating it: `ExportJob.Run` calls `WriteCohort(ctx, CohortSource{FS, Path, Includes, Labelled})` after `SetPulseSchema` + `WriteHeader` and never calls `WriteRow`, because a `.sav` value is derived from a categorical's dictionary ID, a `set_*`'s mask bits and the null bitmap — all three erased by `formatFieldValue`'s rendering (a null and an empty string categorical become the same cell). Consequences: `ExportJob.Includes` / `Labels` are REFUSED with `PULSE_SPSS_EXPORT_UNSUPPORTED` rather than silently dropped, overlays are warn-and-skip, and a `convert` from a text source (no cohort exists) buffers rows and builds an intermediate in-memory cohort through the ordinary import path. Encode-side diagnostics ride the new `io.TargetWarningEmitter` optional interface onto `ExportReport.TargetWarnings` / `ConvertReport.TargetWarnings` (nil for every pre-existing adapter); the CLI re-reads them AFTER `Close`, because a writer that encodes at `Close` has raised none of them when the job builds its report. `PULSE_SPSS_EXPORT_UNSUPPORTED` was REPURPOSED, not retired — it now means "this cohort has no honest `.sav` form", matching E3-S2's treatment of `PULSE_SPSS_COMPRESSION_UNSUPPORTED`. Name policy: illegal names are `PULSE_SPSS_NAME_INVALID` / `_COLLISION` by default; `--sanitize-names` opts into a deterministic, collision-safe rewrite of the SYNTHESISED path only, reporting every rename as `PULSE_SPSS_NAME_SANITIZED`. Detail: `skills/spss-cohorts.md` (Writing `.sav`) + `skills/session-bootstrap.md` (Target-format CLI flags).

**Export predict is target-aware.** `ExportJob.Predict` consults the target through the optional **`io.CohortValidator`** interface (`ValidateCohort(ctx, CohortSource) ([]*errors.CodedError, error)`), the write-side peer of `CohortWriter`; diagnostics land on the new `io.PredictReport.TargetWarnings` slot (symmetric with `ExportReport.TargetWarnings`). A Target that is nil or does not implement it is predicted EXACTLY as before — no extra read, no new failure mode (`TestExportJob_Predict_NonValidatingTargetUnchanged`). `spss.Writer` is the only implementer: `ValidateCohort` runs the writer's own non-data pass (`planCohort` — sidecar resolution, `BuildDictionary`, name policy, charset transcode, derived fold, `NewDataEncoder` column checks) and discards it, so a predicted refusal is the export's own check code-for-code, and it mutates nothing on the Writer. **Sound but INCOMPLETE by design:** anything needing a record (value width overflow, cell-text charset unencodability, a dictionary ID with no source code) is unreachable, and predict must NEVER refuse what the real export would accept — a false refusal is worse than silence. `pulse export predict` reads `--format` (writer built via `newWriterForFormat` against a MemMapFs + throwaway path, never `Close`d, so no file is created) and mounts the four `.sav` write flags, because `--sanitize-names` flips a `PULSE_SPSS_NAME_INVALID` refusal into a warning; with no `--format` behaviour is unchanged and the text output says the target was not checked. `format_version` stays `"1.1"` — `io.PredictReport` is not payload-reachable. Detail: `docs/src/internals/adding-io-format.md` + `docs/src/cli/export-spss.md`.

**Projected buffered decode.** Per-request field projection on the buffered decode iterator is **default-on** — it is output-transparent (same result payload, only faster and lighter per-record), so callers get the win with no flags. Opt out with `pulse.Options{DisableProjection: true}` or the `--no-project` CLI flag on `pulse api process` (v1: `pulse api process` only — `process-chain` / `compose` do not expose it yet). `pulse.Options.ProjectBufferedFields` is retained but deprecated: setting `true` is a harmless no-op; use `DisableProjection` to force full-record decode. Wiring at `pulse.go`: `svc.SetProjectBufferedFields(opts.ProjectBufferedFields || !opts.DisableProjection)`. `processing.NeededFields(req, schema, ext)` walks every request slot and returns a `FieldSet`; the iterator turns retained set into a cached `encoding.DecodePlan` via `Schema.BuildDecodePlan(retained)`. **A slot the walk misses, or a built-in whose `Params` name a field `addAggParamFields` does not know, fails SILENTLY** — the field is decoded onto no `Record`, `Record.NumericValue` answers `ok=false` on every row, and the operator reads a missing input rather than a broken request, so the request succeeds and publishes a confident zero with `n_null` equal to the full admitted count as the only signature. `Crosstab.MarginAggregations` is a walked slot (own `Field`, `Params` fields, and extension widening, exactly as `Crosstab.Cell`); `distinct_by` / `weight_field` / `numerator_field` / `denominator_field` are the aggregator params `addAggParamFields` covers, and a new one belongs there on the day the operator lands. Plan segments: `SkipBytes{N}` (one discard over N bytes) and `DecodeFields{Fields}`. Bit-packed runs stay grouped; null-bitmap whole-or-skip. Extension operators without `FieldInputs` widen retained set to `*`. Bench: ~7× speedup, ~14× fewer allocs on a 4-field projection of a 200-field cohort. Detail: `skills/cohort-schema-design.md` + `docs/src/internals/extension-points.md` + `.claude/reference/execution-modes.md`.

### Smart defaults

When a request slot names a field but omits `Type`, engine infers from schema type. Table in `descriptor/defaults.go` (`defaultRules`).

| Field type | Default aggregation | Default grouper |
|---|---|---|
| numeric (u4/u8/u16/u32/u64, f32/f64, decimal128) | `AGG_SUM` | `GROUP_RANGE` (Interval 10) |
| categorical_* | `AGG_FREQUENCY` | `GROUP_CATEGORY` |
| `date` | (explicit only) | `GROUP_DATE` (`"day"`) |
| `datetime` | (explicit only) | `GROUP_DATE` (`"day"`) |
| `packed_bool` | `AGG_FREQUENCY` | `GROUP_CATEGORY` |

`Field.Nullable` orthogonal — never changes inferred operator. Defaults apply only when `Field` set and `Type` empty; never override explicit `Type`; never cross categories; never default tests, filter expressions, attributes, windows, features. Disable via `pulse.Options{DisableDefaults: true}` or `--no-defaults`. Predict always computes `DefaultsApplied`.

**Date-family field types.** `GROUP_DATE`, `GROUP_DATE_RANGES` and `FILTER_DATE_RANGES` accept BOTH temporal field types — `date` (epoch days, `uint32`) and `datetime` (epoch seconds, `uint64`). Everything downstream of the operator boundary (labeled-range matching, calendar-component bucketing, ISO period boundaries) speaks epoch DAYS only, so a `datetime` column is day-truncated exactly once at that boundary by `encoding.DateTimeToDay` — truncation toward the past, never rounding, naive UTC (`2024-03-04T23:59:59Z` buckets as `2024-03-04`; `1969-12-31T23:59:59Z` is day −1, not day 0). The single adapter is `processing/date_field.go` (`resolveDateFieldSeconds` classifies the column once at construction, `epochDayFromValue` applies it per record) — no call site open-codes a `/ 86400`. `GROUP_DATE_RANGES` / `FILTER_DATE_RANGES` reject any other field type with `PROCESSING_CONFIG`; `GROUP_DATE` keeps its historical non-validating posture and reads a non-temporal `Field` as an epoch-day count.

`GROUP_DATE_RANGES` is an explicit-only date-family grouper (never a smart default): it buckets each row by a labeled `{label, start, end}` date-range set (E1-S1 shared model, `processing.CompileDateRanges`) and emits the matching range's label as the bucket key; out-of-range rows land in a configurable unmatched bucket (default label `"unmatched"`). Streamable + mergeable. Range source is exactly one of inline `ranges` (author-order array) XOR a named `table:` referencing a registered `RangeTable` (`Options.Extensions.RangeTables` / `PULSE_RANGE_TABLES_DIR`); both present or neither → `PULSE_RANGE_SOURCE_AMBIGUOUS`, unknown table name → `PULSE_RANGE_TABLE_UNKNOWN`, a field that is neither `date` nor `datetime` → `PROCESSING_CONFIG`. Because a grouper factory cannot reach the `ExtensionRegistry` at construction (signature `(grp, schema)`), a named `table:` is resolved lazily via the `processing.ExtensionAware` `SetExtensions` hook (threaded through every grouper construction site by `processing.ApplyGrouperExtensions`); the inline source resolves eagerly at construction.

`FILTER_DATE_RANGES` keeps rows whose date-family `Field` day-integer falls inside any range of the same E1-S1 labeled-range set (`processing.CompileDateRanges`); every out-of-range row and every null/missing date is dropped. The range `label` is irrelevant to keep/drop but the range set is still fully validated (`PULSE_RANGE_OVERLAP` / `_DUPLICATE_LABEL` / `_INVALID`); a field that is neither `date` nor `datetime` → `PROCESSING_CONFIG`. Range source is exactly one of inline `ranges` XOR a named `table:` (registered `RangeTable`, resolved via the filterer's `ExtensionAware` hook — filterers already receive `SetExtensions`); both present or neither → `PULSE_RANGE_SOURCE_AMBIGUOUS`, unknown table → `PULSE_RANGE_TABLE_UNKNOWN`. Row-local streamable, so it is auto-available to `process`, `sample`, and `facet` (via `FacetRequest.Filterers`) single-pass. Structured ranges cannot ride `Values []string`, so `types.Filterer` carries an additive `Params json.RawMessage` slot (`{"ranges":[{label,start,end}]}` or `{"table":"<name>"}`) — payload-reachable, additive `omitempty`, `format_version` stays `"1.1"`.

## Output Format Contract

### `--json` envelope

All `--json` CLI output + descriptor operations use `descriptor.Envelope`:

```json
{
  "format_version": "1.1",
  "data": { ... },
  "request": { ... },
  "errors": [],
  "warnings": []
}
```

- `format_version` always `"1.1"`. Bumped from `"1.0"` for the Compose facade lift: `pulse.Compose` / `pulse.ComposeParallel` now return `*ComposedResponse` and `pulse api compose --json` wraps that object on `data` (see Compose-specific envelope below). Future backward-incompatible shape changes MUST update this section.
- `errors` / `warnings` use `{"code", "message", "details"}`. Empty array (never null) when absent. A FATAL error that is a `*errors.CodedError` carries its own code and details — the `import` / `convert` / `export` leaves route through `writeCodedErrorEnvelope`, which unwraps with `errors.As` and falls back to the leaf's placeholder (`IMPORT_ERROR`, `CONVERT_ERROR`, …) only for an uncoded error. Stringifying a coded error into the placeholder makes `errors[0].code` unusable with `pulse errors lookup`.
- `request` is opt-in echo of the *normalized* request. Omitted unless `pulse.Options.EchoRequest` is true or CLI flag `--echo-request`. Shape varies: `Request` for process/predict, `ComposedRequest` for compose, `ChainRequest` for process-chain, `FacetRequest` for facet, `SampleRequest` for sample. Streaming output skips the echo. Use `descriptor.NewEnvelopeWithRequest(data, req)` or `env.WithRequest(req)` to populate.

Additive-only: bump `format_version` only on backward-incompatible shape changes. New `data` fields don't bump; renames/removals do. The `request` field is additive (omitempty) and does NOT bump `format_version`.

**Compose envelope (`pulse api compose --json`).** Since the v1.1 lift `data` is a `ComposedResponse` object — not the legacy `[]*Response` array:

```json
{
  "format_version": "1.1",
  "data": {
    "responses": [ /* one Response per ComposedRequest.Requests slot, in input order */ ],
    "overlays":  [ /* one OverlayLayer per ComposedRequest.Overlays spec; omitted when no Compose overlays */ ]
  },
  "errors": [],
  "warnings": []
}
```

Streaming (`--stream`) bypasses the envelope and emits per-row `{"index", "row"}` NDJSON; Compose overlays surface only at terminal flush in non-streaming mode (see `skills/streaming-and-watching.md`).

### Response.Components

Every `Response` carries an optional `Components *ResponseComponents` (additive `omitempty`; `format_version` stays `"1.1"`). Mirrors the request shape:

- `Aggregations []AggregationComponents` — one entry per aggregator slot; universal floor `{n, n_null}` + operator-specific `Operator map[string]any` keyed by the manifest schema.
- `Groupers []GrouperComponents` — universal floor `{total_n, n_null}` + operator-specific bucket layout.
- `Crosstab *CrosstabComponents` — `CellCounts[r][c]`, `CellComponents[r][c]`, row/column/grand-total margin counterparts, axis-key components. Mirrors `MatrixPayload` coordinate-for-coordinate. Plus, when the request declared `crosstab.margin_aggregations`, the AUXILIARY margin figures: `row_margin_aggregations[r]` / `column_margin_aggregations[c]` / `grand_total_aggregations`, one map per margin slot keyed by each auxiliary's effective label, each entry a `types.MarginAggregationFigure{value, present, components}`. `components` is the floor `{n, n_null}` over the ADMITTED records merged with that operator's own `ComponentSchema` keys, so an `AGG_DISTINCT_SUM` auxiliary's `distinct_count` is reachable PER MARGIN SLOT beside the scalar sum — the whole reason two rendered sample-size rows cost one scan rather than two. They sit BESIDE `row_margin_components` and never inside it: that describes the CELL aggregator's own margin, on a different admission, and merging the key sets would put two differently-based figures under one roof with nothing saying so. **THE ADMISSION RULE IS THE LEAST GUESSABLE PROPERTY ON THIS SURFACE, so it is stated here rather than only where it is implemented: a record contributes to an auxiliary margin ONLY IF IT CONTRIBUTED TO A CELL.** Two exclusions follow and they are the whole difference — a record whose CELL FIELD IS NULL, and a record whose AXIS KEY A GROUPER `Include` EXCLUDED — while the cell's own margins beside it still count both, because they count every filter-passing record routed to that axis slot. That is deliberate, not an inconsistency to reconcile: an auxiliary exists to be a base the cells beside it divide into, so it has to see the same records they did, and a cohort-wide base would silently answer a different question. There is no knob. Getting it wrong is SILENT — every number still renders, correctly formatted and plausible, and only the base is wrong. **`present` is load-bearing and is NOT a zero value** — a slot that admitted no record carries `present: false` and no `value` key at all, because an aggregator over an empty set has no defined output and a fabricated `0` is indistinguishable on the wire from a real one; its `components` still carry the floor, whose `n = 0` is a true statement about the slot. All three keys are `omitempty` and additionally ride the DISPLAY flag (`margins.rows` / `.columns` / `.grand`), matching the emission rule the cell's own margin counts and components already follow, so a margin computed only as a normalize denominator stays off the wire on both arms. **Allocation and emission ask DIFFERENT questions and the gap between them is warned rather than closed**: both execution paths allocate auxiliary accumulators on `NeedsRowMargin` / `NeedsColumnMargin` / `NeedsGrandMargin` (display OR normalize), so the normalize-only shape accumulates every auxiliary and then emits not one of them. `CrosstabSpec.MarginAggregationsObserved` — the predicate behind the `PULSE_CROSSTAB_MARGIN_AGG_UNOBSERVED` predict warning — therefore reads the DISPLAY flags directly, and does NOT go through the `Needs*Margin` trio it was first written on: those answer the cell's question ("is this margin required"), and answering it here left exactly one shape (`margins` all false + `normalize=row|column|total` + a declared auxiliary) both unwarned AND paid for. An auxiliary is never a denominator, so a normalize direction is not a landing site. Keep the predicate and this emission gate stating the one rule; they are two sites, and drift shows up as a request that quietly does the work and returns none of it. A request declaring no auxiliary emits none of the three and is byte-identical to the pre-slot wire form (`TestCrosstab_MarginAggregationsInertAtRequestSurface`, narrowed rather than deleted at E2-S5 to assert exactly that half). `format_version` does NOT move.
- `Filterers []FiltererComponents` — uniform `{n_in, n_out, n_null_input}` across all 11 filterers.
- `Run *RunComponents` — `total_records`, `filtered_records`, `null_records`, `shard_count`, `partial_cohort_reason`. Coexists with `Response.Metadata`: `Metadata` keeps non-numerical run facts (cohort filename); `Run` carries the typed counters.

Per-operator schemas live in `descriptor.Manifest.ComponentsSchemas.{Aggregators,Groupers,Filterers}`. Mergeability axis per operator: `Mergeable` / `Partial` / `None` (`types.ComponentsMergeability`). Streaming chunks emit running state for mergeable; non-mergeable surface only on terminal flush.

**Opt-out.** `pulse.Options.DisableComponents bool` (engine-level default) and `types.Request.DisableComponents *bool` (per-request override, `nil` inherits engine). When the effective decision is "disabled", `Response.Components` stays `nil` and the wire form is byte-identical to the pre-Components baseline — `format_version` is NOT bumped. The gate sits at each execution path's emission block, so the MetaAggregator.Components / MetaGrouper.Components construction work is skipped, not built then discarded. CLI surface: `--no-components` on `pulse api process` / `process-chain` / `compose`. ProcessStream's `.Components()` returns `nil` when disabled. Compose: each `ComposedRequest.Requests[i]` carries its own per-request override; engine flag applies across the batch. MCP tools do not surface the knob (matches `DisableDefaults` / `EchoRequest` precedent).

**Compose surface (v1.1).** `ComposedResponse.Responses[i].Components` carries the per-slot block exactly as it does for a buffered `Process` call — the Compose-overlay fold treats per-slot Components as read-only. Diagnostics from the Compose-host overlay fold (cohesion failures, missing host coordinates, panel-target overflow) ride a sibling per-layer slot `ComposedResponse.Overlays[i].Warnings []OverlayWarning`; the slot is `omitempty` so overlay-free Compose responses stay byte-identical to the v1.0 wire shape (`TestComposedResponse_OverlayFreeByteIdentical`). The same per-layer `Warnings` slot is shared with the CHAIN-host barrier. See `skills/overlay-system.md` (Per-layer warnings).

Full contract: `skills/response-components.md`.

### Payload JSON Schema

`descriptor.BuildPayloadSchema()` returns the formal, deterministic JSON Schema (draft 2020-12) for every public payload — the request envelopes (`#/$defs/Request`, `ComposedRequest`, `ChainRequest`, `FacetRequest`, `SampleRequest`), the result shapes (`Response`, `ComposedResponse`, `ChainResponse`, `FacetResult`), and the universal output `Envelope` (its `data` slot is intentionally open — it wraps any operation). Generated three ways so it cannot drift: reflection over the `types` structs, registry-injected enums (the operator/overlay-kind/regression discriminants pull from `types.All*Types()` / `AllOverlayKinds()` / `AllRegressionTypes()`), and hand-tuned strict unions (`OverlayRef` at-most-one-arm via `maxProperties`, `OverlayPayload` shape-discriminated via `allOf`/`if`-`then`). v1 boundaries: operator `params` (`json.RawMessage`) stay an open object (no central per-operator input-param source) and the small closed mode enums (`OverlayScope`/`OverlayShape`/`CrosstabNormalize`/…) stay plain strings (no registry helper). Golden at `descriptor/testdata/payload-schema.json`; `$id` version held equal to the envelope `format_version`. Reachable three ways: `pulse schema` (raw, not envelope-wrapped), the `pulse://schema` MCP resource, and the published file at `https://frankbardon.github.io/pulse/payload-schema.json` (copied into `docs/book/` by the docs workflow, hash line stripped). Full prose: `docs/src/contract/payload-schema.md`.

- **Crosstab** (`Request.Crosstab`, `Response.Crosstab`) — composed row×column grid; margins recompute from raw rows; `normalize_level` / `normalize_within` compose. `AggregationType.MarginReducibility` classifies each cell aggregator into FOUR classes — `summable` / `mean_reducible` / `independent` / `recompute` — surfaced as `crosstab.*_aggregators` in the manifest. `independent` (`AGG_DISTINCT_COUNT`, `AGG_DISTINCT_SUM`) means the operator keeps its OWN row/column/grand accumulator: the margin is the union across cells, never their sum, and is exact after one pass — so the fused gate ADMITS it. Re-labelling those `recompute` because "a distinct count is not a sum of cells" changes no number and silently costs fusion. `CrosstabSpec.MarginAggregations` (`margin_aggregations`, additive + `omitempty`) carries AUXILIARY aggregations evaluated into the row/column/grand margin accumulators ONLY, never into a cell — `Cell` is a single `*Aggregation`, so this is how a second figure (canonically an unweighted respondent base beside a weighted metric) rides one request instead of a whole second scan. Effective labels (`Label`, else `TYPE_field`) must be unique across the slot AND distinct from `CellLabel`, because margin components are keyed by label. Structural detection is SHARED — `types.CrosstabSpec.MarginAggregationFaults` is called by both `processing.validateCrosstabSpec` and `descriptor.validateCrosstab`, so predict and execution cannot drift on WHICH specs they refuse; only the coded rendering differs. An auxiliary observes the SAME record admission as the cell aggregator (a record contributes only if it contributed to a cell) — deliberately unlike the cell's own margins, and deliberately not configurable. BOTH execution arms implement it and they must AGREE: dispatch picks fused or buffered on request SHAPE and nothing in `Response` reports which ran, so an auxiliary present on one arm only moves a sample-size figure for reasons a caller cannot see or ask about — and `AGG_WELFORD` / `AGG_MEDIAN` force buffered by construction, which is the arm two BERA stat-test families land on. The buffered half is `processing.(*Processor).computeAuxMargins` (`processing/crosstab_margin_agg.go`): it resolves each axis's membership ONCE into pointer sets and narrows each margin slot's own routed bucket, deliberately NOT walking the `(rkey, ckey)` cell buckets — those are admitted by construction but would fold a record into a ROW auxiliary once per COLUMN it landed in, M times under a `GROUP_SET_PER_ELEMENT` fan-out, which is precisely the axis this slot exists to serve and the one shape where the two arms could silently disagree. A slot admitting no record carries no figure on either arm, never a fabricated 0. `TestCrosstab_BufferedAuxMarginMatchesFused` drives one request down both. The figures surface on `Response.Components.Crosstab` as `row_margin_aggregations` / `column_margin_aggregations` / `grand_total_aggregations` — see the `Response.Components` section above for the shape, the presence semantics and the display-flag gate, and `TestCrosstabAuxMargin_WireFiguresAgreeAcrossPaths` for the cross-arm byte comparison at that surface. See `skills/crosstab-guide.md`.
- **Fused crosstab** (`processing.CanFuseCrosstab`, `processing.StreamableGrouper.KeyFor`, `processing.MultiKeyStreamingGrouper.KeysForRow`) — in-decode streaming alternative; ~30–47% faster on benches, and `peak-heap-MB` 8.8× / 18.6× / 20.8× better than buffered at 25k / 100k / 400k rows. **Quote peak heap, never `B/op`** — `B/op` is cumulative bytes allocated, cannot see retention, and understates the win by ~20×; fused `allocs/op` is deliberately HIGHER. Axis groupers may implement EITHER per-record keying interface, so `GROUP_SET_PER_ELEMENT` fan-out axes fuse at any position, on either or both axes; `GROUP_QUANTILE` implements neither and is the only grouper forcing buffered. `Request.Overlays` does NOT force buffered: `RunCrosstabFused` folds layers after `state.Finalize()` through the same `applyOverlaysToResponse` hook the buffered exit calls, byte-identical across arms, and `types.OverlayStreamability` stays all-`false` because a post-`Finalize` fold is not an in-pass computation. The surviving reason an overlay-carrying crosstab may still buffer is the cell-aggregator arm — `AGG_WELFORD` is non-mergeable, so `OVERLAY_PAIRWISE_WELCH_T` / `OVERLAY_PAIRWISE_TWO_MEANS_Z` stay buffered while `OVERLAY_PAIRWISE_PROP_Z` over `AGG_WEIGHTED_MEAN` fuses. Fan-out margins are non-additive on BOTH arms (a 3-label record counts 3× across row margins, once in the grand margin) — deliberate. `CrosstabSpec.MarginAggregations` gets the SAME two gate checks the cell gets — mergeable (an auxiliary rides the same per-record `UpdateRow` walk, so it must be online) and non-decimal — and declining sends the request to buffered rather than DROPPING the auxiliary, which would return a margin with the requested figure silently missing. Its `MarginReducibility` is deliberately NOT consulted: that classification answers "can this aggregator's margin be derived from its CELLS", which an auxiliary does not have — both paths give it its own row/column/grand accumulator fed record by record, so every auxiliary is `independent` in role whatever its declared class, and requiring a class would decline fusion for a request the fused walk computes exactly. The fused walk accumulates auxiliaries in `rowMarginAux` / `colMarginAux` / `grandMarginAux` beside the cell's own margin slices, under the admission rule above — a record reaches an auxiliary ONLY if it reached a cell, so a null cell field and an `Include`-excluded axis key are both absent from it while the cell's own margins still count them. Getting that wrong is SILENT: every number still renders, the base is merely cohort-wide instead of metric-scoped. Slots allocate only for the margins the spec asks for, and nothing at all when the slot is absent. See `skills/crosstab-guide.md` (Fused mergeable path) + `skills/grouper-design.md` + `.claude/reference/execution-modes.md`.
- **Facet endpoints** — simple (`pulse.Facet`) + rich (`pulse.FacetSchema`); four FACET-host overlay kinds (`OVERLAY_INDEX_VS_POP` / `OVERLAY_ZSCORE_VS_POP` / `OVERLAY_CHISQ_VS_POP` / `OVERLAY_KS_VS_POP`) ride `FacetRequest.Overlays`. FACET-host wiring is the FacetSchema-buffered-exit hook at `service.applyFacetOverlays`. See `skills/facet-design.md`.
- **Point lookup** (`pulse.Lookup`, `pulse api lookup`) — O(1) key-exact row addressing against a prebuilt sidecar index (`pulse.BuildIndex` / `pulse index build`; `pulse.VerifyIndex` / `ListIndexes` / `DropIndex` manage it). Single-file cohorts only; equality-only, full-key required. See "Byte-layout invariants" above (Sidecar point-lookup index) + `skills/cohort-schema-design.md` + `skills/tool-lookup.md`.
- **Overlays** (`Request.Overlays`, `Response.Overlays`) — additive post-result decorations keyed to host coordinates; never mutate base payload. Level / Within prefix composition, SERIES-host fold, FACET-host wiring, CHAIN-host barrier, FORMULA kind. Stat-test parity family (`OVERLAY_T_CELL` / `OVERLAY_T_VS_REF` Welch upgrade + `OVERLAY_Z_CELL` / `OVERLAY_Z_VS_REF`) reads `{n, mean, variance}` from `Response.Components.Crosstab.CellComponents[r][c]` (populated by `AGG_WELFORD` via the `MetaAggregator` path) and computes p-values byte-equal to the standalone `TEST_WELCH` / `TEST_Z_TWO_SAMPLE` row tests over the same inputs. The legacy `processing.WelfordTriple` smuggle through `MatrixCell.Value` is removed; `MatrixCell.Value` for `AGG_WELFORD` cells now carries the scalar mean per `Aggregate()`. Additive contract preserved — when no `CellComponents` triple is present, the handler falls back to `Params`-supplied mean/variance/N. See `skills/overlay-system.md` for the migration.

## Build / Env

`make build` (default), `make test`, `make fmt`, `make vet`, `make lint`, `make cover`, `make clean`, `make docs`, `make docs-serve`, `make docs-clean`. A `.env` at repo root auto-loaded.

**Environment variables:**

- `PULSE_DATA_DIR` — base directory for `.pulse` cohort files. Used by `fs.Default()` when no explicit `DataDir` or `afero.Fs` provided. Only required env var. Bypass via `pulse.Options{DataDir}` or `pulse.Options{FS}`.
- `PULSE_IMPORTS_DIR` — managed-imports subdir under fs root. Defaults to `imports`. Honoured by `imports.Manager`. `pulse.Options{ImportsDir}` overrides.
- `PULSE_IMPORT_TTL` — default TTL for managed imports. Go duration (`24h`, `30m`), day form (`7d`, `30d`), or `pin`. Defaults to `7d`. `pulse.Options{ImportTTL}` overrides.
- `PULSE_LABEL_TABLES_DIR` — directory of JSON files auto-loaded as `LabelTables` at `pulse.New` time. Each `*.json` becomes a registered label table keyed by its filename. Honoured when `pulse.Options{LabelTablesDir}` is empty. **Pulse's own sidecars are excluded by suffix before any parse attempt** — `spss.SidecarSuffix` (`.spss.json`) and `imports.SidecarSuffix` (`.meta.json`), the list at `isPulseSidecarName` in `sidecar_names.go` — so pointing this at a directory that also holds cohorts no longer fails `pulse.New` on a file Pulse itself wrote, and a skipped sidecar registers no table under any name. That is an explicit exclusion of known Pulse artefacts, **not** tolerance of unparseable JSON: any OTHER `*.json` that fails to parse is still a hard `pulse.New` error naming the offending path, because a typo'd label table must not silently become a table that is not there. The `.idx` sidecar index needs no entry — it is not `*.json`. `PULSE_RANGE_TABLES_DIR` carries the identical exclusion via the same helper; `PULSE_TEMPLATES_DIR` walks the same shape and does **not** yet carry it (its recursive walk and `Summary.Broken` visibility lifecycle make the right treatment a separate design call).
- `PULSE_RANGE_TABLES_DIR` — directory of JSON files auto-loaded as `RangeTables` (named labeled-date-range sets) at `pulse.New` time. Each `*.json` is a bare array of `{label,start,end}` objects (or a wrapped `{"description":...,"ranges":[...]}`); the filename minus `.json` becomes the registered table name. Registered ranges are validated via the shared range-compilation pass (`PULSE_RANGE_*` codes). Honoured when `pulse.Options{RangeTablesDir}` is empty; a name declared both programmatically and on disk is a hard error. **Pulse's own sidecars are excluded by suffix before any parse attempt** — the same `isPulseSidecarName` list `PULSE_LABEL_TABLES_DIR` uses, with the same boundary: an exclusion of known Pulse artefacts, not tolerance of unparseable JSON, so any other malformed `*.json` still hard-fails `pulse.New` naming its path.
- `PULSE_TEMPLATES_DIR` — one or more directory roots scanned for request templates at `pulse.New` time, separated by `os.PathListSeparator` (`:` on Unix, `;` on Windows) in precedence order, PATH-style. Every `*.json` file beneath a root is a template; its name is its path relative to its own root minus `.json`, forward-slash separated (`<root>/finance/revenue.json` → `finance/revenue`). The first root wins — the same name under a later root is shadowed, not rejected. A root that does not exist is skipped; a root that exists but is not a directory is a `DATA_FILE` error. The store is built eagerly, so a malformed template fails `pulse.New` with the offending path named. The roots stay live afterwards: a lookup whose cached snapshot has aged past the store's 1s rescan interval re-walks them, so added / changed / deleted files are picked up without a restart, and a file is re-parsed only when its size or mtime moved. `Pulse.ReloadTemplates()` forces that walk immediately (no-op returning nil when no directories are configured) and is the deterministic path. **Post-startup breakage degrades per file, not globally:** a template that parsed once and whose file later becomes malformed keeps serving its last-good parse, and `ReloadTemplates()` returns `nil` for it — a per-file document fault (or an unreadable file) must not mask an otherwise-healthy catalog. Brokenness is visible instead on `template.Summary.Broken` + `.Error` from `Pulse.ListTemplates()` (both `omitempty`, so a healthy listing is byte-identical to the pre-E3-S2 shape). A file malformed on its FIRST appearance has no last-good parse: `GetTemplate` / `RenderTemplate` return `PULSE_TEMPLATE_INVALID` naming the path, and it lists as broken with an empty `Target` so it never looks fetchable. Repairing the file clears the state on the next rescan. Whole-walk faults (a root that exists but is not a directory) are still returned by `ReloadTemplates()` and leave the previous index entirely in place. Honoured when `pulse.Options{TemplateDirs}` is empty; unset with no `TemplateDirs` builds no store at all and template lookups return `PULSE_TEMPLATE_NOT_FOUND`.

**Concurrency knobs (`pulse.Options`):**

- `ShardWorkers` (default `0` ⇒ `NumCPU`): bounded per-shard worker pool for shard archives. Explicit `1` forces serial.
- `DecodeWorkers` (default `0` ⇒ `NumCPU`): bounded per-segment pool for single-file cohorts above `parallelDecodeRecordThreshold` (100K records). Negative values rejected at `pulse.New()`. Orthogonal to `ShardWorkers`.

**Overlay knobs (`OverlaySpec.Options`):**

- `DictPrefixFast bool` — Compose multi-slot overlay schema-match via byte-equal dictionary prefix probe. Requires embedder to verify prefix-equal dicts. Default `false`.
- `MaxPanelTargets int` — caps Targets on multi-reference Compose overlays (`OVERLAY_PROP_Z_PANEL`, `OVERLAY_PANEL_INDEX_VS_REF`); overflow → `PULSE_OVERLAY_PANEL_TARGETS_OVER_CAP`. Default `16`.

Hermetic testing: `fs.NewMemMap()` returns a `Config` backed by `afero.NewMemMapFs()`. No disk I/O.

## Extension Points

`pulse.Options.Extensions` is the public surface for embedders injecting domain operators or expression-runtime extensions. Eight operator categories plus expr functions and lookup tables. Registration at `pulse.New()` time.

- **Naming policy:** `^(AGG|ATTR|FILTER|GROUP|WIN|FEAT|TEST|SYNTH)_[A-Z][A-Z0-9]+_[A-Z](?:[A-Z0-9_]*[A-Z0-9])?$`. Reserved namespaces: `BUILTIN`, `STANDARD`, `CORE`, `PULSE`. Collision with built-in rejected.
- **Probe-validation:** engine constructs each factory once against minimal synthetic schema. Streamable-flagged registrations must return streaming interface; mismatch → `PULSE_EXTENSION_STREAMABLE_MISMATCH`. Factory panics → `PULSE_EXTENSION_FACTORY_PANIC`.
- **Expression environment:** `ExprFunctions` merged into expr-lang env (`ATTR_FORMULA`, `FILTER_EXPRESSION`). `LookupTables` reachable via `lookup(table, keys...)`. Unknown → `PULSE_LOOKUP_TABLE_UNKNOWN`. Missing key → `PULSE_LOOKUP_MISS`.
- **Auxiliary tables:** three named-table kinds ride `Extensions` alongside operators — `LookupTables` (numeric `key→float64` for the expr env), `LabelTables` (output-time `key→label`, referenced from a per-request `LabelBinding.Table`; dir-loadable via `PULSE_LABEL_TABLES_DIR`), and `RangeTables` (ordered `{label,start,end}` sets a `GROUP_DATE_RANGES` / `FILTER_DATE_RANGES` references by name; dir-loadable via `PULSE_RANGE_TABLES_DIR`; validated at `pulse.New` via the shared range-compilation pass). All three project into the manifest `extensions` block (`lookup_tables` / `label_tables` / `range_tables`).
- **Manifest visibility:** root manifest carries `extensions` block; schema-bound MCP tools include custom names in per-category enums.
- **Snapshot pattern:** `descriptor.ExtensionsSnapshot` — read-only projection passed into `descriptor.PredictOptions.Extensions` and `mcp.BindSessionToolsWithExtensions`. Built by `pulse.New` via `buildExtensionsSnapshot`. Descriptor stays free of `service/` and `processing/` imports.
- **FieldInputs hook:** every operator registration accepts optional `FieldInputs FieldInputsFunc`. Used by `processing.NeededFields` for projection. Absent → retained set widens to `*` (full-decode fallback).

Surface: `extensions.go`, `extensions_validate.go`, `extensions_probe.go`, `extensions_runtime.go`, `extensions_snapshot.go`. Runtime overlay: `processing/extensions.go`. Full recipe: `docs/src/internals/extension-points.md`.

## Request templating

Stored parameterised JSON that renders into a **validated typed request**. `template/` is the whole implementation (import ceiling: stdlib + `types` + `errors` only — never `descriptor/`, `processing/`, `service/`; gated by `TestTemplatePackage_ImportBoundary`). Facade: `ListTemplates`, `GetTemplate`, `RenderTemplate`, `RenderTemplateRequest`, `ReloadTemplates`. **No CLI leaf, no MCP tool** — library/embedding surface only.

**Not expr-lang.** `$var` / `{{}}` / `$when` are *request-authoring* parameters substituted **before** decode; `ATTR_FORMULA` / `FILTER_EXPRESSION` are expr-lang over *row fields* at execution time. No interop by design — a formula cannot see a template variable, and a formula string in a body is inert text to the renderer.

**File wrapper.** `{"name"?, "description"?, "target", "variables"[], "body"}`; **unknown top-level keys rejected** (a typo'd `"varaibles"` yielding zero variables is the silent failure this feature exists to kill). `target` ∈ `request | composed | chain | facet | sample` (lowercase) selects the strict-decode root — one of the five `types` request roots — required, never inferred. `name` derives from the file path (path relative to its own root, minus `.json`, forward-slash separated); a `name` key disagreeing with the path is rejected. `body` is a non-empty object, deliberately **not runnable as-is**.

**Substitution — three forms, no expression language.** (1) Slot marker `{"$var":"bucket"}` — a marker **iff** `$var` is the only key and its value a non-empty string; replaced whole and **type-preserving** (`{"interval":{"$var":"bucket"}}` → `{"interval":10}`, never `"10"`). `{"$var":"x","other":1}` is literal data; substituted values are spliced as data and never re-walked. (2) String sugar `"{{name}}"` — inside a **string value** only, `{{ name }}` tolerated, `{{{{` escapes a literal `{{`; `list`/`period` have no text form → `PULSE_TEMPLATE_VAR_TYPE`; `{{` in an object **key** is rejected at validation. (3) Guard `{"$when":"segs",…}` — block survives iff the variable resolved; key stripped either way. **Presence, not truthiness**: supplied `""`/`[]`/`0`/`false` KEEPS the block; it drops only when unsupplied AND undefaulted. Guards evaluate **before** descent, so markers inside a dropped block never raise. Array drops compact the slice (a `null` hole would decode to a nil operator slot); root-level `$when` errors.

**Nine variable types** (`template.AllVarTypes()`): `string`, `number`, `integer` (`1.0` yes, `1.5` no), `boolean`, `field` (a string today; cohort binding can layer on later without a wire change), `enum` (+`values`, exact + case-sensitive), `list` (+`items`, scalar element types only — lists do not nest), `date` (only `YYYY-MM-DD`, a strict subset of `encoding.DateFormats`; `03/04/2024` is ambiguous), `period` (exactly one of `ranges` XOR `table`, mirroring the `GROUP_DATE_RANGES` / `FILTER_DATE_RANGES` `Params` shape; unknown keys in it or in a `{label,start,end}` range rejected). The six scalars (`string`/`number`/`integer`/`boolean`/`field`/`date`) are the legal `items` values. Per-declaration slots: `required` (legal together with `default` — the default resolves it, so it can never go missing), `default` (raw JSON, so integer fidelity survives; explicit `null` = no default), `description`.

**Directory precedence.** `Options.TemplateDirs []string`, else `PULSE_TEMPLATES_DIR` split on `os.PathListSeparator` — the programmatic option wins outright and suppresses the env var entirely. Roots are an **ordered precedence list; first root wins**. A same-named template under a later root is **shadowed, not rejected**, and the losers land on the winner's `Summary.Shadows` rather than being discarded (shadowed entries get no summary of their own — a listing whose entries cannot all be fetched would be a trap). Blank root → skipped; missing root → skipped; root that exists but is a **regular file** → error naming the path. **Filesystem faults are `DATA_FILE`**, deliberately outside the `PULSE_TEMPLATE_*` family. Config-dir loading goes through `os`, not afero — same sanctioned exception as `label_loader.go` / `range_loader.go`.

**Hot-reload lifecycle — phase split is the contract.** A lookup whose snapshot has aged past the store's 1s rescan interval (package constant, deliberately not an `Option`) re-walks the roots; a file is re-parsed only when size or mtime moved. `ReloadTemplates()` forces the walk now — the deterministic path for a deploy step that writes then renders.

| Phase | Malformed file does | Why |
|---|---|---|
| At `pulse.New()` | **hard-fails startup**, path named | a broken document at boot is a deploy error the operator must see immediately |
| After startup, parsed before | **serves its last-good parse**; `ListTemplates` marks `Summary.Broken` + `.Error` | a half-written file is the normal transient state of in-place editing; killing the catalog is worse than slightly stale content |
| After startup, never parsed | listed to be SEEN (empty `Target`), not fetchable; `GetTemplate`/`RenderTemplate` → `PULSE_TEMPLATE_INVALID` naming the path | no last-good to fall back to |

`ReloadTemplates()` returns **nil** for a broken file — an error there would mask every otherwise-healthy template. A root that is not a directory **is** still a hard error (misconfiguration, not a transient edit) and a failed walk leaves the previous index entirely in place. Repair clears the state on the next rescan. `Summary.Broken`/`.Error` are both `omitempty`, so healthy listings stay byte-identical to the pre-E3 wire shape.

**Errors — nine `PULSE_TEMPLATE_*` codes, chosen by provenance not detection time.** A bad **declared default** is an author error → `_INVALID` (checked semantically at declaration: enum membership, date parse, period XOR — that is what keeps the fail-fast-at-`pulse.New()` promise real); a bad **caller value** → `_VAR_TYPE` / `_VAR_ENUM`. Same split on names: `$var`/`{{}}`/`$when` naming an **undeclared** variable is an author error caught at validation (`_INVALID`); a **declared but unresolved** reference is render-time `_UNRESOLVED`. Full family: `_NOT_FOUND`, `_INVALID`, `_TARGET_UNKNOWN`, `_VAR_MISSING`, `_VAR_UNKNOWN`, `_VAR_TYPE`, `_VAR_ENUM`, `_UNRESOLVED`, `_RENDER_INVALID`. **`_TARGET_UNKNOWN` currently carries two meanings** — an absent/unrecognised `target`, AND `RenderTemplateRequest` called on a template declaring a different (valid) target; the second case also carries `expected_target` in details. Details keys: `errors.DetailTemplate` (`"template"`) + `errors.DetailVariable` (`"variable"`); `pulse errors lookup CODE` is authoritative.

**Render never opens a cohort.** A rendering template is well-formed against the request *shape* only; field existence, type compatibility, operator applicability and streamability stay `Predict`'s job. Strict decode is harsher than the rest of Pulse — a body pasted from an `examples/` file with its `_meta` block attached fails `_RENDER_INVALID`. `Rendered.JSON` is retained alongside the typed value on purpose: re-marshaling the typed request would NOT reproduce it, because the request structs are dense with `omitempty` and any slot that rendered to an explicit zero would vanish on a round trip — echo `Rendered.JSON`, never a re-marshal.

**`format_version` stays `"1.1"`.** Nothing payload-reachable changed: `Options.TemplateDirs` is not a payload type, and `template.Template` / `Variable` / `Summary` / `Rendered` live in `template/`, not `types/`, so they are not reachable from `descriptor.BuildPayloadSchema`. `descriptor/testdata/payload-schema.json` is untouched by templating; only the manifest golden moved, and only for the nine new error codes.

Env var: `PULSE_TEMPLATES_DIR` — see "Build / Env". Detail: `skills/request-templating.md` + `docs/src/library/request-templating.md`.

## Synthetic data: conditional pair capture and per-numeric models

`pulse profile create --conditional` (`synth.ProfileOptions.IncludeConditional`) adds an additive `conditional` section to the profile JSON: for numeric-numeric field pairs, a row-aligned `{a, b, rho, n}` capture where `n` is the true co-occurrence count (both fields non-null on the same row) — more accurate than the plain `--include-correlations` `pairwise` stats, whose independently-capped per-field reservoirs can drift out of alignment once either field has nulls. `SpecFromProfile` prefers `conditional.numeric_pairs` over `pairwise` when both are present; its absence (including every profile document from before this flag existed) is unaffected — `SpecFromProfile` falls back to `pairwise` exactly as before, so no existing profile document is invalidated.

**Thin-pair warning (generic mechanism).** A pair whose supporting observation count `n` falls below **`synth.MinPairObservations` (30)** is never refused — it still ships — but appends a warning to `Profile.Warnings` naming the pair. This mechanism (`thinPairWarning` in `synth/profile.go`) is deliberately generic across pair *kind*, not numeric-specific: later epics reuse the same threshold and helper for categorical and `set_*` pairs rather than inventing their own. It is now generic across *subject* as well — `thinPairWarning` is a wrapper over `thinSupportWarning(subject, a, b, n, threshold, consequence)`, which thin-MODEL-LEVEL shrinkage also calls so every thin-support line in `Profile.Warnings` reads the same shape whatever produced it. Every pre-existing caller's text is byte-identical.

**Per-numeric linear models (`models` profile section).** `pulse profile create --fit-models` (`synth.ProfileOptions.FitModels`) adds a second additive, `omitempty` section to the profile JSON: one least-squares linear model per numeric field, that field regressed on the categorical **levels** and `set_*` **options** predictor selection admitted, through `processing/regression`'s streaming OLS engine. The cohort is read ONCE (`TestProfileModels_RidesTheExistingScan` counts the bytes), but the fits do NOT run per row: the scan's only job is retaining a bounded Algorithm-R row snapshot (`modelResidualCap`, 10,000), and selection, fitting and residuals all run over that snapshot afterwards. That ordering is forced — both halves of the narrowing below are measured, and a frequency ranking does not exist until rows have been seen. Consequence on the wire: `n_obs` is the fit's own support WITHIN the snapshot, not the cohort's row count (`Profile.RowCount` is that). Document shape per entry: `{field, intercept, predictors, references, n_obs, r2, residual_std, shrinkage_alpha}`, where `predictors[]` is `{kind, field, level, coefficient}` and `shrinkage_alpha` is `omitempty` (absent ⇔ the fit was unpenalized OLS — see thin-level shrinkage below). **A coefficient is addressed by `(field, level)`** — the solver's internal length-prefixed design-column name is `json:"-"` and never reaches the document, because serialising it would freeze that encoding into the file format. `references[]` names the level each categorical DROPPED into the intercept (reference level = dictionary ID 0 today), so a reader holding *k−1* of *k* levels does not have to guess which arm is the zero baseline; a set-only model carries no `references` key, since a multi-select is not a partition. The row-aligned **fitted residuals** (`FieldModel.Residuals` / `ResidualPresent`, capped at `modelResidualCap`) are also `json:"-"` — thousands of numbers per field whose only consumer runs in the same process as the capture, so they are reachable through `synth.Profile.FittedModels()` and are ABSENT from a re-read document. A capture without the flag emits no `models` key at all and is byte-identical to a pre-flag document; a capture with it moves nothing but that one key (`TestProfile_ModelsSection_IsPurelyAdditive`). A model whose fit would serialise a non-finite float is dropped with a warning rather than failing the marshal of the whole document.

**Predictor selection is automatic, absolute, and has no user-facing override.** Two mechanisms in a fixed order, both in `synth/profile_models_select.go`. (1) **Top-K collapse on dummy expansion** — structural. A candidate categorical contributes one column per top-`ProfileOptions.TopK` level by frequency plus ONE catch-all column carried on the wire as an ordinary level named `"other"` (`otherCategoryLabel`), the same collapse `Categorical.Top` and `conditional.categorical_pairs` already apply, so a document's collapsed buckets mean one thing throughout it. This is what makes the flag work at all rather than a refinement of it: on the motivating 381,324-row cohort the unbounded expansion of 16 categoricals was 2,420 columns (`brand` alone 1,906 levels, 79% of the width) and all 105 numeric targets were skipped as too wide — `--fit-models` produced NOTHING on real data. Collapsed, the same cohort is under 200 columns before any statistical criterion runs. The catch-all is never the reference level. (2) **Variance-explained floor** — statistical, applied to the collapsed candidate set. A candidate FIELD enters a target's model iff the ADJUSTED share of that target's total sum of squares lying between the candidate's groups reaches `synth.minVarianceExplained` (**0.01**, Cohen's small-effect boundary). It is a package constant tuned in code, deliberately not a `ProfileOptions` field — `TestModelSelection_NoUserFacingOverride` pins that no capture flag but `TopK` moves an admission. **The criterion is deliberately NOT statistical significance**: at 381k rows every candidate is significant, including ones explaining a thousandth of the variance, so a p-value gate admits everything and is "all predictors enter" in disguise — and silently, since every coefficient it admits is real, merely negligible. An absolute floor is n-invariant by construction and `TestModelSelection_AdmissionInvariantToRowCount` is the build-failing guard on that. Adjusted rather than raw η² so a 33-group collapsed field is not admitted for its width alone. Scoring is MARGINAL (one candidate at a time against the raw target, never against another's residual): two collinear candidates — `age` is a banding of `ageExact`, `region` is nested inside `dma` — BOTH clear the floor and both enter. That is an explicit judgement call, since incremental scoring would make the admitted set depend on candidate order; redundancy is resolved by the SOLVER instead, and the score is what makes that possible — a design refused as rank-deficient is refitted with its WEAKEST admitted predictor dropped, up to `maxModelRefitRounds` (4) times, so the candidate surviving a nesting is the one explaining more. Detecting the nesting directly is deliberately not attempted: the dependency that actually bites is LINEAR, not functional (a retained set of exact ages covering a whole age band makes that band's indicator the sum of theirs), so a functional-dependency probe misses it while claiming to have handled it. Measured on the motivating cohort, the refit is the difference between 23 skipped targets and 2. Selection also prunes design columns that are degenerate ON THE ROWS THE FIT ADMITS — selection scores pairwise, the fit deletes listwise, and a level with pairwise support but no listwise rows is an identically-zero column the solver refuses. A single-level candidate (`wave` on a one-wave cohort) has zero between-group variance and is dropped by the same arithmetic rather than by a special case. A target no candidate clears produces a **zero-predictor model** — its own mean plus its own spread, `r2: 0` — warned as `carries no predictors: …` and NEVER as `skipped: …`, because a complete model and a failed capture mean opposite things. `maxModelColumns` (256) is RETAINED but is no longer an operative limit: it is a backstop against a pathological schema, justified by the accumulator being O(p²) per row in arithmetic as well as memory. **Measured end state on the motivating cohort, with thin-level shrinkage in place:** ALL 105 numeric targets get a model (E1 fitted ZERO — every one skipped at 2,420 columns), 55 of them carrying predictors, 113 admitted (field, target) relationships against the predecessor's 86 applied pairs, and ZERO skips — a ridge-augmented Gram is positive-definite, so the two irreducibly-redundant targets now fit with both nested candidates jointly shrunk, and the refit narrowing above applies to UNPENALIZED designs only. The pre-shrinkage figures were 103 modelled / 53 with predictors / 76 relationships / 2 skips; the difference is the shrinkage interaction, not a change to the floor. The floor's sensitivity is tabulated at the constant.

**Thin LEVELS inside an admitted predictor are SHRUNK, never dropped and never refused.** Selection (above) picks predictor FIELDS; this picks how much to trust the individual LEVELS of a field it already admitted, and the two are independent — a categorical can clear the variance floor convincingly while three of its retained levels rest on a handful of rows each. The top-K collapse removed the bulk of that problem (a retained level is one of the field's 32 most frequent) but it bounds RANK, not SUPPORT: the 32nd most common `brand` is still rare, and LISTWISE deletion cuts it again, hardest on the targets with the most nulls — the motivating cohort's three NPS fields admit 1,736 of the 10,000 reservoir rows, and every level in their designs is measured against that. A design column whose listwise support (rows the fit ADMITS, not cohort frequency) falls below `synth.minLevelObservations` (**50**) puts the whole fit on the shipped engine's ridge — `spec.Penalty = "l2"` with `Alpha = minLevelObservations / n_admitted`, never a hand-rolled penalty. `minLevelObservations` is DELIBERATELY its own constant and not `MinPairObservations` (30): that one answers "does this pair have enough co-occurrences for a reconstructed correlation to mean anything", this one answers "does this level have enough rows for a free coefficient to describe the level rather than the sample", and sharing a constant because the numbers are the same order of magnitude would couple two unrelated tunings forever. **The shrinkage SCALES with thinness rather than switching on at the threshold**, which is what makes one global alpha sufficient: the engine adds `n·λ` to every Gram diagonal, so `λ = 50/n` adds exactly 50 pseudo-observations and a level retains `n_j/(n_j + 50)` of its free coefficient — 3 observations keep 6%, 30 keep 38%, 50 keep half, 500 keep 91%. It shrinks toward the field's REFERENCE level, because that is what a dummy coefficient measures, and a thin level collapsing onto the baseline is the conservative reading ("too few rows to say this level differs"). `shrinkage_alpha` rides the document because a shrunk coefficient and a free one are not the same kind of number and nothing else on the wire says which one a reader is holding; `alpha × n_obs` recovers the pseudo-count. Three properties that are invisible in the output and must not be "fixed": (1) inside a penalized fit, well-supported columns move too, by roughly `50/n_j` — bounded and small, but not zero, and no single-alpha ridge can make it zero; (2) it is GATED on a thin column actually being present, so a clean design stays exact OLS (`TestProfileModels_NoThinLevelLeavesTheFitUnpenalized`, and the 1e-6 exact-recovery bar `TestProfileModels_CleanMultiPredictorFit` holds) at the cost of a bounded discontinuity at the boundary; (3) a penalized Gram is positive-definite, so the solver's rank-deficiency REFUSAL — which E2-S1 uses as its redundancy signal — does not fire for a fit carrying a thin level, and collinear predictors are jointly shrunk instead of one being dropped. Warning volume is **doubly bounded**, because thinness is a property of the LEVEL and the naive per-(target, level) emission restates one finding once per model — 477 lines for 89 distinct levels on the motivating cohort, on a warnings slice `--conditional` alone already puts ~2,900 thin-PAIR lines on. Lines are aggregated by (field, level) across targets (reporting the THINNEST support and the model count), then capped at `maxThinLevelWarnings` (20) thinnest-first with one counted `+N further thin model level(s)` summary naming the fix (lower `--top-k`). Implementation: `synth/profile_models_shrink.go`. `format_version` does NOT move — `synth.Profile` is not payload-reachable.

**`models` retires the numeric-target conditional arms, PER TARGET.** For a numeric field that lands a model on the Spec, `SpecFromProfile` leaves that field out of `Spec.CategoricalNumericPairs` / `Spec.SetNumericPairs`. Those arms each RESAMPLE a numeric from one paired field's conditional moments, so on a wide cohort every categorical and every set option claims the same numeric target and all but the first are dropped by `resolveConflicts` — one warning each. An additive model accounts for all of them at once, so the pairs have nothing left to add. A profile-derived spec therefore never makes the claim; a HAND-AUTHORED spec that declares both is arbitrated in `synth/conflict.go`, where a modelled field is PRE-CLAIMED (see the generation paragraph below) and the competing pair is dropped with the ordinary conflict warning naming it. The decision is per-FIELD and was per-DOCUMENT until E2-S1 — a model dropped in translation (an unknown predictor field; the zero-predictor model selection emits for a target nothing explained — a `--fit-shape` target was a drop reason until E4-S1 and is not one now, see the shape-fitted-conditioning paragraph below) warns `model for numeric field %q not applied: …` and KEEPS that field's captured conditional pair. Under the document-wide rule such a field lost the pair as well and was reconstructed from nothing at all — strictly worse than before the flag existed, and the ordinary outcome once selection can legitimately leave a target unmodelled. The mixed-semantics objection the document-wide rule was built on is answered by the spec itself: `Spec.Models` and `Spec.CategoricalNumericPairs` each name their own fields, and `resolveConflicts` pre-claims a modelled target, so no field is ever reached by both. The three NON-numeric-target arms (`CategoricalPairs`, `SetCategoricalPairs`, `SetSetPairs`) are untouched, so `--conditional` + `--fit-models` is a supported combination that keeps both halves. Absent `models`, every arm populates exactly as before — the same silent-fallback shape `conditional.numeric_pairs`-over-`pairwise` already uses, and the reason no existing profile document is invalidated (`TestSpecFromProfile_PreModelsDocumentUnchanged` pins a checked-in pre-change document to a fixed `Spec.Hash()`). `format_version` does NOT move: `synth.Profile` / `synth.Spec` live in `synth/`, not `types/`, so they are unreachable from `descriptor.BuildPayloadSchema` and `descriptor/testdata/payload-schema.json` is untouched. Detail: `skills/synthetic-data.md` (Profile mode) + `docs/src/cli/profile-create.md`.

**Generation: the composed model draw.** A numeric carrying a `Spec.Models` entry is not drawn from its marginal and then overwritten — it is composed in one step at the END of `drawRow` (`synth/model_draw.go`): `value = Q(Φ(μ(row) + σ·z))`, where `μ` is the model's linear prediction (`Intercept` + every fired coefficient) **standardised by the target's own reconstructed marginal moments**, `σ = ResidualStd/std`, `z ~ N(0,1)`, and `Φ`/`Q` are `copula.go`'s own `phi` / `quantileFor` — deliberately reused so a modelled field and a correlated field agree on what "this field's marginal" means. Standardising first is load-bearing: the OLS fit behind `FieldModelSpec` is in RAW data units and `Φ` accepts only a standard-normal argument. **Because `μ` lives on the latent scale, a coefficient shifts the LATENT Gaussian and not the value, and is therefore NON-LINEAR in value space for any non-normal `Q` — it is not "this many points on the scale". That is the single most misreadable property of the whole feature; the rule and its consequences are stated in the shape-fitted paragraph below and must be repeated wherever a coefficient is surfaced.** A model additionally carries MAIN EFFECTS only — one coefficient per (field, level), summed — so it cannot express "brand X matters only in region Y"; a pairwise interaction between two collapsed 33-column fields is 1,089 columns on its own, which is precisely the width problem the top-K collapse exists to solve, and the marginal scoring rule, the wire format and the recovery refit all assume one term per (field, level). **For a plain `normal` target the round trip collapses exactly to `prediction + ResidualStd·z`** (since `Q(p) = mean + std·u` and `Φ⁻¹(Φ(u)) == u`) — the ordinary OLS draw — and routing through `Φ`/`Q` anyway is what lets a hand-authored `uniform`/`lognormal`/`exponential` target keep its own marginal shape while the linear predictor drives it. **A term fires only on an exact match and contributes ZERO otherwise**, which is the dummy-coded reading, not a convenience default: categorical predictors are read against a dropped reference level folded into the intercept, so a level the fit never saw — a value that is new at generation — reads as the reference, and a NULL predictor also contributes zero because listwise deletion means the coefficients never saw such a row. **The top-K catch-all is NOT such a level: it carries its own firing term.** A predictor field wider than `--top-k` contributes one design column per retained level plus one collapsed catch-all, and that catch-all rides the wire as an ordinary `categorical_level` predictor whose `level` is the literal string `"other"` (`otherCategoryLabel`) — the same spelling every other collapsed bucket in a profile document uses, so a consumer applies it exactly as it applies `region=west` and no reader has to learn a fourth `ModelPredictor.Kind`. It is reached at generation because `--conditional`'s categorical-categorical contingency capture collapses out-of-top-K values to that same `"other"` before building its cells and `categoricalPairSampler` resamples straight out of them, while the model stage runs LAST and therefore reads the value the emitted row actually carries; the field's OWN marginal cannot produce it, because `SpecFromProfile` reconstructs a categorical from `FieldProfile.Categorical.Top`, which truncates to the top K and renormalises rather than appending a catch-all bucket. Mapping that column to `ModelPredictorNumeric` instead — which a `default:` arm in `modelPredictorKind` did until E2-S5 — is SILENT and costs the WHOLE model, because `modelSpecFromProfile` refuses a model wholesale on one unusable predictor rather than dropping a term and leaving the survivors read against a baseline that no longer exists: on the motivating cohort that was 105 captured models applied as 20, with a plausible cohort generated either way. Corrected, 55 apply — exactly the 55 capture reports as predictor-carrying, the other 50 being the zero-predictor models E2-S1's per-target rule drops on purpose — and `Spec.ResidualCorrelations` grows from 190 pairs to the full 1,485, since a surviving model is a residual participant. On a 20,000-row generation from that profile, 18,198 rows carry `brand = "other"`, so the catch-all is not a rare arm but the DOMINANT one. `modelPredictorKind` now names every `dummyColumnKind` and `TestModelPredictorKind_CoversEveryDummyColumnKind` pins the enum's cardinality, so a new member fails a test rather than acquiring a confident wrong answer. **Clamping is exactly one clamp, applied once to the final data-scale value**: the model's own `Min`/`Max` (the target's observed bounds, carried on `FieldModelSpec` for this purpose) win, mirroring `categoricalNumericPairSampler`'s precedent for a conditionally-drawn numeric, with the field's own marginal clamp as the fallback when the model declares none — so the model stage and the copula stage cannot disagree about the admissible range. **Ordering is spec-derived, never map-derived:** the model stage runs after every pair stage and the correlator (its predictors are categorical levels and set bits those stages can still rewrite), drawers are sorted into SCHEMA FIELD ORDER at setup rather than `models` array order, and each consumes exactly one `NormFloat64()` per row *unconditionally* — before any branch on the prediction, and even when `ResidualStd` is 0 — so the seeded stream depends only on the number of surviving models and the determinism contract (same spec + same seed ⇒ byte-identical `.pulse`) holds. A spec with no `models` compiles zero drawers, consumes no extra RNG state and is byte-identical to pre-change output. **`z` comes from `Spec.ResidualCorrelations` when the field participates** — see the residual-draw paragraph below; a drawer that does not participate takes its own fresh `NormFloat64()` exactly where it always did.

**Shape-fitted numerics accept conditioning.** `--fit-shape` and conditioning were MUTUALLY EXCLUSIVE and no longer are. A `DistMixture` field was pre-claimed in `resolveConflicts` ahead of the model claim, `modelSpecFromProfile` refused a mixture target outright, and `fieldMoments` / `quantileFor` refused it too — FOUR independent sites, each of which alone was enough to strip the relationship, which is why a change to any one of them looks like it works and then fails at the next. On the motivating cohort that silently removed every measured conditioning relationship from exactly the numerics whose distributions had earned a shape fit. The exclusivity was never a property of the construction: `value = Q(Φ(μ + σ·z))` admits an ARBITRARY marginal in `Q` — it is precisely what a hand-authored `lognormal` target already does — so once the mixture acquired a `Q` there was nothing holding it up. A captured mixture now carries EXACT moments (law of total variance, `mixtureComponents.moments`) and a quantile function (`synth/mixture_quantile.go`), the fitted mixture becomes `Q`, the predictors shift the latent, and the two compose with NO warning because nothing is dropped. The pre-claim ordering is now model-then-shape, and the shape pre-claim is an ordinary `claim()` rather than a direct map write, so it still owns every `DistMixture` field no model took: an UNMODELLED `--fit-shape` field is byte-for-byte unchanged, keeps its own mixture draw, and still excludes a pair or correlation naming it with the `captured shape (--fit-shape)` warning. **Effects are LATENT-scale and therefore NON-LINEAR in value space for a non-normal `Q`** — a coefficient shifts `μ` on the standard-normal scale, and only an affine `Q` (i.e. `normal`) carries that through to the data scale unchanged; under a bimodal mixture the same coefficient moves mass between modes rather than moving values by its own magnitude. Direction and monotonicity hold, magnitude in data units does not, and a coefficient must NOT be read as "this many units of the field". The value-space alternative (draw the marginal, add the prediction) was considered and REJECTED — it destroys the fitted marginal it was supposed to protect — and must not be quietly re-introduced. The quantile inverse is a FIXED-COUNT bisection (`mixtureQuantileBisections`, 64) over a bracket where `Φ` has saturated at exactly 0 and 1 (`mixtureQuantileTailStds`, 40): no convergence test and no early exit, because a tolerance-terminated inverse makes the answer depend on how many steps a given `p` needed and the determinism contract (same spec + same seed ⇒ byte-identical `.pulse`) is not negotiable; bisection over Newton additionally because the density underflows between well-separated modes and a Newton step there explodes. Both halves of the acceptance are asserted in ONE test (`TestSynthModel_ShapeFittedTargetKeepsShapeAndGainsConditioning`) because each is trivially satisfiable by abandoning the other. `format_version` does NOT move. Detail: `skills/synthetic-data.md` (Shape-fitted targets accept conditioning) + `synth/mixture_quantile.go`.

**Float fusion: capture and generation are architecture-independent by CONSTRUCTION, not by luck.** Go permits an implementation to contract `a + b*c` (and `c - a*b`) into a single fused multiply-add, rounding once instead of twice; the arm64 backend does, the amd64 backend does not, and the contraction is permitted ACROSS STATEMENTS, so `scaled := f * mult` on one line followed by `scaled - 0.5` on the next fuses exactly as readily as the one-liner. That made `pulse profile create`'s byte-identity promise hold per-MACHINE only — a profile document is an artefact a user commits, reviews in a diff and shares, and two engineers on different CPUs got different documents. The ONLY construct in the language that forbids contraction is an EXPLICIT floating-point conversion, so every product in a capture or generation formula that feeds an add or subtract is wrapped as `float64(a*b)`; assigning to a local does NOT help and `math.FMA` is the wrong lever (it FORCES fusion everywhere — portable, but it changes amd64's values rather than preserving them, and would move far more of every existing document). The shared variance form lives once, in `synth/moments.go` (`sampleVariance`), which is also where the whole rule is written down; `synth/moments_internal_test.go` is the build-failing gate, pairing `sampleVariance` / `pearson` / `computePercentiles` against `//go:noinline` twins holding the pre-barrier source and asserting production matches the BARRIERED value — it can only DETECT on a contracting architecture, so it is silent on amd64 by construction and logs which case it is in. **Test cohort generators are part of the contract**: `modelsCohort` computed its `spend` / `visits` columns as a chain of float terms, which made the FIXTURE BYTES architecture-dependent (115 of 1,200 rows differed), so it now accumulates in exact integer hundredths and divides once — a stronger guarantee than a barrier, because it cannot be undone by an edit that merely looks tidier. Two residuals are STATED rather than papered over: `math.Exp` (assembly on both arches) and `math.Log` (assembly on amd64, pure Go on arm64) are architecture-specific in the standard library, so a `--fit-shape` `shape` section can still differ in its last bits; and `processing/regression` — the OLS engine behind `models` — has NOT been made fusion-free, so a `models` coefficient can too. `math.Sqrt` is exempt (IEEE-754 requires correct rounding). The compiler will enumerate every remaining site on demand: `go build -gcflags='github.com/frankbardon/pulse/synth=-d=fmahash=vy' -a ./synth/` prints one line per contraction it applied, and the answer for `synth/` is currently none. `format_version` does NOT move. Detail: `synth/moments.go` + `skills/synthetic-data.md` (Profile mode) + `docs/src/cli/profile-create.md` (Reproducibility).

**Boolean marginals: a `packed_bool` reconstructs as `bernoulli`, never as a clamped normal.** A `packed_bool` is summarised by the profiler's NUMERIC accumulator (it is neither date, categorical nor set, so it falls to that default branch), and the obvious reading of that summary — `normal(mean, std)` clamped to the observed `[0, 1]` — is WRONG on the wire, severely and silently. The field holds ONE BIT, so the writer must reduce a continuous draw to 0 or 1; a clamped normal puts mass at exactly 0 only for the draws that fell BELOW zero, so under the historical `value != 0` threshold `P(false)` was `Φ(−p/σ)` and a 20%-prevalence boolean generated at **69.1%**, a 50% one at **84.2%**, an 80% one at **97.7%** — measured, and matching that formula to three digits. On the motivating 381,324-row survey cohort, where **90 of 122 fields are `packed_bool`** and **90 of 105 captured models target one**, the mean prevalence error was **0.4676** with **89 of 90 fields off by more than 0.05**: every 11–14% brand-attribute item generated at ~64%, turning a rare attribute into the majority answer. Post-fix on the same profile: mean error **0.0032**, max **0.0116**, **0** fields off by more than 0.05. `SpecFromProfile`'s boolean arm (`isBooleanFieldType`, `synth/copula.go`) sits AHEAD of the `--fit-shape` arm deliberately — `fitNumericShape` happily prefers a two-component mixture on a 0/1 column, since two well-separated near-zero-variance spikes beat a normal on BIC every time, and that mixture reproduces the prevalence no better while costing a bisection per draw; a boolean's shape is not a thing to discover, it is one number. **All THREE writers that can reach a boolean are covered, because fixing one leaves the others wrong with no signal.** (1) Its own sampler draws `bernoulli` directly — exact. (2) A conditional pair overwrites the target outright from the cell's captured moments, so `CategoricalNumericPairSpec` / `SetNumericPairSpec` carry an additive `Bernoulli bool` (`bernoulli`, `omitempty`) and `conditionalNumericDraw` (`synth/conditional_sample.go`) draws `Bernoulli(cell Mean)` with `Std` unused; without the flag the defect recurs once PER CELL and is worst exactly where the signal is — a 5% cell generated at 41%, destroying the contrast the pair exists to carry. (3) A model draws through `quantileFor`'s step `Q`, which makes the composed draw a **PROBIT**: `P(1 | row) = Φ((μ − Φ⁻¹(1−p)) / σ)`, marginal held exactly at the captured `p` because `Φ(u)` is uniform whenever `u` is standard normal. `fieldMoments` admits `bernoulli` with exact closed-form moments (`mean = p`, `std = √(p(1−p))`) and declares NO clamp, since `Q` emits only 0 or 1. **`modelSpecFromProfile` admits a bernoulli target rather than refusing it** — refusal would be invisible, because the per-target retirement rule already drops a modelled boolean's captured conditional pair, so a refused model leaves the field with no conditioning at all. Three consequences. `std` is 0 at `p` of exactly 0 or 1 and is deliberately NOT floored: `buildModelDrawers`' own `std <= 0` guard turns that into a dropped model WITH a warning rather than an infinite `invStd`. **A bernoulli target's model recovery is NOT IDENTIFIED**: a step `Q` means a 0/1 value does not determine the latent that produced it, so `latentFor` REFUSES (`latentInvertible`, the only distribution `fieldMoments` admits and `latentFor` does not) and the fidelity report's `models` entry ships its captured coefficients with an `error` instead of a delta — the inverse-Mills alternative was rejected because a two-valued "latent" reports a large false attenuation for a generation path that is exactly correct. And `toBool`'s float arm now rounds at **0.5** rather than testing `!= 0`, which matters only for a HAND-AUTHORED spec putting a continuous distribution on a `packed_bool`: that path is still biased (22.7% for a 0.2 field, because clamping piles asymmetric mass on the near bound) but no longer inverted. `format_version` does NOT move — `synth.Spec` lives in `synth/`, not `types/`, so it is unreachable from `descriptor.BuildPayloadSchema`. Gates: `TestSpecFromProfile_BooleanReconstructsAsBernoulli`, `TestSpecFromProfile_BooleanIgnoresCapturedShape`, `TestSynth_BooleanMarginalPrevalence`, `TestSynth_BooleanConditionalPairPrevalence`, `TestSynthModel_BooleanTargetKeepsPrevalenceAndOrdersByPredictor` (both halves in one test — each is trivially satisfiable by abandoning the other), `TestLatentFor_EveryDistributionIsClassified` (the three-way partition that forces a new distribution to be classified rather than acquiring a default), `TestToBool_ThresholdsAtHalf`. **That non-identification is a fact about the FIELD, not a licence for the fidelity report to go silent on it**: the `models` section no longer ships an `error` for a bernoulli target, it scores both sides on the interval-midpoint probit score, which for K = 2 is the lowest-retention case of that surrogate rather than a special case of it — see the Model-recovery paragraph.Detail: `skills/synthetic-data.md` (Boolean marginals) + `skills/op-synth-bernoulli.md` + `skills/type-packed-bool.md`.

**Small-integer marginals: a `u4`/`u8`/`u16`/`u32`/`u64` reconstructs from its own per-level HISTOGRAM (`discrete`), never as a clamped normal.** The boolean defect one type wider, and on a survey cohort the type family that matters most. An integer column falls to the profiler's NUMERIC accumulator and the writer stores `floor(v+0.5)`, so a `normal(mean, std)` clamped to the observed range is QUANTIZED on the way to the file: the bell flattens whatever shape the scale had and the clamp piles asymmetric mass on the near bound, while the MEAN comes back roughly right — which is exactly how it survived. Measured on the motivating 381,324-row survey cohort at 40,000 generated rows, source share → generated: `familiarity` (u4, 1–7, genuinely U-shaped) level 1 **0.2526 → 0.1373** and level 7 0.2198 → 0.1323; `nps` (u4, 0–10) level 10 **0.3200 → 0.2253** and level 0 **0.0284 → 0.0020**; `useCon` (u4, 1–6) level 6 0.3143 → 0.1806 and level 4 0.0778 → 0.2121; `sow` (u16, 0–15) level 0 **0.6469 → 0.3804** with levels 10 and 12–15 never drawn at all. `nps`'s mean came back 7.3463 against 7.5489 — 3% off while its top level was off by 28% of its own size. Post-fix on the same profile: 0.2493 / 0.2165, 0.3310 / 0.0269, 0.3154 / 0.0792, 0.6460 with every level present; worst per-level error across the four fields 0.1153 → 0.0110. `NumericProfile.Discrete` (`discrete`, additive + `omitempty`) carries one `{value, count, frequency}` entry per observed level in ascending order, and `SpecFromProfile` reconstructs the field as the new `discrete` distribution (`values` strictly ascending + optional `weights`, mirroring `weighted_categorical`'s param shape over a numeric support; exact closed-form moments computed FROM the support in `parseDiscreteLevels`, never read off the profile's mean/std, so a hand-authored and a profile-derived spec cannot disagree). A level's observed count IS its weight, so no threshold is involved. **Which types claim the arm is not a taste judgement**: `isIntegerQuantizedFieldType` is exactly the set of `writeFieldValueForField` arms applying `Floor(f+0.5)`, so `f32`/`f64` (the writer stores the float and a normal round-trips), `decimal128` (exact at its own scale), `date` (owns `uniform_date`, never reaches the numeric accumulator) and `packed_bool` (one bit — `bernoulli` runs AHEAD) are all excluded. A type list ALONE is insufficient: `sow` is a `u16` squarely in the defect while `catSpend` (u32, 0–150,000) and `respondent` (u64, 381,324 distinct) must not be, so an observed-level cap is what separates them. **`maxDiscreteLevels` (64) is where the capture ABANDONS the histogram, never truncates it** — a top-64 view of a 3,000-level column makes every share a share of an arbitrary subset, E3's own rule — and the ABSENCE of the `discrete` key is the record, structurally rather than conventionally (the same distinction `ResidualCorrelationProfile` keeps between `unmeasured` and `pairs`), so there is no warning and no knob: presence or absence of the key IS the answer to which reconstruction a field gets. It is a package constant tuned in code, deliberately NOT a `ProfileOptions` field, matching `minVarianceExplained` / `minLevelObservations` / `nullRateDivergenceThreshold` — a capture flag that moved it would make two documents over the same cohort disagree about what the field IS. 64 admits every coded scale by a wide margin (a `u4`'s ENTIRE domain is 16, an NPS is 11, a 1–7 Likert is 7, `sow` is 16) and bounds the document addition at 64 levels × 2 numbers per field (+0.22% on the motivating cohort). **The boundary is PRAGMATIC, not a fidelity cliff, and must not be read as one**: the clamped normal's per-level RELATIVE error is scale-invariant (its central levels come out ≈1.4× their true share at every K), and only the ABSOLUTE error shrinks (~1/K), so a column just over the cap is wrong by under ~1.5 points per level while one just under it can be wrong by 12. Capture is UNCONDITIONAL — no flag — because this is the DEFAULT reconstruction being wrong rather than an enhancement, and it rides the existing single scan (one bounded `map[int64]int` per eligible column, bucketed by the writer's own rounding rule so a captured level and a generated one are the same integer by construction). The arm sits AHEAD of the `--fit-shape` arm for the boolean arm's reason: `fitNumericShape` happily prefers a two-component mixture on a 7-level column and reproduces the per-level shares no better while costing a bisection per draw — a coded scale's shape is its histogram. **ALL THREE WRITERS are covered, because fixing one leaves the others wrong with no signal.** (1) `discreteSampler` draws the staircase, exact by construction. (2) A conditional pair locates the cell's captured moments ON that staircase — `value = Q(Φ((cellMean−fieldMean)/fieldStd + (cellStd/fieldStd)·z))`, the SAME composed construction `modelDrawer.transform` uses, reused so a modelled and a paired target disagree about nothing but where their location came from — and it is resolved from the target's own `FieldSpec` (`buildDiscreteConditionals`), deliberately NOT from a wire flag mirroring `CategoricalNumericPairSpec.Bernoulli`: a flag can disagree with the field's own reconstruction, and a marginal disagreeing with the draw that overwrites it is the whole failure class this removes. Without it the defect recurs once PER CELL (measured: worst per-level error 0.0903 on an identity-cell pair). (3) The model draw becomes an **ORDERED PROBIT** through `quantileFor`'s staircase `Q`, and `modelSpecFromProfile` ADMITS a discrete target — refusing would be invisible, since the per-target retirement rule has already traded that field's conditional pair away for the model, and the cohort's most-discussed target (`nps`) is one of these. Both numeric-target pair filters in `SpecFromProfile` name `DistDiscrete`, and each is written out separately, so one naming it says nothing about the other. Three consequences. **A modelled discrete target's recovery is NOT IDENTIFIED**: `latentFor` REFUSES a staircase (`latentInvertible` is now a two-member set, `DistBernoulli` and `DistDiscrete` — the step is the two-level case of the staircase), so the fidelity report's `models` entry ships its captured coefficients with an `error` rather than a delta. That is sound and NOT free: on the motivating cohort `models` goes from 14 comparable targets of 55 to **2**, and `model_residual_correlations` from **91 compared pairs to 1**, since a residual-correlation comparison needs a refit at both endpoints. That refusal is CORRECT and it must not reach the fidelity report as an `error`: the section now scores both sides on the interval-midpoint probit score (`Φ⁻¹` of each band's midpoint), which is a monotone re-expression rather than an inversion, attenuates identically on the captured and the recovered side, and therefore divides its own bias out of the delta — restoring the motivating cohort's `models` section to **53 comparable targets of 53** (from 2). `model_residual_correlations` is NOT restored by it and stays at 1 compared of 1,378 — a correlation between two score residuals cannot be calibrated the way a coefficient can, and those pairs stay counted under `no_model_fit` rather than silent. See the Model-recovery paragraph for why there is no minimum-level gate and why an ordered-probit refit would be more efficient without being more correct. **Value-scale Pearson correlation on a `discrete` copula participant attenuates while RANK correlation is exact**, the documented property of every non-normal `Q`. And **the pre-rounding gotcha DISAPPEARS for these fields** — the row value already IS the stored integer, so `round(nps) == 9` and `nps == 9` select the same rows and a `{"set_expr": {"nps": "round(nps)"}}` normalisation is a no-op; E2-S4's `round`-not-`int` advice and its `!isnull` guard remain live only for an `f32`/`f64` field, an integer column too wide for the cap, and a hand-authored continuous distribution on an integer field. Gates: `TestSpecFromProfile_IntegerReconstructsAsDiscrete`, `TestSpecFromProfile_IntegerIgnoresCapturedShape`, `TestSpecFromProfile_PreDiscreteDocumentReconstructsAsNormal`, `TestSpecFromProfile_DiscreteTargetKeepsItsModel`, `TestSpecFromProfile_DiscreteTargetKeepsItsConditionalPair`, `TestSynth_DiscreteMarginalPerLevel`, `TestSynth_DiscreteBeatsTheClampedNormalItReplaced`, `TestSynth_DiscretePairKeepsTheScaleAndCarriesTheContrast`, `TestSynthModel_DiscreteTargetKeepsItsLevelsAndOrdersByPredictor`, `TestSynthDiscrete_GappedSupportStaysOnItsLevels`, `TestProfileDiscrete_AbandonsAboveTheLevelCap`, `TestProfileDiscrete_RidesTheExistingScan`, `TestProfileDiscrete_EveryIntegerTypeClaimsTheArm`, `TestLatentFor_EveryDistributionIsClassified`, `TestRulesCoherence_DiscreteScoreNeedsNoPreRoundingNormalisation`. `format_version` does NOT move — `synth.Profile` / `synth.Spec` live in `synth/`, not `types/`. **Correlation reconstruction.** `synth/copula.go` induces the requested correlation via a Gaussian-copula construction: draw a correlated standard-normal vector `u` via Cholesky, map each `u_i` through the standard normal CDF Φ (`math.Erf`) to `p_i = Φ(u_i) ~ Uniform(0,1)`, then apply each field's own quantile function `Q_i(p_i)` (clamped for `normal` fields with declared `min`/`max`) — `normal`/`uniform`/`lognormal`/`exponential` plus, since E4-S1, `mixture` and, since the boolean/small-integer marginals, `bernoulli` and `discrete` (`fieldMoments` validates, `quantileFor` builds `Q_i`); any other distribution named in `correlations` refuses with `SERVICE_VALIDATION`. **A participant must additionally be a SCALAR field TYPE, and that predicate is DERIVED, never transcribed**: `isNumericFieldType` reads `fieldTypeFromName` and admits every declarable non-`categorical_*`, non-`set_*` type (`u4`…`u64`, `f32`/`f64`, `date`, `decimal128`, `packed_bool`). It was a hand-written list until FU-20, carrying `nullable_u4`/`nullable_u8`/`nullable_u16` — spellings `fieldTypeFromName` cannot build, so no spec naming them ever reached the writer — and OMITTING `u4`, which is what `encoding.FieldType.String()` emits. `addCorrelation` gates on it, so every `u4` field was dropped from `Spec.Correlations` in SILENCE: 11 of the motivating cohort's 14 integer columns including `nps`, and ALL 16 of its captured `conditional.numeric_pairs`, leaving that cohort's reconstructed correlation structure completely empty with nothing anywhere saying so — the same stale-alias class as issue #258, which `sentinelFor` had. `packed_bool` and `decimal128` are IN deliberately: both land in the profiler's NUMERIC accumulator, so both can appear in `conditional.numeric_pairs` (`detractor`, a `packed_bool`, carries one of the 16), and excluding either reproduces the identical silent drop one type over. **The boundary is TYPE, not distribution** — a `date`'s `uniform_date` is refused one call later by `fieldMoments`, NAMING the distribution, which is the honest message for a column that plainly holds a number. A STEP/STAIRCASE participant (`bernoulli`, `discrete`) holds its own marginal EXACTLY (`p` is uniform, so each level lands at its declared share) and attenuates the realised VALUE-scale correlation, costing rank as well as Pearson once ties dominate: measured on the motivating cohort's own `regard` × `meaningfulness` pair (both `u4`, both 7-level `discrete`, captured rho +0.8400, 200,000 rows) Pearson came back +0.8072 and Spearman +0.8051 with both marginals inside 0.003 per level, against no correlation at all before the fix. On that cohort the fix is BYTE-IDENTICAL — all 16 pairs enter and `resolveConflicts` drops all 16, because every participant is already claimed by a model or a conditional pair, turning 16 silent absences into 10 aggregated arbitration warnings. Gates: `TestFieldTypePredicates_ClassifyEveryDeclarableType` (the forcing table, driven off the `encoding.FieldType` enum rather than a sample — the name that is missing is by definition not in a sample), `TestFieldTypePredicates_RefuseUndeclarableNames`, `TestSpecFromProfile_SmallIntegerPairsReachTheCorrelationMatrix`, `TestSynthCorrelation_DiscreteMarginsHoldAndCorrelate`. The `mixture` arm exists for the MODEL draw, not for `correlations` — a `--fit-shape` field is still excluded from the value-scale correlation matrix (pre-claimed by `resolveConflicts` when unmodelled; PERMANENTLY refused when modelled, with its correlation structure riding `residual_correlations` instead — see the correlated-residual paragraph below), so widening `fieldMoments` moved no correlation behaviour. `normal` reduces exactly to `mean + std*u` since `Φ⁻¹(p_i) == u_i` by construction — exact for jointly-`normal` pairs, which is what `SpecFromProfile` always reconstructs for numeric fields — and preserves each OTHER supported field's own marginal shape (not just mean/std) once correlated, unlike the removed v1 direct-override construction. This replaces a removed v0 approximation that blended only ±5%·std of the correlated draw into the original value and shipped with no test asserting how much of the requested correlation actually survived, and the removed v1 direct `mean + std*u` override that was exact for rho but forced every correlated field's marginal to Gaussian regardless of its own declared distribution. `TestSynth_CorrelationReconstructionWithinTolerance` and `TestSynth_CopulaPreservesLognormalMarginal` (`synth/conditional_test.go`, `synth/copula_test.go`) are the build-failing gates on that fidelity now. **Unmeasured matrix entries: ASSUME AND RECORD, never refuse and never silently.** `correlations` is a LIST and the Cholesky needs a MATRIX, so every pair among participants the list does not name has to be filled; `buildCorrelator` fills it with 0 — those two are drawn independent — and returns a warning counting how many pairs it completed by assumption, which `generate()` folds onto its warning channel. Refusal was considered and rejected because an incomplete list is the NORMAL input (a spec correlating a-b and b-c has said nothing about a-c, and a profile-derived list is capped at `CorrelationTopK` by construction), and zero is the only completion that adds no structure the caller did not ask for. What was not acceptable is silence: on a ten-field matrix built from a top-16 pair list, 29 of the 45 pairs were asserted independent with nothing anywhere saying they had been asserted rather than measured. `cholesky` now also RETURNS the accumulated diagonal jitter it needed, and a non-zero ridge is reported as its own warning — the ridge stays as the safety net for jointly-inconsistent SUPPLIED entries, but a request that was bent into shape has to be findable, and until E3-S1 the only trace was in the numbers that came back. Neither warning changes a number, so byte-identity of generated output is untouched. Detail: `skills/synthetic-data.md` (Pairwise correlations, Profile mode).

**Residual correlation capture (`--residual-correlations`).** `pulse profile create --residual-correlations` (`synth.ProfileOptions.FitResidualCorrelations`, requires `--fit-models`) adds a third additive, `omitempty` profile section — `residual_correlations` (`synth.ResidualCorrelationProfile`) — carrying the correlation structure among the FITTED MODEL RESIDUALS rather than among raw values. Once a numeric's systematic variation is explained by its predictors, the part still free to move at generation time is the residual, and a raw correlation double-counts every predictor two targets share (two fields both driven by `region` correlate strongly on raw values while their residuals may be independent). It is measured straight off `FieldModel.Residuals` / `ResidualPresent` after the fits, in memory, adding NO read to the single cohort scan. Shape: `{fields, pairs, unmeasured}` — `fields` the sorted participant set, `pairs[]` `{a, b, rho, n}` per MEASURED pair, `unmeasured[]` `{a, b, n, reason}` per pair that could not be measured; the three are exhaustive and non-overlapping. **The FULL submatrix, never a top-K sample**: the eventual consumer is a joint draw over every participant at once and a matrix is not a ranked list — a pair left out of it is a hole the factorization must fill, not a weak pair. `--include-correlations` / `--correlation-top-k` are untouched and keep their exact meaning (strongest top-K pairs of RAW values); this section shares neither flag, and is deliberately NOT implied by `--fit-models` because it is quadratic in modelled fields (105 targets is 5,460 pairs). **Measured-zero and unmeasured are STRUCTURALLY different, not conventionally different**: a dense N x N array has one slot per pair and every slot must hold a number, so `unmeasured` would have nowhere to live but a sentinel — and the natural sentinel, 0, is also a perfectly ordinary measurement. Two lists make the distinction survive a JSON round trip for free, and an unmeasured entry carries NO `rho` key at all, so there is no slot for a zero to be written into. Two closed reasons: `insufficient_overlap` (fewer than `synth.minResidualPairObservations` = 3 rows carry both residuals — two points always give a Pearson coefficient of exactly +-1, so a handful of rows is an artifact of the arithmetic rather than a weak measurement) and `no_variance` (the rows overlapped but one side's residual is constant, so the correlation is 0/0 — an exactly fitted model is the ordinary cause). That floor is deliberately NOT `MinPairObservations` (30): 30 answers "is this stable enough to trust" and its answer is a WARNING, this answers "is there a measurement at all" and its answer is a GAP — they compose, so a pair at or above 3 but below 30 is measured AND warned. **Participants are every model carrying a residual vector, INCLUDING a zero-predictor model** — selection can legitimately admit nothing for a target, and such a target still has a residual (its whole deviation from its own mean); excluding it would drop real structure for a reason unrelated to that structure, and asymmetrically, since the same field paired against a predictor-carrying target is exactly as measurable. A model whose residual vector is ABSENT (a `Profile` decoded from a document — the reservoir is `json:"-"`) is not a participant, because a submatrix in which every pair is unmeasured describes the reader's situation rather than the cohort's. Warnings are bounded: one summary line names the gap count, and thin measured pairs reuse `thinPairWarning` capped at `maxThinResidualPairWarnings` (20), thinnest-first. Capture is byte-reproducible (participants sorted, pairs enumerated over slices, no float folded in Go map order). `SpecFromProfile` translates the MEASURED pairs onto `Spec.ResidualCorrelations` and the `unmeasured` list into NOTHING — see the residual-draw paragraph below. `format_version` does NOT move: `synth.Profile` lives in `synth/`, not `types/`, so it is unreachable from `descriptor.BuildPayloadSchema`. Detail: `skills/synthetic-data.md` (Profile mode) + `docs/src/cli/profile-create.md`.

**The correlated residual draw (`Spec.ResidualCorrelations`).** The consuming half of the capture above, and the change that makes a numeric able to be **both categorically conditioned and correlated with a sibling numeric** — a combination that was unrepresentable before it. `SpecFromProfile` translates `residual_correlations.pairs` (the MEASURED ones; the `unmeasured` list is translated into NOTHING, because an absent pair is completed-and-counted by the generator while a written-out zero would present a gap as a measurement and silence that count) onto the additive `omitempty` `Spec.ResidualCorrelations []CorrelationSpec` slot. At `generate()` setup, `buildResidualCorrelator` (`synth/residual_draw.go`) compiles it into ONE correlated standard-normal vector drawn per row, and each participating `modelDrawer` reads its own component as the `z` of `value = Q(Φ(μ(row) + σ·z))` instead of calling `rng.NormFloat64()`. **The copula stops being a terminal stage that overwrites `row[field]` and becomes the residual structure a modelled field draws THROUGH** — nothing overwrites anything, so the predictors move μ and the shared vector correlates what is left. **There is exactly ONE Cholesky and ONE completion policy**: `factorCorrelations` (`synth/copula.go`) is shared by `buildCorrelator` (value scale) and `buildResidualCorrelator` (residual scale), differing only in the two nouns it puts in the warning (`correlation` / `residual correlation`, `correlated field` / `modelled field`), so E3-S1's assume-and-record policy and its ridge report cannot land on one scale and miss the other. **Determinism**: component order is DRAWER order, which `buildModelDrawers` already fixed to SCHEMA FIELD ORDER — never the `residual_correlations` array order (a document artifact: bind to it and the cohort depends on how the request was serialized). The vector consumes exactly one normal per participant in component order BEFORE the first drawer runs; a non-participant still consumes its own single draw where it always did; and fewer than two surviving participants produces NO correlator and NO draw at all, which is what keeps a spec declaring none byte-identical to pre-slot output. Participation is decided from the COMPILED drawers, not from `Spec.Models`, so a correlation naming a field whose model was dropped in translation or failed to compile is dropped with one aggregated warning rather than stamping a component index onto a field nothing draws. **A value-scale `Spec.Correlations` entry naming a modelled field stays refused, permanently** — realizing it would require overwriting the model's output, and rerouting its figure into the residual would apply every predictor the two fields share a second time (`synth/residual_corr.go`). `resolveConflicts` reports it as *is not applied … capture residual correlations (`profile create --residual-correlations`)* and deliberately NOT as a `conditional relationship conflict`, because no pair claimed the field. The E1-S4 interim wording (*not yet honoured* / *residual draw is still independent*) is GONE, not relaxed. **The feature's real boundary is the ZERO-PREDICTOR target**: selection emits a zero-predictor model for a target nothing explained, E3-S1 admits it as a CAPTURE participant, but `modelSpecFromProfile` DROPS it at translation under E2-S1's per-target rule (a field nothing explains is better served by its captured conditional pair than by an empty model), so its captured residual pairs reach the Spec as nothing. On the motivating cohort that is ~50 of 105 modelled targets. Reversing the drop would retire those fields' conditional pairs in exchange — a worse trade — so the boundary is pinned by `TestResidualCorrelations_CapturedTargetIsRealizedEndToEnd` rather than closed. For a `normal` target the latent→value map is affine, so the realized value-scale residual correlation is the captured figure exactly; for a `lognormal` or `--fit-shape` `mixture` `Q` the RANK correlation is exact and Pearson attenuates — the identical, documented property of the value-scale copula, not a second approximation. `validateSpec` refuses a residual correlation naming an unmodelled field (hand-authored specs only; `SpecFromProfile` bypasses it and the generator warns instead). `format_version` does NOT move — `synth.Spec` lives in `synth/`, not `types/`. Detail: `skills/synthetic-data.md` (The correlated residual draw) + `docs/src/cli/profile-create.md` + `docs/src/cli/synth-from-schema.md`.

**Model recovery in the fidelity report (`FidelityReport.Models`).** `synth from-profile --fidelity-report` gains a per-field `models` section (`synth/fidelity_models.go`, `synth.BuildModelFidelity`): for every linear model generation ACTUALLY APPLIED, it refits that same model on the output cohort's `_synthetic` partition and reports the captured coefficient beside the recovered one, per predictor. Additive and `omitempty`, so a report for a profile captured without `--fit-models` is byte-identical to the pre-E5 shape; `format_version` does NOT move (`synth.FidelityReport` lives in `synth/`, not `types/`). Every other section of that report asks whether the generated rows LOOK like the source; this one asks whether the captured STRUCTURE survived generation, and the distinction is the whole point — this effort shipped two silent structure-loss bugs (v0.32.2 scoring pairs generation never applied; E2-S5 killing 85 of 105 captured models) and in BOTH the marginals stayed healthy while the conditioning was gone. It is also the only instrument that can separate a faithful generation whose marginal contrasts are merely COMPRESSED (partial effects vs. marginal contrasts, plus predictors drawn from their own marginals so source confounding is absent) from one that genuinely lost structure: recovered ≈ captured means the former, recovered attenuated means the latter. **The comparison is LATENT-scale on both sides and that is not cosmetic.** A modelled numeric is drawn as `value = Q(Φ(μ + σ·z))`, so its coefficients are latent quantities; regressing the RAW generated values would compare a value-space effect against a latent coefficient and would report every `--fit-shape` target as badly recovered while generation was exactly correct. Each generated value is inverted through `latentFor` (`synth/copula.go`, the algebraic inverse of `quantileFor`, one arm per supported distribution, round-trip-gated by `TestLatentFor_InvertsQuantileForEveryDistribution` — the two switches MUST move together or a distribution silently drops out of the section) and the captured coefficient is divided by the target's own marginal std, exactly as `buildModelDrawers` divides it; `latent_scale` rides each entry so a reader can multiply back. **Which models ran is asked of generation's own compiler, never guessed from `Spec.Models`**: `resolveConflicts` AND `buildModelDrawers` are re-run against the same `*Spec` `generate()` was given (both are pure functions of the Spec), so the section reproduces the surviving set including the drawer compiler's two warn-and-skip refusals. A field with no model has no entry; a predictor whose level the output cohort never carries is listed with an `error` and NO computed-looking delta. **That is NOT the top-K `"other"` catch-all** — on the motivating cohort all 54 catch-all terms fire (3,992–9,046 rows each) and none errors, exactly as the composed-draw paragraph above describes. The real cause is that the model's retained level set and `Categorical.Top`'s are ranked on DIFFERENT bases: the design ranks levels by frequency within the listwise-admitted reservoir rows for that target, while the reconstructed marginal ranks over the whole cohort. Both keep 32, and they disagree — 9 of `brand`'s 32 design levels, 4 of `ageExact`'s and 2 of `category`'s are absent from the marginal that generates them, so those columns are constant over the synthetic partition and their coefficients are not identified (138 of 2,235 entries). A zero-predictor model is `marginal: true` with no `predictors` array — a COMPLETE model, not a failure — and still reports its intercept comparison. `flagged` fires only when the gap exceeds BOTH `synth.ModelRecoveryTolerance` (0.10 latent sd) AND twice the refit's own standard error; `n_fired` separates "fired thousands of times and recovered nothing" (a fault) from "never fired" (nothing to recover). The refit uses the SAME `processing/regression` REG_OLS engine through the SAME `dummyRecord` adapter capture used — a second estimator would make every gap ambiguous between "generation lost structure" and "two fitters disagree" — and is deliberately UNPENALIZED even when capture shrank its own, since the captured coefficient being compared against is the shrunken one. It needs no injected `TestRunner`: `synth` cannot import `processing`, but it can and already does import `processing/regression`, so the refit lives in `synth/` rather than at the facade. ****A DISCONTINUOUS target is scored on a CALIBRATED PROBIT SCORE, not refused and not inverted.** `latentFor` refuses `bernoulli` and `discrete` — a step or staircase `Q` maps a whole latent interval onto one stored value, so the latent that produced a row is genuinely not recoverable from it — and for one release that refusal propagated straight into this section as an `error` per target. It was sound and it was an instrumentation LOSS, measured on the motivating cohort at **2 comparable targets of 53** and `model_residual_correlations` at **1 compared pair of 1,378**: the section that exists to catch silent structure loss went blind on the exact field types the cohort is made of, immediately after a change that moved every one of them. The fix is to score BOTH sides with the same deterministic surrogate instead of pretending to invert: `probitScore` (`synth/fidelity_score.go`) maps a stored value to `Φ⁻¹` of its own band's MIDPOINT under the field's reconstructed marginal — the level's cumulative interval `[F(v⁻), F(v)]`, midpoint `Φ⁻¹((F(v⁻)+F(v))/2)` — which is an ordinary monotone re-expression of the level, not an estimate of anything. **It is BIASED toward zero, and the bias is COMPUTED rather than assumed away**: a surrogate regressed on the true latent attenuates every coefficient by a factor set by the target's own band structure, so `synth/fidelity_score.go` projects the score onto the design TWICE — once from the generated values, and once as the conditional mean the CAPTURED model implies for each row (`E[score | m]`, integrating over that model's own residual scale). OLS is linear in its response (`b = (X'X)⁻¹X'y`), so under faithful generation `E[b_observed | X]` equals `b_expected` EXACTLY, and dividing the observed coefficient by `b_expected/captured` returns it to the latent scale with the attenuation REMOVED, not estimated — no distributional assumption beyond the generation formula itself. The standard error is divided by the same factor; a staircase entry reports NO recovered intercept, because its cut points come from the captured MARGINAL, which generation holds exactly, so a calibrated intercept would be a number where there is no measurement. `ModelFidelity.Scale` carries `"probit_score"` (against `"latent"` for a continuously-invertible target) so a reader never has to guess which scale a number is on, and `ModelPredictorFidelity.ScoreRetention` reports the measured factor per term. **There is deliberately NO minimum-level gate.** `K = 2` — the `packed_bool` case, where the surrogate degenerates to exactly the two-valued shape the inverse-Mills construction was rejected for — is admitted, because the objection to inverse-Mills was that it reported a large FALSE attenuation against an un-transformed captured coefficient, and same-transform-both-sides removes that objection whatever K is; K = 2 is merely the lowest-retention case (measured retention 0.54, against 0.83–0.92 at K = 7), and low retention widens the noise band rather than biasing the delta. `minScoreRetention` (0.05) exists only to refuse a degenerate band structure that carries no signal at all. An ordered-probit refit would be more EFFICIENT and is not more CORRECT — `processing/regression` exposes `binomial` + `probit` as a reserved, unimplemented enum, so it is a future narrowing of the same estimate, not a correction of it. Measured restoration on the motivating cohort: comparable targets **2 → 53** of 53, step-quantile errors 51 → 0, compared predictor terms **150 → 2,343** of 2,499, flagged terms 7 → 97, score retention over 2,193 terms min 0.075 / median 0.456. **The boundary is PARTIAL and STATED: `model_residual_correlations` still takes no staircase endpoint** — a COEFFICIENT can be calibrated because OLS is linear in its response, a CORRELATION cannot, since the factor relating two score residuals' correlation to the correlation of the residuals that actually drove the draws depends on the PAIR's joint distribution rather than on either marginal, and no projection removes it. Those pairs stay counted in the unmeasured list under `no_model_fit` (1 compared, 1,377 unmeasured, unchanged) rather than silent; closing it needs a polychoric-style bivariate calibration or the same ordered probit. A partial restoration that is honest beats a full one that is not. A flag on a QUANTIZED target is real but needs reading:** the latent inversion undoes `Q` and cannot undo the writer's integer rounding, so for a `packed_bool` or `u4` target — where a 0/1 value inverts to exactly two latent values — most of the latent effect is destroyed by the WRITE and the refit correctly reports only what survived. On the motivating cohort every modelled target is `packed_bool` or a small integer and 30 of 55 models flag, 18 of them `packed_bool` and 9 `u4`; `peopleAware` recovers 0.11 against a captured 0.556 on 1,447 firing rows at an SE of 0.021, so the attenuation is measured, not noise. That is a property of the generated cohort rather than of the instrument. The discrete draw it named as the fix has SHIPPED (`discrete` / `bernoulli` marginals), and with it the quantization is no longer a flag to read around — a discontinuous target is scored on the calibrated interval-midpoint probit score described above, not on a latent inversion that does not exist for it. Cost is bounded by reusing `decodeSyntheticRows` (the v0.32.1 single-decode cache) plus a `modelRecoveryRowCap` of 10,000 rows per refit — capture's own snapshot size, so neither side is estimated from more rows than the other. Detail: `skills/synthetic-data.md` (Model recovery) + `docs/src/cli/synth-from-profile.md`.

**Residual-correlation recovery + the numeric-arm disjointness (`FidelityReport.ModelResidualCorrelations`).** The same report gains a `model_residual_correlations` section (`synth/fidelity_residual.go`, folded by `BuildModelFidelity` itself): for every residual correlation generation APPLIED, the captured rho beside the rho recovered from the `_synthetic` partition. Additive + `omitempty`, so a report for a profile captured without `--residual-correlations` is byte-identical to the pre-E5-S2 shape; `format_version` does NOT move. **It is deliberately NOT folded into `pairwise`, and the two section names are the load-bearing distinction**: `pairwise` scores `Spec.Correlations`, a VALUE-scale correlation realized by the copula, while this scores `Spec.ResidualCorrelations`, a correlation between two models' RESIDUALS realized by the residual correlator — different numbers over the same two fields (two fields both driven by `region` correlate on raw values while their residuals may be independent), and `resolveConflicts` excludes a modelled field from `Spec.Correlations` precisely so the two arms fire on DISJOINT field sets. The recovered side uses the REFIT's own residuals, not residuals against the captured coefficients: capture measured the residuals of a model fitted on its own rows, so recovery measures the residuals of a model fitted on ITS own rows, and scoring against the captured coefficients would fold every coefficient gap `models` already reports into a correlation and state one finding twice. Scale is latent for the same reason the coefficients are — generation correlates the `z`s, so `σ·z` carries the requested rho exactly while a non-normal `Q`'s value-scale residual is a rank-preserving, Pearson-attenuated image of it. E5-S1's refits produce the residuals as a by-product, so the partition is decoded ONCE and both comparisons ride it (`decodeSyntheticRows`, `modelRecoveryRowCap`). **The listing is BOUNDED because the section is quadratic in participants** — 55 applied models is C(55,2) = 1,485 pairs on a report already 1.65 MB, and a section nobody can read is not an improvement over a section that lied. `compared` / `flagged` / `mean_delta` / `max_delta` cover EVERY pair; `pairs` carries the worst `maxResidualRecoveryPairs` (20) by absolute delta, worst-first, with `omitted` counting the rest — the same worst-first-plus-counted-remainder shape `maxThinLevelWarnings` and `maxThinResidualPairWarnings` already use, so an unlisted pair recovered at least as well as the last one listed. `flagged` fires on `ResidualRecoveryTolerance` (0.10) ALONE, with no standard-error term: a correlation is already unit-free and over thousands of co-present rows its SE is under 0.02, so a noise-scaled band would collapse onto the floor. Unmeasured pairs ride a SEPARATE list carrying `captured_rho` and NO recovered-rho slot at all (`insufficient_overlap` / `no_variance` reused from the capture vocabulary, plus a recovery-only `no_model_fit` for an endpoint whose refit could not run), mirroring `residual_correlations.unmeasured` structurally rather than by convention. Measured on the motivating cohort: 55 participants, 1,485 compared, 147 flagged, mean delta 0.055, max 0.490, 0 unmeasured, +6 KB and ~5s on the existing report; the largest gaps sit on `packed_bool` and small-integer targets (`aware`x`familiarity` 0.738 -> 0.248), the same quantization attenuation the `models` section reports on the same fields. **`models` and the two NUMERIC-TARGET pair sections are disjoint by construction**: a numeric reached by a linear model has no entry in `categorical_numeric_pairwise` or `set_numeric_pairwise`, ever, because the pick-one sampler those sections score does not run for it and an entry would be a delta for a mechanism that never executed (the v0.32.2 bug class). Two independent guards make that structural rather than incidental — `SpecFromProfile` leaves a modelled target's captured pair off the Spec, and `resolveConflicts` pre-claims every modelled field ahead of the categorical-numeric stage, which catches a hand-authored spec declaring both. **The retirement is per TARGET, not per document**: an unmodelled numeric in the same profile keeps its pair and is still scored there, because a field whose model was captured but not applied would otherwise be reconstructed from nothing at all (on the motivating cohort: 55 fields in `models`, 46 in `categorical_numeric_pairwise`, no overlap). The three NON-numeric-target arms (`categorical_pairwise`, `set_categorical_pairwise`, `set_set_pairwise`) are untouched — a linear model targets a numeric and subsumes nothing they describe. **The terminal warning summary (`synth.GroupWarnings`).** Every warning above reaches a FILE — `Profile.Warnings` in the profile document, `SpecFromProfile`'s translation warnings and `Result.Warnings` in the fidelity report / `--json` envelope — and until E6-S3 reached no TERMINAL at all: `pulse profile create` printed the row count and `pulse synth from-profile` the row count plus the report path, so a capture where 85 of 105 models died in translation looked byte-for-byte like one where nothing did. That is not a UX gap, it is how the E2-S5 defect survived the whole effort. `synth.GroupWarnings` (`synth/warning_summary.go`) folds a flat `[]string` into counted `WarningGroup`s; `internal/cli/warnings.go` renders them to **stderr** — never stdout, so every redirect and pipeline keeps exactly the bytes it had — with kinds needing attention FIRST and capped at `maxWarningExamples` (3, the CLI-side screen budget, deliberately smaller than synth's own `maxThinLevelWarnings` / `maxThinResidualPairWarnings` of 20 because those bound a document a reader pages through while this bounds one screen every kind shares). **The taxonomy lives in `synth/`, beside the functions that BUILD the strings**, because a reworded message is a change to the table and a classifier in the CLI would drift silently — the reworded line would simply start landing in the catch-all. **An unrecognised warning is classified as needing ATTENTION, not as expected**, which is the direct inverse of the `default:`-arm lesson E2-S5 taught: a benign default is how a mis-serialised predictor kind disabled 80% of a feature with no signal anywhere. **Expected outcomes are counted separately and must stay that way** — a zero-predictor model is a COMPLETE model, a thin pair still ships, an arbitrated pair claim is the design working, and on the motivating cohort those are 3,004 of 3,005 lines, so folding them into one figure makes "3005 warnings" the reading on a healthy capture and on a broken one alike. `synth from-profile` summarises all THREE channels (capture / translation / generation) because only the middle one carries `model for numeric field "x" not applied: …`; translation and generation both derive their conflict lines from one arbitration over one spec, so the CLI drops byte-identical duplicates before counting. **Since E2-S3 the generation channel also reaches the fidelity REPORT** (`mergeFidelityWarnings`, folded at `Pulse.Synth` — the only place holding both `res.Warnings` and the report path, deduped against the supplied channel). Until then the report carried only what could be computed BEFORE the run, so a `--rules` run's post-merge arbitration — the record of which captured relationships the rules retired, and E2-S3's own never-fired reports, neither of which exists until after generation — reached a terminal nobody keeps while the CLI's own footer claimed `Full list: <report> (.warnings)`. Re-running `resolveConflicts` at the CLI leaf was the alternative and was REJECTED: it fixes the conflict lines only and puts a second copy of generation's arbitration in a second place. Measured on the motivating profile with one claiming rule plus one dead rule, the report went from 3,846 warnings mentioning neither fact to 3,849 carrying the retired model, the dropped residual participant and the dead rule, with the 791 shared lines written once. Only `warnings` CONTENT moves — the slot is the same `[]string`, `synth.Result` is untouched and no `--json` envelope shape changes. With `--fidelity-report` it also prints the E5 recovery headline (`N model(s) checked, M flagged`), re-reading the report rather than adding a slot to `synth.Result`, which is the `--json` payload. Nothing here changes a generated byte or a `--json` envelope SHAPE; there is no silencing flag because no CLI leaf in this repo has one. **Structural rules (`Spec.Rules`, additive + `omitempty`).** The slot for the class of fact no statistical summary can express, because it is not variation at all: a question block that is not ASKED of a respondent who failed a screener, a flag that is a band of another column. Reconstructed from marginals those come back as soft noise with a plausible rate and no gate — measured on the motivating cohort, a 50-field perception block whose real co-missingness is exact generated 22 stray rows in 40,000. Five slots per `RuleSpec` (`synth/rules.go`): `when` (optional expr predicate; ABSENT MEANS EVERY ROW, which is not "never"), `set_null`, `set` (LITERAL values), `set_expr` (expression results) and `null_together` (one null decision across a block) — plus ONE MODIFIER, `owns_nulls`, which changes what a `set_null` MEANS for the fields it names rather than adding a sixth action (see the ownership paragraph below). **`set` and `set_expr` are SIBLING KEYS and must not be merged into one map with a `{"$expr": …}` marker**: one map leaves `{"set": {"region": "west"}}` undecidable between a categorical literal and a bare identifier, and two keys make the question impossible to ask. Rules apply in DECLARATION order, sequentially, LAST WRITE WINS, in one pass at the very END of the row (after the model stage), so an expression reads whatever the row holds when ITS RULE starts and a later rule may still change it. **They are deliberately NOT topologically sorted** — a sort would make the applied order implicit, and declaration order is the one ordering an author can read off the document. The pass consumes no RNG, so a spec declaring no rules is byte-identical to one written before the slot existed. The **standalone rules-file format is the `Spec.Rules` array itself**, so an inline declaration and a `--rules` file are the same JSON and the loader needs no translation layer. **Validation is EAGER — at spec parse, never at row time** (`validateRules`, reached from `validateSpec`, so `ParseSpec` / `Synth` / `SynthBytes` / `AugmentFromProfile` all gate): a rule naming a mistyped field or carrying an uncompilable expression is invisible at run time (the run succeeds and the gate is simply absent), which is the exact failure the slot exists to remove. Eight coded faults, one each: `PULSE_SYNTH_RULE_EMPTY` (no action slot), `_FIELD_UNKNOWN` (a slot names an undeclared field — AND an undeclared name inside `isnull("…")`, which is deliberately NOT `_EXPR_INVALID`: that expression COMPILES, since the builtin's signature is `func(string) bool`, so it is an unknown FIELD and widening "does not compile" to cover it would make one code mean two things; detected by `isnullUnknownField`, which PARSES the author's source rather than substring-matching it, and is applied to `compileConstraints` as well as `validateRules` because the two share one environment and `TestValidateRules_ExprEnvIsTheConstraintEnv` holds their verdicts equal), `_FIELD_NOT_NULLABLE` (`set_null` names a field the schema cannot record a null for — see the pass-runs-LAST paragraph for why `null_together` only warns), `_EXPR_INVALID` (`when` must additionally return bool), `_VALUE_INVALID` (the value a rule wants to write cannot be written — a `set` literal OR a `set_expr` result, since both go through one matrix; `details.slot` says which), `_CONFLICT` (one rule naming a field in two slots that disagree — there is no order to appeal to WITHIN a rule, so it is refused rather than arbitrated) `_BLOCK_INVALID` (`null_together` naming fewer than two DISTINCT fields) and `_OWNERSHIP_INVALID` (`owns_nulls` declared with an EMPTY `set_null` — the claim is scoped to that slot and to nothing else, so it has no referent; refused rather than ignored, because an ignored ownership claim is invisible: the fields keep the double-counted null rate the flag exists to remove and nothing in the run says the flag did nothing). A `when` that fails at RUN time keeps `PROCESSING_RUNTIME` and must NOT acquire a code of its own: the surviving causes are generic expr evaluation faults (an `isnull` argument that is only a string at run time, `int()` of a non-numeric string), identical in kind to a constraint's own failure, and the coded error already carries the rule index, the slot and the expression — the path IS still reachable, so the backstop is not dead code, but a code minted for it would describe a state nobody acts on differently. Every error carries the rule INDEX (`errors.DetailSynthRule`) and where one exists the slot (`errors.DetailSynthRuleSlot`) and field, because a rule has no name of its own and the index is the only handle back to the document. `when` and `set_expr` compile against the SAME environment `Spec.Constraints` uses (`rowExprEnv` / `rowExprOptions`, one builder shared) — a second hand-rolled env is what produced issue #258. Faults are reported in a fixed slot order with SORTED map keys, so a rule with two faults refuses the same one on every run rather than whichever key Go visited first. `format_version` does NOT move — `synth.Spec` lives in `synth/`, not `types/`. Detail: `skills/synth-structural-rules.md` + `docs/src/cli/synth-from-schema.md`.

**The rule pass runs LAST, and that placement IS the semantics.** `drawRow`'s final act, after the model stage, is one pass over `Spec.Rules` (`synth/rules_apply.go`, compiled once per Spec by `compileRules`). The semantics that buys are **`if gate then null else inferred`**: every field has already produced the value generation INFERS for the row — through its own sampler and through whatever model, conditional pair or correlation owns it — and a rule then masks or replaces it ONLY where its `when` selects, so a non-gated row keeps the inferred value untouched. Running the pass any earlier would hand the model the last word on its own target, so a `set_null` over a modelled field would be overwritten on every row and a `set` literal would survive only where no model bid. **The accepted consequence: a field a rule NULLS still contributed its DRAWN value to any model that used it as a PREDICTOR on that row.** The two-phase alternative (evaluate gates, then re-run the dependent stages with gated fields withheld) was considered and REJECTED — it doubles the stage surface and needs a rule↔model dependency order no document declares — and the single-phase reading is defensible on its own terms: the respondent's propensity existed, the question simply was not asked. A later reader will reach for two phases; this is why not to. Per-slot write semantics, which compose symmetrically under declaration order: `set_null` sets the null mask and LEAVES the drawn value in the row (the same shape `nullableSampler` produces, so `isnull()` and a later rule behave identically whether the null came from `null_rate` or from a rule; `writeFieldValueForField` writes the type's zero for every masked field, so nothing leaks to the wire), while `set` writes the value and CLEARS the mask (a rule stating a field's value is stating the field HAS one — leaving a drawn null would write 0 and the literal would silently vanish). A `set` literal is coerced to the row's Go shape ONCE at compile time through `constantRowValue` — the `constant` distribution's own coercion, reused, which is what turns a `set_*` target's JSON `["tv","radio"]` into the `map[string]bool` the row holds. The pass consumes NO RNG and allocates nothing per row. That is a statement about the PASS, and since E2-S2 it no longer implies the stronger one it used to be written as: a spec whose rule PRE-CLAIMS a field (see the paragraph below) retires that field's model, and a retired model stops consuming its own unconditional per-row normal, so the stream legitimately moves — for a reason a warning names, which is the whole difference between that and a determinism bug. A spec declaring no rules, and a spec whose rules claim nothing, are both byte-identical to pre-slot output. Every action slot is now live; `set_expr` has the coercion-matrix paragraph below and `null_together` the block paragraph after it. Two gotchas worth stating because both are silent: a `set_null` over a field NOT declared `"nullable": true` writes the type's zero as an ordinary value with no null bit (`encodeRow` writes the bitmap for nullable fields only) — the rule fires and the file cannot show it — so it is REFUSED at spec parse as `PULSE_SYNTH_RULE_FIELD_NOT_NULLABLE` rather than warned, because it is knowable from `FieldSpec.Nullable` and a warning capped at three examples per kind was three lines out of hundreds as the entire signal for a missing gate. **The refusal is keyed on WHAT THE SLOT CLAIMS, and `null_together` therefore keeps the warning**: `set_null` states the field IS null on a matching row, which a non-nullable field can never honour, while `null_together` states the members carry the GATE's decision — a decision that includes UN-nulling and may be "present" on every row. Do NOT "finish the job" by promoting `null_together` too: the gated-block idiom names a NEVER-NULL field first on purpose, so a refusal keyed on "any field a rule may null" refuses the most useful shape the layer has (falsified — it also breaks two E1 tests); and a `when` reads the row's PRE-ROUNDING float, so `== k` over a numeric reconstructed as a continuous distribution fires only on the draws landing exactly on `k` (for a clamped `normal`, the clamp's point mass) rather than on the whole wire-value-`k` bucket — comparisons (`>= 9`) are the well-behaved numeric form, and `packed_bool` is exact because its row value is exactly `1.0` / `0.0`. Rules reach GENERATED rows only: `AugmentFromProfile` calls `generate()` for its `_synthetic=true` partition and re-encodes the source records straight through, so a `synth from-profile --source` run never rewrites a real row. `format_version` does NOT move. Detail: `skills/synth-structural-rules.md` + `docs/src/cli/synth-from-schema.md`.

**`owns_nulls`: a rule can be the field's ONLY source of absence, and it ZEROES the own draw rather than applying the residual.** `set_null` states WHICH rows a field is absent on and says NOTHING about how many, so each target's own `null_rate` kept firing beneath the gate. That rate is a MARGINAL the profiler captured — already inclusive of everything the gate removed — so the two composed as `g + (1−g)·r` and a gate that was exactly right about every gated row was wrong about the marginal. Measured on the motivating 122-field profile at 40,000 rows: a 50-field `{"when": "aware == 0"}` gate took `regard` from a captured 0.2526 to a generated 0.4369, and the five `*Aware` gates took `people` from 0.4273 to 0.7506 — every gated cell correct, every rate wrong. `RuleSpec.OwnsNulls` (`"owns_nulls": true`, `synth/rules_ownership.go`) discards those fields' own null draw and lands all fifty on 0.2455, the gate's own firing rate, with the gate still exact on 491,200 of 491,200 gated cells. **The exactly-correct suppression would be the RESIDUAL `(r − g)/(1 − g)`, and it is not computable**: it needs `g`, the rule's FIRING PROBABILITY, and a `when` is an arbitrary predicate over a row — no Spec knows how often it will be true, and estimating it needs a generation pass whose own rows are drawn from the very rates being corrected, which would additionally make the answer depend on `RowCount`. So the flag zeroes the draw and the GAP IS MEASURED rather than guessed: `ownershipWarnings` counts each owned field's realised nulls over ACCEPTED rows (the same commit-per-accepted-row rule the firing counter uses) and reports any field whose realised rate misses its discarded `null_rate` by more than `nullOwnershipDivergenceThreshold` (0.02) AND `ownershipNoiseStdErrs` (2) standard errors — the both-terms rule `FidelityReport.Models` already applies, and dropping the noise term makes the line a coin toss on small runs (at 200 rows a CORRECT claim on a 0.25 field misses by 0.02 about half the time). One message covers both failures it can report — a gate explaining only part of the missingness, and a claim over a field the rule never nulls — because the number tells them apart and the remedy is the same three moves; it is an ATTENTION kind, bounded worst-first at 20 with a counted roll-up. **Where `g` IS knowable the residual is BOUNDED rather than unknown, and that is why `--suggest-rules` sets the flag on every gating candidate**: E3-S1 admits a (gate, target) pair only when the target is null on at least `gateHighNullRate` of gated rows and at most `gateLowNullRate` (0.02) of OPEN rows — and `P(null | open)` IS the residual — so every candidate detection can emit is within 0.02 of exact, the distance `nullRateDivergenceThreshold` already calls immaterial. **Suppression is a WRAPPER that discards the verdict (`ruleOwnedNullSampler`), never a rebuild without the nullable wrapper**: `nullableSampler` consumes one inner draw PLUS one `rng.Float64()` whatever the rate, so a rebuild would drop one draw per row per owned field and shift the whole seeded stream — measured against an un-owned run at one seed, the other 72 fields are cell-identical and the ONLY change is 381,351 null flags REMOVED on non-gated rows, 0 added, 0 values moved. **Ownership is a UNION, never a `resolveConflicts` claim**: `set_null` removes a value rather than supplying one and has never claimed a field away from its own generation (that is E2-S2's rule), and "two gates can each account for this field's absence" is a coherent statement needing no arbitration — two rules may own one field, the draw is suppressed once, either gate nulls it, and the divergence line names BOTH indices because editing one of two does not close the gap. **`null_together` already does this for its non-gate members, by COPY rather than by suppression**, so the gated-block idiom (name a never-null field first so the copy clears the block's own MCAR nulls, then supply the real gate with a `set_null`) is ownership obtained as a SIDE EFFECT; `owns_nulls` is the same statement said directly, on the rule that makes it true, and the two are byte-identical where they overlap. Do NOT conclude the block is retired: it alone expresses a co-missing block with NO gating field, where one member's own draw is the block's only source of absence — the four-field NPS block is exactly that, and without it comes back all-present on 45 of 40,000 rows. `format_version` does NOT move. Detail: `skills/synth-structural-rules.md` + `docs/src/cli/synth-from-schema.md`.

**A rule that DETERMINES a field pre-claims it at priority 0.** `resolveConflicts` (`synth/conflict.go`) already owns which stage may write a field; `Spec.Rules` now claims first, ahead of the linear-model pre-claim, because the rule pass runs LAST in `drawRow` and an unconditional write wins outright. Without it a modelled field a rule overwrites still gets its model compiled, its residual correlations drawn and — the reason this is not merely wasted work — **a `FidelityReport.Models` entry reporting a captured-versus-recovered coefficient delta for a value nothing kept**, with no slot on the report saying so. `BuildModelFidelity` asks generation's own compiler which models ran (`resolveConflicts` → `buildModelDrawers`), so the claim removes the work and the false report in one move. Everything downstream falls out of the existing machinery: the model loses with the ordinary `conditional relationship conflict: … is already claimed by structural rule N (set_expr); dropping linear model` wording, a conditional pair naming the field loses the same way, and the field stops being a residual-correlation participant with `buildResidualCorrelator`'s existing dropped-participant warning — no second phrasing was invented. **Which rules claim is the whole contract, and each of the four exclusions is SILENT if it is got backwards** (`synth/rules_claim.go`): a rule carrying `when` writes only some rows, so claiming would strip the model from every row it never touches and leave a plausible bare marginal in its place; **`set_null` NEVER claims, at any conditionality** — it removes a value rather than supplying one, and `if gate then null else inferred` means the field's own model is exactly what produces the value the non-gated rows keep; `null_together` supplies no value either; and a **`set_expr` that READS ITS OWN TARGET does not determine the field, it transforms what generation produced** — the canonical instance is the documented pre-rounding remedy `{"when": "!isnull(nps)", "set_expr": {"nps": "round(nps)"}}`, and claiming there would leave the rounding applied to a bare marginal draw, making the documented fix for one silent fault cause a larger one (measured on the motivating profile: it strips `nps`'s model and all 54 of its residual correlations). The self-reference is detected on the PARSED expression, never by substring — a rule over `nps` must not be excluded by a mention of `nps_reason` — and an unparseable expression (unreachable past `validateRules`) answers "reads", the direction that cannot lose structure. The no-`when` restriction is sufficient rather than limiting because `set_expr` collapses the motivating three-band case into ONE unconditional rule. Measured on the motivating 122-field / 381,324-row profile: an unconditional `set_expr` over `promoter` takes the applied models from 55 to 54, drops its 54 residual-correlation pairs, and removes its `models` fidelity entry; a `set_null` over the same field changes none of the three. `format_version` does NOT move. **`set_expr` and THE COERCION MATRIX.** `set_expr` assigns the RESULT of an expression evaluated over the row, which is what collapses a derived-field relationship from several `when`-gated rules into one unconditional rule (`{"set_expr": {"promoter": "nps >= 9", "passive": "nps >= 7 && nps < 9", "detractor": "nps < 7"}}`) — and, because it carries no `when`, makes the target eligible for the E2-S2 pre-claim, so `promoter` is not modelled and correlated upstream only to be overwritten. It writes the value and CLEARS the null mask exactly as `set` does. An expression returns a Go shape and the target is one of the seventeen declarable field types, so **the matrix is the surface and a wrong cell is a silent wrong value** — a bool reaching a `u8` as a formatted string encodes as `0`, a computed category outside the declared domain adds a dictionary entry that looks like data, a `u4` taking 16 is masked to its low nibble and stored as `0`. There is exactly ONE matrix (`ruleValueFault`, `synth/rules_coerce.go`) and the `set` literal path goes through it too; the row shape then comes from `constantRowValue`, the `constant` distribution's own coercion, so nothing here is a second conversion. The cells, by target CLASS (the three `sentinelFor` derives): a **scalar** (`u4` `u8` `u16` `u32` `u64` `f32` `f64` `date` `packed_bool` `decimal128`) takes a **bool as 1/0** or a **number**, range-checked against the same bounds a `set` literal obeys, and refuses a string; a **categorical_\*** takes a **string that is in the field's declared domain** (`weighted_categorical`'s `params.values`; a `regex` or `constant` field's domain is unbounded and any string is accepted, the same split the literal path makes) and refuses everything else; a **set_\*** takes a **selection** — a `map[string]bool` read straight off another set field, a list of declared option names, or `split()`'s `[]string` — and refuses scalars. **The one asymmetry with `set` is `decimal128` from a STRING, and it is a decision**: a `set` literal string is kept verbatim and parsed by `encoding.ParseDecimal128` (exact), while a `set_expr` string is REFUSED, because expr types every scalar field as the `float64` the row holds so anything computed already lost the digits, AND because a string left in the row for a field `rowExprEnv` typed `float64` makes the NEXT rule's `when` or `set_expr` over it fail at run time — issue #258's failure, now intermittent, firing only on the rows the earlier rule gated. Exactness lives in `set`; the refusal says so. **TWO TIMINGS, one code.** A fault the RETURN TYPE settles is refused at SPEC PARSE (`validateRuleExpr` reads expr's own inferred type off `prog.Node().Type()`; an `interface{}` type is expr saying it could not infer and defers whole), a fault only a VALUE settles — a number out of range, a computed category outside the domain — is refused at ROW time, and both are `PULSE_SYNTH_RULE_VALUE_INVALID` with `slot: "set_expr"`, the field, the expression and the value. The static side does NOT own a table: it probes the same matrix with the type's zero and refuses only on a TYPE fault, so a parse-time refusal cannot disagree with a run-time one. **INTRA-RULE ORDER IS UNOBSERVABLE — every expression in ONE rule, `when` included, reads the row as it stood BEFORE the rule ran, and the rule's writes all land afterwards (`UPDATE t SET a = b, b = a` swaps, and so does this).** That is E1-S4's answer to the question E1-S3 left open, and the alternative was rejected because the order it would expose is not one an author can SEE: a rule's slots are Go maps, JSON key order is gone after decode, and the surviving order is ALPHABETICAL — so renaming a column would silently change a number. Refusing intra-rule reads outright was the third option and also rejected: `{"set_expr": {"nps": "nps + 1"}}`, a field derived from its own drawn value, is the most natural thing an author writes. ACROSS rules nothing changed: sequential, last write wins, so a `set_expr` reading a field an EARLIER rule wrote sees the new value and one reading a field a LATER rule will write sees the old one. **The pre-rounding gotcha bites `set_expr` harder than `when`, because it is silent rather than merely surprising**: the row holds the sampler's float and the wire holds `round(f)`, so a three-band classification written straight off `nps` still sets exactly one flag per row and merely disagrees with the number printed beside it — measured on the motivating 122-field profile at 20,000 rows, 476 of 3,486 scored rows (13.7%). Normalise first, in an EARLIER rule (`{"when": "!isnull(nps)", "set_expr": {"nps": "round(nps)"}}`), which the snapshot rule makes mandatory: in the SAME rule the bands would still read the float. **`round`, not `int`, and the difference is invisible in the metric everyone checks** — both reach 100% band agreement, because an integer field is stored as `floor(v+0.5)` and `band(v) == band(floor(v))` for integer thresholds. `round(v)` moves the FLAGS onto the right side of the band edge; `int(v)` reaches the same agreement by moving the SCORE. Measured on the motivating profile at 40,000 rows: `round` moved `nps` on 0 rows and repaired 1,029 flag disagreements, while `int` moved it on 3,018 of 6,944 scored rows and repaired none — it buys agreement by dropping respondents a point. Same shape on a gate: `familiarity <= 1` fires on 1,843 rows raw, 2,739 behind `round()` with the column unchanged, and 3,824 behind `int()`. **And the `when` guard is not optional**, because a `set_expr` CLEARS the null mask: the ungated form writes a value on every row, so it un-nulls the field and takes any `null_together` block keyed on it along with it — measured, the four-field block goes from 6,944 present to 40,000 of 40,000. That normalisation rule reads its own target, so it does NOT pre-claim `nps` and the field keeps its model, pairs and residual correlations (see the pre-claim paragraph above). The pass still consumes NO RNG and allocates nothing per row of its own — each rule's evaluated results land in a buffer sized once at compile time. `format_version` does NOT move. Detail: `skills/synth-structural-rules.md` + `docs/src/cli/synth-from-schema.md`.

**`null_together` NULLS A BLOCK AS ONE DECISION, and the FIRST named field wins.** A survey question block is asked or skipped as a unit, so its fields are present or absent together; drawing each member's null independently from its own scalar `null_rate` turns the block into a lottery. Measured on the motivating 122-field profile, the `nps` / `promoter` / `passive` / `detractor` block shares `null_rate` 0.8260 exactly and all four came back present in **45 of 40,000** generated rows against the ~6,960 the block actually has, because `0.174⁴` is not `0.174`. With the rule: **6,809–6,994 across five seeds, and zero partial blocks.** The resolution is a COPY of `nullMask[block[0]]` onto every other member (`applyNullTogether`, `synth/rules_apply.go`) — every field has already consumed its own null draw by the time the pass runs, so copying an existing decision is the only resolution that adds no randomness, and the pass consuming no RNG is a hard contract. **The cost is that every member but the first has its own `null_rate` IGNORED**, which is stated here rather than left to be discovered, and is warned about at compile time whenever a member's declared rate sits more than `nullRateDivergenceThreshold` (**0.02**, a package constant with its reasoning at the declaration, deliberately not an `Options` field — matching `minVarianceExplained` / `minLevelObservations`) from the gate's. The comparison is ABSOLUTE and each member is measured against the GATE, not against the block's spread: what the copy discards is a number of ROWS, so a relative test would scream about 0.001 against 0.002 and stay quiet about 0.80 against 0.84. Refusing outright was considered and REJECTED — a real block whose fields drifted slightly (a coding difference, a partial re-ask, a rate read off a rounded table) would become unusable and the copy is still right for it. The warning is classified in `synth/warning_summary.go` as an ATTENTION kind (`rule null_together overrides a declared null_rate`) beside the function that builds the string, so a rewording is a change to the table rather than a line that silently falls into the catch-all. **The copy moves the null DECISION only, never a value** — each member keeps what its own sampler drew, a nulled member exactly as `set_null` leaves it, and an UN-nulled member (gate present, member had drawn a null) publishes the value it drew, which is the half that makes the block share a rate at all rather than only share its nulls. **Within ONE rule the block is the LAST write**, after `set_null` / `set` / `set_expr`, because the slots of a rule have no order an author can read and that is the composition that is useful: `{"set_null": ["nps"], "null_together": ["nps", …]}` nulls the gate and the block follows it, while reversed the block would be decided from the gate's DRAWN state and the `set_null` would break it apart on exactly the rows it was meant to gate. A `set_null` naming a NON-gate member in the same rule is therefore overridden by the block. ACROSS rules the ordinary last-write-wins applies instead: a later `set_null` over any member does break the block, and a later `null_together` re-decides it from whatever the gate holds by then. **The case that actually bites is a later `set_expr`**, because it CLEARS the null mask on every row it writes — declaring `null_together` in one rule and the `set_expr` that derives its members in a LATER one lets the derivation run last and un-null every member on the rows the block had just nulled together: measured on the motivating profile, 33,056 of 40,000 rows come back carrying a classification flag with no score, which is the exact incoherence the block rule was added to remove. Put both slots in ONE rule, where `null_together` is the last write by construction, rather than relying on declaration order to keep them in step. A non-nullable NON-GATE member gets the silent-zero warning, sharing its kind — a WARNING and not `set_null`'s refusal, because this slot copies a decision rather than making one. **The GATE is never reported by either warning**: `applyNullTogether` reads `nullMask[block[0]]` and never writes it, so a non-nullable gate is not a field the block failed to null, and a never-null gate is the IDIOM rather than a mistake (the copy clears every member's own MCAR null, leaving a later rule's `set_null` as the block's only source of absence — measured on the motivating profile as the remedy for the gate rule's marginal shortfall). Reporting it flagged the design as a defect. `format_version` does NOT move. Detail: `skills/synth-structural-rules.md` + `docs/src/cli/synth-from-schema.md`.

**A rule that NEVER FIRES is reported, as an ATTENTION kind.** Eager validation (E1-S2) refuses a rule naming a mistyped field or carrying an uncompilable expression. It cannot refuse a `when` that is simply never TRUE: that rule validates, compiles, applies to nothing, and the cohort generates cleanly with the structural fact the author wrote it for still ABSENT — nothing downstream can tell it from a cohort where the rule worked. That is the fourth instance of one failure class in this package (a fidelity report scoring pairs generation never applied; 85 of 105 captured models silently unapplied; every `packed_bool` prevalence inverted; an emitted spec that parsed and then refused), so the classification follows the standing rule rather than a judgement about severity: `rule never fired` is ATTENTION (`synth/warning_summary.go`, the row sitting beside the function that builds the string), never the expected-outcome count. **The count is over rows that reached the FILE, not draws.** `generate()` re-draws a whole row when a constraint rejects it, so a firing on a rejected attempt left no trace and a count including it cannot be divided by `rowsGenerated` — which is the one arithmetic a reader will do with it. The counter therefore commits per ACCEPTED row (`ruleApplier.commitRow`, `synth/rules_firing.go`) rather than incrementing in `apply`, and a rule firing only on rejected rows correctly reports zero. Two slices sized once at compile time (`rowFired` scratch + `firings` totals): the pass still consumes NO RNG and allocates nothing per row, so generated bytes are identical with the counting and without it. A rule firing on EVERY row and one firing on SOME are both silent; the listing is capped at `maxNeverFiredRuleWarnings` (20, matching `maxThinLevelWarnings`) with a counted `+N further rule(s) never fired` roll-up folded into the same group, and the terminal summary's own 3-example cap is unchanged. The firing count is deliberately NOT a `synth.Result` slot — that struct is the `--json` payload and this is a diagnostic the warning channel already carries; `format_version` does NOT move. The message names the PRE-ROUNDING gotcha because it is the usual cause: measured on the motivating profile at 20,000 rows, `familiarity <= 1` fires on 1,843 rows raw, 2,739 behind `round(familiarity)` with the column unchanged, and 3,824 behind `int(familiarity)`, which reaches the larger figure by dropping 1,085 respondents a point — so the advice the message gives names `round`, not `int`. All three run silently; only the empty case warns. Detail: `skills/synth-structural-rules.md` + `docs/src/cli/synth-from-profile.md`.

**`constant` is normalised to the field's row shape.** `newConstantSampler` is the one sampler whose value comes from the spec DOCUMENT rather than from an arithmetic draw, so it is the one that can put the wrong Go type into the row: every other sampler for a given field type emits one shape (float64 for every scalar including `packed_bool`, string for a categorical, `map[string]bool` for a set) and `sentinelFor` types the expression environment on exactly that assumption. A JSON `true` on a `packed_bool` field therefore put a Go `bool` where the env promised a float64 and broke every constraint — and now every rule `when` / `set_expr` — touching the field at RUN time, the inverse of issue #258. The value is coerced ONCE, at spec compile time (`constantRowValue`), because the row map has no type discipline of its own and the only place the invariant can hold is where the value enters it. Byte-identity holds for every spec that worked before; what changes is the shapes that were BROKEN — a string on a non-decimal scalar encoded as a silent `0` (`toFloat64`'s string arm) and is now refused, a non-string on a categorical and an array on a `set_*` both raised `ENCODING_TYPE_MISMATCH` at row time and are now refused at parse / accepted as the option list. `decimal128` keeps its string form, exactly (`encoding.ParseDecimal128`, no float round trip).

**The profile-derived spec is inspectable and modifiable (`--emit-spec` / `--rules`).** `SpecFromProfile` derives a spec and generates from it in one breath and nothing printed it, which made the WHOLE `Spec.Rules` layer unreachable from the profile path — the only path the motivating use case takes — and made authoring a rule guesswork, since `{"when": "familiarity == 1", …}` requires knowing the field is called `familiarity`, that it is a `u4` and that its floor is 1. Two additive `pulse synth from-profile` flags, both inert when absent (`TestSynthFromProfileCLI_EmitSpecDoesNotChangeTheCohort`). `--emit-spec <path>` (`synth.WriteSpec`, indented, through `afero.Fs`) writes **the spec that actually generated, never a rendering or a re-derivation** — the gate is a ROUND TRIP, `synth.SynthBytes(derived)` against `synth.SynthBytes(ParseSpec(emitted))` at one seed compared BYTE FOR BYTE (`TestEmitSpec_RoundTripsToByteIdenticalCohort`), because a test that merely asserts the JSON parses passes against an emit that dropped `models`, coarsened a float or re-derived the document, each of which is silent and each of which this package has shipped. It is equally a DIAGNOSTIC: the emitted spec is the only place a reader sees which captured models survived translation, which distribution each field reconstructed to, and which conditional pairs were retired. It is written BEFORE generation, so a failing run still leaves it. `--rules <path>` (`synth.ApplyRulesFile`) loads a **bare JSON array of rule objects — the `Spec.Rules` array itself**, the format E1 fixed deliberately so the loader needs no translation layer — and **REPLACES** `Spec.Rules`: a derived spec carries none, so there is nothing to append to and an append mode would only invent an ordering question the declaration-order contract would then have to answer forever. `[]` is a legal document meaning "no rules"; `{"rules": […]}` is REFUSED rather than read as zero rules. Validation runs at the LOAD (a profile-derived spec bypasses `validateSpec` by design, so there is no earlier gate) against a COPY, so a refused file leaves `Spec.Rules` untouched; every refusal keeps E1's own `PULSE_SYNTH_RULE_*` code and adds `details["path"]`, because an analyst editing a rules file beside a spec beside a profile cannot act on "rule 2 names field \"x\"" alone — an unreadable file is `DATA_FILE` and a malformed one `SERVICE_VALIDATION`, both naming the path. The load, the merge and the emit all live in `synth/`; `internal/cli/synth.go` supplies paths and routes the coded refusal through `writeCodedErrorEnvelope` (`cliCodedError`) so `errors[0].code` stays usable with `pulse errors lookup`. One byte-layout consequence the round trip forced: `constantRowValue` now accepts a `set_*` constant as a JSON OBJECT (`{"tv": true}`) as well as an array, because `sentinelFor`'s unsummarisable fallback puts a `map[string]bool` on every all-null `set_*` column and that is the one shape in the whole `Spec` that does not decode back to the Go type it was marshalled from — before it, the emitted spec for a survey with one always-null multi-select parsed cleanly and then refused at generation. `format_version` does NOT move and the `--json` envelope is unchanged. Detail: `skills/synth-structural-rules.md` (Reaching rules from a profile) + `docs/src/cli/synth-from-profile.md`.

**Detecting structural rules from the data (`profile create --suggest-rules`).** The rule layer's value is bounded entirely by rule COVERAGE, and rules get written from recall — on the motivating cohort the analyst supplied ONE, and a second and larger one was found by accident while verifying something else. An unstated rule is invisible in the output because **every marginal inside it is individually correct**, which is why no existing instrument catches it. `pulse profile create --suggest-rules <path>` measures, for every low-cardinality field (`categorical_*`, `packed_bool`, `u4`) and every other field, `P(target null | gate = level)` off the SAME single scan (`synth/profile_gating.go`, `ProfileOptions.SuggestRules`; no additional cohort read, counted in bytes the way `TestProfileModels_RidesTheExistingScan` counts them) and proposes a `set_null` rule for each field whose levels split a target's null rate into ~1 and ~0. It writes the BARE rules array `synth from-profile --rules` consumes UNMODIFIED — asserted by a GENERATION round trip, never by comparing shapes, because a test that merely unmarshals the file passes against a document whose predicates do not compile or whose `when` is silently never true. **PROPOSED, never auto-applied**: a detected pattern can be a coincidence of the sample, and a rule applied without review is exactly the silent structural claim this layer exists to remove. **Detection finds the STATISTICAL gate and a human knows the SEMANTIC one** — measured, not hypothetical: on the motivating cohort it proposes BOTH `round(aware) == 0` and the analyst's own `round(familiarity) == 1` with identical evidence to sixteen digits (96,326 rows each, zero exceptions either way), so nothing in the data can separate them and the output must invite correction rather than assert cause. Each candidate carries its own measurement on **`RuleSpec.Evidence` (`_evidence`), THE ONE INERT SLOT** — never read by `compileRules`, the rule pass or `validateRules`, never an action slot (a rule carrying only `_evidence` is still `PULSE_SYNTH_RULE_EMPTY`), harmless when hand-authored, and `omitempty` so a rule without it is byte-identical. It rides the RULE rather than a sibling block because the file must stay a bare array (a wrapper object is refused by design) and because evidence in a second document drifts from its rule the first time a candidate is deleted; the leading underscore is this repo's own `_meta` marker for documentation rather than payload. `Profile.RuleCandidates` is `json:"-"`: absent the flag the profile document is byte-identical, and WITH the flag only `warnings` moves, because an unreviewed structural claim must not ride inside the document that drives generation. Thresholds are package CONSTANTS with their reasoning at the declaration, never `ProfileOptions` fields (`gateHighNullRate` 0.98 / `gateLowNullRate` 0.02 / `minGateLevelSupport` = `MinPairObservations` / `maxGateLevels` 16 / `maxRuleCandidates` 20), matching `minVarianceExplained` and `minLevelObservations`; they are TIGHT because skip logic is EXACT in the source, and a looser pair finds ordinary ASSOCIATION and proposes it as structure — a rule built from a 10/30/50% null rate is applied unconditionally and wrong on most of the rows it selects. **Numeric gates are emitted through `round()`, uniformly, including `packed_bool`**: a bare `==` reads the pre-rounding float and under-fires silently (531 of 901 rows in the committed regression), and a file where one numeric gate is bare and another is not teaches a reader that bare is sometimes fine with nothing saying which. Every emitted `when` is compiled against the rule layer's OWN environment (`rowExprEnv` / `rowExprOptions`) before it is written — never a hand-rolled identifier check, since a field legally named `in` otherwise yields a candidate the loader refuses. Two things are COUNTED rather than dropped silently: a field over `maxGateLevels` is ABANDONED, never truncated (a partial level map makes every rate below it a rate over an arbitrary subset), and a gate whose ONLY gated level is the null pseudo-level is CO-MISSINGNESS rather than value gating — every member of an N-field block reports the other N−1 that way, so proposing them restates one finding N times and buries the real ones (3,932 on the motivating cohort). Thin candidates SHIP with their support attached, warned thinnest-first with a counted remainder. `gated_share` is the `1 - P(gate)` figure that identified this cohort's gate by hand and is a CHECKING aid, NOT the ranking signal: the split test arithmetically implies it, so ranking by it would be ranking by rounding error; ranking is target count then rows affected. **Candidates COMPOSE in declaration order and are not independent statements** — `aware` nulls the five `*Aware` flags and the five later candidates then fire on those nulls too — and **every gating candidate carries `"owns_nulls": true`, which `gateLowNullRate` is what makes sound**: `P(null | open)` IS the residual that flag zeroes, so an admitted candidate is within 0.02 of exact by construction. Without it a `set_null` gate repairs CO-MISSINGNESS ONLY — each target's own `null_rate` keeps firing beneath it, and since that rate is a marginal already inclusive of the gate the two compose as `g + (1−g)·r` (measured: `regard` 0.2526 captured against 0.4369 generated, `people` 0.4273 against 0.7506). Re-measured on the accepted 11-candidate file at 40,000 rows the 50 gated fields move 0.4320 → 0.2455 and `people` 0.7506 → 0.4208, with the coherence table, the emitted ordering and the zero orphan count all unchanged and no claim diverging enough to warn; the five `*Aware` gates' firing counts drop (22,520 → 16,831 for `peopleAware`) because they read `isnull(<x>Aware)` and their gate field is itself one of the 50 — the drop IS the repair. A CO-MISSING candidate never carries the flag: it discards its non-gate members' rates by copying the gate's decision. Measured on the motivating cohort: 8 candidates, all 50 `0.2526093295989762` fields recovered plus the 13-field `0.2649` cluster research had recorded as unexplained, the four-field NPS block recovered exactly, and all 8 firing on 100% of their gated rows when fed back unmodified. `format_version` does NOT move; the manifest golden moved once for `PULSE_SYNTH_RULE_OWNERSHIP_INVALID` and `payload-schema.json` did not. Detail: `skills/synth-structural-rules.md` (Detecting rules from the data) + `docs/src/cli/profile-create.md`.

**Co-missing blocks and always-null columns (the second `--suggest-rules` detector).** The same scan runs a SECOND detector (`synth/profile_comissing.go`) that proposes `null_together` candidates — fields nulled as one question block — into the SAME file, resolving the finding E3-S1 could only COUNT (a gate whose only gated level is the null pseudo-level is co-missingness, 3,932 relationships on the motivating cohort) into one candidate per block. **AN IDENTICAL `null_rate` IS NEVER ENOUGH, and that is the whole surface**: two independent fields can share a rate to sixteen digits and overlap only by chance, so grouping by rate proposes them as a question block, `null_together` then makes the claim TRUE in generated output, and the cohort acquires a structural fact the source does not have. The rate is the GROUPING KEY; admission is **IDENTICAL NULL PATTERN** — null on exactly the same rows — so every member of an emitted block carries `agreement: 1`, an identical `null_count`, and `max_null_rate_deviation: 0`, which is precisely E1-S5's own divergence measure: an emitted block can never trip `nullRateDivergenceThreshold`, no declared rate is discarded, and the member order is ARBITRARY BY CONSTRUCTION rather than a ranking (pattern identity is an equivalence relation, so there is no "cleanest member" inside an exact block). Accumulation is a per-field BITSET over `blockChunkRows` (65,536) rows folded into an F x F co-null matrix by popcount and cleared, so memory is O(F x chunk / 8 + F²) and **flat in the row count** (under 2.5 MB at the cap) while the per-row cost is one bit write per null field; it rides the existing scan with no extra byte, counted the way `TestProfileModels_RidesTheExistingScan` counts them. A per-field null-pattern HASH is the rejected alternative — it answers only the yes/no question, so a near block is invisible to it and indistinguishable from an unrelated field, and it trades an exact answer for a collision that fabricates a question block. A **NEAR block is REPORTED with its agreement and its disagreeing row count, never emitted**: `null_together` has no dial for "almost" and, unlike a gating candidate whose `when` an analyst corrects, there is nothing in it to fix — deliberately unlike E3-S1's THIN candidates, whose relationship is exact and only whose support is thin. The measure is the null-SET overlap (`nearBlockAgreement` 0.95), never row-level agreement: two independent fields each null at 1% agree on 98% of ROWS, so a row-level threshold near 1 floods, and the negative control must therefore include a LOW-rate independent pair or the substitution goes undetected. An **ALWAYS-NULL column is its own ATTENTION finding**, named with its type, kept out of every block and every gate and NOT proposed as a rule (a `set_null` with no `when` would do it; what generation should do about a column summarised over zero observations is a separate decision). Over `maxBlockFields` (256) nullable fields the detector is ABANDONED, never truncated, for the reason `maxGateLevels` abandons — a truncated field set yields blocks that are EXACT among the fields it kept and silently missing the rest, which is the defect this detector exists to remove, now written down as a rule. Blocks rank largest-first, capped at `maxBlockCandidates` (= `maxRuleCandidates`) applied PER DETECTOR rather than to the file, because a shared budget would let twenty gating candidates hide the fact that the cohort has question blocks at all. **EMITTED ORDER IS APPLIED ORDER and a candidate WRITING a field another candidate READS is emitted BEFORE it** (`synth/profile_rule_order.go`, `ruleCandidateOrder`); the detector preference — gating, then blocks, then dependencies — is a READABILITY choice kept wherever nothing forces a move, and candidates are walked in it with a candidate a walked one depends on HOISTED to just before it, never further. Gate-before-block remains right for a block holding a gate's TARGETS and that half is arithmetic rather than luck (identical patterns classify identically at every level of every gate, so a gate takes a WHOLE block or none of one, and both orders reduce to "null iff the gate fired or the first member drew null"), chosen for the file's actual purpose, being EDITED, where a hand-narrowed `set_null` over PART of a block is repaired by a block that follows it. **THE EQUIVALENCE GOVERNS WHAT A GATE WRITES AND IS FALSE FOR WHAT A GATE READS**, which is the inverse hazard E3-S2 shipped and E3-S3 measured: a block member that is a gate's `when` FIELD moves the gate's own INPUT after the gate has read it, so the gate fires on the drawn value, the block then nulls the field it was reading, and the target it left present becomes an answer on a row whose screener the same file says was never asked — 8,693 of 20,000 generated rows on the motivating cohort, where five `*Aware` gates are all members of the 50-field block, and **0** after the reorder, with the coherence table UNMOVED either way because it measures a different gate (a defect invisible to the acceptance table is exactly why the orphan count is its own gate). Only forced candidates move: the 63-target headline gate stays at the top and one block is hoisted ahead of the five gates reading it. The cost is that a hoisted block loses the repair property FOR THOSE GATES, and the trade is deliberately asymmetric — the repair property protects an edit that may never be made, the ordering fault corrupts every row unconditionally. A mutual pair (each writing a field the other reads) has no satisfying order: the closing edge is dropped, the surviving one decides the pair (possibly inverting the detector order, because an edge is a constraint and the order is a preference) and the drop is WARNED about rather than resolved silently. `RuleEvidence` gains `block` rather than a second evidence type so a reader walks one shape and reads `detector`; the five gating-only slots gained `omitempty` (each populated by construction for a gating candidate, so that wire form is byte-identical) while the SHARED slots deliberately did not, because `max_null_rate_deviation: 0` is a real measurement on both. ## Skill Pack

The pack under `skills/` is the LLM surface, embedded via `//go:embed *.md`. Two skill shapes — **atomic** (one file per registered surface) and **topical** (one file per cross-cutting design topic).

### Convention

- **Atomic skill = one operator / tool / type per file.** Stem encodes the surface:
  - `op-agg-<kebab>.md`, `op-attr-<kebab>.md`, `op-filter-<kebab>.md`, `op-group-<kebab>.md`, `op-win-<kebab>.md`, `op-feat-<kebab>.md`, `op-test-<kebab>.md`, `op-reg-<kebab>.md` / `op-reg-mod-<kebab>.md`, `op-synth-<kebab>.md`, `op-overlay-<kebab>.md` — one per registered operator constant.
  - `tool-<kebab>.md` — one per registered MCP tool (drop the `pulse_` prefix).
  - `type-<kebab>.md` — one per `FieldType`.
- **Topical skill = one cross-cutting design topic per file.** ~17 files (`aggregation-design`, `attribute-composition`, `cohort-schema-design`, `compose-requests`, `crosstab-guide`, `facet-design`, `feature-engineering`, `grouper-design`, `join-design`, `label-display`, `overlay-system`, `process-chain`, `regression-modeling`, `request-envelope`, `response-components`, `session-bootstrap`, `spss-cohorts`, `statistical-testing`, `streaming-and-watching`, `synthetic-data`, `window-design`, plus the optional `financial-cohorts` example pack). Atomic skills cross-link into these for the why/how-it-composes prose; the topical files keep no per-operator detail.

### Frontmatter

Atomic:

```yaml
---
name: op-agg-count            # must match file stem
description: <one-line — what this operator does>
kind: operator                # operator | tool | type
category: AGG                 # AGG | ATTR | FILTER | GROUP | WIN | FEAT | TEST | REG | OVERLAY | SYNTH (empty for tool / type)
operator: AGG_COUNT           # full SCREAMING_SNAKE constant (empty for tool / type)
type: reference
applies_to: process, compose, predict
examples_tags: [streaming-friendly, cohort-analysis]
---
```

Topical:

```yaml
---
name: aggregation-design
description: <what the topic teaches>
kind: design
type: guide
applies_to: process, compose, predict
covers: [AGG, FILTER, aggregations, filterers]
---
```

`applies_to` entries must be valid CLI leaves (`process`, `compose`, `sample`, `facet`, `inspect`, `predict`, `manifest`) — or `mcp` on `tool-*` skills.

### Required body sections (atomic skills)

| Family | Required `##` sections |
|---|---|
| `op-*` (default) | `## Params`, `## Inputs`, `## Output`, `## Gotchas`, `## See` |
| `op-agg-*`, `op-group-*`, `op-filter-*` | the above **plus** `## Components` (v0.20.0 `Response.Components` contract — universal floor + per-operator schema must appear here) |
| `op-overlay-*` | `## Params`, `## Host shape` (replaces `## Inputs` — overlays decorate a host result), `## Output`, `## Gotchas`, `## See` |
| `type-*` | `## Bytes`, `## Range`, `## Null`, `## Dictionary`, `## See` |
| `tool-*` | `## When to use`, `## Input`, `## Output`, `## Gotchas`, `## See` |

`TestAtomicSkillHasRequiredSections` keys off the `category:` frontmatter field; stem prefix is the fallback.

### Token budget

Heuristic: `chars / 4 ≈ tokens`. Budgets are byte counts of the post-frontmatter body.

| Family | Budget (chars) | Token target |
|---|---|---|
| `op-*` | ≤1200 | ≤300 |
| `tool-*` | ≤2000 | ≤500 |
| `type-*` | ≤2000 | ≤500 |
| `kind: design` (topical) | ≤6000 | ≤1500 |

`TestSkillTokenBudget` enforces these. The current regime is transitional — the soft cap allows up to 1000% over budget so reviewers see the live state of legacy bodies without a red gate; a follow-up tightens to 30% over and flips `t.Logf` → `t.Errorf` once the offending `op-reg-*` / `op-reg-mod-*` / `op-feat-*` / `op-synth-regex` bodies have been trimmed.

### List source of truth

`skills.List()` walks the embedded `embed.FS` for `*.md` files and parses each frontmatter block. There is no `skills/index.json` — the filesystem is the manifest, and any new file with valid frontmatter is picked up automatically. Manifest visibility lands via the `skills` block emitted by `BuildManifest()`.

### Registered counts

Counts surfaced at runtime via `pulse_manifest` (`commands`, `components.{aggregators,attributes,filterers,groupers,windows,features}`, `tests`, `post_tests`, `synth_distributions`, `regressions`, `mcp_tools`). Never hardcode these in docs — the manifest is the single source of truth and the per-category coverage gates (`TestSkillsCoverAll*`, `TestOperatorHasAtomicSkill`) reject drift.

### Adding a skill

1. Create the file at the conventional stem (`op-<category>-<kebab>.md`, `tool-<kebab>.md`, `type-<kebab>.md`, or a new topical name).
2. Write the required frontmatter for the matching shape (atomic or topical) and the required `##` section set for that family.
3. Stay under budget — atomic op ≤1200 chars body, tool/type ≤2000, topical ≤6000.
4. Run `go test ./skills/... -count=1`. The filesystem walk picks the new file up; no count bump or index entry is needed.

## What NOT to Do

- **Do not import `service/` or `processing/` from `descriptor/`.** Predict/inspect/manifest are no-execute. `TestPredictNoExecutionImports` fails.
- **Do not hand-edit golden files.** Regenerate via `go test ./descriptor/ -run 'Test.*Golden' -update`. `TestGoldensNotHandEdited` verifies hashes.
- **Do not add implementation without tests in the same PR.** TDD.
- **Do not use `fmt.Sprintf` for JSON/XML.** Use `encoding/json` + `descriptor.NewEnvelope(data)`.
- **Do not defer skill or CLAUDE.md updates.** Follow-up PR won't happen. Next session reads stale guidance.
- **Do not add a component without updating the registry** (`processing/registry.go`) + `types.All*Types()`.
- **Do not bypass `afero.Fs`** — defeats `fs.NewMemMap()` + custom-storage extension hook.
- **Do not put business logic in `cmd/pulse/`.** CLI parses flags, constructs library objects, calls methods, formats output.
- **Do not bypass overlay typing via direct payload mutation.** Overlays are read-only siblings keyed to host coordinates — never mutate `Response.Data` / `Response.Crosstab.Matrix` in an overlay handler. The fold writes `Response.Overlays[i]` only.
