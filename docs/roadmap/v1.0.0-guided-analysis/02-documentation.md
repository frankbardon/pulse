# 02 — Documentation: question-first

The mdBook today is organised by **surface**: CLI, library, file format, MCP, internals. That works when you already know what you want. This theme adds a parallel entry point organised by **question**, rendered as much as possible from the purpose metadata in 01, so it stays in sync with the code.

## Proposed new mdBook part

```
# Analysis Guide                         ← new part, placed right after Getting Started
- What can Pulse answer?                 (landing page)
- Describe a measure

```

## D1. "What can Pulse answer?" landing page (Committed)

A single page made of question cards. Each card has a plain question, a one-line answer saying which kind of analysis it is, and a link to its guide:

> **"Are customers in different regions equally satisfied?"** → *Compare groups* · `TEST_ANOVA_F`
> **"Which survey questions move together?"** → *Find relationships* · `MAT_CORRELATION`
> **"Where do customers go after the Basic tier?"** → *Model flows* · `OVERLAY_MARKOV`

The cards are rendered from `Purpose.Questions`, with one or two featured per intent.

## D2. Question guides, one per intent (Committed)

Every guide has the same five sections, so readers learn the layout once:

1. **The question in plain words.** Two or three phrasings, and what it is *not*, e.g. "If you want to know how strongly X predicts Y, see *Explain or predict*".
2. **Decision tree.** A Mermaid flowchart rendered from `Purpose.NotFor` and the intent's shape descriptors. For example, for *compare groups*:

   ```mermaid
   graph TD
     Q{What is the outcome?} -->|a number| N{How many groups?}
     Q -->|yes/no or a category| C[TEST_CHISQ / TEST_PROP_Z]
     N -->|2| T{Skewed or small samples?}
     N -->|3+| A{Skewed or small samples?}
     T -->|no| W[TEST_WELCH]
     T -->|yes| U[TEST_MANN_WHITNEY_U]
     A -->|no| F[TEST_ANOVA_F → TEST_TUKEY_HSD for which pairs]
     A -->|yes| K[TEST_KRUSKAL_WALLIS]
     N -->|several outcomes at once| M[TEST_MANOVA]
   ```

3. **Minimal request.** The smallest runnable JSON, taken from a tagged example, not hand-copied.
4. **Reading the result.** An annotated sample output rendered from `Interpretation`, e.g. "`p_value: 0.003` → below 0.05, so the regions likely differ. `eta_squared: 0.04` → region explains about 4% of the variation: real but small."
5. **Pitfalls.** The top three mistakes: running many tests without correction, reading a non-significant result as "no difference", correlation versus causation, and so on.

Guides are **hand-written prose around generated blocks**. The generated blocks (tree, request, reading) sit between markers and are regenerated by `make docs`; a gate checks they are current.

## D3. Operator catalog (Committed, fully generated)

One page per category (aggregators, tests, overlays…), each a table:

| Operator | In plain words | Answers questions like | Level | Instead, when… |
|---|---|---|---|---|
| `TEST_WELCH` | Checks whether two group averages differ, without assuming equal spread. | "Do new and returning customers spend differently?" | basic | 3+ groups → `TEST_ANOVA_WELCH`; skewed → `TEST_MANN_WHITNEY_U` |

Each row links to the skill (the contract detail) and to an example. The pages are generated from manifest + `Purpose`, so a new operator appears automatically and a missing purpose fails the gate before the page could ship empty.

## D4. "Reading your results" (Committed)

One page per result family. Each walks a real output field by field: what the field is, its range, its bands, and its caveats. Families: `TestResult`, `RegressionResult`, `MatrixResult`, overlay layers, and `Response.Components` (what `n_null` means for your conclusions). These pages are the human-readable twin of `Explain`.

## D5. Glossary (Committed, generated)

An alphabetical page rendered from the glossary registry (01, P4), with anchors so any guide, catalog row or skill can link a term. Each entry has a short definition, why you care, and see-also links.

## D6. Story examples (Committed)

The examples library is already curated and runnable. Extend `_meta` with:

```jsonc
"_meta": {
  "intent": "compare_groups",
  "question": "Do average satisfaction scores differ by region?",
  "interpretation": "p < 0.05 → regions differ; eta² ≈ 0.04 → small effect. Follow with TEST_TUKEY_HSD to see which regions.",
  "level": "basic"
}
```

Then render a *Stories* page per intent: question → request → (golden) output → interpretation. Golden outputs come from the examples test harness, so the story cannot show a stale number. The target is at least one story per intent, and at least one per committed operator in the vector & matrix theme.

## D7. Translation tables (Stretch)

"Coming from…" pages that map familiar names to Pulse:

| SPSS | R | pandas / SciPy | SQL | Pulse |
|---|---|---|---|---|
| `RELIABILITY` | `psych::alpha` | — | — | `MAT_RELIABILITY` |
| `ONEWAY` | `aov` | `scipy.stats.f_oneway` | — | `TEST_ANOVA_F` |
| `CROSSTABS /STATISTICS=CHISQ` | `chisq.test` | `scipy.stats.chi2_contingency` | `GROUP BY a, b` + … | crosstab + `OVERLAY_CHISQ_MATRIX` |

These help the analyst persona, and they are also good synonym input for search (03, M5). Declared as `Purpose.KnownAs map[string]string`, they are generated as well.

## D8. Concept primers for the vector & matrix theme (Committed with that theme)

Four short, illustrated primers: *What is a correlation matrix?*, *What PCA does, in one picture*, *Distance vs similarity* (including the cosine-on-ratings trap from vector-matrix doc 07), *What a perceptual map shows*. Each is about 600 words, written for developers, and linked from the relevant `Purpose.Glossary` terms.

## Gate & build notes

- New pages live under `docs/src/guide/`. `TestSkillsCoverAllCliLeaves` scans `docs/src/`, so a guide must not name a CLI leaf that isn't mounted. Generated pages use real leaf names only.
- `make docs` gains a generation step (`go run ./internal/docgen`). A test (`TestDocsGeneratedCurrent`) re-renders the pages in memory and diffs them against the committed files, using the same golden discipline as `descriptor/testdata`.
