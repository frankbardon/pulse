# Predict / Inspect — the no-execute contracts

Relocated from CLAUDE.md (section `### Predict / Inspect contracts`). CLAUDE.md keeps the always-load half inline — the structural import ban, the no-record inspect rule (header + schema + sidecar metadata), the streamability mirror, and the fact that `CountRecords` is header-fast. Everything below is the long form it points at.

**Load it before changing `internal/descriptor/predict.go`, `internal/descriptor/inspect.go`, `Pulse.Inspect` / `Pulse.InspectEnvelope`, `mcp.InspectOut` / `HandleInspect`, the `pulse cohort inspect` leaf, or `pulse.CountRecords`.** All four surfaces answer the same question over the same bytes and the failure mode they share is SILENT: a floored or truncated count is indistinguishable on the wire from an honest one.

`format_version` does NOT move for anything described here — `descriptor.InspectResult` is not payload-reachable and `descriptor/testdata/payload-schema.json` is untouched. Only the manifest golden moves, and only for the tool description.

## Inspect — the envelope is the only way to see a truncated tail

`descriptor.Inspect` reads only `encoding.ReadHeader` + `encoding.ReadSchema`, never a record. Dictionaries are truncated to `DefaultDictionaryLimit` (100) unless `FullDict: true`. **The contract is "header + schema + sidecar metadata, never records"** (amended at weighting-descriptive E4-S3): the path-based facade also reads the cohort's SPSS metadata sidecar for the suggested weight — see "Suggested weight" below. Metadata beside the cohort is not a record.

`InspectResult.RecordCount` is derived from the file LENGTH, never by reading a record — the cumulative per-shard sum for an archive, that shard's own count for an `archive.pulse#shard.pulse` anchor, and `payload_bytes / record_stride` for a single file.

**`Pulse.Inspect` returns the RESULT only and drops `env.Warnings` on the floor.** `Pulse.InspectEnvelope(ctx, path, *descriptor.InspectOptions)` returns the ENVELOPE and is the only way to reach the `FullDict` knob or the truncated-tail warning.

**Every `pulse cohort inspect` mode reads through the facade.** The `--json` / `--full-dict` branch used to `os.ReadFile` the raw argument itself, which bypassed the injected `afero.Fs` and silently lost anchor resolution — an anchor that inspected fine as text returned `data:null`. A leaf needing options or warnings takes the envelope sibling, never its own read.

**`pulse_inspect` carries the warnings too.** `mcp.InspectOut` EMBEDS `descriptor.InspectResult` and adds an `omitempty` `warnings []*descriptor.EnvelopeEntry` slot; `HandleInspect` reads `InspectEnvelope`, never `Inspect`, for the same reason the CLI does — a floored `record_count` is indistinguishable on the wire from an honest one, so a tool routed through the result-only wrapper left an agent unable to see a truncated tail at all. Embedding keeps every pre-existing key at the top level and a clean read emits no `warnings` key, so the tool's wire form is byte-identical for the ordinary case. The entries are coded `{code, message, details}` (not strings) so the code is usable with `pulse_errors_lookup`, and `details` carries `record_stride` + `trailing_bytes`.

## Byte-level inspect and predict live on the instance

`Pulse.InspectBytes(ctx, data, *descriptor.InspectOptions)` and `Pulse.PredictBytes(ctx, data, *Request)` are the only public byte-level entry points; both return the envelope WHOLE (the result-only-wrapper trap above does not recur). `descriptor.Inspect` / `descriptor.Predict` sniff the zip magic themselves, so one call covers a single file and a whole shard archive. **`PredictBytes` fills every `PredictOptions` field from the instance** — the extension snapshot, `Options.Strict`, `Options.EchoRequest` — because the free functions it replaced left the snapshot to the caller and every nil caller silently treated an embedder-registered operator as unknown. `Pulse.Predict` (path-based, result-only) still passes the snapshot, not `Strict` / `EchoRequest`. **Both pass the instance feature set (`PredictOptions.Instance`)**, so a name a feature profile hides predicts exactly as a never-registered one — every type-keyed predict rule reads the operator's route (`opRoute`), see `feature-profiles.md` (Predict hiding). Gated by `TestPredictBytes_ExtensionOperatorIsKnown`, `TestPredictBytes_HonoursStrict`, `TestPredictBytes_HonoursEchoRequest`, `TestInspectBytes_SurfacesTruncatedTailWarning`.

## Suggested weight — sidecar metadata, never records

`InspectResult.SuggestedWeight` / `PredictResult.SuggestedWeight` (`suggested_weight {field, source: "spss_sidecar", kind: "probability"}`, additive `omitempty`) name the weighting variable the cohort's SPSS metadata sidecar (`cohort.pulse.spss.json`, `payload.weight.variable`) records. Contract: `.claude/reference/weighting.md` (SPSS suggestion).

- **Who reads what.** The FACADE reads the sidecar — `Pulse.sidecarWeightVariable` (root `weight_suggest.go`) through `spss.LoadSidecar` on the instance `afero.Fs` — and hands the variable NAME down: `descx.InspectWith(rs, opts, InspectMetadata{WeightVariable, Instance})` for inspect, `PredictOptions.SuggestedWeightVariable` for predict. `internal/descriptor` never opens a file, so `TestPredictNoExecutionImports` and "predict.go reads only header + schema" both hold. The one judgement is `descx.SuggestWeight(schema, variable, inst)`: nil unless the variable is a column of the schema just read (the canonical schema for an archive; the COHORT schema, not a joined one, for predict) of a weight-capable type (`IsWeightFieldType`) and the instance offers `capability:weighting`.
- **Every failure is silent** — no suggestion, never a warning or error: no sidecar, a malformed / foreign / unknown-version one, a STALE one (the size+mtime fingerprint `LoadSidecar` checks, which `pulse export spss` refuses on), a variable the schema no longer carries or cannot weight by, an anchor path (`archive.pulse#shard.pulse` — a sidecar sits beside a whole cohort file), and the byte-level `InspectBytes` / `PredictBytes` (no path, so no sidecar — `pulse api predict` goes through `PredictBytes` and so never echoes).
- **Predict echoes it as DATA only while no slot resolves a weight field** (`ResolvedWeight.Field` empty everywhere — no weight named, or every slot `weight: null`); never a warning, so `Options.Strict` cannot turn it into an error. It is never applied, by `DefaultWeight` or otherwise.
- `descriptor.InspectResult` / `PredictResult` are not payload-schema-reachable: no payload golden moves; `internal/apigolden` does (additive).

Gates: `TestSuggestedWeight_*` (root: inspect + envelope JSON, absent / stale / malformed / unweighted silent, predict echo, never auto-applied, hidden with `capability:weighting`), `TestSuggestWeight_Rule`, `TestInspect_SuggestedWeightFromMetadata`, `TestPredict_SuggestedWeightIsDataNotWarning`, `TestHandleInspect_SuggestsTheSPSSWeight` (MCP, incl. hidden), `TestCliCohortInspect_SuggestedWeight`.

## Inspect — parent groups are header-only too

For a cohort newer than `0x01`, `InspectResult` adds `layout` (`pulse_format_version`, physical vs logical record stride), `groups` (one `InspectGroup` per group in file order) and a per-field `group: {group, key, kind}` marker. All three are `omitempty` and absent for `0x01`, so a `0x01` envelope is byte-identical to before (`inspect.json` unchanged; `inspect_grouped.json` pins the grouped shape). **Every figure is header + schema + file length:** the entry count is in the schema block and the record count is the SAME `RecordCountForPayload` floor, so `ratio = record_count ÷ entry_count` needs no scan — `TestInspect_GroupFiguresReadNoRecord` garbles every record byte and asserts identical output. The numbers come from `encoding.AssessGroup` and the verdict from `GroupViability.Finding`, the functions the import gate calls, so inspect and `ImportReport.Groups` cannot disagree over the same file (`TestInspect_GroupFiguresMatchImportReport`); inspect judges at `DefaultDedupRatioFloor` because the file does not record the floor it was imported under. A low verdict is a FIGURE, never an envelope warning — `pulse_inspect`'s `warnings` stay header-read diagnostics. `dictionary_bytes` is `len(Group.Entries)`, the resident cost. Labels come from `internal/encoding.GroupSpecOf(schema, g)` — the format has no group name or declaration ordinal, so they number groups by file position. The archive arm reports no groups: grouped shards are refused at archive build, so the case is unreachable today. The facade parity suites compare inspect through `logicalInspect`, which strips exactly these three additions.

## CountRecords — one floor division, two observability contracts

`pulse.CountRecords(ctx, path) (uint64, error)` returns the record total without decoding the payload. Single-file: `(size − header − schema) / record_stride`. Shard archive: the zip central directory + the `_schema.pulse` SHRD trailer's `AggregateRecordCount`. Anchor: the named shard's own count.

**The single-file floor division exists ONCE, at `encoding.Schema.RecordCountForPayload`, which `descriptor.Inspect` calls too.** Identical arithmetic written twice is one edit away from two different counts over the same bytes, and nothing on either wire says which arm produced the number.

**The arms differ in OBSERVABILITY and only there, deliberately.** `Inspect` has an envelope and raises the `ENCODING_INVALID` truncated-tail warning naming the leftover bytes. `CountRecords` has no warning channel and floors SILENTLY, because it feeds the parallel-decode eligibility gate as well as the facade, and a half-written trailing record must not stop a cohort that still processes from reporting its whole-record count. **Do not close that gap by making `CountRecords` error.**

## Predict

`internal/descriptor/predict.go` MUST NOT import `internal/service/` or `internal/processing/` — gated by `TestPredictNoExecutionImports`. Predict duplicates operator knowledge on purpose; reaching for the real implementation to validate params fails the gate.

`PredictResult.Streamable` mirrors the per-type `Streamable()` methods plus schema gates (decimal — built-in aggregators only; an extension aggregator on a `decimal128` field skips that gate, as `processing.canStream` does); an extension operator answers from its DECLARED registration flag on the `ExtensionsSnapshot` (attributes: `Mode`, whose `two_pass` also trips the two-pass combination gates), which is exactly what the runtime routes on. Runtime parity is asserted against `processing.CanStreamRequest(req, schema)` by `TestPredict_Streamable_MatchesRuntime`, and for extension requests against `processing.CanStreamRequestWithExtensions(req, schema, exts)` by `TestExtensions_StreamabilityFollowsDeclaration`. `DefaultsApplied` is always computed, whatever the request.

`PredictResult.CrosstabFusable` (`crosstab_fusable`, `*bool`, nil ⇔ no crosstab spec or a slot refused before dispatch) + `CrosstabFusionReasons` (`omitempty`, every decline in rule order, short stable prose) sit beside `Streamable` and answer a different question: not "can this stream" but "will this instance run the crosstab on the fused in-decode arm" (identical output, `O(cells + margins)` memory). They come from `descriptor.CrosstabFusion` — the shared rule `crosstabfuse.Decide` (`internal/crosstabfuse`, a leaf importing only `types` + `encoding`, so predict reaches it without the engine) over the `ExtensionsSnapshot` + instance feature set — on the defaults-resolved request and the COHORT schema (what `service.processCrosstab` hands `processing.CanFuseCrosstab`). Instance-aware: `PredictOptions.DisableCrosstabFusion` (from `Options.DisableCrosstabFusion`) answers false with `CrosstabFusionDisabledReason`. `Predict` / `PredictBytes` only — Compose and ProcessChain validation do not report it. Not payload-schema-reachable (`PredictResult` is a `descriptor` type), so no golden moves. One sanctioned divergence: a keyable built-in grouper whose factory rejects its params (`GROUP_DATE` `component:"fortnight"`) — runtime declines, predict says true; the request errors on either answer. Gates: `TestStreamability_CrosstabFusionPredictMatchesRuntime`, `TestPredict_CrosstabFusableMatchesRuntime`.

`PredictResult.TimeZones` (`time_zones`, never nil) comes from the SAME pure resolver the runtime calls — `ResolveZones` in `internal/descriptor/zone_resolve.go`, which imports `internal/temporal` (allowed: it is a stdlib leaf, not the engine). Predict runs it on the defaults-resolved clone with `PredictOptions.DefaultTimeZone` / `ZoneLoader`, which the facade fills from the service, so a zone refusal is a predict error (`Valid=false`) exactly when runtime would refuse. A join resolves against the joined schema (`PredictOptions.SchemaLoader` reads the right cohort's header + schema; `internal/encoding.JoinedSchema` is the one rule both sides use), `PredictOptions.DisableDefaults` mirrors `Options.DisableDefaults`, and a slot still without a `Type` is reported with the runtime's own message. More than one `JoinSpec` is refused right after the header + schema read through `internal/descriptor.JoinCountRefusal`, the rule runtime `Process` applies first, so code, message and details `{count}` match; inside Compose / a chain both sides add the location (`details.request` / `details.stage`) through `RefusalAt`, as for a zone refusal. The chain validator's stage gate is `internal/mergegate.ChainRefusal`, the function the runtime calls, and a stage ≥1 carrying `Joins` is `PULSE_CHAIN_STAGE_JOIN` on both sides — detail: `execution-modes.md` (Time zones, ProcessChain).

`PredictResult.Weights` (`weights`, `omitempty`) comes from the SAME pure resolver the runtime calls — `ResolveWeights` in `internal/descriptor/weight_resolve.go` (slot `weight` → request `weight` → `PredictOptions.DefaultWeight`, which the facade fills from `Options.DefaultWeight` → none). It runs right AFTER the field-reference rule on both sides (the runtime folds it into `checkFieldRefs`; Compose / chain validators run it only when a slot's references pass, located through `RefusalAt`), against the joined schema for a join. One entry per weight-bearing slot `{slot, operator, field, kind, status, source}`; the key is omitted when neither the request, a slot, nor the instance names a weight, so an unweighted predict payload is unchanged. Contract: `.claude/reference/weighting.md` (Resolution order).

`PredictResult.PValues` (`p_values`, `*descriptor.PValueCount` `{total, uncorrected, basis, threshold}`, `omitempty`) answers "how many inferential p-values does this Request emit, and how many does no multiplicity block correct" — the trigger data for a multiple-comparison nudge (`descriptor.MultiplicityTriggerThreshold` = 10, echoed as `threshold`; the `PULSE_ADVISORY_MANY_TESTS` advisory reads `p_values` and that constant — see "Advisories" below). `internal/descriptor/predict_pvalues.go` (`countPValues`) reads only the request, the resolved `MultiplicityPlan` (`ResolveMultiplicity`, the same call the runtime makes) and the schema's dictionaries. Tests and post-tests count one each, `TEST_TUKEY_HSD` none (already family-wise); an `Inferential` overlay kind counts the p-values its payload carries, `uncorrected` being those no resolved block reaches. `basis`, weakest wins: `exact`; `dictionary` (an axis is one `GROUP_CATEGORY` over a categorical or `packed_bool` field, so the cell count assumes every dictionary entry becomes a bucket — an over- or under-count when a filter empties some); `lower_bound` (an axis the schema cannot size counts as one). Only `Predict` / `PredictBytes` report it — Compose, chain and facet validation do not. Omitted when the request emits no p-value and when `capability:multiplicity` is hidden. `PredictResult` is a `descriptor` type, so no payload-schema golden moves. Gate: `TestPredict_PValues`, `TestPredict_PValuesFollowInstance`, `TestPredict_PValuesOmittedOnRefusal`, `TestMultiplicityTriggerThreshold`. Contract: `execution-modes.md` (Multiplicity).

**`PredictResult.Sizes`** (`sizes`, additive `omitempty`) is reported on EVERY single-cohort predict, with or without a `return` block — one `ResponseSectionSize {section, full_bytes, shaped_bytes, basis}` per top-level Response section the request produces (`data`, `metadata`, `tests`, `post_tests`, `regressions`, `matrices`, `crosstab`, `overlays`, `components`), in Response key order, from `internal/descriptor/predict_return_sizes.go`: each section is a tree mirroring its JSON shape, rows or cells × a bytes-per-value model; `full_bytes` is the tree's sum and `shaped_bytes` walks the SAME tree through the plan's `Visit`, so `shaped ≤ full` by construction and an excluded section is 0; with no effective plan (`ResolveReturn` nil) `shaped_bytes == full_bytes`, and a refused block withholds `sizes` entirely. Rows come from `vectors.EstimateBuckets` (the rule `MatrixPredict` reports; `Groups[0]` only, as the engine executes) clamped to the record count, crosstab cells from each axis's per-grouper key counts, matrices from `MatrixPredict.EstimatedBuckets`. A section whose count depends on data — `BucketBasis` `unknown`, a join's open column set, a row-level output with no record count — is OMITTED, never guessed; `components` is sized only when computed (`componentsDisabled`). `basis` describes the count: `exact` (ungrouped aggregation row, ungrouped matrix), `upper_bound` (dictionary / include / boolean / quantile buckets, crosstab axes, a row-level output's record count) or `heuristic` (tests, regressions, overlays, metadata, components). The record count is derived from the file LENGTH (`deriveSingleFileRecordCount`, Inspect's own arm) for a single file and from the per-shard header peek for an archive (passed into `predictSingle`, since the canonical `_schema.pulse` has no records); `RecordCount` stays the archive-only figure it documents. Guidance only — no byte-accuracy gate. Chain validation reports no sizes. `PredictResult.Return` (`return`, the resolved plan — nil when no layer supplies a block) carries **`unresolved_includes`** (#217, additive `omitempty`) — the plan's Open include paths (through a map key or an open value) predict cannot resolve without data, less every `data[*].<column>` include it matches against a CLOSED output-column set (`returnOutputColumns`); at runtime each may match nothing, which a buffered run warns as `PULSE_RETURN_PATH_UNMATCHED` and a stream never reports (streams stay silent by design). `PredictResult` is a `descriptor` type, so no payload-schema or manifest golden moves; the API golden and the predict goldens (`sizes`) do. Gates: `TestPredict_Sizes_NoReturnBlock`, `TestPredict_ReturnSizes_ShapedNeverAboveFull`, `TestPredict_ReturnSizes_ExcludedReportZero`, `TestPredict_ReturnSizes_Basis`, `TestPredict_ReturnSizes_ArchiveRecordCount`, `TestPredict_ReturnUnresolvedIncludes`.

`PredictResult.Matrices` (`matrices`, `omitempty`) reports per matrix spec its shape, axis keys, labels, missing mode, encoding, estimated accumulator bytes, streamability and `pairwise_psd_risk` — read off the runtime's own resolver and the shared no-execute rules in `internal/vectors/matrix_rules.go`, which the engine's `PULSE_MATRIX_NOT_PSD` check also gates on. Long form: `matrix-and-vectors.md` (Predict bullet of the Matrix slot section).

**`PredictResult.LimitFindings`** (`limit_findings`, additive `omitempty`, `[]descriptor.LimitFinding {limit, configured, estimated, grade}`) lists every instance resource limit (`pulse.Limits`, read off `PredictOptions.Instance.Limits()` — pulse.New installs the resolved limits on the snapshot, so `Predict` / `PredictBytes` / MCP `pulse_predict` / the CLI all see them without a new option) that a figure predict computes from the request + schema exceeds. `grade` is `certain` (the exact figure the runtime sees) or `possible` (an upper bound). A CERTAIN finding also adds the `PULSE_LIMIT_EXCEEDED` error the runtime raises — so `Valid` is false; a POSSIBLE one is reported only and never refuses. It is ONE rule, not a predict-only check: `internal/descriptor.RequestLimitFindings` (`limits.go`), over the leaf `internal/limits` (`Grade`, `Finding`, `Evaluate`, `Check*` — stdlib + `types`/`encoding`/`errors` only, `TestLimits_ImportBoundary`), and the runtime calls it as `LimitRefusal` from `Service.limitsPreflight` right after `checkFieldRefs` on every Request arm (serial dispatch, crosstab, join and joined crosstab — through `openJoinStream`'s preflight hook, before the build side decodes — chain stages ≥ 1; stage 0 and Compose slots pass through `Process`) — so a certain breach is refused with the identical code, message and details before any record decodes. Today: `MaxGroups` (`possible`, never a refusal — `EstimateGroups`: `vectors.EstimateBuckets` for Groups[0] plus `GROUP_DATE_RANGES` as its range count + the unmatched bucket (a named table's `range_count` off the snapshot), clamped by the header record count except the fan-out `GROUP_SET_PER_ELEMENT`; `GROUP_RANGE` / `GROUP_DATE` / `GROUP_ROUNDED` / `GROUP_SET_VALUE` and extension groupers yield no finding; the pre-flight reads the count only when `MaxEstimatedMemory` is set — a `possible` finding never refuses, so it needs none; the runtime counts at every bucket mint — `execution-modes.md` (Parallel shards — the resource-limits paragraph)), `MaxCrosstabCells` (`possible` — `EstimateCrosstabCells`: the rows × columns product of each axis's per-position `EstimateGroups` bounds, each axis clamped by the header count unless a position fans out; any unknown position yields no finding; the runtime checks both arms — `execution-modes.md` (Crosstab — the resource-limits paragraph)), `MaxEstimatedMemory` (`certain`, only when set — Unlimited by default, so opt-in; see the memory paragraph below), `MaxMatrixDim` (each matrix's resolved member count, `vectors.ResolveMatrices`) and `MaxJoinBuildRows` (a single join's right-side record count, read header-only through `PredictOptions.RecordCounter` — the facade wires `Service.CountRecords`, never `Cohort.RecordCount`; the right side is decoded unfiltered, so the count is exact and the finding `certain`). The runtime refuses `MaxJoinBuildRows` in `openJoinStream` — shared by the joined Process and the joined crosstab — on the same header count before the build decodes a record, plus an in-loop backstop for a miscount; an Unlimited limit skips the count. The rules read `LimitInputs` beyond request + schema: `Records` (the header count, -1 unknown — the pre-flight reads it only when `MaxEstimatedMemory` is set), `ShardRecords`, `Join` / `JoinRightRows`, and the arm facts `Extensions` / `FusionDisabled`. `MaxComposeSlots` / `MaxChainStages` are fan-out counts checked at the Compose (serial and parallel — the whole call; `FailFast` does not apply) and chain entries right after the empty check; predict has no Compose / chain surface. `PredictResult` is a `descriptor` type, so the payload-schema golden does not move; the API golden does. Gates: `TestLimits_MatrixDim_PredictCertainAndProcessRefuses`, `TestLimits_ComposeSlots`, `TestLimits_ChainStages`, `TestLimitsPreflight_MatrixDimRefusesBeforeDecode`, `TestLimits_JoinBuildRows_PredictCertainAndProcessRefuses`, `TestLimits_JoinBuildRows_PredictReadsRightHeaderOnly`, `TestLimitsPreflight_JoinBuildRowsRefusesBeforeDecode`, `TestLimitsPreflight_JoinBuildRowsLoopBackstop`, `TestEstimateGroups`, `TestPredict_MaxGroupsClampedByHeaderCount`, `TestLimits_MaxGroups_PredictPossibleAndProcessTrips`, `TestRequestLimitFindings_MaxCrosstabCellsPossible`, `TestLimits_MaxCrosstabCells_BothArms`.

**The memory estimate (`MaxEstimatedMemory`, U19 E2-S3).** `internal/descriptor.EstimateMemory` picks the arm the engine dispatches (`MemoryArm`: the fused crosstab iff `CrosstabFusion` accepts and neither a join nor `DisableCrosstabFusion` declines; else buffered for a crosstab; otherwise streaming iff `computeStreamable`) and evaluates the leaf model `internal/limits.EstimateMemory` (`memory.go`) on: the header record count (a join's left side; a chain stage's input rows, counted exactly), the schema stride and `limits.RecordBytes` (one buffered record at FULL schema width: header + a slot per field and per set-mask / parent-group word + bit planes + the decimal aux block), the group bound (`EstimateGroups`, or the record count for an unknown grouper), the crosstab grid (`EstimateCrosstabCells`, or the record count), aggregations (the cell and `margin_aggregations` included) and how many keep per-value state (distinct / mode / frequency families), derived columns (attributes + features + windows), a join's right header count, and the matrices' `MatrixStateBytes` (= `estimated_bytes`). Formula: base 16 MiB + 3 × records × stride (the payload a non-mmap fs reads onto the heap plus the collector's GOGC headroom) + right rows × (3 × stride + 2 × record bytes) + matrix state + records × 96 per value-state aggregation; buffered adds records × (record bytes + 16 × aggs + 128 × derived) + buckets × (512 + 256 × aggs) + cells × 512; streaming adds buckets × (512 + 256 × aggs); fused adds cells × 512. Unknown record count (or a join's right count) → no estimate, no finding. The rich facet has its own estimate and pre-flight (`EstimateFacetMemory` / `FacetLimitRefusal`, `execution-modes.md` (Facet endpoints)). It is an UPPER bound by design — no filter selectivity, no field projection, every dictionary entry assumed — graded `certain` because predict and the pre-flight compute the identical figure from the identical header counts, never because it is exact. **Calibration** (`TestMemoryEstimate_Calibration`, `internal/service`, skipped under `-short`): `buildWideCohort` 95 fields × 200,000 records (stride 228 B), peak heap = the sampled `HeapAlloc` high-water mark above a post-GC baseline (never `B/op`), estimate read back as the runtime's own refusal figure; estimate ≥ peak on every arm, factor (estimate / peak, Apple M1 Max): buffered full width 1.49 (413 vs 278 MB), streaming 1.95 (154 vs 79 MB), streaming grouped 1.90, value-state stream 2.13, fused crosstab 1.76 (154 vs 87 MB), matrix 1.89, lookup join 1.34 (176 vs 131 MB), join build side 1.46 (738 vs 505 MB), rich facet 1.33; with field projection (default-on) the model cannot see the narrowing — buffered projected 4.94 (413 vs 84 MB), streaming projected 3.36, buffered crosstab 3.72 — so the documented ceiling is 2.5× unprojected and 6× projected. A schema with many more narrow fields, a GOGC above 100 or a fan-out (1:N) join can exceed it. `PredictResult.Matrices[].EstimatedBytes` moved in place to merge blocks × buckets × `accumulator_bytes` (`matrix-and-vectors.md`). Gates: `TestEstimateMemory_PerArm`, `TestRecordBytes`, `TestMergeBlocks`, `TestMergeBlockSizeMatchesLinalg` (`internal/limits`), `TestMemoryArm`, `TestEstimateMemory_Terms`, `TestRequestLimitFindings_MaxEstimatedMemoryCertain`, `TestPredict_MaxEstimatedMemory`, `TestFacetLimitRefusal` (`internal/descriptor`), `TestLimitsPreflight_MaxEstimatedMemoryRefusesBeforeDecode` (every host: serial streaming + buffered, crosstab, matrix, facet, plain join, joined crosstab — no cohort drained, the run AT the estimate drains), `TestMaxEstimatedMemory_DefaultReadsNoCount`, `TestMaxEstimatedMemory_ChainStage`, `TestMemoryEstimate_Calibration` (`internal/service`), `TestLimits_MaxEstimatedMemory_PredictCertainAndProcessRefuses` (root, every arm incl. a shard-archive matrix: identical error on predict, MCP and the run).

**Field references are one rule, not a predict-only check.** Whether a name a slot references exists is `internal/descriptor.FieldRefRefusals` (`field_refs.go`), which the runtime calls too (first entry, via `FieldRefRefusal`) — so an unknown name is refused with one code, message and details on both sides, where the runtime used to read it as an all-null column and answer with wrong numbers. Predict reports every entry right after zone resolution, on the defaulted clone and the joined schema; the per-family validators (`validateFeatures`, `validateRequestFields`, `validateTests`, `validateRegressions`, `validateWindows`, `validateSort`, `validateCrosstab`) keep only the checks on fields the schema carries (types, orderability, decimal) and must NOT re-grow an existence check (window `order_by` orderability is NOT one of them any more: it is `IsOrderableType`, applied inside `FieldRefRefusals` so the runtime refuses what predict refuses — every type but `set_*`, following the runtime comparator: a categorical by dictionary LABEL, byte-wise, never by index, which shifts across imports and shards; `date` / `datetime` by signed epoch, pre-1970 first; `packed_bool` 0/1; `decimal128` by `Decimal128.Cmp`; nulls last; `TestWindowOrderBy_CategoricalOrdersByLabel`, `TestWindowOrderBy_OrderabilityPredictMatchesRuntime`) — a second copy is how the two sides drifted. The same walk refuses a derived name (attribute label, feature output, window label) that SHADOWS an available column, and an aggregation label that collides with a group field or another aggregation label in the output row, on both sides (`execution-modes.md`, Predict and the validators). Derived names follow the runtime's own naming and PIPELINE order (features → filterers → attributes → record consumers → output-row consumers); the walk is documented on the function. It also judges names inside params (the built-in `aggParamFieldKeys` / `postTestParamFieldKeys` tables) and an extension's `FieldInputs` declaration, which reaches the no-execute layer as `ExtensionsSnapshot.FieldInputs` — so predict takes the snapshot (`PredictOptions.Extensions`) and the service passes its own; `ValidateFacet` / `FacetSchema` apply its filterer half (`FacetFieldRefRefusals`). Join keys likewise: `internal/encoding.JoinKeysRefusals` is the one kind / OnPair rule (`PULSE_JOIN_FIELD_UNKNOWN {field, index}` and siblings), reported by predict right after the right schema loads and by `ValidateJoin`. Detail: `execution-modes.md` (Predict and the validators).

**Field-type acceptance is gated table-wide.** `TestFieldTypeAcceptance_PredictMatchesRuntime` (root `field_type_acceptance_test.go`) runs every registered operator — aggregators, attributes, features, groupers, windows, filterers, tier-1 tests, regressions — over a cohort carrying one column of every field type, through `Process` and predict, and requires the two to accept exactly the same types. A runtime refusal raised after the type was accepted (too few rows or groups, a degenerate table, a rank-deficient design — `acceptanceDataOutcomes`) counts as acceptance. The disagreements that remain are the `knownTypeDivergence` ledger, which is EXACT: an entry that stops diverging fails the gate, so the fix that closes one deletes it. The ledger holds two directions only — predict LOOSER (a runtime constructor's type check predict lacks: `set_*` on value-reading operators, a non-set column on a `*_SET_*` operator, decimal128 on an aggregator without a decimal arm, where predict only warns, `*_DATE_RANGES` / `FILTER_TRUE`/`FALSE` type gates, …) and predict STRICTER where the runtime is WRONG (it reads a categorical's dictionary index or a set's bitmask as a number: `FEAT_POLY`, regressions on a categorical predictor, value-bearing windows). Predict stricter than a CORRECT runtime is a predict bug and is fixed, never listed: `FEAT_POLY` judged its field with the strict `FieldType.IsNumeric` and refused `u4` and `date`, which the runtime expands and `op-feat-poly` documents; it now reads the operator's own capability declaration (`featureAcceptsType` over `featureCapabilities` `AcceptsTypes`, which gained `decimal128` — the runtime expands it through the f64 echo), so the manifest's `accepts_types` and predict cannot drift.

Debugging procedure: `docs/src/internals/debugging-predict.md`.

## Advisories

**`PredictResult.Advisories`** (`advisories`, additive `omitempty`, `[]descriptor.Advisory {code, message, details}`) carries coded, non-blocking notes that the chosen analysis may not fit the data — a separate slot from the envelope's warnings, because an analysis choice is not a data or engine problem and agents filter them independently. Rules (U22 E1):

- **Never a warning, never escalated.** No advisory is ever appended to `env.Warnings` or `env.Errors`, so `PredictOptions.Strict` / `Options.Strict` / `--strict` cannot promote one and `Valid` never moves. **Never a change to execution** — the runtime never reads advisories.
- **On the result itself.** `Pulse.Predict` keeps only `env.Data`, and MCP `pulse_predict` returns that `PredictResult` (`PredictOut`), which is why the slot is on `PredictResult`, not the envelope. `PredictBytes` / `pulse api predict --json` carry it in `data.advisories`; the text leaf prints one `Advisory [CODE]: message` line each.
- **Predicates** live in `internal/descriptor/predict_advisories.go` (`computeAdvisories`, called last in `predictSingle` on the defaults-resolved request over the schema it executes over), under the predict import ban. Trigger principle: authoritative metadata only — the request, the schema's dictionaries, figures predict already computed (`p_values`), later the SPSS sidecar — never field-name or value-shape heuristics. Computed whether or not the request is valid.
- **Codes** are `PULSE_ADVISORY_*` entries in `errors/codes.go` (`allCodes`) + `codeMetadata` (Message + text Fixup) + an `error_owners.go` owner, AND an entry in `advisoryCodes` (rule order; `TestAdvisoryCodesRegistered` keeps the registry and the catalog equal). `details.suggested` is a replacement operator name or a request patch, never a rewritten request; there is no new `FixupAction`.
  - `PULSE_ADVISORY_TWO_GROUP_TEST_MANY_GROUPS` (owners `TEST_T`, `TEST_WELCH`): a `TEST_T` / `TEST_WELCH` slot (tests, then post-tests) whose `split_by` is a categorical field with more than two dictionary entries; exactly two and `packed_bool` never fire. `split_by` admits no grouper, so the dictionary count is the only computable figure. `details {slot, operator, field, split_by, groups, suggested}`, `suggested` = `TEST_ANOVA_WELCH`, else `TEST_ANOVA_F`, else absent.
  - `PULSE_ADVISORY_MANY_TESTS` (owner `capability:multiplicity`): `p_values.uncorrected >= MultiplicityTriggerThreshold` and `ResolveMultiplicity` returned a nil plan — nothing (request, slot, `Options.DefaultMultiplicity`) names a block, `method: none` included. The message says "at least N" on a `lower_bound` basis and "an estimated N" on `dictionary`. `details {total, uncorrected, basis, threshold, suggested: {"multiplicity": {"method": "holm"}}}`.
- **Profile-scrubbed.** An operator named in a message or `details.suggested` is one the instance offers (`InstanceSnapshot.Enabled`); a hidden `TEST_T` routes as never-registered and fires nothing; a hidden `capability:multiplicity` withholds `p_values`, so MANY_TESTS never proposes it.
- **Suppression.** `Options.SuppressAdvisories []string`, validated at `pulse.New` against the whole registry (`ValidateSuppressAdvisories`; unknown → `PULSE_SUPPRESS_ADVISORY_UNKNOWN`, `details {code, valid}`; a code a profile can never fire is accepted), installed on the instance (`InstanceSnapshot.WithSuppressedAdvisories`, not in the feature-set digest) so every predict path drops it. No per-request or CLI knob.
- **Payload schema.** `descriptor.Advisory` is an ungated root of the payload schema (`PredictResult` itself is not payload-reachable); `format_version` stays `"1.1"`.

Gates: `TestPredict_AdvisoryTwoGroup`, `TestPredict_AdvisoryTwoGroupNeverProposesHidden`, `TestPredict_AdvisoryManyTests`, `TestPredict_AdvisoryManyTestsFollowsInstance`, `TestPredict_AdvisoriesSuppressed`, `TestPredict_StrictNeverEscalatesAdvisories`, `TestPredict_AdvisoryFreeOutputOmitsTheKey`, `TestAdvisoryMessagesPassProseLint`, `TestAdvisoryCodesRegistered`, `TestValidateSuppressAdvisories` (`internal/descriptor`); `TestNew_SuppressAdvisoriesUnknownIsCoded`, `TestPredict_AdvisoriesReachTheFacade`, `TestPredictBytes_StrictNeverEscalatesAdvisories`, `TestAdvisories_NeverChangeExecution`, `TestHandlePredict_CarriesAdvisories` (root); `TestAPIPredict_ShowsAdvisories` (`internal/cli`). Skill: `skills/predict-advisories.md`.

## Import predict is not descriptor predict

`io.ImportJob.Predict` (`pulse import predict`) is the ONLY predict that may read source rows, and none of the rules above bind it — it lives in `internal/io/` (aliased by public `io`), not `internal/descriptor/`. Its measured pass (declared `Groups`, `ElideConstants`, or `SuggestGroups`) converts every row through `rowConverter`, the converter `Run` uses, and derives group figures through `encoding.DedupGate` / `AssessGroup` / `PlanConstantElisionFor` — so import predict, `ImportReport.Groups` and inspect report the same numbers for the same data (`TestImportPredict_DeclaredGroupsMatchImport`, `TestImportPredict_SuggestedMatchesImport`). Candidate detection nominates over a bounded window and confirms on the full pass; it suggests, never declares. Without those three knobs predict keeps its plain row-count pass and its report is unchanged.

## The CLAUDE.md Inspect bullet, pre-compression (relocated verbatim at weighting-descriptive E1-S1)

- **Inspect header-only:** reads only `encoding.ReadHeader` + `encoding.ReadSchema`; dictionaries truncated to `DefaultDictionaryLimit` (100) unless `FullDict: true`. `InspectResult.RecordCount` is derived from the file LENGTH, never by reading a record. **`Pulse.Inspect` drops `env.Warnings` on the floor** — `Pulse.InspectEnvelope` is the only way to reach the `FullDict` knob or the truncated-tail warning, and both the CLI leaf and `pulse_inspect` therefore read the envelope, never the result-only wrapper.
