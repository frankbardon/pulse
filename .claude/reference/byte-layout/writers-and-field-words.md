# Byte layout — the row builder, Materialize, wide-set word order, vector fields, temporal words, import datetime literals

Per-topic slice of the byte-layout reference. Index: `.claude/reference/byte-layout.md` — load it first, then only the slice(s) your change touches.

**Row-at-a-time builder — `Pulse.NewCohortBuilder`.** The public write path for a NEW cohort from typed rows (`pulse.CohortRow`); engine `internal/io.CohortBuild` (`cohort_build.go`).

- **Byte identity with import is the contract.** The builder runs import's explicit-schema code for every byte-deciding step (dictionary assignment with the declared rung as ceiling, decimal rescale, set cells, cell layout, description length) and, with `CohortBuilderOptions.Groups` / `ElideConstants`, import's group path (declaration check + width screen at construction; full-pass constant detection, elision plan, one encode pass and ratio check at `Close`, all before anything is published). A divergence is silent — both files read fine. Gates: `TestCohortBuilder_ByteIdenticalToImport`, `TestCohortBuilder_GroupedByteIdenticalToImport`. Change the shared import code, never fork it.
- **Atomic write:** rows spool as logical records to `<target>.build-spool-*.tmp` beside the target on the instance afero FS (dictionaries precede records, so the preamble is written last); `Close` assembles `<target>.build-*.tmp`, fsyncs, renames. `Abort` or any failure removes every temp and leaves the target untouched. `service.atomicWrite` stages in `filepath.Dir(dst)` — never `""`, which afero maps to `os.TempDir()` outside a `DataDir` base path.
- **Sidecars:** a build never touches sidecars. `Overwrite` replaces the bytes, so the index and SPSS sidecar self-invalidate via their fingerprints and are reported on `CohortBuildResult.InvalidatedSidecars` (enumeration failure is a warning). A replaced managed import has its expiry slid (`touchManaged`), as in-place dedup does. Refused: a `.zst` target, parent groups inside the schema (declare them in `Groups`).
- **Sharded build** (`CohortBuilderOptions.Shards`, `ShardSplit{MaxRecords}`): one full pass over every row, so gate verdicts, elision and dictionaries are archive-wide; the payload is cut at `RecordByteSize` boundaries into `part-NNNNN.pulse` shards with preambles byte-identical to one another and handed to ONE `CreateShardArchive`. Cap: 65,535 shards (`internal/io.MaxBuildShards`, the u16 trailer count).
- **Anchored append** (`archive.pulse#name.pulse`): ONE shard added to an EXISTING archive (never created implicitly). The name must be a plain basename the archive lacks (`PULSE_SHARD_NAME_COLLISION`; `_schema.pulse` is `PULSE_SHARD_RESERVED_NAME`); `Groups` / `ElideConstants` / `Shards` / `Overwrite` are refused (`reason: append_option`) because the archive's layout wins. Cohesion is pre-checked at construction by running `AddShard`'s row-independent merge prefix over a zero-row shard (`service.PrecheckShardCohesion`), so a refusal carries `AddShard`'s exact code; `AddShard` at `Close` stays the authority (`TestCohortBuilder_AppendPrecheckParity`). Its mandatory `PULSE_SHARD_SET_WIDENED` / `PULSE_SHARD_GROUPS_REWRITTEN` warnings pass through to `CohortBuildResult.Warnings`.

**Materialized derived columns — `Pulse.Materialize`.** Writes a NEW cohort holding every filter-passing source record plus one nullable `f64` per derived output (features, attributes, windows) — except an attribute that inherits its source's dictionary (`ATTR_PREVIOUS_STATE`, or an extension declaring `InheritsDictionary`), written as its state field's own `categorical_*` / `packed_bool` type and dictionary. No format change.

- **Engine:** `Processor.DeriveRecords` runs the buffered steps before grouping over a FULL, unprojected decode; survivors map back to their source index before any sort, and `Request.Sort` only permutes emit order, so window values never depend on it. Column labels and descriptions come from `internal/descriptor/materialize.go` (`MaterializeColumns`), shared with predict.
- **Source cells** come from `CohortReader.RecordAt` (exact typed values; archive index global in shard order), never from the decoded `Record`, which loses types and omits nulls.
- **Default layout:** the source's LOGICAL `Schema.Fields` verbatim (never its groups), then derived fields in pipeline order. Always written through `NewCohortBuilder`, so the output is `0x01`, or `0x02` when it keeps a `vec_*` field (re-indexed).
- **The `output` slot** (`types.MaterializeOutput`, materialize-only — elsewhere `PULSE_MATERIALIZE_OUTPUT_ONLY`) is resolved LAST by `descx.MaterializeOutputLayout`, so every other slot reads the full schema; absent `output` is the identity layout, byte-identical (`TestMaterialize_AbsentOutputIsByteIdentical`). `columns` (closed, ordered; `from` / `as` / `description` / `nullable` / `type`) XOR `exclude`. A `type` cast is exact or `PULSE_MATERIALIZE_CAST_FAILED` (integers never through `float64`); a null in a `nullable: false` column is `PULSE_MATERIALIZE_OUTPUT_NULL`, nothing written.
- **Groups** (`output.groups`): absent INHERITS each indexed source group whose every member is written unchanged, else `PULSE_MATERIALIZE_GROUP_NOT_INHERITED` (fatal under Strict); a list declares over written names; `[]` none; constant groups are never inherited.
- **Container:** `output.shards: {max_records}` → the sharded build (`max_records ≤ 0` is `PULSE_MATERIALIZE_OUTPUT_INVALID`; the row that would open shard 65,536 is `PULSE_SHARD_COUNT_LIMIT`); `elide_constants` → import's full-pass elision. An anchored target is refused.
- **Sidecars:** the source's SPSS sidecar is CARRIED (read before the write, re-fingerprinted over the output): without `output` via `SidecarCarry.WriteFor` with a plain numeric variable per derived column (a previous-state column copies its state variable's description, or the carry is refused rather than mis-described); with `output` via `WriteProjected` (next paragraph). No other sidecar is carried; an Overwrite reports stale ones (`PULSE_MATERIALIZE_SIDECARS_INVALIDATED`).
- **Memory pre-flight** is Process's on the buffered arm (every accepted request is non-streamable).

**Projected SPSS carry — `SidecarCarry.WriteProjected`.** A Materialize `output` block carries the SPSS sidecar through `internal/io/spss/carry_projection.go`, one `ProjectedColumn{From, Label, Rebuild, Mirror}` per written column in output order:

- Variables re-laid in output order, indices recounted.
- DROPPED column → its variable, registry entry, very-long-string declaration, variable-set membership, every multiple-response set naming it and the weight (if it was the weight) go.
- RENAMED → keeps codes, labels, missing spec, formats AND its short name (records 7/5, 7/7, 7/14, 7/19 key by it); the new name becomes its long name; registry sources, set fields and weight follow.
- DUPLICATE → the variable stays on the copy keeping the source's name (else the first); other copies are deep copies under fresh short names.
- REBUILT (re-coded by cast / recode / bucket) → regenerated by `spss.RebuildVariable` from the written type and dictionary; no old label, code or missing spec lands on the new codes.
- Refused (not carried, one warning) rather than mis-described: a kept registry column reading a dropped column, a duplicated registry column or very long string, a rebuilt column a registry / response set / very-long-string layout names, two output names SPSS case-folds together.

**Wide-set word order — `set_u128` / `set_u256`.** A wide set field's payload is a fixed-width bitmask of 16 or 32 bytes, read and written ONLY through `encoding.SetMask` and its wire API (`PutSetMask` / `SetMaskFromBytes`, `WriteSetMask` / `ReadSetMask`); the `uint64` value API refuses both rungs with `ENCODING_TYPE_MISMATCH` rather than truncate.

- **The word order is normative: `words[0]` is bits 0–63 (the LOW 64 bits), then `words[1]` bits 64–127, `words[2]` 128–191, `words[3]` 192–255, laid on the wire in that order, each word little-endian.** The payload is the little-endian byte image of the 128/256-bit integer, so **the low 8 bytes of a `set_u128` are byte-identical to a `set_u64` with the same selections** — which makes narrow→wide promotion a pure append of zero bytes. Reverse either order and every existing cohort decodes as a different, plausible selection: no length change, no error. SILENT.
- Bit `i` ↔ dictionary entry `i`; an empty mask is "no selection", distinct from null; nulls ride the bitmap only, so a null row still carries its full 16/32 bytes. A bit at or above `FieldType.MaxSetEntries()` is `ENCODING_INVALID` on write and `PULSE_SHARD_DICT_WIDTH_OVERFLOW` on the shard dict-remap path.
- **Import set-rung promotion relies on it.** An INFERRED set rung whose tokens a later cell outgrows climbs `set_u8` → … → `set_u256` (`internSetOrWiden`, `internal/io/import_widen.go`; one `PULSE_IMPORT_WIDTH_PROMOTED` per field); the rows already held re-stride by zero-extending each mask (`widenBufferedColumn`, set_u64 → set_u128 included), so the cohort is byte-identical to a whole-file-sample import (`TestImportWiden_SetByteIdenticalToFullSample`). A declared rung, or `set_u256`, stays the row error (`PULSE_IMPORT_ROW_ERROR`, reason `PULSE_IMPORT_SET_OVERFLOW`). Import, measured predict and `ConvertJob` share the one decision; convert interns with the inferred delimiter and hands it to its `--keep-pulse` intermediate.
- Three places state this contract and must not drift: the `encoding.SetMask` doc comment (normative), this paragraph, and `skills/type-set-u128.md` / `skills/type-set-u256.md`.
- In memory, narrow rungs reach the decode wide map as `uint64` and wide rungs as `SetMask` — a `uint64` there would carry only the low word. The `values` float64 echo of a wide rung is the low 64 bits, deliberately lossy; the `SetMask` is the authority. See also `skills/cohort-width-overflow.md`.

**Vector fields — `vec_f32` / `vec_f64` and the VECTORS section.** Type bytes `20` / `21` store a fixed-length vector per row: dim little-endian IEEE-754 elements (4 / 8 bytes), contiguous, element 0 first.

- **Width is not in the type byte.** A vec field's width is `VectorElemSize × dim`, a property of the field within its schema; `FieldType.ByteSize()` is 0, so every stride must sum `Schema.FieldWidth`. Any decoder that uses `fixedWidthBytes` or `ByteSize()` for a vector reads it as zero bytes and misaligns the row. Every decoder has an explicit vec arm.
- **Schema copies must keep `Schema.Vectors`** (`Logical()`, `internal/encoding.CloneVectors`, `JoinedSchema` shifting right-side indices). A copy that drops it sizes every vec field at 0 bytes.
- **VECTORS section, tag 2, REQUIRED:** `u16 vector_count (>=1)`, then per vec field in STRICTLY ascending `field_index` (the writer sorts): `u16 field_index`, `u16 dim`, `u8 flags` (bit 0 labels, bit 1 has_kind, bit 2 has_scale_range; bits 3-7 reserved and refused), `[u8 kind]`, `[f64 scale_min, f64 scale_max]`, `[dim × (u16 length + UTF-8 label)]`. `VectorKind`: `0` none, `1` measure, `2` scale, `3` composition, `4` binary — the byte is the wire value, append-only.
- **Validation** (`ENCODING_INVALID` naming the field, on write before any byte AND on read): dim outside 2..1024; index out of range / duplicated / not a vec field; a vec field with no entry (so a `0x01` block with a vec field is refused); reserved flag bits; unknown or zero kind; label count other than 0 or dim; non-finite scale or `scale_min ≥ scale_max`; a label not UTF-8 or over 65,535 bytes.
- **Version:** any vector makes the cohort `0x02`; a vector-free cohort is unchanged — `encoding/testdata/format_v1.pulse` and `format_v2_grouped.pulse` are compatibility fixtures, never regenerated to make a failure pass.
- **Read order is not disk order:** a GROUPS entry width needs a vec member's dim, so the reader checks declared entry widths only after every section is read; GROUPS is written before VECTORS and either order reads identically.
- **Compatibility:** an older binary refuses a vector cohort loudly (unknown type byte or unknown required section); a vector cohort with its VECTORS section stripped is refused, never mis-strided.
- **Values:** `encoding.PutVector` / `VectorFromBytes` / `WriteVector` / `ReadVector` take the dim explicitly; `vec_f32` widens exactly to `float64`; a finite value beyond ±`MaxFloat32` is refused on write rather than stored as ±Inf; NaN / ±Inf stored verbatim. A null vector is a zeroed full stride plus its bitmap bit; a NaN element is a value. The map decoders put a `[]float64` in the wide map with no values echo. Gate: `TestVectorFields_EveryDecodePathAgrees` (single / grouped / sharded × reader / sample / lookup / Process).
- **Import:** `ImportJob.Vectors` (`--vector` / `--vector-kind`, MCP `vectors` / `vector_kinds`, sidecar) folds sibling text columns into one vec field (`internal/io/import_vectors.go`); refusals are `PULSE_IMPORT_VECTOR_INVALID` before any row. An explicit schema declares `dim` (required; missing is `PULSE_IMPORT_SCHEMA_INVALID`), `labels`, `kind`, `scale_min` / `scale_max`; a type override to `vec_*` is `PULSE_IMPORT_OVERRIDE_INVALID`.
- **List arm:** a column-less declaration (`--vector NAME[:f32]`) reads native list column `NAME` through `io.ListAwareReader` (`io.ListCell` / `io.ListState`; contract `docs/src/internals/adding-io-format.md`, Native list cells). Only under such a declaration — an undeclared list column still rides the `set_*` ladder, byte-identical to a build without the declaration. Dim = the first non-null list's length (a probe pass). Null list / all-null elements = null vector; null element = NaN. Refusal reasons: `list_length_varies`, `element_not_numeric`, `not_a_list`, `dim_out_of_range`, `list_dim_unknown`, `malformed_list_cell`; a source without the interface keeps `no_columns`. A `RowList` ERROR (the source failed to read) aborts the import with nothing written; a coded error keeps its code.
- **Export:** a writer implementing `io.ListAwareWriter` receives each vector as ONE list column (JSON array with `null` for non-finite elements and null vectors; Arrow `FixedSizeList`; Parquet `LIST<…>` when nullable because pqarrow cannot encode a null fixed-size list). Other writers get the vector EXPANDED into dim scalar columns `<field>_<label>` (`<field>_1..N` without labels). An expanded name equal to another column is `PULSE_EXPORT_COLUMN_COLLISION`. `ConvertJob` refuses a vector field (`PULSE_IMPORT_VECTOR_INVALID`, `not_declared`).
- **Column typing is never positional.** `planExportColumns` builds one explicit `iocore.ExportColumn` per header column; typed writers receive it through `io.ColumnAwareWriter` and resolve with `io.ColumnFields` (contract `docs/src/internals/adding-io-format.md`, Typing columns on export). Typing column `i` from schema field `i` silently gave a column another field's type under `--include` or a `_label` augment.
- **Shards:** structural cohesion checks a vec field's DIM explicitly (`PULSE_SHARD_SCHEMA_MISMATCH`, `details.dimension: vector_dim`) — a trailing vector with a different dim moves no later offset, so stride math alone would admit the shard and every row would decode misaligned. Element type is the type byte (`vec_f32` × 6 and `vec_f64` × 3 share a stride and are still refused). Labels / kind / scale are description-class: canonical wins, each divergence warns `PULSE_SHARD_DESCRIPTION_DIVERGENCE` (`vector_labels` / `vector_kind` / `vector_scale`).
- **Elsewhere:** set-widen re-stride shifts a vector verbatim; a vector may be a group member or an elided constant (`ConstantDetector` compares the whole stride); dedup and widen carry it unchanged. Synth draws a vector as ONE joint draw (`.claude/reference/synthetic-data.md`, Vector fields).

**Temporal word sign — `date` int32 / `datetime` int64.** The 4-byte `date` word is a two's-complement SIGNED int32 epoch-day count and the 8-byte `datetime` word a SIGNED int64 epoch-second count; pre-1970 values are negative (1969-12-31 is day −1). **Every reader must sign-extend, never zero-extend** — a zero-extended pre-1970 date reads as a day near 4.29e9 and fails SILENTLY (sorts after every real date, buckets into year ~11.7M, exports as nonsense). Find decode sites with `grep -rn 'FieldTypeDate\b\|FieldTypeDateTime\b' --include='*.go' .`; the two float decoders must stay in lockstep (`decode_plan_equivalence_test.go`), and the lookup-key encoder goes through `int32` / `int64` because float64→uint64 of a negative is architecture-defined. `ReadFieldValue` returns raw bits; embedders interpret with `encoding.DateDays` / `encoding.DateTimeSeconds`. An SPSS DATE column imports as `date` — only a time of day widens it to `datetime` (`PULSE_SPSS_DATE_WIDENED`).

**Import datetime literals — instant vs wall clock (SPSS, Arrow, Parquet).** No `.pulse` change: `datetime` stays UTC epoch seconds. What a reader EMITS decides whether an import source zone (`ImportJob.SourceTZ`, `--source-tz`) applies, because `temporal.ParseLocal` consults the zone only for a literal with no `Z` and no offset. Silent if wrong: an instant rendered naive shifts by the source zone's offset; a wall clock rendered `…Z` ignores it.

- **SPSS** `DATETIME` is a wall clock: render a NAIVE literal (`2006-01-02T15:04:05`). With no source zone it reads as UTC, so the stored cohort is unchanged.
- **Arrow / Parquet** timestamps type `datetime` and render through `internal/io/arrow` `FormatTimestamp`: a zoned Arrow type or `isAdjustedToUTC=true` is an INSTANT (canonical `…Z`; the source zone never moves it, and the column zone is not loaded — no host-tzdata dependency); a zone-less type, `isAdjustedToUTC=false` and legacy `INT96` are WALL CLOCKS (naive; source zone + DST policy apply).
- Every unit floors to whole seconds toward the PAST (truncation toward zero moves a pre-1970 fraction one second later); any floored fraction raises ONE `PULSE_IMPORT_TIMESTAMP_TRUNCATED` per `ReadRows` pass (`truncated_n`, `columns`). Export of `datetime` to Arrow / Parquet stays a UTF8 canonical literal.

**Arrow / Parquet declared widths — import pins and the `u4` marker.** No `.pulse` change. Arrow and Parquet readers implement `internal/iocore` `DeclaredTypeReader` (not `SchemaAwareReader`): a column whose Arrow type declares a width (`internal/io/arrow` `DeclaresWidth` — unsigned ints, float32/64, bool, date32/64, timestamp, decimal128 with its precision/scale) is PINNED to that type on import and convert. A pin skips the type vote and is never widenable, so an overflow is a per-row `PULSE_IMPORT_ROW_ERROR`, never `PULSE_IMPORT_WIDTH_PROMOTED`. Signed ints (Pulse has no signed type), strings, binary, dictionaries and lists infer from the data like any untyped source; nullability stays inferred (sample + out-of-sample promotion); `column_type_overrides` beats a pin; an explicit schema makes pins inert. Shared path: `internal/io/import_pins.go`.

- **The `u4` marker.** Arrow has no 4-bit type, so export writes a `u4` field as `Uint8` with field metadata `pulse:type` = `u4` (`FieldFromPulse`; Parquet keeps it via the stored Arrow schema) and the pin restores `u4`. Without it a cohort → Arrow / Parquet → cohort round trip re-imports `u4` as `u8` — readable, but not byte-identical. A plain `Uint8` pins `u8` (`TestArrow_U4PinRoundTrips`). The Parquet guard is `TestParquet_U4PinRoundTrips`: it writes through the Parquet writer and fails when the writer drops `pqarrow.WithStoreSchema()`, which carries the marker.
