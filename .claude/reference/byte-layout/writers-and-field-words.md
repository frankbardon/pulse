# Byte layout — the row builder, Materialize, wide-set word order, vector fields, temporal words, import datetime literals

Per-topic slice of the byte-layout reference (the row builder, Materialize, wide-set word order, vector fields, temporal words, import datetime literals). Index (preamble + section map): `.claude/reference/byte-layout.md` — load it first, then only the slice(s) your change touches.

**Row-at-a-time builder — `Pulse.NewCohortBuilder`.** The public write path for a NEW single-file cohort from typed rows (`pulse.CohortRow`, the `CohortReader.RecordAt` mapping); engine `internal/io.CohortBuild` (`cohort_build.go`). It runs import's explicit-schema code for every byte-deciding step — dictionary assignment with the declared rung as a ceiling (pre-seeded entries first, then first-seen; a rejected row's provisional labels are rolled back by `stagedDict`), decimal rescale + precision, set cells, the `rowCells` layout (`cell_encode.go`), the description-length check — and, with `CohortBuilderOptions.Groups` / `ElideConstants`, import's group path: `NewGroupEncoder` declaration check + `DedupGate.ScreenWidths` at construction (an explicit schema never widens, so the screen is final and `Strict` applies at once), then at `Close` the full-pass `ConstantDetector` over the spool, `PlanConstantElision` with the admitted members reserved, ONE `GroupEncoder.EncodeStream` into a second (physical) spool, and `AssessRatios` — all before anything is published, so a `Strict` refusal leaves nothing. The version byte is `RequiredFormatVersion` of the schema written: a build whose every group was dropped and that elides nothing is the `0x01` file byte-identical to the ungrouped build. **Byte identity** with an explicit-schema `ImportJob` (same schema, `Groups`, `ElideConstants`) is gated by `TestCohortBuilder_ByteIdenticalToImport` / `TestCohortBuilder_GroupedByteIdenticalToImport` and the embeddersmoke flows; a divergence would be silent (both files read fine). **Write path:** rows spool as LOGICAL records to `<target>.build-spool-*.tmp` beside the target on the instance afero FS (dictionaries precede records, so the preamble is written last); `Close` writes preamble + spool (or the `.build-phys-*.tmp` physical spool) into `<target>.build-*.tmp`, fsyncs it, then renames it over the target; `Abort` or any failure removes every temp file and leaves the target untouched. A key violation's `source_row` is the 1-based `Append` call, remapped past rejected calls by `io.withSourceRow`. **Sidecar invalidation:** a build never touches sidecars; `Overwrite` of an existing cohort replaces its bytes, so every sidecar beside it (point-lookup index + manifest, SPSS metadata sidecar) self-invalidates through its own fingerprint, and the facade reports them on `CohortBuildResult.InvalidatedSidecars` through the same `Pulse.InvalidatedSidecars` scan `Pulse.Dedup` uses (an enumeration failure is a warning, never an error); a replaced MANAGED import also gets `touchManaged` (its `.meta.json` expiry slides by its TTL), exactly as an in-place `Pulse.Dedup` does, while a fresh build — even into the imports dir — creates and touches no sidecar (`TestCohortBuilder_OverwriteTouchesManagedImport`). Refused: a `.zst` target, parent groups inside the schema (declare them in `Groups`). **Sharded build (`CohortBuilderOptions.Shards`, `ShardSplit{MaxRecords}`):** the full pass runs ONCE over every spooled row, so the gate verdicts, elision and dictionaries are archive-wide; the final (logical or physical) payload is cut at `RecordByteSize` boundaries into `part-NNNNN.pulse` shards that each carry the byte-identical preamble, staged in `<target>.build-shards-*/` and handed to ONE `CreateShardArchive` call (identical layouts and dictionaries, so its merge rewrites nothing). The staging directory is removed on every outcome; the u16 trailer shard count caps a build at 65,535 shards (`internal/io.MaxBuildShards`). `service.atomicWrite` stages its temp file in `filepath.Dir(dst)` — never `""`, which afero maps to `os.TempDir()` outside an `Options{DataDir}` base path. **Anchored append (`archive.pulse#name.pulse` target):** the build is ONE shard added to an EXISTING archive (never created implicitly; `SERVICE_VALIDATION` `archive_not_found` / `not_an_archive`); the name must be a plain basename the archive lacks (`PULSE_SHARD_NAME_COLLISION`, checked at construction AND by `AddShard` at `Close`; `_schema.pulse` is `PULSE_SHARD_RESERVED_NAME`), and `Groups` / `ElideConstants` / `Shards` / `Overwrite` are refused (`reason: append_option`) because the archive's layout wins. **Cohesion is pre-checked at construction** (`CohortBuildOptions.CheckAppend` → `service.PrecheckShardCohesion`): `AddShard`'s row-independent merge prefix — flatten when either side is grouped, `reconcileFlat` (set-rung plan BEFORE strict cohesion), `MergeDictUnion` — runs over a ZERO-ROW shard of the build schema, so a refusal carries `AddShard`'s exact code, message and details, and every verdict is monotone in the rows still to come (dictionaries only grow from their pre-seeded entries); set widening, dictionary union and group re-layout pass. It is advisory: `AddShard` at `Close` stays the authority (an archive changed meanwhile is caught there), and `TestCohortBuilder_AppendPrecheckParity` pins pre-check ≡ `AddShard` per case. Spool and staging go beside the ARCHIVE (`<archive>.build-*`); `Close` writes the logical payload as one shard file named for the anchor and calls `AddShard` once, which reconciles it atomically (dictionary union, set widening, group re-encode) — its errors are `Close`'s and its mandatory `PULSE_SHARD_SET_WIDENED` / `PULSE_SHARD_GROUPS_REWRITTEN` warnings end `CohortBuildResult.Warnings` unchanged; `Schema` / `FormatVersion` describe the shard as built, pre-reconciliation (`TestCohortBuilder_AppendShard*`).

**Materialized derived columns — `Pulse.Materialize`.** Writes a NEW single-file cohort holding every filter-passing source record plus one nullable `f64` per derived output (features, attributes, windows) of a request — except an `ATTR_PREVIOUS_STATE` output, written as its state field's own `categorical_*` / `packed_bool` type and dictionary, nullable (`MaterializeColumn.Inherits` from `prevstate.KeySchema`; the facade turns each code into its label / flag) — an ordinary column, no format change; facade `materialize.go`, service `internal/service/materialize.go` (`Service.Materialize` + `MaterializeSink`), engine `Processor.DeriveRecords` (`internal/processing/materialize.go`: the buffered steps before grouping over a FULL, unprojected decode, survivors mapped back to their source index by one forward walk over the order-preserving filter output, taken BEFORE any sort; `Request.Sort` then permutes only the emit order through `window.SortOrder` — `Process`'s own comparator, stable, nulls last — so window values never depend on it), columns + descriptions `internal/descriptor/materialize.go` (`MaterializeSlotRefusal`, `MaterializeColumns` — the shared label rules `featureOutputLabels` / `attributeDefaultLabel` / `windowLabel`; a window's frame clause is omitted when its capability declares `IgnoresFrame`; an operator declaring `ReadsExpression` is described by its `Expression` verbatim, its ignored `Field` unnamed; a regression attribute adds its slot-level penalty). The output schema is the source's `Schema.Fields` (the LOGICAL list) carried verbatim — never `Groups` — then the derived fields in pipeline order, unless the request carries the materialize-only `output` slot (`types.MaterializeOutput`, `capability:materialize_output`; every other operation refuses it, `PULSE_MATERIALIZE_OUTPUT_ONLY`): `descx.MaterializeOutputLayout` resolves it AFTER `MaterializeColumns` — `columns` (closed, ordered; `from` / `as` / `description` / `nullable`) XOR `exclude` — into the written columns, each a copy of the source field or derived field it reads (one shared function, so absent `output` is the identity layout, byte-identical — `TestMaterialize_AbsentOutputIsByteIdentical`); projection is LAST, so every other slot reads the full schema; the sink copies cells by layout index and refuses a null in a `nullable: false` column before the append (`PULSE_MATERIALIZE_OUTPUT_NULL`, nothing written); with `output` present the SPSS sidecar is carried THROUGH the layout (`SidecarCarry.WriteProjected`, one `spss.ProjectedColumn` per written column: dropped → variable gone, renamed → same variable under the new name, duplicated → a copy, `MaterializeOutputField.Rebuild` → regenerated — see SPSS metadata sidecar and the projected-carry rules after this paragraph); source cells come from `CohortReader.RecordAt` (exact typed values, archive index global in shard order, which is the scan order), never from the decoded `Record` (that loses types and omits nulls). It always writes through `NewCohortBuilder` (atomic; the builder recomputes the layout), so the output is `0x01` ungrouped whatever the source; an anchored target is refused; the source's SPSS metadata sidecar is CARRIED (read before the write, rewritten with a plain numeric variable per derived column — a previous-state column instead copies its state variable's description (codes, labels, missing spec; `observed` recomputed from the written rows) through `WriteFor`'s `mirrors`, the carry refused rather than mis-described when it cannot — re-fingerprinted over the output — see SPSS metadata sidecar), no other sidecar is; an Overwrite reports stale sidecars (`PULSE_MATERIALIZE_SIDECARS_INVALIDATED`), never the carried, fresh SPSS one. The memory pre-flight is Process's: every accepted request is non-streamable (no aggregations, matrices, tests or regressions — the per-record work the streaming gate needs), so it is judged on the buffered arm.

**Projected SPSS carry — `SidecarCarry.WriteProjected` (cohort-reshape E1-S3).** A Materialize `output` block carries through `SidecarCarry.WriteProjected` (`internal/io/spss/carry_projection.go`), one `ProjectedColumn{From, Label, Rebuild, Mirror}` per written column in output order — never the plain `WriteFor` (absent `output` stays on it, byte-identical): Variables are re-laid in output order, indices recounted, positions = output index; a DROPPED column removes its variable / registry entry, its very-long-string declaration and variable-set membership, every multiple-response set naming it and the weight when it was the weight; a RENAMED one keeps codes, labels, missing spec, formats AND its short name (records 7/5, 7/7, 7/14, 7/19 key by it), the new name its long name, with registry `sources`, set `fields` and `weight.variable` following; a DUPLICATE keeps the variable on the column that keeps the source's name (else the first), every other copy a deep copy under a freshly minted short name; a REBUILT column (`descx.MaterializeOutputField.Rebuild` — re-coded by a cast / recode / bucket) is regenerated by `spss.RebuildVariable` from the written type and dictionary — no old value label, code or missing spec lands on the new codes (a categorical becomes an unlabelled string variable of its entries); a description override relabels the variable. Refused (not carried, one warning) rather than mis-described: a kept registry column reading a dropped column, a duplicated registry column or very long string, a rebuilt column a registry / response set / very-long-string layout names, two output names SPSS case-folds together.

**Wide-set word order — `set_u128` / `set_u256`.** A wide set field's payload is a fixed-width bitmask of 16 or 32 bytes, read and written ONLY through `encoding.SetMask` and its wire API (`PutSetMask` / `SetMaskFromBytes`, `WriteSetMask` / `ReadSetMask`); the `uint64` value API `Read/WriteFieldValue` REFUSES both rungs with `ENCODING_TYPE_MISMATCH` rather than truncate to the low 64 bits. **The word order is normative: `words[0]` is bits 0–63 — the LOW 64 bits — then `words[1]` bits 64–127, `words[2]` bits 128–191, `words[3]` bits 192–255, laid down on the wire in that order (little-endian WORD order) with each word itself little-endian.** The payload is therefore exactly the little-endian byte image of the 128- or 256-bit integer, and **the low 8 bytes of a `set_u128` are byte-identical to a `set_u64` payload carrying the same selections** — the property that makes a narrow→wide rung promotion a pure append of zero bytes. Reverse either the word order or the intra-word byte order and every cohort written since the wide rungs landed decodes as a different, plausible-looking selection: no length changes, no checksum moves, nothing errors. Bit `i` ↔ dictionary entry `i` exactly as on the narrow rungs; an empty mask is a valid "no selection" distinct from null; nulls ride the per-record bitmap alone with no in-band sentinel, so a null row still carries (and every decoder still consumes) its full 16 or 32 payload bytes. A bit at or above `FieldType.MaxSetEntries()` is `ENCODING_INVALID` on write and, on the shard dict-remap rewrite path, `PULSE_SHARD_DICT_WIDTH_OVERFLOW`. Three places state this one contract and none may drift from the others: the `encoding.SetMask` doc comment (normative), this paragraph, and `skills/type-set-u128.md` / `skills/type-set-u256.md` (Bytes). In memory the hand-off type differs by rung and that difference is load-bearing: the narrow rungs (`set_u8`..`set_u64`) reach the decode wide map as a `uint64`, the wide rungs as a `SetMask` — a `uint64` there would carry only the low word. The `values` float64 echo for a wide rung is the low 64 bits and is DELIBERATELY lossy (two masks differing only above bit 63 echo the same number); it exists so a set field is never absent from the values map, and the `SetMask` is the authority. Detail: `skills/cohort-schema-design.md` (Field-type matrix (all 20)) + `skills/cohort-width-overflow.md` (Width overflow).

**Vector fields — `vec_f32` / `vec_f64` and the VECTORS section.** Type bytes `20` / `21` store a fixed-length numeric vector per row: dim little-endian IEEE-754 elements (4 / 8 bytes, `FieldType.VectorElemSize`), contiguous, element 0 first. The dim is NOT in the type byte, so a vec field's width is `VectorElemSize × dim` — a property of the field within its schema, which is exactly why every stride sums `Schema.FieldWidth` (`FieldType.ByteSize()` is 0 for both). In memory the metadata is `Schema.Vectors []VectorField{FieldIndex, Dim, Kind, ScaleMin, ScaleMax, HasScale, Labels}` (`HasVectors`, `Vector(i)`, `VectorDim(i)`, `ValidateVectors`); `Kind` is `VectorKind` (`0` none, `1` measure, `2` scale, `3` composition, `4` binary — the byte IS the wire value, append-only). **Wire — VECTORS section, tag 2, always REQUIRED:** `u16 vector_count (>=1)`, then per vec field, `field_index` STRICTLY ascending (the writer sorts, so the bytes never depend on listing order): `u16 field_index`, `u16 dim`, `u8 flags` (bit 0 labels, bit 1 has_kind, bit 2 has_scale_range; bits 3-7 reserved and refused), `[u8 kind]`, `[f64 scale_min, f64 scale_max]`, `[dim × (u16 length + UTF-8 label)]`. **Validation** (`ENCODING_INVALID` with details naming the field, on BOTH write — before a byte is written, at every version — and read): dim ∉ `MinVectorDim..MaxVectorDim` (2..1024), a field index out of range / duplicated / not a vec field, a vec field with no entry (its width would be unknown, so a `0x01` block carrying a vec field is refused outright), reserved flag bits, an unknown or zero kind byte, a label count other than 0 or dim, a non-finite scale or `scale_min ≥ scale_max`, a label that is not UTF-8 or exceeds 65,535 bytes. **Version:** any vector makes the cohort `0x02` (`RequiredFormatVersion`), whether or not it has groups; a vector-free cohort is unchanged byte-for-byte — `0x01` stays `encoding/testdata/format_v1.pulse` and a vector-free grouped write stays `encoding/testdata/format_v2_grouped.pulse` (generated by the pre-vector writer; never regenerate either to make a failure pass). **Read order is not disk order:** a GROUPS entry width sums its members' `FieldWidth`, and a vec member's needs its dim, so the reader records each group's DECLARED entry width while parsing GROUPS and checks it only after every section is read and `ValidateVectors` passes — the writer emits GROUPS (tag 1) before VECTORS (tag 2), and the reader accepts either order with an identical result. **Compatibility:** a binary that predates vectors refuses a vector cohort LOUDLY — at the unknown type byte `20` / `21` (`unknown field type byte`), or, if it knew the bytes but not the section, at the unknown REQUIRED section; a vector cohort with its VECTORS section stripped (as `0x02` or rewritten `0x01`) is refused by the current reader, never mis-strided. **Values:** `encoding.PutVector` / `VectorFromBytes` (byte slices) and `WriteVector` / `ReadVector` (streams) take the dim explicitly; `vec_f32` widens exactly to `float64` on read and a finite value beyond ±`MaxFloat32` is refused on write rather than stored as ±Inf; NaN and ±Inf are stored verbatim. The `uint64` `Read/WriteFieldValue` API refuses both types with `ENCODING_TYPE_MISMATCH` through explicit arms. **Read paths:** every decoder has an explicit vec arm that advances by `Schema.FieldWidth` — never `fixedWidthBytes`, which answers 0 (unknown) for a vector — so no path can read a vector as a truncated tail: the map decoders (`readRecord`, the plan map decoder, `record_at`) put a `[]float64` in the wide map and NO values echo; the reuse decoders (full stride, plan group, run-skip `writeFieldBytes`, the grouped decoder — whose entry cache never caches a vector member) hand the payload to `internal/encoding.VectorRecord.SetVectorAt` (the processing `Record` decodes it into its own `wideVector` storage, allocation-free) or box a `[]float64` through `SetWideFieldAt`. The processing `Record` answers `VectorValue` (a fresh copy) and `NumericValue` false; `extend.Record.VectorValue` is the extension view; `Cohort.Reader` cells are `[]float32` / `[]float64` by native type, nil when null; the cohort builder takes the same slices (exactly dim elements). Gate: `TestVectorFields_EveryDecodePathAgrees` (random layouts × single / grouped / sharded × reader / sample / lookup / Process) and `TestRecord_AllFieldTypesPositionalParity`. **Null:** a null vector is a zeroed full stride plus its bitmap bit (a nil slice to `PutVector` / `WriteVector` writes the placeholder) — no in-band sentinel; a NaN element is a value. **Schema copies:** every copy a path takes of a vector schema must keep `Vectors` (`Logical()`, `internal/encoding.CloneVectors`, `JoinedSchema` shifting the right side's indices); a copy that drops it sizes every vec field at 0 bytes. **Import:** `ImportJob.Vectors` (`--vector` / `--vector-kind`, MCP `vectors` / `vector_kinds`, `imports.Spec` + sidecar) folds sibling text columns into one vec field in a row-assembly step between the `[]string` reader and `rowConverter` (`internal/io/import_vectors.go` `foldReader`): the folded cell is a presence marker and the elements reach the converter through the fold, never the 32-byte `wideFieldBytes` scratch; refusals are `PULSE_IMPORT_VECTOR_INVALID` before any row. An explicit schema file declares a vector with `dim` (required, refused at PARSE as `PULSE_IMPORT_SCHEMA_INVALID` when absent), `labels`, `kind`, `scale_min` / `scale_max`; a column type override to `vec_*` is `PULSE_IMPORT_OVERRIDE_INVALID`. **List arm:** a column-less declaration (`--vector NAME[:f32]`) reads the native list column `NAME` through `iocore.ListAwareReader.RowList` — public as `io.ListAwareReader` / `io.ListCell` / `io.ListState`, so an embedder's reader gets the built-ins' parity (`io/list_reader_test.go`; contract: `docs/src/internals/adding-io-format.md`, Native list cells) — (Arrow / Parquet via `internal/io/arrow.ListCellAt` off the typed child array, NDJSON / JSON array via `jsonshared.ListCellOf` off the decoded `json.Number`s) — the typed fork happens before the source's pipe-joined row text is consulted, and only under such a declaration, so an undeclared list column still rides the `set_*` ladder byte-identically (`internal/io/veclist`). The dim is the first non-null list's length, taken by a plan-time probe pass and a `Reset`; no labels are written. Null list / all-null elements = null vector, null element = `NaN`; a variable-length list, a non-numeric element, a non-list cell, a dim outside 2..1024, or a column with no non-null list refuses the whole import (`PULSE_IMPORT_VECTOR_INVALID`, reasons `list_length_varies`, `element_not_numeric`, `not_a_list`, `dim_out_of_range`, `list_dim_unknown`, and `malformed_list_cell` for a `ListCell` outside its contract — an undeclared `State` or a `Nulls` neither nil nor `len(Values)`; a nil `Nulls` means no null element and a null element is forced to NaN); a source without the interface (CSV / TSV / Excel) keeps `no_columns`. **`RowList` returns an error** for a cell the source FAILED to read (I/O, decode, corrupt batch) — distinct from a readable cell reported through `State` — and it aborts the import in the dim probe and the row pass alike, with no cohort written, travelling as a `ReadRows` failure does: never restamped, a `*errors.CodedError` keeping its code with `vector` / `column` / `row` added to its details where unset (`listReadFailure`), an uncoded error staying uncoded. Import-side vector surfaces are format features, never profile-gated: the MCP prose scrub treats pulse_import's `vectors` as a homonym of the matrices slot token (`slotTokenHomonyms`). **Export (`ExportJob.Run`, `internal/io/export_vectors.go`):** the field-to-column mapping stops being 1:1. A writer implementing `io.ListAwareWriter` (NDJSON, JSON array, Arrow, Parquet; public, so an embedder's writer gets the same channel — `io/list_writer_test.go`) is told the vector columns through `SetListColumns` before `WriteHeader` and receives each as ONE column whose cell is a reused `[]float64` (nil when null): a JSON array with `null` for a non-finite element and for a null vector, an Arrow `FixedSizeList<float32|float64, dim>`, and in Parquet the same for a non-nullable vector but `LIST<…>` for a nullable one (pqarrow cannot encode a null fixed-size list). Every other row writer gets the vector EXPANDED in place into dim scalar columns `<field>_<label>` (`<field>_1..N` without labels, `internal/io.VectorElementColumn`), the element text rendered like a scalar `f32` / `f64`, `nil` for a NaN element and for every element of a null vector; a `SchemaAwareWriter` (Excel) is handed the schema with each vector replaced by those nullable scalar fields. **Column typing is never positional:** `planExportColumns` builds one explicit `iocore.ExportColumn` per header column (name, kind field / label / element / list, source field, the field that TYPES it — nil = text for a `_label` sibling and for a non-decimal field a label REPLACE rewrites), typed writers take it through `iocore.ColumnAwareWriter` (`SetExportColumns`, once, after `SetPulseSchema` and before `SetListColumns` / `WriteHeader`; never on a `CohortWriter`, under `ConvertJob` or by `Predict`) and resolve it with `iocore.ColumnFields` (no plan: the schema field of the same NAME) — the built-in Excel / Arrow / Parquet writers and, through the public `io.ColumnAwareWriter` / `io.ExportColumn` / `io.ExportColumnKind` (+ its four constants) / `io.ColumnFields`, an embedder's own (`io/column_writer_test.go`; contract: `docs/src/internals/adding-io-format.md`, Typing columns on export), and `ExportJob.Predict`'s `PredictReport.Columns` is that same plan's names. Typing column `i` from the schema's `i`-th field silently gave a column another field's type under `--include` or a `_label` augment (`export_column_typing_test.go`). An expanded name equal to another column is `PULSE_EXPORT_COLUMN_COLLISION` before the header. `Includes` and `_label` augment work on FIELDS — the expansion runs on `applyExportLabels`' output. Round trips (`internal/io/veclist/export_test.go`): CSV / TSV `rate_*` columns folded with `--vector rate:/^rate_(.*)$/` export back to the source text byte for byte and re-import to a byte-identical cohort (the expanded names restore the source's only when the vector's name is the columns' prefix); NDJSON / JSON array / Arrow / Parquet re-import under `--vector NAME` byte-identically — a vector whose elements are ALL NaN comes back null (an all-null list or an all-empty battery is a null vector). `ConvertJob` refuses a vector field in its resolved schema (`PULSE_IMPORT_VECTOR_INVALID`, `not_declared`): a convert is a text pass with no vector declaration. The `.sav` arm is under SPSS export. **Shards, groups, widen, dedup:** structural cohesion (`ValidateStructuralCohesion`) checks a vec field's DIM explicitly at the field itself (`PULSE_SHARD_SCHEMA_MISMATCH`, `details.dimension: vector_dim`, `canonical_dim` / `incoming_dim`) — the dim is not in the type byte, so a TRAILING vector whose dim differs moves no later offset and stride math alone would admit the shard, after which every row of it decodes misaligned at the canonical stride; the element type is the type byte (`vec_f32` × 6 and `vec_f64` × 3 share a stride and are still refused). Labels, kind and scale range are description-class: tolerated, the canonical copy wins, and each divergence is a `PULSE_SHARD_DESCRIPTION_DIVERGENCE` warning with `details.dimension` `vector_labels` / `vector_kind` / `vector_scale` (`canonical` / `incoming`) — a reused code rather than a new one, because the tolerance, the canonical-wins rule and the fixup are exactly the description's; the warning rides `AddShardResult.Warnings` / `CreateShardArchiveResult.Warnings` and `pulse shard verify`. Every stride helper sums `Schema.FieldWidth`, so the set-widen re-stride (`widenFieldOffsets`, `Pulse.WidenSetField` and shard auto-widen) shifts a vector behind the widened set verbatim, a vector may be a parent-group member (entry width = its stride, copied verbatim) or an elided constant (`ConstantDetector` compares the WHOLE stride — a vector differing only in its last element is not constant), and `pulse dedup` / `pulse widen` carry it unchanged. **Synth:** a vector is ONE joint draw on every synth surface (from-schema, `profile create`, from-profile, augment) — `FieldSpec.Vector` / `FieldProfile.Vector`, the written schema's VECTORS entry equal to the spec's, a null vector written as its zeroed full stride (`writeFieldValueDim` takes the dim from the schema) and the augment merge keeping the source's entries and refusing a dim mismatch (`.claude/reference/synthetic-data.md`, Vector fields). Gates: `internal/encoding/cohesion_test.go` (`TestShardArchiveStructuralCohesion_Vectors`), root `vector_archive_test.go`. Tests: `encoding/vector_test.go`, `internal/encoding/vector_format_test.go`, `internal/io/export_vectors_test.go`.

**Temporal word sign — `date` int32 / `datetime` int64.** The 4-byte `date` word is a two's-complement SIGNED int32 epoch-day count and the 8-byte `datetime` word a two's-complement SIGNED int64 epoch-second count — pre-1970 values are negative (1969-12-31 is day −1, `1969-12-31T23:59:59Z` is second −1). The bits never changed: `ParseDate` always wrote `uint32(int64 day)` and `ParseDateTime` `uint64(int64 sec)`, so pre-1970 cohorts written before the read side was fixed already hold the right words, and no format version moved. **Every reader must sign-extend, never zero-extend** — a zero-extended pre-1970 date reads as a day near 4.29e9 and fails SILENTLY (it orders after every real date, buckets into year ~11.7M, exports as a nonsense calendar date). The sites: both float decoders in lockstep (`internal/encoding` `rawToFloat64` / `decodeFixed`, pinned by `decode_plan_equivalence_test.go`), text export (`formatFieldValue`), SPSS export (`cohortNumber`), the lookup-key encoder (`numericOnWireBytes` goes through `int32`/`int64` because a float64→uint64 conversion of a negative is architecture-defined), `internal/daterange` bounds, include-from member sets, and the synth rule range. `ReadFieldValue` keeps returning raw bits; embedders interpret them with `encoding.DateDays` / `encoding.DateTimeSeconds`. An SPSS DATE column holding a pre-1970 value imports as a native `date` — only a time of day widens it to `datetime` (`PULSE_SPSS_DATE_WIDENED`). One residual: a sidecar index built on a pre-1970 `datetime` key BEFORE the fix keyed on a rounded float echo, so rebuild such an index.

**Import datetime literals — instant vs wall clock (SPSS, Arrow, Parquet).** No `.pulse` change: a `datetime` stays UTC epoch seconds. What a reader EMITS decides whether an import source zone (`ImportJob.SourceTZ`, `--source-tz`) can apply, because `temporal.ParseLocal` consults the zone only for a literal with no `Z` and no offset. **SPSS** `DATETIME` is a wall clock with no zone, so `internal/io/spss` renders a NAIVE literal (`2006-01-02T15:04:05`); it used to render `…Z`, which named an instant and silently beat `--source-tz`. With no source zone the naive literal reads as UTC — the instant the `Z` named — so the stored cohort is byte-identical (pinned against a `Z`-replaying reader). **Arrow / Parquet** native timestamps now type `datetime` (`TypeToPulse` used to fall through to `f64`) and render through `internal/io/arrow` `FormatTimestamp`: a zoned Arrow type or `isAdjustedToUTC=true` is an INSTANT (canonical `…Z`; the source zone never moves it, and the column's zone is not loaded — no host-tzdata dependency); a zone-less type, `isAdjustedToUTC=false` and legacy `INT96` (which pqarrow surfaces as UTC-zoned; the Parquet reader overrides it from the physical type) are WALL CLOCKS (naive literal; source zone + DST policy apply). Every unit floors to whole seconds toward the PAST — integer division toward zero would move a pre-1970 fraction one second LATER — and any floored fraction raises ONE `PULSE_IMPORT_TIMESTAMP_TRUNCATED` per `ReadRows` pass (`source_warnings`, details `truncated_n` + `columns`), reset per pass so inference-then-import never doubles it. Export of `datetime` to Arrow / Parquet stays a UTF8 canonical literal (`TypeFromPulse`). Silent if wrong: an instant rendered naive shifts by the source zone's offset; a wall clock rendered `…Z` ignores it.
