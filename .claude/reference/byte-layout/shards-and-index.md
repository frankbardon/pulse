# Byte layout — shard set-width auto-widen, the archive rewrite contract, shard archives with parent groups, the sidecar point-lookup index and its manifest

Per-topic slice of the byte-layout reference. The archive point-lookup index lives in `byte-layout/archive-index.md`; in-place append in `byte-layout/archive-append.md`. Index: `.claude/reference/byte-layout.md` — load it first, then only the slice(s) your change touches.

**Shard set-width auto-widen.** A `shard add` (or `CreateShardArchive`) whose dictionary union outgrows a `set_*` field's bitmask, OR whose arriving shard DECLARES a different rung, does not refuse: the field is promoted to the narrowest rung that holds the union, across the canonical `_schema.pulse` AND every stored shard payload.

- **Order, not a loosened validator.** `encoding.PlanSetWidening` runs BEFORE `ValidateStructuralCohesion` and reconciles the rungs; cohesion then runs over the reconciled schemas as strictly as ever. `pulse shard verify` calls the same validator and must keep refusing a genuinely mixed-stride archive — that is a corruption signature. Cohesion keys on the type-derived layout plus bit position, never the stored byte offset (a cache legacy writers filled wrong).
- **The target rung is never narrower than either side.** A narrower arrival is promoted to the archive's rung and is the only payload rewritten; narrowing the archive would SILENTLY drop every selection above the new ceiling (records still decode, to a smaller plausible selection). `SetWidening.From != To` means the archive moved; `details.archive_widened` says which.
- **One offset derivation.** `encoding.WidenSetFieldBytes` (per shard payload) and `encoding.WidenSchemaSetField` (canonical block) share `widenFieldOffsets`, so every schema block describes the identical post-widen layout by construction. A divergence would not fail to open — every field after the widened one would decode at the wrong offset.
- **`PULSE_SHARD_SET_WIDENED` is MANDATORY**, naming the field, old rung, new rung and shards rewritten: an expensive archive-wide rewrite that happens silently is indistinguishable from a cheap append. `AddShard` / `CreateShardArchive` return result structs (not bare `error`) so the warning has nowhere to be dropped.
- **Limits:** a union above `set_u256` stays fatal `PULSE_SHARD_DICT_WIDTH_OVERFLOW` (256 is the hard ceiling). Categorical widths are fixed at creation and never auto-widen. Foresight: `VerifyShardArchive`'s `SetWidthHeadroom` (`--json` `set_width_headroom`; empty `next_type` = already the widest rung).
- **Sidecars are not updated by a widen.** Both the index and SPSS sidecar self-invalidate (a widen always changes the cohort's LENGTH, the one conclusive staleness verdict). The risk is silent BREAKAGE — lookups stop answering with no explanation — so `pulse widen` / `pulse dedup` / overwriting writers name every invalidated sidecar and its rebuild command (`data.invalidated_sidecars`; library `Pulse.InvalidatedSidecars` / `pulse.StaleSidecar`). Discovery goes through each sidecar's naming authority (`Pulse.ListIndexes`, `spss.SidecarPath`), never a filename glob — an index filename is a hash of its key tuple. No automatic rebuild: it would attach unbounded work to a bounded operation.

**The archive rewrite contract.** Every archive mutation that rewrites (create, add-with-rewrite, remove, compact, the filter-to-file archive arm, zone set) goes through `internal/service/shard_stream.go` `archiveWriter`. Concurrency is caller-owned and no lock is taken, so atomicity is the whole safety argument.

- **Stage + rename.** The new archive streams into ONE deterministic stage beside the original, `<archive>.pulse.tmp-staged` — refreshed `_schema.pulse` first, then every stored shard copied RAW (`zip.Writer.CreateRaw`, CRC and sizes verbatim, no decode), then the arrival — published by flush → fsync → rename → directory fsync (best effort). The destination is never opened for writing, so a failure or crash before the rename leaves the original byte-identical and openable.
- **Memory is O(the arriving shard)** plus fixed buffers, I/O O(the archive) (`TestShardStream_MutationAllocationBoundedByShard`). Filter-to-file filters one shard at a time into `<archive>.pulse.tmp-spool` because `_schema.pulse` leads with the surviving aggregate; `--flatten` writes one single file (canonical preamble, then surviving rows in archive order); single-file and anchored arms stream through a copy window. All are bounded per shard.
- **Create is plan-then-write.** `_schema.pulse` is written first, so its canonical schema must be final before any shard: a PLAN pass folds every source through the same `mergeShard` add uses (header + schema only for an ungrouped merge; rows for a grouped one, one source at a time), then a WRITE pass streams each source once — verbatim if untransformed, else loaded, replayed and stored. Bytes equal create-then-add-each (`TestShardStream_CreateMatchesSequentialAdd`).
- **Shard count limit:** at most 65535 shards (SHRD `shard_count` is `u16`); create, add and filter-to-file refuse more with `PULSE_SHARD_COUNT_LIMIT` before writing.
- **When the archive itself moves** (widen, constant-group promotion) each stored shard is read and re-encoded on its way into the stage, one at a time; a constant-group promotion first runs a discovery pass to fix the final dictionaries. A deflated stored entry is inflated and re-stored, never copied raw; a raw copy does not re-check CRC (`shard verify` does).
- **Trailer:** `aggregate_record_count` and `shard_count` are summed header-only (a re-stride moves records, never their count).
- **Crash hygiene:** every `<archive>.pulse.tmp-*` is swept when the next writer opens — never another archive's (`TestShardStream_CrashBeforeRenameLeavesOriginalAndIsSwept`). In-place tail append is a separate, journalled path: `byte-layout/archive-append.md`.

**Shard archives with parent groups — `0x02` shards.** Every shard is decoded with the CANONICAL schema, so a grouped archive has exactly ONE group layout (count, kinds, members, key flags) and every shard's indices address the canonical dictionaries.

- **Cohesion:** `ValidateStructuralCohesion` compares the group layout (`encoding.ValidateGroupCohesion`) because it decides the physical stride; a `0x01` shard in a `0x02` archive, or the reverse, is `PULSE_SHARD_SCHEMA_MISMATCH`. Group dictionaries follow the append-only prefix rule (`ValidateDictPrefixRule`, else `PULSE_SHARD_DICT_DIVERGENCE`).
- **The merge** (`internal/service/shard_groups.go` `mergeShard`, shared by create and add so the same files produce byte-identical archives either way — `TestShardGroups_CreateAndAddAgree`):
  1. Work on LOGICAL rows: flatten the arrival (`encoding.FlattenCohortBytes`) and reconcile it as an ungrouped shard. The categorical remap keeps NULL placeholders (`RewriteShardCategoricalsKeepNulls`) — a null's bytes are part of an entry's identity, and remapping them would split an identical `(key, null)` tuple into a spurious `PULSE_GROUP_MEMBER_NOT_CONSTANT`.
  2. The ARCHIVE's layout wins: an ungrouped archive stores a grouped arrival as its `0x01` twin; a grouped archive re-encodes the arrival into its own layout. Adopting the arrival's layout would turn an append into an archive-wide rewrite that can fail on data already accepted.
  3. Group dictionaries union canonical-first via a SEEDED encoder (`GroupEncoder.Seed`): stored shards keep their indices and are untouched; only the arrival is renumbered. Past `MaxGroupEntries` is `PULSE_SHARD_DICT_WIDTH_OVERFLOW`, never a wrap.
  4. A CONSTANT group the arrival disagrees with is PROMOTED to indexed across the whole archive; a declared KEY the arrival violates is REFUSED with `PULSE_GROUP_MEMBER_NOT_CONSTANT` (`details.shard`, `details.field`) — a key is a contract.
  5. Strict cohesion runs last over the reconciled grouped schemas.
- **Mandatory warning:** every layout change (`incoming_flattened`, `incoming_regrouped`, `constant_promoted`) emits `PULSE_SHARD_GROUPS_REWRITTEN` plus a typed `GroupReconciliation` on `AddShardResult.Regrouped` / `CreateShardArchiveResult.Regrouped` (`data.regrouped`, present only when non-empty). Foresight: `VerifyShardArchive`'s `GroupIndexHeadroom` (a constant group always reports 0 headroom).
- **Readers:** the anchor form opens a stored shard with its own schema (its dictionary is a prefix of the canonical one). Export and its predict read a whole archive through `encx.OpenArchiveRecords` (canonical schema, archive order, each shard gated by `encx.ShardDecodeCompatible`), so output equals the flattened file's byte for byte; an anchored export reads one shard through the canonical schema; a `.sav` reads the ARCHIVE's SPSS sidecar, never a per-shard one. Inspect reports canonical groups over the archive-wide record count, header-only. `pulse dedup` refuses an archive.

**Sidecar point-lookup index.** `Pulse.Lookup` / `pulse index build` / `pulse api lookup` are backed by a **separate file** beside the cohort, `cohort.pulse.<keyhash>.idx` — never the `.pulse` layout.

- **Format v3** (own magic + version): 9-byte header (`PULSEIDX` + `0x03`) → 32-byte SHA-256 source fingerprint → key spec (ordered key columns + types) → `SourceSize` (u64) + `SourceModTime` (i64 Unix ns) → `u32 bucket_count` → fixed-width `bucket_count × u64` offset table → self-delimited bucket data (FNV-1a hash buckets → `[]uint64` row ids). The fixed-width table makes one bucket directly addressable: a lookup is O(1) seeks via `RecordLocator`, never a full cohort or index read.
- **Staleness has THREE outcomes.** A **size** mismatch is an instant, conclusive `PULSE_INDEX_STALE` (the fingerprint covers the whole file). A full size+mtime **match** is served hash-free — the O(1) property. An **mtime that moved while size held is NOT staleness**: it escalates to the SHA-256 (`service.classifyIndexFreshness`, shared by `Lookup` and `VerifyIndex`) and refuses only if content differs. Reason: `SourceModTime` is nanoseconds and object stores / copies truncate mtimes, so refusing on drift permanently broke lookups on byte-identical indexes served from a bucket.
- **The escalation is memoised** per `(cohort path, size, mtime)` (bounded cache), because bucket drift is permanent — without it every lookup would hash the whole cohort. `VerifyIndex` WRITES the memo and never READS it: verify must not rest on a stat pair. Verify always hashes when size matches; `stat_mismatch` is a SIZE verdict; mtime drift reports `VerifyIndexResult.ModTimeDrift`. Deliberate residual gap: an in-place edit preserving BOTH size and mtime passes `Lookup` and is caught only by `verify`.

**Sidecar index MANIFEST — `cohort.pulse.indexes.json` (`internal/encoding.IndexManifestSuffix`).** A JSON file beside the cohort, written by `pulse index build`. It exists because an index filename is a HASH of its ordered key tuple, so the file cannot be opened without already knowing the tuple — and object storage cannot list a directory to find it.

- **Shape:** `{format_version, kind, cohort, indexes:[{index_path, key_hash, keys:[{name,type}], distinct_keys, indexed_records}]}`; paths are BASENAMES (survive a move); counts recorded at build so a listing reads no index file. Its `format_version` is its OWN (`"1"`), independent of `encoding.FormatVersion` and `IndexFormatVersion`.
- **Wiring:** `BuildIndex` upserts (and seeds a new document from the directory listing); `DropIndex` prunes, and prunes an ORPHANED entry as a successful drop (the repair path); `ListIndexes` reads the manifest first and unions any unnamed on-disk sidecar.
- **Never silently degrade.** An absent manifest falls back to the directory listing (the ordinary pre-manifest state). A manifest that exists and cannot be parsed is `PULSE_INDEX_MANIFEST_INVALID` — degrading succeeds locally but answers "no indexes" on a bucket. A manifest naming an absent sidecar is `PULSE_INDEX_MANIFEST_STALE`.
- It is a Pulse `*.json` sidecar, so table-directory walks must skip it by suffix (`isPulseSidecarName`; `byte-layout/table-directories.md`).
- **Keyable types** (`processing.IsIndexKeyableFieldType`): `u4`/`u8`/`u16`/`u32`/`u64`, `f32`/`f64` (raw bit-pattern equality — `-0.0`/NaN caveat), `date`, `datetime` (signed epoch seconds; the literal parses through `encoding.ParseDateTime`, never `ParseFloat`), `decimal128` (exact mantissa), `categorical_*` (dictionary ID), `packed_bool`. `set_*` is rejected (no single equality value — use `FILTER_SET`).
- **`u64` keys are EXACT:** build reads the stored word and the probe parses integer literals with `strconv.ParseUint`, so ids above 2^53 one float apart key differently. Key bytes are unchanged below 2^53. An index built by an older binary over larger ids collapsed neighbours; `VerifyIndex` cannot detect that — rebuild. Matched rows render a `u64` cell as the exact stored word, so the lookup decode must keep capturing exact words or a hit above 2^53 renders saturated.
- Equality-only, full key required, composite-key order significant. Codes: `PULSE_INDEX_MISSING`, `PULSE_INDEX_STALE`, `PULSE_INDEX_MANIFEST_INVALID`, `PULSE_INDEX_MANIFEST_STALE`, `PULSE_LOOKUP_NOT_FOUND`, `PULSE_LOOKUP_AMBIGUOUS`. A comparison attribute's `{record: {cohort?, keys}}` reference runs the same read path and codes (`.claude/reference/matrix-and-vectors/vector-operators.md`, Stored-record references). Skills: `skills/cohort-sidecar-index.md`, `skills/tool-lookup.md`.
