# Byte layout — the archive point-lookup index and its per-shard key-range and Bloom prunes

Per-topic slice of the byte-layout reference (the archive point-lookup index: one sidecar per shard, the archive manifest's coverage and upkeep, the key-range and Bloom prunes, the distinct-key estimate). Index: `.claude/reference/byte-layout.md` — load it first, then only the slice(s) your change touches. The single-file sidecar and its manifest are in `byte-layout/shards-and-index.md`.

**Archive point-lookup index — one sidecar per shard + the archive manifest's coverage.** `BuildIndex` on a shard archive writes, per shard, a v3 sidecar at the shard's ANCHOR path (`internal/encoding.ArchiveShardIndexPath` = `SidecarIndexPath("archive.pulse#shard.pulse", keys)`): row ids are in-shard ordinals and the fingerprint covers the shard's STORED payload, so the file is byte-identical to an anchored build's (`TestArchiveLookup_ShardSidecarIsTheAnchorSidecar`). One scan of the archive builds each shard's buckets and flushes them as the scan leaves the shard — one shard's keys resident at a time. The index format does not move.

- **Manifest coverage.** The archive's `archive.pulse.indexes.json` entry carries `shards: [{name, size, crc32, index_path, distinct_keys, indexed_records, key_min?, key_max?, hll?}]` in archive order (additive, manifest `format_version` stays `"1"`). The entry's `index_path` is the LOGICAL name (no file lives there); its counts are per-shard SUMS.
- **Shard identity is name + size + zip-central-directory CRC32**, never a bare name — a same-name, same-size replacement moves the CRC32. **Nothing is stored inside the zip**: a second reserved entry would break every reader that treats a non-`_schema.pulse` entry as a shard.
- **Lookup, in order:** read the central directory and the manifest; refuse any current shard no `shards[]` record matches (or whose sidecar records another `SourceSize`) with `PULSE_INDEX_STALE` + `details.shards_uncovered` BEFORE returning a row — never a silent miss; resolve the key literal ONCE against the CANONICAL schema (a literal a shard's prefix dictionary lacks is a miss there; a literal no dictionary holds is `PROCESSING_CONFIG`, as single-file); skip shards the key-range and Bloom prunes exclude; probe one bucket per remaining shard; union hits in archive order then ascending in-shard row id (the single-file global order) and apply multiplicity across the union. A covered shard whose sidecar is gone is `PULSE_INDEX_MANIFEST_STALE`. Parity with the single-file twin: `TestArchiveLookup_*`.
- **Verify / list / drop:** `VerifyIndex` checks coverage (`stat_mismatch`, `ShardsUncovered`), then SHA-256s every stored shard against its sidecar (`ShardsMismatched`), then ranges and Blooms (below); it never uses the memo. `ListIndexes` lists an archive from its manifest ALONE. `DropIndex` removes the entry, the named sidecars, every current shard's derived sidecar and every Bloom file.
- **Upkeep on `shard add` / `remove` is BUILD BEFORE PUBLISH** (`internal/service/index_upkeep.go`). An add scans the new shard once from an unpublished archive identical to what will be published (the tail append's in-memory twin, or a rewriting add's unrenamed stage), stages each sidecar, Bloom data and the manifest as `<file>.pulse.tmp-staged`; ANY failure before the archive rename aborts with archive, sidecars and manifest byte-identical. Publish order: archive, then sidecars and Bloom set, then manifest — a reader between renames sees an uncovered shard (a loud `PULSE_INDEX_STALE`), never a sidecar for bytes the archive lacks. A remove stages the manifest without the shard (an entry losing its last shard is dropped), renames archive then manifest, then deletes that shard's sidecars. Both emit the mandatory `PULSE_SHARD_INDEXES_UPDATED` warning (`details.action` `added` / `removed`). A rename failing AFTER the archive rename cannot roll back: the result warns `PULSE_INDEX_STALE` (`details.reason` `index_upkeep_publish_failed`). An unreadable manifest refuses the add / remove up front (`PULSE_INDEX_MANIFEST_INVALID`). An add that RE-ENCODES stored shards moves every CRC32 and reports each sidecar in `AddShardResult.InvalidatedSidecars`. `compact` copies shards raw, so sidecars stay valid. Pinned by `TestArchiveIndexUpkeep_*`.

**Archive key-range prune — `key_min` / `key_max`.** Each `shards[]` record carries the shard's indexed-key range, one string per key COMPONENT in key order (`encx.IndexKeyRange`). Build and add upkeep share one record builder, so an add's record is byte-identical to a fresh build's.

- **Encoding:** ORDER-PRESERVING fixed-width lowercase hex (`encx.IndexKeyOrderComponents`): little-endian key bytes reversed to big-endian; `date` / `datetime` / `decimal128` with the sign bit flipped; `f32` / `f64` through the IEEE-754 total-order transform of the RAW bits (the index keys on raw bits, so a bit-equal probe always lands inside); categorical bounds are dictionary-ID bounds (sound because shard dictionaries are canonical prefixes). Byte order equals value order; strings keep `u64` bounds exact above 2^53.
- **Bounding box, not a tuple range:** a composite key is excluded when ANY component falls outside its own bounds. A skipped shard's sidecar is never opened — and so not validated; coverage is still checked for every shard first, so the range always describes current bytes.
- **Absent means probe, never skip.** An empty shard records no range; an older binary round-tripping the manifest drops the fields; `KeyRangeExcludes` answers "probe" for an absent, wrong-arity, malformed or wrong-width range.
- **Verify** recomputes each range; a difference is stale with reason `range_mismatch` (`ShardsRangeMismatched`), because a wrong range can hide a match. Repair: `pulse index build`.

**Archive Bloom prune — the per-shard `.bloom` sidecar.** The Bloom filter RECORD layout, shared by the legacy per-shard file and the Bloom set below (`internal/encoding/index_bloom.go`, little-endian): magic `PULSEBLM` (8) · version `0x01` (`ShardBloomFormatVersion`, its own axis) · `hash_count` k (1) · `key_width` u32 · the shard identity as the manifest records it (`shard_size` u64, `shard_crc32` u32, `name_len` u16 + name) · `word_count` u32 · `word_count` × u64 words (bit i = word i/64, bit i%64) · trailing IEEE CRC32 of every preceding byte.

- **Sizing and hashing are integer-only** (bit-identical on arm64 and amd64): 10 bits per distinct key rounded up to a whole word (min one; an empty shard's all-zero filter rejects every key), k = 7 (~1% false positives); h = `HashKey(key)` (FNV-1a 64), h1 = splitmix64(h), h2 = splitmix64(h ⊕ 0x9e3779b97f4a7c15) | 1, probe j = bit (h1 + j·h2) mod bits in uint64 wraparound. Frozen by `TestShardBloom_RoundTripAndFrozenBytes`.
- **Prune only on a trusted negative:** a record skips a shard only when well formed, stamped with the covered shard's exact name + size + CRC32 and key width, and answering "not present". Absent, damaged or stale means probe — a Bloom has no false negatives, and every other state costs speed, never a match (`TestArchiveLookupBloom_StaleFilterNeverHidesAMatch`).
- **Legacy file:** `archive.pulse#shard.pulse.<keyhash>.bloom` beside each per-shard sidecar. Written only by builds that predate the set; read only when NO set file exists (`TestArchiveLookupBloom_LegacySidecarsStillPrune`).

**Archive Bloom set — `<archive>.<keyhash>.blooms`.** `BuildIndex` writes every shard's Bloom record into ONE file per archive index, so a lookup reads its Bloom data in one whole-file read (one GET on object storage) regardless of shard count (`TestArchiveLookupBloomSet_OneReadIndependentOfShardCount`). It is a separate file, not a manifest field, because the manifest is parsed on every lookup and list, and an older binary round-tripping the manifest never sees it.

- **Path:** the logical index path with `.idx` swapped for `.blooms` (`encx.ArchiveBloomSetPath`) — never inside the zip, never named by the manifest, not `*.json` (table-directory exclusion unaffected), not `.pulse` (the cohort scan never sees it); `CohortArtifacts` lists it so an archive index travels with its archive.
- **Layout** (`internal/encoding/index_bloom_set.go`): magic `PULSEBLS` (8) · version `0x01` (`ArchiveBloomSetFormatVersion`) · `count` u32 · `count` × {`len` u32 · one `PULSEBLM` record}, archive order, no trailer.
- **Each record stands or falls alone:** an undecodable record, duplicate name, overlong length or trailing bytes mark the set `Damaged` but decoded records still prune; a bad header makes the whole set unusable (probe every shard). A set file that EXISTS decides alone — no per-shard `.bloom` is consulted beside it.
- **Upkeep:** a build writes the set and best-effort removes superseded per-shard files; an add stages the set with every kept shard's record (migrating legacy `.bloom` files when no set exists; a record not matching the kept shard's identity is dropped, so that shard probes) plus the new one, renamed before the manifest, and deletes legacy files only after publish; a remove restages an existing set without the shard and never creates one. Build, add and remove leave the set byte-identical to a fresh build.
- **Verify:** a covered shard's record must equal the rebuilt filter byte for byte, else `bloom_stale` (`ShardsBloomStale`; outranked by `fingerprint_mismatch` then `range_mismatch`); a damaged set names every covered shard it lacks a record for; a missing record or missing file is never stale.

**Archive distinct-key estimate — the per-shard `hll` sketch.** `distinct_keys` stays the per-shard SUM; the UNION is estimated from a HyperLogLog sketch each `shards[]` record carries as `hll` (`internal/encoding/index_hll.go`). An EMPTY shard records an all-zero sketch (known 0).

- **Precision p = 10** (m = 1024, relative standard error ≈ 3.25%). Integer-only hashing: x = splitmix64(`HashKey(key)`); register = top p bits; value = 1 + leading zeros of the remaining 54 bits, capped at 55; merge = register-wise max.
- **Wire form:** standard base64 of [precision byte `0x0a`][768 bytes: 6-bit registers packed big-endian, four per three bytes] — 1028 characters per shard. Any other precision or length, a register above 55 or bad base64 decodes as NO sketch.
- **Estimate** (`encx.IndexDistinctKeysEstimate`): Ertl's improved raw estimator, IEEE ops only with every product behind a `float64()` barrier, so it is bit-identical across architectures (`TestIndexHLL_FrozenEstimates`); rounded, clamped to [largest per-shard count, sum]. Surfaced as `DistinctKeysEstimate` (`*int`; `--json` `distinct_keys_estimate`). A single-file index reports its exact count.
- **Absent means unknown, never 0:** any covered record without a valid sketch makes the estimate `nil`; rebuild to restore it. The sketch never affects a lookup, so `VerifyIndex` does not check it.
