# Byte layout — the archive point-lookup index and its per-shard key-range and Bloom prunes

Per-topic slice of the byte-layout reference (the archive point-lookup index: one sidecar per shard, the archive manifest's coverage and upkeep, and the per-shard key-range and Bloom prunes). Index (preamble + section map): `.claude/reference/byte-layout.md` — load it first, then only the slice(s) your change touches. The single-file sidecar and its manifest are in `byte-layout/shards-and-index.md`.

**Archive point-lookup index (U51 #359) — one sidecar per shard + the archive manifest's coverage.** `BuildIndex` on a shard archive writes, per shard, a v3 sidecar at the shard's ANCHOR path (`internal/encoding.ArchiveShardIndexPath` = `SidecarIndexPath("archive.pulse#shard.pulse", keys)`): row ids are in-shard ordinals, the fingerprint and `SourceSize` cover the shard's STORED payload and `SourceModTime` is the anchored shard's zero-time mtime — so the file is byte-identical to an anchored build's and an anchored lookup reads it (`TestArchiveLookup_ShardSidecarIsTheAnchorSidecar`). One single scan of the archive (the serial shard iterator, canonical schema, exact u64 words) lays each shard out with the same `indexBucketBuilder` a single-file build uses and flushes it as the scan leaves the shard, so one shard's keys are resident at a time. The index format does NOT move. The archive's manifest (`archive.pulse.indexes.json`, its own `format_version` still `"1"` — the field is additive and `omitempty`) gains, on that index's entry, `shards: [{name, size, crc32, index_path, distinct_keys, indexed_records, key_min?, key_max?}]` in archive order; the entry's `index_path` is the index's LOGICAL name (`SidecarIndexPath` over the archive, carrying the key hash — no file lives there) and its counts are per-shard SUMS (a key in k shards counts k times; the exact union would hold every key of the archive resident). **Shard identity is name + size + zip-central-directory CRC32** (`encx.ArchiveEntry.CRC32`, read with the directory, never recomputed), never a bare name: a same-name, same-size replacement moves the CRC32. **Nothing is stored inside the zip** — a second reserved entry would break every reader that treats a non-`_schema.pulse` entry as a shard. A lookup reads the central directory and the manifest, refuses any current shard no `shards[]` record matches (and any covered shard whose sidecar records another `SourceSize`) with `PULSE_INDEX_STALE` + `details.shards_uncovered` (archive order) BEFORE returning a row — never a silent miss; resolves the key literal ONCE against the CANONICAL schema (a shard dictionary is a prefix of it, so a literal one shard lacks is a miss there, never `PROCESSING_CONFIG`; a literal no dictionary holds is `PROCESSING_CONFIG` exactly as on the single-file twin); probes the one bucket of every shard its recorded key range does not exclude (next paragraph); unions the hits in archive order, ascending in-shard row id — the twin's global-ordinal order — and applies multiplicity across the union (`assert_unique` counts every shard; `first` is the lowest global row); decodes each kept hit through its shard's stored section (`shardRecordLocator`, canonical geometry, exact u64 capture). A covered shard whose sidecar file is gone is `PULSE_INDEX_MANIFEST_STALE`. `VerifyIndex` is the coverage check as its size fast-path (`stat_mismatch`, `VerifyIndexResult.ShardsUncovered`), then a SHA-256 of every stored shard against its sidecar (`fingerprint_match` / `_mismatch`, `ShardsMismatched`); the per-path memo is not used. `ListIndexes` lists an archive from its manifest ALONE (`IndexInfo.ShardIndexPaths`; an anchored build's sidecar no entry names is not an archive index); `DropIndex` prunes the entry and removes the named sidecars plus every current shard's derived one. `Pulse.InvalidatedSidecars` reports each per-shard sidecar. `PULSE_INDEX_UNSUPPORTED_SHARDED` is no longer raised (retained, as `PULSE_CROSSTAB_EMPTY_COLUMNS` was). The comparison attribute's `{record}` reference inherits all of it through `Service.lookupRecords`. Parity with the single-file twin (multiplicity, miss, u64 neighbours, the prefix-dictionary literal, the uncovered refusal): `TestArchiveLookup_*` (`internal/service/archive_lookup_test.go`). **Upkeep on `shard add` / `remove` (`internal/service/index_upkeep.go`) is BUILD BEFORE PUBLISH.** An ordinary add (stored shards kept) scans the new shard ONCE from an unpublished archive holding it exactly as the published one will — the in-place tail append's in-memory twin (`appendUpkeepSource`, `byte-layout/archive-append.md`), or a rewriting add's finished-but-unrenamed stage archive (`archiveWriter.finish` / `publish`) — writes its sidecar for every archive index to `<sidecar>.pulse.tmp-staged` and the manifest with the shard's record appended (identity from the STAGE's central directory, which the rename keeps) to `<manifest>.pulse.tmp-staged`; ANY failure before the archive rename aborts the whole add with the archive, every sidecar and the manifest byte-identical. Then the archive is renamed, then each sidecar, then the manifest — a reader between renames sees an uncovered shard (a loud `PULSE_INDEX_STALE`), never a sidecar for bytes the archive lacks. A remove stages the manifest without the shard's record (an entry losing its last shard is dropped), renames the archive, then the manifest, then deletes that shard's sidecars — no other file. Both emit the mandatory `PULSE_SHARD_INDEXES_UPDATED` warning (`details.action` `added` / `removed`, `details.indexes[{keys, index_path, shard_index_path}]`); `RemoveShard` therefore returns a `*RemoveShardResult`. A rename failing AFTER the archive rename cannot roll back: the mutation stands and the result warns `PULSE_INDEX_STALE` (`details.reason` `index_upkeep_publish_failed`). An unreadable manifest refuses the add / remove up front (`PULSE_INDEX_MANIFEST_INVALID`). An add that RE-ENCODES the stored shards (archive-level set widen, constant-group promotion) keeps nothing — every CRC32 moves — and reports each per-shard sidecar in `AddShardResult.InvalidatedSidecars` (the `Pulse.InvalidatedSidecars` list; an anchored `NewCohortBuilder` append lifts it onto `CohortBuildResult`). `compact` copies shards raw, so sidecars stay valid. Pinned by `TestArchiveIndexUpkeep_*` (`internal/service/archive_index_upkeep_test.go`, root `archive_index_upkeep_test.go`).

**Archive key-range prune — `key_min` / `key_max` (U73 #493).** Each `shards[]` record of an archive index entry carries the shard's indexed-key range: `key_min` / `key_max`, one string per key COMPONENT, in key order (`encx.IndexManifestShard.KeyMin` / `KeyMax`, computed by `encx.IndexKeyRange` from the shard's buckets — `buildArchiveIndex` and `stageAddUpkeep` share `shardManifestRecord`, so an add's record is byte-identical to a fresh build's; a remove keeps the surviving records verbatim). **Encoding:** each bound is ORDER-PRESERVING lowercase hex of fixed width (`encx.IndexKeyOrderComponents`): the component's little-endian key bytes reversed to big-endian; `date` / `datetime` / `decimal128` (two's-complement words) with the sign bit flipped; `f32` / `f64` through the IEEE-754 total-order transform of the RAW bits (sign clear ⇒ flip the sign bit, sign set ⇒ flip every bit), because the index keys on raw bits, so a bit-equal probe always lands inside; `u4` / `packed_bool` take their one-byte key slot; categorical bounds are DICTIONARY-ID bounds, sound because every shard dictionary is a prefix of the canonical one and the literal resolves against canonical. Byte order equals value order, so `bytes.Compare` decides; strings (never JSON numbers) keep `u64` bounds above 2^53 exact. The range is a per-component BOUNDING BOX, not a lexicographic tuple range: a composite key is excluded when ANY component falls outside its own bounds. **Lookup:** after the coverage refusal and the literal resolution, `lookupArchiveHits` skips every covered shard whose range excludes the key BEFORE `probeShardSidecar` — the skipped shard's sidecar is never opened. Consequence, deliberate: a skipped shard's sidecar is not validated, so a stale sidecar (`SourceSize` mismatch) or a missing one there no longer refuses a lookup that shard cannot answer; coverage (name + size + CRC32) is still checked for every shard first, so the range always describes the shard's current bytes. **Absent means probe, never skip:** an empty shard records no range (`omitempty`), and an older binary that round-trips the manifest (`BuildIndex` upsert, add / remove upkeep) drops the fields it does not know — `KeyRangeExcludes` answers "probe" for an absent, wrong-arity, malformed or wrong-width range, so a manifest without the fields costs speed, never a match. The manifest's `format_version` stays `"1"` (additive field); the index format does not move. **Verify:** `VerifyIndex` reads every covered shard's whole sidecar, recomputes its range and compares it with the record (a record with no range matches trivially); any difference is stale with the archive-only reason `range_mismatch` (`IndexFreshnessReasonRangeMismatch`, outranked by `fingerprint_mismatch`) and `VerifyIndexResult.ShardsRangeMismatched` (`--json` `shards_range_mismatched`, omitempty) — a wrong range can hide a match, so it is a freshness failure, repaired by `pulse index build`. The per-shard distinct-key sketch (`hll`, last paragraph) is a further `omitempty` record field — it never prunes, and absent means "estimate unknown"; the Bloom filter is a sidecar FILE instead (next paragraph). Pinned by `TestArchiveLookupPrune_*` (`internal/service/archive_lookup_prune_test.go`, sidecar opens counted) and `TestIndexKeyOrder_SortsByValue` / `TestIndexKeyRange_*` / `TestIndexManifestShard_KeyRangeExcludes` (`internal/encoding/index_key_range_test.go`).

**Archive Bloom prune — the per-shard `.bloom` sidecar (U73 #493).** Superseded on write by the archive Bloom SET (last paragraph, #721): the filter layout, sizing and hashing below are unchanged and are the set's record layout, while the per-shard FILE is now only read for an index built before the set. Beside every per-shard sidecar `BuildIndex` wrote a binary Bloom filter over the composite keys that sidecar holds, at the sidecar's path with `.idx` swapped for `.bloom` (`encx.ArchiveShardBloomPath` / `ShardBloomPathFor` — `archive.pulse#shard.pulse.<keyhash>.bloom`; never inside the zip, never named by the manifest, not a `*.json`, so the table-directory exclusion list does not move). **Layout** (`internal/encoding/index_bloom.go`, every integer little-endian): magic `PULSEBLM` (8) · version `0x01` (1, `ShardBloomFormatVersion` — its own axis, separate from the `.pulse` byte, the `.idx` version and the manifest's `format_version`) · `hash_count` k (1) · `key_width` u32 (one composite on-wire key's bytes) · the shard identity exactly as the manifest records it — `shard_size` u64, `shard_crc32` u32, `name_len` u16 + name bytes · `word_count` u32 · `word_count` × u64 filter words (bit i = word i/64, bit i%64) · trailing IEEE CRC32 of every preceding byte. **Sizing and hashing, integer-only (bit-identical on arm64 and amd64):** 10 bits per distinct key rounded up to a whole word (minimum one; an empty shard's all-zero filter rejects every key), k = 7 (~1% false positives); h = `HashKey(key)` (FNV-1a 64, the bucket hash), h1 = splitmix64(h), h2 = splitmix64(h ⊕ 0x9e3779b97f4a7c15) | 1, probe j is bit (h1 + j·h2) mod bits in uint64 wraparound arithmetic. `TestShardBloom_RoundTripAndFrozenBytes` freezes a filter's bytes. **Lookup:** after the key-range check, `lookupArchiveHits` reads the covered shard's Bloom (one whole-file read) and skips the shard UNOPENED only when the file is present, well formed (magic, version, length, CRC32), stamped with the covered record's exact name + size + CRC32 and key width, and answers "not present" (`encx.ShardBloomExcludes`). **Absent, damaged or stale means probe** — a Bloom has no false negatives, and every other state costs speed, never a match; an index built before the Bloom existed simply has none. **Upkeep:** `shardSidecarIndex`'s callers write it from the same buckets — `buildArchiveIndex` per shard, `stageAddUpkeep` staged as `<bloom>.pulse.tmp-staged` and renamed right after its `.idx` (BUILD BEFORE PUBLISH; a failed Bloom stage aborts the add untouched), `stageRemoveUpkeep` deletes the removed shard's Blooms with its sidecars, `DropIndex` removes every Bloom beside each sidecar it removes; `compact` copies shards raw, so Blooms stay valid; an add that re-encodes the stored shards moves every CRC32, so every Bloom is stale (probe) and the lookups refuse `PULSE_INDEX_STALE` on coverage anyway. `ListIndexes` never lists a Bloom. **Verify:** `VerifyIndex` rebuilds each covered shard's filter from its sidecar and requires a present Bloom to equal it BYTE FOR BYTE; any difference is stale with the archive-only reason `bloom_stale` (`IndexFreshnessReasonBloomStale`, outranked by `fingerprint_mismatch` then `range_mismatch`) and `VerifyIndexResult.ShardsBloomStale` (`--json` `shards_bloom_stale`, omitempty) — a damaged filter stamped with the right identity could hide a match. A missing Bloom is never stale. Pinned by `TestArchiveLookupBloom_*` (`internal/service/archive_lookup_bloom_test.go`, sidecar opens counted) and `TestShardBloom_*` (`internal/encoding/index_bloom_test.go`).

**Archive distinct-key estimate — the per-shard `hll` sketch (U73 #498).** The entry's `distinct_keys` (and `BuildIndexResult` / `IndexInfo.DistinctKeys`) stays the per-shard SUM; the UNION is estimated from a HyperLogLog sketch each `shards[]` record carries as `hll` (`encx.IndexManifestShard.HLL`, `internal/encoding/index_hll.go`), written by `shardManifestRecord` from the shard's buckets — so build and add upkeep record it identically, a remove keeps the survivors' verbatim, and an EMPTY shard records an all-zero sketch (known 0), unlike `key_min` / `key_max`. **Precision p = 10** (`encx.IndexHLLPrecision`): m = 1024 registers, relative standard error 1.04/√m ≈ **3.25%** across the whole range (tests assert within 3σ). **Hashing and registers are integer-only:** x = splitmix64(`HashKey(key)`) (the FNV-1a 64 bucket hash re-mixed as the Bloom's h1); register = top p bits; value = 1 + leading zeros of the remaining 54 bits, capped at 55; merge = register-wise max (exactly the sketch of the union). **Wire form:** standard base64 of [precision byte `0x0a`][768 bytes: the 6-bit registers packed big-endian, four per three bytes] — 1028 characters per shard whatever its size; another precision or length, a register above 55 or bad base64 decodes as NO sketch. **Estimate** (`encx.IndexDistinctKeysEstimate`): Ertl's improved raw estimator (sigma / tau series, no bias table) over the merged registers, IEEE add / multiply / divide / sqrt only with every product behind a `float64()` barrier, so it is bit-identical on arm64 and amd64 (`TestIndexHLL_FrozenEstimates`, `TestIndexHLL_FrozenWireForm`), rounded, then clamped to [largest per-shard `distinct_keys`, their sum] — a one-shard archive reports its exact count. Surfaced as `BuildIndexResult.DistinctKeysEstimate` / `IndexInfo.DistinctKeysEstimate` (`*int`; CLI `--json` `distinct_keys_estimate`, omitempty), computed at build / list time from the records — no entry-level field. **Absent means unknown, never 0:** any covered record without a valid sketch (an index built before it, or a manifest an older binary round-tripped, dropping the field) makes the estimate `nil`; rebuild to restore it. A SINGLE-FILE index reports `DistinctKeysEstimate` = its exact `DistinctKeys` (one file holds each key once). The sketch never affects a lookup, so `VerifyIndex` does not check it. The manifest `format_version` stays `"1"`; envelope `format_version` stays `"1.1"`; nothing is payload-reachable. Pinned by `TestIndexHLL_*` / `TestIndexDistinctKeysEstimate_*` (`internal/encoding/index_hll_test.go`) and `TestArchiveIndexEstimate_*` / `TestIndexEstimate_SingleFileIsExact` (`internal/service/archive_index_estimate_test.go`).

**Archive Bloom set — `<archive>.<keyhash>.blooms` (U73 #721).** Since #721 `BuildIndex` writes every shard's Bloom filter (the per-shard layout of the previous paragraph, byte for byte) into ONE file per archive index instead of one `.bloom` per shard, so a lookup reads its Bloom data in one whole-file read — one GET on object storage — however many shards survive the key-range check (`TestArchiveLookupBloomSet_OneReadIndependentOfShardCount`, `internal/service/archive_lookup_bloomset_test.go`, opens counted). The design call: a separate file beside the archive, not a manifest field — the manifest is parsed by `ListIndexes` / upkeep / every lookup, and ~1.25 bytes per key of base64 Bloom would bloat each of those reads; a separate file is also invisible to an older binary that round-trips the manifest. **Path:** the index's LOGICAL path (`SidecarIndexPath` over the archive) with `.idx` swapped for `.blooms` (`encx.ArchiveBloomSetPath` / `ArchiveBloomSetPathFor`) — never inside the zip, never named by the manifest, not a `*.json` (the table-directory exclusion list does not move), not a `.pulse` (the `pulse://` cohort scan never sees it), listed by `CohortArtifacts` (`^<cohort>\.[0-9a-f]{16}\.blooms$`, beside every per-shard file `^<cohort>#.+\.[0-9a-f]{16}\.(idx|bloom)$` — an archive index travels with its archive, U73 E5-S5). **Layout** (`internal/encoding/index_bloom_set.go`, little-endian): magic `PULSEBLS` (8) · version `0x01` (1, `ArchiveBloomSetFormatVersion` — its own axis) · `count` u32 · `count` × {`len` u32 · `len` bytes: one shard Bloom record in the `PULSEBLM` layout, carrying its own identity stamp and CRC32}, archive order, no trailer. **Each record stands or falls alone:** a record that does not decode, a duplicate name, a length past the end or trailing bytes mark the set `Damaged`, the records that DID decode still prune; a bad header (magic, version, short file) makes the whole set unusable. A record prunes only when stamped with the covered shard's exact name + size + CRC32 and key width (`ArchiveBloomSet.Excludes`); no record, a stale or a damaged one means probe — never a lost match (`TestArchiveLookupBloom_StaleFilterNeverHidesAMatch`). **Lookup** (`archiveBloomPrune` in `index_archive.go`): the set is read lazily, ONCE, on the first shard the range check leaves in play; a set file that EXISTS decides alone (a read error other than not-exist, or a bad header, probes every shard) and no per-shard `.bloom` is read beside it; only when NO set exists — an index built before #721 — does each shard consult its per-shard `.bloom` exactly as before (`TestArchiveLookupBloom_LegacySidecarsStillPrune`). **Upkeep:** a fresh build writes the set and removes, best effort, the per-shard `.bloom` it supersedes; `stageAddUpkeep` stages `<set>.pulse.tmp-staged` with every kept shard's fresh filter (from the existing set, or — migrating an index with no set — from each kept shard's per-shard `.bloom`; a filter that does not decode or match the kept record's identity is dropped, so that shard probes) plus the new shard's, renamed with the sidecars BEFORE the manifest (BUILD BEFORE PUBLISH: a failed stage aborts the add untouched), then — only after the set and the manifest are renamed — deletes, best effort, every per-shard `.bloom` of the kept and new shards (a failed publish keeps them); in any rename order a reader sees at worst a shard with no record (probe). `stageRemoveUpkeep` restages an EXISTING set without the removed shard's record (deletes it when the entry loses its last shard) and never creates one; `DropIndex` removes the set and every legacy per-shard `.bloom`. Build, add and remove leave the set byte-identical to a fresh build (`rebuildMatches`). `compact` keeps it valid; a re-encoding add moves every CRC32, so every record is stale (probe) and coverage refuses anyway. **Verify:** with a set, a covered shard's record must equal the rebuilt filter byte for byte, else `bloom_stale` naming the shard; an undecodable header names every covered shard; a `Damaged` set names every covered shard it holds no record for; an intact set with no record for a shard, or no set and no `.bloom`, is never stale. Without a set the per-shard check of the previous paragraph applies. No format, manifest or envelope `format_version` moves; nothing is payload-reachable. Pinned by `TestArchiveBloomSet_*` (`internal/encoding/index_bloom_set_test.go`) and `TestArchiveLookupBloom_*`.
