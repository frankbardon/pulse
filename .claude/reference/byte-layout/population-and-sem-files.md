# Byte layout — the population file, the SEM fit file

Per-topic slice of the byte-layout reference (the standalone vector-fit population file and SEM fit file, the model file's twins; the model file itself is in `byte-layout/long-form-and-model-files.md`). Index (preamble + section map): `.claude/reference/byte-layout.md` — load it first, then only the slice(s) your change touches.

**Population file — `.pulse-population.json` (`population_format_version` 1).** (U30 E2-S3.) The vector-fit twin of the model file, and NOT a `.pulse` layout or a cohort sidecar: the standalone JSON document a Compose VECTOR fit's `save` writes (`FitSpec.Save` on a fit whose request holds one matrix or fitted-attribute battery, `model.FitKindOf`; gated by `capability:model_save`) so a later plain request scores against the fitted battery without refitting it. **Same conventions, one codec in the leaf:** `internal/model/population.go` (`PopulationFile`, `NewPopulationFile`, `Encode`, `DecodePopulationFile`, `PopulationFile.VectorFit`, `CheckPopulationSavePath`, `PopulationSuffix`, `PopulationFormatVersion`) reuses the model file's `Float` policy (shortest round-trip, NaN `null`, `±Inf` strings), the version-first strict decode, the path rule (`checkFilePath` over the suffix — a vector fit's save MUST end `.pulse-population.json`, a regression fit's `.pulse-model.json`, either other suffix `PULSE_MODEL_SAVE_INVALID` reason `suffix`), the duplicate-path batch rule, the atomic write (`writeModelFile`, `PULSE_MODEL_WRITE_FAILED` via `model.PopulationWriteFailed`) and the MANDATORY overwrite warning (`PULSE_MODEL_OVERWRITTEN` via `model.PopulationOverwritten`, `details.fit`, on `ComposedResponse.warnings`). **Document:** `population_format_version`, `name` (informational), `operator` (the battery's MAT_* / fitted attribute type), `labels` (axis order — what a consumer aligns to BY LABEL), `members`, `basis` (`unweighted` / `frequency` / `probability`), `n` / `n_mass` / `n_weight_invalid`, `sum_weights` / `sum_weights_sq`, `mean` (the RAW stored mean — zeros, not NaN, with no mass), `m2` (the raw co-moment Σw(xi−mi)(xj−mj), full symmetric p × p), `provenance` (the model file's). No struct maps, so one fit encodes to one byte sequence. **Nothing derived is stored:** covariance, correlation, Cholesky, eigen, loadings and rotations are recomputed from `linalg.NewCoMomentFromListwise` at score time, so one file serves every fitted vector operator and a load scores BIT-identically to the in-batch `fit:` on the same architecture (`TestPopulation_SaveThenLoadMatchesFit`); across architectures a recomputed decomposition is tolerance-equal, not bit-equal. **Decode refuses** (`PULSE_MODEL_FILE_INVALID` reason `schema`) no labels, a blank or repeated label, members unlike labels, an unknown basis, a negative count, `n_mass > n`, a non-finite or negative weight sum, a mean / m2 shape unlike the labels and an m2 that is not BITWISE symmetric — exactly what `NewCoMomentFromListwise` and the label alignment need, so a bad file is the file's refusal, never an engine fault; `NewPopulationFile` applies the same check (a malformed state is `PROCESSING_INTERNAL`, never written). **Provenance is informational, NEVER a gate** (the model file's rule, chosen deliberately for populations too): scoring cohort B against a population fitted on cohort A is the point; there is no staleness check. **Load** (`Request.Populations`, `[]types.PopulationRef {name, path}`, gated by `capability:models` — the bound-model namespace's capability): `internal/model/population_load.go` — `Refs` / `RequestRefs` bundle a request's `models` + `populations`; `CheckRefs` runs `CheckModelRefs`, then each population (blank name `PULSE_MODEL_REF_INVALID` `name_empty`, the population path reasons, then `PULSE_MODEL_NAME_COLLISION` against a `models` entry, an earlier population or the outer set, `details.sources` naming slot `populations`); `LoadFiles` reads and decodes (`PULSE_MODEL_FILE_UNREADABLE` / `_FILE_INVALID` / `_VERSION_UNSUPPORTED`, each gaining `details.population` + `name`); `Set.WithLoaded` binds each as a `VectorFit` (`Source` slot `populations`) and `CatalogWithLoaded` is predict's static twin (kind vector, `Members` = the file's labels). Every load site the `models` row names runs it — `Service.process`, materialize, `composeModelsPrepass` (fit requests and slots), the chain pre-pass, `predictSingle`, `loadComposeModels`, `loadChainModels`; a FacetRequest carries no `populations`. **Error family:** no new code — every save / load fault reuses the `PULSE_MODEL_*` code whose semantics match, the entry located by `details.population`. `format_version` does not move: the `populations` key is an additive `omitempty` Request slot.

**SEM fit file — `.pulse-sem.json` (`sem_format_version` 1, 2 or 3).** (U59 E3-S3; version 2 E4-S4.) The SEM-fit twin of the population file, NOT a `.pulse` layout or a cohort sidecar: the standalone JSON document a Compose SEM fit's `save` writes (`FitSpec.Save` on a fit whose request holds one `MAT_SEM` matrix, `model.IsSEMFitRequest`; gated by `capability:model_save`), so a later request scores `ATTR_SEM_SCORE` from the fit without refitting it. **Same conventions, one codec in the leaf:** `internal/model/sem_file.go` (`SEMFile`, `NewSEMFile`, `Encode`, `DecodeSEMFile`, `SEMFile.SEMFit`, `CheckSEMSavePath`, `SEMSuffix`, `SEMFormatVersion`, `SEMOverwritten`, `SEMWriteFailed`, `CheckLoadedSEM`) reuses the `Float` policy, the version-first strict decode, the path rule (a SEM fit's save MUST end `.pulse-sem.json`; a regression or vector fit's save under it is reason `suffix`), the duplicate-path batch rule, the atomic write (`writeModelFile` via `Service.saveFitSEM`, run in the fit's step right after `runSEMFit` binds, so serial and parallel batches write the same bytes) and the MANDATORY `PULSE_MODEL_OVERWRITTEN` (`details.fit`); a failed fit writes nothing. **Document:** `sem_format_version`, `name` (informational), `operator`, `model` (the description), `labels` / `members`, `observed` / `inner` / `latents` (the parsed model's orders — the rows and columns of every stored matrix), `estimator`, `conventions` (`lavaan` / `semopy`), `meanstructure`, `group` / `group_reference` / `group_equal` / `group_partial` (omitted when unset), `solver`, `information`, `basis` (`unweighted` / `frequency`), `n`, `sum_weights`, `dof`, `n_params`, `converged`, `status`, `iterations`, `nearest_pd_min_eigenvalue` (present iff the nearest-PD substitute was used), `groups` (level order; one of level `""` ungrouped — per group `level`, `n`, `sum_weights`, `lambda`, `beta`, `psi`, `theta`, `nu`, `alpha`, `sample_mean` at the estimate, fixed values included), `provenance`. **Version 2 (U59 E4-S4) is an ordinal fit** (`estimator` `dwls` / `wlsmv`): top-level `ordered` (the ordered variables, `observed` order) and `categories` (each one's category values ascending — the raw member values coded 0, 1, …), per group `thresholds` (one list per ordered variable, its categories less one; `theta`'s ordered diagonal is then the delta residual). The version is a function of the content, never a choice — an ML fit writes version 1 byte-identically to a build before version 2, so every version-1 file stays readable, and an older build refuses an ordinal file as `PULSE_MODEL_VERSION_UNSUPPORTED` rather than misreading it; the ordinal keys under version 1, or version 2 without them, are reason `schema` (`SEMFile.checkOrdinal`: ordered names distinct observed variables in observed order, two or more ascending finite categories each, one finite threshold per boundary per group). **Version 3 (sem-group-select E1-S4) is a fit grouped by a column its request computed** (a derived group, either estimator — the ordinal keys optional, signalled by `ordered`): top-level `group_derived: true` and, when the fit declared its levels, `group_levels` (`[{value, label}]`, in order; absent: each group's `level` is an integer's canonical text); a version-2 build would read the computed name as a cohort field, so the version moves. `SEMFile.checkDerived` refuses (reason `schema`) the keys under another version, version 3 without them or ungrouped, fewer than two declared levels, a non-integral value (|value| ≤ 2^53), a repeated value or label, a group `level` outside the declared labels, and, undeclared, a `level` that is no canonical integer. A load signs `Signature.SEMGroup` / `SEMGroupDerived` (known) so the scoring request's computed-group rule (`fit_group_field`) runs at predict and runtime alike. It is `model.SEMFit` field for field (`types.SEMFitResult` 1:1), so a load rebuilds the bound fit exactly (`TestSEMFile_RoundTripBitExact`). **Nothing derived is stored:** the model is re-specified from its description and options and each group's scorer built from the stored matrices by `vectors.RebuildSEMModel` + `semScoreFitFromBound`, the ONE path an in-compose bound fit uses, so loaded scores are the bound fit's bits (`TestSEMFit_SaveThenLoadScoresBitEqual`). **Decode refuses** (`PULSE_MODEL_FILE_INVALID` reason `schema`) no model, empty / blank / repeated labels, observed or inner names, members unlike labels, a latent outside `inner`, unknown conventions or basis, a negative count, a non-finite weight sum, no groups, an ungrouped file not holding exactly one level-`""` group, a repeated level, and any matrix or vector whose shape is not observed × inner; `NewSEMFile` applies the same check (`PROCESSING_INTERNAL`, never written). Right after the decode, `model.CheckLoadedSEM(refs, loaded, vectors.CheckSEMRebuild)` — run by `Service.loadFiles` and predict's `loadModelFiles` alike — refuses a model that does not re-specify the stored `observed` / `inner` / `latents` (`PULSE_MODEL_FILE_INVALID` reason `schema`, `details.model` / `name` / `path`), so a tampered file is the file's refusal, never a `PROCESSING_INTERNAL` mid-scan. **Load** rides `models: [{name, path}]` — NO new request key: the SUFFIX dispatches the kind (`checkModelRefPath`: `.pulse-sem.json` takes the SEM path rule, anything else the model file's; a suffix fault names both); `LoadFiles` keeps SEM entries in `Loaded.SEMs` (index-aligned with `Loaded.Models`, nil at a model-file entry and vice versa), `Set.WithLoaded` binds each via `AddSEM` (`Source` slot `models`), `CatalogWithLoaded` signs it kind `sem` (`Members` = its labels). Every `models` load site therefore loads it — Process, materialize, Compose fit requests and slots, chain stages (a chain stage scoring a loaded fit runs: `TestSEMFit_LoadedChainStage`), facet, predict. Provenance is informational, never compared. No new code; `format_version` does not move.
