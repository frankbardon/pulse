# Byte layout — the population file, the SEM fit file

Per-topic slice of the byte-layout reference (the standalone vector-fit population file and SEM fit file, the model file's twins; the model file itself is in `byte-layout/long-form-and-model-files.md`). Index: `.claude/reference/byte-layout.md` — load it first, then only the slice(s) your change touches.

Both files share the model file's conventions (`byte-layout/long-form-and-model-files.md`, Model file): the bit-exact `Float` policy (shortest round-trip, NaN `null`, `±Inf` strings), version-first strict decode, the save-path rule, the duplicate-path batch rule, the atomic write (`PULSE_MODEL_WRITE_FAILED`), the MANDATORY `PULSE_MODEL_OVERWRITTEN` warning (`details.fit`, on `ComposedResponse.warnings`), informational-only provenance (never a gate — scoring cohort B against a fit on cohort A is the point), and the `PULSE_MODEL_*` error family (no new codes). Neither is a `.pulse` layout or a cohort sidecar, and the save SUFFIX decides the kind: a regression fit must save `.pulse-model.json`, a vector fit `.pulse-population.json`, a SEM fit `.pulse-sem.json`; any other pairing is `PULSE_MODEL_SAVE_INVALID` reason `suffix`. `format_version` does not move for either.

**Population file — `.pulse-population.json` (`population_format_version` 1).** Written by a Compose VECTOR fit's `save` (a fit whose request holds one matrix or fitted-attribute battery, `model.FitKindOf`; `capability:model_save`) so a later request scores against the fitted battery without refitting. Codec: `internal/model/population.go`.

- **Document:** `population_format_version`, `name` (informational), `operator`, `labels` (axis order — consumers align BY LABEL), `members`, `basis` (`unweighted` / `frequency` / `probability`), `n` / `n_mass` / `n_weight_invalid`, `sum_weights` / `sum_weights_sq`, `mean` (the RAW stored mean — zeros, not NaN, with no mass), `m2` (the raw co-moment Σw(xi−mi)(xj−mj), full symmetric p × p), `provenance`. No maps, so one fit encodes to one byte sequence.
- **Nothing derived is stored:** covariance, correlation, decompositions, loadings and rotations are recomputed from `linalg.NewCoMomentFromListwise` at score time, so one file serves every fitted vector operator and a load scores BIT-identically to the in-batch fit on the same architecture (`TestPopulation_SaveThenLoadMatchesFit`); across architectures a recomputed decomposition is tolerance-equal.
- **Decode refuses** (`PULSE_MODEL_FILE_INVALID` reason `schema`) anything `NewCoMomentFromListwise` and label alignment cannot use: no labels, blank or repeated labels, members unlike labels, unknown basis, negative count, `n_mass > n`, non-finite or negative weight sums, mean / m2 shape unlike the labels, an m2 not BITWISE symmetric. `NewPopulationFile` applies the same check (`PROCESSING_INTERNAL`, never written). A bad file is the file's refusal, never an engine fault.
- **Load** (`Request.Populations`, `[]types.PopulationRef {name, path}`, `capability:models`; `internal/model/population_load.go`): ref checks as for `models` (collisions across `models`, earlier populations and the outer set are `PULSE_MODEL_NAME_COLLISION` with `details.sources`), decode faults gain `details.population`. Every `models` load site loads populations too (a FacetRequest carries none); predict signs them as kind vector.
- Directory registration: `byte-layout/table-directories.md` (Populations directory).

**SEM fit file — `.pulse-sem.json` (`sem_format_version` 1, 2 or 3).** Written by a Compose SEM fit's `save` (a fit whose request holds one `MAT_SEM` matrix; `capability:model_save`), right after the fit binds, so serial and parallel batches write the same bytes; a failed fit writes nothing. A later request scores `ATTR_SEM_SCORE` without refitting. Codec: `internal/model/sem_file.go`.

- **Document:** `sem_format_version`, `name`, `operator`, `model` (the description), `labels` / `members`, `observed` / `inner` / `latents` (the orders indexing every stored matrix), `estimator`, `conventions` (`lavaan` / `semopy`), `meanstructure`, group options (omitted when unset), `solver`, `information`, `basis`, `n`, `sum_weights`, `dof`, `n_params`, `converged`, `status`, `iterations`, `nearest_pd_min_eigenvalue` (iff the nearest-PD substitute was used), `groups` (level order; ungrouped = one group of level `""`; per group `lambda`, `beta`, `psi`, `theta`, `nu`, `alpha`, `sample_mean`), `provenance`. It is `types.SEMFitResult` field for field, so a load rebuilds the bound fit exactly (`TestSEMFile_RoundTripBitExact`).
- **The version is a function of content, never a choice:** `1` = ML fit; `2` = ordinal fit (`estimator` `dwls` / `wlsmv`; adds `ordered`, `categories`, per-group `thresholds`); `3` = a fit grouped by a column its request COMPUTED (adds `group_derived: true`, optional `group_levels [{value, label}]`) — an older build would read the computed name as a cohort field, so the version must move. An ML fit writes version 1, byte-identical to the pre-versioning file, so old files stay readable and an older build refuses a newer file as `PULSE_MODEL_VERSION_UNSUPPORTED` rather than misreading it. Version-specific keys under the wrong version, or a version without its keys, are reason `schema` (`SEMFile.checkOrdinal`, `checkDerived` hold the per-key rules).
- **Nothing derived is stored:** the model is re-specified from its description and options and each group's scorer rebuilt by `vectors.RebuildSEMModel` — the ONE path an in-batch bound fit uses — so loaded scores are the bound fit's bits (`TestSEMFit_SaveThenLoadScoresBitEqual`).
- **Decode refuses** (reason `schema`) malformed labels / names, a latent outside `inner`, unknown conventions or basis, bad counts or weights, a bad group set, and any matrix whose shape is not observed × inner; `NewSEMFile` applies the same check. Then `model.CheckLoadedSEM` (runtime and predict alike) refuses a model that does not re-specify the stored orders, so a tampered file is the file's refusal, never a `PROCESSING_INTERNAL` mid-scan.
- **Load rides `models: [{name, path}]` — no new request key:** the path suffix dispatches the kind. Every `models` load site therefore loads SEM fits (Process, materialize, Compose, chain stages, facet, predict); predict signs kind `sem`, including the derived-group signature so the scoring request's computed-group rule runs at predict and runtime alike.
