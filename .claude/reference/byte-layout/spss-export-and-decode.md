# Byte layout — the SPSS sidecar, derived columns, export and convert, target-aware export predict, projected decode, `.pulse.zst`

Per-topic slice of the byte-layout reference. Index: `.claude/reference/byte-layout.md` — load it first, then only the slice(s) your change touches.

**SPSS metadata sidecar.** An SPSS import writes `cohort.pulse.spss.json` (`spss.SidecarSuffix`; distinct from a managed import's `.meta.json`) beside the cohort. JSON, not a `.pulse` layout. It holds every dictionary element the `.pulse` format has no slot for — measure levels, formats, file/variable attributes (7/17, 7/18), documents, weight variable, short names, very-long-string segmentation, MR/MC sets, variable sets, the source charset in the file's own spelling, missing-value specs (raw 8-byte slots verbatim) — and, load-bearing, the `code ↔ label ↔ Pulse dictionary ID` triple per categorical: the cohort dictionary holds SPSS **codes** and this is the only place the **labels** live.

- **Shape:** `{format_version, kind, fingerprint, payload}`. `payload` is flat and self-contained (no paths, offsets or external references) so it can later be lifted into a `.pulse` schema metadata section. `fingerprint` (SHA-256 + `SourceSize` + `SourceModTime`) covers the **`.pulse` cohort**, not the source `.sav`.
- **Read policy** (`spss.LoadSidecar`): **absent → warning** `PULSE_SPSS_SIDECAR_ABSENT` and a default dictionary is synthesised from the schema; **stale → error** `PULSE_SPSS_SIDECAR_STALE` — a stale dictionary over changed data produces a file that looks authoritative and is wrong, so a refusal returns no document at all; **unreadable → error** `PULSE_SPSS_SIDECAR_INVALID` (foreign `kind`, unknown `format_version`, malformed digest, a broken `multiple_response_sets[].fields` array).
- **Staleness is a size+mtime check that still REFUSES on mtime drift** — unlike the index, which escalates to the hash (`byte-layout/shards-and-index.md`, Sidecar point-lookup index). So a `.sav` export through a filesystem that truncates mtimes hits `PULSE_SPSS_SIDECAR_STALE` where a lookup succeeds. The asymmetry is open (#740); `Document.VerifyDigest` is the hash check available to align on.
- **`--ignore-sidecar`** (`spss.WriterOptions{IgnoreSidecar: true}`) skips the READ entirely (healthy or not) and warns `PULSE_SPSS_SIDECAR_IGNORED` on the synthesise path; it never applies a stale dictionary and cannot say which refusal it silenced.
- **Additive fields:** an ABSENT `MRSet.Fields` means "written before the slot existed" and is back-filled by `Document.Normalise`; a PRESENT one of the wrong length is rejected. New fields follow the same pattern, `SidecarFormatVersion` unchanged.
- **Written** through the optional `io.SidecarEmitter` after the cohort write; a source without it imports byte-identically with no sidecar.
- **Carried onto derived cohorts.** `Pulse.Materialize` and `Pulse.Rake` keep source columns verbatim, so they CARRY the document (dropping it stripped every value label): `spss.PrepareSidecarCarry` validates BEFORE the write, `SidecarCarry.WriteFor` rewrites AFTER — every recorded variable kept, one plain numeric variable per added column (or a mirrored copy, refused if the type or dictionary does not fit), a rake-replaced weight variable made plain numeric unless something names it (then not carried) — and re-fingerprints. Not carrying is never a refusal: ONE warning with the cause's own code, and the output exports as sidecar-less. Dictionary IDs survive because the builder pre-seeds source dictionaries in order. Projection through a Materialize `output` block: `byte-layout/writers-and-field-words.md` (Projected SPSS carry).
- **Second reader — the weight suggestion.** Path-based inspect and predict read `payload.weight.variable` as `suggested_weight`, but EVERY refusal is SILENT there (no suggestion, no warning) — optional metadata must not fail or clutter the operation it rides on. See `predict-inspect.md` (Suggested weight).
- Skills: `skills/spss-metadata-sidecar.md`, `skills/spss-response-sets.md`; docs `docs/src/cli/import-spss.md`, `docs/src/internals/adding-io-format.md`.

**SPSS derived columns.** An SPSS import can produce a cohort WIDER than the source dictionary — count columns from the returned schema, never the SPSS variable count. Two additive synthesised kinds:

- a `<var>_missing` `categorical_*` sibling right after every numeric variable declaring user-missing values (the null bitmap is one bit and cannot record *why*);
- one `set_*` bitmask per multiple-DICHOTOMY response set right after its LAST constituent, never instead of the constituents (a bit cannot separate "not selected" from "not asked").
- The CATEGORICAL arm deliberately gets no sibling — the code is already a dictionary entry — so its user-missing entries are FLAGGED (`variables[].categories[].missing` + one per-file `PULSE_SPSS_CATEGORICAL_USER_MISSING`). Do not "fix" this asymmetry.
- `--spss-missing=null` / `spss.WithMissingMode` suppresses the numeric siblings only. Every synthesised column is registered on `payload.derived` (closed `kind` vocabulary, `spss.DerivedKinds()`; nothing derived writes `"derived": []`, never a missing key), so export folds them mechanically, never by name-matching. Skills: `skills/spss-response-sets.md`, `skills/spss-missing-values.md`.

**SPSS export.** `pulse export spss -i cohort.pulse -o out.sav` (and `pulse convert x.csv out.sav`). The import capability's `Export: true` for `spss` and the export block's overlay entry must move together (`TestManifestImportCapability_ExportFlagMatchesExportBlock`). Flags, one per `spss.WriterOptions` field: `--ignore-sidecar`, `--uncompressed`, `--charset`, `--sanitize-names`.

- **The `.sav` writer is a `pio.CohortWriter`**, replacing the row loop: a `.sav` value derives from a categorical's dictionary ID, a set's mask bits and the null bitmap — all erased by text rendering (a null and an empty-string categorical become the same cell).
- **Set masks reach the encoder as `encoding.SetMask` at every rung**, never `uint64` — a `uint64` would export every member at or above bit 64 as "not selected" in a well-formed `.sav`. A member's bit is bounded against its own rung in `NewDataEncoder`'s column check (not per case), so predict sees it. The derived multiple-dichotomy fold keys on `Derived.Kind` and is width-blind; `derived[].sources` records constituents in BIT order.
- **Refused, never silently dropped** (`PULSE_SPSS_EXPORT_UNSUPPORTED` — "this cohort has no honest `.sav` form"): `ExportJob.Includes`, and a non-UTC `--tz` (a `.sav` DATETIME is a naive count with no offset slot, so a local reading would merge a fall-back hour's two instants; UTC-equivalent zones stay byte-identical). Overlays are warn-and-skip. A `convert` builds an intermediate in-memory cohort through the ordinary import path. Encode diagnostics ride `io.TargetWarningEmitter` onto `TargetWarnings`; the CLI re-reads them after `Close`.
- **Value labels:** `ExportJob.Run` and `Predict` resolve label bindings onto the cohort (`CohortSource.ValueLabels` / `ValueLabelOrder`; `io.SPSSWriterOptions.ValueLabels` is the same mechanism, a job binding winning). A bound categorical goes out NUMERIC: codes are the entries' own integers when EVERY entry is a canonical decimal integer with |n| ≤ 2^53; else the table position + 1 (unlisted entries follow, byte-sorted); else rank + 1 in byte-sorted order — never first-seen order. A bound integer field (`u4`–`u32`) keeps its stored integers as codes and labels every table key; a key not canonical in `0..max(type)` is `PULSE_LABEL_KEY_INVALID`, an unenumerable table `PULSE_LABEL_TABLE_NOT_ENUMERABLE`; `u64` stays refused (no exact double past 2^53).
- **Label refusals** are all raised in `BuildDictionary`, so predict ≡ runtime (CLI `pulse export predict --labels` included): a binding beside an HONOURED sidecar `PULSE_SPSS_EXPORT_UNSUPPORTED`, unknown field `PULSE_LABEL_FIELD_UNKNOWN`, wrong type `PULSE_LABEL_FIELD_NOT_CATEGORICAL`, repeat `PULSE_LABEL_DUPLICATE_BINDING`, label > 255 bytes `PULSE_SPSS_WIDTH_OVERFLOW`. Unbound exports are byte-identical (`TestValueLabels_UnboundExportsAreByteIdentical`).
- A synthesised set indicator's variable label is `<set description or name>: <entry>` (≤ 255 bytes, set half shortened first, rune-safe), so a re-import draws no low-quality-description warning.
- **Names:** illegal names are `PULSE_SPSS_NAME_INVALID` / `_COLLISION`; `--sanitize-names` opts into a deterministic rewrite of the SYNTHESISED path only, each rename warned `PULSE_SPSS_NAME_SANITIZED`.
- **Vectors:** on the synthesised path a vector expands to one numeric variable per element (`<field>_<label>` / `<field>_1..N`, element label as variable label; NaN and null write system-missing). The SIDECAR path refuses a vector field with `PULSE_SPSS_SIDECAR_INVALID` — no SPSS import produces one, so a sidecar beside it does not describe the cohort, and binding a same-named variable would encode the vector as a scalar zero.
- Skills: `skills/spss-export.md`, `skills/session-format-flags.md`.

**SPSS convert carries the source through.** `pulse convert survey.sav out.sav` rebuilds a cohort in memory from rendered text, which loses exactly what a `.sav` is encoded from. The optional `io.SourceAwareWriter` / `io.ConvertSource` pair (other adapters: a no-op, output byte-identical to the same adapter without the pair) carries two things together:

- **the DECLARED schema replaces inference** — inference over a rendered set cell sees only TICKED options, so a wide battery re-infers at a narrow rung and silently loses entries, and a value-labelled numeric re-derives as a string of bare numerals;
- **the source's sidecar is re-emitted against the rebuilt cohort** (re-fingerprinted), restoring the `derived` registry — without it every multiple-dichotomy convert collided on names.
- They are carried only when the row stream is FAITHFUL to the schema (one cell per field in order, no `Includes`, no label binding rewriting cells); otherwise neither is carried and the target infers — mismatched facts would bind columns to the wrong cells, silently. A schema-less source (CSV) has `ConvertSource.Schema` nil.

**Export predict is target-aware.** `ExportJob.Predict` consults the target through the optional `io.CohortValidator` (`ValidateCohort`, the write-side peer of `CohortWriter`); diagnostics land on `io.PredictReport.TargetWarnings`. A target that does not implement it gets only the schema-only row-label check every non-`CohortWriter` target shares with `Run` (`internal/io/label_codes.go`; same codes as the `.sav` writer).

- `spss.Writer` runs its own non-data pass (sidecar resolution, `BuildDictionary`, name policy, charset, derived fold, column checks) and discards it, so a predicted refusal is the export's own check code-for-code.
- **Sound but INCOMPLETE by design:** anything needing a record (value width overflow, cell-text charset, a dictionary ID with no code) is unreachable, and predict must NEVER refuse what the export would accept — a false refusal is worse than silence.
- `pulse export predict --format` builds the writer against a MemMapFs and never closes it (no file); it mounts the four `.sav` flags because `--sanitize-names` turns a refusal into a warning. Without `--format`, the text says the target was not checked.
- For a cohort with a vector field a targeted predict also reports `PredictReport.Columns` (the header the row writer would write) and refuses `PULSE_EXPORT_COLUMN_COLLISION` as Run does. Docs: `docs/src/internals/adding-io-format.md`, `docs/src/cli/export-spss.md`.

**Projected buffered decode.** Per-request field projection on the buffered decode iterator is **default-on** and must stay output-transparent (same payload, faster). Opt out: `pulse.Options{DisableProjection: true}` / `--no-project` on `pulse api process`. `Options.ProjectBufferedFields` is deprecated, but set beside `DisableProjection` it turns projection back on (`pulse.go`, `SetProjectBufferedFields`).

- `processing.NeededFields(req, schema, ext)` walks every request slot into a `FieldSet`; the iterator caches `internal/encoding.BuildDecodePlan(schema, retained)` (segments `SkipBytes{N}` and `DecodeFields{Fields, Indices}`; bit-packed runs grouped; bitmap whole-or-skip).
- **A slot the walk misses, or an aggregator param naming a field `addAggParamFields` does not know, fails SILENTLY** — the field is never decoded, `NumericValue` answers `ok=false` on every row, and the request succeeds with a confident zero and `n_null` equal to the admitted count. Add a new field-bearing slot or param to the walk the day it lands.
- A retained `u64` also hands the record its EXACT word (`processing.Record.Uint64Value`) on every reuse path, so keyed readers never collide values above 2^53.
- Extension operators without `FieldInputs` widen to `*`. **Windowed record rows retain the full row:** a windows-only request (no group, aggregation or crosstab) emits whole records, so `NeededFields` widens to `*` for that shape (`TestWindowRecordRows_ProjectionTransparent`).
- Detail: `.claude/reference/execution-modes.md`, `docs/src/internals/extension-points.md`.

**Transport-only compression — `.pulse.zst` (`pulse export transfer` / `pulse import transfer`).** NOT a layout: ONE standard zstd stream (RFC 8878, content checksum on) whose decompressed content is the exact byte image of a cohort — single-file or a whole shard archive. Byte work `internal/io/transfer.go`; facade `Pulse.ExportTransfer` / `ImportTransfer` → `*pio.TransferReport` whose `sha256` is ALWAYS the uncompressed cohort's.

- **Why transport-only:** compressed bytes are not addressable, so compression at rest would cost O(1) `record_at` / `Lookup`, stride segmentation, count-from-length, mmap and per-shard section reads. So there is no third magic variant and archive entries stay Method 0 (store).
- **The only read-side change is classification:** `encoding.ReadHeader` recognises `encoding.ZstdMagic` (`28 B5 2F FD`) and returns `PULSE_COHORT_COMPRESSED` ("decompress first") instead of `ENCODING_INVALID`; every read path keeps that code (`TestTransfer_CompressedCohortRefusedEverywhere`), managed imports included.
- **Import** is atomic (temp + fsync + rename after the stream decoded, its checksum held and the prefix is a Pulse magic), refuses an existing output without `Overwrite`; refusals are `PULSE_TRANSFER_INVALID` (`details.reason` `level` / `not_a_cohort` / `already_compressed` / `not_zstd` / `corrupt_stream` / `output_exists`). Both directions stream in bounded memory. Interoperable with the stock `zstd` CLI.
- **Deliberately not** an io `Format`, a gzip codec or an MCP tool: moving a cohort between machines is an operator act; an agent that meets an artifact gets `PULSE_COHORT_COMPRESSED` naming the CLI fix. Bench and composition with parent groups: `docs/src/format/transfer.md`.
