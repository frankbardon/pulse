# Byte layout — the SPSS sidecar, derived columns, export and convert, target-aware export predict, projected decode, `.pulse.zst`, table-directory sidecar exclusion

Per-topic slice of the byte-layout reference (the SPSS sidecar, derived columns, export and convert, target-aware export predict, projected decode, `.pulse.zst`, table-directory sidecar exclusion). Index (preamble + section map): `.claude/reference/byte-layout.md` — load it first, then only the slice(s) your change touches.

**SPSS metadata sidecar.** An SPSS import writes a SECOND sidecar next to the cohort — `cohort.pulse.spss.json` (`spss.SidecarSuffix`, the `imports.Sidecar` "suffix appended to the cohort filename" convention; deliberately distinct from `imports.SidecarSuffix` `.meta.json`, which a managed import writes for the same cohort). JSON, not a `.pulse` layout. It holds every dictionary element the `.pulse` byte format has no slot for: measure levels, print/write format codes, records `7/17` file attributes and `7/18` variable attributes (kept distinct), record `6` documents, weight variable, compression bias, `nominal_case_size`, original short names, declared byte widths + `7/14` very-long-string segmentation, MR/MC set definitions, `7/5` variable sets, the source charset **in the file's own declared spelling**, product name, missing-value specs in all three shapes (discrete ≤3 / range / range-plus-one-discrete, raw 8-byte slots retained verbatim), and — the load-bearing payload — the `code ↔ label ↔ Pulse dictionary ID` triple per categorical column, since the cohort dictionary holds SPSS **codes** and this is the only place the **labels** live. Document shape: `{format_version, kind, fingerprint, payload}`. **`payload` is flat and self-contained** (no paths, no offsets, no external references) so it can be lifted verbatim into a future `.pulse` schema metadata block — that block is **deferred, not rejected** (it needs a `FormatVersion` `0x01` → `0x02` bump affecting every Pulse user), and this shape is what keeps the door open. `fingerprint` is the only file-bound part and a lift drops it: 32-byte SHA-256 + `SourceSize` (u64) + `SourceModTime` (i64 Unix ns) over the **`.pulse` cohort** (not the source `.sav`), mirroring the sidecar index's size+mtime staleness snapshot. Read-path policy, implemented at `spss.LoadSidecar(fs, cohortPath, spss.WriterOptions{})` (the write side's first act, reached from `pulse export spss`): **absent → warning** `PULSE_SPSS_SIDECAR_ABSENT` and the caller synthesises a default dictionary from the `.pulse` schema (a cohort that was never SPSS-derived correctly has none), **stale → error** `PULSE_SPSS_SIDECAR_STALE` (a stale dictionary over changed data produces a file that looks authoritative and is wrong — a refusal returns NO `SidecarResolution`, so there is no shape in which a caller reaches the stale document), **present-but-unreadable → error** `PULSE_SPSS_SIDECAR_INVALID` (foreign `kind`, unrecognised `format_version`, malformed digest, or a broken `multiple_response_sets[].fields` parallel array). The staleness check is a cheap O(1) size+mtime comparison with the same residual gap `PULSE_INDEX_STALE` has (a size- and mtime-preserving in-place edit) — but it is **no longer the same rule**: the index read path now treats an mtime that moved while the size held as inconclusive and escalates to the fingerprint, while this one still REFUSES there, so a `.sav` export of a cohort read through a filesystem that does not preserve nanosecond mtimes hits `PULSE_SPSS_SIDECAR_STALE` where a lookup would now succeed (`--ignore-sidecar` is the blunt escape). That asymmetry is not a considered position, only the untouched half: `Document.VerifyDigest` already exists and is the same authority the index escalates to. `Document.VerifyDigest` is the authoritative full SHA-256 recompute for a verify-style pass. `spss.WriterOptions{IgnoreSidecar: true}` (`--ignore-sidecar`) suppresses the sidecar READ entirely — not merely the staleness verdict — so a healthy sidecar is ignored too and an unreadable one cannot block; it downgrades both refusals to a `PULSE_SPSS_SIDECAR_IGNORED` warning on the same synthesise-a-default path, and never applies a stale dictionary. That warning deliberately does not report which refusal it silenced — skipping the read means nothing on that path knows. `MRSet.Fields` is additive under `omitempty` and `SidecarFormatVersion` did not move for it, so an ABSENT `fields` key means “written before the slot existed” and is back-filled by `Document.Normalise` from `variables[].short_name` (case-insensitive, first declaration wins), never rejected; a PRESENT one of the wrong length IS rejected. Written via `afero.Fs` + `encoding/json` through the optional `io.SidecarEmitter` interface, which `ImportJob.Run` calls after the cohort write; a source not implementing it yields a byte-identical import and no sidecar. **Second reader — the weight suggestion (weighting-descriptive E4-S3).** Path-based inspect and predict (`Pulse.InspectEnvelope` / `Inspect` / `Predict`, hence `pulse cohort inspect` and `pulse_inspect` / `pulse_predict`) read `payload.weight.variable` through the same `spss.LoadSidecar` and surface it as `suggested_weight` — but EVERY refusal above (absent, stale, invalid) is SILENT there: no suggestion, no warning, because optional metadata must not fail or decorate-with-noise the operation it rides on. The read does not change the document or its policy for export. Detail: `predict-inspect.md` (Suggested weight). Detail: `skills/spss-metadata-sidecar.md` + `skills/spss-response-sets.md` (the derived-column registry) + `docs/src/cli/import-spss.md` + `docs/src/internals/adding-io-format.md`.

**SPSS derived columns.** An SPSS import can produce a cohort WIDER than the source dictionary — count columns from the returned schema, never from the SPSS variable count. Two synthesised kinds, both **additive**: a `<var>_missing` `categorical_*` sibling immediately after every numeric variable declaring user-missing values (the null bitmap is one bit and cannot record *why*, so the reason must be materialised as data), and one `set_*` bitmask per multiple-DICHOTOMY response set immediately after its LAST constituent (never instead of the constituents — a bit cannot separate "not selected" from "not asked"). The asymmetry with the CATEGORICAL arm is deliberate and must not be "fixed": a categorical column already stores the SPSS code as a dictionary entry, so the code is preserved losslessly and a sibling would double the width of an all-categorical survey; those entries are FLAGGED instead (`variables[].categories[].missing` on the sidecar + one per-FILE `PULSE_SPSS_CATEGORICAL_USER_MISSING` diagnostic). `--spss-missing=null` / `spss.WithMissingMode` suppresses the numeric siblings only; the `set_*` column has no opt-out. Every synthesised column is registered on the sidecar's `payload.derived` (closed `kind` vocabulary — `spss.DerivedKinds()` / `spss.DerivedFoldFor`; a cohort that derived nothing writes `"derived": []`, never a missing key), so the export folds them mechanically rather than by name-matching. Detail: `skills/spss-response-sets.md` + `skills/spss-missing-values.md`.

**SPSS export.** `pulse export spss -i cohort.pulse -o out.sav` (and `pulse convert x.csv out.sav`) writes `.sav`; `descriptor.importCapability()` carries `Export: true` for `spss` and `exportCapability()` its `warn_and_skip` overlay entry — `TestManifestImportCapability_ExportFlagMatchesExportBlock` fails if only one moves. Four per-command flags, one per `spss.WriterOptions` field: `--ignore-sidecar`, `--uncompressed`, `--charset`, `--sanitize-names`. The `.sav` writer is a **`pio.CohortWriter`**, the one optional writer interface that replaces the row loop rather than decorating it: `ExportJob.Run` calls `WriteCohort(ctx, CohortSource{FS, Path, Includes, Labelled, TimeZone})` after `SetPulseSchema` + `WriteHeader` and never calls `WriteRow`, because a `.sav` value is derived from a categorical's dictionary ID, a `set_*`'s mask bits and the null bitmap — all three erased by `formatFieldValue`'s rendering (a null and an empty string categorical become the same cell). The mask reaches the encoder as an `encoding.SetMask` at EVERY rung and never as a `uint64`: `readCohortCase` takes `set_u128` / `set_u256` through `encoding.ReadSetMask`, because `ReadFieldValue` refuses them, and a `uint64` there would carry a 206-option battery's low word alone — every member at or above bit 64 exporting as "not selected" in a perfectly well-formed `.sav`. A set member variable's bit is bounded against ITS OWN rung inside `NewDataEncoder`'s `checkColumns`, not on the per-case path, because a bound living per case is a refusal `ValidateCohort` cannot reach: predict would accept a cohort (a `set_u8` declaring ten dictionary entries) that the export fails on record 1. The derived multiple-dichotomy fold is keyed on `Derived.Kind` and is therefore width-blind by construction — a 206-constituent `set_u256` is dropped and its 206 constituents rebuilt exactly as a 3-constituent `set_u8` is — and the sidecar's `derived[].sources` records all 206 in BIT order, so dictionary ID `i` is constituent `i` at any width. Consequences: `ExportJob.Includes` / `Labels` — and a non-UTC `ExportJob.TimeZone` (`--tz`, carried as `CohortSource.TimeZone`, empty for every UTC-equivalent zone so `--tz UTC` stays byte-identical; a `.sav` DATETIME is a naive wall-clock count with no offset slot, so a local reading would drop the offset that separates a fall-back hour's two instants) — are REFUSED with `PULSE_SPSS_EXPORT_UNSUPPORTED` rather than silently dropped, overlays are warn-and-skip, and a `convert` (no cohort exists) buffers rows and builds an intermediate in-memory cohort through the ordinary import path. Encode-side diagnostics ride the new `io.TargetWarningEmitter` optional interface onto `ExportReport.TargetWarnings` / `ConvertReport.TargetWarnings` (nil for every pre-existing adapter); the CLI re-reads them AFTER `Close`, because a writer that encodes at `Close` has raised none of them when the job builds its report. `PULSE_SPSS_EXPORT_UNSUPPORTED` was REPURPOSED, not retired — it now means "this cohort has no honest `.sav` form", matching E3-S2's treatment of `PULSE_SPSS_COMPRESSION_UNSUPPORTED`. Name policy: illegal names are `PULSE_SPSS_NAME_INVALID` / `_COLLISION` by default; `--sanitize-names` opts into a deterministic, collision-safe rewrite of the SYNTHESISED path only, reporting every rename as `PULSE_SPSS_NAME_SANITIZED`. **Vectors:** a `vec_f32` / `vec_f64` field expands on the SYNTHESISED path into one numeric variable per element (`synthesiseVector`, `EncodeVectorElement`, `ColumnPlan.VecElem` bounded against the dim in `checkColumns` so predict sees it), named `<field>_<label>` / `<field>_1..N` by the export's shared rule, the element label as the VARIABLE label, through the ordinary name policy (`PULSE_SPSS_NAME_INVALID` / `_COLLISION`, `--sanitize-names`); `readCohortCase` reads the vector through `encoding.ReadVector` (its `ReadFieldValue` refusal used to fail the export on record 1), and a NaN element and every element of a null vector write system-missing. The SIDECAR path refuses a vector field with `PULSE_SPSS_SIDECAR_INVALID` (details `field`): no SPSS import produces a vector (a vector declaration over a `.sav` is refused) and any rewrite stales the sidecar, so a sidecar beside one does not describe the cohort — and binding a same-named source variable would encode the vector as a scalar zero; `--ignore-sidecar` synthesises the element variables. Detail: `skills/spss-export.md` (Writing `.sav`) + `skills/session-format-flags.md` (Target-format CLI flags).

**SPSS convert carries the source through.** `pulse convert survey.sav out.sav` never builds a cohort on disk, so the `.sav` writer's ROW path rebuilds one in memory from the rendered text — and text is exactly where the two things a `.sav` is encoded FROM do not survive. Both now ride one channel, the optional `io.SourceAwareWriter` / `io.ConvertSource` pair (`SetConvertSource` before `WriteHeader`, type-asserted and otherwise a no-op, so every other adapter's convert output is byte-identical). **The DECLARED schema replaces inference on the rebuilt cohort**, because inference over a rendered `set_*` cell can only see the options somebody TICKED: a 206-member `set_u256` battery whose respondents chose eleven distinct options re-infers at a narrow rung and silently loses a dictionary entry per unticked member, and a value-labelled numeric loses its codes entirely — it re-derives as a STRING variable full of bare numerals, in a `.sav` that opens cleanly. **The source's metadata SIDECAR is written against the rebuilt cohort** (the source Reader's own `pio.SidecarEmitter`, re-fingerprinted by that call — the source's copy is fingerprinted over the SOURCE cohort and `LoadSidecar` would refuse it `PULSE_SPSS_SIDECAR_STALE`), which is what restores the `derived` registry: without it the writer synthesised a default dictionary, expanded the derived multiple-dichotomy column into member variables of its own, and every one collided with the constituent column already in the cohort — `PULSE_SPSS_NAME_COLLISION` refused EVERY multiple-dichotomy convert, at every width. The two are one mechanism because they fail together: a carried sidecar read against a re-inferred dictionary would attach each label to whichever code happened to appear first. Both are carried only when the emitted row stream is FAITHFUL to the schema — one cell per field, in field order, no `ConvertJob.Includes` projection and no label binding inserting or rewriting cells — since facts that do not describe the stream would bind a rebuilt cohort's columns to the wrong cells, which is the silent wrong answer rather than the loud one; an unfaithful stream carries nothing and the target infers exactly as before. `ConvertSource.Schema` is nil for a genuinely schema-less source (a CSV): there is nothing declared to preserve, inference stays the fallback, and `PULSE_SPSS_SIDECAR_ABSENT` still names the intermediate `converted-rows.pulse`. `format_version` does not move — `io.ConvertSource` is not payload-reachable. Detail: `skills/spss-export.md` (Writing `.sav`) + `docs/src/internals/adding-io-format.md`.

**Export predict is target-aware.** `ExportJob.Predict` consults the target through the optional **`io.CohortValidator`** interface (`ValidateCohort(ctx, CohortSource) ([]*errors.CodedError, error)`), the write-side peer of `CohortWriter`; diagnostics land on the new `io.PredictReport.TargetWarnings` slot (symmetric with `ExportReport.TargetWarnings`). A Target that is nil or does not implement it is predicted EXACTLY as before — no extra read, no new failure mode (`TestExportJob_Predict_NonValidatingTargetUnchanged`). `spss.Writer` is the only implementer: `ValidateCohort` runs the writer's own non-data pass (`planCohort` — sidecar resolution, `BuildDictionary`, name policy, charset transcode, derived fold, `NewDataEncoder` column checks) and discards it, so a predicted refusal is the export's own check code-for-code, and it mutates nothing on the Writer. **Sound but INCOMPLETE by design:** anything needing a record (value width overflow, cell-text charset unencodability, a dictionary ID with no source code) is unreachable, and predict must NEVER refuse what the real export would accept — a false refusal is worse than silence. `pulse export predict` reads `--format` (writer built via the `io.NewWriter` factory against a MemMapFs + throwaway path, never `Close`d, so no file is created) and mounts the four `.sav` write flags, because `--sanitize-names` flips a `PULSE_SPSS_NAME_INVALID` refusal into a warning; with no `--format` behaviour is unchanged and the text output says the target was not checked. **For a cohort with a vector field**, a targeted predict also describes the header the row writer would write on `io.PredictReport.Columns` (one column per vector for an `io.ListAwareWriter`, the expanded `<field>_<label>` columns otherwise; nil for a `CohortWriter`, for no target and for a vector-free cohort, which stays predicted exactly as before) and refuses `PULSE_EXPORT_COLUMN_COLLISION` / an unknown `Includes` entry as Run does; the CLI text prints a `Columns:` line. `format_version` stays `"1.1"` — `io.PredictReport` is not payload-reachable. Detail: `docs/src/internals/adding-io-format.md` + `docs/src/cli/export-spss.md`.

**Projected buffered decode.** Per-request field projection on the buffered decode iterator is **default-on** — it is output-transparent (same result payload, only faster and lighter per-record), so callers get the win with no flags. Opt out with `pulse.Options{DisableProjection: true}` or the `--no-project` CLI flag on `pulse api process` (v1: `pulse api process` only — `process-chain` / `compose` do not expose it yet). `pulse.Options.ProjectBufferedFields` is retained but deprecated: setting `true` is a harmless no-op; use `DisableProjection` to force full-record decode. Wiring at `pulse.go`: `svc.SetProjectBufferedFields(opts.ProjectBufferedFields || !opts.DisableProjection)`. `processing.NeededFields(req, schema, ext)` walks every request slot and returns a `FieldSet`; the iterator turns retained set into a cached `encoding.DecodePlan` via `internal/encoding.BuildDecodePlan(schema, retained)`(retained)`. **A slot the walk misses, or a built-in whose `Params` name a field `addAggParamFields` does not know, fails SILENTLY** — the field is decoded onto no `Record`, `Record.NumericValue` answers `ok=false` on every row, and the operator reads a missing input rather than a broken request, so the request succeeds and publishes a confident zero with `n_null` equal to the full admitted count as the only signature. `Crosstab.MarginAggregations` is a walked slot (own `Field`, `Params` fields, and extension widening, exactly as `Crosstab.Cell`); `distinct_by` / `weight_field` / `numerator_field` / `denominator_field` are the aggregator params `addAggParamFields` covers, and a new one belongs there on the day the operator lands. Plan segments: `SkipBytes{N}` (one discard over N bytes) and `DecodeFields{Fields, Indices}` (`Indices` = each field's schema position, which keys the index-keyed reuse record — detail in `.claude/reference/execution-modes.md`). Bit-packed runs stay grouped; null-bitmap whole-or-skip. Extension operators without `FieldInputs` widen retained set to `*`. Bench: ~7× speedup, ~14× fewer allocs on a 4-field projection of a 200-field cohort. Detail: `skills/cohort-schema-design.md` + `docs/src/internals/extension-points.md` + `.claude/reference/execution-modes.md`.

**Transport-only compression — `.pulse.zst` (`pulse export transfer` / `pulse import transfer`).** NOT a layout: a transfer artifact is ONE standard zstd stream (RFC 8878, frame content checksum on) whose decompressed content is the exact byte image of a cohort — single-file `0x01`/`0x02` or a whole shard archive. Byte work: `io.TransferExportJob` / `io.TransferImportJob` (`internal/io/transfer.go`, `github.com/klauspost/compress/zstd`, already in the module graph via arrow/parquet); facade `Pulse.ExportTransfer` / `Pulse.ImportTransfer` → `*pio.TransferReport{source, output, codec, level, layout, cohort_bytes, compressed_bytes, ratio, sha256}`, where `sha256` is ALWAYS the uncompressed cohort's so sender and receiver compare directly. **Why transport-only:** compressed bytes are not addressable ranges, so compression at rest costs `record_at` / `Lookup` O(1) seek, parallel-decode stride segmentation, `RecordCountForPayload` (count from LENGTH), whole-file mmap and `Archive.OpenAt` — none of which this touches. There is deliberately **no third magic-byte variant** and archive entries stay **Method 0**: the ONLY read-side change is error classification — `encoding.ReadHeader` recognises `encoding.ZstdMagic` (`28 B5 2F FD`) and returns `PULSE_COHORT_COMPRESSED` ("decompress first") instead of `ENCODING_INVALID`, and `Service.Open`, `CountRecords`, `descriptor.Inspect` and `descriptor.Predict` keep that code rather than re-wrapping it (the managed-import pool, `imports.Manager.Open` behind `pulse_import`, sniffs the magic and refuses the same way, `.pulse.zst` or renamed `.pulse`) (`TestTransfer_CompressedCohortRefusedEverywhere` pins every facade read path). Import side is atomic (temp + fsync + rename, only after the stream decoded, its checksum held and the decoded prefix is a Pulse magic), refuses an existing output without `Overwrite`, and every refusal is `PULSE_TRANSFER_INVALID` with `details.reason` ∈ `level` / `not_a_cohort` / `already_compressed` / `not_zstd` / `corrupt_stream` / `output_exists`. Both directions stream in bounded memory (`TestTransfer_BoundedMemory`: peak heap flat across a 12× larger file). Interop is two-way with the stock `zstd` CLI. **Deliberately NOT:** an io factory `Format` (`io.FormatFromPath` maps no `.zst`; it is not a tabular format, so `import auto` / `convert` do not see it), a gzip codec, or an MCP tool — moving a cohort between machines is an operator act, and by the `ImportIn` slot policy a slot earns its place only when it is an agent's sole route to a result; an agent that meets an artifact gets `PULSE_COHORT_COMPRESSED` naming the CLI fix. Composition with parent groups: the two SUBSTITUTE on bytes (both remove the repeated parent block) — on a sorted cohort flat+zstd lands within ~5% of grouped+zstd, on a scattered one grouping still wins ~38% over the wire; grouping's at-rest scan and memory wins are what compression never buys. Detail + bench table: `docs/src/format/transfer.md`.

**Table-directory sidecar exclusion — `PULSE_LABEL_TABLES_DIR` / `PULSE_RANGE_TABLES_DIR` (relocated from CLAUDE.md "Build / Env").** Both table directories exclude Pulse's own sidecars by suffix BEFORE any parse attempt — `.spss.json`, `.meta.json`, `.indexes.json`, `.pulse-model.json` (a saved model file, "Model file" below), `.pulse-population.json` (a saved population file, "Population file" below), the list at `isPulseSidecarName` in `sidecar_names.go` — so a cohort's sidecars can share a directory with its tables. **That is an exclusion of KNOWN artefacts, not tolerance of unparseable JSON:** any other `*.json` that fails to parse is still a hard `pulse.New` error naming the path, because a typo'd table must not silently become a table that is not there. A new sidecar suffix joins `isPulseSidecarName` in the same change. `PULSE_TEMPLATES_DIR` does **not** carry the exclusion (`.claude/reference/request-templating.md`). **Collisions.** A name a directory file declares that `Options.Extensions` already declares programmatically is `PULSE_EXTENSION_DUPLICATE` (`details.category` `label_table` / `range_table` / `population`, `name`, `path` — `dirCollision`), raised at `pulse.New`; each table or population has exactly one source. **Populations directory — `PULSE_POPULATIONS_DIR` / `Options.PopulationsDir` (option beats env).** The loader's documents are selected by the population suffix the way the table loaders select `*.json`: every `*.pulse-population.json` directly in the directory (non-recursive) registers as `Extensions.Populations[stem]` (`brand.pulse-population.json` → `brand`); every other file — a label or range table, a cohort and its sidecars, a model file — is skipped unread, so one config directory can hold tables and populations. A population file that does not read or decode fails `pulse.New` naming its path (`PULSE_MODEL_FILE_UNREADABLE` / `_FILE_INVALID` / `_VERSION_UNSUPPORTED`, `details.registered` = the name); a missing directory is a no-op, a non-directory an error. Programmatic entries (`Population{File}` — the encoded document) decode at `New` the same way (a blank key `PULSE_MODEL_REF_INVALID` `name_empty`). Registered populations are FROZEN at `New` and bound as vector fits beneath every request (Process, Compose fits and slots, chain stages, facet, materialize — `model.RegisteredSet`, `Source{slot: "registered"}`); a `fits` / `models` / `populations` entry reusing a registered name is `PULSE_MODEL_NAME_COLLISION`, never a shadow. Predict binds the same names and labels from the instance snapshot (`ExtensionsSnapshot.Populations` → `PopulationCatalog`), and the manifest lists them under `extensions.populations` (`name`, `operator`, `basis`, `labels`, `n` — never the moments). A feature profile hiding `capability:models` registers none.
