# Byte layout — the always-load half (long form), the model file

Per-topic slice of the byte-layout reference (the always-load half (long form), the model file; its population and SEM fit twins are in `byte-layout/population-and-sem-files.md`). Index (preamble + section map): `.claude/reference/byte-layout.md` — load it first, then only the slice(s) your change touches.

**The always-load half, long form — header, schema block, bitmap, field types, shard archive variant (relocated at U18 E1-S1).** What CLAUDE.md's `### Byte-layout invariants` carried before the U18 slim and no paragraph above already states. **Header:** the constants are `encoding.MagicBytes`, `FormatVersionV1` / `FormatVersionV2` and `HeaderSize = 9`; the accepted-version check names the offending byte in its `ENCODING_INVALID`; the version is chosen by `Schema.RequiredFormatVersion` through `WritePreamble`; the `0x01` read path is pinned by the fixture `encoding/testdata/format_v1.pulse`. **Schema block:** the nullable flag byte sits immediately after the type byte, and `1` means the field participates in the null bitmap; an unknown type byte is `ENCODING_INVALID`. The stored byte offset / bit position are a cache of ONE canonical layout, `internal/encoding.LayoutFields(schema)` (running sum of `encoding.Schema.FieldWidth`, the ONE field-aware width every stride / offset / skip sums — never a type-only `ByteSize()`, gated by `TestNoTypeOnlyWidthInStridePaths`; a bit-packed field owns one whole byte at bit 0) — writer and decoder place every field by a width-derived cursor and never read the stored byte offset (the shard dictionary rewrite addresses bytes the same way, `widenFieldOffsets`), but the engine decoder DOES read the stored bit position of a bit-packed field while the writer always fills bit 0 / the low nibble — so shard cohesion (`ValidateStructuralCohesion`) and the shard dictionary rewrite (`rewriteShardDicts`) compare the bit position and the TYPE-DERIVED layout (names, type bytes, field widths), never the stored byte offset (U51 E1-S4, #373): a zero-offset explicit-schema cohort and a pre-canonical schema-file cohort whose first field is bit-packed join, add to and precheck against canonical-offset cohorts and archives with no re-import, and the canonical `_schema.pulse` keeps its seed's stored offsets verbatim. Every reader honours a legacy nonzero bit position identically, with no re-import: the engine `RecordReader` family, export (`internal/io/export.go` `readPackedValue`, through `encoding.ReadBit` / `ReadNibble` — it once read the whole byte), the SPSS cohort writer and lookup (`TestLegacyBitPosition_ExportEngineSPSSLookupAgree`) — so every schema-producing path (inference, explicit schema files via `internal/io.ParseSchemaJSON`, every explicit `ImportJob` / `ConvertJob` / managed-import schema via `resolveExplicitSchema`, which IGNORES caller-supplied offsets, the builder, typed-source adapters, synth, widen) lays out through it. **Bitmap helpers:** `encoding.ReadBitmap` / `WriteBitmap` / `BitmapIsNull` / `BitmapSetNull`, sized by `Schema.BitmapByteSize()`. **Parent groups (`0x02`), the summary CLAUDE.md shortened:** a group dictionary entry is the members' raw on-wire bytes plus member null bits (never strings; members keep their own dictionaries); an indexed group costs a `u32` per row, a constant group holds one entry and no index; `RecordByteSize` / `BitmapByteSize` / `HasBitmap` are PHYSICAL while every field index stays LOGICAL (`Schema.Fields`); physical-byte rewriters refuse via `internal/encoding.RefuseGroups`; written only on request — `--group KEY:MEMBER,...` (key-checked, `PULSE_GROUP_*`, the per-group viability gate) and `--elide-constants`. **Field-type tags:** bit-packed types are named by `FieldType.IsBitPacked()`, dictionary-bearing ones by `FieldType.HasDictionary()`. **Wide set rungs:** `set_u128` is type byte `18`, stride 16 bytes, ≤128 members; `set_u256` is type byte `19`, stride 32 bytes, ≤256 members — 256 is a hard ceiling; import inference picks the SMALLEST rung that fits; both are too wide for the `uint64` `Read/WriteFieldValue` API, which refuses them with `ENCODING_TYPE_MISMATCH` rather than truncating (`FieldType.IsWideSet()`). `datetime` is type byte `17`; `date` is epoch DAYS and `datetime` epoch SECONDS, so swapping them rescales every value by 86,400. **Vector types:** `vec_f32` / `vec_f64` are type bytes `20` / `21`, width element × dim with the dim in the `0x02` VECTORS section ("Vector fields"). **Shard archive variant:** an uncompressed Zip64 (store-only) container whose leading `PK\x03\x04` magic is dispatched at `pulse.Open` — the single-file byte format is unchanged; it holds the reserved `_schema.pulse` entry (canonical schema + SHRD trailer) plus N standalone shards — at most 65535 (`encx.MaxArchiveShards`), because the trailer's `shard_count` is a `u16`: create, add and the filter-to-file archive arm refuse a larger count with `PULSE_SHARD_COUNT_LIMIT` (`details.shard_count`, `details.limit`) before writing anything, and the shared `_schema.pulse` builder refuses it too, so no writer stores a wrapped count; cohesion is structurally strict, categorical dictionaries union-merge, and the anchor `archive.pulse#shard.pulse` opens one shard. **Store-only is what makes it a random-access format:** every read path (U51 E1-S1, `internal/service/archive_open.go`) reads the central directory at the tail through an `io.ReaderAt` and each shard as a SectionReader at its data offset — never the archive whole — so a DEFLATED entry (a third-party zip tool's) is refused with `PULSE_ARCHIVE_CORRUPT` on every record path (serial scan, per-shard reducer, record reader) rather than decoded as compressed bytes; header-only surfaces (`PeekShardRecordCount`) still count it by draining. **Per-field nullability is part of cohesion and never widens** (`encoding.ValidateStructuralCohesion` → `nullabilityCohesion`, so `AddShard` / `CreateShardArchive`, `shard verify`, the anchored `NewCohortBuilder` pre-check and the archive record reader all inherit it): every shard decodes under the CANONICAL flags, so an archive field that is NOT nullable refuses a shard declaring it nullable — the canonical decode would ignore the null bit and a stored null would read back as its placeholder value, silently, whenever another nullable field keeps the bitmap width (and so the stride) equal. The reverse — a nullable archive field, a non-nullable shard field — is admitted as-is only when the two null bitmaps are the same width and the field is no parent-group member (a member's null bits ride its group entry, whose width the member nullability decides): every Pulse writer leaves a non-nullable field's bitmap bit 0 (`TestCohortBuilder_NonNullableShardInNullableArchive`), so each row reads non-null. Every refusal is `PULSE_SHARD_SCHEMA_MISMATCH` with `details.dimension: "nullable"` (plus `canonical_bitmap_bytes` / `incoming_bitmap_bytes` on a width refusal); no nullable-widening rewrite exists. Order therefore matters at seed: `[nullable, non-nullable]` builds, `[non-nullable, nullable]` refuses. A `set_*` field WIDENS (never narrows) to the narrowest rung that holds the union, past `set_u256` is `PULSE_SHARD_DICT_WIDTH_OVERFLOW` ("Shard set-width auto-widen"); grouped shards share ONE archive group layout, the archive's wins ("Shard archives with parent groups"); every archive rewrite is atomic and reports a MANDATORY warning (`PULSE_SHARD_SET_WIDENED` / `PULSE_SHARD_GROUPS_REWRITTEN`). An ORDINARY `shard add` does not rewrite: it appends the shard, a refreshed `_schema.pulse` and a new directory to the tail in place ("Shard add tail append", `byte-layout/archive-append.md`). `.pulse.zst` is transport-only and a read refuses it with `PULSE_COHORT_COMPRESSED` ("Transport-only compression"). **A dictionary code is valid only inside its dictionary (U51 E5-S8).** Every shard decodes against the CANONICAL dictionary, of which each shard's own is a prefix, so a non-null `categorical_*` index at or past the canonical length — or a `set_*` bit at or past it — is corrupt record data, and every reader that keys, labels or renders it refuses with `ENCODING_INVALID` (`details.reason` `categorical_index_out_of_range` / `set_member_out_of_range`, plus `field`, `index` / `bit`, `dictionary_size`; one constructor, `internal/encoding.CategoricalIndexFault` / `SetMemberFault`): `GROUP_CATEGORY` (every arm, fused crosstab axes included — it used to MINT the index as a numeric-key group), the set groupers, join keys, expressions (only the fields an expression reads; `$env` reads all), `FILTER_TRUE` truthy, record rows, Sample / Lookup cells, the rich facet, export (judged AFTER the null bitmap — import stores placeholder `0` under a null even over an EMPTY dictionary, and that is not data), the SPSS set-member columns and the public record reader. **Level reads refuse too (U51 E5-S10)** — they used to read the code as absent like a null and drop the row silently: every engine level read goes through `Record.StringValueChecked` / `LevelValueChecked` (test `split_by`, contingency axes and the `TEST_PROP_Z` outcome, a comparison attribute's `key_field` / centroid `by`, the include-set label predicate, the encoders and the `FEAT_TRAIN_TEST_SPLIT` stratify key), and a regression's `cluster` / `jackknife_by` is judged before the fit reads a row (`regression.LevelFault`; `clusterKey` never falls back to the code's numeric echo). A test or regression slot fails ALONE (`slotfail.CorruptRecordData` admits exactly this refusal to every per-slot kind; a grouped test's bucket gets the sparse-group result); a feature, attribute or filter fails the run. `extend.Record.StringValue` keeps its signature: the root view answers `("", false)`, latches the fault on the engine row (`Record.NoteReadFault`) and every adapter returns it in place of the extension call's result (`TakeReadFault`; `ClearForRow` drops a stale one). The rich facet's filter errors fail the facet (`allPass`), never drop the row. `TestLevelReaders_Checked` fails an unchecked engine read; pinned by `TestCorruptLevel_*`, `TestExtendRecord_StringValueRefusesCorruptCode`. Deliberate exceptions read the CODE, never a label: numeric aggregators over a code (`AGG_MODE`, `AGG_DISTINCT_COUNT`, `AGG_FREQUENCY`…) and set aggregators (bits past the tail are excluded from per-label maps); `FILTER_INCLUDE` / `EXCLUDE` / `ATTR_CODE_IN` match code sets (a corrupt code matches nothing); index keys are the raw ID; a per-row zone field reads an unknown code as a null zone (documented); SPSS categoricals already refuse under `PULSE_SPSS_EXPORT_UNSUPPORTED`; derived-column codes are `PROCESSING_INTERNAL`. Pinned by `TestCorruptCategorical_*`.

**Model file — `.pulse-model.json` (`model_format_version` 1 + `features`).** NOT a `.pulse` layout and not a cohort sidecar: a standalone, human-readable JSON document a regression `save` writes (`RegressionSpec.Save` after the request's run, `FitSpec.Save` after the Compose fit pre-pass, both gated by `capability:model_save`) at an afero path relative to the instance filesystem root, so a later request can score from it without refitting. **One codec, in the leaf:** `internal/model/file.go` (`File`, `NewFile`, `Encode`, `DecodeFile`, `File.Bind`, `CheckSavePath`; stdlib + `types` + `errors` + the no-execute params readings `paramread` / `distlagparams` / `windowparams` only, `TestModel_ImportBoundary`) — the runtime and the no-execute predict path (`internal/descriptor`, `TestPredictNoExecutionImports`) parse ONE format with ONE rule set; the write is the service's (`internal/service/model_save.go`). **Document:** `model_format_version` (always 1), `features` (the optional sections the file carries — see Versioning; absent when none), `name` (informational — a load binds the name the loading request gives), `type`, `family` / `link` (GLM), `penalty` / `selection` / `resample` (echoes), `target`, `predictors` (fit order; under selection the RETAINED ones only), `terms` (the candidate set; equal to `predictors` without selection), `coefficients` / `std_errors` / `ci_lower` / `ci_upper` (maps keyed like `RegressionResult`'s, `(intercept)` included; an absent term has no figure), `df`, `conf_level`, `vcov` (`{kind, encoding, row_keys, column_keys, values}`), `dispersion` (feature `dispersion`, beside a classical `vcov`: `RegressionResult.Dispersion`, the estimated φ̂ a classical vcov carries — REG_OLS σ̂², REG_GLM gamma's Pearson χ²/df, a fixed-θ `negative_binomial` fit's under `dispersion: estimated` — which a bound fit's influence figures read, U65 E1-S2 / E2-S2; `null` when undefined), `theta` (feature `theta`: a `REG_GLM` `negative_binomial` fit's `RegressionResult.Theta`, finite and > 0 — the θ its residual kinds and influence figures read through V(μ) = μ + μ²/θ, U65 E2-S2), `n_obs`, `sum_weights` / `n_eff` (weighted fits only), `covariance` (feature `robust_covariance`: the `RegressionResult.Covariance` echo `{type, cluster, clusters, order_by, lags}` naming the robust estimator the standard errors, intervals, df and vcov came from — U25 E5-S2), `outputs` (feature `outputs`: an extension regression's `RegressionResult.Outputs`, each value in its WIRE JSON form via `types.MarshalFinite` — a non-finite output is `null`, unlike the bit-exact `Float` figures — read back as plain JSON values; `model.NormalizeOutputs` gives the in-request fit the very same form, so an extension `Scorer` scores a fit and its reloaded file identically, `TestModelFile_ExtensionRoundTrip`, U53 E2-S2), `provenance {cohort, fingerprint ("sha256:<hex>" of the training cohort's bytes, omitted when it cannot be computed), request_digest (`Request.Hash`)}`. Keys sort, two-space indent, trailing newline: one fit encodes to one byte sequence. p-values and fit statistics are NOT saved (not scoring figures); `File.Result()` rebuilds a result holding the saved figures only. **Floats are bit-exact — the policy:** a finite float64 is Go's shortest round-trip form (negative zero `-0`, subnormals exact); NaN (an undefined figure — a `df ≤ 0` bound, an undefined vcov entry) is JSON `null` and reads back NaN, never 0 (NaN payload bits are not kept); `±Inf` is the JSON STRING `"+Inf"` / `"-Inf"` (the wire contract's `MarshalFinite` would collapse it to null — a model file must not); any other string is refused. `File.Bind(name)` rebuilds the Bound the in-request fit binds to, every figure bit-identical (`TestModelFile_RoundTripBitExact`, `TestModelSave_ProcessRoundTripsBitExact` across OLS + vcov, GLM, Bayes, selection, resample, weighted and a grouped request — a grouped request's regression is cohort-wide). **Versioning — one version plus a `features` list (U79 E3-S1):** `model_format_version` is always `1` (`FileFormatVersion`); what a file carries beyond the plain fit is LISTED, never encoded in the version: `features` ⊆ `robust_covariance` (`covariance`), `outputs` (`outputs`), `dispersion` (`dispersion`), `theta` (`theta`), `sweep_axes` (`sweep_axes`, U79 E3-S2), `adstock` (`adstock`, U79 E4-S1) — `model.FileFeatures()`, the registry `fileFeatures` in `internal/model/file.go`, one entry `{name, key, present, rule}` per section, so a new section is one entry plus its `File` field and the setter that fills it. The writer DERIVES the list from the sections present (`presentFeatures`, registry order) — exactly what is present, never set by hand; a plain fit lists none and writes no `features` key, byte-identical to a version-1 file of earlier builds. The reader judges SHAPE BY THE LIST: a listed feature without its section, or a section whose feature is unlisted, is reason `schema`, as is a duplicate entry; each present section then obeys its rule — `robust_covariance` a robust `type`; `outputs` a non-built-in `type` (an EXTENSION or model regression's fit — a type outside `types.AllRegressionTypes`, saved only when its registration supplies a `Scorer` — whose coefficients are named by its model, so no `(intercept)` nor one coefficient per predictor is required, at least one coefficient is; such a fit with no outputs lists no feature); `dispersion` a built-in fit with a `vcov` and no `covariance` (a vcov fit of an earlier build is a featureless file with no dispersion, which a design-reading `params.fit` slot refuses with `requires: dispersion`); `theta` a built-in `negative_binomial` fit with a finite θ > 0, and a `negative_binomial` file must list it (`theta` + `robust_covariance` and `theta` + `dispersion` are the fits' combinations). `sweep_axes` is the winning slot's axis values (`RankEntry.Axes`) of a `fits[].from_sweep` fit that saves — a map axis → RAW JSON value (`types.MarshalFinite`; `File.SetSweepAxes`, called by `writeModel` with the pass's `winnerAxes[i]`), so a number, string or bool reads back exactly; its rule: non-empty (a sweep has ≥ 1 axis); it combines with every other section. `File.Bind` restores `SweepBound` + `SweepAxes` (numbers decoded as `json.Number`, normalised by `SweepAxis` to the same float64 the in-request fit reads) and `CatalogWithModels` sets `SweepBound` / `SweepAxes` / `SweepAxesKnown` from the file, so `sweep_axis()` on a loaded model (`models: [{name, path}]` — attributes, filters, window params, `AGG_CONSTANT` `expr`, optimize, Materialize) reads the saved winner and predict judges `axis_unknown` statically exactly as the runtime does; the VALUE stays the model's (a window param / `AGG_CONSTANT` `expr` reading it is listed under `unresolved_scalars`, as `coef()` over a loaded model is). A file without `sweep_axes` binds not sweep-bound: `not_sweep_bound` (`TestModelFile_SweepAxes*`, `TestSweepSaved_*`). `adstock` is a media-mix fit's per-channel adstock LINEAGE — what `response()` reads, so it never guesses a decay or L: a map channel → `model.Adstock` `{kernel, decay | shape + scale, max_lag, normalize}` (a `WIN_DISTRIBUTED_LAG` kernel, e.g. `{"kernel": "geometric", "decay": 0.6, "max_lag": 8, "normalize": true}`). Written only by lineage (`model.AdstockLineage`, taken in `Service.process` over the request's windows RESOLVED by the run's own pass, `processing.ResolveWindowScalars` — a decay read through `sweep_axis()` or `params.d` records the number the window used, never the expression): a `REG_MMM_HILL` channel (a `params.channels` predictor) that is the output column of EXACTLY ONE `WIN_DISTRIBUTED_LAG`, whose field no other window writes and which no feature or attribute label overwrites, records that window's params (`normalize` default true); a `REG_MMM_BAYES` channel records geometric at its `decay:<ch>` posterior mean, `params.max_lag` (default `model.MMMBayesDefaultMaxLag` 13, the model's own), `normalize: false`; a channel built any other way (`WIN_LAG` + a formula, a feature, a cohort column) records NOTHING — no inference. A regression `save` writes it (`File.SetAdstock` from `writeModel`); a Compose fit's Process hands it back through an `adstockSink` on ctx, so the in-request Bound (`Bound.Adstocks`, accessor `Bound.Adstock(channel)` — a copy) and the fit's `save` carry the same record; `REG_MMM_BAYES` cannot save, so its record lives on the bound fit and an inline model. Rule: a `REG_MMM_HILL` / `REG_MMM_BAYES` file only, non-empty, every key a predictor with a `k:<key>` coefficient, every record a kernel `distlagparams.Resolve` accepts (`Adstock.Weights` — the window's own FMA-free reading). `File.Bind` restores it (`TestAdstockLineage_*`, `TestModelFile_AdstockRoundTrip`, `TestDecodeFile_AdstockRefusals`). Order on read is free. The version is read FIRST: absent or null is `PULSE_MODEL_FILE_INVALID` reason `version_missing`, non-integer reason `schema`, any value but 1 `PULSE_MODEL_VERSION_UNSUPPORTED` (`details.version`, `supported` [1]) — the RETIRED ladder 2–6 (which encoded feature combinations as integers) with a "re-save the fit" message, deliberately NO alias (owner decision; embedders re-save). `features` is read NEXT, before the strict decode: not a list of strings is reason `schema`; a name this build does not know is `PULSE_MODEL_VERSION_UNSUPPORTED` with `details.unknown_features` (file order, deduplicated) and `supported_features` — so a newer build's section is refused precisely, never misjudged as an unknown key (`TestModelFile_FeatureCombinationsRoundTrip` — every combination, bit-exact; `TestDecodeFile_LegacyVersions`, `TestDecodeFile_UnknownFeature`, `TestDecodeFile_Refusals`, `TestModelFile_RobustCovarianceRoundTrip`). Every file decodes STRICTLY — an unknown key, a mistyped value, no `type` / `target` / `(intercept)` (built-in types), a predictor without a coefficient (built-in types) or outside `terms`, terms ≠ predictors without a selection, a ragged vcov is `PULSE_MODEL_FILE_INVALID` reason `schema`; malformed JSON reason `json`. A new section is a new FEATURE, never a version bump and never a silent extension. **Provenance is informational, NEVER a gate:** no load compares the fingerprint or digest with anything — a model trained on cohort A scores cohort B with the same predictor columns; there is deliberately no staleness check (unlike the sidecar index). **Save path** (`CheckSavePath`, shared by runtime and predict, checked before any record is read — for `fits`, before any fit runs, so no entry writes in a batch a later entry's path refuses): non-blank, a file name ending `.pulse-model.json` with a stem, never above the root once cleaned (`PULSE_MODEL_SAVE_INVALID` reasons `path_empty` / `suffix` / `name_missing` / `escapes_root`; `details.regression` or `details.fit`). The suffix is mandatory so the table-directory exclusion can recognise every model file. **No silent drop, no silent clobber:** two saves naming one file (compared after `path.Clean`) in a request (`model.CheckRequestSaves`) or anywhere in a Compose batch — `fits[i]`, `fits[i].request.regressions[j]`, `requests[k].regressions[j]` — are `PULSE_MODEL_SAVE_INVALID` reason `duplicate` with `details.sites` naming both writers; a batch judges EVERY save path in its pre-pass (`model.CheckComposeBatch`, right after `CheckFits`, serial and parallel and `PredictCompose` alike — a slot's fault gains `details.request`), so no fit or slot writes in a batch a later path refuses. Materialize refuses `regressions` (`PULSE_MATERIALIZE_SLOT_UNSUPPORTED`) and the chain gate refuses a regression on every stage (`PULSE_CHAIN_NOT_MERGEABLE`, stage 0 before it runs), so neither ever writes a model file (`TestModelSave_MaterializeRefusesSave`, `TestModelSave_ChainNeverWrites`, `TestModelSave_DuplicatePathsRefused`, `TestModelSave_ComposeSlotPathBeforeAnyRun`). **Write:** temp + fsync + rename beside the target (`afero.TempFile`, staging name `<file>.<rand>.tmp` — ends in `.tmp`, never `.json`, so an orphan is never mistaken for a table), parent directories created; a failure at `stat` / `mkdir` / `create` / `write` / `sync` / `close` / `rename` is `PULSE_MODEL_WRITE_FAILED` (`details.stage`), the target keeps its previous bytes and the temp file is removed (`TestModelSave_FailedWriteLeavesTargetIntact`). Overwriting succeeds with the MANDATORY warning `PULSE_MODEL_OVERWRITTEN` — on `Response.warnings` (`details.regression`) for a regression save, on the batch-level `ComposedResponse.warnings` (`details.fit`; a keep path the Compose `return` cannot drop) for a fit save or a save on a fit request's regression. A `return` never skips a regression that saves (the compute-plan save veto). An unnamed regression's model is named after its file stem. **Load** (`Request.Models` / `FacetRequest.Models`, `[]types.ModelRef {name, path}`, gated by `capability:models`): `internal/model/load.go` — `CheckModelRefs` (static, first fault: blank name `PULSE_MODEL_REF_INVALID` `name_empty`, the save-path rule's reasons on `path`, then `PULSE_MODEL_NAME_COLLISION` against an earlier entry or what is already bound — a Compose slot's fits — with `details.sources` [{slot, index[, path]}] naming both), then `LoadModelFiles` (each file read through a `ReadFunc` — the runtime's `Service.ReadModelFile` over afero, which refuses a directory; predict's `PredictOptions.ModelLoader`, the same service method — `PULSE_MODEL_FILE_UNREADABLE` `missing` / `unreadable`, then `DecodeFile`'s codes, each gaining `details.model` / `name`), then `Set.WithModels` (runtime: `File.Bind` under the entry's name, `Bound.Source`) / `CatalogWithModels` (predict: the same `Signature`s). A plain request loads in `Service.process` right after its save rule; a Compose batch loads every fit request's and slot's files in its pre-pass (`composeModelsPrepass`, after `CheckComposeBatch`) and a chain every stage's (after `CheckChainModels`), before anything runs, handing each request a context already carrying its final set (`withModelsBound`, so its Process does not reload) — a load therefore always reads the file as it was BEFORE the run, even one a fit in the same batch saves. A fit request sees only its own `models`; each chain stage loads its own namespace. A loaded name scores exactly like the fit that saved it (`TestModelLoad_ScoresBitEqualToFit`, OLS / GLM / Bayes), on every surface (`TestModelLoad_Surfaces`), across cohorts — provenance is never compared (`TestModelLoad_CrossCohort`); predict refuses every fault with the runtime's error (`TestModelLoad_PredictRuntimeParity_*`). Right after the decode, a file of an extension type the instance does not register — or registers but hides under its feature profile — is `PULSE_MODEL_REGRESSION_UNREGISTERED` (`model.CheckModelTypes` / `CheckLoadedTypes`, `details.model` / `name` / `path` / `type`; `Service.loadFiles` and predict's `loadModelFiles`, `TestExtensions_RegressionModelUnregistered`): nothing could score it. **Inline models (U79 E3-S3):** a `models` entry sets exactly one of `path` / `inline` (`CheckModelRefs`: both `PULSE_MODEL_REF_INVALID` `path_and_inline`, neither `path_empty`); `inline` is the model-file document itself, loaded by the same `LoadFiles` on both sides (`internal/model/inline.go` `loadInline`): every string at a number position (`InlineNumberPaths` — an `adstock.<channel>` record's `decay` / `shape` / `scale` / `max_lag` included, `TestInline_DeclaresAdstock` — mirrored by `exprslots.SlotInlineModelNumber` — a template never splices there, the reads walker reports each) except the codec's `"+Inf"` / `"-Inf"` is a scalar expression over literals and `params.<name>` (`Refs.Params`, the request's — an optimize block's are the batch's) with NO request-bound function in reach, run through the caller-supplied `InlineNumberFunc` (`scalarslot.InlineNumber`; `internal/model` cannot import `internal/scalarslot`), so predict resolves every number exactly as the runtime (`inline_invalid` / `_not_numeric` / `_not_finite` / `_not_integer`, `details.field`; a params refusal keeps its code); then `DecodeFile` (source `(inline)`, `details.inline` replacing `path`) and `checkInline` — type ∈ `InlineTypes` (`REG_OLS`, `REG_GLM`, `REG_BAYES_LINEAR`, `REG_MMM_HILL`, `REG_MMM_BAYES`; `inline_type_unsupported`) and the coefficients (and `std_errors` / `ci_*` keys) naming exactly `(intercept)` + predictors + `ModelRegressionTerms` over the channels (a predictor with a `k:` / `s:` / `decay:` coefficient): `inline_term_unknown` / `inline_term_missing`. It binds with `Source.Inline` (`InlineSource` / `RefSource`; collisions name `inline: true`), so `coef()` / `sweep_axis()` read it, and `CheckScoreFor` / `CheckFitReference` refuse a score of it (`PULSE_MODEL_SCORE_INVALID` `inline_not_scorable`) after the kind check. Filter-to-file keys an inline entry's identity by its body bytes (`modelIdentities`). Pinned by `TestInline_*` (`internal/model`), `TestInlineNumber` (`internal/scalarslot`), `TestOptimize_InlineTruthVsSavedFit`, `TestOptimize_InlineRefusalParity`, `TestModels_InlineScoreRefusedParity` (root). `format_version` does not move: the file is not payload-reachable; the `save` keys and `ComposedResponse.warnings` are additive `omitempty` slots.
