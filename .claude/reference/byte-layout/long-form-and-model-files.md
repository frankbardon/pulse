# Byte layout — the always-load half (long form), the model file, the population file

Per-topic slice of the byte-layout reference (the always-load half (long form), the model file, the population file). Index (preamble + section map): `.claude/reference/byte-layout.md` — load it first, then only the slice(s) your change touches.

**The always-load half, long form — header, schema block, bitmap, field types, shard archive variant (relocated at U18 E1-S1).** What CLAUDE.md's `### Byte-layout invariants` carried before the U18 slim and no paragraph above already states. **Header:** the constants are `encoding.MagicBytes`, `FormatVersionV1` / `FormatVersionV2` and `HeaderSize = 9`; the accepted-version check names the offending byte in its `ENCODING_INVALID`; the version is chosen by `Schema.RequiredFormatVersion` through `WritePreamble`; the `0x01` read path is pinned by the fixture `encoding/testdata/format_v1.pulse`. **Schema block:** the nullable flag byte sits immediately after the type byte, and `1` means the field participates in the null bitmap; an unknown type byte is `ENCODING_INVALID`. The stored byte offset / bit position are a cache of ONE canonical layout, `internal/encoding.LayoutFields(schema)` (running sum of `encoding.Schema.FieldWidth`, the ONE field-aware width every stride / offset / skip sums — never a type-only `ByteSize()`, gated by `TestNoTypeOnlyWidthInStridePaths`; a bit-packed field owns one whole byte at bit 0) — writer and decoder place every field by a width-derived cursor and never read the stored byte offset (the shard dictionary rewrite addresses bytes the same way, `widenFieldOffsets`), but the engine decoder DOES read the stored bit position of a bit-packed field while the writer always fills bit 0 / the low nibble, and shard cohesion compares both. Every reader honours a legacy nonzero bit position identically, with no re-import: the engine `RecordReader` family, export (`internal/io/export.go` `readPackedValue`, through `encoding.ReadBit` / `ReadNibble` — it once read the whole byte), the SPSS cohort writer and lookup (`TestLegacyBitPosition_ExportEngineSPSSLookupAgree`) — so every schema-producing path (inference, explicit schema files via `internal/io.ParseSchemaJSON`, every explicit `ImportJob` / `ConvertJob` / managed-import schema via `resolveExplicitSchema`, which IGNORES caller-supplied offsets, the builder, typed-source adapters, synth, widen) lays out through it. **Bitmap helpers:** `encoding.ReadBitmap` / `WriteBitmap` / `BitmapIsNull` / `BitmapSetNull`, sized by `Schema.BitmapByteSize()`. **Parent groups (`0x02`), the summary CLAUDE.md shortened:** a group dictionary entry is the members' raw on-wire bytes plus member null bits (never strings; members keep their own dictionaries); an indexed group costs a `u32` per row, a constant group holds one entry and no index; `RecordByteSize` / `BitmapByteSize` / `HasBitmap` are PHYSICAL while every field index stays LOGICAL (`Schema.Fields`); physical-byte rewriters refuse via `internal/encoding.RefuseGroups`; written only on request — `--group KEY:MEMBER,...` (key-checked, `PULSE_GROUP_*`, the per-group viability gate) and `--elide-constants`. **Field-type tags:** bit-packed types are named by `FieldType.IsBitPacked()`, dictionary-bearing ones by `FieldType.HasDictionary()`. **Wide set rungs:** `set_u128` is type byte `18`, stride 16 bytes, ≤128 members; `set_u256` is type byte `19`, stride 32 bytes, ≤256 members — 256 is a hard ceiling; import inference picks the SMALLEST rung that fits; both are too wide for the `uint64` `Read/WriteFieldValue` API, which refuses them with `ENCODING_TYPE_MISMATCH` rather than truncating (`FieldType.IsWideSet()`). `datetime` is type byte `17`; `date` is epoch DAYS and `datetime` epoch SECONDS, so swapping them rescales every value by 86,400. **Vector types:** `vec_f32` / `vec_f64` are type bytes `20` / `21`, width element × dim with the dim in the `0x02` VECTORS section ("Vector fields"). **Shard archive variant:** an uncompressed Zip64 (store-only) container whose leading `PK\x03\x04` magic is dispatched at `pulse.Open` — the single-file byte format is unchanged; it holds the reserved `_schema.pulse` entry (canonical schema + SHRD trailer) plus N standalone shards; cohesion is structurally strict, categorical dictionaries union-merge, and the anchor `archive.pulse#shard.pulse` opens one shard. **Per-field nullability is part of cohesion and never widens** (`encoding.ValidateStructuralCohesion` → `nullabilityCohesion`, so `AddShard` / `CreateShardArchive`, `shard verify`, the anchored `NewCohortBuilder` pre-check and the archive record reader all inherit it): every shard decodes under the CANONICAL flags, so an archive field that is NOT nullable refuses a shard declaring it nullable — the canonical decode would ignore the null bit and a stored null would read back as its placeholder value, silently, whenever another nullable field keeps the bitmap width (and so the stride) equal. The reverse — a nullable archive field, a non-nullable shard field — is admitted as-is only when the two null bitmaps are the same width and the field is no parent-group member (a member's null bits ride its group entry, whose width the member nullability decides): every Pulse writer leaves a non-nullable field's bitmap bit 0 (`TestCohortBuilder_NonNullableShardInNullableArchive`), so each row reads non-null. Every refusal is `PULSE_SHARD_SCHEMA_MISMATCH` with `details.dimension: "nullable"` (plus `canonical_bitmap_bytes` / `incoming_bitmap_bytes` on a width refusal); no nullable-widening rewrite exists. Order therefore matters at seed: `[nullable, non-nullable]` builds, `[non-nullable, nullable]` refuses. A `set_*` field WIDENS (never narrows) to the narrowest rung that holds the union, past `set_u256` is `PULSE_SHARD_DICT_WIDTH_OVERFLOW` ("Shard set-width auto-widen"); grouped shards share ONE archive group layout, the archive's wins ("Shard archives with parent groups"); every archive rewrite is atomic and reports a MANDATORY warning (`PULSE_SHARD_SET_WIDENED` / `PULSE_SHARD_GROUPS_REWRITTEN`). `.pulse.zst` is transport-only and a read refuses it with `PULSE_COHORT_COMPRESSED` ("Transport-only compression").

**Model file — `.pulse-model.json` (`model_format_version` 1, 2 or 3).** NOT a `.pulse` layout and not a cohort sidecar: a standalone, human-readable JSON document a regression `save` writes (`RegressionSpec.Save` after the request's run, `FitSpec.Save` after the Compose fit pre-pass, both gated by `capability:model_save`) at an afero path relative to the instance filesystem root, so a later request can score from it without refitting. **One codec, in the leaf:** `internal/model/file.go` (`File`, `NewFile`, `Encode`, `DecodeFile`, `File.Bind`, `CheckSavePath`; stdlib + `types` + `errors` only, `TestModel_ImportBoundary`) — the runtime and the no-execute predict path (`internal/descriptor`, `TestPredictNoExecutionImports`) parse ONE format with ONE rule set; the write is the service's (`internal/service/model_save.go`). **Document:** `model_format_version`, `name` (informational — a load binds the name the loading request gives), `type`, `family` / `link` (GLM), `penalty` / `selection` / `resample` (echoes), `target`, `predictors` (fit order; under selection the RETAINED ones only), `terms` (the candidate set; equal to `predictors` without selection), `coefficients` / `std_errors` / `ci_lower` / `ci_upper` (maps keyed like `RegressionResult`'s, `(intercept)` included; an absent term has no figure), `df`, `conf_level`, `vcov` (`{kind, encoding, row_keys, column_keys, values}`), `n_obs`, `sum_weights` / `n_eff` (weighted fits only), `covariance` (required on version 2, optional on version 3, absent on version 1: the `RegressionResult.Covariance` echo `{type, cluster, clusters, order_by, lags}` naming the robust estimator the standard errors, intervals, df and vcov came from — U25 E5-S2), `outputs` (version 3 ONLY: an extension regression's `RegressionResult.Outputs`, each value in its WIRE JSON form via `types.MarshalFinite` — a non-finite output is `null`, unlike the bit-exact `Float` figures — read back as plain JSON values; `model.NormalizeOutputs` gives the in-request fit the very same form, so an extension `Scorer` scores a fit and its reloaded file identically, `TestModelFile_ExtensionRoundTrip`, U53 E2-S2), `provenance {cohort, fingerprint ("sha256:<hex>" of the training cohort's bytes, omitted when it cannot be computed), request_digest (`Request.Hash`)}`. Keys sort, two-space indent, trailing newline: one fit encodes to one byte sequence. p-values and fit statistics are NOT saved (not scoring figures); `File.Result()` rebuilds a result holding the saved figures only. **Floats are bit-exact — the policy:** a finite float64 is Go's shortest round-trip form (negative zero `-0`, subnormals exact); NaN (an undefined figure — a `df ≤ 0` bound, an undefined vcov entry) is JSON `null` and reads back NaN, never 0 (NaN payload bits are not kept); `±Inf` is the JSON STRING `"+Inf"` / `"-Inf"` (the wire contract's `MarshalFinite` would collapse it to null — a model file must not); any other string is refused. `File.Bind(name)` rebuilds the Bound the in-request fit binds to, every figure bit-identical (`TestModelFile_RoundTripBitExact`, `TestModelSave_ProcessRoundTripsBitExact` across OLS + vcov, GLM, Bayes, selection, resample, weighted and a grouped request — a grouped request's regression is cohort-wide). **Versioning:** the version is a function of the content, never a flag (the `.pulse` header's rule): an EXTENSION regression's fit (a type outside `types.AllRegressionTypes`, saved only when its registration supplies a `Scorer`) writes 3 (`FileFormatVersion`) — its coefficients named by its model, so no `(intercept)` nor one coefficient per predictor is required (at least one coefficient is), plus `outputs`; a built-in fit with a robust covariance writes 2; every other fit writes 1, byte-identical to earlier builds; all three are read (`FileFormatVersions()`). The version is read FIRST; absent or null is `PULSE_MODEL_FILE_INVALID` reason `version_missing`, non-integer reason `schema`, any value outside {1, 2, 3} `PULSE_MODEL_VERSION_UNSUPPORTED` (`details.version`, `supported` [1, 2, 3]). A `covariance` on a version 1 file, none on a version 2 one, a non-robust `type`, `outputs` below version 3, a built-in `type` on version 3 or an extension one below it is reason `schema` (`TestModelFile_RobustCovarianceRoundTrip`, `TestDecodeFile_Refusals`). Every version decodes STRICTLY — an unknown key, a mistyped value, no `type` / `target` / `(intercept)` (versions 1–2), a predictor without a coefficient (versions 1–2) or outside `terms`, terms ≠ predictors without a selection, a ragged vcov is `PULSE_MODEL_FILE_INVALID` reason `schema`; malformed JSON reason `json`. A new field is a version bump, never a silent extension. **Provenance is informational, NEVER a gate:** no load compares the fingerprint or digest with anything — a model trained on cohort A scores cohort B with the same predictor columns; there is deliberately no staleness check (unlike the sidecar index). **Save path** (`CheckSavePath`, shared by runtime and predict, checked before any record is read — for `fits`, before any fit runs, so no entry writes in a batch a later entry's path refuses): non-blank, a file name ending `.pulse-model.json` with a stem, never above the root once cleaned (`PULSE_MODEL_SAVE_INVALID` reasons `path_empty` / `suffix` / `name_missing` / `escapes_root`; `details.regression` or `details.fit`). The suffix is mandatory so the table-directory exclusion can recognise every model file. **No silent drop, no silent clobber:** two saves naming one file (compared after `path.Clean`) in a request (`model.CheckRequestSaves`) or anywhere in a Compose batch — `fits[i]`, `fits[i].request.regressions[j]`, `requests[k].regressions[j]` — are `PULSE_MODEL_SAVE_INVALID` reason `duplicate` with `details.sites` naming both writers; a batch judges EVERY save path in its pre-pass (`model.CheckComposeBatch`, right after `CheckFits`, serial and parallel and `PredictCompose` alike — a slot's fault gains `details.request`), so no fit or slot writes in a batch a later path refuses. Materialize refuses `regressions` (`PULSE_MATERIALIZE_SLOT_UNSUPPORTED`) and the chain gate refuses a regression on every stage (`PULSE_CHAIN_NOT_MERGEABLE`, stage 0 before it runs), so neither ever writes a model file (`TestModelSave_MaterializeRefusesSave`, `TestModelSave_ChainNeverWrites`, `TestModelSave_DuplicatePathsRefused`, `TestModelSave_ComposeSlotPathBeforeAnyRun`). **Write:** temp + fsync + rename beside the target (`afero.TempFile`, staging name `<file>.<rand>.tmp` — ends in `.tmp`, never `.json`, so an orphan is never mistaken for a table), parent directories created; a failure at `stat` / `mkdir` / `create` / `write` / `sync` / `close` / `rename` is `PULSE_MODEL_WRITE_FAILED` (`details.stage`), the target keeps its previous bytes and the temp file is removed (`TestModelSave_FailedWriteLeavesTargetIntact`). Overwriting succeeds with the MANDATORY warning `PULSE_MODEL_OVERWRITTEN` — on `Response.warnings` (`details.regression`) for a regression save, on the batch-level `ComposedResponse.warnings` (`details.fit`; a keep path the Compose `return` cannot drop) for a fit save or a save on a fit request's regression. A `return` never skips a regression that saves (the compute-plan save veto). An unnamed regression's model is named after its file stem. **Load** (`Request.Models` / `FacetRequest.Models`, `[]types.ModelRef {name, path}`, gated by `capability:models`): `internal/model/load.go` — `CheckModelRefs` (static, first fault: blank name `PULSE_MODEL_REF_INVALID` `name_empty`, the save-path rule's reasons on `path`, then `PULSE_MODEL_NAME_COLLISION` against an earlier entry or what is already bound — a Compose slot's fits — with `details.sources` [{slot, index[, path]}] naming both), then `LoadModelFiles` (each file read through a `ReadFunc` — the runtime's `Service.ReadModelFile` over afero, which refuses a directory; predict's `PredictOptions.ModelLoader`, the same service method — `PULSE_MODEL_FILE_UNREADABLE` `missing` / `unreadable`, then `DecodeFile`'s codes, each gaining `details.model` / `name`), then `Set.WithModels` (runtime: `File.Bind` under the entry's name, `Bound.Source`) / `CatalogWithModels` (predict: the same `Signature`s). A plain request loads in `Service.process` right after its save rule; a Compose batch loads every fit request's and slot's files in its pre-pass (`composeModelsPrepass`, after `CheckComposeBatch`) and a chain every stage's (after `CheckChainModels`), before anything runs, handing each request a context already carrying its final set (`withModelsBound`, so its Process does not reload) — a load therefore always reads the file as it was BEFORE the run, even one a fit in the same batch saves. A fit request sees only its own `models`; each chain stage loads its own namespace. A loaded name scores exactly like the fit that saved it (`TestModelLoad_ScoresBitEqualToFit`, OLS / GLM / Bayes), on every surface (`TestModelLoad_Surfaces`), across cohorts — provenance is never compared (`TestModelLoad_CrossCohort`); predict refuses every fault with the runtime's error (`TestModelLoad_PredictRuntimeParity_*`). Right after the decode, a version-3 file whose extension type the instance does not register — or registers but hides under its feature profile — is `PULSE_MODEL_REGRESSION_UNREGISTERED` (`model.CheckModelTypes` / `CheckLoadedTypes`, `details.model` / `name` / `path` / `type`; `Service.loadFiles` and predict's `loadModelFiles`, `TestExtensions_RegressionModelUnregistered`): nothing could score it. `format_version` does not move: the file is not payload-reachable; the `save` keys and `ComposedResponse.warnings` are additive `omitempty` slots.

**Population file — `.pulse-population.json` (`population_format_version` 1).** (U30 E2-S3.) The vector-fit twin of the model file, and NOT a `.pulse` layout or a cohort sidecar: the standalone JSON document a Compose VECTOR fit's `save` writes (`FitSpec.Save` on a fit whose request holds one matrix or fitted-attribute battery, `model.FitKindOf`; gated by `capability:model_save`) so a later plain request scores against the fitted battery without refitting it. **Same conventions, one codec in the leaf:** `internal/model/population.go` (`PopulationFile`, `NewPopulationFile`, `Encode`, `DecodePopulationFile`, `PopulationFile.VectorFit`, `CheckPopulationSavePath`, `PopulationSuffix`, `PopulationFormatVersion`) reuses the model file's `Float` policy (shortest round-trip, NaN `null`, `±Inf` strings), the version-first strict decode, the path rule (`checkFilePath` over the suffix — a vector fit's save MUST end `.pulse-population.json`, a regression fit's `.pulse-model.json`, either other suffix `PULSE_MODEL_SAVE_INVALID` reason `suffix`), the duplicate-path batch rule, the atomic write (`writeModelFile`, `PULSE_MODEL_WRITE_FAILED` via `model.PopulationWriteFailed`) and the MANDATORY overwrite warning (`PULSE_MODEL_OVERWRITTEN` via `model.PopulationOverwritten`, `details.fit`, on `ComposedResponse.warnings`). **Document:** `population_format_version`, `name` (informational), `operator` (the battery's MAT_* / fitted attribute type), `labels` (axis order — what a consumer aligns to BY LABEL), `members`, `basis` (`unweighted` / `frequency` / `probability`), `n` / `n_mass` / `n_weight_invalid`, `sum_weights` / `sum_weights_sq`, `mean` (the RAW stored mean — zeros, not NaN, with no mass), `m2` (the raw co-moment Σw(xi−mi)(xj−mj), full symmetric p × p), `provenance` (the model file's). No struct maps, so one fit encodes to one byte sequence. **Nothing derived is stored:** covariance, correlation, Cholesky, eigen, loadings and rotations are recomputed from `linalg.NewCoMomentFromListwise` at score time, so one file serves every fitted vector operator and a load scores BIT-identically to the in-batch `fit:` on the same architecture (`TestPopulation_SaveThenLoadMatchesFit`); across architectures a recomputed decomposition is tolerance-equal, not bit-equal. **Decode refuses** (`PULSE_MODEL_FILE_INVALID` reason `schema`) no labels, a blank or repeated label, members unlike labels, an unknown basis, a negative count, `n_mass > n`, a non-finite or negative weight sum, a mean / m2 shape unlike the labels and an m2 that is not BITWISE symmetric — exactly what `NewCoMomentFromListwise` and the label alignment need, so a bad file is the file's refusal, never an engine fault; `NewPopulationFile` applies the same check (a malformed state is `PROCESSING_INTERNAL`, never written). **Provenance is informational, NEVER a gate** (the model file's rule, chosen deliberately for populations too): scoring cohort B against a population fitted on cohort A is the point; there is no staleness check. **Load** (`Request.Populations`, `[]types.PopulationRef {name, path}`, gated by `capability:models` — the bound-model namespace's capability): `internal/model/population_load.go` — `Refs` / `RequestRefs` bundle a request's `models` + `populations`; `CheckRefs` runs `CheckModelRefs`, then each population (blank name `PULSE_MODEL_REF_INVALID` `name_empty`, the population path reasons, then `PULSE_MODEL_NAME_COLLISION` against a `models` entry, an earlier population or the outer set, `details.sources` naming slot `populations`); `LoadFiles` reads and decodes (`PULSE_MODEL_FILE_UNREADABLE` / `_FILE_INVALID` / `_VERSION_UNSUPPORTED`, each gaining `details.population` + `name`); `Set.WithLoaded` binds each as a `VectorFit` (`Source` slot `populations`) and `CatalogWithLoaded` is predict's static twin (kind vector, `Members` = the file's labels). Every load site the `models` row names runs it — `Service.process`, materialize, `composeModelsPrepass` (fit requests and slots), the chain pre-pass, `predictSingle`, `loadComposeModels`, `loadChainModels`; a FacetRequest carries no `populations`. **Error family:** no new code — every save / load fault reuses the `PULSE_MODEL_*` code whose semantics match, the entry located by `details.population`. `format_version` does not move: the `populations` key is an additive `omitempty` Request slot.
