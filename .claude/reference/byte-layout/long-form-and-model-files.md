# Byte layout — the always-load half (long form), the model file

Per-topic slice of the byte-layout reference (the `.pulse` format essentials every format change must respect, and the model file; its population and SEM fit twins are in `byte-layout/population-and-sem-files.md`). Index: `.claude/reference/byte-layout.md` — load it first, then only the slice(s) your change touches.

## The always-load half, long form — header, schema block, bitmap, field types, shard archive variant

Each rule below fails SILENTLY if broken: the file still opens and a value is quietly wrong.

**Header.** 9 bytes (`encoding.HeaderSize`): magic `PULSE\x00\x00\x00` (`encoding.MagicBytes`) + one format-version byte ∈ `{0x01, 0x02}` (`FormatVersionV1` / `FormatVersionV2`); any other byte is `ENCODING_INVALID` naming the byte. `ReadHeader` RETURNS the version and every `ReadSchema(r, version)` must be handed it. The version is a function of schema content, never a flag: `0x02` iff the schema declares a parent group, a vector or a default zone field (`Schema.RequiredFormatVersion`, written via `WritePreamble`), else `0x01` byte-identically. `0x01` stays readable forever (fixture `encoding/testdata/format_v1.pulse`). Detail: `byte-layout/format-and-groups.md` (Format version).

**Schema block.** Per field: name, type byte, **nullable flag byte** (immediately after the type byte; `1` = the field participates in the null bitmap), byte offset, bit position, optional description (≤ 1000 bytes). An unknown type byte is `ENCODING_INVALID`. Under `0x02` a `u64`-length-prefixed extension block of tagged sections follows; an unknown REQUIRED section is refused.

- **Layout is derived, never read back.** The stored byte offset / bit position are a cache of ONE canonical layout, `internal/encoding.LayoutFields(schema)` — a running sum of `encoding.Schema.FieldWidth`, the one field-aware width (a bit-packed field owns one whole byte at bit 0; a vector is element × dim). Every stride / offset / skip sums `FieldWidth`, never a type-only `ByteSize()` (`TestNoTypeOnlyWidthInStridePaths`). Writer and decoder place fields by a width-derived cursor and never trust the stored byte offset.
- **Legacy bit positions.** Decoders DO read the stored bit position of a bit-packed field (older writers filled nonzero ones) while the writer always fills bit 0 / the low nibble. So every reader honours a legacy nonzero bit position identically (engine, export, SPSS writer, lookup — `TestLegacyBitPosition_ExportEngineSPSSLookupAgree`), and shard cohesion compares the bit position plus the TYPE-DERIVED layout (names, type bytes, widths), never the stored byte offset — so legacy zero-offset cohorts join canonical archives without re-import. Every schema-producing path lays out through `LayoutFields` and ignores caller-supplied offsets.

**Dictionary blocks.** Inline after the schema, for every dictionary-bearing field (`FieldType.HasDictionary()`: `categorical_*`, `set_*`).

**Record data.** Fixed-width rows; the stride is a pure function of the schema (`Schema.RecordByteSize`). Record count is derived from payload length (`encoding.Schema.RecordCountForPayload`).

**Per-record null bitmap.** Present iff any field is nullable (`Schema.HasBitmap()`): a trailing `ceil(field_count / 8)` bytes per record (`Schema.BitmapByteSize()`); field `i` → byte `i/8`, bit `i%8` (LSB-first); `1` = null. Helpers: `encoding.ReadBitmap` / `WriteBitmap` / `BitmapIsNull` / `BitmapSetNull`. Nullability is orthogonal to type; `decimal128`, `set_*` and `vec_*` nulls ride the bitmap only (no in-band sentinel — a null row still carries its full payload bytes).

**Parent groups (`0x02`).** Each distinct member tuple is stored ONCE in a schema-block dictionary (entry = members' raw on-wire bytes + member null bits, never strings; members keep their own dictionaries); an indexed group costs a `u32` per row, a constant group holds one entry and no index. Byte sizes (`RecordByteSize` / `BitmapByteSize` / `HasBitmap`) are PHYSICAL; every field index is LOGICAL (`Schema.Fields`); decode is identical to the ungrouped twin. Physical-byte rewriters refuse via `internal/encoding.RefuseGroups`. Written only on request — `--group KEY:MEMBER,...` or `--elide-constants`. Detail: `byte-layout/format-and-groups.md` (Parent groups).

**Field types.** 22 types; the registry is the `FieldType` constant block in `encoding/field_type.go`, the per-type table is `skills/cohort-schema-design.md` and each type has `skills/type-<kebab>.md`.

- **`TestSkillsCoverAllFieldTypes`** fails when a registered type lacks its atomic skill; a new type also needs this slice, `skills/cohort-schema-design.md` and the type-byte rules below.
- Bit-packed (`FieldType.IsBitPacked()`): `u4`, `packed_bool` (`ByteSize() == 0`, one whole byte per field in the row).
- **`date` is epoch DAYS (`int32`), `datetime` (type byte `17`) epoch SECONDS (`int64`)** — swapping them rescales every value by 86,400; both are SIGNED (`byte-layout/writers-and-field-words.md`, Temporal word sign).
- `set_*` value is a bitmask: bit `i` ↔ dictionary entry `i`; an empty mask is "no selection", distinct from null. Wide rungs (`FieldType.IsWideSet()`): `set_u128` type byte `18`, 16 bytes, ≤128 members; `set_u256` type byte `19`, 32 bytes, ≤256 members — a hard ceiling. The `uint64` value API refuses both with `ENCODING_TYPE_MISMATCH`, never truncating. Import picks the SMALLEST rung that fits. Word order: `byte-layout/writers-and-field-words.md` (Wide-set word order).
- `vec_f32` / `vec_f64` type bytes `20` / `21`, width element × dim (2..1024), dim in the VECTORS section — size by `Schema.FieldWidth`, never the type (`byte-layout/writers-and-field-words.md`, Vector fields).

**A dictionary code is valid only inside its dictionary.** Every shard decodes against the CANONICAL dictionary (each shard's own is a prefix), so a non-null `categorical_*` index — or `set_*` bit — at or past the canonical length is corrupt record data. Every reader that keys, labels or renders it refuses with `ENCODING_INVALID` (`details.reason` `categorical_index_out_of_range` / `set_member_out_of_range`, `field`, `index` / `bit`, `dictionary_size`; constructors `internal/encoding.CategoricalIndexFault` / `SetMemberFault`). Export judges it AFTER the null bitmap (import stores placeholder `0` under a null even over an empty dictionary).

- **Level reads refuse too** — they once read a bad code as absent and dropped the row silently. Engine level reads go through `Record.StringValueChecked` / `LevelValueChecked` (`TestLevelReaders_Checked` fails an unchecked read). A test or regression slot fails ALONE (`slotfail.CorruptRecordData`); a feature, attribute or filter fails the run. `extend.Record.StringValue` answers `("", false)` and latches the fault on the row, which every adapter returns in place of the extension's result.
- **Deliberate exceptions read the CODE, never a label:** numeric aggregators over a code (`AGG_MODE`, `AGG_DISTINCT_COUNT`, `AGG_FREQUENCY`…), set aggregators (bits past the tail excluded), `FILTER_INCLUDE` / `EXCLUDE` / `ATTR_CODE_IN` code sets (a corrupt code matches nothing), index keys (raw ID), a per-row zone field (unknown code = null zone).

## Shard archive variant

A `.pulse` path may instead be an uncompressed Zip64 **shard archive**, dispatched at `pulse.Open` on its leading zip magic `PK\x03\x04` (`encoding.IsArchive`); the single-file format is unchanged inside it.

- **Contents:** the reserved `_schema.pulse` entry (canonical schema + SHRD trailer, then the optional DIST distinct-count trailer) plus N standalone shards — at most 65535 (`encx.MaxArchiveShards`, because SHRD `shard_count` is a `u16`). Create, add, filter-to-file and the shared `_schema.pulse` builder refuse more with `PULSE_SHARD_COUNT_LIMIT` (`details.shard_count`, `details.limit`) before writing, so no writer stores a wrapped count. The anchor `archive.pulse#shard.pulse` opens one shard.
- **Store-only is what makes it random-access.** Every read path reads the central directory at the tail through an `io.ReaderAt` and each shard as a SectionReader — never the whole archive — so a DEFLATED entry (from a third-party zip tool) is `PULSE_ARCHIVE_CORRUPT` on every record path rather than decoded as compressed bytes.
- **Cohesion is structurally strict** (`encoding.ValidateStructuralCohesion`, inherited by add, create, verify, the builder's append pre-check and the archive record reader). Categorical dictionaries union-merge (prefix rule). **Sets WIDEN** across shards (never narrow; past `set_u256` is `PULSE_SHARD_DICT_WIDTH_OVERFLOW`) — `byte-layout/shards-and-index.md` (Shard set-width auto-widen). Grouped shards share ONE layout, the archive's (Shard archives with parent groups). A vector's dim and the zone default must match exactly.
- **Per-field nullability never widens.** Every shard decodes under the CANONICAL flags, so a non-nullable archive field refuses a shard declaring it nullable — the canonical decode would ignore the null bit and a stored null would read back as its placeholder value, SILENTLY, whenever the bitmap width happened to match. The reverse (nullable archive, non-nullable shard) is admitted only when both bitmaps have the same width and the field is no group member (every Pulse writer leaves a non-nullable field's bit 0). Refusals are `PULSE_SHARD_SCHEMA_MISMATCH` `details.dimension: "nullable"`. Order matters at seed: `[nullable, non-nullable]` builds, `[non-nullable, nullable]` refuses.
- **Mutations:** an ORDINARY `shard add` appends the shard, a refreshed `_schema.pulse` and a new directory to the tail in place, journalled in `<archive>.append` (`byte-layout/archive-append.md`). Every other mutation is an atomic rewrite (staged file + rename; `byte-layout/shards-and-index.md`, The archive rewrite contract), and a rewrite the caller did not ask for MANDATORY-warns (`PULSE_SHARD_SET_WIDENED` / `PULSE_SHARD_GROUPS_REWRITTEN` / `PULSE_SHARD_DEAD_BYTES_RECLAIMED` / `PULSE_SHARD_ZONE_REWRITTEN`).
- **`.pulse.zst` is transport-only:** every read refuses it with `PULSE_COHORT_COMPRESSED` (`byte-layout/spss-export-and-decode.md`, Transport-only compression).

## Model file

**Model file — `.pulse-model.json` (`model_format_version` 1 + `features`).** NOT a `.pulse` layout and not a cohort sidecar: a standalone JSON document a regression `save` writes (`RegressionSpec.Save`, `FitSpec.Save`; `capability:model_save`) at an afero path relative to the instance root, so a later request scores without refitting.

- **One codec, in the leaf:** `internal/model/file.go` (`File`, `Encode`, `DecodeFile`, `File.Bind`, `CheckSavePath`), imported by both runtime and no-execute predict (`TestModel_ImportBoundary`), so both parse one format with one rule set. The write is the service's (`internal/service/model_save.go`).
- **Document:** `model_format_version` (always 1), `features`, `name` (informational — a load binds the name the loading request gives), `type`, GLM `family` / `link`, `penalty` / `selection` / `resample` echoes, `target`, `predictors` (fit order; under selection the retained ones), `terms` (candidate set), `coefficients` / `std_errors` / `ci_lower` / `ci_upper` (keyed like `RegressionResult`, `(intercept)` included), `df`, `conf_level`, `vcov`, `n_obs`, `sum_weights` / `n_eff` (weighted only), the feature sections, and `provenance {cohort, fingerprint, request_digest, union}`. Keys sort, two-space indent, trailing newline: one fit encodes to one byte sequence. p-values and fit statistics are NOT saved.
- **Floats are bit-exact:** a finite float64 is Go's shortest round-trip form (`-0`, subnormals exact); NaN is JSON `null` and reads back NaN, never 0; `±Inf` is the STRING `"+Inf"` / `"-Inf"` (the wire's `MarshalFinite` would collapse it to null — a model file must not). `File.Bind` rebuilds the in-request Bound bit-identically (`TestModelFile_RoundTripBitExact`, `TestModelSave_ProcessRoundTripsBitExact`).
- **Versioning — one version plus a `features` list.** What a file carries beyond the plain fit is LISTED, never encoded in the version. The registry is `fileFeatures` in `internal/model/file.go` (`model.FileFeatures()`), one `{name, key, present, rule}` entry per section — read it for the current list and each section's rule; a new section is one entry plus its `File` field and setter. A new section is a new FEATURE, never a version bump and never a silent extension. The writer DERIVES the list from the sections present (a plain fit writes no `features` key). The reader judges shape by the list: a listed feature without its section, an unlisted section, or a duplicate is reason `schema`; each present section then obeys its rule.
- **Read order:** version FIRST — absent or null `PULSE_MODEL_FILE_INVALID` `version_missing`, non-integer `schema`, anything but 1 `PULSE_MODEL_VERSION_UNSUPPORTED` (`details.version`, `supported`; the retired integer ladder 2–6 is refused with a "re-save the fit" message, no alias). `features` NEXT, before the strict decode: an unknown name is `PULSE_MODEL_VERSION_UNSUPPORTED` with `details.unknown_features` / `supported_features`, so a newer build's section is refused precisely. Then a STRICT decode — unknown key, mistyped value, missing `type` / `target` / `(intercept)` (built-ins), predictor without a coefficient or outside `terms`, ragged vcov → `schema`; malformed JSON → `json`.
- **Notable section rules** (the registry is authoritative): `outputs` belongs only to a non-built-in type with a `Scorer`, values in wire JSON form so a fit and its reloaded file score identically; `adstock` is per-channel LINEAGE recorded only when a channel is provably one `WIN_DISTRIBUTED_LAG` output (or a `REG_MMM_BAYES` kernel at posterior means, with `fixed_at: "posterior_mean"`) — any other channel records nothing, never inferred; `sweep_axes` restores the winning sweep slot's axis values so `sweep_axis()` on a loaded model judges statically like the runtime; `categories` is required on every `REG_MULTINOMIAL` file; `penalized_inverse` is what a loaded penalized fit's leverage reads (absent on older files → refused `requires: penalized_inverse`).
- **Provenance is informational, never a gate:** no load compares fingerprint or digest — a model trained on cohort A scores cohort B; there is deliberately no staleness check.
- **Save path** (`CheckSavePath`, shared by runtime and predict, checked before any record is read): non-blank, a file name ending `.pulse-model.json` with a stem, never above the root once cleaned (`PULSE_MODEL_SAVE_INVALID` `path_empty` / `suffix` / `name_missing` / `escapes_root`). The suffix is mandatory so the table-directory exclusion recognises every model file.
- **No silent drop, no silent clobber:** two saves naming one file (after `path.Clean`) in a request or anywhere in a Compose batch are `PULSE_MODEL_SAVE_INVALID` `duplicate` (`details.sites`); a batch judges EVERY save path in its pre-pass, so nothing writes when a later path refuses. Materialize and chains refuse regressions, so they never write a model file.
- **Write:** temp + fsync + rename beside the target (staging name `<file>.<rand>.tmp` — never `.json`, so an orphan is never mistaken for a table); any failure is `PULSE_MODEL_WRITE_FAILED` (`details.stage`), target unchanged, temp removed. Overwriting succeeds with the MANDATORY warning `PULSE_MODEL_OVERWRITTEN` (on `Response.warnings` for a regression save, on `ComposedResponse.warnings` for a fit save). A `return` never skips a regression that saves.
- **Load** (`Request.Models` / `FacetRequest.Models`, `[]types.ModelRef {name, path | inline}`, `capability:models`; `internal/model/load.go`): `CheckModelRefs` (blank name `PULSE_MODEL_REF_INVALID`, the save-path rules on `path`, `PULSE_MODEL_NAME_COLLISION` with `details.sources`), then `LoadModelFiles` (`PULSE_MODEL_FILE_UNREADABLE` `missing` / `unreadable`, then `DecodeFile`'s codes), then bind. A Compose batch or chain loads every file in its pre-pass before anything runs, so a load always reads the file as it was BEFORE the run, even one the same batch saves. A loaded model scores bit-equal to the fit that saved it (`TestModelLoad_ScoresBitEqualToFit`), and predict refuses every fault with the runtime's error. A file whose extension type the instance does not register (or hides under its feature profile) is `PULSE_MODEL_REGRESSION_UNREGISTERED`.
- **Inline models:** an entry sets exactly one of `path` / `inline` (`path_and_inline`). `inline` is the document itself, loaded by the same code; string values at number positions are scalar expressions over literals and `params.<name>` only, resolved through the caller-supplied `InlineNumberFunc` so predict and runtime agree. Allowed types: `model.InlineTypes`; coefficients must name exactly the expected terms (`inline_term_unknown` / `inline_term_missing`). An inline model can be read (`coef()`, `sweep_axis()`) but not scored (`PULSE_MODEL_SCORE_INVALID` `inline_not_scorable`).
