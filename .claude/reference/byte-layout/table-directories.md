# Byte layout — table directories (label, range and lookup tables): file formats, sidecar exclusion, collisions

Per-topic slice of the byte-layout reference (the table-directory loaders: file formats, the sidecar exclusion, directory collisions, the populations directory). Index (preamble + section map): `.claude/reference/byte-layout.md` — load it first, then only the slice(s) your change touches.

**Table-directory sidecar exclusion — `PULSE_LABEL_TABLES_DIR` / `PULSE_RANGE_TABLES_DIR` / `PULSE_LOOKUP_TABLES_DIR` (relocated from CLAUDE.md "Build / Env").** **File formats (each `*.json` directly in the directory, non-recursive, registers under its file stem; `Options.*Dir` beats the env var; a missing directory is a no-op, a non-directory an error).** A label table is a `{value: label}` object or a `{"description", "rows"}` wrapper. A range table is a bare `{label,start,end}` array or a `{"description","ranges"}` wrapper, typed by its bounds and validated through the shared range-compilation pass. A lookup table (read by `lookup()`) is a bare `{key: number}` object or a `{"description", "rows"}` wrapper — multi-part keys joined with `|` — parsed by the exported `pulse.ParseLookupTableFile` (the loader's own parser): a non-JSON / wrong-shape file, a duplicated key or an unknown wrapped key is `PULSE_LOOKUP_FILE_INVALID` (`details.reason`), a cell that is not a JSON number `PULSE_LOOKUP_CELL_NOT_NUMERIC`, a table with no rows `PULSE_LOOKUP_TABLE_EMPTY`; the loader re-issues the code with the file under `details.path`. **Declared axes.** The wrapped form may add `keys` — one axis per `lookup()` argument, each `{"name", "values": [strings]}` or `{"name", "range_table": "<name>"}`, never both (`LookupTable.Keys` / `pulse.LookupAxis` in code) — and `complete` (a boolean; `LookupTable.Complete`). With `keys`, each row key splits on `|` into one value per axis (`PULSE_LOOKUP_KEY_ARITY`), each on its axis (`PULSE_LOOKUP_KEY_OFF_AXIS`); an axis value listed twice is `PULSE_LOOKUP_KEY_COLLISION`; a malformed axis, a `|` in an inline value or in a referenced range table's label (the joined-key separator stays hard-coded `|`), an unknown range table, `complete` without `keys` or axes on a `Lookup` table is `PULSE_LOOKUP_AXIS_INVALID` (`details.reason`); `complete: true` refuses a missing cross-product cell (`PULSE_LOOKUP_TABLE_INCOMPLETE`), otherwise the table is sparse and an unlisted combination misses at run time (`PULSE_LOOKUP_MISS`). The per-file checks run in `ParseLookupTableFile`; a range-table axis is resolved to its table's labels only at `pulse.New` (`validateLookupTableAxes`, after every loader and programmatic registration), so it may name a directory-loaded range table, and programmatic tables with `Keys` get the same checks. Range-table validation itself is unchanged. A non-boolean `complete` is `PULSE_LOOKUP_FILE_INVALID` (`complete_not_bool`). All three table directories exclude Pulse's own sidecars by suffix BEFORE any parse attempt — `.spss.json`, `.meta.json`, `.indexes.json`, `.pulse-model.json` (a saved model file, "Model file" below), `.pulse-population.json` (a saved population file, "Population file" below), `.pulse-sem.json` (a SEM fit file), the list at `isPulseSidecarName` in `sidecar_names.go` — so a cohort's sidecars can share a directory with its tables. **That is an exclusion of KNOWN artefacts, not tolerance of unparseable JSON:** any other `*.json` that fails to parse is still a hard `pulse.New` error naming the path, because a typo'd table must not silently become a table that is not there. A new sidecar suffix joins `isPulseSidecarName` in the same change. `PULSE_TEMPLATES_DIR` does **not** carry the exclusion (`.claude/reference/request-templating.md`). **Collisions.** A name a directory file declares that `Options.Extensions` already declares programmatically is `PULSE_EXTENSION_DUPLICATE` (`details.category` `label_table` / `range_table` / `lookup_table` / `population`, `name`, `path` — `dirCollision`), raised at `pulse.New`; each table or population has exactly one source. **Populations directory — `PULSE_POPULATIONS_DIR` / `Options.PopulationsDir` (option beats env).** The loader's documents are selected by the population suffix the way the table loaders select `*.json`: every `*.pulse-population.json` directly in the directory (non-recursive) registers as `Extensions.Populations[stem]` (`brand.pulse-population.json` → `brand`); every other file — a label or range table, a cohort and its sidecars, a model file — is skipped unread, so one config directory can hold tables and populations. A population file that does not read or decode fails `pulse.New` naming its path (`PULSE_MODEL_FILE_UNREADABLE` / `_FILE_INVALID` / `_VERSION_UNSUPPORTED`, `details.registered` = the name); a missing directory is a no-op, a non-directory an error. Programmatic entries (`Population{File}` — the encoded document) decode at `New` the same way (a blank key `PULSE_MODEL_REF_INVALID` `name_empty`). Registered populations are FROZEN at `New` and bound as vector fits beneath every request (Process, Compose fits and slots, chain stages, facet, materialize — `model.RegisteredSet`, `Source{slot: "registered"}`); a `fits` / `models` / `populations` entry reusing a registered name is `PULSE_MODEL_NAME_COLLISION`, never a shadow. Predict binds the same names and labels from the instance snapshot (`ExtensionsSnapshot.Populations` → `PopulationCatalog`), and the manifest lists them under `extensions.populations` (`name`, `operator`, `basis`, `labels`, `n` — never the moments). A feature profile hiding `capability:models` registers none.
