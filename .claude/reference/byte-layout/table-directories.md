# Byte layout — table directories (label, range and lookup tables): file formats, sidecar exclusion, collisions

Per-topic slice of the byte-layout reference (the table-directory loaders: file formats, the sidecar exclusion, directory collisions, the populations directory). Index: `.claude/reference/byte-layout.md` — load it first, then only the slice(s) your change touches.

**Table-directory sidecar exclusion — `PULSE_LABEL_TABLES_DIR` / `PULSE_RANGE_TABLES_DIR` / `PULSE_LOOKUP_TABLES_DIR`.**

- **File formats.** Each `*.json` directly in the directory (non-recursive) registers under its file stem; `Options.*Dir` beats the env var; a missing directory is a no-op, a non-directory an error. Every directory (and the populations directory) is read through `configDirFs` (`template_loader.go`): `Options.FS` when set, else `afero.NewOsFs()` (host paths, never DataDir-rooted) — the template store's filesystem; no `os` filesystem call in the loaders (`TestNew_ConfigDirsReadThroughOptionsFS`). A label table is a `{value: label}` object or a `{"description", "rows"}` wrapper. A range table is a bare `{label,start,end}` array or a `{"description","ranges"}` wrapper, typed by its bounds and validated by the shared range-compilation pass; the exported `pulse.ParseRangeTableFile(name, data)` is the loader's own parser, PARSE-ONLY (a refusal is `DATA_FILE` `{kind: range_table, table}`; overlap / duplicate label / empty / bad bound are refused only at `pulse.New`). A lookup table (read by `lookup()`) is a bare `{key: number}` object or a `{"description", "rows"}` wrapper, multi-part keys joined with `|`, parsed by the exported `pulse.ParseLookupTableFile` (the loader's own parser): bad JSON / shape, a duplicated key or an unknown wrapped key is `PULSE_LOOKUP_FILE_INVALID` (`details.reason`), a non-number cell `PULSE_LOOKUP_CELL_NOT_NUMERIC`, no rows `PULSE_LOOKUP_TABLE_EMPTY`; the loader re-issues the code with `details.path`.
- **Declared axes.** The wrapped lookup form may add `keys` (one axis per `lookup()` argument, each `{"name", "values": [...]}` or `{"name", "range_table": "<name>"}`, never both) and `complete` (boolean). With `keys`, each row key splits on `|` into one value per axis (`PULSE_LOOKUP_KEY_ARITY`), each on its axis (`PULSE_LOOKUP_KEY_OFF_AXIS`); a value listed twice is `PULSE_LOOKUP_KEY_COLLISION`; a malformed axis, a `|` inside an axis value or a referenced range label (the separator stays hard-coded), an unknown range table, or `complete` without `keys` is `PULSE_LOOKUP_AXIS_INVALID`; a non-boolean `complete` is `PULSE_LOOKUP_FILE_INVALID` (`complete_not_bool`). `complete: true` refuses a missing cross-product cell (`PULSE_LOOKUP_TABLE_INCOMPLETE`); otherwise the table is sparse and an unlisted combination misses at run time (`PULSE_LOOKUP_MISS`). A range-table axis resolves only at `pulse.New`, after every loader and programmatic registration, so it may name a directory-loaded range table.
- **The exclusion.** All three directories skip Pulse's own sidecars by suffix BEFORE any parse attempt, so a cohort's sidecars can share a directory with its tables. The list is `pulseSidecarSuffixes`, read by `isPulseSidecarName` in `sidecar_names.go` (`.spss.json`, `.meta.json`, `.indexes.json`, `.pulse-model.json`, `.pulse-population.json`, `.pulse-sem.json`). **This excludes KNOWN artefacts; it is not tolerance of bad JSON:** any other `*.json` that fails to parse is a hard `pulse.New` error naming the path, because a typo'd table must not silently become a table that is not there. A new Pulse-written `*.json` suffix joins `pulseSidecarSuffixes` in the same change. `PULSE_TEMPLATES_DIR` carries the same exclusion (`.claude/reference/request-templating.md`).
- **Collisions.** A name a directory file declares that `Options.Extensions` already declares is `PULSE_EXTENSION_DUPLICATE` (`details.category` `label_table` / `range_table` / `lookup_table` / `population`, `name`, `path`) at `pulse.New`; each table or population has exactly one source.

**Populations directory — `PULSE_POPULATIONS_DIR` / `Options.PopulationsDir`** (option beats env).

- Every `*.pulse-population.json` directly in the directory registers as `Extensions.Populations[stem]`; every other file is skipped unread, so one config directory can hold tables and populations. A file that does not read or decode fails `pulse.New` naming its path (`PULSE_MODEL_FILE_UNREADABLE` / `_FILE_INVALID` / `_VERSION_UNSUPPORTED`, `details.registered`). Programmatic entries decode the same way (blank key `PULSE_MODEL_REF_INVALID` `name_empty`).
- Registered populations are FROZEN at `New` and bound as vector fits beneath every request (Process, Compose, chains, facet, materialize); a `fits` / `models` / `populations` entry reusing a registered name is `PULSE_MODEL_NAME_COLLISION`, never a shadow. Predict binds the same names from the instance snapshot; the manifest lists them under `extensions.populations` (`name`, `operator`, `basis`, `labels`, `n` — never the moments). A feature profile hiding `capability:models` registers none. File format: `byte-layout/population-and-sem-files.md` (Population file).
