# Byte layout — `shard add` appends to the archive tail

Per-topic slice of the byte-layout reference (the in-place tail append an ordinary `shard add` takes, its Zip64 records, concurrent readers, the append journal, dead bytes, and the per-shard DIST trailer). Index: `.claude/reference/byte-layout.md` — load it first, then only the slice(s) your change touches. The archive layout itself is in `byte-layout/long-form-and-model-files.md`; the rewrite contract in `byte-layout/shards-and-index.md`; the index upkeep the append keeps in `byte-layout/archive-index.md`.

**Shard add tail append — in place.** An ORDINARY add writes nothing before the archive's old end. Ordinary means: `mergeShard` returned no `rewrite` (no archive-level set widen, no constant-group promotion — a dictionary that only GROWS is ordinary, since stored dictionaries stay canonical prefixes), every entry is store-only, and the tail is appendable.

- **What is appended** (`Service.appendShard`, `internal/service/shard_append.go`), at the old file length: the new shard's local entry, a refreshed `_schema.pulse`, then a NEW central directory (+ zip64 end record and locator when needed) and EOCD. The directory lists the new `_schema.pulse` FIRST, every stored shard's old record VERBATIM (offsets, CRCs, sizes stay valid — those bytes never move), then the new shard — create's entry order — and DROPS the superseded `_schema.pulse` record so no reader sees two. The old directory, EOCD and `_schema.pulse` stay as DEAD bytes; `CompactShardArchive` reclaims them and lands byte-identical on a create of the same shards.
- Bytes written = new shard + `_schema.pulse` + directory (O(shards)), independent of archive size (`TestShardAppend_WriteVolumeIsIndependentOfArchiveSize`). No `.pulse` version byte or SHRD change; any earlier build reads the result.
- **The appended bytes equal `zip.Writer`'s.** The writer is hand-written (`internal/encoding/archive_append.go`) because `zip.Writer` only builds a directory from entries it wrote; every byte must equal what `zip.Writer.CreateHeader` + `Close` writes for the same store-only entry (local header with zeroed CRC/sizes, payload, data descriptor flag `0x8`, the UTF-8 flag rule). Pinned byte-for-byte by `TestArchiveAppender_MatchesZipWriterBytes`.
- **Zip64**, as `zip.Writer.Close` emits it: a record whose size or offset reaches 4 GiB carries `0xFFFFFFFF` size slots and a 24-byte zip64 extra (offset slot `0xFFFFFFFF` past 4 GiB); a ≥ 4 GiB entry's data descriptor carries 64-bit sizes; a directory of ≥ 65535 records (65535 shards + `_schema.pulse` = 65536), or one larger or later than 4 GiB, adds the zip64 end record + locator with EOCD sentinels.
- **Which adds rewrite instead:** a widen or promotion (the staged rewrite keeps a half-widened archive from ever being published); an archive holding a DEFLATED entry; a tail `ReadArchiveDirectory` reports as `*NotAppendableError` (`directory_not_adjacent`, `bytes_after_eocd`, multi-disk, a zip64 extensible data sector); the dead-bytes fallback below; `--rewrite`. A malformed tail stays `PULSE_ARCHIVE_CORRUPT`. Parity: an appended archive's directory order, sizes, CRCs, `_schema.pulse` and warnings equal a create of the same shards (`TestShardAppend_ParityWithRewrite`).
- **Concurrent readers:** an append assumes no concurrent WRITER (as every mutation does) and takes no lock. A reader opened before the append keeps its OLD view — its directory points only at bytes the append never touches — and a reader opened after sees the new shard (`TestShardAppend_ReaderOpenedBeforeKeepsItsView`). The add closes its own read handle before opening for write (`O_WRONLY`, never truncating).
- **A refused write-open** (read-only file or filesystem; on Windows another process holding the archive without write sharing) is `PULSE_SHARD_APPEND_REFUSED` (`details.reason` `open_for_write`), nothing written; the fixup names `--rewrite`, which never opens the archive for writing. The same code with `archive_changed` refuses an archive whose length moved between read and write.
- **Failure:** an in-process write / flush / fsync error truncates back to the old length and returns the error. A CRASH mid-append is the journal's job: the old EOCD may fall outside the 64 KiB a zip reader searches (unopenable) or still sit there before a torn tail — Go's reader tolerates trailing bytes, so the archive would read SILENTLY as its pre-append view.
- **Index upkeep stays build before publish:** before the write-open, the new shard is scanned from an in-memory TWIN archive built through the same appender (so its name, size and CRC — its identity — are the ones the append records), sidecars and manifest are staged, and renamed only after the append is durable. Stored shards' sidecars stay fresh because manifest identity never involves the archive's own size or CRC. An ordinary add with no index emits no warning — the cheap append is the contract.

**Append journal — `<archive>.append`.** A sidecar beside the archive (`encx.AppendJournalPath`), never a zip entry, present only while an in-place append is in flight.

- **Written** after the write-open and `archive_changed` check and BEFORE the first archive byte: JSON `{journal_format_version: 1, archive_size, tail_length, tail_crc32, shard}` — the pre-append length and the CRC-32 of the last `min(size, 22 + 65535)` bytes (the EOCD search window) — via `<archive>.append.tmp`, fsync, rename, directory fsync, so the marker is whole or absent. Removed only after the appended bytes are fsynced and the archive closed; an in-process rollback removes it only once the truncation is itself synced.
- **Open never repairs:** while the marker exists every PATH-based archive open refuses with `PULSE_SHARD_APPEND_INCOMPLETE` (`details.archive`, `details.journal`; fixup `pulse shard verify --repair`) before reading a byte — runtime, predict, inspect, export, lookup and shard admin alike (`TestShardAppendJournal_EverySurfaceRefusesThenRepairs`). New path-based open sites must go through the shared archive opener. Limit: `PredictBytes` / `InspectBytes` / synth byte reads take bytes and cannot see a journal.
- **Repair** (`Pulse.RepairShardArchive` / `pulse shard verify --repair`; `--json` adds `data.repair` only under the flag) is the ONLY path that clears a journal. No marker → `repaired: false` (a stale `.append.tmp` is removed). Otherwise it refuses with `PULSE_SHARD_REPAIR_REFUSED` (`journal_invalid` / `archive_shorter_than_journal` / `tail_checksum_mismatch` / `tail_not_an_archive`), archive and marker untouched, unless the archive is at least the journalled length, the journalled tail still matches its CRC and parses; then it truncates to the journalled length, fsyncs, removes the marker — byte-identical to the pre-append archive.
- **A repair that truncates mandatory-warns** `PULSE_SHARD_APPEND_ROLLED_BACK` (`truncated_bytes` etc.) in `data.repair.warnings` (always present), lifted into the envelope `warnings`; a repair truncating nothing warns nothing. Never escalated. Crash phases (before any byte, mid-shard, mid-`_schema.pulse`, mid-directory, synced-but-marker-not-removed) are each refused then repaired to an archive byte-identical to the pre-append one (`TestShardAppend_CrashPhasesRefusedAndRepaired`).
- **Naming:** not `*.pulse` (cohort scans skip it), not `*.json` (table loaders never parse it), not `.idx` / `.bloom`; `CohortArtifacts` LISTS it — it travels with the archive.
- **Older binaries do not know the journal** and open a journalled archive as if whole (torn-tail or pre-append view, or `PULSE_ARCHIVE_CORRUPT`) and may mutate it; repair with a current build first.

**Dead bytes — superseded copies, the rewrite fallback, `--rewrite`.** Because an append drops the superseded `_schema.pulse` record, dead bytes are measured as GAPS (`encx.MeasureArchiveSpace`, `internal/encoding/archive_space.go`): archive length minus the spans the LIVE directory covers (each live entry from local header through data descriptor, plus the live directory tail). Dead `_schema.pulse` copies are counted structurally — each dead copy opens a gap, checked by one 43-byte header read — never by scanning dead bytes or reading payloads.

- **The fallback:** before appending, `AddShardWithOptions` projects the dead bytes the append would leave (`ArchiveSpace.DeadAfterAppend`) against the exact post-append size (`encx.AppendLength`, `TestAppendLength_MatchesAppender`). `dead × 2 > size` (MORE than half; exactly half still appends) takes the staged rewrite (one `_schema.pulse`, zero dead bytes) and emits ONE mandatory `PULSE_SHARD_DEAD_BYTES_RECLAIMED` (`dead_bytes`, `archive_size`, `dead_schema_copies`, `threshold: 0.5`). Each append re-supersedes the whole O(shards) directory, so many tiny shards trip it often — that is the amortisation, not a bug.
- **`--rewrite`** (`pulse shard add --rewrite`; `AddShardOptions{Rewrite: true}`) forces the rewrite: no warning, the archive never opened for writing, bytes equal a create of the same shards.
- **Reporting:** `VerifyResult.DeadSchemaCopies` / `DeadBytes` (`shard verify --json` `data.dead_schema_copies` / `data.dead_bytes`, always present). Every rewrite (create, remove, compact) leaves zero.

**Per-shard distinct counts — the `_schema.pulse` DIST trailer.** Every archive writer records, per shard and per ELIGIBLE field (`u32`, `u64`, `date`, `datetime`, `f32`, `f64`, logical order — narrower words, dictionary and set types already have a schema-known bound), the exact count of distinct stored words, so predict can bound a grouper header-only (consumer: the memory estimate, `.claude/reference/predict-inspect/limits.md`).

- **Where:** a trailer appended to the `_schema.pulse` entry after SHRD's `shard_count` — never in a `.pulse` schema block, so no version byte moves and single-file cohorts and stored shard bytes are untouched.
- **Wire** (little-endian, `internal/encoding/shard_distinct.go`): magic `DIST`, `u8` trailer version (`DistinctTrailerVersion = 2`, its own axis), `u64 body_length`, body = `u32 field_count` × {`u16` name length, name, `u8` type byte}, `u32 shard_count` × {`u16` name length, entry name, identity {`u8 known` (0 / 1, else malformed), `u64 size`, `u32 crc32`}, `field_count` × {`u8 status`, `u64 count`}}, archive order. Status: `0` absent (unknown — never fabricated), `1` exact, `2` over the limit (`count` = the limit; the shard holds more), `3` opted out.
- **Identity** = the stored payload's uncompressed size + CRC-32, exactly its central-directory record (`encx.EntryIdentity`). A version-1 trailer (no identity) reads with every identity unknown and is never rewritten as v1. An older build skips a newer trailer (no bound) and records stored shards absent.
- **Older readers:** `ReadSchemaDoc` stops at SHRD and never sees the trailer (trailing bytes were always ignored). Reader API (importable by no-execute `internal/descriptor`): `ReadSchemaDocDistinct` — nil = absent (or newer version, skipped, never misread); a truncated / inconsistent trailer is `ENCODING_INVALID` (a bound-only caller may treat it as absent). `ArchiveDistinct.FieldBound` = the SUM of every shard's exact count (an upper bound on the union), `ok=false` if any shard is not exact.
- **A count is trusted only at its identity.** An entry claiming exact / over-limit is `Stale` when its recorded identity is unknown or differs from the shard's current central-directory identity (replaced outside Pulse under the same name). `ArchiveDistinctOf` (predict and the run pre-flight) returns no counts unless every entry is vouched for, so a replaced shard never lends old counts to a bound.
- **Distinct is on the stored bit pattern:** `+0` / `−0` count as two, every NaN payload separately — collapsing could under-count. Integer-only hashing, so counts are identical across architectures. Nulls excluded. Grouped shards count logical values via `NewLogicalStream` against the canonical schema.
- **Per writer — fresh vs carried:** every writer rewrites the trailer through one choke point (`buildSchemaDocPayload`); carries are matched by entry NAME (field name AND type) and gated by IDENTITY — a stale entry is recounted, never carried. Create counts every source; add counts the arrival and carries stored entries (an archive-moving add pre-passes to learn re-encoded identities); remove carries the kept; compact counts every absent or stale entry and is the backfill for archives written before the trailer; filter-to-file counts each filtered shard. A stored shard the prior trailer does not cover is recorded ABSENT by add / remove, never fabricated (`TestShardDistinct_LegacyArchiveNeverFabricatesAndCompactBackfills`).
- **Knobs:** `Options.ShardDistinctLimit` (default `encx.DefaultDistinctLimit` = 4,194,304 keys per field per shard; negative refused at `New`) and `Options.DisableShardDistinct` (new shards recorded opted out; carried entries keep theirs).
- **Memory:** one exact `uint64` set per counted field (≤ 64 MiB per field at the default limit), sized by ONE shard, released when a field passes the limit, reused across shards — a write allocates for its largest shard, never the sum.
