# Byte layout — SPSS type hints (`@PulseType`)

Per-topic slice of the byte-layout reference (the record 7/18 Pulse type hint that lets a `.sav` round trip keep its field types). Index: `.claude/reference/byte-layout.md` — load it first, then only the slice(s) your change touches.

**SPSS type hints — `@PulseType`.** SPSS stores every numeric as a double, so without a hint a cohort exported to `.sav` and re-imported reads every `u4`–`u64`, `f32`, `packed_bool` and `decimal128` as `f64`, and `categorical_u16` / `_u32` as `categorical_u8`. The fix lives in the `.sav` ALONE — neither the `.pulse` format nor the sidecar moves (a `.sav` travels without its sidecar).

- **Write side** (`internal/io/spss/type_hint.go` `applyTypeHints`, run by `BuildDictionary` after charset and name validation, so it keys on final wire names): a record `7/18` variable attribute `@PulseType('<type>'\n)` (the `@` hides it from SPSS's Variable View); `<type>` is the type's `String()` or `decimal128(<precision>,<scale>)`. Written ONLY where the plain re-import would choose a different type: an unlabelled `EncodeNumeric` variable of `u4`/`u8`/`u16`/`u32`/`u64`/`f32`/`packed_bool`/`decimal128`, and a `categorical_u16`/`_u32` text or code variable. A labelled integer binding re-imports categorical by design and gets none. An export with no such column is byte-identical to an unhinted one.
- **The writer owns the attribute inside an otherwise verbatim source 7/18:** it parses the payload PSPP's way, drops every existing `@PulseType`, appends the current hints, and re-emits the rest byte-for-byte — so a retyped column never keeps a stale hint. A source 7/18 the grammar cannot read stays verbatim and gains NO hint (rewriting unreadable bytes would corrupt them).
- **Read side** (`typeHintsFrom` + `mapping.applyTypeHint`): decoded in the file's charset; keyed on long name, else short name, case-insensitively. A hint-free file (every third-party file) maps exactly as before (`TestTypeHint_ThirdPartyFilesImportUnchanged`).
- **A hint is never taken on trust.** Every value is checked during the existing full scan: integers whole and in range; `u64` strictly below 2^53 (2^53+1 rounds to 2^53, so a read-back 2^53 is ambiguous); `packed_bool` 0/1; `f32` exactly representable; `decimal128(p,s)` within `|v|·10^s < 2^50` (where a double's error stays under a quarter unit, so its shortest rendering IS the exported decimal) with at most `s` fraction and `p−s` integer digits. Missing values are nulls and unchecked. Restored cells render positionally (never shortest-`g`, which spells 1e+06).
- **Any misfit** — a value that does not fit, an unreadable hint, or a hint the variable's SPSS shape cannot carry — leaves the plain mapping (doubles kept, never rounded into the type) and raises ONE `PULSE_SPSS_TYPE_NOT_RESTORED` (`variable`, `pulse_type`, `value` for a misfit). Import predict reads the same `PulseSchema()`, so predict and run agree by construction.
- Skills: `skills/spss-import-schema.md`, `skills/spss-export-fidelity.md`; docs `docs/src/cli/import-spss.md` (Pulse type hints).

**Set rungs, vector elements and inexact u64.**

- **Set rungs:** the import derives a multiple-dichotomy `set_*` at the NARROWEST rung with a bit per member, so a wider set would come back narrowed. The set's FIRST member variable (bit 0) carries `@PulseType('<rung>')` whenever the cohort's rung differs from the narrowest — on the synthesised path, and on the sidecar path via the variable written from `derived[].sources[0]` (a fresh sidecar can describe a set wider than its members need). The read side consumes set hints first: on a derived set's first member whose member count fits, it widens the column (lossless); a too-narrow rung or a set hint elsewhere keeps the narrowest rung and warns once.
- **Two-value hint:** a constituent owed its own column type too carries ONE attribute with two values, column type first — `@PulseType('u8'\n'set_u16'\n)`. The reader accepts exactly one column type plus one set rung in either order; any other multi-value attribute is unreadable (one warning, plain mapping).
- **Vectors** cannot round-trip (SPSS has none); `vec_f32` element variables carry `@PulseType('f32')` and come back `f32`.
- **Inexact u64:** past 2^53 a double cannot separate neighbouring integers. `CaseValue.U64` carries the exact word, and every value `> 2^53` on an `EncodeNumeric` variable raises ONE `PULSE_SPSS_INTEGER_INEXACT` per variable on `TargetWarnings` (`variable`, `cohort_field`, `count`, `first_row`, `value`). Under Strict (`ExportJob.Strict` / `ConvertJob.StrictRows`) the first such value fails the encode and nothing is written. Predict cannot read records, so `ValidateCohort` lists the same code without counts for every `u64` numeric variable — a risk, never a refusal.
