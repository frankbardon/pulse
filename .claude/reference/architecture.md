# Architecture — package layout and the MCP layer split

**How to load.** This file is an INDEX: the rules below plus a section map. Load it, then ONLY the per-topic slice(s) under `.claude/reference/architecture/` your change touches; find one with `grep -l '<identifier>' .claude/reference/architecture/*.md`. `.claude/reference/architecture/history.md` is superseded wording — do NOT load it by default. A section-qualified pointer at this file resolves through the section map.

**Load it before moving a package, adding a public package or exported symbol, or touching any import-boundary gate.**

- **Library-first.** The public API is the root package `pulse` (`pulse.go` plus the root `*.go` files). The CLI (`cmd/pulse/`, `internal/cli/`) parses flags, builds library objects, calls them and formats output; it never holds business logic. The frozen exported surface is `internal/apigolden/testdata/public_api.txt` — read it (or `go doc`) for the method list instead of keeping one here.
- **Every non-`internal/` package is public** and frozen at `v1.0.0` by `TestPublicAPIGolden`. A new public package or symbol needs a general embedder use case, never one consumer's convenience.
- **grpc is an accepted transitive dependency (v1 decision, #748).** Pulse has no gRPC code, but the root package links `google.golang.org/grpc` through Parquet: `github.com/apache/arrow-go/v18/parquet/pqarrow` imports `arrow/flight` (`go list -deps . | grep grpc`). `go mod why` names the CLI's OTLP HTTP exporter, yet dropping or moving it would not remove grpc (`observe/otel` itself has none), and a module split cannot shed a dependency the root package's Parquet adapter needs. Accept it; do not try to engineer it out.
- **Import boundaries are gates.** Each leaf package that must stay a leaf has a `Test*ImportBoundary` test beside it; `grep -rn 'func Test.*ImportBoundary' --include='*_test.go' .` lists them.

## Payload schema and manifest payload

**Payload JSON Schema.**

`internal/descriptor.BuildPayloadSchema()` returns the deterministic JSON Schema (draft 2020-12) for every public payload — the request roots, result shapes and the `Envelope` (open `data` slot). It is generated by reflection over `types`, registry-injected enums (`types.All*Types()` / `AllOverlayKinds()` / `AllRegressionTypes()`) and strict unions (`OverlayRef`, `OverlayPayload`); operator `params` stay open. Golden `descriptor/testdata/payload-schema.json`; `$id` version equals `format_version`; root `$comment` carries `feature_set_digest`. **`Pulse.PayloadSchema()` is the instance's view**: enums, slots and roots the instance hides are absent, and every registered extension operator joins its category's operator-type enum from the profile-filtered snapshot (`TestExtensions_PayloadSchemaEnumsCarryExtensions`). It backs `pulse schema`, which prints the schema RAW (not envelope-wrapped); the `pulse://schema` MCP resource serves the mounted instance's view. Detail: `.claude/reference/feature-profiles.md` (Payload schema hiding). Full prose: `docs/src/contract/payload-schema.md`.

**Manifest payload.**

`internal/descriptor.BuildManifest()` returns the deterministic LLM-bootstrap blob — one fetch per session, client-cached, reachable as `pulse --json` (or `pulse features`) and `pulse_manifest`. Its top-level fields are the exported fields of `descriptor.Manifest`; the golden is `descriptor/testdata/manifest.json`. Capability blocks (`facet`, `join`, `process_chain`, `crosstab`, `export`, `import`) are pointers, omitted when hidden. The cache key is `(pulse_version, feature_set_digest, limits_digest)`. Declarations live in `internal/descriptor/capabilities_*.go`; MCP tool metadata in `internal/mcp/toolmeta/meta.go`.

- **Intent-scoped manifest** (`Pulse.ManifestForIntent`, `pulse_manifest {intent}`, `pulse --json --intent`; `internal/descriptor.BuildManifestForIntent`): the operator-keyed sections keep only entries whose `intents` name the intent, `skills` is `SkillsForIntent`'s list, `crosstab` / `matrix` stay only when a remaining operator can use them, and the fixed sections (`descriptor.ScopedManifestElidedKeys`) are ABSENT on the wire and named in `elided`; `scope.intent` carries the intent record. `Scope == nil` encodes exactly as the default struct encoding, so the unscoped manifest is byte-identical. Size gate `TestManifestForIntent_SizeGate`: each analytic intent's scoped slim manifest is ≤ 15% of the full slim one, with named exceptions carrying a measured ceiling — never raise the 15%. An unknown or hidden intent is `PULSE_RECOMMEND_INTENT_UNKNOWN` via the shared `checkIntent`.
- **`names_column`.** A param entry's `names_column` marks a value naming a record column (every `type: "field"` entry, plus column-naming `string` / `list` params). Projection depends on it: `TestManifestNamesColumnMatchesProjection` probes every built-in params key through the projection extractor and fails on an unmarked one it decodes; `TestCapabilities_FieldParamsNameColumns` holds the shape.
