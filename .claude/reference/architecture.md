# Architecture — package layout and the MCP layer split

CLAUDE.md keeps only the always-load half of the architecture (the public package list and a pointer here). This file is the long form: where every package lives, which ones are public, how the narrowed "noun" packages are built, and how the MCP layer splits. **Load it before moving a package, adding a public package or symbol, or touching any import-boundary gate.**

## Public vs internal

Under Go module semantics every non-`internal/` package is public API, and `v1.0.0` freezes every exported identifier in it. The classification is decided in `docs/roadmap/v1.0.0-api-and-release/00-public-surface.md` (Decisions); the migration from the earlier layout is `docs/roadmap/v1.0.0-api-and-release/03-embedder-migration.md`.

## How the narrowed packages are built

Three techniques, chosen per package:

- **Split in place** (`encoding`, `descriptor`). The kept subset stays at the public path; the remainder moved to an `internal/<pkg>` twin with the same package name, so `encoding.X` / `descriptor.X` spellings read the same in prose either way. Methods on kept types that only the remainder needs became functions in the twin (`BuildDecodePlan`, `DecodeGroupEntry`, `NewGroupEntryDecoder`, `GroupSpecOf`, `ReadRecordAt`). The public `encoding` reaches its twin's needs through `internal/encodingbridge` hooks installed at init. `internal/tools/pkgsplit` is the AST rewriter that performed the split.
- **Alias facade** (`io`, `synth`). The whole implementation lives in `internal/io` (+ `internal/iocore`) and `internal/synth`; the public package holds only `type X = internal.X` aliases, re-declared constants and thin function wrappers for the kept subset. An alias freezes its target's fields and methods exactly as if the target were public — which is why `TestPublicAPIGolden` expands every alias.
- **Left whole** (`errors`, `mcpserve`) or **unexported in place** (`mcp/gosdk`).

**Reading package-qualified names.** Because each internal twin keeps its public package's NAME, contributor prose spelling `encoding.X`, `descriptor.X`, `synth.X` or `io.X` may mean the internal twin (`synth.AllDistributions`, `descriptor.BuildManifest`, `encoding.SidecarIndexPath` are all internal). Embedder-facing prose (`docs/src/library/`, README, the skill pack) names only spellings an external module can import; `internal/apigolden/testdata/public_api.txt` is the arbiter.

**Root aliases.** Facade-returned types from internal packages keep their `pulse.X` spelling as aliases (`ComposeOptions`, `Row`, `RowIter`, the shard and index result types, `ImportSpec` / `ImportResult` / `ImportEntry` / `ImportSidecar`, `Example` / `ExampleSummary`, `SkillMetadata`, `Template*` / `RenderedTemplate`, `CohesionWarning`, `GroupIndexHeadroom`, `SidecarIndex`, …). `DateRangeSpec`, `MemberSet` and `LoadMemberSetResult` are root-NATIVE types, not aliases. `pulse.go` also re-exports `types.Request` / `Response` / `ComposedRequest` and `synth.Spec` / `Result` / `Options` / `Profile` / `ProfileOptions`.

**The `io` import boundary.** Nothing under `internal/io/**` or `internal/iocore` may import the public `io` — its factory (`io.NewReader`, `NewReaderFromBytes`, `NewWriter`, `NewWriterToBuffer`, typed `io.Format` constants, `FormatFromPath`) imports every adapter, so the reverse edge is a cycle. Adapters import `internal/iocore` for contracts and `internal/io` for jobs. Gated by `TestIOImportBoundary*` (`internal/iocore/boundary_test.go`); when an adapter moves, move its path in `belowFacade` with it.

**Surface guards.** `TestPublicAPIGolden` (blocking) freezes every public package's exported shape, aliases expanded; regenerate with `go test ./internal/apigolden/ -run TestPublicAPIGolden -update` only for an intentional surface change and review the diff. The `apidiff` job in `.github/workflows/api-compat.yml` is advisory against the latest tag (label `api-break-ok` marks an intentional break) and flips to blocking once a stable `v1.0.0` tag exists. `make smoke` builds `internal/embeddersmoke`, an external module that only uses public spellings. Contributor prose: `docs/src/contributing/pr-process.md`.

## CLI

CLI commands map 1:1 to manifest commands — the list is in CLAUDE.md "Architecture". `pulse schema` prints the payload JSON Schema RAW, not envelope-wrapped.

## MCP layer split

`internal/mcp/` is the SDK-free core (typed In/Out structs, reflected JSON schemas, typed handlers over `*pulse.Pulse`, strict-decode, bind classification — gated by `TestMCPCore_NoSDKImport`). `mcp/gosdk/` is the ONLY package importing the go-sdk; its `Register(server, p, cfg)` mounts the core catalog onto a caller-supplied server, and `pulse mcp` builds a bare server and calls it. `mcp/gosdk` reaches the instance's extension snapshot through `internal/facadebridge`, never through an exported engine handle. `internal/mcp/toolmeta/` holds the leaf metadata both `internal/descriptor` and the core import. One tool per facade method plus skills/examples/errors/import/label tools — **the manifest is the source-of-truth count, never hardcode it** — and two resource schemes (`pulse://`, `pulse-skill://`); `pulse://schema` serves the payload JSON Schema as a RESOURCE, not a tool. Cohort resources are ENUMERATED by a startup walk of the data root, suppressible with `gosdk.Config.DisableCohortScan` / `mcpserve.Options.DisableCohortScan` / `pulse mcp --no-cohort-scan` — the `pulse://` template stays mounted, so a disabled scan costs enumeration only, never readability. Payload tools take the structured request at top level, outputs are typed-wrapped, coded errors surface as `{code, message, details}`. **Feature profiles at the MCP layer:** `mcpserve.NewPulse` is the ONLY reader of `PULSE_FEATURE_PROFILE` (and of `mcpserve.Options.FeatureProfileFile`, flag `pulse mcp --feature-profile`) — an OS path read with `os.ReadFile`, parsed by `pulse.ParseFeatureProfile`, handed to `pulse.New` as `Options.FeatureProfile`; `pulse.New` itself never reads the env. `gosdk.Register` ORs a profile's `behaviour.disable_cohort_scan` into `Config.DisableCohortScan` via the `facadebridge.CohortScanDisabled` hook, and `mcpserve.Describe` reports the effective value plus the profile label through the public `p.FeatureProfile()` accessor (a copy). Contract: `.claude/reference/feature-profiles.md`.

## Extension surface

Embedders author operators against the public `extend` package and register them through `pulse.Options.Extensions` (root `extensions*.go`). `extend` is a leaf: it imports only `encoding`, `types` and `errors` (`TestExtendImportBoundary`, `TestExtendImportBoundary_NoTransitiveEngine`), and no public root signature names an `internal/processing` type (`TestRootSurfaceNamesNoProcessing`). At `pulse.New`, `extensions_adapt.go` lifts each `extend` operator onto the engine interfaces, forwarding every optional sibling explicitly (a streamable operator that also carries `ComponentsFunc` still streams). Engine-only capabilities — `MetaWindow`, `ExtensionAware`, `KeyFor`, the merge hooks — are deliberately absent from `extend` (`TestExtendOmitsEngineOnlyCapabilities`).

- **Snapshot.** `pulse.New` builds the read-only `internal/descriptor.ExtensionsSnapshot` and passes it into `PredictOptions.Extensions` and, inside the instance snapshot, `mcp.BindForInstance` (`mcp/gosdk` reaches it via `internal/facadebridge.InstanceSnapshot`), keeping `internal/descriptor/` free of `internal/service/` and `internal/processing/`. It carries `OperatorMeta.FansOut` (manifest `fans_out`, grouper-only); runtime twin is the engine's extension-registry fan-out map. Both feed `types.CheckPairwiseSlabPartitionWith`, which owns the ONE order: built-in first, then the extension side, and a name known to NEITHER passes (it cannot execute, so it can produce no wrong number).
- **Lazy table resolution.** A grouper factory's `(grp, schema)` signature cannot reach the registry, so a named `table:` resolves through the engine-internal `ExtensionAware` `SetExtensions` hook, threaded by `ApplyGrouperExtensions` through every construction site. Inline sources resolve eagerly.
- **Grouper probe.** A grouper declaring `Streamable: true` without `extend.StreamingGrouper` / `extend.MultiKeyStreamingGrouper` → `PULSE_EXTENSION_STREAMABLE_MISMATCH`. A `GrouperRegistration.FansOut` declaration disagreeing with `extend.MultiKeyStreamingGrouper` in EITHER direction → `PULSE_EXTENSION_FANOUT_MISMATCH` (the embedder-side sibling of `types.GroupType.FansOut()`; omitted defaults false, so a multi-key factory is refused rather than silently under-declared).
- **Streamability follows the declaration.** Extension aggregators, groupers, attributes and row tests route on the DECLARED `Streamable` flag (runtime, predict and the snapshot agree: `TestExtensions_StreamabilityFollowsDeclaration`); `Streamable:false` runs buffered even when the value is online-capable. A grouper declaring `Streamable:true` without a keying sibling is `PULSE_EXTENSION_STREAMABLE_MISMATCH`. Feature streamability is decided by the returned value and is not probed. A built-in ZSCORE + `GROUP_CATEGORY` request predicts `Streamable=false`, matching runtime.
- **Components emission.** `ComponentsFunc` is probe-validated; an operator's own `Components()` method still emits when none is registered, for every emitting category (intentional deviation, NOT probe-validated).
- **Limits.** Extension aggregators merge only when the registration declares `Mergeable` (adapter forwards `extend.MergeableAggregator.Merge` as the engine's `MergeOnline`, unwrapping the partner to the embedder's own value; probe refuses an unhonourable declaration with `PULSE_EXTENSION_MERGEABLE_MISMATCH`); extension groupers merge the same way on a declared `Mergeable` (adapter forwards `extend.MergeableGrouper.MergeState` as `MergeGrouperState`, or folds nothing for a grouper that emits no components); extension filterers and `row_local` attributes merge as row-local operators (`processing.CanMergeRequestWithExtensions`; predict twin `internal/descriptor.ValidateChainWithExtensions` — both decide through `internal/mergegate`, over the registry and the snapshot respectively). Extension grouper per-operator Components figures emit on every grouped path, merged ones included; single-key extension groupers take fused crosstab through an adapter-synthesized `KeyFor` (still omitted from `extend`) — an axis grouper fuses iff it DECLARES `Streamable || FansOut` (`internal/crosstabfuse`; `Streamable:false` + `KeyForRow` runs buffered since cohort-facade E4-S1); an extension crosstab CELL aggregator fuses only on a declared `MarginReducibility` (fusable class + `Mergeable`, else `PULSE_EXTENSION_MARGIN_REDUCIBILITY_MISMATCH`; undeclared → buffered); a `two_pass` extension attribute keeps a crosstab buffered, as the built-in two-pass set does. Extension aggregators are admitted on `decimal128` targets (they read `DecimalValue`) and stream there per their declared `Streamable` flag — `UpdateRow` sees decimal fields via `DecimalValue`; built-ins over decimal stay buffered and serial, while a `Mergeable` extension merges a decimal target.
- **Row weights (`WeightAware`).** `AggregatorRegistration`, `AttributeRegistration` and `TestRegistration` carry `WeightAware`, projected as `OperatorMeta.WeightAware` (manifest `weight_aware`) and recorded on `processing.ExtensionRegistry.WeightAware` (keyed like `Streamable`). ONE declaration drives all three halves: `ResolveWeights` classes an extension slot off the snapshot (`ExtensionsSnapshot.WeightAwareness` — aware ⇒ applied; a non-aware aggregator skipped under the instance default and `PULSE_EXTENSION_NOT_WEIGHT_AWARE` under an explicit weight; a non-aware attribute or test refused under any weight), `processing.StampWeightsWith` stamps the resolved weight onto an aware slot's spec (aggregations, tests, post-tests, attributes), and the root adapter (`extensions_adapt.go`, `slotWeighting`) hands the operator a per-slot `weightedRecord` view whose `extend.Record.Weight()` reports the row's VALID weight — `*processing.Record.Weight()` itself always answers `(0, false)`, because slot weights differ within one request. Invalid-weight rows never reach an aware aggregator or row test (an attribute still gets them, `Weight()` false); the floor keys come from the orchestrator (`WeightFloor`). The probe constructs an aware factory with and without a weight (`details.weighted` on the second's failure). Contract: `.claude/reference/weighting.md` (Extension contract).
- **FieldInputs.** The projection extractor (`NeededFields`, internal) reads each registration's optional `FieldInputs`; absent widens the retained set to `*` — correct, but it forfeits the projection win.
- **DependsOn.** Every operator registration (not synth distributions) carries optional `DependsOn []string` — feature names, each a single-name AND group after the request-host group every extension operator gets. Validated against built-in features + registered extensions at EVERY `pulse.New` (`validateExtensionDependsOn`, right after the probe), profile or not. Extensions carry no `Since`. Contract: `.claude/reference/feature-profiles.md` (Dependency model).
- **Purpose.** Every registration carries optional `Purpose *descriptor.Purpose` (tests also `Interpretation`), validated at every `pulse.New` right after `DependsOn` (`validateExtensionGuidance`, `extensions_guidance.go`) through the built-in tier's `ValidatePurpose` with an instance resolver (built-ins + feature table + every registered extension); Interpretation is structure-only (nil `OutputResolver`). Failure is `PULSE_EXTENSION_PURPOSE_INVALID`. The snapshot carries `Purposes` / `Interpretations`; only intent IDs project (`OperatorMeta.Intents`, `withExtIntents`).
- **Skills.** `Extensions.Skills fs.FS` ships embedder skill files: atomic `op-<category>-<kebab>.md` for ONE registered extension operator (stem = `skills.OperatorStem(name)`) and topical `ext-<kebab>.md`. `validateExtensionUniverse` loads them last (`descx.LoadExtensionSkills`, `internal/descriptor/extension_skills.go`) against the snapshot of EVERY registration plus each operator's `DependsOn`, so validity never depends on the profile; the built-in pack's family rules (`internal/skills/families.go`: `RequiredSections`, `BodyBudget` — HARD for embedders), fence validation against the extended graph and the fence-coverage scanner (`skill_fence_coverage.go`, extension operators added to the scan list) apply. Failure: `PULSE_EXTENSION_SKILL_INVALID` (`details.reason`) or `PULSE_EXTENSION_SKILL_COLLISION` (built-in / virtual stem, or a stem two merged `Extensions` values ship — `mergeExtensions` layers them with `extFSStack`). `pulse.New` hands every validated skill to the snapshot (`ExtensionsSnapshot.Skills`, a skills-only instance gets an empty snapshot); `extendOntology` → `addExtensionSkills` adds the ones whose operator and `requires:` survive, and `Discovery` serves them (built-ins pass through byte-identically on a hide-nothing instance). Docs: `docs/src/internals/extension-points.md` (Embedder skills).
- **Examples.** `Extensions.Examples fs.FS` ships embedder request examples: top-level `.json` files, each a request body plus the built-in library's `_meta` block (`name`, `category`, `description`, `tags`, `operators`, optional `intents` / `capabilities`; `examples.Parse` in strict mode refuses any other `_meta` key). `validateExtensionUniverse` loads them after the skills (`descx.LoadExtensionExamples`, `internal/descriptor/extension_examples.go`) against the snapshot of EVERY registration, reusing the shipped library's rules rather than copies: canonical tags (`examples.IsCanonicalTag`), `IsIntent`, `exampleCapabilityProblems`, `examples.DeriveOperators` (operators-match-body) and `exampleEdgeCoverageProblems` (the `TestExamples_EdgeCoverage` rule, with extension operator names added to the operator set) — plus a STRICT decode of the body as its request root (`requests` → `types.ComposedRequest`, `stages` → `types.ChainRequest`, `fields` → `types.FacetRequest`, else `types.Request`; the shipped library is checked leniently) and every `_meta.operators` entry an operator node of the extended graph. Failure: `PULSE_EXTENSION_EXAMPLE_INVALID` (`details.reason`) or `PULSE_EXTENSION_EXAMPLE_COLLISION` (a built-in example name, or a name shipped twice — across merged `Extensions` values too, via `extFSStack`). `pulse.New` hands them to `ExtensionsSnapshot.Examples`; `extendOntology` → `addExtensionExamples` adds each one whose extension operators (`ExtensionExample.ExtOperators`: every extension operator it names anywhere) survive the profile, with the E1-S2 edges a built-in gets (`addExampleEdges`: `_meta` operators / intents / capabilities, the structural detector table, overlay kinds, description mentions — `ontologyBuilder.extOperators` lets a description route to an extension operator) plus built-in and embedder atomic skills' `## See` `tags=[…]` edges; `pruneOntology` then prunes it like a built-in. `Discovery` merges the survivors into one name-sorted library (`exampleLib`, searched by `examples.SearchIn` with the built-in ranking rules) behind `ExamplesSearch` / `Example` / `ExampleStats`, so the facade, `pulse_examples_*` and the manifest examples stats serve them; built-in records are unchanged. The CLI `pulse examples` leaf stays embedded-library only. Docs: `docs/src/internals/extension-points.md` (Embedder examples).

## The CLAUDE.md Extension Points bullets, pre-compression (relocated verbatim at weighting-descriptive E1-S1)

CLAUDE.md "Extension Points" now carries one pointer bullet in their place; the sections above are the authoritative long form.

- **Probe-validation:** each factory is constructed once against a minimal synthetic schema. A streamable-flagged registration not returning the streaming interface → `PULSE_EXTENSION_STREAMABLE_MISMATCH`; a factory panic → `PULSE_EXTENSION_FACTORY_PANIC`. Grouper `Streamable` / `FansOut` mismatches (`PULSE_EXTENSION_FANOUT_MISMATCH`): `.claude/reference/architecture.md` (Extension surface).
- **Expression env + tables:** `ExprFunctions` merge into the expr-lang env; `LookupTables` (`key→float64`) via `lookup(table, keys...)` (`PULSE_LOOKUP_TABLE_UNKNOWN` / `PULSE_LOOKUP_MISS`), `LabelTables` (output-time labels), `RangeTables` (date-range sets); all three project into the manifest `extensions` block.
- **Snapshot, lazy `table:` resolution, `FieldInputs`, DECLARED `Streamable` / `Mergeable`, `Components()` emission, `DependsOn`:** `.claude/reference/architecture.md` (Extension surface).
- **Skills / examples:** `Extensions.Skills` (`.md`) / `Extensions.Examples` (`_meta` `.json`), validated HARD at `pulse.New` (`PULSE_EXTENSION_SKILL_*` / `_EXAMPLE_*`; never shadowing a built-in), served and pruned like built-ins (stems, rules, wiring: Extension surface).
- **Guidance:** optional `Purpose` (+ test `Interpretation`) checked by the built-in validators at `pulse.New` → `PULSE_EXTENSION_PURPOSE_INVALID`; only intent IDs project.
