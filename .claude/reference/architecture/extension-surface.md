# Architecture — Extension surface

Per-topic slice of the architecture reference (Extension surface). Index (rules + section map): `.claude/reference/architecture.md` — load it first, then only the slice(s) your change touches. Category-specific rules for matrix operators, regressions, overlay kinds and post-fit operators: `architecture/extension-models.md`. Embedder recipe: `docs/src/internals/extension-points.md`.

## Extension surface

Embedders author operators against the public `extend` package and register them through `pulse.Options.Extensions` (root `extensions*.go`) at `pulse.New()`. Predict, manifest, MCP and runtime treat a registered extension exactly like a built-in. `extend` is a leaf over `encoding`, `types`, `errors` and `linalg` (`TestExtendImportBoundary`, `TestExtendImportBoundary_NoTransitiveEngine`), and no public root signature names an `internal/processing` type (`TestRootSurfaceNamesNoProcessing`). At `pulse.New`, `extensions_adapt.go` lifts each `extend` operator onto the engine interfaces and forwards every optional sibling explicitly (a streamable operator that also carries `ComponentsFunc` still streams). Engine-only capabilities — `MetaWindow`, `ExtensionAware`, `KeyFor`, the merge hooks — are deliberately absent from `extend` (`TestExtendOmitsEngineOnlyCapabilities`).

- **Naming and registration.** Eleven operator categories — `AGG`, `ATTR`, `FILTER`, `GROUP`, `WIN`, `FEAT`, `TEST`, `MAT`, `REG`, `OVERLAY`, `POSTFIT` — plus expr functions, four named-table kinds (`LookupTables`, `ReferenceVectors`, `LabelTables`, `RangeTables`) and registered `Populations`. Synth distributions are NOT a category. Names must match `^(AGG|ATTR|FILTER|GROUP|WIN|FEAT|TEST|MAT|REG|OVERLAY|POSTFIT)_[A-Z][A-Z0-9]+_[A-Z](?:[A-Z0-9_]*[A-Z0-9])?$`; the namespaces `BUILTIN` / `STANDARD` / `CORE` / `PULSE` are reserved (`PULSE_EXTENSION_NAME_RESERVED`), and a collision with a built-in is rejected. The runtime overlay is `internal/processing/extensions.go`.
- **Snapshot.** `pulse.New` builds the read-only `internal/descriptor.ExtensionsSnapshot` and hands it to predict (`PredictOptions.Extensions`) and, inside the instance snapshot, to MCP (through `internal/facadebridge`). This keeps `internal/descriptor/` free of the engine. Every "extension declares X" fact has a runtime twin on `processing.ExtensionRegistry` and a predict twin on the snapshot, built from the SAME declaration by one root function; that is what keeps predict and runtime agreeing. Pairwise slab partitioning checks built-ins first, then extensions; a name known to neither passes (it cannot execute, so it can produce no wrong number).
- **Factory presence and probe.** The shared naming / duplicate / `ParamMeta` pass refuses a nil `Factory` (`PULSE_EXTENSION_PARAM_INVALID`, `reason: "missing_factory"`) before any probe (`TestExtensions_NilFactoryRefusedAtValidation`). Each factory is then constructed once against a minimal synthetic schema; a factory panic or error is `PULSE_EXTENSION_FACTORY_PANIC`.
- **Lazy table resolution.** A grouper factory cannot reach the registry, so a named `table:` resolves through the engine-internal `ExtensionAware` hook, threaded through every grouper construction site. Inline sources resolve eagerly.
- **Streamability follows the declaration.** Extension aggregators, groupers, attributes and row tests route on the DECLARED `Streamable` flag in runtime, predict and the snapshot alike (`TestExtensions_StreamabilityFollowsDeclaration`); `Streamable: false` runs buffered even when the value is online-capable. A grouper declaring `Streamable: true` without `extend.StreamingGrouper` / `MultiKeyStreamingGrouper` is `PULSE_EXTENSION_STREAMABLE_MISMATCH`; a `FansOut` declaration disagreeing with `MultiKeyStreamingGrouper` in either direction is `PULSE_EXTENSION_FANOUT_MISMATCH` (omitted defaults false, so a multi-key factory is refused rather than silently under-declared). A feature's streamability is decided by its returned value, so the probe checks it two-way against the declaration.
- **Nullable attributes.** An attribute's null output is the optional `extend.NullableAttribute` (`EmitsNull() bool`); the adapter answers the engine's null-emitter check from it on every tier, so the attribute's `NaN` becomes a null in every arm exactly as a built-in's does (`TestExtensions_NullableAttributeEmitsNull`).
- **Components emission.** An emitter is a `ComponentsFunc` or, with none registered, the operator value's own `Components()` method. One probe helper validates both: an emitter without `ComponentSchema.Keys` is `PULSE_EXTENSION_MISSING_COMPONENT_SCHEMA`; an emitted key outside keys + floor is `PULSE_EXTENSION_COMPONENT_SCHEMA_MISMATCH` (`details.emitter`); a panic or error is `PULSE_EXTENSION_FACTORY_PANIC`; Keys with no emitter is `PULSE_EXTENSION_PARAM_INVALID` `schema_without_emitter`. Whether an attribute emits is ONE root rule, `attributeEmitsComponents`, feeding both the runtime registry and the snapshot (`TestExtensions_ComponentAttributesRuntimeMatchesSnapshot`).
- **Merging.** An extension aggregator or grouper merges only on a declared `Mergeable` (the adapter forwards `extend.MergeableAggregator.Merge` / `MergeableGrouper.MergeState`; an unhonourable declaration is `PULSE_EXTENSION_MERGEABLE_MISMATCH`). Filterers and `row_local` attributes merge as row-local operators; a component-emitting attribute merges only on a declared `Mergeable` with `extend.MergeableAttribute`. Runtime and predict decide through `internal/mergegate`, over the registry and the snapshot respectively. A single-key extension grouper takes fused crosstab through an adapter-synthesized `KeyFor` iff it declares `Streamable || FansOut`; a crosstab CELL aggregator fuses only on a declared `MarginReducibility` (fusable class + `Mergeable`, else `PULSE_EXTENSION_MARGIN_REDUCIBILITY_MISMATCH`); a `two_pass` attribute keeps a crosstab buffered. Extension aggregators are admitted on `decimal128` targets (they read `DecimalValue`) and stream there per their declaration.
- **Row weights (`WeightAware`).** One declaration on aggregator, attribute and test registrations drives three halves: weight resolution classes the slot off the snapshot (aware ⇒ applied; a non-aware aggregator is skipped under the instance default and refused `PULSE_EXTENSION_NOT_WEIGHT_AWARE` under an explicit weight; a non-aware attribute or test is refused under any weight), the engine stamps the resolved weight onto an aware slot, and the adapter hands the operator a per-slot record view whose `Weight()` reports the row's VALID weight. The engine record's own `Weight()` always answers `(0, false)`, because slot weights differ within one request. Contract: `.claude/reference/weighting.md` (Extension contract).
- **Native vector members (`extRecord`).** Every row handoff to an extend operator wraps the engine row in the zero-alloc `extRecord` view, whose `NumericValue` / `IsNull` resolve a native element member `f[k]` by the shared null-member rule. **A new handoff site that passes the bare row silently reads every element null** (`TestExtRecord_EveryHandoffResolvesElements`).
- **Exact `u64` (`Uint64Value`).** `extend.Record.Uint64Value` returns a `u64` field's stored word. Every map-decode site that builds an engine record must install `internal/encoding.ExactU64Words` on its reader and apply it to the record (nil and free when the schema has no `u64`). **A new map-decode site that skips it silently reads the float echo above 2^53** (`TestExtendRecord_Uint64ValueExactEveryMode`, `internal/service/exact_u64_fallback_test.go`).
- **Vector-input aggregators.** `VectorInput` makes the slot read `vector` / `fields` (exactly one; `field` refused) by the built-in vector rules. `ArrayValued` (requires `VectorInput`, no `MarginReducibility`, the value implements `extend.RichAggregator` returning one float per member) makes it array-valued; violations are `PULSE_EXTENSION_ARRAY_VALUED_MISMATCH`, and a `labels` / `expand` `ParamMeta` on a vector input is `PULSE_EXTENSION_PARAM_INVALID` `reserved_vector_param`. `NonScalar` (a Rich value that is not one number) and `EmitsInputValue` (a value picked from the input column, like a mode) are declarations with no probe; both refuse the operator as an overlay's scored aggregation (`reason` `non_scalar` / `categorical_code`) and `NonScalar` also refuses it in a chain stage feeding another. ONE classifier, `vectors.AggregationKinds`, built from the registry at runtime and from the snapshot in predict, feeds every site that asks. Gates: `TestExtensions_VectorAggregator*`, `TestAggregationKinds_*`.
- **Count semantics and value state.** `CountSemantic` makes `return.precision` write the slot exact (refused on a vector-input registration, `count_semantic_vector_input`); `ValueState` counts the slot in the limits model's value-state aggregations. Both read the instance snapshot, so predict and runtime agree.
- **Reference vectors.** `Extensions.ReferenceVectors` (programmatic only) registers labelled profile tables read by the reserved `ref("table", key)` expr built-in. Validated at `pulse.New` (`PULSE_EXTENSION_PARAM_INVALID`, reasons such as `duplicate_label`, `length_mismatch`, `non_finite`), projected to the manifest as labels + keys (never values). Not a feature, outside the feature-set digest. One rule set in `internal/vectors` feeds predict (every issue) and the build (the first issue). Matching is by label, never position: `PULSE_VECTOR_REFERENCE_MISMATCH` (`labels_differ` / `unlabeled_partner`), `PULSE_VECTOR_REFERENCE_UNKNOWN` (`table_unknown` / `table_not_literal` / `key_unknown`).
- **Matrix operators and regression models.** `MatrixOps` and `Regressions` live in the sibling slice `architecture/extension-models.md` (Extension models).
- **Registered populations.** `Extensions.Populations` registers saved vector-fit population files by name; `Options.PopulationsDir` / `PULSE_POPULATIONS_DIR` merges a directory's `*.pulse-population.json` files under their stems (the option beats the env; non-recursive). Decoded and frozen at `pulse.New` (`PULSE_MODEL_FILE_INVALID` / `_VERSION_UNSUPPORTED` / `PULSE_MODEL_REF_INVALID`, each `details.registered`), dropped whole when a feature profile hides `capability:models`, and bound beneath every request as vector fits. A request fit reusing a registered name is `PULSE_MODEL_NAME_COLLISION`; a name both programmatic and on disk is `PULSE_EXTENSION_DUPLICATE`. Manifest `extensions.populations` lists name, operator, basis, labels and n — never the moments. Directory loading: `byte-layout.md` (Table-directory sidecar exclusion).
- **FieldInputs.** The projection extractor reads each registration's optional `FieldInputs`; absent widens the retained set to `*` — correct, but it forfeits the projection win. An aggregator's or grouper's hook names are also its column reads in the windows-first decision; predict and runtime read the same declaration.
- **DependsOn.** Every operator registration carries optional `DependsOn []string` — feature names, each a single-name AND group added after the request-host group every extension operator gets. Validated against built-in features + registered extensions at EVERY `pulse.New`, profile or not. Extensions carry no `Since`. Contract: `.claude/reference/feature-profiles.md` (Dependency model).
- **Purpose.** Every registration carries optional `Purpose` (tests, regressions and overlays also `Interpretation`), validated at every `pulse.New` right after `DependsOn` by the built-in validator with an instance resolver; failure is `PULSE_EXTENSION_PURPOSE_INVALID`. Only intent IDs project to the manifest. Contract: `guided-analysis.md` (Extension hook).
- **Skills.** `Extensions.Skills` ships atomic `op-<category>-<kebab>.md` (one registered extension operator) and topical `ext-<kebab>.md` files, validated last against EVERY registration (so validity never depends on the profile) by the built-in pack's family rules, HARD budgets and fence rules. Failure: `PULSE_EXTENSION_SKILL_INVALID` (`details.reason`) or `PULSE_EXTENSION_SKILL_COLLISION` (a built-in / virtual stem, or one stem shipped twice across merged `Extensions` values). They join the instance ontology and prune like built-ins. Rules: `skill-pack.md` (Embedder skills); docs: `docs/src/internals/extension-points.md` (Embedder skills).
- **Examples.** `Extensions.Examples` ships top-level `.json` request bodies with the built-in library's `_meta` block (strict: any other `_meta` key is refused). They are validated against EVERY registration by the shipped library's own rules (canonical tags, intents, capabilities, operators-match-body, edge coverage) plus a STRICT decode of the body as its request root. Failure: `PULSE_EXTENSION_EXAMPLE_INVALID` or `PULSE_EXTENSION_EXAMPLE_COLLISION`. Survivors of the profile prune merge into one name-sorted library behind the facade, `pulse_examples_*` and the manifest; the CLI `pulse examples` leaf stays embedded-library only. Docs: `docs/src/internals/extension-points.md` (Embedder examples).
- **Inherited output dictionary.** `AttributeRegistration.InheritsDictionary` declares the output a CODE of a coded cohort source (the slot's `Field`, or a named string param), so the column reads as the source wherever an `ATTR_PREVIOUS_STATE` output does. Source refusals are `PROCESSING_CONFIG` (`source_unset` / `source_not_cohort_field`) and `PULSE_FIELD_TYPE_UNSUPPORTED` (`source_not_coded`); an out-of-range code at run or probe is `PULSE_EXTENSION_ATTRIBUTE_OUTPUT_MISMATCH` `dictionary_code_out_of_range`. Gates: `TestExtensions_InheritedDictionary*`.
- **Params validation.** A registration's `Params []ParamMeta` is the slot's params allowlist, exactly as a built-in's manifest Param list, in all nine params-bearing categories, predict ≡ runtime (`descx.ParamsRefusal`). Order: an undeclared key is `PULSE_REQUEST_UNKNOWN_FIELD` (`details.path` `<slot>.params.<key>`, nearest-key suggestion); a wrong `JSONType` (null included) or an omitted `Required` key is `PULSE_REQUEST_PARAM_INVALID` (`wrong_type` / `missing_required`); none or several members of an `ExactlyOneOf` group is `exactly_one_of`. `Default` stays the factory's — never injected. A registration declaring NO params is unchecked (predict advises `PULSE_ADVISORY_EXTENSION_PARAMS_UNDECLARED`). **The probe honours the declaration:** each `Required` param and the first member of each `ExactlyOneOf` group gets its `ParamMeta.Example` (type-checked at `pulse.New`, `example_type_mismatch`), else a `JSONType` placeholder; a factory refusing it is `PULSE_EXTENSION_FACTORY_PANIC` with `details.probe_params`. Gates: `TestParamsRefusal_ExtensionOperators`, `TestExtensions_Params*`, `TestExtensions_ProbeParams*`.
- **Expression-capable params (`ParamMeta.Expression`).** Valid only on `JSONType` `number` (else `expression_not_number`). A string on such a key is a scalar expression resolved by ONE no-execute pass, `internal/extscalar` (`TestExtScalar_ImportBoundary`), ahead of every engine entry point and in predict, which reports what it cannot compute as `unresolved_scalars`; refusals are `PULSE_REQUEST_PARAM_INVALID` reasons `param_*`. A `{{token}}` at such a key in a template is `PULSE_TEMPLATE_EXPR_SPLICE` (the visible flagged keys reach the template store as plain data, so the import ceiling holds), and an axis token there in a sweep / `for_each` is `PULSE_SWEEP_EXPR_SPLICE` / `PULSE_FOR_EACH_EXPR_SPLICE`. Gates: `TestExtensions_ParamsExpression*`, `TestTemplateExprSplice_Extension*`, `Test*ExprSplice_ExtensionParam*`.
- **Deliberate v1 gaps** (recipe: `docs/src/internals/extension-points.md` "Deliberate v1 gaps"). Named tables are not features and sit outside `feature_set_digest`; extension test `Interpretation` is structure-only; extensions are never zone-capable (an explicit `tz` is `PROCESSING_CONFIG`); there is no synth-distribution category. `FilterToFileWithRequest` builds extension filterers through the engine registry as `Process` does; its dedup hash carries referenced-table CONTENT, and a predicate running embedder code is never reused. `io.LateKeyRefuser` is the public opt-in for a keyed custom reader's late-key refusal.
