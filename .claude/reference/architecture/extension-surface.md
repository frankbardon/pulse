# Architecture — Extension surface

Per-topic slice of the architecture reference (Extension surface). Index (preamble + section map): `.claude/reference/architecture.md` — load it first, then only the slice(s) your change touches.

## Extension surface

Embedders author operators against the public `extend` package and register them through `pulse.Options.Extensions` (root `extensions*.go`). `extend` is a leaf: it imports only `encoding`, `types`, `errors` and `linalg` (`linalg` for the read-only `*linalg.CoMoment` a matrix operator finalizes over; itself a leaf) (`TestExtendImportBoundary`, `TestExtendImportBoundary_NoTransitiveEngine`), and no public root signature names an `internal/processing` type (`TestRootSurfaceNamesNoProcessing`). At `pulse.New`, `extensions_adapt.go` lifts each `extend` operator onto the engine interfaces, forwarding every optional sibling explicitly (a streamable operator that also carries `ComponentsFunc` still streams). An attribute's null output is the optional `extend.NullableAttribute` (`EmitsNull() bool`): the adapter answers the engine's `NullEmitter` on every tier from it (false when absent, byte-identical), so the attribute's `NaN` becomes a null in every arm exactly as a built-in's null does (`TestExtensions_NullableAttributeEmitsNull`, the attribute rows of `TestExtensions_BuiltinParity`). Engine-only capabilities — `MetaWindow`, `ExtensionAware`, `KeyFor`, the merge hooks — are deliberately absent from `extend` (`TestExtendOmitsEngineOnlyCapabilities`).

- **Snapshot.** `pulse.New` builds the read-only `internal/descriptor.ExtensionsSnapshot` and passes it into `PredictOptions.Extensions` and, inside the instance snapshot, `mcp.BindForInstance` (`mcp/gosdk` reaches it via `internal/facadebridge.InstanceSnapshot`), keeping `internal/descriptor/` free of `internal/service/` and `internal/processing/`. It carries `OperatorMeta.FansOut` (manifest `fans_out`, grouper-only); runtime twin is the engine's extension-registry fan-out map. Both feed `types.CheckPairwiseSlabPartitionWith`, which owns the ONE order: built-in first, then the extension side, and a name known to NEITHER passes (it cannot execute, so it can produce no wrong number).
- **Factory presence (U34).** `validateOperatorSlice` (the shared naming / duplicate / `ParamMeta` pass) also refuses a nil `Factory` for aggregator, attribute, filterer, grouper, window and feature registrations — `PULSE_EXTENSION_PARAM_INVALID`, details `{category, name, index, reason: "missing_factory"}`, the matrix shape — before any probe (it once surfaced only as a recovered `PULSE_EXTENSION_FACTORY_PANIC`); matrix ops keep theirs in `validateMatrixOps`, tests per tier in `validateTestTiers`. Gate: `TestExtensions_NilFactoryRefusedAtValidation`.
- **Lazy table resolution.** A grouper factory's `(grp, schema)` signature cannot reach the registry, so a named `table:` resolves through the engine-internal `ExtensionAware` `SetExtensions` hook, threaded by `ApplyGrouperExtensions` through every construction site. Inline sources resolve eagerly.
- **Grouper probe.** A grouper declaring `Streamable: true` without `extend.StreamingGrouper` / `extend.MultiKeyStreamingGrouper` → `PULSE_EXTENSION_STREAMABLE_MISMATCH`. A `GrouperRegistration.FansOut` declaration disagreeing with `extend.MultiKeyStreamingGrouper` in EITHER direction → `PULSE_EXTENSION_FANOUT_MISMATCH` (the embedder-side sibling of `types.GroupType.FansOut()`; omitted defaults false, so a multi-key factory is refused rather than silently under-declared).
- **Streamability follows the declaration.** Extension aggregators, groupers, attributes and row tests route on the DECLARED `Streamable` flag (runtime, predict and the snapshot agree: `TestExtensions_StreamabilityFollowsDeclaration`); `Streamable:false` runs buffered even when the value is online-capable. A grouper declaring `Streamable:true` without a keying sibling is `PULSE_EXTENSION_STREAMABLE_MISMATCH`. Feature streamability is decided by the returned value, so `pulse.New` probes it TWO-WAY against the declared `Streamable` (mismatch either way: `PULSE_EXTENSION_STREAMABLE_MISMATCH`). A built-in ZSCORE + `GROUP_CATEGORY` request predicts `Streamable=false`, matching runtime.
- **Components emission.** An emitter is a `ComponentsFunc` OR, with none registered, the operator value's own `Components()` method (the adapters adopt it for aggregators, groupers, filterers and attributes; `componentsEmitter`). Both are probe-validated at `pulse.New` by one helper (`probeComponentEmission`, U34 #195): an emitter without `ComponentSchema.Keys` is `PULSE_EXTENSION_MISSING_COMPONENT_SCHEMA` (self-emitter reason `self_emitter_without_schema_keys`), an emitted key outside keys + floor is `PULSE_EXTENSION_COMPONENT_SCHEMA_MISMATCH` (`details.emitter` `ComponentsFunc` / `Components()`), a panic or error is `PULSE_EXTENSION_FACTORY_PANIC`; Keys with neither emitter is `PULSE_EXTENSION_PARAM_INVALID` `schema_without_emitter` (decided by the probe — only the built value reveals a method). Declared attribute Keys mark the attribute component-emitting at runtime (`ComponentAttributes`), the fact predict reads off `ComponentSchemas`.
- **Limits.** Extension aggregators merge only when the registration declares `Mergeable` (adapter forwards `extend.MergeableAggregator.Merge` as the engine's `MergeOnline`, unwrapping the partner to the embedder's own value; probe refuses an unhonourable declaration with `PULSE_EXTENSION_MERGEABLE_MISMATCH`); extension groupers merge the same way on a declared `Mergeable` (adapter forwards `extend.MergeableGrouper.MergeState` as `MergeGrouperState`, or folds nothing for a grouper that emits no components); extension filterers and `row_local` attributes merge as row-local operators — a component-emitting attribute only on a declared `Mergeable` (U51 E3-S2: the adapter forwards `extend.MergeableAttribute.MergeTally` as the engine's `MergeableAttributeTally`, unwrapping the partner; the probe refuses a non-`row_local` mode, an emitting value without the interface or a `none` schema with `PULSE_EXTENSION_MERGEABLE_MISMATCH`; `OperatorMeta.Mergeable` carries it to the snapshot) (`processing.CanMergeRequestWithExtensions`; predict twin `internal/descriptor.ValidateChainWithOptions` with `PredictOptions.Extensions`, reached in production through `(*Pulse).PredictChain` — both decide through `internal/mergegate`, over the registry and the snapshot respectively). Extension grouper per-operator Components figures emit on every grouped path, merged ones included; single-key extension groupers take fused crosstab through an adapter-synthesized `KeyFor` (still omitted from `extend`) — an axis grouper fuses iff it DECLARES `Streamable || FansOut` (`internal/crosstabfuse`; `Streamable:false` + `KeyForRow` runs buffered since cohort-facade E4-S1); an extension crosstab CELL aggregator fuses only on a declared `MarginReducibility` (fusable class + `Mergeable`, else `PULSE_EXTENSION_MARGIN_REDUCIBILITY_MISMATCH`; undeclared → buffered); a `two_pass` extension attribute keeps a crosstab buffered, as the built-in two-pass set does. Extension aggregators are admitted on `decimal128` targets (they read `DecimalValue`) and stream there per their declared `Streamable` flag — `UpdateRow` sees decimal fields via `DecimalValue`; built-ins over decimal stay buffered and serial, while a `Mergeable` extension merges a decimal target.
- **Row weights (`WeightAware`).** `AggregatorRegistration`, `AttributeRegistration` and `TestRegistration` carry `WeightAware`, projected as `OperatorMeta.WeightAware` (manifest `weight_aware`) and recorded on `processing.ExtensionRegistry.WeightAware` (keyed like `Streamable`). ONE declaration drives all three halves: `ResolveWeights` classes an extension slot off the snapshot (`ExtensionsSnapshot.WeightAwareness` — aware ⇒ applied; a non-aware aggregator skipped under the instance default and `PULSE_EXTENSION_NOT_WEIGHT_AWARE` under an explicit weight; a non-aware attribute or test refused under any weight), `processing.StampWeightsWith` stamps the resolved weight onto an aware slot's spec (aggregations, tests, post-tests, attributes), and the root adapter (`extensions_adapt.go`, `slotWeighting`) hands the operator a per-slot `weightedRecord` view whose `extend.Record.Weight()` reports the row's VALID weight — `*processing.Record.Weight()` itself always answers `(0, false)`, because slot weights differ within one request. Invalid-weight rows never reach an aware aggregator or row test (an attribute still gets them, `Weight()` false); the floor keys come from the orchestrator (`WeightFloor`). The probe constructs an aware factory with and without a weight (`details.weighted` on the second's failure). Contract: `.claude/reference/weighting.md` (Extension contract).
- **Native vector members (`extRecord`).** Every row handoff to an extend operator (`extensions_adapt.go`) wraps the engine row in the one-pointer `extRecord` view (zero-alloc; `weightedRecord` embeds it), whose `NumericValue` / `IsNull` route a native element member `f[k]` through `processing.Record.MemberValue` — the shared fill's null-member rule (a NaN element or a null vector is null) — so a vector-input operator reads a native vector like its scalar twin. The plain name is looked up first; built-ins keep the bare `*processing.Record`. A new handoff site that passes the bare row silently reads every element null (`TestExtRecord_EveryHandoffResolvesElements`).
- **Exact `u64` (`Uint64Value`, U34 #459).** `extend.Record.Uint64Value` is `processing.Record.Uint64Value` (plus element members via `MemberValue`; `featureRecordView` falls back to the saturating echo): a `u64` field's stored word, `(0, false)` exactly when `NumericValue` is. The reuse decoders write the word themselves (`SetExactU64At`); every MAP-decode site that builds an engine record — `stream.go` / `shard_iter.go` / `parallel_decode.go` projection without a plan, `lookup.go`, `filter_to_file.go` — installs an `internal/encoding.ExactU64Words` on its reader (`CaptureExactU64`, or `ReadRecordAtExact`) and `ApplyTo`s the record it builds; nil (zero cost) when the schema has no `u64`. A new map-decode site that skips it silently reads the float echo above 2^53 (`internal/service/exact_u64_fallback_test.go`, `TestExtendRecord_Uint64ValueExactEveryMode`).
- **Vector-input aggregators (`VectorInput` / `ArrayValued`, U27 E2-S5).** `AggregatorRegistration.VectorInput` makes the slot read `vector` / `fields` (exactly one; `field` refused) by the built-in vector rules; `ArrayValued` (requires `VectorInput`, no `MarginReducibility`, the value implements `extend.RichAggregator` returning a `[]float64` of the member count) makes it array-valued. Validated at `pulse.New` (`PULSE_EXTENSION_ARRAY_VALUED_MISMATCH` reasons `array_valued_without_vector_input` / `array_valued_margin_reducibility` / `missing_rich_interface`; a `labels` / `expand` `ParamMeta` on a vector input is `PULSE_EXTENSION_PARAM_INVALID` `reserved_vector_param`). Projected as `OperatorMeta.VectorInput` / `ArrayValued` (manifest `vector_input` / `array_valued`) and recorded on `processing.ExtensionRegistry.VectorAggregators`. ONE classifier, `vectors.AggregationKinds` (`IsVector` / `IsArrayValued`; route + extension declaration), built by `ExtensionRegistry.AggregationKinds()` at runtime and `internal/descriptor.aggregationKinds(inst, snap)` in predict, feeds every site: `vectors.ResolveAggregations` (field-ref step 11 and `processing.ResolveAggregationInputs`), `ArrayValuedCrosstabRefusal`, `AggregationExpands` / `AggregationOutputColumns`, `mergegate.StageArrayValuedRefusal`, the sort / overlay / Compose-overlay hosts, and the recommend binder (`opInfo.vectorInput`, from the manifest flag). The factory sees `vectors.AggregationSlotRewrite`'s copy: literal `Fields`, resolved `params.labels`, its own params kept. The adapter (`aggCore.ExpandedElements`, `aggRich`) checks the Rich shape (else `PROCESSING_INTERNAL`) and writes `expand` columns. Merge stays the embedder's `Merge` (not the blocked merge). `NonScalar` (U46 E4-S11; no probe — a declaration on a scalar operator only refuses conservatively) classes a Rich value that is not one number (label list, count map, struct): projected as `OperatorMeta.NonScalar` (manifest `non_scalar`) and recorded on `VectorAggregators` beside the vector flags; `AggregationKinds.IsNonScalar` (array-valued, the built-in `vectors.NonScalarAggregationTypes`, or the declaration) refuses it as an overlay's scored aggregation (`reason` `non_scalar`, `internal/descriptor/overlay_array_valued.go`) and in a chain stage feeding another (`mergegate.StageArrayValuedRefusal`). `EmitsInputValue` (U46 E4-S14; no probe, no validation) classes a value PICKED from the input column (a mode): projected as `OperatorMeta.EmitsInputValue` (manifest `emits_input_value`) and recorded on `VectorAggregators`; `AggregationKinds.IsCode(t, inputType)` (the built-in `vectors.EmitsInputValueAggregationTypes` — `AGG_MODE` — or the declaration, over a `vectors.IsCodeInputType` field: `categorical_*`, `packed_bool`) refuses it as an overlay's scored aggregation (`reason` `categorical_code`, plus `field` / `field_type`), judged against the schema the slot / stage executes over (Process: the field-ref walk's; Compose: `Service.requestInputSchema` / `composeSlotInputSchema`, opened lazily; chain: stage 0's gate schema, a later stage's synthesised one, checked at runtime once every stage ran). Gates: `TestExtensions_VectorAggregatorParity`, `_RefusalParity`, `_RegistrationRefusals`, `TestResolveAggregations_Extension`, `TestAggregationKinds_Extension`, `TestAggregationKinds_NonScalar`, `TestAggregationKinds_Code`, `TestExtensionAggregator_NonScalarScoredRefused`, `TestExtensionAggregator_CategoricalCodeScoredRefused`, `TestEmitsInputValueAggregationTypes_MatchRowValues`, `TestCatalog_VectorAggregatorDraftsFields`.
- **Count semantics and value state (`CountSemantic` / `ValueState`, U34 #216 / #230).** Two declarations on `AggregatorRegistration`, projected as `OperatorMeta.CountSemantic` / `ValueState` (manifest `count_semantic` / `value_state`, omitempty). `CountSemantic`: `isCountSemantic` (`internal/descriptor/return_precision.go`) adds the snapshot's declaration to `countSemanticAggregations` at all four `returnExactPaths` sites, so `return.precision` writes the slot exact; structurally refused on a `VectorInput` / `ArrayValued` registration (`PULSE_EXTENSION_PARAM_INVALID` `count_semantic_vector_input`; no numeric probe). `ValueState`: the `internal/descriptor/limits.go` aggregation loop counts it in `ValueStateAggregations` like `valueStateAggregation`. Both read the instance snapshot, so predict and the runtime agree.
- **Reference vectors (`ReferenceVectors`, U27 E3-S1).** `Extensions.ReferenceVectors map[string]types.ReferenceVectorTable{Description, Labels, Profiles}` — programmatic only, validated at `pulse.New` (`validateReferenceVectors`: `PULSE_EXTENSION_PARAM_INVALID` reasons `empty_name` / `no_labels` / `empty_label` / `duplicate_label` / `no_profiles` / `empty_key` / `length_mismatch` / `non_finite`), merged like the other named tables, copied read-only into `processing.ExtensionRegistry.ReferenceVectors` (`vectors.NewReferenceTables`) and projected as `ExtensionsSnapshot.ReferenceVectors` / manifest `extensions.reference_vectors` (labels + keys, never values) plus an ontology `table` node `reference/<name>`. Not a feature (no profile gate) and, like every named table, outside the feature-set digest. Read by the reserved `ref("table", key)` expr built-in. ONE rule set, `internal/vectors` (`reference.go`: `ReferenceTables.Table`, `ReferenceTable.Match` / `Profile` / `KeyUnknown`, `ReferenceMismatch`; `reference_expr.go`: `RefScope.CheckRefCall` / `AlignPair`, `ExprReferenceIssues`, `ReferenceIssues`), feeds predict (`predictReferences`, every issue) and the build (`refStaticRefusal` in `newExprProgram`, the first issue) — then `refPatcher` (an `expr.Patch` on every compile) gives each `ref()` a constant plan and, inside `dot` / `dist` / `cosine` (`exprenv.IsVectorPair`, through `PreservesLabels` transforms), the by-label permutation to the other side (a bound named vector or another `ref()`; a literal key folds to a constant `[]float64`). Match is by label, never position: `PULSE_VECTOR_REFERENCE_MISMATCH` (`labels_differ` / `unlabeled_partner`), `PULSE_VECTOR_REFERENCE_UNKNOWN` (`table_unknown` / `table_not_literal` / `key_unknown`). `ATTR_PROFILE_SIMILARITY` / `ATTR_VEC_DISTANCE` (U27 E3-S2) are built-ins, so an extension claiming either collides like any built-in name. The comparison operators' `reference` param reuses `Table` / `Match` / `Profile`.
- **Matrix operators and regression models.** `MatrixOps` (U30 E1) and `Regressions` (U53 E1-S1) live in the sibling slice `architecture/extension-models.md` (Extension models).
- **Registered populations (`Populations`, U30 E2-S4).** `Extensions.Populations map[string]Population{File []byte}` registers saved vector-fit population files (the encoded `*.pulse-population.json` document) by name; `Options.PopulationsDir` / `PULSE_POPULATIONS_DIR` merges a directory's population files under their stems (option beats env; non-recursive; selected by the population suffix). Decoded at `pulse.New` (`decodeRegisteredPopulations`: `PULSE_MODEL_FILE_INVALID` / `_VERSION_UNSUPPORTED` / blank-key `PULSE_MODEL_REF_INVALID`, each `details.registered`), FROZEN, dropped whole when a feature profile hides `capability:models`, and bound beneath EVERY request as vector fits (`model.RegisteredSet` → `Service.SetPopulations`; predict: `ExtensionsSnapshot.Populations` → `PopulationCatalog`). A request entry or Compose fit reusing a registered name is `PULSE_MODEL_NAME_COLLISION`; a name both programmatic and on disk is `PULSE_EXTENSION_DUPLICATE` (`dirCollision`, the label / range loaders' rule too). Manifest: `extensions.populations` (`descriptor.PopulationMeta` — name, operator, basis, labels, n; never the moments). Long form: `byte-layout.md` (Table-directory sidecar exclusion).
- **FieldInputs.** The projection extractor (`NeededFields`, internal) reads each registration's optional `FieldInputs`; absent widens the retained set to `*` — correct, but it forfeits the projection win.
- **DependsOn.** Every operator registration carries optional `DependsOn []string` — feature names, each a single-name AND group after the request-host group every extension operator gets. Validated against built-in features + registered extensions at EVERY `pulse.New` (`validateExtensionDependsOn`, right after the probe), profile or not. Extensions carry no `Since`. Contract: `.claude/reference/feature-profiles.md` (Dependency model).
- **Purpose.** Every registration carries optional `Purpose *descriptor.Purpose` (tests also `Interpretation`), validated at every `pulse.New` right after `DependsOn` (`validateExtensionGuidance`, `extensions_guidance.go`) through the built-in tier's `ValidatePurpose` with an instance resolver (built-ins + feature table + every registered extension); Interpretation is structure-only (nil `OutputResolver`). Failure is `PULSE_EXTENSION_PURPOSE_INVALID`. The snapshot carries `Purposes` / `Interpretations`; only intent IDs project (`OperatorMeta.Intents`, `withExtIntents`).
- **Skills.** `Extensions.Skills fs.FS` ships embedder skill files: atomic `op-<category>-<kebab>.md` for ONE registered extension operator (stem = `skills.OperatorStem(name)`) and topical `ext-<kebab>.md`. `validateExtensionUniverse` loads them last (`descx.LoadExtensionSkills`, `internal/descriptor/extension_skills.go`) against the snapshot of EVERY registration plus each operator's `DependsOn`, so validity never depends on the profile; the built-in pack's family rules (`internal/skills/families.go`: `RequiredSections`, `BodyBudget` — HARD for embedders), fence validation against the extended graph and the fence-coverage scanner (`skill_fence_coverage.go`, extension operators added to the scan list) apply. Failure: `PULSE_EXTENSION_SKILL_INVALID` (`details.reason`) or `PULSE_EXTENSION_SKILL_COLLISION` (built-in / virtual stem, or a stem two merged `Extensions` values ship — `mergeExtensions` layers them with `extFSStack`). `pulse.New` hands every validated skill to the snapshot (`ExtensionsSnapshot.Skills`, a skills-only instance gets an empty snapshot); `extendOntology` → `addExtensionSkills` adds the ones whose operator and `requires:` survive, and `Discovery` serves them (built-ins pass through byte-identically on a hide-nothing instance). Docs: `docs/src/internals/extension-points.md` (Embedder skills).
- **Examples.** `Extensions.Examples fs.FS` ships embedder request examples: top-level `.json` files, each a request body plus the built-in library's `_meta` block (`name`, `category`, `description`, `tags`, `operators`, optional `intents` / `capabilities`; `examples.Parse` in strict mode refuses any other `_meta` key). `validateExtensionUniverse` loads them after the skills (`descx.LoadExtensionExamples`, `internal/descriptor/extension_examples.go`) against the snapshot of EVERY registration, reusing the shipped library's rules rather than copies: canonical tags (`examples.IsCanonicalTag`), `IsIntent`, `exampleCapabilityProblems`, `examples.DeriveOperators` (operators-match-body) and `exampleEdgeCoverageProblems` (the `TestExamples_EdgeCoverage` rule, with extension operator names added to the operator set) — plus a STRICT decode of the body as its request root (`requests` → `types.ComposedRequest`, `stages` → `types.ChainRequest`, `fields` → `types.FacetRequest`, else `types.Request`; the shipped library is checked leniently) and every `_meta.operators` entry an operator node of the extended graph. Failure: `PULSE_EXTENSION_EXAMPLE_INVALID` (`details.reason`) or `PULSE_EXTENSION_EXAMPLE_COLLISION` (a built-in example name, or a name shipped twice — across merged `Extensions` values too, via `extFSStack`). `pulse.New` hands them to `ExtensionsSnapshot.Examples`; `extendOntology` → `addExtensionExamples` adds each one whose extension operators (`ExtensionExample.ExtOperators`: every extension operator it names anywhere) survive the profile, with the E1-S2 edges a built-in gets (`addExampleEdges`: `_meta` operators / intents / capabilities, the structural detector table, overlay kinds, description mentions — `ontologyBuilder.extOperators` lets a description route to an extension operator) plus built-in and embedder atomic skills' `## See` `tags=[…]` edges; `pruneOntology` then prunes it like a built-in. `Discovery` merges the survivors into one name-sorted library (`exampleLib`, searched by `examples.SearchIn` with the built-in ranking rules) behind `ExamplesSearch` / `Example` / `ExampleStats`, so the facade, `pulse_examples_*` and the manifest examples stats serve them; built-in records are unchanged. The CLI `pulse examples` leaf stays embedded-library only. Docs: `docs/src/internals/extension-points.md` (Embedder examples).
- **Naming and registration (relocated from CLAUDE.md "Extension Points" at U18 E1-S2).** `pulse.Options.Extensions` covers nine operator categories (matrix operators since U30, regressions since U53; synthetic-data distributions are NOT a category — the never-sampling `SynthDistributions` slot was removed in U34) plus expr functions, four named-table kinds (`LookupTables` / `ReferenceVectors` / `LabelTables` / `RangeTables`) and registered `Populations`, all registered at `pulse.New()` time and treated identically to built-ins by predict, manifest, MCP and runtime; operators are authored against `extend.Record` / `extend.Rows`, one factory type per category plus optional streaming siblings. Names must match `^(AGG|ATTR|FILTER|GROUP|WIN|FEAT|TEST|MAT|REG)_[A-Z][A-Z0-9]+_[A-Z](?:[A-Z0-9_]*[A-Z0-9])?$`; the namespaces `BUILTIN` / `STANDARD` / `CORE` / `PULSE` are reserved (`PULSE_EXTENSION_NAME_RESERVED`) and a collision with a built-in is rejected. Surface: root `extensions*.go`; runtime overlay `internal/processing/extensions.go`. Full recipe: `docs/src/internals/extension-points.md`.

- **Params validation (U44 E1-S2; values U53 E1-S3).** A registration's `Params []ParamMeta` is the slot's params allowlist, as a built-in's manifest Param list: an undeclared key is `PULSE_REQUEST_UNKNOWN_FIELD` (`details.path` `aggregations[0].params.<key>`, nearest-key suggestion); a value not of its `JSONType` (null included) or an omitted `Required` key is `PULSE_REQUEST_PARAM_INVALID` (`details.reason` `wrong_type` / `missing_required`, same path), and none or several members of an `ExactlyOneOf` group is reason `exactly_one_of` (path `<slot>.params`, `group` / `members` / `present`; decision #12). Order: unknown key, wrong type, missing required, one-of. All nine categories, predict ≡ runtime (`descx.ParamsRefusal` via `SlotRefusal`); `Default` stays the factory's (never injected). Engine keys: vector-input aggregator `labels` / `expand`, matrix `missing` / `max_drop_share`. A registration declaring NO params is unchecked (params reach the factory untouched; predict advises `PULSE_ADVISORY_EXTENSION_PARAMS_UNDECLARED`). Gates: `TestParamsRefusal_ExtensionOperators`, `TestExtensions_ParamsTypeAndRequiredEveryCategory`, `TestExtensions_ParamsExactlyOneOfEveryCategory`. **The `pulse.New` probe honours the same declaration** (`probeParams`, `extensions_probe_params.go`, one synthesizer for every constructed category — aggregator, attribute, grouper, feature, WeightAware test, matrix spec + `MatrixInput.Params`, regression; filterers and windows are never constructed): each `Required` param and the first member of each `ExactlyOneOf` group gets its `ParamMeta.Example` when declared (checked at `pulse.New` by the request value checker `descx.JSONValueType`: not of its `JSONType` or unmarshalable is `PULSE_EXTENSION_PARAM_INVALID` reason `example_type_mismatch`; projected as manifest `example` on `OperatorParamMeta` / `Param`), else a `JSONType` placeholder (number `1`, boolean `false`, object `{}`, string / array the probe's named fields — regression predictors, matrix members — else `""` / `[]`); every other param stays absent, and a registration needing none is probed with nil params as before. A factory refusing its placeholder is `PULSE_EXTENSION_FACTORY_PANIC` with `details.probe_params`. Gates: `TestExtensions_ProbeParamsSatisfyRequired`, `TestExtensions_ProbeParamsRefusalNamesThem`, `TestProbeParams_Placeholders`, `TestExtensions_ProbeParamsUseExample`, `TestExtensions_ProbeParamsEnumExample`, `TestExtensions_ParamExampleTypeChecked`.

- **Deliberate v1 gaps (U34 E3-S2; recipe: `docs/src/internals/extension-points.md` "Deliberate v1 gaps").** Named tables (`LookupTables` / `ReferenceVectors` / `LabelTables` / `RangeTables`) are not features and sit outside `feature_set_digest`; extension test `Interpretation` is structure-only (no output keys to probe); extensions are never zone-capable (an explicit `tz` is `PROCESSING_CONFIG`; an additive v1.x field is the only route); no synth-distribution category. Exact `u64` (above) needs no word at the chain-stage-row builder (`RecordsFromChainRows` — the synthesised stage schema is `categorical_u32` / `f64` only, any other type is `PROCESSING_INTERNAL`) or `synth_fidelity.go` (built-in statistics; no extension runs there). `FilterToFileWithRequest` builds extension / set / date-range filterers through the engine registry as `Process` does; its dedup hash carries referenced-table CONTENT, and a predicate running embedder code is never reused. `io.LateKeyRefuser` is the public opt-in for a keyed custom reader's late-key refusal.
