# Architecture — Extension models

Per-topic slice of the architecture reference (the matrix-operator, regression-model, overlay-kind, expression-derivative and post-fit extension categories). Index (rules + section map): `.claude/reference/architecture.md` — load it first, then only the slice(s) your change touches. The rules shared by every category (snapshot, naming, params validation, weights, components, `Validate`) are in `architecture/extension-surface.md`.

## Extension models

**Every category: the `Validate` hook.** Each registration may carry `Validate` (`extend.SpecValidator[<spec>]`). ONE wrapper, `internal/extspec.Refusal`, runs it on a shallow copy under `recover()`: a coded error is kept, anything else becomes `PULSE_EXTENSION_SPEC_REFUSED {category, type, slot[, name][, panic]}`. Predict (only when the request has no other error) and each factory adapter both call it, and the probe runs it first (`PULSE_EXTENSION_FACTORY_PANIC` stage `validate`). Gates: `TestExtensions_SpecValidate*`, `TestExtensions_RegressionValidate*`.

- **Matrix operators (`MatrixOps`).** `MAT_<NS>_<NAME>` operators authored against `extend.MatrixOperator` are FINALIZE-ONLY: the engine keeps accumulation (per-block `CoMoment`s, the 4096-row `MergeTree`, grouped buckets, missing modes, weights) and calls `Finalize(*extend.MatrixInput)` once per result with the merged, read-only `*linalg.CoMoment`, members / labels, raw params, weight kind, encoding and `Want*` part flags (plus `MatrixRows` on a `Streamable: false` registration). `BlockMerger` stays engine-only, so a pure `Finalize` inherits the bit contract without it.
  - *Registration* (`PULSE_EXTENSION_PARAM_INVALID` unless noted): nil `Factory` (`missing_factory`), empty `OutputKeys.Primary` (`missing_output_keys`), an empty / repeated output key (`invalid_output_key`); `ComponentSchema` is empty or complete (Mergeability without Keys → `PULSE_EXTENSION_MISSING_COMPONENT_SCHEMA`; Keys without Mergeability `missing_mergeability`; a floor key `reserved_component_key`). There is no `ComponentsFunc`: components ride `MatrixOutput.Components`. A `ParamMeta` naming the engine-owned `missing` / `max_drop_share` is `reserved_matrix_param`.
  - *Run-probe* — the one probe that feeds data: three `f64` members + a weight column, six listwise rows, every part wanted (re-probed weighted for a `WeightAware` registration). Panic / error → `PULSE_EXTENSION_FACTORY_PANIC` (`details.stage`); a `Streamable: true` Finalize that needs rows → `PULSE_EXTENSION_STREAMABLE_MISMATCH` `reads_rows`; no `Primary` or an undeclared output key → `PULSE_EXTENSION_MATRIX_OUTPUT_MISMATCH` (a declared key left unfilled is fine); a component key outside the schema → `PULSE_EXTENSION_COMPONENT_SCHEMA_MISMATCH`.
  - *Engine*: resolution goes through `vectors.ResolveMatricesWith` (engine params decoded and stripped, `Accepts` narrowing → `PULSE_VECTOR_MEMBER_TYPE`, the declared tier as `Streamable` / `Mergeable`); the finalizer gets a per-call `CoMoment.Clone()`. Weights: category `matrix` (a non-aware op is refused under any weight in force). Multiplicity opt-in through `MatrixOpRegistration.PValues`. Profiles: an implicit `capability:matrices` group. **Bit contract:** `TestExtensionMatrixInvariance_{Archive,Heavy}` holds an extension `MAT_*` bitwise across `DecodeWorkers` / `ShardWorkers`, grouped and weighted — scope in `execution-modes.md` (Blocked merge). Gates: `TestExtensionMatrix*`, `TestExtensions_Matrix*`.
- **Regression models (`Regressions`).** `REG_<NS>_<NAME>` against `extend.Regression`: `StreamingRegression` (`UpdateRow` / `Merge` / `Finalize`; `Streamable: true`) or `BufferedRegression` (`Fit`). The shared adapter (`internal/regadapt`) admits rows (listwise on target + predictors; a valid positive weight on an aware slot), owns `n_obs` / `sum_weights` / `n_eff`, maps `extend.RegressionOutput` onto `RegressionResult` (per-coefficient maps; absent = NaN) and verifies every output, probe and run alike (`PULSE_EXTENSION_REGRESSION_OUTPUT_MISMATCH`). A streaming model routed buffered is still fed through `UpdateRow`. Probe: eight synthetic rows; a form mismatch is `PULSE_EXTENSION_STREAMABLE_MISMATCH` (`not_streaming` / `missing_merge` / `not_buffered`); a data-dependent refusal is tolerated. Extension regressions are looked up ahead of the built-ins.
  - *Declare-or-refuse.* `descx.ExtensionRegressionSlotRefusal` is the ONE rule, called by predict and the adapter: it classifies EVERY `RegressionSpec` key (identity / accepted / weight class / a slot rule whose `declared` predicate reads a registration field such as `Vcov`, `Penalty`, `SupportsSelection`, `CovarianceTypes`, `Margins`, `Compare`, `Scorer`). An undeclared set slot is `PROCESSING_CONFIG {regression, slot[, key], name}`. Resample is an opt-out slot honoured unless `NoResample`; a modifier-bearing slot reuses the built-in replicate and selection loops. The manifest's slot params come from the same predicates. Gate: `TestExtensions_RegressionSharedSlotsRefused` reflects over the spec, so a new spec key must be classified.
  - *Intervals.* `conf_level` is accepted on every model; the adapter checks it with the built-in rule and attaches intervals (t on the reported df when present, else normal; normal on the replicate SE under resample; NaN SE → null bound). Parity with `REG_OLS` is pinned by the `regression` parity suite.
  - *Warnings.* `RegressionOutput.Warnings` (registered codes only) land on `RegressionResult.Warnings` and are lifted onto `Response.Warnings` (`details.regression` / `index`; a Compose fit's with `details.fit`); under Strict each warned slot fails with its first warning's code first. Gates: `TestExtensions_RegressionWarnings*`.
  - *Context.* A buffered model implementing `extend.ContextRegression` is fitted with the operation ctx, refits included (`TestExtensions_RegressionFitContext*`).
  - *Margins / Compare.* A registration declaring `Margins` (or `Compare`) has its fitted value implement `extend.MarginsRegression` (or `extend.CompareRegression`); the adapter calls it after the fit and verifies the shape (`missing_margins` / `margins_shape`, `missing_compare` / `compare_shape`); the probe re-fits to exercise it. Undeclared, a margins block is refused `requires: declared_margins` and a comparison `type_unsupported`. Gates: `TestExtensions_RegressionMargins*`, `TestExtensions_RegressionCompare*`.
  - *Multiplicity.* Gated by `RegressionRegistration.PValues`: declared, the default family is the result's p-valued coefficients; undeclared, a non-`none` method is `PULSE_MULTIPLICITY_INVALID`, predict counts none, and a finite p in the output is refused (`undeclared_p_value`).
  - *Self-description.* `Purpose` / `Interpretation` / `DependsOn` / `Accepts` / `FieldInputs` as every category. The Interpretation resolver is the figures a `RegressionOutput` can carry plus `outputs.<declared key>` — never structure-only. `Accepts` empty means `REG_OLS`'s analytics-numeric row; non-empty means exactly the list (`invalid_accepts` at `pulse.New`). A hidden model is dropped at `pulse.New`, so it reads never-registered everywhere. Predict `p_values` (a `PValues` model only): an explicit member list exact, else one per non-intercept predictor on `lower_bound`. Sweep reads the adapter's `ReportedFigures` to know which fit figures exist. Parity: the `regression` suite in `TestExtensions_BuiltinParity`, `TestExtensionRegressionInvariance_{Archive,Heavy}`.
  - **Row order.** `types.RegressionSpec.Order` (`{field, partition, gaps}`, `capability:regression_order`) is accepted on every model and every built-in. The no-execute leaf `internal/regorder` holds the spec rule (`PROCESSING_CONFIG {slot: "order", reason}`, called by build and predict), `order_required`, and the series rule (`PROCESSING_REGRESSION_ORDER`, reasons `duplicate` / `gap`, cadence = the smallest positive step over every series; the slot fails alone). The engine sorts each buffered slot's admitted rows by partition key then field (null field / partition dropped) before every buffered driver sees them, a holdout's train rows included; an ordered slot runs buffered. A model declares its need through the spec-only `RequiresOrder func(*types.RegressionSpec) bool` (a registration hook, so predict judges it without the factory). `REG_MMM_BAYES` reads `order.field` as its time field (`params.time` the deprecated alias; both spellings draw the same bits). Gates: `TestRegressionOrder_*`, `TestArrange_*`, `TestExtensionRegressionOrderRefusal`.
- **Overlay kinds (`Overlays`).** `OVERLAY_<NS>_<NAME>` kinds authored against `extend.OverlayHandler` — one func per host: `Matrix` (over a read-only crosstab view), `Series` (a grouped request, scored on its first aggregation unless the kind opts into the series params) and `Compose` (reference + targets, each exposing the one view its judged shape offers: `Matrix`, `Series` or `Scalar`). Handlers get a cloned spec and never a payload pointer. ONE declaration (`overlayhost.ExtensionDecl`: host shapes, payload `Shapes`, `Scopes`, `Refs`, `Validate`) feeds both the runtime registry and the snapshot.
  - *Request rules.* `overlayhost.ExtensionRequestRefusal` is the one Request.Overlays rule (slot, host shape, multi-measure host, Ref, Scope, Level / Within zero, then `Validate`), called by predict and runtime; an extension kind is never an unknown kind on the chain or facet hosts — it gets the built-in wrong-host wording. `overlayhost.ExtensionComposeRefusal` is the Compose twin; every shared Compose gate then holds the kind. Params ride the shared allowlist.
  - *Output.* `overlayhost.ExtensionOutputRefusal` holds every run's and the probe's output (`PULSE_EXTENSION_OVERLAY_OUTPUT_MISMATCH`: `undeclared_shape`, `shape_arm_mismatch`, `undeclared_parts`, `engine_owned`, `invalid_warning`, and the p-value reasons).
  - *Probe.* `Validate` and `ValidateCompose`, then each handler over a synthetic 2×2 crosstab, a 3-group series and a Compose reference + target (`PULSE_EXTENSION_FACTORY_PANIC` stage `validate` / `handler`).
  - *Declarations.* Extension overlays are buffered-only (`overlayhost.StreamReasons` — the one rule runtime routes on and predict reports). `WeightAware` classes the kind for weight resolution. `EmitsPValues` (requires `Inferential`, `p_values_not_inferential`) makes the slot a multiplicity member whose p-site is its payload shape. An `Inferential` registration needs an `Interpretation`. `ReadsCellCountsOnly` exempts a kind from the categorical-code cell rule (unset, a `Matrix` / `Compose` handler is refused `categorical_code` over a code cell). `HonoursField` / `HonoursPartitionBy` opt the kind into the built-ins' series `params.field` / `params.partition_by` rules (registration reasons `field_without_series_handler`, `partition_needs_series`, `reserved_series_param`; a Compose `partition_by` is `PULSE_OVERLAY_PARTITION_INVALID` `compose_host`). Gates: `TestExtensions_Overlay*`, `TestExtensionOutputRefusal*`, `TestExtensionRequestRefusal_Order`, `TestExtensionComposeRefusal_Order`.
- **Regression scoring, probe params, shared options.** `RegressionRegistration.Scorer` (built from `extend.FittedRegression` alone, so a fit and its reloaded model file score identically) feeds `ATTR_REG_PREDICT` and `save` (model file version 3 carrying `outputs`; reloading without the registered type is `PULSE_MODEL_REGRESSION_UNREGISTERED`; no Scorer is `no_scorer`). Built-in-only knobs (`REG_OLS` `unpenalized` / `bounds`, `REG_BAYES_LINEAR` vector `prior_precision`) are classified slots a registered model never honours. Recipe: `docs/src/internals/adding-regression.md`; worked examples: `REG_TESTNLS_EXP` (`internal/integration/extensions_testnls_exp_test.go`) and the OLS clone.
- **Expression-function derivatives (`ExprFunction.Derivative`).** An `ExprFunctions` entry's optional `Derivative func(args ...any) ([]float64, error)` returns ∂Fn/∂argᵢ at the call's arguments (index-aligned), read ONLY by a Compose optimize block's forward-mode gradient. Rule presence is keyed on the name list of differentiable functions (runtime from the registry, predict from manifest `differentiable`), so predict's `PULSE_ADVISORY_OPTIMIZE_GRADIENT_FALLBACK` and the runtime agree; a function without a hook has no rule, and the block falls back to finite differences whole. Registration refusal: `PULSE_EXTENSION_PARAM_INVALID` `details.field: Derivative` (not a function, no numeric argument, or no result). A hook error or wrong partial count at run time is `PROCESSING_RUNTIME` naming the function — never swallowed by the expression VM. Tests: `TestOptimize_ExprFunctionDerivative`, `TestOptimize_GradientFallbackParity`, `TestBoundRules*`.
- **Post-fit operators (`PostFits`).** `POSTFIT_<NS>_<NAME>` against `extend.PostFitFunc` — an extension-only category, run by a `ComposedRequest.PostFit` entry `{label, type, fits, params}` in the Compose phase order slots/sweep → fits → optimize → **post-fit** → compare. When an entry is declared, every slot the result pre-phase did not run runs first. The operator reads no record (`TestPostFitInput_ReachesNoRecord`): it gets copies of the named fits, the `result()` reader, the optimize solutions and its params. Request rules are ONE no-execute leaf, `internal/postfit.Check` (`PULSE_POSTFIT_INVALID`, then declared params; `TestPostFit_ImportBoundary`), which predict replays from the snapshot (`TestPostFit_PredictMatchesRuntime`). Each output is held to the declared `Outputs` schema (fatal `PULSE_EXTENSION_POSTFIT_OUTPUT_MISMATCH`); an operator error or a named failed fit fails the entry alone (`PULSE_SLOT_FAILED` slot_kind `post_fit`; uncoded → `PULSE_POSTFIT_FAILED`); a panic is `PROCESSING_PANIC` `details.op` `compose_post_fit`. Results land in the additive `ComposedResponse.PostFit` root (NaN → null; `format_version` stays `"1.1"`), outside the Compose `return`. The keys ride `capability:compose_post_fit` (hard edge `capability:compose_fits`), which hosts every POSTFIT_* operator. No observe enum: post-fit is a Compose phase, not an operation kind.
