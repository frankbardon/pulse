# Architecture — Extension models

Per-topic slice of the architecture reference (Extension models: the matrix-operator and regression-model extension categories, split out of `architecture/extension-surface.md` at U53 E1-S3). Index (preamble + section map): `.claude/reference/architecture.md` — load it first, then only the slice(s) your change touches. The rules shared by every category (snapshot, naming, params validation, weights, components) stay in `architecture/extension-surface.md`.

## Extension models

- **Matrix operators (`MatrixOps`, U30 E1).** `Extensions.MatrixOps []MatrixOpRegistration` registers `MAT_<NS>_<NAME>` operators authored against `extend.MatrixOperator` — FINALIZE-ONLY: the engine keeps accumulation (per-block `CoMoment`s, the 4096-row `MergeTree`, grouped buckets, missing modes, weights) and calls `Finalize(*extend.MatrixInput)` once per result with the merged, read-only `*linalg.CoMoment` (raw per-pair co-moment via the additive `CoMoment.PairM2`), members / labels, raw params, weight kind, the encoding and the `Want*` part flags (plus `MatrixRows` on a `Streamable:false` registration); `MatrixInput.Square` / `Rect` render in the slot's encoding, mirroring the engine's renderers. `BlockMerger` stays engine-only — a pure Finalize inherits the bit contract without it; `extend.MergeableAggregator.Merge` is within-ulp and never reaches a matrix. Registration validation (`validateMatrixOps`, after the shared naming / params pass with `categoryMatrix`, prefix `MAT`, collisions against `builtinMatrixNames()` = `types.AllMatrixTypes()`, regex-shaped built-ins such as `MAT_PARTIAL_CORRELATION` included): nil `Factory` (`missing_factory`), empty `OutputKeys.Primary` (`missing_output_keys`), an empty / repeated auxiliary / vectors / scalars key (`invalid_output_key`) — all `PULSE_EXTENSION_PARAM_INVALID`; `ComponentSchema` is empty or complete (Mergeability without Keys → `PULSE_EXTENSION_MISSING_COMPONENT_SCHEMA`; Keys without Mergeability `missing_mergeability`, an empty / repeated key `invalid_component_key`, a matrix-floor or weighted-floor key `reserved_component_key`, each `PULSE_EXTENSION_PARAM_INVALID`) — there is no `ComponentsFunc`: components ride `MatrixOutput.Components`. `looksLikeExtensionName` (feature universe) accepts an embedder `MAT_*` name; `mergeExtensions` / `hasAnyRegistrations` carry the slice. A present `Purpose` is validated like every category's (`PULSE_EXTENSION_PURPOSE_INVALID`, category `matrix`). **Run-probe** (`probeMatrixOps`, `extensions_probe_matrix.go`) — the one probe that feeds data: the factory is built against a synthetic schema of three `f64` members + a weight column, and `Finalize` runs under `recover()` over a six-row listwise `CoMoment` with every part wanted (rows only on `Streamable:false`; a `WeightAware` registration is probed again weighted, `details.weighted`): factory / Finalize panic or error → `PULSE_EXTENSION_FACTORY_PANIC` (`details.stage`); a `Streamable:true` Finalize that fails without `Rows` but passes with them → `PULSE_EXTENSION_STREAMABLE_MISMATCH` `reads_rows`; no `Primary` (`missing_primary`) or an auxiliary / vectors / scalars key `OutputKeys` does not declare (`undeclared_output_key`; a declared key left unfilled is fine — `OutputKeys` lists what the operator MAY fill) → `PULSE_EXTENSION_MATRIX_OUTPUT_MISMATCH`; a `Components` key outside `ComponentSchema.Keys` (no floor key tolerated) → `PULSE_EXTENSION_COMPONENT_SCHEMA_MISMATCH`. **Engine wiring (E1-S3).** `extensions_matrix_runtime.go` lifts the registration onto `processing.ExtensionRegistry.MatrixOps` (`processing.MatrixOp`: factory, declared tier, `Accepts`, auxiliary keys) and onto the snapshot (`ExtensionsSnapshot.MatrixOps` as `OperatorMeta` + `MatrixDetails`); resolution is `vectors.ResolveMatricesWith` (`MatrixResolve.Extension`, runtime `matrixExtension` / predict `matrixExtensionFor`): opaque params with the engine-owned `missing` / `max_drop_share` decoded and STRIPPED (a `ParamMeta` naming one is refused, `reserved_matrix_param`), `Accepts` narrowing (`PULSE_VECTOR_MEMBER_TYPE`), the declared tier as `Streamable` / `Mergeable`. The finalizer lookup is built-in first, then the slot's extension finalizer (`matrixSlot.finalize`), handed a per-call `CoMoment.Clone()` and wrapped so `OutputKeys` / `ComponentSchema` bind on every run. Instance-routed tier at every gate: `ExtensionRegistry.MatrixSpecStreamable` (`canStream`), `mergegate.Extensions.Matrix` (both adapters), predict `matrixSpecStreamable`. Weights: snapshot category `matrix` in `WeightAwareness` (a non-aware op is refused under any weight in force), `StampWeightsWith` stamps an aware one. Multiplicity opt-in through `MatrixOpRegistration.PValues` → `ResolvedMultiplicity.PValueKey`. Profiles: `withoutHiddenExtensions`, the feature universe (an implicit `capability:matrices` group) and the ontology (`requires_capability` edge). Gates: `TestExtensionMatrix_*` (root `extensions_matrix_engine_test.go`), `TestMatrixExtension_CanStream`. **Bit contract (E1-S4):** `TestExtensionMatrixInvariance_{Archive,Heavy}` (root `extensions_matrix_invariance_test.go`, public registration only) holds an extension `MAT_*` bitwise across `DecodeWorkers` / `ShardWorkers`, grouped and weighted, both tiers — scope in `execution-modes.md` (Blocked merge); falsified by `TestExtensionMatrixInvariance_ComparatorBites`. Gates: `TestExtensions_MatrixOpRegistrationRefusals`, `TestExtensions_MatrixProbeRefusals`, `TestExtensions_MatrixProbeInput`, `TestExtensions_MatrixPurposeValidated`, `TestExtensionNameRegex_Matrix`, `TestLooksLikeExtensionName_Matrix`, `TestMergeExtensions_MatrixOps`, `TestMatrixInputSquare`, `TestCoMomentPairM2MatchesCov`.

- **Expression-function derivatives (`ExprFunction.Derivative`, U71 E1-S2).** An `ExprFunctions` entry's optional `Derivative func(args ...any) ([]float64, error)` is ∂Fn/∂argᵢ at the call's arguments (one partial per argument, index-aligned; a non-numeric argument's never read), read ONLY by a Compose optimize block's forward-mode gradient: `extensions_runtime.go` forwards it onto `processing.ExprFunction` → `exprenv.NamedFunc.Derivative`, and `optgrad.BoundRules(bound, differentiable)` turns it into the function's rule. Rule presence is keyed on the NAME list `optblock.Env.Differentiable` — the runtime's `Service.differentiableFunctionNames`, predict's `ExprFunctionMeta.Differentiable` (manifest `differentiable`, from the snapshot) — so predict's `PULSE_ADVISORY_OPTIMIZE_GRADIENT_FALLBACK` and the runtime agree; a function without a hook has no rule, even over a fit reader it shadows, and the block falls back to FD whole. Validation (`validateExprDerivative`, `PULSE_EXTENSION_PARAM_INVALID` `details.field` `Derivative`): an `Fn` that is not a function, takes no argument that can be a number, or returns none. A hook error or wrong partial count at run time is `PROCESSING_RUNTIME` naming the function (never `optgrad.ErrEval`, which would let the VM's clean value hide it). Tests: `TestOptimize_ExprFunctionDerivative`, `TestOptimize_GradientFallbackParity` (root), `TestBoundRules*` (`internal/optgrad`).
- **Post-fit operators (`PostFits`, U71 E3-S1).** `Extensions.PostFits []PostFitRegistration` registers `POSTFIT_<NS>_<NAME>` against `extend.PostFitFunc` — an extension-only category (no built-in), run by a `ComposedRequest.PostFit` entry `{label, type, fits, params}` in the Compose post-fit phase: slots/sweep → fits → optimize → **post-fit** → compare. When an entry is declared, every slot the result pre-phase did not run runs before the phase (the operator's `Result` may read any slot); serial and `ComposeParallel` share `runComposePostFit`.
