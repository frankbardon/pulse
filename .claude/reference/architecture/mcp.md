# Architecture — MCP layer split

Per-topic slice of the architecture reference (MCP layer split, the prompts and the MCP `return` default; split out of `architecture/packages.md` at bayesian-mmm E1-S1). Index (preamble + section map): `.claude/reference/architecture.md` — load it first, then only the slice(s) your change touches.

## MCP layer split

`internal/mcp/` is the SDK-free core (typed In/Out structs, reflected JSON schemas — a `json.RawMessage` field reflects as any-JSON, never the reflector's `[]byte` array, `TestSchemasNoRawMessageByteArray` — typed handlers over `*pulse.Pulse`, strict-decode, bind classification — gated by `TestMCPCore_NoSDKImport`). `mcp/gosdk/` is the ONLY package importing the go-sdk; its `Register(server, p, cfg)` mounts the core catalog onto a caller-supplied server, and `pulse mcp` builds a bare server and calls it. `mcp/gosdk` reaches the instance's extension snapshot through `internal/facadebridge`, never through an exported engine handle. `internal/mcp/toolmeta/` holds the leaf metadata both `internal/descriptor` and the core import. One tool per facade method plus skills/examples/errors/import/label tools — **the manifest is the source-of-truth count, never hardcode it** — and two resource schemes (`pulse://`, `pulse-skill://`); `pulse://schema` serves the payload JSON Schema as a RESOURCE, not a tool. Cohort resources are ENUMERATED by a startup walk of the data root, suppressible with `gosdk.Config.DisableCohortScan` / `mcpserve.Options.DisableCohortScan` / `pulse mcp --no-cohort-scan` — the `pulse://` template stays mounted, so a disabled scan costs enumeration only, never readability. Payload tools take the structured request at top level, outputs are typed-wrapped, coded errors surface as `{code, message, details}`. **Feature profiles at the MCP layer:** `mcpserve.NewPulse` is the ONLY reader of `PULSE_FEATURE_PROFILE` (and of `mcpserve.Options.FeatureProfileFile`, flag `pulse mcp --feature-profile`) — an OS path read with `os.ReadFile`, parsed by `pulse.ParseFeatureProfile`, handed to `pulse.New` as `Options.FeatureProfile`; `pulse.New` itself never reads the env. `gosdk.Register` ORs a profile's `behaviour.disable_cohort_scan` into `Config.DisableCohortScan` via the `facadebridge.CohortScanDisabled` hook, and `mcpserve.Describe` reports the effective value plus the profile label through the public `p.FeatureProfile()` accessor (a copy). Contract: `.claude/reference/feature-profiles.md`.

**Prompts** (relocated from CLAUDE.md "Architecture"): `pulse-bootstrap`, `pulse-author-request` (routes a question to a mounted per-intent prompt or tool) and one `pulse-<intent>` per analytic intent (`TestSkillsCoverAllMCPPrompts`). Like tools and resources they are registered per instance, so `gosdk.RegisteredPrompts()` stays the GLOBAL list.

**MCP `return` default (U18 E5-S1).** The request-carrying tools (`pulse_process`, `pulse_predict`, every `pulse_compose` slot, every `pulse_process_chain` stage) shape a request WITHOUT its own `return` block by a host default injected at strict decode in the core (`internal/mcp/return_default.go`, `core.Config.DefaultReturn`). Precedence: request `return` > `gosdk.Config.DefaultReturn` / `mcpserve.Options.DefaultReturn` / `pulse mcp --return` (a `types.ReturnPreset`) > the instance default (`pulse.Options.DefaultReturn`, else the feature profile's `return` — nothing injected, the engine resolves it) > built-in `standard`. `full` on an instance with no default injects nothing, so the output is the library's byte for byte; the library default stays `full`. The default rides as the request's own block, so the engine `DisableComponents` gate still wins (`descx.EffectiveReturn`); only a request `disable_components: false` re-opens it. `Register` refuses an unknown preset (`PULSE_RETURN_INVALID`, via `core.Config.Validate`).
