# Predict / Inspect — Advisories, import predict

Per-topic slice of the predict-inspect reference (Advisories, import predict). Index: `.claude/reference/predict-inspect.md` — load it first, then only the slice(s) your change touches. Skill: `skills/predict-advisories.md`.

## Advisories

**`PredictResult.Advisories`** (`advisories`, `omitempty`, `[]descriptor.Advisory {code, message, details}`) carries coded, non-blocking notes that the chosen analysis may not fit the data — a separate slot from the envelope's warnings, because an analysis choice is not a data or engine problem and agents filter them independently.

- **Never a warning, never escalated, never a change to execution.** No advisory is appended to `env.Warnings` / `env.Errors`, so Strict cannot promote one and `Valid` never moves; the runtime never reads advisories (`TestAdvisories_NeverChangeExecution`, `TestPredict_StrictNeverEscalatesAdvisories`).
- **On the result itself.** `Pulse.Predict` and MCP `pulse_predict` return the `PredictResult`, so the slot lives there, not on the envelope. `PredictEnvelope` / `PredictBytes` / `pulse api predict --json` carry it in `data.advisories`; the text leaf prints `Advisory [CODE]: message`.
- **Result-borne codes.** A few codes also ride a fitted `RegressionResult.Advisories` (attached in the service post-hook `attachRegressionAdvisories` from the SAME predicate and wording as predict): `PULSE_ADVISORY_PENALIZED_INFERENCE_UNDEFINED`, and the result-only `PULSE_ADVISORY_CONSTRAINT_ACTIVE` and `PULSE_ADVISORY_MMM_ADSTOCK_ILL_CONDITIONED` (data-dependent, so no predict rule raises them). Suppression removes the note, never a figure.
- **Predicates** live in `internal/descriptor/predict_advisories*.go` (`computeAdvisories`, run last on the defaults-resolved request over the schema it executes over), under the predict import ban. **Trigger principle: authoritative metadata only** — the request, the schema's dictionaries and nullability, figures predict already computed (`p_values`, record counts), the SPSS sidecar's measure levels and weight — never field-name or value-shape heuristics. Computed whether or not the request is valid. Where the runtime has a predicate for the same condition, the advisory calls it (one rule, never a copy).
- **Adding a code:** a `PULSE_ADVISORY_*` entry in `errors/codes.go` + `codeMetadata` + an `error_owners.go` owner + an entry in `advisoryCodes` (rule order; `TestAdvisoryCodesRegistered`) + a section in `skills/predict-advisories.md`. `details.suggested` is a replacement operator name or a request patch, never a rewritten request. Messages pass the prose lint (`TestAdvisoryMessagesPassProseLint`).
- **Profile-scrubbed.** An operator named in a message or `details.suggested` is one the instance offers; a hidden operator routes as never-registered and fires nothing; hidden `capability:multiplicity` withholds `p_values`, so MANY_TESTS never fires.
- **Suppression.** `Options.SuppressAdvisories []string`, validated at `pulse.New` against the whole registry (unknown → `PULSE_SUPPRESS_ADVISORY_UNKNOWN`, `details {code, valid}`; a code a profile can never fire is accepted), installed on the instance (not in the feature-set digest). No per-request or CLI knob.
- **Payload schema.** `descriptor.Advisory` is an ungated payload-schema root (`PredictResult` itself is not payload-reachable).

**The codes.** The registry is `advisoryCodes`; this list states each trigger and the reason for any non-obvious threshold.

- `PULSE_ADVISORY_TWO_GROUP_TEST_MANY_GROUPS` — `TEST_T` / `TEST_WELCH` whose `split_by` is a categorical with more than two dictionary entries (`packed_bool` never). `suggested`: `TEST_ANOVA_WELCH`, else `TEST_ANOVA_F`.
- `PULSE_ADVISORY_MANY_TESTS` — `p_values.uncorrected >= MultiplicityTriggerThreshold` (10) and no multiplicity block resolves (`method: none` included). Message says "at least N" on a `lower_bound` basis, "an estimated N" on `dictionary`. A penalized regression whose inference is undefined counts none of its p-values (the runtime reports them null and leaves them out of `m`). `suggested: {"multiplicity": {"method": "holm"}}`.
- `PULSE_ADVISORY_CATEGORICAL_AS_NUMERIC` — a field the sidecar records `nominal` that is a NUMERIC cohort field under a mean-family aggregator (`AGG_SUM` deliberately not) or a parametric test. `suggested`: `AGG_FREQUENCY` / `TEST_CHISQ`.
- `PULSE_ADVISORY_ORDINAL_PARAMETRIC` — the same test slots on a numeric field the sidecar records `ordinal`. `suggested`: the routed test's first rank-based `Purpose.NotFor` alternative the instance offers.
- `PULSE_ADVISORY_WEIGHT_AVAILABLE_UNUSED` — fires exactly when `PredictResult.SuggestedWeight` is set, inheriting all its silences (`predict-inspect/inspect-and-roots.md`, Suggested weight).
- `PULSE_ADVISORY_EXTRA_PASS` — an `ATTR_FORMULA` calling `total(expr)` (`internal/totalcall.Contains`, the runtime's two-pass predicate; predict's `Streamable` asks the same). `added_scans` = 1, a per-formula upper bound.
- `PULSE_ADVISORY_FORMULA_NULLABLE_RESULT` — an `ATTR_FORMULA` whose RESULT can be nil (`exprident.NullableResult` over the schema's `Nullable` flags; nil-guards in ternaries / `&&` / `||` / `??` respected). The runtime writes a nil result as a null. Known silent limit: names outside the schema and function results are not judged. Parity: `TestFormulaNullableResult_AdvisoryMatchesRuntime` (fired ⇔ `n_null > 0`).
- `PULSE_ADVISORY_FORMULA_NULLABLE_OPERAND` — an `ATTR_FORMULA` feeding a nullable input, unguarded, to an operand that rejects nil (`exprident.NullableOperands`; the nil-rejecting built-in table `nilRejecting` is pinned by running every built-in, `TestNilRejectingFunctions_MatchRunning`). ATTR_FORMULA is the only row-level site where a nil operand ABORTS the run; filters, `total()`, holdouts and `WIN_FORMULA` drop or null the row and never advise. Nullable inputs: schema `Nullable` flags plus earlier attribute labels whose output can be null (`attributeNullOutputs`, `TestAttributeNullOutputs_Complete`; extensions via `extend.NullableAttribute`). Pin: `TestNullableOperands_FiresIffNullRowAborts`.
- `PULSE_ADVISORY_SERIES_AXIS_NOT_DATE` — an ordered series overlay (`seriespartition.Ordered`) on a series host of ≥ 2 groupers, with no explicit `partition_by`, whose LAST grouper (the implicit series axis) is not date-family. An explicit list (even `[]`) states the order and never fires. Compose: a per-partition Compose-host kind draws the same advisory over its first target slot through the same host rule (`details.request`, `target`).
- `PULSE_ADVISORY_EXTENSION_PARAMS_UNDECLARED` — a slot naming an extension operator that declares NO params while the slot carries a non-empty `params` (keys pass to the embedder's factory unchecked). A declaring extension refuses unknown keys instead.
- `PULSE_ADVISORY_JACKKNIFE_COST` — a leave-one-out jackknife regression when the cohort record count is ≥ `regresample.LeaveOneOutCostRows` (10,000). Reason: LOO is n refits over n rows, quadratic (measured ~35 s at 10,000 rows for a two-predictor GLM, against well under a second for a 50-group jackknife). The count is pre-filter, an upper bound. `suggested: {"jackknife_groups": 50}`.
- `PULSE_ADVISORY_PENALIZED_INFERENCE_UNDEFINED` — a regression with `penalty` `l1` / `elasticnet` and no `resample` (`regpenalty.InferenceUndefined`, the engines' predicate). The data pick the active set, so no analytic sampling distribution exists: standard errors, p-values and intervals are `null` on every key and `vcov` is refused. `suggested: {"resample": "bootstrap"}`. Parity: `TestRegPenalty_InferenceAdvisoryPredictRuntimeParity`.
- `PULSE_ADVISORY_CONSTRAINT_ACTIVE` — result-only: a `bounds.nonnegative` constraint binds (`regbounds.InferenceUndefined`), so inference figures and vcov entries are `null`; a non-binding fit is plain OLS byte for byte.
- `PULSE_ADVISORY_MMM_ADSTOCK_ILL_CONDITIONED` — result-only: a `REG_MMM_HILL` fit with `params.adstock` whose `outputs.condition_number` (1-norm, of the free-parameter correlation matrix) exceeds `model.MMMConditionThreshold` (1e6) or is undefined. Reason: well-identified fits measure ~7e3, degenerate channels 1e13+. Standard errors are KEPT, never nulled; the advisory flags them.
- `PULSE_ADVISORY_COMPOSE_FAMILIES_SPLIT` — Compose only: ≥ 2 slots emit p-values, their corrected p-values join ≥ 2 distinct families other than `compose`, and the slots emit ≥ the threshold in total. `family: "compose"` everywhere silences it.
- `PULSE_ADVISORY_OPTIMIZE_GRADIENT_FALLBACK` — Compose only: an `optimize` block with the default `analytic` gradient whose objective or a constraint uses a function or construct without an `internal/optgrad` derivative rule, so the solver differentiates the WHOLE block by finite differences. The judgement is `optblock`'s, shared with the runtime, which echoes `gradient` / `gradient_fallback` on the result (`TestOptimize_GradientFallbackParity`).

**Sidecar wiring.** The facade's one sidecar read (root `weight_suggest.go`) hands down the suggested weight variable and the measure levels; a missing, malformed, STALE or anchor-path sidecar yields neither, so non-SPSS cohorts and `PredictBytes` never fire the three sidecar codes. Measure levels are judged against the COHORT schema.

**Roots.** Request predict runs every rule.

- **Facet predict** adds `PValues` + `Advisories` (one p-value per inferential facet-host overlay); only MANY_TESTS can fire.
- **Compose predict** adds `PValues`, `Advisories` and `Slots` (`[]descriptor.ComposeSlotPredict {request, label, streamable, streamable_reasons, p_values, families, …}`). Each slot's figures come from Process predict's own calls over the slot's defaulted request, schema and sidecar; `families` are read off the SAME p-value count, so they never drift, and family `id` spells the runtime fold's key (`compose`, `requests[i]#request`, `requests[i].<slot>#<family>`). Slot advisories carry `details.request` and a `requests[i].` prefix. Compose-host overlays add a MANY_TESTS on a `lower_bound` basis. A refused batch multiplicity withholds every count.
- **Chain** carries no advisories (`TestChainValidationResult_CarriesNoAdvisories`).

## Import predict is not descriptor predict

`io.ImportJob.Predict` (`pulse import predict`) is the ONLY predict that may read source rows, and none of the rules above bind it — it lives in `internal/io/`, not `internal/descriptor/`. Its measured pass (declared `Groups`, `ElideConstants`, or `SuggestGroups`) converts every row through the converter `Run` uses and derives group figures through `encoding.DedupGate` / `AssessGroup` / `PlanConstantElisionFor`, so import predict, `ImportReport.Groups` and inspect report the same numbers (`TestImportPredict_DeclaredGroupsMatchImport`). Candidate detection nominates over a bounded window and confirms on the full pass; it suggests, never declares. Without those knobs predict keeps its plain row-count pass.
