## Advisories

**`PredictResult.Advisories`** (`advisories`, additive `omitempty`, `[]descriptor.Advisory {code, message, details}`) carries coded, non-blocking notes that the chosen analysis may not fit the data — a separate slot from the envelope's warnings, because an analysis choice is not a data or engine problem and agents filter them independently. Rules (U22 E1):

- **Never a warning, never escalated.** No advisory is ever appended to `env.Warnings` or `env.Errors`, so `PredictOptions.Strict` / `Options.Strict` / `--strict` cannot promote one and `Valid` never moves. **Never a change to execution** — the runtime never reads advisories.
- **On the result itself.** `Pulse.Predict` keeps only `env.Data`, and MCP `pulse_predict` returns that `PredictResult` (embedded in `PredictOut`), which is why the slot is on `PredictResult`, not the envelope. `PredictBytes` / `pulse api predict --json` carry it in `data.advisories`; the text leaf prints one `Advisory [CODE]: message` line each.
- **Predicates** live in `internal/descriptor/predict_advisories.go` (`computeAdvisories`, called last in `predictSingle` on the defaults-resolved request over the schema it executes over), under the predict import ban. Trigger principle: authoritative metadata only — the request, the schema's dictionaries, figures predict already computed (`p_values`), the SPSS metadata sidecar's measure levels and weight variable — never field-name or value-shape heuristics. Computed whether or not the request is valid.
- **Codes** are `PULSE_ADVISORY_*` entries in `errors/codes.go` (`allCodes`) + `codeMetadata` (Message + text Fixup) + an `error_owners.go` owner, AND an entry in `advisoryCodes` (rule order; `TestAdvisoryCodesRegistered` keeps the registry and the catalog equal). `details.suggested` is a replacement operator name or a request patch, never a rewritten request; there is no new `FixupAction`.
  - `PULSE_ADVISORY_TWO_GROUP_TEST_MANY_GROUPS` (owners `TEST_T`, `TEST_WELCH`): a `TEST_T` / `TEST_WELCH` slot (tests, then post-tests) whose `split_by` is a categorical field with more than two dictionary entries; exactly two and `packed_bool` never fire. `split_by` admits no grouper, so the dictionary count is the only computable figure. `details {slot, operator, field, split_by, groups, suggested}`, `suggested` = `TEST_ANOVA_WELCH`, else `TEST_ANOVA_F`, else absent.
  - `PULSE_ADVISORY_MANY_TESTS` (owner `capability:multiplicity`): `p_values.uncorrected >= MultiplicityTriggerThreshold` and `ResolveMultiplicity` returned a nil plan — nothing (request, slot, `Options.DefaultMultiplicity`) names a block, `method: none` included. The message says "at least N" on a `lower_bound` basis and "an estimated N" on `dictionary`. `details {total, uncorrected, basis, threshold, suggested: {"multiplicity": {"method": "holm"}}}`.
  - `PULSE_ADVISORY_CATEGORICAL_AS_NUMERIC` (owners: the mean-family aggregators + parametric tests, `advisoryQuantityOperators`): a field the sidecar records `nominal` that is a NUMERIC column of the cohort schema (`IsNumeric` or `u4`; a labelled SPSS numeric imports `categorical_*` and never fires) under a mean-family aggregator (`meanFamilyAggregators`: `AGG_AVERAGE`, `AGG_WEIGHTED_MEAN`, `AGG_STDDEV`, `AGG_VARIANCE`, `AGG_ZSCORE`, `AGG_SKEWNESS`, `AGG_KURTOSIS`, `AGG_CI_LOWER` / `_UPPER`, `AGG_WELFORD`; `AGG_SUM` deliberately not) in `aggregations[i]`, `crosstab.cell` or `crosstab.margin_aggregations[i]`, or a parametric test (`parametricTests`: `TEST_T`, `TEST_WELCH`, `TEST_Z_TWO_SAMPLE`, `TEST_PAIRED_T`, `TEST_ANOVA_F`, `TEST_ANOVA_WELCH`, `TEST_ANOVA_RM`, `TEST_PEARSON_R`) on `field` or `field2`. One per (slot, field). `details {slot, operator, field, measure, suggested}`, `suggested` = `AGG_FREQUENCY` (aggregator) / `TEST_CHISQ` (test) when offered.
  - `PULSE_ADVISORY_ORDINAL_PARAMETRIC` (owners: the parametric tests): the same test slots on a numeric field the sidecar records `ordinal`. `suggested` = the first `Purpose.NotFor` `Use` of the routed test that is rank-based (`rankBasedTests`) and offered — `TEST_MANN_WHITNEY_U` / `TEST_WILCOXON_SR` / `TEST_KRUSKAL_WALLIS` / `TEST_SPEARMAN_R`; absent for `TEST_Z_TWO_SAMPLE` / `TEST_ANOVA_RM`, whose NotFor names none. Aggregators never fire it.
  - `PULSE_ADVISORY_WEIGHT_AVAILABLE_UNUSED` (owner `capability:weighting`): fires exactly when `PredictResult.SuggestedWeight` is set, so it inherits every silence of that echo (see "Suggested weight"). `details {field, source, suggested: {"weight": {"field": F}}}`.
  - `PULSE_ADVISORY_EXTRA_PASS` (owner `ATTR_FORMULA`): one per `ATTR_FORMULA` the instance offers whose expression calls `total(expr)` (`internal/totalcall.Contains` — the runtime's two-pass predicate), in declared order. `details {slot, operator, label, totals, added_scans}`: `totals` = distinct one-argument `total()` calls, `added_scans` = 1 (the formula's own pre-pass; formulas or two-pass attributes the planner puts in one layer share it, so it is a per-formula upper bound). Predict's `Streamable` asks the same predicate (`attrTwoPass`), so a total formula with groupers, features, regressions, tier-1 tests or matrices predicts buffered exactly as `canStream` runs it.
  - `PULSE_ADVISORY_SERIES_AXIS_NOT_DATE` (owners: the eight ordered series overlays, `advisoryOrderedOverlayNames` over `seriespartition.Ordered`; U46 E2-S2): one per `overlays[i]` the instance offers whose kind reads its partition as an ordered series (prior, rolling, baseline, sibling pairs) on a SERIES host (`Crosstab` nil) of two or more groupers whose `params.partition_by` is absent or null (`seriespartition.Explicit` false — an explicit list, `[]` included, states the order and never fires), when the LAST grouper (the implicit series axis) is not date-family: not a routed `GROUP_DATE` / `GROUP_DATE_RANGES` and not over a `date` / `datetime` schema column (`seriesAxisIsDate`). The `_TOTAL` kinds partition too but are order-free and never fire. `details {slot, operator, series_axis, grouper, groups, date_axis}`: `date_axis` = the first leading key column that is date-family, absent when none.
  - `PULSE_ADVISORY_EXTENSION_PARAMS_UNDECLARED` (owner: shared — any instance may register an extension; U44 E1-S2): one per slot naming an extension operator whose registration declares NO params (`ParamsDecl.Declared` false) while the slot carries a non-empty `params` object — the keys the params allowlist (`ParamsRefusal`) cannot check, which pass to the embedder's factory untouched. `extensionParamsAdvisories` walks the allowlist's own slot list (`paramsChecker` in advisory mode). `details {slot, operator, keys}`. A declaring extension refuses an unknown key instead, like every built-in.
  - `PULSE_ADVISORY_COMPOSE_FAMILIES_SPLIT` (owner `capability:multiplicity`; U48 E3-S2): Compose predict only, over `ComposeValidationResult.Slots` (`familiesSplitAdvisory`, `internal/descriptor/predict_advisories_roots.go`). Fires when ≥ 2 slots emit p-values (`slots[i].p_values.total > 0`), their corrected p-values join ≥ 2 distinct family IDs other than `compose`, and the slots emit ≥ `MultiplicityTriggerThreshold` p-values in TOTAL (corrected or not; host overlays not counted — MANY_TESTS covers them). Uncorrected p-values form no family, so 6 + 6 uncorrected never fires it (each slot's own MANY_TESTS judges its own count). `family: "compose"` on every member (a slot block, or the batch block the slots inherit) silences it. `details {slots, families, total, uncorrected, basis, threshold, suggested: {"multiplicity": {"method": <first family's method>, "family": "compose"}}}` — `slots` the indices whose p-values join a split family, `families` the IDs in first-seen order; no `details.request` (a batch advisory). Emitted after the slot advisories, before the host many-tests note.
  - **Sidecar wiring.** The facade's one sidecar read (`Pulse.sidecarFacts`, root `weight_suggest.go`) hands `PredictOptions.SuggestedWeightVariable` and `PredictOptions.SidecarMeasureLevels` (field → measure level) down; a missing, malformed, STALE or anchor-path sidecar yields neither, so a non-SPSS cohort and `PredictBytes` never fire the three sidecar codes. Measure levels are judged against the COHORT schema (`cohortSchema`), not a joined one; a field the schema no longer carries is silent.
- **Profile-scrubbed.** An operator named in a message or `details.suggested` is one the instance offers (`InstanceSnapshot.Enabled`); a hidden `TEST_T` routes as never-registered and fires nothing; a hidden `capability:multiplicity` withholds `p_values`, so MANY_TESTS never proposes it.
- **Roots (U22 E1-S4).** Request predict runs every rule. **Facet predict** (`ValidateFacetWithOptions`) gains `FacetValidationResult.PValues` + `.Advisories` (both `omitempty`): `countFacetPValues` counts one p-value per inferential FACET-host overlay (`OVERLAY_CHISQ_VS_POP` / `OVERLAY_KS_VS_POP` carry one scalar p-value each — `exact`; an underivable kind counts one, `lower_bound`), `uncorrected` from `ResolveFacetMultiplicity`'s index-aligned members; then the full rule set runs over a slot-free request — a `FacetRequest` has no test, aggregator or weight slot, so only MANY_TESTS can fire (message opens "The facet request emits"). **Compose predict** (`ValidateComposeWithOptions`) gains `ComposeValidationResult.PValues` + `.Advisories` + `.Slots` (U48 E3-S2; `[]descriptor.ComposeSlotPredict {request, label, streamable, streamable_reasons, p_values, families}`, `omitempty`, one entry per non-nil slot of the effective batch, set wherever advisories are computed): `streamable` / `streamable_reasons` are `computeStreamable` over the slot's defaulted request and schema — Process predict's own call, never re-derived (`TestComposePredict_SlotDetail`, `TestPredictCompose_ShowcaseReadoutFamilies` pin parity); `p_values` is the slot's `countPValues` under `ComposeMultiplicityPlan.Requests[i]` (tests, post-tests, Request overlays, inferential matrices, regression predictors); `families` (`[]descriptor.PValueFamily {id, family, method, count, basis}`) are read off the SAME count through `countPValuesVisit`, so they never drift from `p_values`. Family `id` spells the runtime fold's key (`multFamilyKey` / `overlayFamilyKey`): `compose` (one batch-wide family), `requests[i]#request`, else `requests[i].<slot>#<family>` (an overlay layer's `layer` / `row` / `column`; a matrix spec's `matrix`, which the runtime further splits per group bucket). `p_values` / `families` are withheld when the batch multiplicity is refused or `capability:multiplicity` is hidden; the verdict stays. `composeAdvisories` runs `computeAdvisories` per slot over the slot's defaulted request and its own schema (`SchemaLoader`) and sidecar (`PredictOptions.SidecarLoader`, called once per slot cohort path; nil reads nothing), with the slot's `ComposeMultiplicityPlan.Requests[i]`; each slot advisory carries `details.request = i` and a `requests[i].` prefix on `details.slot` (and in the message). Then MANY_TESTS over the Compose-host overlays: `countComposeHostPValues` counts one per inferential spec, ALWAYS `lower_bound` (the extent is cohort-free), silenced by any resolved compose plan; it carries no `details.request` and its message opens "The compose request's overlays emit". A refused batch multiplicity withholds every count. **Chain is untouched** — `ChainValidationResult` keeps its exact key set (no v1 chain stage reaches a p-site). Neither validation result is payload-reachable, so no payload-schema golden moves. Compose and Facet predict have no facade entry today; the facade wires `SidecarLoader` from `Pulse.sidecarFacts` when one lands.
- **Suppression.** `Options.SuppressAdvisories []string`, validated at `pulse.New` against the whole registry (`ValidateSuppressAdvisories`; unknown → `PULSE_SUPPRESS_ADVISORY_UNKNOWN`, `details {code, valid}`; a code a profile can never fire is accepted), installed on the instance (`InstanceSnapshot.WithSuppressedAdvisories`, not in the feature-set digest) so every predict path drops it. No per-request or CLI knob.
- **Payload schema.** `descriptor.Advisory` is an ungated root of the payload schema (`PredictResult` itself is not payload-reachable); `format_version` stays `"1.1"`.

## Import predict is not descriptor predict

`io.ImportJob.Predict` (`pulse import predict`) is the ONLY predict that may read source rows, and none of the rules above bind it — it lives in `internal/io/` (aliased by public `io`), not `internal/descriptor/`. Its measured pass (declared `Groups`, `ElideConstants`, or `SuggestGroups`) converts every row through `rowConverter`, the converter `Run` uses, and derives group figures through `encoding.DedupGate` / `AssessGroup` / `PlanConstantElisionFor` — so import predict, `ImportReport.Groups` and inspect report the same numbers for the same data (`TestImportPredict_DeclaredGroupsMatchImport`, `TestImportPredict_SuggestedMatchesImport`). Candidate detection nominates over a bounded window and confirms on the full pass; it suggests, never declares. Without those three knobs predict keeps its plain row-count pass and its report is unchanged.
