## Predict

`internal/descriptor/predict.go` MUST NOT import `internal/service/` or `internal/processing/` — `TestPredictNoExecutionImports`. Predict duplicates operator knowledge on purpose, or shares it through a no-execute LEAF package both sides import (`internal/fieldaccept`, `internal/crosstabfuse`, `internal/temporal`, `internal/model`, `internal/vectors` rules, `internal/optblock`, …). **The parity rule:** wherever predict and the runtime judge the same thing, they call the same function; a second copy is how the two sides drift. Each result field below names its shared rule and parity gate.

- **`Streamable`** mirrors the per-type `Streamable()` methods plus schema gates (decimal — built-in aggregators only); an extension answers from its DECLARED registration flag, which is what the runtime routes on. A request with no aggregation streams when it carries a matrix, a tier-1 test or a regression (its `sizes` then carry no `data`). Parity: `TestPredict_Streamable_MatchesRuntime`, `TestExtensions_StreamabilityFollowsDeclaration`. `DefaultsApplied` is always computed.
- **`ComputedBeforeFilters`** lists attributes computed over the unfiltered cohort before filters — `prevstate.BeforeFilters`, the runtime's split rule (`execution-modes.md`, Before-filters attributes).
- **`CrosstabFusable` + `CrosstabFusionReasons`** answer "will this instance run the crosstab on the fused in-decode arm" (identical output, `O(cells + margins)` memory), from `crosstabfuse.Decide` over the defaults-resolved request and the COHORT schema; `Options.DisableCrosstabFusion` answers false. `Predict` / `PredictBytes` only. One sanctioned divergence: a keyable grouper whose factory rejects its params — the request errors either way. Parity: `TestStreamability_CrosstabFusionPredictMatchesRuntime`.
- **`TimeZones`** (never nil) from `ResolveZones` (`internal/descriptor/zone_resolve.go`), the runtime's resolver, on the defaults-resolved clone with the instance's default zone; a join resolves against the joined schema (`internal/encoding.JoinedSchema`). More than one `JoinSpec` is refused right after the header read through `JoinCountRefusal`, the runtime's first rule; inside Compose / chains, locations are added through `RefusalAt`. The chain stage gate is `internal/mergegate.ChainRefusal` (`PULSE_CHAIN_STAGE_JOIN` for a joined stage ≥ 1).
- **`Weights`** (`omitempty`) from `ResolveWeights` (`internal/descriptor/weight_resolve.go`: slot → request → `DefaultWeight` → none), right after the field-reference rule on both sides. Contract: `.claude/reference/weighting.md` (Resolution order).
- **`PValues`** (`{total, uncorrected, basis, threshold}`, `omitempty`) counts inferential p-values the request emits and how many no multiplicity block corrects (`internal/descriptor/predict_pvalues.go`, over `ResolveMultiplicity`, the runtime's call). Threshold `descriptor.MultiplicityTriggerThreshold` = 10 feeds `PULSE_ADVISORY_MANY_TESTS`. Tests count one each, `TEST_TUKEY_HSD` none (family-wise already), inferential overlays their payload's p-values, a correlation matrix under `params.inference` C(k, 2) per spec × grouped buckets. `basis`, weakest wins: `exact`, `dictionary` (assumes every dictionary entry becomes a bucket), `lower_bound`. Omitted with no p-value or with `capability:multiplicity` hidden. Contract: `execution-modes.md` (Multiplicity).
- **`Matrices`** reports per spec its shape, keys, encoding, accumulator bytes, streamability, mergeability, row buffer and `pairwise_psd_risk`, off the runtime's resolver and `internal/vectors/matrix_rules.go`. Long form: `matrix-and-vectors.md` (Predict bullet of the Matrix slot section).

**`PredictResult.Sizes`** (`omitempty`) is reported on EVERY single-cohort predict — one `ResponseSectionSize {section, full_bytes, shaped_bytes, basis}` per top-level Response section the request produces, in Response key order (`internal/descriptor/predict_return_sizes.go`).

- Each section is a tree mirroring its JSON shape (rows or cells × a bytes-per-value model). `shaped_bytes` walks the SAME tree through the `return` plan, so `shaped ≤ full` by construction; no plan → equal; a refused `return` block withholds `sizes`.
- Rows come from `EstimateGroups`, crosstab cells from axis key counts, matrices from estimated buckets — every `auxiliary` key an operator emits under its resolved params is sized, so `return` can shape it (`TestMatrixAuxiliaryNodes_PerOperator` holds every sized key to `OutputKeys.Auxiliary`).
- **A section whose count depends on data is OMITTED, never guessed.** `basis`: `exact`, `upper_bound` or `heuristic`. Record count comes from the file LENGTH (single file) or per-shard header peeks (archive). Guidance only — no byte-accuracy gate. Gates: `TestPredict_ReturnSizes_ShapedNeverAboveFull`, `TestPredict_ReturnSizes_Basis`.
- `PredictResult.Return` (the resolved plan) carries **`unresolved_includes`**: Open include paths predict cannot resolve without data; a buffered run warns `PULSE_RETURN_PATH_UNMATCHED` for one that matches nothing, a stream never does.

**`ComposeSlotPredict.Sizes`** — Compose predict sizes every slot with the SAME model over the normalized slot, its executing schema, its cohort's header count, its model catalog and the batch's resolved multiplicity, headed by a `label` section; absent when its `return` is refused or its schema unresolvable (`TestComposePredict_SlotSizesMatchProcessPredict`). Chain validation reports no sizes.

**Field references are one rule, not a predict-only check.** Existence of every name a slot references is `internal/descriptor.FieldRefRefusals` (`field_refs.go`), which the runtime also calls first — an unknown name used to read as an all-null column and answer with wrong numbers. The per-family validators keep only checks on fields the schema carries (types, orderability, decimal) and must NOT re-grow an existence check.

- The walk follows the runtime's naming and PIPELINE order (features → filterers → attributes → record consumers → output-row consumers), documented on the function. It refuses a derived name that SHADOWS a column and an aggregation label colliding in the output row (`execution-modes.md`, Predict and the validators). It judges names inside params (`aggParamFieldKeys`, `postTestParamFieldKeys`) and an extension's declared `FieldInputs` (so predict must receive the extensions snapshot).
- Window `order_by` orderability is `IsOrderableType` inside the walk: every type but `set_*`; a categorical orders by dictionary LABEL (never the index, which shifts across imports and shards), dates by signed epoch, nulls last.
- **Name the cause.** A filterer naming a later step's label (window, attribute, aggregation) gets `; <label> is the label of window[i] (<TYPE>); filters run before windows…` and `label_source`; a window naming a RECORD column where windows run over output rows gets `reason: "window_over_output_rows"`. One builder serves both sides.
- `FILTER_INCLUDE` / `FILTER_EXCLUDE` values resolve through `internal/valuematch.FilterKeys`, the runtime constructor's rule, on the FULL schema dictionary (an archive's canonical union) — never inspect's truncated view.
- Join keys: `internal/encoding.JoinKeysRefusals` (`PULSE_JOIN_FIELD_UNKNOWN` and siblings).

**Field-type acceptance is gated table-wide, with no ledger.** `TestFieldTypeAcceptance_PredictMatchesRuntime` runs every registered operator over one column of every field type through `Process` and predict: both accept exactly the same types, and where both refuse they raise the SAME code, once (`TestFieldTypeSlots_PredictMatchesRuntime` covers the other slots). Never add a divergence ledger.

- **`internal/fieldaccept` is the single source**: operator → slot → accepted types + code; a leaf, so predict imports it. The manifest's `accepts_types` IS `fieldaccept.TypeNames` (`TestCapabilities_AcceptsTypesMatchFieldAcceptTable`), and atomic skills' `Field` lists are held to it (`TestAtomicSkillFieldTypesMatchFieldAcceptTable`).
- **Codes say what they mean:** a type refusal is `PULSE_FIELD_TYPE_UNSUPPORTED` (`{type, slot, field, field_type, accepts_types}`); a tier-1 numeric test keeps `PULSE_TEST_FIELD_NOT_NUMERIC` / `_FIELD2_`; a "must be categorical" slot is never `*_NOT_NUMERIC`. An unregistered Type is `PROCESSING_CONFIG` "unknown <family> type: <name>" on both sides.
- **The decimal rule** runs before every row: a `decimal128` field on a built-in aggregator outside `fieldaccept.DecimalAggregators()` is one `PULSE_AGG_NOT_MEANINGFUL_FOR_DECIMAL` error at every aggregation slot; extension aggregators are exempt.
- **Readers:** quantity readers (z-score, percentile, quantile groupers, `FILTER_RANGE`, …) refuse a categorical (its echo is an index) and accept `decimal128` / `datetime` / `packed_bool`; numeric readers refuse categorical and `set_*`; counting aggregators keep reading categoricals. Vector fields are refused earlier (`PULSE_VECTOR_FIELD_NOT_SCALAR`).
- **Direction of fixes:** predict stricter than a CORRECT runtime is a predict bug; a runtime computing a wrong number is refused through the table, never widened. A slot's field refusal precedes its param refusal, as the runtime's factories order them.

**Literal `lookup()` / `range_label()` calls are judged statically.** Once an expression compiles, `internal/tablecall.Refusal` walks its CHECKED tree against the instance's tables and raises the evaluating builtin's own code: a literal unknown table (`PULSE_LOOKUP_TABLE_UNKNOWN`, only when lookup tables exist; `PULSE_RANGE_TABLE_UNKNOWN`), a `range_label` value whose static type is string / bool / list (`PULSE_RANGE_TABLE_KIND_MISMATCH`; a date is an epoch-day number and never refused), and — only when EVERY key argument is literal and the table declares `Keys` — a nil key or an off-axis joined key (`PULSE_LOOKUP_MISS`). Computed arguments are left to evaluation. It runs in the field-reference walk (so the run's entry check raises it before any record, even for an untaken branch), the formula overlay gates and optimize. Parity: `TestTableCall_StaticMatchesEvaluation`.

**`PredictResult.PostWindow`** (`omitempty`) is the request's post-window plan `{windows_first, window_labels, attributes: [{index, label, depends_on, window_reads}]}` — which attributes run after the windows, addressed by index into the request as run. It is NOT a second classification: the field-reference walk returns the `vectors.PostWindowAttributes` plan it judged by, and `internal/descriptor/predict_post_window.go` only reshapes it. Reported on every decoded request, refused drafts included; where predict stops before the walk it runs the same call schema-free. `PredictCompose` sets it per slot, over the batch's `fits` plus the slot's models. Parity: `TestPredictPostWindow_ParityWithClassifier`.

**`Pulse.ClassifyPostWindow(ctx, req, schema)`** is that block with NO cohort: it replays Predict's steps up to the walk (early stops, item expansion, model loading, join schema, smart defaults) and returns the walk's plan, so it EQUALS Predict's `post_window` over a cohort with that schema. A nil schema degrades to the schema-free fallback. Not an operation (fires no `predict` hook). Gates: `TestClassifyPostWindow_MatchesPredict`, root `TestClassifyPostWindow_RuntimeRunsThePlan`.

**Saved files are the one non-cohort read predict makes (`models`, `populations`).** Predict reads and decodes `models` / `populations` entries through `PredictOptions.ModelLoader` (the runtime's own `Service.ReadModelFile`) at the point the runtime loads them, by the SAME leaf rules (`model.CheckRefs`, `model.LoadFiles`; `internal/descriptor/predict_models.go`), so a bad entry is refused with the runtime's error (`TestModelLoad_PredictRuntimeParity_*`). A loaded population enters predict's fit catalog WITH its labels, so `params.fit` names, kinds and label alignment (`vectors.AlignFit`) are judged statically; a name whose file failed to load is not also reported `PULSE_MODEL_UNKNOWN`. No record is read and no decomposition recomputed, but scalar slots reading a loaded entry through `coef()` / `sweep_axis()` / `response()` are FOLDED to the runtime's value (`.claude/reference/execution-modes/scalar-slots.md`, Loaded-model fold).
