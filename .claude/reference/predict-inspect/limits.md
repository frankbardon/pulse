# Predict / Inspect — Limit findings and the memory estimate

Per-topic slice of the predict-inspect reference (limit findings on every predict root, the memory estimate). Index (preamble + section map): `.claude/reference/predict-inspect.md` — load it first, then only the slice(s) your change touches.

## Limit findings

**`PredictResult.LimitFindings`** (`limit_findings`, additive `omitempty`, `[]descriptor.LimitFinding {limit, configured, estimated, grade, details}`) lists every instance resource limit (`pulse.Limits`, read off `PredictOptions.Instance.Limits()` — pulse.New installs the resolved limits on the snapshot, so `Predict` / `PredictBytes` / MCP `pulse_predict` / the CLI all see them without a new option) that a figure predict computes from the request + schema exceeds. `grade` is `certain` (the exact figure the runtime sees) or `possible` (an upper bound). A CERTAIN finding also adds the `PULSE_LIMIT_EXCEEDED` error the runtime raises — so `Valid` is false; a POSSIBLE one is reported only and never refuses. It is ONE rule, not a predict-only check: `internal/descriptor.RequestLimitFindings` (`limits.go`), over the leaf `internal/limits` (`Grade`, `Finding`, `Evaluate`, `Check*` — stdlib + `types`/`encoding`/`errors` only, `TestLimits_ImportBoundary`), and the runtime calls it as `LimitRefusal` from `Service.limitsPreflight` right after `checkFieldRefs` on every Request arm (serial dispatch, crosstab, join and joined crosstab — through `openJoinStream`'s preflight hook, before the build side decodes — chain stages ≥ 1; stage 0 and Compose slots pass through `Process`) — so a certain breach is refused with the identical code, message and details before any record decodes. Today: `MaxGroups` (`possible`, never a refusal — an UPPER bound: `EstimateGroups` is the PRODUCT over every `Request.Groups` entry (U54 E1-S3: a multi-grouper run mints one composite key per OBSERVED combination, so the runtime count never exceeds it — `TestMultiGrouper_PredictBoundsRuntime`; the crosstab-axis rule `crosstabAxisEstimate`, `mulSaturating`) of each grouper's bound — `vectors.EstimateBuckets` per grouper plus `GROUP_DATE_RANGES` as its range count + the unmatched bucket (a named table's `range_count` off the snapshot; none while `capability:range_tables` is hidden) — clamped by the header record count unless a grouper fans out (`GROUP_SET_PER_ELEMENT`); ANY `GROUP_RANGE` / `GROUP_DATE` / `GROUP_ROUNDED` / `GROUP_SET_VALUE` / extension grouper yields no finding; the pre-flight reads the count only when `MaxEstimatedMemory` is set — a `possible` finding never refuses, so it needs none; the runtime counts at every bucket mint — `execution-modes.md` (Parallel shards — the resource-limits paragraph)), `MaxCrosstabCells` (`possible` — `EstimateCrosstabCells`: the rows × columns product of each axis's per-position `EstimateGroups` bounds, each axis clamped by the header count unless a position fans out; any unknown position yields no finding; the runtime checks both arms — `execution-modes.md` (Crosstab — the resource-limits paragraph)), `MaxEstimatedMemory` (`certain`, only when set — Unlimited by default, so opt-in; see the memory paragraph below), `MaxMatrixDim` (each matrix's resolved member count, `vectors.ResolveMatrices`) and `MaxJoinBuildRows` (a single join's right-side record count, read header-only through `PredictOptions.RecordCounter` — the facade wires `Service.CountRecords`, never `Cohort.RecordCount`; the right side is decoded unfiltered, so the count is exact and the finding `certain`). The runtime refuses `MaxJoinBuildRows` in `openJoinStream` — shared by the joined Process and the joined crosstab — on the same header count before the build decodes a record, plus an in-loop backstop for a miscount; an Unlimited limit skips the count. The rules read `LimitInputs` beyond request + schema: `Records` (the header count, -1 unknown — the pre-flight reads it only when `MaxEstimatedMemory` is set), `ShardRecords`, `Join` / `JoinRightRows`, and the arm facts `Extensions` / `FusionDisabled`. `MaxComposeSlots` / `MaxChainStages` are fan-out counts checked at the Compose (serial and parallel — the whole call; `FailFast` does not apply) and chain entries right after the empty check. Compose predict refuses `MaxComposeSlots` too — explicit + sweep-expanded slots, through the same `sweep.Expand` preflight and `limits.CheckComposeSlots` over `InstanceSnapshot.Limits()`, so code, message and details match the runtime (`TestPredictCompose_SlotLimitParity`); chain predict checks `MaxChainStages` right after its empty check, as `ProcessChain` does (U35 E7-S1). **The other roots (U35 E7-S1).** `ComposeValidationResult`, `ChainValidationResult` and `FacetValidationResult` carry `LimitFindings` too, graded like Process; `LimitFinding.Details` (`omitempty`) locates a slot's / stage's finding with the key its located error carries. Compose: the slot count (`certain`, unlocated, read off the refusal — `limitRefusalFinding`), then each slot's `requestFindings` (the Process rule incl. `MaxJoinBuildRows`) located `details.request` (a fit request's `details.fit`) right after its weights, on the slot cohort's counts through `PredictOptions.CohortCounter` (the facade wires `Service.CohortCounts`, the runtime pre-flight's own `cohortCounts` — archive shard counts and directory bytes included; nil falls back to `RecordCounter`). Chain: the stage count, then each stage's findings located `details.stage`; stage 0 on the header count (file length; an archive's shard counts and directory bytes), stages ≥ 1 on an unknown count — their input rows exist only at runtime — so no memory estimate (never a certain memory finding) and unclamped group bounds. Facet: `FacetLimitFindings` — a `possible` `MaxGroups` bound `FacetGroupBound` (largest faceted field's dictionary size, 2 for `packed_bool`, clamped; numeric fields mint none) + the `certain` `EstimateFacetMemory`; `FacetLimitRefusal` is its first certain finding. Gates: `TestLimitsPredictRuntimeParity` (each host through its own predict root; only `RequestTimeout` unknowable), `TestLimits_ChainStages_PredictParity`, `TestLimits_PredictChain_StageFindings`, `TestLimits_PredictCompose_SlotFindings`, `TestLimits_PredictFacet_Findings`, `TestFacetGroupBound`. `PredictResult` and the root results are `descriptor` types, so the payload-schema golden does not move; the API golden does. Gates: `TestLimits_MatrixDim_PredictCertainAndProcessRefuses`, `TestLimits_ComposeSlots`, `TestLimits_ChainStages`, `TestLimitsPreflight_MatrixDimRefusesBeforeDecode`, `TestLimits_JoinBuildRows_PredictCertainAndProcessRefuses`, `TestLimits_JoinBuildRows_PredictReadsRightHeaderOnly`, `TestLimitsPreflight_JoinBuildRowsRefusesBeforeDecode`, `TestLimitsPreflight_JoinBuildRowsLoopBackstop`, `TestEstimateGroups`, `TestPredict_MaxGroupsClampedByHeaderCount`, `TestLimits_MaxGroups_PredictPossibleAndProcessTrips`, `TestRequestLimitFindings_MaxCrosstabCellsPossible`, `TestLimits_MaxCrosstabCells_BothArms`.

**The memory estimate (`MaxEstimatedMemory`, U19 E2-S3).** `internal/descriptor.EstimateMemory` picks the arm the engine dispatches (`MemoryArm`: the fused crosstab iff `CrosstabFusion` accepts and neither a join nor `DisableCrosstabFusion` declines; else buffered for a crosstab; otherwise streaming iff `computeStreamable`) and evaluates the leaf model `internal/limits.EstimateMemory` (`memory.go`) on: the header record count (a join's left side; a chain stage's input rows, counted exactly), the schema stride and `limits.RecordBytes` (one buffered record at FULL schema width: header + a slot per field and per set-mask / parent-group word + bit planes + the decimal aux block), the group bound (`memoryGroupBound`: `EstimateGroups`, else the value-width bound below, else the record count × the fan-out multiplicity), the crosstab grid (`EstimateCrosstabCells`, or the record count), aggregations (the cell and `margin_aggregations` included) and how many keep per-value state (distinct / mode / frequency families, or an extension aggregator declaring `ValueState` — `ExtensionsSnapshot.AggregatorValueState`; undeclared it is a fixed accumulator), derived columns (attributes + features + windows), a join's right header count, the matrices' `MatrixStateBytes` (= `estimated_bytes`), the fan-out multiplicity and the tier-1 tests. Formula: base 16 MiB + 3 × records × stride (the payload a non-mmap fs reads onto the heap plus the collector's GOGC headroom) + right rows × (3 × stride + 2 × record bytes) + matrix state + vector-aggregator fragments + records × fan-out × 96 per value-state aggregation + test instances × 1024 + test levels × 256 + buffered-test values × 32; buffered adds records × (record bytes + 16 × aggs + 128 × derived) + records × (fan-out − 1) × 24 + buckets × (state + output) + the crosstab charge + its partitions (records × fan-out × 128 + measures × (cells × 448 + axis keys × 416)); streaming adds buckets × (state + output); fused adds the crosstab charge; the parallel arms add partition buckets × state. **Bucket state and output (U51 E2-S4, per aggregator since E5-S7, `limits.BucketBytes`).** state = 256 + 128 × groupers past the first + Σ each slot's `limits.AggregationStateBytes` + 64 × set members; output = 1024 + 576 × aggs + 128 × set members with components on, 512 + Σ each slot's `limits.AggregationOutputOffBytes` + 128 × set members with them off. **Per-aggregator state (option C).** A built-in's state is its own measured entry in `limits.aggregatorBytesTable` (unweighted / weighted — a weight-unaware built-in charges the same either way; e.g. `AGG_MIN` / `AGG_MAX` 96, `AGG_SUM` 128 / 576, `AGG_DISTINCT_COUNT` 320); an extension aggregator, and the buffered-only built-ins (`AGG_MEDIAN`, `AGG_PERCENTILE`, `AGG_ZSCORE`, `AGG_AUC`: no per-bucket accumulator), keep the 256 / 512 B ceilings. PINNED, never calibrated: `TestGroupMemory_AggregatorStateTable` (`internal/service`) builds a grouped partition of EVERY registered built-in as the parallel reducers do (weighted and not, components on and off, 1 and 4 rows a key), merges two, and asserts each entry ≥ the live heap the slot adds to a bucket (worst 91% of its entry); a built-in with no entry fails it (and `TestAggregationBytes_TableShape`). `AGG_VEC_*` add a member slope (80 B) and, once per run, `limits.VectorAggregationBytes`: a block partial per merge block a bucket (or crosstab cell) holds — min(merge blocks × buckets, rows × fan-out) — plus the rows a mid-block shard buffers (`TestGroupMemory_VectorBufferedRows`); the flat 256 B had hidden ~0.9–1.7 KB of fixed state and every fragment. **Components-off output (option B).** `LimitInputs.DisableComponents` carries `Options.DisableComponents` (predict's `PredictOptions.DisableComponents`, the pre-flight's and a chain stage's `Service.DisableComponents`); `EffectiveDisableComponents` resolves it with the request's `disable_components` — the runtime components gate's rule — so a `return` never changes the charge. Parity: root `TestLimits_MaxEstimatedMemory_ComponentsPredictMatchesRuntime` (every engine / request combination), `TestMaxEstimatedMemory_ChainStageComponentsOff`. **Calibration.** `TestGroupMemory_FinalizedRowBytes` bounds a merged bucket's state + finalize output (live heap, state and response both alive) on and off, for every streaming built-in, `AGG_MAX` widths either side of the Data row map's growth points (8, 14, 28, 56, 112 entries; a column costs ≤ 91 B off, 539 B on just past one — why `aggOutputBytes` rose from 512) under one and three groupers, the retention stage and every built-in in one bucket. `TestGroupMemory_EstimateBoundsPeak` (50,000 one-row groups, whole-run peak): 1.46 / 1.32 on (max 2.0), 2.47 / 2.05 off (max 3.0 — the 16 MiB base is a fifth of that estimate). Retention-shaped stage 0 (`u32` key, 2.52M buckets charged, 1.05M present): 10.55 GB at one live partial, 13.56 GB at the full window, against a 3.6 GB peak heap (`BENCHMARKS_BASELINE.md`). `AGG_SET_DISTINCT_VALUES` joined the value-state set (E2-S4). **Crosstab cells (U51 E5-S9; was a flat 512 B a cell).** Per measure (`crosstab.cell`, or each `crosstab.cells` entry — each runs its own grid, interners and margins): every grid cell and margin slot costs `limits.CrosstabSlotBytes` — the measure's table state (weighted under a weight in force) plus its table `cell` entry (finalize output: matrix value, components entry and the per-cell finalize maps; `on` / `onWeighted` / `off`) + 192 B a set member for `AGG_SET_FREQUENCY`; every axis key (`memoryGroupBound` per axis) `limits.CrosstabAxisKeyBytes` (784 on / 544 off); each `margin_aggregations` entry `limits.CrosstabAuxSlotBytes` (a components-on slot + 256) in every emitted row / column / grand slot, once per measure, nothing with components off (neither arm accumulates it). Margin slots = rows (row margins) + columns (column margins) + 1 (grand) + cells (`normalize_within`) + axis keys (`normalize_level`). A vector element slot reads one member; its fragments are bounded by min(blocks × (cells + margin slots), records × fan-out × the accumulators a row feeds), and a value-state measure keeps a value per row in its cell and each margin it feeds. Extensions: state ceilings + `crosstabCellOutputCeilingBytes` (2,048) on or off. Gate: `TestCrosstabMemory_CellChargeTable` (internal/service) — every built-in usable as a cell measure, fused when the fusion gate admits it and buffered always, weighted × components on/off, a 60 × 60 grid (3,600 cells: just past a map growth point, the finalize maps at their sparsest), the run's peak live heap (GOGC=1, sampled) ≤ `descx.EstimateMemory` less base and payload; plus 4,000 × 1 / 1 × 4,000 grids, margins, three measures, auxiliaries, the normalize denominators, a value-state measure at 16 rows a cell and a vector element over two shards (the blocked merge's fragments and buffered rows — a crosstab has no partial-merge arm). Entries sit ≥ 20% (fused) / 15% (buffered) above the largest peak seen over repeated runs (sampling noise ~8%). Assembly: `TestEstimateMemory_CrosstabCharges`; predict ≡ runtime: root `TestLimits_MaxEstimatedMemory_PredictCertainAndProcessRefuses` (two-measure weighted crosstab with margins and an auxiliary, both arms). Open: an axis of unknown cardinality still bounds the grid by the record count, not rows × columns — a sparse dense grid's empty positions (~64 B each) are not charged. **Value-width bucket bound (U51 E5-S6).** A grouper of data-dependent cardinality whose key is a function of one stored word — `GROUP_CATEGORY` / `GROUP_ROUNDED` / `GROUP_RANGE` over `u4` / `u8` / `u16` / `u32` (and their `categorical_*` twins), `GROUP_SET_VALUE` over `set_u8` / `set_u16` / `set_u32` — mints at most one key per distinct stored value, so `valueKeyBound` charges at most 2^bits buckets (u4 16, u8 256, u16 65,536; a null row mints none). `memoryGroupBound` multiplies the per-grouper bounds (schema-known, else value-width, else unbounded) and clamps by the records — × `FanOutMultiplicity` when a `GROUP_SET_PER_ELEMENT` position fans out (each record can mint that many composite keys; the clamp was the bare record count, under the run). It is the memory estimate's bound only: `MaxGroups` keeps `EstimateGroups`. PROVABLE, never calibrated: `TestLimits_ValueWidthBoundCoversEveryKey` (root) runs a cohort holding every u4 and u8 value and asserts the charged buckets EQUAL the minted keys (the bound is attained); `TestEstimateMemory_ValueWidthBound` (`internal/descriptor`), the `value-width grouper` parity case and the `streaming value-width grouped` calibration case (65,536 charged, 4,096 present: 3.26). Rejected as unprovable (never a memory bound): an index manifest's `distinct_keys` (its freshness is a stat pair or a whole-cohort digest, and the archive figure is a per-shard sum). The per-bucket byte figures stay the measured ceilings above. No 32-bit-or-wider key gains anything: the retention-shaped chain (`GROUP_CATEGORY` over a `u32` customer id, `BENCHMARKS_BASELINE.md`) stays bounded by its records. **Fan-out and tests (U35 E7-S2, #267 / #437).** `FanOutMultiplicity` (beside `EstimateGroups`) is the most buckets one record lands in: the product over every `GROUP_SET_PER_ELEMENT` position (groups and both crosstab axes) of its key bound — the set dictionary, or its include list; popcount is data, so the dictionary size is the only schema-derivable bound (1 without a fan-out position). It scales the per-value state (distinct (bucket, value) pairs reach records × fan-out), a buffered matrix's row store (`row_buffer_bytes` = records × fan-out × 8·(p + 1)) and a buffered test's values. A buffered (rank) matrix charges `limits.MatrixRowWorkBytes` = rows × 8·(p + 1) × 10 — the store's growth plus the rank finalize's column copies, ranks and ties, measured 7.6–9.2× the bare row. Tests (`testMemory`): one instance per tier-1 test per bucket (tests run once per group); each keys up to its split_by / rows × cols / subject_field levels (a categorical dictionary, 2 for `packed_bool`) per instance, never more than the rows it admits (records × fan-out, also the bound for a numeric split); a test that is not a streamable built-in (`types.TestType.Streamable`) keeps records × fan-out × its value columns (field, field2, subject, every vector member, the weight). An extension test charges instances only (its state is its own, like an extension aggregator's). **Join fan-out (U35 E7-S5, #229).** The certain estimate feeds the processor the LEFT count — exact only while no right key repeats (joined rows = Σ_k L_k·R_k). The only SOUND header-only bound is left × right; header + schema hold no uniqueness guarantee (an index manifest's `distinct_keys` is not a freshness claim, Lookup's `assert_unique` is per call), so a right side of ≤ 1 row is the only provably unique key. When the certain estimate fits, `RequestLimitFindings` adds a `possible` `MaxEstimatedMemory` finding (`joinFanOutFinding`, never a refusal) on `JoinRowsBound`: a categorical right key (the joined schema's `As + right_field`) bounds a key's matches by R − D + 1 — sound only if every dictionary entry occurs (derived / filtered / synth / shard-removed cohorts do not guarantee it); a composite key takes its smallest column bound; no dictionary → L × R. Its bound rides `LimitFinding.Details` `{join: 0, join_rows_bound, join_bound: right_key_dictionary | left_x_right}` beside a located finding's `request` / `stage` (`limits.Finding.Join` → `DetailsMap`; `locatedFindingsAt` merges). The runtime backstop: `openJoinStream`, after `NewHashJoinIterator` hashes the build side and BEFORE the first probe, reads `HashJoinIterator.MaxMatches` M and refuses `descx.JoinFanOutRefusal` — the estimate on L × M joined rows over a set `MaxEstimatedMemory`, the memory refusal's details + `join: 0`, `join_rows_bound`, `right_key_multiplicity`, `markLocated` so Compose / chain add `request` / `stage`; the preflight hook returns the request it judged (the Joins-stripped clone), `LimitInputs.JoinSpec` carries the spec. M ≤ 1 or Unlimited → nothing, byte-identical. The joined-row figure (`estimateMemory(…, rows)`, `limits.MemoryInputs.JoinedRows`) replaces records in every per-row term — buffered records and fan-out slots, per-value state, bucket / cell clamps, tests, matrices, point stores — never the payload (the left scan). **Shard archives (E8-S3, re-pinned U51 E1-S2):** since U51 E1-S1 `Open` reads only the central directory and each shard's header and the scan streams one shard at a time through a bounded window — the archive is never resident — so `archiveTerms` charges what the run holds, never the archive's bytes: the payload term reads the LARGEST shard's records (`limits.MemoryInputs.MaxShardRecords`, the max of `LimitInputs.ShardRecords`) × stride × `fileCopyFactor` in place of the cohort's records (per-row state — buffered records, per-value state, buckets, tests, matrices — still counts every record); plus the central directory, `directoryCopyFactor` (8) × `LimitInputs.DirectoryBytes` (`encx.Archive.DirectoryBytes`: the tail past the last entry's data, read the same way by predict's `readArchiveHead` / `predictArchive` and the runtime's `openArchive` → `Cohort.directoryBytes`; resident ~6 bytes per directory byte, `TestArchiveMemory_DirectoryTermBoundsOpen`); plus ONE `limits.SchemaDecodeBytes(canonical schema)` — the canonical entry, whatever the shard count; `Open`'s record-count peek (`Archive.PeekShardRecordCount`, E8-S4) and the scan (E8-S5) read each shard's schema LAYOUT-ONLY — dictionaries and group entry tables read past, never allocated — so neither is charged. The terms key on `ShardRecords` (a whole archive). **An anchor-opened shard** (`archive.pulse#shard.pulse`) is charged as the single file it is — its run reads only its shard (`OpenAnchor` serves a section of the archive) — so no archive term applies on either side (`TestLimits_MaxEstimatedMemory_AnchorChargesShard`: anchored estimate = its standalone twin's); the pre-U51 `PredictOptions.AnchorArchiveBytes` plumbing is gone. And, on the per-shard parallel arm only (`ShardFanOut`, the twin of `Service.shouldFanOut`: ≥ 2 shards, `LimitInputs.ShardWorkers` resolving to ≥ 2, `mergegate.MergeRefusal` clear, no crosstab or join), the partials the incremental merge keeps alive: at most `limits.ShardMergeWindow(workers)` = 2 × workers beside the merged state — under a set `MaxEstimatedMemory` the window `descx.ShardMergeWindow` picks (the largest ≥ 1 whose whole-run estimate fits, `limits.ShardMergeWindowWithin`; the runtime runs that window, so the judged estimate is that window's and a refusal reports the one-partial figure; U51 E5-S4) — (the runtime merges shard i once 0..i are done and releases it, and dispatches no shard past the window — `execution-modes.md` (Parallel shards)), charged as the window's largest shard bucket bounds (`memoryGroupBound` over that shard's records, 1 ungrouped) at a bucket's STATE, and the window's largest shard record counts × 96 per value-state aggregation (`shardWindowPartitions`; U51 E2-S4 — before, every shard's partial was charged). `PredictOptions.ShardWorkers` carries `Options.ShardWorkers` (0 = `runtime.NumCPU` of the predicting process). The single-file twin (U51 E2-S2): on the parallel-decode reducer (`DecodeFanOut`, the twin of `canParallelDecode` + `shouldFanOutDecode`: `LimitInputs.Mappable`, no shards, ≥ `limits.ParallelDecodeRecordThreshold` records, `LimitInputs.DecodeWorkers` resolving to ≥ 2 after the record clamp, merge gate clear, no crosstab or join) every worker partial's buckets (`memoryGroupBound` over its block-aligned segment, ≤ ⌈blocks / workers⌉ × `MergeBlockSize` records) and the second value-state term. `PredictOptions.DecodeWorkers` carries `Options.DecodeWorkers`; `Mappable` comes from `PredictOptions.DecodeMappable` (the facade's `Service.DecodeMappable` — the runtime's `resolveRealPath` probe on the opened cohort, asked only when a memory limit is set and the other conditions hold, so an unbounded predict allocates nothing more — `TestObservabilityOffNoAllocs`) and on the runtime from `limitInputs` (`decodeMappable`). Parity: `TestDecodeFanOut_PredictMatchesRuntime` (every `DecodeWorkers` × mappable / in-memory / under-threshold / archive × mergeable / grouped / median / crosstab) and `TestLimits_MaxEstimatedMemory_DecodeWorkersPredictMatchesRuntime` (facade figure = pre-flight `observed`, at 1 and 4 workers). Archive calibration (`TestArchiveMemory_EstimatedBytesRatio`, min of 3 sampled peaks, `ShardWorkers` 1 and 4): peak / estimate 0.42–0.82 (estimate / peak 1.2–2.4, darwin/arm64, U51 E1-S2; band [0.3, 1.2]) — a 4-shard archive whose shards each carry a 100,000-entry dictionary (ungrouped and grouped), and a payload-dominated 8-shard ~100K × p 50 matrix archive streamed (pairwise covariance) and buffered (`AGG_MEDIAN`); the pre-E1-S2 whole-archive term measured 0.14–0.36. The rich facet has its own estimate and pre-flight (`EstimateFacetMemory` / `FacetLimitRefusal`, `execution-modes.md` (Facet endpoints)).
