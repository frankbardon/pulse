# Predict / Inspect — Limit findings and the memory estimate

Per-topic slice of the predict-inspect reference (limit findings on every predict root, the memory estimate). Index (preamble + section map): `.claude/reference/predict-inspect.md` — load it first, then only the slice(s) your change touches.

## Limit findings

**`PredictResult.LimitFindings`** (`limit_findings`, additive `omitempty`, `[]descriptor.LimitFinding {limit, configured, estimated, grade, details}`) lists every instance resource limit (`pulse.Limits`, read off `PredictOptions.Instance.Limits()` — pulse.New installs the resolved limits on the snapshot, so `Predict` / `PredictBytes` / MCP `pulse_predict` / the CLI all see them without a new option) that a figure predict computes from the request + schema exceeds. `grade` is `certain` (the exact figure the runtime sees) or `possible` (an upper bound). A CERTAIN finding also adds the `PULSE_LIMIT_EXCEEDED` error the runtime raises — so `Valid` is false; a POSSIBLE one is reported only and never refuses. It is ONE rule, not a predict-only check: `internal/descriptor.RequestLimitFindings` (`limits.go`), over the leaf `internal/limits` (`Grade`, `Finding`, `Evaluate`, `Check*` — stdlib + `types`/`encoding`/`errors` only, `TestLimits_ImportBoundary`), and the runtime calls it as `LimitRefusal` from `Service.limitsPreflight` right after `checkFieldRefs` on every Request arm (serial dispatch, crosstab, join and joined crosstab — through `openJoinStream`'s preflight hook, before the build side decodes — chain stages ≥ 1; stage 0 and Compose slots pass through `Process`) — so a certain breach is refused with the identical code, message and details before any record decodes. Today: `MaxGroups` (`possible`, never a refusal — an UPPER bound: `EstimateGroups` is the PRODUCT over every `Request.Groups` entry (U54 E1-S3: a multi-grouper run mints one composite key per OBSERVED combination, so the runtime count never exceeds it — `TestMultiGrouper_PredictBoundsRuntime`; the crosstab-axis rule `crosstabAxisEstimate`, `mulSaturating`) of each grouper's bound — `vectors.EstimateBuckets` per grouper plus `GROUP_DATE_RANGES` as its range count + the unmatched bucket (a named table's `range_count` off the snapshot; none while `capability:range_tables` is hidden) — clamped by the header record count unless a grouper fans out (`GROUP_SET_PER_ELEMENT`); ANY `GROUP_RANGE` / `GROUP_DATE` / `GROUP_ROUNDED` / `GROUP_SET_VALUE` / extension grouper yields no finding; the pre-flight reads the count only when `MaxEstimatedMemory` is set — a `possible` finding never refuses, so it needs none; the runtime counts at every bucket mint — `execution-modes.md` (Parallel shards — the resource-limits paragraph)), `MaxCrosstabCells` (`possible` — `EstimateCrosstabCells`: the rows × columns product of each axis's per-position `EstimateGroups` bounds, each axis clamped by the header count unless a position fans out; any unknown position yields no finding; the runtime checks both arms — `execution-modes.md` (Crosstab — the resource-limits paragraph)), `MaxEstimatedMemory` (`certain`, only when set — Unlimited by default, so opt-in; see the memory paragraph below), `MaxMatrixDim` (each matrix's resolved member count, `vectors.ResolveMatrices`) and `MaxJoinBuildRows` (a single join's right-side record count, read header-only through `PredictOptions.RecordCounter` — the facade wires `Service.CountRecords`, never `Cohort.RecordCount`; the right side is decoded unfiltered, so the count is exact and the finding `certain`). The runtime refuses `MaxJoinBuildRows` in `openJoinStream` — shared by the joined Process and the joined crosstab — on the same header count before the build decodes a record, plus an in-loop backstop for a miscount; an Unlimited limit skips the count. The rules read `LimitInputs` beyond request + schema: `Records` (the header count, -1 unknown — the pre-flight reads it only when `MaxEstimatedMemory` is set), `ShardRecords`, `Join` / `JoinRightRows`, and the arm facts `Extensions` / `FusionDisabled`. `MaxComposeSlots` / `MaxChainStages` are fan-out counts checked at the Compose (serial and parallel — the whole call; `FailFast` does not apply) and chain entries right after the empty check. Compose predict refuses `MaxComposeSlots` too — explicit + sweep-expanded slots, through the same `sweep.Expand` preflight and `limits.CheckComposeSlots` over `InstanceSnapshot.Limits()`, so code, message and details match the runtime (`TestPredictCompose_SlotLimitParity`); chain predict checks `MaxChainStages` right after its empty check, as `ProcessChain` does (U35 E7-S1). **The other roots (U35 E7-S1).** `ComposeValidationResult`, `ChainValidationResult` and `FacetValidationResult` carry `LimitFindings` too, graded like Process; `LimitFinding.Details` (`omitempty`) locates a slot's / stage's finding with the key its located error carries. Compose: the slot count (`certain`, unlocated, read off the refusal — `limitRefusalFinding`), then each slot's `requestFindings` (the Process rule incl. `MaxJoinBuildRows`) located `details.request` (a fit request's `details.fit`) right after its weights, on the slot cohort's counts through `PredictOptions.CohortCounter` (the facade wires `Service.CohortCounts`, the runtime pre-flight's own `cohortCounts` — archive shard counts and bytes included; nil falls back to `RecordCounter`). Chain: the stage count, then each stage's findings located `details.stage`; stage 0 on the header count (file length, + `AnchorArchiveBytes`), stages ≥ 1 on an unknown count — their input rows exist only at runtime — so no memory estimate (never a certain memory finding) and unclamped group bounds. Facet: `FacetLimitFindings` — a `possible` `MaxGroups` bound `FacetGroupBound` (largest faceted field's dictionary size, 2 for `packed_bool`, clamped; numeric fields mint none) + the `certain` `EstimateFacetMemory`; `FacetLimitRefusal` is its first certain finding. Gates: `TestLimitsPredictRuntimeParity` (each host through its own predict root; only `RequestTimeout` unknowable), `TestLimits_ChainStages_PredictParity`, `TestLimits_PredictChain_StageFindings`, `TestLimits_PredictCompose_SlotFindings`, `TestLimits_PredictFacet_Findings`, `TestFacetGroupBound`. `PredictResult` and the root results are `descriptor` types, so the payload-schema golden does not move; the API golden does. Gates: `TestLimits_MatrixDim_PredictCertainAndProcessRefuses`, `TestLimits_ComposeSlots`, `TestLimits_ChainStages`, `TestLimitsPreflight_MatrixDimRefusesBeforeDecode`, `TestLimits_JoinBuildRows_PredictCertainAndProcessRefuses`, `TestLimits_JoinBuildRows_PredictReadsRightHeaderOnly`, `TestLimitsPreflight_JoinBuildRowsRefusesBeforeDecode`, `TestLimitsPreflight_JoinBuildRowsLoopBackstop`, `TestEstimateGroups`, `TestPredict_MaxGroupsClampedByHeaderCount`, `TestLimits_MaxGroups_PredictPossibleAndProcessTrips`, `TestRequestLimitFindings_MaxCrosstabCellsPossible`, `TestLimits_MaxCrosstabCells_BothArms`.

**The memory estimate (`MaxEstimatedMemory`, U19 E2-S3).** `internal/descriptor.EstimateMemory` picks the arm the engine dispatches (`MemoryArm`: the fused crosstab iff `CrosstabFusion` accepts and neither a join nor `DisableCrosstabFusion` declines; else buffered for a crosstab; otherwise streaming iff `computeStreamable`) and evaluates the leaf model `internal/limits.EstimateMemory` (`memory.go`) on: the header record count (a join's left side; a chain stage's input rows, counted exactly), the schema stride and `limits.RecordBytes` (one buffered record at FULL schema width: header + a slot per field and per set-mask / parent-group word + bit planes + the decimal aux block), the group bound (`EstimateGroups`, or the record count for an unknown grouper), the crosstab grid (`EstimateCrosstabCells`, or the record count), aggregations (the cell and `margin_aggregations` included) and how many keep per-value state (distinct / mode / frequency families, or an extension aggregator declaring `ValueState` — `ExtensionsSnapshot.AggregatorValueState`; undeclared it is a fixed accumulator), derived columns (attributes + features + windows), a join's right header count, the matrices' `MatrixStateBytes` (= `estimated_bytes`), the fan-out multiplicity and the tier-1 tests. Formula: base 16 MiB + 3 × records × stride (the payload a non-mmap fs reads onto the heap plus the collector's GOGC headroom) + right rows × (3 × stride + 2 × record bytes) + matrix state + records × fan-out × 96 per value-state aggregation + test instances × 1024 + test levels × 256 + buffered-test values × 32; buffered adds records × (record bytes + 16 × aggs + 128 × derived) + records × (fan-out − 1) × 24 + buckets × (512 + 256 × aggs) + cells × 512; streaming adds buckets × (512 + 256 × aggs); fused adds cells × 512. **Fan-out and tests (U35 E7-S2, #267 / #437).** `FanOutMultiplicity` (beside `EstimateGroups`) is the most buckets one record lands in: the product over every `GROUP_SET_PER_ELEMENT` position (groups and both crosstab axes) of its key bound — the set dictionary, or its include list; popcount is data, so the dictionary size is the only schema-derivable bound (1 without a fan-out position). It scales the per-value state (distinct (bucket, value) pairs reach records × fan-out), a buffered matrix's row store (`row_buffer_bytes` = records × fan-out × 8·(p + 1)) and a buffered test's values. A buffered (rank) matrix charges `limits.MatrixRowWorkBytes` = rows × 8·(p + 1) × 10 — the store's growth plus the rank finalize's column copies, ranks and ties, measured 7.6–9.2× the bare row. Tests (`testMemory`): one instance per tier-1 test per bucket (tests run once per group); each keys up to its split_by / rows × cols / subject_field levels (a categorical dictionary, 2 for `packed_bool`) per instance, never more than the rows it admits (records × fan-out, also the bound for a numeric split); a test that is not a streamable built-in (`types.TestType.Streamable`) keeps records × fan-out × its value columns (field, field2, subject, every vector member, the weight). An extension test charges instances only (its state is its own, like an extension aggregator's). **Join fan-out (U35 E7-S5, #229).** The certain estimate feeds the processor the LEFT count — exact only while no right key repeats (joined rows = Σ_k L_k·R_k). The only SOUND header-only bound is left × right; header + schema hold no uniqueness guarantee (an index manifest's `distinct_keys` is not a freshness claim, Lookup's `assert_unique` is per call), so a right side of ≤ 1 row is the only provably unique key. When the certain estimate fits, `RequestLimitFindings` adds a `possible` `MaxEstimatedMemory` finding (`joinFanOutFinding`, never a refusal) on `JoinRowsBound`: a categorical right key (the joined schema's `As + right_field`) bounds a key's matches by R − D + 1 — sound only if every dictionary entry occurs (derived / filtered / synth / shard-removed cohorts do not guarantee it); a composite key takes its smallest column bound; no dictionary → L × R. Its bound rides `LimitFinding.Details` `{join: 0, join_rows_bound, join_bound: right_key_dictionary | left_x_right}` beside a located finding's `request` / `stage` (`limits.Finding.Join` → `DetailsMap`; `locatedFindingsAt` merges). The runtime backstop: `openJoinStream`, after `NewHashJoinIterator` hashes the build side and BEFORE the first probe, reads `HashJoinIterator.MaxMatches` M and refuses `descx.JoinFanOutRefusal` — the estimate on L × M joined rows over a set `MaxEstimatedMemory`, the memory refusal's details + `join: 0`, `join_rows_bound`, `right_key_multiplicity`, `markLocated` so Compose / chain add `request` / `stage`; the preflight hook returns the request it judged (the Joins-stripped clone), `LimitInputs.JoinSpec` carries the spec. M ≤ 1 or Unlimited → nothing, byte-identical. The joined-row figure (`estimateMemory(…, rows)`, `limits.MemoryInputs.JoinedRows`) replaces records in every per-row term — buffered records and fan-out slots, per-value state, bucket / cell clamps, tests, matrices, point stores — never the payload (the left scan). **Shard archives (E8-S3):** `LimitInputs.ArchiveBytes` (predict: the archive bytes it was handed; the runtime: `Cohort.archiveBytes`, what `Open` read) replaces records × stride in the payload term when larger, modelled on the pre-U51 slurp (`Open` and the scan each read the whole archive; since U51 E1-S1 both read by random access, so the term over-counts until E1-S2 re-pins it); plus ONE `limits.SchemaDecodeBytes(canonical schema)` — the canonical entry, whatever the shard count; `Open`'s record-count peek (`Archive.PeekShardRecordCount`, E8-S4) and the scan (E8-S5) read each shard's schema LAYOUT-ONLY — dictionaries and group entry tables read past, never allocated — so neither is charged. **An anchor-opened shard** (`archive.pulse#shard.pulse`) charges its ARCHIVE's byte length the same way and no extra schema decode (the pre-U51 `OpenAnchor` read the whole archive; it now serves the shard as a section of it): the runtime sets `Cohort.archiveBytes` in `OpenAnchor`, predict reads `PredictOptions.AnchorArchiveBytes`, which the facade's `Predict` and the guidance roots (`Recommend`, `Explain`) set when they resolve an anchor; `PredictBytes` (bytes in hand, no anchor) cannot. And, on the per-shard parallel arm only (`ShardFanOut`, the twin of `Service.shouldFanOut`: ≥ 2 shards, `LimitInputs.ShardWorkers` resolving to ≥ 2, `mergegate.MergeRefusal` clear, no crosstab or join), every shard partial's buckets (`EstimateGroups` clamped by that shard's records, its records for an unknown grouper, 1 ungrouped) and a second records × 96 per value-state aggregation (the merge folds into one partial while the rest are live). `PredictOptions.ShardWorkers` carries `Options.ShardWorkers` (0 = `runtime.NumCPU` of the predicting process). Archive calibration (`TestArchiveMemory_EstimatedBytesRatio`, min of 3 sampled peaks, `ShardWorkers` 1 and 4): estimate / peak 1.35–1.85 (darwin/arm64 and linux/amd64) — a 4-shard archive whose shards each carry a 100,000-entry dictionary, and a payload-dominated 8-shard ~100K × p 50 matrix archive. Unknown record count (or a join's right count) → no estimate, no finding. The rich facet has its own estimate and pre-flight (`EstimateFacetMemory` / `FacetLimitRefusal`, `execution-modes.md` (Facet endpoints)). It is an UPPER bound by design — no filter selectivity, no field projection, every dictionary entry assumed — graded `certain` because predict and the pre-flight compute the identical figure from the identical header counts, never because it is exact. **Calibration** (`TestMemoryEstimate_Calibration`, `internal/service`, skipped under `-short`): `buildWideCohort` 95 fields × 200,000 records (stride 228 B), peak heap = the sampled `HeapAlloc` high-water mark above a post-GC baseline (never `B/op`), estimate read back as the runtime's own refusal figure; estimate ≥ peak on every arm, factor (estimate / peak, Apple M1 Max): buffered full width 1.49 (413 vs 278 MB), streaming 1.95 (154 vs 79 MB), streaming grouped 1.90, value-state stream 2.13, fused crosstab 1.76 (154 vs 87 MB), matrix 1.89, lookup join 1.34 (176 vs 131 MB), join build side 1.46 (738 vs 505 MB), a 1:4 join fan-out (50,000 × 95-field left, 64-row right, buffered, the backstop's figure) 1.20 (341 vs 284 MB), rich facet 1.33, grouped `TEST_T` 1.46, grouped `TEST_KRUSKAL_WALLIS` 1.48, rank matrix 1.38, and over `f.pulse` (every row selecting all 6 set members — the worst case the dictionary multiplier bounds) a `GROUP_SET_PER_ELEMENT` rank matrix 1.37 (p 3) / 1.59 (p 8) and a fan-out distinct count 3.06 (bound 3.5: the value-state model assumes every record distinct per bucket, loose here as on "value-state stream"); with field projection (default-on) the model cannot see the narrowing — buffered projected 4.94 (413 vs 84 MB), streaming projected 3.36, buffered crosstab 3.72 — so the documented ceiling is 2.5× unprojected and 6× projected. A schema with many more narrow fields or a GOGC above 100 can exceed it; a fan-out GROUPER cannot (the multiplicity above), nor a 1:N join past the backstop (which refuses on the measured multiplicity). `PredictResult.Matrices[].EstimatedBytes` moved in place to merge blocks × buckets × `accumulator_bytes` (`matrix-and-vectors.md`). Gates: `TestEstimateMemory_PerArm`, `TestRecordBytes`, `TestMergeBlocks`, `TestMergeBlockSizeMatchesLinalg` (`internal/limits`), `TestMemoryArm`, `TestEstimateMemory_Terms`, `TestFanOutMultiplicity`, `TestMatrixMemory_CountsRowBuffer`, `TestPredict_MatrixRowBufferFanOut`, `TestRequestLimitFindings_MaxEstimatedMemoryCertain`, `TestPredict_MaxEstimatedMemory`, `TestFacetLimitRefusal`, `TestJoinRowsBound`, `TestRequestLimitFindings_JoinFanOutPossible`, `TestJoinFanOutRefusal` (`internal/descriptor`), `TestEstimateMemory_JoinedRows` (`internal/limits`), `TestJoinFanOutBackstop_RefusesBeforeProbe`, `TestLimits_JoinFanOut_PossibleAndBackstop` (`internal/service`), `TestLimitsPreflight_MaxEstimatedMemoryRefusesBeforeDecode` (every host: serial streaming + buffered, crosstab, matrix, facet, plain join, joined crosstab — no cohort drained, the run AT the estimate drains), `TestMaxEstimatedMemory_DefaultReadsNoCount`, `TestMaxEstimatedMemory_ChainStage`, `TestMemoryEstimate_Calibration` (`internal/service`), `TestGroupedMatrices_FanOutRowStorePerBucket` (`internal/processing`: a rank matrix under the fan-out grouper keeps a row per selected member), `TestLimits_MaxEstimatedMemory_PredictCertainAndProcessRefuses` (root, every arm incl. grouped tier-1 tests, a shard-archive matrix and an archive under `ShardWorkers` 1 and 2: identical error on predict, MCP and the run); archives: `TestSchemaDecodeBytes_BoundsDecode` (`internal/limits`), `TestEstimateMemory_ArchiveTerms`, `TestShardFanOut` (`internal/descriptor`), `TestShardFanOut_PredictMatchesRuntime`, `TestArchiveMemory_EstimatedBytesRatio`, `TestMaxEstimatedMemory_RefusesArchiveOverCap` (`internal/service`), `TestLimits_MaxEstimatedMemory_ArchiveShardWorkers`, `TestLimits_MaxEstimatedMemory_AnchorChargesArchive` (root; the anchored shard is also a case of `TestLimits_MaxEstimatedMemory_PredictCertainAndProcessRefuses`), `TestPeekShardRecordCount_SkipsDictionaries` / `_LayoutMatchesFullDecode` (`internal/encoding`).
