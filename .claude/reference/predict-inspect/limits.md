# Predict / Inspect — Limit findings and the memory estimate

Per-topic slice of the predict-inspect reference (limit findings on every predict root, the memory estimate). Index: `.claude/reference/predict-inspect.md` — load it first, then only the slice(s) your change touches.

## Limit findings

**`PredictResult.LimitFindings`** (`limit_findings`, `omitempty`, `[]descriptor.LimitFinding {limit, configured, estimated, grade, details}`) lists every instance resource limit (`pulse.Limits`, read off `PredictOptions.Instance.Limits()`) that a figure predict computes from request + schema exceeds.

- **Grades.** `certain` = the exact figure the runtime sees; it also adds the runtime's `PULSE_LIMIT_EXCEEDED` error, so `Valid` is false. `possible` = an upper bound; reported only, never refuses.
- **One rule, not a predict-only check:** `internal/descriptor.RequestLimitFindings` (`limits.go`) over the leaf `internal/limits` (`TestLimits_ImportBoundary`). The runtime calls it as `LimitRefusal` from `Service.limitsPreflight` right after the field-reference check on every Request arm (serial, crosstab, join, joined crosstab, chain stages), so a certain breach is refused with the identical code, message and details before any record decodes. Parity gate: `TestLimitsPredictRuntimeParity`.
- **Limits judged:** `MaxGroups` (`possible` — `EstimateGroups`, the PRODUCT of each grouper's bound, clamped by the header record count unless a grouper fans out; any grouper of unknown cardinality yields no finding), `MaxCrosstabCells` (`possible` — rows × columns of each axis's bound), `MaxEstimatedMemory` (`certain`, opt-in; next section), `MaxMatrixDim` (each matrix's resolved member count), `MaxJoinBuildRows` (`certain` — the right side's header count via `PredictOptions.RecordCounter`, never `Cohort.RecordCount`; the runtime also refuses it in `openJoinStream` before the build decodes, plus an in-loop backstop), `MaxComposeSlots` / `MaxChainStages` (fan-out counts at the Compose / chain entry, explicit + sweep + banner slots, via the same `sweep.Expand` preflight), `MaxMMMGeos` / `MaxMMMDrawValues` (`REG_MMM_BAYES`).
- **Inputs beyond request + schema** arrive on `LimitInputs` (header record count, shard counts, join right rows, extension and arm facts). The header count is read only when `MaxEstimatedMemory` is set — a `possible` finding needs none.
- **The other roots** carry `LimitFindings` graded the same way; `LimitFinding.Details` locates a slot's / stage's finding with the key its located error carries (`request`, `fit`, `stage`). Compose slots are judged on each slot cohort's counts via `PredictOptions.CohortCounter` (the runtime pre-flight's own counter). Chain stages ≥ 1 have an unknown input count, so no memory estimate and unclamped group bounds. Facet: `FacetLimitFindings` (a `possible` `MaxGroups` from the largest faceted dictionary + a `certain` `EstimateFacetMemory`).

## The memory estimate

**The memory estimate (`MaxEstimatedMemory`)** is `internal/descriptor.EstimateMemory`: pick the arm the engine dispatches (`MemoryArm`: fused crosstab iff the fusion rule accepts; else buffered for a crosstab; else streaming iff streamable; fan-out folds stream), then evaluate the leaf model `internal/limits.EstimateMemory` (`internal/limits/memory.go` — read it for the formula). It is an UPPER bound by design (no filter selectivity, no projection, every dictionary entry assumed), graded `certain` because predict and the pre-flight compute the identical figure from identical header counts, never because it is exact. Unknown record count → no estimate, no finding.

**The bound must be SOUND.** Every term charges what the run can actually hold, proven or measured as a ceiling. A term that under-charges lets a run past a limit the caller set; one that over-charges only refuses early. When you add an operator, arm or cohort shape, add its charge and its pin in the same change.

- **Shape of the model:** base 16 MiB + payload (3 × records × stride: heap copy + GC headroom) + join right side + matrix state + per-value state (distinct / mode / frequency families, or an extension declaring `ValueState`) + tests + buckets × (state + output) + per-arm terms (buffered records and derived columns, crosstab cells / margins / dense grid, parallel partials). `limits.RecordBytes` is one buffered record at FULL schema width.
- **Per-aggregator bucket state and output** come from the measured table `limits.aggregatorBytesTable` (weighted / unweighted; components on / off). PINNED, never calibrated: `TestGroupMemory_AggregatorStateTable` builds a grouped partition of EVERY registered built-in as the reducers do and asserts each entry ≥ the live heap it adds; a built-in with no entry fails it. Extension aggregators and buffered-only built-ins take the fixed 256 / 512 B ceilings. `AGG_VEC_*` add their blocked-merge fragments (`limits.VectorAggregationBytes`).
- **Components-off output** follows `EffectiveDisableComponents` — the runtime components gate's rule — so a `return` never changes the charge.
- **Crosstab cells:** per measure, every grid cell and margin slot costs `limits.CrosstabSlotBytes`, every axis key `limits.CrosstabAxisKeyBytes`, each auxiliary margin aggregation `limits.CrosstabAuxSlotBytes` (nothing with components off). **Dense grid:** both arms emit rows × cols, so every position past the populated cells costs `limits.CrosstabGridPositionBytes`, the grid capped by the effective `MaxCrosstabCells` (both arms refuse a larger grid first; `RequestLimitFindings` fills the cap so predict and pre-flight cap identically). Pinned: `TestCrosstabMemory_CellChargeTable`, `TestCrosstabMemory_GridPositionBytes`.
- **Group bound** (`memoryGroupBound`): per grouper the min of the schema-known bound, the **value-width bound** (a key that is a function of one stored word ≤ 32 bits mints at most 2^bits keys — `valueKeyBound`; provably attained by `TestLimits_ValueWidthBoundCoversEveryKey`) and the **recorded distinct-count bound**; multiply; clamp by records × fan-out.
- **Recorded distinct counts** (archives only, only when `MaxEstimatedMemory` is set): the `_schema.pulse` DIST trailer's `FieldBound` (sum of per-shard exact counts) through ONE reader both sides share, `ArchiveDistinctOf`. It falls back to the other bounds — never a predict failure — on no / newer / malformed trailer, a trailer not naming exactly the archive's shards, a count its shard's identity does not vouch for, any shard not exact, a `GROUP_DATE` under a per-row zone field, a join, a single file or anchored shard. Coverage: `TestLimits_DistinctBoundCoversEveryKey`. An index manifest's `distinct_keys` is rejected as a bound (its freshness is a stat pair and the figure a per-shard sum). `MaxGroups` keeps `EstimateGroups`.
- **Fan-out** (`FanOutMultiplicity`): the most buckets one record lands in — the product over `GROUP_SET_PER_ELEMENT` positions of each set's dictionary (or include list) size. It scales per-value state, a buffered matrix's row store and buffered test values.
- **Tests:** one instance per tier-1 test per bucket, each keying up to its level counts but never more than the rows it admits; a non-streamable test keeps records × fan-out × its value columns; an extension test charges instances only.
- **Join fan-out.** The certain estimate uses the LEFT count — exact only while no right key repeats. The only sound header-only bound is left × right (header + schema hold no uniqueness guarantee). When the certain estimate fits, a `possible` finding reports `JoinRowsBound` (`details.join_rows_bound`, `join_bound`: `right_key_dictionary` — R − D + 1 matches per key, sound only if every dictionary entry occurs — or `left_x_right`). The runtime backstop: after hashing the build side and BEFORE the first probe, `openJoinStream` reads the max key multiplicity M and refuses `descx.JoinFanOutRefusal` if the estimate on L × M joined rows exceeds the limit; M ≤ 1 or Unlimited changes nothing.
- **Shard archives:** the archive is never resident (central directory + one shard at a time), so the payload term reads the LARGEST shard's records, plus `directoryCopyFactor` × the central-directory bytes, plus one canonical `limits.SchemaDecodeBytes` (shard schemas are read layout-only). Per-row state still counts every record. An anchor-opened shard is charged as the single file it is. On the parallel arms (`ShardFanOut` / `DecodeFanOut`, twins of the runtime's dispatch gates — `TestShardFanOut_PredictMatchesRuntime`, `TestDecodeFanOut_PredictMatchesRuntime`) the live partials are charged: at most `limits.ShardMergeWindow(workers)` shard partials, under a set limit the largest window that fits (`descx.ShardMergeWindow`; the runtime runs that window). `PredictOptions.ShardWorkers` / `DecodeWorkers` / `DecodeMappable` carry the instance's settings (mappable is asked only when a memory limit is set, so an unbounded predict allocates nothing more).
- **Calibration** (`TestMemoryEstimate_Calibration`, heavy; `TestArchiveMemory_EstimatedBytesRatio`): estimate ≥ measured peak on every arm. The documented ceiling is estimate / peak ≤ 2.5× unprojected and ≤ 6× with default projection (the model cannot see projection narrowing). A schema with many more narrow fields or GOGC above 100 can exceed it; a fan-out grouper or a 1:N join past the backstop cannot. Rebaseline figures live in the tests and `BENCHMARKS_BASELINE.md`, not here.
- **Predict ≡ runtime:** root `TestLimits_MaxEstimatedMemory_PredictCertainAndProcessRefuses` (every arm; identical error on predict, MCP and the run) and `TestLimitsPreflight_MaxEstimatedMemoryRefusesBeforeDecode` (every host refuses before draining). The rich facet has its own estimate (`EstimateFacetMemory` / `FacetLimitRefusal`, `execution-modes.md` (Facet endpoints)).
