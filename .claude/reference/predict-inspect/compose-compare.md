## Nested-model comparisons (U65 E3-S3)

Right after `OptimizeRefusal` predict runs `regcompare.Check` (`internal/regcompare` — the ONE rule `Service.compose` / `composeParallel` call at the same point, with the instance default weight for the probability-weight refusal): names, both sides regression fits of one type (`REG_OLS`, `REG_GLM`, `REG_MULTINOMIAL` — U68 E5-S2, equal `reference` or `reference_differs` — or a type whose declaration carries `Compare` — `descx.ComparableRegressions`, the predicate both sides hand it off the same instance view; U68 E5-S1), the restricted terms nested in the full fit's, the fit requests equal but for the regression's predictors / intercept / reporting knobs, the test against the family and weight. A refusal (`PULSE_COMPARISON_INVALID`) returns at once; on success `ComposeValidationResult.Compare` (`descriptor.ComparisonSummary {name, restricted, full, test, distribution, terms}`, `omitempty`; the resolved test and distribution the run reports). Nothing is fitted; unequal rows are run-only (`PULSE_COMPARISON_ROWS_DIFFER`, fails alone). A `from_sweep` side (U69 #643) is judged against every sweep slot that could win (`regcompare.CheckSweep`, the same slots both sides expand): all refusing is the refusal, else the summary's `unresolved {slots, refused, varies}` lists what the winner decides — the runtime re-judges it (`Rebind`; a refusal fails the entry alone). Vector fits: member-wise (`members`). Parity: `TestCompareSweep_*`, `TestCompareVector_*` (root). Parity: `TestCompare_PredictMatchesRuntime`, `TestCompare_OrdinalPredictMatchesRuntime`, `TestCompare_MultinomialPredictMatchesRuntime`, `TestExtensions_RegressionCompareRefusalsPredictMatchesRuntime`. Two SEM fits (U69 #643, `regcompare/sem.go` `checkSEM`) are judged on their requests alone — `kind_mismatch`, `test_unsupported`, `request_mismatch` (everything but the model knobs and the reporting / solver params), `same_model`, `observed_differ` (each written model parsed by `internal/sem`, no record) — and summarised `lrt` / `chisq` with empty `terms`; their df difference and conventions are the fits', so `df_not_positive` / `conventions_differ` are run-only and fail the entry alone (like unequal rows). Parity: `TestCompareSEM_PredictMatchesRuntime` (`internal/integration`).
