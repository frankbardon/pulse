# Predict / Inspect — Inspect, byte-level inspect and predict, predicting the non-Request roots, suggested weight, CountRecords

Per-topic slice of the predict-inspect reference (Inspect, byte-level inspect and predict, predicting the non-Request roots, suggested weight, CountRecords). Index (preamble + section map): `.claude/reference/predict-inspect.md` — load it first, then only the slice(s) your change touches.

## Inspect — the envelope is the only way to see a truncated tail

`descriptor.Inspect` reads only `encoding.ReadHeader` + `encoding.ReadSchema`, never a record. Dictionaries are truncated to `DefaultDictionaryLimit` (100) unless `FullDict: true`. **The contract is "header + schema + sidecar metadata, never records"** (amended at weighting-descriptive E4-S3): the path-based facade also reads the cohort's SPSS metadata sidecar for the suggested weight — see "Suggested weight" below. Metadata beside the cohort is not a record.

`InspectResult.RecordCount` is derived from the file LENGTH, never by reading a record — the cumulative per-shard sum for an archive, that shard's own count for an `archive.pulse#shard.pulse` anchor, and `payload_bytes / record_stride` for a single file.

**`Pulse.Inspect` returns the RESULT only and drops `env.Warnings` on the floor.** `Pulse.InspectEnvelope(ctx, path, *descriptor.InspectOptions)` returns the ENVELOPE and is the only way to reach the `FullDict` knob or the truncated-tail warning.

**Every `pulse cohort inspect` mode reads through the facade.** The `--json` / `--full-dict` branch used to `os.ReadFile` the raw argument itself, which bypassed the injected `afero.Fs` and silently lost anchor resolution — an anchor that inspected fine as text returned `data:null`. A leaf needing options or warnings takes the envelope sibling, never its own read.

**`pulse_inspect` carries the warnings too.** `mcp.InspectOut` EMBEDS `descriptor.InspectResult` and adds an `omitempty` `warnings []*descriptor.EnvelopeEntry` slot; `HandleInspect` reads `InspectEnvelope`, never `Inspect`, for the same reason the CLI does — a floored `record_count` is indistinguishable on the wire from an honest one, so a tool routed through the result-only wrapper left an agent unable to see a truncated tail at all. Embedding keeps every pre-existing key at the top level and a clean read emits no `warnings` key, so the tool's wire form is byte-identical for the ordinary case. The entries are coded `{code, message, details}` (not strings) so the code is usable with `pulse_errors_lookup`, and `details` carries `record_stride` + `trailing_bytes`.

## Byte-level inspect and predict live on the instance

`Pulse.InspectBytes(ctx, data, *descriptor.InspectOptions)` and `Pulse.PredictBytes(ctx, data, *Request)` are the only public byte-level entry points; both return the envelope WHOLE (the result-only-wrapper trap above does not recur). `descriptor.Inspect` / `descriptor.Predict` sniff the zip magic themselves, so one call covers a single file and a whole shard archive. **An archive is read by random access when the reader is an `io.ReaderAt`** (`sniffArchive`, `internal/descriptor/cohort_source.go`; the facade hands them the open `afero.File`): the zip central directory, the canonical `_schema.pulse` entry and each shard's header — `PeekShardRecordCount` counts a stored shard from its central-directory size, never reading its records — so `Pulse.Predict` / `Inspect` / the guidance surfaces never read a record of an archive; only `PredictBytes` / `InspectBytes` (bytes in hand) buffer it. The memory estimate still charges the archive's length (`ArchiveBytes`, the bytes the runtime `Open` reads), however predict read it (U35 #248). **`PredictBytes` fills every `PredictOptions` field from the instance** — the extension snapshot, `Options.Strict`, `Options.EchoRequest` — because the free functions it replaced left the snapshot to the caller and every nil caller silently treated an embedder-registered operator as unknown. `Pulse.Predict` (path-based, result-only) still passes the snapshot, not `Strict` / `EchoRequest`. **Both pass the instance feature set (`PredictOptions.Instance`)**, so a name a feature profile hides predicts exactly as a never-registered one — every type-keyed predict rule reads the operator's route (`opRoute`), see `feature-profiles.md` (Predict hiding). Gated by `TestPredictBytes_ExtensionOperatorIsKnown`, `TestPredictBytes_HonoursStrict`, `TestPredictBytes_HonoursEchoRequest`, `TestInspectBytes_SurfacesTruncatedTailWarning`.

## Predicting the non-Request roots

`Pulse.PredictCompose(ctx, *ComposedRequest)`, `PredictFacet(ctx, *FacetRequest)` and `PredictChain(ctx, *ChainRequest)` (root `predict_roots.go`, TODO #246) are the facade over the validators `ValidateComposeWithOptions` / `ValidateFacetWithOptions` / `ValidateChainWithOptions`, which live in `internal/descriptor`, so the import ban holds by construction. Each returns the envelope WHOLE (`Data` = the root aliases `ComposePredictResult` / `FacetPredictResult` / `ChainPredictResult` over the `internal/descriptor` `*ValidationResult` types; `Valid` mirrors `env.Errors` emptiness), so a `--json` caller emits it verbatim and an MCP caller keeps `env.Data`. The returned error is reserved for a cancelled ctx, a nil facet / chain request or cohort (`SERVICE_VALIDATION`) and an unreadable cohort (`DATA_FILE`; `ENCODING_INVALID` for a malformed header or schema); a nil Compose batch is the validator's own enveloped `SERVICE_VALIDATION`, and so is an EMPTY one (no `requests`, no `sweep` — the runtime's first refusal in `Service.expandCompose`, same message, TODO #299).

- **Options.** The facet / chain cohort opens through `openGuideCohort` (the open handle, never a record: a single file's header + schema; a shard archive's zip central directory, canonical schema entry and shard headers by random access — the validators judge it on the canonical schema and per-shard header counts (`readCohortHead`, `internal/descriptor/cohort_source.go`), as `Predict` does; an anchor's one entry; U35 #248, `TestArchivePredict_ReadsHeadersOnly`, `TestPredictRoots_ArchiveMatchesSingleFile`) and validates with `predictOptions(ctx, sidecarFacts(path))`. Compose runs with `composePredictOptions` = `predictOptions(ctx, sidecarFacts{})` + `SidecarLoader` (`Pulse.sidecarLoader` over `sidecarFacts`), so each slot cohort's sidecar feeds that slot's advisories. **These two helpers are the ONLY place the facade builds non-Request predict options** — `Explain`'s checks call the same `composePredictOptions` / `predictCohortRoot`; never re-grow a SidecarLoader closure.
- **Strict and EchoRequest (U35 E3-S4, #255).** The three methods set `PredictOptions.Strict` / `EchoRequest` from the instance (`Pulse.predictRootOptions`; `Explain`'s checks do not) and each validator ends in `finishPredictRoot` (`internal/descriptor/predict_root_finish.go`): Strict promotes EVERY warning the root collected into an error at the ROOT envelope (Valid false), so the per-slot / per-stage body call `validateRequestBodyAt` keeps Strict off and drops its own warnings — nothing is promoted twice; advisories never move. The root warning sources: a Compose slot's or fit's and chain stage 0's `PULSE_VECTOR_METRIC_UNSUITED` (`addMetricUnsuitedAt`, located `details.request` / `details.fit` / `details.stage` — the runtime's Process warns with it and under Strict refuses with the first issue, located the same way; a later chain stage runs no such check), the whole-chain `PULSE_OVERLAY_CHAIN_STAGE_SHAPE_DIVERGENT` (the runtime never promotes that layer warning — Strict predict is stricter there, as with description quality), and the facet's own warnings. EchoRequest sets `env.Request` to the root's normalized request, the form the runtime echoes: Compose — the EFFECTIVE batch (sweep expanded, its overlays appended, no `sweep`) with every slot `for_each`-expanded and defaults-resolved where predict reached it (`composeEcho`, = `ComposedResponse.NormalizedRequest`); chain — cohort, every stage defaults-resolved, the whole-chain overlays (`chainEcho`, = `ChainResponse.NormalizedRequest`); facet — the request as passed. `data.request` stays as written. Gates: `TestPredictRoots_StrictEscalatesWarnings`, `TestPredictRoots_StrictSlotWarningMatchesRuntime`, `TestPredictRoots_EchoRequest` (runtime-echo parity, sweep included).
- **Observed** as `observe.OpPredict` (one operation per call; a Compose predict fires no child per slot); the managed-import TTL slides like `Predict` (each slot cohort for Compose).
- **Profiles.** Predict is a core surface, so the methods carry no `features.go` row and are never gated as a whole; the instance's hiding reaches inside them through `PredictOptions.Instance` (slot gate, routed operator / overlay kind checks). The hidden-name parity harness drives them (`feature_parity_predict_test.go`: `PredictCompose`, `PredictCompose/overlays`, `PredictChain/stage0`, `PredictChain/overlays`, `PredictFacet`; the malformed and named-table sweeps run them too). **The Compose validator judges every slot like `Predict` (U35 E3-S1)** — each slot's runtime-entry checks (join count, matrix host, `return`, zones, field references, weights, ATTR_FORMULA), then the Process-predict request body `validateRequestBody` (`internal/descriptor/predict.go`: operator Type and name, per-operator params, features, accepted types, windows, tests, sort, crosstab cell / margin aggregations, `ValidateOverlays`, `ValidateLabels`), through `validateRequestBodyAt` with each error located `details.request` (fits: `details.fit`; slot warnings dropped, Strict not applied). So a hidden or unknown slot operator is refused exactly as `Predict` refuses it; the harness's `PredictCompose` cells share `Predict`'s vacuous set. Schema-less (no `SchemaLoader`, unreadable cohort) the body is left to the runtime. Pinned by `TestComposePredict_SlotVerdictMatchesProcessPredict` — the parity harness: Process predict and the one-slot compose verdict agree on a shared request set, so a body rule added to `Predict` alone fails it. **The chain validator judges every stage the same way (U35 E3-S2, #254)** — after a stage's field references, weights and ATTR_FORMULA pass, `validateRequestBodyAt(…, "stage", i)` over the stage's input schema (stage 0: the cohort's; later: the synthesised one), so a stage's operators, accepted types, own overlays and label bindings are refused with the runtime's code and message, located `details.stage` (a joined stage 0 whose right side does not load skips it). The runtime locates them identically: **every coded refusal a Compose slot (serial and FailFast parallel) or a chain stage raises carries `details.request` / `details.stage`** (`internal/service/located.go` `locate`, which keeps the error's own chain), not only the entry-pass refusals. Gates: `TestChainPredict_StageBodyMatchesRuntime`, `TestComposePredict_SlotBodyMatchesRuntime` (runtime location required). **One label set (#201b):** the augment-sibling collision set is `descriptor.OutputLabels` (aggregation, attribute, group-key, window and feature output columns, default labels included) on both predict and the runtime's `validateProcessLabels` / auto-label pass — `TestLabelCollision_PredictMatchesRuntime`. **One error per unknown series `field` (#436):** compose stops at the first slot (reference, then targets), chain at the first stage (target, then ref), as the runtime does.
- **Slot and stage overlays (U30 E7-S4).** `PredictCompose` judges a slot's own `Request.Overlays` through the request body (`ValidateOverlays`, so `overlayhost.ScalarSpecRefusal` and every Request-host rule), located `details.request` (U35 E3-S1, TODO #400; it reversed the U30 E7-S4 deferral). `PredictChain` DOES judge every stage's own overlays — the wrong-slot, wrong-shape and shared Ref / Scope rules, through `ChainStageOverlayRefusal`, the pre-pass the chain runtime runs before any stage, located by `details.stage` (`.claude/reference/execution-modes/overlays-matrix-kinds.md` (Spec refusals — one rule per host)).
- **CLI and MCP (E4-S2).** `pulse api predict-compose` / `predict-facet` / `predict-chain` (`internal/cli/api_predict_roots.go`) take `--request FILE`, `--json`, `--strict` and `--echo-request` (the instance options, U35 #255), write the envelope verbatim, route a facade error through `writeCodedErrorEnvelope` and exit 1 in text mode when invalid. MCP `pulse_predict` keeps a bare `types.Request` root byte-identical and accepts ONE alternative root `composed` / `facet` / `chain` alone (`strictPredictDecode`, `internal/mcp/tools.go`: each body through its own tool's strict decode and MCP `return` default; any other root key beside it is `SERVICE_VALIDATION`); `PredictOut` embeds `*PredictResult` for a bare request and otherwise carries the verdict under the sent key; either way the coded `errors` / `warnings` ride beside it (`omitempty`; the bare arm's are `PredictResult.Errors` / `Warnings`, which `Pulse.Predict` sets from its envelope and which marshal as `-` with the result — U35 #256). Unlike the facade, these entries ARE gated on the capability owning the shape (`capability:compose` / `facet` / `process_chain`): the manifest commands bind to it in `commandBindings`, a hidden root's key is refused as `PULSE_REQUEST_UNKNOWN_FIELD`, and the bound `pulse_predict` schema (`buildPredictSchema`, `internal/mcp/bind.go`) drops its property — the bound schema requires no root key. Pinned by `TestPulsePredict_*`, `TestBindForInstance_PredictAdvertisesRoots` (`internal/mcp`), `TestAPIPredictRoots*` (`internal/cli`).

- **Sweeps (U40).** `ValidateComposeExpanded` (behind `ValidateComposeWithOptions`) follows the runtime's entry order: a hidden `sweep` refused first, then `sweep.Expand` with the `MaxComposeSlots` preflight, then the slot gate and the label-collision check over the EFFECTIVE request (explicit slots, then sweep slots) — the collision check now runs for every overlay-free batch, sweep or not, as the runtime's does. Every expanded slot is predicted like a hand-written one; `ComposeValidationResult.Sweep` (`descriptor.SweepSummary {axes, mode, expanded_count, labels}`, `omitempty`) is set whenever the sweep passes `sweep.Validate`, also on a refused batch (labels only once expanded). The facade slides the managed-import TTL of every effective slot cohort. Not payload-reachable: only the API golden moves.
- **Banners (U47 #326).** The same entry order with `banner.ExpandCompose` in place of `sweep.Expand`: a hidden `banner` (or `sweep`) refused first, then `banner.Validate` (`PULSE_BANNER_INVALID`, the one rule set the runtime runs), then the sweep expansion whose `MaxComposeSlots` preflight sees explicit + sweep + banner slots, then the slot gate and every expanded banner slot predicted like a hand-written crosstab slot. `ComposeValidationResult.Banner` (`descriptor.BannerSummary {sections, groups, total, expanded_count, labels}`, `omitempty`) is set whenever the banner passes `banner.Validate`, also on a refused batch. Parity: `TestComposeBanner_RefusalsMatchPredict`, `TestComposeBanner_PredictSummary`.
- **Item fan-out (`for_each`, U41).** `Predict` runs the slot gate (a hidden `for_each` is `PULSE_REQUEST_UNKNOWN_FIELD` at the item, `nestedForEachRefusal`), then `ExpandRequestItems` (`internal/descriptor/for_each.go` over `sweep.ExpandItems` — the ONE expansion `Service.process` / `materialize` / `ProcessChain` also call) with the `MaxDerivedColumns` preflight BEFORE any item renders; a refusal returns at once (Valid false, the coded error, and for a limit breach the single Certain `LimitFindings` entry), as the runtime never gets further. ## Suggested weight — sidecar metadata, never records

`InspectResult.SuggestedWeight` / `PredictResult.SuggestedWeight` (`suggested_weight {field, source: "spss_sidecar", kind: "probability"}`, additive `omitempty`) name the weighting variable the cohort's SPSS metadata sidecar (`cohort.pulse.spss.json`, `payload.weight.variable`) records. Contract: `.claude/reference/weighting.md` (SPSS suggestion).

- **Who reads what.** The FACADE reads the sidecar — `Pulse.sidecarWeightVariable` (root `weight_suggest.go`) through `spss.LoadSidecar` on the instance `afero.Fs` — and hands the variable NAME down: `descx.InspectWith(rs, opts, InspectMetadata{WeightVariable, Instance})` for inspect, `PredictOptions.SuggestedWeightVariable` for predict. `internal/descriptor` never opens a file, so `TestPredictNoExecutionImports` and "predict.go reads only header + schema" both hold. The one judgement is `descx.SuggestWeight(schema, variable, inst)`: nil unless the variable is a column of the schema just read (the canonical schema for an archive; the COHORT schema, not a joined one, for predict) of a weight-capable type (`IsWeightFieldType`) and the instance offers `capability:weighting`.
- **Every failure is silent** — no suggestion, never a warning or error: no sidecar, a malformed / foreign / unknown-version one, a STALE one (the size+mtime fingerprint `LoadSidecar` checks, which `pulse export spss` refuses on), a variable the schema no longer carries or cannot weight by, an anchor path (`archive.pulse#shard.pulse` — a sidecar sits beside a whole cohort file), and the byte-level `InspectBytes` / `PredictBytes` (no path, so no sidecar — `pulse api predict` goes through `PredictBytes` and so never echoes).
- **Predict echoes it as DATA only while no slot resolves a weight field** (`ResolvedWeight.Field` empty everywhere — no weight named, or every slot `weight: null`); never a warning, so `Options.Strict` cannot turn it into an error. It is never applied, by `DefaultWeight` or otherwise.
- `descriptor.InspectResult` / `PredictResult` are not payload-schema-reachable: no payload golden moves; `internal/apigolden` does (additive).

Gates: `TestSuggestedWeight_*` (root: inspect + envelope JSON, absent / stale / malformed / unweighted silent, predict echo, never auto-applied, hidden with `capability:weighting`), `TestSuggestWeight_Rule`, `TestInspect_SuggestedWeightFromMetadata`, `TestPredict_SuggestedWeightIsDataNotWarning`, `TestHandleInspect_SuggestsTheSPSSWeight` (MCP, incl. hidden), `TestCliCohortInspect_SuggestedWeight`.

## Inspect — parent groups are header-only too

For a cohort newer than `0x01`, `InspectResult` adds `layout` (`pulse_format_version`, physical vs logical record stride), `groups` (one `InspectGroup` per group in file order) and a per-field `group: {group, key, kind}` marker. All three are `omitempty` and absent for `0x01`, so a `0x01` envelope is byte-identical to before (`inspect.json` unchanged; `inspect_grouped.json` pins the grouped shape). **Every figure is header + schema + file length:** the entry count is in the schema block and the record count is the SAME `RecordCountForPayload` floor, so `ratio = record_count ÷ entry_count` needs no scan — `TestInspect_GroupFiguresReadNoRecord` garbles every record byte and asserts identical output. The numbers come from `encoding.AssessGroup` and the verdict from `GroupViability.Finding`, the functions the import gate calls, so inspect and `ImportReport.Groups` cannot disagree over the same file (`TestInspect_GroupFiguresMatchImportReport`); inspect judges at `DefaultDedupRatioFloor` because the file does not record the floor it was imported under. A low verdict is a FIGURE, never an envelope warning — `pulse_inspect`'s `warnings` stay header-read diagnostics. `dictionary_bytes` is `len(Group.Entries)`, the resident cost. Labels come from `internal/encoding.GroupSpecOf(schema, g)` — the format has no group name or declaration ordinal, so they number groups by file position. The archive arm reports no groups: grouped shards are refused at archive build, so the case is unreachable today. The facade parity suites compare inspect through `logicalInspect`, which strips exactly these three additions.

## Inspect — vector fields are header-only too

A `vec_f32` / `vec_f64` field adds `InspectField.Vector` (`descriptor.InspectVector`, `omitempty` — absent on every other field, so a vector-free envelope is byte-identical): `dim`, `kind` (omitted when undeclared), `scale_min` / `scale_max` (both or neither) and `labels` — a `DictionaryInfo` truncated by the SAME rule as a dictionary (`truncatedEntries`: `DefaultDictionaryLimit`, `DictionaryLimit`, `FullDict`), omitted when the field declares none. Every figure is the schema's VECTORS section (`Schema.Vector(i)`), so it is header-only: `TestInspect_VectorFieldReadsNoRecord` garbles every record byte and asserts identical output. A vector field with no description synthesizes `Vector field: <name> (<dim> elements)`. The CLI text mode prints a `vector:` line (dim, kind, scale) and a `labels:` line; `pulse_inspect` carries the block through `Pulse.InspectEnvelope` unchanged (`TestVectorField_InspectSurfaces`, single file and shard archive). Not payload-reachable: `payload-schema.json` is untouched; the public API golden gains the type.

## CountRecords — one floor division, two observability contracts

`pulse.CountRecords(ctx, path) (uint64, error)` returns the record total without decoding the payload. Single-file: `(size − header − schema) / record_stride`. Shard archive: the zip central directory + the `_schema.pulse` SHRD trailer's `AggregateRecordCount`. Anchor: the named shard's own count.

**The single-file floor division exists ONCE, at `encoding.Schema.RecordCountForPayload`, which `descriptor.Inspect` calls too.** Identical arithmetic written twice is one edit away from two different counts over the same bytes, and nothing on either wire says which arm produced the number.

**The arms differ in OBSERVABILITY and only there, deliberately.** `Inspect` has an envelope and raises the `ENCODING_INVALID` truncated-tail warning naming the leftover bytes. `CountRecords` has no warning channel and floors SILENTLY, because it feeds the parallel-decode eligibility gate as well as the facade, and a half-written trailing record must not stop a cohort that still processes from reporting its whole-record count. **Do not close that gap by making `CountRecords` error.**
