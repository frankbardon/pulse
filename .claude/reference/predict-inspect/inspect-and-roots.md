# Predict / Inspect — Inspect, byte-level inspect and predict, predicting the non-Request roots, suggested weight, CountRecords

Per-topic slice of the predict-inspect reference. Index: `.claude/reference/predict-inspect.md` — load it first, then only the slice(s) your change touches.

## Inspect — the envelope is the only way to see a truncated tail

`descriptor.Inspect` reads only `encoding.ReadHeader` + `encoding.ReadSchema`, never a record. **The contract is "header + schema + sidecar metadata, never records"**: the path-based facade also reads the SPSS sidecar for the suggested weight (below). Dictionaries are truncated to `DefaultDictionaryLimit` (100) unless `FullDict: true`.

`InspectResult.RecordCount` is derived from the file LENGTH — the per-shard sum for an archive, the shard's own count for an anchor, `payload_bytes / record_stride` for a single file.

**`Pulse.Inspect` returns the RESULT only and drops `env.Warnings` on the floor.** `Pulse.InspectEnvelope(ctx, path, *descriptor.InspectOptions)` returns the ENVELOPE and is the only way to reach `FullDict` or the truncated-tail warning. A floored `record_count` is indistinguishable on the wire from an honest one, so any surface that must show a truncated tail reads the envelope.

**Every `pulse cohort inspect` mode reads through the facade.** A leaf needing options or warnings takes the envelope sibling, never its own `os.ReadFile` — that bypasses the injected `afero.Fs` and loses anchor resolution.

**`pulse_inspect` carries the warnings too.** `mcp.InspectOut` EMBEDS `descriptor.InspectResult` plus an `omitempty` `warnings` slot of coded `{code, message, details}` entries (`details` carries `record_stride` + `trailing_bytes`); `HandleInspect` reads `InspectEnvelope`. A clean read emits no `warnings` key, so the ordinary wire form is unchanged.

## Byte-level inspect and predict live on the instance

`Pulse.InspectBytes(ctx, data, opts)` and `Pulse.PredictBytes(ctx, data, *Request)` are the only public byte-level entry points; both return the envelope WHOLE. `descriptor.Inspect` / `Predict` sniff the zip magic themselves, so one call covers a single file and an archive.

- **An archive is read by random access when the reader is an `io.ReaderAt`** (`internal/descriptor/cohort_source.go`; the facade hands the open `afero.File`): central directory, canonical `_schema.pulse` and each shard's header (counted from its central-directory size). So path-based predict / inspect / guidance surfaces never read an archive record; only the byte-level entry points buffer it. The runtime opens archives the same way (`internal/service/archive_open.go`), never `afero.ReadFile`.
- **The memory estimate charges an archive its central-directory bytes and its largest shard's payload, never its length**, however predict read it.
- **`PredictBytes` fills every `PredictOptions` field from the instance** — the extension snapshot, `Options.Strict`, `Options.EchoRequest` — because a nil snapshot silently treats an embedder-registered operator as unknown. `Pulse.Predict` (path-based, result-only) passes the snapshot but not `Strict` / `EchoRequest`.
- **`Pulse.PredictEnvelope(ctx, *Request)` is the path twin of `PredictBytes`:** `Predict`'s header-only read and sidecar facts, `PredictBytes`' `Strict` / `EchoRequest` and whole envelope; a read failure is a returned error. `pulse api predict` uses it (reading the cohort whole would make an archive resident and anchors unreadable). Gates: `TestPredictEnvelope_MatchesPredictBytes`, `TestPredictEnvelope_ReadsHeaderOnly`.
- **Both pass the instance feature set (`PredictOptions.Instance`)**, so a name a feature profile hides predicts exactly as a never-registered one — see `feature-profiles.md` (Predict hiding).

## Predicting the non-Request roots

`Pulse.PredictCompose`, `PredictFacet`, `PredictChain` and `PredictMaterialize` (root `predict_roots.go`, `materialize.go`) are the facade over `internal/descriptor` validators, so the import ban holds by construction. Each returns the envelope WHOLE (`Valid` mirrors `env.Errors` emptiness). The returned error is reserved for a cancelled ctx, a nil request or cohort (`SERVICE_VALIDATION`) and an unreadable cohort (`DATA_FILE` / `ENCODING_INVALID`); a nil or EMPTY Compose batch is the validator's own enveloped `SERVICE_VALIDATION`, matching the runtime's first refusal.

**The root rule: predict follows the runtime's entry order and judges each slot / stage / item with the runtime's own check function.** Every bullet below is an instance of it, and each has a parity gate; a rule added to one side alone fails that gate.

- **Options.** Facet / chain / materialize cohorts open header-only (`openGuideCohort`, `predictCohortRoot`); Compose adds a per-slot sidecar loader. **`composePredictOptions` and `predictCohortRoot` are the ONLY place the facade builds non-Request predict options** — `Explain` reuses them; never grow another sidecar-loader closure.
- **Strict and EchoRequest.** The methods set both from the instance (`Pulse.predictRootOptions`); each validator ends in `finishPredictRoot` (`internal/descriptor/predict_root_finish.go`), which promotes EVERY root warning to an error once — the per-slot body call keeps Strict off and drops its own warnings, so nothing is promoted twice; advisories never move. EchoRequest sets `env.Request` to the form the runtime echoes (Compose: the effective batch, sweep expanded, slots expanded and defaults-resolved; chain: every stage defaults-resolved; facet: as passed). Gates: `TestPredictRoots_StrictEscalatesWarnings`, `TestPredictRoots_EchoRequest`.
- **Observed** as `observe.OpPredict` (one operation per call); the managed-import TTL slides for every cohort predicted.
- **Profiles.** Predict is a core surface and never gated as a whole; hiding reaches inside through `PredictOptions.Instance`. The hidden-name parity harness drives every root (`feature_parity_predict_test.go`).
- **Compose slots** are judged like `Predict`: each slot's runtime-entry checks, then the shared request body `validateRequestBody` (`internal/descriptor/predict.go`) through `validateRequestBodyAt`, errors located `details.request` (fits: `details.fit`). Gate: `TestComposePredict_SlotVerdictMatchesProcessPredict` (Process predict ≡ one-slot compose verdict). **Chain stages** the same, over each stage's input schema, located `details.stage` (`TestChainPredict_StageBodyMatchesRuntime`). The runtime locates every coded slot / stage refusal identically (`internal/service/located.go`). Slot and stage overlays are judged through the same body (stage overlays via `ChainStageOverlayRefusal`, the runtime's pre-pass; `.claude/reference/execution-modes/overlays-matrix-kinds.md` (Spec refusals — one rule per host)).
- **One label set:** the augment-sibling collision set is `descriptor.OutputLabels`, shared with the runtime (`TestLabelCollision_PredictMatchesRuntime`).
- **CLI and MCP.** `pulse api predict-compose` / `predict-facet` / `predict-chain` take `--request FILE`, `--json`, `--strict`, `--echo-request` and write the envelope verbatim. MCP `pulse_predict` keeps a bare `types.Request` root and accepts ONE alternative root `composed` / `facet` / `chain` (any other key beside it is `SERVICE_VALIDATION`). Unlike the facade, these entries ARE gated on the owning capability (`capability:compose` / `facet` / `process_chain`): a hidden root's key is `PULSE_REQUEST_UNKNOWN_FIELD` and the bound schema drops it.
- **Materialize.** `Pulse.PredictMaterialize` over `ValidateMaterializeWithOptions` (`internal/descriptor/materialize_predict.go`); `Data` = `*descriptor.MaterializePredictResult` (`columns`, `derived_columns`, `risks`, `schema_info`; lists `[]`, never `null`). Order = the run's: slot gate → item expansion → slot refusal → `PULSE_MATERIALIZE_NO_DERIVED`, then `MaterializePlan` (the ONE call the run's pre-flight makes too; its refusal leads the errors), then `Predict` on the request less `output`, then the written schema's description warnings. `risks` name the run's code for each check only records settle. Surfaces: `pulse api materialize --predict`, `pulse_materialize {predict: true}`.
- **Sweeps.** `ValidateComposeExpanded` follows the runtime: a hidden `sweep` refused first, then `sweep.Expand` with the `MaxComposeSlots` preflight, then the slot gate and label-collision check over the EFFECTIVE request. Every expanded slot is predicted like a hand-written one; `ComposeValidationResult.Sweep` (`descriptor.SweepSummary`) is set whenever the sweep validates, even on a refused batch. A sampling sweep reports `rng_seed` = `sweep.EffectiveSeed(spec)`, the one function the runtime seeds with. An axis `target` (`params.<name>`) is echoed and every slot judged with the param written in.
- **Banners.** The same order with `banner.ExpandCompose`: hidden `banner` refused first, then `banner.Validate` (`PULSE_BANNER_INVALID`, the runtime's rule set), then the sweep expansion whose slot preflight counts explicit + sweep + banner slots; `ComposeValidationResult.Banner` (`descriptor.BannerSummary`) is set whenever the banner validates.
- **Optimize blocks.** Right after `model.CheckFits`, predict runs `OptimizeRefusal` (`internal/descriptor/compose_optimize.go` over `internal/optblock.Check`, the ONE rule set the runtime calls at the same point). Bounds and starts go through the scalar-slot evaluator: literal expressions are evaluated and range-checked; one calling a request-bound function (`coef()`, `sweep_axis()`, `response()`, `result()`, `lookup()`, an embedder function) is compiled and checked but not run, and listed on `ComposeValidationResult.UnresolvedScalars` (never a warning). Then objective and constraints. Success sets `ComposeValidationResult.Optimize` (`descriptor.OptimizeSummary`, `rng_seed` = `optblock.EffectiveSeed`). Nothing is solved. A `posterior` block adds its structural rule and the draw-carrier rule (exactly one literal `REG_MMM_BAYES` fit carrying draws). A gradient falling back to finite differences draws `PULSE_ADVISORY_OPTIMIZE_GRADIENT_FALLBACK` (`.claude/reference/predict-inspect/advisories.md`).
- **Nested-model comparisons.** Long form: `.claude/reference/predict-inspect/compose-compare.md`.
- **Item fan-out (`for_each`).** `Predict` runs the slot gate (a hidden `for_each` is `PULSE_REQUEST_UNKNOWN_FIELD`), then `ExpandRequestItems` (`internal/descriptor/for_each.go` over `sweep.ExpandItems`, the ONE expansion the runtime calls) with the `MaxDerivedColumns` then `MaxExpandedItems` preflight BEFORE any item renders; a refusal returns at once (a limit breach with its single Certain `LimitFindings` entry). Every later pass judges the EXPANDED request; `PredictResult.Request` stays as written and `PredictResult.ForEach` reports each fan-out. Compose expands each slot (optimize blocks first, then slots, then fit requests); chains expand every stage up front. The runtime expands IN PLACE, so its echo carries the expanded items.

## Suggested weight — sidecar metadata, never records

`InspectResult.ZoneField` (`zone_field`, `omitempty`) is the cohort's declared default zone field, copied from the schema block — no record read; zone resolution: `execution-modes/per-row-zones.md`.

`InspectResult.SuggestedWeight` / `PredictResult.SuggestedWeight` (`suggested_weight {field, source: "spss_sidecar", kind: "probability"}`, `omitempty`) name the weight variable the SPSS sidecar (`payload.weight.variable`) records. Contract: `.claude/reference/weighting.md` (SPSS suggestion).

- **Who reads what.** The FACADE reads the sidecar (root `weight_suggest.go`, through `spss.LoadSidecar` on the instance fs) and hands the variable NAME down; `internal/descriptor` never opens a file. The one judgement is `descx.SuggestWeight(schema, variable, inst)`: nil unless the variable is a weight-capable field of the cohort schema and the instance offers `capability:weighting`.
- **Every failure is silent** — no suggestion, never a warning or error: no sidecar, a malformed / foreign / STALE one, a variable the schema no longer carries, an anchor path (a sidecar sits beside a whole cohort), and the byte-level entry points (no path).
- **Predict echoes it as DATA only while no slot resolves a weight field**; never a warning, so `Strict` cannot make it an error. It is never applied, by `DefaultWeight` or otherwise.

## Inspect — parent groups are header-only too

For a `0x02` cohort `InspectResult` adds `layout` (format version, physical vs logical stride), `groups` and a per-field `group` marker — all `omitempty`, so a `0x01` envelope is unchanged. **Every figure is header + schema + file length** (`TestInspect_GroupFiguresReadNoRecord` garbles every record byte). Numbers and verdict come from `encoding.AssessGroup` / `GroupViability.Finding`, the import gate's functions, so inspect and `ImportReport.Groups` cannot disagree (`TestInspect_GroupFiguresMatchImportReport`); inspect judges at `DefaultDedupRatioFloor` because the file does not record its import floor. A low verdict is a FIGURE, never an envelope warning. Labels number groups by file position (the format has no group name).

## Inspect — vector fields are header-only too

A `vec_*` field adds `InspectField.Vector` (`omitempty`): `dim`, `kind`, `scale_min` / `scale_max` (both or neither) and `labels` truncated by the same rule as a dictionary. Every figure is the schema's VECTORS section (`TestInspect_VectorFieldReadsNoRecord`). An undescribed vector synthesises `Vector field: <name> (<dim> elements)`.

## CountRecords — one floor division, two observability contracts

`pulse.CountRecords(ctx, path) (uint64, error)` returns the record total without decoding the payload. Single file: `(size − header − schema) / record_stride`. Archive: the central directory + the SHRD `AggregateRecordCount`. Anchor: the shard's own count.

**The single-file floor division exists ONCE, at `encoding.Schema.RecordCountForPayload`, which `descriptor.Inspect` calls too.** The same arithmetic written twice is one edit away from two different counts over the same bytes, and nothing on either wire says which arm produced the number.

**The arms differ in OBSERVABILITY and only there, deliberately.** `Inspect` raises the `ENCODING_INVALID` truncated-tail warning naming the leftover bytes. `CountRecords` has no warning channel and floors SILENTLY, because it feeds the parallel-decode eligibility gate as well as the facade, and a half-written trailing record must not stop a cohort that still processes from reporting its whole-record count. **Do not close that gap by making `CountRecords` error.**

**Predict reads no record byte.** `CountRecords` never reads past the schema end, and neither do predict's runtime-side readers (`SchemaLoader`, `CohortCounter`, `DecodeMappable` go through `Service.OpenExact`, never `Service.Open`, whose buffered schema read over-reads into the payload — `TestExplain_FacadeReadsNoRecord`). Schema-block decodes fetch only bytes the lengths decoded so far PROVE belong to the block, so they stop exactly at the first record byte (`TestReadSchema_NeverReadsPastSchemaEnd`, `TestPredict_HugeDictionaryReadsBounded`).
