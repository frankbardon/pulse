## Matrix slot — `MAT_SEM` reference fixtures (continued)

Continues the `MAT_SEM` section of `.claude/reference/matrix-and-vectors/matrix-sem.md`: the semopy fixtures the covariance-only path is held to, the reference release, and the same-shape parity finding. The lavaan oracles are listed with each lavaan-convention feature there.

- **Reference fixtures.** `internal/sem/testdata`: four models (a synthetic three-level hierarchy, Bollen's political democracy, Holzinger–Swineford and an extended variant) with semopy's default (`*_semopy_default.json`) and `ftol` 1e-14 (`*_semopy_tight.json`) fits. Regenerate with `gen_semopy.sh` (a venv with semopy 2.3.11); compare a run with `compare.py`. Gate: `TestFit_MatchesSemopy` (1e-9 vs default, 1e-6 vs tight).
- **Reference release.** semopy 2.3.11 and its default fit (`semopy.Model(desc).fit(data)`, no options) — the release `gen_semopy.sh` installs. No other semopy release is a reference.
- **Same-shape parity.** A synthetic model with a production-like shape — outputs on one factor, a mediator over constructs, two-level hierarchies, 63 and 89 indicators, mostly 0/1 items, 600 seeded rows z-scored over the listwise rows, plus an n < p variant fitted through `cov_nearest`. Gates: `TestSEMShape_OneRequestMatchesSemopy` (one request, six slots, computed and formula members, `records` wire; the n < p slots warn `PULSE_MATRIX_NEAREST_PD`) and `TestFit_ShapeMatchesSemopy`. **Why the pins are what they are:** the expected information's smallest eigenvalue on this shape is a first-order factor's SCALE direction, along which semopy's default `ftol` 1e-6 stop sits ~1e-3 short of the optimum — yet MAT_SEM reproduces that stopping iterate (same iteration count, every figure within 4e-10 through the engine), so the default pin is 1e-8. At `ftol` 1e-14 the optimum itself is resolved along that direction only to ~1e-7…1e-6, so the tight pin is 5e-6. semopy alone varies by up to 3e-10 default, 3e-7 tight between runs (Python set order differs per process).
