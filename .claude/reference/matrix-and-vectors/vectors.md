# Matrix and vectors — virtual vectors (`Request.Vectors`)

Per-topic slice of the matrix-and-vectors contract. Index (package surface + section map): `.claude/reference/matrix-and-vectors.md` — load it first, then only the slice(s) your change touches. The vector-input operators continue in `.claude/reference/matrix-and-vectors/vector-operators.md`.

## Virtual vectors — `Request.Vectors` (U16)

`Request.Vectors []types.VectorSpec` (`{name, fields | pattern, labels?, coerce?, kind?, scale_min?, scale_max?}`, additive `omitempty`, gated by `capability:matrices`) names a battery of numeric columns once per request. **The one resolver is `internal/vectors`** — a no-execute leaf (stdlib + `encoding` / `errors` / `types`, plus the parse-only `internal/exprident` for expression references) that predict, the runtime and projection all call, so the three cannot disagree. Consumers (the matrix slot and its operators) read members through it: `vectors.Resolve(req.Vectors, schema)` → `[]Resolved{Name, Members, Labels, Coerce}` index-aligned with the specs; `vectors.Find` by name; `vectors.ResolveSpec(at, spec, schema)` for an inline field list (an operator slot's own `fields`, with its own path in `at`).

- **Shape.** `name` non-empty and unique per request; exactly one of `fields` / `pattern`; `coerce` ∈ `types.AllVectorCoerces()` (`binary`). Violations are `PULSE_VECTOR_INVALID` (`details.reason` = `empty_name` / `fields_and_pattern` / `no_fields_or_pattern` / `unknown_coerce` / `empty_field_entry` / `bad_glob` / `bad_pattern`); a repeated name is `PULSE_VECTOR_DUPLICATE` (`indices`); a name that is also a schema field's name is `PULSE_VECTOR_NAME_COLLISION` (`vector`, `name`, `field`; U26 E2-S1 — an expression binds a vector by name beside the fields, so the two must never be ambiguous; judged in `vectors.Resolve`, so predict and the runtime refuse alike). So is a name equal to a feature output, attribute or window label of the same request (U26 E2-S2; `vector`, `name`, `label` + the claiming slot `feature` / `attribute` / `window` + `window_index`) — judged by the field-reference walk right after vector and matrix resolution (`fieldRefWalk.vectorLabelCollision`, labels recorded by `claim` as steps 1 / 3 / 5 name them), so predict and every runtime mode refuse alike; without it the derived column silently won the identifier (`TestPredict_VectorLabelCollision`, `TestVectorExpr_LabelCollisionRefused`).
- **Native vector fields (U29 E2-S1).** A `vec_f32` / `vec_f64` field is a vector with no spec (`internal/vectors/native.go`). **Named directly:** `Resolve` returns the spec-backed vectors (index-aligned) FOLLOWED by one `Resolved` per native field (`vectors.Natives`, schema order), so every by-name lookup — `Find`, `findVector`, a matrix / test / attribute / grouper / aggregation `vector`, an expression identifier — accepts the field's name with no `Request.Vectors` entry; `Resolved.Native` (`{Field, FieldIndex, Dim, Type, HasLabels}`) marks it and `Kind` / scale / `Labels` come from the VECTORS section. A spec named like a native field is `PULSE_VECTOR_NAME_COLLISION` with `details.native: true` (no shadowing). **Expanded:** a `fields` literal, glob or `pattern` match naming a native field expands IN PLACE to its element members `f[k]` (1-based, `vectors.ElementMember`), and a `fields` entry spelled `f[k]` (canonical base-10, 1..dim, f a native field — else it keeps its glob meaning) names one element; that is how a request re-kinds, re-labels or re-scopes a native vector, and the schema metadata is never mutated. Element labels: the schema's, else `f_<k>` (the expanded-export column name, `vectors.ElementLabel`); a spec's `labels` win. `Resolved.Refs` (`[]MemberRef{Field, Element}`, nil when every member is a scalar column — the vector-free shape is byte-identical) locates each member; a literal-member rewrite (`Fields` = the element members) re-resolves to the same elements. **Values — the shared fill** (`processing.memberFill`, `internal/processing/vector_fill.go`): a scalar member reads `NumericValue` (a stored NaN stays a value); a native element reads the vector storage in place, a NaN element is a NULL member and a null vector makes every element null — so a native vector equals its scalar twin (NaN element ↔ null column). `Record.memberValue(name)` is the name-only form (the aggregation floor's `AggregationPresent`). Adopted by the expression binding (`bindVectors` binds a referenced native field as a vector even though it is a schema field: a null vector is all-NaN, never `nil`, never a null-input row; `refScope` / `ReferenceIssues` treat it as a vector) and `AGG_VEC_MEAN` / `AGG_VEC_SUM` (U29 E2-S1), then by every other consumer (E2-S2): the eight `MAT_*` slots (`matrixSlot.readRow`, the MAT_DISTANCE fold and its between grouper), the vector tests (`TEST_BARTLETT_SPHERICITY`, `TEST_BOX_M`, `TEST_HOTELLING_T2` incl. `vector2`, `TEST_MANOVA`, `TEST_MARDIA`), `ATTR_SCALE_SCORE`, the comparison pair (`ATTR_PROFILE_SIMILARITY`, `ATTR_VEC_DISTANCE`) and the fitted attributes (`ATTR_MAHALANOBIS`, `ATTR_PC_SCORE`, `ATTR_FACTOR_SCORE`), and `GROUP_KMEANS` — a slot rewritten to its literal members compiles them once with `memberFillOf(names, schema)` (an element member against the schema via `vectors.ParseElementMember`, else a scalar read that falls back to `memberValue`, so lost vector metadata never silently nulls an element), and `memberFill.complete` is the listwise question (a null member or any NaN drops the row). The metric registry reads the filled arrays, so it needs nothing of its own. **Kind from the schema:** a native field named directly carries its VECTORS-section kind into every kind-driven helper — `vectors.KindIn(specs, schema, name)` (spec kind, else the native field's), `MatrixMetricDefaults` / `AttributeMetricDefaults` / `MetricUnsuitedIssues` (each now takes the schema; the issue scan covers expression metric calls on a native field), `ComparisonFitted` (read through `ComparisonTwoPass`, so the two-pass routing gates, `crosstabfuse.Facts.AttributeSlotTwoPass` and predict's `firstTwoPassAttribute`, see a kind-default fitted metric); the runtime's pre-dispatch strict refusal and post-dispatch warnings open the input schema only when `vectors.NativeKindsMatter(req)` (a judged slot names a vector no spec defines). **Labels:** a matrix whose members read a native element (`Resolved.Refs != nil`) — inline `fields` or a spec without `labels` — renders `labels` (the element labels, a scalar member's its name), never the `f[k]` member names. Member identity (`row_keys`, `members` details, warning text) stays `f[k]`; every value, count and label equals the scalar twin's. **Projection:** every `*Members` helper returns `Resolved.SourceFields()` (an element member's vector field), and `vectors.ReferencedNatives` adds a native field a slot names directly. Predict's `resolved_vectors` echo stays the request's own vectors. Gates: `TestResolve_Native*`, `TestResolveSpec_NativeExpansion`, `TestSlots_AcceptNativeName`, `TestProjection_NativeSourceFields`, `TestMemberFill_*`, `TestNativeVector_RequestsMatchTwin` (expressions + `AGG_VEC_*`, f32 / f64, streaming / buffered / grouped, single file / shard archive), `TestNativeVector_CollisionRefused`, `TestMemberFillOf_LiteralMembers`, `TestMemberValue_AllocatesNothing`, `TestNativeKind_DrivesMetricHelpers`, `TestNativeKindsMatter`, and the parity suite `TestNativeVectorParity` (every vector-consuming operator, weighted and unweighted, NaN elements and null vectors; data, tests, matrices, warnings and all `Components` byte-equal after mapping `f[k]` to the twin column) with its enumeration gate `TestNativeVectorParity_CoversEveryVectorOperator` (every `MAT_*` plus `vectors.Vector{Test,Attribute,Group,Aggregation}Types` — a new vector operator fails until a parity case exercises it).
- **Vector fields in scalar slots (U29 E2-S3).** A native vector field may stand only where a VECTOR or PRESENCE is read. Every BUILT-IN slot that reads one value from a field — a scalar aggregation's `field` and its params field names (`aggParamFieldKeys`; `AGG_RATIO`'s ignored `field` excepted), a non-vector grouper (groups, both crosstab axes), an attribute's `field` / `target` / `predictors`, a feature's `field` / `params.target` / `params.stratify`, a filterer other than `FILTER_NULL` / `FILTER_EXPRESSION` (a vector attribute's `params.fit_on` included), a tier-1 test's `field` / `field2` / `rows` / `cols` / `split_by` / `subject_field`, a regression's target / predictors / covariance keys, and — when they read RECORD columns (no groups and no aggregations, or a crosstab) — a window's `field` / `order_by` / `partition_by` and a sort key — is refused with `PULSE_VECTOR_FIELD_NOT_SCALAR` (`vectors.FieldNotScalar`: `details {field, field_type, dim, slot, suggest?}`) by step 0 of the field-reference walk (`internal/descriptor/vector_scalar.go`, `vectorScalarRefusals`), so predict and every runtime mode return the same code, message and details before any record is read. A slot with no Type naming a vector (no smart default fits one) is refused there too, `suggest` `AGG_VEC_MEAN` / `GROUP_KMEANS`; predict's own slot type checks (empty type, numeric / categorical / date checks) skip a vector field so it reports ONE error. The other single-value rules carry their own arm: a weight (`weightFieldTypeRefusal`, `slot` = the weight's path), a point-lookup key (`Service.BuildIndex`, `slot` `index key`, `details.reason` = `processing.IndexKeyRejectionMessage`), a join key (`PULSE_JOIN_TYPE_MISMATCH`, `details.reason` `vector_key`, `JoinKeyVectorRejection`); a date / zone slot over a vector is skipped by `ResolveZones` and refused by the walk. Presence slots (`AGG_COUNT`, `AGG_NULL_COUNT`, `FILTER_NULL`, the `{n, n_null}` floor, the crosstab cell gate) accept a vector: `processing.FieldPresent` reads `Record.vectorPresent` (a null vector absent, a NaN-element vector present). The capability lists say so: `nonVectorFieldTypes` (`FILTER_TRUE` / `FILTER_FALSE`, `WIN_ROW_NUMBER` / `WIN_RANK` / `WIN_DENSE_RANK`, `FEAT_TRAIN_TEST_SPLIT`); `IsOrderableType` stays false for a vector (the walk's vector refusal wins over the orderability one). Guided analysis: `FieldKindOf` maps a vector to `FieldKindVector`, which no intent role takes; the recommend binder (`internal/guide/bind.go`) never binds a vector field into a scalar slot, and drafts it WHOLE in a vector slot as `"vector": "<field>"` (`.claude/reference/guided-analysis.md`, Recommend — Native vector fields). Gates: `TestFieldTypeAcceptance_PredictMatchesRuntime` (vec cells; no vector ledger entry; a vector refusal is the vector code on both sides and predict's only error), `TestVectorField_ScalarRefusalsPredictMatchRuntime`, `TestVectorField_PresenceSlotsCountVectors`, `TestVectorField_CrosstabCountCell`, `TestVectorField_JoinKeyRefused`, `TestVectorField_IndexKeyRefused`, `TestWindowOrderBy_OrderabilityPredictMatchesRuntime` (vector subtest), `TestRecommendBound_NeverBindsVectorFields`, `TestBind_SkipsVectorFields`, `TestNativeVector_PredictMatrixEchoMatchesRuntime` (predict's matrix `axis_keys` / `labels` and `resolved_vectors` equal the runtime's row keys and labels for natives named directly, inline, re-kinded, re-scoped and re-labelled).
- **Vector kind (U27 E1-S3).** Optional `kind` ∈ `types.AllVectorKinds()` (`measure` / `scale` / `composition` / `binary` — the `linalg/metric` kinds, pinned equal by `TestResolve_KindAndScaleBounds`) and, under `kind: "scale"` only, `scale_min` / `scale_max` (both, finite, min < max). Refusals are `PULSE_VECTOR_INVALID` with `reason` `unknown_kind` / `scale_bounds_without_scale_kind` / `scale_bounds_partial` / `scale_bounds_invalid`, judged after `coerce`. `Resolved` carries `Kind` + `HasScale` / `ScaleMin` / `ScaleMax`. The one reading of kind against metrics is `internal/vectors/metric_kind.go`: (1) the smart-defaults metric fill (`MatrixMetricDefaults`; `execution-modes.md` (Smart defaults)); (2) `ResolveKindMetric(c, explicit, kind, form)` — explicit name via `ResolveFor`, else the kind default, else `PULSE_VECTOR_METRIC_REQUIRED` — for metric-taking operators that have no implicit default (a no-kind `MAT_DISTANCE` keeps `euclidean`); (3) `MetricUnsuitedIssues(req)` — one `PULSE_VECTOR_METRIC_UNSUITED` per EXPLICIT poor-fit pair (`Metric.PoorFitFor`: cosine on scale / measure, the Euclidean family on composition; cosine on binary is fine) on a metric-taking matrix slot reading the vector by name, and on every call of a metric built-in (`exprbuiltins.Metric` — the one function → metric table `internal/processing` also registers through) whose argument IS a kind vector, found by the static walk `exprident.Calls` over the slots `exprReferenced` scans (a transformed argument such as `vcenter(v)` is not judged). Details `vector`, `kind`, `metric`, `slot`, `form`, `consumer` (+ `function` for expr), `suggested` (the consumer's kind default; for expr the kind's table default). Channel: predict (`predictVectors`) adds each as a warning, an ERROR under `PredictOptions.Strict`; the runtime appends each to `Response.Warnings` (`appendVectorWarnings`) and under `Service.strict` refuses the run with the first one before any record is read (`metricUnsuitedRefusal` in `Service.process`). CLI: `pulse api predict --strict` / `pulse api process --strict` (`TestAPIStrict_VectorMetricUnsuited`). A `kind` vector's bounds stand in for `MAT_RELIABILITY`'s `scale_min` / `scale_max` when the spec sets none (explicit params win; `resolveReliability`; a `reverse` list with no range from either is `PROCESSING_CONFIG`). Manifest: `matrix.vector_kinds` (`descriptor.VectorKindMeta`, `metric.Default` per form; `TestManifestVectorKindsComplete`). Skill: `skills/vector-metrics.md`.
- **Order (axis order).** A `fields` entry without `*` `?` `[` — or naming a schema field EXACTLY, metacharacters and all (a chain stage's element column `m[b1]`, U30 E4-S3) — is a literal and keeps the caller's position; a glob entry (`path.Match`, whole name) expands IN PLACE to its matches in schema order; `pattern` is a Go regexp, UNANCHORED, matches in schema order. A member repeated after expansion is `PULSE_VECTOR_DUPLICATE` (`field`); no member at all is `PULSE_VECTOR_EMPTY`. A literal the schema lacks is the field-reference refusal `SERVICE_VALIDATION` (`field`, `vector`, `slot` = `vectors[i].fields[j]`).
- **Member types.** u4 / u8 / u16 / u32 / u64 / f32 / f64; `packed_bool` only under `coerce: "binary"`; categorical, `set_*`, `date`, `datetime`, `decimal128` refused permanently — `PULSE_VECTOR_MEMBER_TYPE` naming `field` + `field_type` (`vectors.MemberTypeAllowed`).
- **Labels.** One per member or `PULSE_VECTOR_LABELS_MISMATCH` (`labels`, `members`, `resolved`); absent → the member names.
- **Order of checks.** Spec by spec in request order; per spec: name, duplicate name, field-name collision, shape, coerce, kind and scale bounds, expansion, empty, member types, labels. First failure wins.
- **Where it runs.** Step 6 of the field-reference walk (`internal/descriptor/field_refs.go`), so the runtime (`Service.checkFieldRefs`, every execution mode, after zones), predict and the Compose / chain validators refuse identically, against the schema the request executes over (joined or chain-stage schema included). Projection: `processing.NeededFields` adds `vectors.Members` (an unresolvable vector widens). Predict echoes `PredictResult.ResolvedVectors` `{name: [members]}` (omitted when none or refused).
- **Expression binding (U26 E2-S1).** An ATTR_FORMULA / FILTER_EXPRESSION expression or a `total()` argument that names a `Request.Vectors` entry reads it as a `[]float64` identifier in axis order: `processing.ExprVectors(req, schema)` resolves once per run (`Processor.prepare` stashes it on `Processor.exprVectors`; the service's per-worker builds call `BuildFiltersWithVectors` / `BindAttributeWithVectors`), the operators receive it through the `vectorBinder` seam, and `newExprProgram(src, what, schema, vecs, opts)` → `exprProgram.bindVectors` declares ONLY the referenced names (unreferenced vectors and vector-free requests bind nothing — byte-identical, no per-row work). Per row `fillVectors` reads each member with `Record.NumericValue`: a null member is a NaN element, all-null members an all-NaN vector — never `nil`, never a null-input row. Buffers are pooled per program (`exprVectorFrame`, pre-boxed so a row binds without allocating); safe because no built-in retains or returns its argument and a vector as the whole result is refused (`PROCESSING_CONFIG`, at build when the expression is the bare identifier). On the deferred-compile / `$env` / cached-`AllValues` path the vectors bind into a pooled COPY of the AllValues map, never the record's cache. Projection: `appendExprIdents` expands a vector identifier to its members (`exprVectorMembers`) on top of the blanket `vectors.Members` union — an unprojected member decodes null and the expression would silently fold NaN. Filter precompute never takes such a filter (a vector name is no group member field). Pinned by `TestVectorExpr_BindsUnderProjection` (every consumer × streaming / buffered / parallel decode / shard archive under projected decode), `TestExprVectors_*`, `TestAppendExprIdents_ExpandsVectors`, `TestVectorExpr_NameCollisionRefused`. **Static pair length (U35 #419):** `dot` / `dist` / `cosine` whose two arguments have request-fixed lengths — literal arrays, or bare identifiers binding a vector (`vectors.ExprVectorLen`: a resolved vector not shadowed by a scalar field nor a `let`; length = member count, a native's dim) — that differ are `PROCESSING_VECTOR_LENGTH_MISMATCH` `{function, left, right}` at build (`vectorStaticRefusal` → `vectors.LengthScope.PairIssue`) and in predict (`predictVectorLengths` → `vectors.LengthIssues`, first per `ExprSlots` expression, every root via `validateRequestBody`); a nested call, slice or unknown name stays per-row, never a false positive (`TestVectorPair_StaticLengthMatchesRuntime`, `TestExprLengthIssue`). Formula `nil` result → null attribute value: `processing.AttributeNull` (a payload NaN, `IsAttributeNull`) written as a null by every arm (`SetAttributeOutput` and the buffered write) whatever the computer's `EmitsNull`; an ordinary NaN keeps its rule (`TestFormula_NilResultIsNull`).
- **Unreferenced warning.** `vectors.Referenced(req)` is the ONE reference set — every `Request.Matrices[i].vector`, every tier-1 `Request.Tests[i].vector` / `vector2`, every `Request.Attributes[i].vector`, every grouper slot's `vector`, and (U26 E2-S2) every `Request.Vectors` name an expression reads as a free identifier — an ATTR_FORMULA expression, a FILTER_EXPRESSION in `Request.Filterers` or in a vector attribute's `params.fit_on`, and so a `total()` argument inside either (`internal/exprident.Free`, the walk `exprProgram.bindVectors` binds by; `TestReferenced_CountsExpressionReads`, `TestPredict_ExpressionVectorReferences`, `TestVectorExpr_ExpressionReferenceCounts`); a vector outside it is `PULSE_VECTOR_UNREFERENCED` — a predict warning and a `Response.Warnings` entry (`Service.process`, after the multiplicity fold). A new consumer slot MUST add its references to `Referenced`.
- **Hashing.** `Request.Hash()` is schema-free and hashes vectors AS WRITTEN; a vector-free request hashes byte-identically to the pre-slot form (`TestRequestHash_VectorFreeByteIdentical`). Resolved-member identity is `vectors.Normalize(req, schema)`: a shallow copy whose vectors carry their resolved `fields` (pattern cleared), so a pattern and its equivalent explicit list hash alike (`TestNormalize_HashesResolvedMembers`). No runtime site hashes a normalized request yet.
- **Codes.** All `PULSE_VECTOR_*` are owned by `capability:matrices` (a hidden capability refuses the slot first); `INVALID` / `EMPTY` / `MEMBER_TYPE` / `DUPLICATE` / `UNKNOWN` are also owned by every vector-input test (`ownVectorInputs`), whose inline `fields` resolve without the slot. `PULSE_VECTOR_UNKNOWN` is a matrix spec naming an undefined vector (`vector`, `slot` = `matrices[i].vector`, `defined`).
