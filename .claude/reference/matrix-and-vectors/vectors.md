# Matrix and vectors — virtual vectors (`Request.Vectors`)

Per-topic slice of the matrix-and-vectors contract. Index (package surface + section map): `.claude/reference/matrix-and-vectors.md` — load it first, then only the slice(s) your change touches. The vector-input operators continue in `.claude/reference/matrix-and-vectors/vector-operators.md`.

## Virtual vectors — `Request.Vectors`

`Request.Vectors []types.VectorSpec` (`{name, fields | pattern, labels?, coerce?, kind?, scale_min?, scale_max?, standardize?}`, additive `omitempty`, gated by `capability:matrices`) names a battery of numeric columns once per request. **The one resolver is `internal/vectors`** — a no-execute leaf that predict, the runtime and projection all call, so the three cannot disagree. Entry points: `vectors.Resolve(specs, schema)` (index-aligned `[]Resolved`), `vectors.ResolveRequest(req, schema)` (adds the request's computed columns — use it wherever a request is in hand), `vectors.Find` by name, `vectors.ResolveSpec` for an operator slot's inline `fields`. Never resolve members anywhere else.

- **Shape.** `name` non-empty and unique; exactly one of `fields` / `pattern`; `coerce` ∈ `types.AllVectorCoerces()`. Violations are `PULSE_VECTOR_INVALID` with a `details.reason` (grep `reason` in `internal/vectors` for the set); a repeated name is `PULSE_VECTOR_DUPLICATE`. A name equal to a schema field, or to a feature output, attribute or window label of the same request, is `PULSE_VECTOR_NAME_COLLISION` — an expression binds a vector by name beside fields and labels, and without the refusal the derived column silently won the identifier.
- **Native vector fields.** A `vec_f32` / `vec_f64` field is a vector with no spec (`internal/vectors/native.go`). **Named directly:** `Resolve` returns the spec-backed vectors followed by one `Resolved` per native field (schema order), so every by-name lookup accepts the field's name; `Resolved.Native` marks it and kind / scale / labels come from the schema's VECTORS section. A spec named like a native field is `PULSE_VECTOR_NAME_COLLISION` with `details.native: true` (no shadowing). **Expanded:** a `fields` literal, glob or `pattern` naming a native field expands IN PLACE to its element members `f[k]` (1-based), and an entry spelled `f[k]` names one element — that is how a request re-kinds, re-labels or re-scopes a native vector; schema metadata is never mutated. Element labels: the schema's, else `f_<k>`; a spec's `labels` win. **Values — the shared fill** (`processing.memberFill`, `internal/processing/vector_fill.go`): a scalar member reads `NumericValue`; a native element reads vector storage in place, a NaN element is a NULL member, a null vector makes every element null — so **a native vector equals its scalar twin** (NaN element ↔ null column). Every vector consumer reads members through this fill; a new consumer must too. **Kind from the schema:** a native field named directly carries its VECTORS-section kind into every kind-driven helper (`vectors.KindIn`). **Labels:** a matrix reading native elements renders the element labels, never the `f[k]` member names; member identity (`row_keys`, details, warning text) stays `f[k]`. **Projection:** member helpers return `Resolved.SourceFields()` (the vector field). Gate: `TestNativeVectorParity` (every vector-consuming operator byte-equal to its scalar twin), with `TestNativeVectorParity_CoversEveryVectorOperator` failing until a new vector operator has a parity case.
- **Vector fields in scalar slots.** A native vector field may stand only where a VECTOR or PRESENCE is read. Every built-in slot that reads one value from a field is refused with `PULSE_VECTOR_FIELD_NOT_SCALAR` (`details {field, field_type, dim, slot, suggest?}`) by step 0 of the field-reference walk (`internal/descriptor/vector_scalar.go`), so predict and every runtime mode return the same code before any record is read; predict's own type checks skip a vector field so it reports ONE error. Weights, point-lookup keys and join keys (`PULSE_JOIN_TYPE_MISMATCH`, `reason` `vector_key`) refuse on their own arm. Presence slots (`AGG_COUNT`, `AGG_NULL_COUNT`, `FILTER_NULL`, the `{n, n_null}` floor, the crosstab cell gate) accept a vector: a null vector is absent, a NaN-element vector present. Guided analysis never binds a vector field into a scalar slot and drafts it whole as `"vector": "<field>"` (`.claude/reference/guided-analysis.md`, Recommend — Native vector fields). Gate: `TestVectorField_ScalarRefusalsPredictMatchRuntime`.
- **Vector kind.** Optional `kind` ∈ `types.AllVectorKinds()` (the `linalg/metric` kinds) and, under `kind: "scale"` only, `scale_min` / `scale_max` (both, finite, min < max); refusals are `PULSE_VECTOR_INVALID`. The one reading of kind against metrics is `internal/vectors/metric_kind.go`: (1) the smart-defaults metric fill (`execution-modes.md` (Smart defaults)); (2) `ResolveKindMetric` — explicit name, else the kind default, else `PULSE_VECTOR_METRIC_REQUIRED` (a no-kind `MAT_DISTANCE` keeps `euclidean`); (3) `MetricUnsuitedIssues` — one `PULSE_VECTOR_METRIC_UNSUITED` per EXPLICIT poor-fit pair (`Metric.PoorFitFor`) on a metric-taking matrix slot or an expression metric call whose argument IS a kind vector. That warning is a predict warning (an error under `PredictOptions.Strict`) and a `Response.Warnings` entry; under `Options.Strict` the run refuses before reading a record. A `kind: scale` vector's bounds stand in for `MAT_RELIABILITY`'s range when the spec sets none. Manifest: `matrix.vector_kinds`. Skill: `skills/vector-metrics.md`.
- **Order (axis order).** A `fields` entry without `*` `?` `[` — or naming a schema field EXACTLY, metacharacters and all — is a literal and keeps the caller's position; a glob (`path.Match`, whole name) expands in place in schema order; `pattern` is an UNANCHORED Go regexp, matches in schema order. A repeated member is `PULSE_VECTOR_DUPLICATE`; no member is `PULSE_VECTOR_EMPTY`; a literal the schema lacks (and no computed column provides) is `SERVICE_VALIDATION`.
- **Standardize.** Optional `standardize: "zscore"`: every member z-scored with its POPULATION SD (divisor Σw) over the rows the matrix keeps after its listwise drop (per bucket when grouped), so the covariance becomes the correlation matrix. **Implemented on the merged state, never the rows** (`processing.standardizeCoMoment`, after the fixed `MergeTree`, via `ListwiseState`): FMA-free, applied once, so every execution path stays bit-equal and streamability is unchanged. Only the vector's own columns are rescaled (a `MAT_PARTIAL_CORRELATION` control keeps its scale). A zero-spread member is left as folded, never divided by zero. Counts, Σw and components are untouched. **Only a listwise co-moment `MAT_*` slot reads a standardized vector**; every other consumer is refused with `PULSE_VECTOR_INVALID` `standardize_unsupported` (`details.slot`), never silently fed raw values (`vectors.StandardizeRefusal`, predict and runtime alike).
- **Computed members.** A LITERAL `fields` entry (a spec, a matrix's inline `fields`, a `MAT_PARTIAL_CORRELATION` control) may name a column the request computes per record: a built-in feature output, an attribute label, or — only when windows run over records (`execution-modes.md` (Windows-first)) — a window label. `vectors.ComputedColumns(req, schema)` is the one name → producer map (first producer wins; a schema field's name stays the field's). Globs and `pattern` match schema fields only; extension feature outputs are unknown. **Only a `MAT_*` member vector reads one**; every other consumer is refused with `PULSE_VECTOR_INVALID` `computed_member_unsupported` (it reads members at a pipeline point where the column may not exist). Values come off the record after producers write it; window labels are copied back onto the records after windows run (`processing.copyWindowMembers`). Producers route as for any slot reading them (a two-pass attribute forces buffered; a matrix reading a `total()`-derived attribute is refused merging). Projection decodes the producer's inputs, never the computed name. **Result contract:** every `MAT_*` over computed members is byte-identical (matrices and `Components.Matrices`) to `pulse.Materialize` followed by the same matrices over the materialized columns (`TestComputedMembers_*`).
- **Member types.** u4 / u8 / u16 / u32 / u64 / f32 / f64; `packed_bool` only under `coerce: "binary"`; categorical, `set_*`, `date`, `datetime`, `decimal128` refused permanently — `PULSE_VECTOR_MEMBER_TYPE` (`vectors.MemberTypeAllowed`).
- **Labels.** One per member or `PULSE_VECTOR_LABELS_MISMATCH`; absent → the member names.
- **Order of checks.** Spec by spec in request order; per spec: name, duplicate, collision, shape, coerce, kind and scale bounds, standardize, expansion, empty, member types, labels. First failure wins.
- **Where it runs.** Step 6 of the field-reference walk (`internal/descriptor/field_refs.go`), so the runtime (every mode, after zones), predict and the Compose / chain validators refuse identically against the schema the request executes over. Projection: `processing.NeededFields` adds `vectors.Members` (an unresolvable vector widens). Predict echoes `PredictResult.ResolvedVectors`.
- **Expression binding.** An ATTR_FORMULA / FILTER_EXPRESSION expression or `total()` argument naming a vector reads it as a `[]float64` identifier in axis order. Only REFERENCED names are bound (a vector-free request is byte-identical, no per-row work). A null member is a NaN element, all-null members an all-NaN vector — never `nil`, never a null-input row. Per-row buffers are pooled, which is safe only because no built-in retains or returns its argument and a vector as the whole result is refused (`PROCESSING_CONFIG`). Projection must expand a vector identifier to its members — an unprojected member decodes null and the expression would silently fold NaN (`TestVectorExpr_BindsUnderProjection`). **Static checks** live in the leaf `vectors.ExprStaticIssue` (`internal/vectors/static_expr.go`): a vector-returning call as the whole expression, a built-in's argument count outside `vectors.BuiltinArity`, a request-fixed pair length mismatch for `dot` / `dist` / `cosine` (`PROCESSING_VECTOR_LENGTH_MISMATCH`), a bad literal `vnormalize` mode. Predict reports each with the runtime's code, message and details; a length only a row can know stays per-row, never a false positive. A formula `nil` result writes a null attribute value on every arm.
- **Expression slots.** `vectors.ExprSlots` is the one typed walk of a request's expressions that every shared expression check reads (reference issues, static issues, lengths, metric suitability, the Compose fit-cycle scan, `vectors.Referenced`). A new expression-bearing slot must join it, or predict misses faults the runtime raises. `TestTemplateExprSplice_EngineExprSlotsMatch` checks it against `internal/exprslots` in both directions (out-of-scope slots are listed, with reasons, in `exprSlotsOutOfScope`).
- **Unreferenced warning.** `vectors.Referenced(req)` is the ONE reference set (every vector-taking slot plus every expression read); a vector outside it is `PULSE_VECTOR_UNREFERENCED`, a predict warning and a `Response.Warnings` entry. **A new consumer slot must add its references to `Referenced`.**
- **Hashing.** `Request.Hash()` is schema-free and hashes vectors AS WRITTEN; a vector-free request hashes byte-identically. Resolved-member identity is `vectors.Normalize(req, schema)` (resolved `fields`, pattern cleared). No runtime site hashes a normalized request.
- **Codes.** All `PULSE_VECTOR_*` are owned by `capability:matrices` (a hidden capability refuses the slot first); `INVALID` / `EMPTY` / `MEMBER_TYPE` / `DUPLICATE` / `UNKNOWN` are also owned by every vector-input test, whose inline `fields` resolve without the slot. `PULSE_VECTOR_UNKNOWN` is a slot naming an undefined vector.
