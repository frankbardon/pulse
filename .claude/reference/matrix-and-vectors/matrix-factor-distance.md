## Matrix slot — `MAT_FACTOR` and `MAT_DISTANCE` (continued)

Continues `## Matrix slot` in `.claude/reference/matrix-and-vectors/matrix-slot.md`; the PSD guard and rotation engine these cite are in `.claude/reference/matrix-and-vectors/matrix-decomposition.md`. Params and outputs: the atomic skills `op-mat-factor` / `op-mat-distance` and the manifest.

- **`MAT_FACTOR`** (`internal/processing/matrix_factor.go`, `matrix_factor_ml.go`). Exploratory factor analysis, always of the correlation R after the shared PSD guard. A `kappa`, `gamma` or `epsilon` beside a rotation that does not read it is refused, never ignored. Extraction dispatch `faExtractors`, each from the SMC start:
  - `principal_axis` = psych `fa(fm = "pa")` step for step, including psych's `min.err` 0.001 / `max.iter` 50, so the iteration count and convergence flag match psych EXACTLY.
  - `minres` solves the minres optimum EXACTLY (the point where the diagonal residual diag(LLᵀ) − h vanishes) by damped Newton with the exact eigen-perturbation Jacobian, to 1e-10. h is unconstrained: a uniqueness ≤ 0 is reported as fitted with `PULSE_MATRIX_HEYWOOD`, where psych bounds ψ.
  - `ml` = Jöreskog maximum likelihood (the `stats::factanal` / psych objective) on psych's box ψ ∈ [0.005, 1], solved EXACTLY by projected Newton in log ψ with the exact Hessian, to a projected gradient ≤ 1e-10 (a stall short of it is NOT_CONVERGED). A ψ held at the 0.005 floor is the ML Heywood case. A singular guarded R withholds the whole ML fit with `PULSE_MATRIX_SINGULAR`. ML fit indices are psych `fa.stats` on the loadings (`faMLFitIndices`); the RMSEA interval follows psych's rule but solves the noncentral χ² bracket to the last bit (psych's `uniroot` tolerance leaves its bounds ~1e-7 off), with the noncentral CDF pinned to R `pchisq(x, df, ncp)`. Fit indices are null at df ≤ 0, and all null with `PULSE_MATRIX_INSUFFICIENT_N` scope `likelihood` when the Bartlett-corrected n ≤ 0; absent on the other extractions.
  - **Sign and order:** columns by descending eigenvalue, each flipped to sum positive (psych `fa`), then the rotation engine's own rule.
  - **Guards:** (p − k)² < p + k (`vectors.FactorIdentified`) → `PULSE_MATRIX_NOT_IDENTIFIED` WARNING and null loadings / vectors / fit scalars (KMO and Bartlett still compute); a capped extraction or rotation → `PULSE_MATRIX_NOT_CONVERGED`, last iterate kept; Kaiser keeping 0 factors emits the zero-factor fit.
  - **`empirical_chisq` is psych's residual size, NOT a likelihood test**; KMO / Bartlett come from the shared sphericity core.
  - **Oracle tolerances** (`scripts/reference/gen_factor.R`): principal axis 1e-9 with iteration count exact; minres 1e-7 against psych's exact optimum and 2e-4 against psych's early-stopped fit, with Pulse's residual never above psych's; ml 1e-9 against the exact ML optimum and 1e-4 against psych, Pulse's F never above psych's; GPA rotations of a fit 1e-4 (GPA stops on a gradient band, so a tiny input change can move its stopping iterate). psych's `"promax"` is not `stats::promax`, so the engine's definition is used. End to end: `TestMatrixFactor_MatchesROracle`.
- **`MAT_DISTANCE`** (`internal/processing/matrix_distance.go`). The k × k distances between the centroids of the buckets a `between` grouper cuts the rows into.
  - **`between`** is a `types.Group` decoded strictly: any built-in or registered extension grouper, by exactly `ResolveGroups`' rule (an unknown or hidden type is `unknown_between_type`; no own `weight`). A `GROUP_KMEANS` or extension vector between resolves its members at slot `matrices[i].params.between`. A date-family between reads its zone like a top-level grouper: `ResolveZones` walks it LAST as that slot, and the zoned request writes the inherited zone into a COPY of the spec's params, so the caller's request stays pristine. An extension between is buffered and serial and reads no weight.
  - **`metric`** resolves through the registry's `MAT_DISTANCE` consumer list (default `euclidean`; an unknown or unaccepted name is `bad_params` with `details.valid`; there is no `sqeuclidean` alias). A non-negative-domain metric beside `standardize` is `bad_params`.
  - **Engine.** A streaming between keys each row and folds it into one block co-moment per bucket key (fan-out: every key); the spec is then streamable, and mergeable when the grouper's keys merge. Any other between keeps the records and runs ONE whole-set grouping pass at finalize, then folds in record order — buffered, serial. Rows in no bucket are `n_null_key`, excluded from the floor. Bucket order is the grouper's emission order.
  - **Cells.** Centroid = bucket `CoMoment.Mean()`; `standardize` z-scores over the bucketed rows (w* covariance). Every cell is the registry's `Eval` under its pairwise-complete policy (fewer than `min_valid` complete coordinates → null; ±Inf ordinary). A zero-spread member under standardize has NO z-score (NaN, never ±Inf from a rounding residual), so it is skipped rather than nulling the pair. A `*metric.DomainError` nulls the cell and raises ONE `PULSE_MATRIX_METRIC_DOMAIN` per slot. Diagonal exactly 0 where defined. Mahalanobis uses the RAW centroids and the pooled within-bucket covariance; its singular DECISION is the shared rank rule (warning, distances null), its value the reference `InverseSPD`; N* ≤ k is `PULSE_MATRIX_INSUFFICIENT_N` scope `pooled`.
  - **Predict:** shape [k, k] from `EstimateBuckets` over the between (else [0, 0]), state × (1 + k). A k-means between is frequency-only (`weighting.DistanceClassOf`). No Interpretation: distances are in the members' units.
  - **Oracle** `scripts/reference/gen_distance.R` (`weighted.mean` centroids, `stats::dist`, `stats::mahalanobis`): `TestMatrixDistance_MatchesROracle` (1e-9, iterating the registry's consumer list).
