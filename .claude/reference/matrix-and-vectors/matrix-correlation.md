## Matrix slot — co-moment operators, inference, missing modes and warnings (continued)

Continues `## Matrix slot` in `.claude/reference/matrix-and-vectors/matrix-slot.md` (wire, resolution, engine, paths, grouped, refusals live there). Each operator's params, outputs and Interpretation are in its atomic skill `op-mat-<kebab>` and its manifest entry; this slice keeps the contracts.

- **`MAT_COVARIANCE`.** `primary` = `CoMoment.Cov(ddof)` = M2_w / (W − ddof), NaN where W − ddof ≤ 0. Weighted under both kinds (`.claude/reference/weighting.md`, Matrix operators). Oracle: numpy `cov` / statsmodels `DescrStatsW` (`TestMatrixCovariance_MatchesReference`); its diagonal matches the variance aggregators.
- **`MAT_CORRELATION` (Pearson).** `primary` = `CoMoment.Corr()`: clamped to [−1, 1], diagonal exactly 1; a zero-spread member has its whole row and column `null`, diagonal included, and the determinant is then `null`. Weighted under both kinds. **Parity with `TEST_PEARSON_R`:** every cell within `1e-12 + 1e-12·|r|`; bitwise only for unweighted serial ≤ 4096 rows with the test's `field` the earlier member (`linalg.md`, Parity tolerance rationale). A weight-0 row counts toward the matrix's n and is skipped by the test: `mat.n == pearson.n + zero_weight_rows`.
- **`MAT_CORRELATION` rank methods.** `params.method` `spearman` | `kendall` (`pearson` default). A rank method is BUFFERED and NOT mergeable: the request routes buffered and serial on every arm. Finalize (`internal/processing/matrix_rank.go`) reads the buffered rows minus weight-0 rows and computes each cell with the TEST's OWN kernel (Spearman over weighted mid-ranks; Kendall τ-b by Knight's O(n log n) count, frequency-weighted, integer-exact below 2⁵³), so **every off-diagonal cell is BITWISE the two-field test's statistic over the same rows** (`TestMatrixRankCorrelation_TestParity`). Listwise ranks each member once over complete rows; pairwise re-ranks per pair (R `cor(use = "pairwise.complete.obs")`). A cell is NaN when its rows leave a member one distinct value. Every other part is the shared co-moment output over the rank primary. Weight class: frequency only — a probability weight is `PULSE_WEIGHT_UNSUPPORTED`. Oracle: R `cor` (`TestMatrixRankCorrelation_MatchesROracle`, 1e-12).
- **`MAT_PARTIAL_CORRELATION`** (`internal/processing/matrix_partial.go`). Partials come off the precision matrix of `Corr()` over the FOLDED columns: `control: "all"` (default) gives −P_ij / √(P_ii·P_jj) with P = R⁻¹ (`ppcor::pcor`); a control LIST makes each output pair control for exactly those fields via the Schur complement R_OO − R_OC·R_CC⁻¹·R_CO. A listed member leaves the output axis; a listed field outside the members resolves by the vector rules and is folded AFTER the members, so it joins the co-moment, missing mode, components floor, `AccumulatorBytes`, `MaxMatrixDim` and projection. Every member as a control is `bad_params`. Both inversions are the REFERENCE `InverseSPD`, so it is streamable and mergeable. Any undefined input r → every cell NaN. A singular input → `PULSE_MATRIX_SINGULAR` with `dependent_fields`. Oracle: `TestMatrixPartialCorrelation_MatchesROracle` (1e-10).
- **Inference — `params.inference` / `params.alpha`** (`MAT_CORRELATION`, every method, and `MAT_PARTIAL_CORRELATION` only: `vectors.InferenceTypes`). `alpha` without `inference: true` is `bad_params`. On, `auxiliary` gains `p`, `ci_lower`, `ci_upper` — square-symmetric twins of the primary over the output axis, diagonal `null` — so the multiplicity fold reads raw p at `auxiliary.p` for every operator. Off / absent → byte-identical.
  - **One arithmetic.** `correlationInference` (`test_pearson.go`) is shared with `TEST_PEARSON_R`: t = r·√(df/(1 − r²)), |r| = 1 → p = 0 and interval [r, r]; Fisher bounds. Pearson df = N* − 2, zDF = N* − 3; partial subtracts g controls and uses ONE N* for the matrix (the fold's, or the smallest folded pair's under pairwise, warned `PULSE_MATRIX_PAIRWISE_N_STAR`) — ppcor's n.
  - **Sizes.** N* is `PairN` unweighted, else `basis.NStar(PairW, PairW2)` (Kish per pair for probability). Row floors read `PairNMass` (rows with mass), so a cell is null exactly where the single-pair test refuses; the components `n` keeps counting weight-0 rows. A size failure nulls the cell with `PULSE_MATRIX_INSUFFICIENT_N` `scope: "inference"`; low probability n_eff warns `PULSE_WEIGHT_LOW_NEFF`. Matrix warnings are never escalated by Strict.
  - **Rank methods.** Same cell rule with a per-method p and Fisher-z variance. p is R `cor.test(method = …)` at its defaults (exact for small untied samples — Kendall n < 50, Spearman n ≤ 1290 — else the normal / t approximation, no continuity correction); one helper per method (`rank_cortest.go`) is shared with `TEST_KENDALL_TAU` / `TEST_SPEARMAN_R`, so cell and test agree in p as in the statistic. `cor.test` has no rank interval, so Pulse emits Fisher z with the published standard errors (Spearman Bonett–Wright, 4 rows; Kendall Fieller–Hartley–Pearson, 5 rows). Frequency weights only. Oracles: `scripts/reference/gen_matrix_inference.R` (incl. the R `pRho` / `pKendall` grids and generated boundary pairs).
  - **Compute gate and `return`.** Inference is built only under `compute.MatrixAuxiliary` (`minimal` skips it and its warnings). The `standard` preset keeps what a spec asked for: the inference keys, `p_adjusted` / `significant_adjusted`, `matrices[*].multiplicity`, and pairwise `auxiliary.n` only as a COMPANION beside a kept `p` (`returnplan.Companion`; echoed in predict `return.companions` and manifest `return_presets[*].companions`). A partially kept `auxiliary` narrows the gate PER SPEC (`ComputePlan.ForMatrix` over `vectors.Matrix.AuxiliaryKeys`, the one key list predict reads). Gate: `TestReturnAuxiliary_PredictRuntimeParity`.
  - **Multiplicity.** `MatrixSpec.Multiplicity` (these two operators only, else `PULSE_MULTIPLICITY_INVALID`) implies `params.inference` (explicit `false` is `bad_params`); an inherited block reaches only a spec that set `inference: true`. Families `matrix` (default; one per result — spec × bucket) and `request` (pooled with tests / post-tests / overlays). Hypotheses are the DISTINCT pairs (the off-diagonal upper triangle of a square result). The fold (`internal/service/multiplicity_matrix.go`, filed last) writes `auxiliary.p_adjusted` / `significant_adjusted` in the result's encoding plus `MatrixResult.Multiplicity`; a null p is excluded from m. A family member vetoes the `return` skip of `auxiliary`. Predict `p_values` counts C(k, 2) per inferential spec (× bucket bound when grouped). Oracle: `scripts/reference/gen_matrix_multiplicity.R`.
- **`PULSE_MATRIX_NOT_CONVERGED`.** The per-matrix WARNING of every iterative matrix routine stopped at its documented cap (`notConvergedWarning`): minres, `MAT_FACTOR` extraction and rotation, the nearest-correlation repair (emitted beside its NOT_PSD warning). Owned by every `MAT_*`.
- **Missing modes and warnings.** Co-moment operators take `params.missing` — `listwise` (default; any null member drops the row) or `pairwise` (each cell over rows where both members are present; `Corr` reads each pair's own variances, as pandas does) — and `params.max_drop_share` (listwise only, no default). Pairwise adds `auxiliary.n` (cells `PairN`, `w = 0` included). `MatrixResult.warnings` are derived from the merged state (`internal/processing/matrix_warnings.go`), so they are as worker-invariant as the cells, in this order:
  - `PULSE_MATRIX_INSUFFICIENT_N` — scope `matrix` (`n` < 2 or no mass; member and PSD checks then skipped) or, pairwise, scope `pairs`. Cells stay what the arithmetic gives.
  - `PULSE_MATRIX_ZERO_VARIANCE` — members with enough rows but zero spread. Correlation nulls the member's row and column; **covariance KEEPS its exact 0 row and column** (a defined figure, and the numpy oracle's).
  - `PULSE_MATRIX_LISTWISE_HEAVY_DROP` — only with `max_drop_share`: `dropped / rows > max_drop_share` (strict), `rows` = every filter-passing row; `dropped` is an integer summed at merge, so worker-invariant.
  - `PULSE_MATRIX_NOT_PSD` — pairwise only (listwise is PSD by construction); a WARNING here, FATAL or repaired on a decomposition operator (`matrix-decomposition.md`). Undefined / non-positive diagonals are left out; if any remaining cell is undefined nothing is judged. The rest is scaled to unit diagonal and factored by the REFERENCE `Cholesky` with `psdTolerance` = 1e-10 on the diagonal, so singular-but-PSD (collinear) matrices and rounding do not warn. FMA-free, arch-independent. The engine runs the check only where predict's `PSDRisk()` says so (`matrix-slot.md`, Predict).
