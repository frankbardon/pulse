## Virtual vectors — vector-input operators (continued)

Continues `## Virtual vectors` in `.claude/reference/matrix-and-vectors/vectors.md`: tests, attributes and groupers that read a vector. Vector aggregators and `expand` live in `.claude/reference/matrix-and-vectors/vector-aggregators.md`.

**The shared pattern.** Each category carries `vector` / `fields` on its slot (tests also `vector2` / `fields2`), resolved by one leaf in `internal/vectors` (`ResolveTests`, `ResolveAttributes`, `ResolveGroups`) that the field-reference walk (runtime + predict), the engine's prepare step and projection all call. The engine rewrites each slot on a COPY — `Fields` = the resolved literal members, `Vector` cleared — so the factory signature shared with extensions is unchanged. **When that rewrite loses labels or kind bounds, it must also rewrite `Params` to the operator's canonical form** (reverse lists by member name, the range explicit, the metric written out, the reference in member order); dropping that is a silent-wrong hazard. The built-in vector operators of each category are `vectors.Vector{Test,Attribute,Group,Aggregation}Types`; any other built-in refuses a vector input. Shape refusals are `SERVICE_VALIDATION` with `details {test|attribute|group, reason}`; an undefined vector is `PULSE_VECTOR_UNKNOWN`. Read the per-operator param rules in the `*Params` decoders in `internal/vectors`.

**Extension slots.** An extension test, attribute or grouper that sets a vector input has its member sets judged by the same MEMBER rules (`vector` XOR `fields`, `vector2` only beside a first set, unknown vector, inline-field rules) and its factory gets the resolved members on the spec copy; its params, `field` and pair lengths stay its own business.

- **Vector-input tests.** Exactly one of `vector` / `fields`, no `field` / `field2`; a second set only on a `SecondVectorTypes` member (same member count, never with `split_by`); every post-test refuses a vector input. Listwise only (`pairwise_unsupported`). `TEST_MARDIA` is the one BUFFERED vector test (`Streamable() == false`): every row's whitened z needs the fitted mean and ML covariance.
- **Row-local vector attribute: `ATTR_SCALE_SCORE`.** Not fitted: no `fit_on`, no two-pass, weight class none. `stat` `mean` | `sum` (PRORATED: valid mean × p); `min_valid` (below → null, never 0); `reverse` by member LABEL needs a range (explicit, or a kind `scale` vector's bounds). The range check and flip are the shared `vectors.ScaleKey`: `MAT_RELIABILITY` REFUSES an out-of-range value (`PROCESSING_CONFIG`); `ATTR_SCALE_SCORE` reads it as missing and raises one `PULSE_ATTR_SCALE_OUT_OF_RANGE` warning per slot on every arm. Its tally merges, so shard / decode reducers and chain stages carry it with the serial run's counts (`execution-modes.md` (Tally attributes)).
- **Reference comparison: `ATTR_PROFILE_SIMILARITY` / `ATTR_VEC_DISTANCE`.** One engine split by direction (`internal/vectors/compare.go`, `internal/processing/attribute_compare.go`). `metric` resolves through `ResolveKindMetric` for the operator's form; a metric only the OTHER operator serves is `PULSE_VECTOR_METRIC_UNKNOWN` with `details.use` — never converted. `reference` forms: a literal (wrong length → `PULSE_VECTOR_REFERENCE_MISMATCH`), a label map, `{table, key}` / `{table, key_field}` (key column categorical or unsigned integer; an integer key matches by canonical base-10 string, exact to 2^53), plus the computed forms below. A `key_field` value with no profile (or a null key) is a null value counted in `n_reference_missing`; a domain violation is null counted in `n_domain_invalid` — never refusals. Either tally, non-zero, also raises one slot warning after the run (`PULSE_VECTOR_REFERENCE_MISSING`, `PULSE_VECTOR_METRIC_DOMAIN`), components on or off, never escalated by Strict (a data-dependent warning). Counters reset between passes, so a two-pass re-score counts each row once. **Two-pass is PER SLOT:** `ATTR_VEC_DISTANCE` over a fitted metric (`std_euclidean` / `mahalanobis`, explicit or the kind default) reads a fit pass and scores pairwise-complete, unless bound by `params.fit` (row-local). The routing predicate is `vectors.ComparisonTwoPass`; the runtime, predict and the crosstab fusion fact must all read it.
- **Centroid and population references.** Told from a label map by operand shape, strict-keyed, alone in the object. **`{centroid: {filter?, by?}}`**: a pre-pass folds, per present member, Σw·x and Σw over the filtered rows `filter` admits — `AGG_VEC_MEAN`'s arithmetic, so the centroid IS `AGG_VEC_MEAN`'s figure over those rows to the bit (`TestComparison_CentroidIsAggVecMean`). `by` folds one centroid per key; a null `by` or a key no centroid row reached is a reference miss. Weighted by the slot's resolved weight. Two-pass for either type and any metric; cohort-wide (grouped requests run buffered and never refold per group). **`{population: name}`**: bound at build from the request's model set (request / registered populations, in-batch Compose vector fits), aligned by label; an unbound name is `PULSE_VECTOR_REFERENCE_UNKNOWN` (`population_unknown`), a regression's name `PULSE_MODEL_KIND_MISMATCH`. Static thereafter, so row-local.
- **Stored-record references.** `{record: {cohort?, keys: [{field, value}]}}`, strict-keyed at every level. Predict judges the SHAPE only and never looks up (`TestPredictNoExecutionImports`). The Service resolves it BEFORE any processor builds (`internal/service/reference_records.go`): one assert-unique lookup per distinct key set, the request's own cohort when `cohort` is omitted. The result — a stored record or the lookup's refusal — rides the request's model set, so every arm reads ONE resolution. Members read by COLUMN name (numeric, packed_bool or a `v[k]` element; never categorical — codes are dictionary-relative); a null member is missing; a column the record's cohort lacks is `PULSE_VECTOR_REFERENCE_MISMATCH` `record_members_absent`. A lookup refusal (`PULSE_INDEX_MISSING` / `_STALE`, `PULSE_LOOKUP_NOT_FOUND` / `_AMBIGUOUS`, a missing key field) is raised at bind, after the request's own validation, located on the slot — never a fallback; the comparison operators co-own those codes (`error_owners.go`). Static, so row-local. A comparison slot never rides a chain stage.
- **Vector-input (fitted) attributes.** Shared base `internal/processing/attribute_fitted.go`: a two-pass fold of a weighted listwise `linalg.CoMoment` over the rows `fit_on` admits, then a per-operator model (`fit` decides singularity and decomposes; `score` per row). Params share `FittedCommon` (`fit_on`, `missing` listwise only, `fit`). A fit with N* ≤ p nulls every score with `PULSE_MATRIX_INSUFFICIENT_N`; a model refusal nulls every score with its code; both are `Response.Warnings` with `details.scope` `"fit"`. Each fitted attribute reproduces its matrix operator on the fit rows — order, sign and loadings — so corr(score, member) equals the matrix operator's loading (`TestPCScore_SignAgreesWithMATPCA`, `TestFactorScore_SignAgreesWithMATFactor`); singularity uses the one rank rule (`linalg.md`, Tolerances, order and sign). Oracles and tolerances: `scripts/reference/gen_fitted_attributes.R` (Mahalanobis 1e-10 rel + 1e-12 abs; PC score 1e-9; factor score 1e-8, minres 1e-6).
- **Prebuilt fitted state, `params.fit`.** Every fitted model decomposes ONLY its fitted state (the listwise `CoMoment` + weight basis), never rows. `params.fit` names a bound `model.VectorFit` (`internal/model/vector.go`; one `model.Set` namespace with regressions, collisions `PULSE_MODEL_NAME_COLLISION`) instead of folding. `fit` beside a written `fit_on` is `SERVICE_VALIDATION` `fit_and_fit_on`; an unbound name (or a regression's) is `PULSE_MODEL_UNKNOWN`; the fit's labels align to the slot's BY LABEL, else `PULSE_VECTOR_REFERENCE_MISMATCH` `labels_differ`. The state is rebuilt in slot order by permuting stored figures (no arithmetic) and closed at bind, so the slot is row-local and streamable (`execution-modes.md`, Vector fits). **The FIT's basis governs N* and the covariance — the slot's weight never refits it.** A captured fit bound back scores every row to the bit of its `fit_on` fold, in any stored axis order (`TestFittedState_PrebuiltMatchesFitOn`). Sources: Compose `fits`, a `populations` load, a registered population; predict aligns every one by the bind's rule (`vectors.AlignFit`).
- **Vector-input groupers (`GROUP_KMEANS`).** Its key column (`vectors.GroupKeyField`, `<TYPE>_<vector>`) is the output column. Params strict (`k` ≥ 2 required, `seed` int64 with 0 = `KMeansDefaultSeed` — never time-derived — `max_iter`, `n_init`, `standardize`, listwise only). **Determinism:** labels are a function of the member-tuple MULTISET — null-member rows skipped, mass-carrying tuples sorted and merged into distinct points, every sum taken in that canonical order — so row order, shard order and worker counts cannot move a bit (`internal/processing/grouper_kmeans.go`, FMA-free). Zero / invalid-weight rows are assigned, never fitted. k-means++ starts on PCG streams `(seed, start)`, Lloyd iterations, lowest within-SS wins (ties: earliest start), clusters renumbered by descending mass and emitted in that order. `k` above the distinct points is `PROCESSING_CONFIG` `k_exceeds_distinct_points`; a capped best start warns `PULSE_MATRIX_NOT_CONVERGED`. The buffered crosstab fits a k-means axis ONCE over the filtered set and routes every partition by that assignment, so no subset is refit. Predict sizes its row buffer (n·p·8 + k·p·8) and answers `k` buckets. Oracle: `scripts/reference/gen_kmeans.R` (`stats::kmeans` Lloyd from fixed starts, 1e-9 relative).
