## Virtual vectors — vector-input operators (continued)

Continues `## Virtual vectors` in `.claude/reference/matrix-and-vectors/vectors.md`: tests, attributes, aggregators and groupers that read a vector.

- **Vector-input tests (U25 E1-S1).** `types.Test` carries `vector` / `fields` and `vector2` / `fields2`, the `MatrixSpec` mirror, resolved by `vectors.ResolveTests(req, schema, route, ext)` — field-reference step 8 (runtime + predict), `processing.buildRowTests` (stashes the resolved members on a spec COPY: `Fields` / `Fields2` become literal member lists, `Vector*` cleared, so the factory signature shared with extensions is unchanged) and projection (`vectors.TestInputMembers` for inline fields; named vectors ride `Members`). Rules: a built-in vector test (`vectors.VectorTestTypes`: `TEST_BARTLETT_SPHERICITY`, `TEST_BOX_M`, `TEST_HOTELLING_T2`, `TEST_MANOVA`, `TEST_MARDIA`) sets exactly one of `vector` / `fields` and no `field` / `field2`; `vector2` / `fields2` at most one, only on a `SecondVectorTypes` member (`TEST_HOTELLING_T2`'s paired form, U25 E1-S2), same member count, never with `split_by` (`reason` `paired_with_split_by`); any other built-in test and every post-test refuses a vector input; listwise only — `params.missing` other than `"listwise"` is refused (`reason` `pairwise_unsupported` for `"pairwise"`); member-count and form params are judged in the same leaf (`HotellingParams`: `mu` length; `variance` `"unequal"` only on the two-sample form, else `reason` `variance_unequal_not_two_sample`; `LevelVectorParams` (`TEST_MANOVA`, `TEST_BOX_M`): `split_by` required, `reason` `split_by_required`, U25 E1-S3; `SphericityParams` (`TEST_BARTLETT_SPHERICITY`): `split_by` refused, `reason` `split_by_not_accepted`, U25 E1-S4; `MardiaParams` (`TEST_MARDIA`): the same refusal plus `statistic` `skewness` | `kurtosis`, U25 E1-S5 — the one BUFFERED vector test, `Streamable() == false`, keeping n × p values because every row's whitened z needs the fitted mean and ML covariance). Shape refusals are `SERVICE_VALIDATION` with `details {test, reason}`; an undefined vector is `PULSE_VECTOR_UNKNOWN` (`slot` = `tests[i].vector`). **Extension slots (TODO #409).** `ext` names the registered extension operators of the category (runtime: the registry lookup; predict: the snapshot); an extension test, attribute or grouper that sets a vector input has its member sets judged by the same MEMBER rules — `vector` XOR `fields` (`vector_and_fields`), `vector2` XOR `fields2` (`vector2_and_fields2`), a second set only beside a first (`no_vector_or_fields`), `PULSE_VECTOR_UNKNOWN`, and the inline-fields rules (unknown field, `PULSE_VECTOR_MEMBER_TYPE`, `PULSE_VECTOR_DUPLICATE`) — and its factory gets the resolved literal members on the spec copy (an extension grouper keeps its authored `field`, which still names its key column; an extension test or attribute reading a vector may name no `field`). Its params, `field` / `field2`, `split_by` and pair lengths stay its own business.
- **Row-local vector attribute: `ATTR_SCALE_SCORE` (U27 E2-S1).** A member of `vectors.VectorAttributeTypes` but NOT of `vectors.FittedAttributeTypes` (no `fit_on`, no two-pass, not in `requiresTwoPass` / predict's `attributeTwoPass` / `weighting.attributeClasses` — weight class none). Params `vectors.ScaleScoreParams(at, raw, members)`, judged once the members resolve (step 9): `stat` `mean` | `sum` (PRORATED: valid mean × p), `min_valid` 1…p (default p; below → null, never 0), `reverse` by member LABEL, `scale_min` / `scale_max` both-or-neither, else the kind `scale` vector's bounds (`reverse` without a range → `reason` `reverse_needs_scale`). The literal-member rewrite in `resolveAttributeInputs` loses labels and kind bounds, so it also rewrites `Params` to `ScaleScoreConfig.CanonicalParams` (reverse by member name, the range explicit) — a silent-wrong hazard if dropped (`TestScaleScore_RowSemantics`). The range check and flip are the shared `vectors.ScaleKey` (`MAT_RELIABILITY`'s `scoreReliability` reads the same one): `MAT_RELIABILITY` REFUSES an out-of-range value (`PROCESSING_CONFIG`), `ATTR_SCALE_SCORE` reads it as missing and raises one `PULSE_ATTR_SCALE_OUT_OF_RANGE` warning per slot (`details.n_out_of_range` values, `n_rows`) — on every arm: `applyAttributes`, the two-pass stages, and `prependRowLocalWarnings` on `processStreaming`, `processStreamingGrouped` and `RunCrosstabFused`. It is NOT in `mergegate`'s row-local list, so shard / decode-worker reducers and chain stages never carry it (their per-partition tallies would need a merge). Gates: `TestResolveAttributes_ScaleScoreRules`, `TestScaleScore_*`.
- **Reference comparison: `ATTR_PROFILE_SIMILARITY` / `ATTR_VEC_DISTANCE` (U27 E3-S2).** One engine split by direction (`internal/vectors/compare.go`, `internal/processing/attribute_compare.go`); both in `vectors.VectorAttributeTypes`, neither in `FittedAttributeTypes`. Params `vectors.ComparisonParams(at, typ, raw, members, schema)` (step 9): `metric` through `ResolveKindMetric` for the operator's consumer and form (explicit, else the kind default, else `PULSE_VECTOR_METRIC_REQUIRED`); a metric only the OTHER operator serves is `PULSE_VECTOR_METRIC_UNKNOWN` with `details.use` naming it — never converted. `reference`: a literal (member order; wrong length → `PULSE_VECTOR_REFERENCE_MISMATCH` reason `length_differs`), a label map, `{table, key}` or `{table, key_field}` (a categorical or unsigned-integer `u4`…`u64` source column — `vectors.ComparisonKeyFieldAccepts`; an integer key matches the table by its canonical base-10 string, exact to 2^53 since the row value rides `float64`; any other type is `SERVICE_VALIDATION` reason `key_field_type` with `details.accepted`) — the table checks are `ComparisonTableIssue` (predict via `ReferenceIssues` → `ComparisonReferenceIssues`; the runtime at bind, `attributePreparer`). A `key_field` value with no profile (or a null key) is a null value counted in `n_reference_missing`, never a refusal; a domain violation is null, counted in `n_domain_invalid`. Either tally, non-zero, ALSO raises one Response warning per slot after the run (E3-S4, `attributeWarner`): `PULSE_VECTOR_REFERENCE_MISSING` (`attribute`, `type`, `table`, `key_field`, `n_reference_missing` = `n_key_null` + `n_key_unmatched`, `keys` — the 10 smallest unmatched values, row-order independent) and `PULSE_VECTOR_METRIC_DOMAIN` (`attribute`, `type`, `metric`, `n_domain_invalid`, `reasons`) — components on or off, never on a clean run, and like `PULSE_MATRIX_METRIC_DOMAIN` never escalated by Strict (a data-dependent runtime warning). The counters reset with `resetTally`, so a two-pass re-score counts each row once. `min_valid` (default 1) counts complete pairs; `labels` names inline fields' elements (refused beside a named vector). The literal-member rewrite writes `ComparisonConfig.CanonicalParams` (metric written out — the kind is lost —, the reference in member order or its table form, the labels) — silent-wrong if dropped. **Two-pass is PER SLOT:** `ATTR_VEC_DISTANCE` over `std_euclidean` / `mahalanobis` (`vectors.ComparisonFitted`, reading an absent metric's kind default off `Request.Vectors`) reads ATTR_MAHALANOBIS's fit pass (`fittedVectorAttribute`; `fit_on` / `missing` refused beside a row-local metric; weighted — `weighting.attributeClasses` ClassAware) and scores every filtered row PAIRWISE-complete; the predicate rides `attrRequiresTwoPassIn`, predict's `attrTwoPass` and the crosstab fusion fact `AttributeSlotTwoPass` — except a slot bound by `params.fit` (`vectors.FitBound`), which is row-local (`AttributeSlotBound`). `key_field` joins projection through `AttributeInputMembers`. Not on `mergegate`'s row-local list: parallel / shard reducers and chain stages never carry it. Gates: `TestComparisonParams_Rules`, `TestComparison_*`.
- **Centroid and population references (U30 E3-S1).** Two more `reference` forms, told from a label map by operand shape (a label map's values are numbers; `centroid` an object, `population` a string), each strict-keyed and alone in the object. **`{centroid: {filter?, by?}}`** (`vectors.ReferenceCentroid`): a pre-pass (`centroidFold`, `internal/processing/attribute_compare.go`) folds, per PRESENT member, Σw·x and Σw over the filtered rows the optional `filter` admits (compiled through the `fitOnBinder` seam with the request's filter build, like `fit_on`; `AttributeFitOn` lists it after `fit_on`, so projection, the planner and the field-reference walk read its columns; expression slots are named `params.reference.centroid.filter[j]`) with a valid weight > 0 — `AGG_VEC_MEAN`'s per-element rule and arithmetic (`vecBlock.add`), so the centroid IS `AGG_VEC_MEAN`'s figure over those rows to the bit (`TestComparison_CentroidIsAggVecMean`). `by` (the `key_field` type rule; reasons `by_unknown` / `by_type`) folds one centroid per key; each row reads its own key's, and a null `by` or a key no centroid row reached is the existing miss (`n_reference_missing`, one `PULSE_VECTOR_REFERENCE_MISSING` with `reference: "centroid"`, `by`, `n_key_null`, `n_key_unmatched`, `keys`) — a by-less centroid no row reached misses every row the same way. Weighted by the slot's resolved weight (both comparison types are `ClassAware` since this story). **Two-pass for either type and any metric**: `vectors.ComparisonTwoPass` (centroid, or `ComparisonFitted` and not `FitBound`) replaces `ComparisonFitted` at every routing site (`attrRequiresTwoPassIn`, predict's `attrTwoPass`, both `AttributeSlotTwoPass` facts), and `FitBound` is false beside a centroid, so a `params.fit` slot with a centroid keeps its pre-pass (`fittedComparisonAttribute.prebuiltFit`). Cohort-wide over the filtered rows; grouped requests run buffered and never refold per group. Row-local metrics take `centroidComparisonAttribute`; a fitted metric folds fit and centroid in one `PrePass`. **`{population: name}`** (`vectors.ReferencePopulation`): bound at build from the request's `model.Set` (request / registered populations, in-batch Compose vector fits) — the fit's stored mean aligned by label (`vectors.PopulationAlign` → `AlignFit`, `PULSE_VECTOR_REFERENCE_MISMATCH` with `details.population`); an unbound name is `PULSE_VECTOR_REFERENCE_UNKNOWN` reason `population_unknown` (`vectors.PopulationRefusal`, `details.valid` the bound vector fits), a regression name keeps `PULSE_MODEL_KIND_MISMATCH`. Static thereafter, so row-local (not `FitBound`: a fitted metric over a population still fits this request; the population need not be the `fit`). Predict judges it in step 12 (`vectorFitRefusals`, after the slot's own `fit`, as the runtime binds) through the same two helpers. Gates: `TestComparisonParams_CentroidPopulation`, `TestComparisonCentroid_Routing`, `TestPopulationRefusal`, `TestComparison_Centroid*` / `TestComparison_PopulationReference`, root `TestComparisonCentroid_*` / `TestComparisonPopulation_ComposeFit`.
- **Stored-record references (U30 E3-S2).** A fourth computed `reference` form, `{record: {cohort?, keys: [{field, value}]}}` (`vectors.ReferenceRecord`), reserved by operand shape (`record` an object) and strict-keyed at every level; predict judges the SHAPE only (non-empty `keys`, non-empty distinct fields, text values, a `cohort` with a `filename`) through the shared decode and never looks up (`TestPredictNoExecutionImports`). The Service resolves it BEFORE any processor builds (`Service.bindReferenceRecords`, `internal/service/reference_records.go`, called by `process` after `bindRequestModels` — so a Compose slot's or chain stage 0's pre-bound set is extended, never skipped — and by `Materialize`): one `lookupRecords` per distinct `RecordKey` (cohort as written + keys), assert-unique, the request's own cohort when `cohort` is omitted, every column decoded. The result — a `model.StoredRecord` (`processing.NewStoredRecord`; `model` stays a leaf) or the lookup's refusal — rides the request's `model.Set` (`WithRecords`; `Clone` / `WithModels` / `WithCapture` carry it), which every arm builds its processors from, so serial, streaming, parallel decode, shard fan-out, crosstab, join and Compose read one resolution. The slot binds at build (`comparisonCore.bindRecord`): members read by COLUMN name (`Member`: integer, float, packed_bool or a `v[k]` vector element — categorical codes are dictionary-relative, so never), a null member a missing element (NaN, pairwise-complete), a column the record's cohort lacks `PULSE_VECTOR_REFERENCE_MISMATCH` `record_members_absent`. A lookup refusal (`PULSE_INDEX_MISSING` / `_STALE` / `_UNSUPPORTED_SHARDED`, `PULSE_LOOKUP_NOT_FOUND` / `_AMBIGUOUS`, a key field the cohort lacks) is bound in the record's place and raised at bind — after the request's own validation, so predict's refusals still come first — located on the slot (a copy: `attribute`, `slot`), never a fallback; the comparison operators co-own those codes (`error_owners.go`). Static, so row-local (not two-pass). A comparison slot never rides a chain stage (the chain gate refuses it), so an omitted cohort always has one. Gates: `TestComparisonParams_Record`, `TestRecordRefusals`, `TestComparison_RecordReference`, `TestStoredRecord_Member`, `TestBindReferenceRecords`, `TestProcess_RecordReference`, root `TestComparisonRecord_*`.
