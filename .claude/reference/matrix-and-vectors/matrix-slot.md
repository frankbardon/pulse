## Matrix slot — `Request.Matrices` / `Response.Matrices`

- **Wire.** `Request.Matrices []types.MatrixSpec` `{name?, type, vector | fields, params?, weight?, encoding?}` → `Response.Matrices []types.MatrixResult` `{name, type, group_key?, group_header?, primary, auxiliary?, vectors?, scalars?, warnings?}`, one per spec in request order (grouped: one per spec per bucket). Every matrix is a `types.MatrixValues` `{kind, encoding, row_keys, column_keys, labels?, values}` — a DEDICATED type, never the crosstab `MatrixPayload` (whose non-`omitempty` crosstab keys would ride every matrix). `kind` is `square_symmetric` or `rectangular` (p × k: row keys the members, column keys the operator's own, written `full` under `upper`). `encoding`: `full` (default), `upper` (row r holds p − r cells, `values[r][k]` = cell (r, r + k)) or `records`. `labels` only when the vector carried explicit labels. NaN → `null`. Additive `omitempty`. Result `name` defaults to `<TYPE>_<vector>` / `<TYPE>` and is unique per request.
- **Records encoding.** `encoding: "records"` writes EVERY matrix of the result as `{kind, encoding, columns, rows, labels?}`, `rows[r]` = `{"key": row_keys[r], <column>: cell, …}`. **WIRE-ONLY:** the Go `MatrixValues` keeps the FULL layout (stamped `Encoding: records` once after the finalizer, `processing.recordsEncode`), so the multiplicity fold, overlays and every Go consumer read it unchanged; `UnmarshalJSON` reads it back into the full layout. `return` paths and precision address the record cells. A member named `key` is `SERVICE_VALIDATION` `records_key_collision` at resolve (predict alike); a data-derived column of that name fails the slot with the same reason. Payload schema: `MatrixValues` is a `oneOf` (full | records). `full` / `upper` are unaffected. Gates: `TestMatrixRecords_RoundTripsFull` (every built-in operator, every part, bit for bit), `TestMatrixRecords_Golden` (`-update-records-golden`).
- **Resolution.** `vectors.ResolveMatrices` — step 7 of the field-reference walk (after vector resolution, whose refusal wins), called again by the engine to build its slots. Per spec: type known and not hidden; exactly one of `vector` / `fields`; encoding; unique name; params decoded STRICTLY (unknown key refused) — `SERVICE_VALIDATION` with `details.matrix` + `details.reason`; then the named vector or inline `fields` through the vector rules. Projection adds `vectors.MatrixMembers` and the slot weight field.
- **Engine.** `internal/processing/matrix.go`: one `matrixSlot` per spec, reading members through the shared fill (null → listwise skip), the stamped weight (invalid → NaN weight), folding into block co-moments (`Listwise`, or `Pairwise` under `params.missing`); it implements `BlockMerger`. Finalize runs the merged tree through the operator's finalizer (built-in registry `matrixFinalizers`, else the slot's extension finalizer) and adds `scalars.determinant` = Π L_ii² from the REFERENCE `linalg.Cholesky` (NaN → `null` when not PD or a cell is undefined). **Finalizer contract** (`internal/processing/matrix_finalize.go`): a finalizer gets the merged co-moment (kept by every slot, so floor counts and co-moment warnings always exist), the buffered rows if any, the plan, and the `Want*` part flags, and returns `{Primary, Auxiliary, Vectors, Scalars, Warnings}` or a coded error returned AS IS (a nil `Primary` is `PROCESSING_INTERNAL`). A finalizer never builds a part the plan skips, and `render` drops one it did, so `return` stays authoritative. **Row buffer.** A spec that is not `Streamable` is BUFFERED: its slot also keeps exactly the rows `CoMoment.Add` counts (listwise complete rows, pairwise any row with a member present, invalid weights out, `w = 0` in), in record order (`TestMatrixRows_AdmitsWhatCoMomentAdmits`). Rows never merge: merging a buffered slot is `PROCESSING_INTERNAL` (the gate keeps it serial first).
- **Paths.** Serial streaming and buffered fold the same rows into the same blocks, so their bits are equal. A matrix-only request streams (the no-aggregation rule is waived). **Spec-level streamability:** routing reads `types.MatrixSpec.Streamable()` / `Mergeable()` — the type-level answer folded with the spec's params (e.g. a rank-method `MAT_CORRELATION` is buffered and not mergeable). `canStream`, predict, `mergegate.MergeRefusal` and the engine's slot builder all read it; a buffered spec routes the whole request buffered and serial. **Parallel:** `mergegate.MergeRefusal` admits matrices (grouped or not, alone or beside mergeable aggregators) when every spec is `Mergeable()`; windows, features, tests, post-tests and regressions still refuse, and a mergeable grouper is still required. Each partition folds its own blocks, so serial == any worker count bitwise (`TestMatrixInvariance_{Archive,Heavy}`; wiring `.claude/reference/execution-modes.md` (Blocked merge)).
- **Grouped.** Matrices follow `Request.Groups` with no opt-in (`internal/processing/matrix_grouped.go`). One zero-state slot set is minted per bucket key on the key's first sighting — the same moment its aggregator bucket is — so the matrix buckets ARE the grouped `Data` rows, and each bucket's matrix is bit-equal to the ungrouped matrix over exactly its rows. Keys come from the executed grouper only (fan-out: one row feeds every label's bucket; composite keys under several groupers). Emission lives in the ONE grouped tail: spec-major, then bucket, in the FINAL Data order including `Request.Sort` (keys are permuted by row identity, so stable-sort ties land as the rows do and `Components.Matrices` follows). Each result carries `group_key` and `group_header`. A non-empty bucket is never dropped; a thin bucket (N < 2 or no mass) is emitted with `PULSE_MATRIX_INSUFFICIENT_N`. Warnings, `top_pairs` and Components are per bucket. Reducers merge key by key. `ProcessStream`'s `RowIter` carries rows + Components only — matrices ride `Process` / `Compose`.
- **Refusals (unsupported sources and hosts).** One shared rule pair in `internal/mergegate` (no-execute, reachable from predict), so predict, the validators and the runtime refuse identically — never `PROCESSING_INTERNAL`. `MatrixRefusal(req)`: with `joins` → `PULSE_MATRIX_UNSUPPORTED_SOURCE` `{source: "join"}` (joined rows are unstamped); with a `crosstab` → `PULSE_MATRIX_HOST_CONFLICT`; joins win when both apply. `StageMatrixRefusal` → `PULSE_MATRIX_UNSUPPORTED_SOURCE` `{source: "chain_stage"}` for chain stage ≥ 1. Chain stage 0 computes its matrices over the stamped cohort rows; a matrix result never reaches the next stage's rows; a matrix-only stage is still refused (no aggregator). The crosstab fusion answer ignores the slot (`TestCrosstab_MatricesDoNotPerturb`). Parity: `TestMatrixRefusal_PredictAndValidatorsMatchRuntime`.
- **`top_pairs`.** `MAT_CORRELATION` `params.summary.top_pairs: k` (positive integer, else `bad_params`) adds `vectors.top_pairs` `[{row, col, r, n}]`: the strict upper triangle in axis order, NaN r skipped, STABLE-sorted by |r| descending, first k. `r` is the primary cell's exact bits; `n` is `CoMoment.PairN`. Ranking reads only merged cells, so it is worker-invariant. `MAT_COVARIANCE` refuses `params.summary` (covariances are in member units and do not rank).
- **Overlays on a matrix result.** `Request.Overlays` on a request with `Request.Matrices` (never with a crosstab) may name a matrix spec through `OverlayRef.Matrix {name}`, every bucket of its result. Handlers read `MatrixValues` (`ExpandMatrixValues` mirrors `upper` first), never `MatrixPayload`; the pass runs after the multiplicity fold. A computed one keeps the `matrices` slot computed under a `return` that drops it. Long form: `execution-modes.md` (Overlays).
- **Under `Return.precision`.** Precision is WIRE-ONLY: Go keeps full float64. `auxiliary.n` (integer pair counts carried as float64) is NEVER rounded — the one entry of the `precisionExempt` registry in `types/return_shape.go`; `TestPrecision_FloatLeavesClassified` fails until every new float leaf of `Response` is classified round / exempt / keyed. Contract: `docs/src/contract/payload-schema.md` (Return slot).
- **Under a `return` exclusion.** An excluded `matrices` slot is not computed (with `components.matrices` also excluded no slot is minted and no record folded); an excluded `auxiliary` / `scalars` / `vectors` part is never rendered. Kept parts are bit-identical. Contract: the Compute plan paragraph of `.claude/reference/response-components.md`.
- **Emitting from a bound vector fit — `params.fit`.** Every co-moment `MAT_*` operator (built-in or extension) takes the engine-owned `params.fit` (`vectors.EngineMatrixParams`; reserved — an extension may not declare it): a bound vector fit's name. The slot folds NO row and emits from the fit's co-moment rebuilt in column order by label, so the result is BIT-identical to the same operator over the fit request's own rows; the fit's basis governs every basis-reading finalizer and the components floor. Static refusals (`SERVICE_VALIDATION`): `bad_fit`, `fit_and_missing`, `fit_unsupported` (`MAT_DISTANCE`, a non-streamable tier, or a `kind: scale` vector whose range check reads rows), `fit_grouped`. Name and kind are judged in field-reference step 12 (`PULSE_MODEL_UNKNOWN` / `PULSE_MODEL_KIND_MISMATCH`), runtime ≡ predict. **Capture:** a slot whose model set carries a `model.VectorCapture` offers its merged listwise state at finalize, once, on whichever arm finalizes it. Gate: `TestComposeVectorFits_EveryMatrixEmitsFromFit`.
- **Self-description.** Manifest `matrices` (`descriptor.MatrixMeta`, `internal/descriptor/capabilities_matrix.go`) + the `matrix` block (`descriptor.MatrixCapability`; omitted when `capability:matrices` is hidden). Payload-schema enums `MatrixType` (instance-filtered), `MatrixEncoding`, `MatrixKind`. `MAT_*` hard-depend on `capability:matrices`. Purpose in `purposes_matrices.go`. Skill `op-mat-<kebab>`. Gates: `TestSkillsCoverAllMatrixOps`, `TestManifestMatrixOpsComplete`.
- **Predict.** `PredictResult.Matrices []descriptor.MatrixPredict` (omitted when any spec is refused — the refusal is the predict error), built by `predictMatrices` (`internal/descriptor/predict_vectors.go`) from the SAME `vectors.ResolveMatrices` call the field-reference pass makes; read the struct for its fields. The per-matrix rules live in `internal/vectors/matrix_rules.go` (no-execute):
  - **`Matrix.PSDRisk()`** is decided PER TYPE (a type the switch does not name carries no risk; listwise never). The engine runs the `PULSE_MATRIX_NOT_PSD` check ONLY where `PSDRisk()` is true, so `pairwise_psd_risk: false` guarantees no warning (`TestMatrixPredict_MatchesRuntime`, which also asserts each risky fixture really fires). A clamped 2 × 2 correlation with unit diagonal is always PSD; a 2 × 2 pairwise covariance is not.
  - **`Matrix.AccumulatorBytes()`** is one `linalg.CoMoment` state's payload bytes; reflection-pinned to the struct layout (`linalg.md`, CoMoment State size). Memory = state × populated merge blocks × buckets (`limits.MatrixStateBytes`); blocks are counted PER SHARD on an archive (numbering restarts per shard). This is the matrix term of `MaxEstimatedMemory` (`predict-inspect.md`). A buffered spec adds its row buffer, multiplied by `descriptor.FanOutMultiplicity` because a fan-out row is kept by every selected bucket.
  - **Buckets.** `vectors.EstimateBuckets(groups, schema)` is schema-only and an UPPER bound: `bucket_basis` names how it was sized (dictionary, boolean, include, quantile bins, product of several groupers); `unknown` (keys that depend on the data) omits the figures — never guessed.
  - **`MaxMatrixDim`** is checked on the p this resolver yields (`internal/descriptor.RequestLimitFindings`): a certain `LimitFindings` entry and `PULSE_LIMIT_EXCEEDED` before any record decodes (`predict-inspect.md` (Predict)).
