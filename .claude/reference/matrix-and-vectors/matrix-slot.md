## Matrix slot — `Request.Matrices` / `Response.Matrices` (U16)

- **Wire.** `Request.Matrices []types.MatrixSpec` `{name?, type, vector | fields, params?, weight?, encoding?}` → `Response.Matrices []types.MatrixResult` `{name, type, group_key?, group_header?, primary, auxiliary?, vectors?, scalars?, warnings?}`, one per spec in request order (grouped: one per spec per bucket — see Grouped below). Every matrix is a `types.MatrixValues` `{kind, encoding, row_keys, column_keys, labels?, values}` — a DEDICATED type, never the crosstab `MatrixPayload` (whose non-`omitempty` crosstab keys would ride every matrix). `kind` is `square_symmetric`, or `rectangular` for a p × k matrix (`MAT_PCA`'s loadings and eigenvectors: `row_keys` the members, `column_keys` its own — `PC1` … `PCk`, k may be 0 — always written `full` whatever `encoding` says; `matrixFinalizeInput.Rect`; `MAT_COLLINEARITY`'s variance decomposition: a row per variable, `(intercept)` first when uncentered, `column_keys` `D1` … `Dq`); `encoding` `full` (default) or `upper` (row r holds p − r cells, `values[r][k]` = cell (r, r + k)); `row_keys` / `column_keys` are the members in axis order; `labels` only when the vector carried explicit labels. NaN → `null` (`MarshalJSON` through `types.MarshalFinite` on both types). Additive `omitempty`; `format_version` stays `"1.1"`. `result name` defaults to `<TYPE>_<vector>` (vector spec) / `<TYPE>` (inline) and is unique per request.
- **Resolution.** `vectors.ResolveMatrices(req, schema, known)` — step 7 of the field-reference walk (after step 6's `Resolve`, whose refusal wins), called again by the engine to build its slots. Per spec in order: type known and not hidden; exactly one of `vector` / `fields`; encoding; unique result name; params decoded STRICTLY (unknown key refused) — all `SERVICE_VALIDATION` with `details.matrix` + `details.reason` (`unknown_type`, `vector_and_fields`, `no_vector_or_fields`, `unknown_encoding`, `duplicate_name`, `bad_params`); then the named vector (`PULSE_VECTOR_UNKNOWN`) or the inline `fields` through `ResolveSpec("matrices[i].fields", …)` (the vector rules). Projection: `vectors.MatrixMembers` (inline members) beside `vectors.Members`; the slot weight field via `requestWeightFields`.
- **Engine.** `internal/processing/matrix.go`: one `matrixSlot` per spec (the `aggs`-entry analogue; the parallel reducers hold a partition's slots as `processing.MatrixSlots` in `shardPartial.mats`; a grouped partition holds `processing.GroupedMatrices` in `shardPartial.groupedMats` instead). A slot reads each member through `Record.NumericValue` (null → NaN → listwise skip), the stamped weight through `readWeight` (invalid → NaN weight), and folds into `BlockCoMoments` (`Listwise`, or `Pairwise` under `params.missing`); it implements `BlockMerger`. Finalize: `BlockCoMoments.Tree()` → `matrixFinalizers[type]` (the built-in registry; else the slot's extension finalizer, U30 E1-S3) → `MatrixValues` + `scalars.determinant` = Π L_ii² from the REFERENCE `linalg.Cholesky` (FMA-free; NaN → `null` when not positive definite or any cell is undefined). **Finalizer contract (U24 E1-S1, `internal/processing/matrix_finalize.go`).** A `matrixFinalizer` takes a `matrixFinalizeInput` — `CM` (the merged co-moment, kept by EVERY slot, so floor counts and co-moment warnings are always available), `Rows` (a buffered slot's rows, else nil), `Plan()` / `Members()`, `Square(at)` (a square symmetric `MatrixValues` in the slot's encoding) and the plan flags `WantAuxiliary` / `WantVectors` / `WantScalars` — and returns `matrixOutput {Primary, Auxiliary, Vectors, Scalars, Warnings}` or a coded error, which `render` returns AS IS (never `PROCESSING_INTERNAL`; a nil `Primary` is). A finalizer never builds a part the plan skips, and `render` drops one it did, so `return` stays authoritative. `MAT_COVARIANCE` / `MAT_CORRELATION` (Pearson) are `coMomentOutput` over `Cov(ddof)` / `Corr()`: the U16 parts (determinant, pairwise `auxiliary.n`, `top_pairs`, warnings) moved unchanged, every U16 golden and parity test byte-identical. **Row buffer.** A plan whose spec is not `Streamable` (below) is BUFFERED: its slot also keeps a `matrixRows` (the `rankSample` pattern widened to p columns: row-major values, weights, Σw, Σw²) admitting exactly the rows `CoMoment.Add` counts — listwise the complete rows, pairwise any row with a member present (a missing member NaN), invalid weights out, `w = 0` in — in fold order (record order; buffered specs never stream). `Pair(i, j)` is a pairwise cell's own rows. Rows never merge: `mergeSlotSets` refuses a buffered slot `PROCESSING_INTERNAL` (the gate keeps it serial first). Gates: `TestMatrixRows_AdmitsWhatCoMomentAdmits`, `TestMatrixFinalizer_MultiOutput`, `TestMatrixFinalizer_NilPrimaryIsInternal`, `TestMatrixSlots_BufferedMergeRefused`.
- **Paths.** Serial streaming (`processStreaming`; emitted at finalize = terminal flush) and buffered (`processRecords`, filtered records in record order) fold the same rows into the same blocks, so their bits are equal (`TestMatrixCovariance_StreamingEqualsBuffered`). `canStream` / predict `computeStreamable` agree: a matrix-only request streams (the no-aggregation rule is waived for matrices); a grouped request streams on the streaming-grouped path when its grouper does; a two-pass attribute routes buffered, an unknown / hidden type routes buffered (where step 7 refused it). **Spec-level streamability (U24 E1-S1).** Routing reads `types.MatrixSpec.Streamable()` / `Mergeable()` — the type-level answer folded with the spec's params (today: `MAT_CORRELATION` with any `params.method` other than `"pearson"` is buffered and not mergeable) — in `canStream`, predict `computeStreamable` (on the instance-routed spec), `mergegate.MergeRefusal` and, through `vectors.Matrix.Streamable` / `Mergeable` copied at resolution, the engine's slot builder (`resolveMatrixPlans` now admits every offered built-in type; a non-streamable spec gets a row buffer, never `unknown_type`) and `MatrixPredict.streamable`. A buffered spec routes the whole request buffered — so `ProcessStream`, which runs `Process`, runs it buffered (the streaming forced-buffered list) — and serial. Gates: `TestMatrixSpec_StreamableMergeable`, `TestCanStream_BufferedMatrixSpecRoutesBuffered`, `TestPredict_Streamable_MatchesRuntime` (rank-method cases), `TestMergeRefusal`, `TestResolveMatrices_CopiesSpecStreamability`. **Parallel.** `mergegate.MergeRefusal` admits a request carrying matrices, grouped or not, — matrix-only (the no-aggregator rule is waived) or beside mergeable aggregators — when every spec is `MatrixSpec.Mergeable()` (manifest `matrices[].mergeable` is the type-level answer; every built-in type is); windows, features, tests, post-tests and regressions still refuse. `DecodeWorkers` / `ShardWorkers` then fan it out and each partition folds its own blocks, absorbed into one set at merge, so serial == any worker count bitwise (`TestMatrixCovariance_WorkerInvariant`; wiring `.claude/reference/execution-modes.md` (Blocked merge)). A mergeable grouper is still required (the grouper rule), so a `GROUP_QUANTILE` request runs serially.
- **Grouped (U16 E4-S1, E4-S3).** Matrices follow `Request.Groups` with no opt-in. `internal/processing/matrix_grouped.go`: `GroupedMatrices` resolves the specs ONCE (`matrixPlanSet`) and mints one zero-state slot set per bucket key on the key's first sighting — the same moment its aggregator bucket is minted, so the matrix buckets ARE the grouped `Response.Data` rows. Each slot's `BlockCoMoments` allocates only the merge blocks that bucket's rows touch, and finalize runs the bucket's own fixed tree, so a bucket's matrix is bit-equal to the ungrouped matrix over exactly its rows (`FILTER_INCLUDE` on the key — `TestMatrixGrouped_OneResultPerBucket`). Keys come from the executed grouper only: the streaming-grouped path and both reducers key through `GroupKeyer` (fan-out: one row feeds every label's bucket), the buffered path folds `Grouper.Group`'s per-bucket record slices in record order; with two or more `groups` entries every arm (buffered, streaming, both reducers — U54) keys a bucket by its composite key, and the matrices follow whatever the rows do (`TestMatrixGrouped_BucketOrderFollowsData`; worker arms: root `TestMultiGrouper_MatricesCarryTuple`, `TestMultiGrouper_BitExactAcrossWorkers`). Emission lives in the ONE grouped tail (`FinalizeGroupedStream`, `GroupedTail.Matrices`; the buffered `processRecords` calls the same `finalize` over `processGrouped`'s ordered keys): spec-major, then bucket, in the FINAL Data order, `Request.Sort` included (owner decision 2026-10-06, E4-S3, reversing E4-S1's pre-Sort order): keys start in `orderKeysByInclude` order, then the ONE shared helper `sortGroupedRows` (both exits call it) runs `window.Sort` on the rows and permutes the keys by row identity — never the group cell — so stable-sort ties land exactly as the rows do and `Components.Matrices` follows; Sort only reorders (no Limit slot), so no bucket drops (`TestMatrixGrouped_BucketOrderFollowsSort`; Compose / chain stage 0: `TestMatrices_ComposeAndChainStageZero`). Without a Sort the output is unchanged. Each result carries `group_key` (`AxisKey{key}`, the Data row's key string; the full key tuple under two or more groupers) and `group_header` (`{fields: [Groups[0].field], types: [Groups[0].type]}`; every grouper's key column and type under two or more); its `Components.Matrices` entry carries the same `group_key`. A bucket key with no matrix state renders from empty slots, so a non-empty bucket is never dropped; a thin bucket (N < 2 or no mass) is emitted with `PULSE_MATRIX_INSUFFICIENT_N` (its correlation cells null; a WEIGHTED covariance over one row is the degenerate finite `0 / (W − ddof)` when W > ddof — the warning flags it). Warnings, `top_pairs` and Components are per result, so per bucket. Reducers: `foldGroupedRow` feeds `groupedMats.UpdateRow(key, rec)` per key, `mergeShardPartials` merges key by key (`GroupedMatrices.Merge`: a key one side alone saw moves over whole, a shared key merges slot-wise via `MergeBlockMerger`), and the grouped arm of `finalizeMergedPartial` hands `groupedMats` to the tail — it no longer attaches an ungrouped `mats` result. Streaming grouped == buffered grouped bitwise (`TestMatrixGrouped_StreamingEqualsBuffered`); the shard and decode arms match serial per bucket (`TestMatrixGrouped_ParallelArms` pins the wiring; `TestMatrixGrouped_WorkerInvariant` is the gate: every operator × listwise / pairwise × unweighted / weighted, a plain grouper with a one-row thin bucket and a fan-out grouper, plus `Request.Sort` asc / desc on an aggregate (the sorted serial run is the reference), serial == DecodeWorkers 2/3/7/8 on a single file above the parallel threshold == ShardWorkers 2/3/8 on an archive — per bucket every cell, `auxiliary.n`, the determinant, `top_pairs`, the matrix warnings incl. the thin bucket's `PULSE_MATRIX_INSUFFICIENT_N`, `Components.Matrices` and `Components.Run`, with the beside-vehicle's per-bucket instance count proving each arm partitioned). `ProcessStream`'s `RowIter` carries rows + Components only — matrices, like tests and regressions, ride `Process` / `Compose`.
- **Refusals (unsupported sources and hosts).** One shared rule pair in `internal/mergegate` (no-execute, reachable from predict), so predict, the validators and the runtime refuse with the same code, message and details — never `PROCESSING_INTERNAL`. `MatrixRefusal(req)` (a non-empty `matrices` slot only): with `joins` → `PULSE_MATRIX_UNSUPPORTED_SOURCE` `{source: "join", matrices, joins}` (joined rows are unstamped); with a `crosstab` → `PULSE_MATRIX_HOST_CONFLICT` `{host: "crosstab", matrices}` (the crosstab arms compute no matrices); joins win when both apply. It sits right after `JoinCountRefusal` at every site: `Service.process` (before every dispatch arm, so Compose / ComposeParallel slots and chain stage 0 get it through `Process`), `Predict`, `ValidateJoin`, the Compose slot validator and the chain validator's stage 0 (joined or not). `StageMatrixRefusal(req, i, name)` → `PULSE_MATRIX_UNSUPPORTED_SOURCE` `{source: "chain_stage", matrices, stage, stage_name}` for a chain stage ≥ 1, checked right after `StageJoinRefusal` by the runtime and the chain validator (which then judges the stage no further). `ChainRefusal` judges a stage with its `matrices` stripped — a matrix result never reaches the next stage's rows — so chain stage 0 computes its matrices over the stamped cohort rows (on stage 0's response); a matrix-only stage still has no aggregator and is refused. Crosstab no-regression: `crosstabfuse` is untouched, and `TestCrosstab_MatricesDoNotPerturb` pins that the fusion answer (runtime and predict) ignores the slot and matrix-free crosstab bytes never move. Parity: `TestMatrixRefusal_PredictAndValidatorsMatchRuntime`, `TestMatrices_ComposeAndChainStageZero`.
- **`top_pairs` (U16 E3-S4).** `MAT_CORRELATION` `params.summary.top_pairs: k` (a positive integer; `0`, negative, fractional, `summary: {}` or an unknown `summary` key → `bad_params`) adds `vectors.top_pairs` — a `[]types.MatrixPair` `[{row, col, r, n}]` (Go: type-assert `MatrixResult.Vectors["top_pairs"]`). Candidates are the strict upper triangle in (row, col) axis order, a NaN r skipped (no diagonal, no zero-spread member); a STABLE sort by |r| descending keeps axis order among equal |r|, then the first k (k past the candidate count lists every one; p = 1 gives `[]`). `r` is the primary cell's exact bits; `n` is `CoMoment.PairN` — the pair's own N under pairwise, the listwise N otherwise. Ranking reads only the merged cells, so it is as worker-invariant as they are (`TestMatrixCovariance_WorkerInvariant` lists every pair and compares bits and order). `MAT_COVARIANCE` refuses `params.summary` (`bad_params`, `details.param` = `summary`): covariances are in the members' own units and do not rank. Manifest `output_keys.vectors` = `["top_pairs"]`; no Interpretation of its own (each entry is a `primary.values` cell). `encoding` does not touch it. Gates: `TestTopPairs_Ranking`, `TestMatrixCorrelation_TopPairsResult`, `TestResolveMatrices_TopPairs`; `upper` end to end over the CLI (`TestAPIProcess_MatrixUpperAndTopPairs`) and MCP (`TestProcessTool_MatrixUpperAndTopPairs`).
- **Overlays on a matrix result (U28 E4-S1).** `Request.Overlays` on a request carrying `Request.Matrices` (no crosstab — `Crosstab + Matrices` stays refused, so one request never mixes crosstab and matrix-result overlays) may name a matrix spec through `OverlayRef.Matrix {name}` (the tenth arm; `EffectiveName`), every group bucket of its result. The runtime pass is `processing.ApplyMatrixResultOverlays`, run by the service AFTER the multiplicity fold; handlers read `MatrixValues` (`ExpandMatrixValues` mirrors an `upper` encoding first), never the crosstab `MatrixPayload`. A computed one keeps the `matrices` slot computed under a `return` that drops it (`resolveComputePlan`). First kind: `OVERLAY_MATRIX_GROUP_SUMMARY`. Long form: `execution-modes.md` (Overlays).
- **Under `Return.precision` (U17 E3-S1).** Precision is WIRE-ONLY: the Go `MatrixValues` / `MatrixResult` keep full float64. On the wire every float in `primary.values`, `vectors.top_pairs[*].r` and `scalars.determinant` is `strconv.FormatFloat(v, 'g', p, 64)` (exponent form accepted, NaN still `null`); `auxiliary.n` (integer pair counts carried as float64) is NEVER rounded — it is the one entry of the declared `precisionExempt` registry in `types/return_shape.go`, gated by `TestPrecision_FloatLeavesClassified` (every float leaf of `Response` classified round / exempt / keyed; `auxiliary` is keyed: `n` exempt, any future companion rounds); `top_pairs[*].n` is an `int` and untouched. `encoding` is unaffected: `upper` keeps its ragged rows cell for cell (`TestPrecision_SlotFamilies`). The path grammar addresses a matrix as `matrices[*].primary.values` like any other slot. Contract: `docs/src/contract/payload-schema.md` (Return slot).
- **Under a `return` exclusion (U18 E2-S3).** An excluded `matrices` slot is not computed: with `components.matrices` also excluded no slot is minted on any arm (serial, grouped, parallel decode, shard), so no record is folded; a kept `components.matrices` still folds but renders no `MatrixResult`. An excluded `matrices[*].auxiliary` / `scalars` / `vectors` is never rendered at finalize (the per-record fold stays: `primary` needs it). Kept parts are bit-identical to the `return`-absent run's; the `Request.Vectors` warnings are request-derived and stay. Contract: the Compute plan paragraph of `.claude/reference/response-components.md`.
- **Emitting from a bound vector fit — `params.fit` (U30 E2-S2).** Every co-moment `MAT_*` operator (built-in or extension) takes the engine-owned `params.fit` (`vectors.EngineMatrixParams` = `missing`, `max_drop_share`, `fit`: decoded on `missingParams`, stripped from an extension's params, a `ParamMeta` naming it `reserved_matrix_param`): the name of a bound vector fit (a Compose `fits` entry of kind vector; the runtime's `model.Set`, `LookupVector`). The slot folds NO row (`UpdateRow` returns at once) and `result()` emits from the fit's co-moment rebuilt in `Columns` order (`bindMatrixFit` → `labelPermutationAt("matrix", …)` over `Matrix.FitLabels()` — each member's display label, then a control outside the members by name — and `fittedStateFromVector`; `merged()` clones it per call), so the result is BIT-identical to the same operator over the fit request's own rows; the fit's basis governs every basis-reading finalizer and the components floor (`basisWeightSpec` replaces the slot weight: `sum_weights` / `n_eff` keys per the fit's kind, `n` = the fit's N, `n_listwise_dropped` 0). Static refusals in `vectors.resolveFit` (SERVICE_VALIDATION `matrix`): `bad_fit` (empty), `fit_and_missing` (`missing` or `max_drop_share` beside it — a bound state reads no row), `fit_unsupported` (`MAT_DISTANCE`, a non-streamable tier — a rank method, a buffered extension — or `HasScale`, whose range check and reverse keying read rows), `fit_grouped` (groups / crosstab). The name and kind are judged in field-reference step 12 (`model.CheckVectorFit`: `PULSE_MODEL_UNKNOWN` / `PULSE_MODEL_KIND_MISMATCH`, `details.matrix`), runtime ≡ predict; the label alignment is the bind's (`PULSE_VECTOR_REFERENCE_MISMATCH labels_differ`, `details.matrix`). Plumbing: `buildMatrixSlotsWith(…, models)`, `processing.BuildMatrixSlots(…, models)` for the shard / parallel-decode reducers (`model.SetFrom(ctx)`). **Capture.** A slot whose set carries a `model.VectorCapture` (a Compose vector fit request's battery) offers its merged listwise state at `result()` (`offerCapture`, labels `FitLabels`, members `Columns`, `Operator` = its type) — once, on whichever arm finalizes it; a fitted attribute of `model.VectorFitAttributeTypes` offers its `fittedState` at `Finalize`. Gates: `TestComposeVectorFits_EveryMatrixEmitsFromFit` (root; every built-in co-moment operator + an extension, `DecodeWorkers` 1 / 4), `TestComposeVectorFits_*` (`internal/service`).

- **Predict (U16 E3-S3).** `PredictResult.Matrices []descriptor.MatrixPredict` (`matrices`, `omitempty`; omitted when any spec is refused — the refusal is the predict error), one per spec in request order, built by `predictMatrices` (`internal/descriptor/predict_vectors.go`) from the SAME `vectors.ResolveMatrices` call the field-reference pass makes: `name`, `type`, `shape [p, p]` (`MAT_PCA`: `[p, k]` for an integer `components`, else the `[p, p]` bound; `MAT_FACTOR` likewise for an integer `factors`), `axis_keys` (= the result's `row_keys` / `column_keys`), `labels` (explicit only), `missing`, `encoding`, `accumulator_bytes`, `bucket_basis` / `estimated_buckets` / `estimated_cells` / `estimated_bytes`, `streamable` (the spec's; request routing is `PredictResult.Streamable`), `mergeable` (the spec's — false for a rank method, U24 E1-S3), `row_buffer_bytes` (a buffered spec only: record count × `vectors.Matrix.RowBytes()` = 8·(p + 1), `limits.MatrixRowBufferBytes`; omitted with the record count unknown — and added to `estimated_bytes` and to the `MaxEstimatedMemory` matrix term, `matrixMemory`; gates `TestPredict_Matrices`, `TestMatrixMemory_CountsRowBuffer`), `pairwise_psd_risk`. The two per-matrix rules live in `internal/vectors/matrix_rules.go` (no-execute, importable by predict): **`Matrix.PSDRisk()`** — decided PER TYPE (U24 E1-S1; a type the switch does not name carries no risk, where it used to inherit the covariance rule — `TestPSDRisk_PerType`): pairwise `MAT_COVARIANCE` and `MAT_PCA` `on: "covariance"` at p ≥ 2, pairwise `MAT_CORRELATION`, `MAT_PARTIAL_CORRELATION`, `MAT_RELIABILITY`, `MAT_COLLINEARITY`, `MAT_FACTOR` and `MAT_PCA` on a correlation at p ≥ 3 (partial: p counts the folded columns, outside controls included; there the risk means refusal or repair, never the plain warning) (a clamped 2 × 2 r with a unit diagonal is always PSD; a 2 × 2 pairwise covariance is not, its variances and covariance resting on different rows); listwise never. The engine runs the `PULSE_MATRIX_NOT_PSD` check ONLY where `PSDRisk()` is true, so `pairwise_psd_risk: false` guarantees no warning (`TestMatrixPredict_MatchesRuntime`, which also asserts each risky fixture really fires). **`Matrix.AccumulatorBytes()`** — the payload bytes of one `linalg.CoMoment` state: `40 + 8·(p + p(p+1)/2)` listwise, `40 + 72·p(p+1)/2` pairwise (header n, nMass, nInvalid, w, w2; listwise means + packed co-moments; pairwise a 9-word state per packed cell — n, nMass, w, w2, mi, mj, mii, mjj, cij; it said 32 / 7 words until matrix-extensions-hardening E8-S1, a ~22% pairwise undercount; `TestAccumulatorBytesMatchesCoMomentLayout` (linalg) now derives both word counts from the structs by reflection). The run holds one per populated merge block until finalize, so its matrix memory is that times its block count; Go and map overhead are not counted. **Grouped cost (U16 E4-S2).** `vectors.EstimateBuckets(req.Groups, schema)` — schema-only; two or more groupers report the PRODUCT of every grouper's bound (basis `product`, unknown if any grouper is; U54 E1-S3) — gives every spec `bucket_basis` plus, when known, `estimated_buckets`, `estimated_cells` (= buckets × p²) and `estimated_bytes` — the real state since U19 E2-S3: merge blocks × buckets × `accumulator_bytes` (`limits.MatrixStateBytes`), the blocks `ceil(records / 4096)` over the header count, PER SHARD on an archive (numbering restarts per shard, so 4,097 + 5 sharded rows hold three blocks where one 4,102-row file holds two; `limits.MergeBlocks`, `limits.MergeBlockSize` pinned to `linalg.MergeBlockSize`). It was buckets × `accumulator_bytes` before — an undercount by the block count. It is the matrix term of the `MaxEstimatedMemory` estimate (`predict-inspect.md`); a bucket count the schema cannot size is bounded there by the record count (each populated block-bucket pair holds a record). Bases: `ungrouped` (1); `dictionary` (`GROUP_CATEGORY` over a categorical, `GROUP_SET_PER_ELEMENT` over a set — the dictionary size); `boolean` (`GROUP_CATEGORY` over `packed_bool`, 2); `include` (`Group.Include`'s distinct keys the field can produce — on `GROUP_CATEGORY` / `GROUP_SET_VALUE` / `GROUP_SET_PER_ELEMENT` only, the groupers that honour it); `quantile_bins` (`GROUP_QUANTILE`'s `interval`, default 4); `product` (two or more sized groupers — the product of their bounds); `unknown` (range, rounded, date, numeric-category and set-composition keys depend on the data — the three figures are omitted, never guessed).
