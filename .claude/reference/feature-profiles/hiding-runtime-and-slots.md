# Feature profiles — Runtime hiding, Predict hiding, Request-slot gate

Per-topic slice of the feature-profiles reference (Runtime hiding, Predict hiding, Request-slot gate). Index (preamble + section map): `.claude/reference/feature-profiles.md` — load it first, then only the slice(s) your change touches.

## Runtime hiding (registry operators)

**Hide at the native lookup site, never with a pre-check.** `Service.SetExtensions` / `SetInstanceSnapshot` both re-derive the runtime registry as `processing.ExtensionRegistry.WithHidden(snap.Hidden)` (`rescopeExtensions`; no hidden names → the installed registry unchanged, nil stays nil). Every `Lookup*` (AGG, ATTR, FILTER, GROUP, WIN, FEAT, row TEST, post TEST) answers a hidden name not-found, so each execution path reaches its OWN unknown-name error — same code, message, details and ordering against zone / field-ref / label / strict faults. Windows and features resolve through `window.Resolver` / `feature.Resolver` (the registry's `LookupWindow` / `LookupFeature`), not an overlay map, so they cannot bypass it. The route-choosing facts read the same predicate: `IsStreamable`, `IsMergeable`, `AggregatorMarginReducibility`, the two-pass check and the merge-gate adapter (`registryMergeFacts`, which answers a hidden name known-and-not-mergeable) give a hidden name the never-registered answer, so it cannot take a different stream / merge / fused route to its error. `internal/mergegate` consults the adapter's attribute answer BEFORE its built-in row-local list (`ATTR_FORMULA`, `ATTR_DATE_PART`) for the same reason.

**Other sites.** The `FacetSchema` `additive_fields` scope filters build against the instance registry (they used a nil registry — which also broke embedder filterers there). `FilterToFileWithRequest`'s filterer→expression translator refuses a hidden type with its unsupported-type error. `descx.ResolveDefaults(req, schema, inst)` skips a hidden default target exactly like "no rule for this type" (no Type written, no `DefaultApplied` entry); the service passes its snapshot, predict and the validators pass `PredictOptions.Instance`, `NormalizeRequest` takes one. Engine-internal uses that no request names stay unscoped: `FilterToFile`'s raw expression still compiles through `FILTER_EXPRESSION` and therefore fails when that operator is hidden; synth fidelity (`synth_fidelity.go`) runs `TEST_KS` / `TEST_CHISQ` on an unscoped processor.

**Regressions.** `regression.BuildWith` / `BuildStreamingWith` / `FitBufferedWith` take a `regression.Resolver`; the processor passes `ExtensionRegistry.LookupRegression`, which misses a hidden type, so both orchestrators raise their own `unknown regression type` error. `canStream` treats a hidden type as non-streamable (a never-registered type's `Streamable()` is false), so a hidden `REG_OLS` routes buffered too.

**Overlay kinds — route, don't re-word.** The five per-host handler tables are globals, so the hide is a ROUTE: `ExtensionRegistry.overlayRoute(kind)` returns the authored kind, or `""` (a kind no table, switch or types catalog knows) when hidden. Every kind-keyed decision keys on the route while messages and details keep naming the authored kind: the MATRIX table + the `OVERLAY_FORMULA` special case + the runtime Level/Within gate (`ApplyOverlaysWithExtensions`), the pairwise slab gate, the SERIES table + YoY frequency promotion + `canStreamOverlays` (so a streamable hidden kind routes buffered), the CHAIN table (`ApplyChainOverlaysWithExtensions`), the FACET table (`ApplyOverlaysFacetWithExtensions`), and the COMPOSE single- and multi-layer tables + its `OVERLAY_FORMULA` arm + panel slab gate + MATRIX-shape gate (`checkSlotShapeAndSchemaRouted`). A never-registered Compose kind SUCCEEDS with an empty stub layer, so a hidden one does too. The parallel shard / decode reducers fold SERIES overlays in the shared grouped tail, which carries the registry (`GroupedTail.Extensions`). The request-time descriptor gates take `PredictOptions.Instance` (`PredictOptions.overlayRoute`): the Request-host catalog probe and its Level/Within rules, the Compose gate 0 and per-spec cost, the Facet catalog probe (`ValidateFacetOverlaysWithOptions`). `types.ResolveBuiltinGroupFanOut` is unreachable for a hidden grouper: both slab gates run after their host materialised, which already resolved every grouper.

## Predict hiding

**Predict sees only the instance.** `Pulse.Predict`, `Pulse.PredictBytes` and the non-Request roots `PredictCompose` / `PredictFacet` / `PredictChain` (core `predict`, no `features.go` row) set `PredictOptions.Instance` to the service's `InstanceSnapshot` (the extension snapshot already omits hidden extensions). Predict cannot import the registry, so the hide is a ROUTE, the no-execute twin of the runtime's: `opRoute(inst, t)` returns `t`, or `""` when the instance hides it, and every type-keyed predict decision keys on the route while messages and details keep naming the authored type — an emptiness check (a slot with no Type) never reads it. Routed sites: the FEAT / WIN / row+post TEST / REG known-type checks (a hidden name gets the unknown error a never-registered one gets); `computeStreamable` (every per-type `Streamable()`, the two-pass attribute set, `routedRegression`); the per-slot `ComponentSchema` lookups; the decimal matrix and numeric-on-categorical rules (Request, crosstab cell and margin aggregations); the crosstab cell's margin class and map-valued gates; the attribute default label; the overlay host-type rules (pairwise weighted cell, baseline-index series length, YoY's `GROUP_DATE`, the two-sample map-valued carve-outs) and the overlay descriptors' streamability / shape / cost (`appendOverlayDescriptors`, facet too); the chain validator's merge-gate adapter (`snapshotMergeFacts`, hidden → known-and-not-mergeable, as `registryMergeFacts`) and chain-overlay kind check; the facet `additive_fields` `FILTER_EXPRESSION` rule; the suggestions (no proposal names a hidden operator; a hidden streamable substitute is no substitute). `ResolveDefaults` gets the instance at every predict / validator / chain site, so `DefaultsApplied` never names a hidden target. Without `capability:weighting` `ResolveWeights` still runs (its refusals stay, `AGG_WEIGHTED_MEAN`'s remedy names only `params.weight_field`) but `PredictResult.Weights` is not reported, and neither inspect nor predict reports the SPSS `suggested_weight` (`descx.SuggestWeight` reads the instance; the facade skips the sidecar read) — `predict-inspect.md` (Suggested weight).

**The shared predict ↔ runtime rules take the instance on BOTH sides**, so the runtime refuses a hidden name at the shared rule exactly where it refuses a never-registered one: `ResolveZones` / `ResolveFacetZones` (a hidden zone-capable operator is not zone-capable), the field-reference walk (`ScopedFieldRefRefusal` / `ScopedFacetFieldRefRefusals` at runtime, `fieldRefRefusals` in predict; the unscoped `FieldRefRefusals` / `FieldRefRefusal` / `FacetFieldRefRefusals` remain) and `CategoricalAggregationIssues` (strict refusal). Refusal prose that still names a built-in as literal text names only a hard-dependency target the refusing operator cannot be enabled without (the T/Z carve-out's `AGG_WELFORD`, YoY's required `GROUP_DATE`); every other fixed list or remedy is instance-dependent ("Instance-dependent wording").

## Request-slot gate

**A set slot the instance hides is an unknown field.** `descx.SlotRefusal(v, inst)` (`internal/descriptor/request_slots.go`) takes a `*types.Request` / `ComposedRequest` / `ChainRequest` / `FacetRequest` and returns `PULSE_REQUEST_UNKNOWN_FIELD` in the strict-decode shape: `unknown_keys` (the hidden slots set on the first offending root), `valid_keys` (that root's VISIBLE keys) and `suggestions` (nearest visible key). The shape is built once, by `strictjson.UnknownFieldError` (`internal/strictjson`, behind `descx.UnknownFieldError`), which the shared strict request decoder raises too — so an unknown key and a hidden slot cannot drift. Every JSON request root (CLI request files, MCP tool arguments, sweep bodies, `for_each` items) decodes through `strictjson.DecodeInto` RECURSIVELY; with `descx.StrictOptions(inst)` (`Hidden` = `descx.StrictHidden(inst)`, the `gatedSlots` table keyed by struct type) a hidden slot at ANY depth is refused at decode as an unknown key, `valid_keys` / `suggestions` never name one, and a ROOT's own keys are judged before anything nested (a compose / chain root's hidden `overlays` before its requests) — byte-identical to `SlotRefusal` (`TestCheckUnknownKeys_HiddenSlot*`, `TestTools_InvokeScopesStrictDecodeToInstance`, `TestTools_InvokeRefusesHiddenNestedWeight`). MCP's decoders take the calling instance (`decodeFunc` gets `facadebridge.InstanceSnapshot(p)`); the CLI instance is unprofiled. A present key is refused even with an empty value, as strict decode refuses any set key.

**Slot → owning feature** (`gatedSlots`): `Request.crosstab` → `capability:crosstab`; `CrosstabSpec.cells` (+ the `MatrixPayload.cell_labels` / `measures` and `CrosstabComponents.measures` result slots) → `capability:crosstab_cells` (a hard edge on `capability:crosstab`; a set one is refused at the crosstab by `nestedCrosstabCellsRefusal`, the MCP bound crosstab schema drops the key, the manifest zeroes `supports_cells` / `cells_rules`; it owns `PULSE_CROSSTAB_CELLS_INVALID` / `_DUPLICATE_LABEL`; both shipped example profiles that keep the crosstab keep it — U47 E2-S2); `Request.joins` → `capability:joins`; `Request.overlays` (+ the `Response.overlays` result slot, one shared `requestOverlaysSlotGate`) → the MATRIX host (`capability:crosstab`), the SERIES host a grouped Process runs (`capability:compose`) or the MATRIX_RESULT host a `Request.matrices` request produces (`capability:matrices`, `OVERLAY_MATRIX_GROUP_SUMMARY`); `ComposedRequest.overlays` (+ `ComposedResponse.overlays`) → `capability:compose`; `ComposedRequest.sweep` (+ the `ComposedResponse.ranking` result slot) → `capability:compose_sweep` (hard edge on `capability:compose`; the `SweepSpec` / `SweepAxis` / `SweepRank` / `RankEntry` defs drop with the slots); `ComposedRequest.fits` (+ the `ComposedResponse.fits` result slot) → `capability:compose_fits` (each fit request's own slots are gated like a slot's, located `details.fit`; the `FitSpec` def drops with the slot; `PULSE_FIT_INVALID` / `PULSE_MODEL_NAME_COLLISION` / `PULSE_MODEL_UNKNOWN` are owned by it — `PULSE_MODEL_UNKNOWN` jointly with `ATTR_REG_PREDICT`, `ATTR_REG_FITTED` and `ATTR_REG_RESIDUAL` (their `params.fit`), which also share `PULSE_MODEL_SCORE_INVALID` / `_PREDICTOR_MISSING` / `_PREDICTOR_NOT_NUMERIC`; `_TERM_UNKNOWN` is `ATTR_REG_PREDICT`'s); the `save` key on `RegressionSpec` and on a `fits` entry (`FitSpec`) → `capability:model_save` (a request-slot capability; a set one is refused at the object by `nestedModelSaveRefusal` / the fits loop of `SlotRefusal` with `details.path` (`regressions[0]`, `fits[0]` + `details.fit`), the payload schema and the MCP bound schemas (`addModelSave`) drop the key; it owns `PULSE_MODEL_SAVE_INVALID` / `_WRITE_FAILED` / `_OVERWRITTEN`; `read-only-analyst` excludes it — it writes files); the `populations` key on `Request` → `capability:models` too (`populationsSlotGate`; one bound-model namespace, so one capability; the MCP `populationsSchema` drops with it — U30 E2-S3); the `params` key on `Request`, `ComposedRequest` and `ChainRequest` (the top-level block every sub-request inherits, U58 E3-S2) → `capability:params` (a request-slot capability, hard edge any-of ATTR_FORMULA / FILTER_EXPRESSION / OVERLAY_FORMULA / `capability:regression_holdout`: `paramsSlotGate`, `setSlots` lists it, the payload schema (`paramsSchema` override) and the MCP bound schemas drop it; an expression reading `params.<name>` on a hiding instance is `PULSE_PARAMS_UNDECLARED`, as on any request declaring none — U58 E3-S1); the `models` key on `Request` and `FacetRequest` → `capability:models` (a root slot of both: `setSlots` lists it, the payload schema and the MCP bound schemas (`modelsSchema`) drop it with the `ModelRef` def; it owns `PULSE_MODEL_REF_INVALID` / `_FILE_UNREADABLE` / `_FILE_INVALID` / `_VERSION_UNSUPPORTED` and shares `PULSE_MODEL_NAME_COLLISION` / `_UNKNOWN` with `capability:compose_fits`; `read-only-analyst` keeps it — a load reads, never writes); `ChainRequest.overlays` (+ `ChainResponse.overlays`) → `capability:process_chain`; the item `for_each` on `Window` / `Feature` / `Attribute` → `capability:for_each` (a request-slot capability; a set one is refused at the item by `nestedForEachRefusal` with `details.path`, the payload schema and the MCP item schemas drop the key and the `ForEach` def; `PULSE_FOR_EACH_INVALID` is owned by `for_each` OR `compose_sweep`, whose body raises `nested_in_sweep`); `FacetRequest.overlays` (+ `FacetResult.overlays`) → `capability:facet`; the `holdout` key on `RegressionSpec` (+ the `RegressionResult.holdout` result slot and the `RegressionHoldout` def) → `capability:regression_holdout` (a request-slot capability, hard edge any-of `REG_*`; a set one is refused at the regression by `nestedHoldoutRefusal` with `details.path`, after the `save` refusal; the MCP regressions schema adds the key only when enabled (`addRegressionHoldout`); it co-owns `PULSE_MODEL_SCORE_INVALID` (no_scorer) and `PULSE_FORMULA_COMPILE_ERROR`); `Request.weight` → `capability:weighting`; `Request.vectors` and `Request.matrices` (+ the `Response.matrices` result slot and `ResponseComponents.matrices`) → `capability:matrices` (a request-slot capability: it depends on any request-executing host; the `VectorSpec` / `VectorCoerce` / `MatrixSpec` / `MatrixResult` / `MatrixComponents` defs drop with the slots, the manifest drops its `matrix` block, and every `MAT_*` operator row hard-depends on it). **An overlay slot is visible iff one of its hosts is enabled AND lists an enabled kind** in `overlayHostKinds` — a host with no runnable kind leaves nothing to put in the slot. `descx.HiddenSlotKeys(sample, inst)` / `VisibleSlotKeys` expose the table to the self-description filters. Nil / unscoped instances hide nothing.

**Nested slots (`capability:weighting`).** `gatedSlots` also keys the nested slot objects that carry a per-slot `weight` (`types.Aggregation`, `Test`, `RegressionSpec`, `Attribute`, `OverlaySpec`, `Group`), so the payload schema (`structSchema` reads `HiddenSlotKeys` per struct) drops each nested `weight` property and with it the `SlotWeight` / `WeightSpec` defs. A typed Go caller never decodes JSON, so the refusal is runtime code too: `SlotRefusal` runs `nestedWeightRefusal` after a Request's own root slots — aggregations, crosstab cell, margin aggregations, tests, post-tests, regressions, attributes, overlays, groups, crosstab rows, crosstab columns (the resolver's slot order) — and over a `FacetRequest`'s overlays; Compose requests and chain stages run it per request (root then nested, then the next request). A set `weight` — `null` included, any non-zero `SlotWeight` — is `PULSE_REQUEST_UNKNOWN_FIELD` with `details.path` locating the key (`aggregations[0].weight`, `crosstab.cell.weight` — the object path plus the first offending key since U44), `valid_keys` / `suggestions` over THAT object's visible keys and the message "unrecognized key(s) in <path>" (`unknownFieldErrorAt`; the root shape is byte-identical to `UnknownFieldError`). MCP refuses it at its recursive strict decode, in the same shape; the bound tool schemas drop every nested `weight` property (`internal/mcp/bind.go` `dropHiddenWeights`). Templates withhold the root `weight` like any hidden root slot; a nested one renders and is refused at execution. `Options.DefaultWeight` under a profile without the capability fails `pulse.New` as `PULSE_FEATURE_PROFILE_DEPENDENCY`, its `unmet` entry `{option: "Options.DefaultWeight", requires_any_of: ["capability:weighting"]}` plus `options` (`validateOptionsAgainstFeatureProfile`, after the three validation classes). `AGG_WEIGHTED_MEAN.params.weight_field` is the operator's own parameter and stays ungated. Pinned by `TestSlotRefusal_WeightAtEveryNestingLevel` / `TestPayloadSchema_WeightingHidden` (`internal/descriptor`), `TestHiddenWeighting_*` (root), `TestBindForInstance_WeightingHidden` / `TestTools_InvokeRefusesHiddenNestedWeight` (`internal/mcp`). Contract: `.claude/reference/weighting.md` (Feature profile).

**Nested slots (`capability:multiplicity`).** `gatedSlots` keys `multiplicity` on `types.Request`, `ComposedRequest` (root slots) and on `Test`, `OverlaySpec`, `MatrixSpec`, `ComposeOverlaySpec` (nested) plus the `MatrixResult` echo, so the payload schema drops every `multiplicity` property and the `Multiplicity` / `MultiplicityMethod` / `MultiplicityFamily` defs (the two enums are closed vocabularies, never instance-filtered — `enumValues`). `SlotRefusal` runs `nestedMultiplicityRefusal` after `nestedWeightRefusal` (tests, post-tests, overlays, matrices), `overlayMultiplicityRefusal` over a FacetRequest's overlays, and `composeOverlayMultiplicityRefusal` over a ComposedRequest's overlays BEFORE its slot requests; same `unknownFieldErrorAt` shape. `Options.DefaultMultiplicity` under a profile without the capability is `PULSE_FEATURE_PROFILE_DEPENDENCY` (`validateOptionsAgainstFeatureProfile` checks both options; each unmet one adds an `unmet` entry, `options` in check order Weight → Multiplicity). The MCP bound tool schemas (`internal/mcp/bind.go`, hand-built) advertise each `multiplicity` block with the surface's own family enum (a test's block carries no `alpha`) and drop every one through `dropHiddenMultiplicity` when the capability is hidden — reaching the compose / chain / predict bodies that embed them; pinned by `TestBindForInstance_MultiplicityAdvertised` / `_MultiplicitySurfaceFamilies` / `_MultiplicityHidden` / `_MatrixMultiplicity` (`internal/mcp`). Pinned by `TestSlotRefusal_MultiplicityAtEveryNestingLevel` / `TestPayloadSchema_MultiplicityHidden` (`internal/descriptor`) and `TestHiddenMultiplicity_RefusedAsUnknownField` (root). Resolver contract: `.claude/reference/update-demand/weighting-and-multiplicity.md` (Multiplicity row).

**Order: first, at the decode point.** Root slots before nested ones; a nested refusal is located with `details.request` (Compose) / `details.stage` (ProcessChain) via `RefusalAt` — the service's located-refusal keys, which MCP's strict decode (`internal/mcp/strict.go`) uses too for an unknown key inside a compose request or chain stage, so an MCP client and a library caller see the same details. Sites: `Service.Process` (after the cohort-required check, BEFORE `JoinCountRefusal` and the crosstab / joins dispatch — covers ProcessStream, Watch-driven runs and chain stage 0), `Compose` / `ComposeParallel` (before label defaults / the worker pool), `ProcessChain` (before the cohort opens, every stage), `FacetSchema` (after its structural checks, before the cohort opens), `descx.Predict` (FIRST, before the header is read — so `Predict` / `PredictBytes` report only this error, as the runtime never gets further) and the compose / chain / facet validators. Pinned by `TestHiddenRequestSlot_*` / `TestHiddenRootSlot_*` (root) and `TestHiddenSlotKeys_Rules` / `TestSlotRefusal_*` (`internal/descriptor`). **Templates refuse a hidden slot as an unknown key, at decode.** `Pulse.RenderTemplate` (and so `RenderTemplateRequest`) on a scoped instance calls `template.RenderWith` with `RenderOptions.WithheldSlots` = `descx.HiddenSlotKeys(root, inst)`; the template package (import ceiling unchanged) renames each set withheld key at a gated position (the target root, `requests[i]`, `stages[i].request`; case-insensitive, as `encoding/json` matches) with a `\x00` suffix before the strict decode and maps the decoder's unknown-field fault back to the original spelling. The result is `PULSE_TEMPLATE_RENDER_INVALID` `{template, target, field}` byte-identical to a never-existing key — message, details, cause and document-order position (a typo earlier in the body still wins); an empty value (`"joins": []`) is refused too, since a set KEY is what strict decode refuses. `Rendered.JSON` stays the unmodified body. Hidden operator NAMES render (not a slot) and fail at execution like never-registered ones. Pinned by `TestRenderTemplate_HiddenSlot*` / `TestRenderTemplate_HiddenOperatorRendersLikeNeverRegistered` (root) and `TestRenderWith_*` (`internal/template`).

**Parity harness.** `runHiddenParity` (root `feature_parity_harness_test.go`, run by `TestHiddenOperatorParity`) drives fixture × category × entry point — Process, ProcessStream, Compose, ComposeParallel, ProcessChain stage 0 and stage 1, FacetSchema (plain and `additive_fields`), FilterToFile, plus the slots a composed / chain request carries itself (`Compose/overlays`, `ComposeParallel/overlays`, `ProcessChain/overlays`; `feature_parity_overlay_test.go` adds the REG and per-host OVERLAY categories); Facet and Watch carry no operator name; `Predict` / `PredictBytes` (`feature_parity_predict_test.go`) report on the envelope, never as an error, so they set `neverOK`, and the crosstab axis / cell cells are vacuous by design there. Predict rules the probes do not reach are pinned in `internal/descriptor` (`TestPredict_Hidden*`, `TestScopedFieldRefRefusals_HiddenIsNeverRegistered`, `TestValidate*_Hidden*`), and the runtime half of the shared rules by `TestHiddenOperatorSharedRuleParity`. A category whose never-registered name succeeds (the Compose stub, the SERIES fold on an ungrouped host) says why in `neverOK`; its outcome is still byte-compared. Each cell byte-compares a hidden built-in with a never-registered name on the profiled instance after substitution, and requires the hidden name to behave DIFFERENTLY on an unprofiled control (else the cell is vacuous; `vacuousOK` records the by-design ones, e.g. slots the chain gate refuses for every name). Extend it with a `parityCategory` (an applier per payload) or a `parityEntryPoint`. **MCP entry points** (`feature_parity_mcp_test.go`, `TestProfileInvisibilityParity`): the same harness driven through an in-memory go-sdk client (`pulse_process`, `pulse_predict`, `pulse_compose` slot + overlays, `pulse_process_chain` stage 0 / 1 / overlays, `pulse_facet_schema`; a tool the instance does not mount skips the cell) over every published example profile, the private fixtures and an inline `mcp-hosts` profile that mounts every request host; plus a surface sweep (also over a prompt-only `mcp-prompts` profile and the `mcp-intent-prompts` profile) — `tools/list` before and after the bind-on-inspect rebind, `prompts/list` + `prompts/get`, resources and templates, `pulse://schema`, the cohort resource, every `pulse-skill://` read, the skills / examples / manifest / errors tools — that names no hidden operator, tool or prompt, with each hidden tool, prompt, skill and example reading byte-identically (after substitution) to a never-registered one. Every skill body is swept, topical included — there is no exemption. The go-sdk side lives in `feature_parity_mcp_bridge_test.go` (the root external test package, since `mcp/gosdk` imports the root); extend the sweep there, not with a parallel harness. **Malformed-request cells** (`feature_parity_malformed_test.go`, `TestHiddenOperatorMalformedParity`) drive the requests a rule refuses BEFORE the name is looked up, through every entry point including Predict / PredictBytes, via `runHiddenParityWith` (a `parityHostConfig` sets `Strict`, or swaps the cohort — a hand-written decimal128 cohort): `tz` on a zone-capable grouper / filterer over a non-temporal field and an unloadable zone, field-reference parameter keys naming missing fields or carrying the wrong JSON type (aggregator, feature, post-test), a filterer with no `Field`, the strict numeric-on-categorical rule (Request and crosstab cell), a decimal128 aggregation (Request and crosstab cell), a `FacetSchema` `additive_fields` scope over an expression filter, and `ATTR_FORMULA` / `FILTER_EXPRESSION` on a crosstab (the fused gate's by-name bail). Two divergences it found are fixed: the buffered orchestrators' **decimal128 dispatch** ran a hidden built-in aggregator (`IsDecimalAggregationSupported` is name-keyed and ran before `LookupAggregator`) — now `ExtensionRegistry.decimalAggregationSupported` answers false for a hidden name, so it is refused "aggregation has no decimal128 implementation" exactly as a never-registered one (`processor.go`, `crosstab.go`); and the `FacetSchema` additive-field rule refused a hidden `FILTER_EXPRESSION` with its own message — `validateFacetSchemaRequest` now takes the instance and skips a hidden one, which then fails at the filter build. Predict reports no envelope errors through `Predict` (only `PredictBytes`) and judges no decimal crosstab cell by name, so those cells are vacuous by design there (`malformedVacuous`).

Fixture profiles for goldens live at `descriptor/testdata/profiles/{minimal,survey-crosstab,empty}.json` (a subdirectory, so `TestGoldensNotHandEdited` does not read them); `TestFeatureSet_FixturesLoad` keeps each one valid at `pulse.New`.
