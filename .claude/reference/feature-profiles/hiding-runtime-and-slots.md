# Feature profiles — Runtime hiding, Predict hiding, Request-slot gate

Per-topic slice of the feature-profiles reference. Index (rules + section map): `.claude/reference/feature-profiles.md` — load it first, then only the slice(s) your change touches.

## Runtime hiding (registry operators)

**Hide at the native lookup site, never with a pre-check.** `Service.SetExtensions` / `SetInstanceSnapshot` re-derive the runtime registry as `processing.ExtensionRegistry.WithHidden(snap.Hidden)` (no hidden names → the installed registry unchanged). Every `Lookup*` (AGG, ATTR, FILTER, GROUP, WIN, FEAT, row TEST, post TEST) answers a hidden name not-found, so each execution path reaches its OWN unknown-name error — same code, message, details and ordering against zone / field-ref / label / strict faults. Windows and features resolve through the registry's `LookupWindow` / `LookupFeature`, so they cannot bypass it. The route-choosing facts read the same predicate: streamability, mergeability, margin reducibility, the two-pass check and the merge-gate adapter give a hidden name the never-registered answer, so it cannot take a different stream / merge / fused route to its error. `internal/mergegate` consults the adapter's attribute answer BEFORE its built-in row-local list for the same reason. **Any name-keyed check that runs before the lookup must consult the hidden predicate too** — a decimal128 dispatch check that ran first once let a hidden built-in aggregator execute; `ExtensionRegistry.decimalAggregationSupported` now answers false for a hidden name.

**Other sites.** The `FacetSchema` `additive_fields` scope filters build against the instance registry, and the facet additive-field rule skips a hidden `FILTER_EXPRESSION` so it fails at the filter build like a never-registered one. `FilterToFileWithRequest`'s filterer→expression translator refuses a hidden type with its unsupported-type error. `descx.ResolveDefaults(req, schema, inst)` skips a hidden default target exactly like "no rule for this type" (no Type written, no `DefaultApplied` entry). Engine-internal uses that no request names stay unscoped: `FilterToFile`'s raw expression still compiles through `FILTER_EXPRESSION` (hence the `capability:filter_to_file` hard edge); synth fidelity runs `TEST_KS` / `TEST_CHISQ` on an unscoped processor.

**Regressions.** Regression build and fit take a `regression.Resolver`; the processor passes `ExtensionRegistry.LookupRegression`, which misses a hidden type, so both orchestrators raise predict's own `PULSE_REGRESSION_INVALID` refusal (`details` `{regression_index, type}`). A hidden type is non-streamable (a never-registered type's `Streamable()` is false), so a hidden `REG_OLS` routes buffered too.

**Overlay kinds — route, don't re-word.** The per-host handler tables are globals, so the hide is a ROUTE: `ExtensionRegistry.overlayRoute(kind)` returns the authored kind, or `""` (a kind nothing knows) when hidden. Every kind-keyed decision — on the MATRIX, SERIES, CHAIN, FACET and COMPOSE hosts, including the `OVERLAY_FORMULA` special cases, the Level/Within gates, the slab gates and streamability — keys on the route, while messages and details keep naming the authored kind. Find the sites with `grep -rn overlayRoute internal/`. A hidden kind is refused like a never-registered one: `PULSE_OVERLAY_KIND_UNKNOWN` on Compose (`overlayhost.ComposeKindUnknownRefusal`, before any other Compose rule), `overlayhost.KindUnknownRefusal` on the other hosts, identically in predict. A hidden EXTENSION kind is dropped at `pulse.New`. The parallel shard / decode reducers fold SERIES overlays in the shared grouped tail, which carries the registry. The request-time descriptor gates take `PredictOptions.Instance` and route the same way.

## Predict hiding

**Predict sees only the instance.** `Pulse.Predict`, `PredictBytes` and the non-Request roots `PredictCompose` / `PredictFacet` / `PredictChain` set `PredictOptions.Instance` to the service's `InstanceSnapshot`. Predict cannot import the registry, so the hide is a ROUTE, the no-execute twin of the runtime's: `opRoute(inst, t)` returns `t`, or `""` when the instance hides it, and every type-keyed predict decision keys on the route while messages and details keep naming the authored type. Routed decisions include the known-type checks, streamability, the per-slot `ComponentSchema` lookups, the decimal and numeric-on-categorical rules, the crosstab cell rules, the attribute default label, the overlay host-type rules and descriptors, the chain validator's merge facts, and the suggestions (no proposal names a hidden operator). Find them with `grep -rn opRoute internal/descriptor/`. A new type-keyed predict decision must go through `opRoute`. `ResolveDefaults` gets the instance at every predict / validator / chain site, so `DefaultsApplied` never names a hidden target. Without `capability:weighting`, `ResolveWeights` still runs (its refusals stay) but `PredictResult.Weights` is not reported, and neither inspect nor predict reports the SPSS `suggested_weight` — `predict-inspect.md` (Suggested weight).

**The shared predict ↔ runtime rules take the instance on BOTH sides**, so the runtime refuses a hidden name at the shared rule exactly where it refuses a never-registered one: `ResolveZones` / `ResolveFacetZones` (a hidden zone-capable operator is not zone-capable), the field-reference walk (`ScopedFieldRefRefusal` / `ScopedFacetFieldRefRefusals` at runtime, `fieldRefRefusals` in predict) and `CategoricalAggregationIssues`. Refusal prose may name a built-in as literal text only when it is a hard-dependency target the refusing operator cannot be enabled without; every other fixed list or remedy is instance-dependent (`feature-profiles/hiding-surfaces.md` (Instance-dependent wording)).

## Request-slot gate

**A set slot the instance hides is an unknown field.** `descx.SlotRefusal(v, inst)` (`internal/descriptor/request_slots.go`) takes a `*types.Request` / `ComposedRequest` / `ChainRequest` / `FacetRequest` and returns `PULSE_REQUEST_UNKNOWN_FIELD` in the strict-decode shape: `unknown_keys`, `valid_keys` (that root's VISIBLE keys) and `suggestions` (nearest visible key). The shape is built once, by `strictjson.UnknownFieldError`, which the shared strict request decoder raises too — so an unknown key and a hidden slot cannot drift. Every JSON request root (CLI request files, MCP tool arguments, sweep bodies, `for_each` items) decodes through `strictjson.DecodeInto` RECURSIVELY with `descx.StrictOptions(inst)`, so a hidden slot at ANY depth is refused at decode as an unknown key, `valid_keys` / `suggestions` never name one, and a root's own keys are judged before anything nested — byte-identical to `SlotRefusal`. MCP's decoders take the calling instance; the CLI instance is unprofiled. A present key is refused even with an empty value, as strict decode refuses any set key.

**Slot → owning feature** is the `gatedSlots` table in `internal/descriptor/request_slots.go` — read it for the current mapping; do not copy it here. Each gated slot (a request key, plus the result slots it produces) belongs to one capability. Gating a new slot means, in one change:

- a `gatedSlots` entry (and `setSlots` listing the key when set; a slot nested in a sub-object gets a `nested*Refusal` that locates it with `details.path`);
- the payload schema drops the key and any def reachable only through it;
- the MCP bound tool schemas drop it (`internal/mcp/bind.go`);
- the manifest drops any block or flag that describes it;
- `errors.Code` owners in `internal/descriptor/error_owners.go` give the slot's own refusal codes to the capability;
- a `slotTokens` entry (`feature-profiles/hiding-surfaces.md` (Slot tokens)), possibly empty.

A capability whose slot rides only inside another slot gets a hard edge on that slot's capability (for example `capability:crosstab_cells` → `capability:crosstab`). A slot-specific refusal that fires only when the slot is visible (such as `PULSE_MATERIALIZE_OUTPUT_ONLY`) runs AFTER the hidden-slot refusal, so a hiding instance answers unknown field everywhere. **An overlay slot is visible iff one of its hosts is enabled AND lists an enabled kind** in `overlayHostKinds` — a host with no runnable kind leaves nothing to put in the slot. `descx.HiddenSlotKeys(sample, inst)` / `VisibleSlotKeys` expose the table to the self-description filters. Nil / unscoped instances hide nothing.

**Nested slots (`capability:weighting`).** `gatedSlots` also keys the nested slot objects that carry a per-slot `weight` (`types.Aggregation`, `Test`, `RegressionSpec`, `Attribute`, `OverlaySpec`, `Group`), so the payload schema drops each nested `weight` property and the `SlotWeight` / `WeightSpec` defs. A typed Go caller never decodes JSON, so the refusal is runtime code too: `SlotRefusal` runs `nestedWeightRefusal` after a Request's own root slots, in the weight resolver's slot order, and per request on Compose / chain. A set `weight` — `null` included — is `PULSE_REQUEST_UNKNOWN_FIELD` with `details.path` locating the key (`aggregations[0].weight`), `valid_keys` / `suggestions` over THAT object's visible keys and the message "unrecognized key(s) in <path>". Templates withhold the root `weight` like any hidden root slot; a nested one renders and is refused at execution. `Options.DefaultWeight` under a profile without the capability fails `pulse.New` as `PULSE_FEATURE_PROFILE_DEPENDENCY`, its `unmet` entry `{option: "Options.DefaultWeight", requires_any_of: ["capability:weighting"]}` plus `options`. `AGG_WEIGHTED_MEAN.params.weight_field` is the operator's own parameter and stays ungated. Pinned by `TestSlotRefusal_WeightAtEveryNestingLevel`, `TestPayloadSchema_WeightingHidden`, `TestHiddenWeighting_*`, `TestBindForInstance_WeightingHidden`. Contract: `.claude/reference/weighting.md` (Feature profile).

**Nested slots (`capability:multiplicity`).** `gatedSlots` keys `multiplicity` on the `Request` and `ComposedRequest` roots and on `Test`, `OverlaySpec`, `MatrixSpec`, `ComposeOverlaySpec` plus the `MatrixResult` echo, so the payload schema drops every `multiplicity` property and the `Multiplicity*` defs (the method and family enums are closed vocabularies, never instance-filtered). `SlotRefusal` runs the multiplicity refusals after the weight ones (a Compose request's overlays BEFORE its slot requests), in the same located shape. `Options.DefaultMultiplicity` under a profile without the capability is `PULSE_FEATURE_PROFILE_DEPENDENCY` (both options are checked; `options` lists them in order Weight → Multiplicity). The MCP bound schemas advertise each block with its surface's own family enum and drop every one when the capability is hidden. Pinned by `TestSlotRefusal_MultiplicityAtEveryNestingLevel`, `TestPayloadSchema_MultiplicityHidden`, `TestHiddenMultiplicity_RefusedAsUnknownField`, `TestBindForInstance_Multiplicity*`. Resolver contract: `.claude/reference/update-demand/weighting-and-multiplicity.md` (Multiplicity row).

**Order: first, at the decode point.** Root slots before nested ones; a nested refusal is located with `details.request` (Compose) / `details.stage` (ProcessChain) — the same keys MCP's strict decode uses for an unknown key inside a compose request or chain stage, so an MCP client and a library caller see the same details. The gate runs before any other dispatch at every entry point: `Service.Process` (after the cohort-required check, before the joins / crosstab dispatch — this covers ProcessStream, Watch-driven runs and chain stage 0), `Compose` / `ComposeParallel`, `ProcessChain` (before the cohort opens, every stage), `FacetSchema` (after its structural checks), `Service.sampleWithRequest` / `lookupRecords`, and `descx.Predict` (FIRST, before the header is read) plus the compose / chain / facet validators. Pinned by `TestHiddenRequestSlot_*`, `TestHiddenRootSlot_*`, `TestHiddenSlotKeys_Rules`, `TestSlotRefusal_*`.

**Templates refuse a hidden slot as an unknown key, at decode.** `Pulse.RenderTemplate` (and `RenderTemplateRequest`) on a scoped instance calls `template.RenderWith` with `RenderOptions.WithheldSlots` = `descx.HiddenSlotKeys(root, inst)`. The template package renames each set withheld key at a gated position (the target root, `requests[i]`, `stages[i].request`; case-insensitive) with a `\x00` suffix before the strict decode and maps the decoder's fault back to the original spelling. The result is `PULSE_TEMPLATE_RENDER_INVALID` `{template, target, field}` byte-identical to a never-existing key — message, details, cause and document-order position; an empty value is refused too. `Rendered.JSON` stays the unmodified body. Hidden operator NAMES render (not a slot) and fail at execution like never-registered ones. Pinned by `TestRenderTemplate_Hidden*`, `TestRenderWith_*`.

**Parity harness.** `runHiddenParity` (root `feature_parity_harness_test.go`, run by `TestHiddenOperatorParity`) drives fixture × category × entry point and byte-compares a hidden built-in with a never-registered name on the profiled instance (after name substitution), and requires the hidden name to behave DIFFERENTLY on an unprofiled control — else the cell is vacuous (`vacuousOK` records the by-design ones). A category whose never-registered name succeeds says why in `neverOK`; its outcome is still byte-compared. Predict reports on the envelope, never as an error, so its cells set `neverOK`. Extend it with a `parityCategory` or a `parityEntryPoint`, never a parallel harness. Its arms:

- **MCP** (`feature_parity_mcp_test.go`, `TestProfileInvisibilityParity`): the same harness through an in-memory go-sdk client over every published example profile, the private fixtures and inline profiles, plus a surface sweep (tools, prompts, resources, `pulse://schema`, skill reads, the skills / examples / manifest / errors tools) that names no hidden operator, tool or prompt. Every served skill body is swept, topical included — there is no exemption. The go-sdk side lives in `feature_parity_mcp_bridge_test.go` (external test package, since `mcp/gosdk` imports the root).
- **Malformed requests** (`feature_parity_malformed_test.go`, `TestHiddenOperatorMalformedParity`): the requests a rule refuses BEFORE the name is looked up (zone, field-reference, missing `Field`, strict numeric-on-categorical, decimal128, facet additive-field, expression operators on a crosstab), through every entry point including Predict. This arm exists because pre-lookup rules are where hidden names leaked.
- Predict rules the probes do not reach are pinned in `internal/descriptor` (`TestPredict_Hidden*`, `TestScopedFieldRefRefusals_HiddenIsNeverRegistered`, `TestValidate*_Hidden*`), and the runtime half of the shared rules by `TestHiddenOperatorSharedRuleParity`.

Fixture profiles for goldens live at `descriptor/testdata/profiles/*.json` (a subdirectory, so `TestGoldensNotHandEdited` does not read them); `TestFeatureSet_FixturesLoad` keeps each one valid at `pulse.New`.
