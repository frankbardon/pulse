## Surface

| Slot | Shape | Notes |
|---|---|---|
| `types.Request.Weight` (`weight`) | `{field, kind}` (`types.WeightSpec`) | `omitempty`. `kind` ∈ `probability` (default) \| `frequency`. |
| Per-slot `weight` (`types.SlotWeight`, `omitzero`) | a field-name string, a `{field, kind}` object, or `null` | On `Aggregation` (so also the crosstab cell and `crosstab.margin_aggregations[i]`), `Test` (`tests` and `post_tests`), `RegressionSpec`, `Attribute`, `OverlaySpec` and `Group` (`groups[i]`, `crosstab.rows[i]`, `crosstab.columns[i]`; E2-S3) — tests, regressions, overlays, attributes and groupers mainly to opt OUT. `Window` and `ComposeOverlaySpec` carry none. Go spellings: `SlotWeightField(f)`, `SlotWeightOf(spec)`, `NullSlotWeight()`; zero value = absent. |
| `pulse.Options.DefaultWeight` | `*WeightSpec` | Validated at `pulse.New`; applies to Process / Compose / ProcessChain inner requests, never to `Facet` / `FacetSchema`. |

**Null ≠ absent.** An ABSENT per-slot `weight` inherits; an explicit `null` opts that slot out. The per-slot type is new to `types/` (no precedent): it carries its own `UnmarshalJSON` / `MarshalJSON` / `IsZero` and rides `omitzero`, and the distinction must survive every hop — `types.CanonicalHash`, the MCP strict decode and binder, and the payload JSON Schema (`internal/descriptor` `BuildPayloadSchema` special-cases it as `#/$defs/SlotWeight` = `oneOf [string, WeightSpec, null]`). A set weight with no `kind` marshals as the bare string (the object form without `kind` re-marshals as the string — same meaning); decoding refuses any other JSON shape and any object key but `field` / `kind`. The fields are unexported on purpose: the three states are reachable only through the constructors, so "null with a field" cannot be built. The MCP binder (`internal/mcp/bind.go`) declares the same union, its field enum drawn from the cohort's weight-capable columns (`descx.IsWeightFieldType`).

No new top-level slot on `ComposedRequest` or `ChainRequest`: each inner `Request` carries its own `weight`. `AGG_WEIGHTED_MEAN.params.weight_field` is slot-weight sugar (see "Aggregator classification").

**Weight field type.** Unsigned integers (`u4`, `u8` … `u64`) and floats (`f32`, `f64`) only. `decimal128`, `categorical_*`, `date`, `datetime`, `packed_bool` and `set_*` are `PROCESSING_CONFIG` with details `{slot, field, type}` (`slot` is `weight`, `<slot>.weight`, or the slot path for an applied default). An empty `field` or a `kind` other than `probability` / `frequency` is `PROCESSING_CONFIG` too (`{slot, field, kind}`), for `Options.DefaultWeight` already at `pulse.New` (`slot: "Options.DefaultWeight"`).

**Weight field existence.** An explicitly named weight (request or slot) is judged by the field-reference rule (`fieldRefWalk.checkWeights` in `internal/descriptor/field_refs.go`) against the SCHEMA, not the derived column set — an attribute label or feature output is no weight — and refused `SERVICE_VALIDATION` `{field, slot}` like any unknown name. A joined (prefixed) name resolves against the joined schema; a chain stage ≥ 1 against its synthesised input schema. The inherited `Options.DefaultWeight` is NOT a request reference: `ResolveWeights` judges its existence and type only on a slot where it is APPLIED, so an instance default never breaks a cohort lacking the column for a request that would not use it. Projection: `processing.NeededFields` adds the request and slot weight fields; the service's `neededFields` adds the instance default (which `NeededFields` cannot see), so projection never decodes a weight as null (`TestProjection_WeightColumnDecodes`).

## Resolution order

One shared resolver, `ResolveWeights(req, schema, defaultWeight, inst)` in `internal/descriptor/weight_resolve.go`, modelled on the time-zone resolver (`internal/descriptor/zone_resolve.go`), called by BOTH runtime and predict so they cannot disagree. The runtime runs it inside `Service.checkFieldRefs`, i.e. right after the field-reference rule passes, in every execution mode (Compose slots and chain stages each resolve their own Request, located by `details.request` / `details.stage`); predict and the Compose / chain validators run it at the same point:

1. the slot's own `weight` (`null` ⇒ opted out, stop);
2. the request's `weight`;
3. `Options.DefaultWeight`;
4. none.

Slot order (and `slot` spelling): `aggregations[i]`, `crosstab.cell`, `crosstab.margin_aggregations[i]`, `tests[i]`, `post_tests[i]`, `regressions[i]`, `attributes[i]`, `overlays[i]` (`operator` = the overlay kind), then (E2-S3, appended so earlier reports keep their order) `groups[i]`, `crosstab.rows[i]`, `crosstab.columns[i]`, `windows[i]`. A slot with an empty `Type` is skipped. Predict reports the outcome per slot as `PredictResult.Weights` (`descriptor.ResolvedWeight`, `weights`, `omitempty`) — `{slot, operator, field, kind, status, source}`: `field` / `kind` are omitted on `opted_out` / `none` and `kind` is spelled out (`probability` when the spec left it empty); `status` ∈ `applied` | `skipped_not_weight_aware` | `opted_out` | `none` (`descriptor.WeightStatus*`); `source` ∈ `slot` | `request` | `options` | `none` (`descriptor.WeightSource*`; an opted-out slot's source is `slot`). The whole list is nil — the key absent — when neither the request, a slot (a `null` included) nor the instance names a weight, so an unweighted predict payload is unchanged. `applied` vs `skipped_not_weight_aware` reads `IsWeightAware(op)`; a hidden operator is never-registered, hence not aware. Refusals surface as predict errors, identical to runtime (`TestWeight_PredictMatchesRuntime`, `TestWeight_ValidatorsMatchRuntime`).

## Threading

**Design (E1-S3): the resolved weight rides the aggregator's SPEC.** `processing.StampWeights(req, Options.DefaultWeight)` returns a copy of the request whose every aggregation slot — `aggregations[i]`, `crosstab.cell`, `crosstab.margin_aggregations[i]` — carries its RESOLVED weight in its own `weight`: set (field + spelled-out kind) when a weight applies to a weight-aware operator, `null` otherwise. It folds the same precedence as `ResolveWeights` (slot → `AGG_WEIGHTED_MEAN` `params.weight_field` → request → `Options.DefaultWeight`) and reads the same class table (`internal/weighting`), so it never refuses — the resolver already did. A request naming no weight anywhere is returned AS-IS (same pointer), so the unweighted path executes the unchanged object; the caller's request is never mutated (the echo and `CanonicalHash` see what the caller sent). Every engine entry stamps: `Processor.Process` / `RunCrosstab` / `RunCrosstabFused` (the processor carries the default through `SetWeighting`, set by `Service.newProcessor`) and both parallel reducers (`processShardArchiveParallel`, `reduceParallelBuffered`), so every mode builds its aggregators off one spec. A factory reads `slotWeight(agg)` and returns the weighted form (`weightedAggregator`, `internal/processing/aggregator_weighted.go`) or, with no weight, the unchanged unweighted type; the per-row weight is read off the record inside the aggregator. Why not the record: per-slot weights differ within one request.

`internal/weighting` is the leaf both halves read: `ClassOf` / `IsAware` (the class table) and `Classify` (the per-row validity rule). `internal/descriptor.IsWeightAware` forwards to it.

## Validation

| Weight value | Treatment |
|---|---|
| positive, finite | used |
| zero | valid; contributes nothing |
| null | excluded, counted (`null`) |
| negative | excluded, counted (`negative`) |
| NaN / ±Inf | excluded, counted (`nan_inf`) |
| non-integer under `kind: frequency` | excluded, counted (`non_integer_frequency`) |

Invalid weights are **never coerced** (`weighting.Classify`; a zero weight is skipped too, so it adds nothing and a leading zero cannot divide by a zero Σw). Each weighted aggregator slot reports `n_weight_invalid` = its VALUE-PRESENT rows excluded for an invalid weight (a null-value row is `n_null` and its weight is not judged). Each Response carries ONE `PULSE_WEIGHT_INVALID_ROWS` warning PER WEIGHT FIELD that excluded rows (in practice one: a request rarely names two weight columns) — `details{field, count, by_reason{null, negative, nan_inf, non_integer_frequency}}`, all four reasons always present — counting the FILTER-PASSING rows (after row-local attributes) whose weight is invalid, whether or not that row's value is present; a fractional weight counts as `non_integer_frequency` when any slot reads that field as `frequency`. It is tallied by `processing.WeightRowTally` from the stamped aggregation slots and merged across buffered, streaming, grouped streaming, two-pass, shard-parallel and parallel-decode execution, and tallied by both crosstab arms (E3-S1) over the slots `NewWeightRowTally` reads — the top-level aggregations, the crosstab cell and every `margin_aggregations` slot, so an auxiliary-only weight warns too; `pulse.Options.Strict` (`--strict`) turns it into an error carrying the same code and details.

## Aggregator classification

| Class | Operators | Weighted meaning |
|---|---|---|
| weight-aware | `AGG_COUNT` | Σw over value-present rows |
| | `AGG_SUM`, `AGG_AVERAGE`, `AGG_WEIGHTED_MEAN` (alias of weighted `AGG_AVERAGE`) | Σwx; Σwx/Σw |
| | `AGG_VARIANCE` / `AGG_STDDEV` | population m2_w/Σw |
| | `AGG_WELFORD` | sample m2_w/(Σw−1) |
| | `AGG_SKEWNESS` / `AGG_KURTOSIS` | weighted population moments |
| | `AGG_MEDIAN` / `AGG_PERCENTILE` | Hmisc `wtd.quantile` (type 7 on the expansion for integer cumulative weights); `probability` weights rescaled to Σw = n (below) |
| | `AGG_MODE` / `AGG_MODE_COUNT` | the max-Σw value / its Σw |
| | `AGG_FREQUENCY` | Σw of matches; share Σw_match/Σw |
| | `AGG_RATIO` | Σw·num / Σw·den |
| | `AGG_SET_FREQUENCY`, `AGG_SET_CARDINALITY_SUM`, `AGG_SET_CARDINALITY_AVG` | Σw per member; Σw·card; Σw·card/Σw |
| not weightable | `AGG_MIN`, `AGG_MAX`, `AGG_RANGE`, `AGG_DISTINCT_COUNT`, `AGG_DISTINCT_SUM`, `AGG_NULL_COUNT`, `AGG_SET_UNION`, `AGG_SET_INTERSECTION`, `AGG_SET_DISTINCT_VALUES`, `AGG_ZSCORE` | skipped under a default weight; an explicit weight is `PROCESSING_CONFIG` |
| refuse (pending) | `AGG_CI_LOWER`, `AGG_CI_UPPER` | any weight in force ⇒ `PULSE_WEIGHT_UNSUPPORTED` |

**The table is `internal/weighting.aggregatorClasses`** (`TestClassify_Complete` holds it total over `types.AllAggregationTypes()`). Three classes: `ClassAware`, `ClassNotWeightable` and `ClassRefuse` (a fourth, `ClassPending` — weight-aware in meaning but treated as not weightable until its computation landed — was emptied by E2-S2 and removed). Manifest `weight_aware` is set only on `ClassAware` (stamped by `withWeightAware`, `internal/descriptor/capabilities_weight.go`). **Explicit** means a slot weight (or `weight_field`) or the REQUEST weight; only `Options.DefaultWeight` is a default — windows, which have no slot weight, can only be explicit through the request. Refusal details: `{slot, operator, field}`. Since E2-S3 the same table (`operatorClasses`) also classes the non-aggregator families — every built-in `TEST_*` / `REG_*`, the four reference-distribution attributes and `GROUP_QUANTILE` are `ClassRefuse`, every `WIN_*` is `ClassNotWeightable` (`TestClassify_NonAggregatorFamilies`); overlays are classed in `internal/descriptor` off their Inferential flag (see "Refusal rules"). Every other operator — row-local attributes, the other groupers, filterers, features, descriptive overlays — and every extension filterer, grouper, window and feature reports `skipped_not_weight_aware`; extension aggregators, attributes and tests are classed by their `WeightAware` declaration ("Extension contract").

**Weight kinds (U12 E1-S1).** A fourth class, `ClassFrequencyOnly`, computes a weighted figure under `kind: frequency` only (exact on the expanded rows) and has no standard probability-weighted form: a frequency weight is applied; a probability weight in force on its slot — slot, request or `Options.DefaultWeight` — is `PULSE_WEIGHT_UNSUPPORTED` naming the kind, details `{slot, operator, field, kind, supported_kinds: ["frequency"]}` (`weightKindUnsupported`); `weight: null` opts out. `weighting.KindsOf(op)` is the table-driven kinds accessor (`ClassAware` ⇒ `["frequency","probability"]`, `ClassFrequencyOnly` ⇒ `["frequency"]`, else none) and `IsAware` is "has a kind", so the engine stamps a frequency-only slot exactly like an aware one (the resolver has already refused the probability case). **A class flips to aware / frequency-only only in the change that lands its weighted computation** — earlier, it would run unweighted silently. `ATTR_NORMALIZED` is `ClassNotWeightable` (a min-max rescale has no weighted meaning: default skipped, explicit `PROCESSING_CONFIG`). **Permanent refusals** carry `details.reason` and state it in the message (`<slot>: <op> cannot be weighted: <reason>`); a pending `ClassRefuse` (weighted form not landed yet) says `has no weighted form yet`. Reasons: `weighting.RefusalReason` (`TEST_SHAPIRO_WILK`, `TEST_TUKEY_HSD`, `TEST_ANOVA_RM`, `TEST_TREND`, `ATTR_PERCENTILE`); slot-level in the resolver (`weightSlot.reason`) — every built-in post-test (it reads aggregated rows) and a regression carrying `resample` or `selection`, refused whatever the regression's own class; the overlay class table (below). Gates: `TestKindsOf`, `TestRefusalReasons_AreRefused`, `TestResolveWeights_FrequencyOnly`, `TestResolveWeights_RegressionModifiersRefused`, `TestResolveWeights_NormalizedNotWeightable`, root `TestWeight_FrequencyOnlyMatchesPredict`, `TestWeight_NormalizedNotWeightableMatchesPredict` (a frequency-only stub via the test seam `weighting.OverrideClassForTest` until a real operator flips).

**Manifest `weight_kinds` (U12 E1-S1).** `["frequency"]` / `["frequency","probability"]`, `omitempty`, on `descriptor.Operator` (aggregators via `withWeightAware`; attributes and groupers via `withWeightKinds`), `TestMeta` (tier 1 only — a post-test never), `RegressionMeta` and `OverlayCapability` (`stampWeightKinds`, off `OverlayWeightKinds`). `weight_aware` is kept and set exactly where `weight_kinds` is non-empty. Both are absent when `capability:weighting` is hidden (`assembleManifest`). `TestManifest_WeightAware`, `TestManifest_WeightKindsFollowClassFlip`, `TestManifest_WeightingHidden`.

**Core formulas (E1-S3).** `AGG_COUNT` = Σw over value-present rows (presence via `FieldPresent`, set columns included; a float). `AGG_SUM` = Σw·x. `AGG_AVERAGE` / `AGG_WEIGHTED_MEAN` = Σw·x / Σw (0 when Σw = 0). `AGG_VARIANCE` / `AGG_STDDEV` = population m2_w / Σw: streaming / merge by the weighted Welford-West recurrence, buffered by the two-pass form the unweighted twin uses (mean = Σwx/Σw, then Σ w·d·d). `AGG_WELFORD` = the running weighted mean; its triple's variance is the sample m2_w / (Σw − 1) (0 when Σw ≤ 1) and `N` stays the CONTRIBUTING ROW count (Σw rides the floor's `sum_weights`). Weighted `mergeWelford` is `mergeWelfordWeighted` (Chan over weight totals). Weighted `AGG_AVERAGE` components = its `sum` (now Σw·x) plus `sum_weighted`, `weighted_mean`, `m2_weighted`, `sum_weights_sq`, `weighted_variance` — declared `optional: true` in its ComponentSchema; `AGG_WEIGHTED_MEAN` keeps its own seven-key map unchanged.

**Weighted percentile / median (Hmisc `wtd.quantile`, E2-S1; `weightedQuantileAggregator`, `internal/processing/aggregator_weighted_shape.go`).** A paired (value, weight) collector (`collectWeightedPairs`: value present, weight valid and > 0) feeds a sort by value (`sort.Float64s` order); W = Σw; h = p·(W−1) (median: 0.5·(W−1)); the 0-based order statistic x₍ₖ₎ is the smallest xᵢ whose cumulative weight is ≥ the 1-based rank k + 1 (`quantileOrderIndex` — Hmisc's `approx(cumsum(w), x, xout = rank, method = "constant", f = 1, rule = 2)`; past the last cumulative weight, the largest value); interpolate linearly between x₍⌊h⌋₎ and x₍⌈h⌉₎. This is exactly Hmisc 5.3.0 `wtd.quantile(x, w, probs, type = "quantile", normwt = TRUE)` for `probability` weights and `normwt = FALSE` for `frequency` weights (user decision, replacing E2-S1's "exceeds the 0-based rank k", which differed from Hmisc wherever cumulative weights are fractional). With integer cumulative weights "≥ k + 1" and "> k" coincide, so frequency weights and w ≡ 1 are still type 7 on the expansion. The interpolation keeps the unweighted twin's `lo + f·(hi − lo)` form rather than Hmisc's `(1 − f)·lo + f·hi` (unity bit-parity, below), so the figure matches Hmisc to the last few ulps, not bit for bit. **Integer snap:** before any comparison every cumulative weight within 1e-9·max(1, |c|) of an integer is snapped to that integer (`snapCumWeights`, `cumWeightSnapTol`), for both kinds. "≥ the rank" is a knife edge exactly on an integer: a cumulative weight that is mathematically the rank but lands one ulp below it — float summation order, the probability rescale, an FMA contraction on one architecture and not another — would pick the next order statistic. Snapped, the answer is the exact-arithmetic one on every platform; integer cumulative weights are fixed points, so frequency and unity results never move. On such a knife edge Pulse can therefore differ from Hmisc's own float output (weights 1.2, 0.3, 0.3 on 10, 20, 30: the normalized cumulative weight 2 computes as 1.9999999999999998; the median is 10, Hmisc answers 20) — Pulse returns the value Hmisc's rule gives in exact arithmetic (`TestWeightedShape_QuantileRankSnap`, `TestWeightedShape_HmiscQuantile`). **Scale rule (by `kind`):** `probability` weights (the default) are RESCALED so W = n, the contributing row count, before the rank is taken — the normalization of Hmisc `wtd.quantile(normwt = TRUE)` — so multiplying every weight by any constant (Σw = 1 included) leaves the figure unchanged and h = p·(n−1); the cumulative weights are rescaled as (cum·n)/W, skipped when W already equals n. `frequency` weights stay RAW (W is the expanded row count), so integer frequency weights equal type 7 on the physically expanded data exactly. Either way W ≥ 1, so h ≥ 0 needs no clamp (a clamp reassigning the rank also changed the compiler's FMA fusion of the interpolation on arm64 and broke unity bit-parity at p95 — the percentile is written in the unweighted twin's statement shape). At w ≡ 1, W = n exactly, so this is the unweighted type 7 in its own operation order (the median's two-middle case keeps `(lo + hi) / 2`); even without the skip, (cum·n)/n is exact for integer cum·n < 2⁵³. Integer `probability` weights therefore no longer reproduce the expanded rows unless Σw = n — expansion equivalence is the `frequency` contract (`TestWeightedShape_ProbabilityQuantileScaleInvariant`, `TestWeightedShape_FrequencyQuantileRaw`, `internal/service` `TestWeightProbabilityQuantileScaleInvariance`). **Components shape:** the unweighted keys and types are kept — `position` / `position_low` / `position_high` are the EXPANDED-space integer indices ⌊h⌋ / ⌈h⌉ (the sorted-row indices at w = 1; in the normalized space for `probability` weights); the fractional h is not emitted. Stays buffered (never streamable, forces the buffered crosstab arm) exactly as unweighted.

**Weighted mode / mode count (E2-S1; `weightedModeAggregator`).** Σw per distinct value; `AGG_MODE` is the value with the largest Σw, `AGG_MODE_COUNT` that Σw; ties go to the smallest value (the unweighted rule) and `tie_count` counts values sharing the maximal Σw. A zero weight contributes nothing, so a value seen only at weight zero is not a distinct value. `count` / `mode_count` become floats (integral, so wire-identical, at w = 1). Streamable and mergeable (per-value Σw add) exactly as unweighted.

**Weighted skewness / kurtosis (E2-S1; `weightedMomentAggregator`).** Weighted population moments with Σw in place of n: g1 = M3 / (W·sd³), g2 = M4 / (W·var²) − 3, var = M2 / W, Mₖ = Σw(x − mean)ᵏ. Streaming folds each (x, w) by Pébaÿ's pairwise update (n_A = W_old, n_B = w), written as the unweighted recurrence with deltaN = (w·δ)/W and the coefficients (n−1), (n−2), (n²−3n+3) replaced by W_old, (W_old − w)/w, (W_old² − W_old·w + w²)/w²; buffered mirrors the unweighted two-pass form. Streamable, not mergeable, exactly as unweighted. **FMA note:** the buffered M2 accumulates `w·d·d`, not `w·d²` — the unweighted `m2 += d²` is fused to `FMA(d, d, m2)` where the compiler emits FMA (arm64), and only `(w·d)·d` fuses to the same instruction at w = 1.

**`AGG_WEIGHTED_MEAN`.** Same implementation as weighted `AGG_AVERAGE`; the type name is preserved in output. `params.weight_field` is a slot-level weight with `kind: probability`: absent ⇒ inherits request / Options; differing from an explicit slot weight ⇒ `PROCESSING_CONFIG`; nothing resolves ⇒ `PROCESSING_CONFIG`. Not deprecated, and deliberately NOT gated by `capability:weighting`. A slot that was never stamped (a direct factory caller) falls back to `weight_field`. `PROCESSING_CONFIG` details: `{slot, operator, field}` for a conflict, `{slot, operator}` when nothing resolves (an AGG_WEIGHTED_MEAN slot makes predict report `weights` even when no other weight is named). **Behaviour notes (release notes):** the scalar and `weighted_mean` shift by at most a few ULP (exact Σwx/Σw replaces the incremental mean; `sum_weighted` is the exact Σwx, no longer mean·Σw, and `m2_weighted` follows the `(w·δ)/Σw` recurrence) — the existing tests moved to 1e-12 relative tolerance; negative / NaN / ±Inf weights are now excluded and warned (`PULSE_WEIGHT_INVALID_ROWS`) where they were previously folded in (negative) or poisoned the result (NaN / Inf); the components gain the floor `n_weight_invalid`. Weighted `AGG_AVERAGE` gains the rich Components the weighted mean already emits (`m2_weighted`, `sum_weights_sq`, `weighted_variance`, `weighted_mean`, `sum_weighted`).

**Weighted counting aggregators (E2-S2; `internal/processing/aggregator_weighted_counts.go`, plus `ratioAggregator`'s own weight).** Rows contribute only with a present value AND a valid weight > 0 (`validRowWeight`).
- `AGG_FREQUENCY` — scalar and `match_count` = Σw of the rows equal to `params.value`; `share` = Σw_match / Σw over the value-present rows, omitted when Σw = 0.
- `AGG_RATIO` — Σw·num / Σw·den; a row with either field null is skipped (as unweighted), and so is a row with an invalid or zero weight; components `numerator` / `denominator` are the weighted sums. The floor keys follow the slot's (ignored) `Field`, exactly as `n` / `n_null` do.
- `AGG_SET_FREQUENCY` — Σw per selected member: Rich `map[string]float64`, scalar fallback the largest member Σw, `per_label_count` / `total_label_observations` Σw (floats), `distinct_labels` stays a count; a member selected only at weight 0 is dropped like an unseen one.
- `AGG_SET_CARDINALITY_SUM` = Σw·popcount; `AGG_SET_CARDINALITY_AVG` = Σw·popcount / Σw (0 when Σw = 0); an empty mask still contributes its weight to Σw.

All five stay streamable and mergeable (Mergeable / Partial as declared) and never take a pre-collected value slice. Unity: Σ of unit weights is the exact integer count and 1·x is x, so w ≡ 1 is bit-identical; with integer weights every figure equals the expanded rows exactly (`TestWeightedCounts_*`, `internal/processing/aggregator_weighted_counts_test.go`). **No scale question:** every one is either a ratio of two weighted sums (scale-free) or a weighted total (scales with the weights, as `AGG_COUNT` / `AGG_SUM` do).

**decimal128 (E2-S2).** A weight-aware slot whose value field is `decimal128` — its `Field`, or `AGG_RATIO`'s `numerator_field` / `denominator_field` (its own `Field` is ignored, so a decimal there is not weighted) — is `PULSE_WEIGHT_UNSUPPORTED` under ANY weight in force, the instance default included: the decimal aggregation path (`AggregateDecimalField`) has no weighted form, and skipping the weight would mix an unweighted figure into a weighted table. Details `{slot, operator, field, value_field, type}` (`field` = the weight). Raised by `ResolveWeights` (`decimalWeightRefusal`), so predict and runtime refuse identically (`TestResolveWeights_DecimalRefused`, `TestWeight_DecimalPredictMatchesRuntime`); opt out with `weight: null`. `AGG_WEIGHTED_MEAN` over a decimal field — always weighted — is therefore `PULSE_WEIGHT_UNSUPPORTED` on both sides (before E2-S2 the runtime refused it `PROCESSING_CONFIG` while predict only warned `PULSE_AGG_NOT_MEANINGFUL_FOR_DECIMAL`; a release-note behaviour change). A NOT-weightable operator over a decimal field is unaffected — skipped under a default weight, `PROCESSING_CONFIG` under an explicit one, exactly as over any other type.

Weighted Rich / Meta outputs that are integers when unweighted (`AGG_SET_FREQUENCY`'s map, `per_label_count` and `total_label_observations`, `AGG_FREQUENCY`'s `match_count`, `AGG_SET_CARDINALITY_*`'s `sum_cardinality`, `mode_count`) become floats only when weighted — integral, so wire-identical, at w = 1; the manifest `EmitsTypeNote` claims and component-key descriptions say so. Streamable / Mergeable flags do not change: a weighted mergeable operator stays streamable, shard-parallel and parallel-decode eligible (`CanMergeRequest`), and weighted percentile / median stay buffered exactly as unweighted.

## Crosstab

**Shipped (E3-S1 buffered arm; E3-S2 fused-arm parity).** Both arms stamp (`RunCrosstab`, `RunCrosstabFused`), so every accumulator builds off the stamped spec — buffered `runCellAggregation` (cells, row / column / grand margins), `p.aggregate` (partial-depth and `normalize_within` denominators) and `computeAuxMargins`; fused `FusedCrosstabState.Update` / `updateAuxMargins`. Cells, every margin class, partial-depth margins and auxiliary `margin_aggregations` are therefore recomputed from the WEIGHTED raw rows, and normalization (row / column / total, `normalize_level`, `normalize_within`) divides a weighted cell by its weighted margin. **A record reaches an auxiliary margin only if it reached a CELL** — unchanged by weighting.

- **Counts stay raw.** `CellCounts` and every margin count are row counts, never Σw; Σw is the map's `sum_weights`.
- **Floor keys on the flat maps.** `CellComponents[r][c]`, `RowMarginComponents` / `ColumnMarginComponents` / `GrandTotalComponents` and each auxiliary figure's `components` carry `sum_weights` / `n_eff` (`probability`) / `n_weight_invalid` when THAT slot is weighted — tallied over the same records as its `{n, n_null}` (buffered: `WeightFloor` beside the `runCellAggregation` walk, stamped by `stampMap`; fused: per-cell / per-margin / per-auxiliary `WeightFloor`s in lockstep with the null counters, allocated only for a weighted cell). An operator's own same-named key wins (`AGG_WEIGHTED_MEAN`'s `sum_weights` / `n_eff`, read by `OVERLAY_PAIRWISE_WEIGHTED_TWO_MEANS_Z`'s `cell_weight_sum`). An auxiliary slot that admitted nothing reports `sum_weights: 0`.
- **The unweighted base.** A `margin_aggregations` slot with `weight: null` (`AGG_COUNT` is the base) beside weighted cells; it carries no floor key. An auxiliary's own weight overrides the request's (field or `kind`) like any slot.
- **Warning.** One `PULSE_WEIGHT_INVALID_ROWS` per weight field over the filter-passing rows (after row-local attributes), on both arms; `--strict` refuses.
- **Fusion.** `crosstabfuse.Decide` reads no weight: a weighted median / percentile cell or auxiliary stays buffered because the operator is non-mergeable, exactly as unweighted, and every other answer is the unweighted one (`TestWeightCrosstabFusionDecision`; predict agrees — weighted cases in the `TestPredict_CrosstabFusableMatchesRuntime` corpus).

- **Fused arm (E3-S2).** No fused code changed: every fused accumulator — cells, row / column / grand margins, the partial-depth (`normalize_level`) and cross-axis (`normalize_within`) denominators, and each auxiliary — is constructed off the STAMPED spec (`newOnlineCell(…, s.cellAgg | s.auxAggs[i], …)`), so each is the weighted form, and its floor `WeightFloor` folds beside it. There is no parallel fused dispatch — `processCrosstabFused` is one serial walk, and the buffered arm's parallel segment decode only materialises records for a single `RunCrosstab` — so no partial crosstab state is ever merged; the invalid-row tally is one `WeightRowTally` over the single walk. Because each class has its own construction site, a class that dropped the weight would silently answer the UNWEIGHTED figure while the rest stay right — hence the per-class gate below.

Gates (`internal/service/weight_crosstab_test.go`; each arm forced — the buffered one by an always-true `FILTER_EXPRESSION`, the fused one by dropping it — and asserted engaged; an operator whose unweighted twin never fuses is not run on the fused arm, and a weighted request must take its twin's arm): `TestWeightCrosstabUnityParity` (every weight-aware cell aggregator × weight source × arm, byte-identical after shedding the unity floor), `TestWeightCrosstabFrequencyExpansion` (both arms: cells, margins, auxiliaries and the three normalizations equal the duplicated rows; counts equal the raw run; the `weight: null` base equals the unweighted figure), `TestWeightCrosstabFusedMatchesBuffered` (one weighted request, both arms, every fusable weight-aware cell × variant × source × kind over weights with negative / NaN / zero rows: payload, flat components incl. floor keys and the warning — byte-exact for the Σw-sum operators `AGG_COUNT` / `AGG_SUM` / `AGG_MODE_COUNT` / `AGG_FREQUENCY` / `AGG_SET_FREQUENCY` / `AGG_SET_CARDINALITY_SUM`, 1e-12 relative for the mean / ratio forms whose running and slice code may contract differently), `TestWeightCrosstabProbabilityQuantileScaleInvariance`, `TestWeightCrosstabAuxSlotOverride`, `TestWeightCrosstabInvalidRows` (both arms). Per accumulator class: `internal/processing` `TestCrosstab_WeightedFusedMatchesBufferedPerClass` isolates each class's own payload and asserts fused = buffered AND that the weight moved it (falsified per construction site). Predict: every built-in aggregator, weighted, as cell and auxiliary in the `TestPredict_CrosstabFusableMatchesRuntime` corpus. A cell whose rows all carry weight 0 makes `AGG_RATIO` answer 0/0 = NaN on both arms (as an unweighted all-zero denominator does); the wire writes it `null` (`types.MarshalFinite`, `.claude/reference/response-components.md` (Undefined figures on the wire)), so the gate runs `AGG_RATIO` × frequency on every variant with no skip.

## Refusal rules

While a weight is in force on a slot, each of these is `PULSE_WEIGHT_UNSUPPORTED` at predict AND runtime — raised by `ResolveWeights`, so the code, message and details match (`TestWeight_InferentialRefusalsMatchPredict`, `TestResolveWeights_InferentialRefused`). "In force" means a weight RESOLVES on the slot — its own `weight`, the request weight or `Options.DefaultWeight`: an instance default refuses these slots too, so each must opt out with `weight: null`. Details `{slot, operator, field}`:

- every built-in `TEST_*` on `tests[i]` whose weighted computation has not landed (the seven moment tests compute weighted since U12 E1-S2 — "Weighted inference" below; an `Options.DefaultWeight` instance now weights a bare `TEST_T`, `TestWeight_DefaultInstanceWeightsTTest`), every built-in `TEST_*` on `post_tests[i]` (permanent: it reads aggregated rows) and every `REG_*`;
- `ATTR_ZSCORE`, `ATTR_TSCORE`, `ATTR_PERCENTILE` (permanent) (the regression attributes `ATTR_REG_*` and the row-local ones are untouched; `ATTR_NORMALIZED` is not weightable since U12 E1-S1);
- `GROUP_QUANTILE` on `groups[i]`, `crosstab.rows[i]` or `crosstab.columns[i]`. **Opt-out decision (E2-S3):** `types.Group` gained the same `SlotWeight` (`weight`, `omitzero`) every other slot carries — the null-opt-out pattern needed a slot, and without one an `Options.DefaultWeight` instance could never run a quantile grouper. A set weight on any other grouper is accepted and skipped; the field is projected and judged by the field-reference rule like every slot weight, and the MCP binder declares it on `groups` and both crosstab axes;
- `AGG_CI_LOWER` / `AGG_CI_UPPER`;
- any weight-aware aggregator over a `decimal128` value field (E2-S2; see "decimal128" above; details add `value_field`, `type`);
- every overlay whose kind is declared `Inferential: true` (`internal/descriptor/capabilities_overlay.go`) — classed by the per-kind overlay table `overlayWeightClasses` (`internal/descriptor/weight_resolve.go`; both kinds / frequency-only / permanent refusal with a reason), else off the flag through `overlayWeightClass` (an unlisted Inferential kind refuses until its weighted form lands). `OVERLAY_PAIRWISE_WEIGHTED_TWO_MEANS_Z` is listed under both kinds (since E1-S1 its resolved status is `applied`, previously `skipped_not_weight_aware`; an inherited default is judged on its host, never on the overlay); `OVERLAY_PAIRWISE_TWO_MEANS_Z` is refused permanently with `details.alternative` naming that twin (omitted when the instance hides it), `OVERLAY_PAIRWISE_PROBIT_T` permanently; its host is an `AGG_WEIGHTED_MEAN` OR a WEIGHTED `AGG_AVERAGE` cell (FR-18) — see "Overlays" below. **On `Request.Overlays`** the overlay's OWN resolved weight decides (slot → request → default — a request or instance weight that weights the host weights the overlay too); its `weight: null` opts out and it then runs over the host as before. A host weighted ONLY by its own slot weight (or `AGG_WEIGHTED_MEAN`'s `params.weight_field`) does not refuse an overlay nothing else weights: the shipped pairwise `n_source` modes (`cell_weight_sum`, …) read such a host on purpose, and refusing it would break shipped requests. **On Compose** (`ComposedRequest.Overlays`, no weight of its own) `ComposeOverlayWeightRefusal` refuses a refused kind (a frequency-only kind only when the inherited host weight is kind `probability`) when a slot it reads (reference or a target; every slot when `targets` is empty) has a REQUEST or INSTANCE default weight applied to an aggregation or crosstab cell — the same line — with details `{slot: "overlays[i]", operator, field, host: "requests[j].<slot>"}`; the opt-out is `weight: null` on that slot's aggregations. Runtime (`Service.applyComposeOverlays`, serial and parallel) and `ValidateComposeWithOptions` call it over the raw slots (`TestWeight_ComposeInferentialOverlayMatchesValidator`). Facet-host kinds are out of scope (facets are never weighted); whole-chain overlays ship only descriptive kinds.

Windows (`WIN_*`, no slot weight): a REQUEST weight is `PROCESSING_CONFIG` `{slot, operator, field}`; `Options.DefaultWeight` is skipped (`skipped_not_weight_aware`). Filters, features, row-local attributes and the other groupers are unaffected (`TestWeight_WindowsAndUnaffectedMatchPredict`). Share and index overlays read the host payload and are therefore weighted automatically ("Overlays" below). Facets are out of scope: no `FacetRequest.Weight`, and `Options.DefaultWeight` does not reach facet-population overlays. **Extension** aggregators, attributes and tests follow their `WeightAware` declaration ("Extension contract"): a non-aware attribute or test is refused under any weight in force, an aware one is applied. U12 inherits this list to lift (its E1-S1 adds the kind dimension above).

## Weighted inference

**Shipped for the moment tests (U12 E1-S2).** One rule (`internal/weighting/inference.go`): N* = Σw under `frequency`, Kish n_eff = (Σw)²/Σw² under `probability` (`weighting.Basis`, `NStar`, `Scale`); w* = w·N*/Σw; every weighted formula is the FREQUENCY formula on w* — point estimates (means, r) are kind-free, spreads / SEs / df read N*. `weighting.Welford` is the shared weighted Welford–West bucket (raw `N`, Σw, Σw², weighted mean, M2_w = Σw(x − mean)²; `Variance(basis)` = c·M2/(N* − 1)); `Add` follows the operation-order rule, so w ≡ 1 is the unweighted recurrence bit for bit (`TestWelford_UnityBitIdentical`) and the built-in tests run every unweighted row through it with w = 1. Later stories reuse the bucket and the basis; do not fork them.

- **Lifted (both kinds):** `TEST_T` (one-sample: t on N*, df = N* − 1; split: Welch on N*_g), `TEST_WELCH`, `TEST_PAIRED_T` (the weight is per ROW = per pair; a null in either field drops the pair before its weight is judged), `TEST_Z_TWO_SAMPLE` (Welch SE on N*_g), `TEST_ANOVA_F` (ONE c = N*/Σw over the whole sample: SSB, SSW on w*, df_within = N* − k), `TEST_ANOVA_WELCH` (v_j = N*_j/s_j², df on N*_j − 1), `TEST_PEARSON_R` (r scale-free; t and df = N* − 2, Fisher CI on N* − 3). Effect sizes read the same s and N*.
- **Threading:** `StampWeightsWith` keeps the resolved weight on a `tests[i]` slot whose operator `weighting.IsAware` (or a WeightAware extension); `post_tests[i]` is stamped for extensions only. The factory reads `spec.Weight` (`testWeight`, `internal/processing/test_weight.go`). A row whose weight is invalid or ZERO is excluded and never enters `n`; invalid ones are tallied once per field by `WeightRowTally` (`PULSE_WEIGHT_INVALID_ROWS`, `--strict` errors).
- **Details:** `n` stays the raw row count; a weighted run adds `sum_weights` and (probability only) `n_eff` in the same shape as `n` (scalar, or per-group array in `groups` order); `df` may be fractional. Raw-n floors (`PULSE_TEST_INSUFFICIENT_N`) are unchanged.
- **`PULSE_WEIGHT_LOW_NEFF`** (warning; error under strict): probability only, one per short group — n_eff below the test's raw-n floor (2 per group; `TEST_PEARSON_R` 3; `TEST_ANOVA_F` k + 1 on the whole-sample N*). Details `{test, type, group (split tests), n_eff, min_required}`. Raised at the three row-test finalize sites (streaming, buffered, buffered crosstab arm).
- Gates: `internal/processing/test_weighted_test.go` — unity (byte-identical once `sum_weights` / `n_eff` are shed), frequency = expansion, closed-form w* oracles for both kinds, a hand-computed case, invalid / zero exclusion, streaming = buffered, the low-n_eff warning on every site.

## Overlays

- **Share / index kinds are descriptive** (no `Inferential` flag, so `overlayWeightClass` never refuses them) and carry NO weight logic: they read the host payload, which is already weighted. Matrix `OVERLAY_SHARE_OF_ROW` / `_COL` / `_TOTAL` and `OVERLAY_INDEX_VS_MARGIN` (both crosstab arms), series `OVERLAY_SHARE_OF_TOTAL` and `OVERLAY_INDEX_VS_TOTAL` / `_PRIOR` / `_BASELINE` / `_ROLLING_MEAN` / `_SIBLING` (streaming fold included), Compose `OVERLAY_INDEX_VS_REF` and the panel index `OVERLAY_PANEL_INDEX_VS_REF` over weighted slots. Gate: frequency expansion — a request-weighted host's layers equal the physically expanded cohort's unweighted layers, differ from the unweighted host's, and leave the host payload byte-identical to the overlay-free run (`TestWeightShareIndexOverlaysReadWeightedHost`, `TestWeightComposeIndexOverlaysReadWeightedSlots`, `internal/service/weight_overlay_test.go`). `OVERLAY_INDEX_VS_STAGE` (chain) and `OVERLAY_INDEX_VS_POP` (facet) read the same way but their hosts carry no top-level weight in U11. An undefined series entry (the first `_PRIOR` point, an unfilled rolling window) is NaN in Go and `statistic: null` in JSON on weighted and unweighted hosts alike, so the gates compare layers on the JSON form. The full audit of non-finite producers and the JSON surfaces they reach (all routed through `types.MarshalFinite`) is `.claude/reference/response-components.md` (Undefined figures on the wire).
- **`OVERLAY_PAIRWISE_WEIGHTED_TWO_MEANS_Z` hosts (FR-18).** The runtime gate is key-based (`HasWeightedMomentCells`: `weighted_mean`, `m2_weighted`, `sum_weights`, `sum_weights_sq`); a weighted `AGG_AVERAGE` cell carries the first, second and fourth as its own keys and `sum_weights` from the weighted floor (`WeightFloor.stampMap`, both arms), so it qualifies, while an unweighted one never does. Predict's cell-host refusal (`validateOverlayPairwise` → `weightedMomentCell`, `internal/descriptor/overlay.go`) admits `AGG_WEIGHTED_MEAN` always and `AGG_AVERAGE` iff a weight resolves on the cell (slot → request → `Options.DefaultWeight`; `weight: null` opts out) — the `StampWeights` precedence, so the two arms agree (`TestPairwiseWeightedTwoMeansZ_PredictRuntimeParity`, `TestPredict_PairwiseWeightedTwoMeansZ_WeightedAverageCell`). A weighted-average host answers exactly as the weighted-mean host (`TestCrosstab_WeightedTwoMeansZ_WeightedAverageHost`, both arms). The feature hard edge is the any-of group `{AGG_AVERAGE, AGG_WEIGHTED_MEAN}` (`hardEdges`, `internal/descriptor/features.go`): a profile keeping the overlay needs either.

## Floor keys

The universal aggregator floor `{n, n_null}` gains three keys, all `omitempty` and present ONLY on a weighted slot:

- `sum_weights` — Σw over the rows that contributed (spelling kept from `AGG_WEIGHTED_MEAN`; no `w_sum` alias);
- `n_eff` — Kish effective n, (Σw)²/Σw², `kind: probability` only;
- `n_weight_invalid` — rows excluded by validation.

`n` / `n_null` keep their value-presence meaning; counts stay raw ints (`CellCounts`, margin counts, grouper `total_n`, `ResponseMetadata` row counts). Absence of `sum_weights` is the only per-slot "unweighted" signal — there is no `weighted` marker and no skip warning; predict's per-slot status is the explanation. Shipped (E1-S3): typed fields `AggregationComponents.SumWeights` / `NEff` / `NWeightInvalid` (pointers, so a weighted zero still marshals), tallied by `processing.WeightFloor` beside `{n, n_null}` on every non-crosstab path and merged slot-wise by both reducers; declared `optional: true` (`descriptor.ComponentKey.Optional`) right after `{n, n_null}` in every weight-aware aggregator's ComponentSchema (`AGG_WEIGHTED_MEAN` already lists `sum_weights` / `n_eff` among its operator keys, so only `n_weight_invalid` is added there). Not-weight-aware operators do not declare them. Extensions get them from the orchestrator and never emit them. Floor prose: `.claude/reference/response-components.md`.

## Operation-order exactness rule

Weighted formulas are written so that w = 1 reproduces the unweighted operation order bit for bit — e.g. `(w·δ)/Σw`, never `(w/Σw)·δ` — and the unweighted path is untouched when no weight is set. Pinned per aggregator by `TestWeightedCore_UnityParity` (buffered, streamed and multi-partition merged, bit for bit, on 400 values); the cross-mode gates are E1-S4's (`internal/service/weight_parity_test.go`): `TestWeightUnityParity` (all-ones weights marshal byte-identically to unweighted, the weight-only keys shed, for every weight-aware operator × buffered, streaming, grouped streaming, two-pass, shard-parallel and parallel-decode execution × weight source — request, slot, `Options.DefaultWeight`) and `TestWeightFrequencyExpansionParity` (integer weights equal physically duplicated rows run unweighted — exact for counts and integer sums, `sum_weights` exactly the expanded `n`, 1e-12 relative otherwise). Both iterate an operator table held equal to the manifest `weight_aware` set (a `coverage` subtest), so an E2 story flipping an operator to aware owes its row; an arm applies when the UNWEIGHTED request reaches it (`AGG_WELFORD` does not merge, so it skips the parallel arms) and the weighted twin must engage the same arm. Rows for the E2-S1 shape aggregators (exact on expansion for median, percentile, mode and mode count — median / percentile under `frequency` only, their `probability` arm skipped because those weights are scale-normalized and pinned instead by `TestWeightProbabilityQuantileScaleInvariance`; 1e-12 for the moments) and the E2-S2 counting aggregators (exact on expansion except `AGG_RATIO`, whose fixture denominator is fractional; the set rows run over the fixture's nullable `set_u8` column `s`) and `TestWeightedShape_*` (`internal/processing/aggregator_weighted_shape_test.go`: unity bit-identity on buffered / streamed / merged paths, frequency expansion, hand-computed fractional-W oracles, Hmisc agreement and the integer snap, closed-form weighted moments) pin them. The buffered crosstab arm joins through `TestWeightCrosstabUnityParity` / `TestWeightCrosstabFrequencyExpansion` (E3-S1, "Crosstab"); the fused arm joins the same two gates plus `TestWeightCrosstabFusedMatchesBuffered` (E3-S2). Arm-comparison float tests otherwise use tolerances; the external values are pinned separately ("Reference fixtures").

## Reference fixtures

**Shipped (E2-S4).** `TestWeightReferenceValues` (`internal/service/weight_reference_test.go`) pins every weight-aware aggregator's weighted figure and floor keys to values an EXTERNAL tool computed, at 1e-12 relative, on the buffered and (where it streams) streaming arms. The numbers are the generated `internal/service/weight_reference_values_test.go`, written by `internal/service/testdata/weight_reference/gen_weight_reference.py` (`uv run --no-project gen_weight_reference.py`, then `gofmt -w`; tool versions pinned in its PEP 723 header and echoed in `weightRefProvenance`). Python never runs in CI; never hand-edit the generated file. A `coverage` subtest demands a case per manifest `weight_aware` aggregator per weight column, so a newly weight-aware aggregator owes a reference as well as a parity row.

| Pulse figure | Reference, configured to Pulse's definition |
|---|---|
| `AGG_COUNT`, `AGG_SUM`, `AGG_AVERAGE` / `AGG_WEIGHTED_MEAN` | statsmodels `DescrStatsW` `.sum_weights`, `.sum`, `.mean` |
| `AGG_VARIANCE` / `AGG_STDDEV` (population) | `DescrStatsW(ddof=0).var` / `.std` |
| `AGG_WELFORD` variance (m2_w / (Σw − 1)) | `DescrStatsW(ddof=1).var` (statsmodels divides by `sum_weights − ddof`) |
| `AGG_MEDIAN` / `AGG_PERCENTILE`, `frequency` | numpy `percentile(method="linear")` on `np.repeat` |
| `AGG_MEDIAN` / `AGG_PERCENTILE`, `probability` | R Hmisc 5.3.0 `wtd.quantile(normwt = TRUE)` (`hmisc_quantile.R`, shelled out to by the generator), cross-checked against an exact-rational transcription of the same rule (below) |
| `AGG_SKEWNESS` / `AGG_KURTOSIS` | scipy `skew` / `kurtosis(fisher=True, bias=True)` on the expansion (frequency, and the probability twin — moment ratios are scale-invariant); exact-rational weighted moments for fractional weights |
| `AGG_MODE`, `AGG_MODE_COUNT`, `AGG_FREQUENCY`, `AGG_RATIO`, `AGG_SET_*` | numpy weighted sums |

The fixture carries three weight columns: `w` (fractional probability weights with a zero, a negative and a NaN), `f` (integer frequency weights with zeros, a negative, a NaN and a non-integer) and the probability twin `p = c·f`. `TestWeightReferenceKindsAgree` runs `f` as `frequency` and `p` as `probability` and holds every scale-free figure equal and every weighted total at `c ×` the frequency figure (`weightRefScale`, held total over `weight_aware`); `AGG_WELFORD`'s sample variance and the quantiles have no such identity.

**Probability quantiles are Hmisc's.** The `probability` median / percentile references are R 4.6.1 + Hmisc 5.3.0 `wtd.quantile(x, w, probs, type = "quantile", normwt = TRUE)`, computed by `internal/service/testdata/weight_reference/hmisc_quantile.R` (which refuses any other Hmisc version; install instructions in its header and the README) — R, like Python, never runs in CI. The generator also asserts each Hmisc figure equals, at 1e-12 relative, an exact-rational (`fractions.Fraction`) transcription of the rule — the transcription is now a cross-check, not the reference. Until the Hmisc adoption the probability reference WAS that transcription of Pulse's own former rule (x₍ₖ₎ = the smallest value whose normalized cumulative weight EXCEEDS the 0-based k), and it differed from Hmisc on the fixture's `w` and `p` columns (`w` median 3.5 vs 4.25, p90 6.55 vs 7.275; `p` p37.5 2.65625 vs 3.5, p90 5.0 vs 6.425); those figures now equal Hmisc. The generator still refuses a fixture whose normalized cumulative weight sits on an integer rank: Pulse snaps there (above) but Hmisc does not, so Hmisc's figure on such a fixture is a last-ulp float artifact, not a usable reference.

## Extension contract

**Shipped (E4-S1).** An embedder break (v1.0.0-alpha.5; `docs/roadmap/v1.0.0-api-and-release/03-embedder-migration.md`).

- `WeightAware bool` on `AggregatorRegistration`, `AttributeRegistration` and `TestRegistration` (tier 1 and tier 2); projected as `descriptor.OperatorMeta.WeightAware` — the manifest extension entry's `weight_aware` (omitempty) — and recorded on `processing.ExtensionRegistry.WeightAware`. Filterers, groupers, windows and features have no declaration: a weight never reaches them (`skipped_not_weight_aware`).
- `extend.Record.Weight() (float64, bool)` — the engine-resolved weight for the slot; only VALID weights are reported (`weighting.Classify`: finite, ≥ 0 — zero included — and an integer under `frequency`); `ok == false` ⇒ no weight in force, or the operator is not WeightAware. The engine's own row (`*processing.Record`) always answers `(0, false)` — slot weights differ within one request — so the root adapter hands a WeightAware slot a per-slot `weightedRecord` view (`slotWeighting`, `extensions_adapt.go`). **A row whose weight is invalid never reaches an aware aggregator (buffered `Aggregate` or online `UpdateRow`) or tier-1 row test; an aware attribute owes every row a value, so it still receives the row, with `Weight()` false** (decision, E4-S1). The factory sees the resolved weight on its spec: `processing.StampWeightsWith` (the registry-aware `StampWeights`) stamps aggregation slots as before and, for a WeightAware extension, `tests[i]` / `post_tests[i]` / `attributes[i]` too; any other test / attribute slot that names a weight is stamped `null`. `NewWeightRowTally` counts the stamped test and attribute slots beside the aggregation ones, so an extension slot alone still raises `PULSE_WEIGHT_INVALID_ROWS`.
- Classing (`ResolveWeights`, off `ExtensionsSnapshot.WeightAwareness`, so predict and runtime agree): aware ⇒ `applied` — including over a `decimal128` value field (the decimal refusal is the BUILT-IN decimal path's; an extension reads `DecimalValue` and owns its weighted form). A non-aware aggregator: explicit (slot or request) weight ⇒ `PULSE_EXTENSION_NOT_WEIGHT_AWARE` `{slot, operator, field}`; instance default ⇒ `skipped_not_weight_aware`, factory sees `null`. A non-aware attribute or test: refused under ANY weight in force, the instance default included (it may read the whole population, like the built-in tests and reference attributes). `weight: null` opts every one out. A hidden extension is never-registered (skipped).
- **Inferential decision (E4-S1).** A WeightAware extension TEST is applied, not refused like a built-in `TEST_*`: the registration declared that it computes a weighted result, which is exactly what U12 lacks for the built-ins. There is no extension `REG_*` category.
- Floor keys: the orchestrator stamps `sum_weights` / `n_eff` / `n_weight_invalid` on an aware aggregator's slot (`WeightFloor`, every mode, crosstab cells and margins included); the extension never emits them and does not declare them in its `ComponentSchema` (the manifest lists only declared operator keys for extensions, floor excluded).
- Probe: a WeightAware aggregator, attribute or test factory is constructed both with and without a weight (`probeWeight`, a field the empty probe schema lacks) and each construction passes the same checks (streaming sibling, mode, merge); a failure of the weighted one carries `details.weighted: true` under the existing codes (`PULSE_EXTENSION_FACTORY_PANIC`, `_STREAMABLE_MISMATCH`, `_MERGEABLE_MISMATCH`). Tests are probed only when they declare WeightAware — probing every test would refuse registrations that worked.

Gates: `TestExtensionWeight_*` (root, `extensions_weight_test.go`: aware aggregator on buffered and streaming paths × slot / request / default source, crosstab cell equal to weighted `AGG_SUM` on both arms, non-aware refusals = predict, aware attribute and test, manifest projection, probe), `TestResolveWeights_ExtensionClasses`, `TestStampWeightsWith_ExtensionAwareness`, `extend` `TestRecordExposesWeight`, and the embedder smoke module's `TestExtendWeightAwareAggregator` (`make smoke`).

Recipe: `docs/src/internals/extension-points.md`; engine wiring: `architecture.md` (Extension surface).

## SPSS suggestion

Inspect reads the SPSS metadata sidecar (`cohort.pulse.spss.json`, header-only — never records) and surfaces `suggested_weight {field, source: "spss_sidecar", kind: "probability"}` (additive, omitempty) on the result and envelope, the CLI leaf and `pulse_inspect`. Predict echoes it as DATA when no weight resolves — never a warning, so `--strict` stays safe. A stale sidecar (variable not in the schema) yields no suggestion, silently. A suggested weight is **never** auto-applied, including via `DefaultWeight`; there is no manifest-level suggestion (the manifest is instance-level). SPSS `WEIGHT BY` is frequency-like, while the default `kind` is `probability` — say so wherever the suggestion is documented. **Shipped (E4-S3).** The predict / inspect contract now reads "header + schema + sidecar metadata, never records"; wiring, the silent-failure list (absent, malformed, fingerprint-stale, variable gone or not weight-capable, anchor, byte-level entry points) and gates: `predict-inspect.md` (Suggested weight).

## Feature profile

**Shipped (E4-S2).** `capability:weighting` is a request-slot capability: a `features.go` row (`Since` `1.0.0`, `descx.FeatureWeighting`) in `requestSlotCapabilities`, so it depends on any-of the request hosts. Hidden:

- the request-root `weight` and EVERY per-slot `weight` — aggregations, crosstab cell, `margin_aggregations`, tests, post-tests, regressions, attributes, overlays (facet overlays too), groups, crosstab rows / columns; inside Compose requests and chain stages too — are `PULSE_REQUEST_UNKNOWN_FIELD`, an explicit `null` included. A nested one carries `details.path` and the nested object's `valid_keys` (`nestedWeightRefusal`, `internal/descriptor/request_slots.go`);
- the payload schema, the MCP bound tool schemas, manifest `weight_aware` (built-in and extension), `weight_kinds` (every family) and the weighted floor keys, and predict `weights` are absent;
- `Options.DefaultWeight` fails `pulse.New` — `PULSE_FEATURE_PROFILE_DEPENDENCY`, `unmet: [{option: "Options.DefaultWeight", requires_any_of: ["capability:weighting"]}]`. Refused rather than ignored: an ignored default would silently change every figure an instance-level setting promised to weight;
- `AGG_WEIGHTED_MEAN.params.weight_field` stays ungated (deliberate asymmetry, `TestHiddenWeighting_WeightedMeanParamUngated`): it is the operator's own parameter, so its invalid-row warning and decimal refusal keep their codes listed while `AGG_WEIGHTED_MEAN` is enabled.

`suggested_weight` (SPSS, E4-S3) is absent too when hidden — on inspect, predict and `pulse_inspect` / `pulse_predict` (`TestSuggestedWeight_HiddenWithWeighting`, `TestHandleInspect_SuggestsTheSPSSWeight`). Contract and pins: `feature-profiles.md` (Request-slot gate, Manifest hiding, Predict hiding, Error hiding).

## Error codes

Each needs a `codeMetadata` entry (Message + ≥1 Fixup) and an `internal/descriptor/error_owners.go` owner. Owners (E4-S2): `PULSE_WEIGHT_INVALID_ROWS` and `PULSE_WEIGHT_UNSUPPORTED` → `capability:weighting` + `AGG_WEIGHTED_MEAN` (its ungated `weight_field` reaches both); `PULSE_EXTENSION_NOT_WEIGHT_AWARE` → `capability:weighting`. E1-S3 raises `PULSE_WEIGHT_INVALID_ROWS` (warning / strict error) and `PULSE_WEIGHT_UNSUPPORTED` (`AGG_CI_*`; E2-S2 adds the decimal128 value field; E2-S3 every "Refusal rules" surface); `PULSE_EXTENSION_NOT_WEIGHT_AWARE` is raised since E4-S1:

- `PULSE_WEIGHT_INVALID_ROWS` — warning; excluded rows with the by-reason breakdown.
- `PULSE_WEIGHT_LOW_NEFF` (U12 E1-S2; owner `capability:weighting`) — warning (strict: error); a weighted test's group n_eff below its raw-n floor ("Weighted inference").
- `PULSE_WEIGHT_UNSUPPORTED` — a refused surface under a weight: a frequency-only operator under a probability weight (`kind`, `supported_kinds`), a permanent refusal (`reason`, optional `alternative`), a pending one, or a decimal128 value field; the fixups name the `weight: null` opt-out, the switch to `kind: frequency` and the alternative operator. Its Message names no operator (`TestErrorMessagesNameOnlyOwners`: a Message names no hideable operator but its owners).
- `PULSE_EXTENSION_NOT_WEIGHT_AWARE` — explicit weight on a non-aware extension aggregator, or any weight in force on a non-aware extension attribute or test.
- `PROCESSING_CONFIG` — bad weight field or type, explicit weight on a not-weightable operator, `weight_field` conflict or nothing resolving for `AGG_WEIGHTED_MEAN`.
