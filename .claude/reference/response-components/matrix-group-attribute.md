# Response.Components — Matrix, per-group aggregation, grouper refit and attribute components

Per-topic slice of the response-components reference. Index (preamble + section map): `.claude/reference/response-components.md` — load it first, then only the slice(s) your change touches.

## Matrix components

`ResponseComponents.Matrices []types.MatrixComponents` (`matrices`, `omitempty`) carries one entry per `Response.Matrices` result, same order, keyed back by `name` + `type` (+ `group_key` on a grouped result: spec-major, then bucket). Built off the slot's MERGED co-moment state, so it is as worker-invariant as the matrix: serial, every `DecodeWorkers` and every `ShardWorkers` count report the same entry (`TestMatrixInvariance_*`).

- **Floor, every entry.** `n` = `CoMoment.N()` — listwise the complete rows, pairwise the rows with at least one member present. A row of weight 0 COUNTS (it adds no mass); an invalid weight does not (`n_weight_invalid`). `n_null` = filter-passing rows skipped for missing members — listwise any member null (equal to `n_listwise_dropped`), pairwise every member null. `n_listwise_dropped` is the integer `PULSE_MATRIX_LISTWISE_HEAVY_DROP` reads (0 under pairwise).
- **Pairwise.** `min_pair_n` / `max_pair_n` — extremes of `auxiliary.n` over the upper triangle, diagonal included. Absent under listwise.
- **Weighted.** `sum_weights`, `n_weight_invalid` when a weight is APPLIED; `n_eff` (Kish) only under `probability`. Absent ⇒ unweighted.
- **Operator map.** Per operator, from its `ComponentSchema` (e.g. `MAT_COVARIANCE` `{ddof}`).
- **Declaration.** `descriptor.MatrixMeta.ComponentSchema` (`internal/descriptor/capabilities_matrix.go`): floor keys, optional pairwise keys, the optional weighted keys (only on an instance offering `capability:weighting`), then the operator's own; mirrored at `components_schemas.matrices`; `Mergeable`. Unlike aggregators the matrix floor IS listed, because it is not the universal `{n, n_null}`.
- **Opt-out and streaming.** Built only when components are on; disabled ⇒ no entry, wire otherwise byte-identical. Streamed, the entry rides the terminal flush with the matrix; `stream.go` `chunkComponents` must carry every `ResponseComponents` field on each chunk clone (`TestChunkComponents_CarriesEveryBlock` checks by reflection).
- **Feature profiles.** `matrices` is gated on `capability:matrices`: an instance without it has no `matrices` key or `MatrixComponents` def in its payload schema.

## Per-group aggregation components

`AggregationComponents.Groups []types.AggregationGroupComponents` (`groups`, `omitempty`) carries a grouped run's per-bucket figures. The slot keeps its identity (`label`) and the ungrouped floor shape; an ungrouped response has no `groups` key.

- **Scope.** Grouped NON-crosstab runs (`Request.Groups`); a crosstab's per-cell figures live in `Components.Crosstab`. Every grouped arm emits it identically — buffered, streaming-grouped at TERMINAL flush, shard and parallel-decode reducers (all through the shared tail). Serial ≡ any worker count ≡ a multi-shard archive's single-file twin; the parity gates compare the whole block un-relaxed.
- **Slot level.** On a grouped run the slot's `n` / `n_null` (and weighted floor keys) are COHORT-WIDE totals over every filter-passing record, and `operator` is omitted. A fan-out grouper therefore has per-group `n` summing past the slot `n`.
- **Per group.** `groups[i]` = `{group_key, n, n_null, sum_weights?, n_eff?, n_weight_invalid?, operator?}` for `Data[i]`: exactly what an ungrouped run filtered to that bucket's records reports — the same builder, floor through `FieldPresent`. Extension aggregators get the floor automatically and `operator` from their existing components hook.
- **Order.** `groups[]` follows the FINAL `Data` order, after `Request.Sort`.
- **Composite keys.** With two or more `Request.Groups`, `group_key` is the full key tuple, and `Components.Groupers` keeps one entry per slot, each tallied over every filter-passing record exactly once.
- **Streaming / parallel floors.** Floors are tallied per slot and per bucket (`processing.SlotFloor`) and merged key by key; the tail builds each bucket entry off the live merged aggregator — operator STATE folds, never components. Shared helpers live in `internal/processing/aggregation_group_components.go` so the shape cannot drift between arms.
- **Streaming chunks.** Per-group figures are TERMINAL-only: `chunkComponents` drops `groups[]` on a non-terminal chunk whatever the mergeability.
- **Gates.** `TestGroupedComponents_*` (per group ≡ filtered ungrouped, data order, opt-out, invariance across arms).

## Grouper refit buckets

`types.GrouperComponents.Buckets` (`buckets`, `omitempty`, `[]GrouperBucketComponents {group_key, total_n, n_null, operator, error}`). Present ONLY on a `params.fit: "within"` position after the first: one entry per outer bucket (the tuple of the groupers before it), in the outer segments' Data order (the order the rows get, NOT record order). Each entry is that refit's components over the segment — what a standalone run of the grouper over the segment reports; the slot's own `total_n` / `n_null` / `operator` stay the WHOLE-SET fit's (byte-equal to `"global"`'s). Components off, or a `return` skipping groupers, builds none. Absent `within` = byte-identical.

**Arms.** Only the buffered plain-groups exit emits it (Compose slots share that path); `GROUP_QUANTILE` / `GROUP_KMEANS` are neither streamable nor mergeable, so no streaming or reducer arm carries a `within` position, and `chunkComponents` strips `Buckets` off non-terminal chunks. A crosstab has no `Groupers` block: a `within` ROW position's `RowKeyComponents[r].axes[p].bucket` is read off THAT row's refit; a `within` COLUMN position keeps the whole-set bucket (a column key spans every row bucket).

**Degenerate refit.** A refit refused on its bucket's data (`slotfail.RefitDegenerate`: `PROCESSING_CONFIG` reason `k_exceeds_distinct_points`; any other refit error stays fatal) fails that bucket alone through the one rule `degenerateRefit`: its records join no bucket of the slot (absent from Data, cells, margins), its entry is `{group_key, n_null: <bucket records>, error}`, and the run warns `PULSE_SLOT_FAILED` `{slot_kind: "groups", index: <composite position; a crosstab counts rows then columns>, label, code, group_key}`; Strict fails with the refit's code. In a crosstab only the two cell partitions warn; every other pass drops the bucket silently, so plain groups, both crosstab axes and Compose raise the same warnings. Predict cannot see data: `GroupPredict.RefitBuckets` (`refit_buckets`) marks the positions that will carry `buckets`. Gates: `TestGroupFit_Buckets_*`, `TestGroupFit_DegenerateRefit`.

## Attribute components

`ResponseComponents.Attributes []types.AttributeComponents` (`attributes`, `omitempty`) gives an attribute operator a typed, `return`-addressable counter surface (rather than counts buried in warning details). A request with no componented attribute slot is byte-identical.

- **Which slots emit.** One entry per `Request.Attributes` slot whose operator declares a `ComponentSchema` — at runtime, whose computer implements `processing.MetaAttribute`. Built-ins: grep `ComponentSchema` in `internal/descriptor/capabilities_attributes.go`, or read the `components_schemas.attributes` manifest block. An extension declares `AttributeRegistration.ComponentSchema` plus an emitter (`ComponentsFunc`, else the value's own `Components()`), probe-validated at `pulse.New`. The slice is NOT index-aligned with `Request.Attributes`: an entry is keyed back by `label` (the EFFECTIVE output label, so it always names the `Data` column) and `type`, in declared order.
- **Floor.** `{n, n_null}` — the rows the attribute scored, split by output presence (`attributeOutputNull`, the same rule the output writer uses). `n + n_null` is the post-filter record count, except a before-filters attribute (`ATTR_PREVIOUS_STATE`), which scored every decoded record (`execution-modes.md` (Before-filters attributes)). Orchestrator-owned. No weighted floor keys: an entry reports rows, not mass.
- **Cohort-wide.** Attributes run before any grouping, so a grouped or crosstab run carries one entry per slot, never per bucket.
- **Two-pass re-scoring.** A row-local stage a prepass needs is scored on the prepass AND the emission scan; an operator whose counters accumulate in `Row` implements `attributeTallyResetter` and is reset before emission, or its counts double (`TestAttributeComponents_TwoPassCountsOnce`).
- **Parallel / shard / chain.** Reducers carry entries only for slots whose tally folds (`processing.MergeableAttributeTally`; an extension declares `extend.MergeableAttribute`), emitted once cohort-wide (`execution-modes.md` (Tally attributes)). Any other componented attribute is reported NOT row-local by both merge-fact sources (runtime registry and predict snapshot, both filled by `attributeEmitsComponents`), so it runs serial and is refused in a `ProcessChain`.
- **Operator keys.** Each operator's keys and their optionality are in its `ComponentSchema` and atomic skill. Two rules worth knowing: a key that reports a check which may not have run is `Optional` and absent when it did not (`ATTR_SCALE_SCORE`'s out-of-range counts without a declared range — a `0` would claim a check that never ran); `ATTR_PREVIOUS_STATE` is the one built-in `None` attribute (one whole-cohort pass), so a mid-stream chunk carries its floor only.
- **Compute plan / `return`.** `components.attributes` off ⇒ no row is tallied and no `Components()` runs; nothing vetoes it; `int` values are never rounded by `precision`. Compose: per slot, as `Process`.
- **Manifest / predict.** `components_schemas.attributes` (extensions merged) + the per-operator `component_schema`; `descriptor.AttributeMergeability`. Predict has no per-attribute-slot entry; its response-size estimate counts the emitting slots. The `attributes` slot is ungated in the payload schema (it rides operators, not a capability).
- **Gates.** `TestAttributeComponents_*`, `TestManifestComponentSchemasComplete`, `TestComponentFloors_PrefixEverySchema`, `TestExtensions_AttributeComponentSchemaParity`.
