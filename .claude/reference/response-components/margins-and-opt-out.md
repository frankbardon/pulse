## Auxiliary crosstab margin aggregations

Relocated from the `Crosstab *CrosstabComponents` bullet, which it continues verbatim:

Plus, when the request declared `crosstab.margin_aggregations`, the AUXILIARY margin figures: `row_margin_aggregations[r]` / `column_margin_aggregations[c]` / `grand_total_aggregations`, one map per margin slot keyed by each auxiliary's effective label, each entry a `types.MarginAggregationFigure{value, present, components}`. `components` is the floor `{n, n_null}` over the ADMITTED records merged with that operator's own `ComponentSchema` keys, so an `AGG_DISTINCT_SUM` auxiliary's `distinct_count` is reachable PER MARGIN SLOT beside the scalar sum — the whole reason two rendered sample-size rows cost one scan rather than two. They sit BESIDE `row_margin_components` and never inside it: that describes the CELL aggregator's own margin, on a different admission, and merging the key sets would put two differently-based figures under one roof with nothing saying so. **THE ADMISSION RULE IS THE LEAST GUESSABLE PROPERTY ON THIS SURFACE, so it is stated here rather than only where it is implemented: a record contributes to an auxiliary margin ONLY IF IT CONTRIBUTED TO A CELL.** Two exclusions follow and they are the whole difference — a record whose CELL FIELD IS NULL (for a vector ELEMENT cell, `params.element` on `AGG_VEC_*` (U30 E4-S4): whose SELECTED MEMBER is null — the prepared slot reads that one member, so `AggregationPresent` on it is the cell's presence on both arms, in the cell floor, the fused `cellValuePresent` and `admitRecords` alike; an element auxiliary's own floor likewise counts its member), and a record whose AXIS KEY did not resolve (a null key, a null or empty `GROUP_SET_PER_ELEMENT` set, or a key A GROUPER `Include` EXCLUDED). **Since U47 (#325, a recorded behaviour break) the cell aggregator's OWN margins follow the axis half of the same rule on both arms: a record reaches a row, column or grand margin — and every normalize denominator, `normalize_level` / `normalize_within` included — only if it reached a CELL**, so column % is "% of those asked", not "% of everyone"; buffered narrows each margin / denominator bucket through `ownMarginMembership` + `admitRecords` (nil cell aggregation), fused gates every margin update on `rowKeys.ok && colKeys.ok` (`TestCrosstab_OwnMarginsFollowCellAdmission`, `TestCrosstab_OwnMarginAdmissionFusedMatchesBuffered`). The two still differ on the cell field: a null cell field reached its cell (as that cell's `n_null`), so it rides the cell margin's `n_null` and is absent from every auxiliary. That is deliberate, not an inconsistency to reconcile: an auxiliary exists to be a metric-scoped base the cells beside it divide into, so it has to see the same records that carried a value, and a wider base would silently answer a different question. There is no knob. Getting it wrong is SILENT — every number still renders, correctly formatted and plausible, and only the base is wrong. **`present` is load-bearing and is NOT a zero value** — a slot that admitted no record carries `present: false` and no `value` key at all, because an aggregator over an empty set has no defined output and a fabricated `0` is indistinguishable on the wire from a real one; its `components` still carry the floor, whose `n = 0` is a true statement about the slot. All three keys are `omitempty` and additionally ride the DISPLAY flag (`margins.rows` / `.columns` / `.grand`), matching the emission rule the cell's own margin counts and components already follow, so a margin computed only as a normalize denominator stays off the wire on both arms. **Allocation and emission ask DIFFERENT questions and the gap between them is warned rather than closed**: both execution paths allocate auxiliary accumulators on `NeedsRowMargin` / `NeedsColumnMargin` / `NeedsGrandMargin` (display OR normalize), so the normalize-only shape accumulates every auxiliary and then emits not one of them. `CrosstabSpec.MarginAggregationsObserved` — the predicate behind the `PULSE_CROSSTAB_MARGIN_AGG_UNOBSERVED` predict warning — therefore reads the DISPLAY flags directly, and does NOT go through the `Needs*Margin` trio it was first written on: those answer the cell's question ("is this margin required"), and answering it here left exactly one shape (`margins` all false + `normalize=row|column|total` + a declared auxiliary) both unwarned AND paid for. An auxiliary is never a denominator, so a normalize direction is not a landing site. Allocation ALSO rides the compute plan: when `components.crosstab` or its `*_margin_aggregations` figures are not computed (a `return` exclusion or the closed DisableComponents gate) neither arm accumulates a single auxiliary — the unknown-operator refusal alone stays ungated (the Compute plan paragraph under "Opt-out and the Compose surface"). Keep the predicate and this emission gate stating the one rule; they are two sites, and drift shows up as a request that quietly does the work and returns none of it. A request declaring no auxiliary emits none of the three and is byte-identical to the pre-slot wire form (`TestCrosstab_MarginAggregationsInertAtRequestSurface`, narrowed rather than deleted at E2-S5 to assert exactly that half). `format_version` does NOT move.

## Opt-out and the Compose surface

**Opt-out.** `pulse.Options.DisableComponents bool` (engine-level default) and `types.Request.DisableComponents *bool` (per-request override, `nil` inherits engine). When the effective decision is "disabled", `Response.Components` stays `nil` and the wire form is byte-identical to the pre-Components baseline — `format_version` is NOT bumped. The gate sits at each execution path's emission block, so the MetaAggregator.Components / MetaGrouper.Components construction work is skipped, not built then discarded. CLI surface: `--no-components` on `pulse api process` / `process-chain` / `compose`. ProcessStream's `.Components()` returns `nil` when disabled. Compose: each `ComposedRequest.Requests[i]` carries its own per-request override; engine flag applies across the batch. MCP tools do not surface the knob (matches `DisableDefaults` / `EchoRequest` precedent). **`return` interplay (U17):** an engine `DisableComponents` sticks — a request `return` block NEVER re-opens the compute gate; only the request's own explicit `disable_components: false` does (the pre-U17 rule); whenever the gate is closed and some `return` layer exists, the effective selection also excludes `components`. With no `return` on any layer the opt-out is the compute gate alone — byte-identical, no `returned` marker. Rule: `descx.EffectiveDisableComponents` / `EffectiveReturn`; contract in `update-demand.md` (the `Request.Return` row).

**Compute plan (U18).** The single opt-out bool is superseded by `processing.ComputePlan` — per-sub-part flags `Aggs` (`components.aggregations`), `Groups` (`…[*].groups`, implies `Aggs`), `Groupers`, `Filterers`, `Run`, `Crosstab`, `AuxMargins` (the `*_margin_aggregations` figures), `Matrices`, plus whole-slot `MatricesSlot` (with its finalize-only sub-parts `MatrixAuxiliary` / `MatrixScalars` / `MatrixVectors`) and `Overlays` / `Tests` / `PostTests` (per entry, below) / `Regressions` (whole slot, below). `Service.process` resolves it ONCE before dispatch (`Service.resolveComputePlan`): `processing.ComputePlanFor(plan)` computes a part iff the `return` plan's `Visit` keeps it or something below it; the VETO is precise: a kept request overlay whose kind reads its host's components (`descx.OverlayReadsHostComponents(kind, basis)` — the `OVERLAY_PAIRWISE_*` family always; a `weighting.ScalesByHostFloor` kind or `OVERLAY_FISHER_EXACT_CELL` only when the crosstab cell is WEIGHTED, frequency or probability, by `descx.CrosstabCellWeightBasis` — request, slot or `Options.DefaultWeight`, resolved as `StampWeightsWith` stamps it — since over an unweighted cell they read the MatrixPayload alone, while a weighted one stamps the floor's `sum_weights` (+ `n_eff`) into their summary Parameters; the host basis itself rides the stamped cell weight (`CrosstabHostView.withCellWeight`), so a skip never hides a weighted host from Fisher's `PULSE_WEIGHT_UNSUPPORTED`; the refusal half is predict's `validateOverlayHiddenFloor`) keeps `components.crosstab` only — the one sub-part any overlay reads; its `*_margin_aggregations` figures still follow the selection, decided on the fused arm by `FusedCrosstabState.setCompute` alone — and a Compose slot a Compose overlay names (reference or target) keeps what `Service.composeSlotVetoes` resolves for it, set per slot by `Service.compose` / `composeParallel` through `composeSlotContext` — weight-basis aware per slot (#221, the per-kind audit table on `composeOverlaySlotVeto`): the floor kinds `OVERLAY_PROP_Z_CELL`, `OVERLAY_PROP_Z_PANEL` and `OVERLAY_CHISQ_VS_REF` (targets only — its reference is a distribution) keep `components.crosstab` alone when that slot's crosstab cell is WEIGHTED (`descx.CrosstabCellWeightBasis`, the basis the hidden-floor refusal reads) and nothing over an unweighted one (their floors read nothing there, and the host basis is read off the floor keys); `OVERLAY_PROP_Z_PANEL` under `n_source` `cell_n_unweighted` / `row_margin_distinct_within` keeps `components.crosstab` whatever the weight; every other kind — the mean kinds reading Welford triples (`OVERLAY_T_CELL` / `_Z_CELL` cells, `OVERLAY_T_VS_REF` / `_Z_VS_REF` aggregation groups), `OVERLAY_FORMULA`, and the payload kinds whose series arm reads an `AGG_WELFORD` leg — keeps every sub-part (the Compose host classifies a slot by its Components block); the strongest veto over the overlays naming a slot wins. A wrong rule for a floor kind still trips the `PROCESSING_INTERNAL` fold backstop (`composeOverlayFloorsPresent`; `TestComposeOverlayFloorsPresent_CatchesMisvetoedFloorKind`); gates `TestComposeSlotVetoes_WeightBasis`, root `TestReturnComposeVetoWeightAware`. An unnamed slot skips what its selection drops. A chain overlay reads its stages' data and crosstab payload only, so it vetoes nothing; every later chain stage runs under its OWN plan (`processChain` resolves each stage's `return` and puts `resolveComputePlan` on the `runChainStage` context); a stage's `data` has no skip. The closed DisableComponents gate then drops every sub-part, veto or not. The facade still prunes a vetoed-but-excluded part at serialization (`TestReturnKeptNumberInvariant`: full vs shaped, kept paths byte-identical; `TestReturnSkipsComputation_Compose` / `_Chain` / `_CrosstabOverlayVeto`; the basis rule: `TestReturnSkipsComponents_UnweightedFloorOverlays`, `TestReturnKeepsComponents_WeightedFloorOverlays`, `TestReturnSkipsComponents_FisherProbabilityHostStillRefuses`, `TestOverlayReadsHostComponents`, `TestCrosstabCellWeightBasis`). The plan rides the dispatch context to every seam — `newProcessor` (`Processor.SetComputePlan`; serial streaming / two-pass / buffered, join, crosstab buffered and fused via `FusedCrosstabState.compute`, chain stages), `reduceParallelBuffered` and the shard reducer (`finalizeMergedPartial(…, compute, …)`, the per-bucket floors via `processing.NewGroupFloors`), and `GroupedTail.Compute`; a caller that bypassed `process` with no plan on its context gets the request's vetoes and the gate over a full selection. Arm choice (merge gate, `canStream`, crosstab fusion) reads the ORIGINAL request, so a selection never moves a request onto another arm. A skipped sub-part is never built, so it is absent from the Go response too; a kept one is byte-identical to the `return`-absent run's (the buffered ungrouped `Run.NullRecords` recounts the first slot's `FieldPresent` floor when `Aggs` is skipped). Build points bump the process-wide `processing.WorkStats()` counters (once per slot / bucket / block, never per record), which `TestReturnSkipsComputation` reads as deltas across serial, parallel-decode and shard arms. **Crosstab:** `Crosstab` off builds no `buildCellComponentMap` (cells, row / column / grand margins — `CrosstabCellComponentMaps`) on the buffered, fused and join arms, which also closes the pre-U18 leak where a closed DisableComponents gate still built them; `AuxMargins` off evaluates no auxiliary figure (buffered `computeAuxMargins` returns nil; fused `FusedCrosstabState.setCompute` forgets the auxiliaries before `Update`, so nothing accumulates per record — `AuxMarginAccumulators`). The auxiliaries' REGISTRY resolution stays ahead of both gates, so an unknown type is refused whatever the plan (`TestReturnSkipsComputation_Crosstab`, `TestReturnSkipsComputation_CrosstabUnknownAuxStillRefused`). **Matrices:** the slot follows the selection with NO veto (refused under joins and crosstab, outside the multiplicity pool, read by no Compose / chain overlay). A run ACCUMULATES `Request.Matrices` iff it computes `MatricesSlot` or `Matrices` (`ComputePlan.AccumulatesMatrices`, checked in `resolveMatrixPlans`, so `buildMatrixSlots` / `BuildMatrixSlots` / `BuildGroupedMatrices` mint no slot and no record is folded — `MatrixAccumulators`); each slot carries the plan, and `matrixSlot.result` renders the `MatrixResult` only under `MatricesSlot` (`MatrixResultBuilds`; `components.matrices` alone folds but renders none), `auxiliary.n` / `scalars.determinant` / `vectors.top_pairs` only under their own flag (`MatrixAuxiliaryBuilds` / `MatrixScalarBuilds` / `MatrixVectorBuilds`) — `standard` drops `auxiliary` except a spec's requested inference keys (built per spec, `ComputePlan.ForMatrix`; `matrix-and-vectors.md` Inference bullet), `minimal` drops it and also `scalars` and `vectors`. The parallel-decode and shard partials build under the same plan (`shardPartial.buildMatrices(…, compute)`). The `Request.Vectors` unreferenced warnings are request-derived and always raised (`TestReturnSkipsComputation_Matrices`). **Overlays (E3-S1):** the slot follows the selection PER LAYER — `ComputePlan.WithOverlayLayers(keep)` / `ComputesOverlay(i)` (the mask rides by pointer, so the plan stays comparable; none marked = slot off, all marked = no mask). An excluded slot still folds every layer a resolved multiplicity family claims (`multiplicityVetoes` over `MultiplicityPlan.Overlays[i].Member` — the request's plan, or a Compose slot's share of its batch's, carried by `composeSlotContext`), so `m` and every kept `p_adjusted` are the full run's; nothing else reads a request layer (Compose / chain overlays read data, crosstab payload and Components). A skipped layer runs no handler and raises no refusal or warning — the slab-partition gate and the `PULSE_OVERLAY_COMPONENTS_REQUIRED` / weight refusals included (FR-25: predict stays the validator) — and stops vetoing `components.crosstab`; when another layer is computed its position holds a zero `OverlayLayer` (the fold aligns by index; the wire prunes the excluded slot). `payload` + `summary` are one compute unit, never split. The Compose-host overlays follow the Compose-level `return` WHOLE (`composeOverlaysComputed`: kept, or any `compose`-plan overlay a member — a spec may emit several layers, so no per-spec mask); skipped, they fold nothing and `composeSlotVetoes` vetoes no slot. Chain overlays have no `return`. Arm choice (`canStream`'s overlay coupling, fusion) still reads the original request. Counter `OverlayLayerRuns` (one per spec through a request-host or Compose-host loop): `TestReturnSkipsComputation_Overlays`, `TestReturnSkipsOverlays_{SeriesArmUnchanged,MultiplicityVeto,ErrorRule,Compose}`, `TestReturnKeptNumberInvariant`. **Tests, post-tests, regressions (E3-S2):** `tests` / `post_tests` follow the selection PER ENTRY with the overlay rules — `ComputePlan.WithTestEntries` / `WithPostTestEntries` + `ComputesTest(i)` / `ComputesPostTest(i)` (shared `narrowSlot` mask), the multiplicity veto over `MultiplicityPlan.Tests` / `.PostTests` (request plan or Compose slot share) — gated inside `buildRowTests` / `buildPostTests`; a skipped position holds nil when another entry is computed (`realignTestResults`, so the fold's index alignment holds). `regressions` follow the selection WHOLE with no veto (outside the multiplicity pool, read by no Compose / chain overlay): `BuildStreamingWith` / `FitBufferedWith` are not called. A skipped entry or fit raises nothing — `PULSE_TEST_*`, `PROCESSING_REGRESSION_*` fit refusals, `PULSE_WEIGHT_LOW_NEFF` included (FR-25). The merge gate (`mergegate`), `canStream` and the chain mergeability refusal (`PULSE_CHAIN_NOT_MERGEABLE`) still read the ORIGINAL request, so excluding a test never moves a request onto the parallel / shard arm or admits it to a chain. Counters `RowTestFolds` / `PostTestRuns` / `RegressionFits`: `TestReturnSkipsComputation_TestsAndRegressions`, `TestReturnSkipsTests_{MultiplicityVeto,ErrorRule,MergeGateArmUnchanged}`, `TestResolveComputePlan_TestEntries`, `TestComputePlan_TestEntries`.

**Compose surface (v1.1).** `ComposedResponse.Responses[i].Components` carries the per-slot block exactly as it does for a buffered `Process` call — the Compose-overlay fold treats per-slot Components as read-only. Diagnostics from the Compose-host overlay fold (cohesion failures, missing host coordinates, panel-target overflow) ride a sibling per-layer slot `ComposedResponse.Overlays[i].Warnings []OverlayWarning`; the slot is `omitempty` so overlay-free Compose responses stay byte-identical to the v1.0 wire shape (`TestComposedResponse_OverlayFreeByteIdentical`). The same per-layer `Warnings` slot is shared with the CHAIN-host barrier. See `skills/overlay-system.md` (Per-layer warnings). Each slot's `return` (and its components compute gate, `EffectiveDisableComponents`) applies per slot exactly as in `Process`; the fold always reads the slot's components BEFORE any pruning, so excluding `components` through a slot's `return` alone never starves a Compose-host overlay. The DisableComponents gate does: a kind that reads a slot's components is refused rather than folded empty — the pairwise and floor-scaling kinds (`PULSE_OVERLAY_COMPONENTS_REQUIRED`, the hidden-floor `PROCESSING_CONFIG`, `weighting.md`), and `OVERLAY_T_VS_REF` / `OVERLAY_Z_VS_REF` scoring a grouped `AGG_WELFORD` slot, whose per-group `mean` / `variance` / `n` they read (`PULSE_OVERLAY_COMPONENTS_REQUIRED`, reason `components_disabled`, predict and runtime alike; U46 E4-S13).

**Compose envelope (relocated from CLAUDE.md "Output Format Contract" at U18 E1-S1).** Since the v1.1 lift (`format_version` bumped from `"1.0"` for it), `pulse api compose --json` puts a `ComposedResponse` OBJECT in `data` — not the legacy `[]*Response` array — carrying `responses` (one `Response` per `ComposedRequest.Requests` slot, in input order) and `overlays` (one `OverlayLayer` per `ComposedRequest.Overlays` spec, omitted when there are none). Each slot's `return` shapes `responses[i]`; `ComposedRequest.Return` (`overlays…` paths only) shapes the layers AFTER the fold and stamps `returned`. Streaming (`--stream`) bypasses the envelope entirely and emits per-row `{"index", "row"}` NDJSON, so Compose overlays surface only at terminal flush in non-streaming mode (`skills/streaming-and-watching.md` (Compose streaming vs. overlays)). Change rows: `update-demand.md` (the `ComposedResponse` row and the `Request.Return` row's Compose / Chain clause).

**Slot label echo (U44 E3-S2).** Each `responses[i]` carries `label` (`types.Response.Label`, `omitempty`): the slot's FINAL label — caller-supplied or the synthesized `request_<i+1>` — stamped by `service.echoSlotLabel` after the slot's `Process` on both orchestrators, so sweep slots carry their expanded label. It is an ordinary `return` path, kept by the `standard` and `minimal` presets; an explicit `include` without it prunes it (in place, like any part). A standalone `Process` never sets it, so its wire is unchanged.

**Sweep (U40).** `ComposedRequest.Sweep` adds no response slot: it expands (`internal/sweep.Expand`) into ordinary slots appended after the explicit `Requests`, so `responses[i]` indexes explicit slots first, then sweep slots in expansion order (grid: first axis slowest). The effective request runs, predicts and echoes: `--echo-request` / `Options.EchoRequest` fills `ComposedResponse.NormalizedRequest` (`json:"-"`) with the expanded slots the service ran, and the CLI writes it. MCP `pulse_compose` fills the `standard` `return` default into a sweep body that sets none (authored `return` never overwritten; library default unchanged). Sweep-free requests are byte-identical on the wire and under `Hash()`. `sweep.rank` adds the one new slot, `ComposedResponse.Ranking` (`[]RankEntry{label, value, rank}`, `omitempty`): sweep slots only, pinned outside the Compose `return` (always emitted, never rounded); `--stream` ends with one `{"ranking":[...]}` line. Prose: `skills/compose-sweeps.md`.

**Fits (U42; vector fits U30 E2-S2).** `ComposedRequest.Fits` adds the response slot `ComposedResponse.Fits` — a `map[string]*FitResult` keyed by fit name (JSON keys sort, so the wire order is by name), one entry per fit: a regression fit's result exactly as that fit request run alone would put in `Response.Regressions[0]` (the embedded `*RegressionResult`; `FitResult.MarshalJSON` writes it as the bare `RegressionResult` object, byte-identical to the regression-only shape), or a vector fit's `{"vector": VectorFitResult}` (`operator, labels, members, basis, n, n_weight_invalid, sum_weights, n_star, mean, covariance` — covariance M2*/(N* − 1) on the fit's basis, `processing.VectorFitResult`; undefined cells `null`). The `vector` key discriminates (payload schema: the `FitResult` `oneOf`). It is `omitempty` (a fit-free batch is byte-identical) and, like `ranking`, PINNED outside the Compose-level `return` (`types/return_shape.go` `fitsKey`, both the prune pass and the planned encoder): always emitted, never rounded by `precision`, because a slot that scores against the fit reads those figures. Serial and parallel Compose marshal it byte-identically. `--stream` writes no fits record. Hidden with `capability:compose_fits` on both the request and the response struct (`gatedSlots`). The pre-pass wiring: `.claude/reference/execution-modes.md` (Compose fits). **Batch warnings.** `ComposedResponse.Warnings` (`warnings`, `[]*ResponseWarning`, `omitempty`) carries the diagnostics no slot owns — today a fit save's `PULSE_MODEL_OVERWRITTEN` (`details.fit`, entry order, serial = parallel). It needs no pin: every `warnings` slot is a KEEP path (`returnWarningPaths`, retained unless excluded), and a Compose-level `return` may name only `overlays…` paths, so it is always emitted. Ungated. The model file: `.claude/reference/byte-layout.md` (Model file).
