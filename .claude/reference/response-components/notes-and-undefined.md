## Implementation notes displaced from the skill pack

Contributor-facing detail; the LLM-facing prose is `skills/response-components.md`.

- **Floor ownership.** The orchestrator fills the universal floor, never the operator's `Components()`; it is filled even when `ComponentSchema.Keys` is empty (`AGG_COUNT` is floor-only). The floor is tallied through `processing.FieldPresent`, never `Record.NumericValue` — a set column has no numeric value, and asking the value question would move a whole set column into `n_null`.
- **Weighted floor.** A slot with an APPLIED row weight adds `sum_weights` (Σw over value-present rows with a valid weight), `n_eff` (Kish (Σw)²/Σw², `kind: probability` only) and `n_weight_invalid` (value-present rows excluded for an invalid weight), tallied by the orchestrator (`processing.WeightFloor`) on the same rows as `{n, n_null}`. Absent ⇒ unweighted; `n` / `n_null` keep value-presence meaning. Declared as `optional: true` keys on weight-aware aggregators only (`internal/descriptor/capabilities_weight.go`). The crosstab's cell, margin and auxiliary component maps carry them too, over the same records as that map's floor (an auxiliary over its ADMITTED records: a record reaches an auxiliary margin only if it reached a CELL) and keyed off that slot's OWN resolved weight, so a `weight: null` auxiliary carries none; an operator's own same-named key wins. Counts stay raw ints. Contract: `.claude/reference/weighting.md` (Floor keys).
- **Opt-out gate sites.** One gate per Components sub-part (the `ComputePlan` flag) at each execution path's emission block; the parallel and shard reducers gate through the plan passed to `finalizeMergedPartial`. Find every site with `grep -rln 'compute\.\(Aggs\|Crosstab\|Groupers\)' internal/processing internal/service`.
- **Parallel arms.** No per-operator components merge exists: the arms fold OPERATOR STATE (`MergeOnline`, `MergeableGrouper`, an extension's `MergeState`), so each merged slot's `Components()` is the serial one's; `processing.CanMergeRequest` refuses anything whose state cannot fold. Grouped parallel runs share the serial tail (`processing.FinalizeGroupedStream`), so row order, `Sort`, overlays and `Groupers` cannot drift by worker count. Long form: `execution-modes.md`.
- **`Run.null_records`.** One figure on every arm. Ungrouped with an aggregation: the FIRST slot's floor `n_null` (a vector aggregator's row is null when every member is), whether or not `components.aggregations` is computed. Grouped, or no aggregation: the null count of the primary field — the first aggregation that names a `Field`, else the first grouper's (`primaryNullFieldName`). Gate: `TestRunNullRecords_ArmParity`.
- **Buffered auxiliary admission.** `admitted = resolved on the OTHER axis AND cell field non-null`, computed from the two axis partitions ONCE and deliberately NOT from the `(rkey, ckey)` cell buckets — those count a record once per (row, column) pair, which would multiply a row auxiliary by the fan factor under a fan-out (`GROUP_SET_PER_ELEMENT`) axis. The fused arm folds each admitted record during the walk.
- **Paired-input floor.** `AGG_MAPE` / `AGG_RMSE` / `AGG_MAE` read two columns but the floor keys on `field` alone, like every aggregator — the floor is shared engine machinery, never re-keyed per operator. The prediction side's nulls ride `n_null_prediction`; contributing rows are `n_scored`; MAPE's zero-actual skips `n_zero_actual`. State is additive, so the class is `Mergeable`. `AGG_AUC` follows the same rule (`field` is the score; `n_null_outcome`, `n_pos` / `n_neg`) and is `None`.
- **Manifest duplication.** Each `ComponentSchema` appears twice by design — in the per-operator manifest entry and in top-level `components_schemas` — declared in `internal/descriptor/capabilities_*.go`.
- **Reading the schema.** A key's `type` is one of `"int"`, `"float64"`, `"WelfordTriple"`, `"map[string]int"`, …. Read a mergeability class off the manifest; never infer it from the operator's name.
- **Examples and benchmarks.** `grep -rl welford-triple internal/examples/`; baselines in `docs/src/ops/performance.md` (Components emission baselines).

## Undefined figures on the wire

**One rule for every JSON payload: a non-finite float (NaN, +Inf, -Inf) is written as JSON `null` IN PLACE — the key keeps its presence — and the rest of the response serialises normally.** Without it `encoding/json` refuses the whole value, so no valid output exists for a response carrying one undefined figure.

- **Go keeps NaN.** Library results carry NaN for undefined figures (ratios over zero denominators, CIs under two rows, overlays with a zero or missing reference, undefined test / regression statistics, a stored NaN cohort value echoed back, …); an embedder detects them with `math.IsNaN`. Find producers with `grep -rn 'math.NaN' internal/processing`. Every one reaches JSON only through the serialisation boundary below, which is why the fix is structural, not per producer.
- **A figure over no value is undefined, never 0.** Every built-in aggregator whose figure has no value over an empty input (empty non-null bucket, or Σw = 0 under a weight) answers NaN — averages, min / max / range, spreads, quantiles, mode, shape moments, z-score, the model-error trio, vector element figures. A count or a sum of nothing stays `0` (`AGG_COUNT`, `AGG_SUM`, `AGG_DISTINCT_COUNT`, …). Operator-map keys that MIRROR the scalar follow it; the empty sums (`sum`, `m2`, …) stay `0`. Buffered, streaming, merged and the `decimal128` dispatch agree (never a `"0"` string). Downstream readers take NaN as undefined: a window / sort reads null, a series overlay host a missing point (`.claude/reference/execution-modes/overlays.md`), a chain stage a null cell, a post-test runs with a `null` statistic and drops no row (`skills/statistical-testing.md`). Gate: `TestUndefinedFigures_NoValueIsNull` (every arm × weighted).
- **A 0/0 figure is undefined too.** NaN where the formula is 0/0 on the data it has, on every arm, weighted and not: skewness / kurtosis over one value or zero spread; z-score over zero spread; `ATTR_ZSCORE` / `ATTR_TSCORE` rows over a zero population sd and `ATTR_NORMALIZED` over `max = min`; a SAMPLE variance below its support (Welford at n < 2, weighted at Σw ≤ 1). A POPULATION spread of one value or a constant is a defined `0`. Readers: the pairwise / t / z overlays skip a leg whose variance is undefined. Gates: `TestUndefinedFigures_*` (`internal/service`).
- **Null, not omission.** `null` means "reported, undefined at this coordinate"; an absent `omitempty` key means "not reported for this kind". They never collapse: a NaN in an `omitempty` slot is `"statistic": null`, a NaN `MatrixCell.Value` is `{"value": null, "present": true}`.
- **Structural, at the serialisation boundary.** `types.MarshalFinite` is the single implementation — byte-identical to `json.Marshal` when the value holds no non-finite float (only a subtree holding one takes the slow walk, which keeps encoding/json's field order, tags, embedding and marshaller rules). It is wired at `descriptor.Envelope.MarshalJSON`, the CLI's JSON writer and `--stream` rows, `mcp/gosdk`'s result writer, and a `MarshalJSON` method on every public result type that carries a float (find them with `grep -rn 'MarshalFinite' types/`), so an embedder's own `json.Marshal` of a result follows the rule. A new result type carrying a float needs that method (`TestMarshalFinite_PublicResultTypes`).
- **Reading it back.** Plain `encoding/json` decodes `null` into a Go float as `0` — a confident 0 where the engine said undefined. `internal/jsonfinite.Unmarshal` is the inverse: `null` in a non-pointer float slot is NaN; pointer and `any` slots stay nil; input with no `null` decodes as `json.Unmarshal`. Every surface that decodes a RESULT a caller hands back uses it (`pulse explain --response`, MCP `pulse_explain`); requests stay on plain `encoding/json`.
- **`format_version` stays `"1.1"`.** Only outputs that previously failed to serialise change. The payload schema widens float slots on result-only defs to `["number", "null"]` (additive); request floats stay `number` (`internal/descriptor/schema.go` `resultOnlyStructs`; `docs/src/contract/payload-schema.md`, "Undefined figures"). Gates: `TestNonFiniteFiguresMarshalAsNull`, `TestPayloadSchema_UndefinedFiguresValidate`.

**Under `Return.precision`.** Float64 component figures (operator maps, `sum_weights`, `n_eff`) are written at the requested significant digits; floor counts and every operator key declared `int` are Go ints and never rounded. An auxiliary margin figure from a COUNT aggregation (`countSemanticAggregations` in `internal/descriptor/return_precision.go`, or an extension declaring `CountSemantic`) is written exact. Contract: `docs/src/contract/payload-schema.md` (Return slot).

## Run-time warnings in the envelope and the stream

**Promotion.** Every run-time warning a result carries — `Response.Warnings`, each Compose slot's and chain stage's, `ComposedResponse.Warnings`, `FacetResult.Warnings` (a regression result's own `warnings` lift into `Response.Warnings` first) — is ALSO written to the `--json` envelope's top-level `warnings` (`internal/cli/json.go` `runtimeWarnings`). `data` keeps its copy unchanged. A Compose slot's entry gains `details.request` (slot index), a chain stage's `details.stage`, unless already present. Overlay-layer warnings stay on their layer. A warning-free result's envelope is byte-identical. `--strict` is `Options.Strict`: the warnings it covers (leakage, vector metric, weighting) refuse the run before any record is read, and a failed slot refuses it after the scan with the slot's own code (envelope `errors`, exit 1). MCP results have no envelope split.

**Streams.** `ProcessStream`'s iterators expose an optional `Warnings()` (read once exhausted), shaped by the same `return`; `ProcessStreamResult` sets `StreamTerminator.Warnings` on completion. `pulse api process --stream` ends with one `{"warnings":[...]}` record when the run warned; `api compose --stream` writes one after the rows and before a ranked sweep's ranking line. `PULSE_RETURN_PATH_UNMATCHED` is raised by the buffered shaping pass, so a stream does not report it (predict's `return.unresolved_includes` lists the candidates).

## Per-slot failures

**One bad slot does not discard the response.** A regression, test (tier-1 or post) or matrix slot whose DATA its operator refuses — a data-dependent refusal the request could not foresee from the schema — fails alone; every other slot survives. The closed per-kind code sets are in `internal/slotfail` (`RegressionCodes`, `TestCodes`, `MatrixCodes`); a new data-dependent refusal code joins its set explicitly. Corrupt record data (`ENCODING_INVALID`, `details.reason` `categorical_index_out_of_range` / `set_member_out_of_range`, `slotfail.CorruptRecordData`) is admitted to every kind. Every other error — configuration fault, uncoded error, invariant violation, any other `ENCODING_INVALID` — stays FATAL.

- **Wire shape.** The failed result keeps its object — never `nil`, which means "skipped by `return`" — with its identity and `error`, a `types.SlotError` `{code, message, details}`. Every numeric field is ABSENT (`RegressionResult` `{name, type, error}`, `TestResult` `{label, type, group_key, error}`, `MatrixResult` `{name, type, group_key, group_header, error}`). In Go a failed test keeps NaN statistics. A response without a failure is byte-identical. The payload schema requires the figures only when `error` is absent (`hasSlotError`).
- **Warning.** The service lifts each failed slot once, after every arm returns (`slotfail.Apply` in `Service.process`, so every arm agrees): one `PULSE_SLOT_FAILED` per slot, details `{slot_kind, index, label, code}` (+ `group_key` for one bucket of a grouped matrix) — `slot_kind` the Response key, `index` the REQUEST slot index. It promotes to the envelope like any warning; exit 0. Each slot error passes the instance's refusal scoping first, so a feature-profiled instance names no hidden operator.
- **Strict.** Under `Options.Strict` the run fails with the FIRST failed slot's own code (order: tests, post-tests, regressions, matrices), its details plus `{slot_kind, index, label}`.
- **Paths.** The engine converts at each finalize site (row tests, post-tests, regression fits, every matrix slot). A failed matrix emits no `Components.Matrices` entry. A GROUPED tier-1 test or partitioned post-test keeps its finer rule: one sparse group gets a null-statistics result plus a per-group warning under the test's own code.
- **Consumers.** The multiplicity fold skips a failed slot; a regression `save` whose fit failed writes no model file. A failed slot's `error` is a `return` keep path: no preset or include list shapes it away; an explicit exclude does.
- **Compose fits.** A `fits` entry whose fit request's slot failed on its data fails ALONE: `ComposedResponse.Fits[name]` keeps `{name, type, error}` (regression) or `{"vector": {operator, error}}`; its `PULSE_SLOT_FAILED` lifts to `ComposedResponse.Warnings` with `details.fit`; no `save` file is written. The name binds as a FAILED fit (`model.Set.AddFailed`), so references pass the same static checks as in predict. Under Strict the batch fails with the fit's code before any slot runs (lowest fit index, serial and parallel). **PredictCompose is unchanged**: a data fault is not foreseeable from the schema.
- **Readers of a failed fit.** Every reader checks `model.Set.FailedOfKind` at BIND, before any row, and fails alone: an ATTRIBUTE (`ATTR_REG_PREDICT`, an `ATTR_FORMULA` with a literal `coef()` call, a fitted vector attribute, a `{population}` reference) has no value on any row — all-null column plus one `PULSE_FIT_UNAVAILABLE` `{fit, attribute, code}` warning per failed fit; a `MAT_*` slot's `params.fit` fails THAT SLOT alone. Two readers stay FATAL with the fit's own code plus `details.fit` (`model.FailedFitRefusal`): a `FILTER_EXPRESSION` naming the fit in a literal `coef()`, refused at build — a filter's verdict cannot be null, and dropping or keeping every row would be a silently wrong population; and a `coef()` whose fit name is not a literal, which only a row's evaluation resolves.
- **Gates.** `internal/slotfail` (whole package); `TestSlotFailure_*` in `internal/processing` and `internal/integration`.
