# Guided analysis — Data model, Intent taxonomy, Recommend

Per-topic slice of the guided-analysis reference (Data model, Intent taxonomy, Recommend). Index (preamble + section map): `.claude/reference/guided-analysis.md` — load it first, then only the slice(s) your change touches.

## Data model

Public types live in `descriptor/guidance.go`; the registries and built-in declarations live in `internal/descriptor/` beside `capabilities_*.go` (and so inherit the no-execute import ban, `TestPredictNoExecutionImports`).

| Type | Fields | Notes |
|---|---|---|
| `Intent` | `ID`, `Label`, `Analytic`, `Sounds []string`, `Shapes []Shape` | one taxonomy entry |
| `Shape` | `Roles []Role` | one alternative data shape an intent applies to |
| `Role` | `Name`, `Kinds []FieldKind`, `Min`, `Max` | `Min 0` = optional; `Max` = `RoleUnbounded` (-1) for no ceiling |
| `FieldKind` | `numeric` / `categorical` / `date` / `bool` / `set` | every field type maps to exactly one (`FieldKindOf`, total over the registered types) |
| `Purpose` | `Plain`, `Intents`, `Questions`, `KnownAs []string`, `UseCases map[Domain]string`, `NotFor []Alternative`, `FollowUps []Alternative`, `Assumptions`, `Level`, `Glossary []string` | per operator; `FollowUps` and `KnownAs` optional |
| `Alternative` | `When`, `Use` | `Use` = bare registered operator or `<kind>:<name>` feature spelling; shared by `NotFor` (use instead) and `FollowUps` (run next) |
| `Domain` | `survey` / `ops` / `science` / `harness` | closed |
| `Level` | `basic` / `intermediate` / `advanced` | closed |
| `Interpretation` | `Field`, `Means`, `Bands []Band`, `Abs`, `Convention`, `Sign map[string]string`, `Caveats`, `Shared` | per output field |
| `Band` | `Min *float64`, `Max *float64`, `Label` | half-open `[Min, Max)`; nil = open end |
| `Term` | `ID`, `Short`, `WhyCare`, `SeeAlso`, `Jargon`, `Forms` | one glossary entry |

**Purpose limits** (`internal/descriptor/purpose_validate.go`): `Plain` non-empty and ≤ `PurposePlainMax` (140) characters; ≥1 intent; ≥ `PurposeQuestionsMin` (2) non-empty `Questions`; ≥1 `NotFor`; ≥1 `UseCases` entry keyed by a known `Domain` with a non-empty value; `Level` one of the three. `FollowUps` is optional (no coverage gate forces it), but each entry is held to the `NotFor` entry rules through the same resolver. Each broken rule is a `PurposeRule` (`plain`, `intents`, `questions`, `not_for`, `use_cases`, `level`, `alternative`, `follow_up`, `intent_unknown`, `glossary_unknown`, `jargon_unlinked`, `known_as`).

**Follow-ups** (U22). `Purpose.FollowUps` names the natural next step once an operator has run, built into the ontology as a `follow_up` edge (operator → operator or capability; `internal/descriptor/ontology.go` `addPurposeEdges`) and pruned with its target like every edge into a hidden node (`TestOntologyPrune_FollowUps`). The curated set is small and deliberate: `TEST_ANOVA_F` / `TEST_ANOVA_WELCH` → `TEST_TUKEY_HSD` and `OVERLAY_PAIRWISE_WELCH_T`; `TEST_KRUSKAL_WALLIS` → `TEST_MANN_WHITNEY_U`; `TEST_CHISQ` → `OVERLAY_FISHER_EXACT_CELL` and `OVERLAY_CHISQ_ROW`; `OVERLAY_CHISQ_MATRIX` → `OVERLAY_STD_RESIDUAL` (U28: the adjusted residuals show which cells drive it), `OVERLAY_FISHER_EXACT_CELL` (small counts) and `OVERLAY_CHISQ_ROW`; `OVERLAY_STD_RESIDUAL` → `OVERLAY_CORRESPONDENCE` (the whole-table map) and back (U28 E1-S3: a stand-out point → the cells behind it); `TEST_PEARSON_R` / `TEST_SPEARMAN_R` / `TEST_KENDALL_TAU` → `REG_OLS`; `TEST_SHAPIRO_WILK` → the rank-based `TEST_MANN_WHITNEY_U` / `TEST_KRUSKAL_WALLIS`; `TEST_BROWN_FORSYTHE` → `TEST_ANOVA_WELCH`. `MAT_CORRELATION` carries none until U24. Follow-up prose is pulled like the rest (`GuidanceProse` sweeps it by reflection) and never reaches the manifest; docgen renders it as a "Follow up with" list in the operator's detail block, dropping a hidden target.

**Aliases (`Purpose.KnownAs`, U23).** The other names analysts already know an operator by — SPSS, R or textbook spellings (`anova`, `aov`, `chi square`, `chisq.test`, `pearson`, `lm`, `levene's test`). Optional, and backfilled ONLY where a real alias exists (statistical tests, regressions, the two matrices and a handful of descriptive / window / feature operators); never a paraphrase of `Plain`. Compared in the folded form `FoldAlias` (lower-case, whitespace collapsed, punctuation kept — `chi-square` ≠ `chi square`). Rule `known_as` (`internal/descriptor/known_as.go`, inside `ValidatePurpose`): each alias non-empty, ≤ `KnownAsMax` (48) characters, listed once, and not equal to any intent's `Sounds`. Across operators each alias is unique: `KnownAsCollisions` over the built-ins (gate below) and, at `pulse.New`, `extensionKnownAsCollisions` against every built-in alias (the full registry, profile-blind) and every earlier extension → `PULSE_EXTENSION_PURPOSE_INVALID` rule `known_as`. Aliases are identifiers, not prose (`proseIdentifierFields`), and never enter the manifest. **Instance view:** `InstanceSnapshot.KnownAs()` — folded alias → operator over built-in plus extension Purposes, keeping only operators whose node survives the instance ontology, so a hidden operator's aliases act never-declared. Consumer: example search's synonym tier (U23 E2-S2); skill ranking by intent reads `Level`, not aliases (Skills for an intent, below). Docgen renders them as an "Also known as" line in the operator's detail block.

**Glossary limits** (`internal/descriptor/glossary.go`): unique kebab-case IDs; `Short` ≤200 runes and `WhyCare` ≤300; every `SeeAlso` resolves; every `Jargon` term has ≥1 `Form`; no `Form` claimed by two terms. The set started as a ~60-term starter; `TestGlossary_Size` holds it to a loose 55..150 (`glossaryMinTerms` / `glossaryMaxTerms`, never an exact count) so backfills can add the terms their prose links. It includes a term for every emitted effect-size key (`TestGlossary_EffectSizeKeysHaveTerms`, key in kebab case — `cramers_v` → `cramers-v`). `TestGlossary_OrphanReport` is binding: every term is linked by some built-in Purpose or carries an owner-tagged exemption (Gates).

## Intent taxonomy

`internal/descriptor/intents.go` `intentRegistry`, in declaration order. Fifteen IDs, closed, **not a feature** — the registry (`pulse.Intents()`) never changes under a feature profile. The instance ontology prunes an intent node when ≥1 operator serves it and every server is hidden (an intent no operator serves — `lookup` — always stays; `flows` was one until U28 E2-S2, so a profile hiding its servers, `OVERLAY_MARKOV`, `OVERLAY_SYMMETRY` (U30 E7-S1) and `OVERLAY_RETENTION` (U30 E7-S2), now drops `flows`); the manifest `intents[]` lists only the surviving intent nodes (`TestManifestIntents_PrunedUnderProfile`), and the `intents` virtual skill renders from that graph (`.claude/reference/feature-profiles.md`, Discovery prune (ontology)).

- Analytic (`Analytic: true`): `describe`, `compare_groups`, `relationship`, `drivers`, `change_over_time`, `composition`, `benchmark`, `distribution_shape`, `segment`, `measure_construct`, `flows`, `data_quality`.
- Non-analytic — routes to tooling, not operators: `prepare`, `simulate`, `lookup`.

Every intent declares ≥1 `Shape` with validated kinds (`TestIntentRegistry_WellFormed`; the exact ID set is pinned by `TestIntentRegistry_ExactIDs`). Shapes' first runtime consumer is Recommend (section below).

**Manifest projection.** Top-level `intents[]` is the sorted ID strings ONLY. Each `Operator`, `TestMeta`, `RegressionMeta`, `DistributionMeta`, overlay-kind `OverlayCapability` and extension `OperatorMeta` entry carries `intents []string` (`omitempty`) — the sorted intent IDs of its Purpose. The nested `ProcessChainCapability.Overlays` list does NOT carry them. An entry without a Purpose omits the key, so guidance-free output is byte-identical. A hidden operator under a feature profile drops its intents through the existing hide path (`TestManifestIntents_EntriesAndHidePath`). `format_version` stays `"1.1"` — the slots are additive.

## Recommend (U22)

`Pulse.Recommend(ctx, descriptor.RecommendRequest{Intent, Cohort?, Fields?, Level?, Limit?})` is the first consumer of intent `Shapes`. Types live in `descriptor/recommend.go`; logic in the NO-EXECUTE `internal/guide/` (`TestGuideNoExecutionImports`). It reads the instance snapshot only: the PRUNED ontology (`OperatorsServing`, `not_for` / `follow_up` edges), the instance manifest (`BuildManifestForInstance`: categories, `Requires`, required params) and each operator's `Purpose` (built-in, else the extension registration's).

- **Unbound** (no cohort, `bound: false`, never predict-run): one draft per serving operator whose category takes a single-slot draft (tests, post-tests, regressions, matrices and the six component categories; overlays need a host and distributions serve `simulate`, so neither is drafted). A draft is wire JSON with `"<key>"` placeholders named after the wire key (`placeholders[]` lists them; `cohort` always). `TestMeta.Requires` Go names map through `requireKey` (`SplitBy` → `split_by`), a regression's params and a grouper's `interval` are top-level keys, every other required param rides `params`; filterer value slots come from a written table (`filtererShape`). `TEST_T` under `compare_groups` drafts the two-sample form (`split_by`). `why` = the scrubbed `Purpose.Plain` plus a fixed placeholder sentence (lint-clean, `TestRecommend_ProseLintAndProvenance`); `alternatives` / `follow_ups` are exactly the declared `NotFor` / `FollowUps` whose target survives the prune — never invented. The result echoes the intent's `shapes`.
- **Ranking + cap.** Keys in order: drafts using MORE hinted fields first (bound mode), then a fully bound draft before one with `needs` (a draft the caller can run as written beats one they must finish — FR-13's "ranked below fully-bound drafts"; FR-15 listed this key last, the story's acceptance criterion placed it above level, and E2-S3 took the acceptance reading), then the requested `level` (else simplest), then fewest advisories, then category (`test` → `regression` → `matrix` → `aggregator` → `window` → `attribute` → `feature` → `grouper` → `filterer` → `post_test`), then name; stable, so one operator's bindings keep schema order (`rank` / `before`, pinned key-by-key by `TestRank_KeyOrder`). Unbound drafts tie on the first two and the advisory key, so their order is unchanged. `limit` (default 10, plain request field, not `Options.Limits`) cuts the list: `truncated` + `candidates_considered` (the drafts that survived — bound: passed predict — before the cut). A negative limit or unknown level is `SERVICE_VALIDATION`.
- **No drafts.** A non-analytic intent (`prepare`, `simulate`, `lookup`) and an analytic one with no draftable operator (`flows`: its servers, `OVERLAY_MARKOV`, `OVERLAY_SYMMETRY` and `OVERLAY_RETENTION`, are overlays, never drafted) return `recommendations: []` plus `routes_to[]` (`{when, use}`, a feature spelling: import / dedup / widen, synth, lookup, crosstab; `measure_construct` drafts `MAT_RELIABILITY` since U24 E2-S2, and `MAT_PCA` since E3-S1, and routes to `MAT_RELIABILITY` only when no draft survives), each route dropped when its feature is hidden. Not an error. An unknown intent is `PULSE_RECOMMEND_INTENT_UNKNOWN` (`details.intent`, `details.valid` = every intent ID; the fixup lists them).
- **Native vector fields** (U29 E2-G1; `internal/guide/bind.go`, `vector_route_test.go`). A `vec_f32` / `vec_f64` field (`FieldKindVector`) binds only a VECTOR slot (`bslot.vector`: the member-list `fields` slot of a vector test, matrix, vector attribute, `GROUP_KMEANS` and a vector aggregator, built-in or `VectorInput` extension), WHOLE and by name — drafted as `"vector": "<field>"` in place of `fields`; every scalar slot skips it (judged in `bind`, not left to the predict probe), so `PULSE_VECTOR_FIELD_NOT_SCALAR` is never drafted. A native fits when its element type passes the slot's `accept`, its dim ≥ the slot's `min`, and its SCHEMA kind suits the operator: the item-battery operators `MAT_RELIABILITY` / `ATTR_SCALE_SCORE` take only a `scale`, `binary` or kind-less native (`batteryKinds`), and a comparison attribute over a native whose kind has a default for it (`vectors.KindDefault`) drops its `metric` need — the kind supplies it, never a poor fit (`nativeNeeds`). Each fitting native is drafted (schema order) BEFORE a member-column list, inside the same K. A native hint is valid for an intent iff a serving operator drafts a vector slot (`takesVector`); it pins that slot alone, and is refused as kind `vector` (`SERVICE_VALIDATION`) otherwise. The two-sample `TEST_HOTELLING_T2` `split_by` binds only a two-level field — a two-value categorical or a `packed_bool` (`twoLevels` over `fieldaccept.Levels`): its runtime refuses any other, which predict cannot see. Every native draft runs end to end (root `TestRecommend_NativeVectorDraftsRun`, f32 and f64, needs filled); pinned by `TestRecommendBound_NativeVectorsOnlyInVectorSlots`, `_PrefersNativeVector`, `_NativeKindSuitability`, `_VectorHint`, `_HotellingSplitTwoLevels`, `TestBind_NativeVectorSlots`.
- **Profiles.** No hidden operator or capability appears in a draft, alternative, follow-up or route (`TestRecommend_ProfileHidesOperators`, root `TestRecommend_FacadeProfiled`).
- **Surfaces** (E2-S4). CLI `pulse recommend --intent ID [--cohort C] [--field F …] [--level L] [--limit N] [--json]` (`internal/cli/recommend.go`, a thin adapter; refusals keep their own code) and MCP `pulse_recommend` (`RecommendIn`: `cohort` is a PATH string lifted onto `types.Cohort{Filename}`; an empty intent is left to the library's `PULSE_RECOMMEND_INTENT_UNKNOWN`, whose `details.valid` helps an agent more than a missing-argument error). Both bind to the hideable feature `capability:recommend` (no dependency edge): hiding it unmounts the tool, drops the manifest `recommend` command, the payload-schema roots `RecommendRequest` / `RecommendResult` and the code `PULSE_RECOMMEND_INTENT_UNKNOWN` (owned by it) — the facade itself stays callable, like every facade method (`TestRecommend_HiddenFeatureSurfaces`, `TestRegister_RecommendFollowsItsFeature`). In the payload schema a draft's `request` is an open object (`fieldOverrides`): a placeholder may sit where `Request` takes a number. Goldens: `descriptor/testdata/recommend.<intent>.<unbound|bound>.json` for every analytic intent over a seven-field fixture (`TestRecommendGolden`, `-update`).
- **Bound mode** (a cohort, `bound: true` on the result; E2-S3). The facade (`recommend.go`) checks intent / level / limit first (`guide.ValidateRequest`), then opens the cohort: a single file stays an open handle and is read for header + schema only — predict seeks to the end for the record count, never reads a record (`TestRecommend_FacadeBoundReadsNoRecord`, a read-offset spy); a shard archive is read by random access (central directory, canonical schema entry, shard headers) and an anchored shard is its one entry, as `Predict` reads them; the spans read are kept (`readCache`), so the per-draft predicts reach storage once (U35 #248, `TestArchivePredict_ReadsHeadersOnly`). `guide.RecommendBound(inst, req, Bound{Cohort, Schema, Predict})` then, per serving operator: `plan` lists the field slots (tests: `requireKey` slots with predict's own kind rules — numeric `field` / `field2`, categorical `split_by` / `rows` / `cols` / `subject_field`, `TEST_PROP_Z`'s categorical `field`, a date-preferred `order_by`; components: `field` within `accepts_types` ∩ the intent's role kinds; a manifest `field`-typed param by its `field_filter`; regression `target` + list `predictors` within `accepts_types`; matrix `fields`, numeric, ≥2) and the needs (every other required default-less param, the FIRST member of each manifest `exactly_one_of` group — its `why` adds "Or give X instead; give only one." naming the other members, `catalog.go` `requiredParams` for built-ins and the extension arm alike —, a filterer's value slot, a frame-required window's `frame` via `descx.WindowFrameRequired`, one-sample `TEST_T`'s `mu` under `benchmark`); `bind` finds up to K = `BindingsPerOperator` (3) bindings — each hint pins the first slot that takes it (a list slot takes every hint that fits), free slots take schema order, a hint never fills an unpinned slot, and with hints an operator no hint fits gets no draft; a list slot takes up to 5 free fields. **k-group tests prefer three levels** (U45 E1-G1): `TEST_ANOVA_F`, `TEST_ANOVA_WELCH`, `TEST_KRUSKAL_WALLIS`, `TEST_BROWN_FORSYTHE` and `TEST_TUKEY_HSD` (`manyGroupTests`, a written table — no registry declares a group minimum) draw `split_by` from fields with ≥3 declared levels (`threeLevels`) whenever the cohort has one (`bslot.narrow`: the other candidates are dropped unless hinted); a two-level categorical or `packed_bool` binds only by hint or when no ≥3-level field exists — a preference, never a refusal — except `TEST_TUKEY_HSD`, whose runtime refuses fewer than three groups, so its `split_by` accepts only ≥3 levels (`TestBind_ManyGroupTestsPreferThreeLevels`). Each draft is predict-run IN-PROCESS with the facade's predict options (`Pulse.predictOptions`, shared with `Predict`: instance snapshot, defaults, sidecar facts) — so suppression and profile scrubbing apply — and is dropped unless valid with no error; a draft with needs is probed WITHOUT them and survives only if every predict error names a need. Survivors carry predict's `advisories`; a draft with needs keeps its bound fields, `bound: false`, `needs[{param, why}]` (fixed `needWhy` sentences, lint-clean) and `"<param>"` placeholders. `why` = scrubbed `Plain` + "It uses NAME (TYPE[, N groups])…" + the placeholder sentence when needs remain. Predict calls ≤ K × draftable serving operators, independent of schema width (`TestRecommendBound_WideSchemaCapped`). Hints: a hint the schema lacks, or whose kind no role of the intent takes, is `SERVICE_VALIDATION` with `details {field: "fields", hint[, kind, kinds]}` (`TestRecommendBound_BadHintIsCoded`); a cohort that cannot be opened is `DATA_FILE`, a malformed header / schema `ENCODING_INVALID`. Coverage: `TestRecommendBound_ServingOperatorsMapped` holds every draftable serving operator to a draft over the fixture unless its exact `unmappedOnFixture` entry says why — only the two intentional `compare_groups` rows (it takes no date / set field). U35 #249 closed the rest: `AGG_RATIO` (`ignores_field`, yet the wire requires a field) names its numerator as `field`; `ATTR_REG_FITTED` / `RESIDUAL` / `LEVERAGE` declare top-level `target` / `predictors` (+ penalty knobs) and draft like a regression (`regressionShaped`, no `field`); `AGG_WEIGHTED_MEAN` (`weightParams`) binds `params.weight_field` to the cohort's suggested weight (`Bound.Weight` = Inspect's `suggested_weight`), else asks for it — an optional need dropped when the probe shows an instance default weight resolves (`TestRecommendBound_RatioAndRegressionAttributes`, `_WeightedMeanWeight`, root `TestRecommend_FacadeBindsSuggestedWeight`). `WIN_EWMA` (`alpha` / `decay`) and `FEAT_BUCKETIZE` (`boundaries` / `quantiles`) draft through their `exactly_one_of` groups (derived-cohort E3-S3); `TestManifestExactlyOneOfComplete` (+ processing's `TestExactlyOneOfRefusedAtRuntime`) holds every component operator whose predict refuses empty params naming an optional param to declare the group, so a new one-of param cannot silently drop out of Recommend. Beside it: `TestRecommendBound_EveryDraftPassesPredict`, `_NeedsOperators`, `_NeedsRankBelowBound`, `_AdvisoriesRankAndAttach`, `_HintsPinRoles`, `_ProfileHidesOperators`, `TestRecommend_NeedsWhyLint`, root `TestRecommend_FacadeBoundSidecarAdvisories`. Not an observed operation (`.claude/reference/observability.md`, Not operations).
