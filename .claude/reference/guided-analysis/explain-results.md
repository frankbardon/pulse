## Explain results, operator mode and surfaces

### Response mode

- `ExplainRequest.Response` (a Process `Response`) with `Request` as its optional companion — the request that produced it; any other request root beside a response is `SERVICE_VALIDATION`.
- `mode: response`, `root: response`; `valid`, `steps`, `defaults_applied`, `advisories`, `refusals`, `warnings` stay empty, and no cohort is opened.
- Logic: `internal/guide/explain_response.go`.
- One finding per test / post-test result (a nil `return`-skipped position is skipped), per regression (a model finding, then one per predictor coefficient — never `(intercept)`), per overlay layer, per matrix result and per aggregation slot.
- **Verdict** (closed `Verdicts()`): a test's p is evidence of a `difference` or an `association` by the family's class (`testClass` / `overlayClass`, held complete by `TestExplainResponse_ClassTablesComplete`; an extension is `association` when its Purpose serves `relationship` / `drivers`, else `difference`); a regression coefficient's is `evidence_of_effect` / `no_evidence_of_effect`; aggregations, matrices, model fits and descriptive overlay kinds are `descriptive`; an undefined p is `not_computable` — NaN in Go, and after a JSON round trip the `p_value: 0` + `reject_null: false` pair no defined p produces.
- The prose says "no evidence of a difference", never "no difference".
- **Alpha** is the result's own `TestResult.alpha` (never an assumed 0.05).
- When a correction ran the verdict reads `significant_adjusted` (an overlay: `summary.significant_adjusted`, or each cell's `payload.significant_adjusted`) and the finding names `multiplicity {method, family, m}`; the raw p never decides it.
- A regression and an UNCORRECTED overlay carry no alpha of their own: they are read against 0.05 and a caveat says so ("Regression p-values are raw…", "OVERLAY_X carries no alpha of its own…").
- An overlay's p-values sit where its Interpretation's `Shared: "p-value"` field says (`summary.p_value`, `scalar`, `summary.statistic`, `cells.value`, or each series entry's summary); a per-cell / series layer is one finding with `tests` + `below_alpha` (or `below_alpha_adjusted`) and is evidence when any cell is.
- **Bands**: `strength_band` only from an Interpretation with bands, always with `convention` (the Interpretation's citation), via `descx.BandOf` (reads `|v|` under `Abs` and `max(v, 1/v)` under a registered SymmetricLog convention); a test bands its first banded effect size (the family's declared order), then `statistic`; a regression its `r2` / `adj_r2` / `pseudo_r2`; `MAT_CORRELATION` its strongest off-diagonal value.
- An unbanded effect size gets its number only.
- **Numbers** are keyed by Interpretation path (`statistic`, `p_value`, `alpha`, `df`, `p_adjusted`, `details.effect_size.<k>`, `summary.p_value`, `scalars.<k>`) or component key (`n`, `n_null`, `sum_weights`, `n_eff`, `n_weight_invalid`, `n_listwise_dropped`, `value`); an undefined figure is `null`.
- **Caveats** (terse too): ≥2 uncorrected p-values from tests, post-tests (not the self-controlling `TEST_TUKEY_HSD`) and overlay cells → a caveat citing `PULSE_ADVISORY_MANY_TESTS`, plus a separate remedy sentence naming `multiplicity` / `p_adjusted` that the prose scrub drops on an instance hiding the capability (the cited caveat survives); without the companion, a "Partial reading" note; absent Components (rows left out not reported), a `returned` marker, a `partial_cohort_reason`.
- **With the companion** each aggregation names its operator, its scrubbed `Purpose.Plain` and its weight (the slot's own, else the request's; a `null` slot is unweighted); **without it** an aggregation is its Components label and floor only (`n`, `n_null` as rows left out, `sum_weights` flagged as an unnamed weight) and the summary says "aggregated output of N rows across G groups" — never a guessed operator.
- The summary counts the parts, the run's records (`components.run`, else `metadata`) and how many inferential findings show evidence.
- Full detail adds one sentence per finding plus the `Run` floor sentence, glossary refs and follow-ups of every named operator, and the inferential operators' assumptions.
- A hidden operator is never named (the finding keeps its verdict, `operator` empty).
- Every response-mode finding carries `slot`, the wire path of the result it reads (`tests[0]`, `regressions[0].coefficients.hours`, `aggregations[0]` — an aggregation by its request slot).

### Result roots

- (`internal/guide/explain_results.go`).
- Exactly one result root — `response`, `composed_response` (`ComposedResponse`), `chain_response` (`ChainResponse`), `facet_result` (`FacetResult`) — with at most ITS OWN companion (`request` / `composed` / `chain` / `facet`); two result roots, or any other request root beside one, is `SERVICE_VALIDATION`; `root` echoes the result root's name.
- Each larger result reuses the Process-response reader under a SCOPE (sentence lead `"Request 2's test 1 (TEST_T) …"`, `"Stage 1's aggregation 1 …"`, `"Field `region`'s overlay 1 …"`, `"The batch's overlay 1 …"`) and a path prefix, sharing ONE reader so the many-tests caveat counts the WHOLE result: **Compose** — each slot `responses[i].…` with the batch request's `Requests[i]`, a per-slot sentence (`"Request 2 reports 1 test …"`) ahead of its findings, then the batch overlays (`overlays[k]`), each naming its `multiplicity {method, family: compose, m}`; the cross-slot count matches predict's per-slot + host-overlay advisories.
- **Chain** — each stage `stages[i].…` read with the response's echoed `normalized_request` FIRST (what the engine ran, defaults resolved), else the `chain` companion, so an echoed chain names its aggregations with no request supplied; `final` alone is read as the one stage; whole-chain overlays follow.
- **Facet** — one block per field (`fields.<name>`, the companion's field order then sorted): a descriptive finding (discrete: `distinct_count`, `top_count`, `truncated_at`, `null_count`; numeric: `count`, `min`, `max`, `mean`, `stddev`, `sum`, `percentiles.<k>`; a numeric field with no value is `not_computable`, `mean` null), then the overlay layers decorating it (tied by the companion spec's `params.field`, else the only field); then `additive.<name>` blocks and any layer no field could host (with a caveat when the companion is absent).
- Per-result caveats are scoped (`"Request 2's response carries no components …"`); an overlay layer's `warnings` become a caveat naming their CODES only (the messages are engine prose and stay in the slot), as do a facet's `warnings` (counted).
- The partial-reading caveat names the missing companion (`composed`, `chain` — "or run the chain with its request echoed" — `facet`).

### Operator mode

- (`internal/guide/explain_operator.go`).
- `ExplainRequest.Operator` (an operator name) set ALONE — any root beside it is `SERVICE_VALIDATION` `details.field: operator`, as is a name the instance does not offer (unknown and hidden alike, read off the pruned ontology) — gives `mode` / `root` `operator`, no steps, empty `findings`, and `validation` (`descriptor.OperatorValidation`: `references[]` `{against, tolerance, tests, weighted?}` (always an array), `gap?`, `weight_refusal?` `{code, reason, tests}`, `certification[]?` — one NIST StRD row per dataset `{family, dataset, difficulty?, digits, min_digits}`, holding only the figures the operator produces: the univariate rows split `mean` (`AGG_AVERAGE`) from `sd` (`AGG_STDDEV`, `AGG_WELFORD`)).
- It is `InstanceSnapshot.Validation`, the view docgen renders, so the book and the engine cannot disagree: weighted references and the refusal drop when `capability:weighting` is hidden, the refusal reason is the engine's (`ValidationWeightRefusalReason`), and every prose string passes `ProseScrub.Text` (a reference left empty by the scrub is dropped).
- An operator with no record (an extension, a descriptive operator outside the registry) has no `validation` and a caveat saying so.
- Summary counts the references; caveats point at a gap and a weight refusal by template (the gap and reason themselves stay verbatim in `validation`, unlinted); full adds the operator's glossary refs, follow-ups and assumptions.
- **Pulled, never pushed:** no manifest or default payload carries it (`TestManifestGuidanceBudget` unmoved).
- Surfaces: CLI `pulse explain OPERATOR [--detail] [--json]` (the positional name; beside `--request` / `--response` or a second name is `CLI_INPUT`) and `pulse_explain {operator}`.
- Pinned by `TestExplainOperator_*` (`internal/guide`), `TestPulseExplain_OperatorMode`, `TestCliExplain_Operator` and the goldens `explain.operator.<detail>.json` (`TEST_ANOVA_F`).

### Surfaces

- CLI `pulse explain --request F | --response F [--request F] [--root request|composed|chain|facet|sample] [--detail terse|full] [--json]` (`internal/cli/explain.go`, a thin adapter: `--root` names which root the files hold — default `request`; a `--response` file that is a `--json` envelope is unwrapped to `data`; `CLI_INPUT` for no file, a bad root, `sample` with a response or unreadable JSON; other refusals keep their own code) and MCP `pulse_explain` (`ExplainIn`: every root an OPEN object — the agent learns request shapes from the execute tools — re-encoded and decoded into its typed slot by `HandleExplain`; a root that does not decode is `SERVICE_VALIDATION` with `details.field`).
- **Undefined figures stay undefined on the way back in.** A result root (`response`, `composed_response`, `chain_response`, `facet_result`) is decoded through `internal/jsonfinite.Unmarshal` — `types.MarshalFinite`'s inverse: a JSON `null` in a non-pointer float slot is NaN, not the 0 plain `encoding/json` leaves — on both surfaces, so a `null` statistic, p-value or coefficient p reads `not_computable` with a `null` number rather than as a real 0 (a null coefficient p would otherwise read `evidence_of_effect`).
- Request roots decode with plain `encoding/json` (a null request float means unset).
- Both surfaces bind to the hideable feature `capability:explain` (Since 1.0.0, no dependency edge): hiding it unmounts the tool, drops the manifest `explain` command and the payload-schema roots `ExplainRequest` / `ExplainResult`; the facade stays callable.
- `ExplainRequest`'s own root slots follow their capabilities (`gatedSlots`), so an instance hiding compose has no `composed` / `composed_response` property and no `ComposedRequest` / `ComposedResponse` def through it (`TestExplain_HiddenFeatureSurfaces`, `TestRegister_ExplainFollowsItsFeature`); the closed `ExplainDetail` / `ExplainMode` / `ExplainRoot` / `Verdict` vocabularies are schema enums.
- Goldens `descriptor/testdata/explain.<family>.<terse|full>.<with|without>_request.json` for every family {test, regression, overlay, matrix, descriptive, compose, facet, chain}, plus request mode `explain.request.<detail>.json` over the Recommend fixture cohort (`TestExplainGolden`, `-update`); the result fixtures travel through the same JSON round trip the surfaces use (written by the wire rule, read back through `jsonfinite`), and `TestExplainGolden_NullFigureStaysUndefined` pins the null case.
- **`TestExplainProseLint`** (binding) runs `LintGuidanceText` over the template-built prose — `summary`, step texts, follow-up conditions, `sentences`, `caveats` — of every golden case, both as generated now (a non-compliant template fails before a golden moves) and as stored on disk, and requires every case's golden to exist; `refusals`, `warnings` and advisory messages carry verbatim engine text and are not linted.
