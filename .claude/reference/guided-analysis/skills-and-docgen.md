# Guided analysis — Glossary, virtual skills and generated reference

Per-topic slice of the guided-analysis reference (Glossary and the jargon rule, Virtual skills, skills for an intent, generated skill sections and the generated reference (docgen)). Index (rules + section map): `.claude/reference/guided-analysis.md` — load it first, then only the slice(s) your change touches.

## Glossary and the jargon rule

- A `Jargon: true` term must be LINKED (listed in `Purpose.Glossary`) wherever one of its `Forms` appears in a `Plain` sentence.
- Matching is case-insensitive, word-boundary, longest match wins (`jargonTermsIn`; `TestJargonTermsIn_LongestMatchWordBoundary`).
- `pulse.Glossary()` returns the whole registry on every instance; the instance ontology prunes a term only when ≥1 operator cites it (`Purpose.Glossary`) and every citing operator is hidden, and the `glossary` virtual skill renders from that graph, dropping SeeAlso links into pruned terms.

## Virtual skills

- `glossary` and `intents` are skills with no file, rendered as markdown from the registries (`RenderGlossarySkill` / `RenderIntentsSkill`, `internal/descriptor/guidance_skills.go`) and registered through `skills.RegisterVirtual` at init.
- Kind `reference` (`skills.KindReference`): no atomic family, no `##` set, no budget.
- They reach every skill surface — `pulse skills list|show`, `pulse_skills_list` / `pulse_skills_get`, the `pulse-skill://glossary` / `pulse-skill://intents` exact resources, manifest `skills[]` — and no feature profile hides them; on a profiled instance their BODIES render from the pruned ontology (`renderIntentsSkill` / `renderGlossarySkill` with the graph's keep filter, via `Discovery.Skill`), so a pruned intent or term is absent.
- `TestDiscovery_VirtualSkillsRenderPrunedGraph` and the root `TestGuidanceSkills_NeverPrunedByFeatureProfile` (served sections = surviving nodes) pin it.
- The stems are reserved (`skills.ReservedVirtualNames`; `TestVirtualSkillStemsNotEmbedded`).
- Mechanics: `.claude/reference/skill-pack.md` (List source of truth).
- Facade: `pulse.Glossary()` / `pulse.Intents()` return deep copies in declaration order.

### Skills for an intent

- `pulse.SkillsForIntent(intent)` / `pulse_skills_list {intent}` (`InstanceSnapshot.SkillsForIntent`, `internal/descriptor/skills_for_intent.go`) rank the instance's skills for one intent, every edge read off the PRUNED ontology: tier 1 the skills the intent node is `documented_by` (the virtual `intents` skill); tier 2 the `kind: design` skills whose rendered `covers` names an operator serving the intent (`OperatorsServing`) or that operator's category prefix (`TEST` covers `TEST_T`), by name; tier 3 the atomic skills those operators are `documented_by`, by the operator's `Purpose.Level` (basic → intermediate → advanced; no Purpose / Level last — built-in registry, else `ExtensionsSnapshot.PurposeOf`), then name.
- Level is JOINED through the skill's `operator`, never stored on skill metadata.
- Each entry is the rendered metadata `Skills()` lists; an intent no operator serves (`lookup`) answers `intents` alone.
- The intent resolves through `InstanceSnapshot.checkIntent` — the ONE resolver example search shares — so an unknown or pruned intent is `PULSE_RECOMMEND_INTENT_UNKNOWN` with `details.valid` = the instance's intents.
- No intent: `pulse_skills_list` is `Skills()` byte-identically, and `Skills()` itself is unchanged.
- Pinned by `TestSkillsForIntent_Ranking` / `_NoServingOperator` / `_ProfilePruning` and `TestSkillsList_IntentArg` (`internal/mcp`).
- Not an observed operation (`.claude/reference/observability.md`, Not operations).

### Generated skill sections

- An atomic skill's `<!-- generated: use-when -->` / `<!-- generated: reading-the-output -->` markers render from the operator's `Purpose` / `Interpretation` at read time (`internal/descriptor/skill_sections.go`; contract: `.claude/reference/skill-pack.md` (Generated sections)); `<!-- generated: contract -->` renders `## Contract` from the capability declarations, not guidance (`skill_contract.go`).
- That is on-demand skill text, so `TestManifestGuidanceBudget` is unaffected; the glue text is held to the prose lint's text rules by `TestSkillSections_BuiltinsWithinCapsAndLint`.

### Generated reference (docgen)

- `internal/docgen` renders the same registries into an instance-scoped Markdown tree: one catalog page per `PurposeSurfaces()` category (summary table Operator | In plain words | Answers questions like | Level | Instead, when…, then a detail block per operator under anchor `op-<lowercased name>`), a glossary page (anchor `term-<id>`) and every visible skill as `Discovery.Skill` serves it.
- It walks the PRUNED ontology: a hidden operator has no row, block, skill page or link; a not-for alternative whose target the prune removed is dropped; every Purpose / glossary prose string passes `ProseScrub.Text`.
- Glossary terms are kept by the virtual glossary skill's keep-function (owning operators), and a kept term's `Forms` are spellings rendered verbatim — never token-scrubbed (so "transition matrices" survives a matrices-hidden instance with its term).
- An extension operator without a `Purpose` renders "No guidance provided." plus its manifest description.
- Docs on disk are outside `TestManifestGuidanceBudget`.
- **Reading pages** (`reading.md` + `reading/<family>.md`): one Interpretation page per family — `test`, `regression`, `matrix`, `overlay`, `descriptive` (aggregator / attribute / filterer / grouper / window / feature / synth distribution) — each field rendering `Means`, `Bands` under the named `Convention`, `Sign` and `Caveats`, scrubbed like all prose; a field whose PATH names a hidden token (`p_adjusted` without `capability:multiplicity`) is dropped whole, and a family with no visible entry has no page.
- A shared rule set (the p-value reading) renders ONCE, at the top of the first page citing it (the Test page whenever a test is visible, anchor `shared-<key>`), and every citing field links there.
- `reading/components.md` documents the slot floors (`ComponentFloors()`), the weighted floor keys (`WeightFloorKeys()`, only when `capability:weighting` is offered), the mergeability classes and every visible operator's own `ComponentSchema` keys from the instance manifest.
- **Preserve markers:** hand-written prose inside a generated page sits between `<!-- docgen:preserve begin <id> -->` and `<!-- docgen:preserve end <id> -->` and is copied verbatim from a file EMBEDDED in `internal/docgen` (so an export outside the repo carries it); the Components intro's source of truth is `internal/docgen/components_intro.md` — edit it there, never in a rendered page.
- **Validation page** (`validation.md`, rendered by `internal/docgen/validation.go`): the hand-maintained `validationRegistry` (`internal/descriptor/validation_registry.go`, shared with Explain's operator mode through `InstanceSnapshot.Validation`; the StRD record it embeds is `internal/descriptor/strd_lre.json`) maps each built-in test, regression, matrix operator and inferential overlay to its external references (implementation + pinned version, tolerance, repo-relative test files) and an optional plain-words `Gap`; it renders as a "Validated against" list in each catalog detail block and a per-category summary table under the preserved `validation_intro.md` prose.
- A weighted-reference entry (`Weighted`) is dropped when `capability:weighting` is hidden, and so is `WeightRefused` — the test files pinning a permanent weight refusal (`PULSE_WEIGHT_UNSUPPORTED`, reason from `descx.OperatorWeightRefusal`, or `descx.PostTestWeightRefusal` for a `PostTestOnly` record) for an operator with no weighted form.
- Gates (`internal/descriptor/validation_test.go`): `TestValidationRegistryCoversInferential` (every required operator has a record; no reference means a declared `Gap`), `TestValidationRegistryNamesBuiltins`, `TestValidationReferencesExist` (every cited file exists, `WeightRefused` included, and EXERCISES the operator: it names it by wire name or a `types` constant spelling it (`OverlayKindChiSqRow`), or a string literal in it names a golden under its package's `testdata/` (path, base name or stem) that does; failing that, a file cited beside it in the same reference and package that does name it must either declare a top-level name this file uses (a runner reading a table: the weighted runner and its values) or call a non-test package function this file also calls (a kernel oracle and the routing test running that kernel); the rule itself is pinned by `TestValidationExercisesRule`), `TestValidationWeightRefusalIsPermanent` (a `WeightRefused` operator is refused permanently with a reason and cites no weighted reference); docgen keeps `TestValidationWeightRefusalRenders` and `TestValidationDropsWeightedWhenHidden`.
- Add or change a reference test → update its registry row in the same PR; a claim with no harness is never published.
- **Question pages:** `questions.md` ("What can Pulse answer?": one row per guide — `Intent.Label` linked, the first `Sounds` phrasing — plus a mention of the utility intents, which get no guide) and `questions/<intent_id>.md`, one per analytic intent the instance keeps that a visible operator serves, titled by `Intent.Label`, in six parts: the question; pick your analysis (the intent's `Shapes`, then every visible serving operator grouped by category, basic first, with `Purpose.Plain` + Level); worked stories (EVERY story example whose FIRST `_meta.intents` entry is the intent and whose operators are all visible, in name order — a second story on an intent renders too, never dropped: request, the committed golden from `examples.StoryGolden` verbatim — docgen never executes — and `_meta.interpretation`); how to read (the stories' operators' Interpretation fields, deduplicated); pitfalls; next steps (the three guides sharing most serving operators, the intent's non-atomic skills plus the story operators' skills, and real CLI leaves gated on their capability).
- Hand prose lives in `internal/docgen/guides/<stem>.md` (`index` for the landing page), sections opened by whole `<!-- section <name> -->` lines — `intro` (landing), `question` and `pitfalls` (guides) — rendered in `guide-<intent>-<section>` / `questions-<section>` preserve spans and passed through `ProseScrub.Text` (verbatim on an instance hiding nothing it names); a missing file or section renders a generated fallback outside any span.
- `TestProse_EmbeddedFilesWellFormed` refuses an unknown stem or section, and question pages pass the same lint as reading pages (`TestRender_QuestionPagesLint`).
- Every reading page passes `LintGuidanceText` line by line (`TestRender_ReadingPagesLint`, with the registry allowlist's two shared p-value exemptions mirrored).
