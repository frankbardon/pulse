# Execution modes — full prose

CLAUDE.md keeps one-line pointers; this file is the in-depth wiring detail per mode. Skill docs are the canonical longform — this file is the "everything tightly cross-referenced in one place" view for engine work.

## Streaming Process

`pulse.ProcessStream`, `pulse api process --stream`. Four orchestrator modes — single-pass, grouped, two-pass attributes (Welford-Pébaÿ), streaming features. Forced-buffered: median/percentile/zscore aggregators, `ATTR_PERCENTILE`, `GROUP_QUANTILE`/`GROUP_DATE`, window operators, decimal paths, tier-1 tests with groupers/features/two-pass, all tier-2 tests. NDJSON one row per line. See `skills/streaming-and-watching.md`.

## Projected buffered decode

Per-request field projection on the buffered decode iterator is **default-on** — output-transparent (byte-identical result, only faster and lighter per record). Opt out with `pulse.Options{DisableProjection: true}` or the `--no-project` CLI flag on `pulse api process` (v1: `pulse api process` only; `process-chain` / `compose` do not expose it yet). `pulse.Options.ProjectBufferedFields` is retained but deprecated — a harmless no-op; use `DisableProjection` to force full-record decode. Wiring: `svc.SetProjectBufferedFields(opts.ProjectBufferedFields || !opts.DisableProjection)`. `processing.NeededFields(req, schema, ext)` walks every request slot — Aggregations, Attributes (incl. expr-AST identifiers via `expr-lang/expr/parser` + `expr-lang/expr/ast` for `ATTR_FORMULA` / `FILTER_EXPRESSION`), Filterers, Groups, Windows, Features, Tests, Regressions, Sort.Field. The iterator turns the retained set into an `encoding.DecodePlan` via `Schema.BuildDecodePlan(retained)` (cached per-iterator); per-record hot path walks the plan via `RecordReader.ReadRecordWithWidePlan`. Plan segments: `SkipBytes{N}` (one `Seek` / `io.CopyN` discarding N bytes, coalescing contiguous unprojected non-bit-packed runs) and `DecodeFields{Fields}`. Bit-packed grouping: any contiguous `u4`/`packed_bool` run stays grouped — if any member retained the whole group becomes one `DecodeFields` (unretained still decoded to keep cursor aligned, map writes suppressed); otherwise the run folds into one `SkipBytes{K}`. Null-bitmap whole-or-skip: bitmap decoded once when any nullable field retained; else single `SkipBytes{N: Schema.BitmapByteSize()}`. Extension operators without `FieldInputs` widen retained set to `*` (full-coverage plan). Bench: synth 200-field × 100K-row Process drops from ~1.07s to ~155ms (~7×, 14× fewer allocs) on a 4-field projection. Detail: `skills/cohort-schema-design.md` (Decode plan and projection) + `docs/src/internals/extension-points.md` (FieldInputs hook).

## Parallel Compose

`pulse.ComposeParallel`, `pulse api compose --parallel N`. Bounded worker pool over `ComposedRequest`. Order-preserving by slot index. `ComposeOptions{MaxWorkers, PerRequestTimeout, FailFast}` (FailFast defaults true).

Post-slot-barrier Compose-overlay fold (`service/compose_overlay.go` ⇒ `processing.ApplyComposeOverlays` in `processing/overlay_compose_dispatch.go`): the orchestrator invokes `s.applyComposeOverlays(ctx, req, requests, responses)` once every slot has produced a finalised `*Response` and BEFORE the response is returned. Operates EXCLUSIVELY on `*Response` objects; per-slot `Responses[i].Overlays` is left UNTOUCHED.

FailFast handling: when `FailFast=true` (default) AND any slot fails, the orchestrator returns the first observed error WITHOUT invoking the overlay hook. FailFast=false routes slot failures through `SERVICE_INTERNAL` which also skips the hook. Empty / nil `req.Overlays` short-circuits with no allocation (overlay-free Compose JSON is byte-identical to a request that omits the slot entirely).

Per-kind handlers replace the chassis stub (`applyComposeStub`) for every Compose-only kind that has shipped. The six crosstab-shape COMPOSE handlers (`OVERLAY_INDEX_VS_REF`, `OVERLAY_DELTA_VS_REF`, `OVERLAY_PROP_Z_CELL`, `OVERLAY_T_CELL`, `OVERLAY_CHISQ_VS_REF`, `OVERLAY_RANK`) are wired today; remaining Compose-only kinds dispatch through the chassis stub until their handler lands. All buffered — streamable subset is empty across COMPOSE by construction.

Slot label resolution: `applyComposeLabelDefaults` synthesises `request_<index+1>` for empty `Request.Label`; `ApplyComposeOverlays` builds a `Label → Index` lookup. The dedicated error codes `PULSE_OVERLAY_REFERENCE_UNKNOWN` and `PULSE_OVERLAY_TARGET_UNKNOWN` are pending — the chassis currently falls back to `PULSE_OVERLAY_REF_UNKNOWN` with a `which` Detail. See `skills/compose-requests.md`.

## Parallel shards

`pulse.Options.ShardWorkers`, default `0` ⇒ `runtime.NumCPU()`. Bounded per-shard worker pool inside `Process` when cohort is a shard archive. Reducer engages only when every operator is mergeable per `processing.CanMergeRequest` (built-ins only; non-decimal targets; no windows/features/regressions/tests/two-pass). Non-mergeable falls through to serial `shardIter`. Associative+commutative byte-equal vs serial; Welford within ULP via Chan-Welford. Surface: `service/shard_reduce.go`, `processing.MergeableAggregator`, `types.AggregationType.Mergeable()`. See `skills/cohort-schema-design.md` (Sharded).

## Parallel buffered Process

`pulse.Options.DecodeWorkers`, default `0` ⇒ `runtime.NumCPU()`. Bounded per-segment worker pool inside `Process` for single-file (non-shard) cohorts. Engages only when `service.canParallelDecode` accepts — `DecodeWorkers != 1`, `recordCount >= service.parallelDecodeRecordThreshold` (currently `100_000`), single-file (sharded routes through `ShardWorkers`), `resolveRealPath` succeeds (mmap available), `processing.CanMergeRequest(req, schema)` is true. Ineligible falls through to serial `scanIter`.

Crosstab is intentionally NOT exercised today — `validateCrosstabSpec` requires `req.Aggregations` empty so crosstab requests always fail `CanMergeRequest`. This infrastructure benefits future non-crosstab buffered Process calls.

Segments stride-aligned at record boundaries over the mmap'd record region; same `DecodeFields`/`SkipBytes` plan shared read-only across workers; each worker owns a `shardPartial`; partials fold in worker-index order via `mergeShardPartials` + `finalizeMergedPartial`. Byte-equal vs serial; Welford within ULP via Chan-Welford. Surface: `service/parallel_decode.go`, `service/parallel_reduce.go`. See `skills/cohort-schema-design.md` (Parallel decode).

## ProcessChain

`pulse.ProcessChain`, `pulse_process_chain`, `pulse api process-chain`. Source-rooted linear chain. Stage 0 against `ChainRequest.Cohort`; subsequent stages receive prior `Response.Data` as synthesised in-memory cohort (grouper keys → categorical_u32, aggregator outputs → f64). Mergeable-only at v1 (`CanChainRequest` requires `CanMergeRequest` AND scalar aggregator emission — rejects `AGG_FREQUENCY`/`AGG_MODE`). Failures: `PULSE_CHAIN_NOT_MERGEABLE`, `PULSE_CHAIN_EMPTY`. Predict equivalent: `descriptor.ValidateChain`. Surface: `types/chain.go`, `processing/chain.go`, `service/chain.go`, `descriptor/chain.go`, `descriptor/capabilities_chain.go`.

Dual-slot overlay design: per-stage overlays ride `ChainRequest.Stages[i].Request.Overlays`; whole-chain overlays ride `ChainRequest.Overlays []*ChainOverlaySpec` and produce `ChainResponse.Overlays []*OverlayLayer` after every stage finalises. `ChainOverlaySpec` carries `Ref StageRef` + `Target StageRef`. Whole-chain barrier: `service.applyChainOverlays` runs after the stage loop, dispatching through `processing.ApplyChainOverlays`. Per-stage `Stages[i].Overlays` is left UNTOUCHED. The dedicated error codes `PULSE_OVERLAY_TARGET_UNKNOWN`, `PULSE_OVERLAY_REFERENCE_UNKNOWN`, and `PULSE_OVERLAY_CHAIN_STAGE_SHAPE_DIVERGENT` are pending follow-ups. See `skills/process-chain.md`.

## Pushdown hash join

`Request.Joins []*JoinSpec`. v1 = exactly one inner join per Request (`PULSE_JOIN_TOO_MANY`, `PULSE_JOIN_KIND_NOT_IMPLEMENTED`); in-memory build (no spill; `PULSE_JOIN_SPILL_DIR` + `PULSE_JOIN_MAX_MEMORY_BYTES` reserved). `JoinedSchema(left,right,spec)` produces `left.Fields + right.Fields` with optional `spec.As` prefix; non-prefixed collisions → `PULSE_JOIN_FIELD_COLLISION`. Key compatibility: identical types match; categorical of any width match; unsigned-int/float/date numeric family interchangeable; decimal128 rejects cross-type. Surface: `types/join.go`, `processing/join.go`, `service/join.go`, `descriptor/join.go`, `descriptor/capabilities_join.go`. See `skills/join-design.md`.

## Crosstab

`Request.Crosstab`, `Response.Crosstab`. Composes existing groupers + aggregators across a row × column axis grid; reshape, margin recompute, normalization layered on top. Multi-grouper axes recursively partitioned. Margins always recomputed from raw rows for correctness — `AGG_MEDIAN` row margin equals the standalone single-axis median, NOT the median of cell medians. Per-aggregator classification at `AggregationType.MarginReducibility` (`summable` / `mean_reducible` / `recompute`). `shape: matrix` (default) populates `Response.Crosstab.Matrix`; `shape: long` emits tuple rows on `Response.Data` with margin rows tagged `_margin=row|column|grand`. Inherently buffered except `shape=long` + no margins + `normalize=none`.

Normalization layering: `normalize_level` truncates the same axis as `normalize`; `normalize_within` fixes a prefix of the OPPOSITE axis. Both compose.

Buffered record set automatically projected via `service.applyCrosstabProjection` (extends `processing.NeededFields` to walk `Crosstab.Rows/Columns/Cell` + `req.Labels[].Field` + `AGG_WEIGHTED_MEAN/RATIO` Cell.Params); wide-cohort crosstab cost is `O(|referenced|)` not `O(|schema|)`; forced on regardless of `opts.DisableProjection`. Capability: `Manifest.Crosstab`. Predict gate: `descriptor.validateCrosstab`. See `skills/crosstab-guide.md`.

## Fused crosstab

`processing.CanFuseCrosstab`, `processing.FusedCrosstabState`, `processing.StreamableGrouper.KeyFor`. In-decode streaming alternative to the buffered Crosstab orchestrator. When the gate accepts, `service.processCrosstab` short-circuits `materializeRecords` + recursive `PartitionByAxis` and drives a single streaming pass that interns row/col composite axis keys on first sight and folds each filter-passing record into the matching cell / row-margin / column-margin / grand-margin / cross-axis-margin online aggregator. Memory drops from `O(filtered records)` to `O(cells + margins)`.

Gate composition (`CanFuseCrosstab`): mergeable + non-recompute scalar cell aggregator; every row/col grouper implements `StreamableGrouper` (CATEGORY/RANGE/ROUNDED/DATE/SET_VALUE — `GROUP_DATE` is admitted here even though `GroupType.Streamable()` is false at the Process layer); no tests; no features; no `ATTR_FORMULA`; no `FILTER_EXPRESSION`; no decimal128 cell field; no extension operator without `FieldInputs` hook; no `Request.Overlays` (overlay fold runs in the buffered RunCrosstab exit only — fused finalize is deferred).

Axis-key nullity is per-axis: a record with non-null row key + null col key still updates the row margin and the grand margin. Cells only land at intersections where both axes resolved. Margins recompute from raw rows so byte-for-byte equivalent to buffered RunCrosstab. Map-valued cell aggregators paired with `normalize != none` are rejected (`PULSE_CROSSTAB_NORMALIZE_MAP_VALUED`). Disable via internal `disableCrosstabFusion` toggle.

Perf: synth 200-field × 100K-row bench ~0.51 × buffered (~47% faster); canonical 1M-row real-cohort bench 2.57s vs buffered crosstab baseline 3.82s (~32% faster); allocs/op ~+25% from per-cell accumulator construction but bytes/op ~−18%. See `skills/crosstab-guide.md` (Fused mergeable path) + `skills/grouper-design.md` (StreamableGrouper).

## Facet endpoints

`pulse.Facet(ctx, path, field)` simple distinct-values (categorical fast path through dict, numeric streams file). `pulse.FacetSchema(ctx, *FacetRequest)` rich multi-field — counts (sorted desc by count, ties asc by value), null tallies, Welford online numeric stats, optional `NumericPercentiles` (forces buffered per-field sort), optional `IncludeHistogram` with caller-supplied `HistogramRange` (single-pass), optional `DiscreteTopK` (`TruncatedAt` warning), optional `AdditiveFields` contribution counts, optional `FacetRequest.Overlays []*OverlaySpec` carrying the four FACET-host overlay kinds (`OVERLAY_INDEX_VS_POP` / `OVERLAY_ZSCORE_VS_POP` / `OVERLAY_CHISQ_VS_POP` / `OVERLAY_KS_VS_POP`).

Overlay dispatch runs at the buffered FacetSchema exit via `processing.ApplyOverlaysFacet`, attaches layers to `FacetResult.Overlays` in spec order, and recurses `FacetSchema` against `Ref.Population.Cohort` to materialise the per-spec population view (strips Filterers / Labels / Additive; cycle-safe). Streamability mixed: INDEX_VS_POP / ZSCORE_VS_POP are streamable per `types/overlay_streamability.go` but run at the same buffered exit since FacetSchema is structurally buffered today. Capability: `Manifest.Facet` carries `SupportsOverlays: true` + `SupportedOverlayKinds`. Predict: `descriptor.ValidateFacet` (calls `descriptor.ValidateFacetOverlays`). CLI `pulse api facet` falls back to simple shape unless rich flag set. See `skills/facet-design.md` and `skills/overlay-system.md` (FACET-host wiring section).

## Overlays

`Request.Overlays []*OverlaySpec`, `Response.Overlays []*OverlayLayer`. Additive post-result decorations attached to an already-computed base result. Each spec produces one `OverlayLayer` in matching slot order; layers carry the host-shape payload and never mutate the base payload — overlays are read-only siblings keyed to host coordinates. Catalog at `types.AllOverlayKinds()` + `types.OverlayStreamability`; per-kind capability at `descriptor.overlayCapabilityFor` (surfaced on `Manifest.Overlays`).

Buffered-by-default rule: `OverlayStreamability[kind] == false` for every kind in the initial catalog. The overlay family covers index/share/delta/cumulative/rolling shapes across cell/row/column/total scopes. Forward-compat: `Request.Overlays` is omitempty so `CanonicalHash`/`Request.Hash` stay byte-identical for requests that omit the slot. Fused crosstab automatically falls back to buffered when `Request.Overlays` non-empty. Failures: `PULSE_OVERLAY_KIND_UNKNOWN`, `PULSE_OVERLAY_SCOPE_UNSUPPORTED`, `PULSE_OVERLAY_REF_INCOMPATIBLE_WITH_SHAPE`, `PULSE_OVERLAY_HOST_NOT_SUPPORTED`, `PULSE_OVERLAY_LEVEL_OUT_OF_RANGE`.

**Level / Within composition.** The share / index / delta / zscore family honours `OverlaySpec.Level` (same-axis prefix truncation) and `OverlaySpec.Within` (opposite-axis prefix fixing). `Level=0, Within=0` preserves the leaf-margin denominator and is byte-identical to the no-Level/no-Within handler output. Composition mirrors the buffered crosstab `normalize_level` / `normalize_within` semantics (byte-equivalent for summable cell aggregators) and reuses the same prefix-key helpers (`processing.SameAxisPrefixDepth` / `processing.OppositeAxisPrefixDepth` / `processing.AxisKeyPrefix`). Out-of-range slots fire `PULSE_OVERLAY_LEVEL_OUT_OF_RANGE` at both predict and runtime; the χ² / Fisher inferential family rejects non-zero values with the same code (implicit-margin contract).

**Grouped Process wiring.** The SERIES-host overlay fold (`processing.ApplyOverlaysSeries`) attaches at the grouped Process exit in both `processing/processor.go` paths (buffered + streaming). No-op when `req.Overlays` is empty, when `req.Crosstab` is set, or when the request has no `Groups`. Mixed-mode downgrade rule: a Request mixing streamable overlay kinds with non-streamable kinds forces the entire request to the buffered path via `processing.canStreamOverlays`.

**FACET-host wiring.** The FACET-host overlay fold (`processing.ApplyOverlaysFacet`) attaches at the FacetSchema buffered exit in `service/facet_rich.go` via `service.applyFacetOverlays`. `FacetRequest.Overlays []*OverlaySpec` is the FACET-host slot; the four FACET-host kinds MUST attach there, not on `Request.Overlays` — the Request-host validator rejects FACET kinds with a `PULSE_OVERLAY_REF_INCOMPATIBLE_WITH_SHAPE` redirect message. Per-spec host-field selection via `OverlaySpec.Params["field"]`. Service-layer wiring recurses `FacetSchema` against `Ref.Population.Cohort`, caches per-cohort+field tuples. `FacetResult.Overlays []OverlayLayer` is omitempty. Predict equivalent: `descriptor.ValidateFacetOverlays` — per-kind Ref / Scope / Level / Within gates; CHISQ rejects numeric hosts; KS rejects categorical hosts. Predict surface: `FacetValidationResult.OverlaysApplied` + `FacetValidationResult.OverlayCost` mirror the Request-host shape. Manifest: `Manifest.Facet` carries `SupportsOverlays: true` + `SupportedOverlayKinds: ["OVERLAY_CHISQ_VS_POP", "OVERLAY_INDEX_VS_POP", "OVERLAY_KS_VS_POP", "OVERLAY_ZSCORE_VS_POP"]`.

**CHAIN-host wiring.** The CHAIN-host overlay fold (`processing.ApplyChainOverlays`) attaches at the post-stage-loop barrier inside `service.ProcessChain` (`service.applyChainOverlays` hook). Dispatcher chassis ships stub handlers for the two whole-chain kinds (`OVERLAY_INDEX_VS_STAGE`, `OVERLAY_DELTA_VS_STAGE`) so the round-trip path is exercised end-to-end without per-kind arithmetic; per-stage `Stages[i].Overlays` is left UNTOUCHED.

**FORMULA kind.** `OVERLAY_FORMULA` is a caller-supplied expression-driven projection compiled ONCE per spec via `expr-lang/expr` (the same evaluator that backs `ATTR_FORMULA` / `FILTER_EXPRESSION`) and run per cell / entry / scalar against a per-host-shape variable namespace (MATRIX: `cell` / `margin_*` / `sd_*`; SERIES: `value` / `total` / `prior` / `baseline`; SCALAR: `value`; Compose hosts add the dotted `slot.<label>.{cell|value}` namespace). Inherently buffered across every host shape. `pulse.Options.Extensions.ExprFunctions` flow through the evaluator (functions widen the function surface only; the variable surface stays fixed per-host-shape). Failures: `PULSE_OVERLAY_FORMULA_PARSE_ERROR` / `PULSE_OVERLAY_FORMULA_TYPE_MISMATCH` / `PULSE_OVERLAY_FORMULA_INVALID_IDENT`.

Surface: `types/overlay.go`, `types/overlay_streamability.go`, `processing/overlay.go`, `processing/crosstab.go` (hook), `processing/crosstab_normalize.go` (shared prefix helpers), `processing/overlay_series.go` (SERIES fold engine), `processing/overlay_series_response.go` (grouped Process wiring + mixed-mode gate), `processing/overlay_facet_dispatch.go` (FACET dispatch table) + `processing/overlay_facet_pop.go` (FACET population resolver), `processing/overlay_chain_dispatch.go` (CHAIN dispatch table + StageRef resolver), `descriptor/overlay.go`, `descriptor/overlay_facet.go`, `descriptor/capabilities_overlay.go`, `descriptor/capabilities_facet.go`, `descriptor/manifest.go`, `descriptor/predict.go`, `descriptor/facet.go`, `service/facet_overlay.go`, `service/chain.go` (`applyChainOverlays` hook), `types/facet.go`, `types/chain.go`. See `skills/overlay-system.md`.
