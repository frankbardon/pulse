# Execution modes — full prose

CLAUDE.md keeps one-line pointers; this file is the in-depth wiring detail per mode. Skill docs are the canonical longform — this file is the "everything tightly cross-referenced in one place" view for engine work.

## Streaming Process

`pulse.ProcessStream`, `pulse api process --stream`. Four orchestrator modes — single-pass, grouped, two-pass attributes (Welford-Pébaÿ), streaming features. Forced-buffered: median/percentile/zscore aggregators, `ATTR_PERCENTILE`, `GROUP_QUANTILE`/`GROUP_DATE`, window operators, decimal paths, tier-1 tests with groupers/features/two-pass, all tier-2 tests. NDJSON one row per line. See `skills/streaming-and-watching.md`.

## Projected buffered decode

Per-request field projection on the buffered decode iterator is **default-on** — output-transparent (byte-identical result, only faster and lighter per record). Opt out with `pulse.Options{DisableProjection: true}` or the `--no-project` CLI flag on `pulse api process` (v1: `pulse api process` only; `process-chain` / `compose` do not expose it yet). `pulse.Options.ProjectBufferedFields` is retained but deprecated — a harmless no-op; use `DisableProjection` to force full-record decode. Wiring: `svc.SetProjectBufferedFields(opts.ProjectBufferedFields || !opts.DisableProjection)`. `processing.NeededFields(req, schema, ext)` walks every request slot — Aggregations, Attributes (incl. expr-AST identifiers via `expr-lang/expr/parser` + `expr-lang/expr/ast` for `ATTR_FORMULA` / `FILTER_EXPRESSION`), Filterers, Groups, Windows, Features, Tests, Regressions, Sort.Field, and the whole Crosstab block (Rows, Columns, Cell, **MarginAggregations**). It also reads the built-in `Params` that NAME a field but do not live on the operator struct (`addAggParamFields`: `distinct_by`, `weight_field`, `numerator_field`, `denominator_field`; plus `stratify` / `target` on the two feature ops). A missed slot or a missed param is SILENT — the field is decoded onto no `Record`, `NumericValue` answers `ok=false` on every row, and the operator publishes a confident zero with `n_null` equal to the full admitted count. The iterator turns the retained set into an `encoding.DecodePlan` via `internal/encoding.BuildDecodePlan(schema, retained)`(retained)` (cached per-iterator); per-record hot path walks the plan via `RecordReader.ReadRecordReusedWithPlan` on BOTH arms — the reuse arm into one reused `Record`, the buffered arm into a FRESH `Record` per row (the map decoder `ReadRecordWithWidePlan` survives only as the defensive projection-without-plan fallback and for non-iterator callers). Plan segments: `SkipBytes{N}` (one `Seek` / `io.CopyN` discarding N bytes, coalescing contiguous unprojected non-bit-packed runs) and `DecodeFields{Fields, Indices}` — `Indices[k]` is the schema position of `Fields[k]`, recorded by the builder's own walk. **Index-keyed reuse.** The reuse decoders write through `encoding.IndexedReusableRecord` (`SetNumericAt` / `SetNullFieldAt` / `SetWideFieldAt`, keyed by position in `Schema.Fields`) whenever the record implements it — `*processing.Record` does — and fall back to the name-keyed `encoding.ReusableRecord` through an allocation-free shim otherwise; a record implementing both is always driven index-keyed. The position is never looked up by name: the full-stride path counts it during its schema walk, the plan path reads `DecodeFields.Indices`, the bitmap uses the bit index. A hand-built `DecodeFields` without `Indices` still decodes (positions recovered on a slow path; a field absent from the reader's schema is `ENCODING_INVALID`). The index is only meaningful against the schema the `RecordReader` was built with — the stream and shard iterators build record and reader over the same schema. **Positional `Record`.** `processing.Record` stores values, null marks and wide values positionally (a `[]float64`, three presence bit-planes — has-value / null / has-wide — and sparse wide slots for decimal128 / `set_*` fields only), so an absent (projected-out) field stays distinguishable from a present zero. Name → slot resolution goes through a `recordLayout` built once per binding: the full layout is cached per schema under a WEAK key (dropped when the schema is collected) and shared by every record over it; a projected layout (`processing.BindRecords(schema, keep)`, built once per iterator / parallel-decode context) stores only the retained fields densely, so a buffered projected record costs O(retained), not O(schema width). A name with no slot — attribute labels, feature/window outputs, a schema field outside the projection — lands in lazily-allocated overflow maps with the former map semantics. The map-taking constructors (`NewRecord*`) convert on entry and do not alias the caller's maps; they are the slow path. Invariants a later change must keep: `ClearForRow` clears the null and has-wide planes (not values) — on the reuse arm it now runs only when run-skip cannot keep the previous row (below) — a `SetNumericAt` position outside a projected layout falls back to the overflow side by name, and `Record.*At` positions are valid only for a record built over the reader's schema (full layout) or a projection of it (a position past the schema panics rather than landing on another field). **Run-skip.** On the reuse arm the decoders skip rewriting fields whose on-wire bytes repeat the previous row — a cohort sorted by its parent key repeats the whole parent block across that parent's child rows. Self-activating: no declaration, no metadata, no format change, and the buffered arm (a fresh `Record` per row) never takes it. The contract is split: the READER (`internal/encoding/reader_runskip.go`) keeps the previous row's bytes (the whole stride on the full path; on the plan path the ASSEMBLED row — every `DecodeFields` group read into one buffer before decoding, which also puts the bitmap in hand first) and passes keep=true to `encoding.RunSkipRecord.BeginRunRow(token, keep)` only when that baseline was decoded, successfully, under the same decode shape (full, or the same `*DecodePlan` — `keep` must stay fixed per plan), into the same record; the RECORD answers true only when the token is the reader that began its previous row, it has the full identity layout (projected and duplicate-name layouts always refuse), and no schema field was written since by anything but that reader's `*At` writes — every name-keyed schema-field mutator (`Set`, `SetNull`, `SetWide`, attribute injection onto a schema name, the name-keyed `SetNumeric`/`SetNullField`/`SetWideField`, `copyStateInto`'s target, a wide value that fell to the overflow side) calls `resetRun()`, and `ClearForRow` zeroes the owner. Off-schema writes (attribute labels, feature outputs) do NOT withdraw the record. A kept row clears only the overflow null/wide marks and the `AllValues` cache; the field walk compares value bytes only (8 bytes at a time over runs of narrow fields) and rewrites a changed field in full; `settleNulls` then visits the fields null on either row, re-signalling null, or clearing it and restoring the value (`ClearNullAt`). Result: after every row the record is identical, accessor for accessor, to a full decode — sorted and scattered, full and plan, across `Reset` two-pass rescans and shard boundaries (a new reader per shard, so the first row of each shard repopulates everything). Backoff: comparing costs a mispredicted branch per field on data that does not repeat, so the reader tallies rewrites over every 32 kept rows and, when more than half the fields changed, decodes the next 1024 rows without comparing before probing again. Bench (`BenchmarkJoinShape_RunSkip`, synthetic 95-field 12.5x-fanout join, 100K rows, in-memory payload, arm64): sorted full-stride 783 → 500 ns/row (1.57x), sorted 4-field projection 117 → 96; scattered full 860 → 754 and projection 114 → 100 — both gains on scattered data come from caching the per-reader stride layout (`strideLayout`, formerly recomputed per row), and the run-skip mechanism itself costs +1.8–2.6% there against a same-commit decode that never compares (without the backoff it was +40–50%). Field-level continuation on that fixture: 0.71 sorted, 0.21 scattered. Gates: `TestJoinShapeRunSkip_WorkCounts` (`make test`, deterministic COUNTS through a counting record on a 5,000-row sorted/scattered pair — sorted keeps every row after the first and writes 1 − continuation of a full decode's values; scattered compares ≤ 5% of rows and never writes more than a full decode, the structural net-loss bound) and `BenchmarkJoinShape_RunSkip` (`-bench` only, against a same-commit no-compare arm on the production record: sorted full ≥ 1.15x, measured 1.31–1.34x arm64 / 1.40–1.42x amd64-under-Rosetta; sorted 4-field projection ≥ 1.00x, measured 1.03–1.06x / 1.09x — two of its four fields change almost every row, write fraction 0.45, just under the backoff's 50% trip; scattered REPORTED, not gated: full 0.97–0.99x on both arches, projection break-even). Against the true pre-run-skip commit the scattered decode is still faster (stride-layout cache), so the loss is relative to the same-commit no-compare decode only. **Grouped (`0x02`) reuse decode.** Over a parent-grouped cohort the reuse decoders do not expand rows (`internal/encoding/group_decode.go`; the logical-stream expansion stays for the map decoders and whole-row consumers — byte-layout.md, Parent groups). The physical row is read whole (one `io.ReadFull` of the physical stride, even under a plan — it is small), every group index bounds-checked, and fields are written at their LOGICAL positions. The decode shape (full, or one plan, keyed by `*DecodePlan` identity exactly as run-skip keys it) is compiled once into a selection: row fields taking a value write, row fields surfacing a null (the plan's bitmap segment surfaces every nullable field `keep` accepts), and per group the members taking each. Plain records (`ClearForRow`) and fresh buffered records get every selected field written. A `RunSkipRecord` gets `BeginRunRow(token, prevValid && sameSink && samePlan)` — the backoff does NOT gate keeping, because an unchanged group index is a certain hit; it only decides whether ROW fields are byte-compared (compare → rewrite changed, as run-skip) or rewritten wholesale this row, with the null settle honouring which it did. A retained group whose index equals the committed row's is skipped outright; a changed one writes its value members from the entry cache, then re-signals null / `ClearNullAt` from the new and old entries' null bits. Entry cache per group, budget `groupEntryCacheBudget` (8 MiB per reader per decode shape, split across value-writing groups, allocated on first changed index): WHOLE mode when the whole dictionary fits (every value member's float64 + decoded `Decimal128`, slot = entry), else DECIMALS mode (only decimal members, direct-mapped — decimal decode is the one expensive member decode; caching cheap members in a thrashing table measured SLOWER than decoding them), else none. Work-count gate (`make test`): `TestGroupedDecode_MemberWriteCounts` — member value writes == Σ changes × members exactly, a row with no index change takes zero member-field writes, sorted ≈ 1.3 member writes/row of 14 members, fresh records decode each entry once (fills == distinct entries); correctness: `TestGroupedDecode_CacheModesMatchFlat` (every cache mode × sorted/scattered × full/plans × fresh/run-skip × backoff on/off), `TestGroupedDecode_RunSkipRowFields`, `TestGroupedDecode_ProjectionSkipsUnretainedGroups`, `TestGroupedDecode_InterleavedPaths`, `TestGroupedDecode_PositionalRecordParity` (production `Record`). Bench `BenchmarkGroupedDecode_ParentWidth` (arm64, 60K rows, 29-field child block, 12.5x fanout, parent 10/40/80 fields; ns/row 0x01 → 0x02): reuse sorted full 444→379, 543→433, 722→520; reuse scattered full 483→481, 1225→649, 2223→1006; buffered full sorted 553→464, 1241→723, 2138→997; 4-field projection flat at ~58 (reuse sorted), ~80 (reuse scattered), ~130 (buffered) for every width vs 145–345 on 0x01. Before this (expansion, E3-S2) 0x02 was 3–30% SLOWER than 0x01 on every arm. Remaining width dependence is inherent: a changed entry must reach the record (scattered ≈ every row), a fresh buffered record takes every retained member, and in sorted order each entry is decoded once on first touch. Past the budget (DECIMALS mode, thrashing) scattered w80 measured 2005 ns/row at a 1 MiB budget — still under 0x01's 2223, the cost of bounded memory. **Typed wide storage.** Wide values live UNBOXED — a lazily allocated `[]encoding.Decimal128`, and set-mask words (1 per narrow rung, 2 for `set_u128`, 4 for `set_u256`) stored bit-for-bit in the spare CAPACITY of the value slice past its length (so a set costs no extra allocation or slice header; every range over the values sees only the slots) — and the reuse decoders hand set masks over through the optional `encoding.TypedSetRecord` (`SetNarrowSetAt` / `SetWideSetAt`), so decoding a set field allocates nothing (boxing a mask ≥ 256 or any `SetMask` into `any` cost one heap allocation per set field per row; `BenchmarkCrosstabWideSetFanout` buffered 100K rows: peak heap 63.3 → 53.0 MB, 3 fewer allocs per row). `WideValue` still returns the stored dynamic type exactly (`Decimal128` / `uint64` / `SetMask`); a value a slot cannot hold typed AND exactly (another dynamic type, a mask past the rung) stays boxed on the overflow side — never truncated. Decimal128 needs no typed twin: a single-pointer struct boxes for free; its decode cost is `big.Int` / `big.Float` work, not boxing. **Null drops the wide value.** `SetNullField` / `SetNullFieldAt` (the decoder's bitmap-null signal) clear the wide value as the map decoder's `delete` did, so a later `Set` on a decoded-null field never resurfaces the decoded mask or decimal; public `SetNull` keeps its documented asymmetry. **Duplicate field names** (nothing on import rejects a repeated column) share ONE slot per name, whose metadata is the first occurrence (`Schema.Field(name)`): the last occurrence decoded wins the value and wide value, a null on any occurrence marks the name null — exactly the former map-key behaviour. Bench (`BenchmarkBufferedRecordFootprint`, synthetic 95 fields × 200K rows): retained heap 3.99 KiB → 1.04 KiB per buffered record full-decode, 408 → 144 B under a 4-field projection; buffered decode 4.1 µs → 1.1 µs per record. Bit-packed grouping: any contiguous `u4`/`packed_bool` run stays grouped — if any member retained the whole group becomes one `DecodeFields` (unretained still decoded to keep cursor aligned, map writes suppressed); otherwise the run folds into one `SkipBytes{K}`. Null-bitmap whole-or-skip: bitmap decoded once when any nullable field retained; else single `SkipBytes{N: Schema.BitmapByteSize()}`. Extension operators without `FieldInputs` widen retained set to `*` (full-coverage plan). Bench: synth 200-field × 100K-row Process drops from ~1.07s to ~155ms (~7×, 14× fewer allocs) on a 4-field projection. Detail: this file (above) is the projection/decode-plan home; `docs/src/internals/extension-points.md` (FieldInputs hook) carries the extension side, and CLAUDE.md "Byte-layout invariants" (Projected buffered decode) the contract summary. `skills/cohort-schema-design.md` deliberately carries NO decode-plan section — it is the schema-authoring surface, and a projection section there would push an already-over-budget skill further over for prose that belongs beside the execution modes.

## Parallel Compose

`pulse.ComposeParallel`, `pulse api compose --parallel N`. Bounded worker pool over `ComposedRequest`. Order-preserving by slot index. `ComposeOptions{MaxWorkers, PerRequestTimeout, FailFast}` (FailFast defaults true).

Post-slot-barrier Compose-overlay fold (`internal/service/compose_overlay.go` ⇒ `processing.ApplyComposeOverlaysWithRequests` in `processing/overlay_compose_dispatch.go`; the bare `ApplyComposeOverlays` is the nil-requests, nil-extensions delegate kept for embedders): the orchestrator invokes `s.applyComposeOverlays(ctx, req, requests, responses)` once every slot has produced a finalised `*Response` and BEFORE the response is returned. Operates EXCLUSIVELY on `*Response` objects; per-slot `Responses[i].Overlays` is left UNTOUCHED.

FailFast handling: when `FailFast=true` (default) AND any slot fails, the orchestrator returns the first observed error WITHOUT invoking the overlay hook. FailFast=false routes slot failures through `SERVICE_INTERNAL` which also skips the hook. Empty / nil `req.Overlays` short-circuits with no allocation (overlay-free Compose JSON is byte-identical to a request that omits the slot entirely).

Per-kind handlers replace the chassis stub (`applyComposeStub`) for every Compose-only kind that has shipped. The six crosstab-shape COMPOSE handlers (`OVERLAY_INDEX_VS_REF`, `OVERLAY_DELTA_VS_REF`, `OVERLAY_PROP_Z_CELL`, `OVERLAY_T_CELL`, `OVERLAY_CHISQ_VS_REF`, `OVERLAY_RANK`) are wired today; remaining Compose-only kinds dispatch through the chassis stub until their handler lands. All buffered — streamable subset is empty across COMPOSE by construction.

Request-shape gates on the COMPOSE host. Everything else in this fold reads `*Response` only, but `processing/overlay_compose_partition.go` needs the AUTHORED request: the `OVERLAY_PROP_Z_PANEL` within-prefix slab gate turns on each slot's declared `Crosstab.Rows` grouper types, and a materialised `MatrixPayload` carries its row KEYS but never the grouper that produced them — a fan-out row axis is invisible downstream of execution. So `service.(*Service).applyComposeOverlays` passes the per-slot requests and the `*ExtensionRegistry` into `ApplyComposeOverlaysWithRequests`, and the gate runs per spec INSIDE the dispatch loop (after reference/target resolution, before the key-set and schema walk — mirroring predict's Gate 3b position) rather than in the handler, because the `composeOverlayHandler` signature must stay `(spec, reference, targets, refIdx, targetIdxs)`. The gate declines whenever an earlier refusal is due, so the cap still fires first. An embedder calling the bare `ApplyComposeOverlays` gets no request-shape gate — the documented counterpart of the exported `ApplyOverlaysWithExtensions` bypass on the MATRIX host.

Slot label resolution: `applyComposeLabelDefaults` synthesises `request_<index+1>` for empty `Request.Label`; `ApplyComposeOverlays` builds a `Label → Index` lookup. The dedicated error codes `PULSE_OVERLAY_REFERENCE_UNKNOWN` and `PULSE_OVERLAY_TARGET_UNKNOWN` are pending — the chassis currently falls back to `PULSE_OVERLAY_REF_UNKNOWN` with a `which` Detail. See `skills/compose-requests.md`.

## Parallel shards

`pulse.Options.ShardWorkers`, default `0` ⇒ `runtime.NumCPU()`. Bounded per-shard worker pool inside `Process` when cohort is a shard archive. Reducer engages only when every operator is mergeable per `processing.CanMergeRequest` (built-ins only; non-decimal targets; no windows/features/regressions/tests/two-pass). Non-mergeable falls through to serial `shardIter`. Associative+commutative byte-equal vs serial; Welford within ULP via Chan-Welford. Surface: `internal/service/shard_reduce.go`, `processing.MergeableAggregator`, `types.AggregationType.Mergeable()`. See `skills/cohort-schema-design.md` (Sharded).

**`Response.Components` is part of that parity, not an exception to it.** Both reducers share `shardPartial` / `mergeShardPartials` / `finalizeMergedPartial`, and `shardPartial` carries per-slot floor tallies (`aggN` / `aggNNull`) and `processing.FilterPassCounters` alongside the operator state, all folded slot-wise on merge. The per-operator `Operator` map is read off the MERGED aggregator — the arms fold operator STATE, so no components-level merge exists or is needed, and the `Mergeable` / `Partial` / `None` classes need no second gate here because `CanMergeRequest` already refused anything whose state cannot fold. Emitted: `Aggregations` (ungrouped only — the grouped arm matches serial, which emits none), `Filterers`, `Run`, and `Groupers`: each worker builds its own grouper instance, and those instances' live bucket state folds through `processing.MergeableGrouper` (implemented by exactly the `GroupType.Mergeable()` set), so the merged grouper's `Components()` is the serial one's. **The grouped arm has no emission tail of its own** — it hands the merged buckets and grouper to `processing.FinalizeGroupedStream`, the tail the serial streaming-grouped path uses (row order incl. include order, `Request.Sort`, Components, SERIES overlays), and keys records through `processing.GroupKeyer` (multi-key fan-out for `GROUP_SET_PER_ELEMENT`). A private copy of that tail used to drop `Sort`, `Overlays`, include order and `Groupers`, and refused `GROUP_SET_PER_ELEMENT` outright. `Run.ShardCount` is the archive's shard count on BOTH arms — the serial exit stamps it in `Service.Process` (`stampShardCount`) because the processing layer has no shard concept. Counting presence for the floor goes through `processing.FieldPresent`, never `Record.NumericValue`, or a set column reads as entirely null. Parity gates: `TestShardWorkers_AggregationComponentsParity`, `TestShardWorkers_FiltererComponentsParity`, `TestDecodeWorkers_ComponentsParity`, `TestShardWorkers_ComponentsParity_GroupedAndFlatArchives` (whole `{data, components, overlays}` document, flat + grouped `0x02` archives), `TestDecodeWorkers_GroupedAnswersParity`, `TestMergeableGrouper_MergedComponentsEqualSerial`.

## Parallel buffered Process

`pulse.Options.DecodeWorkers`, default `0` ⇒ `runtime.NumCPU()`. Bounded per-segment worker pool inside `Process` for single-file (non-shard) cohorts. Engages only when `service.canParallelDecode` accepts — `DecodeWorkers != 1`, `recordCount >= service.parallelDecodeRecordThreshold` (currently `100_000`), single-file (sharded routes through `ShardWorkers`), `resolveRealPath` succeeds (mmap available), `processing.CanMergeRequest(req, schema)` is true. Ineligible falls through to serial `scanIter`. Components parity is the ShardWorkers paragraph above verbatim — same `shardPartial`, same merge, same emission set; `ShardCount` stays 0 because a single-file run is not a shard run.

Crosstab is intentionally NOT exercised today — `validateCrosstabSpec` requires `req.Aggregations` empty so crosstab requests always fail `CanMergeRequest`. This infrastructure benefits future non-crosstab buffered Process calls.

Segments stride-aligned at record boundaries over the mmap'd record region; same `DecodeFields`/`SkipBytes` plan shared read-only across workers; each worker owns a `shardPartial`; partials fold in worker-index order via `mergeShardPartials` + `finalizeMergedPartial`. Byte-equal vs serial; Welford within ULP via Chan-Welford. Surface: `internal/service/parallel_decode.go`, `internal/service/parallel_reduce.go`. See CLAUDE.md "Execution modes (pointers)" (Parallel buffered Process) for the knob and the threshold; the mechanics above are the detail home.

## Filter precompute (grouped cohorts)

Over a parent-grouped (`0x02`) cohort a filter whose every input field is a member of ONE group has at most `entry_count` distinct answers, whatever the row count or order. `processing/filter_precompute.go` evaluates it once per dictionary ENTRY into a two-bit-per-entry verdict table (unknown / fail / pass / per-row) and turns each row's verdict into a bit test on the row's entry index. On the effort's reference shape that is ~109K evaluations instead of ~1.4M. Derived at read time, never persisted; opt-out process-wide with `processing.SetFilterPrecompute(false)` (benchmarks / A-B only — it changes speed, never a result). Diagnostics: `processing.FilterPrecomputeStats()` (tables built, entry evaluations, table bytes, ineligible pairs) — only table builds and entry evaluations touch its atomics, never the per-row path.

**Seam.** The wrap is at the `FilterFunc`: `Processor.buildFilterFuncs` and `processing.BuildFilters` wrap each ELIGIBLE filterer (grouped build schema only; an ungrouped schema gets the builder's `FilterFunc` back unchanged, so a `0x01` cohort pays nothing). `applyFilterPass` is untouched, so `{n_in, n_out, n_null_input}` are the per-row counts by construction: `n_in` / `n_out` follow the verdict, and `n_null_input` still reads the record's own null state (`Record.IsNull`, now one name resolution instead of three). **The entry index** reaches the record through `encoding.GroupIndexRecord` (`SetGroupIndices(schema, idx)`), called by the grouped reuse decoder after every row on the full, plan, plain-sink and run-skip paths (`nil` for a plan that decodes nothing). `*processing.Record` stores the indices bit-exactly in the tail of `vals` past the set-mask words (`recordLayout.nGroups`; no allocation, none at all for an ungrouped schema) and reports them through `Record.GroupIndex(g)` only while valid: `ClearForRow` and `resetRun` — every schema-field mutation that is not a decode write — withdraw them, and indices addressing another schema than the record's own (by identity; the decoder passes the GROUPED schema, not its `Logical()` view) are refused. A feature or attribute rewriting a member's name therefore sends that row per-row, never to a stale verdict.

**Eligibility** (`precomputeInputs`, then per record schema `precomputeGroup`): every built-in filterer on its `Field`; `FILTER_EXPRESSION` when its AST's free identifiers are all fields and every call is pure — expr-lang built-ins except `now()`, the set built-ins, and `lookup()` only when every lookup table is a static `Rows` map. Embedder `ExprFunctions` (even one shadowing a built-in), `let` names, `$env` and off-schema columns disqualify. Extension filterers never qualify — a registration declares no purity and `FieldInputs` does not prove statelessness. Inputs must resolve to unique field names in ONE group: a group member mixed with a row field, or two groups, stays per-row (the verdict space is the product; there is no small table). **Evaluation is lazy**: an entry is evaluated the first time a row carrying it reaches the filter, so the work is the DISTINCT entries reached — never more than the per-row count, even behind a selective earlier slot. An entry whose evaluation ERRORS is marked per-row and re-evaluated on each of its rows, so an error surfaces on exactly the row the per-row path raises it on, and never when no such row gets there. Per-entry evaluation decodes only the filter's input members (`internal/encoding.NewGroupEntryDecoder(schema, g, fields)`), not the whole entry.

**Arms.** Routed: streaming Process (reuse record), buffered and projected Process (fresh record per row through `ReadRecordReusedWithPlan`), fused crosstab and buffered crosstab, parallel buffered Process (one `FilterFunc` set — and so one verdict table — per worker; bounded by workers × entries), Compose (per slot), ProcessChain stage 0, `FacetSchema`, and `FilterToFile` (its map decode forwards `RecordReader.GroupIndex` into `Record.SetGroupIndices`; `TestGroupedCohort_FilterToFilePrecompute`). Per-row fallback (correct, not precomputed): every other map-decode consumer — `Lookup`, the shard reducer, the projection-without-plan fallback — plus joined records (`Request.Joins`), ProcessChain stages ≥ 1 (synthesised ungrouped cohorts) and any extension filterer. Shard archives refuse grouped shards today; the tables are keyed by the record's schema pointer (the shard's own dictionary), so grouped shards need no change here beyond the decoder handing over that shard's schema. Gates: `TestFilterPrecompute_ParityEveryFilterer` (all built-in filterers, both reuse arms, verdicts + components vs per-row and vs `0x01`, evaluation count = distinct entries, ≥10x at 12x fanout), `TestGroupedCohort_FilterPrecomputeParity` (facade arms, exact entry-evaluation counts), `TestFilterPrecompute_ParallelDecode`, `TestGroupedDecode_ReportsGroupIndices`, `TestRecord_GroupIndexWithdrawnByEveryMutator`. Bench: `BenchmarkFilterPrecompute` (`internal/service/`).

## Compile-once expressions (`FILTER_EXPRESSION`, `ATTR_FORMULA`)

Both compile their expr-lang program ONCE per build (`processing/expr_program.go`), never per row. **Prototype**: every schema field declared with the Go type `Record.AllValues` gives it (`exprValueType` — float64; string for a dictionary categorical; `[]string` for a dictionary set; `Decimal128` / `uint64` / `SetMask` otherwise), so build-time type checking equals the old per-row check on a row with every field present — same program, same results, same `PROCESSING_RUNTIME` "compiling … expression" error, now raised by `BuildFilters` / `buildFilterFuncs` / the attribute build (`bindAttribute` → `prepare`) before any row. A name the schema cannot declare (feature output, earlier attribute label) DEFERS the compile to the first record, against prototype + that record — the old first-row env — then caches it. **Env**: per row, only the named fields (`Record.exprValue`, pinned to `AllValues` by `TestRecord_ExprValueMatchesAllValues`) in a pooled map; `$env`, a deferred compile, or a record already carrying its `AllValues` map take the whole map. **Null**: a null field is absent → reads as nil. Rows with every referenced field present run the typed program; a null-input row runs an untyped twin (every name `any`, compiled lazily once) so nil follows expr-lang's nil rules uniformly (`== nil` true, `==` false, `!=` true, `in` false, `??` substitutes; ordering / arithmetic / nil-rejecting functions error). `FILTER_EXPRESSION` reads a null-input evaluation error (or nil result) as UNKNOWN → row dropped; `ATTR_FORMULA` raises it ("evaluating formula expression"). `now()` still evaluates per row. **Concurrency**: `*vm.Program` is immutable and `expr.Run` builds a VM per call; the lazy compiles sit behind a mutex + atomic publish. Gates: `TestExprProgram_CompilesOncePerBuild` (`processing.ExprCompileCount` deltas independent of row count), `TestExprProgram_MatchesPerRowCompile` (per-row-compile oracle), `TestExprValueType_MatchesAllValues` (every field type × every decode path), `TestExprFilter_NullSemantics`, `TestExprProgram_ConcurrentRuns` (`-race`). Bench `BenchmarkExprCompileOnce` (95-field join fixture, 100K rows): filter pass ~8.7 µs → ~0.14 µs/row, end to end ~24 → ~2.1 µs/row (0x01), ~24 → ~1.1 (0x02).

## ProcessChain

`pulse.ProcessChain`, `pulse_process_chain`, `pulse api process-chain`. Source-rooted linear chain. Stage 0 against `ChainRequest.Cohort`; subsequent stages receive prior `Response.Data` as synthesised in-memory cohort (grouper keys → categorical_u32, aggregator outputs → f64). Mergeable-only at v1 (`CanChainRequest` requires `CanMergeRequest` AND scalar aggregator emission — rejects `AGG_FREQUENCY`/`AGG_MODE`). Failures: `PULSE_CHAIN_NOT_MERGEABLE`, `PULSE_CHAIN_EMPTY`. Predict equivalent: `descriptor.ValidateChain`. Surface: `types/chain.go`, `processing/chain.go`, `internal/service/chain.go`, `internal/descriptor/chain.go`, `internal/descriptor/capabilities_chain.go`.

Dual-slot overlay design: per-stage overlays ride `ChainRequest.Stages[i].Request.Overlays`; whole-chain overlays ride `ChainRequest.Overlays []*ChainOverlaySpec` and produce `ChainResponse.Overlays []*OverlayLayer` after every stage finalises. `ChainOverlaySpec` carries `Ref StageRef` + `Target StageRef`. Whole-chain barrier: `service.applyChainOverlays` runs after the stage loop, dispatching through `processing.ApplyChainOverlays`. Per-stage `Stages[i].Overlays` is left UNTOUCHED. The dedicated error codes `PULSE_OVERLAY_TARGET_UNKNOWN`, `PULSE_OVERLAY_REFERENCE_UNKNOWN`, and `PULSE_OVERLAY_CHAIN_STAGE_SHAPE_DIVERGENT` are pending follow-ups. See `skills/process-chain.md`.

## Pushdown hash join

`Request.Joins []*JoinSpec`. v1 = exactly one inner join per Request (`PULSE_JOIN_TOO_MANY`, `PULSE_JOIN_KIND_NOT_IMPLEMENTED`); in-memory build (no spill; `PULSE_JOIN_SPILL_DIR` + `PULSE_JOIN_MAX_MEMORY_BYTES` reserved). `JoinedSchema(left,right,spec)` produces `left.Fields + right.Fields` with optional `spec.As` prefix; non-prefixed collisions → `PULSE_JOIN_FIELD_COLLISION`. ## Crosstab

`Request.Crosstab`, `Response.Crosstab`. Composes existing groupers + aggregators across a row × column axis grid; reshape, margin recompute, normalization layered on top. Multi-grouper axes recursively partitioned. Margins always recomputed from raw rows for correctness — `AGG_MEDIAN` row margin equals the standalone single-axis median, NOT the median of cell medians. Per-aggregator classification at `AggregationType.MarginReducibility` (`summable` / `mean_reducible` / `independent` / `recompute`; `independent` = the operator keeps its own row/column/grand accumulator, so the margin — a union, not a cell sum — is exact after one pass and the fused gate admits it). `shape: matrix` (default) populates `Response.Crosstab.Matrix`; `shape: long` emits tuple rows on `Response.Data` with margin rows tagged `_margin=row|column|grand`. Inherently buffered except `shape=long` + no margins + `normalize=none`.

Normalization layering: `normalize_level` truncates the same axis as `normalize`; `normalize_within` fixes a prefix of the OPPOSITE axis. Both compose.

Auxiliary margin-only aggregations (`margin_aggregations`) are computed by `processing.(*Processor).computeAuxMargins` (`processing/crosstab_margin_agg.go`) alongside the cell aggregator's own three margin blocks, and MUST match what the fused walk accumulates for the same request — dispatch picks the arm on request shape and nothing in `Response` reports which ran. The admission rule is the same one stated under Fused crosstab: a record contributes to an auxiliary only if it contributed to a CELL, so a null cell field and an axis key an `Include` excluded are absent from every auxiliary slot while the cell's own margin loops beside them still count both. The buffered implementation resolves each axis's membership ONCE into pointer sets and then walks each margin slot on its own axis — deliberately NOT the `(rkey, ckey)` cell buckets, which are admitted-by-construction but would fold a record into a ROW auxiliary once per COLUMN it landed in, M times under a `GROUP_SET_PER_ELEMENT` fan-out, where fused folds it once per distinct row key. Each slot's admitted subset is shared across the auxiliaries in it and rides `runCellAggregation`, so the `{n, n_null}` floor is over ADMITTED records and decimal128 dispatch comes for free; a slot admitting nothing carries no figure at all, mirroring the fused path's unconstructed accumulator. An auxiliary naming an unknown operator is refused up front, matching `NewFusedCrosstabState`. Partial-depth and cross-axis margins get no auxiliary on either path: those are normalization denominators, and an auxiliary is never a denominator. `TestCrosstab_BufferedAuxMarginMatchesFused` drives one request down both arms.

Buffered record set automatically projected via `service.applyCrosstabProjection` (extends `processing.NeededFields` to walk `Crosstab.Rows/Columns/Cell` + `req.Labels[].Field` + `AGG_WEIGHTED_MEAN/RATIO` Cell.Params); wide-cohort crosstab cost is `O(|referenced|)` not `O(|schema|)`; forced on regardless of `opts.DisableProjection`. Capability: `Manifest.Crosstab`. Predict gate: `descriptor.validateCrosstab`. See `skills/crosstab-guide.md`.

## Fused crosstab

`processing.CanFuseCrosstab`, `processing.FusedCrosstabState`, `processing.StreamableGrouper.KeyFor`, `processing.MultiKeyStreamingGrouper.KeysForRow`. In-decode streaming alternative to the buffered Crosstab orchestrator. When the gate accepts, `service.processCrosstab` short-circuits `materializeRecords` + recursive `PartitionByAxis` and drives a single streaming pass that interns row/col composite axis keys on first sight and folds each filter-passing record into the matching cell / row-margin / column-margin / grand-margin / cross-axis-margin online aggregator. Memory drops from `O(filtered records)` to `O(cells + margins)`.

Gate composition (`CanFuseCrosstab`): mergeable + non-recompute scalar cell aggregator; every row/col grouper constructs AND implements one of the two per-record keying interfaces — `StreamableGrouper.KeyFor` (one bucket per record: CATEGORY/RANGE/ROUNDED/DATE/SET_VALUE — `GROUP_DATE` is admitted here even though `GroupType.Streamable()` is false at the Process layer) or `MultiKeyStreamingGrouper.KeysForRow` (N buckets per record: `GROUP_SET_PER_ELEMENT`); no tests; no features; no `ATTR_FORMULA`; no `FILTER_EXPRESSION`; no decimal128 cell field; no extension operator without `FieldInputs` hook; every `margin_aggregations` entry mergeable and non-decimal (an auxiliary rides the same per-record `UpdateRow` walk, so it must be online — declining sends the request to buffered rather than dropping the auxiliary, which would return a margin with the requested figure silently missing). An auxiliary's `MarginReducibility` is deliberately NOT consulted: the classification answers "can this aggregator's margin be derived from its CELLS", a question an auxiliary does not have — it has none, and both paths give it its own row / column / grand accumulator fed record by record, so every auxiliary is `independent` in role whatever its declared class. `GROUP_QUANTILE` implements neither keying interface and is the only grouper that forces buffered.

`Request.Overlays` is explicitly NOT an exclusion. Overlays decorate a finalised response and consume no records, so `RunCrosstabFused` folds them after `state.Finalize()` through the same `processing.applyOverlaysToResponse` hook the buffered exit calls — cells, `Components`, `Overlays` and `Warnings` are byte-identical across arms. `types.OverlayStreamability` is unchanged (every kind still `false`): a post-`Finalize` fold is not an in-pass computation. The surviving reason an overlay-carrying crosstab may still buffer is the CELL-AGGREGATOR arm — `AGG_WELFORD` is non-mergeable, so `OVERLAY_PAIRWISE_WELCH_T` / `OVERLAY_PAIRWISE_TWO_MEANS_Z` (which read its `{n, mean, variance}` triple off `CellComponents`) stay buffered; `TestCrosstabWelfordCell_StaysBufferedWithCorrectOverlays` pins it. `OVERLAY_PAIRWISE_PROP_Z` over an `AGG_WEIGHTED_MEAN` cell fuses.

Multi-key axis routing: `fusedAxisKeyer.derive` returns the cartesian product of each position's key set plus deduped per-depth prefix sets, so one record updates every accumulator the buffered path would touch, exactly once per distinct key at that depth. Fan-out is legal at any axis position, on either or both axes, several positions per axis. Consequence (deliberate, mirrors buffered): margins are NON-ADDITIVE under fan-out — a record selecting 3 labels counts 3× across row margins but once in the grand margin, so row margins do not sum to the grand total.

`normalize_level` denominators gate on PREFIX depth, not full-axis resolution: the buffered denominator is `PartitionByAxis(spec.Rows[:level+1], filtered)`, which never looks past `level`, so a record whose DEEPER axis positions are null still feeds it. Fused now matches. Releases before this alignment returned a different `normalize_level` denominator on the fused arm whenever a nullable grouper sat ahead of the level — a numbers-changing fix, not a no-op.

Auxiliary margin accumulation (`FusedCrosstabState.rowMarginAux` / `colMarginAux` / `grandMarginAux`, one `auxMarginAccumulator` per declared auxiliary per occupied slot, instance built on first admission) observes a DIFFERENT record admission from the cell's own margins beside it, and that is the point of the slot: a record contributes to an auxiliary only if it contributed to a CELL. Three exclusions follow — a null cell field, an unresolved row key (including one a grouper `Include` excluded, which surfaces as `ErrGrouperKeyNull`), and an unresolved column key. The cell aggregator's own margins are untouched and still count every filter-passing record with a non-null axis key on that axis: measured, a `rows=[brand]` crosstab returns byte-identical column margins with a two-brand `Include` and with none at all. Reusing that for an auxiliary would make the figure cohort-wide and metric-agnostic. Getting it wrong is SILENT — every number still renders, the base is merely wrong. Slots are allocated only for the margins the spec asks for, and nothing at all when `margin_aggregations` is absent. The figures are accumulated and held; exposing them on `Response.Components` is a later change.

Axis-key nullity is per-axis: a record with non-null row key + null col key still updates the row margin and the grand margin. Cells only land at intersections where both axes resolved. Margins recompute from raw rows so byte-for-byte equivalent to buffered RunCrosstab. Map-valued cell aggregators paired with `normalize != none` are rejected (`PULSE_CROSSTAB_NORMALIZE_MAP_VALUED`). Disable via internal `disableCrosstabFusion` toggle.

Perf: synth 200-field × 100K-row bench ~0.51 × buffered (~47% faster); canonical 1M-row real-cohort bench 2.57s vs buffered crosstab baseline 3.82s (~32% faster). **Quote peak heap, never `B/op`.** The combined fan-out + overlay bench (`BenchmarkCrosstabSetFanoutOverlay`) measures `peak-heap-MB` 8.8× / 18.6× / 20.8× better on fused at 25k / 100k / 400k rows, while `B/op` moves only ~30% — `B/op` is cumulative bytes allocated and cannot see retention, so quoting it alone understates the win by ~20×. `allocs/op` is HIGHER on fused (the fan-out keyer builds a key tuple per fanned key); expected, not a regression. See `skills/crosstab-guide.md` (Fused mergeable path) + `skills/grouper-design.md` (Fused crosstab eligibility).

## Facet endpoints

`pulse.Facet(ctx, path, field)` simple distinct-values (categorical fast path through dict, numeric streams file). `pulse.FacetSchema(ctx, *FacetRequest)` rich multi-field — counts (sorted desc by count, ties asc by value), null tallies, Welford online numeric stats, optional `NumericPercentiles` (forces buffered per-field sort), optional `IncludeHistogram` with caller-supplied `HistogramRange` (single-pass), optional `DiscreteTopK` (`TruncatedAt` warning), optional `AdditiveFields` contribution counts, optional `FacetRequest.Overlays []*OverlaySpec` carrying the four FACET-host overlay kinds (`OVERLAY_INDEX_VS_POP` / `OVERLAY_ZSCORE_VS_POP` / `OVERLAY_CHISQ_VS_POP` / `OVERLAY_KS_VS_POP`).

Streamability mixed: INDEX_VS_POP / ZSCORE_VS_POP are streamable per `types/overlay_streamability.go` but run at the same buffered exit since FacetSchema is structurally buffered today. ## Overlays

`Request.Overlays []*OverlaySpec`, `Response.Overlays []*OverlayLayer`. Additive post-result decorations attached to an already-computed base result. Each spec produces one `OverlayLayer` in matching slot order; layers carry the host-shape payload and never mutate the base payload — overlays are read-only siblings keyed to host coordinates. Catalog at `types.AllOverlayKinds()` + `types.OverlayStreamability`; per-kind capability at `descriptor.overlayCapabilityFor` (surfaced on `Manifest.Overlays`).

Buffered-by-default rule: `OverlayStreamability[kind] == false` for every kind in the initial catalog. The overlay family covers index/share/delta/cumulative/rolling shapes across cell/row/column/total scopes. Forward-compat: `Request.Overlays` is omitempty so `CanonicalHash`/`Request.Hash` stay byte-identical for requests that omit the slot. A crosstab carrying `Request.Overlays` no longer falls back to buffered — the MATRIX fold runs at the fused exit through the same hook (see "Fused crosstab" above); the flag table stays all-`false` because that fold is post-`Finalize`, not in-pass. Failures: `PULSE_OVERLAY_KIND_UNKNOWN`, `PULSE_OVERLAY_SCOPE_UNSUPPORTED`, `PULSE_OVERLAY_REF_INCOMPATIBLE_WITH_SHAPE`, `PULSE_OVERLAY_HOST_NOT_SUPPORTED`, `PULSE_OVERLAY_LEVEL_OUT_OF_RANGE`.

**Level / Within composition.** The share / index / delta / zscore family honours `OverlaySpec.Level` (same-axis prefix truncation) and `OverlaySpec.Within` (opposite-axis prefix fixing). `Level=0, Within=0` preserves the leaf-margin denominator and is byte-identical to the no-Level/no-Within handler output. Composition mirrors the buffered crosstab `normalize_level` / `normalize_within` semantics (byte-equivalent for summable cell aggregators) and reuses the same prefix-key helpers (`processing.SameAxisPrefixDepth` / `processing.OppositeAxisPrefixDepth` / `processing.AxisKeyPrefix`). Out-of-range slots fire `PULSE_OVERLAY_LEVEL_OUT_OF_RANGE` at both predict and runtime; the χ² / Fisher inferential family rejects non-zero values with the same code (implicit-margin contract).

**Grouped Process wiring.** The SERIES-host overlay fold (`processing.ApplyOverlaysSeries`) attaches at the grouped Process exit in both `processing/processor.go` paths (buffered + streaming). No-op when `req.Overlays` is empty, when `req.Crosstab` is set, or when the request has no `Groups`. Mixed-mode downgrade rule: a Request mixing streamable overlay kinds with non-streamable kinds forces the entire request to the buffered path via `processing.canStreamOverlays`.

**FACET-host wiring.** The FACET-host overlay fold (`processing.ApplyOverlaysFacet`) attaches at the FacetSchema buffered exit in `internal/service/facet_rich.go` via `service.applyFacetOverlays`. `FacetRequest.Overlays []*OverlaySpec` is the FACET-host slot; the four FACET-host kinds MUST attach there, not on `Request.Overlays` — the Request-host validator rejects FACET kinds with a `PULSE_OVERLAY_REF_INCOMPATIBLE_WITH_SHAPE` redirect message. Per-spec host-field selection via `OverlaySpec.Params["field"]`. Service-layer wiring recurses `FacetSchema` against `Ref.Population.Cohort`, caches per-cohort+field tuples. `FacetResult.Overlays []OverlayLayer` is omitempty. Predict equivalent: `descriptor.ValidateFacetOverlays` — per-kind Ref / Scope / Level / Within gates; CHISQ rejects numeric hosts; KS rejects categorical hosts. Predict surface: `FacetValidationResult.OverlaysApplied` + `FacetValidationResult.OverlayCost` mirror the Request-host shape. Manifest: `Manifest.Facet` carries `SupportsOverlays: true` + `SupportedOverlayKinds: ["OVERLAY_CHISQ_VS_POP", "OVERLAY_INDEX_VS_POP", "OVERLAY_KS_VS_POP", "OVERLAY_ZSCORE_VS_POP"]`.

**CHAIN-host wiring.** The CHAIN-host overlay fold (`processing.ApplyChainOverlays`) attaches at the post-stage-loop barrier inside `service.ProcessChain` (`service.applyChainOverlays` hook). Dispatcher chassis ships stub handlers for the two whole-chain kinds (`OVERLAY_INDEX_VS_STAGE`, `OVERLAY_DELTA_VS_STAGE`) so the round-trip path is exercised end-to-end without per-kind arithmetic; per-stage `Stages[i].Overlays` is left UNTOUCHED.

**FORMULA kind.** `OVERLAY_FORMULA` is a caller-supplied expression-driven projection compiled ONCE per spec via `expr-lang/expr` (the same evaluator that backs `ATTR_FORMULA` / `FILTER_EXPRESSION`) and run per cell / entry / scalar against a per-host-shape variable namespace (MATRIX: `cell` / `margin_*` / `sd_*`; SERIES: `value` / `total` / `prior` / `baseline`; SCALAR: `value`; Compose hosts add the dotted `slot.<label>.{cell|value}` namespace). Inherently buffered across every host shape. `pulse.Options.Extensions.ExprFunctions` flow through the evaluator (functions widen the function surface only; the variable surface stays fixed per-host-shape). Failures: `PULSE_OVERLAY_FORMULA_PARSE_ERROR` / `PULSE_OVERLAY_FORMULA_TYPE_MISMATCH` / `PULSE_OVERLAY_FORMULA_INVALID_IDENT`.

Surface: `types/overlay.go`, `types/overlay_streamability.go`, `processing/overlay.go`, `processing/crosstab.go` (hook), `processing/crosstab_normalize.go` (shared prefix helpers), `processing/overlay_series.go` (SERIES fold engine), `processing/overlay_series_response.go` (grouped Process wiring + mixed-mode gate), `processing/overlay_facet_dispatch.go` (FACET dispatch table) + `processing/overlay_facet_pop.go` (FACET population resolver), `processing/overlay_chain_dispatch.go` (CHAIN dispatch table + StageRef resolver), `internal/descriptor/overlay.go`, `internal/descriptor/overlay_facet.go`, `internal/descriptor/capabilities_overlay.go`, `internal/descriptor/capabilities_facet.go`, `internal/descriptor/manifest.go`, `internal/descriptor/predict.go`, `internal/descriptor/facet.go`, `internal/service/facet_overlay.go`, `internal/service/chain.go` (`applyChainOverlays` hook), `types/facet.go`, `types/chain.go`. See `skills/overlay-system.md`.
