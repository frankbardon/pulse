# Execution modes — full prose

CLAUDE.md keeps one-line pointers; this file is the in-depth wiring detail per mode. Skill docs are the canonical longform — this file is the "everything tightly cross-referenced in one place" view for engine work.

## Streaming Process

`pulse.ProcessStream`, `pulse api process --stream`. Four orchestrator modes — single-pass, grouped, two-pass attributes (Welford-Pébaÿ), streaming features. Forced-buffered: median/percentile/zscore aggregators, `ATTR_PERCENTILE`, `GROUP_QUANTILE`/`GROUP_DATE`, window operators, decimal paths, tier-1 tests with groupers/features/two-pass, all tier-2 tests. NDJSON one row per line. See `skills/streaming-and-watching.md`.

## Projected buffered decode

Per-request field projection on the buffered decode iterator is **default-on** — output-transparent (byte-identical result, only faster and lighter per record). Opt out with `pulse.Options{DisableProjection: true}` or the `--no-project` CLI flag on `pulse api process` (v1: `pulse api process` only; `process-chain` / `compose` do not expose it yet). `pulse.Options.ProjectBufferedFields` is retained but deprecated — a harmless no-op; use `DisableProjection` to force full-record decode. Wiring: `svc.SetProjectBufferedFields(opts.ProjectBufferedFields || !opts.DisableProjection)`. `processing.NeededFields(req, schema, ext)` walks every request slot — Aggregations, Attributes (incl. expr-AST identifiers via `expr-lang/expr/parser` + `expr-lang/expr/ast` for `ATTR_FORMULA` / `FILTER_EXPRESSION`), Filterers, Groups, Windows, Features, Tests, Regressions, Sort.Field, and the whole Crosstab block (Rows, Columns, Cell, **MarginAggregations**). It also reads the built-in `Params` that NAME a field but do not live on the operator struct (`addAggParamFields`: `distinct_by`, `weight_field`, `numerator_field`, `denominator_field`; plus `stratify` / `target` on the two feature ops). A missed slot or a missed param is SILENT — the field is decoded onto no `Record`, `NumericValue` answers `ok=false` on every row, and the operator publishes a confident zero with `n_null` equal to the full admitted count. The iterator turns the retained set into an `encoding.DecodePlan` via `Schema.BuildDecodePlan(retained)` (cached per-iterator); per-record hot path walks the plan via `RecordReader.ReadRecordWithWidePlan`. Plan segments: `SkipBytes{N}` (one `Seek` / `io.CopyN` discarding N bytes, coalescing contiguous unprojected non-bit-packed runs) and `DecodeFields{Fields}`. Bit-packed grouping: any contiguous `u4`/`packed_bool` run stays grouped — if any member retained the whole group becomes one `DecodeFields` (unretained still decoded to keep cursor aligned, map writes suppressed); otherwise the run folds into one `SkipBytes{K}`. Null-bitmap whole-or-skip: bitmap decoded once when any nullable field retained; else single `SkipBytes{N: Schema.BitmapByteSize()}`. Extension operators without `FieldInputs` widen retained set to `*` (full-coverage plan). Bench: synth 200-field × 100K-row Process drops from ~1.07s to ~155ms (~7×, 14× fewer allocs) on a 4-field projection. Detail: this file (above) is the projection/decode-plan home; `docs/src/internals/extension-points.md` (FieldInputs hook) carries the extension side, and CLAUDE.md "Byte-layout invariants" (Projected buffered decode) the contract summary. `skills/cohort-schema-design.md` deliberately carries NO decode-plan section — it is the schema-authoring surface, and a projection section there would push an already-over-budget skill further over for prose that belongs beside the execution modes.

## Parallel Compose

`pulse.ComposeParallel`, `pulse api compose --parallel N`. Bounded worker pool over `ComposedRequest`. Order-preserving by slot index. `ComposeOptions{MaxWorkers, PerRequestTimeout, FailFast}` (FailFast defaults true).

Post-slot-barrier Compose-overlay fold (`service/compose_overlay.go` ⇒ `processing.ApplyComposeOverlays` in `processing/overlay_compose_dispatch.go`): the orchestrator invokes `s.applyComposeOverlays(ctx, req, requests, responses)` once every slot has produced a finalised `*Response` and BEFORE the response is returned. Operates EXCLUSIVELY on `*Response` objects; per-slot `Responses[i].Overlays` is left UNTOUCHED.

FailFast handling: when `FailFast=true` (default) AND any slot fails, the orchestrator returns the first observed error WITHOUT invoking the overlay hook. FailFast=false routes slot failures through `SERVICE_INTERNAL` which also skips the hook. Empty / nil `req.Overlays` short-circuits with no allocation (overlay-free Compose JSON is byte-identical to a request that omits the slot entirely).

Per-kind handlers replace the chassis stub (`applyComposeStub`) for every Compose-only kind that has shipped. The six crosstab-shape COMPOSE handlers (`OVERLAY_INDEX_VS_REF`, `OVERLAY_DELTA_VS_REF`, `OVERLAY_PROP_Z_CELL`, `OVERLAY_T_CELL`, `OVERLAY_CHISQ_VS_REF`, `OVERLAY_RANK`) are wired today; remaining Compose-only kinds dispatch through the chassis stub until their handler lands. All buffered — streamable subset is empty across COMPOSE by construction.

Slot label resolution: `applyComposeLabelDefaults` synthesises `request_<index+1>` for empty `Request.Label`; `ApplyComposeOverlays` builds a `Label → Index` lookup. The dedicated error codes `PULSE_OVERLAY_REFERENCE_UNKNOWN` and `PULSE_OVERLAY_TARGET_UNKNOWN` are pending — the chassis currently falls back to `PULSE_OVERLAY_REF_UNKNOWN` with a `which` Detail. See `skills/compose-requests.md`.

## Parallel shards

`pulse.Options.ShardWorkers`, default `0` ⇒ `runtime.NumCPU()`. Bounded per-shard worker pool inside `Process` when cohort is a shard archive. Reducer engages only when every operator is mergeable per `processing.CanMergeRequest` (built-ins only; non-decimal targets; no windows/features/regressions/tests/two-pass). Non-mergeable falls through to serial `shardIter`. Associative+commutative byte-equal vs serial; Welford within ULP via Chan-Welford. Surface: `service/shard_reduce.go`, `processing.MergeableAggregator`, `types.AggregationType.Mergeable()`. See `skills/cohort-schema-design.md` (Sharded).

## Parallel buffered Process

`pulse.Options.DecodeWorkers`, default `0` ⇒ `runtime.NumCPU()`. Bounded per-segment worker pool inside `Process` for single-file (non-shard) cohorts. Engages only when `service.canParallelDecode` accepts — `DecodeWorkers != 1`, `recordCount >= service.parallelDecodeRecordThreshold` (currently `100_000`), single-file (sharded routes through `ShardWorkers`), `resolveRealPath` succeeds (mmap available), `processing.CanMergeRequest(req, schema)` is true. Ineligible falls through to serial `scanIter`.

Crosstab is intentionally NOT exercised today — `validateCrosstabSpec` requires `req.Aggregations` empty so crosstab requests always fail `CanMergeRequest`. This infrastructure benefits future non-crosstab buffered Process calls.

Segments stride-aligned at record boundaries over the mmap'd record region; same `DecodeFields`/`SkipBytes` plan shared read-only across workers; each worker owns a `shardPartial`; partials fold in worker-index order via `mergeShardPartials` + `finalizeMergedPartial`. Byte-equal vs serial; Welford within ULP via Chan-Welford. Surface: `service/parallel_decode.go`, `service/parallel_reduce.go`. See CLAUDE.md "Execution modes (pointers)" (Parallel buffered Process) for the knob and the threshold; the mechanics above are the detail home.

## ProcessChain

`pulse.ProcessChain`, `pulse_process_chain`, `pulse api process-chain`. Source-rooted linear chain. Stage 0 against `ChainRequest.Cohort`; subsequent stages receive prior `Response.Data` as synthesised in-memory cohort (grouper keys → categorical_u32, aggregator outputs → f64). Mergeable-only at v1 (`CanChainRequest` requires `CanMergeRequest` AND scalar aggregator emission — rejects `AGG_FREQUENCY`/`AGG_MODE`). Failures: `PULSE_CHAIN_NOT_MERGEABLE`, `PULSE_CHAIN_EMPTY`. Predict equivalent: `descriptor.ValidateChain`. Surface: `types/chain.go`, `processing/chain.go`, `service/chain.go`, `descriptor/chain.go`, `descriptor/capabilities_chain.go`.

Dual-slot overlay design: per-stage overlays ride `ChainRequest.Stages[i].Request.Overlays`; whole-chain overlays ride `ChainRequest.Overlays []*ChainOverlaySpec` and produce `ChainResponse.Overlays []*OverlayLayer` after every stage finalises. `ChainOverlaySpec` carries `Ref StageRef` + `Target StageRef`. Whole-chain barrier: `service.applyChainOverlays` runs after the stage loop, dispatching through `processing.ApplyChainOverlays`. Per-stage `Stages[i].Overlays` is left UNTOUCHED. The dedicated error codes `PULSE_OVERLAY_TARGET_UNKNOWN`, `PULSE_OVERLAY_REFERENCE_UNKNOWN`, and `PULSE_OVERLAY_CHAIN_STAGE_SHAPE_DIVERGENT` are pending follow-ups. See `skills/process-chain.md`.

## Pushdown hash join

`Request.Joins []*JoinSpec`. v1 = exactly one inner join per Request (`PULSE_JOIN_TOO_MANY`, `PULSE_JOIN_KIND_NOT_IMPLEMENTED`); in-memory build (no spill; `PULSE_JOIN_SPILL_DIR` + `PULSE_JOIN_MAX_MEMORY_BYTES` reserved). `JoinedSchema(left,right,spec)` produces `left.Fields + right.Fields` with optional `spec.As` prefix; non-prefixed collisions → `PULSE_JOIN_FIELD_COLLISION`. Key compatibility: identical types match; categorical of any width match; unsigned-int/float/date numeric family interchangeable; decimal128 rejects cross-type. Surface: `types/join.go`, `processing/join.go`, `service/join.go`, `descriptor/join.go`, `descriptor/capabilities_join.go`. See `skills/join-design.md`.

## Crosstab

`Request.Crosstab`, `Response.Crosstab`. Composes existing groupers + aggregators across a row × column axis grid; reshape, margin recompute, normalization layered on top. Multi-grouper axes recursively partitioned. Margins always recomputed from raw rows for correctness — `AGG_MEDIAN` row margin equals the standalone single-axis median, NOT the median of cell medians. Per-aggregator classification at `AggregationType.MarginReducibility` (`summable` / `mean_reducible` / `independent` / `recompute`; `independent` = the operator keeps its own row/column/grand accumulator, so the margin — a union, not a cell sum — is exact after one pass and the fused gate admits it). `shape: matrix` (default) populates `Response.Crosstab.Matrix`; `shape: long` emits tuple rows on `Response.Data` with margin rows tagged `_margin=row|column|grand`. Inherently buffered except `shape=long` + no margins + `normalize=none`.

Normalization layering: `normalize_level` truncates the same axis as `normalize`; `normalize_within` fixes a prefix of the OPPOSITE axis. Both compose.

Auxiliary margin-only aggregations (`margin_aggregations`) are computed by `processing.(*Processor).computeAuxMargins` (`processing/crosstab_margin_agg.go`) alongside the cell aggregator's own three margin blocks, and MUST match what the fused walk accumulates for the same request — dispatch picks the arm on request shape and nothing in `Response` reports which ran. The admission rule is the same one stated under Fused crosstab: a record contributes to an auxiliary only if it contributed to a CELL, so a null cell field and an axis key an `Include` excluded are absent from every auxiliary slot while the cell's own margin loops beside them still count both. The buffered implementation resolves each axis's membership ONCE into pointer sets and then walks each margin slot on its own axis — deliberately NOT the `(rkey, ckey)` cell buckets, which are admitted-by-construction but would fold a record into a ROW auxiliary once per COLUMN it landed in, M times under a `GROUP_SET_PER_ELEMENT` fan-out, where fused folds it once per distinct row key. Each slot's admitted subset is shared across the auxiliaries in it and rides `runCellAggregation`, so the `{n, n_null}` floor is over ADMITTED records and decimal128 dispatch comes for free; a slot admitting nothing carries no figure at all, mirroring the fused path's unconstructed accumulator. An auxiliary naming an unknown operator is refused up front, matching `NewFusedCrosstabState`. Partial-depth and cross-axis margins get no auxiliary on either path: those are normalization denominators, and an auxiliary is never a denominator. `TestCrosstab_BufferedAuxMarginMatchesFused` drives one request down both arms.

Buffered record set automatically projected via `service.applyCrosstabProjection` (extends `processing.NeededFields` to walk `Crosstab.Rows/Columns/Cell` + `req.Labels[].Field` + `AGG_WEIGHTED_MEAN/RATIO` Cell.Params); wide-cohort crosstab cost is `O(|referenced|)` not `O(|schema|)`; forced on regardless of `opts.DisableProjection`. Capability: `Manifest.Crosstab`. Predict gate: `descriptor.validateCrosstab`. See `skills/crosstab-guide.md`.

## Fused crosstab

`processing.CanFuseCrosstab`, `processing.FusedCrosstabState`, `processing.StreamableGrouper.KeyFor`, `processing.MultiKeyStreamingGrouper.KeysForRow`. In-decode streaming alternative to the buffered Crosstab orchestrator. When the gate accepts, `service.processCrosstab` short-circuits `materializeRecords` + recursive `PartitionByAxis` and drives a single streaming pass that interns row/col composite axis keys on first sight and folds each filter-passing record into the matching cell / row-margin / column-margin / grand-margin / cross-axis-margin online aggregator. Memory drops from `O(filtered records)` to `O(cells + margins)`.

Gate composition (`CanFuseCrosstab`): mergeable + non-recompute scalar cell aggregator; every row/col grouper constructs AND implements one of the two per-record keying interfaces — `StreamableGrouper.KeyFor` (one bucket per record: CATEGORY/RANGE/ROUNDED/DATE/SET_VALUE — `GROUP_DATE` is admitted here even though `GroupType.Streamable()` is false at the Process layer) or `MultiKeyStreamingGrouper.KeysForRow` (N buckets per record: `GROUP_SET_PER_ELEMENT`); no tests; no features; no `ATTR_FORMULA`; no `FILTER_EXPRESSION`; no decimal128 cell field; no extension operator without `FieldInputs` hook; every `margin_aggregations` entry mergeable and non-decimal (an auxiliary rides the same per-record `UpdateRow` walk, so it must be online — declining sends the request to buffered rather than dropping the auxiliary, which would return a margin with the requested figure silently missing). An auxiliary's `MarginReducibility` is deliberately NOT consulted: the classification answers "can this aggregator's margin be derived from its CELLS", a question an auxiliary does not have — it has none, and both paths give it its own row / column / grand accumulator fed record by record, so every auxiliary is `independent` in role whatever its declared class. `GROUP_QUANTILE` implements neither keying interface and is the only grouper that forces buffered.

`Request.Overlays` is explicitly NOT an exclusion. Overlays decorate a finalised response and consume no records, so `RunCrosstabFused` folds them after `state.Finalize()` through the same `processing.applyOverlaysToResponse` hook the buffered exit calls — cells, `Components`, `Overlays` and `Warnings` are byte-identical across arms. `types.OverlayStreamability` is unchanged (every kind still `false`): a post-`Finalize` fold is not an in-pass computation. The surviving reason an overlay-carrying crosstab may still buffer is the CELL-AGGREGATOR arm — `AGG_WELFORD` is non-mergeable, so `OVERLAY_PAIRWISE_WELCH_T` / `OVERLAY_PAIRWISE_TWO_MEANS_Z` (which read its `{n, mean, variance}` triple off `CellComponents`) stay buffered; `TestCrosstabWelfordCell_StaysBufferedWithCorrectOverlays` pins it. `OVERLAY_PAIRWISE_PROP_Z` over an `AGG_WEIGHTED_MEAN` cell fuses.

Multi-key axis routing: `fusedAxisKeyer.derive` returns the cartesian product of each position's key set plus deduped per-depth prefix sets, so one record updates every accumulator the buffered path would touch, exactly once per distinct key at that depth. Fan-out is legal at any axis position, on either or both axes, several positions per axis. Consequence (deliberate, mirrors buffered): margins are NON-ADDITIVE under fan-out — a record selecting 3 labels counts 3× across row margins but once in the grand margin, so row margins do not sum to the grand total.

`normalize_level` denominators gate on PREFIX depth, not full-axis resolution: the buffered denominator is `PartitionByAxis(spec.Rows[:level+1], filtered)`, which never looks past `level`, so a record whose DEEPER axis positions are null still feeds it. Fused now matches. Releases before this alignment returned a different `normalize_level` denominator on the fused arm whenever a nullable grouper sat ahead of the level — a numbers-changing fix, not a no-op.

Auxiliary margin accumulation (`FusedCrosstabState.rowMarginAux` / `colMarginAux` / `grandMarginAux`, one `auxMarginAccumulator` per declared auxiliary per occupied slot, instance built on first admission) observes a DIFFERENT record admission from the cell's own margins beside it, and that is the point of the slot: a record contributes to an auxiliary only if it contributed to a CELL. Three exclusions follow — a null cell field, an unresolved row key (including one a grouper `Include` excluded, which surfaces as `ErrGrouperKeyNull`), and an unresolved column key. The cell aggregator's own margins are untouched and still count every filter-passing record with a non-null axis key on that axis: measured, a `rows=[brand]` crosstab returns byte-identical column margins with a two-brand `Include` and with none at all. Reusing that for an auxiliary would make the figure cohort-wide and metric-agnostic. Getting it wrong is SILENT — every number still renders, the base is merely wrong. Slots are allocated only for the margins the spec asks for, and nothing at all when `margin_aggregations` is absent. The figures are accumulated and held; exposing them on `Response.Components` is a later change.

Axis-key nullity is per-axis: a record with non-null row key + null col key still updates the row margin and the grand margin. Cells only land at intersections where both axes resolved. Margins recompute from raw rows so byte-for-byte equivalent to buffered RunCrosstab. Map-valued cell aggregators paired with `normalize != none` are rejected (`PULSE_CROSSTAB_NORMALIZE_MAP_VALUED`). Disable via internal `disableCrosstabFusion` toggle.

Perf: synth 200-field × 100K-row bench ~0.51 × buffered (~47% faster); canonical 1M-row real-cohort bench 2.57s vs buffered crosstab baseline 3.82s (~32% faster). **Quote peak heap, never `B/op`.** The combined fan-out + overlay bench (`BenchmarkCrosstabSetFanoutOverlay`) measures `peak-heap-MB` 8.8× / 18.6× / 20.8× better on fused at 25k / 100k / 400k rows, while `B/op` moves only ~30% — `B/op` is cumulative bytes allocated and cannot see retention, so quoting it alone understates the win by ~20×. `allocs/op` is HIGHER on fused (the fan-out keyer builds a key tuple per fanned key); expected, not a regression. See `skills/crosstab-guide.md` (Fused mergeable path) + `skills/grouper-design.md` (Fused crosstab eligibility).

## Facet endpoints

`pulse.Facet(ctx, path, field)` simple distinct-values (categorical fast path through dict, numeric streams file). `pulse.FacetSchema(ctx, *FacetRequest)` rich multi-field — counts (sorted desc by count, ties asc by value), null tallies, Welford online numeric stats, optional `NumericPercentiles` (forces buffered per-field sort), optional `IncludeHistogram` with caller-supplied `HistogramRange` (single-pass), optional `DiscreteTopK` (`TruncatedAt` warning), optional `AdditiveFields` contribution counts, optional `FacetRequest.Overlays []*OverlaySpec` carrying the four FACET-host overlay kinds (`OVERLAY_INDEX_VS_POP` / `OVERLAY_ZSCORE_VS_POP` / `OVERLAY_CHISQ_VS_POP` / `OVERLAY_KS_VS_POP`).

Overlay dispatch runs at the buffered FacetSchema exit via `processing.ApplyOverlaysFacet`, attaches layers to `FacetResult.Overlays` in spec order, and recurses `FacetSchema` against `Ref.Population.Cohort` to materialise the per-spec population view (strips Filterers / Labels / Additive; cycle-safe). Streamability mixed: INDEX_VS_POP / ZSCORE_VS_POP are streamable per `types/overlay_streamability.go` but run at the same buffered exit since FacetSchema is structurally buffered today. Capability: `Manifest.Facet` carries `SupportsOverlays: true` + `SupportedOverlayKinds`. Predict: `descriptor.ValidateFacet` (calls `descriptor.ValidateFacetOverlays`). CLI `pulse api facet` falls back to simple shape unless rich flag set. See `skills/facet-design.md` and `skills/overlay-system.md` (Host-arm wiring — the FACET bullet).

## Overlays

`Request.Overlays []*OverlaySpec`, `Response.Overlays []*OverlayLayer`. Additive post-result decorations attached to an already-computed base result. Each spec produces one `OverlayLayer` in matching slot order; layers carry the host-shape payload and never mutate the base payload — overlays are read-only siblings keyed to host coordinates. Catalog at `types.AllOverlayKinds()` + `types.OverlayStreamability`; per-kind capability at `descriptor.overlayCapabilityFor` (surfaced on `Manifest.Overlays`).

Buffered-by-default rule: `OverlayStreamability[kind] == false` for every kind in the initial catalog. The overlay family covers index/share/delta/cumulative/rolling shapes across cell/row/column/total scopes. Forward-compat: `Request.Overlays` is omitempty so `CanonicalHash`/`Request.Hash` stay byte-identical for requests that omit the slot. A crosstab carrying `Request.Overlays` no longer falls back to buffered — the MATRIX fold runs at the fused exit through the same hook (see "Fused crosstab" above); the flag table stays all-`false` because that fold is post-`Finalize`, not in-pass. Failures: `PULSE_OVERLAY_KIND_UNKNOWN`, `PULSE_OVERLAY_SCOPE_UNSUPPORTED`, `PULSE_OVERLAY_REF_INCOMPATIBLE_WITH_SHAPE`, `PULSE_OVERLAY_HOST_NOT_SUPPORTED`, `PULSE_OVERLAY_LEVEL_OUT_OF_RANGE`.

**Level / Within composition.** The share / index / delta / zscore family honours `OverlaySpec.Level` (same-axis prefix truncation) and `OverlaySpec.Within` (opposite-axis prefix fixing). `Level=0, Within=0` preserves the leaf-margin denominator and is byte-identical to the no-Level/no-Within handler output. Composition mirrors the buffered crosstab `normalize_level` / `normalize_within` semantics (byte-equivalent for summable cell aggregators) and reuses the same prefix-key helpers (`processing.SameAxisPrefixDepth` / `processing.OppositeAxisPrefixDepth` / `processing.AxisKeyPrefix`). Out-of-range slots fire `PULSE_OVERLAY_LEVEL_OUT_OF_RANGE` at both predict and runtime; the χ² / Fisher inferential family rejects non-zero values with the same code (implicit-margin contract).

**Grouped Process wiring.** The SERIES-host overlay fold (`processing.ApplyOverlaysSeries`) attaches at the grouped Process exit in both `processing/processor.go` paths (buffered + streaming). No-op when `req.Overlays` is empty, when `req.Crosstab` is set, or when the request has no `Groups`. Mixed-mode downgrade rule: a Request mixing streamable overlay kinds with non-streamable kinds forces the entire request to the buffered path via `processing.canStreamOverlays`.

**FACET-host wiring.** The FACET-host overlay fold (`processing.ApplyOverlaysFacet`) attaches at the FacetSchema buffered exit in `service/facet_rich.go` via `service.applyFacetOverlays`. `FacetRequest.Overlays []*OverlaySpec` is the FACET-host slot; the four FACET-host kinds MUST attach there, not on `Request.Overlays` — the Request-host validator rejects FACET kinds with a `PULSE_OVERLAY_REF_INCOMPATIBLE_WITH_SHAPE` redirect message. Per-spec host-field selection via `OverlaySpec.Params["field"]`. Service-layer wiring recurses `FacetSchema` against `Ref.Population.Cohort`, caches per-cohort+field tuples. `FacetResult.Overlays []OverlayLayer` is omitempty. Predict equivalent: `descriptor.ValidateFacetOverlays` — per-kind Ref / Scope / Level / Within gates; CHISQ rejects numeric hosts; KS rejects categorical hosts. Predict surface: `FacetValidationResult.OverlaysApplied` + `FacetValidationResult.OverlayCost` mirror the Request-host shape. Manifest: `Manifest.Facet` carries `SupportsOverlays: true` + `SupportedOverlayKinds: ["OVERLAY_CHISQ_VS_POP", "OVERLAY_INDEX_VS_POP", "OVERLAY_KS_VS_POP", "OVERLAY_ZSCORE_VS_POP"]`.

**CHAIN-host wiring.** The CHAIN-host overlay fold (`processing.ApplyChainOverlays`) attaches at the post-stage-loop barrier inside `service.ProcessChain` (`service.applyChainOverlays` hook). Dispatcher chassis ships stub handlers for the two whole-chain kinds (`OVERLAY_INDEX_VS_STAGE`, `OVERLAY_DELTA_VS_STAGE`) so the round-trip path is exercised end-to-end without per-kind arithmetic; per-stage `Stages[i].Overlays` is left UNTOUCHED.

**FORMULA kind.** `OVERLAY_FORMULA` is a caller-supplied expression-driven projection compiled ONCE per spec via `expr-lang/expr` (the same evaluator that backs `ATTR_FORMULA` / `FILTER_EXPRESSION`) and run per cell / entry / scalar against a per-host-shape variable namespace (MATRIX: `cell` / `margin_*` / `sd_*`; SERIES: `value` / `total` / `prior` / `baseline`; SCALAR: `value`; Compose hosts add the dotted `slot.<label>.{cell|value}` namespace). Inherently buffered across every host shape. `pulse.Options.Extensions.ExprFunctions` flow through the evaluator (functions widen the function surface only; the variable surface stays fixed per-host-shape). Failures: `PULSE_OVERLAY_FORMULA_PARSE_ERROR` / `PULSE_OVERLAY_FORMULA_TYPE_MISMATCH` / `PULSE_OVERLAY_FORMULA_INVALID_IDENT`.

Surface: `types/overlay.go`, `types/overlay_streamability.go`, `processing/overlay.go`, `processing/crosstab.go` (hook), `processing/crosstab_normalize.go` (shared prefix helpers), `processing/overlay_series.go` (SERIES fold engine), `processing/overlay_series_response.go` (grouped Process wiring + mixed-mode gate), `processing/overlay_facet_dispatch.go` (FACET dispatch table) + `processing/overlay_facet_pop.go` (FACET population resolver), `processing/overlay_chain_dispatch.go` (CHAIN dispatch table + StageRef resolver), `descriptor/overlay.go`, `descriptor/overlay_facet.go`, `descriptor/capabilities_overlay.go`, `descriptor/capabilities_facet.go`, `descriptor/manifest.go`, `descriptor/predict.go`, `descriptor/facet.go`, `service/facet_overlay.go`, `service/chain.go` (`applyChainOverlays` hook), `types/facet.go`, `types/chain.go`. See `skills/overlay-system.md`.

- **Crosstab** (`Request.Crosstab`, `Response.Crosstab`) — composed row×column grid; margins recompute from raw rows; `normalize_level` / `normalize_within` compose. `AggregationType.MarginReducibility` classifies each cell aggregator into FOUR classes — `summable` / `mean_reducible` / `independent` / `recompute` — surfaced as `crosstab.*_aggregators` in the manifest. `independent` (`AGG_DISTINCT_COUNT`, `AGG_DISTINCT_SUM`) means the operator keeps its OWN row/column/grand accumulator: the margin is the union across cells, never their sum, and is exact after one pass — so the fused gate ADMITS it. Re-labelling those `recompute` because "a distinct count is not a sum of cells" changes no number and silently costs fusion. `CrosstabSpec.MarginAggregations` (`margin_aggregations`, additive + `omitempty`) carries AUXILIARY aggregations evaluated into the row/column/grand margin accumulators ONLY, never into a cell — `Cell` is a single `*Aggregation`, so this is how a second figure (canonically an unweighted respondent base beside a weighted metric) rides one request instead of a whole second scan. Effective labels (`Label`, else `TYPE_field`) must be unique across the slot AND distinct from `CellLabel`, because margin components are keyed by label. Structural detection is SHARED — `types.CrosstabSpec.MarginAggregationFaults` is called by both `processing.validateCrosstabSpec` and `descriptor.validateCrosstab`, so predict and execution cannot drift on WHICH specs they refuse; only the coded rendering differs. An auxiliary observes the SAME record admission as the cell aggregator (a record contributes only if it contributed to a cell) — deliberately unlike the cell's own margins, and deliberately not configurable. BOTH execution arms implement it and they must AGREE: dispatch picks fused or buffered on request SHAPE and nothing in `Response` reports which ran, so an auxiliary present on one arm only moves a sample-size figure for reasons a caller cannot see or ask about — and `AGG_WELFORD` / `AGG_MEDIAN` force buffered by construction, which is the arm two BERA stat-test families land on. The buffered half is `processing.(*Processor).computeAuxMargins` (`processing/crosstab_margin_agg.go`): it resolves each axis's membership ONCE into pointer sets and narrows each margin slot's own routed bucket, deliberately NOT walking the `(rkey, ckey)` cell buckets — those are admitted by construction but would fold a record into a ROW auxiliary once per COLUMN it landed in, M times under a `GROUP_SET_PER_ELEMENT` fan-out, which is precisely the axis this slot exists to serve and the one shape where the two arms could silently disagree. A slot admitting no record carries no figure on either arm, never a fabricated 0. `TestCrosstab_BufferedAuxMarginMatchesFused` drives one request down both. The figures surface on `Response.Components.Crosstab` as `row_margin_aggregations` / `column_margin_aggregations` / `grand_total_aggregations` — see the `Response.Components` section above for the shape, the presence semantics and the display-flag gate, and `TestCrosstabAuxMargin_WireFiguresAgreeAcrossPaths` for the cross-arm byte comparison at that surface. See `skills/crosstab-guide.md`.
- **Fused crosstab** (`processing.CanFuseCrosstab`, `processing.StreamableGrouper.KeyFor`, `processing.MultiKeyStreamingGrouper.KeysForRow`) — in-decode streaming alternative; ~30–47% faster on benches, and `peak-heap-MB` 8.8× / 18.6× / 20.8× better than buffered at 25k / 100k / 400k rows. **Quote peak heap, never `B/op`** — `B/op` is cumulative bytes allocated, cannot see retention, and understates the win by ~20×; fused `allocs/op` is deliberately HIGHER. Axis groupers may implement EITHER per-record keying interface, so `GROUP_SET_PER_ELEMENT` fan-out axes fuse at any position, on either or both axes; `GROUP_QUANTILE` implements neither and is the only grouper forcing buffered. `Request.Overlays` does NOT force buffered: `RunCrosstabFused` folds layers after `state.Finalize()` through the same `applyOverlaysToResponse` hook the buffered exit calls, byte-identical across arms, and `types.OverlayStreamability` stays all-`false` because a post-`Finalize` fold is not an in-pass computation. The surviving reason an overlay-carrying crosstab may still buffer is the cell-aggregator arm — `AGG_WELFORD` is non-mergeable, so `OVERLAY_PAIRWISE_WELCH_T` / `OVERLAY_PAIRWISE_TWO_MEANS_Z` stay buffered while `OVERLAY_PAIRWISE_PROP_Z` over `AGG_WEIGHTED_MEAN` fuses. Fan-out margins are non-additive on BOTH arms (a 3-label record counts 3× across row margins, once in the grand margin) — deliberate. `CrosstabSpec.MarginAggregations` gets the SAME two gate checks the cell gets — mergeable (an auxiliary rides the same per-record `UpdateRow` walk, so it must be online) and non-decimal — and declining sends the request to buffered rather than DROPPING the auxiliary, which would return a margin with the requested figure silently missing. Its `MarginReducibility` is deliberately NOT consulted: that classification answers "can this aggregator's margin be derived from its CELLS", which an auxiliary does not have — both paths give it its own row/column/grand accumulator fed record by record, so every auxiliary is `independent` in role whatever its declared class, and requiring a class would decline fusion for a request the fused walk computes exactly. The fused walk accumulates auxiliaries in `rowMarginAux` / `colMarginAux` / `grandMarginAux` beside the cell's own margin slices, under the admission rule above — a record reaches an auxiliary ONLY if it reached a cell, so a null cell field and an `Include`-excluded axis key are both absent from it while the cell's own margins still count them. Getting that wrong is SILENT: every number still renders, the base is merely cohort-wide instead of metric-scoped. Slots allocate only for the margins the spec asks for, and nothing at all when the slot is absent. See `skills/crosstab-guide.md` (Fused mergeable path) + `skills/grouper-design.md` + `.claude/reference/execution-modes.md`.

- **Overlays** (`Request.Overlays`, `Response.Overlays`) — additive post-result decorations keyed to host coordinates; never mutate base payload. Level / Within prefix composition, SERIES-host fold, FACET-host wiring, CHAIN-host barrier, FORMULA kind. Stat-test parity family (`OVERLAY_T_CELL` / `OVERLAY_T_VS_REF` Welch upgrade + `OVERLAY_Z_CELL` / `OVERLAY_Z_VS_REF`) reads `{n, mean, variance}` from `Response.Components.Crosstab.CellComponents[r][c]` (populated by `AGG_WELFORD` via the `MetaAggregator` path) and computes p-values byte-equal to the standalone `TEST_WELCH` / `TEST_Z_TWO_SAMPLE` row tests over the same inputs. The legacy `processing.WelfordTriple` smuggle through `MatrixCell.Value` is removed; `MatrixCell.Value` for `AGG_WELFORD` cells now carries the scalar mean per `Aggregate()`. Additive contract preserved — when no `CellComponents` triple is present, the handler falls back to `Params`-supplied mean/variance/N. See `skills/overlay-system.md` for the migration.
