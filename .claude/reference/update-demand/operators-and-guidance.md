**Param-enum values are not example-gated (matrix-extensions-hardening E9-S4, option (c)).** `TestEveryOperatorHasAnExampleTag` gates operator NAMES (`types.All*Types()` via `_meta.operators`, overlay kinds via `overlays[].kind`) and nothing finer. An enum value inside `params` (a `rotation`, a `metric`, an `extraction`, a `method`), a request slot (`populations`), a fit, a reference form or an embedder-registered extension operator is not checked, and none will be. Why: the accepted lists are open-ended per operator, and a body that only spells a value proves it parses, not that it computes. Each algorithm behind an enum value is pinned by its oracle test instead (`mv_rotation.json`, `TestRotation_MatchesROracle`, and so on), and `make sites ARGS="op <TYPE>"` lists the operator's enum values with their dispatch sites. Examples for new enum values and slots are still expected, as documentation: an effort that adds them adds or extends an example (E8-S2: `matrices/14_rotations.json`, `compose/05_vector_fit_save.json` + `06_population_score.json`, `crosstab/17_vector_element_cells.json`). An extension operator cannot live in the embedded library, because it is registered by the embedder; its worked example is in `docs/src/internals/extension-points.md`.
