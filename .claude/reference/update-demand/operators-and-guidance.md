# Update Demand — operators, examples and guidance

Per-area slice of the Update Demand trigger table. Index: `.claude/reference/update-demand.md` — load it first, then only the slice(s) your change triggers. Rule: a change in column 1 also updates everything in column 2, in the same PR.

Scope: registered operators of every category (aggregator, attribute, filterer, grouper, window, feature operator, `TEST_*`, `REG_*`, synth distribution, overlay kind), `Group.Include`, streamability, `ExactlyOneOf` and expression params, the params allowlist, example tags and taxonomy, skill fences, built-in Purposes / Interpretations, intents and glossary, the extension guidance hook, advisories, Recommend / Explain, the regression jackknife and holdout.

**Find the sites first.** `make sites ARGS="op <TYPE>"` lists every skill, capability, example, enum and dispatch site for an existing operator; `make sites ARGS="new-op <category>"` lists what a new one in that category needs. The registered set is `types.All*Types()` plus `internal/processing/registry.go`.

**Param-enum values are not example-gated.** `TestEveryOperatorHasAnExampleTag` gates operator NAMES (`types.All*Types()` via `_meta.operators`, overlay kinds via `overlays[].kind`) and nothing finer. An enum value inside `params`, a request slot, a fit or an embedder-registered extension operator is not checked: the accepted lists are open-ended per operator, and a body that only spells a value proves it parses, not that it computes. Each algorithm behind an enum value is pinned by its oracle test instead, and `make sites ARGS="op <TYPE>"` lists the enum values with their dispatch sites. Examples for new enum values and slots are still expected as documentation. An extension operator cannot live in the embedded library; its worked example is in `docs/src/internals/extension-points.md`.
