Scope: `Request.Overlays` / `Response.Overlays`, `OVERLAY_*` kinds and `Extensions.OverlayKinds`, pairwise and panel params, the Compose fold and its components view, overlay error-code carriage, `OverlayLayer.Warnings`. Sites for one kind: `make sites ARGS="op OVERLAY_<KIND>"`; for a new kind: `make sites ARGS="new-op overlay"`. Engine wiring: `.claude/reference/execution-modes.md` (overlay slices).

## Pairwise acceptance

- Acceptance is per kind and stated as one rule, not per mode.
- The two Welford-input kinds (`types.PairwiseKindUsesWelford`) read n, mean and variance from the AGG_WELFORD triple, so they accept neither selector. The refusal is predict-only: an inert param cannot produce a wrong number, and a runtime twin would break `pulse.Process` calls that succeed. One narrow exception, not to be widened: a distinct-key `n_source` on a Welford kind is refused at runtime with predict's `PULSE_OVERLAY_PARAM_MISSING`, so one request never yields two codes (scoped to `PairwiseNSourceReadsDistinctKeys`).
- `n_basis` belongs to the weighted-moments kind alone (`types.PairwiseKindUsesWeightedMoments`, disjoint from Welford). That kind requires `n_basis` (no default — the variance convention is the embedder's call) and refuses both selectors, with `PULSE_OVERLAY_PARAM_MISSING` naming `details.param`, at predict and runtime. Predict also refuses its cell host when `Crosstab.Cell.Type` names a built-in aggregator other than `AGG_WEIGHTED_MEAN`; an extension type defers to runtime. On every other pairwise kind `n_basis` is inert and refused at predict only.

## Panel params

`OVERLAY_PROP_Z_PANEL` pairs across Compose slots. Its contract, all enforced on both arms unless marked:

- **Host.** `ComposedRequest.Overlays` is the only slot the panel executes from; Chain and Facet refuse it. The predict arm is `descriptor.ValidateCompose` / `ValidateComposeWithOptions`, not `ValidateOverlays`; a panel spec on `Request.Overlays` is a wrong-host spec, not a params diagnostic. The Compose (`map[string]any`) and Request (`json.RawMessage`) carriers funnel through one decoder so hosts cannot drift. Absent params and `{}` stay byte-identical to the no-params baseline.
- **Cap first.** `OverlayOptions.MaxPanelTargets` (`PULSE_OVERLAY_PANEL_TARGETS_OVER_CAP`) rides `Options`, never params, and fires before every params gate.
- **Closed `n_source` enum.** The empty value is the legacy default, not a mode (`types.PanelNSources()` excludes it). An unknown value is `PULSE_OVERLAY_PARAM_MISSING` naming the value and valid set — at runtime too, because `pulse.Compose` does not run predict and an unknown mode falling through would return the default number under a name the caller chose.
- **Names encode the carrier.** `row_margin_value` reads the margin cell's value off `MatrixPayload.RowMargins` (under a percentage normalization not a count); the pairwise family's `row_margin_n` reads `CrosstabComponents.RowMarginCounts`. `row_margin_value_within` sums `RowMargins` over a row-key prefix, all columns; the pairwise `n_within` sums `CellCounts` over a pair-axis slab at one column. `row_margin_distinct_within` reads `RowMarginComponents` via `ComposeSlotView.RowMarginDistinctN`. The pairwise spellings (`row_margin_n`, `n_within`, `n_within_distinct`) are unknown modes on the panel and are never admitted as aliases — one wire name meaning two quantities is the hazard. A mode name is shared across families only where the quantity is the same (`cell_n_unweighted`). "Row" and "column" mean each slot's own axes.
- **No cell value as n.** `types.PanelNSourceFallsBackToCellValue` is false for every mode. A missing or zero margin on the legacy leg reads as n = 0 (pairs are NaN with `PULSE_OVERLAY_REF_ZERO`); borrowing the cell value forced the share to 1 and returned a spuriously small p with no warning. A counted leg that cannot be read skips the coordinate with an `n_missing` warning.
- **Components gate is mode-scoped** (`PanelNSourceReadsComponents`), so a panel that never needed components does not start refusing. `Disabled` / `NonCrosstab` ⇒ `PULSE_OVERLAY_COMPONENTS_REQUIRED`; `SlotAbsent` ⇒ `PULSE_OVERLAY_SLOT_NOT_CROSSTAB`. The gate covers the reference slot; details carry `panel_index` and the authored `slot_index` (panel 0 is the reference, rarely Compose slot 0).
- **By-key reads.** A components read resolves each slot's coordinate by key (`matrixAxisIndexLookups`), never positionally: slots share the key set, not the order.
- **`NWithinDepth` is `*int` and stays one.** `nil` = the exact per-slot row margin, no summing; `d` = sum over rows agreeing on the first `d+1` dims. Depth 0 is meaningful, so a plain `int` would hand the first-dim request the unsummed margin silently. (`PairwiseOverlayParams.NWithinDepth` is a plain `int` with exactly this defect; its wire value shipped, so do not copy it.) The prefix compare is `processing.axisKeyPrefixEqual`, never a second one. A slab is readable only when every row carries a margin; a partial sum understates the denominator silently. Both within modes share one slab walk (`panelRowMarginSlabLookup`).
- **Depth refusals** (`PULSE_OVERLAY_PARAM_MISSING`): a negative depth, or a depth with a mode that does not read it (`PanelNSourceUsesWithinDepth`), both arms; a depth past a slot's row-axis dim count, runtime only (a validator cannot see a materialised axis). Slots may declare different depths; one out-of-range slot refuses the whole spec, first offender in panel order.
- **Slab partition.** An explicit depth sums across rows, so the summed-across row-axis dims must partition the key set (`types.CheckPanelSlabPartitionWith`, `PULSE_OVERLAY_DISTINCT_SLAB_NOT_PARTITIONED`). The gate keys off `PanelNSourceUsesWithinDepth`, not an additivity predicate, because a panel margin is whatever the slot's aggregator emitted and cannot be assumed additive. Accepted: an omitted depth, a fan-out at depth ≤ `NWithinDepth`, an unregistered grouper name. Details carry `panel_index`, `slot_index`, `slot_label`.
- **Distinct-key admission** (`row_margin_distinct_within`, sole member of `PanelNSourceReadsDistinctKeys`) is runtime-only, up front, per slot, on the cell aggregator's exact identity (`ComposeSlotView.AdmitsDistinctKeyN`, forwarding to the matrix arm): `AGG_DISTINCT_SUM` on `distinct_count`, `AGG_DISTINCT_COUNT` on `cardinality`, else `PULSE_OVERLAY_REF_INCOMPATIBLE_WITH_SHAPE`. Identity, never key presence — `AGG_MODE_COUNT` / `AGG_MODE` emit a `distinct_count` that counts measure values. Slots naming different admitted aggregators refuse too (different units). A slab cell no record reached contributes zero; a nil margin entry skips with `n_missing`.
- **Wholesale refusals.** One offending slot refuses the whole spec, never a per-slot drop: dropping a slot changes M, which sets the length and pair order of every cell's flattened upper-triangular vector.
