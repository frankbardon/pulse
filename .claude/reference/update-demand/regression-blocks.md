# Update Demand — regression opt-in result blocks

Per-area slice of the Update Demand trigger table. Index: `.claude/reference/update-demand.md` — load it first, then only the slice(s) your change triggers. Rule: any change in column 1 MUST also update everything in column 2, in the SAME PR. CI fails otherwise.

Scope: the opt-in blocks a `REG_OLS` / `REG_GLM` spec adds to its `RegressionResult` — `margins` (marginal effects) and `collinearity` (variance inflation factors) — and the Compose-level nested-model comparison of two such fits (`compare`). Each block is an additive `omitempty` `RegressionSpec` object with a result twin, a shared no-execute rule leaf read by predict and the engine alike, an extension shared-slot row and an R oracle; the comparison is an additive `omitempty` `ComposedRequest` list with a `ComposedResponse` twin and the same leaf-rule-plus-oracle shape. The regression operators themselves, the jackknife knobs and `holdout` stay in `update-demand/operators-and-guidance.md`; `vcov` / `covariance` in `update-demand/compose.md` and `matrix-and-vectors/regression-vcov.md`.
