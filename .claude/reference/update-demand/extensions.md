# Update Demand — extensions

Per-area slice of the Update Demand trigger table. Index: `.claude/reference/update-demand.md` — load it first, then only the slice(s) your change triggers. Rule: a change in column 1 updates everything in column 2 in the same PR.

Scope: `pulse.Options.Extensions`, the `extend/` interfaces and adapters, embedder skills and examples, extension matrix / regression / overlay / post-fit operators, extension enum values in the instance payload schema, `FieldInputsFunc`, label tables, directory-loaded lookup tables (`PULSE_LOOKUP_TABLES_DIR`), the `range_label` expression built-in, extension `ComponentSchema` and aggregator classifiers. Contract: `.claude/reference/architecture.md` (Extension surface); recipe: `docs/src/internals/extension-points.md`.

**Finding the sites.** The root `extensions*.go` files are the adapter, validation, probe, snapshot and runtime layer; grep the registration field name (e.g. `PValues`, `HonoursField`) across the root, `internal/descriptor/` and `internal/processing/` to find every reader. **Each registration flag has a runtime reader AND a predict / snapshot reader** — wire one without the other and predict and runtime disagree with no error; every row's `*PredictMatchesRuntime` gate is the check. **Every expression built-in or reserved name must be admitted at every compile site** — grep an existing one (`RangeLabelFunc`) for the list.

**Shared rules.** `extend` stays a leaf (`TestExtendImportBoundary`); engine-only capabilities stay out of it. A spelling change updates the embedder migration doc under `docs/roadmap/`. A public type change regenerates the public-API golden; a manifest-visible one the manifest goldens; run `make smoke` for anything the embedder smoke module touches.
