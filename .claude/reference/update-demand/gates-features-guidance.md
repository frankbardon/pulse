# Update Demand — feature, guidance and docs gates

Per-area slice of the Update Demand reference. Index: `.claude/reference/update-demand.md`; the engine and CI-job gates are in `.claude/reference/update-demand/gates.md`. To find a gate, `grep -rn 'func TestName' --include='*_test.go' .`; to list a family, `go test ./... -list 'TestFamily_'`.

## Other load-bearing contract gates — features, guidance and docs

Enforced by their own packages and binding on every PR.

**Registry completeness.** The `TestManifest*Complete` family holds the manifest equal to every registry (operators, tests, post tests, distributions, regressions, error codes, MCP tools, ComponentSchemas); `TestStreamability_*Known` and `TestRegistryStreamabilityMatchesTypes` hold every `All*Types()` entry to a streamability row; `TestCodesHaveFixups` holds every error code to a fixup. A new registry entry that fails one of these is missing a companion, not a test bug.

**Feature profiles.** `TestFeaturesHaveSince`, `TestFeatureDependenciesResolve` and `TestProfileDependenciesComplete` hold the feature table and dependency graph (`.claude/reference/feature-profiles.md`). `TestProfileInvisibilityParity` holds a hidden operator, tool, prompt, skill or example indistinguishable from a never-registered one on every MCP surface (skill bodies included); a new MCP surface joins its sweep when it lands. The heavy `TestProfileServedTextNoHiddenFeature` (root `served_text_sweep_heavy_test.go`) renders every surface for each single-feature-hidden profile (`allFeaturesBut`, one per built-in feature): manifest, MCP tools / prompts / resources, skill metadata and bodies, examples and the `ExportReference` tree, and fails on a hidden operator, hidden-feature tool or hidden slot token, and on a core tool description that loses a sentence to the scrub (fence the clause: `feature-profiles.md` (Prose scrub)). Its shrink-only list is `internal/doccheck/allowlists/served-text.txt` (empty: fix a hit — fence the prose, fix the serving code — never list a code-owned one). A new served surface joins `servedTexts` when it lands.

**Public surface and import boundaries.**

- `TestPublicAPIGolden` (`internal/apigolden/`) freezes the exported shape of every public package, type aliases expanded into their targets — the gap apidiff cannot see behind a root alias into `internal/`. Regenerate with `go test -tags heavy ./internal/apigolden/ -run TestPublicAPIGolden -update` only for an intended surface change, and review the diff as the surface delta.
- `TestExtendImportBoundary` (+ `_NoTransitiveEngine`): `extend` imports only stdlib plus the module's `encoding`, `types`, `errors`; no engine package is reachable. Widen `allowedModuleImports` only with a contract reason.
- `TestIOImportBoundary` (+ `_FacadeReachesAdapters`, `_NoFileImportsFacade`): nothing below the public `io` facade (`internal/iocore`, `internal/io`, every adapter) may import `github.com/frankbardon/pulse/io`, whose factory imports every adapter. The `NoFileImportsFacade` arm parses test files too, because `go list -deps` omits them. When an adapter moves, move its path in `belowFacade`.
- `TestNoHardcodedVersionLiterals`: no semver literal in non-test `.go` under `mcpserve/`, `mcp/gosdk/`, `cmd/pulse/`; every version surface reads `pulse.Version()`.

**Extension parity.** `TestExtensions_BuiltinParity` runs each category's `extend` reimplementation of a built-in beside it through every execution mode (streaming, buffered, parallel decode, shard archive) and requires equal `Response.Data`, `Response.Components`, `Response.Metadata` and stream chunks; the aggregator and grouper suites count merge calls so a parallel mode cannot silently degrade to serial. A new extension category adds a `paritySuite`, never a parallel harness. The `TestExtensions_Probe*Mismatch` tests pin each `PULSE_EXTENSION_MERGEABLE_MISMATCH` / `PULSE_EXTENSION_MARGIN_REDUCIBILITY_MISMATCH` trigger.

**Stride widths.** `TestNoTypeOnlyWidthInStridePaths` walks every non-test `.go` file and fails on a type-only width call (a zero-argument `.ByteSize()`, `fixedWidthBytes(`) outside the `typeOnlyWidthAllowed` file → function → reason list; a stale entry fails too. Every stride, offset and skip is a sum of `encoding.Schema.FieldWidth`, because a field's width is not always a function of its type byte, and a type-only site silently misaligns every field after it.

**Time zones.** `TestNoZoneMathOutsideTemporal` bans zone math outside `internal/temporal/` (the literal `86400`, `SecondsPerDay`, `time.LoadLocation` / `FixedZone` / `Local`, dot-importing `time`, importing `time/tzdata`); the sole exemption is the `encoding.SecondsPerDay` re-export, via `zoneMathAllowed`. `TestUTCZoneIsIdentity` and `TestDSTBoundaries` are tables a newly zone-aware operator joins as a row: `UTC` prints byte-identical to no zone on every zone-aware operator, and DST transitions in several zones equal a `time.In` reference. `TestZoneCapabilities_ExactSet` holds the zone-capable set to the declared table. The `TestTimeZone_*` family pins local-day bucketing on every execution mode, predict ≡ runtime refusals, and that a zone write never mutates the caller's request. `TestDateFieldRejectsTZ`: an explicit `tz` on a `date` field is `PROCESSING_CONFIG` on both sides. `TestTZDataVersion_MatchesEmbeddedZip`: refreshing `zoneinfo.zip` via `make tzdata` without updating `TZDataVersion` and the hash fails; `TestLoadZone_IgnoresHostZoneinfo` keeps `$ZONEINFO` from changing what `LoadZone` accepts.

**Chain and join defaults.** `ValidateChain*` runs the runtime's smart-defaults pass before field checks, so a defaulted stage is accepted or refused alike; more than one `JoinSpec` is `PULSE_JOIN_TOO_MANY` from every side through `internal/descriptor.JoinCountRefusal`. A crosstab with one `JoinSpec` crosstabs the joined rows on both arms, and the fused gate declines any join (`TestCrosstabJoin_*`, `TestCanFuseCrosstab_JoinsForceBuffered`).

**Guidance (Purpose, Interpretation, glossary, intents).** Contract and rule detail: `.claude/reference/guided-analysis.md`.

- Purpose: `ValidatePurpose(name, purpose, resolver)` is the one validator, reused by the extension path. Validity is binding (`Plain` ≤140 characters, ≥1 intent, ≥2 `Questions`, ≥1 `NotFor`, ≥1 `UseCases`, a `Level`; every reference resolves; every jargon `Form` in `Plain` is linked). Coverage is binding against the exemption ledger: every built-in declares a Purpose; every intent has ≥3 operators and a `_meta.intents`-tagged example. Gates: `TestSkillsCoverAllPurposes`, `TestPurposeAlternativesResolve`, `TestPurposeQuestionsResolve`.
- Interpretation: `ValidateInterpretations(name, ins, resolver)` (structure-only for extensions, nil resolver). Each `Field` is a normalised path naming an output the operator really emits per `BuiltinOutputResolver`. Coverage: every test family, regression and `Inferential` overlay kind reads `statistic` / `p_value` / its effect sizes; every needs-reading descriptive operator its `value` / `value.*`. Gate: `TestInterpretationCoversOutputs`.
- Runtime halves: `TestInterpretationFieldsHoldAtRuntime`, `TestEffectSizeKeysHoldAtRuntime`, `TestRegressionOutputsHoldAtRuntime`, `TestOverlayInterpretationFieldsHoldAtRuntime` hold every declared output path and `details.effect_size` key to what a probe fixture really emits, two-way — a declared key no fixture emits fails, an undeclared emitted key fails. Conditional key sets need their own fixture.
- `TestDescriptiveReadingLists`: every descriptive built-in is in exactly one of `needsReadingOperators` / `selfReadingOperators`, so a new operator fails until classified.
- `TestGlossaryTermsResolve` (well-formed glossary), `TestGlossary_EffectSizeKeysHaveTerms` (a new effect-size key joins `effectSizeKeys` and the glossary together), `TestGlossary_OrphanReport`.
- `TestConventionRegistryMatchesFixture` + `TestBuiltinBandsCiteRegisteredConvention`: `builtinConventions` is the single source of built-in `Interpretation.Bands`, held equal to the hand-transcribed cited fixture `internal/descriptor/testdata/conventions.json`. A new band set changes registry and fixture together from a cited source; Cramér's V, Kendall's tau and rank-biserial r are refused bands.
- `TestGuidanceProseLint`: binding statistical-prose lint over every built-in Purpose and Interpretation; allowlist entries keyed `(operator, field, rule)` need a justification and must still match. Rules: `.claude/reference/guided-analysis.md` (Interpretation).
- `TestManifestGuidanceBudget` (+ `_DefaultResults`): guidance prose is pulled, never pushed — the compact manifest stays under ≤64 B per entry `intents` and ≤1280 B fixed, and no declared prose string appears in a default manifest, `Response` or `PredictResult`. Registry-driven, so new guidance is swept with no gate change.
- `TestGuidanceExemptions_*`: a ledger entry needs a justification and an owner (or `permanent`) and fails as stale once its gap is covered. Ledger tables: `.claude/reference/guided-analysis.md` (Gates).
- `TestIntentRegistry_ExactIDs` pins the closed intent taxonomy; `TestManifestIntents_*` hold `intents[]` to the instance ontology under a feature profile. `TestExtensions_Purpose*`: extension guidance is validated at every `pulse.New` with the built-in validators, first invalid wins as `PULSE_EXTENSION_PURPOSE_INVALID`, prose never in the instance manifest.
- `TestVirtualSkillStemsNotEmbedded`: no embedded file claims a virtual skill stem (`glossary`, `intents`); both virtual skills are listed under every profile.

**Documentation checks and their allowlists.** Contributor how-to (running, tiers, snippet tags): `docs/src/contributing/doc-checks.md`; a new fast check joins the Makefile's `DOC_CHECKS`. Every documentation check reads one committed allowlist through the shared loader in `internal/doccheck` (`doccheck.Load`, `AllowlistFile(<check>)` → `internal/doccheck/allowlists/<check>.txt`; lines are `path<TAB>entry<TAB>reason`) and reconciles its findings with `Allowlist.Reconcile`: a violation the list does not name fails, and an entry that no longer violates fails as stale, so a list only shrinks. Fix a new violation, never append it; delete an entry when you fix its violation. A new documentation check gets its own list (an empty one is fine) and reuses the loader, never a parallel one. `TestDocsLinksResolve` (`internal/integration/`) resolves every relative link and `#anchor` in `docs/src/**` (the generated guide included) and the repo-root `*.md` files the way they are published: a book page's target stays inside `docs/src`, is a `SUMMARY.md` chapter and carries the anchor under mdBook's heading-slug rule (smart punctuation drops a `--` outside code); a root file resolves as GitHub renders it; existence is case-exact. A broken link in `docs/src/guide` is fixed in its generator (`internal/docgen`, the skill, the glossary), then `make docs`. External links are `make linkcheck-external` (manual, network, never CI); `.claude/reference/` pointers belong to `TestReferenceDocPointersResolve`. `TestCliHelpMatchesFlagsDoc` (`cmd/pulse/`) walks the post-setup urfave tree (`internal/cli` `SetUpTree` / `Leaves`): every runnable leaf has a section on the generated `docs/src/cli/reference.md` listing exactly its flags (aliases included; `--help` / `-h` once, with the global flags), both directions, and every `--long` / `-x` token the concepts page `docs/src/cli/flags.md` spells (link destinations excluded) is mounted somewhere. `TestCLIReferenceCurrent` (`internal/cli/`) holds the generated page byte for byte; `make docs` rewrites it. A new flag needs only `make docs`; its shared semantics, if any, go on `flags.md`. `TestDocsSnippetsRun` (`internal/integration/`, fast tier) runs every fenced `json` block in `docs/src/**` (guide included) that is a request root (Request, compose, chain, facet; `doccheck.RequestRoot`): predict valid, process with no error, no output assertion. The root kind comes from the one shared key rule `internal/requestroot` (also the request read maps', the extension-example validator's and the example library's). A block is a root by its keys (a `cohort` object, or `requests` / `base` / `sweep`) or by strict-decoding as one; a keyed root that fails the strict decode is a violation naming the decode error, never skipped. Responses, fragments and `...`-elided JSON are skipped; `jsonc` blocks are never read (comments are not strict JSON). Snippet tags ride the fence's info string: `json norun <reason>` opts a block out of decode and run (`SnippetInfo.NoRunReason`, one word; a reasonless `norun` fails); `json cohort=<name>[,<name>…]` names the `internal/examples/fixtures` cohorts it runs on (every cohort reference is pointed at them; a filename that is not one of them becomes the first); a runnable block without a cohort fails. `go compile` opts a Go block in to `TestDocsSnippetsCompile` (heavy: `go build -overlay`, a block without a package clause gets `package snippet`, so it carries its own imports). Allowlist entries key on a hash of the block body (`json:<hash>`, `go:<hash>`; lists `snippets.txt`, `snippets-go.txt`), so editing a block re-checks it. A guide story's tag comes from the generator (`storyCohortTag`), a skill block's from the skill. `TestDocsCoverageCurrent` and `TestDocsCoverageNoGaps` (`internal/cli/`, serial: they clear the `make docs` env vars) hold the generated coverage matrix `docs/src/contract/coverage.md` (`internal/doccoverage`; `make docs` runs `TestDocsCoverageCurrent -update-coverage`). They live in `internal/cli` because only it and `cmd/pulse` may reach the CLI framework: `internal/doccoverage` takes the tree as data (`CLISurface`) and never imports `internal/cli` or urfave (`TestRootTestGraphExcludesCLI`, `TestObservabilityVendorImportBoundaryModule`). Rows come from sources of truth (the public API dump, the `internal/cli.App` tree, the default manifest, the `mcp/gosdk` prompt / resource registrations, the env vars source reads, `Options` / Request / Response fields), each row kind declares its required columns (`doccoverage.Kinds`), and a mention is verbatim. A stale page fails the first; a required cell left empty fails the second unless `coverage.txt` names it (key: row kind, `<identifier> <surface>`). A new public thing ships documented and with `make docs`; a new row kind is a `Kinds` entry plus its collector, never a hand row list. Any other check that scans `docs/src` for mentions skips the coverage page, or it goes vacuous. `TestDocCoverageNotImportedByDescriptor` keeps the generator out of the no-execute descriptor packages. `TestNoRemovedNamesInDocs` (root, fast tier) holds served text to the removed-name denylist `doccheck.RemovedNames` (`internal/doccheck/removed_names.go`; each entry a spelling plus why it is gone; a qualified `io.<Name>` entry also matches the import alias `pio.<Name>`, `DeniedName.Spellings`): `docs/src/**` (the coverage page skipped), the root README / CONTRIBUTING / SECURITY, and what a default instance serves (skill bodies and metadata, `toolmeta` descriptions, manifest string values, error messages and fixup hints, examples), whole-word (`doccheck.CheckRemovedNames`); `docs/roadmap/**`, CLAUDE.md, `.claude/reference/` and tests are out of scope. Its heavy sibling `TestNoRemovedNamesInPromptsAndReference` (`mcp/gosdk`) scans every prompt a default server mounts (description, arguments, body) and the `ExportReference` tree, against its own list `removed-names-prompts.txt`. Removing a public name with a distinctive spelling adds an entry in the same PR; never list a name some package still exports, a live method or a live string. `go run ./internal/tools/removednames` re-runs the v0.39.0 sweep that seeded it.

**GoDoc task examples.** The runnable `Example*` functions an embedder sees in `go doc` live in external test packages (`package pulse_test`, `observe_test`, `mcpserve_test`), use public API only and run on a fresh `afero.NewMemMapFs()` with the tiny cohort the untagged helper `example_helpers_test.go` builds: no `PULSE_DATA_DIR`, no network, output limited to labels, counts and small exact values so it is the same on every architecture. `TestFacadeExamplesPresent` (root) pins them in `facadeExamples` (name -> package directory): a pinned example that disappears, or loses its `// Output:`, fails, and so does an example added to one of those directories without a pin. Only an example that blocks when run (a served transport) is compile-only, named in `compileOnlyExamples`. A new facade task gets an example and a pin in the same PR; dropping one is an owner call, recorded in the PR body.

**Examples and ontology.** `TestExamples_EveryExampleHasIntent` (unless the category is in `exampleIntentExemptions`), `TestExamples_IntentsFromTaxonomy`, `TestExamples_EdgeCoverage` (every operator a body names is an ontology edge; an example without `_meta.operators` declares a capability — `skill-pack.md` (Skill ontology)). `TestOntologyPrune_*` pin the per-instance prune (`feature-profiles.md` (Discovery prune (ontology))); `TestSkillsCoverProfileGet` and `TestSkills_FacadeMCPParity` hold a pruned skill or example indistinguishable from a never-existing name on facade, MCP and manifest.

**Reading semantics.** `TestReading_*` and the per-operator contract tests pin each Interpretation's claim to the engine's real behaviour (null handling, population vs sample estimators); `TestDistributionDocs_*` hold synth distribution skills to the generator.

**Assembled-output R oracles.** The `TestReferenceOracle_*` family covers every test family, regression and inferential overlay against committed R goldens; regimes and tolerances: `guided-analysis/conventions-and-oracle.md` (Statistical primitives and the R oracle). Related contract gates pin unweighted-only refusals (`TestWeight_UnweightedOnlyTestsRefusalPinned`), post-test twins equal to row variants, penalised-regression inference as null, and infinite statistics as `null`. A failure means the code is wrong, never the golden.
