# Update Demand — CLI, MCP, error codes and environment

Per-area slice of the Update Demand trigger table. Index: `.claude/reference/update-demand.md` — load it first, then only the slice(s) your change triggers. Rule: any change in column 1 MUST also update everything in column 2, in the SAME PR. CI fails otherwise.

Scope: error codes, CLI leaves and flags, the `--json` fatal error envelope, skill cross-references, environment variables, managed-import sidecars, MCP tools / binding / serve entry / resources, feature-profile MCP scope, architectural decisions.

**`TestSkillsCoverAllCliLeaves` enforces NAMING, not quality.** The gate (`cmd/pulse/cli_leaves_test.go`, written at E5-S8 after being cited for several efforts without existing) walks the real `buildApp()` command tree and requires every ACTIONABLE command path — a command with a non-nil `Action`, which includes `pulse convert` alongside its `predict` subcommand — to appear verbatim somewhere under `skills/` or `docs/src/`. The command index in `docs/src/cli/flags.md` is the minimum home for a leaf with no dedicated page. It does NOT check that the mention is adequate, so the `skills/session-bootstrap.md` and `docs/src/cli/` companions in the rows below remain author judgement; what the gate catches is the case that actually happens — a leaf ships and nothing anywhere names it.
