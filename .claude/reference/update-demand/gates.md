# Update Demand — gates

Per-area slice of the Update Demand reference. Index: `.claude/reference/update-demand.md`. This file holds the engine, runtime-parity and CI-job gates and what each structural gate checks; the cross-arch family is in `.claude/reference/update-demand/gates-cross-arch.md`, the feature, guidance and docs gates in `.claude/reference/update-demand/gates-features-guidance.md`. The contributor-facing gate table is `docs/src/contributing/testing.md` (Structural gates): **a new CI gate adds a row there** in the same PR as the test. To find a gate's file, `grep -rn 'func TestName' --include='*_test.go' .`.

## Other load-bearing contract gates

Enforced by their own packages and binding on every PR.

**Recommend / Explain (no-execute guidance).** `TestGuideNoExecutionImports` (`internal/guide`) — `internal/guide` is no-execute like predict: nothing it reaches imports `internal/service` or `internal/processing`. `TestRecommend_SkeletonKeysMatchWire` / `TestRequireKeysMatchWire` / `TestSlotKeysMatchWire` hold every unbound draft's keys to the wire types; `TestRecommendBound_EveryDraftPassesPredict` and `TestRecommendBound_ServingOperatorsMapped` hold bound drafts valid under an independent predict, so an operator or slot change that breaks a draft fails one of them. `TestRecommendGolden` / `TestExplainGolden` (`descriptor`) pin results — a Purpose, Interpretation, ranking or binding change moves them; regenerate with `-update`. `TestExplainProseLint` lints every golden's generated prose and fails on a missing golden. The `TestExplain_*`, `TestExplainResponse_*` and `TestExplainResults_*` families cover request mode, response mode and result roots; `TestExplainResponse_ClassTablesComplete` fails when a new `TEST_*` family or inferential overlay kind has no verdict class. Contract: `guided-analysis.md` (Recommend, Explain).

**Params allowlist.** `TestParamsDeclaredMatchRead` records every params read while running every embedded example on every root (plus probes for operators no example reaches) and holds each operator's manifest Param list (+ `OverlayCapability.Params`) equal to its reads — an undeclared read fails, a declared key never read fails. `TestParamsReadThroughParamread` bans reading `x.Params` outside `internal/paramread`, so the recorder sees every read. Adding a params key = reading it through `paramread` AND declaring it in the capability table. `TestParamsRefusal_PredictMatchesRuntime` / `_ExtensionOperators` pin the refusal's predict ≡ runtime parity.

**Observability.** `TestObservabilityDefaultsSilent`, `TestObservabilityNoRowData`, `TestHookPanicRecovered`, `TestObservabilityOffNoAllocs` are the four non-negotiable gates; `TestObservedMethodsCoverSurface` requires every exported `*Pulse` method instrumented or listed excluded; `TestObservabilityDocCoversEnums` requires every enum value and metric name in `observability.md`; the import-boundary gates keep vendor (OTel / Prometheus) packages out of everything but the adapters. Contract: `observability.md`.

**Chain / join / field-reference refusal parity.** Process, ProcessStream, both crosstab arms, predict and the `ValidateCompose*` / `ValidateChain*` validators refuse a bad request with ONE code, message and details through shared rules: `internal/mergegate.ChainRefusal` (stage gate; a stage ≥1 carrying `Joins` is `PULSE_CHAIN_STAGE_JOIN`), `internal/descriptor.FieldRefRefusals` (an unknown field name in any slot family, fields named inside built-in params, an extension's `FieldInputs`, label shadowing, output-namespace collisions, `order_by` orderability via `IsOrderableType`), and `internal/encoding.JoinKeysRefusals` (`PULSE_JOIN_FIELD_UNKNOWN`). Inside Compose a refusal carries `details.request`; on a chain stage, `details.stage`. Pipeline-produced names are accepted and visible only downstream of their producer. Gates: `TestChainGate_*`, `TestFieldRefs_*`, `TestFieldRefRefusals_*`, `TestJoinKeys*`, `TestLabelShadow_*`, `TestWindowOrderBy_*`, `TestOutputNamespace_*`. A new built-in whose params name a field adds its arm to `aggParamFieldKeys` / `postTestParamFieldKeys` when it joins `addAggParamFields`. An output-namespace collision (an aggregation label equal to a group field or another label, two groupers writing one key column) is refused because it would drop one figure silently from the row. `TestMergeableAggregatorsAreRegistered` holds every `Mergeable()` aggregator in `aggregatorRegistry`.

**Reference oracles.** `TestReferenceOracle_*` (in `internal/processing`, `internal/statdist` and each package that owns a fitted figure): every shared distribution primitive matches the committed R goldens under `internal/processing/testdata/reference/` to relative `1e-10`, p down to ~1e-300. Goldens come from `scripts/reference/gen_reference.R` via `make reference` (CI never runs R) and are hash-gated; a failure means the primitive is wrong — fix it, never regenerate to match. The Student-t family has one implementation, `internal/statdist` (`TestStatdistImportBoundary`, `TestStudentTFormsAgree`); its helpers keep their function boundaries on purpose, because Go may fuse `a*b+c` differently on arm64 across a constant-folded operand and restructuring can move a p-value by an ulp. Normal tails: every normal-approximation p goes through `normalTwoSidedP` (`erfc(|z|/√2)`) or `normalUpperTailP`, never `2·(1 − Φ(|z|))`, which silently cancels to 0 past |z| ≈ 8.3; each family has a `*_TinyP` test in `internal/processing/normal_tail_test.go` and a new normal-approximation family adds its own.

Numeric determinism: the `TestCrossArch*` gates — `update-demand/gates-cross-arch.md` (Cross-arch determinism gates).

**`TestSkillsCoverAllCliLeaves`** (`cmd/pulse/`) is two-way: every runnable leaf in the real `internal/cli.App()` tree is named under `skills/` or `docs/src/` and has a section on the generated `docs/src/cli/reference.md`, and every section is a mounted, actionable leaf. The reverse direction catches a deleted registration whose documentation stayed. It checks naming only, not prose quality.

**`TestFieldTypeAcceptance_PredictMatchesRuntime`**: every registered operator × every field type is accepted by predict exactly when `Process` accepts it, and every refusal carries one identical code from both sides (the `internal/fieldaccept` table's code wherever the slot is tabled). Siblings: `TestFieldTypeSlots_PredictMatchesRuntime`, `TestDecimalAggregation_PredictMatchesRuntime`, `TestUnregisteredOperator_PredictMatchesRuntime`. A new operator needs an `acceptanceTemplates` row when it is registered; a new field type is picked up automatically. Detail: `predict-inspect.md`.

**Two-pass attribute order.** `TestTwoPassOrder_*` and `TestTwoPass_DeclaredOrder_*`: every two-pass attribute fed by row-local or earlier two-pass outputs gives the buffered arm's figures on every decode arm and the `ProcessStream` terminal chunk, and each dependent two-pass layer adds exactly one scan. A PrePass that misses an earlier attribute's output fails silently: it folds zero or missing input and every downstream figure is wrong.

**Weight parity and reference values.** `TestWeightUnityParity` + `TestWeightFrequencyExpansionParity` (`internal/service`): over every weight-aware aggregator, tier-1 test and regression, on every execution arm and weight source, an all-1.0 weight marshals byte-identically to no weight once weight-only keys are shed, and integer frequency weights equal the physically duplicated rows run unweighted (1e-12 relative). The weighted twin must engage the same arm as the unweighted request. A `coverage` subtest holds the parity tables equal to the manifest `weight_aware` set, so flipping an operator to aware without a row fails. `TestWeightReferenceValues` + `TestWeightReferenceKindsAgree` pin weighted figures and floor keys to external values generated offline by `internal/service/testdata/weight_reference/gen_weight_reference.py` into a generated `_test.go` file — regenerate, never hand-edit. Contract: `.claude/reference/weighting.md` (Operation-order exactness rule, Reference fixtures).

**Resource limits.** `TestLimitsDefaultsNeverTripGoldens`: every embedded example, on every host its body names, runs on a defaults-only instance with no predict `LimitFindings` and no `PULSE_LIMIT_EXCEEDED`. `TestLimitsPredictRuntimeParity`: one tight-limit case per runtime enforcement site trips exactly its named limit, every `certain` finding trips with the same `{code, limit, configured}`, and raising the limit to the estimate clears it — a new enforcement site joins its case table. `TestLimitsReleaseMemory` measures retained heap after a trip (post-`runtime.GC()` growth, never `B/op`) under 2 B/record. Contracts: `predict-inspect.md`, `execution-modes.md`.

**Operator declaration flags, runtime halves.** Each manifest flag has a runtime test that can contradict it:

- `Operator.EmitsType` is the materialized column type. `TestManifestEmitsTypeMatchesMaterialize` (root) holds it to the column Materialize writes and `TestManifestEmitsTypeHoldsAtRuntime` holds the emitted values to its (or the note's narrower) domain; a declaration without a probe in both tables fails, because an unprobed declaration is prose nothing can contradict.
- `TestCapabilities_IgnoresFieldDeclarationsAreCoherent` + `TestAggregators_IgnoredFieldSlotIsReallyIgnored` cover `Operator.IgnoresField` (the Field slot is never read, e.g. AGG_RATIO): the operator accepts every type, names its real inputs as `Type: "field"` params, and returns the same scalar whatever Field names.
- `TestWindows_IgnoresFrameMatchesRuntime` covers `Operator.IgnoresFrame`: the column is identical across bounded frames exactly when the flag is set.
- `TestOperators_ReadsExpressionMatchesRuntime` covers `Operator.ReadsExpression`: a flagged attribute or filterer refuses a missing `Expression`, an unflagged one builds identically with or without it, and no other category may declare it.

**`TestDocsGeneratedCurrent`**: the exported default instance (no feature profile, table / population / template env vars cleared) must equal `docs/src/guide/**` byte for byte, and the `docs/src/SUMMARY.md` span between the `<!-- docgen:summary begin -->` / `end` lines must equal the export's SUMMARY fragment. Any Purpose, Interpretation, glossary, intent, `ComponentSchema`, skill or `internal/docgen/components_intro.md` edit needs `make docs` in the same PR; never hand-edit `docs/src/guide`. Recipe: `docs/src/internals/regenerating-goldens.md` (The generated Analysis Guide).

**CI jobs that are not Go tests.**

- `docs` job (`.github/workflows/ci.yml`) runs `mdbook build docs` and fails on any mdBook `WARN` / `ERROR` line, so a broken SUMMARY splice, a generated page or a search index past mdBook's 10 MB warning fails before merge; then `make doc-checks` (the fast doc checks, named in the Makefile's `DOC_CHECKS`; a new fast doc check joins it). The generated guide and coverage page are out of the search index (`docs/book.toml` `[output.html.search.chapter]`); fix a size warning by excluding generated pages or trimming, never by dropping the check.
- `Embedder smoke module` step: `make smoke` builds, vets and tests `internal/embeddersmoke/`, a separate Go module that embeds Pulse through the exported surface only. Root `./...` never descends into it, so `make test` / `make lint` do not see it; when a public API changes spelling, or a migration-guide row lands, update the module in the same PR. `TestSmokeModuleImportAllowlist` fails on a non-stdlib import outside its allowlist.
- `apidiff` job (dispatch only): diffs the exported API against the latest `v*` tag. Advisory until a stable `v1.0.0` exists; after that it fails on any incompatible change unless the PR carries the `api-break-ok` label.

**`TestReferenceDocSplitLayout` + `TestReferenceDocPointersResolve`**: a `.claude/reference/<name>.md` with a same-named subdirectory is an index — it carries a "How to load" note, names every slice as `<name>/<slice>.md`, and stays ≤ 25 KiB; every slice but `history.md` stays ≤ 32 KiB (split, never raise the number). Every reference the test names must stay split. Every `.claude/reference/<path>.md` named in CLAUDE.md, `.claude/**`, the skill pack, `docs/src/` or Go source must exist, and every `<ref>.md` (Section) pointer must land on a heading, a bold lead, or (for "(X row)") a table row's first cell in that file or any slice of its index. `TestSkillsCoverAllCrossReferences` and `TestMCPToolMentionsAreRegistered` scan the slices too.

## Structural gates, per-gate prose

What each structural gate checks.

**Doc hygiene.** `TestClaudeMdMentionsFormatVersion` — CLAUDE.md names the current `format_version` literal. `TestClaudeMdSizeBudget` — CLAUDE.md stays under its size ceiling; move prose into `.claude/reference/` rather than raising it. `TestEnvVarsDocumented` — every `PULSE_*` read in Go source has a row in `docs/src/library/options.md`. `TestComponentsContractDocumented` — the response-components reference documents the `Response.Components` shape, the universal floor and the `Response.Metadata` coexistence note. `TestUpdateDemandTableCovers` / `TestUpdateDemandTableCoversComponents` — the Update Demand index + slices carry a trigger row for every component category and contract word, and the `Response.Components` / per-operator `ComponentSchema` / extension `ComponentSchema` rows.

**Error-code registry.** `TestEmittedCodeLiteralsRegistered` (`internal/integration`) — a non-test string literal spelled like a domain code (`<DOMAIN>_<NAME>`), and every SCREAMING_SNAKE literal under `internal/cli` / `cmd/pulse`, is a registered code; exempt are the options.md environment variables, `OTEL_*`, the `PULSE_STATS_SKIP_*` tally reasons and `doccheck.RemovedNames`. A CLI leaf's fallback for an uncoded error is `CLI_ERROR`, never a per-leaf label. Its converse `TestRegisteredCodesEmittedOrReserved` (same file) — every registered code is named as a value (not only as a map key, case label, `==` operand or `HasCode` argument) by a non-test file outside `errors/codes.go`, `errors/fixup_metadata.go` and `error_owners.go`, or sits in `reservedCodes` with a reason; a code nothing raises is retired (constant, metadata, owner, docs, a `doccheck.RemovedNames` entry, a migration row). `TestRefusalMessagesUseWireKeys` (`internal/integration`) — refusal prose in the overlay, regression, test, filter, crosstab and join validators spells request keys as the wire does (`params.field`, `ref.margin`, `max_iters`, `split_by`), never as Go field paths; its rule table names the files and spellings. `TestFixupPathsAreWireKeys` (`internal/integration`) — every `Fixup.Path` segment is an index (`*`, digits) or a wire key (a module JSON tag, a manifest param name, `nestedParamKeys`); a fix on a Go-only surface (a `pulse.Options` field, a CLI flag, an extension registration func) drops the Path and names the field in its Hint. Predict's `defaults_applied[].path` and `suggestions[].path` are wire keys too (`TestPredict_DefaultsAppliedPathsAreWireKeys`).

**Predecessor references.** `TestNoOrbitPrefix` (no type constant) and `TestNoOrbitPrefixes` (no error code) carry a predecessor-project prefix.

**Descriptor contracts.** `TestPredictNoExecutionImports` — predict imports neither `internal/service` nor `internal/processing`. `TestDescriptorNoFmtSprintf` — no `fmt.Sprintf`-built JSON in the descriptor packages. `TestGoldensNotHandEdited` — every golden ends with a valid `// golden-hash:` line. `TestPerPackageCoverageFloors` — `.github/coverage-floors.txt` is sound; `make cover` measures against it.

**Skill coverage (existence).** Each asserts an atomic skill exists at the stem derived from the name. An operator type's stem is `skills.OperatorStem`: `op-` plus the whole type name lowercased with `_` → `-` (`AGG_COUNT` → `op-agg-count`, `WIN_LAG` → `op-win-lag`): `TestSkillsCoverAllComponents` (aggregators / attributes / filterers / groupers / features: `op-agg-*`, `op-attr-*`, `op-filter-*`, `op-group-*`, `op-feat-*`), `TestSkillsCoverAllWindowTypes` (`op-win-*`), `TestSkillsCoverAllRegressions` (`op-reg-*`), `TestSkillsCoverAllMatrixOps` (`op-mat-*`), `TestSkillsCoverAllOverlayKinds` (`op-overlay-*`). The rest: `TestSkillsCoverAllFieldTypes` (`type-` + the kebab type name), `TestSkillsCoverAllMCPTools` (`tool-*`, strip `pulse_`), `TestSkillsCoverAllSynthDistributions` (`op-synth-` + the kebab distribution name).

**Skill coverage (content).**

- `TestSkillsCoverAllPurposes` — built-in Purposes valid; a missing one fails unless exempted (`guided-analysis.md`).
- `TestSkillsCoverShardingTopics` — `skills/cohort-schema-design.md` carries a `Sharded` section.
- `TestSkillsCoverAllCliLeaves` — two-way CLI leaf ↔ `docs/src/cli/reference.md` sections (above). `TestCLIReferenceCurrent` holds that generated page byte for byte (`make docs`); `TestCliHelpMatchesFlagsDoc` holds it to the tree per leaf, flag names both ways.
- `TestSkillsCoverAllOperatorComponents` — each operator's `ComponentSchema` keys appear in its rendered atomic skill (the generated `## Contract` names every key, so the skill carries `<!-- generated: contract -->`).
- `TestSkillsCoverProfileGet` — per shipped feature profile, a pruned skill or example lists, searches and reads exactly like a never-existing name.
- `TestSkillsCoverFeatureFences` — an operator, feature-owned tool or `<kind>:<name>` mention in a skill body sits in a fence naming it, never in a `description` (`skill-pack.md`).
- `TestSkillsCoverAllCrossReferences` — every skill stem named in CLAUDE.md, `.claude/reference/**` or the pack resolves, and a `` `skills/<stem>.md` (Section) `` pointer names a real heading. Deliberate non-skill kebab tokens ride the allowlist in `skill_xref_test.go`.
- `TestSkillExampleTagPointersResolve` (`internal/descriptor`) — every `tags=[…]` list in a raw skill body (fenced spans included; `seeTags` parsing, `a|b` alternatives) matches ≥ 1 shipped example; fix a failure by pointing at a tag an example carries or tagging the example (tags come from `examples.CanonicalTags`), never by dropping the pointer's lead.

**Atomic-skill structure.** `TestAtomicSkillHasRequiredSections` (required `##` set per family), `TestSkillTokenBudget` (per-family body size against the `skills.BodyBudget` tiers — `skill-pack.md` (Token budget)), `TestOperatorHasAtomicSkill` (every operator, MCP tool and field type has a file at its stem), `TestEveryOperatorHasAnExampleTag` (every operator is tagged on at least one `internal/examples/<dir>/*.json`), `TestSkillPurposeSectionsCurrent` (every built-in `op-*` skill carries the `use-when` marker, and the `reading-the-output` marker exactly when its operator has `Interpretation` entries — `skill-pack.md` (Generated sections)).
