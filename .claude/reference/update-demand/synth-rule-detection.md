# Update Demand — synth: rule detection

Per-area slice of the Update Demand trigger table. Index: `.claude/reference/update-demand.md` — load it first, then only the slice(s) your change triggers. Rule: a change in column 1 also updates everything in column 2, in the same PR.

Scope: `--suggest-rules` gating detection, co-missing detection, rule-candidate emission order, exact-dependency detection. **Contract: `.claude/reference/synthetic-data.md` — load it first.** Each detector's full contract and the measurement behind each rule: `.claude/reference/synthetic-data/rule-detection.md` and `synthetic-data/rules-reporting-and-suggest.md`.

Shared by every row: thresholds are package constants with their reasoning at the declaration, never `ProfileOptions` fields (a threshold meant to mean the same thing across cohorts is not tunable per run). Every detector rides the existing profile scan — assert it by counting bytes pulled. Absent the flag the profile document is byte-identical; with it only `warnings` moves (`Profile.RuleCandidates` is `json:"-"`: an unreviewed structural claim never rides the document that drives generation). The candidate file is the bare rules array `--rules` consumes unmodified, and the only proof is a generation round trip — unmarshalling into `[]RuleSpec` passes against predicates that do not compile or never fire. Every emitted `when` / `set_expr` is compiled against the rule layer's own environment before it is written. Numeric gates and terms go through `round()` (a bare `==` reads the pre-rounding float and under-fires); assert by firing on generated rows. Over a cardinality cap a detector abandons the field, never truncates. Thin candidates ship with their support. No error code is added and `format_version` does not move, so neither golden moves. Common companions: `internal/synth/rules_evidence.go`, `internal/synth/profile.go`, `internal/synth/warning_summary.go`, `internal/cli/warnings.go` (`writeSuggestedRulesCaveat`), `skills/synth-rules-from-profile.md` (Detecting rules from the data), `docs/src/cli/profile-create.md`.
