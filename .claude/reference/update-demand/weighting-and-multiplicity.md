# Update Demand — weighting and multiplicity

Per-area slice of the Update Demand trigger table. Index: `.claude/reference/update-demand.md` — load it first, then only the slice(s) your change triggers. Rule: a change in column 1 also updates everything in column 2, in the same PR.

Scope: `Request.Weight` and every per-slot weight (the weighting row), computing weights with `Pulse.Rake` (the Rake row), and `types.Multiplicity` with its folds and adjusted outputs (the Multiplicity row). **Contracts: `.claude/reference/weighting.md`** (index + slices under `weighting/`) and **`.claude/reference/execution-modes/inference.md`** (Multiplicity) — load the one your change touches first; the rows below list companions and the rules a change most often breaks.

Every row: additive `omitempty` / `omitzero`, `format_version` stays `"1.1"`; a request with no weight / no multiplicity block is byte-identical including `CanonicalHash`. Regenerate payload-schema, manifest and API goldens. A new code needs its error-code companions.
