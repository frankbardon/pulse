## Overlays — SERIES host (measure, partitions, FORMULA, rolling windows)

Continues the `## Overlays` section of `.claude/reference/execution-modes/overlays.md` (split out at U35 E4-S2 when that slice reached its ceiling).

- **Series measure (`params.field`, U46 E1-S1).** Every process-host series kind that scores one aggregation (`internal/seriesfield.Kinds`: the prior / rolling / baseline / sibling pairs, `OVERLAY_YOY` and the three `_TOTAL` kinds) reads `params.field`, an aggregation OUTPUT LABEL (`types.AggregationLabelOf`: explicit `Label`, else `TYPE_field`); absent or empty scores `Aggregations[0]`. `applyOverlaysSeriesToResponse` resolves it once per spec (`seriesfield.Resolve` → `Scored{Index, Column}`) and hands the spec the host `buildSeriesHostFromGroupedResponse(req, resp, aggIndex, column)` builds (one view per distinct scored column), so the buffered, streaming and parallel tails agree. **Element columns (U30 E4-S2).** `params.field` may name an expanded element column `<label>[<element label>]` of a `params.expand` vector aggregation on all three hosts: `seriesfield.Columns` (built once, `vectors.AggregationColumns`) lists each aggregation's columns — predict over the schema the slot executes over (Process: the field-ref walk's / `ValidateOverlays`'; Compose: `composeSlotInputSchema`; chain: `chainStageInputSchema`), the runtime from the prepared slot's inline element labels (Process) or the same schema handed in (`ApplyComposeOverlaysWithSchemas` ← `Service.requestInputSchema`, `ApplyChainOverlaysWithSchemas` ← `descx.ChainStageInputSchema`), read only for a bracketed name. An element column is never `array_valued` (`Scored.Element`); the bare label still is; an element the slot does not write is `PULSE_OVERLAY_FIELD_UNKNOWN`, its `available` listing every element column after its label. A NaN host value (an unanswered element, or any scalar aggregate's undefined figure — `AGG_AVERAGE` of a group with no value) is MISSING on all three hosts (E4-S5): the entry keeps its key but carries no `statistic` (absent, never `null`), raises no warning and stays out of the summary count; on the Process host it never poisons a `_TOTAL` and a `_PRIOR` kind compares across the gap, and on a Compose / chain pair (`undefinedSeriesPair`: `INDEX_VS_REF`, `DELTA_VS_REF`, `PANEL_INDEX_VS_REF`, `T_VS_REF`, `Z_VS_REF`, `INDEX_VS_STAGE`, `DELTA_VS_STAGE`) either side's NaN skips the pair before any kernel, so no spurious `PULSE_OVERLAY_REF_ZERO`. A `null` statistic stays reserved for a figure the kind computed and found undefined (zero reference, degenerate test). Gate: `TestOverlayHosts_UndefinedValueIsMissing`. A two-sample vs-ref kind reads an element as a bare mean (params triple required, `label` the column). Gates: `TestProcessOverlay_ScoresElementColumn`, `TestComposeOverlay_ScoresElementColumn`, `TestChainOverlay_ScoresElementColumn`, `TestProcessOverlay_ElementColumnRefusedParity`, `TestResolve_ElementColumn*`, `TestAggregationColumns`. Predict runs the same `Resolve` (`validateOverlaySeriesField`, on the defaults-resolved request, SERIES host only): an unknown label or non-string field is `PULSE_OVERLAY_FIELD_UNKNOWN`, Details `{index, kind, field, available}` identical on both sides. No wire echo of the scored label — the default is documented instead. `Pulse.ApplySeriesOverlays` (caller-held points) has no aggregation and ignores the param.
- **Series partitions (`params.partition_by`, U46 E2-S1 / E2-S2).** With two or more groupers the grouped-Process host is the composite rows; the prior / rolling / baseline / sibling pairs and the three `_TOTAL` kinds (`internal/seriespartition.Kinds`; `Ordered` = the first eight) run once per PARTITION — the rows sharing the first `depth` key elements. `seriespartition.Depth` is the one reading, called by `applyOverlaysSeriesToResponse` (per spec, beside `seriesfield.Resolve`) and predict `validateOverlaySeriesPartition`: absent / null = every key but the last (one grouper ⇒ 0, the pre-U46 walk), an explicit list must be a LEADING PREFIX of the group key columns (`vectors.GroupKeyField`), `[]` = 0; anything else is `PULSE_OVERLAY_PARTITION_INVALID`, Details `{index, kind, partition_by, groups, reason, field}` identical on both sides (the #346 `PULSE_OVERLAY_REF_INCOMPATIBLE_WITH_SHAPE` refusal of these kinds is gone; `OVERLAY_YOY` reads its own rule, below). `runSeriesHandlerPartitioned` splits the host with `seriespartition.Partition` — KEY EQUALITY on the prefix, never contiguity, because a user `sort` can interleave buckets — runs the UNCHANGED handler on each sub-host (rows in host order, full key tuples, the host's group fields / grouper kinds) and merges: entries back on their host ordinals; summary Min / Max widen, Count sums, other fields the first partition's; warnings one per code (first raiser's message and Details, `group_count` restated as the host's, `partitions` = raising count). One partition runs the handler on the host itself, byte-identical. Every tail (buffered, streaming, parallel) calls the same hook. `seriespartition.Partition` / `RowKeys` / `KeyColumns` are the reusable split for any consumer of composite rows by a key prefix. The host builder keys each row on `vectors.GroupKeyField` (a vector-input grouper with no `Field` keys on `<TYPE>_<first field>`, not the empty column). A `_TOTAL` kind's total (`computeSeriesGrandTotal`) or mean and SD (`computeSeriesWelfordPopulation`) is therefore the partition's own; `partition_by: []` restores the grand total. No streaming accumulator exists outside the handler — every tail folds the finished host — so streaming needs no change; the handlers set only `Baseline` beyond Min / Max / Count, so the summary merge is complete, and a zero-total warning's `grand_total` / `mean` / `sd` Details are the first raising partition's. Predict adds `PULSE_ADVISORY_SERIES_AXIS_NOT_DATE` on an ordered kind whose implicit series axis (the last grouper) is not date-family (`predict-inspect.md`, Advisories).
- **YoY partitions (U46 E2-S3, #429).** `OVERLAY_YOY` is not a prefix kind (`seriespartition.Applies` is false): `seriespartition.YoY(groups, isDate, spec, index)` — called by the runtime `seriesPartitionFor` (authored `GROUP_DATE`) and predict `validateOverlayYoY` (instance route, so a hidden `GROUP_DATE` is not one) — requires EXACTLY ONE date grouper anywhere in `groups` and partitions on every OTHER key index (`seriespartition.PartitionOn`, key equality on arbitrary indices). Refusals are shared: one non-date grouper keeps the pre-U46 `{index, kind, host_grouper, required}`; zero or 2+ date groupers among N ≥ 2 are `PULSE_OVERLAY_REF_INCOMPATIBLE_WITH_SHAPE` `{index, kind, groupers, date_groupers, required}`; an explicit `partition_by` must name exactly the non-date columns in any order, else `PULSE_OVERLAY_PARTITION_INVALID` (`reason` `not_string_list` / `unknown_field` / `not_non_date_keys`, `field` the repeated, date or missing column). The plan PROJECTS each sub-host onto the date key (key, group field, grouper kind), so the unchanged single-date handler — whose daily / hourly arms read `key[0]` and whose coarse strides walk ordinals in host order — runs inside each segment; the runner restores every entry's full composite key. The handler's own composite-host refusal stays as defense for a caller-built view. The `frequency` fallback reads `seriespartition.DateGrouper` (the date grouper wherever it sits), on predict and in `promoteYoYFrequencyFromGroupParams`. YoY stays outside `Ordered` and `PULSE_ADVISORY_SERIES_AXIS_NOT_DATE` (its axis is the date grouper by construction). Gates: root `TestMultiGrouper_YoYPerPartition` (every layer-returning mode, date first / middle / last, frequency from an inner date grouper), `TestMultiGrouper_YoYRefused`, `TestOverlay_YoY_GroupedPartitions`, `TestValidateOverlay_YoYMultiGrouper`, `seriespartition.TestYoY_Refused`.
- **SERIES FORMULA (U35 #432).** `OVERLAY_FORMULA` on `Request.Overlays` of a grouped Process (groups + aggregations, no crosstab) runs once per host row (`processing.applyFormulaSeriesWith`, `internal/processing/overlay_formula_series.go`; `seriesOverlayHandlers` entry, the dispatcher swaps in the registry-aware arm through `callSeriesHandler`). Namespace: `value` (the scored aggregation — FORMULA joins `seriesfield.Kinds`, so `params.field` applies), `total` (sum of the partition's present values), `prior` (the nearest earlier PRESENT row, NaN on the first — the Compose SERIES arm's read), `baseline` (only with `params.baseline_position`, a 0-based row of the partition; NaN when that row has no value). FORMULA joins `seriespartition` (ordered), so with N ≥ 2 groupers `total` / `prior` / `baseline` never cross a partition. A row with no value emits an entry with no statistic; a non-finite result stays in the payload (null) and out of `summary.count`; no `Baseline`. Refusals, in predict's order and identical on both sides: `overlayhost.SeriesSpecRefusal` (FORMULA is a dual-dispatch row: empty `Ref`, scope `group`, details `host: "series"`), then `formulaident.RequestSpecRefusal` (no usable formula `PULSE_OVERLAY_PARAM_MISSING {index, kind, param: "formula", reason}` — `formulaident.MissingFormula`, the rule of EVERY FORMULA arm incl. MATRIX and Compose (E4-S3) — `PARSE_ERROR`, `total()`, vector built-ins, `baseline_position` not a non-negative integer → `PULSE_OVERLAY_LEVEL_OUT_OF_RANGE {param, baseline_position}`, unknown identifier → `INVALID_IDENT`) — the runtime runs it before the `params.field` / `partition_by` reads, as predict's per-kind validator precedes them — then `seriesfield` / `seriespartition`. A `baseline_position` at or past a partition's length is `PULSE_OVERLAY_REF_UNKNOWN {index, kind, baseline_position, series_length}` (`formulaident.BaselineOutOfRange`; the SERIES dispatcher stamps the index, `codeAt`): predict raises it too when every in-partition grouper (past the `seriespartition.Depth` prefix) is a `GROUP_CATEGORY` over a categorical field — `categoricalSeriesLengthBound`, the product of dictionary sizes (null rows form no group), `series_length` = the bound — and only on a spec no other rule refused (E4-S3); a data-dependent axis (range, date, quantile, set) stays runtime-only. A grouped request with no aggregations takes the SCALAR rule's SERIES dispatch message. The shared gate also aligned the MATRIX arm's syntax error (was its compiler message). **Escape analysis:** the SERIES arm hands `applyFormulaSeriesWith` a COPY of the registry — the compile captures it (the `lookup` method value), and a leaked `exts` heap-allocated the grouped tail and the streaming grouped path's per-run state on every run (`TestStreamingGrouped_SingleGrouperAllocCeiling`). Gates: root `TestSeriesFormula_{Namespace,MatchesComposeSeries,RefusalsMatchPredict,BaselineOutOfRange,BaselineBoundMatchesPredict}`, `TestComposeFormula_MissingFormulaMatchesPredict`, the partition / field suites (`mgSeriesOverlaySpecs` carries a FORMULA), `TestSeriesOverlay_SpecRefusalsMatchPredict`.
- **Rolling windows (U35 #431).** `rollingCarrier` (shared by `OVERLAY_INDEX_VS_ROLLING_MEAN` / `OVERLAY_ZSCORE_VS_ROLLING`) evicting the only value of a window-1 ring resets to the empty sample instead of dividing by `count - 1 == 0` — that NaN nulled every row from the third on. Window 1 of the index equals `OVERLAY_INDEX_VS_PRIOR`. The floor is shared: `overlayhost.RollingWindowFloorRefusal` (`RollingWindowMin`: 1, or 2 for the z-score, whose rolling sample SD is undefined over one point and would answer null at every row) — `PULSE_OVERLAY_LEVEL_OUT_OF_RANGE {kind, param, window, min}` (+ `index` in predict), raised by predict's `validateOverlayRollingWindowParam` and `applyZScoreVsRolling`. Gates: root `TestRollingOverlays_Window1`, `TestOverlay_IndexVsRollingMean_Window1` (its tolerance helper `assertSeriesEntryStatisticWithinTol` had passed a NaN statistic). **Warm-up (`params.min_periods`, U50 E2-S3).** Both kinds read it beside the window (`processing.extractRollingParams`); `overlayhost.RollingMinPeriods` resolves it for predict and runtime alike: absent = the window, else an integer from `RollingWindowMin` to the window, otherwise `PULSE_OVERLAY_LEVEL_OUT_OF_RANGE {kind, param: "min_periods", min_periods, min, max}` (+ `index` in predict). A present point gets a figure once the carrier holds `min_periods` present priors (`rollingCarrier.ready`; absent points never count); before that `null`, no warning. Default = window was a behaviour break for the z-score, which used to answer from two priors. Gates: `TestRollingOverlays_MinPeriods` (hand-computed, absent point included), `TestRollingOverlays_MinPeriodsRefused`, root `TestRollingOverlays_MinPeriodsPredictParity`, `TestRollingMinPeriods`.
- **Prior-period tests (U47 #328).** `OVERLAY_T_VS_PRIOR` / `_Z_VS_PRIOR` / `_PROP_Z_VS_PRIOR` (`overlayhost.PriorTestKind`) test each period against the last present one (Ref `Prior`, lag 1) on TWO `Request.Overlays` hosts: a grouped Process (SERIES; `seriesfield` / `seriespartition` `Ordered` kinds) and a crosstab with NO column grouper (MATRIX handler `applyPriorTestMatrixAt`, the rows of the implicit Total column; `params.field` resolves against the cell, partitions are the leading row keys). Legs are read off components — the series arm through `seriesLegSource` (`withPriorLegs` in `hostFor`, the scored aggregation's `Components.Aggregations[].Groups`), the crosstab arm through `MeanLeg` / `CellAt` + `pairwiseSampleSize` — and run the pairwise kernels (`pwOutcome.stat`). The first present period of each partition carries a NaN statistic (`null`) and NO `PValue`, so it is never a multiplicity member (`pSiteSeriesPValue` files only non-nil p); a missing period keeps its key with no statistic and does not advance the carrier; a degenerate pair is NaN + one `PULSE_OVERLAY_REF_ZERO` per skip reason. Shared refusals (`internal/overlayhost/vs_prior.go`, predict `internal/descriptor/overlay_vs_prior.go` in the runtime's order): columns (`PriorColumnsRefusal`, pre-pass), multi-measure, Ref / Scope (SERIES rule on both hosts), Level / Within (crosstab runtime; series predict-only like its siblings), measure type (`PriorMeasureRefusal`; extension types by declared schema / emitted keys), normalized crosstab (proportion kind), components disabled. Compute plan: `requestOverlaysReadGroupComponents` keeps `Aggs` + `Groups` under a `return`; the crosstab form rides `OverlayReadsHostComponents`. Weighted (`ClassAware`, both kinds): every leg reads N* = `sum_weights` (frequency) or `n_eff` (probability) — `readMeanLeg` for the Welford triple, `seriesLegSource.floorN` for the proportion n, p̂ the weighted mean — and stamps NO `summary.parameters` weight keys (a partitioned layer merge would keep only the first partition's). Buffered (`Streamable() == false`). Gates: root `TestVsPrior_*`, `TestResolveComputePlan_PriorKindsKeepGroupComponents`, the `ov_prior*` weight-reference rows, `prior_*` overlay parity cases.
