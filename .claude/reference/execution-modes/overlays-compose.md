# Execution modes — overlays: the COMPOSE host

## Overlays — COMPOSE host (arm, series value + key, fan-out)

Continues the `## Overlays` section of `.claude/reference/execution-modes/overlays.md` (split out at U66 E2-S2 when that slice reached its ceiling).

- **COMPOSE arm.** `internal/service/compose_overlay.go` gates slot-label, schema, key alignment and dict drift, in that order (`DictPrefixFast` ⇒ prefix probe; the schema match precedes the key-set gate since U67 E2-S4, so slots whose grouper kinds AND keys differ are `PULSE_OVERLAY_SCHEMA_DIVERGENT` at predict and runtime alike; predict-compose twins the cell-shape arm off each crosstab cell aggregation's type, `overlayhost.CellShapeOf`, held to the runtime's `canonicalCellShape` by `TestCellShapeOf_MatchesRuntime`; pinned by `TestCompose_SchemaGatePrecedesKeySetMatchesPredict`). Handlers may read a slot's `Components.Crosstab` through `processing.ComposeHostView` / `ComposeSlotView`, whose `State()` is four-valued (slot-absent / disabled / non-crosstab / present) — contract in `update-demand.md`. The panel's slab-partition and distinct-key gates are twinned in `internal/descriptor.ValidateCompose`; its cell-aggregator ADMISSION is runtime-only, like the MATRIX arm's.
- **Compose series value + key (U46 E1-S2).** A Compose kind whose SERIES arm scores one slot aggregation (`seriesfield.ComposeKinds`: `INDEX_VS_REF`, `DELTA_VS_REF`, `T_VS_REF`, `Z_VS_REF`, `PANEL_INDEX_VS_REF`, and since U66 #441 `FORMULA` — its `value` / `ref_value` / `slot.<label>.value`) reads `params.field` on every slot it reads (absent = each slot's `Aggregations[0]`). `ApplyComposeOverlaysWithRequests` narrows each non-crosstab slot, after label resolution and the panel slab gate and BEFORE the key-set gate, to its group columns (`vectors.GroupKeyField`) plus that one value column (`projectComposeSeriesSlots`; a shallow copy, so `ComposedResponse.Responses` keeps every column) — every kind's slots are narrowed, the field read only for those six. `encodeSeriesRow`'s entry key is unchanged apart from the dropped value fold; before, it took the alphabetically first numeric column as the value and folded the other aggregations' VALUES into the key (`PULSE_OVERLAY_KEY_SET_DIVERGENT`, or the wrong measure). Predict-compose Gate 4 runs the same `seriesfield.ResolveComposeSlot` (`PULSE_OVERLAY_FIELD_UNKNOWN`, Details `+slot`; a slot with an untyped, unlabelled aggregation is judged on its smart defaults resolved against its schema — the joined one for a joined slot, header only (`composeSlotAsExecuted`); it defers to the runtime only when that schema does not load or defaults are off) and refuses two SERIES slots whose sorted group key columns differ by name (`PULSE_OVERLAY_KEY_SET_DIVERGENT`, Details `{index, reference, target, reference_fields, target_fields}`). The bare `ApplyComposeOverlays` (no Requests) keeps the sorted-first rule.
- **Compose fan-out (U66 #443).** Every Compose kind but `FORMULA` (host = the first target, the rest read as `slot.<label>`) and the two panel kinds reads ONE target, so it fans out: `INDEX_VS_REF`, `DELTA_VS_REF`, `T_VS_REF`, `Z_VS_REF`, `T_CELL`, `Z_CELL`, `PROP_Z_CELL`, `CHISQ_VS_REF`, `RANK` (`overlayhost.ComposeFanOutKind`) sit in `composeOverlayMultiLayerHandlers` and emit one layer per target, in Targets order, each the single-target handler's layer for its pair (`composeFanOut`); one target keeps the spec's Name (byte-identical), two or more are `<name>__<target>` (a MATRIX layer's `CellLabel` follows). `T_CELL` / `Z_CELL` read each target's OWN authored cell type (`composeCellTypes(requests, refIdx, targetIdx)` per target layer, `composeCellTypedHandlers`); `ComposeOverlayTwoSampleInputsRefusal` judges every target. Cap: `overlayhost.ComposeFanOutCapRefusal` (Details `{index, kind, observed, cap}`), predict-compose Gate 3 and the dispatcher after target resolution. Layer → spec map: `overlayhost.ComposeLayerSpecs` — read by the multiplicity fold (`composeLayerMultiplicity`: each target layer its own `layer` family, `compose` pools) and predict's `p_values` (one per layer); warnings route by layer position (`ApplyComposeOverlaysRouted`), `overlay_index` stays the spec index. Gates: `TestComposeFanOut*` (integration, processing), `TestComposeKinds_NoSilentTargetDrop`, `TestComposeFanOutKinds_MatchMultiLayerTable`.
- **Compose code cells (U66 #445).** A crosstab slot an overlay reads (reference, targets; every slot with no targets) whose cell aggregation is a categorical code (`codeInput`: `AGG_MODE` or an `EmitsInputValue` extension over `categorical_*` / `packed_bool`, judged against the slot's input schema) is refused for a kind that reads the cell VALUE — `overlayhost.ComposeReadsCellValue(kind, cellMoments)`: `INDEX_VS_REF`, `DELTA_VS_REF`, `PANEL_INDEX_VS_REF`, `PROP_Z_CELL`, `PROP_Z_PANEL`, `CHISQ_VS_REF`, `RANK`, `FORMULA`, and `T_CELL` / `Z_CELL` unless the cell carries moments (`cellCarriesMoments` with components enabled — `disabled` is the effective gate). One rule (`descriptor.composeCellCodeRefusal`, inside `ComposeOverlayArrayValuedRefusal`), predict Gate 2d and `Service.applyComposeOverlays`; `PROCESSING_CONFIG`, Details `{overlay_index, kind, slot, host: "requests[j].crosstab.cell", aggregation, label, reason: "categorical_code", field, field_type}`. A chain has no crosstab host (`mergegate.ChainRefusal` refuses every crosstab stage, `PULSE_CHAIN_NOT_MERGEABLE`). Gates: `TestComposeReadsCellValue` (overlayhost), `TestComposeReadsCellValue_MatchesHandlers` (processing), `TestComposeOverlay_CategoricalCodeCell*`, `TestChainOverlay_CrosstabStageNeverScored` (integration).
