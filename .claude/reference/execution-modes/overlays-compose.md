# Execution modes — overlays: the COMPOSE host

Per-topic slice of the execution-modes reference. Index (Mode index + section map): `.claude/reference/execution-modes.md` — load it first, then only the slice(s) your engine work touches.

## Overlays — COMPOSE host (arm, series value + key, fan-out)

Continues the `## Overlays` section of `.claude/reference/execution-modes/overlays.md`.

- **COMPOSE arm.** `internal/service/compose_overlay.go` gates slot-label, schema, key alignment and dict drift, in that order. The schema match precedes the key-set gate, so slots whose grouper kinds AND keys differ are `PULSE_OVERLAY_SCHEMA_DIVERGENT` at predict and runtime alike. Predict-compose derives each crosstab cell's shape from its aggregation type (`overlayhost.CellShapeOf`, held to the runtime by `TestCellShapeOf_MatchesRuntime`). Handlers may read a slot's `Components.Crosstab` through `processing.ComposeHostView` / `ComposeSlotView`, whose `State()` is four-valued (slot-absent / disabled / non-crosstab / present). The panel's slab-partition and distinct-key gates are twinned in `internal/descriptor.ValidateCompose`; its cell-aggregator admission is runtime-only, like the MATRIX arm's.
- **Compose series value + key.** A Compose kind whose SERIES host scores one slot aggregation (`seriesfield.ComposeKinds` is the list) reads `params.field` on every slot it reads (absent = each slot's `Aggregations[0]`). Before the key-set gate, each non-crosstab slot is narrowed to its group columns plus that one value column (a shallow copy, so `ComposedResponse.Responses` keeps every column); an extension kind honours `field` only when it declares `HonoursField`. The reason this exists: without the narrowing the alphabetically first numeric column became the value and the other aggregations' values folded into the key — a spurious `PULSE_OVERLAY_KEY_SET_DIVERGENT`, or silently the wrong measure. Predict-compose runs the same `seriesfield.ResolveComposeSlot` (`PULSE_OVERLAY_FIELD_UNKNOWN`, Details `+slot`; an untyped, unlabelled aggregation is judged on its smart defaults against the slot's schema, deferring to runtime only when that schema does not load or defaults are off) and refuses two SERIES slots whose sorted group key columns differ by name (`PULSE_OVERLAY_KEY_SET_DIVERGENT`, Details `{index, reference, target, reference_fields, target_fields}`). The bare `ApplyComposeOverlays` (no Requests) keeps the sorted-first rule.
- **Compose fan-out.** Every Compose kind that reads ONE target fans out (`overlayhost.ComposeFanOutKind` is the list; `FORMULA` — host = first target, the rest read as `slot.<label>` — and the two panel kinds do not). It emits one layer per target, in Targets order, each the single-target handler's layer for its pair. One target keeps the spec's Name (byte-identical); two or more are `<name>__<target>`. `T_CELL` / `Z_CELL` read each target's OWN authored cell type. Cap: `overlayhost.ComposeFanOutCapRefusal` (Details `{index, kind, observed, cap}`), at predict and in the dispatcher. `overlayhost.ComposeLayerSpecs` is the layer → spec map read by the multiplicity fold (each target layer its own `layer` family, `compose` pools) and predict's `p_values` (one per layer); warnings route by layer position, `overlay_index` stays the spec index. `TestComposeKinds_NoSilentTargetDrop` pins that no target is dropped.
- **Compose code cells.** A crosstab slot an overlay reads whose cell aggregation is a categorical code (`AGG_MODE`, or an `EmitsInputValue` extension, over `categorical_*` / `packed_bool`) is refused for a kind that reads the cell VALUE — `overlayhost.ComposeReadsCellValue(kind, cellMoments)` is the rule; `T_CELL` / `Z_CELL` pass only when the cell carries moments with components enabled, and an extension kind passes only when it declares `ReadsCellCountsOnly`. One rule (`descriptor.composeCellCodeRefusal`) for predict and runtime: `PROCESSING_CONFIG`, Details `{overlay_index, kind, slot, host: "requests[j].crosstab.cell", aggregation, label, reason: "categorical_code", field, field_type}`. A chain has no crosstab host (every crosstab stage is `PULSE_CHAIN_NOT_MERGEABLE`).
- **Compose series-axis advisory.** Predict-compose raises `PULSE_ADVISORY_SERIES_AXIS_NOT_DATE` for an ordered per-partition kind with no explicit `partition_by` whose first target slot is a SERIES host of ≥ 2 groupers whose last is not date-family — the Process rule, with `details.slot` = `overlays[i]` plus `request` / `target`. Predict only; the runtime never reads it. Long form: `predict-inspect.md` (Advisories).
