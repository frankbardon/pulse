# Execution modes — streaming, projection, parallel decode, cancellation, timeout

Per-topic slice of the execution-modes reference. Index (Mode index + section map): `.claude/reference/execution-modes.md` — load it first, then only the slice(s) your engine work touches.

## Streaming Process

`pulse.ProcessStream`, `pulse api process --stream`. Four orchestrator modes — single-pass, grouped, two-pass attributes (Welford-Pébaÿ), streaming features. NDJSON, one row per line. The forced-buffered list is `skills/streaming-and-watching.md`; the rule is `processing.canStream`, and predict's `computeStreamable` must agree with it (`TestPredict_Streamable_MatchesRuntime`). Notable buffered cases: median / percentile / zscore aggregators, `ATTR_PERCENTILE`, `ATTR_PREVIOUS_STATE` (orders every record of a subject), `GROUP_QUANTILE` / `GROUP_DATE` / `GROUP_KMEANS`, windows, built-in decimal paths (a `Streamable` extension aggregator does stream a `decimal128` target), tier-1 tests beside groupers / features / two-pass, every tier-2 test, and a buffered matrix spec (`types.MatrixSpec.Streamable()` false; `matrix-and-vectors.md`, Matrix slot).

**No-aggregation work streams.** A request with no aggregation streams when it carries a matrix, a tier-1 test or a regression (`processing.hasStreamingWork`; predict and the merge gate follow — a tests- or regression-only request is refused a merge for its tests / regressions, never for a missing aggregator). Tests beside a streamable regression stream too: the ungrouped scan folds each filter-passing record into both in buffered record order and finalizes tests before regressions, so a whole experiment readout is ONE streaming request; a grouper, feature or two-pass attribute beside a regression still buffers. Such a request emits no `data` row on either arm, so `ProcessStream` yields no row and `ProcessStreamResult` sends only the `StreamCompleted` terminator (`TotalRows` 0); results ride `Response.Tests` / `Regressions` / `Matrices`. A request with none of that work (empty; filters, attributes or features only) stays buffered. Pinned by `TestNoAggregationRequests_StreamAndMatchBuffered`.

**Response shaping on a stream.** `return` wraps the finished iterator at the facade (`returnshape.NewRowIter`): every row is a deep-cloned, pruned copy equal to the buffered shaped `data` element (an excluded `data` yields NO rows). Components / Metadata are shaped COPIES, so the run keeps accumulating an excluded slot — except an excluded Components sub-part, which the compute plan never builds (the Compute plan paragraph of `.claude/reference/response-components.md`). The `returned` marker rides the terminal chunk only. Precision is wire-only — rows stay float64 and the shaped iterator's `MarshalRow` writes them. Run-time warnings reach a stream through the iterator's `Warnings()` / the terminator and the CLI's trailing `{"warnings":[...]}` NDJSON record (`.claude/reference/response-components.md` (Run-time warnings in the envelope and the stream)). `PULSE_RETURN_PATH_UNMATCHED` is raised by the buffered shaping pass only; predict lists the includes it cannot resolve without data as `return.unresolved_includes` (`predict-inspect.md` (Predict)). `return` participates in `Request.Hash`; no effective block ⇒ byte-identical.

**Extension operators route on their DECLARED flags**, because the no-execute predict arm can read only the declaration and both arms run one rule:

- `Streamable` decides streaming (aggregators, groupers, attributes, tier-1 row tests; features on the returned value). `Streamable:false` runs buffered even when the value is online-capable.
- `Mergeable` (probe-validated — `PULSE_EXTENSION_MERGEABLE_MISMATCH`) decides merging for aggregators and groupers, decimal128 targets included. Extension filterers and `row_local` attributes merge as row-local operators; `two_pass` / `buffered` attributes, features, windows and tests never merge. A merged grouper folds its components state through `extend.MergeableGrouper.MergeState`, and both reducers sum the (record, bucket) assignment count so a bucket-less grouper's `{total_n, n_null}` floor matches serial.
- Fused crosstab: an extension AXIS grouper fuses iff it declares `Streamable` (single-key; the adapter synthesizes `KeyFor`) or `FansOut` — both probe-validated. A `two_pass` extension attribute declines fusion like the built-in set. An extension CELL aggregator fuses only when it declares a fusable `MarginReducibility` (summable / mean_reducible / independent; requires `Mergeable`; probe-validated — `PULSE_EXTENSION_MARGIN_REDUCIBILITY_MISMATCH`); undeclared reads as recompute → buffered.
- Detail: `.claude/reference/architecture.md` (Extension surface).

**Two-pass attributes run in DECLARED order on every scan.** The buffered arm runs `req.Attributes` one after another, so attribute i sees the final output of every attribute before it. The streaming two-pass drive reproduces that with a pass plan (`internal/processing/two_pass_plan.go`):

- Each two-pass attribute gets a prepass LAYER — 0 when its inputs (followed back through row-locals) are source fields, else one more than the deepest two-pass attribute it reads. Scan L evaluates, in declared order, only what a layer-L `PrePass` depends on, then that layer `Finalize`s and the iterator rewinds. The last scan emits every attribute in declared order and folds the aggregations. Filters gate every scan; row counts and filter counters are taken on scan 0 only.
- Inputs come from `Field`, `Target`, `Predictors`, a vector attribute's resolved `Fields` and its `params.fit_on` filterers' columns, every identifier in an `ATTR_FORMULA` expression and, for an extension, its `FieldInputs` hook. An extension WITHOUT one (or an unparsable formula) is assumed to read every earlier attribute — correct, but may add scans.
- Why it exists: when the prepass saw no attribute output, `ATTR_FORMULA x` → `ATTR_ZSCORE x` silently gave `AGG_MAX(zx) = 0` streaming against 1.689 buffered.
- Two-pass-ness is PER SLOT, never by type alone: an `ATTR_FORMULA` calling `total(expr)` and an `ATTR_VEC_DISTANCE` over `std_euclidean` / `mahalanobis` are two-pass; the same type over a row-local metric streams in one pass; any fitted slot bound to a prebuilt fit (`vectors.FitBound`) is row-local whatever its type. `attrRequiresTwoPassIn` is the predicate every routing site reads.
- `total(expr)` sums its argument over filtered rows, nulls skipped (Σw·x under a frequency weight; a probability weight refused); it streams alone, buffers with groups / features, and the reducers and chain stages run it two-phase (`execution-modes/parallel-totals.md`). Otherwise the parallel reducers never take two-pass requests.
- The fitted vector attributes (`matrix-and-vectors.md` (Virtual vectors)) are two-pass the same way: a cohort-wide co-moment fit over the filtered rows `fit_on` admits, never per group; their fit warnings ride `Response.Warnings` on every arm. A row-local attribute's warnings ride the single-pass streaming and fused crosstab arms too, first and in declared order.

## Projected buffered decode

Per-request field projection on the decode iterator is **default-on** and output-transparent (byte-identical result, only faster and lighter per record). Opt out with `pulse.Options{DisableProjection: true}` or `--no-project` on `pulse api process` (the only CLI leaf exposing it).

**`processing.NeededFields(req, schema, ext)` must name every field the request reads.** It walks every request slot — aggregations, attributes (incl. expression identifiers for `ATTR_FORMULA` / `FILTER_EXPRESSION`), filterers, groups, windows, features, tests, regressions, sort, the whole crosstab block including margin aggregations, zone fields — and the built-in `Params` that NAME a field (`addAggParamFields`, plus `stratify` / `target` on the two feature ops). **A missed slot or param is SILENT:** the field is decoded onto no `Record`, `NumericValue` answers `ok=false` on every row, and the operator publishes a confident zero with `n_null` equal to the full admitted count. Extension operators without `FieldInputs` widen the retained set to every field. When you add a slot or a field-naming param, extend `NeededFields` in the same change.

**Decode plan.** `encoding.BuildDecodePlan(schema, retained)` (cached per iterator) yields segments: `SkipBytes{N}` (coalescing contiguous unprojected non-bit-packed runs) and `DecodeFields{Fields, Indices}` (`Indices[k]` = the schema position of `Fields[k]`). Both arms walk it through `RecordReader.ReadRecordReusedWithPlan` — the reuse arm into one reused `Record`, the buffered arm into a fresh `Record` per row. The map decoder survives only as a defensive projection-without-plan fallback and for non-iterator callers.

- **Bit-packed runs:** any contiguous `u4` / `packed_bool` run stays grouped — if any member is retained the whole run is one `DecodeFields` (unretained members still decoded to keep the cursor aligned); otherwise one `SkipBytes{K}`.
- **Null bitmap:** decoded once when any nullable field is retained; else one `SkipBytes{N: Schema.BitmapByteSize()}`.
- **Windowed record rows retain the full row.** A windows-only request (no group, aggregation or crosstab) emits the filtered records themselves as rows, so `NeededFields` widens to every field for exactly that shape; a window beside a group, aggregation or crosstab still projects (`TestWindowRecordRows_ProjectionTransparent`).

**Index-keyed reuse.** The reuse decoders write through `encoding.IndexedReusableRecord` (`SetNumericAt` / `SetNullFieldAt` / `SetWideFieldAt`, keyed by position in `Schema.Fields`) whenever the record implements it — `*processing.Record` does — and fall back to the name-keyed `encoding.ReusableRecord` otherwise. Positions are never looked up by name. A position is only meaningful against the schema the `RecordReader` was built with — record and reader are always built over the same schema.

**Positional `Record`.** `processing.Record` stores values, null marks and wide values positionally (a `[]float64`, three presence bit-planes — has-value / null / has-wide — and sparse wide slots), so an absent (projected-out) field stays distinguishable from a present zero. Name → slot resolution goes through a `recordLayout`: the full layout is cached per schema under a WEAK key and shared; a projected layout (`processing.BindRecords(schema, keep)`) stores only the retained fields, so a projected record costs O(retained). A name with no slot (feature / window outputs, an unreserved attribute label, a field outside the projection) lands in lazily-allocated overflow maps; a binding reserves its run's attribute labels (`execution-modes/shards-and-merge.md` (Attribute slots)). Invariants a later change must keep:

- `ClearForRow` clears the null and has-wide planes (not values).
- A `SetNumericAt` position outside a projected layout falls back to the overflow side by name.
- `Record.*At` positions are valid only for a record built over the reader's schema or a projection of it; a position past the schema panics rather than landing on another field.
- **Null drops the wide value:** the decoder's null signal clears the wide value, so a later `Set` on a decoded-null field never resurfaces a decoded mask or decimal; public `SetNull` keeps its documented asymmetry.
- **Duplicate field names** share ONE slot per name, whose metadata is the first occurrence: the last occurrence decoded wins the value, a null on any occurrence marks the name null — the former map-key behaviour.
- **Typed wide storage:** decimals live unboxed in a lazily allocated `[]encoding.Decimal128`; set-mask words sit bit-for-bit in the spare capacity of the value slice past its length, handed over through `encoding.TypedSetRecord`, so decoding a set allocates nothing. `WideValue` still returns the stored dynamic type exactly; a value a slot cannot hold typed AND exactly stays boxed on the overflow side — never truncated.

**Run-skip.** On the reuse arm the decoders skip rewriting fields whose on-wire bytes repeat the previous row (a cohort sorted by its parent key repeats the whole parent block across that parent's child rows). Self-activating: no declaration, no metadata, no format change; the buffered arm (a fresh record per row) never takes it. The contract is split:

- The READER (`internal/encoding/reader_runskip.go`) keeps the previous row's bytes (the whole stride on the full path; on the plan path the ASSEMBLED row) and passes keep=true to `encoding.RunSkipRecord.BeginRunRow(token, keep)` only when that baseline was decoded, successfully, under the same decode shape (full, or the same `*DecodePlan`), into the same record.
- The RECORD answers true only when the token is the reader that began its previous row, it has the full identity layout (projected and duplicate-name layouts always refuse), and no schema field was written since by anything but that reader's `*At` writes. **Every name-keyed schema-field mutator must call `resetRun()`**; `ClearForRow` zeroes the owner. Off-schema writes (attribute labels, feature outputs) do NOT withdraw the record.
- A kept row compares value bytes only and rewrites a changed field in full; nulls are then settled on the fields null on either row. After every row the record is identical, accessor for accessor, to a full decode — sorted and scattered, full and plan, across `Reset` rescans and shard boundaries.
- **Backoff:** the reader tallies rewrites over every 32 kept rows and, when more than half the fields changed, decodes the next 1024 rows without comparing before probing again (without it the comparison cost scattered data +40–50%).
- Pinned by `TestJoinShapeRunSkip_WorkCounts` (deterministic write counts: sorted keeps every row after the first; scattered never writes more than a full decode) and `BenchmarkJoinShape_RunSkip` (`-bench` only; sorted full gated ≥ 1.15x vs a same-commit no-compare arm, scattered reported, not gated).

**Grouped (`0x02`) reuse decode.** Over a parent-grouped cohort the reuse decoders do not expand rows (`internal/encoding/group_decode.go`; the logical-stream expansion stays for the map decoders and whole-row consumers — `byte-layout.md`, Parent groups). The physical row is read whole, every group index bounds-checked, and fields are written at their LOGICAL positions. The decode shape (full, or one plan, keyed by `*DecodePlan` identity as run-skip keys it) is compiled once into a selection.

- A `RunSkipRecord` keeps across rows whenever the previous row is valid under the same sink and plan — the backoff does NOT gate keeping (an unchanged group index is a certain hit); it only decides whether ROW fields are byte-compared or rewritten wholesale.
- A retained group whose index equals the previous row's is skipped outright; a changed one writes its value members from the entry cache, then settles nulls from the new and old entries' null bits.
- Entry cache per group, budget `groupEntryCacheBudget` (8 MiB per reader per decode shape): WHOLE mode when the whole dictionary fits, else DECIMALS mode (only decimal members — decimal decode is the one expensive member decode; caching cheap members in a thrashing table measured slower than decoding them), else none.
- Pinned by `TestGroupedDecode_MemberWriteCounts` (member writes == Σ changes × members exactly; a row with no index change takes zero member writes) and `TestGroupedDecode_CacheModesMatchFlat`.

Extension side: `docs/src/internals/extension-points.md` (FieldInputs hook). `skills/cohort-schema-design.md` deliberately carries no decode-plan section — it is the schema-authoring surface.

## Parallel buffered Process

`pulse.Options.DecodeWorkers`, default `0` ⇒ `runtime.NumCPU()`. A bounded per-segment worker pool inside `Process` for single-file (non-shard) cohorts. Engages only when `service.canParallelDecode` accepts: `DecodeWorkers != 1`, `recordCount >= service.parallelDecodeRecordThreshold`, single-file (sharded routes through `ShardWorkers`), a real path that maps (platforms: `byte-layout.md` (Memory-mapped reads)), and `processing.CanMergeRequestWithExtensions` true. Ineligible requests fall through to the serial scan. Components parity is exactly the Parallel shards rule (same partial, merge and emission); `ShardCount` stays 0 because a single-file run is not a shard run. A crosstab never merges, so this reducer never runs one.

Segments are stride-aligned over the mapped record region AND block-aligned: every boundary is a multiple of `linalg.MergeBlockSize` (4096 records; blocks spread evenly, the ragged tail in the last segment, surplus workers get an empty segment that never reaches its factory). `DecodeCallbackFactory(workerIdx, startRecord, recordCount)` hands each worker its segment's ABSOLUTE start record, so a block-keyed reducer keys row `startRecord+i` to block `(startRecord+i)/4096`. The plan is shared read-only; each worker owns a partial; partials fold in worker-index order. Exactness as Parallel shards (`shards-and-merge.md`, Reproducible sums). Surface: `internal/service/parallel_decode.go`, `parallel_reduce.go`.

## Cooperative cancellation (ctx polling)

Every SERIAL per-record loop polls the caller's ctx through `processing.CtxPoller` (`internal/processing/ctxpoll.go`): `Poll()` reads `ctx.Err()` on the first row and then once every `processing.CtxPollInterval` (4,096) rows — a counter mask, inlined, no allocation — so a pre-cancelled ctx stops before the first fold and a mid-run cancel within 4,096 rows. One poller per function, so a multi-pass scan keeps one cadence across `Reset`. The parallel arms read `ctx.Err()` every record. Only in-memory passes over an already-materialized slice are unpolled.

- **The ctx error is returned UNCHANGED** — `context.Canceled` / `context.DeadlineExceeded` itself, never coded, never wrapped. Mapping an INNER deadline (`RequestTimeout`) to `PULSE_LIMIT_EXCEEDED` is the entry point's job via `context.Cause`, not the loop's.
- **A new serial per-record loop adds a poll and a case** to the cancellation tables (`internal/processing/ctxpoll_test.go`, `internal/service/ctx_poll_test.go`).
- Fail-fast `ComposeParallel`: a still-running sibling stops with `context.Canceled`, so the reported error is the lowest-index failure that is NOT a sibling cancellation (`failFastWinner`); a caller-done ctx keeps the plain lowest-index failure. A ctx done before every slot launched, with no slot error, returns the ctx error — never a "successful" response with unrun `nil` slots.

## Request timeout (`Limits.RequestTimeout`)

An inner deadline on one top-level call, applied by `Service.BoundRequest` (`internal/service/request_timeout.go`) through `context.WithTimeoutCause` at every entry — Process, streaming, Facet, FacetSchema, Compose / ComposeParallel (the WHOLE call) and ProcessChain (the whole call); `ProcessStreamResult` bounds its run AND its drain. Default unlimited ⇒ the caller's ctx untouched. A nested entry bounds again with the same duration, starting later, so the outer deadline and cause win — the outermost call owns the budget.

- Each entry maps through `MapRequestTimeout(ctx, err)`: ONLY when `context.Cause` is the RequestTimeout cause does the error become a bare `PULSE_LIMIT_EXCEEDED` `{limit: request_timeout, configured, observed: elapsed ns}` (no partial result; never slot- or stage-located).
- A caller's own deadline or cancel passes through as `context.DeadlineExceeded` / `context.Canceled`, and so does `ComposeOptions.PerRequestTimeout`, the per-slot knob.
- `ProcessStreamResult`: a trip during the buffered run returns the coded error up front; one mid-stream ends `StreamErrored` with it (`StreamCancelled` stays the caller's).
