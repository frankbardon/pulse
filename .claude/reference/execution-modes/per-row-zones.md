# Execution modes — per-row zones and the cohort default zone field

Slice of `execution-modes.md` (Time zones): the zone NAME rules (precedence, refusal order, `ZonedRequest`) are in `execution-modes/time-and-defaults.md`; this slice holds the per-row zone FIELD rungs.

## Per-row zones

**Per-row zones.** Sibling plain-string slots `tz_field` (slot) / `time_zone_field` (`Request`, `FacetRequest`) name a `categorical_*` cohort field of IANA names. Precedence: slot `tz` → slot `tz_field` → `time_zone_field` → `time_zone` → cohort default → `Options.DefaultTimeZone` → `UTC`, all in the one `ResolveZones` pass.

- **Refusals.** `tz` + `tz_field` on one slot, `tz_field` on a non-capable operator or explicit on a non-`datetime` field, a non-categorical zone field, and a zone field onto a derived field → `PROCESSING_CONFIG`. A dictionary entry `temporal.ValidZoneName` refuses → `PULSE_TIMEZONE_UNKNOWN {slot, field, tz, dictionary_index}`. A zone field absent from the executing schema (the joined one included) → `SERVICE_VALIDATION` (`checkZoneFields`, schema-only). An inherited field on a `date` slot is neither applied nor judged.
- **Echo** `source: "field"`, `tz_field`, `tz: null`; `ZonedRequest` writes an inherited field into `tz_field`. Expressions (`to_day`) stay request-zone only.
- **Runtime.** Each operator builds a `temporal.ZoneTable` from the zone field's dictionary at construction (one per constructed operator, so per worker; a shard dictionary is a prefix of the canonical one) and reads the row's code per record, with no per-row allocation (`TestPerRowZone_OperatorsAllocationFree`).
- **A NULL zone cell makes the row's local value null, never UTC:** date groupers (and a `MAT_DISTANCE` between) key it into no bucket (grouper `n_null`), `ATTR_DATE_PART` / every `FEAT_DATE_FEATURES` column is null, `FILTER_DATE_RANGES` drops it like a null date and counts it in `n_null_input`.
- **Projection (silent if wrong).** Every zone field must join `processing.NeededFields` (`requestZoneFields`: request + every slot, crosstab axes, between). Omitted, projected decode reads it null and every row drops silently. A filter's zone field is a filter-precompute input. `OVERLAY_YOY` follows its host's keys.
- Proof: `TestTimeZoneField_PerRowEqualsSingleZoneSlotsEveryMode` (per-row ≡ N single-zone slots combined ≡ `time.In`, every arm).

**Through a join.** A per-row zone runs over the JOINED schema like any other field: the zone column on the left cohort, on the right (read through `As`), or the left cohort's default (`encx.JoinedSchema` carries it). Each runner hands the join processor the zoned request, so every arm equals the per-site single-`tz` runs combined, and predict echoes the joined zone field the run read. A null zone cell on either side is a null local value, exactly as on one cohort. Proof: `TestTimeZoneField_JoinPerRowEqualsSingleZoneSlots` (heavy; the other side is a wrong-zone decoy, so reading its column fails).

**Chain stage ≥ 1: refused permanently.** A later stage reads the previous stage's output rows (group keys and aggregation figures), where no `datetime` survives, so a per-row zone has nothing to apply to — this is by construction, not a gap to close. `descx.ChainStageZoneFieldRefusal` refuses the stage's request `time_zone_field`, else its first slot `tz_field`, as `SERVICE_VALIDATION {slot, field, stage}` ("… no datetime survives a chain stage …"), whatever the column, on both runtime and the chain validator. Stage 0 takes per-row zones like any request (`TestTimeZoneField_ChainStageZoneFieldRefusedPermanently`). Import's per-row source zone (`source_tz_field`) is a separate seam: `internal/io/import_zone.go` — `column_source_tz` wins, empty cell → `source_tz` else row error, unknown name → skipped-row `PULSE_TIMEZONE_UNKNOWN`.

**Cohort default zone field.** A cohort's declared `encoding.Schema.ZoneField` (the `0x02` ZONE section; `byte-layout.md`) is the rung between `time_zone` and `Options.DefaultTimeZone` (`zoneFieldFor`; request and facet roots alike). It inherits exactly like `time_zone_field`: echo `source: "cohort"`, `tz_field`, `tz: null`; not applied (nor judged) on a non-`datetime` slot; a derived slot field → `PROCESSING_CONFIG {slot, operator, tz_field}` advising a request `time_zone` override. `ZonedRequest` / `AppliedZones` treat it as an inherited field, so every arm, the projection and the filter-to-file hash see it with no further plumbing. It is read from the executing schema, so it never trips `checkZoneFields`; a nil schema has none, `encx.JoinedSchema` carries the LEFT cohort's (never the right's), and a chain stage ≥ 1's synthesised schema has none. Proof: `TestTimeZoneCohort_RunEqualsTimeZoneFieldEveryRunner` (heavy).
