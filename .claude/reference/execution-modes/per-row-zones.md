# Execution modes — per-row zones and the cohort default zone field

Slice of `execution-modes.md` (Time zones): the zone NAME rules (precedence, refusal order, `ZonedRequest`) stay in `execution-modes/time-and-defaults.md`; this slice holds the per-row zone FIELD rungs.

## Per-row zones

**Per-row zones (U50).** Sibling plain-string slots `tz_field` (slot) / `time_zone_field` (`Request`, `FacetRequest`) name a `categorical_*` cohort field of IANA names; precedence slot `tz` → slot `tz_field` → `time_zone_field` → `time_zone` → default → `UTC`, in the same `ResolveZones` pass (`resolveFieldZone`). Refusals: `tz` + `tz_field` on one slot, `tz_field` on a non-capable operator or explicit on a non-`datetime` field, a non-categorical zone field (`{slot, operator, tz_field, field, field_type}`) and a zone field onto a derived field → `PROCESSING_CONFIG`; a dictionary entry `temporal.ValidZoneName` refuses → `PULSE_TIMEZONE_UNKNOWN {slot, field, tz, dictionary_index}`; a zone field absent from the executing schema (the joined one included) → the field-reference pass's `SERVICE_VALIDATION` (`checkZoneFields`, schema-only). An inherited field on a `date` slot is neither applied nor judged. Echo `source: "field"`, `tz_field`, `tz: null`; `ZonedRequest` writes an inherited field into `tz_field` (second write-set). Expressions (`to_day`) stay request-zone only. **Runtime (E1-S2):** each operator builds a `temporal.ZoneTable` from the zone field's dictionary at construction (`resolveDateField` / the `FEAT_DATE_FEATURES` computer; one table, forked per constructed operator, so per worker; a shard dictionary is a prefix of the canonical one) and reads the row's code per record — no per-row allocation (`TestPerRowZone_OperatorsAllocationFree`). A NULL zone cell makes the row's local value null, never UTC: `GROUP_DATE` / `GROUP_DATE_RANGES` (and a `MAT_DISTANCE` between) key it into no bucket (grouper `n_null`), `ATTR_DATE_PART` / every `FEAT_DATE_FEATURES` column is null (aggregation `n_null`), `FILTER_DATE_RANGES` drops it like a null date and counts it in `n_null_input`. Every zone field joins `processing.NeededFields` (`requestZoneFields`: request + every slot, crosstab axes, between) — omitted, projected decode reads it null and every row drops silently — and a filter's zone field is a filter-precompute input. `OVERLAY_YOY` follows its host's keys. Proof: `TestTimeZoneField_PerRowEqualsSingleZoneSlotsEveryMode` (per-row ≡ N single-zone slots combined ≡ `time.In`, every arm), `TestTimeZoneField_NullZoneCellIsNullLocalValue`, `TestTimeZoneField_RefusalsPredictMatchRuntime`.

**Through a join (U75 #481).** A per-row zone runs over the JOINED schema like any other field: the zone column on the left cohort (`tz`) or the right (`r_tz`, read through `As`), or the left cohort's default (`encx.JoinedSchema` carries it), each equals the per-site single-`tz` runs combined in every runner (the join is its own arm — `processWithJoin`, and the buffered crosstab's `processCrosstabWithJoin`, each hand the processor `s.zoned(&clone, zones)`; stream and the shard entry points reach the same arm), and predict echoes the joined zone field the run read. A null zone cell on either side is a null local value through the join, exactly as on one cohort (inner join only, so it is the join's only null-row case). Proof: `TestTimeZoneField_JoinPerRowEchoMatchesRuntime`, `TestTimeZoneField_JoinPerRowEqualsSingleZoneSlots` + `TestTimeZoneField_JoinNullZoneCellIsNullLocalValue` (heavy); the other side is a wrong-zone decoy, so reading its zone column fails.

**Chain stage ≥ 1: refused, PERMANENTLY (U75 #481).** A later stage reads the previous stage's output rows (`vectors.ChainStageSchema`: group keys and aggregation figures), where no `datetime` survives, so a per-row zone has nothing to apply to and stage-≥ 1 equivalence is impossible by construction — not a gap to close. `descx.ChainStageZoneFieldRefusal` refuses the stage's request `time_zone_field`, else its first slot `tz_field`, as `SERVICE_VALIDATION {slot, field, stage}` with the message "… no datetime survives a chain stage …", whatever the column (a forwarded categorical zone key included; it once passed as a no-op), raised on both sides right before the stage's zone pass (`Service` chain stage loop; `validateChainWithOptions`). Stage 0 takes per-row zones like any request. Proof: `TestTimeZoneField_ChainStageZoneFieldRefusedPermanently` (runtime ≡ chain validator ≡ `PredictChain`). Import's per-row source zone (`source_tz_field`, E1-S3) is a separate seam: `internal/io/import_zone.go`, `column_source_tz` wins, empty cell → `source_tz` else row error, unknown name → skipped-row `PULSE_TIMEZONE_UNKNOWN`.

**Cohort default zone field (U75).** A cohort's declared `encoding.Schema.ZoneField` (the `0x02` ZONE section; `byte-layout.md`) is one more rung of the same pass: slot `tz` → slot `tz_field` → `time_zone_field` → `time_zone` → **cohort default** → `Options.DefaultTimeZone` → `UTC` (`zoneFieldFor`; request and facet roots alike). It inherits exactly like `time_zone_field` through `resolveFieldZone`: echo `source: "cohort"` (`descriptor.ZoneSourceCohort`), `tz_field`, `tz: null`; not applied (nor judged) on a non-`datetime` slot; a derived slot field → `PROCESSING_CONFIG {slot, operator, tz_field}` whose message advises a request `time_zone` override; `ZonedRequest` / `AppliedZones` treat it as an inherited field, so every arm, the projection and the filter-to-file hash see it with no further plumbing. It is read from the schema the request executes over, so it never trips `checkZoneFields` (not a request name), a nil schema (schema-less validator) has none, `encx.JoinedSchema` carries the LEFT cohort's (never the right's) and a chain stage ≥ 1's synthesised schema none. Expressions stay request-zone only. Proof: `TestResolveZones_CohortDefaultPrecedence`, `TestTimeZoneCohort_PrecedenceAtRuntime`, `TestTimeZoneCohort_RunEqualsTimeZoneFieldEveryRunner` (heavy; every runner, the shard arms over an archive declared by `Pulse.SetCohortZoneField`), `TestTimeZoneCohort_JoinCarriesLeftDefault`, `TestTimeZoneCohort_ChainStages`, `TestTimeZoneCohort_RefusalPredictMatchesRuntime`.
