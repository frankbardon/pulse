## Categorical-outcome scores

A fit predicting a probability per level scores through `model.ProbabilityScorer` (`internal/model/probability.go`: the full per-row vector over `Outcomes()`, the one kernel the column scorers, a holdout's proper scores and per-level effects read; `regordinal.Fitted` rebuilds it from the coefficients + `outputs.link` / `levels` alone, so a reloaded model file scores bit-identically, and the fit's own mean fitted probabilities share `cumulativeProbabilities`). One slot is one column: `model.OutcomeScorer` over `ScoreParams.Output` / `Level` (`Category` declared, refused everywhere until a type takes it); the adapter routes the whole reference through `RegressionAdapter.ParamScorer` (`regordinal.ParamScorers`) ahead of `Scorer`. The outcome rule `checkOutcome` closes `model.CheckScoreFor` (predict ≡ runtime; reasons `outcome_unsupported`, `output_unknown`, `outcome_required`, `outcome_unused`, `outcome_unknown`, `output_scale`); an unknown level is judged against `Signature.Outcomes` when known — the run's `Set`, a loaded model file (`CatalogWithModels`), a `fits` entry pinning `params.levels` — else only by the run. Its `holdout` stays refused (`model.HoldoutScorerRefusal`, `OutcomeType`; the manifest drops the slot). Gates: `TestCheckScore_Outcome`, `TestOutcomeScorer` (`internal/model`), `TestOrdinalOracle_RowScores`, `TestRegOrdinal_Score*` (`internal/regordinal`).

**`REG_MULTINOMIAL` (U68 E1-S2).** A native built-in, so its scorer is a `regression.BuiltinScorer` case (`newMultinomialScorer`, `internal/processing/regression/multinomial_score.go`) and the type is in `model.scorableBuiltins` (`TestBuiltinScorer_MatchesScorableType`). `regression.MultinomialFitted` rebuilds the fit from `Result.Coefficients` (`"<category>:<term>"`), `Categories` and `Reference` — what a model file keeps under feature `categories` (`model.FeatureCategories`, `categoriesRule`) — and computes each row's vector through `multinomialSoftmax`, the very kernel the engine's `rowEval` runs (the former `multinomialEngine.fitted` test seam is gone: the oracle reads the production scorer). Its `outcomeRules` row: selector `category`, outputs `probability` (the default — so a bare slot is `outcome_required`) / `class` (`OutcomeScorerFor`: a 0-based index into `Categories`, `classOrigin` 0), `linkNeedsOutcome` (`scale: link` is the category's log-odds against the reference and needs `category`). `model.NamesOwnCoefficients` marks it, beside every extension type, as naming its own coefficients: `Bind` NaN-fills the per-predictor slots, `coef()` reads `"<category>:<term>"` only (predict admits any such key over the fit's terms; the run judges the category), a model file needs no `(intercept)`, and `CheckScoreFor` refuses `terms` / a `lower` / `upper` `bound`. `Signature.Outcomes` are `Result.Categories` (`model.ResultOutcomes`), from the bound fit or a loaded file — never from a `fits` entry (the data decide them). `model.ScoresWholeVectorByDefault` keeps the params.fit fitted / residual / design slots off it (`type_unsupported`: their default score would need a category). The `PULSE_FIT_INVALID` `regression_type` reason and `regmultinom`'s `save` → `no_save` row are gone. Gates: `TestCheckScore_MultinomialOutcome`, `TestDecodeFile_CategoriesRefusals`, `TestCoef_Multinomial`, `TestCheckFitReference_Multinomial` (`internal/model`), `TestReferenceOracle_MultinomialMatchesR`, `TestMultinomialScorer_*` (`internal/processing/regression`), `TestMultinomial_Score*` / `_CoefOverBoundFit` (root).
