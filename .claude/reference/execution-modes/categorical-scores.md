## Categorical-outcome scores

A fit predicting a probability per level scores through `model.ProbabilityScorer` (`internal/model/probability.go`: the full per-row vector over `Outcomes()`, the one kernel the column scorers, a holdout's proper scores and per-level effects read; `regordinal.Fitted` rebuilds it from the coefficients + `outputs.link` / `levels` alone, so a reloaded model file scores bit-identically, and the fit's own mean fitted probabilities share `cumulativeProbabilities`). One slot is one column: `model.OutcomeScorer` over `ScoreParams.Output` / `Level` (`Category` declared, refused everywhere until a type takes it); the adapter routes the whole reference through `RegressionAdapter.ParamScorer` (`regordinal.ParamScorers`) ahead of `Scorer`. The outcome rule `checkOutcome` closes `model.CheckScoreFor` (predict ≡ runtime; reasons `outcome_unsupported`, `output_unknown`, `outcome_required`, `outcome_unused`, `outcome_unknown`, `output_scale`); an unknown level is judged against `Signature.Outcomes` when known — the run's `Set`, a loaded model file (`CatalogWithModels`), a `fits` entry pinning `params.levels` — else only by the run. Gates: `TestCheckScore_Outcome`, `TestOutcomeScorer` (`internal/model`), `TestOrdinalOracle_RowScores`, `TestRegOrdinal_Score*` (`internal/regordinal`).

**`REG_MULTINOMIAL` (U68 E1-S2).** A native built-in, so its scorer is a `regression.BuiltinScorer` case (`newMultinomialScorer`, `internal/processing/regression/multinomial_score.go`) and the type is in `model.scorableBuiltins` (`TestBuiltinScorer_MatchesScorableType`). `regression.MultinomialFitted` rebuilds the fit from `Result.Coefficients` (`"<category>:<term>"`), `Categories` and `Reference` — what a model file keeps under feature `categories` (`model.FeatureCategories`, `categoriesRule`) — and computes each row's vector through `multinomialSoftmax`, the very kernel the engine's `rowEval` runs (the former `multinomialEngine.fitted` test seam is gone: the oracle reads the production scorer). Its `outcomeRules` row: selector `category`, outputs `probability` (the default — so a bare slot is `outcome_required`) / `class` (`OutcomeScorerFor`: a 0-based index into `Categories`, `classOrigin` 0), `linkNeedsOutcome` (`scale: link` is the category's log-odds against the reference and needs `category`). `model.NamesOwnCoefficients` marks it, beside every extension type, as naming its own coefficients: `Bind` NaN-fills the per-predictor slots, `coef()` reads `"<category>:<term>"` only (predict admits any such key over the fit's terms; the run judges the category), a model file needs no `(intercept)`, and `CheckScoreFor` refuses `terms` / a `lower` / `upper` `bound`. `Signature.Outcomes` are `Result.Categories` (`model.ResultOutcomes`), from the bound fit or a loaded file — never from a `fits` entry (the data decide them). `model.ScoresWholeVectorByDefault` keeps the params.fit fitted / residual / design slots off it (`type_unsupported`: their default score would need a category). The `PULSE_FIT_INVALID` `regression_type` reason and `regmultinom`'s `save` → `no_save` row are gone. Gates: `TestCheckScore_MultinomialOutcome`, `TestDecodeFile_CategoriesRefusals`, `TestCoef_Multinomial`, `TestCheckFitReference_Multinomial` (`internal/model`), `TestReferenceOracle_MultinomialMatchesR`, `TestMultinomialScorer_*` (`internal/processing/regression`), `TestMultinomial_Score*` / `_CoefOverBoundFit` (root).

**Holdout (U68 E1-S3).** `model.HoldoutScorerRefusal` no longer refuses an `OutcomeType` fit, so a `holdout` on `REG_ORDINAL` / `REG_MULTINOMIAL` runs (predict ≡ runtime; the manifest declares the slot with `outcomeHoldoutParamDescription`). `fitHoldout` (`internal/processing/regression_holdout.go`) branches on `model.OutcomeType` BEFORE building a RowScorer (multinomial's default column needs a category): `regression.BoundProbabilities(b)` — `NewMultinomialFitted`, or a model regression's `model.ProbabilityFactory` registered by `regadapt` from `regordinal.Probabilities` (`regression.RegisterModelProbabilities`) — then `regression.HoldoutOutcomeFigures(spec, ps, model.OrderedOutcomes(t), held, nNull)`. Per scored row (target present, its label — categorical, else `'g'`-formatted as ordinal levels — among `Outcomes()`, the vector finite, the weight passing `rowWeights.of`), weighted means in record order: `log_loss` −ln p_y (`detmath.Log`; p_y = 0 → +Inf → null), `brier` Σ_k (p_k − o_k)², `accuracy` [first argmax = y], ordered `rps` Σ_{k<K} (F_k − O_k)²/(K − 1). A held-out outcome the fit lacks is skipped; an undecodable label is the slot's `ENCODING_INVALID`. `types.RegressionHoldout`'s figures are all `*float64` `omitempty`, so a numeric fit writes `rmse` / `mae` / `r2` byte-identically and a categorical one only its scores. Guidance: `holdoutOutputs` (`interpretation_validate.go`) resolves `holdout.<key>` apart from the plain-fit `regressionOutputs` table; `regOutcomeHoldout` Interpretations. Oracles: `gen_ordinal.R` `ord_scores` / `gen_multinomial.R` `mn_scores` over `predict(type = "probs")` on fixed `holdout_rows`. Gates: `TestHoldoutOutcomeFigures_*`, `TestBoundProbabilities_EveryOutcomeType`, `TestReferenceOracle_MultinomialMatchesR` (`internal/processing/regression`), `TestRegOrdinal_HoldoutMatchesR`, `TestHoldout_EveryScorableBuiltin` (root, gate B over `ATTR_REG_PREDICT` probability columns), `TestHoldoutOutputs_AreResultTags` (`internal/descriptor`).
