# Execution modes — parallel shards, blocked merge

Per-topic slice of the execution-modes reference. Index (Mode index + section map): `.claude/reference/execution-modes.md` — load it first, then only the slice(s) your engine work touches. Skills: `skills/cohort-schema-design.md` (Sharded), `skills/cohort-sharding.md`.

## Parallel shards

`pulse.Options.ShardWorkers`, default `0` ⇒ `runtime.NumCPU()`; an explicit `1` forces serial. `ShardWorkers` and `DecodeWorkers` (Parallel buffered Process) are orthogonal and reject negatives at `pulse.New()`. A bounded per-shard worker pool runs inside `Process` when the cohort is a shard archive (`internal/service/shard_reduce.go`).

**Admission.** The reducer engages only when every operator is mergeable per `processing.CanMergeRequestWithExtensions` (one rule, `internal/mergegate`): built-ins per type with non-decimal targets, extension aggregators per their `Mergeable` declaration; no windows / features / regressions / tests / two-pass; attributes row-local — except a `total()` formula run two-phase (`execution-modes/parallel-totals.md`) and the tally attributes below. Non-mergeable requests fall through to the serial shard iterator. The per-row order is filter → row-local attributes → floor and `Run.NullRecords` tallies on both reducers and the serial grouped path, so a primary field that is an attribute label is read after it lands.

**Exactness.** Integer / sentinel reducers and the binned reproducible sums are byte-equal vs serial under any worker count or shard split. Welford state (variance, stddev, `AGG_WELFORD`, shape moments, the weighted `m2_weighted` / `weighted_variance` components) merges within ULP via Chan-Welford — never bit-exact. Matrices and vector aggregates are bit-exact through the blocked merge (below).

**Decode and memory.** Each worker decodes rows into a fresh positional `Record` through the same projected decode as the parallel-decode reducer: the projection is built ONCE per run and every worker reads it, so unretained fields are skipped, `projected_fields` is stamped, and parent-group indices still reach the record. An anchor-opened shard streams its archive section through the same bounded window, never `afero.ReadFile`.

- **The archive itself is never resident.** Every service read path opens it through `archiveFile` (`internal/service/archive_open.go`: one handle, the central directory parsed once per scan), and each shard is read through a buffered section reader at its data offset. A deflated entry is `PULSE_ARCHIVE_CORRUPT` on serial and parallel arms alike.
- **No shard's schema is decoded with its dictionaries.** The record-count peek and the scan read each shard's block layout-only (`encoding.ReadSchemaLayout`), because the canonical schema decodes every row.
- **`MaxEstimatedMemory` on an archive** charges the LARGEST shard's records × stride × the file-copy factor in place of the cohort's payload, 8 × the central-directory bytes, the live partials, and ONE dictionary-bearing schema decode; an anchored shard is charged as a single file (`.claude/reference/predict-inspect.md` (The memory estimate)).

**`Response.Components` is part of that parity, not an exception to it.** Both reducers share `shardPartial` / `mergeShardPartials` / `finalizeMergedPartial`; a partial carries per-slot floor tallies (per bucket on a grouped partial) and filter-pass counters beside the operator state, all folded slot-wise on merge. The per-operator `Operator` map is read off the MERGED aggregator — the arms fold operator STATE, so no components-level merge exists, and the mergeability classes need no second gate because the merge rule already refused anything whose state cannot fold.

- Grouper components: each worker builds its own grouper instances, whose live bucket state folds through `processing.MergeableGrouper` (implemented by exactly the `GroupType.Mergeable()` set), so the merged grouper's `Components()` is the serial one's.
- **The grouped arm has no emission tail of its own** — it hands the merged buckets and groupers to `processing.FinalizeGroupedStream`, the tail the serial streaming-grouped path uses (row order incl. include order, `Request.Sort`, Components, SERIES overlays), and keys records through `processing.GroupKeyer`. (A private copy of that tail once silently dropped sort, overlays and include order.)
- `Run.ShardCount` is the archive's shard count on BOTH arms (the serial exit stamps it in the service, since the processing layer has no shard concept).
- Counting presence for the floor goes through `processing.FieldPresent`, never `Record.NumericValue`, or a set field reads as entirely null.
- **An empty merge is seeded, never counters-only.** Every partition is built by one constructor; when NO partition published (zero-record segments never do), `finalizeMergedPartial` seeds the merge with that zero-record state, so the ungrouped arm writes the zero-n `Data` row and Components entries and the grouped arm runs the shared tail over zero buckets — the serial zero-record answer.
- Pinned by `TestShardWorkers_ComponentsParity_GroupedAndFlatArchives` (whole `{data, components, overlays}` document) and `TestMergeableGrouper_MergedComponentsEqualSerial`.

**Incremental merge and group memory.** The per-shard arm folds each result through a `partialMerger` the moment shards 0..i are all done, on the caller's goroutine while later shards scan, then drops it. The merge ORDER is still shard insertion order, so every answer (Welford slots included) is byte-identical under any worker count; row order comes from the grouped tail, never the merge.

- **Live partials are bounded by the window** `limits.ShardMergeWindow(workers)` = workers — under a set `MaxEstimatedMemory`, shrunk to the largest window (≥ 1) whose whole-run estimate fits (`limits.ShardMergeWindowWithin`; predict judges the same window, so a refusal fires only when one partial does not fit). Shard j is dispatched only once j < next unmerged + window; every dispatched shard reports exactly once (a panic is recovered per shard), so the first error cancels the rest and is returned after every dispatched shard reported. `TestGroupMemory_LivePartialsBoundedByWindow` counts the partials still reachable.
- **Per-group bytes.** A bucket is ONE map entry `*processing.GroupBucket{Aggs, Floors}` on every streaming-grouped arm, minted by the run's `processing.BucketMinter`, its floors shaped once per run. `AGG_MAX` / `AGG_MIN` state is ONE 8-byte word carved from one slab per type per bucket (zero = "none seen"; a seen value is its bits XOR a quiet-NaN key, so only an input carrying that NaN's exact payload comes back as `math.NaN()`). An unweighted slot carries no weight floor. `AGG_DISTINCT_COUNT` keeps its exact value set inline (`processing.distinctValueSet`: up to 16 value words in one slice, deduped by a linear scan, promoted to a map past that; ±0 one value, every NaN one more, as the `map[float64]struct{}` it replaced), so a group of 1–8 values costs ~75–130 B, not ~232. Budgets are pinned by `TestGroupMemory_PartitionBytesPerGroup` / `_MergedBytesPerGroup` (≤ 512 B/group live after GC), `TestGroupMemory_ExtremumBytesPerGroup` and `TestGroupMemory_DistinctCountBytesPerGroup`; when you add bucket state, re-measure against them.
- The finalize output (Data rows, per-group Components) is NOT in that figure — roughly 2.6 KB a group at peak — and the memory model charges it separately. The grouped tail CONSUMES the buckets (each deleted once its row and Components entry are written), so merged state and rows never peak together; the estimate still charges both.

**Two or more groupers, streaming and buffered.** The streaming path keys each record through one `GroupKeyer` per slot and `CompositeKeySet.Expand` mints the per-record cartesian product; the buffered path builds the same keys. Every grouper is driven once per record (a null at an earlier position does not skip later ones), so per-slot `Components.Groupers` entries and `groups[].group_key` tuples agree across arms. Data-dependent groupers follow `params.fit` (`execution-modes/crosstab.md`, Data-dependent axis groupers). Series overlays run per partition of the composite rows (`overlays-series.md`, Series partitions).

**Two or more groupers on both reducers.** A partition holds EVERY `Request.Groups` slot: one grouper instance and `GroupKeyer` per slot, per-grouper keyed-record counts (once per record, however many keys a fan-out gives it), and a `processing.CompositeKeySet`. Rows key exactly as on the serial path; `Expand` mints nothing when any position is empty; a key holding `"\x00"` is refused `PROCESSING_GROUP` at intern time on every arm. Merge folds each slot's grouper state and keyed count in partition order and unions the key sets; the tail then writes key columns from the tuple (never the parsed string). `MaxGroups` counts composite keys per partition and on the merged count. One grouper keeps the plain-key path. Pinned by `TestMultiGrouperInvariance_{Archive,Heavy}` (shared harness `internal/testutil/invariance`: the whole response bitwise across ShardWorkers / DecodeWorkers, weighted and unweighted).

**Resource limits on the grouped paths.** `MaxGroups` is counted at every bucket mint — O(1) per NEW key, never per row — and a breach raises `PULSE_LIMIT_EXCEEDED` with no partial result: at the serial streaming mint, on the buffered partition size, at the grouped-matrix bucket mint, in each parallel partition, and on the MERGED key count (every partition can sit under the limit while their union does not). The parallel reducers bypass the processor, so their partials take the limits explicitly. A partition never holds more keys than the run, so a local trip is a sound early abort; the parallel `observed` is the count AT BREACH and is not reproducible across worker counts — parity compares `{code, limit, configured}` only. Facet bounds each faceted field's distinct values the same way, except the simple facet's categorical fast path, which mints nothing.

**Reproducible sums.** `AGG_SUM`, `AGG_AVERAGE` (binned Σ over the exact integer n), `AGG_RATIO`, the weighted Σw / Σw·x / Σw², the `sum_weights` / `n_eff` floor, the weighted counting aggregators, `AGG_DISTINCT_SUM` and `ATTR_FORMULA` `total()` accumulate in `internal/reprosum.Sum` (a ReproBLAS-style K=3/W=40 binned sum) on EVERY path, and merges combine the binned state — so the value is a function of the multiset of inputs: no order, partition or merge tree reaches the bits, on amd64 and arm64 alike. The kernel carries its own `float64(...)` FMA barriers; callers add none (a weighted product goes through `AddWeighted`). It is not correctly rounded (bound in the package doc). Welford state keeps its running Σw separate from the binned Σw, and the weighted two-pass variance mean stays sequential so unit weights still reproduce the unweighted variance. **A new summing accumulator must use `reprosum`**, or `TestBitExact_*` (`internal/integration/bit_exact_invariance_test.go`: serial vs DecodeWorkers vs ShardWorkers over a hash-scattered uneven archive, each parallel run required to take its arm) will catch the drift.

**Two-phase `total()`** — both reducers run a total-bearing `ATTR_FORMULA` in two phases (a parallel pre-pass per layer publishes the totals, then the ordinary reduce): `execution-modes/parallel-totals.md`.

**Tally attributes.** `ATTR_SCALE_SCORE`, a non-centroid `ATTR_PROFILE_SIMILARITY`, an `ATTR_VEC_DISTANCE` over a row-local metric and no centroid (the metric must resolve and not be fitted; `std_euclidean` / `mahalanobis`, `fit_on` or a bound `fit` stay out) and an extension attribute declared `Mergeable` (`extend.MergeableAttribute`) keep a per-run tally — their `Components.Attributes` operator counts and the warnings those back (`PULSE_ATTR_SCALE_OUT_OF_RANGE`, `PULSE_VECTOR_REFERENCE_MISSING`, `PULSE_VECTOR_METRIC_DOMAIN`). They implement `processing.MergeableAttributeTally`, so `mergegate` admits them on both reducers AND chain stages; the centroid forms stay two-pass.

- Each partition keeps its attribute specs (instance + `{n, n_null}` floor); merge folds them slot by slot (floors add, tallies fold; a component-bearing attribute without a fold is `PROCESSING_INTERNAL`).
- Finalize folds the merged slots into the run's ONE bound build (which scores no row and is where fit warnings and the capture offer come from) and emits from it once, cohort-wide, in declared order — no per-partition warning ever reaches the response. A zero-row run reports zero tallies, as serial does. Integer tallies, so the fold is exact in any order.
- An extension attribute emitting components without the declaration stays serial and chain-refused.

**Attribute slots.** `processing.BindRecords(schema, keep, extras...)` gives each off-schema name in `extras` (the request's attribute labels) a positional float64 slot instead of a per-row overflow-map entry; every arm that mints a fresh record passes the labels. An extra reads exactly as its overflow entry did (wide values stay in the overflow; schema names are never extras), and the list is a sizing hint only. Pinned by `TestAttributeSlots_*` (allocations a row flat in attribute count) and `TestBitExact_RetentionShapeChain`.

**Grouped fan-out is cardinality-blind.** A mergeable grouped request fans out whatever its key count; there is no cardinality admission. Value-keyed groupers stop gaining once each partition mints keys for most of its rows, and predict cannot see their cardinality; a rule routing high-cardinality groupings serial was measured and dropped (`BenchmarkGroupedSumScale`, `docs/internals/BENCHMARKS_BASELINE.md`). The decode dispatch counts records from the file length less the header + schema bytes `Open` read, never a second schema decode.

## Blocked merge (`processing.BlockMerger`)

The opt-in for a reducer whose answer must be BIT-identical under every concurrency knob, not merely within ULP. Surface: `internal/processing/block_merge.go`. The built-in user is the matrix slot (`MAT_*`; an extension `MAT_*` runs in that same slot with only the finalizer swapped, so it inherits the tree); `AGG_VEC_MEAN` / `AGG_VEC_SUM` / `AGG_VEC_SD` key their per-element partials the same way. Every other reducer keeps the `MergeOnline` path above.

- **Positions.** Every record source stamps the row's merge-block position on the `Record` (`SetMergePosition(shard, shardStart, record)`, packed into padding — the Record stays 96 bytes). Blocks key by the GLOBAL record ordinal `shardStart + record` (shard starts from the archive's per-shard record counts). `BlockKey{Block, Shard, Head}` with `Block = global / linalg.MergeBlockSize` (4096) and `Head` = the shard holds the block's first ordinal; keys order by block, then shard. **A new record source must stamp positions**, or matrices refuse its rows.
- **State.** One FRAGMENT per (block, shard) that saw a row. A head fragment holds a `linalg.CoMoment`, rows folded in record order; a fragment whose shard starts inside the block (at most the shard's first block) buffers its rows. A record no source stamped (join output, a chain stage, a test harness) is refused `PROCESSING_INTERNAL` rather than guessed at.
- **Merge.** Partitions move fragments in by disjoint union (`BlockCoMoments.Absorb`), so partition order cannot reach the bits; a key on both sides means a fragment was split across partitions and is `PROCESSING_INTERNAL`.
- **Tree.** At `Finalize`, each block's partial is its head fragment with the block's other fragments replayed on top in shard order — the block's sequential fold in ordinal order — then one `linalg.MergeTree` over the block partials in block order. A block no row reached has no entry; a head that is not its block's first fragment is `PROCESSING_INTERNAL`. Serial, any `DecodeWorkers`, any `ShardWorkers` and any shard split — an archive versus its single-file twin — therefore produce the same bits on every architecture (the kernels are FMA-free).
- **Matrix slots.** `Request.Matrices` state is not an aggregator: each partition carries a `*processing.MatrixSlots` (per-bucket `GroupedMatrices` on a grouped partition, rendered by the grouped tail in the final, sorted Data order — `.claude/reference/matrix-and-vectors.md`), built off the stamped request, folding every filter-passing row after the universal floor and merging by the same disjoint union. The merge gate waives the at-least-one-aggregator rule for a request carrying matrices and requires every `MatrixType.Mergeable()`; `ChainRefusal` strips `matrices` first. `Run.NullRecords` stays 0 for a matrix-only request on every arm.
- **Memory.** `limits.MergeBlocks` counts fragments and `limits.MergeBufferedRows` the rows non-head fragments keep; predict's `estimated_bytes` and the memory pre-flight add both.
- **Gates.** `TestMatrixInvariance_{Archive,Heavy}` drive every real `MAT_*` registration and a test-only raw CoMoment reducer through the real dispatch — serial vs DecodeWorkers vs ShardWorkers vs the single-file twin, listwise / pairwise × weighted / unweighted — bitwise. `TestExtensionMatrixInvariance_{Archive,Heavy}` do the same for an operator registered only through `Options.Extensions.MatrixOps`, and `TestExtensionMatrixInvariance_ComparatorBites` proves the comparator catches a reordered block merge.
