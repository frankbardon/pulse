## Overlays — payload parts, MATRIX_RESULT host and the U28 kinds

Continues the `## Overlays` section of `.claude/reference/execution-modes/overlays.md` (the displaced contributor-wiring bullets).

- **Parity overlays — Welford migration** (displaced from `skills/overlay-system.md` at U28 E1-S1; the cell / vs-ref t / z atomics carry it for the LLM). The Compose t / z kinds (cell, vs-ref) read `{n, mean, variance}` from `Response.Components.Crosstab.CellComponents[r][c]`, so the cell aggregator must emit that triple; with no triple at the coordinate they fall back to `params` (`variance_*`, `sample_size_*`).
- **Payload parts (U28 E1-S1).** `types.OverlayPayload.Parts map[string]*OverlayPayload` (`parts`, `omitempty`) carries a multi-output kind's named secondary payloads beside the primary — one spec, one layer; `Series2` and two-layer emission were rejected because they broke the fold, `return` and multiplicity keying. A part is a plain scalar / series / matrix payload and never nests: every overlay dispatcher calls `overlayhost.PartsRefusal` right after a handler returns (the MATRIX arm in `applyOverlaysPlanned` today; a new dispatcher — the MATRIX_RESULT host — must call it too), refusing a nested, nil, unnamed or shapeless part as `PROCESSING_INTERNAL` (a handler fault, not a caller one). The payload schema's per-part definition omits `parts` (`overlayPayloadUnion(t, false)` in `internal/descriptor/schema.go`). A points × dimensions part keys its columns with `overlayhost.DimAxisKeys(n)` (`["dim_1"]` …, prefix `overlayhost.DimAxisKeyPrefix`). `return` needs no part-specific code: `overlays[*].payload.parts.<part>` steps through a map, so the generic resolver marks it Open and the map pruner / planned encoder drop the key (`internal/returnshape/parts_test.go`). Export: NDJSON / Arrow / Parquet marshal the layer, parts included; the Excel writer implements `iocore.OverlayWarningEmitter` and raises `PULSE_OVERLAY_EXPORT_PARTS_DROPPED` (details `layer_count`, `layer_names`, `parts`) because its one-sheet-per-layer layout carries the primary only; CSV / TSV / SPSS drop the whole layer as before (`internal/io/exportoverlay/parts_test.go`). Byte-identity: `types/overlay_parts_test.go`, `TestApplyOverlays_ExistingKindsCarryNoParts`. **Declared in the manifest (E4-G2):** `OverlayCapability.Parts` (`parts`, `omitempty`; `descriptor.OverlayPart{name, shape, when}`) is derived from the one `overlayPartShapes` table in `internal/descriptor` (`overlayPartsFor`) — the Interpretation resolver reads the same table (`overlayPartShape`), skipping a templated name (`step_<n>`, `distribution_<n>`: holds `<`), which only the manifest lists. `when` states a conditional part's condition (`only with params.absorbing`); a kind without parts has no key (`TestOverlayCapabilities_PartsFromTable`).
- **`OVERLAY_STD_RESIDUAL` (U28 E1-S2).** The first parts kind: MATRIX (crosstab) host, scope `cell`, implicit-margin. `internal/processing/overlay_std_residual.go` reads the host through `readContingencyTable` (the `OVERLAY_CHISQ_MATRIX` table: absent cell = observed 0, totals recomputed from the cells, < 2×2 or zero grand total `PULSE_OVERLAY_REF_INCOMPATIBLE_WITH_SHAPE`, probability host scaled to its Kish n_eff by `scaleContingency`; a later whole-table kind reuses it) and emits the Haberman residual `(O − E) / sqrt(E (1 − r/N) (1 − c/N))` as the primary MATRIX, `parts.expected` and `parts.p` (two-sided normal, `normalTwoSidedP`) on the host coordinates; every coordinate is present, a non-positive variance term (E = 0, or a row / column holding the whole table) is NaN → `null`, and any E < 5 raises one `PULSE_OVERLAY_EXPECTED_LOW` `{kind, low_expected_cells, zero_expected_cells, expected_min}`. It joins `weighting.ScalesByHostFloor` (so the components-disabled probability refusal and `OverlayReadsHostComponents` cover it) and the inferential Level / Within gate. Multiplicity: the p-site is `pSiteMatrixPart` (`internal/service/multiplicity_overlay.go`, part named by `overlayPParts`) — the fold reads `parts.p` but writes `payload.p_adjusted` / `significant_adjusted` like every MATRIX p-site, and `row` / `column` key off the part's grid. The Interpretation resolver admits `parts.<part>.cells.value` / `.scalar` only for a part `overlayPartShapes` (`internal/descriptor/overlay_std_residual.go`) declares; the explainer reads a `parts.*` p field coordinate-aligned with its adjusted twin. Oracle: `scripts/reference/gen_std_residual.R` → `internal/processing/testdata/reference/std_residual.json` (`chisq.test()$stdres`, per-row `p.adjust`), sourced by `make reference`; worked example Agresti (2007) Table 2.5.

- **MATRIX_RESULT host (U28 E4-S1).** A third Process host shape beside MATRIX and SERIES: `overlayhost.ShapeMatrixResult` (`"matrix_result"`, a host-judging value only — no payload carries it), the `Response.Matrices` of a request carrying `Request.Matrices` and no crosstab. `overlayhost.JudgedShape(authored, matrices, route)` is the shape every gate judges a `Request.Overlays` spec by (predict `ValidateOverlays`, runtime `refuseWrongHostOverlays`, `canStreamOverlays`): a MATRIX_RESULT kind on a matrices request, and EVERY kind over a SCALAR authored shape that carries matrices, is judged against MATRIX_RESULT; a SERIES kind on a grouped request that also carries matrices keeps SERIES. So a crosstab or series kind on a matrices-only request, and a MATRIX_RESULT kind on a crosstab / series / scalar host, raise the shared `ShapeRefusal` (`shapes: ["matrix_result"]`, "a matrix-result host (Request.Matrices, no Request.Crosstab)"). `Crosstab + Matrices` stays refused (`mergegate.MatrixRefusal`), so a request never carries both a crosstab overlay and a matrix-result overlay. The reference arm is `OverlayRef.Matrix {name}` (the tenth arm), naming a `Request.Matrices` spec by `EffectiveName`; the overlay reads EVERY group bucket of that spec. Shared refusals, predict and runtime alike — `overlayhost.MatrixResultRefusal`, in order: Ref.Matrix unset / empty or another arm populated (`PULSE_OVERLAY_REF_INCOMPATIBLE_WITH_SHAPE`), scope other than `matrix` (`_SCOPE_UNSUPPORTED`), non-zero Level / Within (`_LEVEL_OUT_OF_RANGE`), any params (`_PARAM_MISSING`), an unknown name (`PULSE_OVERLAY_REFERENCE_UNKNOWN`, `which: "matrix"`, `name`, `matrices`), no `Request.Groups` (`PULSE_OVERLAY_GROUPS_REQUIRED`, `{index, kind, name}`). Reach: a process request and a Compose slot's own `Request.Overlays`; the Compose-host, chain and facet overlay slots refuse the kind through `overlayhost.Refusal` (hosts `["request"]`), and a ProcessChain stage's own `Request.Overlays` through `overlayhost.StageRefusal` (`descx.ChainStageOverlayRefusal`, details `{index, kind, host: "chain", stage}`, after the stages' models on both ValidateChain and the chain runtime). **Apply order — decided: AFTER the multiplicity fold.** `Service.process` runs `processing.ApplyMatrixResultOverlays` right after `foldRequestMultiplicity`, so a MATRIX_RESULT handler reads every result as the caller receives it (`auxiliary.p_adjusted` / `significant_adjusted`, the `Multiplicity` echo); a Compose slot's matrix correction happens at the batch barrier, so the slot's pass is DEFERRED (`deferMatrixResultOverlays` ctx cell) and both orchestrators run it right after `foldComposeMultiplicity`, before the sweep rank. Pinned by `TestMatrixResultOverlays_RunAfterMultiplicityFold` (`internal/service`). The crosstab and SERIES dispatch loops skip a MATRIX_RESULT spec (its position stays a zero layer); the pass writes each layer at its spec's index (allocating index-aligned layers when no other hook did), calls `overlayhost.PartsRefusal`, and promotes handler warnings to `Response.Warnings`. A request without a computed MATRIX_RESULT spec runs nothing — byte-identical. A computed one keeps `MatricesSlot` computed under a `return` that drops `matrices` (`resolveComputePlan`). Feature edge: the kind's host group is `capability:matrices` (`overlayHostKinds`, `matrixResultOverlayHandlers`). SERIES partition detail displaced from `skills/overlay-system.md`: `params.partition_by` `[]` runs one partition; OVERLAY_YOY partitions by every non-date key.
- **`OVERLAY_MATRIX_GROUP_SUMMARY` (U28 E4-S1).** The first MATRIX_RESULT kind (`internal/processing/overlay_matrix_result.go` `applyMatrixGroupSummary`): scope `matrix`, descriptive (no p-site, no weight class), no params, buffered. Keys are the union of the buckets' `Primary` row / column keys in first-seen order (bucket order, then axis order); each bucket's `Primary` is expanded (`ExpandMatrixValues`: `upper` → full, mirrored); per cell over the buckets whose cell exists and is finite: `mean` = Σx / |G| summed in bucket order (UNWEIGHTED — every bucket counts once; a weighted mean is out of scope), `min`, `max`, `range` = max − min, `n_groups` = |G|. A NaN (null) cell or a key a bucket lacks contributes nothing; a cell with no contributing bucket is NaN → `null` in mean / min / max / range and 0 in `n_groups`; every cell is `present`. Primary MATRIX `mean`; parts `min`, `max`, `range`, `n_groups` (MATRIX each, `overlayhost.GroupSummaryParts`); headers `row` / `column` (type `matrix_key`), keys one-element `AxisKey`s. Default layer name `group_summary_<name>`.
- **`OVERLAY_CORRESPONDENCE` (U28 E1-S3).** Simple CA (R `ca::ca`), MATRIX (crosstab) host, scope `matrix`, implicit-margin, descriptive (no p-site, no weight class: scale-invariant, so a weighted host's Σw table is read as is — no `scaleContingency`, not in `ScalesByHostFloor`). `internal/processing/overlay_correspondence.go`: absent cell = 0; a known cell aggregation other than `AGG_COUNT` / `AGG_SUM` (`CrosstabHostView.cellType`, stamped in `applyOverlaysToResponse`) or a negative / non-finite cell is `PULSE_OVERLAY_NONNEGATIVE_REQUIRED`; zero-total rows / columns are dropped with one `PULSE_OVERLAY_REF_ZERO` per axis `{kind, axis, dropped, dropped_keys, reason: "zero_margin"}`; < 2×2 kept is `PULSE_OVERLAY_REF_INCOMPATIBLE_WITH_SHAPE`. `S = D_r^-1/2 (P − r cᵀ) D_c^-1/2` → `linalg.SVD`; K = min(r, c) − 1 inertias form the SERIES primary (`dim_k`, `share` / `cumulative_share` / `singular_value`), `Summary.Statistic` = Σ S² (χ²/n) with `dimensions`, `retained_share`, `share_dim_<k>`. Parts on the KEPT keys × `overlayhost.DimAxisKeys(d)`: `row_` / `column_coordinates` (symmetric = both principal, `row_principal` = principal rows + standard columns, `column_principal` the mirror), `row_` / `column_contribution` (= U² / V², each dimension sums to 1), `row_` / `column_quality` (SERIES, Σ cos² over the retained dims; `mass`, `inertia` parameters). `row_` / `column_distance` (U30 E5-S3, MATRIX kept keys × kept keys, both headers the host axis's): the pairwise chi-square profile distances, `chiSquareDistances` — the registry's `chi_square` resolved for `metric.ConsumerCorrespondence` over the other axis's masses (`sqrt(Σ_j (O_ij/O_i· − O_kj/O_k·)² / c_j)`), full-space (independent of `dimensions` / `normalization`), symmetric bit for bit, diagonal exactly 0, always defined (kept points have positive totals and masses); Σ_i Σ_k m_i m_k d² = 2 × total inertia. Scale-free like the rest, so weights follow the kind's none-class rule (Σw table as is). A dimension with σ ≤ `linalg.RankTolerance` has NaN coordinates / contributions; a profile on the centroid has NaN quality. Signs are `linalg.SVD`'s (V's dominant component positive), so R comparisons sign-normalize. Params and refusals are the shared `internal/overlayhost/correspondence.go` helpers (`ParseCorrespondenceParams` strict decode, `CorrespondenceDimensionsRefusal`, `NonnegativeCellRefusal` — reused by MARKOV / RAKE): `dimensions` defaults to 2 CAPPED at K, an explicit value above K is `PULSE_OVERLAY_PARAM_MISSING` — predict judges it on the dictionary extent (`axisBuckets`, when known), runtime on the kept table (zero-margin drops can shrink it, a runtime-only refusal). Interpretation paths on a SERIES part are `parts.<part>.summary.<key>` (`overlayPartShapes`). Oracle: `scripts/reference/gen_correspondence.R` (`ca` 0.72; distances = `stats::dist` over profiles / √mass, cross-checked against `ca`'s `rowdist` / `coldist`) → `correspondence.json` (`TestCorrespondence_MatchesR`, distances at 1e-12; `TestCorrespondence_ChiSquareDistances` hand-exact on `ca::smoke`); worked example Greenacre's smoking data (`ca::smoke`).

- **`OVERLAY_MARKOV` (U28 E2-S2).** Markov chain of a from-state (rows) × to-state (columns) transition crosstab: MATRIX (crosstab) host, scope `matrix`, implicit-margin, descriptive (no p-site, no weight class: every output row-normalizes, so a weighted Σw table is read as is). `internal/processing/overlay_markov.go` (`applyMarkovAt`, index-aware like CA in `applyOverlaysPlanned`). **Square host:** states are the row keys in row order, the columns aligned BY KEY (`overlayhost.MarkovStateName`: a one-element string key is itself, any other key its JSON), never by position; a different grouper count per axis is `PULSE_OVERLAY_MATRIX_NOT_SQUARE` on predict AND runtime (`MarkovArityRefusal`, details `{kind, row_groupers, column_groupers, index}`), differing key sets runtime-only (`MarkovKeySetRefusal`, `{kind, row_only, column_only, index}`) because a crosstab emits only observed keys — an absorbing state with no observed move out is missing from the row axis. **Declared-absorbing synthesis (owner decision 2026-10-12):** when there is no row-only key and EVERY column-only key is named in `params.absorbing`, each gets a synthesized unit row (appended after the observed rows, in column order; known by declaration, not invented), reported by one `PULSE_OVERLAY_REF_ZERO` `{kind, axis: "row", states, reason: "absorbing_row_synthesized"}` plus `summary.parameters.synthesized_rows` (absent when 0, so the unsynthesized output is byte-identical); an observed row that is also declared absorbing is NOT rewritten. Any other one-axis key keeps the refusal (the fixup names the `absorbing` route). Predict cannot see observed keys, so it accepts both and the rule stays runtime-only (`TestMarkov_ColumnOnlyAbsorbing`, `TestMarkov_SynthesizedAbsorbingRow`). Cells: `NonnegativeCellRefusal` / `NonnegativeValueRefusal` (shared with CA); absent cell = 0; < 2 states or a zero total is `PULSE_OVERLAY_REF_INCOMPATIBLE_WITH_SHAPE`. A zero row becomes the unit row (absorbing) with one `PULSE_OVERLAY_REF_ZERO` `{kind, axis: "row", rows, states, reason: "zero_row_absorbing"}`. Params (`overlayhost.ParseMarkovParams`, strict, `PULSE_OVERLAY_PARAM_MISSING`): `steps` (default `[1,3,6,12]`, distinct integers 1–1000, ≤ `MarkovMaxStepCount` 64 — a cap the interview left open, set so one spec cannot ask for unbounded k × k parts), `absorbing` (non-empty, distinct), `initial` (`"margin"` = row totals / grand, or a share map normalized by its sum; omitted states 0); a key naming no host state is refused at runtime only (`MarkovStateRefusal`). Outputs: primary MATRIX P; parts `step_<n>` (Pⁿ by binary powering), `distribution_<n>` (π₀ Pⁿ, with `initial`), `steady_state` (power iteration from uniform, `max|Δ| < 1e-12` within 10,000 steps; slower chains fall back to the exact `linalg.Solve` of π(I − P) = 0, Σπ = 1 — `summary.parameters.steady_state_converged` 0 says which; only for one communicating class (Tarjan) with period 1 (gcd of `level(u)+1−level(v)` over edges from a BFS), else one `PULSE_OVERLAY_MARKOV_NOT_ERGODIC` `{reason: reducible, classes}` / `{reason: periodic, period}` and no part), `absorption_time` (with `absorbing`: expected steps to FIRST reach the declared set — the declared rows are not rewritten, so it is a first-passage time — `(I − Q)⁻¹·1` via `linalg.FactorLU` over the non-absorbing states certain to be absorbed; a state that can reach a closed class outside the set is NaN → `null` with one `PULSE_OVERLAY_MARKOV_NOT_ERGODIC` `{reason: absorption_not_certain, states}`; an LU-refused (numerically singular) I − Q drops the part with a `PULSE_MATRIX_SINGULAR` WARNING carrying linalg's details plus `kind` / `part` — the layer still ships, never a silent NaN). Summary parameters `states`, `classes`, `irreducible`, `period` (irreducible only), `steady_state_iterations` / `_converged`. Every product is FMA-free (explicit `float64()` around it). Interpretation addresses only the fixed-name parts (`overlayPartShapes`: `steady_state`, `absorption_time`); `step_<n>` / `distribution_<n>` are named by params. Oracle: `scripts/reference/gen_markov.R` (`markovchain` 1.2; its igraph / expm deps need the Homebrew Fortran workaround) → `markov.json`, plus the power-iteration self-check (πP = π) and the closed-form two-state fallback test. Example `crosstab-markov` runs on the `tier_migrations` fixture cohort.

- **`OVERLAY_RAKE` (U28 E2-S3).** 2-D raking (iterative proportional fitting) of the crosstab to target margins: MATRIX (crosstab) host, scope `matrix`, implicit-margin, descriptive (no p-site, no weight class: a weighted host's Σw table is raked as is, and share targets scale to its Σw grand total). Read-only — the host payload is never written (`TestRake_DoesNotMutateHost`, root `TestRake_EndToEnd` byte-identity). `internal/processing/overlay_rake.go` (`applyRakeAt`, index-aware in `applyOverlaysPlanned`). Params (`overlayhost.ParseRakeParams`, strict, `PULSE_OVERLAY_PARAM_MISSING`): `row_targets` / `col_targets` REQUIRED (non-empty key → finite ≥ 0 maps with a positive sum), `targets_as` `shares` (default: each axis ÷ its sum × the host grand total) | `counts` (as given; row and column totals differing by more than `tolerance` relative to the larger is `PULSE_OVERLAY_RAKE_TARGET_MISMATCH` reason `totals_differ` — params-only, so predict and runtime alike), `max_iter` (default 100, 1–100,000 — the upper cap an interview gap, set so one spec cannot ask for unbounded sweeps), `tolerance` (default 1e-8, in (0, 1)). Target sums run in sorted key order so both sides round alike. **Keys:** a target key matches a host key by `overlayhost.RakeKeyName` (= `MarkovStateName`); a mismatch either way is `PULSE_OVERLAY_RAKE_TARGET_MISMATCH` reason `keys` `{kind, reason, axis, target_only, host_only, index}` (row axis first) — refuse, never drop (a dropped key would mislabel the fit). Predict judges only target keys outside a single `GROUP_CATEGORY` categorical axis's dictionary (`axisDictionary`, `host_only` empty); a dictionary entry the records never hold is the runtime's call. Cells: `NonnegativeCellRefusal` / `NonnegativeValueRefusal`; absent cell = 0; a zero grand total is `PULSE_OVERLAY_REF_INCOMPATIBLE_WITH_SHAPE`. **Sweep:** rows with a positive total × target / total, then columns likewise; residual = max over both axes of `|margin − target| / target` (`|margin| / Σ targets` for a zero target); stop once residual ≤ `tolerance` or after `max_iter` sweeps. Every fitted cell is `obs · a_i · b_j`, so a structural zero stays zero and an all-zero row / column cannot reach a positive target. Outputs: primary MATRIX fitted table on the host keys (every cell present); part `factors` (MATRIX fitted / observed, NaN → `null` where observed is 0); summary parameters `iterations`, `residual`, `converged` (1 / 0). A capped fit ships anyway with one `PULSE_OVERLAY_RAKE_NOT_CONVERGED` WARNING `{kind, iterations, residual, tolerance}` on `Response.Warnings` (the per-Request overlay path's warning carrier). Rake-to-weights (writing a weight column) is out of scope. Oracle: `scripts/reference/gen_rake.R` (`stats::loglin(outer(r, c)/Σr, list(1, 2), start = x, fit = TRUE)`, cross-checked against `survey::rake` + `svytable` at 1e-6) → `rake.json`; a capped case runs loglin `eps = 0` for exactly `max_iter` cycles, matching Pulse sweep for sweep; host columns are reversed against the targets in `TestRake_MatchesR`. Example `crosstab-rake` (region × segment of the `experiment` fixture).
