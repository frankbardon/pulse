# Execution modes — crosstab and fused crosstab

Per-topic slice of the execution-modes reference. Index (Mode index + section map): `.claude/reference/execution-modes.md` — load it first, then only the slice(s) your engine work touches. Skill: `skills/crosstab-guide.md`.

## Crosstab

`Request.Crosstab`, `Response.Crosstab`. Composes existing groupers + aggregators across a row × column axis grid; reshape, margin recompute and normalization layer on top. Multi-grouper axes are recursively partitioned. **Margins are always recomputed from raw rows** — an `AGG_MEDIAN` row margin equals the standalone single-axis median, NOT the median of cell medians. Per-aggregator classification is `AggregationType.MarginReducibility` (`summable` / `mean_reducible` / `independent` / `recompute`; `independent` = the operator keeps its own row / column / grand accumulator, so the margin — a union, not a cell sum — is exact after one pass and the fused gate admits it). `shape: matrix` (default) populates `Response.Crosstab.Matrix`; `shape: long` emits tuple rows on `Response.Data` with margin rows tagged `_margin=row|column|grand`. Buffered except the fused arm below, or `shape=long` + no margins + `normalize=none`. Capability: `Manifest.Crosstab`; predict gate `descriptor.validateCrosstab`. A `null` axis slot (`rows: [null]`) is refused `PROCESSING_CONFIG` `{axis, index}` by `crosstabaxis.NilGrouperRefusals`, which both validators call ahead of any arm (`TestCrosstab_NilAxisGrouperRefusedOnEveryArm`).

Normalization: `normalize_level` truncates the same axis as `normalize`; `normalize_within` fixes a prefix of the OPPOSITE axis. Both compose.

**Projection.** The buffered record set is always projected to the fields the crosstab references (`processing.NeededFields` walks rows, columns, cell, label fields and cell params), regardless of `DisableProjection`, so wide-cohort cost is `O(|referenced|)`.

**The implicit Total column.** `Columns` is optional: absent, `null` or `[]` runs the crosstab with ONE column keyed `types.CrosstabTotalColumnKey` (`["Total"]`) under `CrosstabSpec.ColumnHeader()` = `{fields: ["_total"], types: ["TOTAL"]}` — a synthetic header position so header position i still names key position i. Every record resolves a zero-grouper axis, so cell admission reduces to "the row key resolved"; the column margin equals the grand margin and each row margin its one cell.

- Internally the column's composite key is `""` on both arms (buffered relabels only the column tuples after partitioning; fused derives the same `("", ["Total"])` pair and interns it at `Finalize` when no record was seen, so an empty cohort still emits the column).
- A column-axis `normalize_level` (normalize=column) or `normalize_within` (normalize=row) has no depth to read: `_OUT_OF_RANGE` with `axis_len: 0` on predict and runtime alike.
- Long shape: rows carry the row fields only. Fusable whenever the rows are.
- **Overlays** read it the same way on both sides: Level / Within depth = the header length (1); the square-host arity rule counts groupers through `overlayhost.HeaderGrouperCount` (0 for TOTAL, so the paired-flow kinds are `PULSE_OVERLAY_MATRIX_NOT_SQUARE`); `overlayhost.TotalColumnRefusal` refuses the kinds that need two columns up front; `OVERLAY_RAKE` col targets are checked against the one key `Total` at predict too; predict's p-value count reads 1 column.
- Pinned by `TestCrosstab_TotalColumnFusedMatchesBuffered` and `TestCrosstab_TotalColumnPredictMatchesRuntime`.

**Several measures as stub rows.** `CrosstabSpec.Cells` (exclusive with `Cell`; faults detected once in `types.CellsFaults`) runs the crosstab once per measure as `MeasureSpec(i)` over axis partitions computed ONCE, then `foldCrosstabMeasures` (`internal/processing/crosstab_measures.go`) stitches the results: row r, measure m at payload row r*M+m, `RowHeader` + `{_measure, MEASURE}`, column margins + grand total into `MatrixPayload.Measures`, the column / grand components into `CrosstabComponents.Measures`, long and post-test rows stamped `_measure`. Divergent axis keys between measures are `PROCESSING_INTERNAL` (an invariant). The fused arm keeps one state per measure, updated in one scan, and runs the same fold — so fused ≡ buffered and each measure ≡ its single-cell run by construction. `crosstabfuse.Decide` fuses the table only when every measure would.

- Every per-cell pass iterates the measures too (weight, projection, vector slots, array-valued refusal at `cells[i]`, predict field refs, limits, return sizes rows × M, p-value count × M, smart defaults per entry). When adding a per-cell pass, iterate `CellAggregations()`.
- **Overlays:** the pairwise kinds run per measure through one shared accumulator (column scope maps r → r*M+m). Every other kind is refused up front by `overlayhost.MeasureHostRefusal` (`PULSE_OVERLAY_REF_INCOMPATIBLE_WITH_SHAPE`, `multi_measure_host`); a Compose overlay reading a multi-measure slot is refused on both sides. Gated by `capability:crosstab_cells`.

**Auxiliary margin-only aggregations** (`margin_aggregations`) are computed by `computeAuxMargins` (`internal/processing/crosstab_margin_agg.go`) beside the cell aggregator's own margins, and **must match what the fused walk accumulates for the same request** — dispatch picks the arm on request shape and nothing in `Response` reports which ran. **A record reaches an auxiliary margin only if it reached a CELL**, so a null cell field and an axis key an `Include` excluded are absent from every auxiliary slot.

- The buffered implementation resolves each axis's membership ONCE and walks each margin slot on its own axis — deliberately NOT the `(rkey, ckey)` cell buckets, which would fold a record into a ROW auxiliary once per COLUMN it landed in (M times under a `GROUP_SET_PER_ELEMENT` fan-out), where fused folds it once per distinct row key.
- Each slot's `{n, n_null}` floor is over ADMITTED records; a slot admitting nothing carries no figure at all, mirroring fused's unconstructed accumulator.
- An auxiliary naming an unknown operator is refused up front, AHEAD of the compute plan gate (past which nothing is evaluated when the figures are not requested).
- Partial-depth and cross-axis margins get no auxiliary on either path: those are normalization denominators, and an auxiliary is never a denominator.
- Pinned by `TestCrosstab_BufferedAuxMarginMatchesFused`.

A crosstab carrying a `JoinSpec` runs over the joined rows, always buffered — `execution-modes/chain-join-facet.md` (Crosstab over a join).

**Data-dependent axis groupers: `params.fit`.** `GROUP_QUANTILE` and `GROUP_KMEANS` take `params.fit` `"global"` (default) or `"within"`, read ONCE by `internal/groupfit` for predict and runtime (an unknown value is `PROCESSING_CONFIG`, details `{type, param, value, valid, reason: "bad_fit"}`).

- Under `global` the buffered crosstab fits the slot once over the filtered records and every partition call only ROUTES records by that assignment (nested positions, per-row-bucket column partition, normalisation denominators), so crosstab bands equal plain `groups` bands.
- Under `within` the slot refits on each outer bucket's records (rows, then columns: a column position's outer segment is the full row tuple plus its column prefix). Plain `groups` mirrors it (a fresh grouper per prefix bucket; the whole-set fit still sources that slot's Components, unstamped warnings and key order; each refit's own figures are that slot's `Buckets` entry, and a refit refused on its bucket's data fails that bucket alone — `.claude/reference/response-components.md` (Grouper refit buckets)). Compose slots take the same path.
- **Refit warnings.** Every warning a `within` refit raises reaches `Response.Warnings` ONE PER REFIT AND CODE (never collapsed, since each bucket stops at its own iteration count): details gain `group_key` (the outer segment), the message a `(fit within group [...])` suffix. The crosstab collects only from its two CELL partitions, so margin, normalisation and component passes refit silently and each outer bucket reports once.
- The outermost position (`groups[0]`, crosstab `rows[0]`) has no outer segment: `within` there is a no-op, never refused. `global` and absent `fit` are byte-identical. Neither grouper fuses, so `fit` never moves `crosstab_fusable`. Pinned by `TestGroupFit_CrossPath`.

**Axis key order.** Each axis position emits by its explicit `Include` (members first), else its grouper's fitted order (GROUP_KMEANS), else its grouper's intrinsic key order (`keyOrderer` — e.g. quantile bucket id, range low edge, supplied range index with the unmatched label last, `day_of_week` Monday first), else alphabetically. Date groupers also honour `Group.Include` (restrict and order). Buffered, fused (partial normalisation margins included) and plain `groups` resolve the same chain (`TestFusedCrosstab_BucketOrderMatchesBuffered`). A new grouper with a natural order implements `keyOrderer`.

**Resource limits on the crosstab arms.** `MaxCrosstabCells` bounds the grid (rows × columns of observed composite axis keys); a breach raises `PULSE_LIMIT_EXCEEDED` with no partial result.

- Buffered checks once, right after partitioning and BEFORE the per-cell map preallocations. Fused checks on the PROSPECTIVE product at key interning, before any dense slice grows; a fused state built without limits enforces nothing.
- Both arms see the same final grid, so the same request trips with the same `{code, limit, configured}`; `observed` is the final grid on buffered and the first product past the limit on fused. The joined crosstab trips in the buffered arm.
- Predict grades the Cartesian upper bound `EstimateCrosstabCells` as `possible` only, so the pre-flight never refuses on it.

**Labels on axes and overlay keys.** Label application runs after the overlay fold on every arm (fused, buffered, joined) and reaches past `Response.Data` (`internal/service/label_surfaces.go`): a `replace` binding on an axis field rewrites `Matrix.RowKeys` / `ColumnKeys`, every overlay matrix / series key and its adjusted twins and parts, and rebuilds each pairwise PAIR key from the relabelled host key (`processing.PairKeyElement`).

- Keys are rebuilt into fresh slices (a layer may share the host's key slices, so an in-place rewrite would translate twice), and only key TEXT moves — positions and figures never change, so overlay coordinates still address the same host cell.
- A grouped run's `group_key` tuples (tests, post-tests, matrices, Components) follow positionally.
- `augment` cannot ride a matrix axis key and warns `PULSE_LABEL_NOT_APPLIED` (`reason: augment_on_matrix_axis`); a caller binding reaching no surface warns `reason: field_not_in_output`; `Options.AutoLabels` defaults never warn.
- An `ATTR_PREVIOUS_STATE` output column inherits every default on its state field, so both axes of a previous-state × state crosstab carry display labels.

## Fused crosstab

`processing.CanFuseCrosstab` — a thin adapter over the shared rule `crosstabfuse.Decide` in the no-execute leaf `internal/crosstabfuse` — and `processing.FusedCrosstabState`. An in-decode streaming alternative to the buffered orchestrator: when the gate accepts, the service skips record materialisation and recursive partitioning and drives one streaming pass that interns row / column composite keys on first sight and folds each filter-passing record into the matching cell / margin online aggregators. Memory drops from `O(filtered records)` to `O(cells + margins)`. Disable via `Options.DisableCrosstabFusion`.

**Gate.** `crosstabfuse.Decide` is the rule; read it for the full list. Its shape:

- The cell aggregator is mergeable and not `recompute`, read through the registry so an extension answers with its DECLARED `Mergeable` / `MarginReducibility`. A vector ELEMENT cell (`AGG_VEC_*` with `params.element`) answers its scalar twin's class.
- Every row / column grouper is KEYABLE: a built-in per the static `crosstabfuse` keyability table (`TestBuiltinGrouperKeyableMatchesRegistry`), an extension per its declared `Streamable || FansOut`. Keying means `StreamableGrouper.KeyFor` (one bucket per record — `GROUP_DATE` is admitted here even though it is not streamable at the Process layer) or `MultiKeyStreamingGrouper.KeysForRow` (N buckets per record: `GROUP_SET_PER_ELEMENT`). `GROUP_QUANTILE` and `GROUP_KMEANS` (both fit over every row first) always force buffered. An extension grouper opts in via `extend.StreamingGrouper` or `extend.MultiKeyStreamingGrouper`, returning `extend.ErrGrouperKeyNull` on nulls; without either it stays correct, buffered.
- Declined: tests, features, windows (a windows-first crosstab is buffered; a crosstab window nothing reads is refused, `crosstab_window_unread`), regressions (the buffered arm fits them over the filtered records), two-pass attributes (the fused walk never runs a `PrePass`, so admitting one would value every row against empty stats), buffered-only attributes (`reason buffered attribute (<TYPE>)`), `ATTR_FORMULA`, `FILTER_EXPRESSION`, a decimal128 cell field on a BUILT-IN cell, an extension operator without a `FieldInputs` hook, joins.
- Every `margin_aggregations` entry must be mergeable (and non-decimal for a built-in): declining sends the request to buffered rather than dropping the auxiliary, which would silently return a margin missing the requested figure. An auxiliary's `MarginReducibility` is deliberately NOT consulted — every auxiliary is `independent` in role, fed record by record.
- Every `AssertCanFuse` refusal is declined by `Decide` first (`TestAssertCanFuse_RejectionsDeclinedByGate`).

**Predict reports the decision.** `PredictResult.CrosstabFusable` (`*bool`, nil ⇔ no crosstab) + `CrosstabFusionReasons` (every decline, rule order) come from `descriptor.CrosstabFusion` — the same `Decide` over the extension snapshot + instance feature set — on the defaults-resolved request; `PredictOptions.DisableCrosstabFusion` answers false with `CrosstabFusionDisabledReason`. `Predict` / `PredictBytes` only. A name the feature profile hides answers as never-registered on both arms, so the answer cannot reveal a hidden operator. **One sanctioned divergence:** a keyable built-in grouper whose factory rejects its params (e.g. `GROUP_DATE` `component:"fortnight"`) — runtime declines, predict says fusable from the static table; the request errors either way. Pinned by `TestStreamability_CrosstabFusionPredictMatchesRuntime`.

**Overlays do not force buffered.** They decorate a finalised response, so the fused run folds them after `Finalize` through the same hook the buffered exit calls — cells, `Components`, `Overlays` and `Warnings` are byte-identical across arms. The surviving reason is the cell aggregator: `AGG_WELFORD` is non-mergeable, so the Welch t / two-means z pairwise kinds stay buffered; the proportion and weighted two-means kinds over an `AGG_WEIGHTED_MEAN` cell fuse.

**Multi-key axis routing.** The fused keyer returns the cartesian product of each position's key set plus deduped per-depth prefix sets, so one record updates every accumulator the buffered path would touch, exactly once per distinct key at that depth. Fan-out is legal at any axis position, on either or both axes. Deliberately, as in buffered: margins are NON-ADDITIVE under fan-out — a record selecting 3 labels counts 3× across row margins but once in the grand margin.

**Margins follow cell admission.** A record reaches a row, column or grand margin, or a `normalize_level` / `normalize_within` denominator, only if it reached a CELL — BOTH axes resolved in full. Buffered narrows each margin / denominator bucket to admitted records (partitions are still built over all filtered records, so data-dependent groupers route as before); fused gates every margin and denominator update on `rowKeys.ok && colKeys.ok` while still interning each axis's keys per axis (so both arms emit the same `RowKeys` / `ColumnKeys`, a key with no admitted record carrying an absent margin), and emits a grand margin only when one was admitted. Pinned by `TestCrosstab_OwnMarginsFollowCellAdmission`.

**Auxiliary accumulation on the fused arm.** One accumulator per declared auxiliary per occupied slot, built on first admission. It observes a DIFFERENT admission from the cell's own margins: three exclusions — a null cell field, an unresolved row key (including one an `Include` excluded, surfacing as `ErrGrouperKeyNull`), an unresolved column key. The cell's own margins share the two axis exclusions but still count a null cell field as `n_null`; an auxiliary is metric-scoped. **Getting this wrong is SILENT** — every number still renders, the base is merely wrong. Slots are allocated only for the margins the spec asks for, and none when `margin_aggregations` is absent or the compute plan drops the figures. They surface on `Response.Components` (`crosstab.margin_aggregations`, `response-components.md`) unless a `return` drops them.

Cells land only where both axes resolved. Map-valued cell aggregators paired with `normalize != none` are rejected (`PULSE_CROSSTAB_NORMALIZE_MAP_VALUED`).

**Measuring.** Quote peak heap, never `B/op`: `B/op` is cumulative bytes allocated and cannot see retention, so it understates the fused win by roughly 20× on the fan-out + overlay bench (`BenchmarkCrosstabSetFanoutOverlay`). `allocs/op` is higher on fused (the fan-out keyer builds a key tuple per fanned key) — expected, not a regression. See `skills/crosstab-guide.md` (Fused mergeable path) and `skills/grouper-design.md` (Fused crosstab eligibility).
