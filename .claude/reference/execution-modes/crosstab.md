# Execution modes — crosstab and fused crosstab

Per-topic slice of the execution-modes reference. Index (Mode index + section map): `.claude/reference/execution-modes.md` — load it first, then only the slice(s) your engine work touches.

## Crosstab

`Request.Crosstab`, `Response.Crosstab`. Composes existing groupers + aggregators across a row × column axis grid; reshape, margin recompute, normalization layered on top. Multi-grouper axes recursively partitioned. Margins always recomputed from raw rows for correctness — `AGG_MEDIAN` row margin equals the standalone single-axis median, NOT the median of cell medians. Per-aggregator classification at `AggregationType.MarginReducibility` (`summable` / `mean_reducible` / `independent` / `recompute`; `independent` = the operator keeps its own row/column/grand accumulator, so the margin — a union, not a cell sum — is exact after one pass and the fused gate admits it). `shape: matrix` (default) populates `Response.Crosstab.Matrix`; `shape: long` emits tuple rows on `Response.Data` with margin rows tagged `_margin=row|column|grand`. Inherently buffered except `shape=long` + no margins + `normalize=none`.

Normalization layering: `normalize_level` truncates the same axis as `normalize`; `normalize_within` fixes a prefix of the OPPOSITE axis. Both compose.

**The implicit Total column (U47 E2-S1, #326 / #328).** `Columns` is optional: absent, `null` or `[]` (`CrosstabSpec.HasImplicitTotalColumn`) runs the crosstab with ONE column keyed `types.CrosstabTotalColumnKey` (`["Total"]`) under `CrosstabSpec.ColumnHeader()` = `{fields: ["_total"], types: ["TOTAL"]}` — a synthetic header position (the PAIR-axis precedent) so header position i still names key position i. Every record resolves a zero-grouper axis, so the cell-admission rule reduces to "the row key resolved"; the column margin equals the grand margin and each row margin its one cell. Internally the column's composite key is `""` on both arms: buffered keeps `PartitionByAxis`'s empty-axis bucket and relabels only `colPart.Tuples` after the partition (the per-row column partition, margins and normalize lookups keep addressing `""`); the fused `fusedAxisKeyer.derive` returns that same `("", ["Total"])` pair for a zero-grouper axis (one level, so a `normalize: column` + `normalize_within` cross-axis consumer reads `prefixes(0) = [""]`, matching buffered's row-prefix-only joined partition with column part `""`), and `Finalize` interns it when no record was seen so an empty cohort still emits the column on both arms. Buffered guards the two column-depth slices (`axisLen == 0` → leaf margin; `Columns[:min(colDepth+1, len)]`). A column-axis `normalize_level` (normalize=column) or `normalize_within` (normalize=row) has no depth to read and is `_OUT_OF_RANGE` with `axis_len: 0` on predict and runtime alike. Long shape: rows carry the row fields only (the streaming long arm lowers to rows-only `groups`). `PULSE_CROSSTAB_EMPTY_COLUMNS` is no longer raised (retained for lookups). Fusable whenever the rows are. **Overlays** read the column the same way on both sides (predict sees no grouper, runtime one header position): Level / Within depth = the header length (1; predict `len(ColumnHeader().Fields)`, runtime `len(ColumnKeys[0])`); the square-host arity rule counts groupers through `overlayhost.HeaderGrouperCount` (0 for the TOTAL header, so `OVERLAY_MARKOV` / `_RETENTION` / `_SYMMETRY` are `PULSE_OVERLAY_MATRIX_NOT_SQUARE` on both); `overlayhost.TotalColumnRefusal` refuses the two-column kinds (`OVERLAY_CHISQ_MATRIX` / `_CHISQ_ROW` / `_STD_RESIDUAL` / `_CORRESPONDENCE`) `PULSE_OVERLAY_REF_INCOMPATIBLE_WITH_SHAPE` up front in `ValidateOverlays` and `refuseWrongHostOverlays`; `OVERLAY_RAKE` col targets are checked both ways against the one key `Total` at predict too; predict's p-value count reads 1 column. Gates: `TestCrosstab_TotalColumnFusedMatchesBuffered`, `TestCrosstab_TotalColumnShape`, `TestCrosstab_TotalColumnNormalizeWithinOracle`, `TestCrosstab_TotalColumnPairwiseAlongRows`, `TestCrosstab_TotalColumnPredictMatchesRuntime`, `TestCrosstab_TotalColumnOverlaysPredictMatchesRuntime`, `TestCrosstab_TotalColumnPValueCount`, `TestFusedAxisKeyer_ZeroGroupersIsTotalColumn`, the `no_columns*` rows of `TestPredict_CrosstabFusableMatchesRuntime`.

**Several measures as stub rows (U47 E2-S2, #326).** `CrosstabSpec.Cells` (exclusive with `Cell`; faults DETECTED once in `types.CellsFaults`, rendered by `validateCrosstabSpec` and predict alike) runs the crosstab once per measure as `MeasureSpec(i)` — `Cell = Cells[i]`, `Cells = nil` — over axis partitions computed ONCE (`innerCols`, row/column membership, axis-key components), then `foldCrosstabMeasures` (`internal/processing/crosstab_measures.go`) stitches the per-measure responses: row r, measure m at payload row r*M+m, `RowHeader` + `{_measure, MEASURE}`, `CellLabels`, column margins + grand total into `MatrixPayload.Measures`, the column / grand components into `CrosstabComponents.Measures`, long and post-test rows concatenated and stamped `_measure`. Divergent axis keys between measures are `PROCESSING_INTERNAL` (an invariant: they share the partitions). The fused arm (`crosstab_fused_run.go`) keeps one `FusedCrosstabState` per measure, `Update`s every state per record in one scan, finalizes each and runs the same fold — so fused ≡ buffered and each measure ≡ its single-cell run by construction. `crosstabfuse.Decide` iterates `CellAggregations()`: the table fuses only when every measure would. Every per-cell pass iterates the measures too (weight stamp / tally, projection fields, attribute rewrite, vector slots, array-valued refusal `cells[i]`; predict field refs, limits, params allowlist `crosstab.cells`, weight resolve `CellSlotPath(i)`, return sizes rows × M, p-value count × M, smart defaults per entry). **Overlays:** `applyOverlaysToResponse` hands the pairwise kinds a `CrosstabHostView` with per-measure sub-hosts (`measures`); `runPairwiseOverlayMeasures` runs `pairwiseGate` per measure through one shared `pairwiseAccumulator` (column scope maps r → r*M+m, skip-warning `sample_opposite_idx` is the folded index; row scope concatenates per-measure pairs labelled by the folded row keys). Every other kind is refused up front by `overlayhost.MeasureHostRefusal` (`PULSE_OVERLAY_REF_INCOMPATIBLE_WITH_SHAPE`, `multi_measure_host`) in `ValidateOverlays` and `refuseWrongHostOverlays`; predict's pairwise validation recurses per `MeasureSpec`; a Compose overlay reading a multi-measure slot is refused by `ComposeOverlayMeasureSlotRefusal` in both predict (`compose.go`) and `service.applyComposeOverlays`. Gated by `capability:crosstab_cells`. Gates: `TestCrosstabCells_*` (root `crosstab_cells_test.go`), the `cells_*` rows of `fusionParityCorpus` (`TestStreamability_CrosstabFusionPredictMatchesRuntime`), `TestCrosstabSpec_CellsFaults`.

Auxiliary margin-only aggregations (`margin_aggregations`) are computed by `processing.(*Processor).computeAuxMargins` (`internal/processing/crosstab_margin_agg.go`) alongside the cell aggregator's own three margin blocks, and MUST match what the fused walk accumulates for the same request — dispatch picks the arm on request shape and nothing in `Response` reports which ran. The admission rule is the same one stated under Fused crosstab: a record contributes to an auxiliary only if it contributed to a CELL, so a null cell field and an axis key an `Include` excluded are absent from every auxiliary slot. The cell's own margin loops beside them share the axis half (U47 #325, below) but still count a null cell field as `n_null`. The buffered implementation resolves each axis's membership ONCE into pointer sets and then walks each margin slot on its own axis — deliberately NOT the `(rkey, ckey)` cell buckets, which are admitted-by-construction but would fold a record into a ROW auxiliary once per COLUMN it landed in, M times under a `GROUP_SET_PER_ELEMENT` fan-out, where fused folds it once per distinct row key. Each slot's admitted subset is shared across the auxiliaries in it and rides `runCellAggregation`, so the `{n, n_null}` floor is over ADMITTED records and decimal128 dispatch comes for free; a slot admitting nothing carries no figure at all, mirroring the fused path's unconstructed accumulator. An auxiliary naming an unknown operator is refused up front, matching `NewFusedCrosstabState` — AHEAD of the compute plan's `AuxMargins` gate, past which `computeAuxMargins` returns nil and evaluates nothing when the figures are not computed. Partial-depth and cross-axis margins get no auxiliary on either path: those are normalization denominators, and an auxiliary is never a denominator. `TestCrosstab_BufferedAuxMarginMatchesFused` drives one request down both arms.

A crosstab carrying a `JoinSpec` runs over the joined row stream, always buffered — see Pushdown hash join (Crosstab over a join). Relocated from `skills/crosstab-guide.md` (Fused mergeable path) at U46 E4-S1 to free budget: a joined crosstab runs buffered over the JOINED rows: axes / cell may name `as`-prefixed right fields; an unmatched left row is counted nowhere; a 1:N match counts once per joined row (`join-design`).

**Data-dependent axis groupers: `params.fit` (U46 E4-S1, #428).** `GROUP_QUANTILE` and `GROUP_KMEANS` take `params.fit` `"global"` (default) or `"within"`, read ONCE by `internal/groupfit` (`Parse` / `IsWithin`; the runtime factories `newQuantileGrouper` / `newKMeansGrouper` and predict's `validateGroupFitParams` both call it, so an unknown value is refused `PROCESSING_CONFIG` with identical message and details `{type, param, value, valid, reason: "bad_fit"}`). Under `global` the buffered `RunCrosstab` fits the slot once over `filtered` in `fitWholeSetAxes` (`wholeSetAxis`, keyed by slot) and `PartitionByAxis` only ROUTES records by that assignment at every call site — nested position, the per-row-bucket column partition, and the normalisation denominators — so the crosstab bands equal plain `groups` bands. Under `within` the slot is not whole-set and `PartitionByAxis` refits it on each outer bucket's records (rows, then columns: a column position's outer segment is the full row tuple plus its column prefix) — the pre-U46 crosstab quantile behaviour, now opt-in (behaviour break; migration row in `03-embedder-migration.md`). Plain `groups` mirrors it in `partitionComposite` → `partitionCompositeWithin` (prefix buckets outer → inner, a fresh grouper instance per bucket for a `within` position; the whole-set fit still sources that slot's Components, unstamped warnings and key order), and every Compose slot runs the same processor path. **Refit warnings (E4-S5).** Every warning a `within` refit raises (today `GROUP_KMEANS`'s `PULSE_MATRIX_NOT_CONVERGED`; quantile cuts raise none) reaches `Response.Warnings` ONE PER REFIT AND CODE — the grouped-tests per-group convention, never collapsed, since each bucket stops at its own iteration count — through `refitWarnings` (`grouper.go`): details gain `group_key` (the outer segment as an `AxisKey`), the message a `(fit within group [...])` suffix. Plain groups collect them in `partitionCompositeWithin` (`compositePartition.RefitWarnings`); the crosstab collects only from its two CELL partitions (`partitionByAxis` with a warning sink: rows over `filtered`, then columns per row bucket under the row tuple), so the column-key, margin, normalisation and component passes refit silently and each outer bucket reports once. `fitWholeSetAxes` also fits a `within` position whole-set (`wholeSetAxis.route = false`: Components plus the unstamped warning plain groups emit) and routes an outermost `within` like `global`, so both paths raise the same set; `global` and absent `fit` are byte-identical. The outermost composite position (`groups[0]`, crosstab `rows[0]`) has no outer segment: `within` there is a no-op, never refused. The fused path never carries either grouper (`crosstabfuse` keyability table), so `fit` never moves `crosstab_fusable` / `crosstab_fusion_reasons`. Gate: `TestGroupFit_CrossPath` (plain × nested rows × column axis × Compose, both values, quantile and k-means; `within` equals the per-region runs), `TestGroupFit_OutermostWithinIsNoOp`, `TestGroupFit_RefusedIdentically`, `TestGroupFit_RefitWarnings` (one per outer bucket, same set on plain × both crosstab axes × normalised crosstab × Compose), `TestPredict_GroupFitParams`.

Buffered record set automatically projected via `service.applyCrosstabProjection` (extends `processing.NeededFields` to walk `Crosstab.Rows/Columns/Cell` + `req.Labels[].Field` + `AGG_WEIGHTED_MEAN/RATIO` Cell.Params); wide-cohort crosstab cost is `O(|referenced|)` not `O(|schema|)`; forced on regardless of `opts.DisableProjection`. Capability: `Manifest.Crosstab`. Predict gate: `descriptor.validateCrosstab`. See `skills/crosstab-guide.md`.

**Axis key order (U49 E2-S3, #346).** Each axis position emits by its explicit `Include` (members first), else its grouper's fitted order (`emissionOrderer`, GROUP_KMEANS), else its grouper's intrinsic key order (`keyOrderer` — GROUP_QUANTILE bucket id, GROUP_RANGE numeric low edge, GROUP_ROUNDED key value, GROUP_NUMERIC_RANGES and GROUP_DATE_RANGES supplied range index with the unmatched label last — E2-S4, U50 E2-S1; GROUP_DATE `day_of_week` Monday first; its ISO and zero-padded `hour_of_day` keys stay unranked, already chronological as strings), else alphabetically. GROUP_DATE / GROUP_DATE_RANGES also honour `Group.Include` (restrict at `KeyFor`, order by it, on every arm; `TestDateKeyOrder_*`). Buffered `partitionByAxis` and the fused `orderCompositeKeysByAxisInclude` / `buildPartialAxisFromKeys` (handed the fused axis groupers) resolve the same chain, so both arms — partial normalisation margins included — match; plain `groups` (`includeFilterOf`, composites via `OrderCompositeGroupKeys`) uses the same rank. Pinned by `TestFusedCrosstab_BucketOrderMatchesBuffered` and root `TestBucketOrder_*`.

**Resource limits on the crosstab arms (U19).** `MaxCrosstabCells` bounds the grid, rows × columns of observed composite axis keys, and a breach raises `PULSE_LIMIT_EXCEEDED` (`limits.Check`) with no partial result. The buffered arm (`RunCrosstab`) checks once, right after the two `PartitionByAxis` calls and BEFORE the `rows*cols` per-cell map preallocations. The fused arm checks in `internRowKey` / `internColKey` on the PROSPECTIVE product (`(len(rowKeys)+1)*len(colKeys)` / `len(rowKeys)*(len(colKeys)+1)`) before any dense slice grows; `RunCrosstabFused` installs the processor's limits through `FusedCrosstabState.setLimits`, and a state built without them enforces nothing. Both arms see the same final grid, so the same request trips with the same `{code, limit, configured}` on either; `observed` is the final grid on buffered and the first product past the limit on fused. The joined crosstab is buffered, so it trips in `RunCrosstab` over the joined rows. Predict grades the Cartesian upper bound `EstimateCrosstabCells` (each axis the product of its positions' `EstimateGroups` bounds, clamped by the header record count unless a position fans out) as `possible` only — so the pre-flight never refuses on it. Gates: `TestMaxCrosstabCells_Arms`, `TestLimits_MaxCrosstabCells_BothArms`, `TestLimits_MaxCrosstabCells_JoinedCrosstab`, `TestEstimateCrosstabCells`.

## Fused crosstab

`processing.CanFuseCrosstab` (a thin adapter over the shared rule `crosstabfuse.Decide` in the no-execute leaf `internal/crosstabfuse`), `processing.FusedCrosstabState`, `processing.StreamableGrouper.KeyFor`, `processing.MultiKeyStreamingGrouper.KeysForRow`. In-decode streaming alternative to the buffered Crosstab orchestrator. When the gate accepts, `service.processCrosstab` short-circuits `materializeRecords` + recursive `PartitionByAxis` and drives a single streaming pass that interns row/col composite axis keys on first sight and folds each filter-passing record into the matching cell / row-margin / column-margin / grand-margin / cross-axis-margin online aggregator. Memory drops from `O(filtered records)` to `O(cells + margins)`.

Gate composition (`CanFuseCrosstab`): mergeable + non-recompute scalar cell aggregator (both read through the registry — `IsMergeable` / `AggregatorMarginReducibility` — so an extension cell answers with its DECLARED `Mergeable` / `MarginReducibility`; a vector ELEMENT cell — built-in `AGG_VEC_*` with `params.element`, U30 E4-S4 — answers its scalar twin's class through the per-slot fact `AggregatorSlotMarginClass` → `vectors.ElementMarginClass`, `AGG_VEC_MEAN` mean_reducible / `AGG_VEC_SUM` summable / `AGG_VEC_SD` keeps its type's recompute class (buffered, like `AGG_STDDEV`), on both facts adapters and predict's normalize advisory); every row/col grouper is KEYABLE — a built-in per the static `crosstabfuse` keyability table (pinned against the constructed instances by `TestBuiltinGrouperKeyableMatchesRegistry`), an extension per its DECLARED `Streamable || FansOut`; the runtime facts adapter additionally declines a grouper whose factory fails to construct — and keying means one of the two per-record interfaces: `StreamableGrouper.KeyFor` (one bucket per record: CATEGORY/RANGE/ROUNDED/DATE/SET_VALUE — `GROUP_DATE` is admitted here even though `GroupType.Streamable()` is false at the Process layer) or `MultiKeyStreamingGrouper.KeysForRow` (N buckets per record: `GROUP_SET_PER_ELEMENT`); no tests; no features; no windows (the fused walk runs none, `AssertCanFuse` echoes it — a windows-first crosstab and a historical-order one with windows are both buffered; mmm-followups E4-S3); no two-pass attribute (the built-in set or a `two_pass` extension — the fused walk never runs a `PrePass`, so admitting one values every row against empty stats; `AssertCanFuse` echoes it); no buffered-only attribute (`ATTR_PERCENTILE`, an extension declared not streamable — no per-record arm to score; `Facts.AttributeBuffered`, reason `buffered attribute (<TYPE>)`, U50 E6-S1: the fused arm used to take it and fail `PROCESSING_INTERNAL` while predict promised a fused run); no `ATTR_FORMULA`; no `FILTER_EXPRESSION`; no decimal128 cell field on a BUILT-IN cell (an extension cell reads decimals through `DecimalValue` and fuses on its declarations); no extension operator without `FieldInputs` hook; every `margin_aggregations` entry mergeable (extension: declared `Mergeable`) and, for a built-in, non-decimal (an auxiliary rides the same per-record `UpdateRow` walk, so it must be online — declining sends the request to buffered rather than dropping the auxiliary, which would return a margin with the requested figure silently missing). An auxiliary's `MarginReducibility` is deliberately NOT consulted: the classification answers "can this aggregator's margin be derived from its CELLS", a question an auxiliary does not have — it has none, and both paths give it its own row / column / grand accumulator fed record by record, so every auxiliary is `independent` in role whatever its declared class. `GROUP_QUANTILE` implements neither keying interface and is the only grouper that forces buffered.

**Predict reports the decision.** `PredictResult.CrosstabFusable` (`*bool`, nil ⇔ no crosstab) + `CrosstabFusionReasons` (every decline, rule order) come from `descriptor.CrosstabFusion` — the same `crosstabfuse.Decide` over the `ExtensionsSnapshot` + instance feature set — on the defaults-resolved request and the cohort schema; `PredictOptions.DisableCrosstabFusion` (filled from `Options.DisableCrosstabFusion`) answers false with `CrosstabFusionDisabledReason`. `Predict` / `PredictBytes` only, not Compose / ProcessChain validation. A name the feature profile hides answers as never-registered on both arms — the name-keyed `ATTR_FORMULA` / `FILTER_EXPRESSION` bails consult `Facts.Hidden` — so the answer cannot reveal a hidden operator (`TestHiddenOperatorMalformedParity`, `TestDecide_HiddenNameKeyedBails`). **One sanctioned divergence:** a keyable built-in grouper whose factory rejects its params (e.g. `GROUP_DATE` `component:"fortnight"`) — runtime declines (construction fails → buffered → coded error), predict says fusable from the static table; the request errors on either answer. Gates: `TestStreamability_CrosstabFusionPredictMatchesRuntime` (rule parity, both instances), `TestPredict_CrosstabFusableMatchesRuntime` (end to end through the facade, incl. the disable knob).

`Request.Overlays` is explicitly NOT an exclusion. Overlays decorate a finalised response and consume no records, so `RunCrosstabFused` folds them after `state.Finalize()` through the same `processing.applyOverlaysToResponse` hook the buffered exit calls — cells, `Components`, `Overlays` and `Warnings` are byte-identical across arms. `types.OverlayStreamability` is unchanged (every kind still `false`): a post-`Finalize` fold is not an in-pass computation. The surviving reason an overlay-carrying crosstab may still buffer is the CELL-AGGREGATOR arm — `AGG_WELFORD` is non-mergeable, so `OVERLAY_PAIRWISE_WELCH_T` / `OVERLAY_PAIRWISE_TWO_MEANS_Z` (which read its `{n, mean, variance}` triple off `CellComponents`) stay buffered; `TestCrosstabWelfordCell_StaysBufferedWithCorrectOverlays` pins it. `OVERLAY_PAIRWISE_PROP_Z` and `OVERLAY_PAIRWISE_WEIGHTED_TWO_MEANS_Z` (which reads the mergeable cell's `{weighted_mean, m2_weighted, sum_weights, sum_weights_sq}` moments) over an `AGG_WEIGHTED_MEAN` cell fuse.

Multi-key axis routing: `fusedAxisKeyer.derive` returns the cartesian product of each position's key set plus deduped per-depth prefix sets, so one record updates every accumulator the buffered path would touch, exactly once per distinct key at that depth. Fan-out is legal at any axis position, on either or both axes, several positions per axis. Consequence (deliberate, mirrors buffered): margins are NON-ADDITIVE under fan-out — a record selecting 3 labels counts 3× across row margins but once in the grand margin, so row margins do not sum to the grand total.

**Margins follow cell admission (U47 #325).** A record reaches a row, column or grand margin, a `normalize_level` (partial-depth) or `normalize_within` (cross-axis) denominator only if it reached a CELL — BOTH axes resolved in full. Buffered resolves `ownMarginMembership(rowPart, colPart, len(filtered))` once (a nil set = every record resolved that axis, so the common crosstab filters nothing) and narrows each margin / denominator bucket with `admitRecords(bucket, …, nil)` — partitions are still built over `filtered` so data-dependent groupers route exactly as before; fused computes `admitted := rowKeys.ok && colKeys.ok` per record and gates every margin and denominator update on it, while still INTERNING each axis's keys per axis (so both arms emit the same `RowKeys` / `ColumnKeys`, a key with no admitted record carrying an absent margin), and emits a grand margin only when `grandMarginCount > 0`, matching buffered's empty-admitted skip. A record whose deeper axis positions are null therefore no longer feeds a `normalize_level` denominator (pre-U47 both arms gated it on PREFIX depth). Numbers-changing, recorded in `03-embedder-migration.md` ("Changes from U47"). Gates: `TestCrosstab_OwnMarginsFollowCellAdmission` (null-set / empty-set / Include-excluded records change no margin and no normalised cell, every normalize mode, both arms), `TestCrosstab_OwnMarginAdmissionFusedMatchesBuffered`, `TestFusedCrosstab_PartialDepthMarginFollowsCellAdmission`.

Auxiliary margin accumulation (`FusedCrosstabState.rowMarginAux` / `colMarginAux` / `grandMarginAux`, one `auxMarginAccumulator` per declared auxiliary per occupied slot, instance built on first admission) observes a DIFFERENT record admission from the cell's own margins beside it, and that is the point of the slot: a record contributes to an auxiliary only if it contributed to a CELL. Three exclusions follow — a null cell field, an unresolved row key (including one a grouper `Include` excluded, which surfaces as `ErrGrouperKeyNull`), and an unresolved column key. The cell aggregator's own margins share the two axis exclusions since U47 (#325, above) but not the cell-field one — a null cell field still counts as the margin's `n_null`; an auxiliary is metric-scoped. Getting it wrong is SILENT — every number still renders, the base is merely wrong. Slots are allocated only for the margins the spec asks for, and nothing at all when `margin_aggregations` is absent — or when the compute plan drops the figures (`FusedCrosstabState.setCompute` forgets the auxiliaries before `Update`; construction already resolved them against the registry). The figures are accumulated and held; they surface on `Response.Components` (`crosstab.margin_aggregations`, response-components.md) unless a `return` drops them.

Axis-key nullity is per-axis for KEYS only: a record with non-null row key + null col key still interns its row key, but it reached no cell, so (U47 #325) it updates no margin. Cells only land at intersections where both axes resolved. Margins recompute from raw rows so byte-for-byte equivalent to buffered RunCrosstab. Map-valued cell aggregators paired with `normalize != none` are rejected (`PULSE_CROSSTAB_NORMALIZE_MAP_VALUED`). Disable via internal `disableCrosstabFusion` toggle.

Perf: synth 200-field × 100K-row bench ~0.51 × buffered (~47% faster); canonical 1M-row real-cohort bench 2.57s vs buffered crosstab baseline 3.82s (~32% faster). **Quote peak heap, never `B/op`.** The combined fan-out + overlay bench (`BenchmarkCrosstabSetFanoutOverlay`) measures `peak-heap-MB` 8.8× / 18.6× / 20.8× better on fused at 25k / 100k / 400k rows, while `B/op` moves only ~30% — `B/op` is cumulative bytes allocated and cannot see retention, so quoting it alone understates the win by ~20×. `allocs/op` is HIGHER on fused (the fan-out keyer builds a key tuple per fanned key); expected, not a regression. See `skills/crosstab-guide.md` (Fused mergeable path) + `skills/grouper-design.md` (Fused crosstab eligibility).

**Embedder groupers and fusion** (displaced from `skills/grouper-design.md` at U46 E2-S1). An extension grouper opts into the fused crosstab via `extend.StreamingGrouper` or `extend.MultiKeyStreamingGrouper`, returning `extend.ErrGrouperKeyNull` on nulls; without either it stays correct, buffered.

**Labels on axes and overlay keys (U44 #306).** `Service.buildAndApplyLabels` runs after the overlay fold on both arms (fused, buffered, joined) and carries the bindings past `Response.Data` (`internal/service/label_surfaces.go`, `labelPass`): a `replace` binding on an axis field rewrites `Matrix.RowKeys` / `ColumnKeys`, every overlay matrix / series key and its `p_adjusted` / `significant_adjusted` twins and parts, and rebuilds each pairwise PAIR key from the relabelled host key it names (`processing.PairKeyElement`, the one stringifier). Keys are rebuilt into fresh slices (a layer may share the host's key slices, so an in-place rewrite would translate twice), each distinct value goes through the resolver once, and only key TEXT moves — positions and figures never change, so overlay coordinates still address the same host cell (the read-only-sibling rule). A grouped run's `group_key` tuples (tests, post-tests, matrices, Components) follow positionally over the grouper key columns. `augment` cannot ride a matrix axis key and warns `PULSE_LABEL_NOT_APPLIED` (`reason: augment_on_matrix_axis`); a caller binding reaching no surface warns `reason: field_not_in_output`; `Options.AutoLabels` defaults never warn. An `ATTR_PREVIOUS_STATE` output column inherits every default on its state field (`Service.autoLabelDefaults` / `applyAutoLabels` over `prevstate.KeySchema`; a label naming a real schema field gets none), so both axes of a previous-state × state crosstab carry display labels (`TestPreviousState_AutoLabelsCarryToTheOutputColumn`). Gates: `TestCrosstab_LabelsReachAxesAndPairKeys` (both arms, figures equal to the unlabelled run), `TestCrosstab_AugmentOnMatrixAxisWarns`, `TestProcess_LabelNotApplied`, `TestProcess_LabelsReachGroupKeys`, `TestFacet_LabelNotApplied`. Before U44 only `Data` rows were labelled: a matrix crosstab ignored the binding silently.
