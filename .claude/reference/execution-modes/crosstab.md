# Execution modes — crosstab and fused crosstab

Per-topic slice of the execution-modes reference. Index (Mode index + section map): `.claude/reference/execution-modes.md` — load it first, then only the slice(s) your engine work touches.

## Crosstab

`Request.Crosstab`, `Response.Crosstab`. Composes existing groupers + aggregators across a row × column axis grid; reshape, margin recompute, normalization layered on top. Multi-grouper axes recursively partitioned. Margins always recomputed from raw rows for correctness — `AGG_MEDIAN` row margin equals the standalone single-axis median, NOT the median of cell medians. Per-aggregator classification at `AggregationType.MarginReducibility` (`summable` / `mean_reducible` / `independent` / `recompute`; `independent` = the operator keeps its own row/column/grand accumulator, so the margin — a union, not a cell sum — is exact after one pass and the fused gate admits it). `shape: matrix` (default) populates `Response.Crosstab.Matrix`; `shape: long` emits tuple rows on `Response.Data` with margin rows tagged `_margin=row|column|grand`. Inherently buffered except `shape=long` + no margins + `normalize=none`.

Normalization layering: `normalize_level` truncates the same axis as `normalize`; `normalize_within` fixes a prefix of the OPPOSITE axis. Both compose.

Auxiliary margin-only aggregations (`margin_aggregations`) are computed by `processing.(*Processor).computeAuxMargins` (`internal/processing/crosstab_margin_agg.go`) alongside the cell aggregator's own three margin blocks, and MUST match what the fused walk accumulates for the same request — dispatch picks the arm on request shape and nothing in `Response` reports which ran. The admission rule is the same one stated under Fused crosstab: a record contributes to an auxiliary only if it contributed to a CELL, so a null cell field and an axis key an `Include` excluded are absent from every auxiliary slot while the cell's own margin loops beside them still count both. The buffered implementation resolves each axis's membership ONCE into pointer sets and then walks each margin slot on its own axis — deliberately NOT the `(rkey, ckey)` cell buckets, which are admitted-by-construction but would fold a record into a ROW auxiliary once per COLUMN it landed in, M times under a `GROUP_SET_PER_ELEMENT` fan-out, where fused folds it once per distinct row key. Each slot's admitted subset is shared across the auxiliaries in it and rides `runCellAggregation`, so the `{n, n_null}` floor is over ADMITTED records and decimal128 dispatch comes for free; a slot admitting nothing carries no figure at all, mirroring the fused path's unconstructed accumulator. An auxiliary naming an unknown operator is refused up front, matching `NewFusedCrosstabState` — AHEAD of the compute plan's `AuxMargins` gate, past which `computeAuxMargins` returns nil and evaluates nothing when the figures are not computed. Partial-depth and cross-axis margins get no auxiliary on either path: those are normalization denominators, and an auxiliary is never a denominator. `TestCrosstab_BufferedAuxMarginMatchesFused` drives one request down both arms.

A crosstab carrying a `JoinSpec` runs over the joined row stream, always buffered — see Pushdown hash join (Crosstab over a join). Relocated from `skills/crosstab-guide.md` (Fused mergeable path) at U46 E4-S1 to free budget: a joined crosstab runs buffered over the JOINED rows: axes / cell may name `as`-prefixed right fields; an unmatched left row is counted nowhere; a 1:N match counts once per joined row (`join-design`).

**Data-dependent axis groupers: `params.fit` (U46 E4-S1, #428).** `GROUP_QUANTILE` and `GROUP_KMEANS` take `params.fit` `"global"` (default) or `"within"`, read ONCE by `internal/groupfit` (`Parse` / `IsWithin`; the runtime factories `newQuantileGrouper` / `newKMeansGrouper` and predict's `validateGroupFitParams` both call it, so an unknown value is refused `PROCESSING_CONFIG` with identical message and details `{type, param, value, valid, reason: "bad_fit"}`). Under `global` the buffered `RunCrosstab` fits the slot once over `filtered` in `fitWholeSetAxes` (`wholeSetAxis`, keyed by slot) and `PartitionByAxis` only ROUTES records by that assignment at every call site — nested position, the per-row-bucket column partition, and the normalisation denominators — so the crosstab bands equal plain `groups` bands. Under `within` the slot is not whole-set and `PartitionByAxis` refits it on each outer bucket's records (rows, then columns: a column position's outer segment is the full row tuple plus its column prefix) — the pre-U46 crosstab quantile behaviour, now opt-in (behaviour break; migration row in `03-embedder-migration.md`). Plain `groups` mirrors it in `partitionComposite` → `partitionCompositeWithin` (prefix buckets outer → inner, a fresh grouper instance per bucket for a `within` position; the whole-set fit still sources that slot's Components, unstamped warnings and key order), and every Compose slot runs the same processor path. **Refit warnings (E4-S5).** Every warning a `within` refit raises (today `GROUP_KMEANS`'s `PULSE_MATRIX_NOT_CONVERGED`; quantile cuts raise none) reaches `Response.Warnings` ONE PER REFIT AND CODE — the grouped-tests per-group convention, never collapsed, since each bucket stops at its own iteration count — through `refitWarnings` (`grouper.go`): details gain `group_key` (the outer segment as an `AxisKey`), the message a `(fit within group [...])` suffix. Plain groups collect them in `partitionCompositeWithin` (`compositePartition.RefitWarnings`); the crosstab collects only from its two CELL partitions (`partitionByAxis` with a warning sink: rows over `filtered`, then columns per row bucket under the row tuple), so the column-key, margin, normalisation and component passes refit silently and each outer bucket reports once. `fitWholeSetAxes` also fits a `within` position whole-set (`wholeSetAxis.route = false`: Components plus the unstamped warning plain groups emit) and routes an outermost `within` like `global`, so both paths raise the same set; `global` and absent `fit` are byte-identical. The outermost composite position (`groups[0]`, crosstab `rows[0]`) has no outer segment: `within` there is a no-op, never refused. The fused path never carries either grouper (`crosstabfuse` keyability table), so `fit` never moves `crosstab_fusable` / `crosstab_fusion_reasons`. Gate: `TestGroupFit_CrossPath` (plain × nested rows × column axis × Compose, both values, quantile and k-means; `within` equals the per-region runs), `TestGroupFit_OutermostWithinIsNoOp`, `TestGroupFit_RefusedIdentically`, `TestGroupFit_RefitWarnings` (one per outer bucket, same set on plain × both crosstab axes × normalised crosstab × Compose), `TestPredict_GroupFitParams`.

Buffered record set automatically projected via `service.applyCrosstabProjection` (extends `processing.NeededFields` to walk `Crosstab.Rows/Columns/Cell` + `req.Labels[].Field` + `AGG_WEIGHTED_MEAN/RATIO` Cell.Params); wide-cohort crosstab cost is `O(|referenced|)` not `O(|schema|)`; forced on regardless of `opts.DisableProjection`. Capability: `Manifest.Crosstab`. Predict gate: `descriptor.validateCrosstab`. See `skills/crosstab-guide.md`.

**Resource limits on the crosstab arms (U19).** `MaxCrosstabCells` bounds the grid, rows × columns of observed composite axis keys, and a breach raises `PULSE_LIMIT_EXCEEDED` (`limits.Check`) with no partial result. The buffered arm (`RunCrosstab`) checks once, right after the two `PartitionByAxis` calls and BEFORE the `rows*cols` per-cell map preallocations. The fused arm checks in `internRowKey` / `internColKey` on the PROSPECTIVE product (`(len(rowKeys)+1)*len(colKeys)` / `len(rowKeys)*(len(colKeys)+1)`) before any dense slice grows; `RunCrosstabFused` installs the processor's limits through `FusedCrosstabState.setLimits`, and a state built without them enforces nothing. Both arms see the same final grid, so the same request trips with the same `{code, limit, configured}` on either; `observed` is the final grid on buffered and the first product past the limit on fused. The joined crosstab is buffered, so it trips in `RunCrosstab` over the joined rows. Predict grades the Cartesian upper bound `EstimateCrosstabCells` (each axis the product of its positions' `EstimateGroups` bounds, clamped by the header record count unless a position fans out) as `possible` only — so the pre-flight never refuses on it. Gates: `TestMaxCrosstabCells_Arms`, `TestLimits_MaxCrosstabCells_BothArms`, `TestLimits_MaxCrosstabCells_JoinedCrosstab`, `TestEstimateCrosstabCells`.

## Fused crosstab

`processing.CanFuseCrosstab` (a thin adapter over the shared rule `crosstabfuse.Decide` in the no-execute leaf `internal/crosstabfuse`), `processing.FusedCrosstabState`, `processing.StreamableGrouper.KeyFor`, `processing.MultiKeyStreamingGrouper.KeysForRow`. In-decode streaming alternative to the buffered Crosstab orchestrator. When the gate accepts, `service.processCrosstab` short-circuits `materializeRecords` + recursive `PartitionByAxis` and drives a single streaming pass that interns row/col composite axis keys on first sight and folds each filter-passing record into the matching cell / row-margin / column-margin / grand-margin / cross-axis-margin online aggregator. Memory drops from `O(filtered records)` to `O(cells + margins)`.

Gate composition (`CanFuseCrosstab`): mergeable + non-recompute scalar cell aggregator (both read through the registry — `IsMergeable` / `AggregatorMarginReducibility` — so an extension cell answers with its DECLARED `Mergeable` / `MarginReducibility`); every row/col grouper is KEYABLE — a built-in per the static `crosstabfuse` keyability table (pinned against the constructed instances by `TestBuiltinGrouperKeyableMatchesRegistry`), an extension per its DECLARED `Streamable || FansOut`; the runtime facts adapter additionally declines a grouper whose factory fails to construct — and keying means one of the two per-record interfaces: `StreamableGrouper.KeyFor` (one bucket per record: CATEGORY/RANGE/ROUNDED/DATE/SET_VALUE — `GROUP_DATE` is admitted here even though `GroupType.Streamable()` is false at the Process layer) or `MultiKeyStreamingGrouper.KeysForRow` (N buckets per record: `GROUP_SET_PER_ELEMENT`); no tests; no features; no two-pass attribute (the built-in set or a `two_pass` extension — the fused walk never runs a `PrePass`, so admitting one values every row against empty stats; `AssertCanFuse` echoes it); no `ATTR_FORMULA`; no `FILTER_EXPRESSION`; no decimal128 cell field on a BUILT-IN cell (an extension cell reads decimals through `DecimalValue` and fuses on its declarations); no extension operator without `FieldInputs` hook; every `margin_aggregations` entry mergeable (extension: declared `Mergeable`) and, for a built-in, non-decimal (an auxiliary rides the same per-record `UpdateRow` walk, so it must be online — declining sends the request to buffered rather than dropping the auxiliary, which would return a margin with the requested figure silently missing). An auxiliary's `MarginReducibility` is deliberately NOT consulted: the classification answers "can this aggregator's margin be derived from its CELLS", a question an auxiliary does not have — it has none, and both paths give it its own row / column / grand accumulator fed record by record, so every auxiliary is `independent` in role whatever its declared class. `GROUP_QUANTILE` implements neither keying interface and is the only grouper that forces buffered.

**Predict reports the decision.** `PredictResult.CrosstabFusable` (`*bool`, nil ⇔ no crosstab) + `CrosstabFusionReasons` (every decline, rule order) come from `descriptor.CrosstabFusion` — the same `crosstabfuse.Decide` over the `ExtensionsSnapshot` + instance feature set — on the defaults-resolved request and the cohort schema; `PredictOptions.DisableCrosstabFusion` (filled from `Options.DisableCrosstabFusion`) answers false with `CrosstabFusionDisabledReason`. `Predict` / `PredictBytes` only, not Compose / ProcessChain validation. A name the feature profile hides answers as never-registered on both arms — the name-keyed `ATTR_FORMULA` / `FILTER_EXPRESSION` bails consult `Facts.Hidden` — so the answer cannot reveal a hidden operator (`TestHiddenOperatorMalformedParity`, `TestDecide_HiddenNameKeyedBails`). **One sanctioned divergence:** a keyable built-in grouper whose factory rejects its params (e.g. `GROUP_DATE` `component:"fortnight"`) — runtime declines (construction fails → buffered → coded error), predict says fusable from the static table; the request errors on either answer. Gates: `TestStreamability_CrosstabFusionPredictMatchesRuntime` (rule parity, both instances), `TestPredict_CrosstabFusableMatchesRuntime` (end to end through the facade, incl. the disable knob).

`Request.Overlays` is explicitly NOT an exclusion. Overlays decorate a finalised response and consume no records, so `RunCrosstabFused` folds them after `state.Finalize()` through the same `processing.applyOverlaysToResponse` hook the buffered exit calls — cells, `Components`, `Overlays` and `Warnings` are byte-identical across arms. `types.OverlayStreamability` is unchanged (every kind still `false`): a post-`Finalize` fold is not an in-pass computation. The surviving reason an overlay-carrying crosstab may still buffer is the CELL-AGGREGATOR arm — `AGG_WELFORD` is non-mergeable, so `OVERLAY_PAIRWISE_WELCH_T` / `OVERLAY_PAIRWISE_TWO_MEANS_Z` (which read its `{n, mean, variance}` triple off `CellComponents`) stay buffered; `TestCrosstabWelfordCell_StaysBufferedWithCorrectOverlays` pins it. `OVERLAY_PAIRWISE_PROP_Z` and `OVERLAY_PAIRWISE_WEIGHTED_TWO_MEANS_Z` (which reads the mergeable cell's `{weighted_mean, m2_weighted, sum_weights, sum_weights_sq}` moments) over an `AGG_WEIGHTED_MEAN` cell fuse.

Multi-key axis routing: `fusedAxisKeyer.derive` returns the cartesian product of each position's key set plus deduped per-depth prefix sets, so one record updates every accumulator the buffered path would touch, exactly once per distinct key at that depth. Fan-out is legal at any axis position, on either or both axes, several positions per axis. Consequence (deliberate, mirrors buffered): margins are NON-ADDITIVE under fan-out — a record selecting 3 labels counts 3× across row margins but once in the grand margin, so row margins do not sum to the grand total.

`normalize_level` denominators gate on PREFIX depth, not full-axis resolution: the buffered denominator is `PartitionByAxis(spec.Rows[:level+1], filtered)`, which never looks past `level`, so a record whose DEEPER axis positions are null still feeds it. Fused now matches. Releases before this alignment returned a different `normalize_level` denominator on the fused arm whenever a nullable grouper sat ahead of the level — a numbers-changing fix, not a no-op.

Auxiliary margin accumulation (`FusedCrosstabState.rowMarginAux` / `colMarginAux` / `grandMarginAux`, one `auxMarginAccumulator` per declared auxiliary per occupied slot, instance built on first admission) observes a DIFFERENT record admission from the cell's own margins beside it, and that is the point of the slot: a record contributes to an auxiliary only if it contributed to a CELL. Three exclusions follow — a null cell field, an unresolved row key (including one a grouper `Include` excluded, which surfaces as `ErrGrouperKeyNull`), and an unresolved column key. The cell aggregator's own margins are untouched and still count every filter-passing record with a non-null axis key on that axis: measured, a `rows=[brand]` crosstab returns byte-identical column margins with a two-brand `Include` and with none at all. Reusing that for an auxiliary would make the figure cohort-wide and metric-agnostic. Getting it wrong is SILENT — every number still renders, the base is merely wrong. Slots are allocated only for the margins the spec asks for, and nothing at all when `margin_aggregations` is absent — or when the compute plan drops the figures (`FusedCrosstabState.setCompute` forgets the auxiliaries before `Update`; construction already resolved them against the registry). The figures are accumulated and held; they surface on `Response.Components` (`crosstab.margin_aggregations`, response-components.md) unless a `return` drops them.

Axis-key nullity is per-axis: a record with non-null row key + null col key still updates the row margin and the grand margin. Cells only land at intersections where both axes resolved. Margins recompute from raw rows so byte-for-byte equivalent to buffered RunCrosstab. Map-valued cell aggregators paired with `normalize != none` are rejected (`PULSE_CROSSTAB_NORMALIZE_MAP_VALUED`). Disable via internal `disableCrosstabFusion` toggle.

Perf: synth 200-field × 100K-row bench ~0.51 × buffered (~47% faster); canonical 1M-row real-cohort bench 2.57s vs buffered crosstab baseline 3.82s (~32% faster). **Quote peak heap, never `B/op`.** The combined fan-out + overlay bench (`BenchmarkCrosstabSetFanoutOverlay`) measures `peak-heap-MB` 8.8× / 18.6× / 20.8× better on fused at 25k / 100k / 400k rows, while `B/op` moves only ~30% — `B/op` is cumulative bytes allocated and cannot see retention, so quoting it alone understates the win by ~20×. `allocs/op` is HIGHER on fused (the fan-out keyer builds a key tuple per fanned key); expected, not a regression. See `skills/crosstab-guide.md` (Fused mergeable path) + `skills/grouper-design.md` (Fused crosstab eligibility).

**Embedder groupers and fusion** (displaced from `skills/grouper-design.md` at U46 E2-S1). An extension grouper opts into the fused crosstab via `extend.StreamingGrouper` or `extend.MultiKeyStreamingGrouper`, returning `extend.ErrGrouperKeyNull` on nulls; without either it stays correct, buffered.
