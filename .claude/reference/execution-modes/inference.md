# Execution modes — multiplicity and grouped tier-1 tests

Per-topic slice of the execution-modes reference. Index (Mode index + section map): `.claude/reference/execution-modes.md` — load it first, then only the slice(s) your engine work touches.

## Multiplicity

`multiplicity {method, family, alpha}` (`types.Multiplicity`; slots on `Request`, `Test`, `OverlaySpec`, `MatrixSpec`, `ComposeOverlaySpec`, `ComposedRequest`; engine default `Options.DefaultMultiplicity`) corrects the p-values of tests, post-tests, inferential overlays and inferential correlation matrices. Methods `none|bonferroni|holm|bh|by` live in the leaf `internal/processing/multiplicity` (pure `[]float64 → []float64`, R `p.adjust` parity, BY to 1e-13, NaN excluded from `m`, ties by original position, capped at 1). Families `layer|row|column|request|compose|matrix`. ONE resolver, `ResolveMultiplicity` / `ResolveComposeMultiplicity` / `ResolveFacetMultiplicity` (`internal/descriptor/multiplicity_resolve.go`, schema-free), serves runtime AND predict, so refusals are identical (`PULSE_MULTIPLICITY_INVALID` / `_CONFLICT`). Precedence per key: slot → request → `ComposedRequest` → `Options` → none; an inherited family a surface does not offer takes the surface default, only an explicit one is refused; `row` / `column` need a MATRIX payload kind, `compose` exists only inside Compose, `request` is refused on a Compose-host overlay and `request` / `compose` on a facet overlay; an explicit block on a descriptive overlay is accepted and inert; an explicit non-`none` block on `TEST_TUKEY_HSD` is refused, an inherited one skipped. A matrix spec (U28 E3-S4) offers `matrix` (default: one family per result — spec × group bucket — over its distinct pairs, the off-diagonal upper triangle, m = k(k − 1)/2) and `request` (pooled with the request's other members); `layer` / `row` / `column` / `compose` on it are refused (`compose` inherited falls back to `matrix`), `matrix` off it is refused, a block on a matrix type outside `vectors.InferenceTypes` is refused (key `type`); its own block implies `params.inference`, an inherited one reaches only a spec already under it.

**Wire outputs (relocated from CLAUDE.md "Output Format Contract" at U18 E1-S1).** An absent block is byte-identical and `format_version` stays `"1.1"`. The correction adds BESIDE the raw p, which never moves: `TestResult` / `OverlaySummary` gain `p_adjusted` + `significant_adjusted`, `OverlayPayload` gains the matching `p_adjusted` / `significant_adjusted` matrices, and each corrected surface echoes `multiplicity {method, family, alpha, m, excluded}` (`types.AppliedMultiplicity`). A NaN p is excluded from `m`, its `p_adjusted` is `null`, and the echo's `excluded` counts the family's NaN members (additive `omitempty`: absent when every member is defined; a `row` / `column` echo sums it over its families like `m`).

Fold sites (raw p never written; every output additive `omitempty`):

- **Process** — `foldRequestMultiplicity` (`internal/service/multiplicity_fold.go`) after `processDispatch` returns, so every arm (serial buffered / streaming, fused and buffered crosstab, join, shard, parallel decode, `ProcessStream`) corrects in one place. Overlay half: `multiplicity_overlay.go`, the `overlayPSites` table (one entry per `Inferential` kind, `TestOverlayPSites_CoverEveryInferentialKind`). Matrix half: `multiplicity_matrix.go` (`collectMatrixResultSites`, a `MatrixValues`-shaped writer: reads `auxiliary.p` in `full` or `upper`, writes `auxiliary.p_adjusted` / `significant_adjusted` + `MatrixResult.Multiplicity`; results pair with their slot by `ResolvedMultiplicity.Name`). **Collection order is fixed: tests → post-tests → overlay layers → matrices**, and the fold reads `Response.Matrices` exactly as the dispatch arm finished it — the MATRIX_RESULT overlay pass (U28 E4-S1, `processing.ApplyMatrixResultOverlays`) runs AFTER `foldRequestMultiplicity` (a Compose slot's after `foldComposeMultiplicity`), so it sees `p_adjusted` — the Overlays section's "MATRIX_RESULT host" bullet. Compose slots and chain stage 0 fold their matrices in their own (slot / stage) families; later chain stages carry no matrices (`StageMatrixRefusal`).
- **Compose** — `foldComposeMultiplicity`, run by BOTH `compose` and `composeParallel` after the slots and the Compose-host overlays finish; collection is slot-index then spec order, never completion order, so serial == parallel byte for byte. Non-compose families stay per slot (scope `requests[i]/`), `compose` pools every slot and Compose-host layer. `--stream` emits slot rows only (no corrections); a failed slot errors the batch before the barrier, so a `compose` family never folds over partial members.
- **ProcessChain** — each stage folds its own plan (stage 0 in `Service.process`, later stages in `runChainStage`); one `request` family per stage, never spanning stages; the whole-chain `ChainOverlaySpec` has no slot. The v1 stage gate refuses tests and crosstab, so no gate-passing stage reaches a p-site yet.
- **Facet** — `applyFacetOverlays` folds each spec's layers alone under `ResolveFacetMultiplicity`.
- **Excluded members still fold** — a `return` that excludes overlays skips every layer EXCEPT a family member (`multiplicityVetoes`; Compose-host layers whole under any member), so `m` and every kept `p_adjusted` match the full run (`TestReturnSkipsOverlays_MultiplicityVeto`). Tests / post-tests reuse it per entry (E3-S2, `TestReturnSkipsTests_MultiplicityVeto`); regressions are outside the pool and skip whole.

`row` / `column` are coordinate-based on the layer's own MATRIX (pairwise rows are the compared groups); a panel cell's vector elements each join their cell's family; the layer echo carries `m_per`. Extension `TEST_*` operators join like built-ins. An extension `MAT_*` operator joins only by declaring `MatrixOpRegistration.PValues` (U30 E1-S3), the auxiliary key of its per-cell p matrix: it is then a member under the spec's, the request's or the instance block (it always emits its p-values, so no `params.inference`), the fold reads `auxiliary.<PValues>` and writes `<PValues>_adjusted` / `significant_adjusted` (`ResolvedMultiplicity.PValueKey`, `descx.MatrixAdjustedKeys`), and predict counts its k(k − 1)/2 pairs; without `PValues` a spec-level block is refused like a non-inferential built-in. Feature `capability:multiplicity`. Skill: `skills/multiplicity-correction.md`; update-demand row: Multiplicity.

## Grouped tier-1 tests

U46 E3-S1. With `groups` set, every `tests[]` entry runs once per COMPOSITE group key — the buckets the grouped `Response.Data` rows are, from the same `Grouper.Group` / `partitionComposite` partition (a fan-out grouper adds a record to several buckets). `processGrouped` folds each bucket's records, in record order, into that bucket's own instances (`internal/processing/test_grouped.go`: `groupedRowTests` minted from `planRowTests` plans; `bucketFolds` carries them beside the grouped matrices), so a group's result is bit-for-bit the result of the same test over an ungrouped run filtered to that group (`TestGroupedTests_EqualFilteredSingleGroupRuns`, weighted and unweighted, every arm that admits tests).

- **Wire.** `Response.Tests` is flat: tests x groups entries, TEST-MAJOR, groups in the FINAL `Data` row order (Sort included), each carrying `TestResult.GroupKey` (`group_key`: the bucket's per-grouper tuple, one element for one grouper — the `MatrixResult.GroupKey` shape). A test the `return` plan skips is nil at each of its positions, so entry k always belongs to `Request.Tests[k / groups]` (`internal/groupedtests.SpecIndex`, read by the multiplicity fold's `collectTestSites` and explain). Ungrouped requests are byte-identical; `format_version` stays `"1.1"`.
- **Arm.** Buffered only — `canStream` / predict's `streamableTestReasons` route tests + groups buffered ("grouped tier-1 tests run once per group via the buffered path"), as they did before; the merge gate already refuses tests, so the shard and parallel-decode arms run serially.
- **Refusal.** A test whose `split_by` (`PULSE_TEST_SPLIT_GROUPS_LT_2`) or chi-square / Fisher `rows` / `cols` (`PULSE_TEST_CONTINGENCY_DEGENERATE`) names a grouper field is refused by ONE helper, `groupedtests.SplitRefusal`, on predict (`validateTests`) and runtime (`buildGroupedRowTests`), Details `{index, type, slot, field, groups, reason: "split_is_grouper"}`.
- **Sparse groups.** A group whose `Finalize` refuses with a data-dependent code (`sparseTestCodes`: `_SPLIT_GROUPS_LT_2`, `_INSUFFICIENT_N`, `_VARIANCE_ZERO`, `_CONTINGENCY_DEGENERATE`, `_CORRELATION_UNDEFINED`) gets a result with NaN (`null`) `statistic` / `p_value`, the test's alpha, the refusal on `warnings`, plus one Response warning under that code with the refusal's Details + `{test, type, index, group_key}`; the other groups proceed. The NaN p is excluded from `m` by the existing rule. An ungrouped run still errors.
- **Cost.** Predict counts tests x `EstimateGroups` p-values (`countPValues`; dictionary basis, or one per test as a lower bound when a grouper's keys depend on the data), so `PULSE_ADVISORY_MANY_TESTS` reads the grouped total; `RequestLimitFindings` grades `MaxGroups` on tests x groups and the runtime's `admit` refuses the observed product `PULSE_LIMIT_EXCEEDED` before any bucket folds.
- **Weights.** `applyLowNEff` runs over the flat per-bucket entries: one `PULSE_WEIGHT_LOW_NEFF` per short group per bucket, `details.group_key` naming the bucket (beside a split test's `group`).
- **Multiplicity.** `collectTestSites` pairs results with slots by `SpecIndex`, so one `request` family pools every (test x group) and (post-test x partition) p-value; a sparse group's or partition's NaN p is left out of `m` and counted in the echo's `excluded` (`TestGroupedPostTests_OneFamily`: BH and Holm against a hand-assembled family). The plan stays slot-aligned — membership, method and family are per slot, the fan-out lives in the results — and predict's `p_values` counts tests x groups plus post-tests x partitions.

**Partitioned post-tests (U46 E3-S2).** Over two or more groupers every `post_tests[]` entry runs once per PARTITION of the final `Data` rows — key equality on the leading group key columns (`seriespartition.RowKeys` / `Partition`), every key but the last by default, or the leading prefix its `params.partition_by` names (`[]` = one run over every row, the pre-U46 walk). One reading, `groupedtests.PostTestDepth`, serves predict (`validateTests`, `countPValues`, the return-size model) and the runtime (`runPostTests` → `runPartitionedPostTests`); `WithoutPartition` strips the key before a factory decodes `params`. Every post-test of a request must resolve to ONE depth (`PULSE_TEST_PARTITION_INVALID` `mixed_depth`), so `Response.PostTests` is flat: post-tests x partitions, TEST-MAJOR, partitions in first-appearance `Data` order (a `sort` reorders rows inside a partition, which reorders an order-sensitive sum), each result's `group_key` the partition key; a `return`-skipped post-test is nil at each position. A post-test whose `split_by` / `rows` / `cols` names a partition key is refused (`split_is_partition_key`); a sparse partition gets null statistics plus a warning naming its `group_key`. Crosstab post-tests (cell rows) never partition. Arms: the buffered tail and the streaming grouped tail (`GroupedTail.PostTests` returns the warnings too); the merge gate still refuses post-tests on the parallel reducers.
