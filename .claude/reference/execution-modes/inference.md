# Execution modes — multiplicity and grouped tier-1 tests

Per-topic slice of the execution-modes reference. Index (Mode index + section map): `.claude/reference/execution-modes.md` — load it first, then only the slice(s) your engine work touches.

## Multiplicity

`multiplicity {method, family, alpha}` (`types.Multiplicity`; grep the type for the slots that carry it, plus `types.RegressionMultiplicity` — the same keys + `coefficients` — on `RegressionSpec`; engine default `Options.DefaultMultiplicity`) corrects the p-values of tests, post-tests, inferential overlays, inferential correlation matrices and member regression coefficients.

- **Methods** `none|bonferroni|holm|bh|by` live in the leaf `internal/processing/multiplicity` (pure `[]float64 → []float64`, R `p.adjust` parity, BY to 1e-13, NaN excluded from `m`, ties by original position, capped at 1). **Families** `layer|row|column|request|compose|matrix`.
- **One resolver** (`internal/descriptor/multiplicity_resolve.go`, schema-free) serves runtime AND predict, so refusals are identical (`PULSE_MULTIPLICITY_INVALID` / `_CONFLICT`; `TestMultiplicity_RefusalsMatchPredict`).
- **Precedence per key:** slot → request → `ComposedRequest` → `Options` → none. An inherited family a surface does not offer takes the surface default; only an explicit one is refused. `row` / `column` need a MATRIX payload kind; `compose` exists only inside Compose; `request` is refused on a Compose-host overlay, and `request` / `compose` on a facet overlay. An explicit block on a descriptive overlay is accepted and inert; an explicit non-`none` block on `TEST_TUKEY_HSD` is refused, an inherited one skipped.
- **Matrix spec.** Offers `matrix` (default: one family per result — spec × group bucket — over its distinct pairs, the off-diagonal upper triangle, m = k(k − 1)/2) and `request` (pooled with the request's other members). `layer` / `row` / `column` / `compose` are refused (`compose` inherited falls back to `matrix`); `matrix` off a matrix spec is refused; a block on a matrix type outside `vectors.InferenceTypes` is refused (key `type`). Its own block implies `params.inference`; an inherited one reaches only a spec already under it.
- **Regression.** Joins ONLY through its own block — an inherited block never reaches a block-less regression (byte-identical), though it fills the own block's empty keys. Offers `request` (default) and `compose` (inside Compose); `alpha` drives `significant_adjusted` (default 0.05). `coefficients` must each name a predictor or `(intercept)`, once (`key: coefficients`), defaulting to every predictor. A non-`none` method on `REG_BAYES_LINEAR` is refused (`key: method`).

**Wire outputs.** An absent block is byte-identical and `format_version` stays `"1.1"`. The correction adds BESIDE the raw p, which never moves: `TestResult` / `OverlaySummary` gain `p_adjusted` + `significant_adjusted`, `OverlayPayload` gains the matching matrices, and each corrected surface echoes `multiplicity {method, family, alpha, m, excluded}` (`types.AppliedMultiplicity`). A NaN p is excluded from `m`, its `p_adjusted` is `null`, and `excluded` counts the family's NaN members (`omitempty`: absent when every member is defined; a `row` / `column` echo sums it over its families like `m`).

Fold sites (raw p never written; every output additive `omitempty`):

- **Process** — `foldRequestMultiplicity` (`internal/service/multiplicity_fold.go`) runs after dispatch returns, so every arm corrects in one place. The overlay half reads the `overlayPSites` table (one entry per `Inferential` kind, `TestOverlayPSites_CoverEveryInferentialKind`); the matrix half reads `auxiliary.p` and writes `auxiliary.p_adjusted` / `significant_adjusted` + `MatrixResult.Multiplicity`; the regression half files one site per member coefficient (a default member without a p-value is skipped; an explicit one stays as NaN, excluded from `m`). **Collection order is fixed: tests → post-tests → overlay layers → matrices → regressions.** The MATRIX_RESULT overlay pass runs AFTER the fold, so it sees `p_adjusted` (see the Overlays "MATRIX_RESULT host" bullet). Compose slots and chain stage 0 fold their matrices in their own families; later chain stages carry no matrices.
- **Compose** — `foldComposeMultiplicity`, run by BOTH orchestrators after the slots and Compose-host overlays finish. Collection is slot-index then spec order, never completion order, so serial == parallel byte for byte. Non-compose families stay per slot (scope `requests[i]/`); `compose` pools every slot and Compose-host layer. `--stream` emits slot rows only (no corrections); a failed slot errors the batch before the barrier, so a `compose` family never folds over partial members.
- **ProcessChain** — each stage folds its own plan; one `request` family per stage, never spanning stages; the whole-chain `ChainOverlaySpec` has no slot. The stage gate refuses tests and crosstab, so no gate-passing stage reaches a p-site.
- **Facet** — `applyFacetOverlays` folds each spec's layers alone under `ResolveFacetMultiplicity`.
- **Excluded members still fold.** A `return` that excludes overlays, tests or regressions still computes every family member (`multiplicityVetoes`; Compose-host layers whole under any member; a member regression keeps the whole regressions slot computed), so `m` and every kept `p_adjusted` match the full run.

`row` / `column` are coordinate-based on the layer's own MATRIX (pairwise rows are the compared groups); a panel cell's vector elements each join their cell's family; the layer echo carries `m_per`. Extension `TEST_*` operators join like built-ins. **An extension `MAT_*` operator joins only by declaring `MatrixOpRegistration.PValues`**, the auxiliary key of its per-cell p matrix: it is then a member under any block (it always emits p-values, so no `params.inference`), the fold reads `auxiliary.<PValues>` and writes `<PValues>_adjusted` / `significant_adjusted`, and predict counts its k(k − 1)/2 pairs; without `PValues` a spec-level block is refused like a non-inferential built-in. Feature `capability:multiplicity`. Skill: `skills/multiplicity-correction.md`; update-demand row: Multiplicity.

## Grouped tier-1 tests

With `groups` set, every `tests[]` entry runs once per COMPOSITE group key — the buckets the grouped `Response.Data` rows are, from the same partition (a fan-out grouper adds a record to several buckets). Each bucket's records fold, in record order, into that bucket's own instances (`internal/processing/test_grouped.go`), so a group's result is bit-for-bit the same test over an ungrouped run filtered to that group (`TestGroupedTests_EqualFilteredSingleGroupRuns`).

- **Wire.** `Response.Tests` is flat: tests × groups entries, TEST-MAJOR, groups in the FINAL `Data` row order (Sort included), each carrying `TestResult.GroupKey` (`group_key`: the bucket's per-grouper tuple — the `MatrixResult.GroupKey` shape). A test the `return` plan skips is nil at each of its positions, so entry k always belongs to `Request.Tests[k / groups]` (`groupedtests.SpecIndex`). Ungrouped requests are byte-identical.
- **Arm.** Buffered only — streaming routing and predict route tests + groups buffered; the merge gate refuses tests, so the shard and parallel-decode arms run serially.
- **Refusal.** A test whose `split_by` (`PULSE_TEST_SPLIT_GROUPS_LT_2`) or chi-square / Fisher `rows` / `cols` (`PULSE_TEST_CONTINGENCY_DEGENERATE`) names a grouper field is refused by ONE helper, `groupedtests.SplitRefusal`, on predict and runtime; Details `{index, type, slot, field, groups, reason: "split_is_grouper"}`.
- **Sparse groups.** A group whose `Finalize` refuses with a data-dependent code (`sparseTestCodes` is the list) gets a result with NaN (`null`) `statistic` / `p_value`, the test's alpha, the refusal on `warnings`, plus one Response warning under that code with the refusal's Details + `{test, type, index, group_key}`; the other groups proceed. An ungrouped run still errors.
- **Cost.** Predict counts tests × `EstimateGroups` p-values (one per test as a lower bound when a grouper's keys depend on the data), so `PULSE_ADVISORY_MANY_TESTS` reads the grouped total; `MaxGroups` is graded on tests × groups and the runtime refuses the observed product `PULSE_LIMIT_EXCEEDED` before any bucket folds.
- **Weights.** One `PULSE_WEIGHT_LOW_NEFF` per short group per bucket, `details.group_key` naming the bucket.
- **Multiplicity.** Results pair with slots by `SpecIndex`, so one `request` family pools every (test × group) and (post-test × partition) p-value; a sparse group's NaN p is left out of `m` and counted in `excluded`. The plan stays slot-aligned — the fan-out lives in the results — and predict's `p_values` counts tests × groups plus post-tests × partitions.

**Partitioned post-tests.** Over two or more groupers every `post_tests[]` entry runs once per PARTITION of the final `Data` rows — key equality on the leading group key columns, every key but the last by default, or the prefix its `params.partition_by` names (`[]` = one run over every row). One reading, `groupedtests.PostTestDepth`, serves predict and runtime. Every post-test of a request must resolve to ONE depth (`PULSE_TEST_PARTITION_INVALID` `mixed_depth`), so `Response.PostTests` is flat: post-tests × partitions, TEST-MAJOR, partitions in first-appearance `Data` order (a `sort` reorders rows inside a partition, which reorders an order-sensitive sum), each result's `group_key` the partition key; a `return`-skipped post-test is nil at each position. A post-test whose `split_by` / `rows` / `cols` names a partition key is refused (`split_is_partition_key`); a sparse partition gets null statistics plus a warning naming its `group_key`. Crosstab post-tests (cell rows) never partition. Arms: the buffered tail and the streaming grouped tail; the merge gate refuses post-tests on the parallel reducers.

- **A null cell is dropped listwise:** a row holding a null (a present nil — a `WIN_LAG` leading row, a nullable field passed through) in any column a post-test reads leaves that test, as R's default `na.action`; `details.n` is the n used.
- **A NaN cell is undefined, not dropped.** A cell holding an undefined figure (an aggregate over no value, or an unanswered vector element) stays in, so the test's statistic and p-value are NaN (`null` on the wire) and the p is left out of `m`. To test the rest, drop the group upstream with a filter.
