## Overlays — paired-flow kinds: `OVERLAY_MARKOV`, `OVERLAY_SYMMETRY`, `OVERLAY_RETENTION`

Continues the `## Overlays` section of `.claude/reference/execution-modes/overlays.md` via `.claude/reference/execution-modes/overlays-matrix-kinds.md` (split out at U66 E10-S1 when that slice reached its ceiling). All three read a from-state (rows) × to-state (columns) crosstab; the shared Crosstab spec refusals stay in `overlays-matrix-kinds.md` (Spec refusals — one rule per host).

- **`OVERLAY_MARKOV` (U28 E2-S2).** Markov chain of a from-state (rows) × to-state (columns) transition crosstab: MATRIX (crosstab) host, scope `matrix`, implicit-margin, descriptive (no p-site, no weight class: every output row-normalizes, so a weighted Σw table is read as is). `internal/processing/overlay_markov.go` (`applyMarkovAt`, index-aware like CA in `applyOverlaysPlanned`). **Square host:** states are the row keys in row order, the columns aligned BY KEY (`overlayhost.MarkovStateName`: a one-element string key is itself, any other key its JSON), never by position; a different grouper count per axis is `PULSE_OVERLAY_MATRIX_NOT_SQUARE` on predict AND runtime (`MarkovArityRefusal`, details `{kind, row_groupers, column_groupers, index}`), differing key sets runtime-only (`MarkovKeySetRefusal`, `{kind, row_only, column_only, index}`) because a crosstab emits only observed keys — an absorbing state with no observed move out is missing from the row axis. **Declared-absorbing synthesis (owner decision 2026-10-12):** when there is no row-only key and EVERY column-only key is named in `params.absorbing`, each gets a synthesized unit row (appended after the observed rows, in column order; known by declaration, not invented), reported by one `PULSE_OVERLAY_REF_ZERO` `{kind, axis: "row", states, reason: "absorbing_row_synthesized"}` plus `summary.parameters.synthesized_rows` (absent when 0, so the unsynthesized output is byte-identical); an observed row that is also declared absorbing is NOT rewritten. Any other one-axis key keeps the refusal (the fixup names the `absorbing` route). Predict cannot see observed keys, so it accepts both and the rule stays runtime-only (`TestMarkov_ColumnOnlyAbsorbing`, `TestMarkov_SynthesizedAbsorbingRow`). Cells: `NonnegativeCellRefusal` / `NonnegativeValueRefusal` (shared with CA); absent cell = 0; < 2 states or a zero total is `PULSE_OVERLAY_REF_INCOMPATIBLE_WITH_SHAPE`. A zero row becomes the unit row (absorbing) with one `PULSE_OVERLAY_REF_ZERO` `{kind, axis: "row", rows, states, reason: "zero_row_absorbing"}`. Params (`overlayhost.ParseMarkovParams`, strict, `PULSE_OVERLAY_PARAM_MISSING`): `steps` (default `[1,3,6,12]`, distinct integers 1–1000, ≤ `MarkovMaxStepCount` 64 — a cap the interview left open, set so one spec cannot ask for unbounded k × k parts), `absorbing` (non-empty, distinct), `initial` (`"margin"` = row totals / grand, or a share map normalized by its sum; omitted states 0); a key naming no host state is refused at runtime only (`MarkovStateRefusal`). Outputs: primary MATRIX P; parts `step_<n>` (Pⁿ by binary powering), `distribution_<n>` (π₀ Pⁿ, with `initial`), `steady_state` (power iteration from uniform, `max|Δ| < 1e-12` within 10,000 steps; slower chains fall back to the exact `linalg.Solve` of π(I − P) = 0, Σπ = 1 — `summary.parameters.steady_state_converged` 0 says which; only for one communicating class (Tarjan) with period 1 (gcd of `level(u)+1−level(v)` over edges from a BFS), else one `PULSE_OVERLAY_MARKOV_NOT_ERGODIC` `{reason: reducible, classes}` / `{reason: periodic, period}` and no part), `absorption_time` (with `absorbing`: expected steps to FIRST reach the declared set — the declared rows are not rewritten, so it is a first-passage time — `(I − Q)⁻¹·1` via `linalg.FactorLU` over the non-absorbing states certain to be absorbed; a state that can reach a closed class outside the set is NaN → `null` with one `PULSE_OVERLAY_MARKOV_NOT_ERGODIC` `{reason: absorption_not_certain, states}`; an LU-refused (numerically singular) I − Q drops the part with a `PULSE_MATRIX_SINGULAR` WARNING carrying linalg's details plus `kind` / `part` — the layer still ships, never a silent NaN). Summary parameters `states`, `classes`, `irreducible`, `period` (irreducible only), `steady_state_iterations` / `_converged`. Every product is FMA-free (explicit `float64()` around it). Interpretation addresses only the fixed-name parts (`overlayPartShapes`: `steady_state`, `absorption_time`); `step_<n>` / `distribution_<n>` are named by params. Oracle: `scripts/reference/gen_markov.R` (`markovchain` 1.2; its igraph / expm deps need the Homebrew Fortran workaround) → `markov.json`, plus the power-iteration self-check (πP = π) and the closed-form two-state fallback test. Example `crosstab-markov` runs on the `tier_migrations` fixture cohort.

- **`OVERLAY_SYMMETRY` (U30 E7-S1).** Test of symmetry for a from-state (rows) × to-state (columns) crosstab of PAIRED observations — McNemar on 2 × 2, Bowker on k × k (R `mcnemar.test`): MATRIX (crosstab) host, scope `matrix`, implicit-margin, INFERENTIAL (SCALAR payload = χ², `Summary{Statistic, PValue, Parameters}`). `internal/processing/overlay_symmetry.go` (`applySymmetryAt`, index-aware in `applyOverlaysPlanned`; joins the Level / Within-zero gate on both sides). **States** align BY KEY (`overlayhost.MarkovStateName`): row keys in row order, then column-only keys in column order; a one-axis state is a zero row / column — never a refusal (unlike MARKOV). A different grouper count per axis is `PULSE_OVERLAY_MATRIX_NOT_SQUARE` (`MarkovArityRefusal`, predict AND runtime). **Spec refusals are shared, predict AND runtime** (`overlayhost.CrosstabSpecRefusal`, Crosstab spec refusals in `overlays.md`): a set `Ref` is `PULSE_OVERLAY_REF_INCOMPATIBLE_WITH_SHAPE`, a scope other than `matrix` `PULSE_OVERLAY_SCOPE_UNSUPPORTED`. Params (`overlayhost.ParseSymmetryParams`, strict, `PULSE_OVERLAY_PARAM_MISSING`): `correct` (boolean, default `true` = R's default). Cells: `NonnegativeCellRefusal` / `NonnegativeValueRefusal`; an absent or undefined (NaN, `CellAt`) cell = 0; < 2 states or a zero total is `PULSE_OVERLAY_REF_INCOMPATIBLE_WITH_SHAPE`. **Statistic:** over pairs i < j, `s = n_ij + n_ji`, `χ² = Σ (n_ij − n_ji)² / s`, `df` = the pairs with `s > 0` — **an empty pair is DROPPED** (R keeps it: 0/0 = NaN; decision: an empty pair carries no information); none kept ⇒ statistic / p / scalar NaN → `null`, `df` 0. 2 × 2 with `correct` and `n_12 ≠ n_21`: Edwards' `max(0, |d| − 1)²` — the clamp differs from R only on a non-integer table (Kish-scaled / `AGG_SUM`), where R's `(|d| − 1)²` can exceed it. `params.exact` (2 × 2): R `binom.test(n_12, n)` (`statdist.BinomialTwoSidedP`) + `odds_ratio` n_12 / n_21 and `odds_ratio_ci_lower` / `_upper` (the `conf.int` at `params.conf_level` — default 0.95, echoed; `needs_exact` / `out_of_range` refusals in the shared parser — as odds, `statdist.BinomialOddsInterval`; n_21 = 0 → `null`); refusals + weight rule in `overlayhost/symmetry.go`. **`params.exact` on k × k (U66 E10-S1)** is the exact conditional Bowker test (`symmetryBowkerExactLayer`, `statdist.BowkerExactP`): given each pair's total m, n_ij ~ Binomial(m, ½) independently; statistic = the uncorrected χ² bit for bit, p = P(X² ≥ obs) by exact convolution (narrowest pair first, values merged at 1e-12 relative, an outcome in when X²·(1 + 1e-7) ≥ obs — fisher.test's relErr); on one pair it equals `binom.test` (`TestSymmetry_BowkerExactTwoStatesIsMcNemar`), and k = 2 stays the McNemar arm. Parameters `exact`, `states`, `discordant`, `pairs_dropped`, `continuity_corrected` (0) (no `df` / odds keys / `conf_level`). Runtime-only refusals (states and counts are data): an explicit `conf_level` ⇒ `PULSE_OVERLAY_PARAM_MISSING` `needs_2x2`; more than `BowkerExactMaxTerms` (2^22) enumeration terms ⇒ the same code, `exact_too_large` `{states, terms, limit}` — never a silent χ² (root `TestSymmetry_ExactStateRefusalsRuntimeOnly`). Its oracle rows are R brute-force enumeration over every binomial outcome (`sy_bowker_exact`, rel 1e-10). p = `chiSquareSurvival` (the TEST_CHISQ tail). Summary parameters `df`, `states`, `discordant` (Σ off-diagonal), `pairs_dropped`, `continuity_corrected` (1 / 0), plus the weighted floor. Any pair with `s / 2 < 5` (expected count under symmetry) raises ONE `PULSE_OVERLAY_EXPECTED_LOW` `{kind, low_expected_pairs, zero_pairs, expected_min}`. **Weights:** `ClassAware`, the `OVERLAY_CHISQ_MATRIX` rule — the Σw table, scaled to its Kish n_eff under probability (`weighting.ScalesByHostFloor`, so a components-disabled probability host is the hidden-floor `PROCESSING_CONFIG`). **Multiplicity:** one p per layer, `pSiteSummaryPValue`; predict `p_values` counts 1 (`overlayPValueCount`). Explain class `difference`. Oracle: `scripts/reference/gen_symmetry.R` → `symmetry.json` (`TestSymmetry_MatchesR`, columns reversed; rel 1e-12, odds CI 1e-10); weighted rows `ov_symmetry` in the weighted reference generator (GROUP_RANGE x × y buckets, R on `rep()`-expanded rows). Example `crosstab-symmetry` on `tier_migrations`.

- **`OVERLAY_RETENTION` (U30 E7-S2).** Per from-state stay / switch / churn rates of a from-state (rows) × to-state (columns) crosstab: MATRIX (crosstab) host, scope `row`, implicit-margin, DESCRIPTIVE (no p-site, no weight class). `internal/processing/overlay_retention.go` (`applyRetentionAt`, index-aware in `applyOverlaysPlanned`; joins the Level / Within-zero gate on both sides). **Rates** over `R_i` = the row's total over EVERY column: `stay` = the cell whose column key names the row's state (BY KEY, `overlayhost.MarkovStateName`; no such column ⇒ 0 — a row-only state is never refused), `churn` = Σ over the columns named in `params.absorbing`, `switch` = every other column; each is its own sum over `R_i` (never 1 minus the others), so they add to 1 up to rounding. Without `absorbing` there is no churn split (`churn` absent everywhere). **A from-state named in `absorbing` is not reported** (churn is the way into it; its own row — a reactivation — is not a retention rate). A row with `R_i = 0` has `null` rates (decision: undefined, never 0) and one `PULSE_OVERLAY_REF_ZERO` `{kind, axis: "row", states, reason: "zero_row"}`; no zero-total refusal (unlike MARKOV / SYMMETRY). **Spec refusals are shared, predict AND runtime** (`overlayhost.CrosstabSpecRefusal`): a set `Ref` is `PULSE_OVERLAY_REF_INCOMPATIBLE_WITH_SHAPE`, a scope other than `row` `PULSE_OVERLAY_SCOPE_UNSUPPORTED`. Params (`overlayhost.ParseRetentionParams`, strict, `PULSE_OVERLAY_PARAM_MISSING`): `absorbing` only — MARKOV's form, one shared decoder (`parseAbsorbing`); a name that is neither a row nor a column key is refused at runtime only (`MarkovStateRefusal`, `{param: absorbing, unknown, states}`: predict reads no record — pinned both ways by root `TestRetention_RefusalsMatchPredict`). Cells: `NonnegativeCellRefusal` / `NonnegativeValueRefusal`; absent cell = 0; an undefined (NaN) cell is absent (E4-S6, `CellAt`); a different grouper count per axis is `PULSE_OVERLAY_MATRIX_NOT_SQUARE` (`MarkovArityRefusal` — no row key could name a column). **Output:** SERIES, one entry per reported from-state in host row order, `Summary.Statistic` = stay, `Summary.Parameters` `switch`, `from_total` (`R_i`) and `churn` (with `absorbing`); layer `Summary.Parameters` pool the reported rows (`stay`, `switch`, `churn`, `states`, `total`; each pooled rate = Σ numerators / Σ totals, `null` when the total is 0). **Weights:** none-class — a ratio of host cells, so the Σw table is read as is under either kind (= the `rep()`-expanded rows; no Kish scaling): service `TestRetention_FrequencyWeightEqualsExpandedRows` (frequency ≡ expanded rows byte for byte, probability ≡ frequency, weighted ≠ unweighted). No product is taken, so figures are bit-identical across architectures. Oracle: hand-checked fixtures in `overlay_retention_test.go` (exact decimal literals — each rate is one correctly rounded integer division). Interpretation `summary.statistic` + deferred `summary.parameters.{switch,churn,from_total}` (runtime probe `retentionOverlayLayer`). Explain class: none (descriptive). Example `crosstab-retention` on `tier_migrations` (`absorbing: ["churned"]`). Third `flows` declarer: the `intentDeclarerExemptions` entry is gone.
