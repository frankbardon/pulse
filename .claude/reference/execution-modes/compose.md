# Execution modes — Compose, fits and item fan-out

Per-topic slice of the execution-modes reference. Index (Mode index + section map): `.claude/reference/execution-modes.md` — load it first, then only the slice(s) your engine work touches.

## Parallel Compose

`pulse.ComposeParallel`, `pulse api compose --parallel N`. Bounded worker pool over `ComposedRequest`. Order-preserving by slot index. `ComposeOptions{MaxWorkers, PerRequestTimeout, FailFast}` (FailFast defaults true).

Post-slot-barrier Compose-overlay fold (`internal/service/compose_overlay.go` ⇒ `processing.ApplyComposeOverlaysWithRequests` in `internal/processing/overlay_compose_dispatch.go`; the bare `ApplyComposeOverlays` is the nil-requests, nil-extensions delegate kept for embedders): the orchestrator invokes `s.applyComposeOverlays(ctx, req, requests, responses)` once every slot has produced a finalised `*Response` and BEFORE the response is returned. Operates EXCLUSIVELY on `*Response` objects; per-slot `Responses[i].Overlays` is left UNTOUCHED.

FailFast handling: when `FailFast=true` (default) AND any slot fails, the orchestrator returns the first observed error WITHOUT invoking the overlay hook. FailFast=false routes slot failures through `SERVICE_INTERNAL` which also skips the hook. Empty / nil `req.Overlays` short-circuits with no allocation (overlay-free Compose JSON is byte-identical to a request that omits the slot entirely).

Per-kind handlers replace the chassis stub (`applyComposeStub`) for every Compose-only kind that has shipped. The six crosstab-shape COMPOSE handlers (`OVERLAY_INDEX_VS_REF`, `OVERLAY_DELTA_VS_REF`, `OVERLAY_PROP_Z_CELL`, `OVERLAY_T_CELL`, `OVERLAY_CHISQ_VS_REF`, `OVERLAY_RANK`) are wired today; remaining Compose-only kinds dispatch through the chassis stub until their handler lands. All buffered — streamable subset is empty across COMPOSE by construction.

Request-shape gates on the COMPOSE host. Everything else in this fold reads `*Response` only, but `internal/processing/overlay_compose_partition.go` needs the AUTHORED request: the `OVERLAY_PROP_Z_PANEL` within-prefix slab gate turns on each slot's declared `Crosstab.Rows` grouper types, and a materialised `MatrixPayload` carries its row KEYS but never the grouper that produced them — a fan-out row axis is invisible downstream of execution. So `service.(*Service).applyComposeOverlays` passes the per-slot requests and the `*ExtensionRegistry` into `ApplyComposeOverlaysWithRequests`, and the gate runs per spec INSIDE the dispatch loop (after reference/target resolution, before the key-set and schema walk — mirroring predict's Gate 3b position) rather than in the handler, because the `composeOverlayHandler` signature must stay `(spec, reference, targets, refIdx, targetIdxs)`. The gate declines whenever an earlier refusal is due, so the cap still fires first. An embedder calling the bare `ApplyComposeOverlays` gets no request-shape gate — the documented counterpart of the exported `ApplyOverlaysWithExtensions` bypass on the MATRIX host.

Response shaping (`return`) never runs inside the service: `Service.ComposeResolved` / `ComposeParallelResolved` hand the facade the label- and defaults-resolved slot clones, and `Pulse.Compose` / `ComposeParallel` apply each slot's plan plus the Compose-level `ComposedRequest.Return` (top-level overlays only) via `returnshape.ApplyComposed` AFTER the overlay and multiplicity folds — so every layer reads unshaped slots and serial ≡ parallel. What a slot's selection skips COMPUTING is decided per slot, where the whole `ComposedRequest` is in hand: a slot a Compose overlay names (reference or target) keeps the Components its overlays read (`Service.composeSlotVetoes`: every sub-part, except that the floor kinds `OVERLAY_PROP_Z_CELL` / `_PANEL` / `OVERLAY_CHISQ_VS_REF` keep `components.crosstab` only over a weighted slot and nothing over an unweighted one, #221), an unnamed slot skips what it excludes — the Compute plan paragraph of `.claude/reference/response-components.md`. Contract row: `update-demand/payload-and-return.md` (`Request.Return` row).

Slot label resolution: `applyComposeLabelDefaults` synthesises `request_<index+1>` for empty `Request.Label`; `ApplyComposeOverlays` builds a `Label → Index` lookup. The dedicated error codes `PULSE_OVERLAY_REFERENCE_UNKNOWN` and `PULSE_OVERLAY_TARGET_UNKNOWN` are pending — the chassis currently falls back to `PULSE_OVERLAY_REF_UNKNOWN` with a `which` Detail. See `skills/compose-requests.md`.

## Compose fits

`ComposedRequest.Fits` (`[]types.FitSpec {name, request}`, gated by `capability:compose_fits`). Order inside `Service.compose` / `composeParallel`: sweep expansion → slot gate (`descx.SlotRefusal` also walks every fit request, located `details.fit`) → `model.CheckFits` (the one structural rule set, shared with `PredictCompose`: `PULSE_FIT_INVALID` reasons `name_missing` / `request_missing` / `regression_count` / `grouped`, then `PULSE_MODEL_NAME_COLLISION`) → the batch save + load pre-pass (`composeModelsPrepass`: `model.CheckComposeBatch` — every slot's save path, every save's uniqueness, every fit request's and slot's `models` entry against the fits' names — then every model file read; `PredictCompose` runs the same, so a refusal leaves nothing written) → multiplicity / `return` / labels → the fit pre-pass `runComposeFits` (`internal/service/compose_fits.go`) → slots → post-slot folds. Each fit runs as an ordinary standalone `Process` over `model.FitRequest` (a clone with `return` cleared, so a fit request's `return` can never skip the regression) under the Compose ctx BEFORE `withinCompose`, so a fit resolves its own multiplicity like a standalone request and never reads a slot's filters, features or weight. Serial Compose runs fits in order; `ComposeParallel` runs them concurrently on `MaxWorkers`, cancelling siblings on the first failure; either way the reported failure is the lowest-index fit (`failFastWinner`), its coded error kept with `details.fit` added (`descx.RefusalAt`). Results bind through `model.Bind` (predictor order = spec order, or the selection's retained predictors; full float64 coefficients, SE, vcov, family/link) into one `model.Set` (each Bound stamped `model.FitSource(i)`); `bindSlotModels` puts on every slot ctx that set plus the slot's own pre-loaded `models` (`Set.WithModels`), marked loaded (`withModelsBound`) so the slot's Process does not reload — sweep slots included, since the sweep expanded first. A fit request's Process gets its own loaded `models` alone. `internal/model` is a leaf (stdlib + types + errors, `TestModel_ImportBoundary`) so predict and the engine share the resolver (`Set.Lookup` → `PULSE_MODEL_UNKNOWN {name, available}`). `ComposedResponse.Fits` (map keyed by name) is nil without fits — byte-identical — and pinned outside the Compose `return` (`types/return_shape.go` `fitsKey`). The fits are not part of `--stream` output. Gates: `TestComposeFits_*` (`internal/service`, run-once counter, serial ≡ parallel bytes, refusals), `TestComposeFits_PredictRuntimeParity`, `TestHiddenComposeFits_RefusedAsUnknownField` (root), `TestCheckFits` (`internal/model`).

**Vector fits (U30 E2-S2).** A `fits` entry is a regression fit OR a vector fit (`model.FitKindOf`): a request with no regression and exactly one vector battery — one `matrices` entry or one `model.VectorFitAttributeTypes` attribute (`ATTR_MAHALANOBIS`, `ATTR_PC_SCORE`, `ATTR_FACTOR_SCORE`). `model.CheckFits` adds reasons `kind_ambiguous` (a regression AND a battery), `vector_count`, `vector_source` (`model.VectorSourceRefusal`: `params.missing` pairwise, `MAT_DISTANCE`, a `MAT_RELIABILITY` `reverse` list) (`vector_save` was lifted by E2-S3: a vector fit's `save` now writes a population file, judged by `model.CheckPopulationSavePath` — `PULSE_MODEL_SAVE_INVALID`); `regression_count` still covers "no battery". `runComposeFits` runs a vector fit through `runVectorFit`: the fit request's Process gets its set copied with a fresh `model.VectorCapture` (`Set.WithCapture`, carried to every arm on the one ctx `model.Set`), the battery offers its closed listwise state at finalize, and exactly ONE offer (else `PROCESSING_INTERNAL`) is bound by `Set.AddVector` (`Source` = `FitSource(i)`); `ComposedResponse.Fits[name]` is `&types.FitResult{Vector: processing.VectorFitResult(vf)}`. One namespace, two kinds: `model.Signature` gains `Kind` (`types.FitKind`, empty reads regression — `EffectiveKind`) and `Members` (the runtime's labels; nil from predict's static `FitCatalog`); `Set.Names` / `Len` count both kinds (`RegressionNames` / `VectorNames` one each); a reference of the other kind is `PULSE_MODEL_KIND_MISMATCH {name, fit, kind, expected}` (`model.KindMismatch` — `Set.Lookup`, `LookupVector`, `CheckScore`, `CheckCoef`, `CheckVectorFit`), and `PULSE_MODEL_UNKNOWN`'s `available` lists the kind the reference reads (`model.NamesOfKind`). Every `params.fit` (fitted attribute, matrix) is judged at field-reference step 12 — runtime and `PredictCompose` alike; predict's `FitSummary` lists a vector fit as `{name, cohort, vector: {operator, labels, members}}` (`vectorFitAxis` resolves the battery against the fit request's schema). Gates: `TestCheckFits`, `TestCheckVectorFit`, `TestFitKindOf`, `TestVectorCapture` (`internal/model`), `TestComposeVectorFits_*` (`internal/service`, root — predict ≡ runtime parity, wire shape, every `MAT_*`). **A fit-bound attribute is ROW-LOCAL (U30 E2-S5).** An `ATTR_MAHALANOBIS` / `ATTR_PC_SCORE` / `ATTR_FACTOR_SCORE` / fitted `ATTR_VEC_DISTANCE` slot whose `params.fit` names a fit (`vectors.FitBound` — an in-batch Compose fit, a `populations` load or a registered population) holds its whole state before the scan: `bindFitOn` rebuilds AND closes it at bind (decomposition, fit warnings, a capture offer), its `PrePass` / `Finalize` are no-ops, and every routing site reads the one predicate — `attrRequiresTwoPassIn` (so `canStream` streams it beside groupers, features, matrices and tier-1 tests, and `hasTwoPassAttribute` never picks the two-pass drive for it), predict's `attrTwoPass`, the fused-crosstab facts (`crosstabfuse.Facts.AttributeSlotBound`), the two-pass planner (`prebuiltAttribute`: a bound slot is a row-local input, available on scan 0) and `mergegate` (the three `FittedAttributeTypes` only; a bound `ATTR_VEC_DISTANCE` stays off the list like its row-local metrics). Merged, it runs on the shard and parallel-decode reducers and in chain stages: the reducers resolve its vector input (`processing.ResolveAttributeInputs`), build it ONCE at the orchestrator for its fit warnings and capture offer (`boundAttributeWarnings`, prepended where the serial arms put row-local warnings) and bind each partition's copy with the capture stripped (`partitionModels`), so a Compose vector fit whose battery is a bound attribute still closes exactly one state. Scores are the two-pass `fit_on` run's to the bit (same state, same per-row kernel); `fit_on` behaviour is unchanged. Gates: `TestFittedState_BoundIsRowLocal`, `TestFittedState_PrebuiltMatchesFitOn` (every arm, grouped streaming included), `TestFitBound_*` (root: two-pass parity on Process / ProcessStream, the shard reducer, a chain stage, Compose on shards; `internal/service`: the parallel-decode reducer), `TestPredict_Streamable_MatchesRuntime`, `TestStreamability_CrosstabFusionPredictMatchesRuntime`, `TestMergeRefusal`.

**Population saves and loads (U30 E2-S3).** A vector fit's `save` (`.pulse-population.json`) is written in the fit's run step right after `runVectorFit` closes its state (`saveFitPopulation`, under the fit's NAME, not the summary — the stored listwise figures), so serial and parallel batches write the same bytes; its `PULSE_MODEL_OVERWRITTEN` warning lifts to `ComposedResponse.warnings` in entry order like a regression fit's. `Request.Populations` loads at the very point `models` loads (`bindRequestModels` / the Compose and chain pre-passes, through `model.Refs`), binding each file as a `model.VectorFit` beside the batch's fits — a plain `Process` therefore reads `params.fit` against a saved population exactly as a Compose slot reads a vector fit, and a pre-pass load reads the file as it was BEFORE the run (a population a fit in the same batch saves is not visible to that batch's slots). Format and load rules: `byte-layout.md` (Population file).

**Scoring a bound fit (`ATTR_REG_PREDICT`, U42 E1-S2).** The service hands `model.SetFrom(ctx)` to every processor it builds (`newProcessor` → `Processor.SetModels`), to the field-reference pass (`checkFieldRefs(ctx, …)` → `descx.ScopedFieldRefRefusalWithModels`; predict passes `model.CatalogFromFits(req.Fits)` per slot and nil for a fit request or a plain request, so both sides refuse an unbound name as `PULSE_MODEL_UNKNOWN {name, available}`), to the projected decode (`neededFields(ctx, …)` → `processing.NeededFieldsWithModels` adds the bound predictors the request never spells) and to the per-shard / parallel-decode reducers (`buildRowLocalAttrSpecs` binds through `processing.BindAttribute`). One rule judges a reference — `model.CheckScore` (params, fit name, scorable type, `terms`, `scale`) then each `Signature.Terms` column present (`PULSE_MODEL_PREDICTOR_MISSING`) and, when a schema field, numeric (`_NOT_NUMERIC`) — in the field-reference walk (predict ≡ runtime) and again at bind. `Signature.Terms` is the fit spec's candidate list, not the selection's kept subset, so predict (which never fits) judges exactly what the runtime judges. Bound, the attribute is ROW-LOCAL (not in `requiresTwoPass`; `canStream` admits it; `mergegate` lists it beside `ATTR_FORMULA` / `ATTR_DATE_PART`; Materialize admits it); the two-pass planner treats its inputs as unknown (it depends on every earlier attribute). Scoring is `regression.Scorer` over `regression.LinearPredictor` — the ONE kernel `ATTR_REG_FITTED` / `RESIDUAL` / `LEVERAGE` and the GLM engine's own η also evaluate — plus the engine's own `InverseLink` on the GLM response scale, so a training row's score equals the fit's fitted value bit for bit. A null input emits NaN, which every arm writes as a NULL through the `processing.NullEmitter` opt-in (`SetAttributeOutput`; buffered `applyAttributes`, streaming, two-pass, fused crosstab, both reducers), so a downstream aggregation counts the row in `n_null`; `ATTR_REG_FITTED` / `RESIDUAL` / `LEVERAGE` opt in the same way (null predictor, or null target for `RESIDUAL`; `TestAttrReg_Null*`). Gates: `TestRegPredict_*` (`internal/processing`, `internal/service`, root parity), `TestScorer_*` (`internal/processing/regression`), `TestCheckScore` / `TestSignature_RuntimeMatchesPredict` (`internal/model`).

**Reading a bound fit's figures (`bound`, `coef()`, U42 E2-S3).** `ATTR_REG_PREDICT` `params.bound` `lower` / `upper` swaps the coefficient for its confidence bound (`model.Bound.CILower` / `CIUpper`, full precision) in `regression.NewScorer`; `model.CheckScore` refuses it unless `terms` is exactly one predictor (`PULSE_MODEL_SCORE_INVALID` `bound_terms`; an unknown value `bound_unknown`), and a term without a bound (lasso-dropped, selection-dropped candidate, df ≤ 0) scores null on every row. `coef(fit, term[, stat])` is a built-in expr function of `ATTR_FORMULA` and `FILTER_EXPRESSION` only (not `OVERLAY_FORMULA`): `processing.exprOptionsWithModels` registers it after the set helpers and before the embedder's `ExprFunctions` (an embedder `coef` shadows it and the static check stands down), closed over the request's `model.Set` — injected through `modelBinder` into the formula attribute (`BindAttribute`) and the expression filterer (`buildFilterFuncs`, `processing.BuildFiltersWithModels` for the shard / parallel-decode reducers; facet and filter-to-file pass nil). One rule, `model.CheckCoef` (fit → `PULSE_MODEL_UNKNOWN`, term → `_TERM_UNKNOWN`, stat → `_STAT_UNKNOWN`), runs on every all-literal call in the descriptor field-reference walk (predict ≡ runtime entry) and at build (`internal/model/coefcall`), and on every call at evaluation (`model.Coef`, which adds `_INTERVALS_UNAVAILABLE` for a fit with no standard errors — runtime only). `exprProgram.evalError` returns a `PULSE_MODEL_*` refusal under its own code, and a filter never reads one as a null-row UNKNOWN. An absent figure is NaN, never 0. `coef` is not pure for filter precompute. Gates: `TestCoef_*` (`internal/model`, `internal/model/coefcall`, `internal/processing`, `internal/service`, root parity), `TestRegPredict_Bound*` (`internal/processing`).

## Item fan-out (`for_each`)

A `for_each {axes, mode}` on a window, feature or attribute item is expanded by ONE function, `sweep.ExpandItems` (import-fenced `internal/sweep`, reusing the compose sweep's `forEachCombination`, `variablesFor` and `template.RenderJSON`), wrapped with the `MaxDerivedColumns` preflight by `descx.ExpandRequestItems`. Every request host calls it right after the slot gate and before anything else reads the item lists: `Service.process` (so `Process`, `ProcessStream`, every serial and parallel Compose slot and chain stage 0), `Service.materialize` (before the materialize gates, so every expanded item becomes a column), `Service.ProcessChain` (every stage, located `details.stage`), and predict (`Predict`, each Compose slot, each chain stage). The runtime rewrites `req.Features` / `Attributes` / `Windows` IN PLACE — as smart defaults resolve in place — so the request echo shows the expanded lists and a second run is a no-op; predict expands a clone. Order: structural and reference checks over every for_each item (pipeline order: features, attributes, windows), then the limit over plain + expanded items, then rendering (grid first axis slowest; zip lockstep) and a strict decode per item. A sweep body carrying a for_each is refused (`nested_in_sweep`) by `sweep.Expand` before its placeholder scan. `Request.Hash` hashes the request as written (the `for_each` key is `omitempty`, so a for_each-free request hashes byte-identically); the hash of the expanded request equals its hand-expanded twin's.
