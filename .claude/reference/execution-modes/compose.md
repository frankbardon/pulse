# Execution modes — Compose, fits and the result pre-phase

Per-topic slice of the execution-modes reference. Index (Mode index + section map): `.claude/reference/execution-modes.md` — load it first, then only the slice(s) your engine work touches. Parallel Compose, banner, base and item fan-out are in `execution-modes/compose-parallel-banner.md`; adaptive sweeps in `execution-modes/compose-adaptive.md`.

## Compose fits

`ComposedRequest.Fits` (`[]types.FitSpec {name, request}`, gated by `capability:compose_fits`). Order inside both orchestrators:

1. sweep expansion;
2. slot gate (`descx.SlotRefusal` also walks every fit request, located `details.fit`);
3. `model.CheckFits` — the one structural rule set, shared with `PredictCompose` (`PULSE_FIT_INVALID` reasons, then `PULSE_MODEL_NAME_COLLISION`);
4. the batch save + load pre-pass (`model.CheckComposeBatch` — every save path, save uniqueness, every `models` entry against the fits' names — then every model file read; predict runs the same, so a refusal leaves nothing written);
5. multiplicity / `return` / labels;
6. the fit pre-pass (`internal/service/compose_fits.go`);
7. slots, then post-slot folds.

**How a fit runs.** Each fit runs as an ordinary standalone `Process` over `model.FitRequest` (a clone with `return` cleared, so a fit request's `return` can never skip the regression), outside the Compose slot context — so it resolves its own multiplicity like a standalone request and never reads a slot's filters, features or weight. Serial Compose runs fits in order; `ComposeParallel` runs them concurrently on `MaxWorkers`, cancelling siblings on the first failure; either way the reported failure is the lowest-index fit, its coded error kept with `details.fit` added.

**How a fit binds.** Results bind through `model.Bind` (predictor order = spec order, or the selection's retained predictors; full float64 coefficients, SE, vcov, family / link) into one `model.Set`. Every slot context gets that set plus the slot's own pre-loaded `models`, marked loaded so the slot does not reload (sweep slots included, since the sweep expanded first). A fit request gets its own loaded `models` alone. `internal/model` is a leaf (`TestModel_ImportBoundary`), so predict and the engine share the resolver (`Set.Lookup` → `PULSE_MODEL_UNKNOWN {name, available}`).

**Wire.** `ComposedResponse.Fits` (map keyed by name) is nil without fits — byte-identical — and is outside the Compose `return`. `--stream-fits` / `ComposeStreamOptions.TerminalFits` streams them as one final `fits` line. Pinned by `TestComposeFits_PredictRuntimeParity`.

**A fit that fails on its data fails alone.** A fit whose regression or `MAT_*` battery comes back as a failed slot is not a batch failure: its `Fits[name]` entry keeps `error`, the name binds as a failed fit (`model.Set.AddFailed`), its `PULSE_SLOT_FAILED` warning lifts with `details.fit`, and every other fit and slot runs. A reader scoring it gets null + `PULSE_FIT_UNAVAILABLE`; a `MAT_*` `params.fit` slot fails alone; a `FILTER_EXPRESSION` `coef()` or a non-literal fit name is refused with the fit's own code. Under Strict the fit's Process fails and the lowest-index rule applies (deterministic: the parallel stage cancels only fits after a failure). Long form: `.claude/reference/response-components.md` (Per-slot failures).

**Sweep-bound fits.** A `fits` entry may carry `from_sweep {regression}` (`capability:compose_sweep_bind`) instead of `request`. Both sides build `descx.SweepFitScope` (the as-written sweep / rank plus the expanded sweep slots, and whether a sweep slot reads the fit — a literal `coef()` / `sweep_axis()` or a `params.fit`) and run `model.CheckFitsIn` over it (reasons `from_sweep_with_request` / `_no_sweep` / `_no_rank` / `_regression_unknown` / `_signature_varies` / `_cycle`). `model.ResolveSweepFits` then fills each binding's request with `model.SweepFitRequest` over the FIRST sweep slot (the slot's rows and the named regression, `save` cleared, every part a fit refuses dropped), so every downstream check and predict's `FitSummary` see an ordinary regression fit. `NormalizedRequest` echoes the request as expanded.

**The sweep-first schedule** (`internal/service/compose_sweep_bind.go`). A batch holding a from_sweep entry runs, in BOTH orchestrators:

1. the authored fits (run ONCE), bound into the set the sweep slots read;
2. phase 0 — the sweep slots, then their slot-local multiplicity families, then the rank, computed ONCE. The `compose` family pools slots not yet run, so it stays at the barrier; a `rank.by` on its adjusted figure resolves in no slot and is refused, never misread;
3. each bound fit refitted as an ordinary regression fit over the winning slot's `SweepFitRequest` with that slot's loaded `models` — so its numerics, its `save` file and the slots scoring it are an authored fit's of the winning body to the byte;
4. optimize, then every slot phase 0 did not run.

Responses keep index order; sweep slots run once. A failed phase 0 returns early with no explicit slot run: a non-fail-fast pool's `SERVICE_INTERNAL` aggregate gains `details.skipped_indices`; serial / fail-fast keep the located slot error. **An EMPTY ranking binds the fit FAILED:** its `Fits` entry is `{name, type, error}` with `PULSE_SWEEP_RANK_PATH` `reason: "empty"`, a `PULSE_SLOT_FAILED` warning lifts with `details.fit`, readers get `PULSE_FIT_UNAVAILABLE`; Strict fails the batch with that code. There is no rank-2 fallback. A batch with no from_sweep entry takes the plain fit pre-pass — order and bytes identical.

**Winning axes, `sweep_axis(fit, axis)`.** A reserved request-bound expr function (an embedder of that name is `PULSE_EXTENSION_NAME_RESERVED`), declared beside `coef` as `(string, string) → any`. One rule, `model.CheckSweepAxis`: unknown fit → `PULSE_MODEL_UNKNOWN`; a fit that is not sweep-bound → `PULSE_MODEL_TERM_UNKNOWN` `reason: not_sweep_bound`; an axis outside the fit's sweep axes (judged only when known) → same code, `reason: axis_unknown` + `details.axes`. It runs on every all-literal call beside `coef()` statically and on every call at evaluation (which then gives a failed fit's own refusal, else the value — numbers as `float64`). At runtime the binding records the winner's axes; a failed bound fit carries the scope axes, so readers follow `PULSE_FIT_UNAVAILABLE`.

**Steady-state response, `response(fit, channel, spend)`.** Reserved, declared `(string, string, float64) → float64`. Value: `beta · hill(m · spend, k, s)` off coef()'s point reads of `<ch>`, `k:<ch>`, `s:<ch>` — or, for a `REG_MMM_BAYES` fit whose saturation record names `logistic` / `michaelis_menten`, that curve over `lam:<ch>` / `k:<ch>` (`hill()` stays Hill-only) — with `m = Adstock.SteadyState()` (weights summed in lag order; FMA-free). Rule `model.CheckResponse`: unknown fit, kind, then no adstock record → `PULSE_MODEL_TERM_UNKNOWN` `reason: adstock_unknown` + `details.channel` / `channels`, judged only when the adstock records are known statically (a `from_sweep` entry is judged at run).

- **Geo form:** `response(fit, channel, spend, geo)` reads a `REG_MMM_BAYES` geo panel's own terms (β `<ch>[<geo>]`, the kernel at `decay:<ch>[<geo>]` …, per-geo curve terms when the fit names them, else shared); without it a panel reads μ. `model.CheckResponseGeo` adds a geo outside the fit's geos → `PULSE_MODEL_TERM_UNKNOWN` `reason: geo_unknown` + `details.geo` / `geos`.

**Optimize bounds as scalar expressions.** An optimize `lower` / `upper` / `start` is a scalar-expression slot read once after the fits: params-only values are range-checked by predict; a `coef()` / `sweep_axis()` one is listed under `unresolved_scalars` and range-checked at runtime. Long form: `.claude/reference/execution-modes/scalar-slots.md`.

**Vector fits.** A `fits` entry is a regression fit OR a vector fit (`model.FitKindOf`): a request with no regression and exactly one vector battery — one `matrices` entry or one attribute in `model.VectorFitAttributeTypes`. `model.CheckFits` adds `kind_ambiguous` (a regression AND a battery), `vector_count` and `vector_source` (`model.VectorSourceRefusal`); a vector fit's `save` writes a population file (`model.CheckPopulationSavePath`). Categorical regressions bind too (`execution-modes/categorical-scores.md`).

- The fit request's Process gets a fresh `model.VectorCapture`; the battery offers its closed listwise state at finalize and exactly ONE offer (else `PROCESSING_INTERNAL`) binds through `Set.AddVector`. `ComposedResponse.Fits[name]` is `{vector: …}`.
- One namespace, two kinds: `model.Signature` carries `Kind` (empty reads regression) and `Members`. A reference of the other kind is `PULSE_MODEL_KIND_MISMATCH {name, fit, kind, expected}`, and `PULSE_MODEL_UNKNOWN`'s `available` lists the kind the reference reads.
- Every `params.fit` (fitted attribute, matrix) is judged at field-reference step 12 (`internal/descriptor/field_refs.go`), runtime and `PredictCompose` alike; predict's `FitSummary` lists a vector fit as `{name, cohort, vector: {operator, labels, members}}`.

**A fit-bound attribute is ROW-LOCAL.** A fitted attribute whose `params.fit` names a fit (`vectors.FitBound` — an in-batch Compose fit, a `populations` load or a registered population) holds its whole state before the scan: it is rebuilt AND closed at bind (decomposition, fit warnings, a capture offer), its `PrePass` / `Finalize` are no-ops, and every routing site reads the one predicate (streaming routing, predict's two-pass judgement, the fused-crosstab facts, the two-pass planner, `mergegate`). Merged, it runs on the shard and parallel-decode reducers and in chain stages: the reducers build it ONCE at the orchestrator for its fit warnings and capture offer, and bind each partition's copy with the capture stripped, so a Compose vector fit whose battery is a bound attribute still closes exactly one state. Scores equal the two-pass `fit_on` run's to the bit (`TestFittedState_PrebuiltMatchesFitOn`).

**SEM fits.** A `fits` entry whose request holds exactly one `MAT_SEM` matrix and no regression is kind `sem` (checked BEFORE the vector arm — a `MAT_SEM` battery is never a vector fit). It uses the same capture handle; finalize offers a `model.SEMFit` (model description and options, labels / members, observed / inner / latent variables, solver stop, `dof` / `n_params`, per level `n`, Σw and parameters) from the merged state, once, on whichever arm runs. An undefined input fails the slot of a SEM fit request (`PULSE_MATRIX_INSUFFICIENT_N` / `_SINGULAR`) instead of nulling, so a fit always binds or fails. `ComposedResponse.Fits[name]` is `{"sem": …}`, a failure `{"sem": {operator, error}}`.

- `ATTR_SEM_SCORE` `params.fit` (refused beside a model knob — `fit_and_model` — or `fit_on`) is judged by `model.CheckSEMFit` (other `params.fit` slots keep `CheckVectorFit`, so the kind mismatch holds both ways). Binding aligns labels, re-specifies the model from its description and options (one model for every group; a model that does not reproduce the stored orders is `PROCESSING_INTERNAL`), matches each fit level to the scoring schema's group field by LABEL, and builds the scorer through the ONE path the inline `Finalize` uses — so scores are the inline fit's bits on the same rows. Bound, the slot is row-local (as above), and projection decodes the fit's group field.
- A SEM fit's `save` (`.pulse-sem.json`) is written right after the fit binds (its `PULSE_MODEL_OVERWRITTEN` lifts to the batch, `details.fit`), and a `models` entry ending `.pulse-sem.json` loads it back as a SEM fit. Format and load: `.claude/reference/byte-layout.md` (SEM fit file).

**Population saves and loads.** A vector fit's `save` (`.pulse-population.json`) is written right after the fit closes its state, under the fit's NAME, so serial and parallel batches write the same bytes; its `PULSE_MODEL_OVERWRITTEN` warning lifts to `ComposedResponse.warnings` in entry order. `Request.Populations` loads at the very point `models` loads, binding each file as a vector fit beside the batch's fits — a plain `Process` reads `params.fit` against a saved population exactly as a Compose slot reads a vector fit. A pre-pass load reads the file as it was BEFORE the run (a population a fit in the same batch saves is not visible to that batch's slots). Format and load rules: `byte-layout.md` (Population file).

**Scoring a bound fit (`ATTR_REG_PREDICT`).** The service hands the request's `model.Set` to every processor, to the field-reference pass (predict passes the static fit catalog, so both sides refuse an unbound name as `PULSE_MODEL_UNKNOWN {name, available}`), to the projected decode (which adds the bound predictors the request never spells) and to the per-shard / parallel-decode reducers.

- **One rule judges a reference:** `model.CheckScore` (params, fit name, scorable type, `terms`, `scale`), then each `Signature.Terms` column present (`PULSE_MODEL_PREDICTOR_MISSING`) and, when a schema field, numeric (`_NOT_NUMERIC`) — in the field-reference walk (predict ≡ runtime) and again at bind. `Signature.Terms` is the fit spec's candidate list, not the selection's kept subset, so predict (which never fits) judges exactly what the runtime judges.
- Bound, the attribute is ROW-LOCAL (streams, merges, materializes); the two-pass planner treats its inputs as unknown (it depends on every earlier attribute).
- **Scoring is ONE path, `model.RowScorer`:** `Bound.Scorer` delegates to the fit type's `model.ScorerFactory`; built-ins resolve through `regression.BuiltinScorer` — the linear types over `regression.LinearPredictor`, the ONE kernel the fitted / residual / leverage attributes and the GLM engine's own η also evaluate, GLM adding the engine's own inverse link — so a training row's score equals the fit's fitted value bit for bit. A registered extension regression scores through its own `Scorer` (whole model only; none → reason `no_scorer`).
- **A null input emits NaN, which every arm writes as NULL** through the `processing.NullEmitter` opt-in, so a downstream aggregation counts the row in `n_null`. The fitted / residual / leverage attributes opt in the same way.

**Categorical-outcome scores** (`REG_ORDINAL`, `REG_MULTINOMIAL`): `execution-modes/categorical-scores.md`.

**Reading a bound fit's figures (`bound`, `coef()`).** `ATTR_REG_PREDICT` `params.bound` `lower` / `upper` swaps the coefficient for its confidence bound (full precision) in the built-in linear scorer; `model.CheckScore` refuses it unless `terms` is exactly one predictor (`PULSE_MODEL_SCORE_INVALID` `bound_terms`; an unknown value `bound_unknown`), and a term without a bound (lasso-dropped, selection-dropped, df ≤ 0) scores null on every row.

- `coef(fit, term[, stat])` is a built-in expr function of `ATTR_FORMULA` and `FILTER_EXPRESSION` only (not `OVERLAY_FORMULA`), registered before the embedder's `ExprFunctions` (an embedder `coef` shadows it and the static check stands down), closed over the request's `model.Set`.
- One rule, `model.CheckCoef` (fit → `PULSE_MODEL_UNKNOWN`, term → `_TERM_UNKNOWN`, stat → `_STAT_UNKNOWN`), runs on every all-literal call in the field-reference walk and at build, and on every call at evaluation (which adds `_INTERVALS_UNAVAILABLE` for a fit with no standard errors — runtime only). A `PULSE_MODEL_*` refusal keeps its own code; a filter never reads one as a null-row UNKNOWN.
- An absent figure is NaN, never 0. `coef` is not pure for filter precompute.

## Result pre-phase

**What.** `result("<slot label>", "<aggregation label>")` is a request-bound, reserved expr function (an embedder of that name is `PULSE_EXTENSION_NAME_RESERVED`; also a reserved decision-variable name) that reads one ungrouped aggregation of a Compose slot. It is in reach of an `optimize` block ONLY — bounds and starts, objective and constraints. Every other scalar slot compiles with a nil catalog and refuses a call as `PULSE_RESULT_INVALID` `out_of_scope` before compiling; a non-scalar expression slot (formula, filter) does not declare it, so a call there is that slot's ordinary compile error. Nothing a slot computes reads an optimize block, so the dependency graph is one level deep (optimize → slots) and a cycle cannot form.

**One rule set, `internal/resultcall`** (no-execute leaf, `TestResultCall_ImportBoundary`). `CatalogOf(requests)` runs over the EXPANDED slots (sweep and banner slots included; label = own or `request_<i+1>`; grouped = groups or crosstab). `Refusal(src, cat)`, in walk order: nil cat → `out_of_scope`; a non-literal argument → `args_not_literal`; `slot_unknown` (`available` = slot labels); `aggregation_unknown` (`available` = the slot's labels); `grouped`; `not_numeric` (the aggregation writes no single number). Details `slot`, `aggregation`, plus `optimize` / `field` once located. Predict and the runtime's optimize refusal build the same catalog, so they refuse identically; a reading bound is listed under `unresolved_scalars` with `reads: ["result"]`.

**Schedule** (`internal/service/compose_result.go`). The result phase runs between the fit phases and optimize in BOTH orchestrators: every slot a literal `result()` call names, minus the slots phase 0 already ran, through the orchestrator's own runner — so a referenced slot sees the fits exactly as it would later, runs ONCE, keeps its index, and is skipped in the final phase. Optimize then reads `Data[0][label]` of the finished, unshaped response: a finite number, else `PULSE_RESULT_INVALID` `null` (nil or NaN), `not_numeric` (`type`), `not_finite` (`value`), `grouped` (not one row). A run-time refusal is FATAL, located at the bound or expression. The multiplicity barrier and the overlay fold still run after every slot.

**Execution modes.**

- *Parallel:* `ComposeParallel` runs the pre-phase slots on its pool after the fit phases and before the blocks; the bytes equal serial `Compose`'s.
- *Failure:* slots are marked run before running, so none reruns. A failed read slot stops every optimize block and the comparisons. Serial and fail-fast parallel return at once with the slot's OWN coded error, located `details.request`, plus `details.result_slot` (its label) and `details.optimize` (the first block reading it). A non-fail-fast pool still runs every other slot, then returns the batch's `SERVICE_INTERNAL` aggregate (`failed_indices`, `first_error`) with `details.result_slots`.
- *Stream:* `--stream` is written from the finished `ComposedResponse`, so a pre-phase slot's rows appear ONCE, at its slot index (never run order).
- *Limits:* `MaxComposeSlots` counts the expanded slot list up front; a pre-phase slot is counted once.

## Post-fit phase

**Schedule.** Phase order: slots / sweep → fits → result pre-phase → optimize → **post-fit** → compare → the remaining slots. A batch declaring `post_fit` runs every slot not yet run BEFORE the phase (the operator's `Result` may read any slot), then marks all run; a post-fit-free batch skips the phase. `internal/postfit.Check` runs after the compare refusal, before any fit or slot; predict runs the same check right after `regcompare.Check` (`TestPostFit_PredictMatchesRuntime`). Both orchestrators share the phase runner. Contract (operator surface, failures, codes): `.claude/reference/architecture/extension-models.md` (Extension models).
