## Two-phase `total()`

**Two-phase `total()` (U51 E3-S1, #399; grouped and multi-layer U74 E3-S1 / E3-S2, #494).** A total-bearing `ATTR_FORMULA` is not row-local, yet both reducers run it when `mergegate.ParallelTotals` admits it: every `total()` formula of a request with no `Crosstab` (and no nil attribute slot) — grouped too (the cohort-wide total publishes before any grouper reads a row), and in any pre-pass layer of the serial two-pass plan (`twoPassPlan`: a formula whose input reads, directly or through row-local slots, an earlier `total()` formula's label sits one layer deeper; an `ATTR_REG_PREDICT`, fit-referenced or extension slot without `FieldInputs` reads every earlier one). The request's other attributes are judged as ever: a non-row-local one keeps it serial. Phase 1 (`internal/service/totals_prepass.go`) is one parallel pre-pass per layer (`processing.TotalsPrepassLayers`, `prepassLayers`), in order, over the same partitions — shards on the per-shard arm, the block-aligned segments on the decode arm — under the layer's own projection (`processing.TotalsPrepassRequest(req, exts, layer)`: filters, weights, zones, the stages a layer-L `total()` argument reads — an earlier layer's formula among them whole — and each layer-L formula reduced to its arguments — never a field only a formula's row expression or an aggregation reads; `TestTotalsPrepass_ProjectionNarrowsToTotalInputs`, `TestTotalsPrepass_MultiLayerProjectsPerLayer`): each worker builds a `processing.TotalsPrepass` for layer L with every earlier layer's published values bound (`PublishTotals`; a missing one is `PROCESSING_INTERNAL`, never a 0) and folds its filter-passing rows (the stages a layer-L argument reads, in declared order, then each layer-L formula's `PrePass` — the serial layer-L scan's record state), the workers' states merge through `MergeableTotals.PartialTotals` / `AbsorbTotals` (binned `reprosum` sums, integer counts — order-free, so the merged totals are the serial pre-pass bits) and `Publish` finalizes them beside the earlier layers' values (the next layer's prior; after the last, everything phase 2 binds). Phase 2 is the ordinary reduce: `buildRowLocalAttrSpecs` binds each partition's formula through `PublishedTotals.Bind` → `PublishTotals` before its first row (an unbound one refuses, never reads 0). Predict follows the shared gate (`ShardFanOut` / `DecodeFanOut`: `TestShardFanOut_PredictMatchesRuntime`, `TestDecodeFanOut_PredictMatchesRuntime`) and `PULSE_ADVISORY_EXTRA_PASS` stays one added scan per formula (each sits in one layer). **The chain stays out:** `ChainRefusal` judges with `total()` admission off (a stage has no two-phase runtime), so every `total()` stage keeps `PULSE_CHAIN_NOT_MERGEABLE` with the row-local reason, runtime and validator alike (`TestChainGate_ValidatorMatchesRuntime`). Gates: the bit-exactness family `TestBitExact_Archive` / `TestBitExact_Heavy` (DecodeWorkers 2/3/7/8, ShardWorkers 2/3/8 on a scattered nine-shard archive, each parallel cell required to fan out, == the serial bits; plain, weighted, filtered share-over-label, matrix-beside, grouped and three-layer (ungrouped and grouped) `formula_total*` shapes), `TestParallelTotals`, `TestTotalsPrepass_*` (`_MultiLayerPartitionMergeEqualsSerial`: any partition, layer by layer, == the serial buffered bits), `TestFormulaTotal_PartitionedRouting`, the fan-out parity tests' multi-layer shapes.
