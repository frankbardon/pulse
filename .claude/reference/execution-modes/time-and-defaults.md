# Execution modes — time zones, date-family types, labeled date ranges, smart defaults

Per-topic slice of the execution-modes reference. Index (Mode index + section map): `.claude/reference/execution-modes.md` — load it first, then only the slice(s) your engine work touches.

## Time zones

Long form of CLAUDE.md's "Date-family field types" zone clause. Storage stays UTC epoch; a zone is a request-time configuration that is resolved, validated, echoed and — on a `datetime` field of a zone-aware operator — applied: the instant is read on its LOCAL calendar day. It is refused wherever it would otherwise be silently ignored (a derived field).

**One home for date math.** Epoch-day, calendar and zone math lives in `internal/temporal` (a leaf over stdlib + `errors`; it must not import `encoding`). The public `encoding` date helpers (`ParseDate`, `ParseDateTime`, `FormatDateTime`, `DateTimeToDay`, `SecondsPerDay`) keep their frozen signatures and forward into it. `internal/processing/date_field.go` remains the OPERATOR-boundary adapter: a `datetime` (epoch seconds) is day-truncated exactly once there — toward the past, never rounding (`1969-12-31T23:59:59Z` is UTC day −1, not day 0) — by `DateTimeToDay` when no zone applies, or by `temporal.LocalDay` in the slot's resolved non-UTC zone (`resolveDateField` decides once at construction, `dateField.epochDay` per record; a nil zone is exactly the zone-free path, so UTC / absent costs nothing) — and everything downstream speaks epoch days. `GROUP_DATE`, `GROUP_DATE_RANGES` and `FILTER_DATE_RANGES` read the zone there, so `GROUP_DATE` keys and `period_start` / `period_end` are local calendar labels with no format change and range literals are local days. `TestNoZoneMathOutsideTemporal` (root `zone_math_gate_test.go`, `go/ast`) fails on the int literal `86400`, any `SecondsPerDay` reference, `time.LoadLocation` / `LoadLocationFromTZData` / `FixedZone` / `Local`, a dot-import of `time`, or a `time/tzdata` import anywhere outside `internal/temporal`; the sole allow-list entry is the `encoding.SecondsPerDay` re-export declaration. `.In(` is deliberately not banned — with every means of obtaining a non-UTC location banned, only `time.UTC` can reach it.

**`Zone`.** `temporal.LoadZone(name)` accepts exactly `UTC` (the `temporal.UTC` sentinel) or an IANA `Area/Location` name (contains `/`, each segment opens with an ASCII upper-case letter) with an exact, case-sensitive entry in Pulse's own embedded `internal/temporal/zoneinfo.zip` (release `temporal.TZDataVersion`, hash-pinned by `TestTZDataVersion_MatchesEmbeddedZip`; refresh with `make tzdata`). `$ZONEINFO`, host zoneinfo and `time/tzdata` are never consulted, so acceptance and offsets are host-independent (`TestLoadZone_IgnoresHostZoneinfo`). `EST`, `EST5EDT`, `GMT`, `Local`, `""` and offset strings (`+05:00`) are `PULSE_TIMEZONE_UNKNOWN` with the name under `details.tz`. Offset lookup is allocation-free, amortized O(1): a transition table built from `Time.ZoneBounds` over 1900–2100, binary search plus a last-span cache, `time.In` fallback outside the window. `LocalDay`, `LocalMidnightUTC` and `LocalParts` are the primitives zone-aware operators consume. `(*Zone).IsUTC()` is true for the sentinel and every fixed-zero-offset zone (`Etc/UTC`, `Etc/GMT`, `Etc/Zulu`, `Etc/UCT`, `Etc/GMT-0`). A per-instance `temporal.Cache` (built in `pulse.New`) memoises loads so a request does not rebuild a transition table.

**Wire.** `Request.TimeZone` / `FacetRequest.TimeZone` (`time_zone`) and per-slot `TimeZone` (`tz`) on `types.Group`, `Filterer`, `Attribute`, `Feature` — all additive `omitempty`, `format_version` stays `"1.1"`. `ComposedRequest` / `ChainRequest` carry no zone of their own (each inner `Request` does); `SampleRequest` has none. `pulse.Options.DefaultTimeZone` (`""` = UTC) is validated at `pulse.New` (unknown → `PULSE_TIMEZONE_UNKNOWN`) and a non-UTC default is ACCEPTED there (it applies wherever it resolves onto a `datetime` slot). No env var and no CLI default-zone flag (decided in U14); `skills/time-zones.md` is the agent-facing form.

**Capability.** `internal/descriptor/capabilities_zone.go` is the single declaration table (`ZoneCapabilityOf` / `IsZoneCapable`), projected onto the manifest `zone` key of an operator entry (`descriptor.Operator.Zone`) or an overlay kind entry (`descriptor.OverlayCapability.Zone`): `capable` on `GROUP_DATE`, `GROUP_DATE_RANGES`, `FILTER_DATE_RANGES`, `ATTR_DATE_PART`, `FEAT_DATE_FEATURES`; `following` on `OVERLAY_YOY` (no `tz` slot — it inherits its host grouper's zone, because a disagreeing overlay zone would be meaningless); absent everywhere else. Extension operators are never zone-capable. Windows are excluded (no time-based window exists).

**Resolution.** `internal/descriptor/zone_resolve.go` — `ResolveZones(req, schema, defaultZone, load)` / `ResolveFacetZones` — is pure, never mutates the request, and is the ONE pass both runtime and predict call, so they accept and refuse identically. Precedence per zone-capable slot: slot `tz` → request `time_zone` → `Options.DefaultTimeZone` → `UTC`. Refusal order:

1. unknown `time_zone` / default zone → `PULSE_TIMEZONE_UNKNOWN {tz}` — even with no zone-capable slot;
2. explicit `tz` on a non-capable operator (built-in or extension) → `PROCESSING_CONFIG {slot, operator, tz}`;
3. explicit `tz` on a field present in the schema that is not `datetime` (a calendar `date`, or the epoch-day count `GROUP_DATE` tolerates) — even `"UTC"` → `PROCESSING_CONFIG {slot, operator, tz, field, field_type}` (`TestDateFieldRejectsTZ`);
4. unknown slot `tz` → `PULSE_TIMEZONE_UNKNOWN {slot, tz}`;
5. a non-UTC-equivalent zone resolving onto a field ABSENT from the schema (a derived or chain-synthesised column; a JOINED column is in the joined schema and resolves by its own type) → `PROCESSING_CONFIG {slot, operator, tz}`, message "… a zone cannot be applied to a derived field …" — the operators read an absent field as epoch DAYS, so the zone would be silently ignored (`TestTimeZone_DerivedFieldRefusedEveryMode`). Onto a `datetime` schema field it is ACCEPTED and applied (`TestTimeZone_LocalDayEveryMode`).

**Per-row zones (U50).** Sibling plain-string slots `tz_field` (slot) / `time_zone_field` (`Request`, `FacetRequest`) name a `categorical_*` cohort field of IANA names; precedence slot `tz` → slot `tz_field` → `time_zone_field` → `time_zone` → default → `UTC`, in the same `ResolveZones` pass (`resolveFieldZone`). Refusals: `tz` + `tz_field` on one slot, `tz_field` on a non-capable operator or explicit on a non-`datetime` field, a non-categorical zone field (`{slot, operator, tz_field, field, field_type}`) and a zone field onto a derived field → `PROCESSING_CONFIG`; a dictionary entry `temporal.ValidZoneName` refuses → `PULSE_TIMEZONE_UNKNOWN {slot, field, tz, dictionary_index}`; a zone field absent from the executing schema (joined / chain-stage included) → the field-reference pass's `SERVICE_VALIDATION` (`checkZoneFields`, schema-only). An inherited field on a `date` slot is neither applied nor judged. Echo `source: "field"`, `tz_field`, `tz: null`; `ZonedRequest` writes an inherited field into `tz_field` (second write-set). Expressions (`to_day`) stay request-zone only. **Runtime (E1-S2):** each operator builds a `temporal.ZoneTable` from the zone field's dictionary at construction (`resolveDateField` / the `FEAT_DATE_FEATURES` computer; one table, forked per constructed operator, so per worker; a shard dictionary is a prefix of the canonical one) and reads the row's code per record — no per-row allocation (`TestPerRowZone_OperatorsAllocationFree`). A NULL zone cell makes the row's local value null, never UTC: `GROUP_DATE` / `GROUP_DATE_RANGES` (and a `MAT_DISTANCE` between) key it into no bucket (grouper `n_null`), `ATTR_DATE_PART` / every `FEAT_DATE_FEATURES` column is null (aggregation `n_null`), `FILTER_DATE_RANGES` drops it like a null date and counts it in `n_null_input`. Every zone field joins `processing.NeededFields` (`requestZoneFields`: request + every slot, crosstab axes, between) — omitted, projected decode reads it null and every row drops silently — and a filter's zone field is a filter-precompute input. `OVERLAY_YOY` follows its host's keys. Proof: `TestTimeZoneField_PerRowEqualsSingleZoneSlotsEveryMode` (per-row ≡ N single-zone slots combined ≡ `time.In`, every arm), `TestTimeZoneField_NullZoneCellIsNullLocalValue`, `TestTimeZoneField_RefusalsPredictMatchRuntime`. Import's per-row source zone (`source_tz_field`, E1-S3) is a separate seam: `internal/io/import_zone.go`, `column_source_tz` wins, empty cell → `source_tz` else row error, unknown name → skipped-row `PULSE_TIMEZONE_UNKNOWN`.

A slot with an EMPTY operator `Type` (defaults disabled, or no default rule fits) is skipped — it is a type error, reported by operator construction (`PROCESSING_CONFIG "unknown group type: "` and siblings) with or without a `tz`, never as a zone-capability refusal. A NIL schema (only a validator with no cohort schema in reach) skips rules 3 and 5, so a schema-less check never refuses what the schema-holding runtime accepts.

An INHERITED zone on a non-`datetime` field is not applied and echoes `tz: null`. `ATTR_DATE_PART` / `FEAT_DATE_FEATURES` accept `date` and `datetime`: over a `datetime` they read the resolved zone's wall clock (`temporal.LocalParts`; part / column `hour` is `datetime`-only, and ATTR `iso_weekday` / FEAT `dow` are ISO 1..7, Monday = 1 — the local day — never following `week_start`; `dow` was Sunday = 0 before U50; a null source cell is null on both, never `0`, in every mode — `TestDatePart_NullInputIsNullEveryMode`, `TestDateFeatures_NullInputIsNullEveryMode`), over a `date` an explicit `tz` is refused (rule 3) and an inherited one is never applied. Their field rules are read once, by `internal/datepart` (ATTR) and the predict feature check, so predict and runtime refuse alike. A UTC-equivalent zone is never refused and output is byte-identical to no zone (`TestUTCZoneIsIdentity`); the echo keeps the caller's spelling. Slot paths: `filterers[i]`, `features[i]`, `attributes[i]`, `groups[i]`, `crosstab.rows[i]`, `crosstab.columns[i]`, then each `MAT_DISTANCE` `matrices[i].params.between` (a grouper slot inside params; `ZonedRequest` writes its inherited zone into a copy of the params — `matrix-and-vectors.md`), walked in that order.

**Call sites (one per mode).** `Service.SetTimeZones` is installed at `pulse.New`; the service resolves once per Request after `applyDefaults` in the Process main arm, `processCrosstab`, `processWithJoin` (against the joined schema), `ProcessChain` (every stage, BEFORE the chain gate — stage 0 explicitly against the cohort schema, unless it carries a join, which resolves inside Process), `FacetSchema` and `Materialize`, and once per predicate in the `FilterToFile*` family (`buildSingleFilter`: a synthetic `Request{Filterers, TimeZone}` through `resolveZones` + `zoned`, `TimeZone` being `FilterToFileRequest.TimeZone` — validated up front by the facade, unknown → `PULSE_TIMEZONE_UNKNOWN` — so `to_day()` reads it, else `Options.DefaultTimeZone`; the resolved non-UTC zone joins the `FilterToFileWithRequest` dedup hash via `descx.ExpressionZone`, `TestTimeZone_FilterToFileRequestZone`; its structured `Filterers` refuse `FILTER_DATE_RANGES` and every other untranslatable type `PROCESSING_CONFIG {operator}`). `ProcessStream`, `ProcessStreamResult`, `Compose` and `ComposeParallel` inherit through Process. Every public executing entry point is pinned by `TestTimeZone_DefaultZoneReachesEveryEntryPoint`; Sample, Lookup, Dedup, BuildIndex and CountRecords run no filter or expression. **Applying the zone.** The operator factories see only `(slot, schema)`, so each mode hands its arm `descx.ZonedRequest(req, zones, loader)` (`ZonedFacetRequest` for facet; `Service.zoned`) right after its last caller-visible mutation (auto labels): a shallow copy whose slots that INHERITED a non-UTC zone are copies carrying it in `tz` — or `req` itself when there is none (zone-free and UTC requests run the unchanged object). An explicit slot `tz` is already on the slot; an inherited zone on a `date` field resolved to null and is never written. Every arm built from it — buffered, streaming, fused crosstab and its gate probe, parallel decode, shard reduce, chain stages ≥1 — sees the zone with no further plumbing; the factory loads the name through a process-wide `temporal.Cache` in `internal/processing` (zones are immutable and built from the one embedded tz database). The caller's request is never written, so the request echo, `Request.Hash` / `ComposedRequest.Hash` and the Compose echo show it as written (`TestTimeZone_ZoneWriteLeavesCallerRequestPristine`). **Location:** a Compose refusal keeps its message prefix `request N:` and adds `details.request` (0-based slot) on the serial and the `FailFast` parallel path (`FailFast=false` still aggregates into `SERVICE_INTERNAL`); a chain refusal adds `details.stage` (0-based). Both are copies of the resolver's coded error, so the code survives `errors.As` and the CLI envelope (`TestTimeZone_RefusalCarriesLocation`, `TestAPI_TimeZoneRefusalKeepsItsCode`). The service marks a **located refusal** where it is raised (`locatedRefusal` in `internal/service/located.go`, unwrapping to the coded error; `locate` copies it through `descx.RefusalAt`) — the zone refusals and the join-count refusal — so only those gain a location; the validators call `RefusalAt` at the same points, so the location matches. `FilterToFileWithRequest` refuses any filterer `tz` (`PROCESSING_CONFIG {operator, tz}`).

**Predict and the validators.** Predict resolves on the defaults-resolved clone (`PredictOptions.DefaultTimeZone` / `ZoneLoader`, which the facade fills from the service) and echoes `PredictResult.TimeZones` — `"time_zones": [{slot, operator, field_type (omitempty), tz (string|null), source}]`, `source` ∈ `slot|request|options|default` (`descriptor.ZoneSource*`), never nil, zone-capable slots only (`OVERLAY_YOY` not listed); a refusal is a predict error (`Valid=false`). For a single `JoinSpec` predict reads the right cohort's header + schema through `PredictOptions.SchemaLoader` (the facade passes the runtime's own `Service.Open`) and validates the whole request against `internal/encoding.JoinedSchema` — the one join-schema rule `processing.JoinedSchema` delegates to — so a joined `date` field echoes `tz: null`, a joined `datetime` echoes its zone and a name in neither schema refuses exactly as runtime does (`TestTimeZone_JoinPredictMatchesRuntime`). `PredictOptions.DisableDefaults` (facade: `Options.DisableDefaults`) validates the request as written; `DefaultsApplied` then lists what WOULD apply. Predict reports any top-level slot still without a `Type` with the runtime's own `PROCESSING_CONFIG` message (`validateOperatorTypes`; `TestTimeZone_DisableDefaultsSameErrorBothSides`). `ValidateComposeWithOptions`, `ValidateChainWithOptions` and `ValidateFacetWithOptions` run the same pass (defaults on a clone unless disabled, then `ResolveZones` / `ResolveFacetZones`) and record each refusal with the runtime's code, message and details, location included; Compose reads each slot's schema through `SchemaLoader` and resolves schema-less without one (`TestTimeZone_ValidatorsMatchRuntime`). `ValidateChain*` also runs the chain gate, the field checks and the next stage's synthesised schema (whose `<TYPE>_<field>` labels embed a defaulted Type) on each stage AFTER the shared `ResolveDefaults` pass against its input schema — the cohort's for stage 0, even when it joins — unless `DisableDefaults`, exactly as the runtime's `applyDefaults` does; the echoed request stays as written (`TestChainDefaults_ValidatorMatchesRuntime`). The gate is the shared `internal/mergegate.ChainRefusal` on both sides (see ProcessChain), so code, message and details `{stage_index, stage_name}` match. **Join count.** `internal/descriptor.JoinCountRefusal` is the one v1 rule — more than one `JoinSpec` → `PULSE_JOIN_TOO_MANY "v1 supports exactly one JoinSpec per Request" {count}`. Runtime `Process` applies it first (after the cohort check, before the crosstab and join dispatch, so a crosstab is covered too); predict right after the header + schema read, before the joined schema and defaults; the Compose validator per slot before that slot's zones; the chain validator on stage 0 after the gate and before its joined-schema zones (a joined stage 0 resolves zones inside Process). It is a located refusal: inside Compose it gains `details.request` (serial and `FailFast` parallel), on chain stage 0 `details.stage`; predict and a single `Process` add none (`TestJoinTooMany_PredictAndValidatorsMatchRuntime`, `TestJoinTooMany_LocatedInsideComposeAndChain`). Chain stages ≥1 never reach it: their `Joins` is `PULSE_CHAIN_STAGE_JOIN` first. **Join keys.** `internal/encoding.JoinKeysRefusals(left, right, spec)` is the one kind / OnPair rule, in runtime order: no OnPair (`PULSE_JOIN_KEYS_EMPTY`), a kind other than inner, then per pair a blank side, an unknown left then right key (`PULSE_JOIN_FIELD_UNKNOWN {field, index}`), incompatible key types (`PULSE_JOIN_TYPE_MISMATCH`, the set-key sentence `JoinKeySetRejection`). The service applies it as soon as both cohorts are open — before the right side is decoded — as a located refusal, and `NewHashJoinIterator` re-applies it; predict reports every entry once `SchemaLoader` reads the right schema, `ValidateJoin` the same; the Compose slot validator and the chain stage-0 validator report it located and stop there (it precedes zones and field references). **Field references.** `internal/descriptor.FieldRefRefusals(req, schema, snap)` is the one unknown-name rule. Every execution mode calls `Service.checkFieldRefs` (its first entry, `FieldRefRefusal`) right after `resolveZones`, against the schema the request executes over — the cohort's in `Process` / `processCrosstab` (both crosstab arms, so fused and buffered agree), the joined schema in `processWithJoin` / `processCrosstabWithJoin`, the synthesised stage schema on chain stages ≥1 (after the gate); ProcessStream, Compose and chain stage 0 reach it through `Process`; `FacetSchema` applies its filterer half (`FacetFieldRefRefusals`, against the cohort schema) right after `resolveFacetZones`, so a FACET-host overlay request is covered, and `ValidateFacet` reports every entry at that point (`TestFieldRefs_FacetFiltererRefusedLikeValidator`). `FilterToFileWithRequest` with structured `Filterers` applies the filterer half too (`Service.FilterToFileFilterers`, against the cohort schema — the canonical one for an archive — before the translated expression compiles; `TestFilterToFile_FilterersRefusedLikeProcess`). It is a located refusal (`details.request` / `details.stage`). Predict reports every entry after zones; `validateComposeSlots` after the slot's zones on the defaulted slot; `ValidateChain*` after the gate, against the joined schema for a joined stage 0 (defaults re-applied against it, as `processWithJoin` does) — none once an earlier located refusal on that slot / stage fired. The walk is PIPELINE order: features see the schema and earlier features' outputs (`Field`, `FEAT_TARGET_ENCODE` `params.target` and its `params.fit_on` expression — compiled, so a later or own label is `PULSE_FORMULA_COMPILE_ERROR` — `FEAT_TRAIN_TEST_SPLIT` `params.stratify`); filterers see features but NOT attribute labels (attributes run after filters); each attribute sees earlier attributes' labels (`ATTR_FORMULA` may omit `Field`; `ATTR_REG_*` judge `Target` / `Predictors`); tier-1 tests, regressions, groups, aggregations and crosstab rows / columns / cell / `margin_aggregations` see every attribute label; windows (order_by, partition_by, and `Field` only on a value-bearing operator), sort and post-tests see the OUTPUT row columns — group fields + aggregation labels (`<TYPE>_<field>` with a defaulted Type), or the record columns when there are neither, plus earlier windows' labels (sort / post-tests see all) — a window `order_by` key that is a schema field is also judged by `IsOrderableType` (every type but `set_*`, the types the window comparator orders by value; `PULSE_WINDOW_INVALID "window[i]: order_by field F is not orderable (type T)"` on both sides, `TestWindowOrderBy_OrderabilityPredictMatchesRuntime`); a crosstab's post-tests run over cell rows and are not judged. An extension feature (outputs unnameable without executing) opens the set for everything after it. **Shadowing.** A derived column whose name is already available at its producer's point — an attribute label (or default label) equal to a schema field, feature output or earlier attribute label; a feature output equal to a schema field or earlier output; a window label equal to an output-row column or earlier window label — is refused `SERVICE_VALIDATION` `"attribute label <l> shadows an existing field"` `{label, attribute}` / `"feature <TYPE> output <l> shadows an existing field"` `{label, feature}` / `"window[i] label <l> shadows an existing column"` `{window_index, label, type}`. Writing it overwrote the column in place, and the arms disagreed (buffered `applyAttributes` kept a nullable field's null mark through `injectValue`, the streaming orchestrator cleared it with `Set`); no documented request relied on the overwrite, so both sides refuse (`TestLabelShadow_RefusedOnEverySide`). It supersedes predict's former warning-level window label collision. A name only an extension feature might produce is not judged. Aggregation labels are judged too (Output namespace, below). **Names inside params** are judged at the operator's own pipeline point: the built-in aggregation params (`aggParamFieldKeys` — `AGG_WEIGHTED_MEAN` `weight_field`, `AGG_RATIO` `numerator_field` / `denominator_field`, `AGG_DISTINCT_SUM` `distinct_by`, on every aggregation slot including crosstab cell and `margin_aggregations`; message `"<slot> <TYPE>: params.<key> references unknown field <f>"`, details `{field, param, aggregation|role}`), the post-test output-column params (`TEST_ANOVA_F` / `TEST_ANOVA_WELCH` `n_col` / `variance_col`, an explicit `TEST_TUKEY_HSD` `n_column`), and an extension's own declaration — `ExtensionsSnapshot.FieldInputs` carries every registration's `FieldInputs` hook (the projection hook, keyed `<category>|<name>`; row tests only), the service passes its snapshot to the rule so both sides call the same hook with the slot's `Params` (`nil` for a filterer) and refuse `"<category> <NAME>: FieldInputs references unknown field <f>"` with `field_inputs: true`; a hook that panics is undeclared (nothing judged), an extension without one is not judged (`TestFieldRefs_ParamFieldsRefusedLikePredict`, `TestFieldRefs_ExtensionFieldInputsJudged`, `TestFieldRefRefusals_ParamsAndFieldInputs`). Empty names are refused where the slot requires one (aggregation, group, attribute but `ATTR_FORMULA`, regression predictor, every built-in filterer but `FILTER_EXPRESSION` — an extension filterer's `Field` is its own business), even after an extension feature opened the set, with the slot's unknown-field message naming `""` (`TestFieldRefs_EmptyFilterFieldRefusedLikePredict`). Gates: `TestFieldRefs_*`, `TestJoinKeys_UnknownKeyRefusedLikeRuntime`, `TestFieldRefRefusals_*`, `TestJoinKeysRefusals_*`.

**Output namespace.** An aggregation label (explicit, or `<TYPE>_<field>` with a defaulted Type) equal to a group field or to an earlier aggregation's label is refused the same way — `"aggregation[i] label <l> collides with group[j] field <l>"` `{label, aggregation_index, aggregation, group_index, group}` / `"aggregation[i] label <l> collides with aggregation[j] label <l>"` `{label, aggregation_index, aggregation, other_aggregation_index, other_aggregation}` — because an output row holds one value per name: the group key is written after the aggregations (the aggregation vanished) and a duplicate label kept only the last figure, on every arm (`TestOutputNamespace_CollisionRefusedOnEverySide`, `TestOutputNamespace_DistinctNamesAccepted`, located inside Compose and on every chain stage, the final one included — `ChainOutputSchema`'s own `PROCESSING_CONFIG` collision only ever saw a non-final stage and is now unreachable behind it). A label equal to the field it reads or to an attribute label is not a collision (neither is an output column); a crosstab's top-level labels are not judged (its output is the cell grid, whose cell / `margin_aggregations` labels `MarginAggregationFaults` already keeps distinct). Tests and regressions emit slices, not row columns, so their labels cannot collide.

## Date-family field types

**Date-family field types.** `GROUP_DATE`, `GROUP_DATE_RANGES` and `FILTER_DATE_RANGES` accept BOTH temporal types — `date` (epoch days, `int32`) and `datetime` (epoch seconds, `int64`). Past the operator boundary (`internal/processing/date_field.go`) everything speaks epoch DAYS: a `datetime` is day-truncated once there, toward the past, naive UTC (`1969-12-31T23:59:59Z` is day −1). **All epoch-day / calendar / zone math lives in `internal/temporal`** (`encoding` forwards); `TestNoZoneMathOutsideTemporal` bans `86400` / zone loading elsewhere. `GROUP_DATE_RANGES` / `FILTER_DATE_RANGES` reject any other field type with `PROCESSING_CONFIG`; `GROUP_DATE` stays non-validating and reads a non-temporal `Field` as an epoch-day count — except `component: hour`, the one sub-day bucket, which reads the local epoch HOUR (`temporal.LocalHour`; key `YYYY-MM-DDTHH`, the skipped DST hour has no bucket and the repeated one is ONE) and refuses any field that is not a `datetime` schema field. `week_start` (`week` only, default `monday` = ISO `YYYY-Www`) keys any other start by the week's first local date. Both params are read once, by `internal/dategroup`, for the factory and predict alike. `ATTR_DATE_PART` / `FEAT_DATE_FEATURES` also take both types (see Time zones). **Zones:** request `time_zone` and slot `tz` (manifest `zone: capable` operators) resolve slot → request → `Options.DefaultTimeZone` → UTC; a `datetime` is read on its local day in that zone, and non-UTC on a derived field is `PROCESSING_CONFIG`. See `execution-modes.md` (Time zones).

## Labeled date ranges

Relocated verbatim from CLAUDE.md (Smart defaults). `GROUP_DATE_RANGES` (explicit-only) and `FILTER_DATE_RANGES` share one compiled `{label, start, end}` model (`daterange.Compile`): inline `ranges` XOR a named `table:` (`RangeTable`). Structured ranges ride the additive `omitempty` `types.Filterer.Params` slot — `format_version` stays `"1.1"`. **Zones:** range literals are LOCAL calendar days in the slot's resolved zone (Time zones); over a `datetime` the record side is floored to its local day by `temporal.LocalDay` and matched on day numbers, so the compiled model is zone-free. A `RangeTable` is calendar-only — no table-level `tz` — and follows the referencing slot's zone exactly like inline `ranges`. Proven by `TestTimeZone_DateRangeBoundsAreLocalDays` + `TestTimeZone_DateRangesLocalDayEveryArm`. Skills: `skills/op-group-date-ranges.md`, `skills/op-filter-date-ranges.md`. **Typed tables (U49 E2-S4).** A `RangeTable` is typed by its bounds — ISO strings a date table (`Ranges`), numbers a numeric one (`NumericRanges`, half-open `[start, end)`, `numrange.Compile`) read only by `GROUP_NUMERIC_RANGES`; either side naming the other kind is `PULSE_RANGE_TABLE_KIND_MISMATCH`, which predict raises too (`validateRangeOperatorParams`, with the unknown-table code). `TestNumericRanges_RefusalsPredictMatchesRuntime`, `TestRangeTables_TypedByBounds`.

## Smart defaults

(Relocated from CLAUDE.md at recommend-explain E1-S1.)

When a request slot names a field but omits `Type`, engine infers from schema type. Table in `internal/descriptor/defaults.go` (`defaultRules`).

| Field type | Default aggregation | Default grouper |
|---|---|---|
| numeric (u4/u8/u16/u32/u64, f32/f64, decimal128) | `AGG_SUM` | `GROUP_RANGE` (Interval 10) |
| categorical_* | `AGG_MODE_COUNT` | `GROUP_CATEGORY` |
| `date` | (explicit only) | `GROUP_DATE` (`"day"`) |
| `datetime` | (explicit only) | `GROUP_DATE` (`"day"`) |
| `packed_bool` | `AGG_MODE_COUNT` | `GROUP_CATEGORY` |

`Field.Nullable` never changes the inferred operator. The crosstab cell — and each measure of a multi-measure `crosstab.cells` (U47 E2-S2) — is an aggregation slot and takes the aggregation default (`DefaultApplied.Path` `["Crosstab", "Cell", "Type"]` / `["Crosstab", "Cells", i, "Type"]`); before E2-S2 an untyped cell was refused. Defaults apply only when `Field` is set and `Type` empty; never override `Type`, cross categories, or default tests, filter expressions, attributes, windows, features. Disable via `pulse.Options{DisableDefaults: true}` or `--no-defaults`. Predict always computes `DefaultsApplied`.

**Metric defaults (U27 E1-S3).** One more fill rides the same pass: a metric-taking matrix slot (`vectors.MatrixMetricConsumer` — `MAT_DISTANCE` today) that reads a `kind`-declared vector BY NAME and names no `params.metric` (absent or `null`) gets the kind's default for its consumer (`vectors.MatrixMetricDefaults` → `metric.DefaultFor`: the kind's table default when the consumer accepts it, else the first accepted metric suiting the kind, never a poor fit; under `MAT_DISTANCE` `standardize` the non-negative-domain metrics are skipped). `resolveMetricDefaults` (`internal/descriptor/defaults.go`) rewrites the slot's `Params` on a COPY of the `Matrices` slice and reports `DefaultApplied{Path: ["Matrices", i, "Params", "metric"], Field: <vector>, Type: <metric>, Category: "metric"}`, the reason naming a fallback. It honours `DisableDefaults` and a hidden operator like every other default, and never fills an inline-`fields` slot or a kind-free vector (`MAT_DISTANCE` then keeps its implicit `euclidean`). Runtime and predict run the same pass, so the metric predict reports is the one executed (`TestVectorKind_MetricDefaultMatchesRuntime`, `TestPredict_MetricDefaultsApplied`).
