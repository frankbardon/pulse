## Overlays

`Request.Overlays []*OverlaySpec`, `Response.Overlays []*OverlayLayer`. Additive post-result decorations attached to an already-computed base result. Each spec produces one `OverlayLayer` in matching slot order; layers carry the host-shape payload and **never mutate the base payload** — overlays are read-only siblings keyed to host coordinates. The catalog is `types.AllOverlayKinds()` + `types.OverlayStreamability`; per-kind capability is `descriptor.overlayCapabilityFor` (surfaced on `Manifest.Overlays`). To find a kind's handler, validator and skill, run `make sites ARGS="op <OVERLAY_KIND>"`.

**Streamability.** Every flag in `OverlayStreamability` is `false`. A crosstab carrying overlays still runs fused — the MATRIX fold runs at the fused exit, post-`Finalize`, not in-pass. **One streamability rule:** `overlayhost.StreamReasons` lists every spec that routes a request off the streaming arm (an extension kind, an unknown or hidden kind, a kind off its slot / host shape or refused on a SCALAR host, a `false` flag); the runtime streams iff it is empty and predict appends its reasons, so `PredictResult.Streamable` matches the arm (`TestExtensions_OverlayStreamableMatchesRuntime`). Crosstab fusion is unaffected. `Request.Overlays` is `omitempty`, so `Request.Hash` stays byte-identical for requests that omit it. Base failures: `PULSE_OVERLAY_KIND_UNKNOWN`, `PULSE_OVERLAY_SCOPE_UNSUPPORTED`, `PULSE_OVERLAY_REF_INCOMPATIBLE_WITH_SHAPE` (also a kind on the wrong slot or shape — Overlay slot, below), `PULSE_OVERLAY_LEVEL_OUT_OF_RANGE`.

**Level / Within composition.** The share / index / delta / zscore family honours `OverlaySpec.Level` (same-axis prefix truncation) and `OverlaySpec.Within` (opposite-axis prefix fixing). `Level=0, Within=0` keeps the leaf-margin denominator and is byte-identical to a spec without them. Composition mirrors the buffered crosstab `normalize_level` / `normalize_within` semantics (byte-equivalent for summable cell aggregators) through the same prefix-key helpers. Out-of-range values fire `PULSE_OVERLAY_LEVEL_OUT_OF_RANGE` at predict and runtime; the χ² / Fisher inferential family rejects non-zero values with the same code (implicit-margin contract).

**Excluded overlays are not folded.** Every request-host fold and the Compose barrier consult the run's `processing.ComputePlan`: a layer a `return` excludes runs no handler and raises nothing unless a resolved multiplicity family claims it; dispatch (streaming, fusion) still reads the original request. Long form: `.claude/reference/response-components.md` (the Compute plan paragraph, Overlays).

**Hosts.** `internal/overlayhost` declares which slot runs each kind and, for `Request.Overlays`, which Process shape(s):

- **MATRIX (crosstab)** — `applyOverlaysToResponse` (`internal/processing/crosstab.go`) runs from BOTH the buffered and fused exits.
- **SERIES (grouped Process, groups + aggregations, no crosstab)** — `processing.ApplyOverlaysSeries` at the grouped exit, buffered and streaming. No-op when there are no overlays, a crosstab, or no `Groups`. A request mixing streamable and non-streamable kinds goes buffered whole. Long form: `overlays-series.md`.
- **FACET** — `FacetRequest.Overlays` folded at the `FacetSchema` exit (`internal/service/facet_rich.go`). The FACET kinds attach only there; on `Request.Overlays` they are refused with a redirect message. Per-spec host field via `params.field`; the population side recurses `FacetSchema` against `Ref.Population.Cohort`, cached per cohort + field. Predict: `descriptor.ValidateFacetOverlays` (CHISQ rejects numeric hosts; KS rejects categorical ones). `Manifest.Facet.SupportedOverlayKinds` is the list.
- **CHAIN** — `processing.ApplyChainOverlays` at the post-stage-loop barrier of `ProcessChain`; per-stage `Stages[i].Request.Overlays` is left untouched.
- **COMPOSE** — `overlays-compose.md` and `execution-modes/compose-parallel-banner.md` (Parallel Compose).

**FORMULA kind.** `OVERLAY_FORMULA` is a caller-supplied expression compiled ONCE per spec through the same evaluator as `ATTR_FORMULA` / `FILTER_EXPRESSION`, run per cell / entry / scalar against a fixed per-host-shape namespace (MATRIX: `cell` / `margin_*` / `sd_*`; SERIES: `value` / `total` / `prior` / `baseline`; SCALAR: `value`; Compose hosts add `slot.<label>.{cell|value}`). Always buffered. `Extensions.ExprFunctions` widen the function surface only. Failures: `PULSE_OVERLAY_FORMULA_PARSE_ERROR` / `_TYPE_MISMATCH` / `_INVALID_IDENT`. **Request-host gate:** `formulaident.RequestSpecRefusal` runs in predict AND the runtime MATRIX / SERIES dispatch before compile, identical both sides (`TestRequestFormula_IdentRefusalMatchesPredict`).

**Contributor wiring.** Rules the LLM skill does not carry:

- **MATRIX arm.** The distinct-key slab-partition refusal (`PULSE_OVERLAY_DISTINCT_SLAB_NOT_PARTITIONED`) sits in `applyOverlaysToResponse`, twinned with predict's. A direct `processing.ApplyOverlaysWithExtensions` caller bypasses both — accepted; that entry is for embedders who own their host. Both exits also hand the host each cell's normalise-denominator floor (built only under a normalize mode on a run that folds overlays, never on the wire): the pairwise proportion kinds' default n is that base, and a host that knows its normalize mode but lacks a base skips the pair — it never reads the cell's own n.
- **Moment pairwise cell.** Predict reads the cell's declared ComponentSchema (`mean` + `variance`). **The legs read the SAMPLE variance m2/(n−1):** an unweighted `AGG_VARIANCE` / `AGG_STDDEV` cell (population m2/n) is converted through `overlayhost.SampleVariance` (n < 2 → NaN, the pair skips), equal to an `AGG_WELFORD` cell within 1e-12 relative. Compose `OVERLAY_T_CELL` / `_Z_CELL` read the same; since a `*Response` does not record its cell aggregator, the dispatcher hands the handlers each slot's `Crosstab.Cell.Type`. A component schema cannot say which variance it carries, so an extension cell is read as is and must expose the sample variance. **Components disabled:** every pairwise kind is `PULSE_OVERLAY_COMPONENTS_REQUIRED {index, kind}` on both sides.
- **Pairwise n-source predicates.** `types.PairwiseNSourceUsesWithinDepth`, `types.PairwiseNSourceSumsDistinctCells` and `types.CheckPairwiseSlabPartition` are called by BOTH predict and runtime, so message and Details cannot drift. Distinct-mode admission classifies the cell aggregator by exact component-key set; on the direct `ApplyOverlaysWithExtensions` path it classifies from the host's key SHAPE, so a modal aggregator under a distinct-bearing shape is misread there. The moment kinds' `n_source` / `p_source` refusal is predict-only for Welch t / two-means z (an inert param cannot make a wrong number; a DISTINCT mode is still refused at runtime) and both arms for the weighted kind. The panel twin is `types.CheckPanelSlabPartition`.
- **Pairwise significance letters.** `params.letters` adds the `letters` part (`internal/processing/overlay_pairwise_letters.go`): `{letter, group, higher, above}` per host cell, one comparison group per `pair_along_dim` bucket (a multi-measure ROW host one per measure bucket). `above` reads the layer ALONE (`RefreshPairwiseLetters`), so both multiplicity folds re-run it after writing the adjusted twins; an inactive plan leaves the raw-p letters. The alpha refusal is `types.PairwiseLettersRefusal`, raised on both sides.
- **Per-layer warning routing.** The chain / Compose dispatchers stamp `Details["overlay_index"] = i`; the service routes each warning to `out.Overlays[idx].Warnings` (none ⇒ `nil`; missing key ⇒ layer 0). Gates: `Test*_OverlayFreeByteIdentical`.
- **Parity overlays, cell value and p parity.** The cell t / z kinds' host cell `MatrixCell.Value` is the scalar mean (the `{n, mean, variance}` triple rides `Components`), and their p-values equal the matching row-level two-sample tests on the same inputs.
  - **Shifted moments.** `AGG_WELFORD` (weighted too) and the two-sample groups of `TEST_T` / `TEST_WELCH` / `TEST_Z_TWO_SAMPLE` accumulate `value − origin`, the origin their first value; a merge keeps the receiver's origin and re-expresses the other partial's mean about it. The components add `origin` and `shifted_mean`; a leg pair carrying both differences as `(origin_a − origin_b) + (shifted_mean_a − shifted_mean_b)` through the one shared kernel the tests use, so parity holds and a 1e12 common offset costs no digits. Any other leg differences the levels.
  - **Inputs, one rule.** `descriptor.ComposeOverlayTwoSampleInputsRefusal` (predict-compose, and the runtime before the fold, re-run against the returned Components as `PROCESSING_INTERNAL`) maps each side's `(mean, variance, n)` source: a grouped `AGG_WELFORD` row → its per-group Components (disabled → `PULSE_OVERLAY_COMPONENTS_REQUIRED`); a crosstab cell whose ComponentSchema declares `mean` + `variance` with components on → the cell Components; ANY other scalar side → `params` via `internal/twosample.Inputs` (per-side key, else symmetric `variance` / `sample_size`; finite > 0) — absent is `PULSE_OVERLAY_PARAM_MISSING` `{…, side, params, reason: params_missing}`, never a guessed var = 1, n = 2; a vs-ref kind over a crosstab slot → `PULSE_OVERLAY_REF_INCOMPATIBLE_WITH_SHAPE`.
  - **Vs-ref measure.** A grouped slot's scored measure must be a mean or carry the moments — `overlayhost.ComposeVsRefMeasureRefusal`, at predict (on the slots as executed, smart defaults applied) and in the dispatcher before the key-set gate. `AGG_AVERAGE` / `AGG_WEIGHTED_MEAN` / an `AGG_VEC_MEAN` element are means (params); `AGG_WELFORD`, `AGG_VARIANCE`, `AGG_STDDEV` and an extension declaring `mean` + `variance` read the per-group components (population variance converted to sample; absent → `PULSE_OVERLAY_COMPONENTS_REQUIRED`); anything else → `PULSE_OVERLAY_REF_INCOMPATIBLE_WITH_SHAPE` `{overlay_index, kind, slot, host, label, measure_type, reason: measure_not_mean}`, reference first; a target read differently from the reference → `PULSE_OVERLAY_SCHEMA_DIVERGENT` (reason `mixed_measure_read`). A spec a structural rule owns (unknown reference / target, mixed shapes, unknown `params.field`) is left to it.
- **Matrix measure: an undefined cell is MISSING.** The matrix twin of `overlays-series.md` (Series measure). A NaN crosstab cell (an all-null `AGG_AVERAGE` bucket, an unanswered vector element cell, a degenerate shape moment) is read by every crosstab-host kind exactly as an ABSENT cell — `CrosstabHostView.CellAt` answers `(0, false)` — so the per-kind absent-cell rule applies and fused and buffered arms agree. The reason: one NaN cell used to turn a whole Level / Within bucket's shares, or a whole z-score slice, non-finite. Consequences: share / index / delta / z-score cells are absent, no warning, out of `summary.count` and of every bucket sum and slice SD; matrix FORMULA is never evaluated there; the χ² / residual / symmetry / retention kinds read an absent observation (0); `FISHER_EXACT_CELL` has an absent p; cell-value pairwise legs skip as `PULSE_STATS_SKIP_EXTRACT_FAILED`; component-reading pairwise legs with an undefined variance skip as `PULSE_STATS_SKIP_N_TOO_SMALL` / `_VARIANCE_INVALID` — never a NaN p in a present cell. Kinds requiring `AGG_COUNT` / `AGG_SUM` cells never see NaN; a non-finite cell there stays `PULSE_OVERLAY_NONNEGATIVE_REQUIRED`. A NaN MARGIN beside a defined cell stays an undefined denominator: absent cell + `PULSE_OVERLAY_REF_ZERO` on the dividing kinds, silent on `DELTA_VS_MARGIN`; FORMULA binds the NaN. The Compose MATRIX arm of the cell-pair kinds leaves the overlay cell absent when either side is undefined. Gate: `TestCrosstabOverlays_UndefinedCellIsMissing`.
- **Overlay host shape is authored.** The Compose and whole-chain gates judge a slot's / stage's host shape off its authored Request (`processing.AuthoredHostShape`, twin of predict's inference, `TestAuthoredHostShape_MatchesDescriptor`): crosstab = matrix, groups + aggregations = series, else scalar — an ungrouped result keeps one aggregate row in `Data`, so a Response probe would call it series. A grouped-vs-ungrouped Compose pair is `PULSE_OVERLAY_SLOT_SHAPE_DIVERGENT` on both sides, Details `{index, kind, reference, target_label, reference_shape, target_shape}`. The chain answers the empty layer plus one `PULSE_OVERLAY_CHAIN_STAGE_SHAPE_DIVERGENT` WARNING on both sides with deep-equal Details; the runtime never promotes a layer warning under `Strict`, while predict-chain's Strict promotes it like every predict-root warning (`.claude/reference/predict-inspect.md` (Predicting the non-Request roots)). The bare `ApplyComposeOverlays` / `ApplyChainOverlays` keep the Response probe.
- **Chain-stage series value + key.** `OVERLAY_INDEX_VS_STAGE` / `OVERLAY_DELTA_VS_STAGE` follow the Compose rule per stage: each stage's executed Request reaches the dispatcher, which narrows target then reference (non-crosstab stages; a shallow copy, so `ChainResponse.Stages` keeps every column) to its group columns plus the aggregation `params.field` names (absent = the stage's `Aggregations[0]`). `seriesfield.ResolveChainStage` refuses an unknown label `PULSE_OVERLAY_FIELD_UNKNOWN`, Details `+{which, stage_index}`; predict-chain runs the same call on each stage as executed, so an untyped aggregation's default label is judged, not deferred. Divergent stage keys stay `PULSE_OVERLAY_REF_ZERO` layer warnings (no chain key-set gate).
- **Overlay slot.** `internal/overlayhost` declares which slot runs each kind (`request`, `compose`, `chain`, `facet`; `OVERLAY_FORMULA` alone runs on two) and owns the one refusal of a kind on any other slot: `PULSE_OVERLAY_REF_INCOMPATIBLE_WITH_SHAPE`, Details `{index, kind, host, hosts}`. Predict raises it first per spec; the runtime raises it from both Process hooks before any payload guard (so an empty or ungrouped run refuses too), every dispatch loop and the FACET service loop, honouring the `ComputePlan` mask. A kind outside the catalog (or hidden by the feature profile) takes each slot's shared unknown-kind refusal. `TestOverlayHostTable_MatchesRuntimeHandlers` pins the table to the handler tables.
- **Overlay Process shape + Compose FORMULA.** `overlayhost.Shapes` declares the Process shape(s) each `Request.Overlays` kind runs on, and `ShapeRefusal` owns the wrong-shape refusal: `PULSE_OVERLAY_REF_INCOMPATIBLE_WITH_SHAPE`, Details `{index, kind, host: "request", shape, shapes}`, judged on the AUTHORED shape (a SCALAR host refuses every kind — `overlays-matrix-kinds.md`, SCALAR host). Predict raises it right after the slot refusal; the runtime from both Process hooks and the dispatch loops. A Compose `OVERLAY_FORMULA` computes with host = the first target and shape = the reference's: MATRIX binds the target's cell / margins / SDs + `ref_cell`; SERIES `value` / `total` / `prior` + `ref_value`, per partition over 2+ groupers (`seriespartition.ComposeHostDepth`; `PULSE_OVERLAY_PARTITION_INVALID` + `slot`); SCALAR `value` + `ref`; `slot.<label>.cell|value` for every slot, aligned by key. A coordinate with no figure binds NaN (null), never 0. Its identifier gate is `internal/formulaident.ComposeRefusal`, same code, message and Details on both sides.
- **Spec refusals — one rule per host.** Crosstab spec refusals, the SERIES twin, the FACET contract and the Compose / whole-chain slot references: predict and every runtime arm call the same helper, so a bad Ref / Scope refuses with one code, message and details. Long form: `.claude/reference/execution-modes/overlays-matrix-kinds.md` (Spec refusals — one rule per host).
- **Adding an overlay kind.** Declare the constant + `AllOverlayKinds()`; add the `types/overlay_streamability.go` row; write the handler in `internal/processing/overlay_*.go`; register it in host dispatch and declare its slot (and, for `Request.Overlays`, its Process shapes and its crosstab or SERIES spec-rules row) in `internal/overlayhost`; add the predict validator (`internal/descriptor/overlay_*.go`); raise faults under the kind's own `PULSE_OVERLAY_*` code; ship `skills/op-overlay-<kebab>.md` + Purpose / Interpretation (`guided-analysis.md`).

**Weighted hosts.** Share / index kinds carry no weight logic: they read the already-weighted host payload on every arm. The `Inferential` kinds read the host's weighted floor keys for N* (the mean kinds through `CrosstabHostView.MeanLeg`, the contingency / proportion kinds through the cell / margin / base floors and the Kish scale of a Σw table), with the MATRIX arm's basis taken from the STAMPED crosstab cell weight and Compose slots' inferred from the floor keys. `OVERLAY_FISHER_EXACT_CELL` is frequency-only; `OVERLAY_PAIRWISE_TWO_MEANS_Z` / `_PROBIT_T` stay refused; the weighted twin takes an `AGG_WEIGHTED_MEAN` or weighted `AGG_AVERAGE` cell. Long form: `.claude/reference/weighting.md` (Overlays).

**Overlay knobs.** `ComposeOverlaySpec.Options` (`types.OverlayOptions`, Compose host only): `DictPrefixFast bool` (default `false`) matches Compose multi-slot overlay schemas by byte-equal dictionary PREFIX probe and requires the embedder to have verified prefix-equal dicts; `MaxPanelTargets int` (default `16`) caps Targets on multi-target Compose overlays (panel and fan-out kinds), overflow → `PULSE_OVERLAY_PANEL_TARGETS_OVER_CAP`.
