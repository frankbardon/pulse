# Weighting — Extension contract, SPSS suggestion, Feature profile, Error codes

Per-topic slice of the weighting reference (Extension contract, SPSS suggestion, Feature profile, Error codes). Index (preamble + section map): `.claude/reference/weighting.md` — load it first, then only the slice(s) your change touches.

## Extension contract

**Shipped (E4-S1).** An embedder break (v1.0.0-alpha.5; `docs/roadmap/v1.0.0-api-and-release/03-embedder-migration.md`).

- `WeightAware bool` on `AggregatorRegistration`, `AttributeRegistration`, `TestRegistration` (tier 1 and tier 2) and `MatrixOpRegistration` (U30 E1-S3: snapshot category `matrix`; a non-aware matrix operator is refused under ANY weight in force like an attribute or test; an aware one's slot is stamped and folds the weight into the engine's co-moment, the kind on `extend.MatrixInput.WeightKind`, and the manifest entry carries the weighted floor keys and both `weight_kinds` — `matrixClasses` / the default `ClassRefuse` stay built-in-only, the extension class precedes them in `ResolveWeights`); projected as `descriptor.OperatorMeta.WeightAware` — the manifest extension entry's `weight_aware` (omitempty) — and recorded on `processing.ExtensionRegistry.WeightAware`. Filterers, groupers, windows and features have no declaration: a weight never reaches them (`skipped_not_weight_aware`).
- `extend.Record.Weight() (float64, bool)` — the engine-resolved weight for the slot; only VALID weights are reported (`weighting.Classify`: finite, ≥ 0 — zero included — and an integer under `frequency`); `ok == false` ⇒ no weight in force, or the operator is not WeightAware. The engine's own row (`*processing.Record`) always answers `(0, false)` — slot weights differ within one request — so the root adapter hands a WeightAware slot a per-slot `weightedRecord` view (`slotWeighting`, `extensions_adapt.go`). **A row whose weight is invalid never reaches an aware aggregator (buffered `Aggregate` or online `UpdateRow`) or tier-1 row test; an aware attribute owes every row a value, so it still receives the row, with `Weight()` false** (decision, E4-S1). The factory sees the resolved weight on its spec: `processing.StampWeightsWith` (the registry-aware `StampWeights`) stamps aggregation slots as before and, for a WeightAware extension, `tests[i]` / `post_tests[i]` / `attributes[i]` too; any other test / attribute slot that names a weight is stamped `null`. `NewWeightRowTally` counts the stamped test and attribute slots beside the aggregation ones, so an extension slot alone still raises `PULSE_WEIGHT_INVALID_ROWS`.
- Classing (`ResolveWeights`, off `ExtensionsSnapshot.WeightAwareness`, so predict and runtime agree): aware ⇒ `applied` — including over a `decimal128` value field (the decimal refusal is the BUILT-IN decimal path's; an extension reads `DecimalValue` and owns its weighted form). A non-aware aggregator: explicit (slot or request) weight ⇒ `PULSE_EXTENSION_NOT_WEIGHT_AWARE` `{slot, operator, field}`; instance default ⇒ `skipped_not_weight_aware`, factory sees `null`. A non-aware attribute or test: refused under ANY weight in force, the instance default included (it may read the whole population, like the built-in tests and reference attributes). `weight: null` opts every one out. A hidden extension is never-registered (skipped).
- **Inferential decision (E4-S1).** A WeightAware extension TEST is applied, not refused: the registration declared that it computes a weighted result (in U11 the built-in tests still refused; since U12 they are classed per kind, which keeps the two consistent). There is no extension `REG_*` category.
- **No kind dimension (decision, U12 E1-S1).** `descriptor.OperatorMeta` carries `weight_aware` but NO `weight_kinds`, and the registration has no kinds field: a WeightAware extension is applied under BOTH kinds (`frequency` and `probability`), and the resolver never refuses it by kind. `extend.Record.Weight()` reports the value only; the kind rides the stamped slot spec the factory receives (`spec.Weight`), so an extension with no probability form must check it and refuse itself. Adding a kinds declaration is an additive embedder-API change left for demand (U34 owns extension validation).
- Floor keys: the orchestrator stamps `sum_weights` / `n_eff` / `n_weight_invalid` on an aware aggregator's slot (`WeightFloor`, every mode, crosstab cells and margins included); the extension never emits them and does not declare them in its `ComponentSchema` (the manifest lists only declared operator keys for extensions, floor excluded).
- Probe: a WeightAware aggregator, attribute or test factory is constructed both with and without a weight (`probeWeight`, a field the empty probe schema lacks) and each construction passes the same checks (streaming sibling, mode, merge); a failure of the weighted one carries `details.weighted: true` under the existing codes (`PULSE_EXTENSION_FACTORY_PANIC`, `_STREAMABLE_MISMATCH`, `_MERGEABLE_MISMATCH`). Tests are probed only when they declare WeightAware — probing every test would refuse registrations that worked.

Gates: `TestExtensionWeight_*` (root, `extensions_weight_test.go`: aware aggregator on buffered and streaming paths × slot / request / default source, crosstab cell equal to weighted `AGG_SUM` on both arms, non-aware refusals = predict, aware attribute and test, manifest projection, probe), `TestResolveWeights_ExtensionClasses`, `TestStampWeightsWith_ExtensionAwareness`, `extend` `TestRecordExposesWeight`, and the embedder smoke module's `TestExtendWeightAwareAggregator` (`make smoke`).

Recipe: `docs/src/internals/extension-points.md`; engine wiring: `architecture.md` (Extension surface).

## SPSS suggestion

Inspect reads the SPSS metadata sidecar (`cohort.pulse.spss.json`, header-only — never records) and surfaces `suggested_weight {field, source: "spss_sidecar", kind: "probability"}` (additive, omitempty) on the result and envelope, the CLI leaf and `pulse_inspect`. Predict echoes it as DATA when no weight resolves — never a warning, so `--strict` stays safe. A stale sidecar (variable not in the schema) yields no suggestion, silently. A suggested weight is **never** auto-applied, including via `DefaultWeight`; there is no manifest-level suggestion (the manifest is instance-level). SPSS `WEIGHT BY` is frequency-like, while the default `kind` is `probability` — say so wherever the suggestion is documented. **Shipped (E4-S3).** The predict / inspect contract now reads "header + schema + sidecar metadata, never records"; wiring, the silent-failure list (absent, malformed, fingerprint-stale, variable gone or not weight-capable, anchor, byte-level entry points) and gates: `predict-inspect.md` (Suggested weight). Predict also raises `PULSE_ADVISORY_WEIGHT_AVAILABLE_UNUSED` exactly when it echoes the suggestion — an advisory, never a warning (`predict-inspect.md`, Advisories).

## Feature profile

**Shipped (E4-S2).** `capability:weighting` is a request-slot capability: a `features.go` row (`Since` `1.0.0`, `descx.FeatureWeighting`) in `requestSlotCapabilities`, so it depends on any-of the request hosts. Hidden:

- the request-root `weight` and EVERY per-slot `weight` — aggregations, crosstab cell, `margin_aggregations`, tests, post-tests, regressions, attributes, overlays (facet overlays too), groups, crosstab rows / columns; inside Compose requests and chain stages too — are `PULSE_REQUEST_UNKNOWN_FIELD`, an explicit `null` included. A nested one carries `details.path` and the nested object's `valid_keys` (`nestedWeightRefusal`, `internal/descriptor/request_slots.go`);
- the payload schema, the MCP bound tool schemas, manifest `weight_aware` (built-in and extension), `weight_kinds` (every family) and the weighted floor keys, and predict `weights` are absent;
- `Options.DefaultWeight` fails `pulse.New` — `PULSE_FEATURE_PROFILE_DEPENDENCY`, `unmet: [{option: "Options.DefaultWeight", requires_any_of: ["capability:weighting"]}]`. Refused rather than ignored: an ignored default would silently change every figure an instance-level setting promised to weight;
- `AGG_WEIGHTED_MEAN.params.weight_field` stays ungated (deliberate asymmetry, `TestHiddenWeighting_WeightedMeanParamUngated`): it is the operator's own parameter, so its invalid-row warning and decimal refusal keep their codes listed while `AGG_WEIGHTED_MEAN` is enabled.

`suggested_weight` (SPSS, E4-S3) is absent too when hidden — on inspect, predict and `pulse_inspect` / `pulse_predict` (`TestSuggestedWeight_HiddenWithWeighting`, `TestHandleInspect_SuggestsTheSPSSWeight`). Contract and pins: `feature-profiles.md` (Request-slot gate, Manifest hiding, Predict hiding, Error hiding).

## Error codes

Each needs a `codeMetadata` entry (Message + ≥1 Fixup) and an `internal/descriptor/error_owners.go` owner. Owners (E4-S2): `PULSE_WEIGHT_INVALID_ROWS` and `PULSE_WEIGHT_UNSUPPORTED` → `capability:weighting` + `AGG_WEIGHTED_MEAN` (its ungated `weight_field` reaches both); `PULSE_EXTENSION_NOT_WEIGHT_AWARE` → `capability:weighting`. E1-S3 raises `PULSE_WEIGHT_INVALID_ROWS` (warning / strict error) and `PULSE_WEIGHT_UNSUPPORTED` (`AGG_CI_*`, lifted in U12 E5-S1; E2-S2 adds the decimal128 value field; E2-S3 every "Refusal rules" surface); `PULSE_EXTENSION_NOT_WEIGHT_AWARE` is raised since E4-S1:

- `PULSE_WEIGHT_INVALID_ROWS` — warning; excluded rows with the by-reason breakdown.
- `PULSE_WEIGHT_LOW_NEFF` (U12 E1-S2; owner `capability:weighting`) — warning (strict: error); a probability-weighted test's group n_eff below its raw-n floor, or a probability-weighted regression's n_eff below p + 1 ("Weighted inference").
- `PULSE_WEIGHT_UNSUPPORTED` — a refused surface under a weight: a frequency-only operator under a probability weight (`kind`, `supported_kinds`), a permanent refusal (`reason`, optional `alternative`), a pending one, or a decimal128 value field; the fixups name the `weight: null` opt-out, the switch to `kind: frequency` and the alternative operator. Its Message names no operator (`TestErrorMessagesNameOnlyOwners`: a Message names no hideable operator but its owners).
- `PULSE_EXTENSION_NOT_WEIGHT_AWARE` — explicit weight on a non-aware extension aggregator, or any weight in force on a non-aware extension attribute or test.
- `PROCESSING_CONFIG` — bad weight field or type, explicit weight on a not-weightable operator, `weight_field` conflict or nothing resolving for `AGG_WEIGHTED_MEAN`.
