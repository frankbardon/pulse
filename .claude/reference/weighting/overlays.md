## Overlays

- **Share / index kinds are descriptive** (no `Inferential` flag, so `overlayWeightClass` never refuses them) and carry NO weight logic: they read the host payload, which is already weighted. Matrix `OVERLAY_SHARE_OF_ROW` / `_COL` / `_TOTAL` and `OVERLAY_INDEX_VS_MARGIN` (both crosstab arms), series `OVERLAY_SHARE_OF_TOTAL` and `OVERLAY_INDEX_VS_TOTAL` / `_PRIOR` / `_BASELINE` / `_ROLLING_MEAN` / `_SIBLING` (streaming fold included), Compose `OVERLAY_INDEX_VS_REF` and the panel index `OVERLAY_PANEL_INDEX_VS_REF` over weighted slots. Gate: frequency expansion — a request-weighted host's layers equal the physically expanded cohort's unweighted layers, differ from the unweighted host's, and leave the host payload byte-identical to the overlay-free run (`TestWeightShareIndexOverlaysReadWeightedHost`, `TestWeightComposeIndexOverlaysReadWeightedSlots`, `internal/service/weight_overlay_test.go`). `OVERLAY_INDEX_VS_STAGE` (chain) and `OVERLAY_INDEX_VS_POP` (facet) read the same way but their hosts carry no top-level weight in U11. An undefined series entry (the first `_PRIOR` point, an unfilled rolling window) is NaN in Go and `statistic: null` in JSON on weighted and unweighted hosts alike, so the gates compare layers on the JSON form. The full audit of non-finite producers and the JSON surfaces they reach (all routed through `types.MarshalFinite`) is `.claude/reference/response-components.md` (Undefined figures on the wire).
- **Mean overlays on a weighted host (U12 E3-S1; both kinds).** `OVERLAY_T_CELL`, `OVERLAY_Z_CELL`, `OVERLAY_T_VS_REF`, `OVERLAY_Z_VS_REF` and `OVERLAY_PAIRWISE_WELCH_T` are `ClassAware` in `overlayWeightClasses`. A host cell is WEIGHTED when it carries the floor key `sum_weights`, whatever the weight's source (its own slot weight included — before E3-S1 such a slot-only host ran these kinds on the triple's raw `n` and its frequency-form variance, silently too narrow; the bug fix). Its kind is read off the floor too (`n_eff` is stamped only under probability). The one reader is `processing.readMeanLeg` behind `CrosstabHostView.MeanLeg` (the Compose matrix arm reads `Response.Components.Crosstab` through it, the series arm a row's triple map): N* = `sum_weights` (frequency) or `n_eff` (probability) — never the triple's `n` — and the variance recomputed from `m2` as `weighting.ScaledVariance` (c·m2/(N* − 1), c = N*/Σw; `Welford.Variance`'s operation order); Welch df on N* (fractional). An unweighted cell reads `{mean, variance, n}` exactly as before (byte-identical). The welford-shape pairwise arm reads both kinds through it (`OVERLAY_PAIRWISE_TWO_MEANS_Z` stays permanently refused by class; on a slot-only host it now reads N* too). `OverlaySummary.Parameters` adds `sum_weights` = Σw over the distinct legs read and, under probability, `n_eff` = Kish over their union ((ΣΣw)²/Σ(Σw²/n_eff)); nothing on an unweighted host. Real series hosts carry `processing.WelfordTriple` values (not maps; never read — the struct has no floor keys): a Compose / chain slot narrowed to its scored `AGG_WELFORD` (`narrowSeriesHost`) takes each row's leg from that row's bucket components instead (`welfordComponentsLeg`: `mean` / `variance` / `m2` + `n` + `sum_weights` / `n_eff`), so the series arm reads the weighted leg as the matrix arm does (U46 E4-S11; before, the layer came back empty); with components disabled on such a slot (the effective gate: its `disable_components`, else `Options.DisableComponents`; a `return` never removes them, the Compose veto keeps them) the overlay is `PULSE_OVERLAY_COMPONENTS_REQUIRED` `{overlay_index, kind, slot, host, aggregation, label, reason: "components_disabled"}` — `descriptor.ComposeOverlayTwoSampleInputsRefusal` (which also requires a scalar side's variance / sample-size params — `PULSE_OVERLAY_PARAM_MISSING`, no default — U46 E4-S16), called by `ValidateComposeWithOptions` and `Service.applyComposeOverlays` and re-run at fold time against what each slot returned (`composeOverlayTwoSampleLegsPresent`, `PROCESSING_INTERNAL`) — never the empty layer it was before (U46 E4-S13; gate root `TestComposeOverlay_WelfordComponentsDisabledRefused`). **`n_source` on a weighted host** (`weighting.NSourceRefusal`, FR-27): an omitted source reads N*; `cell_n_unweighted` is `PROCESSING_CONFIG` ("raw row count is not a valid sample size on a weighted host"; the margin modes read a margin floor's N* since U47 #324); `cell_weight_sum` is accepted under frequency and `PROCESSING_CONFIG` under probability. Wired for the welford pairwise kinds: runtime (`runPairwiseOverlay`, host basis = `CrosstabHostView.WeightBasis`) and predict (`validateOverlayPairwise`, basis = the crosstab cell's APPLIED resolved weight, `crosstabCellWeightBasis`) raise the same code and message, the predict refusal REPLACING the inertness `PULSE_OVERLAY_PARAM_MISSING` for those modes; every other mode keeps the predict-only inertness refusal. Gates: `internal/processing/overlay_weighted_host_test.go` (closed-form w* references under both kinds, raw-n answer differs, Parameters, the n_source rule), `internal/descriptor/overlay_weighted_host_nsource_test.go`, root `TestWeight_PairwiseNSourceMatchesPredict` (predict = runtime on a slot-only host), `internal/service/weight_mean_overlay_test.go` (slot-only host: frequency = expansion, probability scale invariance, Process + Compose).
- **Contingency and proportion overlays on a weighted host (U12 E3-S2).** `OVERLAY_CHISQ_ROW` / `_COL` / `_MATRIX` / `_VS_REF`, `OVERLAY_SYMMETRY` (U30 E7-S1), `OVERLAY_PROP_Z_CELL` / `_PANEL` and `OVERLAY_PAIRWISE_PROP_Z` are `ClassAware`; `OVERLAY_FISHER_EXACT_CELL` is `ClassFrequencyOnly`. A weighted host's cells and margins are Σw (weighted `AGG_COUNT`), read through the floor keys: `processing.floorLeg` / `CrosstabHostView.CellFloor` / `RowMarginFloor` give each cell's or margin's {Σw, N*}, `weightedLegTally` folds a set of them into the union's Kish scale c = n_eff/Σw (each leg's Σw² recovered as Σw²/n_eff). **χ²:** frequency = Pearson on the Σw table (the expanded rows); probability = the table (`_MATRIX`, `OVERLAY_STD_RESIDUAL`'s residuals / expected counts, U28, and `OVERLAY_SYMMETRY`'s McNemar / Bowker table), each row (`_ROW`) or column (`_COL`) scaled by the c of the cells it reads, then ordinary Pearson — `TEST_CHISQ`'s first-order Kish form, NOT Rao-Scott; the margin's own floor equals the cell union whenever the cells partition it. `_VS_REF` scales the TARGET table (the reference is the fixed distribution). `PULSE_OVERLAY_EXPECTED_LOW` and `expected_min` read the scaled expected; `Summary.Min` / `Max` stay the observed Σw. Frequency and unweighted hosts never multiply (byte-identical). **Proportions:** p̂ = Σw_success/Σw_base (the weighted cell share / cell over margin), n = N*_base. **Base n (U47 #324):** `PAIRWISE_PROP_Z` / `_PROBIT_T` with `n_source` omitted read the N* of the cell's BASE (`CrosstabHostView.BaseFloor`) — its normalise denominator (row / column / grand margin, or the `normalize_level` / `normalize_within` one, admitted), handed per cell by both arms (`crosstab_base_floors.go`, never on the wire; unreadable ⇒ the pair skips, never the cell's N*); an unweighted host reads that base's count, so unity and expansion parity hold; `row_margin_n` / `column_margin_n` read the displayed margin's floor (gates `TestCrosstab_WeightedPairwisePropZ_*`, oracle `_IndicatorMeanOracle`); `PROP_Z_CELL` and the panel's value modes scale the cell and the payload margin (or slab) by the row base's c under probability (`composeRowBases`: the row margin's floor, else the Kish union of the row's cells; a probability row with no readable floor is a missing margin, never Σw). **Host basis:** a per-Request host takes it from the STAMPED crosstab cell weight (`CrosstabHostView.withCellWeight`, set in `applyOverlaysToResponse`) — an `AGG_WEIGHTED_MEAN` cell emits its own `n_eff` under either kind, so floor keys cannot tell; Compose slots infer it from the floor keys (a components-disabled slot shows none — hence the refusal below). **`n_source` rule extended (`weighting.NSourceRefusal`, decision E3-S2):** besides the raw cell source, `n_within` (a raw slab) and every distinct-key mode (`n_within_distinct`, `row_margin_distinct`, `column_margin_distinct`, panel `row_margin_distinct_within`) are unweighted counts and `PROCESSING_CONFIG` on a weighted host, and `cell_value_weighted` joins `cell_weight_sum` as a weight sum (frequency only; the probability refusal's reason is `weighting.WeightSumNotSampleSize` — Σw is arbitrary in scale under probability and can overstate OR understate the sample size, U12 review WS-07); applied to every non-weighted-moment pairwise kind and the panel's `cell_n_unweighted` / `row_margin_distinct_within` — predict (`validateOverlayPairwise`; Compose `validateComposeOverlaySpec`, basis = any panel slot's applied cell weight) = runtime. **Fisher:** the exact test on the integer Σw table under frequency; a probability weight on the overlay slot is the resolver's refusal, and one on the HOST cell alone (slot-only, or the overlay opted out) is `PULSE_WEIGHT_UNSUPPORTED` `{slot, operator, host: crosstab.cell, kind, supported_kinds}` (`weighting.FrequencyOnlyHostRefusal`) at dispatch (`ApplyOverlaysWithExtensions`) and in predict. `OverlaySummary.Parameters` adds `sum_weights` (+ `n_eff`) over what was read: the table / per-entry margin (χ²), the target (`_VS_REF`), the legs (pairwise), the row bases (cell / panel). Gates: `internal/processing/overlay_weighted_contingency_test.go` (closed-form references per kind × frequency / Kish, scaled expected-low, the margin floor read first, the missing-floor row), `TestFusedCrosstab_PairwisePropZOverWeightedMeanMatchesBuffered` / service `TestCrosstabFused_PairwisePropZOverWeightedMeanEndToEnd` (stamped basis, refusals both arms), `internal/descriptor` `TestValidateOverlays_ProportionWeightedHostNSource` / `_FisherProbabilityHost`, `TestValidateCompose_PanelWeightedSlotNSource`, root `TestWeight_ContingencyOverlaysMatchPredict`.
- **Components-disabled host (U12 E3-S3).** The floor is the only place a probability host's n_eff shows, so a kind that scales Σw onto N* with it (`weighting.ScalesByHostFloor`: `OVERLAY_CHISQ_ROW` / `_COL` / `_MATRIX` / `_VS_REF`, `OVERLAY_STD_RESIDUAL`, `OVERLAY_SYMMETRY`, `OVERLAY_PROP_Z_CELL` / `_PANEL`) over a host weighted under kind probability AND built with components disabled (the request's `disable_components`, else `Options.DisableComponents`) is `PROCESSING_CONFIG` `{slot: "overlays[i]", operator, host, kind: "probability", reason: "components_disabled"}` (+ `slot_label` on Compose) — `weighting.HiddenFloorRefusal`. Before, the χ² kinds scaled by 1 and the Compose kinds read the slot as unweighted: Σw silently became n. Per-Request host: the basis is the stamped cell weight, refused at dispatch (`ApplyOverlaysWithExtensions`, `!host.HasComponents()`) and in predict (`validateOverlayHiddenFloor`, `PredictOptions.DisableComponents` = the engine default the facade passes). Compose: `descriptor.ComposeOverlayHiddenFloorRefusal` over the raw slots (basis = the slot's applied crosstab-cell weight, any source; disabled = the runtime's effective setting), called by `Service.applyComposeOverlays` and `ValidateComposeWithOptions`, then re-run at fold time against what each slot actually returned (`Service.composeOverlayFloorsPresent`: a read probability slot with no crosstab Components is `PROCESSING_INTERNAL` — the gate refusal and the U18 Compose veto make it unreachable — the veto is weight-basis aware per slot (#221): a floor kind keeps a slot's `components.crosstab` exactly when that slot's crosstab cell is weighted, any kind, by the same `CrosstabCellWeightBasis` — so a hit is an engine bug, never silent Σw-as-n; gates `TestComposeOverlayFloorsPresent`, `TestComposeOverlayFloorsPresent_CatchesMisvetoedFloorKind`); the proportion kinds read every slot, `_VS_REF` its targets only (the reference is a distribution, scale-free). Frequency hosts (Σw IS N*) and the pairwise kinds (already `PULSE_OVERLAY_COMPONENTS_REQUIRED`) are untouched; the mean kinds' components-disabled fallback is the caller's `params` triple. Decision: refuse rather than force components on. Gate: root `TestWeight_ComponentsDisabledFloorRefusalMatchesPredict`.
- **Overlay gates (U12 E3-S3).** `internal/service/weight_overlay_parity_test.go`, a case table held total over the manifest's overlay `weight_kinds` (shared coverage helper), run per host — the per-Request crosstab on both arms (fused where the unweighted twin fuses) and Compose — and per source (request, slot-only cell / series weight, `Options.DefaultWeight`): `TestWeightOverlayUnityParity` (byte-identical after shedding the layer `sum_weights` / `n_eff`; n_eff = sum_weights), `TestWeightOverlayFrequencyExpansionParity` (= the expanded rows, ≠ the unweighted host, per layer), `TestWeightOverlayProbabilityScaleInvariance` (c·w = w, `sum_weights` × c, `n_eff` fixed, each layer ≠ the frequency layer; a χ² layer's `Summary.Min` / `Max` echo Σw and move by c), `TestWeightOverlaySlotOnlyHostReadsNStar` (the slot-only-host fix: slot-only = request-weighted, n_eff < Σw). `OVERLAY_PAIRWISE_WEIGHTED_TWO_MEANS_Z` runs with `n_basis` weights / kish by kind and stamps no Parameters; `OVERLAY_T_VS_REF` / `_Z_VS_REF` run on a scalar-mean series (`compose_mean_series`) and on an `AGG_WELFORD` series read from the bucket components (`compose_welford_series`, U46 E4-S11). Reference rows: `TestWeightReferenceValues/overlays` (`weight_reference_overlays_test.go`; generator `OV_CASES`, R `ov_*`). Predict = runtime for every pairwise and panel `n_source` × kind × request / slot-only source: root `TestWeight_OverlayNSourceRefusalsMatchPredict`.
- **`OVERLAY_PAIRWISE_WEIGHTED_TWO_MEANS_Z` hosts (FR-18).** The runtime gate is key-based (`HasWeightedMomentCells`: `weighted_mean`, `m2_weighted`, `sum_weights`, `sum_weights_sq`); a weighted `AGG_AVERAGE` cell carries the first, second and fourth as its own keys and `sum_weights` from the weighted floor (`WeightFloor.stampMap`, both arms), so it qualifies, while an unweighted one never does. Predict's cell-host refusal (`validateOverlayPairwise` → `weightedMomentCell`, `internal/descriptor/overlay.go`) admits `AGG_WEIGHTED_MEAN` always and `AGG_AVERAGE` iff a weight resolves on the cell (slot → request → `Options.DefaultWeight`; `weight: null` opts out) — the `StampWeights` precedence, so the two arms agree (`TestPairwiseWeightedTwoMeansZ_PredictRuntimeParity`, `TestPredict_PairwiseWeightedTwoMeansZ_WeightedAverageCell`). A weighted-average host answers exactly as the weighted-mean host (`TestCrosstab_WeightedTwoMeansZ_WeightedAverageHost`, both arms). The feature hard edge is the any-of group `{AGG_AVERAGE, AGG_WEIGHTED_MEAN}` (`hardEdges`, `internal/descriptor/features.go`): a profile keeping the overlay needs either. **`n_basis` vs `kind` (U12 review WS-06):** this kind takes its sample size from `params.n_basis`, but `n_basis: "weights"` (Σw as n) on a `probability` host — a slot / request / default weight of that kind, or the `AGG_WEIGHTED_MEAN` `weight_field` sugar, which is kind probability — is `PROCESSING_CONFIG` (`weighting.NBasisRefusal`, opening with `NSourceRefusal`'s `WeightSumNotSampleSize` reason), raised identically by predict (`validateOverlayPairwise`, basis = `crosstabCellWeightBasis`) and runtime (`applyPairwiseWeightedTwoMeansZ`, basis = `CrosstabHostView.WeightBasis`, the stamped cell weight); `kish`, and `weights` on a frequency or unweighted host, are unaffected (`TestWeight_PairwiseWeightedNBasisMatchesPredict`, `TestPairwiseWeightedTwoMeansZ_PredictRuntimeParity`). This breaks the shipped v0.39.1 `weight_field` + `weights` request (migration doc, U12 table).
