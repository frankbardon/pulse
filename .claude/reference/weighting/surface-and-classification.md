# Weighting — Surface, Resolution order, Threading, Validation, Classification by family

Per-topic slice of the weighting reference (Surface, Resolution order, Threading, Validation, Classification by family). Index (preamble + section map): `.claude/reference/weighting.md` — load it first, then only the slice(s) your change touches.

## Surface

| Slot | Shape | Notes |
|---|---|---|
| `types.Request.Weight` (`weight`) | `{field, kind}` (`types.WeightSpec`) | `omitempty`. `kind` ∈ `probability` (default) \| `frequency`. |
| Per-slot `weight` (`types.SlotWeight`, `omitzero`) | a field-name string, a `{field, kind}` object, or `null` | On `Aggregation` (so also the crosstab cell and `crosstab.margin_aggregations[i]`), `Test` (`tests` and `post_tests`), `RegressionSpec`, `Attribute`, `OverlaySpec` and `Group` (`groups[i]`, `crosstab.rows[i]`, `crosstab.columns[i]`; E2-S3) — tests, regressions, overlays, attributes and groupers mainly to opt OUT. `Window` and `ComposeOverlaySpec` carry none. Go spellings: `SlotWeightField(f)`, `SlotWeightOf(spec)`, `NullSlotWeight()`; zero value = absent. |
| `pulse.Options.DefaultWeight` | `*WeightSpec` | Validated at `pulse.New`; applies to Process / Compose / ProcessChain inner requests, never to `Facet` / `FacetSchema`. |

**Null ≠ absent.** An ABSENT per-slot `weight` inherits; an explicit `null` opts that slot out. The per-slot type is new to `types/` (no precedent): it carries its own `UnmarshalJSON` / `MarshalJSON` / `IsZero` and rides `omitzero`, and the distinction must survive every hop — `types.CanonicalHash`, the MCP strict decode and binder, and the payload JSON Schema (`internal/descriptor` `BuildPayloadSchema` special-cases it as `#/$defs/SlotWeight` = `oneOf [string, WeightSpec, null]`). A set weight with no `kind` marshals as the bare string (the object form without `kind` re-marshals as the string — same meaning); decoding refuses any other JSON shape and any object key but `field` / `kind`. The fields are unexported on purpose: the three states are reachable only through the constructors, so "null with a field" cannot be built. The MCP binder (`internal/mcp/bind.go`) declares the same union, its field enum drawn from the cohort's weight-capable columns (`descx.IsWeightFieldType`).

No new top-level slot on `ComposedRequest` or `ChainRequest`: each inner `Request` carries its own `weight`. `AGG_WEIGHTED_MEAN.params.weight_field` is slot-weight sugar (see "Aggregator classification").

**Weight field type.** Unsigned integers (`u4`, `u8` … `u64`) and floats (`f32`, `f64`) only. `decimal128`, `categorical_*`, `date`, `datetime`, `packed_bool` and `set_*` are `PROCESSING_CONFIG` with details `{slot, field, type}` (`slot` is `weight`, `<slot>.weight`, or the slot path for an applied default). An empty `field` or a `kind` other than `probability` / `frequency` is `PROCESSING_CONFIG` too (`{slot, field, kind}`), for `Options.DefaultWeight` already at `pulse.New` (`slot: "Options.DefaultWeight"`).

**Weight field existence.** An explicitly named weight (request or slot) is judged by the field-reference rule (`fieldRefWalk.checkWeights` in `internal/descriptor/field_refs.go`) against the SCHEMA, not the derived column set — an attribute label or feature output is no weight — and refused `SERVICE_VALIDATION` `{field, slot}` like any unknown name. A joined (prefixed) name resolves against the joined schema; a chain stage ≥ 1 against its synthesised input schema. The inherited `Options.DefaultWeight` is NOT a request reference: `ResolveWeights` judges its existence and type only on a slot where it is APPLIED, so an instance default never breaks a cohort lacking the column for a request that would not use it. Projection: `processing.NeededFields` adds the request and slot weight fields; the service's `neededFields` adds the instance default (which `NeededFields` cannot see), so projection never decodes a weight as null (`TestProjection_WeightColumnDecodes`).

## Resolution order

One shared resolver, `ResolveWeights(req, schema, defaultWeight, inst)` in `internal/descriptor/weight_resolve.go`, modelled on the time-zone resolver (`internal/descriptor/zone_resolve.go`), called by BOTH runtime and predict so they cannot disagree. The runtime runs it inside `Service.checkFieldRefs`, i.e. right after the field-reference rule passes, in every execution mode (Compose slots and chain stages each resolve their own Request, located by `details.request` / `details.stage`); predict and the Compose / chain validators run it at the same point:

1. the slot's own `weight` (`null` ⇒ opted out, stop);
2. the request's `weight`;
3. `Options.DefaultWeight`;
4. none.

Slot order (and `slot` spelling): `aggregations[i]`, `crosstab.cell`, `crosstab.margin_aggregations[i]`, `tests[i]`, `post_tests[i]`, `regressions[i]`, `attributes[i]`, `overlays[i]` (`operator` = the overlay kind), then (E2-S3, appended so earlier reports keep their order) `groups[i]`, `crosstab.rows[i]`, `crosstab.columns[i]`, `windows[i]`. A slot with an empty `Type` is skipped. Predict reports the outcome per slot as `PredictResult.Weights` (`descriptor.ResolvedWeight`, `weights`, `omitempty`) — `{slot, operator, field, kind, status, source}`: `field` / `kind` are omitted on `opted_out` / `none` and `kind` is spelled out (`probability` when the spec left it empty); `status` ∈ `applied` | `skipped_not_weight_aware` | `opted_out` | `none` (`descriptor.WeightStatus*`); `source` ∈ `slot` | `request` | `options` | `none` (`descriptor.WeightSource*`; an opted-out slot's source is `slot`). The whole list is nil — the key absent — when neither the request, a slot (a `null` included) nor the instance names a weight, so an unweighted predict payload is unchanged. `applied` vs `skipped_not_weight_aware` reads `IsWeightAware(op)`; a hidden operator is never-registered, hence not aware. Refusals surface as predict errors, identical to runtime (`TestWeight_PredictMatchesRuntime`, `TestWeight_ValidatorsMatchRuntime`).

## Threading

**Design (E1-S3): the resolved weight rides the aggregator's SPEC.** `processing.StampWeights(req, Options.DefaultWeight)` returns a copy of the request whose every aggregation slot — `aggregations[i]`, `crosstab.cell`, `crosstab.margin_aggregations[i]` — carries its RESOLVED weight in its own `weight`: set (field + spelled-out kind) when a weight applies to a weight-aware operator, `null` otherwise. It folds the same precedence as `ResolveWeights` (slot → `AGG_WEIGHTED_MEAN` `params.weight_field` → request → `Options.DefaultWeight`) and reads the same class table (`internal/weighting`), so it never refuses — the resolver already did. A request naming no weight anywhere is returned AS-IS (same pointer), so the unweighted path executes the unchanged object; the caller's request is never mutated (the echo and `CanonicalHash` see what the caller sent). Every engine entry stamps: `Processor.Process` / `RunCrosstab` / `RunCrosstabFused` (the processor carries the default through `SetWeighting`, set by `Service.newProcessor`) and both parallel reducers (`processShardArchiveParallel`, `reduceParallelBuffered`), so every mode builds its aggregators off one spec. A factory reads `slotWeight(agg)` and returns the weighted form (`weightedAggregator`, `internal/processing/aggregator_weighted.go`) or, with no weight, the unchanged unweighted type; the per-row weight is read off the record inside the aggregator. Why not the record: per-slot weights differ within one request.

`internal/weighting` is the leaf both halves read: `ClassOf` / `IsAware` (the class table) and `Classify` (the per-row validity rule). `internal/descriptor.IsWeightAware` forwards to it.

## Validation

| Weight value | Treatment |
|---|---|
| positive, finite | used |
| zero | valid; contributes nothing |
| null | excluded, counted (`null`) |
| negative | excluded, counted (`negative`) |
| NaN / ±Inf | excluded, counted (`nan_inf`) |
| non-integer under `kind: frequency` | excluded, counted (`non_integer_frequency`) |

Invalid weights are **never coerced** (`weighting.Classify`; a zero weight is skipped too, so it adds nothing and a leading zero cannot divide by a zero Σw). Each weighted aggregator slot reports `n_weight_invalid` = its VALUE-PRESENT rows excluded for an invalid weight (a null-value row is `n_null` and its weight is not judged). Each Response carries ONE `PULSE_WEIGHT_INVALID_ROWS` warning PER WEIGHT FIELD that excluded rows (in practice one: a request rarely names two weight columns) — `details{field, count, by_reason{null, negative, nan_inf, non_integer_frequency}}`, all four reasons always present — counting the FILTER-PASSING rows (after row-local attributes) whose weight is invalid, whether or not that row's value is present; a fractional weight counts as `non_integer_frequency` when any slot reads that field as `frequency`. It is tallied by `processing.WeightRowTally` from the stamped aggregation slots and merged across buffered, streaming, grouped streaming, two-pass, shard-parallel and parallel-decode execution, and tallied by both crosstab arms (E3-S1) over the slots `NewWeightRowTally` reads — the top-level aggregations, the crosstab cell and every `margin_aggregations` slot, so an auxiliary-only weight warns too; `pulse.Options.Strict` (`--strict`) turns it into an error carrying the same code and details.

## Classification by family

One table per weight kind, the whole built-in surface (U12 E6-S1 summary; the per-family sections below carry the formulas, the code is `internal/weighting` `operatorClasses` plus the overlay table `overlayWeightClasses` in `internal/descriptor/weight_resolve.go`). Manifest `weight_kinds` is `["frequency","probability"]` for "both kinds", `["frequency"]` for "frequency only" and absent otherwise; the coverage harnesses (`assertWeightKindCoverage`) read it, so this table and the manifest cannot drift without a red gate.

|---|---|---|---|---|
| Aggregators | `AGG_COUNT`, `AGG_SUM`, `AGG_AVERAGE`, `AGG_WEIGHTED_MEAN`, `AGG_VARIANCE`, `AGG_STDDEV`, `AGG_WELFORD`, `AGG_SKEWNESS`, `AGG_KURTOSIS`, `AGG_MEDIAN`, `AGG_PERCENTILE`, `AGG_MODE`, `AGG_MODE_COUNT`, `AGG_FREQUENCY`, `AGG_RATIO`, `AGG_SET_FREQUENCY`, `AGG_SET_CARDINALITY_SUM`, `AGG_SET_CARDINALITY_AVG`, `AGG_CI_LOWER`, `AGG_CI_UPPER`, `AGG_MAPE`, `AGG_RMSE`, `AGG_MAE`, `AGG_AUC`, `AGG_VEC_MEAN`, `AGG_VEC_SUM`, `AGG_VEC_SD` | — | any weight-aware aggregator over a `decimal128` value field (no `reason`; `value_field`, `type`) | `AGG_MIN`, `AGG_MAX`, `AGG_RANGE`, `AGG_DISTINCT_COUNT`, `AGG_DISTINCT_SUM`, `AGG_NULL_COUNT`, `AGG_SET_UNION`, `AGG_SET_INTERSECTION`, `AGG_SET_DISTINCT_VALUES`, `AGG_ZSCORE` (default skipped, explicit `PROCESSING_CONFIG`) |

| Windows, filterers, features | — | — | — | windows: a REQUEST weight is `PROCESSING_CONFIG`, the default skipped; filterers and features skipped |
| Extensions | aggregators, attributes and tests declaring `WeightAware` (applied under BOTH kinds — `OperatorMeta` has no `weight_kinds`, by decision) | — | a non-aware attribute or test under any weight, a non-aware aggregator under an explicit one (`PULSE_EXTENSION_NOT_WEIGHT_AWARE`) | filterers, groupers, windows, features skipped |

"Refused" lists only PERMANENT refusals: since U12 no built-in `TEST_*` / `REG_*` / attribute / grouper / Request-host overlay is a pending `ClassRefuse` ("has no weighted form yet" is reachable only by an `Inferential` overlay kind with no `overlayWeightClasses` entry — today the facet-host kinds, whose hosts never carry a weight; a NEW inferential kind lands there until its weighted form exists). The one rule behind "both kinds" — N*, w*, the frequency formula on w* — is "Weighted inference"; the reasons are `weighting.RefusalReason` and the overlay table's `reason`.
