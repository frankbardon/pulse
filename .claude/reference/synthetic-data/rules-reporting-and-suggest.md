# Synthetic data — `null_together`, never-firing rules, `constant`, the inspectable spec, `--suggest-rules` detection

Per-topic slice of the synthetic-data reference (`null_together`, never-firing rules, `constant`, the inspectable spec, `--suggest-rules` detection). Index (preamble + section map): `.claude/reference/synthetic-data.md` — load it first, then only the slice(s) your change touches.

**`null_together` NULLS A BLOCK AS ONE DECISION, and the FIRST named field wins.** A survey question block is asked or skipped as a unit, so its fields are present or absent together; drawing each member's null independently from its own scalar `null_rate` turns the block into a lottery. Measured on the motivating 122-field profile, the `nps` / `promoter` / `passive` / `detractor` block shares `null_rate` 0.8260 exactly and all four came back present in **45 of 40,000** generated rows against the ~6,960 the block actually has, because `0.174⁴` is not `0.174`. With the rule: **6,809–6,994 across five seeds, and zero partial blocks.** The resolution is a COPY of `nullMask[block[0]]` onto every other member (`applyNullTogether`, `internal/synth/rules_apply.go`) — every field has already consumed its own null draw by the time the pass runs, so copying an existing decision is the only resolution that adds no randomness, and the pass consuming no RNG is a hard contract. **The cost is that every member but the first has its own `null_rate` IGNORED**, which is stated here rather than left to be discovered, and is warned about at compile time whenever a member's declared rate sits more than `nullRateDivergenceThreshold` (**0.02**, a package constant with its reasoning at the declaration, deliberately not an `Options` field — matching `minVarianceExplained` / `minLevelObservations`) from the gate's. The comparison is ABSOLUTE and each member is measured against the GATE, not against the block's spread: what the copy discards is a number of ROWS, so a relative test would scream about 0.001 against 0.002 and stay quiet about 0.80 against 0.84. Refusing outright was considered and REJECTED — a real block whose fields drifted slightly (a coding difference, a partial re-ask, a rate read off a rounded table) would become unusable and the copy is still right for it. The warning is classified in `internal/synth/warning_summary.go` as an ATTENTION kind (`rule null_together overrides a declared null_rate`) beside the function that builds the string, so a rewording is a change to the table rather than a line that silently falls into the catch-all. **The copy moves the null DECISION only, never a value** — each member keeps what its own sampler drew, a nulled member exactly as `set_null` leaves it, and an UN-nulled member (gate present, member had drawn a null) publishes the value it drew, which is the half that makes the block share a rate at all rather than only share its nulls. **Within ONE rule the block is the LAST write**, after `set_null` / `set` / `set_expr`, because the slots of a rule have no order an author can read and that is the composition that is useful: `{"set_null": ["nps"], "null_together": ["nps", …]}` nulls the gate and the block follows it, while reversed the block would be decided from the gate's DRAWN state and the `set_null` would break it apart on exactly the rows it was meant to gate. A `set_null` naming a NON-gate member in the same rule is therefore overridden by the block. ACROSS rules the ordinary last-write-wins applies instead: a later `set_null` over any member does break the block, and a later `null_together` re-decides it from whatever the gate holds by then. **The case that actually bites is a later `set_expr`**, because it CLEARS the null mask on every row it writes — declaring `null_together` in one rule and the `set_expr` that derives its members in a LATER one lets the derivation run last and un-null every member on the rows the block had just nulled together: measured on the motivating profile, 33,056 of 40,000 rows come back carrying a classification flag with no score, which is the exact incoherence the block rule was added to remove. Put both slots in ONE rule, where `null_together` is the last write by construction, rather than relying on declaration order to keep them in step. A non-nullable NON-GATE member gets the silent-zero warning, sharing its kind — a WARNING and not `set_null`'s refusal, because this slot copies a decision rather than making one. **The GATE is never reported by either warning**: `applyNullTogether` reads `nullMask[block[0]]` and never writes it, so a non-nullable gate is not a field the block failed to null, and a never-null gate is the IDIOM rather than a mistake (the copy clears every member's own MCAR null, leaving a later rule's `set_null` as the block's only source of absence — measured on the motivating profile as the remedy for the gate rule's marginal shortfall). Reporting it flagged the design as a defect. `format_version` does NOT move. Detail: `skills/synth-rule-nulls.md` + `docs/src/cli/synth-from-schema.md`.

**A rule that NEVER FIRES is reported, as an ATTENTION kind.** Eager validation (E1-S2) refuses a rule naming a mistyped field or carrying an uncompilable expression. It cannot refuse a `when` that is simply never TRUE: that rule validates, compiles, applies to nothing, and the cohort generates cleanly with the structural fact the author wrote it for still ABSENT — nothing downstream can tell it from a cohort where the rule worked. That is the fourth instance of one failure class in this package (a fidelity report scoring pairs generation never applied; 85 of 105 captured models silently unapplied; every `packed_bool` prevalence inverted; an emitted spec that parsed and then refused), so the classification follows the standing rule rather than a judgement about severity: `rule never fired` is ATTENTION (`internal/synth/warning_summary.go`, the row sitting beside the function that builds the string), never the expected-outcome count. **The count is over rows that reached the FILE, not draws.** `generate()` re-draws a whole row when a constraint rejects it, so a firing on a rejected attempt left no trace and a count including it cannot be divided by `rowsGenerated` — which is the one arithmetic a reader will do with it. The counter therefore commits per ACCEPTED row (`ruleApplier.commitRow`, `internal/synth/rules_firing.go`) rather than incrementing in `apply`, and a rule firing only on rejected rows correctly reports zero. Two slices sized once at compile time (`rowFired` scratch + `firings` totals): the pass still consumes NO RNG and allocates nothing per row, so generated bytes are identical with the counting and without it. A rule firing on EVERY row and one firing on SOME are both silent; the listing is capped at `maxNeverFiredRuleWarnings` (20, matching `maxThinLevelWarnings`) with a counted `+N further rule(s) never fired` roll-up folded into the same group, and the terminal summary's own 3-example cap is unchanged. The firing count is deliberately NOT a `synth.Result` slot — that struct is the `--json` payload and this is a diagnostic the warning channel already carries; `format_version` does NOT move. The message names **the cause that applies to THAT rule**, in three arms, because a single named cause was wrong for most rules. (1) CONSTRAINT — the rule DID select rows and a constraint rejected every one; DETECTED rather than guessed (`noteFired` remembers the attempt and is never cleared, `commitRow` counts the acceptance, so a rule with one and not the other is exactly this case), and the line blames the constraint and says nothing about rounding. (2) PRE-ROUNDING — the predicate reads a field that ROUNDS ON WRITE (`u4`/`u8`/`u16`/`u32`/`u64`, `date`, `packed_bool` — the `writeFieldValueForField` arms applying `Floor(f+0.5)` plus `toBool`'s 0.5 threshold) AND draws continuous values; the remedy it names is `round`, not `int`: measured on the motivating profile at 20,000 rows, `familiarity <= 1` fires on 1,843 rows raw, 2,739 behind `round(familiarity)` with the column unchanged, and 3,824 behind `int(familiarity)`, which reaches the larger figure by dropping 1,085 respondents a point. (3) NEUTRAL — neither applies; the line names each field the predicate reads with its type and distribution and explicitly RULES PRE-ROUNDING OUT for a field that quantizes on write but draws exact values. **That third arm is the whole reason the split exists and it is not a refinement**: since the `discrete` and `bernoulli` marginals shipped, a field that rounds on write still draws EXACT values whenever its distribution is `discrete`, `bernoulli`, `uniform_date`, `poisson` or `monotonic_from` — and a small integer reconstructs as `discrete` and a `packed_bool` as `bernoulli` AUTOMATICALLY, so the old single message was actively WRONG for **103 of the motivating cohort's 123 fields** against 3 that carry the hazard: it sent an author to normalise a gate that was already exact while the real cause went unstated. The fields a `when` reads are parsed from the AUTHOR'S SOURCE (`internal/synth/rules_firing_cause.go`, both the bare identifier and `isnull`'s string spelling), following `exprReadsIdentifier`'s rule, and a field some rule's `set_expr` WRITES loses its exactness claim because an expression result is an arbitrary float. All three arms run silently on a rule that fires; only the empty case warns, and the classification adds one bool per rule sized at compile time, so generated bytes are unmoved (checked byte-for-byte against the pre-change tree over the real 14-candidate rules file at 5,000 rows). Detail: `skills/synth-rule-validation.md` + `docs/src/cli/synth-from-profile.md`.

**`constant` is normalised to the field's row shape.** `newConstantSampler` is the one sampler whose value comes from the spec DOCUMENT rather than from an arithmetic draw, so it is the one that can put the wrong Go type into the row: every other sampler for a given field type emits one shape (float64 for every scalar including `packed_bool`, string for a categorical, `map[string]bool` for a set) and `sentinelFor` types the expression environment on exactly that assumption. A JSON `true` on a `packed_bool` field therefore put a Go `bool` where the env promised a float64 and broke every constraint — and now every rule `when` / `set_expr` — touching the field at RUN time, the inverse of issue #258. The value is coerced ONCE, at spec compile time (`constantRowValue`), because the row map has no type discipline of its own and the only place the invariant can hold is where the value enters it. Byte-identity holds for every spec that worked before; what changes is the shapes that were BROKEN — a string on a non-decimal scalar encoded as a silent `0` (`toFloat64`'s string arm) and is now refused, a non-string on a categorical and an array on a `set_*` both raised `ENCODING_TYPE_MISMATCH` at row time and are now refused at parse / accepted as the option list. `decimal128` keeps its string form, exactly (`encoding.ParseDecimal128`, no float round trip).

**The profile-derived spec is inspectable and modifiable (`--emit-spec` / `--rules`).** `SpecFromProfile` derives a spec and generates from it in one breath and nothing printed it, which made the WHOLE `Spec.Rules` layer unreachable from the profile path — the only path the motivating use case takes — and made authoring a rule guesswork, since `{"when": "familiarity == 1", …}` requires knowing the field is called `familiarity`, that it is a `u4` and that its floor is 1. Two additive `pulse synth from-profile` flags, both inert when absent (`TestSynthFromProfileCLI_EmitSpecDoesNotChangeTheCohort`). `--emit-spec <path>` (`synth.WriteSpec`, indented, through `afero.Fs`) writes **the spec that actually generated, never a rendering or a re-derivation** — the gate is a ROUND TRIP, `synth.SynthBytes(derived)` against `synth.SynthBytes(ParseSpec(emitted))` at one seed compared BYTE FOR BYTE (`TestEmitSpec_RoundTripsToByteIdenticalCohort`), because a test that merely asserts the JSON parses passes against an emit that dropped `models`, coarsened a float or re-derived the document, each of which is silent and each of which this package has shipped. It is equally a DIAGNOSTIC: the emitted spec is the only place a reader sees which captured models survived translation, which distribution each field reconstructed to, and which conditional pairs were retired. It is written BEFORE generation, so a failing run still leaves it. `--rules <path>` (`internal/synth.ApplyRulesFile`) loads a **bare JSON array of rule objects — the `Spec.Rules` array itself**, the format E1 fixed deliberately so the loader needs no translation layer — and **REPLACES** `Spec.Rules`: a derived spec carries none, so there is nothing to append to and an append mode would only invent an ordering question the declaration-order contract would then have to answer forever. `[]` is a legal document meaning "no rules"; `{"rules": […]}` is REFUSED rather than read as zero rules. Validation runs at the LOAD (a profile-derived spec bypasses `validateSpec` by design, so there is no earlier gate) against a COPY, so a refused file leaves `Spec.Rules` untouched; every refusal keeps E1's own `PULSE_SYNTH_RULE_*` code and adds `details["path"]`, because an analyst editing a rules file beside a spec beside a profile cannot act on "rule 2 names field \"x\"" alone — an unreadable file is `DATA_FILE` and a malformed one `SERVICE_VALIDATION`, both naming the path. The load, the merge and the emit all live in `synth/`; `internal/cli/synth.go` supplies paths and routes the coded refusal through `writeCodedErrorEnvelope` (`cliCodedError`) so `errors[0].code` stays usable with `pulse errors lookup`. One byte-layout consequence the round trip forced: `constantRowValue` now accepts a `set_*` constant as a JSON OBJECT (`{"tv": true}`) as well as an array, because `sentinelFor`'s unsummarisable fallback puts a `map[string]bool` on every all-null `set_*` column and that is the one shape in the whole `Spec` that does not decode back to the Go type it was marshalled from — before it, the emitted spec for a survey with one always-null multi-select parsed cleanly and then refused at generation. `format_version` does NOT move and the `--json` envelope is unchanged. Detail: `skills/synth-rules-from-profile.md` (Reaching rules from a profile) + `docs/src/cli/synth-from-profile.md`.

**Detecting structural rules from the data (`profile create --suggest-rules`).** The rule layer's value is bounded entirely by rule COVERAGE, and rules get written from recall — on the motivating cohort the analyst supplied ONE, and a second and larger one was found by accident while verifying something else. An unstated rule is invisible in the output because **every marginal inside it is individually correct**, which is why no existing instrument catches it. `pulse profile create --suggest-rules <path>` measures, for every low-cardinality field (`categorical_*`, `packed_bool`, `u4`) and every other field, `P(target null | gate = level)` off the SAME single scan (`internal/synth/profile_gating.go`, `ProfileOptions.SuggestRules`; no additional cohort read, counted in bytes the way `TestProfileModels_RidesTheExistingScan` counts them) and proposes a `set_null` rule for each field whose levels split a target's null rate into ~1 and ~0. It writes the BARE rules array `synth from-profile --rules` consumes UNMODIFIED — asserted by a GENERATION round trip, never by comparing shapes, because a test that merely unmarshals the file passes against a document whose predicates do not compile or whose `when` is silently never true. **PROPOSED, never auto-applied**: a detected pattern can be a coincidence of the sample, and a rule applied without review is exactly the silent structural claim this layer exists to remove. **Detection finds the STATISTICAL gate and a human knows the SEMANTIC one** — measured, not hypothetical: on the motivating cohort it proposes BOTH `round(aware) == 0` and the analyst's own `round(familiarity) == 1` with identical evidence to sixteen digits (96,326 rows each, zero exceptions either way), so nothing in the data can separate them and the output must invite correction rather than assert cause. Each candidate carries its own measurement on **`RuleSpec.Evidence` (`_evidence`), THE ONE INERT SLOT** — never read by `compileRules`, the rule pass or `validateRules`, never an action slot (a rule carrying only `_evidence` is still `PULSE_SYNTH_RULE_EMPTY`), harmless when hand-authored, and `omitempty` so a rule without it is byte-identical. It rides the RULE rather than a sibling block because the file must stay a bare array (a wrapper object is refused by design) and because evidence in a second document drifts from its rule the first time a candidate is deleted; the leading underscore is this repo's own `_meta` marker for documentation rather than payload. `Profile.RuleCandidates` is `json:"-"`: absent the flag the profile document is byte-identical, and WITH the flag only `warnings` moves, because an unreviewed structural claim must not ride inside the document that drives generation. Thresholds are package CONSTANTS with their reasoning at the declaration, never `ProfileOptions` fields (`gateHighNullRate` 0.98 / `gateLowNullRate` 0.02 / `minGateLevelSupport` = `MinPairObservations` / `maxGateLevels` 16 / `maxRuleCandidates` 20), matching `minVarianceExplained` and `minLevelObservations`; they are TIGHT because skip logic is EXACT in the source, and a looser pair finds ordinary ASSOCIATION and proposes it as structure — a rule built from a 10/30/50% null rate is applied unconditionally and wrong on most of the rows it selects. **Numeric gates are emitted through `round()`, uniformly, including `packed_bool`**: a bare `==` reads the pre-rounding float and under-fires silently (531 of 901 rows in the committed regression), and a file where one numeric gate is bare and another is not teaches a reader that bare is sometimes fine with nothing saying which. Every emitted `when` is compiled against the rule layer's OWN environment (`rowExprEnv` / `rowExprOptions`) before it is written — never a hand-rolled identifier check, since a field legally named `in` otherwise yields a candidate the loader refuses. Two things are COUNTED rather than dropped silently: a field over `maxGateLevels` is ABANDONED, never truncated (a partial level map makes every rate below it a rate over an arbitrary subset), and a gate whose ONLY gated level is the null pseudo-level is CO-MISSINGNESS rather than value gating — every member of an N-field block reports the other N−1 that way, so proposing them restates one finding N times and buries the real ones (3,932 on the motivating cohort). Thin candidates SHIP with their support attached, warned thinnest-first with a counted remainder. `gated_share` is the `1 - P(gate)` figure that identified this cohort's gate by hand and is a CHECKING aid, NOT the ranking signal: the split test arithmetically implies it, so ranking by it would be ranking by rounding error; ranking is target count then rows affected. **Candidates COMPOSE in declaration order and are not independent statements** — `aware` nulls the five `*Aware` flags and the five later candidates then fire on those nulls too — and **every gating candidate carries `"owns_nulls": true`, which `gateLowNullRate` is what makes sound**: `P(null | open)` IS the residual that flag zeroes, so an admitted candidate is within 0.02 of exact by construction. Without it a `set_null` gate repairs CO-MISSINGNESS ONLY — each target's own `null_rate` keeps firing beneath it, and since that rate is a marginal already inclusive of the gate the two compose as `g + (1−g)·r` (measured: `regard` 0.2526 captured against 0.4369 generated, `people` 0.4273 against 0.7506). Re-measured on the accepted 11-candidate file at 40,000 rows the 50 gated fields move 0.4320 → 0.2455 and `people` 0.7506 → 0.4208, with the coherence table, the emitted ordering and the zero orphan count all unchanged and no claim diverging enough to warn; the five `*Aware` gates' firing counts drop (22,520 → 16,831 for `peopleAware`) because they read `isnull(<x>Aware)` and their gate field is itself one of the 50 — the drop IS the repair. A CO-MISSING candidate never carries the flag: it discards its non-gate members' rates by copying the gate's decision. Measured on the motivating cohort: 8 candidates, all 50 `0.2526093295989762` fields recovered plus the 13-field `0.2649` cluster research had recorded as unexplained, the four-field NPS block recovered exactly, and all 8 firing on 100% of their gated rows when fed back unmodified. `format_version` does NOT move; the manifest golden moved once for `PULSE_SYNTH_RULE_OWNERSHIP_INVALID` and `payload-schema.json` did not.
