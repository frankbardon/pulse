# Synthetic data — `null_together`, never-firing rules, `constant`, the inspectable spec, `--suggest-rules` detection

Slice of `.claude/reference/synthetic-data.md` — load the index first, then only the slice(s) your change touches.

**`null_together` NULLS A BLOCK AS ONE DECISION, and the FIRST named field wins.** A question block is asked or skipped as a unit; independent per-member null draws turn it into a lottery (four members at rate 0.83 all-present on 45 of 40,000 rows instead of ~6,960, because 0.174⁴ ≠ 0.174). The resolution COPIES `nullMask[block[0]]` onto every other member (`applyNullTogether`, `internal/synth/rules_apply.go`) — every field has already drawn its null, so copying is the only resolution adding no randomness.
- **Every member but the first has its own `null_rate` IGNORED.** Warned at compile time when a member's rate differs from the gate's by more than `nullRateDivergenceThreshold` (**0.02**, a package constant), compared ABSOLUTELY against the GATE (the copy discards ROWS, so a relative test would scream at 0.001 vs 0.002 and stay quiet at 0.80 vs 0.84). Not refused: a real block with slightly drifted rates is still right to copy. ATTENTION kind (`rule null_together overrides a declared null_rate`).
- **The copy moves the null DECISION only, never a value**: an UN-nulled member publishes the value it drew.
- **Within ONE rule the block is the LAST write** (after `set_null` / `set` / `set_expr`), so `{"set_null": ["nps"], "null_together": ["nps", …]}` nulls the gate and the block follows; a `set_null` on a non-gate member in the same rule is overridden. ACROSS rules last-write-wins applies.
- **The case that bites is a later `set_expr`**: it CLEARS the null mask, so deriving members in a LATER rule un-nulls them on rows the block nulled (flags with no score). Put both slots in ONE rule.
- A non-nullable NON-GATE member warns (silent-zero kind), not refused — this slot copies a decision rather than making one. **The GATE is never reported**: a never-null gate is the IDIOM (the copy clears members' own MCAR nulls, leaving a later `set_null` as the only source of absence). Detail: `skills/synth-rule-nulls.md`.

**A rule that NEVER FIRES is reported, as an ATTENTION kind.** Eager validation cannot refuse a `when` that is never TRUE; such a rule compiles, applies to nothing, and the cohort is indistinguishable from one where it worked — so `rule never fired` is ATTENTION (`internal/synth/warning_summary.go`), never an expected-outcome count.
- **The count is over rows that reached the FILE, not draws**: `generate()` redraws rejected rows, so the counter commits per ACCEPTED row (`ruleApplier.commitRow`, `internal/synth/rules_firing.go`) and a rule firing only on rejected rows reports zero. Scratch slices are sized at compile; no RNG, no per-row allocation, bytes unchanged.
- Capped at `maxNeverFiredRuleWarnings` (20) with a counted roll-up. The count is deliberately NOT a `synth.Result` slot (that is the `--json` payload).
- **The message names the cause that applies to THAT rule**, in three arms: (1) CONSTRAINT — the rule selected rows and a constraint rejected every one, DETECTED (`noteFired` without `commitRow`); (2) PRE-ROUNDING — the predicate reads a field that rounds on write AND draws continuous values; the remedy is `round`, not `int` (`int` reaches a larger count by dropping respondents a point); (3) NEUTRAL — names each read field with type and distribution and RULES PRE-ROUNDING OUT for a quantizing field that draws exact values (`discrete`, `bernoulli`, `uniform_date`, `poisson`, `monotonic_from`). The third arm exists because a single rounding message was WRONG for most fields once small integers and booleans reconstruct exactly. Read fields are parsed from the AUTHOR'S SOURCE (`internal/synth/rules_firing_cause.go`); a field some `set_expr` writes loses its exactness claim. Detail: `skills/synth-rule-validation.md`.

**`constant` is normalised to the field's row shape.** `newConstantSampler` is the one sampler whose value comes from the DOCUMENT, so it alone can put the wrong Go type into the row (a JSON `true` on a `packed_bool` where the expression env promised float64, breaking every constraint and rule touching it at run time). The value is coerced ONCE at compile (`constantRowValue`), the only place the invariant can hold. A string on a non-decimal scalar is refused at parse (it would encode as a silent 0); an array on a `set_*` is accepted, and so is a JSON object `{"tv": true}`, because that is how an all-null `set_*` fallback marshals and the emitted spec must round-trip. `decimal128` keeps its exact string form (`encoding.ParseDecimal128`).

**The profile-derived spec is inspectable and modifiable (`--emit-spec` / `--rules`).** Without an emitted spec the whole rule layer was unreachable from the profile path and rule authoring was guesswork. Both flags are inert when absent (`TestSynthFromProfileCLI_EmitSpecDoesNotChangeTheCohort`).
- `--emit-spec <path>` (`synth.WriteSpec`, through `afero.Fs`) writes **the spec that actually generated, never a rendering or a re-derivation**. The gate is a ROUND TRIP compared BYTE FOR BYTE at one seed (`TestEmitSpec_RoundTripsToByteIdenticalCohort`) — a parse-only test passes against an emit that dropped `models` or coarsened a float. It is written BEFORE generation, so a failing run still leaves it, and it is the diagnostic for which models survived and how each field reconstructed.
- `--rules <path>` (`internal/synth.ApplyRulesFile`) loads a **bare JSON array — the `Spec.Rules` array itself** — and **REPLACES** `Spec.Rules` (a derived spec carries none; an append mode would invent an ordering question). `[]` means no rules; `{"rules": […]}` is REFUSED rather than read as zero rules. Validation runs at LOAD against a COPY (a derived spec bypasses `validateSpec`), so a refused file changes nothing; refusals keep their `PULSE_SYNTH_RULE_*` code plus `details["path"]`; unreadable = `DATA_FILE`, malformed = `SERVICE_VALIDATION`. Load, merge and emit live in `internal/synth/` (`spec_io.go`); the CLI routes coded refusals through `writeCodedErrorEnvelope`. Detail: `skills/synth-rules-from-profile.md`.

**Detecting structural rules from the data (`profile create --suggest-rules`).** Rule value is bounded by COVERAGE, and an unstated rule is invisible because **every marginal inside it is individually correct**. `--suggest-rules <path>` measures `P(target null | gate = level)` for every low-cardinality gate (`categorical_*`, `packed_bool`, `u4`) × every target off the SAME single scan (`internal/synth/profile_gating.go`) and proposes a `set_null` rule where levels split a target's null rate into ~1 and ~0. It writes the bare rules array `--rules` consumes UNMODIFIED, asserted by a GENERATION round trip (a shape test passes against predicates that never fire).
- **PROPOSED, never auto-applied**: a pattern can be sample coincidence. **Detection finds the STATISTICAL gate; a human knows the SEMANTIC one** — two gates can carry identical evidence, so output invites correction rather than asserting cause.
- Evidence rides **`RuleSpec.Evidence` (`_evidence`), THE ONE INERT SLOT** — never read by compile, apply or validate; not an action (a rule with only `_evidence` is still `PULSE_SYNTH_RULE_EMPTY`); `omitempty`. It rides the rule because the file must stay a bare array and separate evidence drifts when a candidate is deleted. `Profile.RuleCandidates` is `json:"-"`: with the flag only `warnings` moves in the profile, because an unreviewed claim must not ride inside the document that drives generation.
- Thresholds are package CONSTANTS (`gateHighNullRate` 0.98, `gateLowNullRate` 0.02, `minGateLevelSupport` = `MinPairObservations`, `maxGateLevels` 16, `maxRuleCandidates` 20), TIGHT because skip logic is exact in the source — looser thresholds propose ordinary association as structure, applied unconditionally and wrong on most selected rows.
- **Numeric gates are emitted through `round()`, uniformly, including `packed_bool`**: a bare `==` reads the pre-rounding float and under-fires silently, and mixing forms teaches that bare is sometimes fine. Every `when` is compiled against the rule layer's OWN environment before it is written (a field named `in` would otherwise yield an unloadable candidate).
- Counted, never silently dropped: a field over `maxGateLevels` is ABANDONED, never truncated; a gate whose only gated level is the null pseudo-level is CO-MISSINGNESS (each block member would restate the others N−1 times) and is handled by the co-missing detector (`synthetic-data/rule-detection.md`). Thin candidates ship with their support, warned thinnest-first. `gated_share` is a checking aid, NOT the ranking signal (the split implies it); ranking is target count then rows affected.
- **Candidates COMPOSE in declaration order** (a gate that nulls a flag makes later candidates keyed on that flag fire too). **Every gating candidate carries `"owns_nulls": true`**, sound because `gateLowNullRate` bounds the residual it zeroes; without it a gate repairs co-missingness only and every gated field's marginal overshoots (`g + (1−g)·r`). A co-missing candidate never carries the flag. Detail: `skills/synth-rules-from-profile.md` (Detecting rules from the data), `docs/src/cli/profile-create.md`.
