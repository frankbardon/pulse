# Synthetic data — cross-row reads, local time, rule draws, pair arbitration, synthetic-only twins

Per-topic slice of the synthetic-data reference (`row()` / `lag()` and lag partitions, the datetime stage and time effects, rule draws and helper fields, contested pair targets, synthetic-only twins). Index (preamble + section map): `.claude/reference/synthetic-data.md` — load it first, then only the slice(s) your change touches.

**Cross-row expressions (`row()`, `lag()`) read ACCEPTED-row order, and consume no RNG.** Generation is serial and row-major on one RNG with no shuffle, so a spec's declaration order IS the accepted-row order and "n rows back" is well defined (`internal/synth/row_lag.go`, `row_expr_builtins.go`). Three load-bearing facts, each SILENT if wrong. (1) The ordinal and the history advance on ACCEPTANCE only: a constraint-rejected attempt redraws at the SAME ordinal and never enters the lag buffer, so a rejecting spec still reads `0..row_count-1` and a `lag` never sees a row that was not written; `monotonic_from` counts the same way (a behaviour break from counting attempts). (2) Neither function draws: `row()` is a counter and `lag` a ring-buffer read after the rule pass, so adding one moves no other field's stream, and the rule pass keeps consuming NO RNG (the byte-identical-per-seed contract needs no new draw-order rule). The buffer holds the post-rule row value BEFORE encode rounding, so a `u*` / `f32` field can lag a value that differs from its stored one. (3) Null follows SQL `LAG`: a lagged null is null, never the default; the default fills only rows before `n`. The offset (1..1024) and name are literals, validated at spec parse, which is what lets the buffer be sized once. Profile capture, the fidelity report and `--suggest-rules` are deliberately blind to `lag` (no serial-dependence measurement exists); in augment mode the history starts empty at the first generated row. A contiguous panel is the author's job: `row() % P == 0 ? 0 : lag(...)`. An interleaved one takes the 4th argument (#572): `lag(name, n, default, "geo")`, a literal `categorical_*` field, keys one ring per partition value (null its own, created on the value's first ACCEPTED row; `nil` default dropped by the patcher), read under the CURRENT row's value and committed under the FINAL one — so `lagPartitionRefusal` refuses a partition a rule at or after the reading rule writes (the same rule included: snapshot reads), plus a non-categorical one, at validateSpec, `ApplyRulesFile` and `generate` alike (`PULSE_SYNTH_LAG_PARTITION_INVALID`); SILENT if dropped, since the row would commit under a key the read never used. Partitions interleave in draw order with no guarantee; a spec without the argument builds no partition state (`TestSynthLagPartition_UnpartitionedSpecsAreByteIdentical` pins pre-change digests). Skill: `skills/synth-cross-row.md`; worked spec: `internal/examples/synth/07_mmm_adstock.synth.json`.

**A `datetime` field is drawn in LOCAL time and stored as the UTC instant; the conversion is a stage, not a sampler detail.** `uniform_datetime` (`internal/synth/datetime.go`, #362) draws a local wall-clock reading — a local day by `weekday_weights` × that weekday's days in range (an INTENSITY: over whole weeks the realised weekday shares are the normalised weights, over a partial week they are not), a local hour by `hour_weights`, a uniform second — in exactly FOUR RNG draws per row whatever the weights, so the draw sequence is a function of the spec alone. The reading is converted to its instant by `datetimeStage.resolve`, which runs inside `drawRow` after the model stage and BEFORE the rule pass and consumes no RNG; a field with no zone or a UTC-equivalent one compiles no stage entry (its reading already is the instant), and a spec with no zoned datetime compiles no stage at all — `TestSynthDatetime_SpecWithoutDatetimeIsByteIdentical` pins every shipped example spec's bytes from before the type existed. Three facts are SILENT if got wrong. (1) Representation: before the stage a ZONED field's row value is the LOCAL reading, so any arm writing it (pair, copula, model) is converted too; after it, rules and constraints read and write the UTC instant the file stores (`TestUniformDateTime_RulesReadTheUTCInstant`). A rule rewriting the zone field after the stage does not move the datetime. (2) Per-row zone (`time_zone_field`, a `categorical_*` field of IANA names): a NULL zone cell makes the datetime null, never UTC — so a nullable zone field over a non-nullable datetime is refused at compile (`TestUniformDateTime_NullZoneCellIsNullDatetime`); an unknown name is `PULSE_TIMEZONE_UNKNOWN`, eagerly for a `weighted_categorical` domain and per row otherwise. (3) DST: a skipped or repeated reading follows `dst_policy` with the import's spellings (`temporal.ResolveLocal`): the default `error` stops the run (`PULSE_SYNTH_DST_NONEXISTENT` / `PULSE_SYNTH_DST_AMBIGUOUS`) — the reversible default, since relaxing a refusal later is additive — while `earlier` / `later` resolve and add one terminal warning per field with the gap / overlap counts, committed on ACCEPTED rows only (`TestUniformDateTime_DSTGapEveryPolicy`, `_DSTOverlapEveryPolicy`, `_ResolvedCountsAcceptedRowsOnly`). Zone math is `internal/temporal` only (`TestNoZoneMathOutsideTemporal`); the writer stores `int64(Floor(f+0.5))` and refuses a non-finite value rather than writing a platform-dependent `int64(NaN)`. Skill: `skills/synth-datetime.md`.

**Time effects read a date-family field on ITS clock, and a profiled `datetime` is a marginal, never a number.** `trend(t, slope)`, `season(t, "dow"|"hour"|"month", weights)` and `between(t, a, b)` (`internal/synth/row_time.go`, #363) take a BARE declared `date` / `datetime` field as `t`; `timePatcher` rewrites each call onto an internal `:`-named function carrying the field NAME, so the function reads the field's null bit and its declaration (`rowTimeFields`: kind, fixed zone, zone field, `start`) — `trend` alone also accepts any number (`slope × t`). Unit, weights and bounds are literals settled at parse by `timeCallShape`, called from the shared walker (`rowExprStaticRefusal`, now handed the time declarations), so validateSpec, compileRules / compileConstraints and both `--suggest-rules` detectors refuse or accept identically (`PULSE_SYNTH_RULE_EXPR_INVALID` in a rule, `SERVICE_VALIDATION` in a constraint — no new code). Three facts are SILENT if wrong. (1) The clock: a `datetime` is read in its field's fixed `time_zone`, in the zone the datetime STAGE resolved this row in for a `time_zone_field` (`datetimeStage.rowZoneOf`, so a rule rewriting the zone field before the call moves nothing — `TestRowTime_PerRowZoneIsTheStagesNotARewrite`), else UTC; a `date` is a calendar day. Reading the instant in UTC instead quietly shifts every weekday / hour / window by the zone offset, which is exactly what `TestSynthTimeEffects_RecoveredByAQuery` catches by recovering each effect EXACTLY through `GROUP_DATE` with `tz_field`. (2) `trend` counts fractional days on the local clock from local midnight of the field's `start` (`uniform_date` / `uniform_datetime` only — a field without one is refused rather than silently counted from the epoch); `between`'s date-only upper bound covers its whole day (`temporal.DayEndWall`), an offset-bearing bound is refused (a bound is a reading, not an instant). (3) No RNG and a null `t` returns null (`lag`'s rule), so adding a call moves no drawn value and an unguarded null is a loud row-time fault. Zone math is `internal/temporal` only (`LocalWall`, `ParseWall`, `ElapsedDays`, `LocalParts`). **Capture:** `profileRecords` gives a `datetime` its own accumulator (`datetimeAcc`) and section (`FieldProfile.Datetime`, `synth.DatetimeProfile`: UTC `start` / `end`, `weekdays` Monday first, `hours`) instead of the numeric default branch — which used to put epoch seconds into `pairwise`, `conditional` numeric pairs and `--fit-models` targets (`modelTargetFields` now excludes it), all of which a `uniform_datetime` cannot ride (it has no moments). `SpecFromProfile` rebuilds it as UNZONED `uniform_datetime`: `hour_weights` = the hour counts, `weekday_weights` = each count ÷ that weekday's days in `[start, end]` (the distribution's weight is a per-day INTENSITY; raw counts over-weight the weekdays a partial week repeats — `TestProfileDatetime_WeekdayWeightsArePerDay`). The schema carries no zone, so the capture is UTC and reproduces the instants' UTC weekday / hour marginals; a volume trend across days is NOT captured. A document from before the section keeps its `numeric` summary and still rebuilds as a clamped `normal`; a datetime-free document is byte-identical. Gates: `internal/synth/row_time_internal_test.go`, `profile_datetime_internal_test.go`, `internal/integration/synth_time_effects_test.go`, `internal/cli/synth_datetime_test.go`. Skill: `skills/synth-datetime.md` (Time effects in rules, Profile capture).

**Rule draws read a counter-based stream per call site, never the generation RNG; a helper field is drawn but never written.** `uniform()` / `bernoulli(p)` (`internal/synth/row_draw.go`, #364) are rewritten by `drawPatcher` onto internal `:`-named functions carrying a site index; after each rule expression compiles, `compileRules` keys the sites it registered by FNV-1a 64 of a structural label — `rule/<index>/when/<k>` or `rule/<index>/set_expr/<field>/<k>`, `k` the call's position in the parse walk. A value is `drawUniformAt(seedKey, siteKey, ordinal, attempt, call)`: `seedKey = drawStreamKey(seed, ruleDrawDomain)`, then splitmix64 chained over the site key, the ACCEPTED-row ordinal, `attempt` (the constraint-rejected tries at this ordinal, stamped by `generate` through `setDrawAttempt`, reset to 0 on acceptance) and `call` (this site's calls within the attempt, reset by `beginDrawAttempt` at the top of every rule pass), top 53 bits × 2⁻⁵³ — integer-only, so bit-identical on every architecture. **This is the reusable design**: another stage needing seeded draws that must not move the main stream (E2-S1's numeric-predictor order) derives its own seed key with a different domain constant and its own labels, and keys on ordinal + attempt the same way. Three facts are SILENT if wrong. (1) No shared position: because no site reads an offset in a shared stream, a draw-free spec consumes exactly its old RNG sequence (`TestRuleDraw_EveryExistingSpecFixtureIsByteIdentical` pins every shipped spec fixture's bytes from before the functions), ADDING a draw moves no other field (`TestRuleDraw_AddingADrawMovesNoOtherField`), and a short-circuited `when` or an unfired rule moves no later draw. A sequential per-site stream was rejected: it is deterministic too, but every row's draw would depend on how often earlier rows evaluated the site. (2) Rejection DISCARDS, never replays: the redraw at the same ordinal reads `attempt + 1`, so a constraint on a drawn value terminates and the accepted value is predictable from the formula alone (`TestRuleDraw_RejectedAttemptsDrawFreshValuesFromTheDocumentedStream` recomputes every row and the rejection count from it). Without the attempt term the same draw is rejected forever. (3) Draws are refused in `constraints[]` (`constraintExprStaticRefusal`, at spec validation and `compileConstraints` alike) — an acceptance test that draws makes rejection random — as is bad arity or a literal `p` outside [0, 1]; a computed `p` outside [0, 1] or NaN is refused on its row, the builtin's `*CodedError` lifted out of expr's wrapper by `ruleDrawError`: all `PULSE_SYNTH_RULE_DRAW_INVALID`. **Helpers (`FieldSpec.Output`, `"output": false`):** `buildSchema` still builds every field's sampler in spec order — so hiding a field moves no other column (`TestHelperField_AbsentFromSchemaAndMovesNoOtherColumn`) — but lays out a WRITTEN schema of the output fields only (`CsvColumnIdx` and VECTORS indices are written-schema positions); a helper's `writerField.helper` points at a Field outside the schema, `encodeRow` skips it and numbers null-bitmap bits by written position. Rules, constraints, `isnull` and `lag` read it from the row like any field; a spec with no written field is `SERVICE_VALIDATION`. Profile and `SpecFromProfile` never see one (the file does not carry it); the fidelity report says so instead of scoring an empty partition — `BuildModelFidelity` gives a model over a helper target or predictor an `Error` (without it the refit reported a fabricated intercept), and `ScoredRelationships` drops each pair or correlation reading a helper with a warning. Claims (`conflict.go`) need no change: a helper is a full generation target. Skill: `skills/synth-rule-draws.md`; fixture: `internal/synth/testdata/credit_rule_draws.synth.json` (the credit idiom: a PD in a rule, `bernoulli(true_pd)`, one stored `uniform()` reused, both helpers absent).

**A contested pair target goes to the strongest association, and the options of one set field depend on each other.** Capture declares every conditional pair in field order (`i < j`), so the old first-declared arbitration let the EARLIEST field in the schema drive every later one: on the customer showcase a noise `region` conditioned all five product options and `contract`, while `plan` and the options that really drive them were dropped with an ordinary-looking conflict warning. `resolveConflicts` now collects the five pair stages as candidates per target and keeps the strongest — bias-corrected Cramér's V (Bergsma) for a categorical or set-option target, adjusted η² (ε², from each category's `n`, mean and sample std) for a numeric one — ties to the first-declared, and across kinds (a set option bid for by a set-set and a set-categorical pair goes to the stronger). The bias correction is load-bearing: plain V grows with the table's shape, so a ten-level noise field would out-bid a weak real two-level driver. **Failure modes, each silent:** a strength computed from a numeric pair missing a category `n` is a guess, so such a target is arbitrated first-declared (never computed from the rest); products in the strength sums are `float64(a*b)` because a last-bit cross-arch difference could flip a near-tie and change the file; and a pre-claimed target (rule, model, shape) is won by no pair. Winners claim before losers are reported, so every warning names the pair that actually kept the target. `Spec.PairArbitration` (`"strength"` default, `"declared"` restores the old rule exactly — the pin `TestProfileNumericPredictors_AbsentIsByteIdenticalToPreChange` generates under it) is the author's override; capture order stays topological for whichever pairs win, because a pair's source is declared before its target. **Within-set capture** (`computeWithinSetPairs`): for each option `j` of one set field, at most ONE `set_set_pairs` entry with `set_a == set_b`, from the earlier option with the strongest V, kept only at V ≥ 0.1 (φ² ≥ 0.01, the model selection floor) — one per target because a target draws from one pair, and it bounds a 256-member set at 255 entries instead of 32,640. The 2x2 table is derived from per-row co-selection counts (cost ∝ selected options², not dictionary²), and a combination the source never shows is an ABSENT cell, which the sampler reads as probability 0 — "tv requires broadband" generates exactly zero tv-without-broadband rows (5,113 of 40,000 before). **Generation order is the second half:** within-set pairs run in their own stage AFTER set-categorical (`rowStages.setWithinPairs`), because the source option is often resampled there (broadband from region); run with the cross-field set-set stage they read a broadband state the row does not keep and the impossible rows come back. Cross-field set-set pairs keep their old stage, so a spec without within-set pairs draws the same RNG sequence. Validation now accepts `set_a == set_b` and refuses `option_a == option_b` on one field. Gates: `TestPairArbitration_StrongestAssociationKeepsContestedTarget`, `TestPairArbitration_NumericTargetByAdjustedEtaSquared`, `TestPairArbitration_SetOptionTargetAcrossKinds`, `TestPairArbitration_Validation`, `TestWithinSet_ImpossibleCombinationStaysImpossible`, `TestContingencyStrength_*`, `TestGroupedStrength_KnownGroups`. Skills: `skills/synth-conflicts.md`, `skills/synth-set-fields.md`.

**A synthetic-only twin drops the source rows from the FILE, never from the report; profile-path constraints are the spec's own.** `SynthOptions.SyntheticOnly` / `synth from-profile --synthetic-only` (#368) writes the generated rows alone under `buildOutputSchema(src, gen, false)`: the source's fields, descriptions and VECTORS, no `_synthetic` column (every row would carry `true`), FRESH dictionaries, so a categorical level only the source holds is not written either. The source is still read, and the alignment checks still refuse a profile from another cohort. The rows are drawn ONCE (`AugmentWithFidelityCohort`) and re-encoded into both layouts, so the report — built from the in-memory TAGGED cohort `encodeTaggedCohort` returns, never written — scores exactly the rows the file holds. The `--fidelity-model` synthetic refit reads the whole output (no tag to filter on). The report is byte-identical to the tagged run's at the same seed (`TestSynth_SyntheticOnlyFidelityReportIsTheTaggedRunsReport`). `--constraints` (`ApplyConstraintsFile`) loads the bare `constraints` array, REPLACES, and compiles it eagerly naming the file. `--max-rejection-rate` (`ApplyMaxRejectionRate`, [0, 1), NaN refused) sets the ceiling `generate` enforces with `PULSE_SYNTH_CONSTRAINT_INFEASIBLE`. Both land before `--emit-spec`; absent, both are byte-identical. Gates: `TestSynth_SyntheticOnlyWritesGeneratedRowsAlone`, `TestApplyConstraintsFile_*`, `TestApplyMaxRejectionRate_BoundsTheProfilePathRun`, `TestSynthFromProfileCLI_SyntheticOnlyWithConstraints`. Skills: `skills/synth-fidelity-report.md`, `skills/session-synth-flags.md`.
