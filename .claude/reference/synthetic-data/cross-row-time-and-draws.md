# Synthetic data — cross-row reads, local time, rule draws, pair arbitration, synthetic-only twins

Slice of `.claude/reference/synthetic-data.md` — load the index first, then only the slice(s) your change touches.

**Cross-row expressions (`row()`, `lag()`) read ACCEPTED-row order, and consume no RNG.** Generation is serial and row-major on one RNG, so declaration order IS accepted-row order and "n rows back" is well defined (`internal/synth/row_lag.go`, `row_expr_builtins.go`). Each fact below is SILENT if wrong.
1. **The ordinal and the history advance on ACCEPTANCE only.** `row()` (`func() int`) is stamped before every attempt as the count already accepted, so a rejected attempt redraws at the SAME ordinal and the cohort reads exactly `0..row_count-1`; a rejected row never enters the lag buffer. `monotonic_from` counts the same way: it commits its step after accept (`acceptCommitters`, which must look through the null and rule-owned-null wrappers — a wrapper hiding the counter would freeze the column or restore gaps).
2. **Neither function draws.** `row()` is a counter, `lag` a ring-buffer read after the rule pass, so adding one moves no other field's stream.
3. **`lag(name, n[, default])` returns `name`'s FINAL value on the n-th previous accepted row** — the post-rule row value BEFORE encode rounding (a `u*` / `f32` can lag a value that differs from its stored one), typed as the field reads. **Null follows SQL `LAG`**: a lagged null is null, never the default; the default fills only rows before `n`. An unguarded null in arithmetic or written by `set_expr` is a loud row-time fault, never 0.
- `name` must be a string literal naming a declared field (`PULSE_SYNTH_LAG_FIELD_INVALID`) and `n` an integer literal 1..`maxLagOffset` = **1024** (`PULSE_SYNTH_LAG_OFFSET_INVALID`), checked at spec parse and compile, because they SIZE the state: `lagBuffer` holds max-n rows over ONLY lagged fields, committed beside `ruleApplier.commitRow`. A lag-free spec builds no buffer (byte-identical).
- Typing: `lagPatcher` rewrites each call onto one of four internal `:`-named functions carrying the field's class (expr types a function once per name), which keeps parse-time coercion live; bare `lag` is not registered.
- Self-lag is allowed and pre-claims its target (`synthetic-data/structural-rules.md`).
- Profile capture, the fidelity report and `--suggest-rules` are deliberately blind to `lag`/`row` (the detectors only compile them). In augment mode `row()`, `monotonic_from` and the lag history start at the first GENERATED row.
- A contiguous panel is the author's job (`row() % P == 0 ? 0 : lag(...)`). An interleaved one takes the 4th argument: `lag(name, n, default, "geo")`, a literal `categorical_*` field, keys one ring per partition value, read under the CURRENT row's value and committed under the FINAL one — so `lagPartitionRefusal` refuses (`PULSE_SYNTH_LAG_PARTITION_INVALID`) a partition that a rule at or after the reading rule writes, or a non-categorical one; otherwise the row commits under a key the read never used, silently. Unpartitioned specs build no partition state (`TestSynthLagPartition_UnpartitionedSpecsAreByteIdentical`).
- Skill: `skills/synth-cross-row.md`; worked spec: `internal/examples/synth/07_mmm_adstock.synth.json`.

**A `datetime` field is drawn in LOCAL time and stored as the UTC instant; the conversion is a stage, not a sampler detail.** `uniform_datetime` (`internal/synth/datetime.go`) draws a local day by `weekday_weights` × that weekday's days in range (an INTENSITY: realised shares equal the weights only over whole weeks), a local hour by `hour_weights`, a uniform second — exactly FOUR RNG draws per row whatever the weights. `month_weights` (`internal/synth/month_weights.go`; `uniform_date` too) adds a per-month intensity (day weight = weekday × month, separable by assumption) drawn as ONE `Float64` (three draws per datetime row); only a spec carrying it takes that path, so shipped specs stay byte-identical. `datetimeStage.resolve` converts reading → instant inside `drawRow` after the model stage and BEFORE the rule pass, consuming no RNG; unzoned / UTC-equivalent fields compile no entry (`TestSynthDatetime_SpecWithoutDatetimeIsByteIdentical`). SILENT if wrong:
1. **Representation**: before the stage a zoned field's row value is the LOCAL reading (so any arm writing it is converted too); after it, rules and constraints read and write the UTC instant. A rule rewriting the zone field after the stage does not move the datetime.
2. **Per-row zone** (`time_zone_field`, a `categorical_*` of IANA names): a NULL zone cell makes the datetime null, never UTC — so a nullable zone field over a non-nullable datetime is refused at compile. An unknown name is `PULSE_TIMEZONE_UNKNOWN` (eager for a `weighted_categorical` domain, else per row).
3. **DST** follows `dst_policy` (`temporal.ResolveLocal`): default `error` stops the run (`PULSE_SYNTH_DST_NONEXISTENT` / `_AMBIGUOUS`) — the reversible default; `earlier` / `later` resolve with one warning per field counting ACCEPTED rows only.
- Zone math is `internal/temporal` only (`TestNoZoneMathOutsideTemporal`). The writer stores `int64(Floor(f+0.5))` and refuses a non-finite value rather than writing a platform-dependent `int64(NaN)`. Skill: `skills/synth-datetime.md`.

**Time effects read a date-family field on ITS clock, and a profiled `datetime` is a marginal, never a number.** `trend(t, slope)`, `season(t, "dow"|"hour"|"month", weights)`, `between(t, a, b)` (`internal/synth/row_time.go`) take a BARE declared `date` / `datetime` field (`trend` also any number); `timePatcher` rewrites each call to carry the field NAME so it reads the null bit and declaration. Literal arguments are settled at parse by `timeCallShape` from the shared walker, so every validator agrees (no new code). SILENT if wrong:
1. **The clock**: a `datetime` is read in its fixed `time_zone`, else in the zone the datetime STAGE resolved for this row (`datetimeStage.rowZoneOf` — a later rewrite of the zone field moves nothing), else UTC; a `date` is a calendar day. Reading in UTC shifts every weekday / hour by the offset (`TestSynthTimeEffects_RecoveredByAQuery` recovers each effect exactly via `GROUP_DATE` with `tz_field`).
2. `trend` counts fractional local days from local midnight of the field's `start` (a field without one is refused, never counted from the epoch); `between`'s date-only upper bound covers the whole day; an offset-bearing bound is refused.
3. No RNG; a null `t` returns null.
- **Capture**: a `datetime` gets its own accumulator and `FieldProfile.Datetime` section (`start` / `end`, `weekdays` Monday first, `hours`, `month_start` + `months`), never the numeric branch — epoch seconds once leaked into pairwise, conditional pairs and model targets, none of which a `uniform_datetime` can ride. `SpecFromProfile` rebuilds `uniform_datetime` with `weekday_weights` = count ÷ that weekday's days in range (raw counts over-weight partial-week weekdays) and `month_weights` = count ÷ the month's in-range weekday weights. A one-month series emits nothing; a series not fitting its range emits nothing and WARNS. Pre-section documents keep their numeric summary and rebuild as a clamped normal.
- **The capture clock** (`internal/synth/profile_zone.go`): `ProfileOptions.TimeZone` or `TimeZoneField` (CLI `--time-zone` / `--time-zone-field`, exclusive) reads every count on the LOCAL clock and records it; with neither, a cohort's declared default zone field is used; else UTC (byte-identical). `SpecFromProfile` emits `dst_policy: "earlier"` because a refilled reading can land in a gap and `error` would abort the run. SILENT if wrong: (1) a UTC capture of a local schedule yields a twin faithful on a clock nobody reads (`TestSynthProfileZone_LocalMarginalRecoveredByAQuery`); (2) a reading whose zone cell is null has no local clock — left out of every count with a warning, never read on UTC, and the rebuilt datetime is `nullable` whenever the zone field carries nulls. The fidelity `shape` reads the same clock (`synthetic-data/residuals-and-fidelity.md`).
- Skill: `skills/synth-datetime.md` (Time effects in rules, Profile capture).

**Rule draws read a counter-based stream per call site, never the generation RNG; a helper field is drawn but never written.** `uniform()` / `bernoulli(p)` (`internal/synth/row_draw.go`) are rewritten by `drawPatcher` onto internal functions carrying a site index; `compileRules` keys each site by FNV-1a 64 of a structural label (`rule/<index>/when/<k>`, `rule/<index>/set_expr/<field>/<k>`). A value is `drawUniformAt(seedKey, siteKey, ordinal, attempt, call)` — splitmix64 chained over seed domain, site, ACCEPTED-row ordinal, rejected-attempt count and per-attempt call count; integer-only, so bit-identical on every arch. **This is the reusable design**: another stage needing draws that must not move the main stream derives its own domain constant and labels and keys on ordinal + attempt. SILENT if wrong:
1. **No shared position**: a draw-free spec consumes its old RNG sequence (`TestRuleDraw_EveryExistingSpecFixtureIsByteIdentical`), adding a draw moves no other field, an unfired rule moves no later draw. A sequential per-site stream was rejected — each row's draw would depend on how often earlier rows evaluated the site.
2. **Rejection DISCARDS, never replays**: the redraw reads `attempt + 1`; without the attempt term a constraint on a drawn value rejects forever.
3. **Draws are refused in `constraints[]`** (an acceptance test that draws makes rejection random), as are bad arity and a literal `p` outside [0, 1]; a computed bad `p` is refused on its row — all `PULSE_SYNTH_RULE_DRAW_INVALID`.
- **Helpers (`"output": false`)**: every sampler is still built in spec order (hiding a field moves no other column), but only output fields are written (`CsvColumnIdx`, VECTORS indices and null-bitmap bits use written positions). Rules, constraints, `isnull` and `lag` read helpers like any field; a spec with no written field is `SERVICE_VALIDATION`. The fidelity report gives a model over a helper an `Error` (otherwise the refit reports a fabricated intercept) and drops pairs reading a helper with a warning. Skill: `skills/synth-rule-draws.md`; fixture `internal/synth/testdata/credit_rule_draws.synth.json`.

**A contested pair target goes to the strongest association, and the options of one set field depend on each other.** Capture declares pairs in field order, so first-declared arbitration let the EARLIEST schema field drive every later one (a noise `region` beat the real drivers). `resolveConflicts` collects the pair stages as candidates per target and keeps the strongest — bias-corrected Cramér's V (Bergsma) for categorical / set-option targets, ε² for numeric — ties to first-declared, across kinds. The bias correction is load-bearing: plain V grows with table shape, so a wide noise field would out-bid a real two-level driver.
- **Silent failure modes**: a numeric pair missing a category `n` makes its strength a guess, so that target is arbitrated first-declared; strength sums use `float64(a*b)` (a cross-arch last bit could flip a near-tie); a pre-claimed target (rule, model, shape) is won by no pair.
- **The noise floor (`Spec.PairStrengthFloor`, default `DefaultPairStrengthFloor` = 0.02).** Below it two noise bidders handed the target to whichever noise measured larger — a choice that moved with the seed. A target whose strongest bidder is sub-floor goes to the FIRST-DECLARED bidder, and each loser's warning says so; an above-floor bidder always beats sub-floor ones. The floor is on the V scale; a numeric ε² is compared against `float64(floor*floor)`, never `math.Sqrt(ε²)` (which could merge distinct strengths into a tie). 0.02 sits above all measured noise (V ≤ 0.015) and below every winning real driver (V ≥ 0.036). `0` restores floorless arbitration byte-for-byte; negative / non-finite is `SERVICE_VALIDATION`.
- `Spec.PairArbitration`: `"strength"` (default) or `"declared"` (the old rule exactly, ignores the floor). Winners claim before losers are reported, so every warning names the pair that kept the target.
- **Within-set capture** (`computeWithinSetPairs`): per option, at most ONE `set_set_pairs` entry with `set_a == set_b`, from the earlier option with the strongest V, kept at V ≥ 0.1 — one per target because a target draws from one pair, bounding a 256-member set at 255 entries. A combination the source never shows is an ABSENT cell, read as probability 0, so "tv requires broadband" generates zero violations.
- **Generation order is the second half**: within-set pairs run in their own stage AFTER set-categorical (`rowStages.setWithinPairs`), because the source option is often resampled there; run earlier they read a state the row does not keep and impossible rows come back. Validation accepts `set_a == set_b`, refuses `option_a == option_b` on one field.
- Skills: `skills/synth-conflicts.md`, `skills/synth-set-fields.md`.

**A synthetic-only twin drops the source rows from the FILE, never from the report; profile-path constraints are the spec's own.** `SynthOptions.SyntheticOnly` / `--synthetic-only` writes generated rows alone: the source's fields, descriptions, VECTORS and default zone field (a generated invalid zone is `PULSE_TIMEZONE_UNKNOWN` at write), no `_synthetic` column, FRESH dictionaries (a level only the source holds is not written). The source is still read and alignment-checked. Rows are drawn ONCE and re-encoded into both layouts, so the report — built from the in-memory TAGGED cohort — scores exactly the rows the file holds and is byte-identical to the tagged run's (`TestSynth_SyntheticOnlyFidelityReportIsTheTaggedRunsReport`). `--constraints` (`ApplyConstraintsFile`) loads the bare `constraints` array, REPLACES, compiles eagerly naming the file; `--max-rejection-rate` ([0, 1), NaN refused) sets the ceiling enforced by `PULSE_SYNTH_CONSTRAINT_INFEASIBLE`. Both land before `--emit-spec`; absent, byte-identical. Skills: `skills/synth-fidelity-report.md`, `skills/session-synth-flags.md`.
