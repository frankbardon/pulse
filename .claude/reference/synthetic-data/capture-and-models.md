# Synthetic data — conditional pair capture, per-numeric models, predictor selection, thin levels, generation, shape conditioning, float fusion

Slice of `.claude/reference/synthetic-data.md` — load the index first, then only the slice(s) your change touches.

## The contract

`pulse profile create --conditional` (`synth.ProfileOptions.IncludeConditional`) adds an additive `conditional` section: for numeric-numeric pairs a row-aligned `{a, b, rho, n}` where `n` is the true co-occurrence count — more accurate than `--include-correlations` `pairwise`, whose independently-capped per-field reservoirs drift out of alignment once either field has nulls. `SpecFromProfile` prefers `conditional.numeric_pairs` over `pairwise`; without it, it falls back to `pairwise` exactly as before, so no existing profile document is invalidated.

**Thin-pair warning (generic mechanism).** A pair with support `n` below **`internal/synth.MinPairObservations` (30)** still ships but appends a warning to `Profile.Warnings`. `thinPairWarning` wraps `thinSupportWarning(subject, a, b, n, threshold, consequence)`, shared across pair kinds and with thin-model-level shrinkage, so every thin-support line reads the same shape. Reuse it; do not invent another.

**Per-numeric linear models (`models` profile section).** `--fit-models` (`ProfileOptions.FitModels`) adds an additive `omitempty` section: one least-squares model per numeric field, regressed on the categorical levels, `set_*` options and earlier-declared numerics that selection admitted, via `internal/processing/regression`'s OLS engine.
- The cohort is read ONCE (`TestProfileModels_RidesTheExistingScan`), but the scan only retains a bounded Algorithm-R row snapshot (`modelResidualCap`, 10,000); selection, fitting and residuals run over that snapshot afterwards — a frequency ranking does not exist until rows have been seen. So `n_obs` is support WITHIN the snapshot, not the cohort row count.
- Entry shape `{field, intercept, predictors, references, n_obs, r2, residual_std, shrinkage_alpha}`; `predictors[]` is `{kind, field, level, coefficient}`; `shrinkage_alpha` absent ⇔ unpenalized OLS.
- **A coefficient is addressed by `(field, level)`.** The solver's internal design-column name is `json:"-"` — serialising it would freeze that encoding into the file format.
- `references[]` names the level each categorical dropped into the intercept, so a reader holding k−1 of k levels need not guess the baseline; a set-only model has no `references` (a multi-select is not a partition).
- Fitted residuals are `json:"-"` (reachable via `synth.Profile.FittedModels()` in-process; ABSENT from a re-read document).
- Without the flag no `models` key is emitted (byte-identical); with it only that key moves (`TestProfile_ModelsSection_IsPurelyAdditive`). A model that would serialise a non-finite float is dropped with a warning rather than failing the whole marshal.

**Predictor selection is automatic, absolute, and has no user-facing override.** Two mechanisms in fixed order, `internal/synth/profile_models_select.go`:
1. **Top-K collapse on dummy expansion** (structural). A categorical contributes one column per top-`TopK` level plus ONE catch-all carried as an ordinary level named `"other"` (`otherCategoryLabel`) — the same collapse used throughout the document. Without it the flag produces nothing on real data: an unbounded 16-categorical expansion was 2,420 columns and every target was skipped as too wide. The catch-all is never the reference level.
2. **Variance-explained floor** (statistical). A candidate FIELD enters iff its ADJUSTED between-group share of the target's SS reaches `synth.minVarianceExplained` (**0.01**). A package constant, not an option (`TestModelSelection_NoUserFacingOverride`: only `TopK` moves an admission). **Deliberately NOT statistical significance**: at large n every candidate is significant, so a p-value gate silently admits everything; an absolute floor is n-invariant (`TestModelSelection_AdmissionInvariantToRowCount`). Adjusted, so a wide collapsed field is not admitted for its width alone.
- Scoring is MARGINAL (each candidate vs the raw target), so two collinear candidates both enter — incremental scoring would make the admitted set depend on candidate order. Redundancy is resolved by the SOLVER: a design refused as rank-deficient is refitted with its WEAKEST predictor dropped, up to `maxModelRefitRounds` (4). Nesting is not detected directly because the dependency that bites is LINEAR, not functional (exact ages covering a band sum to the band's indicator).
- Selection prunes design columns degenerate ON THE ROWS THE FIT ADMITS (selection scores pairwise, the fit deletes listwise, so a level can have pairwise support but no listwise rows). A single-level candidate drops by the same arithmetic.
- A target nothing clears gets a **zero-predictor model** (own mean and spread, `r2: 0`), warned `carries no predictors: …` and NEVER `skipped: …` — a complete model and a failed capture mean opposite things.
- `maxModelColumns` (256) is a backstop only (the accumulator is O(p²) per row).
- **A NUMERIC candidate enters only a target declared AFTER it in the schema**, scored by adjusted r² against the same floor, carried as one `kind: "numeric"` column (`level: ""`). A numeric predictor is read off the row being built, so it must be drawn first; admitting only earlier→later edges makes every model set a DAG, so no cycle needs breaking. Three sites had to learn a scalar column, each silently wrong otherwise: `prune` judges it CONSTANT rather than by non-zero count, thin-level shrinkage skips it, the fidelity refit reads it as a value not an indicator.
- **The overlap with `--residual-correlations` is exact**: an OLS residual is orthogonal to its design, so two numerics joined by a numeric predictor show residual correlation ~0; the section holds only what the DAG leaves over. No numeric clearing the floor ⇒ byte-identical pre-change document (`TestProfileNumericPredictors_AbsentIsByteIdenticalToPreChange`).

**Thin LEVELS inside an admitted predictor are SHRUNK, never dropped and never refused.** Top-K bounds RANK, not SUPPORT, and listwise deletion cuts support again. A design column whose listwise support falls below `internal/synth.minLevelObservations` (**50**) puts the whole fit on the engine's ridge — `Penalty = "l2"`, `Alpha = minLevelObservations / n_admitted`, never a hand-rolled penalty (`internal/synth/profile_models_shrink.go`).
- Its own constant, not `MinPairObservations`: the two answer unrelated questions and must not be coupled.
- **Shrinkage SCALES with thinness**: λ = 50/n adds exactly 50 pseudo-observations, so a level keeps n_j/(n_j + 50) of its free coefficient, toward the REFERENCE level (the conservative reading). `shrinkage_alpha` rides the document because a shrunk coefficient is a different kind of number; `alpha × n_obs` recovers the pseudo-count.
- Do not "fix": (1) well-supported columns move slightly too (~50/n_j) — unavoidable with one alpha; (2) it is GATED on a thin column existing, so a clean design stays exact OLS (`TestProfileModels_NoThinLevelLeavesTheFitUnpenalized`), with a bounded discontinuity at the boundary; (3) a penalized Gram is positive-definite, so the rank-deficiency refit never fires and collinear predictors are jointly shrunk instead.
- Warnings are aggregated by (field, level) across targets (thinnest support, model count), then capped at `maxThinLevelWarnings` (20) with one `+N further thin model level(s)` summary naming the fix (lower `--top-k`) — per-(target, level) emission restated one finding hundreds of times.

**`models` retires the numeric-target conditional arms, PER TARGET.** For a numeric field that lands a model, `SpecFromProfile` leaves it out of `Spec.CategoricalNumericPairs` / `Spec.SetNumericPairs` — those arms each resample from one paired field, so on a wide cohort all but the first are dropped by `resolveConflicts`; an additive model accounts for all at once. A HAND-AUTHORED spec declaring both is arbitrated in `internal/synth/conflict.go`: the modelled field is PRE-CLAIMED and the pair dropped with a conflict warning. The decision is per-FIELD: a model dropped in translation (unknown predictor, zero-predictor model) warns `model for numeric field %q not applied: …` and KEEPS that field's conditional pair — a document-wide rule would reconstruct such a field from nothing, strictly worse than no flag. The non-numeric-target arms are untouched, so `--conditional` + `--fit-models` keeps both halves. Absent `models` every arm populates as before (`TestSpecFromProfile_PreModelsDocumentUnchanged` pins a pre-change document to a fixed `Spec.Hash()`). Detail: `skills/synth-profile-capture.md`.

**Generation: the composed model draw.** A modelled numeric is composed in one step at the END of `drawRow` (`internal/synth/model_draw.go`): `value = Q(Φ(μ(row) + σ·z))`, μ the linear prediction **standardised by the target's reconstructed marginal moments**, σ = `ResidualStd`/std, z ~ N(0,1), Φ / Q are `copula.go`'s `phi` / `quantileFor` (reused so modelled and correlated fields agree on "this field's marginal"). Standardising is load-bearing: the fit is in raw units and Φ takes a standard-normal argument.
- **Because μ lives on the latent scale, a coefficient shifts the LATENT Gaussian, not the value — NON-LINEAR in value space for any non-normal Q. State this wherever a coefficient is surfaced.** For a `normal` target it collapses exactly to `prediction + ResidualStd·z`.
- MAIN EFFECTS only — one coefficient per (field, level); interactions would reintroduce the width problem, and scoring, wire format and refit all assume one term per (field, level).
- **A term fires only on an exact match, ZERO otherwise** (dummy coding): an unseen level reads as the reference, and a NULL predictor contributes zero (listwise deletion means the fit never saw one).
- **The top-K catch-all is NOT an unseen level: it carries its own firing term** — an ordinary `categorical_level` predictor with `level: "other"`. Generation reaches it because conditional capture collapses out-of-top-K values to `"other"` and the model stage runs LAST, reading the emitted value. Mapping it to a numeric kind is SILENT and costs the WHOLE model (`modelSpecFromProfile` refuses a model on one unusable predictor) — once applying 20 of 105 models, and the catch-all was the DOMINANT arm. `TestModelPredictorKind_CoversEveryDummyColumnKind` pins the enum's cardinality so a new member fails a test.
- **Exactly one clamp, once, on the final value**: the model's own `Min`/`Max` win, the field's marginal clamp is the fallback.
- **Ordering is spec-derived, never map-derived**: the model stage runs after every pair stage and the correlator; drawers sort into SCHEMA order, then DEPENDENCY order (`drawOrder`, Kahn, lowest schema index first) when a numeric term reads another modelled field — with no such term this IS schema order. A hand-authored cycle is `SERVICE_VALIDATION`. A numeric term reads the predictor's STORED value (`storedScalar`) because the fit read stored values. Each drawer consumes exactly one `NormFloat64()` per row *unconditionally* (even at `ResidualStd` 0), so the stream depends only on the number of models. No `models` ⇒ zero drawers, byte-identical.
- **z comes from `Spec.ResidualCorrelations` when the field participates** (`synthetic-data/residuals-and-fidelity.md`); otherwise its own fresh `NormFloat64()`.

**Shape-fitted numerics accept conditioning.** A `--fit-shape` (`DistMixture`) target composes with a model: the fitted mixture becomes Q, predictors shift the latent, no warning. Four independent sites each used to strip the relationship silently (the shape pre-claim, `modelSpecFromProfile`, `fieldMoments`, `quantileFor`), so a change to one looks like it works and fails at the next. A mixture carries EXACT moments (law of total variance) and a quantile function (`internal/synth/mixture_quantile.go`). Pre-claim order is model-then-shape via ordinary `claim()`, so an UNMODELLED shape field is byte-for-byte unchanged and still excludes pairs naming it (`captured shape (--fit-shape)` warning).
- **Effects are LATENT-scale**: under a bimodal mixture a coefficient moves mass between modes. The value-space alternative (draw marginal, add prediction) destroys the fitted marginal and was REJECTED — do not reintroduce it.
- The quantile inverse is a FIXED-COUNT bisection (`mixtureQuantileBisections`, 64) over a bracket where Φ saturates (`mixtureQuantileTailStds`, 40): no convergence test or early exit, because a tolerance-terminated inverse breaks byte determinism; bisection because the density underflows between modes and Newton explodes.
- Both halves (shape kept, conditioning gained) are asserted in ONE test (`TestSynthModel_ShapeFittedTargetKeepsShapeAndGainsConditioning`), because each is trivially satisfiable by abandoning the other. Detail: `skills/synth-shape-fit.md`.

**Float fusion: capture and generation are architecture-independent by CONSTRUCTION, not by luck.** Go may contract `a + b*c` into an FMA — arm64 does, amd64 does not — even ACROSS STATEMENTS. A profile document is committed and diffed, so per-machine bytes are a bug.
- The ONLY construct that forbids contraction is an EXPLICIT conversion: every product feeding an add / subtract in capture or generation is `float64(a*b)`. Assigning to a local does NOT help; `math.FMA` is wrong (it forces fusion and moves amd64's values). The rule and the shared variance form live in `internal/synth/moments.go` (`sampleVariance`); `moments_internal_test.go` compares against `//go:noinline` pre-barrier twins (detects only on a contracting arch).
- **Test cohort generators are part of the contract**: a fixture computed as a float chain made the FIXTURE bytes arch-dependent, so it accumulates in exact integer hundredths and divides once.
- **Transcendentals** (`math.Exp`, `Log`, `Pow`, …) are arch-specific in the stdlib, so synth calls `linalg/detmath` ports: `--fit-shape`, row-expression maths (`exprenv.MathOptions`), distribution draws and the copula's Φ / Φ⁻¹. This matters MORE in generation: a `set_expr` result rounds into an integer and feeds later `when` comparisons, so one ulp means a different set of fired rows.
- **Variates**: every draw uses `detmath.NormFloat64` / `ExpFloat64`, which pull the `*rand.Rand` exactly as the stdlib (same calls, order, count) without its arch-specific tail maths; the stdlib methods are banned in synth (`TestSynthZiggurat_NoStdlibVariates`). Generation is byte-identical per `(spec, seed)` on every machine (`TestSynthZiggurat_GenerationBytesPortable`), and the OLS engine behind `--fit-models` is FMA-free, so captured coefficients match too.
- `math.Sqrt` and `math.Pow10` are exempt (correctly rounded). Find remaining contractions with `go build -gcflags='github.com/frankbardon/pulse/internal/synth=-d=fmahash=vy' -a ./internal/synth/` (currently none).
