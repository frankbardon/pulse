Per-topic slice of the synthetic-data reference (conditional pair capture, per-numeric models, predictor selection, thin levels, generation, shape conditioning, float fusion). Index (preamble + section map): `.claude/reference/synthetic-data.md` — load it first, then only the slice(s) your change touches.

## The contract

`pulse profile create --conditional` (`synth.ProfileOptions.IncludeConditional`) adds an additive `conditional` section to the profile JSON: for numeric-numeric field pairs, a row-aligned `{a, b, rho, n}` capture where `n` is the true co-occurrence count (both fields non-null on the same row) — more accurate than the plain `--include-correlations` `pairwise` stats, whose independently-capped per-field reservoirs can drift out of alignment once either field has nulls. `SpecFromProfile` prefers `conditional.numeric_pairs` over `pairwise` when both are present; its absence (including every profile document from before this flag existed) is unaffected — `SpecFromProfile` falls back to `pairwise` exactly as before, so no existing profile document is invalidated.

**Thin-pair warning (generic mechanism).** A pair whose supporting observation count `n` falls below **`internal/synth.MinPairObservations` (30)** is never refused — it still ships — but appends a warning to `Profile.Warnings` naming the pair. This mechanism (`thinPairWarning` in `internal/synth/profile.go`) is deliberately generic across pair *kind*, not numeric-specific: later epics reuse the same threshold and helper for categorical and `set_*` pairs rather than inventing their own. It is now generic across *subject* as well — `thinPairWarning` is a wrapper over `thinSupportWarning(subject, a, b, n, threshold, consequence)`, which thin-MODEL-LEVEL shrinkage also calls so every thin-support line in `Profile.Warnings` reads the same shape whatever produced it. Every pre-existing caller's text is byte-identical.

**Per-numeric linear models (`models` profile section).** `pulse profile create --fit-models` (`synth.ProfileOptions.FitModels`) adds a second additive, `omitempty` section to the profile JSON: one least-squares linear model per numeric field, that field regressed on the categorical **levels** and `set_*` **options** predictor selection admitted, through `internal/processing/regression`'s streaming OLS engine. The cohort is read ONCE (`TestProfileModels_RidesTheExistingScan` counts the bytes), but the fits do NOT run per row: the scan's only job is retaining a bounded Algorithm-R row snapshot (`modelResidualCap`, 10,000), and selection, fitting and residuals all run over that snapshot afterwards. That ordering is forced — both halves of the narrowing below are measured, and a frequency ranking does not exist until rows have been seen. Consequence on the wire: `n_obs` is the fit's own support WITHIN the snapshot, not the cohort's row count (`Profile.RowCount` is that). Document shape per entry: `{field, intercept, predictors, references, n_obs, r2, residual_std, shrinkage_alpha}`, where `predictors[]` is `{kind, field, level, coefficient}` and `shrinkage_alpha` is `omitempty` (absent ⇔ the fit was unpenalized OLS — see thin-level shrinkage below). **A coefficient is addressed by `(field, level)`** — the solver's internal length-prefixed design-column name is `json:"-"` and never reaches the document, because serialising it would freeze that encoding into the file format. `references[]` names the level each categorical DROPPED into the intercept (reference level = dictionary ID 0 today), so a reader holding *k−1* of *k* levels does not have to guess which arm is the zero baseline; a set-only model carries no `references` key, since a multi-select is not a partition. The row-aligned **fitted residuals** (`FieldModel.Residuals` / `ResidualPresent`, capped at `modelResidualCap`) are also `json:"-"` — thousands of numbers per field whose only consumer runs in the same process as the capture, so they are reachable through `synth.Profile.FittedModels()` and are ABSENT from a re-read document. A capture without the flag emits no `models` key at all and is byte-identical to a pre-flag document; a capture with it moves nothing but that one key (`TestProfile_ModelsSection_IsPurelyAdditive`). A model whose fit would serialise a non-finite float is dropped with a warning rather than failing the marshal of the whole document.

**Predictor selection is automatic, absolute, and has no user-facing override.** Two mechanisms in a fixed order, both in `internal/synth/profile_models_select.go`. (1) **Top-K collapse on dummy expansion** — structural. A candidate categorical contributes one column per top-`ProfileOptions.TopK` level by frequency plus ONE catch-all column carried on the wire as an ordinary level named `"other"` (`otherCategoryLabel`), the same collapse `Categorical.Top` and `conditional.categorical_pairs` already apply, so a document's collapsed buckets mean one thing throughout it. This is what makes the flag work at all rather than a refinement of it: on the motivating 381,324-row cohort the unbounded expansion of 16 categoricals was 2,420 columns (`brand` alone 1,906 levels, 79% of the width) and all 105 numeric targets were skipped as too wide — `--fit-models` produced NOTHING on real data. Collapsed, the same cohort is under 200 columns before any statistical criterion runs. The catch-all is never the reference level. (2) **Variance-explained floor** — statistical, applied to the collapsed candidate set. A candidate FIELD enters a target's model iff the ADJUSTED share of that target's total sum of squares lying between the candidate's groups reaches `synth.minVarianceExplained` (**0.01**, Cohen's small-effect boundary). It is a package constant tuned in code, deliberately not a `ProfileOptions` field — `TestModelSelection_NoUserFacingOverride` pins that no capture flag but `TopK` moves an admission. **The criterion is deliberately NOT statistical significance**: at 381k rows every candidate is significant, including ones explaining a thousandth of the variance, so a p-value gate admits everything and is "all predictors enter" in disguise — and silently, since every coefficient it admits is real, merely negligible. An absolute floor is n-invariant by construction and `TestModelSelection_AdmissionInvariantToRowCount` is the build-failing guard on that. Adjusted rather than raw η² so a 33-group collapsed field is not admitted for its width alone. Scoring is MARGINAL (one candidate at a time against the raw target, never against another's residual): two collinear candidates — `age` is a banding of `ageExact`, `region` is nested inside `dma` — BOTH clear the floor and both enter. That is an explicit judgement call, since incremental scoring would make the admitted set depend on candidate order; redundancy is resolved by the SOLVER instead, and the score is what makes that possible — a design refused as rank-deficient is refitted with its WEAKEST admitted predictor dropped, up to `maxModelRefitRounds` (4) times, so the candidate surviving a nesting is the one explaining more. Detecting the nesting directly is deliberately not attempted: the dependency that actually bites is LINEAR, not functional (a retained set of exact ages covering a whole age band makes that band's indicator the sum of theirs), so a functional-dependency probe misses it while claiming to have handled it. Measured on the motivating cohort, the refit is the difference between 23 skipped targets and 2. Selection also prunes design columns that are degenerate ON THE ROWS THE FIT ADMITS — selection scores pairwise, the fit deletes listwise, and a level with pairwise support but no listwise rows is an identically-zero column the solver refuses. A single-level candidate (`wave` on a one-wave cohort) has zero between-group variance and is dropped by the same arithmetic rather than by a special case. A target no candidate clears produces a **zero-predictor model** — its own mean plus its own spread, `r2: 0` — warned as `carries no predictors: …` and NEVER as `skipped: …`, because a complete model and a failed capture mean opposite things. `maxModelColumns` (256) is RETAINED but is no longer an operative limit: it is a backstop against a pathological schema, justified by the accumulator being O(p²) per row in arithmetic as well as memory. **Measured end state on the motivating cohort, with thin-level shrinkage in place:** ALL 105 numeric targets get a model (E1 fitted ZERO — every one skipped at 2,420 columns), 55 of them carrying predictors, 113 admitted (field, target) relationships against the predecessor's 86 applied pairs, and ZERO skips — a ridge-augmented Gram is positive-definite, so the two irreducibly-redundant targets now fit with both nested candidates jointly shrunk, and the refit narrowing above applies to UNPENALIZED designs only. The pre-shrinkage figures were 103 modelled / 53 with predictors / 76 relationships / 2 skips; the difference is the shrinkage interaction, not a change to the floor. The floor's sensitivity is tabulated at the constant.

**Thin LEVELS inside an admitted predictor are SHRUNK, never dropped and never refused.** Selection (above) picks predictor FIELDS; this picks how much to trust the individual LEVELS of a field it already admitted, and the two are independent — a categorical can clear the variance floor convincingly while three of its retained levels rest on a handful of rows each. The top-K collapse removed the bulk of that problem (a retained level is one of the field's 32 most frequent) but it bounds RANK, not SUPPORT: the 32nd most common `brand` is still rare, and LISTWISE deletion cuts it again, hardest on the targets with the most nulls — the motivating cohort's three NPS fields admit 1,736 of the 10,000 reservoir rows, and every level in their designs is measured against that. A design column whose listwise support (rows the fit ADMITS, not cohort frequency) falls below `internal/synth.minLevelObservations` (**50**) puts the whole fit on the shipped engine's ridge — `spec.Penalty = "l2"` with `Alpha = minLevelObservations / n_admitted`, never a hand-rolled penalty. `minLevelObservations` is DELIBERATELY its own constant and not `MinPairObservations` (30): that one answers "does this pair have enough co-occurrences for a reconstructed correlation to mean anything", this one answers "does this level have enough rows for a free coefficient to describe the level rather than the sample", and sharing a constant because the numbers are the same order of magnitude would couple two unrelated tunings forever. **The shrinkage SCALES with thinness rather than switching on at the threshold**, which is what makes one global alpha sufficient: the engine adds `n·λ` to every Gram diagonal, so `λ = 50/n` adds exactly 50 pseudo-observations and a level retains `n_j/(n_j + 50)` of its free coefficient — 3 observations keep 6%, 30 keep 38%, 50 keep half, 500 keep 91%. It shrinks toward the field's REFERENCE level, because that is what a dummy coefficient measures, and a thin level collapsing onto the baseline is the conservative reading ("too few rows to say this level differs"). `shrinkage_alpha` rides the document because a shrunk coefficient and a free one are not the same kind of number and nothing else on the wire says which one a reader is holding; `alpha × n_obs` recovers the pseudo-count. Three properties that are invisible in the output and must not be "fixed": (1) inside a penalized fit, well-supported columns move too, by roughly `50/n_j` — bounded and small, but not zero, and no single-alpha ridge can make it zero; (2) it is GATED on a thin column actually being present, so a clean design stays exact OLS (`TestProfileModels_NoThinLevelLeavesTheFitUnpenalized`, and the 1e-6 exact-recovery bar `TestProfileModels_CleanMultiPredictorFit` holds) at the cost of a bounded discontinuity at the boundary; (3) a penalized Gram is positive-definite, so the solver's rank-deficiency REFUSAL — which E2-S1 uses as its redundancy signal — does not fire for a fit carrying a thin level, and collinear predictors are jointly shrunk instead of one being dropped. Warning volume is **doubly bounded**, because thinness is a property of the LEVEL and the naive per-(target, level) emission restates one finding once per model — 477 lines for 89 distinct levels on the motivating cohort, on a warnings slice `--conditional` alone already puts ~2,900 thin-PAIR lines on. Lines are aggregated by (field, level) across targets (reporting the THINNEST support and the model count), then capped at `maxThinLevelWarnings` (20) thinnest-first with one counted `+N further thin model level(s)` summary naming the fix (lower `--top-k`). Implementation: `internal/synth/profile_models_shrink.go`. `format_version` does NOT move — `synth.Profile` is not payload-reachable.

**`models` retires the numeric-target conditional arms, PER TARGET.** For a numeric field that lands a model on the Spec, `SpecFromProfile` leaves that field out of `Spec.CategoricalNumericPairs` / `Spec.SetNumericPairs`. Those arms each RESAMPLE a numeric from one paired field's conditional moments, so on a wide cohort every categorical and every set option claims the same numeric target and all but the first are dropped by `resolveConflicts` — one warning each. An additive model accounts for all of them at once, so the pairs have nothing left to add. A profile-derived spec therefore never makes the claim; a HAND-AUTHORED spec that declares both is arbitrated in `internal/synth/conflict.go`, where a modelled field is PRE-CLAIMED (see the generation paragraph below) and the competing pair is dropped with the ordinary conflict warning naming it. The decision is per-FIELD and was per-DOCUMENT until E2-S1 — a model dropped in translation (an unknown predictor field; the zero-predictor model selection emits for a target nothing explained — a `--fit-shape` target was a drop reason until E4-S1 and is not one now, see the shape-fitted-conditioning paragraph below) warns `model for numeric field %q not applied: …` and KEEPS that field's captured conditional pair. Under the document-wide rule such a field lost the pair as well and was reconstructed from nothing at all — strictly worse than before the flag existed, and the ordinary outcome once selection can legitimately leave a target unmodelled. The mixed-semantics objection the document-wide rule was built on is answered by the spec itself: `Spec.Models` and `Spec.CategoricalNumericPairs` each name their own fields, and `resolveConflicts` pre-claims a modelled target, so no field is ever reached by both. The three NON-numeric-target arms (`CategoricalPairs`, `SetCategoricalPairs`, `SetSetPairs`) are untouched, so `--conditional` + `--fit-models` is a supported combination that keeps both halves. Absent `models`, every arm populates exactly as before — the same silent-fallback shape `conditional.numeric_pairs`-over-`pairwise` already uses, and the reason no existing profile document is invalidated (`TestSpecFromProfile_PreModelsDocumentUnchanged` pins a checked-in pre-change document to a fixed `Spec.Hash()`). `format_version` does NOT move: `synth.Profile` / `synth.Spec` live in `synth/` (aliases over `internal/synth/`), not `types/`, so they are unreachable from `internal/descriptor.BuildPayloadSchema` and `descriptor/testdata/payload-schema.json` is untouched. Detail: `skills/synth-profile-capture.md` (Profile mode) + `docs/src/cli/profile-create.md`.

**Generation: the composed model draw.** A numeric carrying a `Spec.Models` entry is not drawn from its marginal and then overwritten — it is composed in one step at the END of `drawRow` (`internal/synth/model_draw.go`): `value = Q(Φ(μ(row) + σ·z))`, where `μ` is the model's linear prediction (`Intercept` + every fired coefficient) **standardised by the target's own reconstructed marginal moments**, `σ = ResidualStd/std`, `z ~ N(0,1)`, and `Φ`/`Q` are `copula.go`'s own `phi` / `quantileFor` — deliberately reused so a modelled field and a correlated field agree on what "this field's marginal" means. Standardising first is load-bearing: the OLS fit behind `FieldModelSpec` is in RAW data units and `Φ` accepts only a standard-normal argument. **Because `μ` lives on the latent scale, a coefficient shifts the LATENT Gaussian and not the value, and is therefore NON-LINEAR in value space for any non-normal `Q` — it is not "this many points on the scale". That is the single most misreadable property of the whole feature; the rule and its consequences are stated in the shape-fitted paragraph below and must be repeated wherever a coefficient is surfaced.** A model additionally carries MAIN EFFECTS only — one coefficient per (field, level), summed — so it cannot express "brand X matters only in region Y"; a pairwise interaction between two collapsed 33-column fields is 1,089 columns on its own, which is precisely the width problem the top-K collapse exists to solve, and the marginal scoring rule, the wire format and the recovery refit all assume one term per (field, level). **For a plain `normal` target the round trip collapses exactly to `prediction + ResidualStd·z`** (since `Q(p) = mean + std·u` and `Φ⁻¹(Φ(u)) == u`) — the ordinary OLS draw — and routing through `Φ`/`Q` anyway is what lets a hand-authored `uniform`/`lognormal`/`exponential` target keep its own marginal shape while the linear predictor drives it. **A term fires only on an exact match and contributes ZERO otherwise**, which is the dummy-coded reading, not a convenience default: categorical predictors are read against a dropped reference level folded into the intercept, so a level the fit never saw — a value that is new at generation — reads as the reference, and a NULL predictor also contributes zero because listwise deletion means the coefficients never saw such a row. **The top-K catch-all is NOT such a level: it carries its own firing term.** A predictor field wider than `--top-k` contributes one design column per retained level plus one collapsed catch-all, and that catch-all rides the wire as an ordinary `categorical_level` predictor whose `level` is the literal string `"other"` (`otherCategoryLabel`) — the same spelling every other collapsed bucket in a profile document uses, so a consumer applies it exactly as it applies `region=west` and no reader has to learn a fourth `ModelPredictor.Kind`. It is reached at generation because `--conditional`'s categorical-categorical contingency capture collapses out-of-top-K values to that same `"other"` before building its cells and `categoricalPairSampler` resamples straight out of them, while the model stage runs LAST and therefore reads the value the emitted row actually carries; the field's OWN marginal cannot produce it, because `SpecFromProfile` reconstructs a categorical from `FieldProfile.Categorical.Top`, which truncates to the top K and renormalises rather than appending a catch-all bucket. Mapping that column to `ModelPredictorNumeric` instead — which a `default:` arm in `modelPredictorKind` did until E2-S5 — is SILENT and costs the WHOLE model, because `modelSpecFromProfile` refuses a model wholesale on one unusable predictor rather than dropping a term and leaving the survivors read against a baseline that no longer exists: on the motivating cohort that was 105 captured models applied as 20, with a plausible cohort generated either way. Corrected, 55 apply — exactly the 55 capture reports as predictor-carrying, the other 50 being the zero-predictor models E2-S1's per-target rule drops on purpose — and `Spec.ResidualCorrelations` grows from 190 pairs to the full 1,485, since a surviving model is a residual participant. On a 20,000-row generation from that profile, 18,198 rows carry `brand = "other"`, so the catch-all is not a rare arm but the DOMINANT one. `modelPredictorKind` now names every `dummyColumnKind` and `TestModelPredictorKind_CoversEveryDummyColumnKind` pins the enum's cardinality, so a new member fails a test rather than acquiring a confident wrong answer. **Clamping is exactly one clamp, applied once to the final data-scale value**: the model's own `Min`/`Max` (the target's observed bounds, carried on `FieldModelSpec` for this purpose) win, mirroring `categoricalNumericPairSampler`'s precedent for a conditionally-drawn numeric, with the field's own marginal clamp as the fallback when the model declares none — so the model stage and the copula stage cannot disagree about the admissible range. **Ordering is spec-derived, never map-derived:** the model stage runs after every pair stage and the correlator (its predictors are categorical levels and set bits those stages can still rewrite), drawers are sorted into SCHEMA FIELD ORDER at setup rather than `models` array order, and each consumes exactly one `NormFloat64()` per row *unconditionally* — before any branch on the prediction, and even when `ResidualStd` is 0 — so the seeded stream depends only on the number of surviving models and the determinism contract (same spec + same seed ⇒ byte-identical `.pulse`) holds. A spec with no `models` compiles zero drawers, consumes no extra RNG state and is byte-identical to pre-change output. **`z` comes from `Spec.ResidualCorrelations` when the field participates** — see the residual-draw paragraph below; a drawer that does not participate takes its own fresh `NormFloat64()` exactly where it always did.

**Shape-fitted numerics accept conditioning.** `--fit-shape` and conditioning were MUTUALLY EXCLUSIVE and no longer are. A `DistMixture` field was pre-claimed in `resolveConflicts` ahead of the model claim, `modelSpecFromProfile` refused a mixture target outright, and `fieldMoments` / `quantileFor` refused it too — FOUR independent sites, each of which alone was enough to strip the relationship, which is why a change to any one of them looks like it works and then fails at the next. On the motivating cohort that silently removed every measured conditioning relationship from exactly the numerics whose distributions had earned a shape fit. The exclusivity was never a property of the construction: `value = Q(Φ(μ + σ·z))` admits an ARBITRARY marginal in `Q` — it is precisely what a hand-authored `lognormal` target already does — so once the mixture acquired a `Q` there was nothing holding it up. A captured mixture now carries EXACT moments (law of total variance, `mixtureComponents.moments`) and a quantile function (`internal/synth/mixture_quantile.go`), the fitted mixture becomes `Q`, the predictors shift the latent, and the two compose with NO warning because nothing is dropped. The pre-claim ordering is now model-then-shape, and the shape pre-claim is an ordinary `claim()` rather than a direct map write, so it still owns every `DistMixture` field no model took: an UNMODELLED `--fit-shape` field is byte-for-byte unchanged, keeps its own mixture draw, and still excludes a pair or correlation naming it with the `captured shape (--fit-shape)` warning. **Effects are LATENT-scale and therefore NON-LINEAR in value space for a non-normal `Q`** — a coefficient shifts `μ` on the standard-normal scale, and only an affine `Q` (i.e. `normal`) carries that through to the data scale unchanged; under a bimodal mixture the same coefficient moves mass between modes rather than moving values by its own magnitude. Direction and monotonicity hold, magnitude in data units does not, and a coefficient must NOT be read as "this many units of the field". The value-space alternative (draw the marginal, add the prediction) was considered and REJECTED — it destroys the fitted marginal it was supposed to protect — and must not be quietly re-introduced. The quantile inverse is a FIXED-COUNT bisection (`mixtureQuantileBisections`, 64) over a bracket where `Φ` has saturated at exactly 0 and 1 (`mixtureQuantileTailStds`, 40): no convergence test and no early exit, because a tolerance-terminated inverse makes the answer depend on how many steps a given `p` needed and the determinism contract (same spec + same seed ⇒ byte-identical `.pulse`) is not negotiable; bisection over Newton additionally because the density underflows between well-separated modes and a Newton step there explodes. Both halves of the acceptance are asserted in ONE test (`TestSynthModel_ShapeFittedTargetKeepsShapeAndGainsConditioning`) because each is trivially satisfiable by abandoning the other. `format_version` does NOT move. Detail: `skills/synth-shape-fit.md` (Shape-fitted targets accept conditioning) + `internal/synth/mixture_quantile.go`.

**Float fusion: capture and generation are architecture-independent by CONSTRUCTION, not by luck.** Go permits an implementation to contract `a + b*c` (and `c - a*b`) into a single fused multiply-add, rounding once instead of twice; the arm64 backend does, the amd64 backend does not, and the contraction is permitted ACROSS STATEMENTS, so `scaled := f * mult` on one line followed by `scaled - 0.5` on the next fuses exactly as readily as the one-liner. That made `pulse profile create`'s byte-identity promise hold per-MACHINE only — a profile document is an artefact a user commits, reviews in a diff and shares, and two engineers on different CPUs got different documents. The ONLY construct in the language that forbids contraction is an EXPLICIT floating-point conversion, so every product in a capture or generation formula that feeds an add or subtract is wrapped as `float64(a*b)`; assigning to a local does NOT help and `math.FMA` is the wrong lever (it FORCES fusion everywhere — portable, but it changes amd64's values rather than preserving them, and would move far more of every existing document). The shared variance form lives once, in `internal/synth/moments.go` (`sampleVariance`), which is also where the whole rule is written down; `internal/synth/moments_internal_test.go` is the build-failing gate, pairing `sampleVariance` / `pearson` / `computePercentiles` against `//go:noinline` twins holding the pre-barrier source and asserting production matches the BARRIERED value — it can only DETECT on a contracting architecture, so it is silent on amd64 by construction and logs which case it is in. **Test cohort generators are part of the contract**: `modelsCohort` computed its `spend` / `visits` columns as a chain of float terms, which made the FIXTURE BYTES architecture-dependent (115 of 1,200 rows differed), so it now accumulates in exact integer hundredths and divides once — a stronger guarantee than a barrier, because it cannot be undone by an edit that merely looks tidier. **The transcendental kernels are the second half (U58).** `math.Exp` (assembly on arm64, an FMA path chosen per CPU on amd64) and `math.Log` (assembly on amd64, pure Go on arm64) are architecture-specific in the standard library, so no barrier can fix them; `--fit-shape` (`internal/synth/shape.go`) and the row-expression maths every `set_expr` / `when` / `constraints[]` sees (`exprenv.MathOptions`, wired in `internal/synth/row_expr_builtins.go`) therefore call `internal/detmath`'s portable ports, which give identical bits on every arch and CPU (`TestShapeFit_RunsOnDetmath`, `TestMathOptions_SameBitsAsQueryImpl`). This matters MORE in generation than in capture: a `set_expr` result is rounded into an integer field and read by later `when` comparisons, so a one-ulp drift is not a last-bit difference but a different set of fired rows. On the in-repo bimodal fixture the move left the `shape` bits unchanged on arm64; amd64 documents may move once. Two residuals are STATED rather than papered over: `internal/processing/regression` — the OLS engine behind `models` — has NOT been made fusion-free, so a `models` coefficient can still differ; and the GENERATION draws that still call the standard library (lognormal / exponential / pareto / poisson in `distributions.go`, the copula's marginal transforms in `copula.go`) stay machine-sensitive in their last bits. `math.Sqrt` is exempt (IEEE-754 requires correct rounding). The compiler will enumerate every remaining site on demand: `go build -gcflags='github.com/frankbardon/pulse/internal/synth=-d=fmahash=vy' -a ./internal/synth/` prints one line per contraction it applied, and the answer for `internal/synth/` is currently none. `format_version` does NOT move.
