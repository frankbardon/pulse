# Synthetic data — co-missing blocks, exact dependencies, detection calibration

Per-topic slice of the synthetic-data reference (co-missing blocks, exact dependencies, detection calibration). Index (preamble + section map): `.claude/reference/synthetic-data.md` — load it first, then only the slice(s) your change touches.

**Co-missing blocks and always-null columns (the second `--suggest-rules` detector).** The same scan runs a SECOND detector (`internal/synth/profile_comissing.go`) that proposes `null_together` candidates — fields nulled as one question block — into the SAME file, resolving the finding E3-S1 could only COUNT (a gate whose only gated level is the null pseudo-level is co-missingness, 3,932 relationships on the motivating cohort) into one candidate per block. **AN IDENTICAL `null_rate` IS NEVER ENOUGH, and that is the whole surface**: two independent fields can share a rate to sixteen digits and overlap only by chance, so grouping by rate proposes them as a question block, `null_together` then makes the claim TRUE in generated output, and the cohort acquires a structural fact the source does not have. The rate is the GROUPING KEY; admission is **IDENTICAL NULL PATTERN** — null on exactly the same rows — so every member of an emitted block carries `agreement: 1`, an identical `null_count`, and `max_null_rate_deviation: 0`, which is precisely E1-S5's own divergence measure: an emitted block can never trip `nullRateDivergenceThreshold`, no declared rate is discarded, and the member order is ARBITRARY BY CONSTRUCTION rather than a ranking (pattern identity is an equivalence relation, so there is no "cleanest member" inside an exact block). Accumulation is a per-field BITSET over `blockChunkRows` (65,536) rows folded into an F x F co-null matrix by popcount and cleared, so memory is O(F x chunk / 8 + F²) and **flat in the row count** (under 2.5 MB at the cap) while the per-row cost is one bit write per null field; it rides the existing scan with no extra byte, counted the way `TestProfileModels_RidesTheExistingScan` counts them. A per-field null-pattern HASH is the rejected alternative — it answers only the yes/no question, so a near block is invisible to it and indistinguishable from an unrelated field, and it trades an exact answer for a collision that fabricates a question block. A **NEAR block is REPORTED with its agreement and its disagreeing row count, never emitted**: `null_together` has no dial for "almost" and, unlike a gating candidate whose `when` an analyst corrects, there is nothing in it to fix — deliberately unlike E3-S1's THIN candidates, whose relationship is exact and only whose support is thin. The measure is the null-SET overlap (`nearBlockAgreement` 0.95), never row-level agreement: two independent fields each null at 1% agree on 98% of ROWS, so a row-level threshold near 1 floods, and the negative control must therefore include a LOW-rate independent pair or the substitution goes undetected. **Each block side carries a HANDLE back to its candidate — the `null_together` whose FIRST entry is that field — and the handle is CONTENT-DERIVED rather than positional on purpose**: the candidate file exists to be edited by DELETION and every index below a deleted line shifts, so a candidate index is a handle that goes wrong silently. The first entry is additionally load-bearing rather than incidental (`applyNullTogether` makes `block[0]` the gate, the only member whose own null decision survives), so it cannot be reordered away without changing what the rule means. A side that produced NO candidate — a singleton, or a class beyond `maxBlockCandidates` — carries no handle and says so, because advertising one would send a reader hunting for a line that is not in the file; the emitted representative set is therefore passed into the reporter rather than assumed. Measured on the motivating cohort: 4 near-miss lines, 3 advertised handles, all 3 resolving to emitted candidates of exactly the advertised sizes (50 / 26 / 13). An **ALWAYS-NULL column is its own ATTENTION finding**, named with its type and kept out of every block and every gate, and **NO rule is proposed for it because one would change NOTHING** — not because the question was deferred. A column the profiler summarised nothing for reaches `SpecFromProfile`'s no-marginal arm — reached precisely BECAUSE there is no marginal to fabricate from — which reconstructs a typed `constant` placeholder with `null_rate` 1.0, so `nullableSampler` nulls every row and `encodeRow` writes the type's zero behind a set null bit. Measured on the motivating profile at 20,000 generated rows, `lgbt` came back null on 20,000 of 20,000. `owns_nulls` does not make the candidate coherent either: the flag discards a field's own null draw when a gate accounts for the missingness, and here the field's own draw already nulls every row, so there is nothing to own. The warning previously claimed generation "fabricates a distribution" for such a column, which was false in the one direction that mattered — it was the whole case for proposing the rule — and now states the reproduction and points the analyst at the SOURCE or the slice profiled rather than at the rules file (`TestProfileAlwaysNull_ReproducedExactlyWithoutARule` asserts it across all three row-value classes, since the no-marginal arm is shared and a regression restoring the fabrication for one type only would otherwise pass). Over `maxBlockFields` (256) nullable fields the detector is ABANDONED, never truncated, for the reason `maxGateLevels` abandons — a truncated field set yields blocks that are EXACT among the fields it kept and silently missing the rest, which is the defect this detector exists to remove, now written down as a rule. Blocks rank largest-first, capped at `maxBlockCandidates` (= `maxRuleCandidates`) applied PER DETECTOR rather than to the file, because a shared budget would let twenty gating candidates hide the fact that the cohort has question blocks at all. **EMITTED ORDER IS APPLIED ORDER and a candidate WRITING a field another candidate READS is emitted BEFORE it** (`internal/synth/profile_rule_order.go`, `ruleCandidateOrder`); the detector preference — gating, then blocks, then dependencies — is a READABILITY choice kept wherever nothing forces a move, and candidates are walked in it with a candidate a walked one depends on HOISTED to just before it, never further. Gate-before-block remains right for a block holding a gate's TARGETS and that half is arithmetic rather than luck (identical patterns classify identically at every level of every gate, so a gate takes a WHOLE block or none of one, and both orders reduce to "null iff the gate fired or the first member drew null"), chosen for the file's actual purpose, being EDITED, where a hand-narrowed `set_null` over PART of a block is repaired by a block that follows it. **THE EQUIVALENCE GOVERNS WHAT A GATE WRITES AND IS FALSE FOR WHAT A GATE READS**, which is the inverse hazard E3-S2 shipped and E3-S3 measured: a block member that is a gate's `when` FIELD moves the gate's own INPUT after the gate has read it, so the gate fires on the drawn value, the block then nulls the field it was reading, and the target it left present becomes an answer on a row whose screener the same file says was never asked — 8,693 of 20,000 generated rows on the motivating cohort, where five `*Aware` gates are all members of the 50-field block, and **0** after the reorder, with the coherence table UNMOVED either way because it measures a different gate (a defect invisible to the acceptance table is exactly why the orphan count is its own gate). Only forced candidates move: the 63-target headline gate stays at the top and one block is hoisted ahead of the five gates reading it. The cost is that a hoisted block loses the repair property FOR THOSE GATES, and the trade is deliberately asymmetric — the repair property protects an edit that may never be made, the ordering fault corrupts every row unconditionally. A mutual pair (each writing a field the other reads) has no satisfying order: the closing edge is dropped, the surviving one decides the pair (possibly inverting the detector order, because an edge is a constraint and the order is a preference) and the drop is WARNED about rather than resolved silently. `RuleEvidence` gains `block` rather than a second evidence type so a reader walks one shape and reads `detector`; the five gating-only slots gained `omitempty` (each populated by construction for a gating candidate, so that wire form is byte-identical) while the SHARED slots deliberately did not, because `max_null_rate_deviation: 0` is a real measurement on both. Measured on the motivating cohort: FOUR blocks — 50 fields at `0.2526093295989762`, **26 at `0.3564055763602606` (the cluster no single gate could explain, now an EXACT block — the interview's remaining open question answered)**, 13 at `0.2648718674932603` and the four-field NPS block at `0.8260193431307760` — plus one always-null column (`lgbt`) and four near misses, alongside E3-S1's eight gating candidates whose file bytes are UNCHANGED; twelve candidates in one file, consumed by `--rules` unmodified, all four blocks all-or-nothing on 20,000 of 20,000 generated rows against 20,000 / 20,000 / 19,660 / 10,761 partial at the same seed without them, for +2% CPU and no additional cohort read. `format_version` does NOT move and no error code is added, so neither golden moves. **Exact dependencies (the third `--suggest-rules` detector).** The first candidate kind to read VALUES rather than null state: a field that is an exact function of ONE other on every row where both are present, proposed as `set_expr` (`detector: "dependency"`, evidence on `_evidence.dependency` / `.source_field` / `.source_levels`). It exists because `promoter` IS `nps >= 9` — generation samples it independently and gives it a captured model, so the synthetic cohort holds promoters scoring 3, while the profile document has carried the proof the whole time (`promoter + passive + detractor = 1.0000`, exactly) with nothing reading it. **THE SEARCH IS NARROW BY DESIGN AND THE BOUNDS ARE PUBLISHED** — in every candidate's `note`, on stderr and in the docs: targets are `packed_bool` and `u4` ONLY, sources are `categorical_*`/`packed_bool`/`u4` with at most `maxDepLevels` (16) observed levels, and the dependency is on exactly ONE source; wider numerics, `date`, `set_*`, categorical-VALUED targets and joint two-field dependencies were NOT looked for, so **a field missing from the file was not cleared — it was not examined**. Claiming generality the implementation does not have is worse than the bound, because an analyst who believes a field was checked stops looking. **BAND EDGES ARE DISCOVERED, NEVER ENCODED.** The measurement is a LOOKUP and the rendering is a separate judgement: a threshold form is preferred wherever the target's value regions are CONTIGUOUS in the source's own order, because it is a TOTAL function of the source — a value generation produces that the cohort never carried lands in the nearest band instead of off the end of an enumeration — and `form` names which reading was chosen (`threshold`/`threshold_chain` total; `membership`/`membership_complement`/`enumeration_chain` fall to a default arm). The standard 9-10 / 7-8 / 0-6 NPS definition is this detector's OUTPUT on the motivating cohort and was nowhere in its input; a detector that hardcodes it is not a detector, and the negative fixture must carry NON-standard edges because the motivating one agrees with a hardcoded answer by accident. **A PARTITION IS ONE CANDIDATE**, grouped by SOURCE: three rules would have to be kept consistent by hand, and deleting one silently stops the remaining two partitioning. **ALL THREE E2-S4 REMEDIES RIDE THE EMITTED RULE** — `round()` on every numeric term (838 of 4,495 scored rows disagree without it, measured by GENERATION); NO separate normalisation rule, because the rounding is INSIDE each band predicate, so nothing writes the source and the `!isnull()` guard is unnecessary as the write does not happen; and `null_together` naming the SOURCE FIRST inside the SAME rule, where it is the last write (split into two rules the derivation runs afterwards and un-nulls every member — 1,505 orphan rows). The rule carries **no `when`**, which is both the true statement and what makes its targets PRE-CLAIM-ELIGIBLE (E2-S2): accepting one RETIRES the target's captured linear model, conditional pairs and residual correlations rather than computing them and overwriting the result, and the note says so because that is the most valuable consequence of accepting a candidate. That must be asserted against `ruleClaims` and never a substring test — `region == "west"` CONTAINS its target's name inside a quoted literal and does not read it. **ADMISSION IS IDENTICAL NULL PATTERNS**, served from E3-S2's own co-null accumulator (`blockDetector.sameNullPattern`) rather than a second one; a differing pattern is REPORTED because a `set_expr` clears the null mask and would un-null the target wherever its source is absent, and an UNAVAILABLE accumulator answers "unknown" and reports rather than guessing. Reported-never-proposed also covers an ALMOST-determined pair (1..`maxDepExceptions` = 8 contradicting rows, following E3-S2's near-block precedent — the relationship is measurably FALSE on some rows and there is nothing in the rule to correct; over 8 the pair is dropped AND unreported, being not "almost" anything), a CONSTANT column, a mutually-determining pair, and a target contested by two sources (written once, by the strongest, since two rules writing one field leaves the earlier firing with no effect). **The exception count is ORDER-INDEPENDENT and that took two slots per source level**: a single first-observation slot answers the EXACT question correctly whatever order rows arrive in and the NEAR question backwards when the minority value arrives first — a 3-row miss scored 80 and was dropped as unrelated. **EMITTED LAST** by PREFERENCE, after gating and blocks, so the derivation re-resolves its own block AFTER every null-state rule has decided the source's null state; measured on a hand-narrowed `set_null` over the source alone, dependency-last leaves 0 orphan rows and dependency-first 940. The one exception is E3-S4's writer-before-reader rule: a dependency whose `set_expr` writes a field a GATE reads is HOISTED ahead of that gate, because otherwise the gate fires on a value the dependency rewrites afterwards. `aware = round(familiarity) >= 2` against `round(aware) == 0` is exactly that shape on the motivating cohort, and it costs 0 rows there ONLY because the detector also emits the proxy gate `round(familiarity) == 1` over the identical 63 targets, reading a field nothing rewrites — delete the proxy, which is the ordinary deletion-only edit the file exists for, and the violation is live, so a fixture that keeps it tests nothing. Bounded: the pair table starts at F×(F−1) and is affordable only because a pair DIES the moment two rows share a source level and disagree, with the live list held per source and filtered in place; over `maxDepFields` (256) participants the detector ABANDONS rather than truncating. Measured on the 381,324-row motivating cohort it proposes TWO candidates alongside E3-S1's eight and E3-S2's four (14 in one file, the other twelve byte-identical): the NPS partition off `nps`, and **`aware = round(familiarity) >= 2` on all 381,324 rows — which ANSWERS E3-S1's proxy question**, since nothing in a null-state measurement separates `aware` from `familiarity == 1` and values show one is DERIVED from the other. Fed back unmodified both reproduce the source mapping on 100% of co-present rows with zero orphans; +7.5% CPU over the two-detector figure and no additional cohort read. `format_version` does NOT move. **Detection is calibrated against the motivating cohort, and the candidate file closes the loop.** All three detectors were measured on the real 381,324-row survey cohort where the answers were established independently, by hand, from null rates and means. They emit FOURTEEN candidates reproducing every known relationship: `aware` gating 63 fields (a strict SUPERSET of the 50-field block, the extra 13 being the 0.2649 cluster, both recovered as exact blocks beside it), the four-field NPS block found twice (as a `useCon` gate and as an exact block), the 26-field 0.3564 cluster that no single gate explained, the promoter/passive/detractor partition as ONE candidate with edges DISCOVERED from an 11-level mapping as ≤6 / 7-8 / ≥9, `lgbt` as the only always-null column, and `aware = round(familiarity) >= 2` exact on all 381,324 rows — which ANSWERS the proxy question E3-S1 could only pose. Eleven further findings are REPORTED rather than proposed (5 fields too wide to gate, 3,932 co-missing relationships restating the blocks, 4 near blocks at 0.9989 / 0.9798 / 0.9788 / 0.9537, 5 fields too wide for dependency, 3 constant columns) — including the 27th field at 0.3564, which research had counted into the cluster by RATE and which is NOT null on the same rows (145 disagree), the exact case an identical-rate test would have fabricated. Edited only by DELETION — the `familiarity` proxy gate, the `useCon` gate and the `familiarity -> aware` dependency removed — and fed back through `synth from-profile --rules`, the file reproduces the E2-S4 coherence table at 40,000 rows: all four NPS fields present together 39 -> 6,968 (target ~6,959), all four null together 18,560 -> 33,032, `nps`-present-flag-null 6,845 -> 0, `nps`-null-flag-present 14,556 -> 0, mixed blocks 21,401 -> 0, exactly-one-flag 113 -> 6,968, band agreement 16 -> 6,968 (100%), and all 50 gated fields null on 9,878 of 9,878 `aware == 0` rows with none present. It BEATS the hand-written file on the one row E2-S4 reported as a shortfall — NON-gated rows carrying all 50 fields goes 0 -> 22,572 — because detection proposes the co-missing block beside the gate, so E2-S4's documented workaround is now a proposal rather than an idiom an analyst has to know. Every candidate fires on a non-zero row count (lowest 5,491 of 40,000) and no `rule never fired` line is raised. Two deletions are themselves findings: accepting `familiarity -> aware` moves `aware`'s generated marginal from 0.2469 to 0.1373, because an exactly-determined dependency inherits its SOURCE's reconstruction error; and keeping the `useCon` gate over the NPS block double-counts against the block's own null draw, collapsing `nps` presence from 6,884 to 1,098 — E2-S4's "a gate repairs co-missingness only" shortfall, now measurable on a proposal.
