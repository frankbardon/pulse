# Synthetic data — co-missing blocks, exact dependencies, detection calibration

Slice of `.claude/reference/synthetic-data.md` — load the index first, then only the slice(s) your change touches.

**Co-missing blocks and always-null fields (the second `--suggest-rules` detector).** `internal/synth/profile_comissing.go` proposes `null_together` candidates into the same file, one per block.
- **AN IDENTICAL `null_rate` IS NEVER ENOUGH, and that is the whole surface**: independent fields can share a rate to sixteen digits, and `null_together` would make a coincidence TRUE in generated output. The rate is only the grouping key; admission is **IDENTICAL NULL PATTERN** (null on exactly the same rows). So every emitted member has `agreement: 1` and `max_null_rate_deviation: 0` — an emitted block never trips `nullRateDivergenceThreshold`, and member order is arbitrary by construction.
- Accumulation is a per-field BITSET over `blockChunkRows` (65,536) folded into an F×F co-null matrix by popcount — memory flat in row count, riding the existing scan. A null-pattern HASH was rejected: it cannot see a near block and a collision fabricates one.
- **A NEAR block is REPORTED, never emitted** — `null_together` has no dial for "almost". Measured on null-SET overlap (`nearBlockAgreement` 0.95), never row-level agreement (two independent 1%-null fields agree on 98% of rows); the negative control must include a LOW-rate independent pair.
- **Each reported block side carries a CONTENT-DERIVED handle** — the `null_together` whose FIRST entry is that field — never a positional index, because the file is edited by DELETION and indices shift silently. The first entry is load-bearing (`block[0]` is the gate). A side with no candidate (singleton, or beyond the cap) says it has no handle; the emitted set is passed to the reporter, not assumed.
- **An ALWAYS-NULL field is its own ATTENTION finding, and NO rule is proposed because one would change NOTHING**: `SpecFromProfile`'s no-marginal arm already rebuilds a typed `constant` with `null_rate` 1.0, so generation reproduces it exactly; `owns_nulls` has nothing to own. The warning points at the SOURCE or the profiled slice (`TestProfileAlwaysNull_ReproducedExactlyWithoutARule` covers all three row-value classes).
- Over `maxBlockFields` (256) nullable fields the detector is ABANDONED, never truncated — a truncated field set yields blocks exact among kept fields and silently missing the rest. Blocks rank largest-first, capped at `maxBlockCandidates` PER DETECTOR (a shared budget would let gating candidates hide that blocks exist).
- **EMITTED ORDER IS APPLIED ORDER, and a candidate WRITING a field another candidate READS is emitted BEFORE it** (`internal/synth/profile_rule_order.go`, `ruleCandidateOrder`). The detector preference (gating, blocks, dependencies) is readability, kept wherever nothing forces a move; a forced dependency is HOISTED to just before its reader, never further. Gate-before-block is safe for a block holding a gate's TARGETS (identical patterns classify identically, so both orders agree) and helps the file's real use — editing. **THE EQUIVALENCE IS FALSE FOR WHAT A GATE READS**: a block member that is a gate's `when` field moves the gate's input after it was read, producing answers on rows whose screener was never asked — invisible to the coherence table, so the orphan count is its own gate. The trade is deliberately asymmetric: the repair property protects an edit that may never happen; the ordering fault corrupts every row. A mutual pair has no satisfying order: the closing edge is dropped and WARNED, never silently resolved.
- `RuleEvidence` gains `block` (one shape, read `detector`); gating-only slots are `omitempty`, shared slots are not (`max_null_rate_deviation: 0` is a real measurement). Detail: `skills/synth-rules-from-profile.md`.

**Exact dependencies (the third `--suggest-rules` detector).** A field that is an exact function of ONE other on every co-present row, proposed as `set_expr` (`detector: "dependency"`). It exists because a derived flag (`promoter` = `nps >= 9`) is otherwise sampled independently, yielding promoters scoring 3.
- **THE SEARCH IS NARROW BY DESIGN AND THE BOUNDS ARE PUBLISHED** (each candidate's `note`, stderr, docs): targets `packed_bool` and `u4` only; sources `categorical_*` / `packed_bool` / `u4` with ≤ `maxDepLevels` (16) levels; exactly ONE source. **A field missing from the file was not cleared — it was not examined.**
- **BAND EDGES ARE DISCOVERED, NEVER ENCODED.** The measurement is a lookup; rendering prefers a threshold form wherever regions are CONTIGUOUS in source order, because it is TOTAL (an unseen generated value lands in the nearest band); `form` names the reading (`threshold` / `threshold_chain` total; `membership` / `membership_complement` / `enumeration_chain` fall to a default arm). The negative fixture must use NON-standard edges, since standard NPS edges agree with a hardcoded answer by accident.
- **A PARTITION IS ONE CANDIDATE**, grouped by source — three rules would need hand-kept consistency.
- **The emitted rule carries every pre-rounding remedy**: `round()` on every numeric term; no separate normalisation rule (rounding is inside each predicate, so nothing writes the source and no `!isnull()` guard is needed); `null_together` naming the SOURCE FIRST in the SAME rule (split, the derivation un-nulls members). **No `when`**, which makes targets PRE-CLAIM-ELIGIBLE — accepting retires the target's model, pairs and residual correlations; the note says so. Assert claims via `ruleClaims`, never substring (`region == "west"` contains a name without reading it).
- **ADMISSION IS IDENTICAL NULL PATTERNS**, from the block detector's accumulator (`blockDetector.sameNullPattern`); a differing pattern is reported (a `set_expr` would un-null the target where the source is absent); an unavailable accumulator answers "unknown" and reports.
- Reported, never proposed: an ALMOST-determined pair (1..`maxDepExceptions` = 8 contradicting rows; over 8 it is dropped unreported), a constant field, a mutually-determining pair, a target contested by two sources (written once, by the strongest).
- **The exception count is ORDER-INDEPENDENT, using two slots per source level** — a single first-observation slot gets the near question backwards when the minority value arrives first.
- **EMITTED LAST** by preference, so the derivation resolves its block after every null-state rule; except a dependency writing a field a GATE reads is HOISTED ahead of that gate (writer-before-reader). A fixture testing this must delete the proxy gate that otherwise masks it.
- Bounded: a pair dies as soon as two rows share a source level and disagree; over `maxDepFields` (256) participants the detector ABANDONS. Detail: `skills/synth-rules-from-profile.md`.

**Detection is calibrated against the motivating cohort, and the candidate file closes the loop.** All three detectors were measured on a real survey cohort whose relationships were established independently by hand; they reproduce every known relationship, and the rate-identical-but-pattern-different field that a rate test would have fabricated into a block is correctly reported, not proposed. Edited only by DELETION and fed back through `--rules`, the file reproduces the hand-written coherence table and beats it on gated-block presence, because detection proposes the co-missing block beside the gate. Every candidate fires (no `rule never fired`). Two findings to keep in mind when accepting candidates: an exactly-determined dependency inherits its SOURCE's reconstruction error; and keeping a gate over a block that already owns its nulls double-counts against the block's own draw (a gate repairs co-missingness only). Detail: `skills/synth-rules-from-profile.md`, `docs/src/cli/profile-create.md`.
