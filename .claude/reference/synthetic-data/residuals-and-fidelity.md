# Synthetic data — the correlated residual draw, model and residual-correlation recovery, the terminal warning summary, utility against the source and marginal effect sizes

Slice of `.claude/reference/synthetic-data.md` — load the index first, then only the slice(s) your change touches.

**The correlated residual draw (`Spec.ResidualCorrelations`).** Lets a numeric be **both categorically conditioned and correlated with a sibling numeric**. `SpecFromProfile` translates only MEASURED `residual_correlations.pairs`; `unmeasured` becomes NOTHING, because an absent pair is completed-and-counted by the generator while a written-out zero would present a gap as a measurement and silence that count. `buildResidualCorrelator` (`internal/synth/residual_draw.go`) draws ONE correlated standard-normal vector per row; each participating `modelDrawer` reads its component as the z of `Q(Φ(μ + σ·z))`. Nothing overwrites anything: predictors move μ, the shared vector correlates what is left.
- **Exactly ONE Cholesky and ONE completion policy**: `factorCorrelations` (`copula.go`) serves both value and residual scale, differing only in warning nouns, so assume-and-record and the ridge report cannot land on one scale and miss the other.
- **Determinism**: component order is DRAWER order (schema field order), never `residual_correlations` array order (a serialization artifact). The vector consumes one normal per participant BEFORE the first drawer; non-participants draw where they always did; fewer than two participants ⇒ no correlator and no draw, so a spec declaring none is byte-identical.
- Participation is decided from the COMPILED drawers, not `Spec.Models`; a correlation naming a field whose model did not compile is dropped with one aggregated warning.
- **A value-scale `Spec.Correlations` entry naming a modelled field stays refused, permanently** — realizing it would overwrite the model's output, and rerouting it into the residual would apply shared predictors twice (`internal/synth/residual_corr.go`). `resolveConflicts` reports it as *is not applied … capture residual correlations (`profile create --residual-correlations`)*, not as a pair conflict.
- **The real boundary is the ZERO-PREDICTOR target**: captured as a participant, but dropped at translation by the per-target rule (its conditional pair serves it better), so its residual pairs reach the Spec as nothing. Reversing that would retire those fields' pairs — a worse trade — so the boundary is pinned (`TestResidualCorrelations_CapturedTargetIsRealizedEndToEnd`), not closed.
- Normal target: realized residual correlation is exact; non-normal Q: rank exact, Pearson attenuates. `validateSpec` refuses a residual correlation naming an unmodelled field in a hand-authored spec. Detail: `skills/synth-residual-correlations.md`.

**Model recovery in the fidelity report (`FidelityReport.Models`).** `--fidelity-report` refits every model generation ACTUALLY APPLIED on the `_synthetic` partition and reports captured beside recovered coefficients (`internal/synth/fidelity_models.go`, `BuildModelFidelity`). It asks whether captured STRUCTURE survived — silent structure-loss bugs have kept marginals healthy while conditioning was gone, and only this section sees it. Recovered ≈ captured separates faithful-but-compressed marginal contrasts from real loss.
- **The comparison is LATENT-scale on both sides**: each generated value is inverted through `latentFor` (the algebraic inverse of `quantileFor`) and the captured coefficient divided by the marginal std as the drawer does; `latent_scale` lets a reader multiply back. Raw-value regression would flag every shape-fitted target while generation was correct. **`latentFor` and `quantileFor` MUST move together** (`TestLatentFor_InvertsQuantileForEveryDistribution`) or a distribution silently drops out.
- **Which models ran is asked of generation's own compiler**: `resolveConflicts` and `buildModelDrawers` are re-run on the same `*Spec` (both pure), never guessed from `Spec.Models`.
- A predictor level the output never carries is listed with an `error` and NO delta. This is NOT the `"other"` catch-all (which fires); it happens because the design ranks levels within the listwise reservoir while the reconstructed marginal ranks over the whole cohort, so some design levels never generate.
- A zero-predictor model is `marginal: true`, a COMPLETE model, still comparing its intercept.
- `flagged` fires only when the gap exceeds BOTH `ModelRecoveryTolerance` (0.10 latent sd) AND twice the refit SE; `n_fired` separates "fired and recovered nothing" (a fault) from "never fired".
- The refit uses the SAME REG_OLS engine and `dummyRecord` adapter as capture — a second estimator would make every gap ambiguous — and is UNPENALIZED (the captured coefficient compared against is already the shrunken one). It lives in `synth/` (which may import `internal/processing/regression`).
- **A DISCONTINUOUS target is scored on a CALIBRATED PROBIT SCORE, not refused and not inverted.** `latentFor` cannot invert `bernoulli` / `discrete`, and an `error` per target blinded the section on exactly the field types survey cohorts are made of. `probitScore` (`internal/synth/fidelity_score.go`) maps a stored value to Φ⁻¹ of its band's MIDPOINT under the reconstructed marginal — a monotone re-expression. **Its bias toward zero is COMPUTED, not assumed away**: the score is projected onto the design twice — from the generated values and as the conditional mean the CAPTURED model implies (`E[score | m]`); OLS is linear in its response, so dividing by `b_expected/captured` removes the attenuation exactly under faithful generation. The SE is divided by the same factor; a staircase entry reports NO recovered intercept (its cut points come from the marginal, held exactly). `ModelFidelity.Scale` is `"probit_score"` or `"latent"`; `ScoreRetention` reports the factor per term.
- **No minimum-level gate**: K = 2 is admitted — same transform on both sides removes the false-attenuation objection; low retention widens noise, not bias. `minScoreRetention` (0.05) only refuses a band structure with no signal. An ordered-probit refit would be more efficient, not more correct.
- **The boundary is PARTIAL and STATED: `model_residual_correlations` takes no staircase endpoint** — a coefficient can be calibrated (OLS linear in response), a correlation cannot (the factor depends on the pair's joint distribution). Such pairs stay counted under `no_model_fit`, never silent.
- A flag on a QUANTIZED target is real: inversion undoes Q but not the writer's integer rounding, so most of a latent effect on a 0/1 or `u4` target is destroyed by the WRITE and the refit correctly reports what survived.
- Cost bounded by the single-decode cache (`decodeSyntheticRows`) and `modelRecoveryRowCap` (10,000 — capture's snapshot size, so neither side uses more rows). Detail: `skills/synth-model-recovery.md`.

**Residual-correlation recovery + the numeric-arm disjointness (`FidelityReport.ModelResidualCorrelations`).** Captured rho beside rho recovered on `_synthetic` for every applied residual correlation (`internal/synth/fidelity_residual.go`).
- **Deliberately NOT folded into `pairwise`**: `pairwise` scores value-scale `Spec.Correlations`; this scores residual-scale `Spec.ResidualCorrelations` — different numbers over the same fields, on disjoint field sets by construction.
- The recovered side uses the REFIT's own residuals; scoring against the captured coefficients would fold every coefficient gap into a correlation and state one finding twice. Scale is latent.
- **The listing is BOUNDED because the section is quadratic**: `compared` / `flagged` / `mean_delta` / `max_delta` cover every pair; `pairs` lists the worst `maxResidualRecoveryPairs` (20) worst-first with `omitted` counting the rest. `flagged` uses `ResidualRecoveryTolerance` (0.10) ALONE — with thousands of rows the SE is tiny, so a noise band would collapse onto the floor.
- Unmeasured pairs ride a SEPARATE list with `captured_rho` and no recovered slot (`insufficient_overlap`, `no_variance`, recovery-only `no_model_fit`).
- **`models` and the two NUMERIC-TARGET pair sections are disjoint by construction**: a modelled numeric never appears in `categorical_numeric_pairwise` / `set_numeric_pairwise` — the sampler those score did not run for it, and an entry would be a delta for a mechanism that never executed. Two guards: `SpecFromProfile` omits the pair, and `resolveConflicts` pre-claims every modelled field (hand-authored specs). The retirement is per TARGET. Detail: `skills/synth-residual-recovery.md`.

**The terminal warning summary (`internal/synth.GroupWarnings`).** Warnings reach files (`Profile.Warnings`, translation warnings, `Result.Warnings`); without a terminal summary a capture where most models died looked identical to a clean one. `GroupWarnings` (`internal/synth/warning_summary.go`) folds them into counted groups; `internal/cli/warnings.go` renders to **stderr** (never stdout, so pipelines keep their bytes), attention kinds FIRST, capped at `maxWarningExamples` (3, one screen).
- **The taxonomy lives in `synth/`, beside the functions that BUILD the strings** — a classifier in the CLI would drift silently when a message is reworded.
- **An unrecognised warning is classified as needing ATTENTION, not as expected** — a benign `default:` is how a mis-serialised predictor kind once disabled most of a feature with no signal.
- **Expected outcomes are counted separately** (zero-predictor models, thin pairs, arbitrated claims); folded together, a healthy and a broken capture both read "N warnings".
- `synth from-profile` summarises all three channels (capture / translation / generation), dropping byte-identical duplicates. The generation channel also reaches the fidelity REPORT (`mergeFidelityWarnings` at `Pulse.Synth`, deduped), since post-merge arbitration and never-fired reports exist only after generation; re-running `resolveConflicts` at the CLI was rejected (a second copy of arbitration). Only `warnings` content moves; no envelope shape changes. With `--fidelity-report` it prints the recovery headline by re-reading the report. Detail: `docs/src/cli/profile-create.md` (Warning summary).

**Utility against the SOURCE, and effect sizes beside every marginal p-value (`FidelityReport.Utility`, `FieldFidelity.EffectSize`).** Recovery sections compare with the CAPTURED model; a coefficient is a PARTIAL effect, while an analyst's table is a MARGINAL contrast carrying source confounders, so the twin can recover the model yet compress the contrast.
- `utility.target_rates` (`internal/synth/fidelity_utility.go`, `BuildTargetRates`) is automatic for every applied model: per categorical predictor, the target's mean per level on each partition, the spread over levels with ≥ 30 rows on BOTH, `spread_ratio`, ε² via `groupedStrength`, and a `verdict` — `compressed` / `inflated` only when the spread moves by more than `UtilityContrastTolerance` (20%) AND more than 2 SEs, else `preserved`.
- `utility.model_fits` is opt-in (`SynthOptions.FidelityModel` / `--fidelity-model`): a `pulse process` request whose regressions run through the engine at the facade (`synth_fidelity.go`) on the SOURCE before generation (an engine refusal fails the call, nothing written), then on the output filtered to `_synthetic`. `CompareModelFits` reports fit statistic, `fit_ratio`, and per term `ratio`, `difference`, `z` (a `*float64`, ABSENT — never 0 — when both SEs are 0) and `ratio_reliable` (`false` when |source| ≤ source SE, because `ratio` explodes near zero). An invalid model is `PULSE_SYNTH_FIDELITY_MODEL_INVALID`, before generation.
- **Effect sizes**: each marginal `fields[]` entry gains `effect_size {measure, value, magnitude, convention}` — Cohen's d (signed, pooled SD, FMA-free) for numerics, Cramér's V from the χ² test's own `details.effect_size` for categoricals, on Cohen (1988) bands, "very small" below small (never "negligible"). Bands are restated in synth and pinned by `TestSynthFidelityEffectBandsMatchConventions`. `marginalEffectSize` is the one switch a new scoring arm extends.
- **Every scalar type is scored, and a rule-caused flag says so.** `marginalTest` (`internal/synth/fidelity_marginal.go`) routes each type to an existing operator: `u4`, `date`, `datetime` ride `TEST_KS` + d (a `u4` reconstructs like a `u8`, so χ² would score twins of identical generation on two scales); `packed_bool` rides `TEST_CHISQ` via the `categorical_u8` view schema built in the facade bridge (synth takes an injected `TestRunner`). A `set_*` option gains V of its own 2x2 table (`setOptionEffectSize`).
- A `datetime` entry adds `shape {clock, hour_tvd, weekday_tvd, month_tvd}` (month bins in month order), because KS and d read instants as one line and miss a morning→evening shift. **The shape reads the clock GENERATION used, never UTC behind a local capture**: the facade passes the generating spec (`BuildFidelityReportForSpec`) and the field's `time_zone` / `time_zone_field` picks the zone (`clock: "local"`), else `"utc"`; read on UTC, a faithful per-row local schedule scored as badly wrong. Null zone cells are left out with a count warning; a zone field absent from the compared cohort falls back to UTC with a warning. Zone reads go through `internal/temporal` only. A `date` entry gets `{clock: "utc", weekday_tvd, month_tvd}`; `HourTVD` is a `*float64` so datetime reports stay byte-identical and a real 0 stays present.
- `AttachRuleNotes` (`fidelity_rule_note.go`) sets `rule_note` on a marginal flagged at ≥ `small` whose field a rule writes (declaration then slot order, no map seed): the rule pass runs last on generated rows only, so the rule may be the cause. It names rules that CAN move the field; firing is the never-fired warning's job.
- Reports gain keys only (additive `omitempty`). Detail: `skills/synth-fidelity-report.md`, `docs/src/cli/synth-from-profile.md`.
