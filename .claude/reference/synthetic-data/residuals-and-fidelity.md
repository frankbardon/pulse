# Synthetic data — the correlated residual draw, model and residual-correlation recovery in the fidelity report, the terminal warning summary, utility against the source and marginal effect sizes

Per-topic slice of the synthetic-data reference (the correlated residual draw, model and residual-correlation recovery in the fidelity report, the terminal warning summary, utility against the source and marginal effect sizes). Index (preamble + section map): `.claude/reference/synthetic-data.md` — load it first, then only the slice(s) your change touches.

**The correlated residual draw (`Spec.ResidualCorrelations`).** The consuming half of the capture above, and the change that makes a numeric able to be **both categorically conditioned and correlated with a sibling numeric** — a combination that was unrepresentable before it. `SpecFromProfile` translates `residual_correlations.pairs` (the MEASURED ones; the `unmeasured` list is translated into NOTHING, because an absent pair is completed-and-counted by the generator while a written-out zero would present a gap as a measurement and silence that count) onto the additive `omitempty` `Spec.ResidualCorrelations []CorrelationSpec` slot. At `generate()` setup, `buildResidualCorrelator` (`internal/synth/residual_draw.go`) compiles it into ONE correlated standard-normal vector drawn per row, and each participating `modelDrawer` reads its own component as the `z` of `value = Q(Φ(μ(row) + σ·z))` instead of calling `rng.NormFloat64()`. **The copula stops being a terminal stage that overwrites `row[field]` and becomes the residual structure a modelled field draws THROUGH** — nothing overwrites anything, so the predictors move μ and the shared vector correlates what is left. **There is exactly ONE Cholesky and ONE completion policy**: `factorCorrelations` (`internal/synth/copula.go`) is shared by `buildCorrelator` (value scale) and `buildResidualCorrelator` (residual scale), differing only in the two nouns it puts in the warning (`correlation` / `residual correlation`, `correlated field` / `modelled field`), so E3-S1's assume-and-record policy and its ridge report cannot land on one scale and miss the other. **Determinism**: component order is DRAWER order, which `buildModelDrawers` already fixed to SCHEMA FIELD ORDER — never the `residual_correlations` array order (a document artifact: bind to it and the cohort depends on how the request was serialized). The vector consumes exactly one normal per participant in component order BEFORE the first drawer runs; a non-participant still consumes its own single draw where it always did; and fewer than two surviving participants produces NO correlator and NO draw at all, which is what keeps a spec declaring none byte-identical to pre-slot output. Participation is decided from the COMPILED drawers, not from `Spec.Models`, so a correlation naming a field whose model was dropped in translation or failed to compile is dropped with one aggregated warning rather than stamping a component index onto a field nothing draws. **A value-scale `Spec.Correlations` entry naming a modelled field stays refused, permanently** — realizing it would require overwriting the model's output, and rerouting its figure into the residual would apply every predictor the two fields share a second time (`internal/synth/residual_corr.go`). `resolveConflicts` reports it as *is not applied … capture residual correlations (`profile create --residual-correlations`)* and deliberately NOT as a `conditional relationship conflict`, because no pair claimed the field. The E1-S4 interim wording (*not yet honoured* / *residual draw is still independent*) is GONE, not relaxed. **The feature's real boundary is the ZERO-PREDICTOR target**: selection emits a zero-predictor model for a target nothing explained, E3-S1 admits it as a CAPTURE participant, but `modelSpecFromProfile` DROPS it at translation under E2-S1's per-target rule (a field nothing explains is better served by its captured conditional pair than by an empty model), so its captured residual pairs reach the Spec as nothing. On the motivating cohort that is ~50 of 105 modelled targets. Reversing the drop would retire those fields' conditional pairs in exchange — a worse trade — so the boundary is pinned by `TestResidualCorrelations_CapturedTargetIsRealizedEndToEnd` rather than closed. For a `normal` target the latent→value map is affine, so the realized value-scale residual correlation is the captured figure exactly; for a `lognormal` or `--fit-shape` `mixture` `Q` the RANK correlation is exact and Pearson attenuates — the identical, documented property of the value-scale copula, not a second approximation. `validateSpec` refuses a residual correlation naming an unmodelled field (hand-authored specs only; `SpecFromProfile` bypasses it and the generator warns instead). `format_version` does NOT move — `synth.Spec` lives in `synth/`, not `types/`. **Model recovery in the fidelity report (`FidelityReport.Models`).** `synth from-profile --fidelity-report` gains a per-field `models` section (`internal/synth/fidelity_models.go`, `internal/synth.BuildModelFidelity`): for every linear model generation ACTUALLY APPLIED, it refits that same model on the output cohort's `_synthetic` partition and reports the captured coefficient beside the recovered one, per predictor. Additive and `omitempty`, so a report for a profile captured without `--fit-models` is byte-identical to the pre-E5 shape; `format_version` does NOT move (`synth.FidelityReport` lives in `synth/`, not `types/`). Every other section of that report asks whether the generated rows LOOK like the source; this one asks whether the captured STRUCTURE survived generation, and the distinction is the whole point — this effort shipped two silent structure-loss bugs (v0.32.2 scoring pairs generation never applied; E2-S5 killing 85 of 105 captured models) and in BOTH the marginals stayed healthy while the conditioning was gone. It is also the only instrument that can separate a faithful generation whose marginal contrasts are merely COMPRESSED (partial effects vs. marginal contrasts, plus predictors drawn from their own marginals so source confounding is absent) from one that genuinely lost structure: recovered ≈ captured means the former, recovered attenuated means the latter. **The comparison is LATENT-scale on both sides and that is not cosmetic.** A modelled numeric is drawn as `value = Q(Φ(μ + σ·z))`, so its coefficients are latent quantities; regressing the RAW generated values would compare a value-space effect against a latent coefficient and would report every `--fit-shape` target as badly recovered while generation was exactly correct. Each generated value is inverted through `latentFor` (`internal/synth/copula.go`, the algebraic inverse of `quantileFor`, one arm per supported distribution, round-trip-gated by `TestLatentFor_InvertsQuantileForEveryDistribution` — the two switches MUST move together or a distribution silently drops out of the section) and the captured coefficient is divided by the target's own marginal std, exactly as `buildModelDrawers` divides it; `latent_scale` rides each entry so a reader can multiply back. **Which models ran is asked of generation's own compiler, never guessed from `Spec.Models`**: `resolveConflicts` AND `buildModelDrawers` are re-run against the same `*Spec` `generate()` was given (both are pure functions of the Spec), so the section reproduces the surviving set including the drawer compiler's two warn-and-skip refusals. A field with no model has no entry; a predictor whose level the output cohort never carries is listed with an `error` and NO computed-looking delta. **That is NOT the top-K `"other"` catch-all** — on the motivating cohort all 54 catch-all terms fire (3,992–9,046 rows each) and none errors, exactly as the composed-draw paragraph above describes. The real cause is that the model's retained level set and `Categorical.Top`'s are ranked on DIFFERENT bases: the design ranks levels by frequency within the listwise-admitted reservoir rows for that target, while the reconstructed marginal ranks over the whole cohort. Both keep 32, and they disagree — 9 of `brand`'s 32 design levels, 4 of `ageExact`'s and 2 of `category`'s are absent from the marginal that generates them, so those columns are constant over the synthetic partition and their coefficients are not identified (138 of 2,235 entries). A zero-predictor model is `marginal: true` with no `predictors` array — a COMPLETE model, not a failure — and still reports its intercept comparison. `flagged` fires only when the gap exceeds BOTH `internal/synth.ModelRecoveryTolerance` (0.10 latent sd) AND twice the refit's own standard error; `n_fired` separates "fired thousands of times and recovered nothing" (a fault) from "never fired" (nothing to recover). The refit uses the SAME `internal/processing/regression` REG_OLS engine through the SAME `dummyRecord` adapter capture used — a second estimator would make every gap ambiguous between "generation lost structure" and "two fitters disagree" — and is deliberately UNPENALIZED even when capture shrank its own, since the captured coefficient being compared against is the shrunken one. It needs no injected `TestRunner`: `synth` cannot import `processing`, but it can and already does import `internal/processing/regression`, so the refit lives in `synth/` rather than at the facade. ****A DISCONTINUOUS target is scored on a CALIBRATED PROBIT SCORE, not refused and not inverted.** `latentFor` refuses `bernoulli` and `discrete` — a step or staircase `Q` maps a whole latent interval onto one stored value, so the latent that produced a row is genuinely not recoverable from it — and for one release that refusal propagated straight into this section as an `error` per target. It was sound and it was an instrumentation LOSS, measured on the motivating cohort at **2 comparable targets of 53** and `model_residual_correlations` at **1 compared pair of 1,378**: the section that exists to catch silent structure loss went blind on the exact field types the cohort is made of, immediately after a change that moved every one of them. The fix is to score BOTH sides with the same deterministic surrogate instead of pretending to invert: `probitScore` (`internal/synth/fidelity_score.go`) maps a stored value to `Φ⁻¹` of its own band's MIDPOINT under the field's reconstructed marginal — the level's cumulative interval `[F(v⁻), F(v)]`, midpoint `Φ⁻¹((F(v⁻)+F(v))/2)` — which is an ordinary monotone re-expression of the level, not an estimate of anything. **It is BIASED toward zero, and the bias is COMPUTED rather than assumed away**: a surrogate regressed on the true latent attenuates every coefficient by a factor set by the target's own band structure, so `internal/synth/fidelity_score.go` projects the score onto the design TWICE — once from the generated values, and once as the conditional mean the CAPTURED model implies for each row (`E[score | m]`, integrating over that model's own residual scale). OLS is linear in its response (`b = (X'X)⁻¹X'y`), so under faithful generation `E[b_observed | X]` equals `b_expected` EXACTLY, and dividing the observed coefficient by `b_expected/captured` returns it to the latent scale with the attenuation REMOVED, not estimated — no distributional assumption beyond the generation formula itself. The standard error is divided by the same factor; a staircase entry reports NO recovered intercept, because its cut points come from the captured MARGINAL, which generation holds exactly, so a calibrated intercept would be a number where there is no measurement. `ModelFidelity.Scale` carries `"probit_score"` (against `"latent"` for a continuously-invertible target) so a reader never has to guess which scale a number is on, and `ModelPredictorFidelity.ScoreRetention` reports the measured factor per term. **There is deliberately NO minimum-level gate.** `K = 2` — the `packed_bool` case, where the surrogate degenerates to exactly the two-valued shape the inverse-Mills construction was rejected for — is admitted, because the objection to inverse-Mills was that it reported a large FALSE attenuation against an un-transformed captured coefficient, and same-transform-both-sides removes that objection whatever K is; K = 2 is merely the lowest-retention case (measured retention 0.54, against 0.83–0.92 at K = 7), and low retention widens the noise band rather than biasing the delta. `minScoreRetention` (0.05) exists only to refuse a degenerate band structure that carries no signal at all. An ordered-probit refit would be more EFFICIENT and is not more CORRECT — `internal/processing/regression` exposes `binomial` + `probit` as a reserved, unimplemented enum, so it is a future narrowing of the same estimate, not a correction of it. Measured restoration on the motivating cohort: comparable targets **2 → 53** of 53, step-quantile errors 51 → 0, compared predictor terms **150 → 2,343** of 2,499, flagged terms 7 → 97, score retention over 2,193 terms min 0.075 / median 0.456. **The boundary is PARTIAL and STATED: `model_residual_correlations` still takes no staircase endpoint** — a COEFFICIENT can be calibrated because OLS is linear in its response, a CORRELATION cannot, since the factor relating two score residuals' correlation to the correlation of the residuals that actually drove the draws depends on the PAIR's joint distribution rather than on either marginal, and no projection removes it. Those pairs stay counted in the unmeasured list under `no_model_fit` (1 compared of C(applied models, 2) — 1,377 unmeasured at 53 participants, 1,652 at the 58 the current tree applies; unchanged either way) rather than silent; closing it needs a polychoric-style bivariate calibration or the same ordered probit. A partial restoration that is honest beats a full one that is not. A flag on a QUANTIZED target is real but needs reading:** the latent inversion undoes `Q` and cannot undo the writer's integer rounding, so for a `packed_bool` or `u4` target — where a 0/1 value inverts to exactly two latent values — most of the latent effect is destroyed by the WRITE and the refit correctly reports only what survived. On the motivating cohort every modelled target is `packed_bool` or a small integer and 30 of 55 models flag, 18 of them `packed_bool` and 9 `u4`; `peopleAware` recovers 0.11 against a captured 0.556 on 1,447 firing rows at an SE of 0.021, so the attenuation is measured, not noise. That is a property of the generated cohort rather than of the instrument. The discrete draw it named as the fix has SHIPPED (`discrete` / `bernoulli` marginals), and with it the quantization is no longer a flag to read around — a discontinuous target is scored on the calibrated interval-midpoint probit score described above, not on a latent inversion that does not exist for it. Cost is bounded by reusing `decodeSyntheticRows` (the v0.32.1 single-decode cache) plus a `modelRecoveryRowCap` of 10,000 rows per refit — capture's own snapshot size, so neither side is estimated from more rows than the other. **Residual-correlation recovery + the numeric-arm disjointness (`FidelityReport.ModelResidualCorrelations`).** The same report gains a `model_residual_correlations` section (`internal/synth/fidelity_residual.go`, folded by `BuildModelFidelity` itself): for every residual correlation generation APPLIED, the captured rho beside the rho recovered from the `_synthetic` partition. Additive + `omitempty`, so a report for a profile captured without `--residual-correlations` is byte-identical to the pre-E5-S2 shape; `format_version` does NOT move. **It is deliberately NOT folded into `pairwise`, and the two section names are the load-bearing distinction**: `pairwise` scores `Spec.Correlations`, a VALUE-scale correlation realized by the copula, while this scores `Spec.ResidualCorrelations`, a correlation between two models' RESIDUALS realized by the residual correlator — different numbers over the same two fields (two fields both driven by `region` correlate on raw values while their residuals may be independent), and `resolveConflicts` excludes a modelled field from `Spec.Correlations` precisely so the two arms fire on DISJOINT field sets. The recovered side uses the REFIT's own residuals, not residuals against the captured coefficients: capture measured the residuals of a model fitted on its own rows, so recovery measures the residuals of a model fitted on ITS own rows, and scoring against the captured coefficients would fold every coefficient gap `models` already reports into a correlation and state one finding twice. Scale is latent for the same reason the coefficients are — generation correlates the `z`s, so `σ·z` carries the requested rho exactly while a non-normal `Q`'s value-scale residual is a rank-preserving, Pearson-attenuated image of it. E5-S1's refits produce the residuals as a by-product, so the partition is decoded ONCE and both comparisons ride it (`decodeSyntheticRows`, `modelRecoveryRowCap`). **The listing is BOUNDED because the section is quadratic in participants** — 55 applied models is C(55,2) = 1,485 pairs on a report already 1.65 MB, and a section nobody can read is not an improvement over a section that lied. `compared` / `flagged` / `mean_delta` / `max_delta` cover EVERY pair; `pairs` carries the worst `maxResidualRecoveryPairs` (20) by absolute delta, worst-first, with `omitted` counting the rest — the same worst-first-plus-counted-remainder shape `maxThinLevelWarnings` and `maxThinResidualPairWarnings` already use, so an unlisted pair recovered at least as well as the last one listed. `flagged` fires on `ResidualRecoveryTolerance` (0.10) ALONE, with no standard-error term: a correlation is already unit-free and over thousands of co-present rows its SE is under 0.02, so a noise-scaled band would collapse onto the floor. Unmeasured pairs ride a SEPARATE list carrying `captured_rho` and NO recovered-rho slot at all (`insufficient_overlap` / `no_variance` reused from the capture vocabulary, plus a recovery-only `no_model_fit` for an endpoint whose refit could not run), mirroring `residual_correlations.unmeasured` structurally rather than by convention. Measured on the motivating cohort: 55 participants, 1,485 compared, 147 flagged, mean delta 0.055, max 0.490, 0 unmeasured, +6 KB and ~5s on the existing report; the largest gaps sit on `packed_bool` and small-integer targets (`aware`x`familiarity` 0.738 -> 0.248), the same quantization attenuation the `models` section reports on the same fields. **`models` and the two NUMERIC-TARGET pair sections are disjoint by construction**: a numeric reached by a linear model has no entry in `categorical_numeric_pairwise` or `set_numeric_pairwise`, ever, because the pick-one sampler those sections score does not run for it and an entry would be a delta for a mechanism that never executed (the v0.32.2 bug class). Two independent guards make that structural rather than incidental — `SpecFromProfile` leaves a modelled target's captured pair off the Spec, and `resolveConflicts` pre-claims every modelled field ahead of the categorical-numeric stage, which catches a hand-authored spec declaring both. **The retirement is per TARGET, not per document**: an unmodelled numeric in the same profile keeps its pair and is still scored there, because a field whose model was captured but not applied would otherwise be reconstructed from nothing at all (on the motivating cohort: 55 fields in `models`, 46 in `categorical_numeric_pairwise`, no overlap). The three NON-numeric-target arms (`categorical_pairwise`, `set_categorical_pairwise`, `set_set_pairwise`) are untouched — a linear model targets a numeric and subsumes nothing they describe. **The terminal warning summary (`internal/synth.GroupWarnings`).** Every warning above reaches a FILE — `Profile.Warnings` in the profile document, `SpecFromProfile`'s translation warnings and `Result.Warnings` in the fidelity report / `--json` envelope — and until E6-S3 reached no TERMINAL at all: `pulse profile create` printed the row count and `pulse synth from-profile` the row count plus the report path, so a capture where 85 of 105 models died in translation looked byte-for-byte like one where nothing did. That is not a UX gap, it is how the E2-S5 defect survived the whole effort. `internal/synth.GroupWarnings` (`internal/synth/warning_summary.go`) folds a flat `[]string` into counted `WarningGroup`s; `internal/cli/warnings.go` renders them to **stderr** — never stdout, so every redirect and pipeline keeps exactly the bytes it had — with kinds needing attention FIRST and capped at `maxWarningExamples` (3, the CLI-side screen budget, deliberately smaller than synth's own `maxThinLevelWarnings` / `maxThinResidualPairWarnings` of 20 because those bound a document a reader pages through while this bounds one screen every kind shares). **The taxonomy lives in `synth/`, beside the functions that BUILD the strings**, because a reworded message is a change to the table and a classifier in the CLI would drift silently — the reworded line would simply start landing in the catch-all. **An unrecognised warning is classified as needing ATTENTION, not as expected**, which is the direct inverse of the `default:`-arm lesson E2-S5 taught: a benign default is how a mis-serialised predictor kind disabled 80% of a feature with no signal anywhere. **Expected outcomes are counted separately and must stay that way** — a zero-predictor model is a COMPLETE model, a thin pair still ships, an arbitrated pair claim is the design working, and on the motivating cohort those are 3,004 of 3,005 lines, so folding them into one figure makes "3005 warnings" the reading on a healthy capture and on a broken one alike. `synth from-profile` summarises all THREE channels (capture / translation / generation) because only the middle one carries `model for numeric field "x" not applied: …`; translation and generation both derive their conflict lines from one arbitration over one spec, so the CLI drops byte-identical duplicates before counting. **Since E2-S3 the generation channel also reaches the fidelity REPORT** (`mergeFidelityWarnings`, folded at `Pulse.Synth` — the only place holding both `res.Warnings` and the report path, deduped against the supplied channel). Until then the report carried only what could be computed BEFORE the run, so a `--rules` run's post-merge arbitration — the record of which captured relationships the rules retired, and E2-S3's own never-fired reports, neither of which exists until after generation — reached a terminal nobody keeps while the CLI's own footer claimed `Full list: <report> (.warnings)`. Re-running `resolveConflicts` at the CLI leaf was the alternative and was REJECTED: it fixes the conflict lines only and puts a second copy of generation's arbitration in a second place. Measured on the motivating profile with one claiming rule plus one dead rule, the report went from 3,846 warnings mentioning neither fact to 3,849 carrying the retired model, the dropped residual participant and the dead rule, with the 791 shared lines written once. Only `warnings` CONTENT moves — the slot is the same `[]string`, `synth.Result` is untouched and no `--json` envelope shape changes. With `--fidelity-report` it also prints the E5 recovery headline (`N model(s) checked, M flagged`), re-reading the report rather than adding a slot to `synth.Result`, which is the `--json` payload. Nothing here changes a generated byte or a `--json` envelope SHAPE; there is no silencing flag because no CLI leaf in this repo has one. Detail: `docs/src/cli/profile-create.md` (Warning summary) + `docs/src/cli/synth-from-profile.md`.

**Utility against the SOURCE, and effect sizes beside every marginal p-value (`FidelityReport.Utility`, `FieldFidelity.EffectSize`).** Every recovery section above compares the twin with the CAPTURED model; none compares it with the SOURCE rows, which the merged output cohort already carries (`_synthetic` false). That is the blind spot E2-S3 closes: a coefficient is a PARTIAL effect, an analyst's churn-by-contract table a MARGINAL contrast that in the source also carries every confounder contract travels with, so `models` can report a captured effect recovered while the twin's contrast is compressed against the source. `utility.target_rates` (`internal/synth/fidelity_utility.go`, `BuildTargetRates`) is automatic for every APPLIED model (same `resolveConflicts` + `buildModelDrawers` re-run as `models`; helper fields skipped): per categorical predictor field, the target's mean per level on each partition (a rate for a `packed_bool` target), the spread max − min over levels with ≥ 30 rows on BOTH partitions, `spread_ratio`, ε² on each side through the SAME `groupedStrength` arbitration uses, and a `verdict` — `compressed` / `inflated` only when the spread moves by more than `UtilityContrastTolerance` (20%) AND by more than 2 standard errors of the two spreads, else `preserved`. One decode pass, all pairs. `utility.model_fits` is opt-in: `SynthOptions.FidelityModel` / `--fidelity-model` supplies a `pulse process` request whose regressions run through the ordinary engine at the facade (`synth_fidelity.go`; synth cannot import processing) — on the SOURCE cohort BEFORE generation, so an engine refusal fails the call under the engine's own code and nothing is written, then on the output filtered `FILTER_TRUE _synthetic` — and `CompareModelFits` folds both: `statistic` (`pseudo_r2` for `REG_GLM`, `r2` otherwise), `source_fit` / `synthetic_fit` / `fit_ratio`, `n_obs` per side, coefficients sorted by term with `ratio` and a `missing` side. A model without regressions, a source or a report path is `PULSE_SYNTH_FIDELITY_MODEL_INVALID`, before generation. Measured on the privacy mirror (`TestFidelityUtility_ChurnTwinPseudoR2RatioIsInTheReport`, 20,000 rows): churn-logit pseudo-R² source 0.2086, twin 0.2206, `fit_ratio` 1.057; churned-by-contract spread 0.493 → 0.515, `preserved`. **Effect sizes (FR-17)**: each marginal `fields[]` entry gains `effect_size {measure, value, magnitude, convention}` beside its p-value — Cohen's d (signed synthetic − source, pooled SD, one shifted-sum pass, FMA-free) for a numeric field, Cramér's V read from the χ² test's OWN `details.effect_size` for a categorical one, labelled on the repo's Cohen (1988) bands (`cohen1988_d`, `cohen1988_w`; V takes w's bands only because the test runs against the two-level `_synthetic`, df* = 1), "very small" below small, never "negligible". The bands are restated in synth (descriptor imports synth) and pinned by `TestSynthFidelityEffectBandsMatchConventions`. At 20,000 rows a 0.05 SD shift rejects KS at p ≈ 2e-4 and reads "very small". `marginalEffectSize` is the one switch a new marginal scoring arm extends. Reports gain keys only — additive `omitempty`, a models-free spec without a supplied model carries no `utility`; `format_version` does not move. **Every scalar type is scored, and a rule-caused flag says so (E2-S4, FR-18).** `marginalTest` (`internal/synth/fidelity_marginal.go`) routes each type to an operator that already accepts it, so no stat math is new: `u4`, `date` (epoch days) and `datetime` (epoch seconds) ride `TEST_KS` + Cohen's d beside the wider integers — a `u4` reconstructs from the same per-level histogram a `u8` does, so scoring it on χ² would read two identically-generated columns on two scales — and `packed_bool` rides `TEST_CHISQ` (the field accepts it natively; `_synthetic` alone needs the `categorical_u8` VIEW schema `SyntheticAsCategoricalSchema` builds for the call, in the facade bridge `writeSynthFidelityReport`, because `internal/synth` cannot import processing and takes an injected `TestRunner`), whose 2x2 χ² is the two-sample proportion test and whose V is |phi|. A `datetime` entry adds `shape {clock: "utc", hour_tvd, weekday_tvd}`, because KS and d read instants as one line: measured, the same days drawn at evening instead of morning hours give d = −0.06 and KS p = 0.07 while `hour_tvd` is 1.0. The clock is UTC because the schema stores instants and no zone; both partitions share it, so a faithful local schedule is faithful on UTC. A `set_*` option gains V of its own 2x2 table, computed directly (`setOptionEffectSize`, FMA-free) since a multi-select is neither KS's scalar nor χ²'s partition. `AttachRuleNotes` (`fidelity_rule_note.go`, called from the bridge with the generating `*Spec`) sets `rule_note` on a `fields[]` / `set_fields[]` marginal flagged at an effect of at least `small` whose field a rule writes (`set`, `set_expr`, `set_null`, a non-first `null_together` member; declaration then slot order, so no map seed reaches the text): the rule pass runs last on generated rows only, so the rule may be the cause. It names rules that CAN move the field; firing is the never-fired warning's job. A report over none of these types with no rule-written flag is byte-identical (SHA-256 measured unchanged across the story on three fixtures).
