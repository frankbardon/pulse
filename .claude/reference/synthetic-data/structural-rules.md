# Synthetic data — structural rules: the slot, the rule pass, `owns_nulls`, priority-0 claims, `set_expr` and the coercion matrix

Slice of `.claude/reference/synthetic-data.md` — load the index first, then only the slice(s) your change touches.

**Structural rules (`Spec.Rules`, additive + `omitempty`).** The slot for facts that are not variation at all — a block not ASKED after a failed screener, a flag that is a band of another column. Reconstructed from marginals they come back as soft noise with a plausible rate and no gate. Five slots per `RuleSpec` (`internal/synth/rules.go`): `when` (optional predicate; ABSENT MEANS EVERY ROW), `set_null`, `set` (LITERALS), `set_expr` (expression results), `null_together` (one null decision across a block) — plus ONE MODIFIER, `owns_nulls`, which changes what `set_null` MEANS rather than adding an action.
- **`set` and `set_expr` are SIBLING KEYS, never one map with a `{"$expr": …}` marker**: one map leaves `{"set": {"region": "west"}}` undecidable between a literal and an identifier.
- Rules apply in DECLARATION order, sequentially, LAST WRITE WINS, in one pass at the END of the row. **Deliberately NOT topologically sorted** — declaration order is the one order an author can read off the document. The pass consumes no generation RNG, so a spec with no rules is byte-identical.
- The **standalone rules-file format is the `Spec.Rules` array itself** — inline and `--rules` are the same JSON.
- **Validation is EAGER — at spec parse, never at row time** (`validateRules` from `validateSpec`, so every entry point gates): a mistyped rule is otherwise invisible — the run succeeds with the gate simply absent. Codes: `PULSE_SYNTH_RULE_EMPTY`, `_FIELD_UNKNOWN` (also an undeclared name inside `isnull("…")` — that expression COMPILES, so it is an unknown FIELD, not `_EXPR_INVALID`; `isnullUnknownField` PARSES the source, and constraints share the check — `TestValidateRules_ExprEnvIsTheConstraintEnv`), `_FIELD_NOT_NULLABLE`, `_EXPR_INVALID` (`when` must return bool), `_VALUE_INVALID` (a `set` literal or `set_expr` result the matrix refuses; `details.slot` says which), `_CONFLICT` (one rule naming a field in two disagreeing slots — no order to appeal to within a rule), `_BLOCK_INVALID` (`null_together` with fewer than two distinct fields), `_OWNERSHIP_INVALID` (`owns_nulls` with an empty `set_null` — an ignored ownership claim would be invisible).
- A `when` failing at RUN time keeps `PROCESSING_RUNTIME` — generic expr faults identical to a constraint's; the coded error already carries rule index, slot and expression. Do not mint a code for it.
- Every error carries the rule INDEX (`errors.DetailSynthRule`) and, where one exists, slot (`errors.DetailSynthRuleSlot`) and field — a rule has no name, so the index is the only handle.
- `when` and `set_expr` compile against the SAME environment as `Spec.Constraints` (`rowExprEnv` / `rowExprOptions`) — a second hand-rolled env once broke field typing. Faults report in fixed slot order with SORTED keys, so the same fault refuses every run.
- Detail: `skills/synth-structural-rules.md`, `docs/src/cli/synth-from-schema.md`.

**The rule pass runs LAST, and that placement IS the semantics.** `drawRow`'s final act (`internal/synth/rules_apply.go`, compiled once by `compileRules`) gives **`if gate then null else inferred`**: every field already holds the value generation infers (sampler, model, pair, correlation), and a rule masks or replaces it ONLY where `when` selects. Any earlier and the model would overwrite a `set_null` on every row.
- **Accepted consequence: a field a rule NULLS still contributed its DRAWN value to any model using it as a predictor on that row.** Two-phase evaluation was REJECTED (doubles the stage surface, needs an undeclared rule↔model order); the respondent's propensity existed, the question was simply not asked.
- `set_null` sets the null mask and LEAVES the drawn value (as `nullableSampler` does, so `isnull()` behaves identically); `set` writes the value and CLEARS the mask (otherwise a drawn null would write 0 and the literal silently vanish). A `set` literal is coerced once at compile via `constantRowValue`.
- The pass consumes no generation RNG (rule draws read their own streams — `synthetic-data/cross-row-time-and-draws.md`, Rule draws). But a rule that PRE-CLAIMS a field retires its model, which stops consuming its per-row normal, so the stream legitimately moves — for a reason a warning names.
- **`set_null` over a non-nullable field is REFUSED** (`PULSE_SYNTH_RULE_FIELD_NOT_NULLABLE`): the writer has no null bit, so the rule would fire and the file could not show it. **`null_together` keeps only a warning**, because it states the members carry the GATE's decision (which may be "present"); the gated-block idiom names a NEVER-NULL field first on purpose. Do NOT promote `null_together` to a refusal.
- A `when` reads the row's PRE-ROUNDING float, so `== k` over a continuous reconstruction fires only on exact draws; use comparisons (`>= 9`). `packed_bool` and `discrete` fields are exact.
- Rules reach GENERATED rows only: `AugmentFromProfile` copies source records straight through.

**`owns_nulls`: a rule can be the field's ONLY source of absence, and it ZEROES the own draw rather than applying the residual.** `set_null` says WHICH rows are absent, not how many, so the target's own captured `null_rate` (a marginal already inclusive of the gate) kept firing beneath it: `g + (1−g)·r` — every gated cell right, every rate wrong. `RuleSpec.OwnsNulls` (`internal/synth/rules_ownership.go`) discards those fields' own null draw.
- **The exact correction, the residual (r − g)/(1 − g), is not computable**: `g` is the firing probability of an arbitrary predicate. So the flag zeroes the draw and the GAP IS MEASURED: `ownershipWarnings` counts realised nulls over ACCEPTED rows and warns when the realised rate misses the discarded `null_rate` by more than `nullOwnershipDivergenceThreshold` (0.02) AND `ownershipNoiseStdErrs` (2) SEs (without the noise term the line is a coin toss on small runs). Under-firing and over-firing get different sentences, because their remedies are opposite (`TestOwnsNulls_WarningNamesTheDirectionOfTheGap`). One ATTENTION kind, capped at 20 worst-first.
- **Where g IS knowable the residual is bounded**, so `--suggest-rules` sets the flag on every gating candidate: it admits a pair only when the target is null on ≤ `gateLowNullRate` (0.02) of OPEN rows, and that IS the residual.
- **Suppression is a WRAPPER that discards the verdict (`ruleOwnedNullSampler`), never a rebuild without the nullable wrapper**: `nullableSampler` consumes one inner draw plus one `Float64()` whatever the rate, so a rebuild would shift the whole seeded stream.
- **Ownership is a UNION, never a `resolveConflicts` claim**: two rules may own one field; the draw is suppressed once; the divergence line names BOTH indices.
- `null_together` already does this for non-gate members by COPY. It is not retired: it alone expresses a co-missing block with NO gating field. Detail: `skills/synth-rule-nulls.md`.

**A rule that DETERMINES a field pre-claims it at priority 0.** `resolveConflicts` (`internal/synth/conflict.go`) lets `Spec.Rules` claim first, ahead of the model pre-claim, because an unconditional write in the last pass wins outright. Without it the overwritten field's model still compiles, draws residual correlations and — the real harm — **produces a `FidelityReport.Models` delta for a value nothing kept**. The model, a pair naming the field and its residual participation all drop through the existing warnings (`… is already claimed by structural rule N (set_expr); …`).
- **A whole-field claim SUBSUMES that field's `set_*` OPTIONS, one-directionally.** `claimTarget` is `{field}` or `{field, option}`; `resolveConflicts.claimedBy` expresses containment. A pair on ONE option never reaches the whole field (or one pair would evict a rule or model from the whole multi-select). A future per-option rule slot MUST key on `{field, option}` (`TestClaimTarget_OptionGranularity`, `TestRuleClaims_NeverEmitsAnOptionTarget`).
- **Which rules claim is the whole contract, and each exclusion is SILENT if backwards** (`internal/synth/rules_claim.go`): a rule with `when` does not claim (it writes only some rows; claiming would strip the model from the rest); **`set_null` NEVER claims** (the model produces what non-gated rows keep); `null_together` supplies no value; **a `set_expr` that READS ITS OWN TARGET does not claim** — it transforms the draw (the documented `round(nps)` normalisation would otherwise strip `nps`'s model and every residual correlation). Self-reference is detected on the PARSED expression, never by substring; an unparseable expression answers "reads" (the direction that cannot lose structure). A self-`lag("x", …)` DOES claim — the string argument is not a read of the current draw.
- **The same test decides which `categorical_*` may omit `distribution`** (`ruleDeterminesCategorical`): a wholly-claimed categorical needs no sampler (and refuses `params`); it consumes no RNG and only an EARLIER rule reads its `""` placeholder. Detail: `skills/synth-rule-claims.md`.

**`set_expr` and THE COERCION MATRIX.** `set_expr` assigns an expression result, collapsing several gated rules into one unconditional rule (`{"set_expr": {"promoter": "nps >= 9", …}}`) that is eligible for the pre-claim. It clears the null mask like `set`. **The matrix is the surface and a wrong cell is a silent wrong value** (a bool as a string encodes 0; an out-of-domain category becomes a dictionary entry that looks like data). There is exactly ONE matrix (`ruleValueFault`, `internal/synth/rules_coerce.go`); the `set` path goes through it too, and the row shape comes from `constantRowValue`.
- By target class (`sentinelFor`'s three): **scalar** takes bool as 1/0 or a number, range-checked, refuses strings; **categorical_\*** takes a string in the declared domain (unbounded for `regex` / `constant` fields); **set_\*** takes a selection (a `map[string]bool`, a list of option names, `split()`'s `[]string`), refuses scalars.
- **`decimal128` from a STRING is refused in `set_expr` (accepted verbatim in `set`)**: anything computed has already lost digits as float64, and a string left in a float-typed row field makes the NEXT rule fail intermittently at run time. Exactness lives in `set`.
- **TWO TIMINGS, one code.** A fault the RETURN TYPE settles is refused at SPEC PARSE (`validateRuleExpr`, off `prog.Node().Type()`; `interface{}` defers), a fault only a VALUE settles at ROW time — both `PULSE_SYNTH_RULE_VALUE_INVALID` with `slot: "set_expr"`. The static side probes the same matrix with the type's zero, so parse-time and run-time cannot disagree.
- **INTRA-RULE ORDER IS UNOBSERVABLE — every expression in ONE rule, `when` included, reads the row as it stood BEFORE the rule ran; writes land afterwards** (`UPDATE t SET a = b, b = a` swaps). The alternative would expose Go map / alphabetical order, so renaming a column would silently change a number. Across rules: sequential, last write wins.
- **The pre-rounding gotcha bites `set_expr` silently**: the row holds the sampler's float, the wire `round(f)`, so bands written off a continuous field disagree with the printed number on a share of rows. Normalise in an EARLIER rule — `{"when": "!isnull(nps)", "set_expr": {"nps": "round(nps)"}}` (the snapshot rule makes "earlier" mandatory). **`round`, not `int`**: both reach full band agreement, but `int` gets there by moving the SCORE, `round` by moving the FLAGS. **The `when` guard is mandatory**: `set_expr` clears the null mask, so the ungated form un-nulls the field and every `null_together` block keyed on it. That rule reads its own target, so it does not pre-claim. (Moot for fields reconstructed as `discrete`.)
- **The row environment's functions** are expr-lang's stock set minus `now()` (`PULSE_SYNTH_EXPR_NONDETERMINISTIC`: the wall clock breaks the `(spec, seed)` contract), plus `isnull`, plus `exprenv.MathOptions` on `detmath` (typed, so bad arity fails at parse), plus the cross-row, time and draw functions (`synthetic-data/cross-row-time-and-draws.md`) — and NOTHING query-only. A field named like a built-in follows the query side's precedence: bare = the field, calling a shadowed name is refused, a bare built-in name no field declares is refused (expr-lang would compile it to nil). The reserved names are in `internal/synth/row_expr_builtins.go`.
- The pass allocates nothing per row of its own. Detail: `skills/synth-rule-expressions.md`.
