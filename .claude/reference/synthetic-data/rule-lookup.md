# Synthetic data — `lookup()` in rule expressions

Per-topic slice of the synthetic-data reference (`lookup(table, keys...)` in a rule `when` / `set_expr` and in `constraints[]`). Index (preamble + section map): `.claude/reference/synthetic-data.md` — load it first, then only the slice(s) your change touches.

**A rule's `lookup()` tables are an INPUT of the run: the table name is a literal, every referenced table's content digest folds into the spec's identity, and a null key is a miss, never the drawn value (U79 G5b).** The row env (`rowExprOptions`, so constraints, `when`, `set_expr` and both `--suggest-rules` detectors alike) declares `lookup` on every compile and answers it from `Options.LookupTables` (`internal/synth/row_lookup.go`, `synth.LookupTable{Rows, Axes}`). The Pulse facade fills that field when it is nil from the instance's VISIBLE tables (`Service.Extensions().LookupTables`: `Extensions.LookupTables`, `LookupTablesDir`, `PULSE_LOOKUP_TABLES_DIR`, after feature-profile hiding), so the CLI synth leaves honour the env var through `pulse.New` with no flag; a non-nil map — an empty one included — is used as given (`synthLookupOptions`, root `synth_lookup.go`). Five rules, each of which fails SILENTLY when got wrong:

1. **The table name must be a string LITERAL**, refused at spec parse in every slot (`lookupCallShape` inside `rowExprStaticRefusal`: `PULSE_SYNTH_RULE_EXPR_INVALID` in a rule, `SERVICE_VALIDATION` in a constraint). That is what makes the referenced set a static fact (`Spec.ReferencedLookupTables`); a computed name would make it per-row and no hash could carry it. Folding EVERY instance table instead was rejected — an unrelated table edit would move every lookup-calling spec's identity.
2. **Identity = spec + referenced digests.** `Spec.HashWithLookups(tables)` is `Spec.Hash()` for a spec calling no `lookup()` (byte-identical identity for every pre-existing spec), otherwise `types.CanonicalHash("synth", {spec, lookups: {name: digest}})`, an unregistered referenced table digesting as `"unregistered"`. `LookupDigest` is SHA-256 over sorted keys, each value's exact `float64` bits (so `-0`, NaN payloads and the last ulp count — JSON would choke on NaN) and the axes. It is the synth operation's `RequestHash` (`synthIdentity`, `observability.go`) and the `SynthStream` header's. `Spec.Hash()` stays table-blind; an unreferenced table never moves the identity.
3. **Judged before row 0, with the query side's codes** (`checkLookupCalls`, first act of `generate`, so even a call behind a gate no row reaches): `tablecall.Refusal` over each literal call against a `lookupCatalog` (`HasLookup` always true — the function is always declared, so a literal name with no tables is `PULSE_LOOKUP_TABLE_UNKNOWN`, not a compile fault), a literal null key or a literal key off the declared axes `PULSE_LOOKUP_MISS`, plus synth's own arity rule: MORE key arguments than declared axes can never hit (each argument contributes at least one `|` part) and is `PULSE_LOOKUP_MISS {table, key_count, axes}`. Fewer is NOT refused — a computed key may itself carry `|`. Details add `rule_index` / `rule_slot` / `field` / `expr`.
4. **A key that READS a null field is a null key.** A nulled field still carries its drawn value in the row env, so without `lookupKeyPatcher` a null `region` would silently read the table at whatever region the sampler drew. The patcher wraps every key argument reading a declared field (bare identifier, not a callee) in `lookup:key(<fields>, <arg>)`, which binds nil when any of those fields is null on the row, so the builtin raises `PULSE_LOOKUP_MISS {null_key}`; it runs after the isnull patcher, so `isnull(x)`'s name is not a read. A row-time miss keeps its code through `ruleDrawError` / the constraint evaluator (`lookupRunError`, processing's `tableRefusal` rule), never `PROCESSING_RUNTIME`.
5. **A callback-backed instance table is refused when named** (`PULSE_SYNTH_EXPR_NONDETERMINISTIC {function, table}`): it has no content to digest, so the output would not be a function of (spec, seed, tables). An unnamed one is simply not passed. `synth.LookupTable` therefore has no `Lookup` field.

Keys stringify as processing's `lookupBuiltin` does (`%v` of the row value — every scalar is `float64`, so `3`, a `packed_bool` `1` / `0`, a categorical its level) and join with `tablecall.KeySeparator`; a `set_*` or vector key has no meaningful string. `lookup` joins `rowReservedNames` (a field named `lookup` reads bare; calling it is refused). `--suggest-rules` probes compile against the same env (parity, `TestSuggestRulesProbes_ShareTheLookupEnv`) and never render a `lookup()` candidate — a table is an instance fact the captured cohort cannot evidence (`TestSuggestRules_NeverProposesLookup`). Pinned by `TestSynthLookup_*`, `TestLookupDigest_ContentSensitive` (`internal/synth`), `TestSynth_ReadsInstanceLookupTables`, `TestSynth_CallbackLookupTableRefused`, `TestSynthStream_HeaderHashFoldsLookups` (root) and `TestSynthFromSchemaCLI_HonoursLookupTablesDirEnv` (`internal/cli`).
