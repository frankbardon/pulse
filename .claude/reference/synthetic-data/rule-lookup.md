# Synthetic data — `lookup()` in rule expressions

Slice of `.claude/reference/synthetic-data.md` — load the index first, then only the slice(s) your change touches.

**A rule's `lookup()` tables are an INPUT of the run: the table name is a literal, every referenced table's content digest folds into the spec's identity, and a null key is a miss, never the drawn value.** The row env (`rowExprOptions` — constraints, `when`, `set_expr` and the `--suggest-rules` detectors alike) declares `lookup` on every compile and answers from `Options.LookupTables` (`internal/synth/row_lookup.go`, `synth.LookupTable{Rows, Axes}`). When that field is nil the facade fills it from the instance's VISIBLE lookup tables (after feature-profile hiding), so CLI synth honours `PULSE_LOOKUP_TABLES_DIR` with no flag; a non-nil map, even empty, is used as given (root `synth_lookup.go`). Five rules, each SILENT when got wrong:

1. **The table name must be a string LITERAL**, refused at spec parse in every slot (`lookupCallShape`: `PULSE_SYNTH_RULE_EXPR_INVALID` in a rule, `SERVICE_VALIDATION` in a constraint). That makes the referenced set static (`Spec.ReferencedLookupTables`); folding EVERY instance table was rejected — an unrelated table edit would move every lookup-calling spec's identity.
2. **Identity = spec + referenced digests.** `Spec.HashWithLookups(tables)` equals `Spec.Hash()` for a spec calling no `lookup()`, else `types.CanonicalHash("synth", {spec, lookups: {name: digest}})` (an unregistered table digests as `"unregistered"`). `LookupDigest` is SHA-256 over sorted keys, exact `float64` bits (so `-0`, NaN payloads and the last ulp count) and axes. It is the synth operation's `RequestHash` and the `SynthStream` header's. `Spec.Hash()` stays table-blind.
3. **Judged before row 0, with the query side's codes** (`checkLookupCalls`, first act of `generate`, so even a call behind an unreachable gate): `tablecall.Refusal` per literal call (a literal name with no table is `PULSE_LOOKUP_TABLE_UNKNOWN`; a literal null or off-axis key `PULSE_LOOKUP_MISS`), plus synth's arity rule: MORE key arguments than declared axes can never hit and is `PULSE_LOOKUP_MISS {table, key_count, axes}`; fewer is not refused (a computed key may carry `|`). Details add `rule_index` / `rule_slot` / `field` / `expr`.
4. **A key that READS a null field is a null key.** A nulled field still carries its drawn value in the row env, so without `lookupKeyPatcher` a null `region` would read the table at the drawn region. The patcher wraps each key argument reading a declared field in `lookup:key(<fields>, <arg>)`, binding nil when any is null, so the built-in raises `PULSE_LOOKUP_MISS {null_key}` (it runs after the isnull patcher). A row-time miss keeps its code, never `PROCESSING_RUNTIME`.
5. **A callback-backed instance table is refused when named** (`PULSE_SYNTH_EXPR_NONDETERMINISTIC {function, table}`): it has no content to digest, so the output would not be a function of (spec, seed, tables). Hence `synth.LookupTable` has no `Lookup` field.

Keys stringify as processing's `lookupBuiltin` does (`%v`; joined with `tablecall.KeySeparator`); a `set_*` or vector key has no meaningful string. `lookup` is a reserved row name (a field named `lookup` reads bare; calling it is refused). `--suggest-rules` compiles against the same env (`TestSuggestRulesProbes_ShareTheLookupEnv`) and never proposes a `lookup()` candidate — a table is an instance fact the cohort cannot evidence. Gates: `TestSynthLookup_*`, `TestLookupDigest_ContentSensitive`, root `TestSynth_ReadsInstanceLookupTables`, `TestSynth_CallbackLookupTableRefused`, `TestSynthStream_HeaderHashFoldsLookups`, `TestSynthFromSchemaCLI_HonoursLookupTablesDirEnv`.
