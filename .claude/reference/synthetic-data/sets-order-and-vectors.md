# Synthetic data — wide set capture, run-continuation and shard archives, vector fields

Slice of `.claude/reference/synthetic-data.md` — load the index first, then only the slice(s) your change touches.

**Wide set columns are captured member-for-member, and the mask read is the whole risk.** A `set_*` value reaches capture through the record reader's WIDE map as a plain `uint64` (narrow rungs) or an `encoding.SetMask` (`set_u128`, `set_u256`). Every synth site resolves it through `setMaskFromWide` (value) or `setMaskFromWideEntry` (value + presence) and NONE type-asserts `.(uint64)`: a failed assertion yields the zero value, which for a set is a plausible **"selected nothing"**, not an error. Such assertions once silently zeroed marginals, collapsed every pair contrast, deleted model candidates listwise (reported as an ordinary `carries no predictors`), and made every fidelity delta exactly 0.0.
- **The presence distinction is not cosmetic**: `setMaskFromWideEntry` reports `ok == false` for a nil map, an absent key (a null set — the decoder deletes the entry) or a non-mask value, which the model fit's listwise deletion needs; marginals and pairs want the empty-mask value form.
- `SpecFromProfile` reads bit-ordered `FieldProfile.Set.Options`, and the writer derives width from `MaxSetEntries()`, so wide sets round-trip member-for-member.
- **A dictionary WIDER than its own rung's mask is reported, not clamped in silence** (`setMaskWidthWarning`, ATTENTION kind `set options beyond the mask width`) — members past the cap would otherwise look like options nobody selects. Never repaired: widening is `pulse widen`'s job.
- Rules address members by NAME, so they are width-agnostic; but `set_expr` assigns a whole selection and there is no bit-count / single-member / mutual-exclusion primitive, so cardinality constraints are UNSTATED, not expressible.
- Gates: `TestProfile_WideSet*`, `TestSpecFromProfile_WideSetRoundTrip`, `TestProfileModels_WideSetPredictorIsAdmitted`, `TestBuildFidelityReport_WideSetFieldCoverage`, `TestBuildModelFidelity_WideSetPredictorRecovers`. Detail: `skills/synth-set-fields.md`, `skills/op-synth-set-bernoulli.md`.

**Run-continuation is a row-ORDER measurement that rides the scan, and shard archives profile as one stream.** `--run-continuation` (`ProfileOptions.RunContinuation`, `internal/synth/profile_continuation.go`) adds `run_continuation`: per field the fraction of adjacent row pairs with identical on-wire bytes (and null bit), plus `overall`, `high_fields` (≥ `RunContinuationHighThreshold`, 0.75) and `advice` (`low:` below 0.5, suggesting an upstream `ORDER BY` of the parent key).
- **The definition is the run-skip decode's own comparison (`internal/encoding/reader_runskip.go`), byte for byte** (a null then a non-null zero is a CHANGE), so `overall` IS that decode's hit rate (`TestJoinShapeContinuation_ProfilePredictsRunSkip`).
- The `rowTap` is **installed only when the flag is set**: the default scan pays nothing and no extra byte is read (`TestRunContinuation_RidesTheExistingScan`). `SpecFromProfile` never reads it (generation does not reproduce order). Not in `pulse inspect`: continuation needs every record and `descriptor/` is header-only.
- **Shard archives:** `ProfileFile` dispatches on the zip magic and profiles every shard in archive order as ONE stream against the canonical `_schema.pulse` schema (`profileSegments`), valid because dictionaries were union-merged at insert. **Only run-continuation treats a shard boundary as a break** (`pairs` = Σ(rows − 1) per shard) because the decode restarts its baseline per shard. An `archive.pulse#shard.pulse` anchor is not resolved by `ProfileFile`. Detail: `skills/synth-profile-capture.md`.

**Vector fields are ONE joint draw, never dim independent scalars.** A `vec_f32` / `vec_f64` field's elements are jointly distributed; per-element drawing or profiling parses and is quietly wrong. **A vector must never reach a SCALAR arm**: the map decoder echoes nothing into `values` for a vector (elements ride the wide map as `[]float64`), so the numeric branch would summarise zeros and a pair or copula would overwrite a `[]float64` with a float.
- **Spec:** `FieldSpec.Vector` (additive `omitempty`; vector-free specs and their `Spec.Hash()` are byte-identical) is REQUIRED on a `vec_*` field and refused elsewhere (`validateVectorField`): `dim` 2..1024, `kind`, `scale_min` + `scale_max` together, `labels`, `nan_rate`, per-element `elements` (an empty distribution INHERITS the field's, params laid over key by key), `correlations` as 1-based `{a, b, rho}`. `FieldSpec.Distribution` is the DEFAULT ELEMENT FAMILY. Element families are those `fieldMoments` + `quantileFor` admit. The kind fills omitted params (`vectorKindDefaults`).
- **The written schema's VECTORS entry IS the spec's** (`vectorFieldFor`), set BEFORE `LayoutFields` — otherwise the field is sized at 0 bytes.
- **Generation (`vectorSampler`, `internal/synth/vector.go`)** reuses the copula WITHIN the field through `factorCorrelations` (the one completion policy: unlisted pairs independent and counted, inconsistent lists ridge-regularized and reported), then per-element Q, clamps, `binary` rounding at 0.5, NaN draw, `composition` closure (simplex exact, per-element marginals approximate) and for `vec_f32` `float64(float32(x))` so constraints read the stored number. **RNG consumption is a function of the spec alone**: exactly `dim` `NormFloat64` per row, then — only if some element has a NaN rate — exactly `dim` `Float64`. A null VECTOR (`null_rate`) is distinct from a NaN ELEMENT (`nan_rate`, a stored value).
- **A vector never takes part in cross-field structure**: correlations, pairs, model targets / predictors naming one are refused (`refuseVectorCrossFieldUse`); `isNumericFieldType` is false; per-field loops reading `Distribution` as a scalar marginal skip it. Rules: `set_null` / `null_together` / `owns_nulls` apply; `set` / `set_expr` onto a vector is a TYPE fault at parse (it would bypass kind bounds and element correlation). In expressions a vector reads as `[]float64`, 0-based.
- **Capture (`vecAcc`, `internal/synth/vector_profile.go`)** rides the scan: `FieldProfile.Vector` is ALWAYS present on a vector field (even all-null — the dim is needed to rebuild), with per-element `NumericProfile` (shared `numericProfileFrom`) and pairwise-complete `correlations[]` (barrier-wrapped products). An element's `discrete` histogram is captured while every value is an integer and ABANDONED on the first non-integer. Unmeasurable pairs are ABSENT; thin / unmeasured pairs get ONE aggregated warning per field.
- **`maxVectorCorrelationDim` (64)** is where capture ABANDONS the correlation (and element reservoirs), never truncates — cost is dim² per row and a partial matrix would present an arbitrary subset as the structure. Above it elements keep marginals, a warning names the field, generation draws elements independent.
- **`SpecFromProfile`** rebuilds vectors AHEAD of every scalar arm (`vectorFieldSpecFromProfile`); the emitted spec round-trips byte-identically.
- **Augment** copies source vectors verbatim (full zeroed stride for a null), carries VECTORS entries (`CloneVectors`, tag appended LAST so indices hold), and refuses a profile dim differing from the source's (`PULSE_SYNTH_PROFILE_SCHEMA_MISMATCH`, `source_dim` / `profile_dim`) rather than re-encoding at the wrong width.
- **Fidelity:** `FidelityReport.VectorFields` compares per-element moments and the correlation matrix using the SAME `vecAcc` code as capture (one definition throughout); above the cap, `correlation_skipped`. No per-element KS — the question is joint structure.
