# Synthetic data — wide set capture, run-continuation and shard archives, vector fields

Per-topic slice of the synthetic-data reference (wide set capture, run-continuation and shard archives, vector fields). Index (preamble + section map): `.claude/reference/synthetic-data.md` — load it first, then only the slice(s) your change touches.

**Wide set columns are captured member-for-member, and the mask read is the whole risk.** A `set_*` field's membership reaches capture through the record reader's WIDE map, in one of TWO shapes: a plain `uint64` for the narrow rungs (`set_u8`..`set_u64`) and an `encoding.SetMask` for the wide ones (`set_u128`, `set_u256`). Every synth site that reads one resolves it through `setMaskFromWide` (value) or `setMaskFromWideEntry` (value + presence), and NONE type-asserts `.(uint64)`: an assertion that fails yields the zero value, which for a set field is a perfectly plausible **"selected nothing"** rather than an error. Nine sites carried that assertion and each failed differently and silently — the per-option marginal (`profileRecords`) captured `frequency: 0.0` for every member of the column; all three conditional pair kinds (set x categorical, set x numeric, set x set) put the entire cohort in the `not_selected` arm, so a captured contrast came back as no contrast; the `--fit-models` row snapshot read `present == false`, which is MISSING and not empty, so every row of the candidate was deleted LISTWISE and the target was reported as `carries no predictors` — a complete and entirely ordinary outcome elsewhere, which is exactly why the loss carried no signal; the dummy design-column reader (`dummyRecord`) and the recovery refit's reader (`recoveryIndicator`) did the same on the generated side, the latter surfacing as `design column is constant over the admitted synthetic rows`, a message that blames the COHORT for the reader's defect; and all four fidelity sections (`set_fields`, `set_categorical_pairwise`, `set_numeric_pairwise`, `set_set_pairwise`) read BOTH partitions as empty, so every delta came back exactly `0.0` and the report certified a generation it never measured. **The presence distinction is not cosmetic**: `setMaskFromWideEntry` reports `ok == false` for a nil map, an absent key (the decoder DELETES the wide entry for a null set field) and any non-mask value, which is what the model fit's listwise deletion needs, while the marginal and the pair arms want the empty-mask value form. `SpecFromProfile` needed no width change — it reads `FieldProfile.Set.Options`, which is bit-ordered and bounded only by `MaxSetEntries()` — so a 206-member `set_u256` round-trips member-for-member once capture is correct, and `internal/synth/writer.go` derives its write width from `MaxSetEntries()` rather than a rung table. **A dictionary WIDER than its own rung's mask is now reported rather than clamped in silence**: members past the cap get no marginal, no pair capture and no fidelity comparison, which is indistinguishable in the document from an option nobody selects, so `setMaskWidthWarning` names the field, the dictionary size and the mask width on `Profile.Warnings` and `warning_summary.go` gives it its own ATTENTION kind (`set options beyond the mask width`). It is stated, never repaired — widening is `pulse widen`'s job, and a profiler that quietly re-typed a column would be making a structural claim about the data. **Structural rules needed no change and one honest limit is worth stating**: a rule addresses a set member by option NAME (the row value is a `map[string]bool`), never by bit, so rules are width-agnostic — but `set_expr` assigns a WHOLE selection and the vocabulary has no bit-count, no single-member edit and no mutual-exclusion primitive, so a cardinality constraint over 206 members is UNSTATED rather than expressible. `format_version` does NOT move. Gates: `TestProfile_WideSetMarginalFrequencies`, `TestProfile_WideSetConditionalPairsMatchNarrowBehaviour`, `TestSpecFromProfile_WideSetRoundTrip`, `TestProfileModels_WideSetPredictorIsAdmitted`, `TestBuildFidelityReport_WideSetFieldCoverage`, `TestBuildPairwise_WideSetOptionsAreMeasured`, `TestBuildModelFidelity_WideSetPredictorRecovers`, `TestProfile_WideSetDictionaryBeyondMaskWidthWarns`. Detail: `skills/synth-set-fields.md` (Set (multi-select) field profiling) + `skills/synth-models.md` (Capture (`--fit-models`)) + `skills/op-synth-set-bernoulli.md`.

**Run-continuation is a row-ORDER measurement that rides the scan, and shard archives profile as one stream.** `pulse profile create --run-continuation` (`synth.ProfileOptions.RunContinuation`) adds the additive, `omitempty` `run_continuation` section (`synth.RunContinuationProfile`, `internal/synth/profile_continuation.go`): per field, the fraction of adjacent row pairs whose on-wire bytes — and, for a nullable field, null bit — are identical, plus `overall` (total repeats over `pairs × fields`), `high_fields` (rate ≥ `RunContinuationHighThreshold`, 0.75) and a one-line `advice` (`low:` below 0.5, the run-skip decode's backoff regime, pointing at an upstream `ORDER BY` of the parent key). **The definition is the run-skip decode's own comparison (`internal/encoding/reader_runskip.go`), byte for byte** — a bit-packed field is its one on-wire byte, and a null followed by a non-null zero is a CHANGE even though the value bytes match — so `overall` is that decode's hit rate, not an estimate; `TestJoinShapeContinuation_ProfilePredictsRunSkip` pins equality against the join-shape fixture's byte-level helper (0.71 sorted / 0.21 scattered). It is fed by a `rowTap` that copies the bytes the existing `RecordReader` pulls — **installed only when the flag is set**, so the default scan pays nothing and the document is byte-identical; with it no extra byte is read (`TestRunContinuation_RidesTheExistingScan`). `SpecFromProfile` never reads the section: it describes the source's ORDER, which generation does not reproduce. It lives in `synth/`, so `format_version` does NOT move. It is deliberately NOT in `pulse inspect`: continuation needs every record and `descriptor/` is header-only. **Shard archives:** `ProfileFile` now dispatches on the zip magic and profiles every shard in archive order as ONE stream decoded against the canonical `_schema.pulse` schema (`profileSegments`) — the shard iterator's own reading, valid because dictionaries were union-merged and remapped at insert — so every section folds across shards. **Only run-continuation treats a shard boundary as a break**: `pairs` is Σ(rows − 1) per shard and `shards` counts the payloads, because the decode restarts its baseline per shard and a cross-shard pair measures nothing it can use (`TestRunContinuation_PairsNeverSpanASegment`, `TestProfile_ShardArchiveRunContinuation`). An `archive.pulse#shard.pulse` anchor is not resolved by `ProfileFile`. Detail: `skills/synth-profile-capture.md` (Profile mode) + `docs/src/cli/profile-create.md`.

**Vector fields are ONE joint draw, never dim independent scalars.** A `vec_f32` / `vec_f64` field's elements are jointly distributed; drawing each from its own marginal, or profiling each as an unrelated numeric, writes a cohort (or a profile) that parses and is quietly wrong. The one thing that must never happen is a vector reaching a SCALAR arm: the map decoder echoes NOTHING into `values` for a vector (its elements ride the wide map as `[]float64`), so the profiler's default numeric branch would summarise a column of zeros, and a pair or the copula would overwrite a `[]float64` row value with a float. Until #450 (landed in U29, before release) every surface refused a vector with `PULSE_SYNTH_VECTOR_UNSUPPORTED`; that code never shipped and is GONE. **Spec:** `FieldSpec.Vector` (`vector`, additive + `omitempty`, so a vector-free spec — and its `Spec.Hash()` — is byte-identical) is REQUIRED on a `vec_*` field and refused on any other (`validateVectorField`, `SERVICE_VALIDATION`): `dim` 2..1024, `kind` (measure / scale / composition / binary), `scale_min` + `scale_max` together, `labels` absent or `dim`, `nan_rate`, `elements` absent or `dim` (each `{distribution, params, nan_rate}` — an empty distribution INHERITS the field's `distribution` with `params` laid over the field's key by key), `correlations` as 1-based `{a, b, rho}` element pairs (the `emb[k]` numbering requests use). `FieldSpec.Distribution` is the DEFAULT ELEMENT FAMILY and may be empty only when every element names its own (a profile-derived spec does exactly that). Element families are the copula's own set — `normal`, `uniform`, `lognormal`, `exponential`, `bernoulli`, `discrete`, `mixture` — because every element is driven through `fieldMoments` + `quantileFor`; anything else is refused at build naming the element. The kind fills a param the author left out (`vectorKindDefaults`): `discrete` with no `values` takes the integers inside the scale range (or `{0, 1}` for `binary`), `uniform` with no `min` / `max` takes the scale range — so `{"distribution": "discrete", "vector": {"dim": 5, "kind": "scale", "scale_min": 1, "scale_max": 7}}` is a complete 1–7 battery. **The written schema's VECTORS entry IS the spec's** (`vectorFieldFor`: dim, kind, scale range, labels), set on the schema BEFORE `LayoutFields`, because a schema without it sizes the field at 0 bytes. **Generation (`vectorSampler`, `internal/synth/vector.go`)** reuses the value-scale copula WITHIN the field: `dim` correlated standard normals through ONE Cholesky (`factorCorrelations` — the package's one completion policy, so an unlisted pair is drawn independent and COUNTED in a warning, and a jointly-inconsistent list is ridge-regularized and REPORTED; both warnings ride `writerField.warnings` onto the generation channel), each element through its own `Q`, then the element's own clamp, the scale-range clamp, `binary` rounding at 0.5, the NaN draw, the `composition` closure (negatives floored at 0, present elements rescaled to sum 1 — which a per-element marginal cannot guarantee, so a composition's per-element marginals are honoured only approximately and the simplex exactly) and, for `vec_f32`, `float64(float32(x))` so a constraint reads the stored number. **RNG consumption is a function of the spec alone**: exactly `dim` `NormFloat64` per row, then — only when some element declares a NaN rate — exactly `dim` `Float64`, one per element whether or not it comes up NaN; the null VECTOR is the ordinary `nullableSampler` wrapper's draw (`null_rate`), distinct from a NaN ELEMENT (`nan_rate`), which is a stored value. A staircase element (`discrete`, `bernoulli`) holds its own marginal exactly and attenuates the realised value-scale correlation — the documented property of every non-normal `Q`. **A vector never takes part in cross-field structure**: a value-scale or residual correlation, any conditional pair, or a model target / predictor naming one is refused at `validateSpec` (`refuseVectorCrossFieldUse`), `isNumericFieldType` answers false for it, and the per-field loops that read `Distribution` as a SCALAR marginal (`buildDiscreteConditionals`, `buildBernoulliConditionals`, the `--fit-shape` pre-claim) skip it, since on a vector it names the element family. Rules: `set_null` / `null_together` / `owns_nulls` apply (they write no value); `set` / `set_expr` onto a vector is a TYPE fault in THE COERCION MATRIX (`PULSE_SYNTH_RULE_VALUE_INVALID`, at parse) — a written vector would bypass its kind's bounds and its element correlation. In `constraints[]` / `when` a vector reads as its `[]float64` (`sentinelFor`), indexed 0-based by expr. **Capture (`vecAcc`, `internal/synth/vector_profile.go`)** rides the single scan: `FieldProfile.Vector` (`VectorProfile`, additive + `omitempty`, ALWAYS present on a vector field — even all-null — because the dim is what lets the field be rebuilt) carries the schema's dim / kind / scale range / labels, `n` (non-null vectors), one `VectorElementProfile{nan_rate, numeric}` per element — `numeric` is the SAME `NumericProfile` a scalar gets, built by the shared `numericProfileFrom` — and `correlations[]` `{a, b, rho, n}`: Pearson over the rows where BOTH elements are present (pairwise-complete, Welford co-moments, products barrier-wrapped per the float-fusion rule). An element's `discrete` histogram is captured while EVERY observed value is an integer (≤ `maxDiscreteLevels`) and ABANDONED on the first non-integer — the type rule (`isIntegerQuantizedFieldType`) cannot apply to a float element, but an integer-valued scale or binary battery has the small-integer defect exactly. An unmeasurable pair (fewer than `minResidualPairObservations` co-present rows, or a constant element) is ABSENT — generation completes and counts it — and thin and unmeasured pairs are each ONE aggregated warning per field, never one line per pair. **`maxVectorCorrelationDim` (64)** is where capture ABANDONS the correlation (and the per-element percentile / shape reservoir), never truncates it: the accumulator is `dim·(dim−1)/2` pair updates per row, a 768-dim embedding would be ~295k a row, and a partial matrix would present an arbitrary subset as the structure. Above it the field keeps its element marginals, a warning names it, and generation draws its elements independent. **`SpecFromProfile`** rebuilds the field AHEAD of every scalar arm (`vectorFieldSpecFromProfile`): each element by the scalar rules (`discrete` from the histogram's counts, `mixture` from a captured shape, else `normal` clamped to the observed range), its captured NaN rate, the measured correlations; an all-null capture rebuilds as a placeholder family under `null_rate` 1. The emitted spec round-trips to a byte-identical cohort (`--emit-spec`). **Augment** copies a source vector verbatim (`decodedFieldValue` → `writeFieldValueDim`, the dim from the schema since a null vector still writes its full zeroed stride), carries the source's VECTORS entries onto the merged schema (`CloneVectors`, the tag appended LAST so indices hold), and refuses a profile-derived dim that differs from the source's (`PULSE_SYNTH_PROFILE_SCHEMA_MISMATCH`, `source_dim` / `profile_dim`) rather than re-encoding at the wrong width. **Fidelity:** `FidelityReport.VectorFields` (`VectorFieldFidelity`, additive + `omitempty`) compares the two partitions per element (mean, std, NaN rate, deltas) and over the correlation matrix (`correlation_pairs`, `mean_correlation_delta`, `max_correlation_delta`, `max_correlation_pair`) with the SAME `vecAcc` / co-moment code capture uses, so the source, the profile and the generated side are measured by one definition; above the dim cap it reports `correlation_skipped`. No TEST_KS per element: the question is the joint structure, which a per-element KS cannot see. `format_version` does NOT move — every type here lives in `synth/`. Gates: `internal/synth/vector_test.go` (`TestSynthVector_FromSchemaHonoursKindBounds`, `TestSynthVector_ElementCorrelationIsInduced`, `TestSynthVector_NullVectorAndNaNElementRates`, `TestSynthVector_F32ElementsAreStoredPrecision`, `TestSynthVector_DeterministicUnderSeed`, `TestProfileVector_CaptureThenRegenerateReproducesStructure`, `TestProfileVector_WideVectorAbandonsCorrelation`, `TestProfileVector_AllNullVectorRegeneratesNull`, `TestSpecVector_EmitSpecRoundTrip`, `TestAugmentVector_TopUpAndFidelity`, `TestAugmentVector_DimMismatchRefused`, `TestSpecVector_Refusals`, `TestRulesVector_SetNullMasksAndSetIsRefused`, `TestConstraintsVector_IndexesTheRowSlice`), the forcing tables (`TestFieldTypePredicates_ClassifyEveryDeclarableType`, `TestSentinelFor_MatchesDrawnRowValueForEveryDeclarableType`, `TestRuleCoercion_MatrixCoversEveryDeclarableTargetType`), `internal/integration/vector_archive_test.go` (`TestVectorSynth_EverySurface`, shard archives included), `internal/cli/synth_vector_test.go` (`TestSynthCLI_VectorFieldEverySurface`). **Cross-row expressions (`row()`, `lag()`) read ACCEPTED-row order, and consume no RNG.** Generation is serial and row-major on one RNG with no shuffle, so a spec's declaration order IS the accepted-row order and "n rows back" is well defined (`internal/synth/row_lag.go`, `row_expr_builtins.go`). Three load-bearing facts, each SILENT if wrong. (1) The ordinal and the history advance on ACCEPTANCE only: a constraint-rejected attempt redraws at the SAME ordinal and never enters the lag buffer, so a rejecting spec still reads `0..row_count-1` and a `lag` never sees a row that was not written; `monotonic_from` counts the same way (a behaviour break from counting attempts). (2) Neither function draws: `row()` is a counter and `lag` a ring-buffer read after the rule pass, so adding one moves no other field's stream, and the rule pass keeps consuming NO RNG (the byte-identical-per-seed contract needs no new draw-order rule). The buffer holds the post-rule row value BEFORE encode rounding, so a `u*` / `f32` field can lag a value that differs from its stored one. (3) Null follows SQL `LAG`: a lagged null is null, never the default; the default fills only rows before `n`. The offset (1..1024) and name are literals, validated at spec parse, which is what lets the buffer be sized once. Profile capture, the fidelity report and `--suggest-rules` are deliberately blind to `lag` (no serial-dependence measurement exists); in augment mode the history starts empty at the first generated row. A panel is the author's job: `row() % P == 0 ? 0 : lag(...)`. Skill: `skills/synth-cross-row.md`; worked spec: `internal/examples/synth/07_mmm_adstock.synth.json`.

**A `datetime` field is drawn in LOCAL time and stored as the UTC instant; the conversion is a stage, not a sampler detail.** `uniform_datetime` (`internal/synth/datetime.go`, #362) draws a local wall-clock reading — a local day by `weekday_weights` × that weekday's days in range (an INTENSITY: over whole weeks the realised weekday shares are the normalised weights, over a partial week they are not), a local hour by `hour_weights`, a uniform second — in exactly FOUR RNG draws per row whatever the weights, so the draw sequence is a function of the spec alone. The reading is converted to its instant by `datetimeStage.resolve`, which runs inside `drawRow` after the model stage and BEFORE the rule pass and consumes no RNG; a field with no zone or a UTC-equivalent one compiles no stage entry (its reading already is the instant), and a spec with no zoned datetime compiles no stage at all — `TestSynthDatetime_SpecWithoutDatetimeIsByteIdentical` pins every shipped example spec's bytes from before the type existed. Three facts are SILENT if got wrong. (1) Representation: before the stage a ZONED field's row value is the LOCAL reading, so any arm writing it (pair, copula, model) is converted too; after it, rules and constraints read and write the UTC instant the file stores (`TestUniformDateTime_RulesReadTheUTCInstant`). A rule rewriting the zone field after the stage does not move the datetime. (2) Per-row zone (`time_zone_field`, a `categorical_*` field of IANA names): a NULL zone cell makes the datetime null, never UTC — so a nullable zone field over a non-nullable datetime is refused at compile (`TestUniformDateTime_NullZoneCellIsNullDatetime`); an unknown name is `PULSE_TIMEZONE_UNKNOWN`, eagerly for a `weighted_categorical` domain and per row otherwise. (3) DST: a skipped or repeated reading follows `dst_policy` with the import's spellings (`temporal.ResolveLocal`): the default `error` stops the run (`PULSE_SYNTH_DST_NONEXISTENT` / `PULSE_SYNTH_DST_AMBIGUOUS`) — the reversible default, since relaxing a refusal later is additive — while `earlier` / `later` resolve and add one terminal warning per field with the gap / overlap counts, committed on ACCEPTED rows only (`TestUniformDateTime_DSTGapEveryPolicy`, `_DSTOverlapEveryPolicy`, `_ResolvedCountsAcceptedRowsOnly`). Zone math is `internal/temporal` only (`TestNoZoneMathOutsideTemporal`); the writer stores `int64(Floor(f+0.5))` and refuses a non-finite value rather than writing a platform-dependent `int64(NaN)`. Skill: `skills/synth-datetime.md`.

**Time effects read a date-family field on ITS clock, and a profiled `datetime` is a marginal, never a number.** `trend(t, slope)`, `season(t, "dow"|"hour"|"month", weights)` and `between(t, a, b)` (`internal/synth/row_time.go`, #363) take a BARE declared `date` / `datetime` field as `t`; `timePatcher` rewrites each call onto an internal `:`-named function carrying the field NAME, so the function reads the field's null bit and its declaration (`rowTimeFields`: kind, fixed zone, zone field, `start`) — `trend` alone also accepts any number (`slope × t`). Unit, weights and bounds are literals settled at parse by `timeCallShape`, called from the shared walker (`rowExprStaticRefusal`, now handed the time declarations), so validateSpec, compileRules / compileConstraints and both `--suggest-rules` detectors refuse or accept identically (`PULSE_SYNTH_RULE_EXPR_INVALID` in a rule, `SERVICE_VALIDATION` in a constraint — no new code). Three facts are SILENT if wrong. (1) The clock: a `datetime` is read in its field's fixed `time_zone`, in the zone the datetime STAGE resolved this row in for a `time_zone_field` (`datetimeStage.rowZoneOf`, so a rule rewriting the zone field before the call moves nothing — `TestRowTime_PerRowZoneIsTheStagesNotARewrite`), else UTC; a `date` is a calendar day. Reading the instant in UTC instead quietly shifts every weekday / hour / window by the zone offset, which is exactly what `TestSynthTimeEffects_RecoveredByAQuery` catches by recovering each effect EXACTLY through `GROUP_DATE` with `tz_field`. (2) `trend` counts fractional days on the local clock from local midnight of the field's `start` (`uniform_date` / `uniform_datetime` only — a field without one is refused rather than silently counted from the epoch); `between`'s date-only upper bound covers its whole day (`temporal.DayEndWall`), an offset-bearing bound is refused (a bound is a reading, not an instant). (3) No RNG and a null `t` returns null (`lag`'s rule), so adding a call moves no drawn value and an unguarded null is a loud row-time fault. Zone math is `internal/temporal` only (`LocalWall`, `ParseWall`, `ElapsedDays`, `LocalParts`). **Capture:** `profileRecords` gives a `datetime` its own accumulator (`datetimeAcc`) and section (`FieldProfile.Datetime`, `synth.DatetimeProfile`: UTC `start` / `end`, `weekdays` Monday first, `hours`) instead of the numeric default branch — which used to put epoch seconds into `pairwise`, `conditional` numeric pairs and `--fit-models` targets (`modelTargetFields` now excludes it), all of which a `uniform_datetime` cannot ride (it has no moments). `SpecFromProfile` rebuilds it as UNZONED `uniform_datetime`: `hour_weights` = the hour counts, `weekday_weights` = each count ÷ that weekday's days in `[start, end]` (the distribution's weight is a per-day INTENSITY; raw counts over-weight the weekdays a partial week repeats — `TestProfileDatetime_WeekdayWeightsArePerDay`). The schema carries no zone, so the capture is UTC and reproduces the instants' UTC weekday / hour marginals; a volume trend across days is NOT captured. A document from before the section keeps its `numeric` summary and still rebuilds as a clamped `normal`; a datetime-free document is byte-identical.
