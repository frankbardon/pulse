# Synthetic data — the disclosure section

Per-topic slice of the synthetic-data reference (the fidelity report's `disclosure` section). Index (preamble + section map): `.claude/reference/synthetic-data.md` — load it first, then only the slice(s) your change touches.

**A twin's closeness to real records is MEASURED, never guaranteed: the disclosure section reads the tagged cohort, its own seeded stream and the instance memory limit.** `FidelityReport.Disclosure` (`internal/synth/disclosure.go`, FR-21 / #368) is written on every report against a source unless `SynthOptions.DisableDisclosure` (`--no-disclosure`) — the one report section that is ON by default, so a pre-E3-S2 report gains the key (migration row). It reports `exact_matches` / `exact_match_rate` over ALL generated rows (a generated row whose stored value equals some source row's on every output column, null equal to null — the key reads the u64 exact word through `CaptureExactU64`, a `decimal128`'s digits, a set's mask words and a vector's element bits, never a lossy float echo: `TestDisclosure_ExactKeyIsFaithfulPerType`) and `dcr_median` / `dcr_p5` (type-7) of each SAMPLED generated row's Gower distance to its closest source row. The Gower term per column is in [0, 1]: range-normalised `|a − b|` for numbers, `decimal128`, `u4`, `date` and `datetime`, the range over the SOURCE rows and clamped at 1 (a zero range scores 0 equal / 1 otherwise; NaN equals only NaN); a 0/1 mismatch for `categorical_*` and `packed_bool` (the merged dictionary gives both partitions one index per label); Jaccard `|A xor B| / |A or B|` for `set_*` (two empty selections 0); the mean of per-element terms for `vec_*`; null 0 when both, 1 when one (`TestDisclosure_GowerTerms`). The distance is the mean over the output columns (`_synthetic` excluded). **The sample is the section's own:** at most `SynthOptions.DisclosureSample` rows (0 → `DefaultDisclosureSample`, 10,000; negative → `SERVICE_VALIDATION`), picked by Floyd's algorithm over a splitmix64 counter stream keyed `drawStreamKey(seed, disclosureSampleDomain)` and sorted, so turning the section on, off or resizing it moves no generated byte (`TestSynth_DisclosureOffLeavesOutputAndReportOtherwiseIdentical`) and tagged and `--synthetic-only` runs write identical sections (`TestSynth_DisclosureSectionIsDeterministicInBothLayouts`). **Bits:** each distance sums its column terms in schema order with adds and divisions only, the quantile's product is barriered `float64(...)`, and `go build -gcflags='github.com/frankbardon/pulse/internal/synth=-d=fmahash=vy' -a ./internal/synth/` reports no contraction; each sampled row's minimum is independent, so `closestDistances` splits rows across `GOMAXPROCS` workers without moving a bit (`TestDisclosure_WorkerCountMovesNoBit`). A partial sum at or past the best is abandoned — every term is non-negative, so it cannot win. **Cost and the limit:** sample × source comparisons; the working set (`DisclosureMemoryEstimate`: every source row's slots + exact-match key + 64 B map entry, every sampled row's slots + 16 B) is charged against `Limits.MaxEstimatedMemory` by `CheckDisclosureBudget`, which the facade runs BEFORE the fidelity-model source refit and generation, reading the source header only; past it the call is `PULSE_LIMIT_EXCEEDED` (`limit: max_estimated_memory`) and nothing is written (`TestSynth_DisclosureOverBudgetRefusesBeforeGeneration`). No new error code. `Synth` has no predict root, so there is no predict side to keep in parity. Measured: a 40,000-row source and a 20,000-row twin (three normals + a two-level categorical) report 0 exact matches, DCR median 0.00313, p5 0.00121, sample 10,000, the whole report under a second. A twin of only low-cardinality columns copies rows by construction (`TestSynth_DisclosureExactCopiesReportMatchesAndZeroDistance`: rate 1, DCR 0) — the measure is honest about it. Gates: `TestDisclosure_*` (`internal/synth`), `TestSynth_Disclosure*` (root), `TestSynthFromProfileCLI_DisclosureFlags`. Skills: `skills/synth-disclosure-report.md` (routed from `synthetic-data`, `synth-fidelity-report`, `session-synth-flags`).
