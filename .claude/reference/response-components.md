## Auxiliary crosstab margin aggregations

Relocated from the `Crosstab *CrosstabComponents` bullet, which it continues verbatim:

Plus, when the request declared `crosstab.margin_aggregations`, the AUXILIARY margin figures: `row_margin_aggregations[r]` / `column_margin_aggregations[c]` / `grand_total_aggregations`, one map per margin slot keyed by each auxiliary's effective label, each entry a `types.MarginAggregationFigure{value, present, components}`. `components` is the floor `{n, n_null}` over the ADMITTED records merged with that operator's own `ComponentSchema` keys, so an `AGG_DISTINCT_SUM` auxiliary's `distinct_count` is reachable PER MARGIN SLOT beside the scalar sum — the whole reason two rendered sample-size rows cost one scan rather than two. They sit BESIDE `row_margin_components` and never inside it: that describes the CELL aggregator's own margin, on a different admission, and merging the key sets would put two differently-based figures under one roof with nothing saying so. **THE ADMISSION RULE IS THE LEAST GUESSABLE PROPERTY ON THIS SURFACE, so it is stated here rather than only where it is implemented: a record contributes to an auxiliary margin ONLY IF IT CONTRIBUTED TO A CELL.** Two exclusions follow and they are the whole difference — a record whose CELL FIELD IS NULL, and a record whose AXIS KEY A GROUPER `Include` EXCLUDED — while the cell's own margins beside it still count both, because they count every filter-passing record routed to that axis slot. That is deliberate, not an inconsistency to reconcile: an auxiliary exists to be a base the cells beside it divide into, so it has to see the same records they did, and a cohort-wide base would silently answer a different question. There is no knob. Getting it wrong is SILENT — every number still renders, correctly formatted and plausible, and only the base is wrong. **`present` is load-bearing and is NOT a zero value** — a slot that admitted no record carries `present: false` and no `value` key at all, because an aggregator over an empty set has no defined output and a fabricated `0` is indistinguishable on the wire from a real one; its `components` still carry the floor, whose `n = 0` is a true statement about the slot. All three keys are `omitempty` and additionally ride the DISPLAY flag (`margins.rows` / `.columns` / `.grand`), matching the emission rule the cell's own margin counts and components already follow, so a margin computed only as a normalize denominator stays off the wire on both arms. **Allocation and emission ask DIFFERENT questions and the gap between them is warned rather than closed**: both execution paths allocate auxiliary accumulators on `NeedsRowMargin` / `NeedsColumnMargin` / `NeedsGrandMargin` (display OR normalize), so the normalize-only shape accumulates every auxiliary and then emits not one of them. `CrosstabSpec.MarginAggregationsObserved` — the predicate behind the `PULSE_CROSSTAB_MARGIN_AGG_UNOBSERVED` predict warning — therefore reads the DISPLAY flags directly, and does NOT go through the `Needs*Margin` trio it was first written on: those answer the cell's question ("is this margin required"), and answering it here left exactly one shape (`margins` all false + `normalize=row|column|total` + a declared auxiliary) both unwarned AND paid for. An auxiliary is never a denominator, so a normalize direction is not a landing site. Keep the predicate and this emission gate stating the one rule; they are two sites, and drift shows up as a request that quietly does the work and returns none of it. A request declaring no auxiliary emits none of the three and is byte-identical to the pre-slot wire form (`TestCrosstab_MarginAggregationsInertAtRequestSurface`, narrowed rather than deleted at E2-S5 to assert exactly that half). `format_version` does NOT move.

## Opt-out and the Compose surface

**Opt-out.** `pulse.Options.DisableComponents bool` (engine-level default) and `types.Request.DisableComponents *bool` (per-request override, `nil` inherits engine). When the effective decision is "disabled", `Response.Components` stays `nil` and the wire form is byte-identical to the pre-Components baseline — `format_version` is NOT bumped. The gate sits at each execution path's emission block, so the MetaAggregator.Components / MetaGrouper.Components construction work is skipped, not built then discarded. CLI surface: `--no-components` on `pulse api process` / `process-chain` / `compose`. ProcessStream's `.Components()` returns `nil` when disabled. Compose: each `ComposedRequest.Requests[i]` carries its own per-request override; engine flag applies across the batch. MCP tools do not surface the knob (matches `DisableDefaults` / `EchoRequest` precedent).

**Compose surface (v1.1).** `ComposedResponse.Responses[i].Components` carries the per-slot block exactly as it does for a buffered `Process` call — the Compose-overlay fold treats per-slot Components as read-only. Diagnostics from the Compose-host overlay fold (cohesion failures, missing host coordinates, panel-target overflow) ride a sibling per-layer slot `ComposedResponse.Overlays[i].Warnings []OverlayWarning`; the slot is `omitempty` so overlay-free Compose responses stay byte-identical to the v1.0 wire shape (`TestComposedResponse_OverlayFreeByteIdentical`). The same per-layer `Warnings` slot is shared with the CHAIN-host barrier. See `skills/overlay-system.md` (Per-layer warnings).

## Implementation notes displaced from the skill pack

Moved out of the skills at the U10 progressive-disclosure rewrite; contributor-facing, not LLM-facing.

- **Floor ownership.** The orchestrator fills the universal floor, never the operator's `Components()`; it is filled even when `ComponentSchema.Keys` is empty (`AGG_COUNT` is the canonical floor-only aggregator). The floor is tallied through `processing.FieldPresent`, never `Record.NumericValue` — a set column has no numeric value, and asking the value question would move a whole set column into `n_null`. `FiltererComponents` has no `Operator` slot today; `MetaFilterer` exists for extension parity.
- **Opt-out gate sites.** The gate sits at each execution path's emission block (`processStreaming` / `processStreamingGrouped` / `processStreamingTwoPass` / `processRecords` exits, `RunCrosstab`, `FusedCrosstabState.Finalize`), so `MetaAggregator.Components` / `MetaGrouper.Components` construction is skipped, not built then discarded. Parallel-buffered and per-shard reducers gate via the `disableComponents` parameter threaded through `finalizeMergedPartial` (into `processing.FinalizeGroupedStream` on the grouped arm). The Compose-host overlay fold treats per-slot Components read-only, so dropping a slot's block never interacts with `Overlays[i].Warnings`. The full trigger row is in `update-demand.md`.
- **Parallel arms.** No per-operator components merge exists: the arms fold OPERATOR STATE (`MergeableAggregator.MergeOnline`, `processing.MergeableGrouper`, an extension grouper's `extend.MergeableGrouper.MergeState`), so each merged slot's `Components()` is the serial one's, and `processing.CanMergeRequest` already refused anything whose state cannot fold. Grouped parallel runs share the serial tail (`processing.FinalizeGroupedStream`), so row order, `Sort`, overlays and `Groupers` cannot drift by worker count (`TestShardWorkers_ComponentsParity_GroupedAndFlatArchives`). Long form: `execution-modes.md`.
- **Buffered auxiliary admission.** The buffered arm narrows each margin slot's routed bucket to the admitted set and aggregates once, where `admitted = resolved on the OTHER axis AND cell field non-null`, resolved from the two axis partitions ONCE and deliberately NOT from the `(rkey, ckey)` cell buckets — those count a record once per (row, column) pair, which would multiply a row auxiliary by the fan factor under a fan-out (`GROUP_SET_PER_ELEMENT`) axis. The fused arm folds each admitted record into `rowMarginAux` / `colMarginAux` / `grandMarginAux` during the walk.
- **Manifest duplication.** Each `ComponentSchema` appears twice by design — inside the per-operator manifest entry (self-contained drilldown) and in top-level `components_schemas` (one O(N) scan) — declared in `internal/descriptor/capabilities_{aggregators,groupers,filterers}.go`.
- **Emission benchmarks.** `docs/src/ops/performance.md` (Components emission baselines). Runnable examples: `internal/examples/aggregations/08_welford_components.json`, `internal/examples/crosstab/16_welford_components_revenue_by_region_treatment.json` (tag `welford-triple`).
