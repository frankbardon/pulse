## Auxiliary crosstab margin aggregations

Relocated from the `Crosstab *CrosstabComponents` bullet, which it continues verbatim:

Plus, when the request declared `crosstab.margin_aggregations`, the AUXILIARY margin figures: `row_margin_aggregations[r]` / `column_margin_aggregations[c]` / `grand_total_aggregations`, one map per margin slot keyed by each auxiliary's effective label, each entry a `types.MarginAggregationFigure{value, present, components}`. `components` is the floor `{n, n_null}` over the ADMITTED records merged with that operator's own `ComponentSchema` keys, so an `AGG_DISTINCT_SUM` auxiliary's `distinct_count` is reachable PER MARGIN SLOT beside the scalar sum — the whole reason two rendered sample-size rows cost one scan rather than two. They sit BESIDE `row_margin_components` and never inside it: that describes the CELL aggregator's own margin, on a different admission, and merging the key sets would put two differently-based figures under one roof with nothing saying so. **THE ADMISSION RULE IS THE LEAST GUESSABLE PROPERTY ON THIS SURFACE, so it is stated here rather than only where it is implemented: a record contributes to an auxiliary margin ONLY IF IT CONTRIBUTED TO A CELL.** Two exclusions follow and they are the whole difference — a record whose CELL FIELD IS NULL, and a record whose AXIS KEY A GROUPER `Include` EXCLUDED — while the cell's own margins beside it still count both, because they count every filter-passing record routed to that axis slot. That is deliberate, not an inconsistency to reconcile: an auxiliary exists to be a base the cells beside it divide into, so it has to see the same records they did, and a cohort-wide base would silently answer a different question. There is no knob. Getting it wrong is SILENT — every number still renders, correctly formatted and plausible, and only the base is wrong. **`present` is load-bearing and is NOT a zero value** — a slot that admitted no record carries `present: false` and no `value` key at all, because an aggregator over an empty set has no defined output and a fabricated `0` is indistinguishable on the wire from a real one; its `components` still carry the floor, whose `n = 0` is a true statement about the slot. All three keys are `omitempty` and additionally ride the DISPLAY flag (`margins.rows` / `.columns` / `.grand`), matching the emission rule the cell's own margin counts and components already follow, so a margin computed only as a normalize denominator stays off the wire on both arms. **Allocation and emission ask DIFFERENT questions and the gap between them is warned rather than closed**: both execution paths allocate auxiliary accumulators on `NeedsRowMargin` / `NeedsColumnMargin` / `NeedsGrandMargin` (display OR normalize), so the normalize-only shape accumulates every auxiliary and then emits not one of them. `CrosstabSpec.MarginAggregationsObserved` — the predicate behind the `PULSE_CROSSTAB_MARGIN_AGG_UNOBSERVED` predict warning — therefore reads the DISPLAY flags directly, and does NOT go through the `Needs*Margin` trio it was first written on: those answer the cell's question ("is this margin required"), and answering it here left exactly one shape (`margins` all false + `normalize=row|column|total` + a declared auxiliary) both unwarned AND paid for. An auxiliary is never a denominator, so a normalize direction is not a landing site. Allocation ALSO rides the compute plan: when `components.crosstab` or its `*_margin_aggregations` figures are not computed (a `return` exclusion or the closed DisableComponents gate) neither arm accumulates a single auxiliary — the unknown-operator refusal alone stays ungated (the Compute plan paragraph under "Opt-out and the Compose surface"). Keep the predicate and this emission gate stating the one rule; they are two sites, and drift shows up as a request that quietly does the work and returns none of it. A request declaring no auxiliary emits none of the three and is byte-identical to the pre-slot wire form (`TestCrosstab_MarginAggregationsInertAtRequestSurface`, narrowed rather than deleted at E2-S5 to assert exactly that half). `format_version` does NOT move.

## Opt-out and the Compose surface

**Opt-out.** `pulse.Options.DisableComponents bool` (engine-level default) and `types.Request.DisableComponents *bool` (per-request override, `nil` inherits engine). When the effective decision is "disabled", `Response.Components` stays `nil` and the wire form is byte-identical to the pre-Components baseline — `format_version` is NOT bumped. The gate sits at each execution path's emission block, so the MetaAggregator.Components / MetaGrouper.Components construction work is skipped, not built then discarded. CLI surface: `--no-components` on `pulse api process` / `process-chain` / `compose`. ProcessStream's `.Components()` returns `nil` when disabled. Compose: each `ComposedRequest.Requests[i]` carries its own per-request override; engine flag applies across the batch. MCP tools do not surface the knob (matches `DisableDefaults` / `EchoRequest` precedent). **`return` interplay (U17):** an engine `DisableComponents` sticks — a request `return` block NEVER re-opens the compute gate; only the request's own explicit `disable_components: false` does (the pre-U17 rule); whenever the gate is closed and some `return` layer exists, the effective selection also excludes `components`. With no `return` on any layer the opt-out is the compute gate alone — byte-identical, no `returned` marker. Rule: `descx.EffectiveDisableComponents` / `EffectiveReturn`; contract in `update-demand.md` (the `Request.Return` row).

**Compute plan (U18).** The single opt-out bool is superseded by `processing.ComputePlan` — per-sub-part flags `Aggs` (`components.aggregations`), `Groups` (`…[*].groups`, implies `Aggs`), `Groupers`, `Filterers`, `Run`, `Crosstab`, `AuxMargins` (the `*_margin_aggregations` figures), `Matrices`, plus whole-slot `MatricesSlot` (with its finalize-only sub-parts `MatrixAuxiliary` / `MatrixScalars` / `MatrixVectors`) and `Overlays` / `Tests` / `PostTests` (per entry, below) / `Regressions` (whole slot, below). `Service.process` resolves it ONCE before dispatch (`Service.resolveComputePlan`): `processing.ComputePlanFor(plan)` computes a part iff the `return` plan's `Visit` keeps it or something below it; the VETO is precise: a kept request overlay whose kind reads its host's components (`descx.OverlayReadsHostComponents` — the `OVERLAY_PAIRWISE_*` family, every `weighting.ScalesByHostFloor` kind, `OVERLAY_FISHER_EXACT_CELL`; the refusal half is predict's `validateOverlayHiddenFloor`) keeps `components.crosstab` only — the one sub-part any overlay reads; its `*_margin_aggregations` figures still follow the selection, decided on the fused arm by `FusedCrosstabState.setCompute` alone — and a Compose slot a Compose overlay names (reference or target; `composeSlotVetoes`, set per slot by `Service.compose` / `composeParallel` through `withComponentsVeto`) keeps every Components sub-part (the Compose host classifies a slot by its Components block); an unnamed slot skips what its selection drops. A chain overlay reads its stages' data and crosstab payload only, so it vetoes nothing; every later chain stage runs under its OWN plan (`processChain` resolves each stage's `return` and puts `resolveComputePlan` on the `runChainStage` context); a stage's `data` has no skip. The closed DisableComponents gate then drops every sub-part, veto or not. The facade still prunes a vetoed-but-excluded part at serialization (`TestReturnKeptNumberInvariant`: full vs shaped, kept paths byte-identical; `TestReturnSkipsComputation_Compose` / `_Chain` / `_CrosstabOverlayVeto`). The plan rides the dispatch context to every seam — `newProcessor` (`Processor.SetComputePlan`; serial streaming / two-pass / buffered, join, crosstab buffered and fused via `FusedCrosstabState.compute`, chain stages), `reduceParallelBuffered` and the shard reducer (`finalizeMergedPartial(…, compute, …)`, the per-bucket floors via `processing.NewGroupFloors`), and `GroupedTail.Compute`; a caller that bypassed `process` with no plan on its context gets the request's vetoes and the gate over a full selection. Arm choice (merge gate, `canStream`, crosstab fusion) reads the ORIGINAL request, so a selection never moves a request onto another arm. A skipped sub-part is never built, so it is absent from the Go response too; a kept one is byte-identical to the `return`-absent run's (the buffered ungrouped `Run.NullRecords` recounts the first slot's `FieldPresent` floor when `Aggs` is skipped). Build points bump the process-wide `processing.WorkStats()` counters (once per slot / bucket / block, never per record), which `TestReturnSkipsComputation` reads as deltas across serial, parallel-decode and shard arms. **Crosstab:** `Crosstab` off builds no `buildCellComponentMap` (cells, row / column / grand margins — `CrosstabCellComponentMaps`) on the buffered, fused and join arms, which also closes the pre-U18 leak where a closed DisableComponents gate still built them; `AuxMargins` off evaluates no auxiliary figure (buffered `computeAuxMargins` returns nil; fused `FusedCrosstabState.setCompute` forgets the auxiliaries before `Update`, so nothing accumulates per record — `AuxMarginAccumulators`). The auxiliaries' REGISTRY resolution stays ahead of both gates, so an unknown type is refused whatever the plan (`TestReturnSkipsComputation_Crosstab`, `TestReturnSkipsComputation_CrosstabUnknownAuxStillRefused`). **Matrices:** the slot follows the selection with NO veto (refused under joins and crosstab, outside the multiplicity pool, read by no Compose / chain overlay). A run ACCUMULATES `Request.Matrices` iff it computes `MatricesSlot` or `Matrices` (`ComputePlan.AccumulatesMatrices`, checked in `resolveMatrixPlans`, so `buildMatrixSlots` / `BuildMatrixSlots` / `BuildGroupedMatrices` mint no slot and no record is folded — `MatrixAccumulators`); each slot carries the plan, and `matrixSlot.result` renders the `MatrixResult` only under `MatricesSlot` (`MatrixResultBuilds`; `components.matrices` alone folds but renders none), `auxiliary.n` / `scalars.determinant` / `vectors.top_pairs` only under their own flag (`MatrixAuxiliaryBuilds` / `MatrixScalarBuilds` / `MatrixVectorBuilds`) — `standard` drops `auxiliary`, `minimal` also `scalars` and `vectors`. The parallel-decode and shard partials build under the same plan (`shardPartial.buildMatrices(…, compute)`). The `Request.Vectors` unreferenced warnings are request-derived and always raised (`TestReturnSkipsComputation_Matrices`). **Overlays (E3-S1):** the slot follows the selection PER LAYER — `ComputePlan.WithOverlayLayers(keep)` / `ComputesOverlay(i)` (the mask rides by pointer, so the plan stays comparable; none marked = slot off, all marked = no mask). An excluded slot still folds every layer a resolved multiplicity family claims (`multiplicityVetoes` over `MultiplicityPlan.Overlays[i].Member` — the request's plan, or a Compose slot's share of its batch's, carried by `composeSlotContext`), so `m` and every kept `p_adjusted` are the full run's; nothing else reads a request layer (Compose / chain overlays read data, crosstab payload and Components). A skipped layer runs no handler and raises no refusal or warning — the slab-partition gate and the `PULSE_OVERLAY_COMPONENTS_REQUIRED` / weight refusals included (FR-25: predict stays the validator) — and stops vetoing `components.crosstab`; when another layer is computed its position holds a zero `OverlayLayer` (the fold aligns by index; the wire prunes the excluded slot). `payload` + `summary` are one compute unit, never split. The Compose-host overlays follow the Compose-level `return` WHOLE (`composeOverlaysComputed`: kept, or any `compose`-plan overlay a member — a spec may emit several layers, so no per-spec mask); skipped, they fold nothing and `composeSlotVetoes` vetoes no slot. Chain overlays have no `return`. Arm choice (`canStream`'s overlay coupling, fusion) still reads the original request. Counter `OverlayLayerRuns` (one per spec through a request-host or Compose-host loop): `TestReturnSkipsComputation_Overlays`, `TestReturnSkipsOverlays_{SeriesArmUnchanged,MultiplicityVeto,ErrorRule,Compose}`, `TestReturnKeptNumberInvariant`. **Tests, post-tests, regressions (E3-S2):** `tests` / `post_tests` follow the selection PER ENTRY with the overlay rules — `ComputePlan.WithTestEntries` / `WithPostTestEntries` + `ComputesTest(i)` / `ComputesPostTest(i)` (shared `narrowSlot` mask), the multiplicity veto over `MultiplicityPlan.Tests` / `.PostTests` (request plan or Compose slot share) — gated inside `buildRowTests` / `buildPostTests`; a skipped position holds nil when another entry is computed (`realignTestResults`, so the fold's index alignment holds). `regressions` follow the selection WHOLE with no veto (outside the multiplicity pool, read by no Compose / chain overlay): `BuildStreamingWith` / `FitBufferedWith` are not called. A skipped entry or fit raises nothing — `PULSE_TEST_*`, `PROCESSING_REGRESSION_*` fit refusals, `PULSE_WEIGHT_LOW_NEFF` included (FR-25). The merge gate (`mergegate`), `canStream` and the chain mergeability refusal (`PULSE_CHAIN_NOT_MERGEABLE`) still read the ORIGINAL request, so excluding a test never moves a request onto the parallel / shard arm or admits it to a chain. Counters `RowTestFolds` / `PostTestRuns` / `RegressionFits`: `TestReturnSkipsComputation_TestsAndRegressions`, `TestReturnSkipsTests_{MultiplicityVeto,ErrorRule,MergeGateArmUnchanged}`, `TestResolveComputePlan_TestEntries`, `TestComputePlan_TestEntries`.

**Compose surface (v1.1).** `ComposedResponse.Responses[i].Components` carries the per-slot block exactly as it does for a buffered `Process` call — the Compose-overlay fold treats per-slot Components as read-only. Diagnostics from the Compose-host overlay fold (cohesion failures, missing host coordinates, panel-target overflow) ride a sibling per-layer slot `ComposedResponse.Overlays[i].Warnings []OverlayWarning`; the slot is `omitempty` so overlay-free Compose responses stay byte-identical to the v1.0 wire shape (`TestComposedResponse_OverlayFreeByteIdentical`). The same per-layer `Warnings` slot is shared with the CHAIN-host barrier. See `skills/overlay-system.md` (Per-layer warnings). Each slot's `return` (and its components compute gate, `EffectiveDisableComponents`) applies per slot exactly as in `Process`; the fold always reads the slot's components BEFORE any pruning, so excluding `components` through a slot's `return` alone never starves a Compose-host overlay.

**Compose envelope (relocated from CLAUDE.md "Output Format Contract" at U18 E1-S1).** Since the v1.1 lift (`format_version` bumped from `"1.0"` for it), `pulse api compose --json` puts a `ComposedResponse` OBJECT in `data` — not the legacy `[]*Response` array — carrying `responses` (one `Response` per `ComposedRequest.Requests` slot, in input order) and `overlays` (one `OverlayLayer` per `ComposedRequest.Overlays` spec, omitted when there are none). Each slot's `return` shapes `responses[i]`; `ComposedRequest.Return` (`overlays…` paths only) shapes the layers AFTER the fold and stamps `returned`. Streaming (`--stream`) bypasses the envelope entirely and emits per-row `{"index", "row"}` NDJSON, so Compose overlays surface only at terminal flush in non-streaming mode (`skills/streaming-and-watching.md` (Compose streaming vs. overlays)). Change rows: `update-demand.md` (the `ComposedResponse` row and the `Request.Return` row's Compose / Chain clause).

## Implementation notes displaced from the skill pack

Moved out of the skills at the U10 progressive-disclosure rewrite; contributor-facing, not LLM-facing.

- **Floor ownership.** The orchestrator fills the universal floor, never the operator's `Components()`; it is filled even when `ComponentSchema.Keys` is empty (`AGG_COUNT` is the canonical floor-only aggregator). The floor is tallied through `processing.FieldPresent`, never `Record.NumericValue` — a set column has no numeric value, and asking the value question would move a whole set column into `n_null`. `FiltererComponents` has no `Operator` slot today; `MetaFilterer` exists for extension parity.
- **Weighted floor.** A slot with an APPLIED row weight adds three typed, optional floor fields — `AggregationComponents.SumWeights` (`sum_weights`, Σw over the value-present rows whose weight is valid), `NEff` (`n_eff`, Kish (Σw)²/Σw², `kind: probability` only) and `NWeightInvalid` (`n_weight_invalid`, value-present rows excluded for an invalid weight) — tallied by the orchestrator (`processing.WeightFloor`) on the same filter-passing rows as `{n, n_null}` and merged slot-wise by both parallel reducers. Absent ⇒ the slot is unweighted (opted out, skipped, or no weight); `n` / `n_null` keep value-presence meaning. Declared in the manifest as `optional: true` keys on weight-aware aggregators only (`withWeightAware`, `internal/descriptor/capabilities_weight.go`). Since weighting E3-S1 the crosstab's flat maps carry them too — `CellComponents[r][c]`, the row / column / grand margin components and each auxiliary `margin_aggregations` figure's `components` — tallied over the same records as that map's `{n, n_null}` (an auxiliary over its ADMITTED records: a record reaches an auxiliary margin only if it reached a CELL) and keyed off that slot's OWN resolved weight, so a `weight: null` auxiliary (the unweighted base) carries none; an operator's own same-named key wins (`AGG_WEIGHTED_MEAN`). `CellCounts` and every margin count stay raw ints. Contract: `.claude/reference/weighting.md` (Floor keys).
- **Opt-out gate sites.** One gate per Components sub-part (the `ComputePlan` flag) sits at each execution path's emission block (`processStreaming` / `processStreamingGrouped` / `processStreamingTwoPass` / `processRecords` exits, `RunCrosstab`, `FusedCrosstabState.Finalize`), so `MetaAggregator.Components` / `MetaGrouper.Components` construction is skipped, not built then discarded. Parallel-buffered and per-shard reducers gate via the `compute` plan threaded through `finalizeMergedPartial` (into `processing.FinalizeGroupedStream` via `GroupedTail.Compute` on the grouped arm). The Compose-host overlay fold treats per-slot Components read-only, so dropping a slot's block never interacts with `Overlays[i].Warnings`. The full trigger row is in `update-demand.md`.
- **Parallel arms.** No per-operator components merge exists: the arms fold OPERATOR STATE (`MergeableAggregator.MergeOnline`, `processing.MergeableGrouper`, an extension grouper's `extend.MergeableGrouper.MergeState`), so each merged slot's `Components()` is the serial one's, and `processing.CanMergeRequest` already refused anything whose state cannot fold. Grouped parallel runs share the serial tail (`processing.FinalizeGroupedStream`), so row order, `Sort`, overlays and `Groupers` cannot drift by worker count (`TestShardWorkers_ComponentsParity_GroupedAndFlatArchives`). Long form: `execution-modes.md`.
- **Buffered auxiliary admission.** The buffered arm narrows each margin slot's routed bucket to the admitted set and aggregates once, where `admitted = resolved on the OTHER axis AND cell field non-null`, resolved from the two axis partitions ONCE and deliberately NOT from the `(rkey, ckey)` cell buckets — those count a record once per (row, column) pair, which would multiply a row auxiliary by the fan factor under a fan-out (`GROUP_SET_PER_ELEMENT`) axis. The fused arm folds each admitted record into `rowMarginAux` / `colMarginAux` / `grandMarginAux` during the walk.
- **Manifest duplication.** Each `ComponentSchema` appears twice by design — inside the per-operator manifest entry (self-contained drilldown) and in top-level `components_schemas` (one O(N) scan) — declared in `internal/descriptor/capabilities_{aggregators,groupers,filterers}.go`.
- **Displaced from `skills/response-components.md` (budget).** The effective opt-out is `effective = req.DisableComponents != nil ? *req.DisableComponents : opts.DisableComponents` (`descx.EffectiveDisableComponents`; a request `return` never re-opens it). A `ComponentSchema` key's `type` is one of `"int"`, `"float64"`, `"WelfordTriple"`, `"map[string]int"`, …. Read a mergeability class off the manifest — never infer it from the operator's name. Reading the block from Go: `for _, a := range resp.Components.Aggregations { mean, _ := a.Operator["mean"].(float64); … }`, and on a grouped run `for _, g := range a.Groups { g.GroupKey, g.N, g.Operator["mean"] }`.
- **Emission benchmarks.** `docs/src/ops/performance.md` (Components emission baselines). Runnable examples: `internal/examples/aggregations/08_welford_components.json`, `internal/examples/crosstab/16_welford_components_revenue_by_region_treatment.json` (tag `welford-triple`).

## Undefined figures on the wire

**One rule for every JSON payload: a non-finite float (NaN, +Inf, -Inf) is written as JSON `null` IN PLACE — the key keeps its presence — and the rest of the response serialises normally.** Before this rule `encoding/json` refused the whole value (`json: unsupported value: NaN`), so no valid output existed for any response carrying an undefined figure.

- **Go keeps NaN.** The engine's library results are unchanged: `AGG_RATIO` over an all-zero denominator (unweighted, or a cell whose rows all carry weight 0), `AGG_CI_LOWER` / `AGG_CI_UPPER` under two rows, `AGG_WELFORD` over a group with no value, `OVERLAY_INDEX_VS_PRIOR`'s first entry or a zero prior, `OVERLAY_INDEX_VS_ROLLING_MEAN` before the window fills; and, found by the U11 audit (`grep math.NaN` over `internal/processing`), every overlay that substitutes NaN for a zero / missing reference (`INDEX_VS_MARGIN`, `INDEX_VS_STAGE`, `INDEX_VS_SIBLING`, `INDEX_VS_BASELINE`, `INDEX_VS_TOTAL`, `YOY`, the `DELTA_*` / `Z_*` / `ZSCORE_*` kinds), the degenerate `CHISQ_ROW` / `CHISQ_COL` rows (NaN statistic and p-value), undefined `TEST_*` statistics / effect sizes and regression fit statistics, and a stored NaN / ±Inf `f32` / `f64` cohort value echoed by a Lookup / Sample row or a min / max. An embedder detects them with `math.IsNaN`. Every one reaches JSON only through the surfaces below, which is why the fix is structural rather than per producer.
- **Null, not omission.** `null` means "reported, undefined at this coordinate"; an absent `omitempty` key keeps meaning "not reported for this kind" (a descriptive overlay's `statistic`, an absent host point's `statistic`). The two never collapse, so a NaN in a `*float64` / `omitempty` slot is `"statistic": null`, a NaN `MatrixCell.Value` is `{"value": null, "present": true}`, and a NaN in a components map is `"ratio": null`.
- **Structural, at the serialisation boundary.** `types.MarshalFinite` is the single implementation — `json.Marshal` with non-finite floats rerouted; byte-identical to `json.Marshal` when the value holds none (a check pass decides; only a subtree holding a non-finite float takes the slow walk, which keeps encoding/json's field order, tag options, embedding, map-key order and marshaller-receiver rules). It is wired at: `descriptor.Envelope.MarshalJSON` (every `--json` leaf, every MCP tool that returns an envelope), the CLI's `writeJSON` and the `--stream` NDJSON rows of `api process` / `api compose`, `mcp/gosdk`'s `jsonResult`, and a `MarshalJSON` method on each result type that carries a float or an open slot — `Response`, `ComposedResponse`, `ChainResponse`, `FacetResult`, `FacetField`, `OverlayLayer`, `OverlayPayload`, `OverlaySummary`, `CrosstabResult`, `MatrixPayload`, `ResponseComponents`, `AggregationComponents`, `GrouperComponents`, `CrosstabComponents`, `TestResult`, `RegressionResult` — so an embedder's own `json.Marshal` of a result (or of one layer) follows the same rule. No per-operator patch: a future operator that emits NaN for an undefined figure cannot fail the response.
- **`format_version` stays `"1.1"`.** Output that was valid before is byte-identical; the only outputs that change are ones that previously failed to serialise at all. The payload JSON Schema widens every float slot on a result-only def (`TestResult`, `RegressionResult`, `OverlaySummary`, `OverlayPayload.scalar`, `FacetNumeric`, `FacetHistogram`, `AggregationComponents.sum_weights` / `n_eff`) to `["number", "null"]` — additive, since every previously valid document still validates; request floats stay `number` (`internal/descriptor/schema.go` `resultOnlyStructs`; `docs/src/contract/payload-schema.md`, "Undefined figures").
- **Gates.** `types` `TestMarshalFinite_*` (fast path = `json.Marshal`; slow path = `json.Marshal` with the non-finite spots nulled; every result type); `descriptor` `TestEnvelope_UndefinedFigureIsNull`; `internal/descriptor` `TestPayloadSchema_UndefinedFiguresValidate` (the nulled wire form validates; a request float still refuses null); `internal/service` `TestNonFiniteFiguresMarshalAsNull` (each producer above through the real envelope, buffered + streaming + both crosstab arms + series overlays + streamed rows) and `TestNonFiniteSweepMarshals` (every weight-aware aggregator, weighted and not, over degenerate groups); `internal/cli` `TestAPI_UndefinedFiguresAreNullOnTheWire`; `mcp/gosdk` `TestJSONResult_UndefinedFigureIsNull`. `TestWeightCrosstabFusedMatchesBuffered` runs `AGG_RATIO` × frequency on every variant and the weighted overlay gates compare layers on the JSON form.

**Under `Return.precision`.** Component figures follow the same wire-only rule as every float: a float64 in an operator map (`components.aggregations[*].operator`, crosstab cell / margin component maps), `sum_weights` and `n_eff` is written at the requested significant digits; the floor counts (`n`, `n_null`, `n_weight_invalid`, the crosstab `*_counts`) and every operator key declared `int` are Go ints and never rounded. An auxiliary margin figure from a COUNT aggregation (`countSemanticAggregations` in `internal/descriptor/return_precision.go`) is written exact via the plan's request-derived `Exact` paths. Contract: `docs/src/contract/payload-schema.md` (Return slot).

## Matrix components

`ResponseComponents.Matrices []types.MatrixComponents` (`matrices`, additive `omitempty`; `format_version` stays `"1.1"`) carries one entry per `Response.Matrices` result, in the same order, keyed back by `name` + `type` (and `group_key` on a grouped result — one entry per per-bucket result, spec-major then bucket; ungrouped runs omit it). Built in `internal/processing/matrix.go` (`matrixSlot.components`) off the slot's MERGED co-moment state and its two integer tallies, so it is as worker-invariant as the matrix: serial, every `DecodeWorkers` and every `ShardWorkers` count report the same entry (`TestMatrixCovariance_WorkerInvariant` compares it; `TestMatrixComponents_ShardWorkerInvariant` covers the all-null tally).

- **Floor, every entry.** `n` = `CoMoment.N()` — rows the mode counted: listwise the complete rows, pairwise the rows with at least one member present. A row of weight 0 COUNTS (it adds no mass); a row with an invalid weight does not (it is `n_weight_invalid`). `n_null` = filter-passing rows skipped for missing members — listwise any member null (equal to `n_listwise_dropped`), pairwise every member null (the rows pairwise admits nowhere; `matrixSlot.allNull`, summed at `MatrixSlots.Merge` like `dropped`). `n_listwise_dropped` = the listwise drop count (0 under pairwise) — the same integer `PULSE_MATRIX_LISTWISE_HEAVY_DROP` reads.
- **Pairwise.** `min_pair_n` / `max_pair_n` — the extremes of `auxiliary.n` over the upper triangle, diagonal included. Absent under listwise.
- **Weighted.** `sum_weights` (`CoMoment.W()`), `n_weight_invalid` (`CoMoment.NWeightInvalid()`) when a row weight is APPLIED to the slot; `n_eff` (`CoMoment.NEff()`, Kish) only under kind `probability`. Absent ⇒ unweighted.
- **Operator map.** `MAT_COVARIANCE` `{ddof}`; `MAT_CORRELATION` none (key omitted).
- **Declaration.** `descriptor.MatrixMeta.ComponentSchema` (`internal/descriptor/capabilities_matrix.go` `matrixSchema`: the floor keys, the optional pairwise keys, then — spliced by `withMatrixWeightKeys` only on an instance offering `capability:weighting` — the optional weighted keys, then the operator's own), mirrored at `components_schemas.matrices`; `Mergeable`. Unlike the aggregator family the matrix floor IS listed, because it is not the universal `{n, n_null}`. Gates: `TestManifestMatrixComponentSchemasComplete`, `TestManifestMatrixComponentSchemas_WeightingHidden`, `TestSkillsCoverAllOperatorComponents` (`matrices` subtest over `op-mat-*`).
- **Opt-out and streaming.** Built only when components are on (`finalizeMatrixSlots(slots, withComponents)` / `MatrixSlots.Finalize`), attached inside each emission block's gate (`processStreaming`, `processRecords`, `finalizeMergedPartial`); disabled ⇒ no entry, wire form otherwise byte-identical (`TestMatrixComponents_OptOut`). Streamed, the entry rides the terminal flush with the matrix; `stream.go` `chunkComponents` carries the block on every shell clone (`TestChunkComponents_CarriesEveryBlock` checks every `ResponseComponents` field by reflection).
- **Profiles.** `ResponseComponents.matrices` is a `gatedSlots` entry on `capability:matrices`: an instance without it has no `matrices` key or `MatrixComponents` def in its payload schema (`TestPayloadSchema_MatricesHidden`).

## Per-group aggregation components

`AggregationComponents.Groups []types.AggregationGroupComponents` (`groups`, additive `omitempty`; `format_version` stays `"1.1"`) carries a grouped run's per-bucket aggregator figures. Wire option (a) of the U17 design: the slot keeps its identity (`label`) and the ungrouped floor shape is untouched — an ungrouped response has no `groups` key and is byte-identical to before.

- **Scope.** Grouped NON-crosstab runs (`Request.Groups`). A crosstab's per-cell figures already live in `Components.Crosstab` (`CellComponents`), so a crosstab response is byte-identical to before. Every grouped arm emits it, identically: the buffered arm (`Processor.processGrouped` → `processRecords`), the streaming-grouped arm at TERMINAL flush (`processStreamingGrouped` → `FinalizeGroupedStream`), and the shard / parallel-decode reducers (`finalizeMergedPartial` → the same tail). Serial ≡ any `DecodeWorkers` ≡ any `ShardWorkers`, and a multi-shard archive ≡ its single-file twin; the parity gates compare the whole block un-relaxed.
- **Slot level.** On a grouped run the slot's `n` / `n_null` (and, on a weighted slot, `sum_weights` / `n_eff` / `n_weight_invalid`) are COHORT-WIDE totals over every filter-passing record — the figures an ungrouped run reports — and `operator` is omitted (an operator's figures are per bucket). A fan-out grouper therefore has per-group `n` summing past the slot `n`, as its bucket counts sum past `total_n`. `Run.null_records` is unchanged (it still scans the primary field; the grouped slot entries are kept apart from the ungrouped `aggComponents` that rule reads).
- **Per group.** `groups[i]` = `{group_key, n, n_null, sum_weights?, n_eff?, n_weight_invalid?, operator?}` for `Data[i]`: `group_key` is the bucket's `AxisKey` (the value the row carries under the grouper field), and the rest is exactly what an ungrouped run filtered to that bucket's records reports — the same builder (`aggregateWithComponents` → `buildAggregationComponents` + `WeightFloor`), the floor tallied through `FieldPresent`, never `NumericValue`. Extension aggregators get the floor automatically and their `operator` from each per-bucket instance's existing components hook (`ComponentsFunc` / type-level `Components()`); no new API.
- **Order.** `groups[]` follows the FINAL `Data` order — after `sortGroupedRows`, so `Request.Sort` included — exactly as `GroupedMatrices.finalize(keys)` orders per-bucket matrices.
- **Opt-out.** Built behind the processor's `disableComponents` gate (`processGrouped` passes `collect = !disableComponents` per bucket), so `DisableComponents` skips the work and leaves `Components` nil.
- **Streaming / parallel floors.** The streaming-grouped path and each shard / decode partial tally the floors through `processing.SlotFloor` (`NewSlotFloors` / `ObserveSlotFloors`, after row-local attributes land): cohort-wide per slot (`GroupedTail.SlotTotals`; on a partial `shardPartial.aggFloor`, shared with the ungrouped arm) and per bucket, minted with the bucket (`GroupedTail.BucketFloors`; `shardPartial.groupFloors`, merged key by key with `MergeSlotFloors` like `aggN` was). The tail builds each bucket entry off the live (merged) per-bucket aggregator through `buildAggregationComponents` + the weighted floor — operator STATE folds, never components. Tallied only when components are on.
- **Streaming chunks.** Per-group figures are TERMINAL-only: `stream.go` `chunkComponents` drops every slot's `groups[]` on a non-terminal chunk (on a copy), whatever its mergeability; the slot-level floor stays and a `None` slot's slot-level `operator` is still redacted. Ungrouped running state is unchanged.
- **Shared helpers** (`internal/processing/aggregation_group_components.go`): `slotTotalComponents` (cohort-wide slot floors), `AggregationGroupEntry` (slot entry → per-group entry) and `GroupedAggregationComponents` (assemble over the final keys). The streaming and parallel arms reuse them (via `streamedGroupedAggregationComponents` in `FinalizeGroupedStream`) so the shape cannot drift.
- **Gates.** `TestGroupedComponents_PerGroupMatchesFilteredUngrouped` (built-in, floor-only, weighted and extension slots; byte-identical per bucket), `TestGroupedComponents_FollowDataOrder` (default and sorted), `TestGroupedComponents_OptOut` (request + engine), `TestChunkComponents_NonTerminalCarriesNoGroups`, `TestGroupedComponents_ArmsAgree` (buffered ≡ streaming ≡ archive serial ≡ `ShardWorkers=3`, archive ≡ single-file twin, extension merged), `TestGroupedComponents_DecodeWorkersAgree`, `TestGroupedComponents_StreamTerminalOnly`, `TestShardWorkers_ComponentsParity_GroupedAndFlatArchives` / `TestDecodeWorkers_GroupedAnswersParity` / `TestExtensions_BuiltinParity` (whole block), `TestWeightUnityParity` (per-group weighted floor), `TestMarshalFinite_PublicResultTypes` (`AggregationGroupComponents` row).
