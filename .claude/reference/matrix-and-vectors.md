# Matrix and vectors — the `linalg` core, its backend policy and the blocked merge (U15)

CLAUDE.md names `linalg` in the public package list and points here. This file is the long form of the numerical contract every matrix and vector feature builds on. **Load it before touching `linalg/`, a caller of it (synth's correlator, the regression SPD path), `internal/processing/block_merge.go`, the parallel-decode segment split, or any future `MAT_*` / vector surface.** Package layout and the import gates: `.claude/reference/architecture.md` (Public vs internal, Surface guards). Engine wiring of the blocked merge: `.claude/reference/execution-modes.md` (Blocked merge). Embedder-facing guide: `docs/src/library/linalg.md`.

U15 shipped no request slot, response slot, operator, manifest block or skill. The only user-visible addition is two error codes in the manifest error list. Synth and regression output did not move by one bit.

## Package surface

`linalg/` is public and frozen-additive (`TestPublicAPIGolden`). It holds Pulse-owned value types (`Matrix` dense row-major, `Sym` packed upper triangle, `Vec`) and three groups of routines:

| Group | Routines | Backend | Bit contract |
|---|---|---|---|
| Reference SPD kernels | `Cholesky`, `CholeskyRidge` (+ `RidgeSchedule`, `DefaultRidgeSchedule`), `SolveSPD`, `InverseSPD` | pure Go, FMA-free | identical bits on every architecture |
| Reference general solve (U28) | `Solve`, `FactorLU` → `LUFactor` (`Solve`, `SolveMatrix`, `Inverse`, `ConditionNumber`, `N`) | pure Go, FMA-free; the singular decision rides gonum singular values | values identical bits on every architecture; refusal portable except within an ulp of the rank tolerance |
| Co-moments | `CoMoment` (`NewCoMoment`, `Add`, `Merge`, `Clone`, `N`, `W`, `NEff`, `NWeightInvalid`, `PairN`, `PairNMass`, `PairW`, `PairW2`, `PairNEff`, `Mean`, `Cov`, `Corr`; modes `Listwise` / `Pairwise`), `MergeBlockSize`, `MergeTree` | pure Go, FMA-free | identical bits on every architecture |
| Decompositions | `SymEigen`, `SVD`, `QR`, `Rank`, `ConditionNumber` | gonum, canonicalised | decisions (order, sign, rank) portable; values may differ in the last ulps across architectures |
| Gonum SPD path | `FactorSPD` → `SPDFactor` (`Solve`, `Inverse`, `ConditionNumber`, `N`), `Mul`, `ConditionTolerance` | thin gonum wrappers | equal to the raw gonum call bit for bit on ONE machine; not across architectures |

No gonum type appears on the exported surface: gonum is pre-1.0 and the surface is frozen. `TestLinalgSurfaceNamesNoGonum` (`internal/apigolden`) asserts the golden's `linalg` section carries no `gonum` token; `TestLinalgImportBoundary` (`linalg/boundary_test.go`) keeps the package a leaf over the standard library, gonum and Pulse's `errors`.

## Metric registry — `linalg/metric` (U27)

`linalg/metric` is the ONE definition of every v1 distance / similarity metric (15: plain `euclidean` `sq_euclidean` `manhattan` `chebyshev` `cosine` `correlation` `hellinger` `aitchison`; set `jaccard` `dice` `hamming` `overlap`; fitted `std_euclidean` `mahalanobis` `chi_square`). Public, a leaf over stdlib + `errors` + `linalg` (`TestMetricImportBoundary`); `Metric` is an opaque handle over the registry entry, every returned slice a copy. Manifest: `matrix.metrics` (`descriptor.MetricMeta`, built by `metricCapabilities` in `internal/descriptor/capabilities_matrix.go`; `consumers` lists only consumers the instance offers — a hidden or not-yet-registered operator is dropped, `expr` rides `ATTR_FORMULA` / `FILTER_EXPRESSION`); gate `TestManifestMetricsComplete`.

- **Direction contract.** Each metric declares `Direction` (native) and `Forms`; `cosine` alone has both (distance `1 − cos`, the cosine clamped to [−1, 1] first, so [0, 2]). A consumer asks for a form; a metric without it is `PULSE_VECTOR_METRIC_UNKNOWN` (`reason` `no_form`), an unknown name `unregistered`, a metric the consumer does not accept `not_accepted`; an empty name `PULSE_VECTOR_METRIC_REQUIRED`. Never a silent transform.
- **NaN policy.** Pairwise-complete (NaN = missing; ±Inf ordinary). The element sums (`Scaled`: euclidean, sq_euclidean, manhattan, std_euclidean, hamming) are rescaled `s / (p_observed / p)` — R `stats::dist()`, and skipped when nothing is missing so a complete vector's bits never move; chebyshev (a max) is not. The compositional metrics close the observed sub-composition and are not rescaled. `mahalanobis` is `Complete` (a sub-block of the inverse is not the inverse of the sub-block). Zero overlap → NaN, no error; length mismatch → `*LengthMismatchError`, never NaN.
- **Domains.** hellinger / aitchison / chi_square ≥ 0, set metrics 0 / 1; a violation is NaN + `*DomainError` (aitchison zero → `ReasonZero`, the consumer nulls and counts the row). Fitted stats arrive explicitly in `Stats` (`SD`, `InverseCovariance`, `ColumnMasses`); unusable ones are `*StatsError`.
- **Per-consumer acceptance** (`Consumers`, `Accepted`, `ResolveFor`): `expr` exactly the metrics an expression function exposes — `euclidean` (`dist`), `cosine` (similarity form only: a per-consumer form narrowing, so `ResolveFor(expr, "cosine", Distance)` is `not_accepted`), `jaccard`, `dice`, `hamming`, `overlap` (U27 E1-S2 trimmed the E1-S1 "every row-local metric" claim so the manifest is truthful; a new expr metric function adds its metric here); `ATTR_VEC_DISTANCE` row-local distance-form + std_euclidean + mahalanobis; `ATTR_PROFILE_SIMILARITY` similarity-form; `MAT_DISTANCE` its pre-U27 set + hellinger + aitchison (hamming excluded: centroids are not 0 / 1); `GROUP_KMEANS` euclidean + sq_euclidean; `chi_square` none (registered, unexposed until U28).
- **Kind defaults (U27 E1-S3).** `metric.Default(kind, form)` is the kind → default table (distance: measure `std_euclidean`, scale `euclidean`, composition `aitchison`, binary `hamming`; similarity: scale `correlation`, composition `cosine`, binary `jaccard`, measure none); `metric.DefaultFor(consumer, kind, form, admit)` is that default when the consumer accepts it, else the first accepted metric that suits the kind and is no poor fit (`TestDefault_KindTable`, `TestDefaultFor_ConsumerFallback`). Its users: the Vector kind bullet under Virtual vectors below.
- **Consumers folded onto it (U27 E1-S2, #407).** No local metric list or kernel survives. Expr: `dist` / `cosine` are `exprMetricKernel` (`internal/processing/expr_env_vector.go`), the set built-ins `EvalSets` over `labelSetCounts` / mask popcounts (`expr_env_setsim.go`; `hamming` stays an int); `internal/vecmath` keeps only the non-metric kernels (`Dot`, reductions, maps). `dist` therefore rescales a partial pair by p/p_observed (pre-registry it did not; unreleased). `GROUP_KMEANS` `sqDist` is the registry's `sq_euclidean` resolved once (`kmeansMetric`); its points are finite and complete, so the bits equal the old plain sum (`TestKMeans_SqDistIsRegistrySqEuclidean`). `MAT_DISTANCE`: below.
- **Bits.** FMA-free `float64(a*b)`, left-to-right; `go build -gcflags='github.com/frankbardon/pulse/linalg/metric=-d=fmahash=vy' -a ./linalg/metric/` reports no contraction. Stated residual: aitchison's `math.Log` (assembly on amd64). Oracle: `scripts/reference/gen_metric.R` → `metricOracle` (`linalg/metric/oracle_test.go`, `TestMetricsMatchROracle`).

## Backend policy — why two backends

A routine is a reference kernel when something downstream has a BIT contract on it; otherwise gonum backs it.

- **Synth seed reproducibility.** Same seed, same bytes, on every machine. Synth's correlator factors a correlation matrix and draws `u = L·z`, so any drift in `L` reaches every correlated value. Synth's hand-rolled Cholesky was already arch-independent, and it had to stay that way.
- **Merge determinism.** The blocked merge tree promises serial == parallel bitwise. That holds only if `Add` and `Merge` produce the same bits wherever they run.
- **Regression was already arch-dependent.** It factored through gonum's `mat.Cholesky` before U15, and gonum has amd64 assembly. Routing it through `FactorSPD` / `SPDFactor` / `Mul` keeps gonum underneath, which is why its output is byte-identical to the pre-U15 build on the same machine. The internal regression types stayed on gonum where converting would add a rounding.

**Why a gonum-backed Cholesky could not replace synth's.** A pre-implementation study (2026-10-05, gonum v0.17.0, darwin/arm64) swapped synth's factor loop for gonum's `Factorize` and compared bitwise:

- **Different operation order, in at least three places.** gonum accumulates a dot product and then subtracts it (`Ddot`), where synth subtracts one term at a time. gonum scales a row by a reciprocal (`Dscal(1/ajj)`), where synth divides. Above an order of about 64, gonum switches to a blocked `Dsyrk` / `Dgemm` / `Dtrsm` path. Its amd64 assembly also unrolls with multiple accumulators.
- **Results.**
  - 96% of 7,800 random SPD matrices (order 2–40) differed in at least one bit of `L`, typically by a few ulps; the largest relative difference was 1.1e-8, on tiny off-diagonals.
  - On exactly rank-deficient unit-diagonal inputs, 21% of the factor-or-fail decisions differed. That changes the ridge retry count and the reported accumulated ridge.
- **The existing suite passed anyway.** All 58 packages stayed green with the swap, because nothing pinned the factor bitwise. The bitwise pins U15 added close that hole: `TestCholesky_BitIdenticalToSynthReference` and `TestCholeskyRidge_BitIdenticalToSynthReference` (`linalg/cholesky_reference_test.go`), plus the synth draw pin.

**FMA-free means:** every product that feeds an addition or subtraction is written `float64(a*b)`. The Go specification forbids fusing an explicitly converted product into a fused multiply-add, and arm64 and amd64 otherwise make different fusion choices. Never remove one of these conversions. Never "simplify" a reference kernel's loop order either: the operation order IS the contract.

**Reference Cholesky operation order.** Lower-triangular Banachiewicz (row by row). For `j ≤ i`, start from `S[i][j]` and subtract `L[i][k]·L[j][k]` for k ascending, one term at a time. Then take the square root on the diagonal, or do a true division by `L[j][j]` off it. The factor fails iff a diagonal pivot is ≤ 0. A NaN pivot is NOT ≤ 0, so it propagates into `L` exactly as synth's original comparison did; the gonum `FactorSPD` refuses it instead.

**Ridge schedule.** `CholeskyRidge` retries with `DefaultRidgeSchedule()`: eight increments `10^(t-6)` for t = 0..7 (1e-6 … 1e1), each added to the diagonal on top of the last. It returns the ACCUMULATED ridge, 0 when the first attempt succeeds. When every attempt fails, the error carries the schedule total of 11.111111 together with `attempts`. Synth surfaces a positive ridge as its existing warning and still raises `SERVICE_VALIDATION` on exhaustion; the linalg code does not leak through.

## Tolerances, order and sign

- **`Epsilon`** = 2⁻⁵². **`RankTolerance(rows, cols, sigmaMax)`** = `max(rows, cols)·Epsilon·σ_max`. This is the ONE rank tolerance, the LAPACK / NumPy `matrix_rank` default. A singular value at or below it is zero. `Rank(m, tol)` uses it unless `tol > 0`; `ConditionNumber` is `+Inf` for a matrix that is rank-deficient under it.
- **Order.** Eigenvalues and singular values are descending. Values within the rank tolerance of their neighbour form a tie cluster, ordered by the index of each vector's dominant component, lowest first, so ties keep the original variable order.
- **Sign.** Every eigenvector, and every right singular vector, is flipped so that its largest-magnitude component is positive. `U` and `V` flip together. A magnitude tie, within `DominanceTolerance` = 2⁻²⁶ relative, goes to the lowest index. `QR` flips so that `R`'s diagonal is non-negative. Without this rule gonum may return either sign, and goldens flake across platforms.
- **One singular decision (TODO #408; `internal/processing/singular_rule.go`).** Every multivariate surface that needs a covariance-shaped matrix's inverse, determinant or full rank — the vector tests, `MAT_PCA` / `MAT_FACTOR` KMO + Bartlett and `MAT_FACTOR` `ml`, `MAT_PARTIAL_CORRELATION`, `MAT_COLLINEARITY`'s VIF, `MAT_DISTANCE` mahalanobis, the minres SMC start, the fitted attributes — asks `rankDeficient` / `singularUnderRule`: singular when a diagonal entry is ≤ 0 or non-finite, or when the smallest eigenvalue of the CORRELATION form is ≤ `RankTolerance(p, p, λ_max)` (gonum `SymEigen`; scale-free). A tiny positive Cholesky pivot left by rounding is not invertibility: the old matrix-operator rule ("singular only when `InverseSPD` fails") called such a near-exact dependency invertible while the tests refused it. The values stay on the reference kernels; an inversion that still fails is singular too (defensive). `singularUnderRule`'s `PULSE_MATRIX_SINGULAR` carries `rank` / `condition_number` / `dependent_indices` like the linalg errors, so `singularMatrixError` adds `dependent_fields`. Oracle: `mv_singularity.json` (`gen_singularity.R`: the rule vs `Matrix::rankMatrix`, `chol()` still factoring the borderline case), `TestSingularRule_EverySurfaceAgreesWithROracle`.
- **General solve (U28 E2-S1, `linalg/lu.go`).** `FactorLU` is Doolittle LU with partial pivoting: per column k ascending, the pivot is the largest |a[i][k]| for i ≥ k (tie → lowest row), swapped into row k; multipliers are true divisions; `a[i][j] -= float64(l·a[k][j])` over j > k ascending. `Solve` / `SolveMatrix` run forward substitution on P·b then back substitution with a true division by U's diagonal, each a running FMA-free subtraction; `SolveMatrix` column j equals `Solve` on column j bit for bit, and `Inverse` is `SolveMatrix` on the identity. **Singularity policy:** refused iff rank-deficient under `RankTolerance(n, n, σ_max)` (exactly where `ConditionNumber` is `+Inf`), plus a defensive exact-zero pivot; a full-rank ill-conditioned matrix still solves and `LUFactor.ConditionNumber` reports κ. **Round-trip tolerance:** ‖A·x − b‖∞ ≤ 8·n·ε·(‖A‖∞·‖x‖∞ + ‖b‖∞). Gates: `TestSolve_BitPinned` (cross-architecture bit pin), `TestFactorLU_NearSingularFollowsRankTolerance`, `TestSolve_RoundTripRandomNonSymmetric`. A pivot-magnitude proxy (pivot ≤ n·ε·‖A‖∞) was tried and rejected: on [[1, 1], [1, 1+δ]] it solved δ = 4ε–7ε to garbage the rank tolerance calls rank-deficient. Consumer: the Markov overlay's absorption time (I − Q)⁻¹·1.
- **`ConditionTolerance`** = 1e16, gonum's own threshold. An `SPDFactor` whose condition estimate exceeds it still factors, but its `Solve` and `Inverse` refuse.
- **Co-moment merge tolerance.** A merged split is not bit-identical to one serial pass, because float addition is not associative. It agrees within 1e-10 relative to scale (means, covariances, correlations, `W`, `NEff`). Counts are exact. Bit identity across worker counts comes from the blocked tree below, not from `Merge` alone.

## Errors

Both codes are `*errors.CodedError`, owned `shared`, and listed in the manifest. Each carries a `codeMetadata` Message and fixups in `errors/fixup_metadata.go`.

- **`PULSE_MATRIX_SHAPE_MISMATCH`** is raised for operands whose dimensions disagree: non-square, ragged, a vector length different from the matrix order, data length ≠ rows×cols, a nil operand, or two `CoMoment`s of different `P` or mode merged. Details name the dimensions.
- **`PULSE_MATRIX_SINGULAR`** is raised when a matrix cannot be factored, solved against, inverted or decomposed. Details vary by routine:

| Routine | Details |
|---|---|
| `Cholesky` / `SolveSPD` / `InverseSPD` | `pivot` + the singular diagnostics below |
| `FactorLU` / `Solve` | `reason` = `singular`, `n`, `rank`, `condition_number` (`+Inf`), + `pivot` on an exact-zero pivot; or `reason` = `non_finite` |
| `CholeskyRidge` exhausted | `attempts`, `ridge` |
| `FactorSPD` | `reason` = `not_positive_definite`, `n` + the singular diagnostics below |
| `SPDFactor.Solve` / `Inverse` | `reason` = `ill_conditioned` + `condition_number` (`+Inf` on breakdown), or `reason` = `backend_error` |
| gonum decompositions | `reason` = `non_finite` (a NaN / ±Inf element) or `no_convergence` |

**Singular diagnostics (U24 E1-S1).** A failed reference `Cholesky` (and so `SolveSPD` / `InverseSPD`) or `FactorSPD` on a FINITE matrix adds, from one gonum `SymEigen` on the failure path only (`linalg/singular.go`; the factor's bits are untouched): `rank` — eigenvalues with |λ| above `RankTolerance(n, n, max|λ|)`, the one rank tolerance; `condition_number` — max|λ| / min|λ|, `+Inf` (wire `null`) when rank < n; and, only when rank < n, `dependent_indices` — the ascending axis indices with a component above √ε (2⁻²⁶) in some null-space eigenvector, i.e. the variables in the (near-)linear dependency. A full-rank indefinite matrix has rank n and no `dependent_indices`; a NaN / ±Inf element or a failed decomposition adds nothing ("where identifiable"). The values are gonum-backed — same-machine stable, not bit-stable across architectures. A matrix operator that refuses with the code wraps it through `processing.singularMatrixError` (`matrix_finalize.go`), which adds `matrix` and `dependent_fields` (the member names at `dependent_indices`, axis order) without mutating the linalg error. Gates: `TestCholesky_SingularDiagnostics`, `TestFactorSPD_SingularDiagnostics`, `TestMatrixFinalizer_CodedErrorPropagates`, `TestSingularMatrixError_PassesOthersThrough`. `CholeskyRidge` (synth) is unchanged. Callers that own a domain code keep it: synth still raises `SERVICE_VALIDATION`, and regression keeps its rank-deficient codes and `gonum_error` detail text.

## `CoMoment` weight and missing semantics

- **Update.** Weighted Welford–West: the first row with mass sets the mean exactly, so a constant column has variance exactly 0. **Merge** uses the exact Chan–Golub–LeVeque combine. `Merge` mutates the receiver; `MergeTree` mutates nothing.
- **Missing values.** A NaN in `x` means missing. `Listwise` skips the whole row. `Pairwise` skips per pair: each pair keeps its own count, weight, means and co-moments. A row the mode admits nowhere is not counted, and its weight is never judged.
- **Weights.** Weights follow `.claude/reference/weighting.md` (Validation). A NaN, ±Inf or negative `w` skips the row and increments `NWeightInvalid`. **`w = 0` is valid: the row counts toward `N` (and `PairN`) but adds no mass** to `W`, the means or the co-moments. `NEff` is Kish's `(Σw)²/Σw²`.
- **Per-pair Σw² (U28 E3-S1).** `PairW2(i, j)` is the pair's squared-weight sum over the rows the pair admits, accumulated beside `PairW` (the `w = 0` row adds nothing; invalid weights never reach it) and merged by plain addition, so a fixed merge tree gives the same bits whatever the segmentation, and a split agrees with one serial pass to the `W` tolerance. Listwise returns the global Σw² for every pair. `PairNEff(i, j)` is exactly `PairW²/PairW2` — the arithmetic `weighting.KishNEff` / `Basis.NStar` use, so a pairwise probability-weighted inference reads N* as `basis.NStar(PairW, PairW2)` — and `0` for a pair with no mass (as `NEff`); under Listwise it equals `NEff`. Cost: 8 bytes per pair (56→64 B) in Pairwise mode only; on the `BenchmarkCoMomentAdd` / `BenchmarkCoMomentMerge` pair (p = 8, Apple M1) Pairwise `Add` is ≈ +4.5% and `MergeTree` ≈ +7% (the larger per-pair copy), Listwise unchanged. Every pre-existing figure is bit-identical.
- **Per-pair massed rows (U28 E3-G2).** `PairNMass(i, j)` counts the pair's rows that carry mass (w > 0) — `PairN` less its weight-0 rows, `PairN` itself under unit weights; Listwise returns the global massed count for every pair. Counted beside `n` in `Add` and summed in `Merge` (exact, like every count); 8 more bytes per pair in Pairwise mode. It exists so inference's row floors read the rows a weighted single-pair test reads (`TEST_PEARSON_R` / `TEST_SPEARMAN_R` / `TEST_KENDALL_TAU` skip a weight-0 row from their raw `n`) while the matrix's own `n` (`PairN`, the components floor) keeps counting weight-0 rows. Every pre-existing figure is bit-identical.
- **Porting caveat.** The engine's weighted aggregators (`internal/processing/aggregator_weighted*.go`, the weighted Welford path) treat `w == 0` as NOT contributing: such rows are skipped before the row count. Porting an existing weighted reducer onto `CoMoment` therefore moves its row count on zero-weight rows. Decide that change deliberately, and gate it, rather than inheriting it.
- **Outputs.** `Cov(ddof)` is `M2/(W − ddof)`, NaN where `W − ddof ≤ 0`; probability-weight corrections are the caller's job. `Corr` is C_ij/√(M2_ii·M2_jj) — `TEST_PEARSON_R`'s one-root arithmetic, so one unit-weight block correlates to that test's bits on a non-fusing architecture — falling back to the two-root C_ij/(√M2_ii·√M2_jj) when the product leaves the normal range (overflow / underflow), clamped to [−1, 1] (`TestCoMomentCorrOneRootForm`). A variable with zero spread has NaN for every entry touching it, its own diagonal included, never 0. `Mean` of a variable with no mass is NaN.
- **Concurrency.** A `CoMoment` is not safe for concurrent use: give each worker its own and merge them.

## Blocked merge-tree contract

The contract is that one answer has the same bits under every concurrency knob.

- **Blocks.** Fold the row at GLOBAL record ordinal `r` (a shard archive row: its shard's start — the record counts of the shards before it — plus its in-shard index) into block `r / MergeBlockSize` (4096), never into "this worker's partial". `MergeBlockSize` is part of the bit contract: changing it changes merged bits.
- **Tree.** `MergeTree(blocks)` merges level-wise by position, `(b0·b1)`, `(b2·b3)`, …, carrying an odd tail up unmerged. Five blocks merge as `((b0·b1)·(b2·b3))·b4`. The shape depends only on the sequence length, and `Merge` is FMA-free, so the root is a pure function of the block sequence.
- **Engine.** Parallel-decode segment boundaries snap to multiples of 4096 records, so no block straddles two workers. `DecodeCallbackFactory` receives the segment's absolute start record. Every record source stamps `(shard, shardStart, record)` on the `Record`. A shard edge may fall inside a block: the block then arrives as one fragment per shard. The fragment of the shard holding the block's first ordinal folds as rows arrive; any other fragment (≤ 4096 rows, the first block of its shard) buffers its rows and is replayed on top in shard order, so every block is the one sequential fold of its rows.
- **Opt-in.** The opt-in is the internal interface `processing.BlockMerger`. Its state is per-fragment `CoMoment`s (or buffered rows); partitions combine by disjoint union, and `Finalize` rebuilds each block, then runs one `MergeTree` over the blocks in block order. Every other reducer keeps its existing merge path unchanged. `BlockMerger` is NOT reachable through `extend`, so extensions cannot opt in yet. Full wiring: `.claude/reference/execution-modes.md` (Blocked merge).
- **Guarantee.** Serial == any `DecodeWorkers` == any `ShardWorkers` count == any shard split, bitwise, on every architecture: a shard archive (uneven shards, 1-row and empty shards included) equals its single-file twin bitwise. The same holds for `AGG_VEC_MEAN` / `AGG_VEC_SUM`.
- **Unstamped records are refused.** A row built by a join (`copyStateInto`) or by a ProcessChain intermediate stage carries no position. A `BlockMerger` refuses such a row with `PROCESSING_INTERNAL` rather than guessing.
- **Gate U16 inherits.** `TestCoMomentMergeTree_WorkerInvariant` (`internal/service/comoment_merge_tree_test.go`) drives a `_test.go`-only CoMoment reducer through the real dispatch:
  - serial vs `DecodeWorkers` 2/3/7/8, on cohorts that end mid-block and on block boundaries;
  - serial vs `ShardWorkers` 2/3/8 on an 8-shard archive, and that archive vs its single-file twin (bitwise);
  - listwise and pairwise, each weighted and unweighted.

  The first `MAT_*` operator passes the same invariance through its real registration: `TestMatrixCovariance_WorkerInvariant` (`internal/service/matrix_merge_invariance_test.go`, listwise and pairwise).

## Virtual vectors — `Request.Vectors` (U16)

`Request.Vectors []types.VectorSpec` (`{name, fields | pattern, labels?, coerce?, kind?, scale_min?, scale_max?}`, additive `omitempty`, gated by `capability:matrices`) names a battery of numeric columns once per request. **The one resolver is `internal/vectors`** — a no-execute leaf (stdlib + `encoding` / `errors` / `types`, plus the parse-only `internal/exprident` for expression references) that predict, the runtime and projection all call, so the three cannot disagree. Consumers (the matrix slot and its operators) read members through it: `vectors.Resolve(req.Vectors, schema)` → `[]Resolved{Name, Members, Labels, Coerce}` index-aligned with the specs; `vectors.Find` by name; `vectors.ResolveSpec(at, spec, schema)` for an inline field list (an operator slot's own `fields`, with its own path in `at`).

- **Shape.** `name` non-empty and unique per request; exactly one of `fields` / `pattern`; `coerce` ∈ `types.AllVectorCoerces()` (`binary`). Violations are `PULSE_VECTOR_INVALID` (`details.reason` = `empty_name` / `fields_and_pattern` / `no_fields_or_pattern` / `unknown_coerce` / `empty_field_entry` / `bad_glob` / `bad_pattern`); a repeated name is `PULSE_VECTOR_DUPLICATE` (`indices`); a name that is also a schema field's name is `PULSE_VECTOR_NAME_COLLISION` (`vector`, `name`, `field`; U26 E2-S1 — an expression binds a vector by name beside the fields, so the two must never be ambiguous; judged in `vectors.Resolve`, so predict and the runtime refuse alike). So is a name equal to a feature output, attribute or window label of the same request (U26 E2-S2; `vector`, `name`, `label` + the claiming slot `feature` / `attribute` / `window` + `window_index`) — judged by the field-reference walk right after vector and matrix resolution (`fieldRefWalk.vectorLabelCollision`, labels recorded by `claim` as steps 1 / 3 / 5 name them), so predict and every runtime mode refuse alike; without it the derived column silently won the identifier (`TestPredict_VectorLabelCollision`, `TestVectorExpr_LabelCollisionRefused`).
- **Vector kind (U27 E1-S3).** Optional `kind` ∈ `types.AllVectorKinds()` (`measure` / `scale` / `composition` / `binary` — the `linalg/metric` kinds, pinned equal by `TestResolve_KindAndScaleBounds`) and, under `kind: "scale"` only, `scale_min` / `scale_max` (both, finite, min < max). Refusals are `PULSE_VECTOR_INVALID` with `reason` `unknown_kind` / `scale_bounds_without_scale_kind` / `scale_bounds_partial` / `scale_bounds_invalid`, judged after `coerce`. `Resolved` carries `Kind` + `HasScale` / `ScaleMin` / `ScaleMax`. - **Wire.** `Request.Matrices []types.MatrixSpec` `{name?, type, vector | fields, params?, weight?, encoding?}` → `Response.Matrices []types.MatrixResult` `{name, type, group_key?, group_header?, primary, auxiliary?, vectors?, scalars?, warnings?}`, one per spec in request order (grouped: one per spec per bucket — see Grouped below). ## Regression vcov — `RegressionSpec.Vcov` (U24 E4)

Opt-in per regression: `vcov: true` (a flat `RegressionSpec` field — regressions carry flat params, there is no `params` object) adds `RegressionResult.Vcov` and `.Correlation`, both a `*types.MatrixValues` (`square_symmetric`, `full`, keys `(intercept)` then the predictors in spec order). Off by default: both slots are `omitempty` pointers, so a fit without it is byte-identical (`TestRegressionVcov_OffByDefault`). No feature row (a param, like the rank methods), so the ungated `regressions` slot makes `MatrixValues` reachable on an instance with `capability:matrices` hidden (`TestPayloadSchema_MatricesHidden`).

- **Sources** (`internal/processing/regression/vcov.go`). `REG_OLS` unpenalized: σ̂²·M2_xx⁻¹ for the slopes, intercept row Cov(β₀, β_j) = −Σ_k μ_x[k]·Cov(β_k, β_j) (ȳ is uncorrelated with the centred slopes), Var(β₀) as the SE reads it; ridge: the same assembly over the sandwich. `REG_GLM`: (XᵀWX)⁻¹ at the CONVERGED β's working weights, dispersion 1. `REG_BAYES_LINEAR`: the POSTERIOR covariance b_n/(a_n−1)·Λ_n⁻¹ (NaN → `null` when a_n ≤ 1) — not StdErrors² on the diagonal (those are the marginal-t scales; the ratio is a_n/(a_n−1)).
- **Diagonal = SE² exactly** on OLS / ridge / GLM: the diagonal is the clamped pre-square-root variance the standard error is `math.Sqrt` of, so `√diag == StdErrors` bit for bit. Weighted fits inherit the N* basis (Σw frequency, n_eff probability) because σ̂² and the GLM prior weights already sit on w*.
- **Correlation** is R's `cov2cor` (`(s_i·V_ij)·s_j`, s = √(1/diag), unit diagonal), computed on the upper triangle and mirrored so both matrices are exactly symmetric; a zero or undefined variance makes its row / column `null`.
- **Modifiers** (`resample.go`, `modifier_engine.go`; owner call (e), 2026-10-10). Under Resample the vcov is the REPLICATE covariance its SEs are the √diag of, over the same replicate set the SE sums (a skipped bootstrap replicate is absent from both; a failed jackknife refit fails the fit): jackknife (n−1)/n·Σ(β₋ᵢ−β̄)(β₋ᵢ−β̄)ᵀ, bootstrap the B−1 sample covariance, deterministic for a seed (`replicateCov`, which forms the off-diagonal only when `vcov` is set). The base fit's analytical matrix is replaced, never kept. Under Selection it is the inner engine's matrix from the final refit on the selected predictors (keys `(intercept)` + `selected_features` order; an intercept-only OLS result carries the 1×1 Var(ȳ)); Selection + Resample follows the resample SEs over the selected set. Bayes never reaches a modifier (`PROCESSING_CONFIG`).
- **Refusal.** Lasso / elastic net — alone or under a modifier (no sampling covariance of a data-dependent active set — never approximated) → `PROCESSING_REGRESSION_VCOV_UNSUPPORTED`, `details.reason` `penalty`; predict (`vcovRefusal`) and the engine (`validateVcov`) apply the one rule (`TestRegressionVcov_Refusals`, `TestVcov_ModifierRefusals`).
- **Oracle.** `mv_vcov.json` `cases` (vcov(lm), vcov(glm) binomial / poisson; mtcars, attitude, weighted; unweighted, frequency, probability): `TestRegressionVcov_MatchesROracle`. OLS at 1e-10 (worst seen 3e-13). GLM at 1e-11 (worst seen 2.1e-13): R's raw vcov(glm) inverts XᵀWX at the working weights from the START of glm.fit's last iteration, one β update behind its coefficients (≈ 1e-7 on the near-separated mtcars binomial fit), so the generator refines each fit by Fisher-scoring steps to the IRLS fixed point and inverts there (`glm_fixed_point`), the point Pulse evaluates at. `jackknife_cases` (leave-one-out lm) and `selection_cases` (`stats::step`, whose extractAIC differs from Pulse's criterion by a constant) pin the modifiers at 1e-10 (`TestRegressionVcov_ModifiersMatchROracle`); bootstrap has no oracle and is pinned by invariants (diag = SE², symmetry, PSD, seed determinism, the hand-computed replicate covariance: `TestVcov_Bootstrap_*`).
- **Robust covariance (U25 E5-S1).** `RegressionSpec.Covariance {type, cluster, order_by, lags}` (absent = `classical`, byte-identical: `TestRegressionCovariance_ClassicalByteIdentical`) swaps the estimator behind `StdErrors`, `PValues`, the intervals AND `Vcov` on `REG_OLS`: `hc0`–`hc3`, `cluster` (CR1, G/(G−1)·(N*−1)/(N*−k), inference on G − 1 df, < 2 clusters refused), `hac` (Newey–West Bartlett, `prewhite = FALSE`, N*/(N*−k), rows sorted by `order_by`, a repeated value refused, `lags` an int or `"auto"` = ⌊4(n/100)^(2/9)⌋ over the fit's rows). The engine (`covariance.go` `sandwich`) is engine-free — bread, per-row unit-weight score, w*, leverage, keys — and REG_OLS feeds it from a buffered SECOND pass (`ols_covariance.go`, centred coordinates, bread diag(1/N*, M2⁻¹/c), mapped back by J = [[1, −μᵀ],[0, I]]); √diag == `StdErrors` bit for bit (the clamped diagonal IS the variance). A robust type makes `RegressionSpec.Streamable` false (predict names the reason), its `cluster` / `order_by` enter projection and the field-reference rule, a null key drops the row listwise, and `RegressionResult.Covariance` echoes `{type, cluster, clusters, order_by, lags}`. One rule for predict and runtime: `internal/regcov.Check` (shape → `PROCESSING_CONFIG`; beside a penalty / resample / selection or on a non-OLS type → `PROCESSING_REGRESSION_VCOV_UNSUPPORTED` `details.reason`; the engine adds `clusters` / `order_by_ties`). Cluster keys read the optional `regression.LabeledRecord.StringValue` (categorical label), else `NumericValue` — `Record` itself stays one method. Oracle `mv_robust_vcov.json` (`gen_robust_vcov.R`: `sandwich` 3.1-3 `vcovHC` / `vcovCL(type = "HC1")` / `NeweyWest`, `lmtest::coeftest` p-values) at 1e-10. **E5-S2 lifts `REG_GLM` and `REG_BAYES_LINEAR`** (`regcov.robustTypes`; `ReasonType` is now reachable only by a type without the estimators). GLM (`glm_covariance.go`): the same sandwich over the IRLS scores at the converged weights — unit score μ'·(y − μ)/V(μ)·x, bread the classical (XᵀW*X)⁻¹, unit leverage μ'²/V·xᵀBx, w* = the prior weight — so it is R `sandwich` on `glm` (dispersion cancels, every family); inference stays Wald z, `cluster` included (no `DF`). Rows with a null key drop in `buildWeightedDesign` (`robustKeyReader`). Bayes (`bayes_covariance.go`): Müller's (2013) sandwich posterior — μ_n KEPT, the posterior covariance REPLACED by Λ_n⁻¹·M·Λ_n⁻¹ (bread the posterior precision, σ²-free; score (y − xᵀμ_n)·x; leverage xᵀΛ_n⁻¹x) — with NORMAL credible / confidence intervals and no `DF`, √diag(`Vcov`) = `StdErrors` (unlike its classical posterior vcov); forces the buffered path (`fitRow` second pass). Oracle `mv_robust_vcov_glm.json` (`gen_robust_vcov_glm.R`: binomial / poisson against `sandwich` on a `glm` refit from the polished MLE, `coeftest` z p-values; Bayes closed form, checked = the `lm` sandwich at precision 0) at 1e-10 (`TestRegressionCovariance_MatchesROracle/REG_GLM+REG_BAYES_LINEAR`). The model file records the estimator (`model_format_version` 2, byte-layout.md "Model file").
- **Return.** `regressions[*].vcov` / `.correlation` / `.covariance` are in `standard` (so an opted-in matrix survives the MCP default), not `minimal`, excludable like any path, every float rounded by `precision` (`TestReturn_RegressionVcov`, `TestPrecision_FloatLeavesClassified`).

## Parity tolerance rationale (U16)

`MAT_CORRELATION` agrees with `TEST_PEARSON_R` within `1e-12 + 1e-12·|r|`, not byte for byte. Two arithmetics differ on purpose: the matrix is FMA-free and block-merged (arch-independent, worker-invariant), while the test's recurrence is plain Go that arm64 fuses into multiply-adds, so its bits differ between architectures. Bitwise parity (unweighted, serial, ≤ 4096 rows, test `field` the earlier member) is therefore an amd64-only assertion; making the test arch-independent would move `TEST_PEARSON_R` bits on arm64 and is not done here. `linalg.CoMoment.Corr` was changed in U16 to the one-root `C / √(M2ii·M2jj)` (two-root `C / (√M2ii·√M2jj)` only when the product leaves the normal float64 range) so that bitwise case holds (public method, no production caller outside the matrix slot; see the embedder-migration doc).
