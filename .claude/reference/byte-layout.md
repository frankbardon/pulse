## The contract

**Format version — `0x01` / `0x02`.** Header byte 8 is the `.pulse` format version; the accepted set is `{0x01, 0x02}` (`encoding.IsSupportedFormatVersion`, `SupportedFormatVersions`, `MaxFormatVersion = 0x02`). `encoding.ReadHeader(r) (byte, error)` RETURNS the version, and `encoding.ReadSchema(r, version)` parses the schema block in that version's layout — the version is NOT optional plumbing, because the schema block has no terminator and records begin at the first byte after it, so a `0x02` block parsed as `0x01` starts the record region early and every stride consumer (`RecordCountForPayload`, `record_at`, parallel segment splitting, lookup offsets, export, shard rewrite) is silently wrong. `internal/encoding.ReadPreamble` is the one-call form; `TestReadSchemaCallersThreadHeaderVersion` fails any production `ReadSchema` whose version argument is not the variable `ReadHeader` returned in the same function. Any other version byte is `ENCODING_INVALID` with `details.version` (the byte) and `details.supported_versions`; the shard peek (`Archive.PeekShardHeader` / `PeekShardRecordCount`) applies the same set under `PULSE_SHARD_HEADER_INVALID`. **Layouts.** `0x01`: `u16 field_count` + field descriptors, nothing after. `0x02`: the identical descriptors followed by the **schema extension block** — `u64 extension_length` + that many payload bytes — so the record region's start is derivable without understanding the payload. The payload is `u16 section_count` then tagged sections (`u16 tag`, `u8 flags` — bit 0 REQUIRED, bits 1-7 reserved and refused when set — `u64 length`, bytes). A reader REFUSES an unknown REQUIRED section (`ENCODING_INVALID`, `details.tag`) rather than skip bytes whose meaning changes how records decode, and skips an unknown optional one; a duplicated tag or a payload not consumed exactly is `ENCODING_INVALID`. That section framing plus the reserved bits is how later additions stay readable or refusable WITHOUT a `0x03`. The one section defined is tag `1`, GROUPS — next paragraph. The hooks are `writeSchemaExtension` / `readSchemaExtension` in `encoding/group_wire.go`, and the version-selection hook is `Schema.RequiredFormatVersion` (`0x02` iff `Schema.HasGroups()`). **Writers.** The version written is a FUNCTION OF SCHEMA CONTENT, never a global flag: `internal/encoding.WritePreamble(w, schema)` writes the header at `schema.RequiredFormatVersion()` plus the matching schema block, and every production writer (import, synth, augment, widen, shard rewrite, `_schema.pulse`) goes through it. A schema with no group is `0x01`, so every ungrouped output is byte-identical to a pre-`0x02` write. The legacy pair `WriteHeader` + `WriteSchema` still emits `0x01` and `WriteSchema` refuses a schema that requires newer (it would contradict its own header). `service.FilterToFile` copies the source's header + schema bytes verbatim, so a `0x02` source yields a `0x02` destination carrying its group descriptors and dictionaries UNCHANGED — entries no surviving row references are carried, never pruned (v1: pruning costs a pass and renumbers indices; re-dedup the output to prune), so inspect's ratio reads surviving rows ÷ carried entries; a filter keeping nothing writes a valid empty `0x02` cohort (the preamble alone, constant groups included). Filter-to-file never drops output fields — its projection narrows the predicate's DECODE only. Every other `.pulse`-from-`.pulse` writer either refuses a grouped source (`RefuseGroups`: set-field widen and the byte-level `RewriteShardCategoricals`), deliberately FLATTENS to `0x01` (synth augment), regroups from scratch (retro-dedup), or flattens-reconciles-regroups against an archive's layout (shard create/add — "Shard archives with parent groups" below). Gate: `TestGroupedCohort_FilterToFile`. **Compatibility.** `0x01` cohorts are readable forever — `encoding/testdata/format_v1.pulse` (synthetic; NEVER regenerated to make a failure pass — a failure is a compatibility break; see `docs/src/internals/regenerating-goldens.md`) is read by every build and the current writer must still reproduce it byte-for-byte. A binary that predates `0x02` refuses a `0x02` cohort at header parse with a coded `ENCODING_INVALID` (inspect: "unsupported pulse format version"; the process path's older message names only the file) — loud, never a misparse, and the release-note-worthy break. A shard archive's canonical `_schema.pulse` participates in versioning like any shard payload; the `SHRD` trailer follows the (possibly extension-bearing) schema block. `encoding.IsArchive`'s zip-vs-`PULSE` magic dispatch runs before any header read and is unaffected.

**Parent groups — the `0x02` group descriptor.** A parent group stores each distinct tuple of its member fields ONCE, in a dictionary in the schema block, and each row carries a fixed-width `u32` index (`encoding.GroupIndexWidth`) into it. N independent groups per cohort; no group references another; a field is in at most one group. **Terms** (`encoding/group.go`): the LOGICAL schema is `Schema.Fields`, every field in original order — every field index anywhere in the API, `Record` position, plan `Indices` and bitmap bit a decoder hands a record is a LOGICAL position; the LOGICAL row is the `0x01` row of that schema; the PHYSICAL row is `[u32 index per INDEXED group, group order][row fields — fields in no group — logical order][narrowed bitmap: ceil(row_field_count/8), bit j = j-th row field, present iff a row field is nullable]`. `Schema.RecordByteSize` / `BitmapByteSize` / `HasBitmap` describe the PHYSICAL row (still fixed, still a pure function of the schema — every stride consumer is unchanged in form); `Schema.Logical()` is the ungrouped view over the SAME `Fields` slice. A cohort whose every nullable field is a member has NO per-row bitmap. **GROUPS section (tag 1, always REQUIRED):** `u16 group_count (>=1)`; per group `u8 kind` (0 indexed, 1 constant), `u8 index_width` (4 / 0 — any other pairing refused), `u8 flags` (reserved, 0), `u16 member_count (>=1)`, per member `u16 field_index` (logical, strictly ascending) + `u8 flags` (bit 0 = KEY member, rest reserved), `u32 entry_width` (must equal what the members imply), `u32 entry_count` (constant: exactly 1), then `entry_count × entry_width` bytes. **Entry** = each member's logical on-wire bytes in member order + a `ceil(member_count/8)` member null bitmap iff any member is nullable (bit k = member k, LSB-first, 1 = null). Raw encoded values, never strings: a categorical member's bytes ARE its dictionary ID, and every member keeps its own inline `Field.Dictionary`, byte-identical to the ungrouped cohort — the SPSS `code ↔ label ↔ dictionary-ID` triple, `GROUP_CATEGORY`, labels and export need no special case. **Bit-packing rule:** a bit-packed member (`u4`, `packed_bool`) stores its ONE whole on-wire byte verbatim — the `0x01` row never shares a byte between fields, so a group may split a bit-packed run anywhere with no repacking. **Constant groups** (kind 1) are how a global-constant field is elided: one entry, no per-row index; a null constant is an entry whose null bit is set. A physical stride of 0 (every field constant-grouped) is refused at write and read — the record count would be underivable. **Decode reads ONE physical row per record on every path** (never ahead — `FilterToFile` copies physical rows by reader position, so it carries the dictionary through unchanged), and `BuildDecodePlan` on a grouped schema returns the LOGICAL plan (`SkipBytes` widths are logical). Two routes, one result: the MAP decoders (`ReadRecordWithWide*`, the record locator) read a logical stream (`encoding.NewLogicalStream`, `RowExpander`) that splices entries in by index and merges null bits, then run the `0x01` decoder unchanged; the REUSE decoders (`ReadRecordReused*` — streaming, buffered, parallel, shard scans) never expand (`internal/encoding/group_decode.go`): they read the physical row and write each field at its LOGICAL position — row fields from their bytes with E2 run-skip, a retained group SKIPPED outright when its index equals the one the run-skip record already holds (O(1), no member compare, independent of the backoff), and a changed group written from a per-entry decoded cache (every member's float64 + decoded `Decimal128` when the whole dictionary fits `groupEntryCacheBudget` = 8 MiB per reader per decode shape, else only the decimals, direct-mapped; derived at read time, never persisted; a cached `Decimal128` is shared across records, safe because it is immutable). The retained set is read off the plan, so a group with no retained member is neither expanded nor decoded — its index is still bounds-checked. Per-row cost is therefore independent of parent-block width on the reuse arm; a FRESH record per row (buffered) still takes one cheap write per retained member. An index past its dictionary is `ENCODING_INVALID`. Byte-level consumers that do not go through `RecordReader` must read through `NewLogicalStream` (export and the SPSS cohort writer do; profile run-continuation compares EXPANDED rows). Paths that REWRITE physical bytes by logical offsets refuse a grouped cohort with a coded error via `internal/encoding.RefuseGroups` — set-field widen and the shard categorical rewrite; shard create/add work on the flattened form instead (below). **Precompute hooks** (derived at read time, never persisted): `Schema.FieldGroup`, `GroupEntryCount/Width`, `GroupEntry`, `GroupMemberBytes`, `GroupMemberIsNull`, `DecodeGroupEntry` (writes one entry's members into a record at their logical indices), `GroupIndexOffset`, and `RecordReader.GroupIndex(g)` (the entry the last decoded row resolved to). **Encode:** `encoding.GroupEncoder` (logical row → physical row, dictionary built by lookup-or-append; a declared KEY whose non-key member disagrees or a constant group that changes is `PULSE_GROUP_MEMBER_NOT_CONSTANT`, `MaxGroupEntries` (2^32) exhaustion `PULSE_GROUP_ENTRIES_EXHAUSTED`, each naming group/label/field/row; an unknown member `PULSE_GROUP_FIELD_UNKNOWN`, a field in two groups `PULSE_GROUP_FIELD_CONFLICT`, an empty group / field twice in one group / key-not-member `PULSE_GROUP_DECLARATION_INVALID` — ENCODING_INVALID stays reserved for a corrupt FILE) and `encoding.DedupCohort` (whole cohort → grouped twin, physical rows spooled in memory because the dictionary precedes the records). Resident cost: the dictionaries load with the schema at exactly `entry_count × entry_width` bytes per group. Contract tests: `internal/encoding/group_test.go`, `internal/encoding/group_decode_test.go` (`TestGroupedDecode_*`, incl. the member-write COUNT gate), `internal/service/group_decode_record_test.go`, `group_format_facade_test.go`.

**Global-constant elision — opt-in, full-pass detection.** A field with exactly one distinct value across the WHOLE cohort is stored once as a member of a single constant group (kind 1: one entry, no per-row index) and dropped from the physical row, so `RecordByteSize` and the narrowed `BitmapByteSize` shrink by exactly its bytes and bit. Surface: `io.ImportJob.ElideConstants` / `pulse import <fmt> --elide-constants` (every import leaf, so every `io/` adapter — they all route through `ImportJob.Run`), reported as `ImportReport.ElidedConstants`. **Default OFF**, because the output is `0x02` and a binary predating `0x02` refuses it; with it off, import is byte-identical to before. **Detection is the trap:** `internal/io/infer.go` samples 500 rows, and a column constant across the sample may vary later — so constancy is decided ONLY by `encoding.ConstantDetector` observing EVERY logical row of the final schema after the row pass (`writeCohortPayload` in `internal/io/import.go`), never from inference. Same value ⇔ same on-wire bytes AND same null bit: a column null on every row is a NULL constant (its entry carries the null bit), one value plus some nulls is NOT constant, and two nulls with differing placeholder bytes count as different (conservative — it can forgo an elision, never make a wrong one). `encoding.PlanConstantElision(detector, reserved)` is the ONE decision shared with import-time group declaration and retro-dedup (pass declared members as `reserved`): fewer than `MinElisionRows` (2) rows → nothing (a single row makes every field trivially constant; zero rows leave the constant entry nothing to hold); every field constant → the LOWEST-index field stays in the row (a zero stride is unwritable); and the elision must shrink the file — per-row bytes removed × rows must exceed the preamble growth (`BytesSaved`), else nothing. Whenever nothing is elided the cohort is written `0x01`, byte-identical to elision off. Dictionary-bearing constants keep their own inline dictionaries (the entry holds the ID). Decode is the ordinary group expansion, so values, nulls, `AllValues()`, export and every `Response` match the flat import (`elide_constants_facade_test.go`). Import still holds the whole cohort in memory (pre-existing); the physical rows are spooled beside it because the dictionary precedes the records. Tests: `internal/encoding/group_constant_test.go`, `internal/io/import_elide_test.go`.

**Import-time group declaration — `--group` / `ImportJob.Groups`.** `pulse import <fmt> --group KEY[,KEY...]:MEMBER[,MEMBER...]` (repeatable, one group per flag; every import leaf sets `DisableSliceFlagSeparator` so the value's own commas survive) parses through `internal/io.ParseGroupDecl` into `io.GroupDecl{Key, Members}`; the library surface is `ImportJob.Groups`. A decl lowers to one INDEXED `encoding.GroupSpec` whose members are Key ∪ Members and whose `Key` is Key (so the descriptor's member KEY flag is set on exactly the key fields); no colon = a tuple group whose every member is key. **Key semantics:** non-key members must be functionally determined by the key — the encoder compares each row's full entry (member bytes AND member null bits) against the entry its key tuple already selected and refuses a mismatch with `PULSE_GROUP_MEMBER_NOT_CONSTANT` (details `group`, `group_label`, `field`, `row` = 0-based record, plus `source_row` = 1-based source data row, remapped past earlier `RowErrors` by `io.withSourceRow`). **Names:** the format has no group-name slot and none was added; `GroupSpec.Label(g)` derives `group <g+1> [key: a,b]` (or `[members]` without a key) for errors and `ImportReport.Groups`. **Order of checks:** names are resolved by a throwaway `NewGroupEncoder` over the resolved schema BEFORE the row pass (inferred, `SchemaAwareReader`-authoritative and explicit arms alike — names never change mid-pass, only nullability does), so `PULSE_GROUP_FIELD_UNKNOWN` / `_FIELD_CONFLICT` / `_DECLARATION_INVALID` cost no row reads; the real encoder is rebuilt over the FINAL schema (after null promotion) in `writeCohortPayload`. **Single pass:** the source is read once; the dictionaries are built in ONE pass over the in-memory row spool (lookup-or-append), and the physical rows are spooled because the dictionaries precede the records. **Composition:** declared groups are the descriptor's first groups in declaration order; `--elide-constants` passes every declared member as `reserved` to `PlanConstantElision` and appends its constant group last (its saving estimate ignores that the extension framing is already paid — conservative). Every declaration then passes the per-group viability gate (next paragraph); `ImportReport.Groups[i]` reports its verdict and numbers. Zero declarations → the `0x01` write path untouched, byte-identical. A zero-row import with declared groups writes `0x02` with empty dictionaries. Managed imports take groups too: `imports.Spec.Groups` threads into the manager's `ImportJob`, reached by `pulse import auto --group` and `pulse_import` `groups: [{key, members}]` (the core strict-decodes each entry, so a misspelled `keys` is `PULSE_GROUP_DECLARATION_INVALID`, never a keyless tuple group), at the DEFAULT floor with findings as warnings (`Result.Groups` / `GroupWarnings`); `Spec.SuggestGroups` runs `ImportJob.Predict` detection first and returns `Result.GroupCandidates`. A `.pulse` passthrough refuses groups. Elision stays CLI + library only. Tests: `internal/io/import_groups_test.go` (incl. export round trip against the source table), `cmd/pulse/import_group_test.go`, `internal/encoding/group_test.go` (`TestGroupEncoder_Violations`).

**Per-group viability gate — `PULSE_GROUP_TOO_NARROW` / `PULSE_DEDUP_LOW_RATIO` / `--strict`.** A badly chosen group is a SILENT pessimization, never a decode error: every row still pays the 4-byte index, the dictionary holds one entry per distinct tuple, the file can come out BIGGER than the flat cohort, and the dictionary is fully resident (O(distinct tuples) against an O(1) streaming profile). So each declared INDEXED group is judged on its own numbers — never the cohort's — by `encoding.DedupGate` (`internal/encoding/group_viability.go`), the ONE policy import and retro-dedup share. **Width floor** (`ScreenWidths`, schema-only, before the row pass): members no wider than the index (`member_row_bytes ≤ GroupIndexWidth`, inclusive — equal widths save nothing and still pay the dictionary) can never save a byte at any ratio, so the group is DROPPED — its members stay row fields, are no longer reserved from constant elision, and the other groups proceed — with `PULSE_GROUP_TOO_NARROW` naming the group and both widths. **Ratio floor** (`AssessRatios`, over the dictionaries the full pass built, BEFORE the file is written): ratio = rows ÷ distinct tuples; a group below the floor OR whose `byte_delta ≥ 0` draws `PULSE_DEDUP_LOW_RATIO` with `rows`, `entry_count`, `ratio`, `ratio_floor`, `break_even_ratio` (= `entry_width ÷ (member_row_bytes − 4)`), `grows_file`, `dictionary_bytes` (= `entry_count × entry_width`, the resident cost), `undeduped_bytes`, `deduped_bytes`, `byte_delta` — and is STILL WRITTEN: ratio alone never refuses, because a deliberately deduped low-ratio group is legitimate and no floor is honest for every cohort. **Byte arithmetic** per group: `deduped = rows × 4 + dictionary_bytes + descriptor_bytes` (`13 + 3 × members`, `groupDescriptorBytes`, pinned to `writeGroupsSection` by `TestGroupDescriptorBytes`), `undeduped = rows × member_row_bytes`; the row null bitmap is excluded (it can only shrink, so a delta never invents a saving). Summed over the written groups plus the one-off 23-byte extension framing it IS the file-size difference against the flat import (`TestImportJob_GroupGate_PerGroup`). **Floor = 2.0** (`encoding.DefaultDedupRatioFloor`), a judgement not a law: for members wide against the index the dictionary is `member_bytes × rows ÷ ratio`, so 2 means the parent block at least halves and each tuple is shared by at least two rows; below it most of the parent data turns resident while the saving tends to zero. Overridable: `ImportJob.DedupRatioFloor` / `--dedup-ratio-floor` (0 → default; a value in (0, 1] disables the floor but NEVER the grows-the-file check, which catches a group only slightly wider than the index at any ratio). **Strict:** `ImportJob.StrictDedup` / `pulse import <fmt> --strict` returns the first finding as a fatal `*errors.CodedError` with that SAME code (the CLI's `writeCodedErrorEnvelope` unwraps it into `errors[0].code`) and writes nothing — the width floor fails before the row pass, the ratio floor after the encode but before `afero.WriteFile`. It governs the gate only. Findings otherwise ride `ImportReport.GroupWarnings` into the `--json` envelope's `warnings` after `source_warnings`. **Report:** `ImportReport.Groups[i]` gains `verdict` (`admitted` / `low_ratio` / `dropped_too_narrow`), `reason`, `dictionary_bytes`, `ratio`, `break_even_ratio`, `ratio_floor`, `byte_delta`; a dropped group carries widths only. **Labels survive a drop:** `GroupSpec.Ordinal` pins the declared position, so the group after a dropped one is still `group 3`, in the gate AND in any later `PULSE_GROUP_MEMBER_NOT_CONSTANT`. Constant groups (elision) are never gated — no index, and the elision planner already refuses a non-shrinking plan. `format_version` does not move (`ImportReport` is not payload-reachable). Tests: `internal/encoding/group_viability_test.go`, `internal/io/import_group_gate_test.go`, `cmd/pulse/import_group_test.go` (`TestCliImportGroupGate`).

**Retro-dedup — `pulse dedup` / `Pulse.Dedup` / `pulse_dedup`.** Converts an EXISTING single-file cohort to `0x02`, so grouping no longer needs the original source. Byte work: `io.DedupJob` (`internal/io/dedup.go`); layout dispatch: `service.Service.DedupPreflight`; facade `Pulse.Dedup(ctx, path, DedupOptions{Groups, Out, ElideConstants, RatioFloor, Strict, SuggestGroups})` → `*DedupResult` (the inlined `io.DedupReport` plus `invalidated_sidecars` / `sidecar_warnings`). **One path, not a parallel one:** declarations lower through the same `GroupDecl` → `GroupSpec`, names resolve through a throwaway `NewGroupEncoder`, the width floor (`DedupGate.ScreenWidths`) runs before any record, rows encode through `GroupEncoder.EncodeStream` (also behind `encoding.DedupCohort`), and the ratio floor (`AssessRatios`) runs after the pass and BEFORE anything is written, with `Strict` escalating either. Elision goes through `PlanConstantElision` with the admitted declared members reserved. Candidate detection goes through the SAME `candidateDetector` import predict uses, fed the cohort's decoded logical rows, which are padded to the full `ceil(fields/8)` bitmap when the schema has none. Pinned by tests: dedup of a flat cohort is byte-identical to importing its source with the same flags (`TestDedupJob_InPlaceMatchesImport`, `_ElideConstants`, `_Gate`); detection over the cohort equals import-predict detection over its source (`TestDedupJob_SuggestGroups`); every facade read path is byte-identical before and after (`TestDedup_RoundTrip`). **Source is read LOGICALLY**, so a `0x02` cohort is regrouped from scratch (its groups replaced, never extended). **Passes:** one encode pass, plus ONE shared observation pass when elision or suggestion is asked for (elision cannot ride the encode pass, because the constant group changes the encoder). All passes walk `encoding.ForEachRecord`, and a truncated tail is `ENCODING_INVALID`. **Memory is O(dictionaries):** physical rows spool to `<target>.dedup-spool-*.tmp` (dictionaries precede records on the wire), then the preamble and the spool are assembled into `<target>.dedup-*.tmp`, fsynced and renamed over the target. Any failure, including a strict finding, `PULSE_GROUP_MEMBER_NOT_CONSTANT` mid-pass or cancellation, removes both temp files and leaves the original byte-identical (`TestDedupJob_FailureLeavesOriginal`). `Out` writes a NEW path and refuses an existing one (`SERVICE_VALIDATION`). Nothing is written, and `rewritten: false` is reported, when the call is suggest-only or every declared group is dropped as too narrow with nothing to elide. **Shard archives and anchored shards are REFUSED** (`SERVICE_VALIDATION`, `details.layout = "shard_archive"`). Archives DO carry grouped shards, but an archive-wide dedup would have to decide the gate, elision and suggestion over the union of every shard (a cross-shard observation pass) and rewrite every shard to one layout atomically — not built; the route is to dedup each source shard and `shard create` the results, which reconciles them. **Sidecars:** an in-place rewrite changes the cohort's length, so the index and the SPSS sidecar self-invalidate; `Pulse.Dedup` reports each through `Pulse.InvalidatedSidecars` exactly as `pulse widen` does and rebuilds nothing. An `Out` rewrite reports none, because the source's sidecars still describe the untouched source. **MCP** `pulse_dedup` takes `path`, `groups` (strict `{key, members}` shape), `suggest_groups` and `out`. It deliberately has no floor, strict or elision slot — `pulse_import`'s slot policy. `format_version` does not move.

**Row-at-a-time builder — `Pulse.NewCohortBuilder`.** The public write path for a NEW single-file cohort from typed rows (`pulse.CohortRow`, the `CohortReader.RecordAt` mapping); engine `internal/io.CohortBuild` (`cohort_build.go`). It runs import's explicit-schema code for every byte-deciding step — dictionary assignment with the declared rung as a ceiling (pre-seeded entries first, then first-seen; a rejected row's provisional labels are rolled back by `stagedDict`), decimal rescale + precision, set cells, the `rowCells` layout (`cell_encode.go`), the description-length check — and, with `CohortBuilderOptions.Groups` / `ElideConstants`, import's group path: `NewGroupEncoder` declaration check + `DedupGate.ScreenWidths` at construction (an explicit schema never widens, so the screen is final and `Strict` applies at once), then at `Close` the full-pass `ConstantDetector` over the spool, `PlanConstantElision` with the admitted members reserved, ONE `GroupEncoder.EncodeStream` into a second (physical) spool, and `AssessRatios` — all before anything is published, so a `Strict` refusal leaves nothing. The version byte is `RequiredFormatVersion` of the schema written: a build whose every group was dropped and that elides nothing is the `0x01` file byte-identical to the ungrouped build. **Byte identity** with an explicit-schema `ImportJob` (same schema, `Groups`, `ElideConstants`) is gated by `TestCohortBuilder_ByteIdenticalToImport` / `TestCohortBuilder_GroupedByteIdenticalToImport` and the embeddersmoke flows; a divergence would be silent (both files read fine). **Write path:** rows spool as LOGICAL records to `<target>.build-spool-*.tmp` beside the target on the instance afero FS (dictionaries precede records, so the preamble is written last); `Close` writes preamble + spool (or the `.build-phys-*.tmp` physical spool) into `<target>.build-*.tmp`, fsyncs it, then renames it over the target; `Abort` or any failure removes every temp file and leaves the target untouched. A key violation's `source_row` is the 1-based `Append` call, remapped past rejected calls by `io.withSourceRow`. **Sidecar invalidation:** a build never touches sidecars; `Overwrite` of an existing cohort replaces its bytes, so every sidecar beside it (point-lookup index + manifest, SPSS metadata sidecar) self-invalidates through its own fingerprint, and the facade reports them on `CohortBuildResult.InvalidatedSidecars` through the same `Pulse.InvalidatedSidecars` scan `Pulse.Dedup` uses (an enumeration failure is a warning, never an error). Refused: an anchored (`#`) target, a `.zst` target, parent groups inside the schema (declare them in `Groups`).

**Wide-set word order — `set_u128` / `set_u256`.** A wide set field's payload is a fixed-width bitmask of 16 or 32 bytes, read and written ONLY through `encoding.SetMask` and its wire API (`PutSetMask` / `SetMaskFromBytes`, `WriteSetMask` / `ReadSetMask`); the `uint64` value API `Read/WriteFieldValue` REFUSES both rungs with `ENCODING_TYPE_MISMATCH` rather than truncate to the low 64 bits. **The word order is normative: `words[0]` is bits 0–63 — the LOW 64 bits — then `words[1]` bits 64–127, `words[2]` bits 128–191, `words[3]` bits 192–255, laid down on the wire in that order (little-endian WORD order) with each word itself little-endian.** The payload is therefore exactly the little-endian byte image of the 128- or 256-bit integer, and **the low 8 bytes of a `set_u128` are byte-identical to a `set_u64` payload carrying the same selections** — the property that makes a narrow→wide rung promotion a pure append of zero bytes. Reverse either the word order or the intra-word byte order and every cohort written since the wide rungs landed decodes as a different, plausible-looking selection: no length changes, no checksum moves, nothing errors. Bit `i` ↔ dictionary entry `i` exactly as on the narrow rungs; an empty mask is a valid "no selection" distinct from null; nulls ride the per-record bitmap alone with no in-band sentinel, so a null row still carries (and every decoder still consumes) its full 16 or 32 payload bytes. A bit at or above `FieldType.MaxSetEntries()` is `ENCODING_INVALID` on write and, on the shard dict-remap rewrite path, `PULSE_SHARD_DICT_WIDTH_OVERFLOW`. Three places state this one contract and none may drift from the others: the `encoding.SetMask` doc comment (normative), this paragraph, and `skills/type-set-u128.md` / `skills/type-set-u256.md` (Bytes). In memory the hand-off type differs by rung and that difference is load-bearing: the narrow rungs (`set_u8`..`set_u64`) reach the decode wide map as a `uint64`, the wide rungs as a `SetMask` — a `uint64` there would carry only the low word. The `values` float64 echo for a wide rung is the low 64 bits and is DELIBERATELY lossy (two masks differing only above bit 63 echo the same number); it exists so a set field is never absent from the values map, and the `SetMask` is the authority. Detail: `skills/cohort-schema-design.md` (Field-type matrix (all 20)) + `skills/cohort-width-overflow.md` (Width overflow).

**Temporal word sign — `date` int32 / `datetime` int64.** The 4-byte `date` word is a two's-complement SIGNED int32 epoch-day count and the 8-byte `datetime` word a two's-complement SIGNED int64 epoch-second count — pre-1970 values are negative (1969-12-31 is day −1, `1969-12-31T23:59:59Z` is second −1). The bits never changed: `ParseDate` always wrote `uint32(int64 day)` and `ParseDateTime` `uint64(int64 sec)`, so pre-1970 cohorts written before the read side was fixed already hold the right words, and no format version moved. **Every reader must sign-extend, never zero-extend** — a zero-extended pre-1970 date reads as a day near 4.29e9 and fails SILENTLY (it orders after every real date, buckets into year ~11.7M, exports as a nonsense calendar date). The sites: both float decoders in lockstep (`internal/encoding` `rawToFloat64` / `decodeFixed`, pinned by `decode_plan_equivalence_test.go`), text export (`formatFieldValue`), SPSS export (`cohortNumber`), the lookup-key encoder (`numericOnWireBytes` goes through `int32`/`int64` because a float64→uint64 conversion of a negative is architecture-defined), `internal/daterange` bounds, include-from member sets, and the synth rule range. `ReadFieldValue` keeps returning raw bits; embedders interpret them with `encoding.DateDays` / `encoding.DateTimeSeconds`. An SPSS DATE column holding a pre-1970 value imports as a native `date` — only a time of day widens it to `datetime` (`PULSE_SPSS_DATE_WIDENED`). One residual: a sidecar index built on a pre-1970 `datetime` key BEFORE the fix keyed on a rounded float echo, so rebuild such an index.

**Shard set-width auto-widen.** A `pulse shard add` whose dictionary union outgrows a `set_*` field's declared bitmask does NOT refuse the shard: the field is promoted to the narrowest rung that holds the union, across the canonical `_schema.pulse` AND every shard payload already in the archive, and the merge then proceeds into a rung that fits. **A second, independent force triggers the identical promotion: the arriving shard DECLARING a different rung.** That is the case the field actually produces — a re-import of a new period infers the rung its own data needs, so a `set_u128` shard meets a `set_u64` archive with no dictionary overflow anywhere in sight, and the old behaviour refused it as `PULSE_SHARD_SCHEMA_MISMATCH` before the widen planner was ever consulted. The relaxation is ONE dimension wide and is implemented by ORDER rather than by loosening a validator: `PlanSetWidening` now runs BEFORE `ValidateStructuralCohesion` and reconciles the rungs, and cohesion then runs over the reconciled schemas as strictly as ever — which matters because `pulse shard verify` calls the same validator, and an archive whose shards really do carry different strides is a corruption signature that must stay fatal there. **The target rung is never narrower than either side declared.** A shard arriving at a NARROWER rung is promoted to the archive's rung and is the only payload rewritten; narrowing the archive to meet it would drop every selection above the target's ceiling, and would do so silently — the record still decodes, to a smaller, entirely plausible selection. `SetWidening.From != To` is the caller's test for "the archive moved"; equal means only the arriving shard did, and the mandatory warning's prose and its `details.archive_widened` both say which. **`CreateShardArchive` auto-widens on exactly the same conditions**, through the same planner and executor: refusing at seed while widening at add was an asymmetry with no defence, since the same two files produced an archive when fed one after the other and an error when fed together. It therefore returns a `*CreateShardArchiveResult` rather than a bare `error`, for the identical reason `AddShard` returns a result — a silent whole-archive rewrite is exactly the failure class this file exists to prevent, and the shards inside the archive are no longer byte-identical to the `.pulse` files the caller named. Refusing was the wrong trade — it forces a full re-import (re-read the source, re-infer, rebuild) to reach a layout a mechanical re-stride already produces, and the re-stride is strictly cheaper than the thing it would be avoiding. **But an expensive whole-archive rewrite that happens silently is exactly the failure class this file exists to prevent, so the `PULSE_SHARD_SET_WIDENED` warning is MANDATORY rather than advisory** — it names the field, the old rung, the new rung and the number of shards rewritten, and `Service.AddShard` returns an `*AddShardResult` rather than a bare `error` specifically so the warning has nowhere to be dropped. The planner is `encoding.PlanSetWidening`, which answers the question `MergeDictUnion` structurally cannot (nothing at the schema layer may perform an archive-wide byte rewrite); the executor is E4-S1's engine — `encoding.WidenSetFieldBytes` per shard payload and `encoding.WidenSchemaSetField` for the canonical block, which share ONE offset derivation (`widenFieldOffsets`) so the canonical schema block and every shard's own schema block describe the identical post-widen layout by construction rather than by agreement. A divergence there would not fail to open: it would decode every field after the widened one at the wrong offset, with the schema confidently describing a stride the records do not have. **A union above `set_u256` stays fatal `PULSE_SHARD_DICT_WIDTH_OVERFLOW`** — 256 is the hard ceiling and there is nowhere left to widen to; that is the one set-width overflow auto-widen does not remove. `PULSE_SHARD_DICT_DIVERGENCE` in `pulse shard verify` is untouched, and CATEGORICAL widths are untouched too: a categorical's width is fixed at folder creation by contract and its capacity is not a per-record bitmask the same rewrite widens. Atomicity is the whole safety argument, because concurrency here is caller-owned and no lock is added: the rebuilt archive is staged to a temp file beside the original, fsynced, and only then renamed over it (`service.atomicWrite`), so a mid-rewrite failure leaves the original byte-identical and openable at its old rung rather than half-widened. `aggregate_record_count` and `shard_count` in the SHRD trailer are recomputed from the widened payloads, so the trailer is correct after the re-stride, and the `archive.pulse#shard.pulse` anchor opens a widened shard as a one-shard cohort unchanged. Foresight is `VerifyShardArchive`'s `SetWidthHeadroom` (`pulse shard verify`, `--json` `set_width_headroom`): per set field, entries used, bitmask capacity, remaining headroom, and the rung a widen would promote to — empty `next_type` meaning the widest rung, where an overflow is fatal rather than widenable. The sidecar point-lookup index and the SPSS metadata sidecar are NOT updated by a widen; both invalidate themselves through their own size+mtime fingerprints on the next read, and rebuilding them is the caller's business. **That is a REPORTED fact rather than an unmentioned one**: the risk here was never stale data — a widen always changes the cohort's LENGTH, and a size mismatch is the one conclusive staleness verdict both fingerprints carry — it was silent BREAKAGE, a corpus that simply stopped answering lookups with nothing having said why. `pulse widen` therefore names every sidecar it invalidated and the exact command that rebuilds it (`data.invalidated_sidecars` on the `--json` arm, structured rather than prose; nothing at all on either arm when there are none). Discovery goes through each sidecar's own naming authority — `Pulse.ListIndexes` over the `cohort.pulse.indexes.json` manifest for indexes, `spss.SidecarPath` for the SPSS document — never a filename glob, because an index's filename is a HASH of its key tuple and the rebuild command needs the tuple back. **No automatic rebuild**, deliberately: it would attach unbounded work to a bounded metadata operation with no way for the caller to decline. `pulse dedup` reports the same way (`Pulse.Dedup`, above). Library surface: `Pulse.InvalidatedSidecars` / `pulse.StaleSidecar`. `pulse shard verify` uses the same `ValidateStructuralCohesion` and must keep refusing a genuinely mixed-stride archive; `PULSE_SHARD_SET_WIDENED` is mandatory because an expensive archive-wide re-stride that happens silently is indistinguishable from a cheap append. Detail: `skills/cohort-schema-design.md` (Sharded cohorts) + `skills/cohort-sharding.md` + `docs/src/internals/managing-shard-archives.md`.

**Shard archives with parent groups — `0x02` shards.** Every shard of an archive is decoded with the CANONICAL schema (`shard_iter`, the parallel shard reducer, profile, filter-to-file), so a grouped archive has exactly ONE group layout — group count, kinds, members and key flags — and every shard's per-row indices address the canonical group dictionaries. `ValidateStructuralCohesion` therefore compares the group layout too (`encoding.ValidateGroupCohesion`, `details.dimension`): it decides the physical stride, and a `0x01` shard in a `0x02` archive, or the reverse, is `PULSE_SHARD_SCHEMA_MISMATCH` in `pulse shard verify`. Group dictionaries follow the append-only prefix rule byte for byte (`ValidateDictPrefixRule`: a stored shard's entries are the archive's first entries in the archive's order, else `PULSE_SHARD_DICT_DIVERGENCE`). **The merge** (`internal/service/shard_groups.go`, `mergeShard` — the ONE routine create and add share, so the same two files produce byte-identical archives either way, `TestShardGroups_CreateAndAddAgree`): (1) work on LOGICAL rows — the arrival is flattened (`encoding.FlattenCohortBytes`, byte-identical to its `0x01` original) and reconciled exactly as an ungrouped shard (set-rung plan BEFORE strict field cohesion, categorical union, remap), because every one of those speaks logical offsets; the remap keeps NULL placeholders (`RewriteShardCategoricalsKeepNulls`), because a null's bytes are part of an entry's identity and a remapped placeholder would make an identical `(key, null)` tuple a different entry — a spurious `PULSE_GROUP_MEMBER_NOT_CONSTANT` on a keyed group; (2) the ARCHIVE's layout wins: an ungrouped archive stores a grouped arrival as its `0x01` twin (byte-identical to adding that twin), a grouped archive re-encodes an arrival with another layout (or none) into its own — adopting the arrival's layout instead would turn an append into an archive-wide rewrite that can FAIL on data already accepted; (3) group dictionaries union-merge canonical-first — the `GroupEncoder` is SEEDED with the canonical dictionaries (`GroupEncoder.Seed`), so every stored shard's entries keep their indices, stored shards are untouched, and only the arrival is renumbered (no warning, exactly as a categorical union has none); a union past the u32 index space (`MaxGroupEntries`) is `PULSE_SHARD_DICT_WIDTH_OVERFLOW` naming the shard and `capacity`, never a wrap; (4) a CONSTANT group the arrival disagrees with is PROMOTED to an indexed group across the whole archive — every shard re-encoded with fresh dictionaries in archive order, each row gaining a 4-byte index — while a declared KEY the arrival violates (same key, different non-key member) is REFUSED with `PULSE_GROUP_MEMBER_NOT_CONSTANT` (`details.shard`, `details.field`), exactly as import refuses it: a key is a contract; (5) strict cohesion runs over the reconciled GROUPED schemas last. A set-rung widen of a grouped archive also re-encodes every shard (a member's rung moves the entry width) and is reported by `PULSE_SHARD_SET_WIDENED`. **Mandatory warning:** every layout change — `incoming_flattened`, `incoming_regrouped`, `constant_promoted` — emits `PULSE_SHARD_GROUPS_REWRITTEN` (`details.reason`, `archive_rewritten`, `shards_rewritten`, `records_rewritten`, `groups`) and a typed `GroupReconciliation` on `AddShardResult.Regrouped` / `CreateShardArchiveResult.Regrouped` (`data.regrouped` on the `--json` arm, present only when non-empty), for the reason `PULSE_SHARD_SET_WIDENED` exists. The rewrite is the same atomic temp + fsync + rename. **Foresight:** `VerifyShardArchive`'s `GroupIndexHeadroom` (`--json` `group_index_headroom`, grouped archives only): per group, entries, capacity (the u32 space; 1 for a constant group) and headroom — a constant group always reports 0, because its next distinct value promotes it archive-wide. **Readers:** the anchor form opens a stored grouped shard with its own schema (its dictionary is a prefix of the canonical one, so its indices are valid in it); filter-to-file copies physical rows by position and carries each shard's preamble; the parallel shard reducer hands each record its entry indices (`SetGroupIndices`) so the filter precompute engages on both archive arms; inspect's archive arm reports the CANONICAL groups over the archive-wide record count (ratio = total records ÷ canonical entries, header-only). `pulse dedup` still refuses an archive (Retro-dedup, above). Gates: `internal/service/shard_groups_test.go` (`TestShardGroups_*`), `internal/encoding/shard_groups_test.go`.

**Sidecar point-lookup index.** `Pulse.Lookup` / `pulse index build` / `pulse api lookup` are backed by a **separate file** next to the cohort — `cohort.pulse.<keyhash>.idx` — never the `.pulse` layout above. Format **v3** (own magic + version, distinct from `encoding.MagicBytes`/`FormatVersion`): 9-byte header (magic `PULSEIDX` + version `0x03`) → 32-byte SHA-256 source fingerprint → key-spec (ordered key columns + types) → `SourceSize` (u64) + `SourceModTime` (i64 Unix ns) → `u32 bucket_count` → fixed-width `bucket_count × u64` bucket-offset table → self-delimited bucket data (FNV-1a hash buckets → `[]uint64` row-id multimap). The fixed-width offset table makes one bucket directly addressable — a lookup hashes the key, seeks to its offset entry, seeks to that bucket's data, then seeks straight to each matched record via `RecordLocator`; never a full-cohort or full-index read (O(1) flat, measured ~5µs across 10k→1M rows vs. linear unindexed scan). **Read-path staleness has THREE outcomes, not two, and the middle one is the whole contract.** A **size** mismatch is an instant `PULSE_INDEX_STALE` with no hash, and it is CONCLUSIVE rather than merely cheap — the fingerprint covers the whole file, so a different length cannot produce the recorded digest. A full size+mtime **match** is served hash-free: that is the O(1) property the sidecar exists for. An **mtime that moved while the size held is NOT staleness** — it escalates to the sidecar's own SHA-256 (`service.classifyIndexFreshness`, shared by `Lookup` and `VerifyIndex` so the two cannot drift on which stat differences count as evidence) and refuses only if the content genuinely differs. Refusing on drift alone was wrong in the one direction that matters: `SourceModTime` is Unix NANOSECONDS, an S3 `LastModified` is whole SECONDS, and every copy, restore and cache hop truncates somewhere of its own choosing, so a cohort read through a bucket had its byte-identical index refused PERMANENTLY rather than transiently and point lookup could not work there at all (measured: a 2 ms truncation on an external drive, size identical, six trailing zeros on the mtime). The `encoding.Index` doc comment already promised the fingerprint as the authority for a stat MATCH; this applies the same authority to the one other case it can answer. **The escalation is memoised per `(cohort path, size, mtime)`** (`Service.fingerprints`, bounded at `cohortFingerprintCacheCap` 1024 with a clear-on-overflow flush), because bucket mtime drift is PERMANENT, not transient — without the memo the fix would trade a hard failure for an O(cohort) read on every lookup, silently losing the property the feature is built on, and a multi-GB cohort would hash per call. The memo assumes exactly what the existing stat fast path already assumes (same path + size + mtime ⇒ same bytes) and so adds no freshness gap. **`VerifyIndex` WRITES that memo and never READS it** — its whole job is the answer that does not rest on a stat pair, so serving it from a cache keyed on that pair would hollow it out, while a digest it just computed is as true as one `Lookup` computed. `verify` therefore always hashes when the size matches; its `stat_mismatch` reason is now a SIZE verdict, mtime drift lands on `fingerprint_match` / `fingerprint_mismatch` with the additive `VerifyIndexResult.ModTimeDrift` (and `--json` `modtime_drift`, `omitempty`) reporting that the stat pair disagreed and the hash overruled it. The residual gap is unchanged and still deliberate: an in-place edit preserving BOTH size and mtime passes `Lookup` and is caught only by `verify`.

**Sidecar index MANIFEST — `cohort.pulse.indexes.json` (`internal/encoding.IndexManifestSuffix`).** A THIRD file beside the cohort, JSON and not a `.pulse` layout, written by `pulse index build`. It exists because `SidecarIndexPath` derives an index's filename from a HASH OF ITS ORDERED KEY TUPLE, so **the file cannot be opened without already knowing the thing a caller is trying to learn**, and key order is significant so guessing is a permutation search. The tuple IS recorded inside the sidecar (`IndexMeta.Keys`), so on a local disk the escape is to glob `<cohort>.*.idx` and read each match — **but object storage cannot list a directory**, which is where cohorts are actually served from, so a bucket caller has neither the hash nor a listing and cannot discover an index at all. Document shape: `{format_version, kind, cohort, indexes:[{index_path, key_hash, keys:[{name,type}], distinct_keys, indexed_records}]}`, with `index_path` / `cohort` as BASENAMES so the document survives the corpus being moved or synced, and the counts recorded at build time **so a listing served from the manifest reads NO sidecar bucket table** — one GET plus one existence probe per entry, instead of downloading every index to answer "which indexes exist". `format_version` is the manifest's OWN (`"1"`), independent of both `encoding.FormatVersion` and `IndexFormatVersion`, so adding a field to it can never force a cohort or index rebuild. Wiring: `BuildIndex` upserts its entry (and SEEDS the document from the directory listing when creating it, best-effort, so the first build after an upgrade does not publish a manifest naming only itself); `DropIndex` prunes the entry, and prunes an ORPHANED entry as a successful drop rather than `PULSE_INDEX_MISSING` — that is the repair path, and without it a stale manifest could not be repaired by any command; `ListIndexes` reads the manifest FIRST and UNIONS any on-disk sidecar it does not name (so a pre-manifest sidecar does not vanish the day a manifest appears beside it), tolerating a failed directory listing only when the manifest answered. **An absent manifest is the ordinary pre-upgrade state and falls back to the directory listing; a manifest that EXISTS and cannot be parsed is `PULSE_INDEX_MANIFEST_INVALID`, never a silent degrade to that listing** — the degrade SUCCEEDS on a local disk and answers "this cohort has no indexes" on a bucket, which is precisely the backend-dependent divergence the manifest removes. A manifest naming a sidecar that is not present is `PULSE_INDEX_MANIFEST_STALE` rather than a skipped entry, because a listing reporting two indexes for a manifest claiming three is indistinguishable from a correct answer. It is one of Pulse's own `*.json` sidecars and therefore rides `isPulseSidecarName` — a `PULSE_LABEL_TABLES_DIR` / `PULSE_RANGE_TABLES_DIR` walk must skip it by suffix or `pulse.New` fails on a file Pulse wrote. `BuildIndexResult.ManifestPath` / `--json` `manifest_path` name it. `format_version` (the envelope's) does NOT move: nothing here is payload-reachable. **Keyable-type policy** (`processing.IsIndexKeyableFieldType`): ALLOW `u4`/`u8`/`u16`/`u32`/`u64`, `f32`/`f64` (raw bit-pattern equality — `-0.0`/NaN caveat), `date`, `datetime` (signed epoch seconds; literal resolves through `encoding.ParseDateTime`, never `ParseFloat`; exact within ±2^53 s, pre-1970 included), `decimal128` (exact mantissa, no float round-trip), `categorical_*` (dictionary ID), `packed_bool`. REJECT `set_*` (a multi-select bitmask has no single unambiguous equality value — use `FILTER_SET` instead). Single-file cohorts only: shard archives → `PULSE_INDEX_UNSUPPORTED_SHARDED` (the `archive.pulse#shard.pulse` anchor is a tested single-shard workaround). Equality-only, full-key required, composite-key order significant end to end. Coded errors: `PULSE_INDEX_MISSING`, `PULSE_INDEX_STALE`, `PULSE_INDEX_UNSUPPORTED_SHARDED`, `PULSE_INDEX_MANIFEST_INVALID`, `PULSE_INDEX_MANIFEST_STALE`, `PULSE_LOOKUP_NOT_FOUND`, `PULSE_LOOKUP_AMBIGUOUS`. Detail: `skills/cohort-sidecar-index.md` (Sidecar index) + `skills/tool-lookup.md`.

**SPSS metadata sidecar.** An SPSS import writes a SECOND sidecar next to the cohort — `cohort.pulse.spss.json` (`spss.SidecarSuffix`, the `imports.Sidecar` "suffix appended to the cohort filename" convention; deliberately distinct from `imports.SidecarSuffix` `.meta.json`, which a managed import writes for the same cohort). JSON, not a `.pulse` layout. It holds every dictionary element the `.pulse` byte format has no slot for: measure levels, print/write format codes, records `7/17` file attributes and `7/18` variable attributes (kept distinct), record `6` documents, weight variable, compression bias, `nominal_case_size`, original short names, declared byte widths + `7/14` very-long-string segmentation, MR/MC set definitions, `7/5` variable sets, the source charset **in the file's own declared spelling**, product name, missing-value specs in all three shapes (discrete ≤3 / range / range-plus-one-discrete, raw 8-byte slots retained verbatim), and — the load-bearing payload — the `code ↔ label ↔ Pulse dictionary ID` triple per categorical column, since the cohort dictionary holds SPSS **codes** and this is the only place the **labels** live. Document shape: `{format_version, kind, fingerprint, payload}`. **`payload` is flat and self-contained** (no paths, no offsets, no external references) so it can be lifted verbatim into a future `.pulse` schema metadata block — that block is **deferred, not rejected** (it needs a `FormatVersion` `0x01` → `0x02` bump affecting every Pulse user), and this shape is what keeps the door open. `fingerprint` is the only file-bound part and a lift drops it: 32-byte SHA-256 + `SourceSize` (u64) + `SourceModTime` (i64 Unix ns) over the **`.pulse` cohort** (not the source `.sav`), mirroring the sidecar index's size+mtime staleness snapshot. Read-path policy, implemented at `spss.LoadSidecar(fs, cohortPath, spss.WriterOptions{})` (the write side's first act, reached from `pulse export spss`): **absent → warning** `PULSE_SPSS_SIDECAR_ABSENT` and the caller synthesises a default dictionary from the `.pulse` schema (a cohort that was never SPSS-derived correctly has none), **stale → error** `PULSE_SPSS_SIDECAR_STALE` (a stale dictionary over changed data produces a file that looks authoritative and is wrong — a refusal returns NO `SidecarResolution`, so there is no shape in which a caller reaches the stale document), **present-but-unreadable → error** `PULSE_SPSS_SIDECAR_INVALID` (foreign `kind`, unrecognised `format_version`, malformed digest, or a broken `multiple_response_sets[].fields` parallel array). The staleness check is a cheap O(1) size+mtime comparison with the same residual gap `PULSE_INDEX_STALE` has (a size- and mtime-preserving in-place edit) — but it is **no longer the same rule**: the index read path now treats an mtime that moved while the size held as inconclusive and escalates to the fingerprint, while this one still REFUSES there, so a `.sav` export of a cohort read through a filesystem that does not preserve nanosecond mtimes hits `PULSE_SPSS_SIDECAR_STALE` where a lookup would now succeed (`--ignore-sidecar` is the blunt escape). That asymmetry is not a considered position, only the untouched half: `Document.VerifyDigest` already exists and is the same authority the index escalates to. `Document.VerifyDigest` is the authoritative full SHA-256 recompute for a verify-style pass. `spss.WriterOptions{IgnoreSidecar: true}` (`--ignore-sidecar`) suppresses the sidecar READ entirely — not merely the staleness verdict — so a healthy sidecar is ignored too and an unreadable one cannot block; it downgrades both refusals to a `PULSE_SPSS_SIDECAR_IGNORED` warning on the same synthesise-a-default path, and never applies a stale dictionary. That warning deliberately does not report which refusal it silenced — skipping the read means nothing on that path knows. `MRSet.Fields` is additive under `omitempty` and `SidecarFormatVersion` did not move for it, so an ABSENT `fields` key means “written before the slot existed” and is back-filled by `Document.Normalise` from `variables[].short_name` (case-insensitive, first declaration wins), never rejected; a PRESENT one of the wrong length IS rejected. Written via `afero.Fs` + `encoding/json` through the optional `io.SidecarEmitter` interface, which `ImportJob.Run` calls after the cohort write; a source not implementing it yields a byte-identical import and no sidecar. Detail: `skills/spss-metadata-sidecar.md` + `skills/spss-response-sets.md` (the derived-column registry) + `docs/src/cli/import-spss.md` + `docs/src/internals/adding-io-format.md`.

**SPSS derived columns.** An SPSS import can produce a cohort WIDER than the source dictionary — count columns from the returned schema, never from the SPSS variable count. Two synthesised kinds, both **additive**: a `<var>_missing` `categorical_*` sibling immediately after every numeric variable declaring user-missing values (the null bitmap is one bit and cannot record *why*, so the reason must be materialised as data), and one `set_*` bitmask per multiple-DICHOTOMY response set immediately after its LAST constituent (never instead of the constituents — a bit cannot separate "not selected" from "not asked"). The asymmetry with the CATEGORICAL arm is deliberate and must not be "fixed": a categorical column already stores the SPSS code as a dictionary entry, so the code is preserved losslessly and a sibling would double the width of an all-categorical survey; those entries are FLAGGED instead (`variables[].categories[].missing` on the sidecar + one per-FILE `PULSE_SPSS_CATEGORICAL_USER_MISSING` diagnostic). `--spss-missing=null` / `spss.WithMissingMode` suppresses the numeric siblings only; the `set_*` column has no opt-out. Every synthesised column is registered on the sidecar's `payload.derived` (closed `kind` vocabulary — `spss.DerivedKinds()` / `spss.DerivedFoldFor`; a cohort that derived nothing writes `"derived": []`, never a missing key), so the export folds them mechanically rather than by name-matching. Detail: `skills/spss-response-sets.md` + `skills/spss-missing-values.md`.

**SPSS export.** `pulse export spss -i cohort.pulse -o out.sav` (and `pulse convert x.csv out.sav`) writes `.sav`; `descriptor.importCapability()` carries `Export: true` for `spss` and `exportCapability()` its `warn_and_skip` overlay entry — `TestManifestImportCapability_ExportFlagMatchesExportBlock` fails if only one moves. Four per-command flags, one per `spss.WriterOptions` field: `--ignore-sidecar`, `--uncompressed`, `--charset`, `--sanitize-names`. The `.sav` writer is a **`pio.CohortWriter`**, the one optional writer interface that replaces the row loop rather than decorating it: `ExportJob.Run` calls `WriteCohort(ctx, CohortSource{FS, Path, Includes, Labelled})` after `SetPulseSchema` + `WriteHeader` and never calls `WriteRow`, because a `.sav` value is derived from a categorical's dictionary ID, a `set_*`'s mask bits and the null bitmap — all three erased by `formatFieldValue`'s rendering (a null and an empty string categorical become the same cell). The mask reaches the encoder as an `encoding.SetMask` at EVERY rung and never as a `uint64`: `readCohortCase` takes `set_u128` / `set_u256` through `encoding.ReadSetMask`, because `ReadFieldValue` refuses them, and a `uint64` there would carry a 206-option battery's low word alone — every member at or above bit 64 exporting as "not selected" in a perfectly well-formed `.sav`. A set member variable's bit is bounded against ITS OWN rung inside `NewDataEncoder`'s `checkColumns`, not on the per-case path, because a bound living per case is a refusal `ValidateCohort` cannot reach: predict would accept a cohort (a `set_u8` declaring ten dictionary entries) that the export fails on record 1. The derived multiple-dichotomy fold is keyed on `Derived.Kind` and is therefore width-blind by construction — a 206-constituent `set_u256` is dropped and its 206 constituents rebuilt exactly as a 3-constituent `set_u8` is — and the sidecar's `derived[].sources` records all 206 in BIT order, so dictionary ID `i` is constituent `i` at any width. Consequences: `ExportJob.Includes` / `Labels` are REFUSED with `PULSE_SPSS_EXPORT_UNSUPPORTED` rather than silently dropped, overlays are warn-and-skip, and a `convert` (no cohort exists) buffers rows and builds an intermediate in-memory cohort through the ordinary import path. Encode-side diagnostics ride the new `io.TargetWarningEmitter` optional interface onto `ExportReport.TargetWarnings` / `ConvertReport.TargetWarnings` (nil for every pre-existing adapter); the CLI re-reads them AFTER `Close`, because a writer that encodes at `Close` has raised none of them when the job builds its report. `PULSE_SPSS_EXPORT_UNSUPPORTED` was REPURPOSED, not retired — it now means "this cohort has no honest `.sav` form", matching E3-S2's treatment of `PULSE_SPSS_COMPRESSION_UNSUPPORTED`. Name policy: illegal names are `PULSE_SPSS_NAME_INVALID` / `_COLLISION` by default; `--sanitize-names` opts into a deterministic, collision-safe rewrite of the SYNTHESISED path only, reporting every rename as `PULSE_SPSS_NAME_SANITIZED`. Detail: `skills/spss-export.md` (Writing `.sav`) + `skills/session-format-flags.md` (Target-format CLI flags).

**SPSS convert carries the source through.** `pulse convert survey.sav out.sav` never builds a cohort on disk, so the `.sav` writer's ROW path rebuilds one in memory from the rendered text — and text is exactly where the two things a `.sav` is encoded FROM do not survive. Both now ride one channel, the optional `io.SourceAwareWriter` / `io.ConvertSource` pair (`SetConvertSource` before `WriteHeader`, type-asserted and otherwise a no-op, so every other adapter's convert output is byte-identical). **The DECLARED schema replaces inference on the rebuilt cohort**, because inference over a rendered `set_*` cell can only see the options somebody TICKED: a 206-member `set_u256` battery whose respondents chose eleven distinct options re-infers at a narrow rung and silently loses a dictionary entry per unticked member, and a value-labelled numeric loses its codes entirely — it re-derives as a STRING variable full of bare numerals, in a `.sav` that opens cleanly. **The source's metadata SIDECAR is written against the rebuilt cohort** (the source Reader's own `pio.SidecarEmitter`, re-fingerprinted by that call — the source's copy is fingerprinted over the SOURCE cohort and `LoadSidecar` would refuse it `PULSE_SPSS_SIDECAR_STALE`), which is what restores the `derived` registry: without it the writer synthesised a default dictionary, expanded the derived multiple-dichotomy column into member variables of its own, and every one collided with the constituent column already in the cohort — `PULSE_SPSS_NAME_COLLISION` refused EVERY multiple-dichotomy convert, at every width. The two are one mechanism because they fail together: a carried sidecar read against a re-inferred dictionary would attach each label to whichever code happened to appear first. Both are carried only when the emitted row stream is FAITHFUL to the schema — one cell per field, in field order, no `ConvertJob.Includes` projection and no label binding inserting or rewriting cells — since facts that do not describe the stream would bind a rebuilt cohort's columns to the wrong cells, which is the silent wrong answer rather than the loud one; an unfaithful stream carries nothing and the target infers exactly as before. `ConvertSource.Schema` is nil for a genuinely schema-less source (a CSV): there is nothing declared to preserve, inference stays the fallback, and `PULSE_SPSS_SIDECAR_ABSENT` still names the intermediate `converted-rows.pulse`. `format_version` does not move — `io.ConvertSource` is not payload-reachable. Detail: `skills/spss-export.md` (Writing `.sav`) + `docs/src/internals/adding-io-format.md`.

**Export predict is target-aware.** `ExportJob.Predict` consults the target through the optional **`io.CohortValidator`** interface (`ValidateCohort(ctx, CohortSource) ([]*errors.CodedError, error)`), the write-side peer of `CohortWriter`; diagnostics land on the new `io.PredictReport.TargetWarnings` slot (symmetric with `ExportReport.TargetWarnings`). A Target that is nil or does not implement it is predicted EXACTLY as before — no extra read, no new failure mode (`TestExportJob_Predict_NonValidatingTargetUnchanged`). `spss.Writer` is the only implementer: `ValidateCohort` runs the writer's own non-data pass (`planCohort` — sidecar resolution, `BuildDictionary`, name policy, charset transcode, derived fold, `NewDataEncoder` column checks) and discards it, so a predicted refusal is the export's own check code-for-code, and it mutates nothing on the Writer. **Sound but INCOMPLETE by design:** anything needing a record (value width overflow, cell-text charset unencodability, a dictionary ID with no source code) is unreachable, and predict must NEVER refuse what the real export would accept — a false refusal is worse than silence. `pulse export predict` reads `--format` (writer built via the `io.NewWriter` factory against a MemMapFs + throwaway path, never `Close`d, so no file is created) and mounts the four `.sav` write flags, because `--sanitize-names` flips a `PULSE_SPSS_NAME_INVALID` refusal into a warning; with no `--format` behaviour is unchanged and the text output says the target was not checked. `format_version` stays `"1.1"` — `io.PredictReport` is not payload-reachable. Detail: `docs/src/internals/adding-io-format.md` + `docs/src/cli/export-spss.md`.

**Projected buffered decode.** Per-request field projection on the buffered decode iterator is **default-on** — it is output-transparent (same result payload, only faster and lighter per-record), so callers get the win with no flags. Opt out with `pulse.Options{DisableProjection: true}` or the `--no-project` CLI flag on `pulse api process` (v1: `pulse api process` only — `process-chain` / `compose` do not expose it yet). `pulse.Options.ProjectBufferedFields` is retained but deprecated: setting `true` is a harmless no-op; use `DisableProjection` to force full-record decode. Wiring at `pulse.go`: `svc.SetProjectBufferedFields(opts.ProjectBufferedFields || !opts.DisableProjection)`. `processing.NeededFields(req, schema, ext)` walks every request slot and returns a `FieldSet`; the iterator turns retained set into a cached `encoding.DecodePlan` via `internal/encoding.BuildDecodePlan(schema, retained)`(retained)`. **A slot the walk misses, or a built-in whose `Params` name a field `addAggParamFields` does not know, fails SILENTLY** — the field is decoded onto no `Record`, `Record.NumericValue` answers `ok=false` on every row, and the operator reads a missing input rather than a broken request, so the request succeeds and publishes a confident zero with `n_null` equal to the full admitted count as the only signature. `Crosstab.MarginAggregations` is a walked slot (own `Field`, `Params` fields, and extension widening, exactly as `Crosstab.Cell`); `distinct_by` / `weight_field` / `numerator_field` / `denominator_field` are the aggregator params `addAggParamFields` covers, and a new one belongs there on the day the operator lands. Plan segments: `SkipBytes{N}` (one discard over N bytes) and `DecodeFields{Fields, Indices}` (`Indices` = each field's schema position, which keys the index-keyed reuse record — detail in `.claude/reference/execution-modes.md`). Bit-packed runs stay grouped; null-bitmap whole-or-skip. Extension operators without `FieldInputs` widen retained set to `*`. Bench: ~7× speedup, ~14× fewer allocs on a 4-field projection of a 200-field cohort. Detail: `skills/cohort-schema-design.md` + `docs/src/internals/extension-points.md` + `.claude/reference/execution-modes.md`.

**Transport-only compression — `.pulse.zst` (`pulse export transfer` / `pulse import transfer`).** NOT a layout: a transfer artifact is ONE standard zstd stream (RFC 8878, frame content checksum on) whose decompressed content is the exact byte image of a cohort — single-file `0x01`/`0x02` or a whole shard archive. Byte work: `io.TransferExportJob` / `io.TransferImportJob` (`internal/io/transfer.go`, `github.com/klauspost/compress/zstd`, already in the module graph via arrow/parquet); facade `Pulse.ExportTransfer` / `Pulse.ImportTransfer` → `*pio.TransferReport{source, output, codec, level, layout, cohort_bytes, compressed_bytes, ratio, sha256}`, where `sha256` is ALWAYS the uncompressed cohort's so sender and receiver compare directly. **Why transport-only:** compressed bytes are not addressable ranges, so compression at rest costs `record_at` / `Lookup` O(1) seek, parallel-decode stride segmentation, `RecordCountForPayload` (count from LENGTH), whole-file mmap and `Archive.OpenAt` — none of which this touches. There is deliberately **no third magic-byte variant** and archive entries stay **Method 0**: the ONLY read-side change is error classification — `encoding.ReadHeader` recognises `encoding.ZstdMagic` (`28 B5 2F FD`) and returns `PULSE_COHORT_COMPRESSED` ("decompress first") instead of `ENCODING_INVALID`, and `Service.Open`, `CountRecords`, `descriptor.Inspect` and `descriptor.Predict` keep that code rather than re-wrapping it (the managed-import pool, `imports.Manager.Open` behind `pulse_import`, sniffs the magic and refuses the same way, `.pulse.zst` or renamed `.pulse`) (`TestTransfer_CompressedCohortRefusedEverywhere` pins every facade read path). Import side is atomic (temp + fsync + rename, only after the stream decoded, its checksum held and the decoded prefix is a Pulse magic), refuses an existing output without `Overwrite`, and every refusal is `PULSE_TRANSFER_INVALID` with `details.reason` ∈ `level` / `not_a_cohort` / `already_compressed` / `not_zstd` / `corrupt_stream` / `output_exists`. Both directions stream in bounded memory (`TestTransfer_BoundedMemory`: peak heap flat across a 12× larger file). Interop is two-way with the stock `zstd` CLI. **Deliberately NOT:** an io factory `Format` (`io.FormatFromPath` maps no `.zst`; it is not a tabular format, so `import auto` / `convert` do not see it), a gzip codec, or an MCP tool — moving a cohort between machines is an operator act, and by the `ImportIn` slot policy a slot earns its place only when it is an agent's sole route to a result; an agent that meets an artifact gets `PULSE_COHORT_COMPRESSED` naming the CLI fix. Composition with parent groups: the two SUBSTITUTE on bytes (both remove the repeated parent block) — on a sorted cohort flat+zstd lands within ~5% of grouped+zstd, on a scattered one grouping still wins ~38% over the wire; grouping's at-rest scan and memory wins are what compression never buys. Detail + bench table: `docs/src/format/transfer.md`.

**Table-directory sidecar exclusion — `PULSE_LABEL_TABLES_DIR` / `PULSE_RANGE_TABLES_DIR` (relocated from CLAUDE.md "Build / Env").** Both table directories exclude Pulse's own sidecars by suffix BEFORE any parse attempt — `.spss.json`, `.meta.json`, `.indexes.json`, the list at `isPulseSidecarName` in `sidecar_names.go` — so a cohort's sidecars can share a directory with its tables. **That is an exclusion of KNOWN artefacts, not tolerance of unparseable JSON:** any other `*.json` that fails to parse is still a hard `pulse.New` error naming the path, because a typo'd table must not silently become a table that is not there. A new sidecar suffix joins `isPulseSidecarName` in the same change. `PULSE_TEMPLATES_DIR` does **not** carry the exclusion (`.claude/reference/request-templating.md`).
