# Request templating — the `internal/template/` document model

A request template is stored, parameterised JSON that `internal/template/` renders into a **validated typed request**. It is a **library / embedding surface only: no CLI leaf, no MCP tool.**

Load it before changing the request-template document model (`template.Template` / `Variable` / `Summary` wrapper keys), the variable type set (`template.AllVarTypes`), the target set (`template.AllTargets`), or the substitution syntax (`$var` / `{{}}` / `$when`). Companions for such a change: `skills/request-templating.md` and `docs/src/library/request-templating.md`.

## The contract

**Not expr-lang.** `$var` / `{{}}` / `$when` are *request-authoring* parameters substituted **before** decode; `ATTR_FORMULA` / `FILTER_EXPRESSION` are expr-lang over *row fields* at execution time. A formula cannot see a template variable, and the renderer never splices text into an expression: a `{{token}}` inside an expression-bearing string is refused `PULSE_TEMPLATE_EXPR_SPLICE` (see Substitution, form 2). **Params carry values into expressions; templates never splice text into them** — a template fills the request's `params` with a type-preserving marker (`"params": {"from_wave": {"$var": "from_wave"}}`) and the expression reads `params.from_wave` (contract: `.claude/reference/execution-modes/filters-and-expressions.md`; skill `skills/request-params.md`).

**Import ceiling and facade.** `internal/template/` is the whole implementation and imports stdlib + `types` + `errors` only, plus the stdlib-only `internal/returnplan` reached via `types`, the stdlib-only strict decoder `internal/strictjson`, and the stdlib-only expression-slot list `internal/exprslots` — never `descriptor/`, `internal/processing/` or `internal/service/` (`TestTemplatePackage_ImportBoundary`). The facade is `ListTemplates`, `GetTemplate`, `RenderTemplate`, `RenderTemplateRequest`, `ReloadTemplates`; there is no CLI leaf and no MCP tool. Skill `skills/request-templating.md`; docs `docs/src/library/request-templating.md`.

**File wrapper.** `{"name"?, "description"?, "target", "variables"[], "body"}`; **unknown top-level keys rejected** (a typo'd `"varaibles"` yielding zero variables is the silent failure this feature exists to kill). `target` ∈ `request | composed | chain | facet | sample` (lowercase) selects the strict-decode root — one of the five `types` request roots — required, never inferred. `name` derives from the file path (path relative to its own root, minus `.json`, forward-slash separated); a `name` key disagreeing with the path is rejected. `body` is a non-empty object, deliberately **not runnable as-is**.

**Substitution — three forms, no expression language.** (1) Slot marker `{"$var":"bucket"}` — a marker **iff** `$var` is the only key and its value a non-empty string; replaced whole and **type-preserving** (`{"interval":{"$var":"bucket"}}` → `{"interval":10}`, never `"10"`). `{"$var":"x","other":1}` is literal data; substituted values are spliced as data and never re-walked. (2) String sugar `"{{name}}"` — inside a **string value** only, `{{ name }}` tolerated, `{{{{` escapes a literal `{{`; `list`/`period` have no text form → `PULSE_TEMPLATE_VAR_TYPE`; `{{` in an object **key** is rejected at validation. **Never inside an expression:** a `{{token}}` in an expression-bearing string slot — matched by `internal/exprslots.Match` on the string's key path, array indices dropped: an `expression` (filterer, attribute, `total()` argument, a params-borne `fit_on` / centroid `filter` list), a `holdout`, an `overlays[].params.formula`, a `features[].params.fit_on` (FEAT_TARGET_ENCODE's row expression); a key directly under a `params` object is data and never matches — except an embedder extension's expression-capable key (`ParamMeta.Expression`): `params.<key>` of an object whose literal `type` names an operator flagging `<key>` on this instance, slot `extension_param`, handed in as plain data (`ValidateOptions.ExprParams` via `ParseWith` / `NewStoreWith`, filled by the facade from the visible extensions, so the import ceiling is unchanged; a `type` that is itself template syntax — an interpolation or a `$var` marker — is judged conservatively against every key ANY visible operator flags, the refusal carrying `details.type_templated: true`) — is `PULSE_TEMPLATE_EXPR_SPLICE` (author provenance, raised by the declaration `bodyScan`, so at `pulse.New()`; details `template`, `variable`, `path`, `slot`). **Axis tokens too:** a `for_each` / `sweep` axis token in an expression slot is the same refusal, `variable` = the axis name — that expansion would splice the axis value's text exactly as the renderer would a variable's. Still legal there: a whole-value `{"$var": "f"}` marker and the `{{{{` escape. A REQUEST carrying the same token (no template involved) is refused by the expansion itself, before any substitution and identically by predict and the runtime, under request provenance: `PULSE_SWEEP_EXPR_SPLICE` (`internal/sweep.Expand`'s reference scan) and `PULSE_FOR_EACH_EXPR_SPLICE` (`ExpandItems`, scanning the item nested under its list key so `features[].params.fit_on` matches); details `field`, `placeholder`, `slot`; parity `TestExprSplice_PredictRuntimeParity` (root). The slot list is shared with the engine: `internal/exprenv`'s `Site*` compile-site nouns are `exprslots` constants and the OVERLAY_FORMULA key is `exprslots.OverlayFormulaParam`; gates `TestTemplateExprSplice_CompileSitesShared` (`internal/exprenv`), `TestTemplateExprSplice_SlotsCoverRequestRoots` (`internal/exprslots`), `TestTemplateExprSplice_EngineExprSlotsMatch` (`internal/vectors`), `TestTemplateExprSplice_FeatureFitOnSlot` (`internal/targetencode`). A new expression slot is declared in `internal/exprslots` first. (3) Guard `{"$when":"segs",…}` — block survives iff the variable resolved; key stripped either way. **Presence, not truthiness**: supplied `""`/`[]`/`0`/`false` KEEPS the block; it drops only when unsupplied AND undefaulted. Guards evaluate **before** descent, so markers inside a dropped block never raise. Array drops compact the slice (a `null` hole would decode to a nil operator slot); root-level `$when` errors. **`for_each` items.** An object carrying a `for_each` object whose `axes` list literal `name`s scopes those names over its OTHER keys: inside, a `{{axis}}` token (re-emitted as `{{axis}}`, spacing normalised) or a `{"$var":"axis"}` marker naming one of them passes through untouched for the item's own expansion (`internal/sweep.ExpandItems`, run by every request surface after render); template variables substitute everywhere else, including beside the axis tokens and inside the `for_each` value itself (walked in the enclosing scope, so `"values":{"$var":"decays"}` supplies an axis list). The rule is structural on the JSON tree — `internal/template/for_each.go` — because `internal/sweep` imports this package, never the reverse, and the import ceiling holds. Both walks (declaration `bodyScan`, render) thread the same scope. An axis `name` spelled as template syntax (`{{…}}` or a lone-`$var` object) is `_INVALID` (the scope must be known before any variable resolves); a declared variable sharing an axis's name is `_AXIS_COLLISION` at declaration (details `variable` = the name, `path` = the axis name's body path). The `{{{{` escape still renders a literal `{{` inside an item. **`sweep`.** The same rule one level down: an object carrying a `sweep` object whose `axes` list literal `name`s scopes those names over the sweep's `request`, `overlays` and `label` ONLY — `axes`, `mode` and `rank` walk in the enclosing scope (so a variable supplies `values`), and an explicit `requests[i]` slot never sees them. Literal-name (`_INVALID`) and `_AXIS_COLLISION` rules are shared (details `path` = `body.sweep.axes[i].name`); `internal/sweep.Expand` resolves the surviving placeholders.

**Nine variable types** (`template.AllVarTypes()`): `string`, `number`, `integer` (`1.0` yes, `1.5` no), `boolean`, `field` (a string; no cohort binding), `enum` (+`values`, exact + case-sensitive), `list` (+`items`, scalar element types only — lists do not nest), `date` (only `YYYY-MM-DD`, a strict subset of `encoding.DateFormats`; `03/04/2024` is ambiguous), `period` (exactly one of `ranges` XOR `table`, mirroring the `GROUP_DATE_RANGES` / `FILTER_DATE_RANGES` `Params` shape; unknown keys in it or in a `{label,start,end}` range rejected). The six scalars (`string`/`number`/`integer`/`boolean`/`field`/`date`) are the legal `items` values. **Root spellings:** every target and variable type is re-declared at the facade as `pulse.TemplateTarget<Name>` / `pulse.TemplateVar<Name>` (equal to the internal value); a new internal value without its root constant fails `TestTemplateConstants_RootSetComplete`, so add both together. Per-declaration slots: `required` (legal together with `default` — the default resolves it, so it can never go missing), `default` (raw JSON, so integer fidelity survives; explicit `null` = no default), `description`.

**Directory precedence.** `Options.TemplateDirs []string`, else `PULSE_TEMPLATES_DIR` split on `os.PathListSeparator` — the programmatic option wins outright and suppresses the env var entirely. Roots are an **ordered precedence list; first root wins**. A same-named template under a later root is **shadowed, not rejected**, and the losers land on the winner's `Summary.Shadows` rather than being discarded (shadowed entries get no summary of their own — a listing whose entries cannot all be fetched would be a trap). Blank root → skipped; missing root → skipped; root that exists but is a **regular file** → error naming the path. **Filesystem faults are `DATA_FILE`**, deliberately outside the `PULSE_TEMPLATE_*` family. The store reads through an `afero.Fs` (`template.NewStoreWith(fsys, …)`): `Options.FS` when set, else `afero.NewOsFs()` — never the `DataDir`-rooted instance Fs, because template roots are host paths outside the data directory (`templateFs` in `template_loader.go`). No direct `os` filesystem call in `internal/template/` non-test code. With `PULSE_TEMPLATES_DIR` unset and no `TemplateDirs`, no store is built and every lookup is `PULSE_TEMPLATE_NOT_FOUND`.

**Sidecar exclusion.** Like the label-, lookup- and range-table loaders, the store's walk skips Pulse's own `*.json` sidecars unread (`isPulseSidecarName`, injected as `template.ValidateOptions.SkipName` because `internal/template` cannot import the root package), at `pulse.New` and on every rescan — never parsed, never `Summary.Broken` (`TestNew_TemplateDirsSkipPulseSidecars`). A wrapped document fault carries the file in `details.file` and keeps its own body `details.path` (the file only when it has none; `TestNew_TemplateLoadFaultKeepsBothPaths`).

**Hot-reload lifecycle — phase split is the contract.** A lookup whose snapshot has aged past the store's 1s rescan interval (package constant, deliberately not an `Option`) re-walks the roots; a file is re-parsed only when size or mtime moved. `ReloadTemplates()` forces the walk now — the deterministic path for a deploy step that writes then renders.

| Phase | Malformed file does | Why |
|---|---|---|
| At `pulse.New()` | **hard-fails startup**, path named | a broken document at boot is a deploy error the operator must see immediately |
| After startup, parsed before | **serves its last-good parse**; `ListTemplates` marks `Summary.Broken` + `.Error` | a half-written file is the normal transient state of in-place editing; killing the catalog is worse than slightly stale content |
| After startup, never parsed | listed to be SEEN (empty `Target`), not fetchable; `GetTemplate`/`RenderTemplate` → `PULSE_TEMPLATE_INVALID` naming the path | no last-good to fall back to |

`ReloadTemplates()` returns **nil** for a broken file — an error there would mask every otherwise-healthy template. A root that is not a directory **is** still a hard error (misconfiguration, not a transient edit) and a failed walk leaves the previous index entirely in place. Repair clears the state on the next rescan. `Summary.Broken`/`.Error` are both `omitempty`, so healthy listings carry neither key.

**Errors — the `PULSE_TEMPLATE_*` codes, chosen by provenance not detection time.** A bad **declared default** is an author error → `_INVALID` (checked semantically at declaration: enum membership, date parse, period XOR — that is what keeps the fail-fast-at-`pulse.New()` promise real); a bad **caller value** → `_VAR_TYPE` / `_VAR_ENUM`. Same split on names: `$var`/`{{}}`/`$when` naming an **undeclared** variable is an author error caught at validation (`_INVALID`); a **declared but unresolved** reference is render-time `_UNRESOLVED`. Full family: `_NOT_FOUND`, `_INVALID`, `_TARGET_UNKNOWN`, `_TARGET_MISMATCH`, `_VAR_MISSING`, `_VAR_UNKNOWN`, `_VAR_TYPE`, `_VAR_ENUM`, `_UNRESOLVED`, `_RENDER_INVALID`, `_AXIS_COLLISION` (author error: a declared variable named like a `for_each` or `sweep` axis in the body), `_EXPR_SPLICE` (author error: a `{{token}}` — a variable's or an axis's — inside an expression string). **`_TARGET_UNKNOWN`** is an absent/unrecognised `target` only; `RenderTemplateRequest` called on a template declaring a different (valid) target is **`_TARGET_MISMATCH`** (details `template`, `target`, `expected_target`). Details keys: `errors.DetailTemplate` (`"template"`) + `errors.DetailVariable` (`"variable"`); `pulse errors lookup CODE` is authoritative.

**Render never opens a cohort.** A rendering template is well-formed against the request *shape* only; field existence, type compatibility, operator applicability and streamability stay `Predict`'s job. Strict decode (as every JSON request root, but under the template's own code): an unknown key fails `_RENDER_INVALID` with `details.field` plus, from `internal/strictjson`'s document-order walk, `details.path` (location in the rendered body), `valid_keys` (withheld ones removed) and `suggestion`; unlike a request file, a body with an `internal/examples/` `_meta` block attached fails too. `Rendered.JSON` is retained alongside the typed value on purpose: re-marshaling the typed request would NOT reproduce it, because the request structs are dense with `omitempty` and any slot that rendered to an explicit zero would vanish on a round trip — echo `Rendered.JSON`, never a re-marshal. **Withheld slots:** `template.RenderWith(t, vars, RenderOptions{WithheldSlots})` refuses a top-level key the caller's engine does not offer (root, `requests[i]`, `stages[i].request`) exactly as an undeclared key — same `_RENDER_INVALID` message, details, cause and document-order position — by renaming it with a `\x00` suffix before the strict decode; `Render` is `RenderWith` with zero options. The facade passes the instance's hidden slots (`.claude/reference/feature-profiles.md`, Request-slot gate); the package never learns why a key is withheld, so its import ceiling is unchanged.

**`format_version` stays `"1.1"`.** Nothing payload-reachable changed: `Options.TemplateDirs` is not a payload type, and `template.Template` / `Variable` / `Summary` / `Rendered` live in `internal/template/`, not `types/`, so they are not reachable from `internal/descriptor.BuildPayloadSchema`. `descriptor/testdata/payload-schema.json` is untouched by templating; a new template error code moves only the manifest golden.

Env var: `PULSE_TEMPLATES_DIR` (documented in `docs/src/library/options.md`). Detail: `skills/request-templating.md` + `docs/src/library/request-templating.md`.
